# 沉浸式与三维领域综述

## 一、发展历程

**版本里程碑说明**：本语料不含任何 repo_release 条目，故本节以论文时间线呈现；观测窗口集中于 2026-07 至 2026-09，约三个月，属局部切片观测。〔综述推断〕

### 阶段一：属性级帧间压缩的精细化（—2026-07 上旬）

动态点云压缩的重心从几何编码转向**属性的时间冗余消除**。paper:arxiv:2607.03576 提出基于几何的帧间属性编码方案，核心技术为基于图的运动估计（去除属性时间冗余）与免插值的分数体素运动估计（将运动精度从整数体素细化至分数体素级）。量化结果：MPEG 点云数据集、有损几何条件下，平均码率节省 vs G-PCC 55.3%、vs GeS-TM 42.3%、vs V-PCC 16.5%；且在无损与有损几何两种条件下均优于三个基线（paper:arxiv:2607.03576）。

### 阶段二：统一连续表示路线的成形（2026-07 中旬）

paper:arxiv:2607.16362 提出 OmniStyle-INR，以隐式神经表示（INR）作为统一连续表示，在文本提示与视觉范例双引导下覆盖 2D 图像、视频、3D 场景、4D 动态全部视觉模态的风格迁移。该工作同时给出了对显式表示路线的明确批评：高斯泼溅表示视频与 2D 图像这类稠密连续域时结构上欠优，所需高斯数量常逼近像素总数，实用性被削弱（paper:arxiv:2607.16362）。表示层选型（显式高斯 vs 隐式神经场）由此上升为沉浸式媒体管线的基础性争论。

### 阶段三：实时交互级传输与端侧落地（2026-09）

paper:arxiv:2609.19750 提出 DELUGE（分解式熵编码非结构化几何交换），面向实时物理模拟粒子流，利用粒子的时间相干性与速度可预测性实现**亚帧延迟**编解码：动态点云数据集上解码速度较 G-PCC（TMC13）快约 20×，编码速度较 Draco 快约 6×。落地形态为 Web 浏览器与 Apple Vision Pro 双端到端客户端，经感知质量评估与双人协作任务研究（实时手部追踪流体交互）验证（paper:arxiv:2609.19750）。至此，本窗口内的脉络可概括为：**压缩效率 → 表示统一 → 实时交互落地**三级递进。

## 二、技术主线与代表工作

### 主线 A：动态点云/粒子流的时域压缩

**A1. 图上运动估计 + 免插值分数体素细化**（paper:arxiv:2607.03576）
- 以几何为锚的帧间属性编码：基于图的运动估计建模动态实体点云跨帧属性对应关系；免插值分数体素运动估计将运动补偿精度细化至分数体素级，规避插值环节。
- 定位：补强 G-PCC 体系中属性维度的时间预测能力，覆盖无损与有损几何两种工作点。

**A2. DELUGE：物理先验驱动的实时编码**（paper:arxiv:2609.19750）
- 分解式熵编码的非结构化几何交换；核心先验为物理模拟粒子的速度可预测性与时间相干性，据此实现亚帧延迟编码与解码。
- 定位：切入 TMC13（解码过慢）与 Draco（编码过慢）均无法满足的实时传输场景。

### 主线 B：统一连续表示与上层编辑能力

**OmniStyle-INR**（paper:arxiv:2607.16362）
- 以 INR 为统一连续表示，单框架服务 2D 图像/视频/3D/4D 四类模态的风格迁移，支持文本提示与视觉范例双引导。
- 论点性贡献：高斯泼溅在稠密连续域（视频、2D 图像）中高斯数量常逼近像素总数，结构性欠优；INR 天然适配各视觉域，附带数据压缩、超分辨能力与深度生成模型无缝集成三重红利。

### 主线 C：端侧实时协作系统

DELUGE 配套的 Web 浏览器与 Apple Vision Pro 客户端构成异构双端部署，以感知质量评估 + 双人协作任务（实时手部追踪流体交互）完成系统级验证（paper:arxiv:2609.19750），代表了从「码率指标」向「交互任务绩效指标」的验证范式迁移。

## 三、当前关键问题

**1. 属性运动估计的精度—复杂度权衡**
整数体素级运动精度不足以支撑属性对齐，需细化至分数体素级；而传统亚体素细化依赖插值，引入额外误差与计算开销，免插值细化（paper:arxiv:2607.03576）是对该矛盾的直接回应。跨帧对应关系的建模方式（图结构 vs 简单平移搜索）仍是属性帧间编码的核心设计变量。

**2. 编码范式间增益严重不均衡**
同条件下，paper:arxiv:2607.03576 的节省幅度从 vs V-PCC 的 16.5% 到 vs G-PCC 的 55.3% 拉开近 4 倍差距，说明视频投影路线（V-PCC）在属性维度已具较强竞争力，几何基方案的优势高度依赖对比对象与内容类型。〔综述推断〕不存在跨内容类型通吃的属性压缩方案，基线选择本身即影响结论量级，评测需多基线并报。

**3. 表示选型之争：高斯泼溅与 INR 的域适配边界**
稠密连续域中高斯数量逼近像素总数导致表示退化（paper:arxiv:2607.16362），这是对显式泼溅路线在视频/2D 模态的结构性批评；INR 具备压缩、超分、生成式集成三重优势。但条目未涉及 INR 自身的解码串行性、每查询前向计算成本与训练开销——这构成该争论尚未闭合的部分。〔综述推断〕稀疏三维域（点云、粒子流）与稠密连续域（视频、图像）可能走向不同的表示选型。

**4. 通用标准编解码器的实时性鸿沟**
TMC13 解码速度落后专用方案约 20×，Draco 编码落后约 6×（paper:arxiv:2609.19750，动态点云数据集）。根因在于标准编码器面向通用内容设计，未利用物理模拟数据的结构先验（速度场可预测性、时间相干性）；「亚帧延迟」（单帧时间预算内完成编解码）作为新的硬约束，正把实时粒子流推向专用编码器路线。

**5. 端侧异构部署与多人协作验证方法学**
Apple Vision Pro 与 Web 浏览器算力差异悬殊却需共享同一实时码流（paper:arxiv:2609.19750）；验证手段从客观失真指标扩展为感知质量评估叠加双人协作任务研究，任务级指标（协作交互流畅度）如何标准化仍缺成熟口径。〔综述推断〕

**6. 几何失真与属性压缩的耦合**
paper:arxiv:2607.03576 需在无损与有损几何两种条件下分别验证，说明几何误差会传导至属性运动补偿环节。〔综述推断〕几何—属性联合率失真优化（而非属性单独优化）是有损链路下尚未解决的技术点。

**7. 压缩管线与上层可编辑性的割裂**
DELUGE/属性压缩代表传输管线成熟，OmniStyle-INR 代表 4D 内容可编辑能力成形，但二者分属两条技术栈；「INR 即压缩」的端到端管线（传输表示同时即编辑表示）尚无条目覆盖。〔综述推断〕

## 四、趋势与展望

1. **时间维度成为压缩增益主战场**：从帧内属性编码转向帧间运动估计（paper:arxiv:2607.03576）与物理速度先验（paper:arxiv:2609.19750），时域冗余消除是本窗口内两个压缩工作的共同增益来源。

2. **内容先验驱动的专用编码器崛起**：DELUGE 证明利用模拟数据速度可预测性可获得 20× 级解码加速（paper:arxiv:2609.19750）。〔综述推断〕仿真—编码协同设计（如以速度场直接作为运动矢量预测源）可能成为物理模拟类沉浸式内容的标配。

3. **表示层按模态分工收敛**：INR 以压缩 + 超分 + 生成式集成的三重优势争取统一表示地位（paper:arxiv:2607.16362），高斯泼溅在稠密连续域受结构性质疑。〔综述推断〕短期更可能形成「稀疏三维域显式表示、稠密连续域隐式表示」的分工格局，而非单一表示通吃。

4. **评测指标体系扩展**：从 MPEG 数据集上的 BD-rate 式码率节省（paper:arxiv:2607.03576），扩展至延迟（亚帧级）、解码吞吐（≈20×）、感知质量与双人协作任务绩效（paper:arxiv:2609.19750）。

5. **落地场景锚定 XR 多人协作**：XR 头显 + 浏览器异构双端、实时手部追踪流体交互（paper:arxiv:2609.19750）显示沉浸式媒体的验证场景正从单机点播转向多用户实时协作。
