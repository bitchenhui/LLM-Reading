# 音频编码领域综述

**基线说明**：本库共 11 条条目（3 条 IAMF 版本动态 + 8 篇论文），数据截至 2026-11-14。条目时间分布呈两个聚集区：2023.11–2024.11 的沉浸式音频标准化窗口、2026.08–2026.10 的研究密集期；两段之间（2024.11–2026.08）本库无条目收录，下述演化仅基于既有条目。

## 发展历程

**阶段一（2023.11–2024.11）：沉浸式音频标准 IAMF 从格式定义走向部署就绪**

AOMedia 于 2023-11-07 发布 IAMF 首个正式规范 v1.0.0，定义沉浸式音频的模型与格式（Immersive Audio Model and Formats），场景覆盖互联网音频流、组播/广播、文件下载、游戏、通信与 VR/AR，呈现端横跨耳机、手机、平板、电视、Soundbar、家庭影院与大屏 (repo_release:github:iamf-v1.0.0)。其后的版本演进呈现清晰的规范化节奏：

**阶段二（2026.08–2026.10）：研究密集期，三条线并行**

- **神经编解码器量化主线**沿“事后适配 → 架构内扩容 → 弃 VQ”递进：BAMU（2026-08-09，冻结模型上的事后 RVQ 深度分配）→ UniStream（2026-09-09，ME-RVQ 架构内扩容；其精读明确 BAMU 为同组前作）→ GS-Codec（2026-10-03，以高斯泼溅分解替代量化瓶颈）。
- **Opus/CELT 传统生态补全**：OLAC（09-14）补无损通路、Opus 感知透明阈值测定（10-14）补质量标定、SEMAC（10-23）将 CELT 能量匹配推广到高阶 Ambisonics。
- **端侧资源与实测方法学**：AudioTQ（08-15）单线程 CPU 实时标量量化；解码端码率-能耗-质量实测（09-28）首次在本库口径内给出神经编解码器端侧能耗证据。

## 技术主线与代表工作

### 1. 神经编解码器的量化瓶颈与码率控制

基线范式为“卷积 encoder–decoder + RVQ”（SoundStream 一脉，EnCodec/DAC 为代表）：每帧 latent 经 K 级残差码本量化，收发约定统一前缀深度，所有帧使用相同码本数 (paper:arxiv:2608.08432, paper:arxiv:2609.09866)。四篇工作分别从不同层面松动该范式：

- **BAMU** (paper:arxiv:2608.08432)：对**冻结**预训练 codec 做**事后**帧级 RVQ 深度分配。两个辨识点： 将“序列化容器字节精确”（激活索引 + 深度图 RLE 边信息 + 固定头部 + 字节对齐填充）而非名义码率纳入分配约束； 轻量、与码率无关的预测器估计帧级/层级边际潜在失真减少量，不触碰预训练权重。30 名听者主观测试 MOS 3.449→3.780（相对匹配的固定深度编码）；EnCodec 全程率失真增益一致，DAC 改进集中于中高码率（LibriSpeech 实验，另含 VCTK 评估）。
- **UniStream** (paper:arxiv:2609.09866)：全因果 48 kHz 流式编解码器。ME-RVQ 将路由依据改为“已解码量化状态的确定性函数”，实现零专家 ID 信令的量化容量扩展，相对单一共享码本仅 +5.5M 参数；OT-CFM 将流匹配降格为纯训练期正则、推理零开销。关键口径：12 kbps Top1 语音 Mel-D 13.07→8.21（EnCodec 基线）、PESQ/UTMOS 与 EnCodec 相当；22.5 kbps Top2 ViSQOL 语音模式 4.67、环境声模式 3.96（超过所有 ≤12 kbps 被评估系统）；语音上 ViSQOL audio 模式与 24 kbps Opus 差距不超过 0.03 MOS-LQO。
- **GS-Codec** (paper:arxiv:2610.04651)：以 1D 高斯基元加权和的参数化信号分解替代 VQ-VAE 式量化瓶颈，训练管线不含任何量化器，训练后对拟合参数做标量量化；单一 checkpoint 通过改变基元数量与每参数位深实现免重训练的细粒度码率控制。可比码率下 SIM/STOI/UTMOS 达到或超过开源 EnCodec/DAC，语义性能（WER）相当。
- **AudioTQ** (paper:arxiv:2608.15369)：数据无关路线，思想迁移自 LLM 权重量化。随机化 FWHT 正交旋转将时域幅度均匀化为标准正态分布，使逐坐标标量量化可行；6 bit Lloyd-Max + 1 bit QJL 残差构成 7 bit 虚拟索引、打包进 8 bit 容器对齐 CPU 寄存器边界，单线程 CPU 实时。基准测试最高 74.4% 物理体积缩减、SQNR 约 30 dB；论文推导了稀疏输入下的数学失效模式并给出 24 bit 录音棚音轨逐比特重建分析。

### 2. Opus/CELT 生态的功能补全

- **OLAC** (paper:arxiv:2609.15616)：作者为 Opus/RFC 6716/CELT 核心作者。镜像 CELT 的重叠结构（固定 120 样本 = 2.5 ms 重叠、Vorbis 窗、平顶窗形、与帧长无关），但全部计算留在时域、仅线性预测 + 熵编码，实现有损↔无损逐帧无痕切换（无冗余信息传输）且无损压缩率达 SOTA——TDAC 不受罚。两个目标用例：无线干扰回退（带宽受压缩时瞬时、无爆音降级有损）与机会性无损（有损 >200 kb/s/声道且音频复杂度足够低时切无损省比特）。开源 C 实现托管于 AOMediaCodec 组织 oac 仓库，产业化意图明显；对比路线 IntMDCT/MPEG-4 SLS 在代码复杂度与压缩性能两端都要付出代价。
- **Opus 感知透明阈值** (paper:arxiv:2610.20246)：两阶段 ITU-R BS.1116-3 双盲听测 + LMM/TOST 统计分析。第一阶段（21 名合格听音员、23 段音乐片段）中 128 kbps 与未压缩参考在差异检验上不可区分（LMM p=0.456）但未通过严格等效性检验（TOST p=0.064）；第二阶段 BLUP 筛选的最坏条件压力测试（10 名最关键听音员 + 8 个最难样本）中 128 kbps 被明确检出退化（p=0.030），160 kbps 通过严格统计等效（LMM p=0.747，TOST p=0.024）。结论：160 kbps 是 Opus 音乐压缩对未压缩 CD 音质的感知透明码率阈值。
- **SEMAC** (paper:arxiv:2610.32981)：作者名单含 Valin 与 Skoglund（Opus 核心团队）。针对 RFC 8486 CMF 2/3（逐通道 / 固定线性变换后立体声耦合）仍需传输全部 C=(N+1)² 路 HOA 波形、码率随球谐阶数二次增长（五阶即 36 通道）的瓶颈，改为“量化全阶方向性能量包络（边信息）+ 更少的 CELT 编码传输通道，解码端重新施加包络”。五阶素材、512/768 kbit/s 匹配配置的 MUSHRA 中，仅使用 36 个传输通道中 16 个的 SEMAC 评分高于全阶 CMF 3；相同传输通道数下优于直接阶数截断。

### 3. 沉浸式/空间音频的“标准层—编码层”分工

IAMF 三条版本动态解决格式、profile、加密与呈现元数据层 (repo_release:github:iamf-v1.0.0, repo_release:github:iamf-v1.1.0)；SEMAC 与 RFC 8486 路线解决 HOA 有效载荷压缩层 (paper:arxiv:2610.32981)。二者在条目层面无直接交叉引用，衔接状态属未知〔综述推断：标准层与 codec 层的集成是潜在结合点，本库无证据〕。

### 4. 端侧资源约束与测量方法学

- **能耗实测** (paper:arxiv:2609.34524)：实测四款神经音频编解码器（条目点名 EnCodec、DAC、SNAC）在笔记本与手机平台的解码端能耗。质量匹配工作点上，神经 codec 以更低码率达到相近 ViSQOL，但解码端能耗通常高于适用的传统编解码器（AAC-LC、Opus）；EnCodec 在两组质量匹配队列、两种平台上均给出神经 codec 中最低的盈亏平衡传输能耗阈值；若干 DAC 与 SNAC 对比项在 Phone XNNPACK CPU 路径上盈亏平衡阈值超过 200 mJ/kbit；DAC 与 SNAC 的全频段 Phone 配置解码 1 秒音频需超过 1 秒，无法满足实时解码。
- **评测口径**：UniStream 背景明确指出 PESQ/STOI 需重采样到 16 kHz 计算、属窄带语音口径，无法刻画全频段质量 (paper:arxiv:2609.09866)。

## 当前关键问题

**（1）神经编解码器“低码率 ≠ 低能耗”的端侧赤字。** 质量匹配下神经 codec 解码能耗通常高于 AAC-LC/Opus，若干 DAC/SNAC 配置盈亏平衡传输能耗阈值超过 200 mJ/kbit——按盈亏平衡定义，只有信道传输能耗高于该阈值时，码率节省才能补偿解码能耗增量 (paper:arxiv:2609.34524)；DAC/SNAC 全频段 Phone 配置甚至无法实时解码（解码 1 s 音频 >1 s）。〔综述推断〕在典型无线链路的传输能耗量级下该阈值难以满足，神经 codec 的优势场景被压缩到“传输昂贵、解码算力廉价”的组合。遗留技术点： 解码计算密度未被纳入设计目标，现有证据均为事后测量； 新架构的端侧特性未知——UniStream 仅给出 GPU 实时推理口径，而 2609.34524 未测 UniStream，但同范式 codec 在 Phone 上的失败结果提示 ME-RVQ 类路由架构需重新过端侧关〔综述推断〕。

**（2）码率控制约束的口径错位：名义码率 vs 序列化字节。** 既有自适应工作普遍以名义码率为约束，而部署硬约束是容器字节（激活索引 + 深度图 RLE 边信息 + 固定头部 + 字节对齐填充），名义码率最优的分配落盘可超预算 (paper:arxiv:2608.08432)。三个待解点： 帧级边际效用预测器的跨码本泛化——BAMU 预测器与码率无关，但在 DAC 上改进集中于中高码率，低码率 DAC 缺口仍在 (paper:arxiv:2608.08432)； 三条路线未收敛：事后分配（BAMU，零训练成本）vs 联合训练（VRVQ 需将可变码率行为与 codec 联合训练）vs 架构级免重训练（GS-Codec 单 checkpoint 改基元数/位深）(paper:arxiv:2608.08432, paper:arxiv:2610.04651)； 逐帧深度切换在流式信道下的缓冲与延迟语义。

**（3）量化容量扩展与码流信令的两难。** 每级残差量化仅配一本共享码本，等价于迫使语音共振峰、音乐谐波与环境声纹理共享同一表示空间 (paper:arxiv:2609.09866)；MoE 化路线（如 SwitchCodec）需将专家 ID 写入码流，增加信令开销并复杂化流式部署。UniStream 以“已解码量化状态的确定性函数”路由实现零信令扩容（+5.5M 参数），但其质量声明高度依赖口径：对 24 kbps Opus 的 ≤0.03 MOS-LQO 差距仅在 22.5 kbps、Top2、ViSQOL audio 模式、语音素材下成立 (paper:arxiv:2609.09866)——更低码率档与跨域（音乐/环境声）的容量-信令边界仍开放。

**（4）非 VQ 瓶颈的保真与适用边界。** GS-Codec 去掉训练管线中的量化器、训练后对连续参数做标量量化，语义（WER）持平，但条目未覆盖极端码率与非语音素材 (paper:arxiv:2610.04651)；AudioTQ 的 SQNR 约 30 dB，且论文自行推导了稀疏输入下的数学失效模式 (paper:arxiv:2608.15369)——数据无关标量路线的感知质量上限与适用信号类别是硬边界，当前定位更接近物理体积缩减工具而非感知透明编码。

**（5）有损↔无损无缝切换的重叠结构对齐。** 独立无损格式（FLAC/ALAC/ALS 等，时域、非重叠帧）与 MDCT 有损编码器的重叠-相加结构无法对齐，切换要么产生不连续、要么需冗余编码重叠区样本并处理量化噪声突变 (paper:arxiv:2609.15616)。OLAC 以可逆 TDAC 镜像 CELT 重叠参数（120 样本 = 2.5 ms、Vorbis 窗、平顶窗形）解决，遗留： 机会性无损的切换判据（音频复杂度估计 vs >200 kb/s/声道有损档位）的稳健性； 该对齐方法的 codec 通用性——条目仅覆盖 Opus/CELT 栈〔综述推断：迁移到其他重叠变换有损栈需重新设计可逆加窗〕； IntMDCT 共窗路线（SLS）的复杂度-压缩率代价并未被消除，只是被绕开。

**（6）HOA 码率二次增长与参数化保真上限。** 通道数 C=(N+1)² 使逐通道波形编码在高阶工程上不可行；SEMAC 证明“少传输通道 + 全阶方向能量包络”在感知上优于“低精度编码全部通道”（16/36 通道胜全阶 CMF 3，512/768 kbit/s 匹配配置）(paper:arxiv:2610.32981)。但其设计前提是方向能量构成关键感知特征——ITD/ILD/双耳相关度线索未显式表征，重建质量受场景参数估计准确度制约；更高阶（>5）、更低码率扩展均未在条目中验证。

**（7）评测口径碎片化与方法学风险。** 客观侧：PESQ/STOI 的 16 kHz 窄带口径无法刻画 48 kHz 全频段 (paper:arxiv:2609.09866)，ViSQOL 模式选择直接改变结论可比性。主观侧：常规差异检验会把“检出力不足”误判为“透明”——Opus 128 kbps 在 21 人/23 段池化检验 p=0.456，却在 10 人 + 8 样本最坏条件筛选下 p=0.030 被检出，直到 160 kbps 才通过严格等效 (paper:arxiv:2610.20246)。能耗维度刚进入视野但尚未标准化 (paper:arxiv:2609.34524)。领域缺乏“码率-质量-能耗-字节”的统一评测协议。

## 趋势与展望

- **设计目标从二维走向多维。** 码率-质量之外，字节精确容器约束 (paper:arxiv:2608.08432)、解码能耗 (paper:arxiv:2609.34524)、全因果流式实时性 (paper:arxiv:2609.09866) 已各自成为一等公民约束；〔综述推断〕下一个周期应出现把能耗测量前置到架构设计与训练目标中的工作。
- **“不动预训练模型”成为工程主线。** BAMU 的事后分配与 GS-Codec 的单 checkpoint 免重训练共享同一动机：在预训练 codec 生态上叠加码率控制而不付训练成本 (paper:arxiv:2608.08432, paper:arxiv:2610.04651)。该范式与 LLM 领域推理期适配技术形成跨域合流——AudioTQ 即从 LLM 权重量化迁移 FWHT 旋转 + Lloyd-Max + QJL 残差整套工具 (paper:arxiv:2608.15369)。
- **Opus/AOMedia 开源栈横向扩张，生态位互补成环。** OLAC 补无损（开源 C 入 AOMediaCodec oac 仓库）、SEMAC 扩空间音频、IAMF v1.1.0 补齐加密与分层——同一生态内“格式（IAMF）—传输（CENC）—编码（CELT/OLAC/SEMAC）”三层补全加速 (paper:arxiv:2609.15616, paper:arxiv:2610.32981, repo_release:github:iamf-v1.1.0)。〔综述推断〕OLAC 与 SEMAC 均出自 Opus 核心作者圈（Valin、Skoglund），沿 RFC/开源路径标准化的概率高；HOA 表示与 IAMF 载荷层的集成是下一个可见衔接点。
- **空间音频压缩范式从“全通道波形”转向“参数化方向能量 + 子集波形”。** SEMAC 的 16/36 通道胜全阶 CMF 3 的主观证据为该范式提供了条目内首个强信号；与 DirAC/SPAR 类参数化空间编码在估计精度与线索保真上的融合是开放方向 (paper:arxiv:2610.32981)。
- **评测标准化压力上升。** 等效性检验（TOST）+ 最坏条件筛选（BLUP）有望成为透明性声明的默认协议 (paper:arxiv:2610.20246)；〔综述推断〕全频段客观指标与质量匹配的“码率-能耗”联合报告将成为神经 codec 工作的隐性门槛。
- **神经编解码器的胜负手在端侧。** 在盈亏平衡证据下，若解码计算密度不下降，神经 codec 将被限制在服务器转码、离线分发等算力廉价场景，通信与无线音频等能耗敏感场景继续由 Opus 系主导 (paper:arxiv:2609.34524)。〔综述推断〕量化架构创新（ME-RVQ、高斯泼溅）与端侧部署路线（CPU 实时、寄存器对齐标量量化）能否合流，将决定下一周期神经 codec 的实际渗透率。
