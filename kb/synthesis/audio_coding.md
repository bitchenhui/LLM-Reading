# 音频编码（audio_coding）领域综述

## 发展历程

语料呈现两条时间脉络：**2023-11 至 2024-11 的沉浸式音频标准化进程**，与 **2026-08 至 2026-10 的编码算法研究密集产出期**；两个区间之间（2024-11 至 2026-08）知识库无条目入库。

### 阶段一：沉浸式音频标准从首发到比特流冻结（2023-11 — 2024-11）

- **2023-11-07｜IAMF v1.0.0**：AOMedia 发布沉浸式音频标准首个正式规范，定义 Immersive Audio Model and Formats，面向流媒体与离线场景，覆盖互联网音频流、组播/广播、文件下载、游戏、通信及 VR/AR，呈现端横跨耳机、手机、平板、电视、Soundbar、家庭影院与大屏（repo_release:github:iamf-v1.0.0）。
- **2024-05-06｜IAMF v1.0.0-errata**：勘误版集中处理互操作细节——为 configOBUs 定义专用 Box、更新保留 OBU 条款、修订 ACN 与 SN3D 规范引用、约束同一 MixPresentation 内 audio_element_id 不重复，并清理 base profile 勘误与 9.1.4/9.2 节歧义（repo_release:github:iamf-v1.0.0-errata）。
- **2024-07-01 比特流冻结（bitstream frozen）→ 2024-11-08 发布 v1.1.0**：新增 Base-Enhanced Profile、CENC（Common Encryption）通用加密、9.1.6ch 等新布局及 MixPresentationTags 语法语义（repo_release:github:iamf-v1.1.0）。

### 阶段二：量化机制、流式架构与评估方法密集产出（2026-08 — 2026-10）

- **2026-08｜码率分配与超轻量化**：BAMU 在冻结预训练神经语音编解码器上按精确字节预算动态选择 RVQ 前缀深度（paper:arxiv:2608.08432）；AudioTQ 借鉴 LLM 权重量化思想，构建数据无关的单线程 CPU 实时方案（paper:arxiv:2608.15369）。
- **2026-09｜流式、混合编码与能效实测**：UniStream 提出全因果 48 kHz 多专家 RVQ 流式编解码器（paper:arxiv:2609.09866）；OLAC 实现与 Opus CELT 重叠兼容的无缝有损/无损切换（paper:arxiv:2609.15616）；语料中唯一一份解码端码率-能耗-质量的端侧实测研究发布（paper:arxiv:2609.34524）。
- **2026-10｜表示革新、严格评估与空间音频**：GS-Codec 以一维高斯泼溅替代量化瓶颈（paper:arxiv:2610.04651）；两阶段 BS.1116-3 听测 + LMM/TOST 统计确定 Opus 音乐感知透明阈值 160 kbps（paper:arxiv:2610.20246）；SEMAC 以方向能量包络压缩高阶 Ambisonics（paper:arxiv:2610.32981）。

## 技术主线与代表工作

| 代表工作 | 时间 | 定位 | 核心机制 | 关键量化口径 |
|---|---|---|---|---|
| BAMU | 2026-08 | 码率分配 | 冻结模型 + RVQ 前缀深度边际效用分配 | MOS 3.449→3.780（30 名听者） |
| AudioTQ | 2026-08 | 超轻量 CPU | FWHT 旋转 + 6bit Lloyd-Max + 1bit 残差 | 最高 74.4% 体积缩减、SQNR≈30 dB |
| UniStream | 2026-09 | 因果流式 | ME-RVQ + 历史解码状态路由 | +5.5M 参数；22.5 kbps ViSQOL 语音 4.67 |
| OLAC | 2026-09 | 无损混合 | TDAC 与 CELT 重叠结构匹配 | 无缝切换 + SOTA 无损压缩率 |
| 端侧能效实测 | 2026-09 | 部署评估 | 笔记本/手机解码端能耗 | 若干 DAC/SNAC >200 mJ/kbit；解码 >1 s/s |
| GS-Codec | 2026-10 | 表示革新 | 1D 高斯泼溅替代量化瓶颈 | 单 checkpoint 免重训练调码率 |
| Opus 透明阈值 | 2026-10 | 感知评估 | 两阶段 BS.1116-3 + LMM/TOST | 透明阈值 160 kbps |
| SEMAC | 2026-10 | 空间音频 | 方向能量包络 + 少量 CELT 通道 | 16/36 通道优于全阶 CMF 3 |

### 主线一：沉浸式与空间音频——标准定义与高效压缩双轨并行

标准轨上，IAMF v1.0.0 确立沉浸式音频模型与格式基础，v1.1.0 通过 Base-Enhanced Profile、CENC 加密与 9.1.6ch 布局扩展能力边界（repo_release:github:iamf-v1.0.0；repo_release:github:iamf-v1.1.0）。压缩轨上，Opus 经 Channel Mapping Families 2/3（RFC 8486）逐通道编码全部 Ambisonics 通道，码率随球谐阶数二次增长，构成 HOA 编码的主要瓶颈（paper:arxiv:2610.32981）。SEMAC 将 CELT 频带能量匹配原理推广至方向性信号：仅传输量化后的全阶方向性能量包络 + 更少的 CELT 编码通道，解码端重新施加编码端观测的包络以恢复全阶方向能量分布。在五阶 HOA、与 Opus CMF 3 匹配配置（512 与 768 kbit/s）的 MUSHRA 测试中，仅用 36 个传输通道中 16 个即评分高于全阶 CMF 3；相同传输通道数下亦优于直接阶数截断（paper:arxiv:2610.32981）。

### 主线二：量化瓶颈的系统性再设计

1. **RVQ 深度边际效用分配（BAMU）**：冻结预训练模型不动，用轻量且与码率无关的预测器估计帧级/层级边际潜在失真减少量，在精确序列化字节预算下选择前缀有效的 RVQ 深度；相对匹配的固定深度编码，主观 MOS 由 3.449 提升至 3.780（30 名听者）；EnCodec 上一致率失真增益，DAC 改进集中于中高码率（LibriSpeech 实验，另含 VCTK 评估）（paper:arxiv:2608.08432）。
2. **多专家扩展量化容量（UniStream ME-RVQ）**：专家路由仅依赖历史解码量化状态、无需传输专家标识；ME-RVQ 相对单一共享码本仅增加 5.5M 参数，支持 GPU 实时推理（paper:arxiv:2609.09866）。
3. **去 VQ 化瓶颈（GS-Codec）**：以一维高斯基元加权和拟合替代 VQ-VAE 式量化瓶颈，训练管线不含任何量化器，训练后仅对拟合参数做标量量化；单一 checkpoint 通过改变基元数量与每参数位深实现免重训练的细粒度码率-质量控制；可比码率下 SIM/STOI/UTMOS 达到或超过开源 EnCodec 与 DAC，语义性能（WER）相当（paper:arxiv:2610.04651）。
4. **数据无关标量量化（AudioTQ）**：随机 FWHT 正交旋转将时域幅度均匀化为标准正态分布后逐坐标标量量化；6 比特 Lloyd-Max + 1 比特 QJL 残差构成 7 比特虚拟索引，打包进 8 比特容器对齐 CPU 寄存器边界，无硬件并行加速器的单线程 CPU 上实时执行；基准测试中最高 74.4% 物理体积缩减，SQNR 约 30 dB；论文推导了稀疏输入下的数学失效模式并给出 24 比特录音棚音轨逐比特重建分析（paper:arxiv:2608.15369）。

### 主线三：因果流式与端侧部署能效

UniStream 为语料中唯一全因果 48 kHz 流式神经编解码器，覆盖语音/音乐/环境声：12 kbps 下 UniStream-Top1 的 PESQ 与 UTMOS 与 EnCodec 相当，语音 Mel-D 由 EnCodec 的 13.07 降至 8.21；22.5 kbps 的 UniStream-Top2 在 ViSQOL 语音模式达 4.67、环境声模式达 3.96（后者超过所有 ≤12 kbps 被评估系统）；语音 ViSQOL audio 模式与 24 kbps Opus 差距不超过 0.03 MOS-LQO（paper:arxiv:2609.09866）。部署侧，对四款神经编解码器的笔记本/手机实测表明：质量匹配工作点上，神经编解码器以更低码率达到相近 ViSQOL，但解码端能耗通常高于适用的传统编解码器（AAC-LC、Opus）；EnCodec 在两组质量匹配队列、两种平台上均给出神经编解码器中最低的盈亏平衡传输能耗阈值；若干 DAC 与 SNAC 对比项在 Phone XNNPACK CPU 路径的该阈值超过 200 mJ/kbit，且其全频段 Phone 配置解码 1 秒音频需超过 1 秒（paper:arxiv:2609.34524）。

### 主线四：有损/无损混合与生态兼容（OLAC）

OLAC 基于 TDAC 并与 Opus CELT 模式的重叠结构匹配，实现有损与无损之间无间断、无需传输冗余信息的切换，且在采用 TDAC 的前提下达到 SOTA 无损压缩性能（paper:arxiv:2609.15616）。

### 主线五：感知透明的统计化评估（Opus 透明阈值）

第一阶段（21 名合格听音员、23 段音乐片段）中，128 kbps 与未压缩参考差异检验不可区分（LMM p=0.456）但未通过严格等效检验（TOST p=0.064）；第二阶段 BLUP 筛选的最坏条件压力测试（10 名最关键听音员 + 8 个最难样本）中，128 kbps 被明确检出退化（LMM p=0.030），160 kbps 同时通过差异检验（p=0.747）与严格等效（TOST p=0.024）；结论为 160 kbps 是 Opus 音乐压缩在苛刻听音环境下对未压缩 CD 音质的感知透明码率阈值（paper:arxiv:2610.20246）。

## 当前关键问题

### P1｜神经编解码器“低码率”与“高解码能耗”的结构性矛盾（最突出的落地障碍）

- 质量匹配工作点上，被测神经编解码器解码能耗通常高于 AAC-LC/Opus（paper:arxiv:2609.34524）。〔综述推断〕盈亏平衡传输能耗阈值刻画“传输侧节省 = 解码能耗增量”的链路能耗水平，阈值越低越易净获益；DAC/SNAC 若干项 >200 mJ/kbit（Phone XNNPACK CPU 路径）意味着在低能耗近场链路下这些配置净能耗为正——神经编解码器的码率优势仅在传输能耗占主导的链路兑现。
- 实时性失守：DAC 与 SNAC 全频段 Phone 配置解码 1 s 音频需 >1 s（paper:arxiv:2609.34524）；而 UniStream 的实时性依赖 GPU 推理（paper:arxiv:2609.09866）。〔综述推断〕“GPU 实时”与“手机 CPU 实时”之间的鸿沟（CPU 推理路径的算子效率）是神经编解码器端侧化的核心工程瓶颈，解码端架构选择影响巨大（EnCodec 在两组队列、两种平台均为神经方案中最低阈值）。
- 待解技术点：解码端计算与码本访问的能耗优化、按平台分级的模型配置策略；条目未覆盖相关优化手段。

### P2｜码率控制与训练架构的耦合：固定深度/固定码率的次优性

- 固定 RVQ 深度在精确字节预算下显著次优：BAMU 动态前缀深度选择将 MOS 由 3.449 提至 3.780（paper:arxiv:2608.08432）。
- 冻结模型约束下的适配边界：BAMU 预测器与码率无关且轻量、无需改动冻结模型，但增益依架构而异——EnCodec 一致增益、DAC 集中于中高码率（paper:arxiv:2608.08432），跨架构泛化性条目未覆盖。
- 免重训练码率控制的另一路径是 GS-Codec 的“基元数量 × 每参数位深”双旋钮（paper:arxiv:2610.04651），但条目仅覆盖语音维度，且训练后标量量化的码率-质量边界标定未展开。〔综述推断〕外挂分配器（BAMU）与架构内建连续可调（GS-Codec）两条路线尚未在统一评测下比较；可变码率与流式自适应码率（ABR）的协同亦无条目涉及。

### P3｜因果流式下的量化容量、边信息与跨内容通用性

- ME-RVQ 以 +5.5M 参数（相对单一共享码本）解决共享码本容量不足，路由仅依赖历史解码量化状态、零专家标识边信息（paper:arxiv:2609.09866）。
- 质量余差仍存在：语音 ViSQOL audio 模式下 UniStream-Top2 与 24 kbps Opus 差距 ≤0.03 MOS-LQO——接近但按条目口径未声明超越（paper:arxiv:2609.09866）。
- 极低码率语音已具优势（12 kbps 语音 Mel-D 8.21 vs EnCodec 13.07），环境声 22.5 kbps ViSQOL 3.96 超过所有 ≤12 kbps 被评估系统，但音乐维度条目未给出量化指标（paper:arxiv:2609.09866）。〔综述推断〕路由依赖历史解码状态的设计在丢包/失同步场景下的鲁棒性，是流式部署的关键未知项。

### P4｜空间音频：码率随阶数二次增长 vs 参数化方向表示的保真边界

- Opus CMF 2/3 逐通道编码使码率随球谐阶数二次增长（paper:arxiv:2610.32981），HOA 高阶化的传输成本失控。
- SEMAC 已验证“少传输通道 + 量化方向能量包络”在感知上优于“低精度编码全部 HOA 通道”与“直接阶数截断”（16/36 通道、512 与 768 kbit/s、五阶 MUSHRA 优于全阶 CMF 3）（paper:arxiv:2610.32981）。
- 开放点：SEMAC 恢复的是全阶方向能量分布，包络量化精度与通道削减数的联合率失真优化、非能量类空间属性（相位/相干性等）的保持，条目均未涉及〔综述推断〕。〔综述推断〕该问题与 IAMF 部署侧相关：IAMF 定义格式与呈现，HOA 传输效率仍取决于底层编解码器的选择。

### P5｜感知评估方法学：“不可区分”不等于“等效”

- 128 kbps 差异检验 p=0.456 却未过 TOST（p=0.064），且在最坏条件压力测试下被检出退化（p=0.030）；160 kbps 双重通过（p=0.747 / p=0.024）（paper:arxiv:2610.20246）。
- 技术要点：仅依赖差异检验（零假设不显著）会系统性高估透明性；等效性检验（TOST）+ BLUP 双向（听音员 × 样本）最坏条件筛选构成更严格的透明性声明流程（paper:arxiv:2610.20246）。〔综述推断〕该方法论对神经编解码器的主观评测同样构成改进方向；160 kbps 阈值为 Opus 音乐场景码率规划提供量化锚点。

### P6｜超轻量数据无关编码的质量上限与失效边界

- AudioTQ 的 SQNR 约 30 dB、最高 74.4% 物理体积缩减（基准测试最大值），存在被推导证明的稀疏输入数学失效模式（paper:arxiv:2608.15369）。
- 其设计取向是 CPU 寄存器对齐（7 比特虚拟索引入 8 比特容器）而非感知最优（paper:arxiv:2608.15369）；24 比特录音棚音轨逐比特重建分析指向专业音轨场景的适用边界，但条目未给出与传统/神经感知编解码器的横向主观对比〔综述推断：其与感知编码路线的质量差距待界定〕。

### P7｜标准文本工程化与互操作风险（IAMF）

v1.0.0-errata 集中修复 configOBUs 封装、保留 OBU 处理、audio_element_id 唯一性等互操作细节（repo_release:github:iamf-v1.0.0-errata），表明沉浸式标准的部署一致性依赖持续的规范澄清机制；v1.1.0 引入 CENC 与 Base-Enhanced Profile 后，加密流与 MixPresentation 混合呈现的交互正确性成为新的互操作面（repo_release:github:iamf-v1.1.0）〔综述推断：CENC 与 MixPresentationTags 的交互细节条目未展开〕。

## 趋势与展望

1. **量化瓶颈“去 VQ 化”与码率控制后置化**：从端到端学习量化器（RVQ）转向“参数化分解 + 训练后量化”（paper:arxiv:2610.04651）与“冻结模型 + 外挂分配器”（paper:arxiv:2608.08432），训练成本与部署期码率控制正在解耦。〔综述推断〕该方向有望统一可变码率、按内容自适应深度与流式 ABR 需求，是神经编解码器走向工程化的关键路径。
2. **评估维度从“码率-质量”扩展为“码率-能耗-质量”**：端侧实测确立“低码率不必然带来端侧能耗收益”的结论（paper:arxiv:2609.34524）。〔综述推断〕解码能耗将进入编解码器设计的优化目标与基准报告的固定栏目，移动 CPU 实时性可能成为神经方案的准入门槛。
3. **以 Opus/CELT 为锚点的兼容式演进**：OLAC 的无缝有损/无损切换（paper:arxiv:2609.15616）与 SEMAC 对 CELT 的复用（paper:arxiv:2610.32981）表明新能力倾向于在既有生态内叠加而非整体替换。
4. **空间音频标准与压缩双轨推进**：标准化侧 IAMF 完成比特流冻结并补齐 Profile 与加密能力（repo_release:github:iamf-v1.1.0）；压缩侧“能量包络 + 少通道”已被主观验证优于逐通道编码与阶数截断（paper:arxiv:2610.32981）。〔综述推断〕更高球谐阶数与动态空间场景下的包络编码效率是下一步竞争点。
5. **透明性声明的统计严格化**：等效性检验 + 最坏条件压力测试的流程（paper:arxiv:2610.20246）〔综述推断〕或成为后续编解码器主观评测与“透明”营销声明的方法论基线。
6. **超轻量与全神经两条路线并行，中间地带空白**：数据无关 8 比特容器方案面向无加速器环境（paper:arxiv:2608.15369），全因果 48 kHz 多专家方案面向 GPU 实时流式（paper:arxiv:2609.09866）；〔综述推断〕移动 CPU 上的实时高质量神经编码——兼顾 P3 的容量设计与 P1 的能耗约束——是当前语料中未见覆盖、最具价值的攻关方向。
