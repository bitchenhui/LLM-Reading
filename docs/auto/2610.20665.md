## 1. 背景与动机

本文处理的是 LLM 智能体落地实时环境时的一个根本性矛盾：**推理与工具调用耗时，而世界在推理期间继续演化**。一个在观测时刻正确的动作，经推理延迟后送达时可能已不适用——Mario 在模型判断"是否跳"时继续向敌人移动，判断抵达时碰撞已发生。作者将"决策正确性"与"决策时效性"解耦，指出既往游戏类基准（SmartPlay、BALROG、lmgame-Bench 等 step-based 交互）在模型响应期间暂停游戏，等于系统性抹除了决策延迟的后果，其分数无法预测游戏持续运行时的表现。

论文动机链条有三层：

1. **评测缺口**：需要一套在推理期间游戏持续运行、且时钟条件（暂停/实时/加速）可控可配对的评测框架，才能干净地度量"响应速度—任务表现"关系。
2. **现象发现**：作者用该框架揭示了一个核心张力——强推理慢模型（GPT-6.1-sol，约 19 s/响应）在暂停时钟下五分之四以上游戏类型胜过快决策模型 Jev（约 0.52 s/响应），但在实时时钟下均分只有 1.51 对 13.51；而单纯求快也不够，所有被测模型实时均分不超 16.62。推理能力与响应速度在实时条件下形成两难。
3. **方法回应**：既然快模型决策快但弱、慢模型强但慢，能否让慢模型的推理"离线地"改善快模型的在线决策？这就是 TORSI（Two-Timescale Offline Recursive Self-Improvement）的出发点——把深思熟虑放到游戏间隙（慢时间尺度），把动作执行留给快模型（快时间尺度），且部署时零教师调用。

从音视频技术上下游视角看，这一问题结构对实时音视频交互系统（云游戏、实时互动直播、低延迟具身控制）是直接同构的：端侧轻量策略负责毫秒级响应，云端大模型负责离线蒸馏经验与规则，本文给出的正是"时钟可控评测 + 双时间尺度自改进"的完整参考实现。论文基准采用结构化文本状态而非原始像素，即刻意隔离感知延迟、只研究决策延迟，这一点在迁移到端到端视觉智能体时需注意（作者在 Limitations 中明示）。

## 2. 方法总览

工作由两部分组成：**RealtimeBench 基准**与 **TORSI 方法**。

**RealtimeBench**：180 个任务、六种游戏类型（Mario/Snake/Tetris/Temple/River/Bird），每种 30 个任务，划分为 10 feedback（经验收集）+ 10 validation（更新选择）+ 10 test（仅最终报告）。核心协议是 **live-clock**：智能体从当前观测的合法动作中做选择期间，游戏以先前已接受的控制继续运行。关键概念区分：

- **响应延迟** L_i = t_i^r − t_i^o（观测到响应的等待）；
- **动作年龄** A_i = t_i^a − t_i^o（观测到动作实际生效的总延迟，含调度/等待合法 tick）。

二者在响应需等待合法游戏 tick 或调度时发生分离；**结果由 t_i^a 时刻的状态决定**——这是整个评测语义的锚点。时钟条件四档：Paused（推理时冻结）、Current（声明的实时钟）、1.5×、2× 加速，通过改变 pacing 而不改游戏物理实现配对比较。

**TORSI**：四步循环——① 学生在 feedback 任务上以实时钟运行，收集失败轨迹 D^(f,k)（含观测、响应、响应延迟、动作年龄、结果、对齐截图）；② 教师在**暂停或减速环境**中从保存的 feedback 状态出发试错替选动作序列，随后学生在其实时延迟下检验草稿指引，形成练习证据 B^(f,k)；③ 教师综合当前指引 + 失败轨迹 + 练习证据，产出修订指引（公式：ĥ^(f)_{k+1} = T_k(h^(f)_k, D^(f,k), B^(f,k))）；④ 候选指引冻结后在 validation 任务上评估，**仅当均分严格高于当前指引才被采纳**，平局或被拒则保持原样，随后进入下一轮针对新学生剩余失败的学习。测试任务永远不参与更新选择。

整个过程中，只有指引 变化；学生权重、观测、合法动作、物理、时钟、目标、预算、评分、数据划分全部冻结。

## 3. 关键设计

**（1）进度式评分而非二值完成**。部分游戏无离散完成条件，且成功完成稀少时二值分无法区分部分进展。归一化公式 q(e) = 100·min(p(e)/R_f, 1)，其中 p(e) 为峰值进展（不受后续失败影响），R_f 为各游戏类型的参考目标：Mario 3200 像素、Snake 85 食物、Tetris 260 行、Temple 130,000 分、River 11,000 分、Bird 25 管道。100 分代表达到参考目标而非通关；归一化提供公共量纲而非等难度。游戏类型得分为其任务均值，Avg 为六类型无权重均值。

**（2）时间语义感知的动作接口**。这是工程上最有参考价值的部分——各游戏接口显式吸收推理延迟，而非假装动作即时生效：

| 游戏 | 动作接口与执行语义 |
|---|---|
| Mario | 未来时间槽上的按键计划，显式短跳/长跳/松开 A 语义 |
| Snake | 方向 + 以 tick 计的延迟；同向重复选择保留先前的待定转弯；转弯时机锚定观测 tick |
| Tetris | 联合旋转/列选择；响应抵达时做可达性检查，放置不可达时允许一次重查询 |
| Temple | Wait/左移/右移/跳/滑铲/Pulse |
| River | 车道/开火/油门决策，转向转换器把模型输出映射为连续转向 |
| Bird | 八套完整扇翅日程，选中日程在响应间持续执行 |

Bird 的日程式接口解释了它在中等加速下的相对稳健（作者标注这是解释而非因果检验）。观测均为结构化文本（棋盘高度、可见危险、时序线索等），harness 可从当前状态计算几何/时序特征，但打分期间禁止检查未来状态或搜索模拟器。

**（3）离线练习的访问权限分层**。教师可在保存的 feedback 状态上探索（暂停/减速环境），但此权限仅限离线学习且排除 test 状态；部署学生在游戏中无教师调用、无未来状态访问。这一分层保证了方法效力来自"可重置环境的离线试错"而非在线作弊——也意味着对物理或不可逆交互（真机）的直接迁移受限，作者明确承认此局限。

**（4）指引的可执行形态**。练习验证过的动作序列只适配特定状态，可复用指引须泛化为条件规则。指引使用固定字段：技能指令、动作特定指令、条件规则；规则引用当前观测特征（如 Tetris 低于高度 17 时仅在消行同时降低峰值高度且至多新增一个埋穴时才偏好消行；Snake 检查下一步转弯并保留逃生路线而非把食物追进死巷；Mario 起跳前松开跳跃键、按附近危险与落面确定起跳时机）。规则保持简洁以适配动作选择场景。

**（5）验证门控 + 按游戏类型独立采纳**。候选先冻结再评估，防止评估期间继续修改；采纳决策按游戏类型分别进行，Mario 与 Temple 在第二轮被验证门拒绝后即沿用 R1 指引——"由 validation 而非 test 表现选择"是防止测试集信息泄漏的关键机制。

核心消融是**离线练习的作用**（Table 3，一轮，各变体均从学生失败轨迹生成教师指引，每格为 validation(候选)/test(采纳)，按游戏类型独立过验证门，被拒时 test 用 Base 分）：

|---|---|
| Base | 16.38 / 13.51 |
| 仅指引（无练习） | 14.51 / **13.08** |
| + 教师练习 | 15.88 / 14.14 |
| + 学生练习 | 15.76 / 13.07 |

三个结论值得注意：① **无练习时 test 反而低于 Base**（13.08 对 13.51）——仅从失败轨迹反思产出的指引净效果为负，说明纯回顾式蒸馏在实时控制上不可靠；② 教师、学生练习**单独**作用都很有限（14.14 / 13.07），二者**组合**才跳升到 19.35——检验替选方案（教师视角的因果验证）与检验方案在快学生实时延迟下能否执行（学生视角的时延验证）是互补环节：教师可证"该做什么"，只有学生实践能证"在该延迟下做不做得成"；③ 作者诚实地标注练习预算在各变体间未配平，这是该消融的口径限制。分游戏类型看，Full TORSI 的增益主要来自 Temple（validation 3.65→47.04）与 Tetris/Snake/River，Mario 增益相对小。

另一层"隐性消融"是验证门本身：R2 指引在 Mario（validation 22.38 < R1 32.49）和 Temple（26.29 < 47.04）上未过门而被拒，最终 Adopted 仍比 R2 全量套用均分高（24.19 对 23.57 的 test 均分），门控机制实际发挥了防止回归的作用。

## 6. 贡献与启示

**贡献**：① RealtimeBench 提供了显式时钟控制（暂停/实时/加速配对）的统一评测框架，作者的相关工作对比表（Table 6）显示其为同时覆盖 wall-clock、推理期状态演化、延迟后果度量、暂停对照与 pacing 扫描的基准；② 用配对评测把"强推理 vs 快响应"的张力提炼为实时智能体的中心实践难题；③ TORSI 证明了慢速深思可以离线地、递归地转化为快速执行器的可复用指引，且验证门控 + 零在线教师调用 + 指引跨模型可迁移。

**工程启示**（对音视频/实时交互系统）：

- **评测语义**：任何评估实时 LLM 驱动的交互系统（低延迟数字人、云游戏 AI、实时推流中的内容理解与响应）的基准，必须区分响应延迟与动作年龄，并以动作生效时刻的状态结算结果；暂停式评测会系统性高估慢而强的模型。本文 GPT-6.1-sol 暂停 48–57 分、实时 1.51 分的悬崖是这一点的极端例证。
- **架构范式**：快慢双时间尺度分工（<1 s 端侧决策模型 + 离线云端教师）与音视频领域经典的"轻量在线模型 + 云端离线蒸馏"管线同构，但 TORSI 的增量在于三点可移植机制：**可重置状态上的离线反事实试错**（教师练习）、**在真实在线延迟下的部署前验证**（学生练习，二者缺一即失效）、**验证门控的冻结式采纳**。消融证明第三点尤其关键——纯反思式更新净收益为负。
- **接口设计**：把延迟语义写进动作接口（按键计划、扇翅日程、tick 锚定转弯、不可达重查询）是廉价而有效的稳健性手段，Bird 在加速时钟下的相对稳健即部分归因于日程式接口。
- **局限**：结构化文本观测排除了视觉感知误差与延迟（对端到端视觉智能体结论不直接适用）；依赖可保存状态/可重置环境，物理交互与不可逆场景需另建纠错检验机制；仅两轮改进、六游戏类型，指引按类型独立开发，未见环境的泛化与长轮次持续改进未验证；跨模型迁移存在游戏级回退（StartLux 27B 的 Tetris/Temple）。

**成本口径**：TORSI 两轮总开销 $24.39（教师 token 输入 11.22 M / 输出 0.049 M，Jev 按 $0.042/M 输入估算、输出免费，教师按 $2/M 输入、$10/M 输出），本地开源模型评测另耗 46.47 GPU-hours（NVIDIA L20Y 单卡、无张量/流水线并行）。

## 7. 与其他论文的联系

（基于相关论文清单中确有真实关联的条目）

- **paper:arxiv:2611.10787｜Trustworthy Recursive Self-Improvement with Statistical Guarantees（TRUST）**：关联点是"递归自改进的更新可靠性控制"。TORSI 用冻结候选 + validation 严格占优的采纳门来防止指引回归，本质上是一个启发式/单次比较的接受准则；TRUST 提供在线多重假设检验框架来控制自改进过程中的错误演化率并给出统计保证。二者可视为同一问题（自改进更新何时可信）在"游戏分数验证门"与"统计检验保证"两个严格度层级上的解法，TRUST 的方法可直接用于强化 TORSI 的验证门，使其对随机运行方差（本文仅三次运行均值）更稳健。
- **paper:arxiv:2611.11558｜InfraRSI: Harnessing Recursive Self-Improvement for Training Infrastructure**：关联点是"验证工作流门控的递归自改进"范式迁移。InfraRSI 用五阶段验证工作流把开放式指令转化为分布式 LLM 训练优化（最高加速 2.75 倍），TORSI 用"反馈→教师练习→学生练习→冻结验证"四阶段把开放式失败诊断转化为实时控制指引；两者共享"改进必须通过外部验证才被采纳"的核心设计，区别在于 TORSI 的验证信号是游戏进度分数、且改进对象是不动权重的提示层指引，InfraRSI 改进的是基础设施代码本身。
- **paper:arxiv:2611.12109｜SkillDuet: Co-Evolving Models and Skills through Response Feedback**：关联点是"快执行体 + 可复用技能/指引"的双层改进结构。SkillDuet 以响应反馈协同 LLM 参数更新与外部技能库演化，TORSI 则显式冻结学生权重、只演化指引，并把协同发生的位置放在离线（游戏间隙）而非在线。TORSI 的跨模型迁移结果（同一冻结指引令 StartLux 4B 均分 +12.83）恰好支持了 SkillDuet 式"技能与参数可分离演化"的前提；反过来，SkillDuet 代表了 TORSI 明确不做的另一半（权重侧改进）。
- **paper:arxiv:2610.32026｜RSI-Opt 与 paper:arxiv:2611.10463｜LongCapHarness**：这两篇与本文的关联较弱（前者是优化器训练智能体的递归自改进，后者是长上下文推理能力的免训练挂接，问题域与实时时钟无交集），仅共享"递归自改进/免后训练改进"这一宽泛标签，不构成实质性技术关联，故不展开。

总体而言，本文在"递归自改进"谱系中的独特定位是：**改进循环被实时时钟约束切割为两个时间尺度**——离线慢循环负责学习与验证，在线快循环只执行不学习；而 TRUST（统计保证）、InfraRSI（验证工作流）、SkillDuet（技能-参数协同）均未处理"被改进体必须在亚秒级持续行动"这一约束。
