## 1. 背景与动机

Agent 记忆系统当前存在两条主流路线，且各有结构性缺陷。其一是**预管理结构化记忆**：A-Mem 用 Zettelkasten 式记忆图做规则化链接，MemoryOS 以短/中/长期分层与 FIFO 聚合做页级固化，LightMem 走“感觉过滤—主题感知短期聚合—睡眠期长时更新”三段管线，Mem0 用 LLM 控制器做记忆抽取与剪枝。这类方法为检索效率提前压缩/组织历史，牺牲了细粒度细节。其二是**端到端 RL 优化记忆行为**（Memory-R1 的 ADD/UPDATE/DELETE/NOOP 策略学习、MemAgent 式多轮 RL），训练开销高，且奖励信号停留在结果层面。

第三条路线是**面向记忆系统的深度搜索**（GAM、MemSearcher）：不预压缩原始历史，推理时以 planning→searching→reflection 循环动态构造任务相关上下文，以计算换精度。但论文指出的核心痛点是：现有 deep search agent 将每条搜索轨迹视为孤立事件，不做跨轨迹经验沉淀，导致相似的低效规划/反思行为在不同查询上反复出现——冗余探索、检索质量退化、推理成本上升。更关键的是**粒度问题**：轨迹内部质量混杂，成功轨迹可能包含冗余甚至错误的中间步骤，失败轨迹也可能含有价值的局部行为，因此对整条轨迹做“好/坏”二分不可靠，必须下沉到步级诊断。论文同时批评既有经验学习方法多在轨迹/任务级操作，粒度不足以约束长搜索轨迹中的规划与反思动作；rubric 信号虽已被用于终局评估、奖励构造与 RL 对齐，但几乎未被用于多步轨迹的**中间过程质量诊断**。

R²-Mem 的定位由此明确：一个 RL-free、低成本的“过程级诊断 + 反射式经验复用”外挂框架，三点差异化学术主张为——经验粒度从轨迹级细化到步级（且按质量 good/bad 与功能 Planning/Reflection 双索引）；rubric 信号从结果评估迁移到过程诊断；失败经验与成功经验同权重入库（消融显示失败经验甚至更具修正价值）。

从音视频交叉视角看，该问题类在长视频多轮问答、会议音频归档检索、跨会话流式语音助手等长时程多模态记忆场景中同构存在：凡是“原始历史体量大到不能整体入上下文、又必须做多跳与时序推理”的媒体理解任务，都面临同样的检索规划与停止判据问题（迁移可行性见第 6 节）。

## 2. 方法总览

论文先把深度记忆搜索形式化为闭环：初始查询 q₁=Q，第 i 轮执行——**Planning**：f_plan(qᵢ, mᵢ) 将问题分解为子信息需求 {qᵢ¹…qᵢⁿ} 并生成工具感知计划 pᵢ∈{keyword, semantic, page}；**Searching**：f_search(pᵢ, M) 在记忆库 M 上执行检索得 {rᵢ¹…rᵢⁿ}，f_integrate(qᵢ, mᵢ, {rᵢʲ}) 聚合为临时记忆 mᵢ₊₁；**Reflection**：f_reflect(mᵢ₊₁, Q) 判断信息是否充分，充分则输出 mᵢ₊₁，否则生成精化查询 qᵢ₊₁ 进入下一轮。搜索轨迹 τ=(s₀,…,s_T)，sᵢ=(qᵢ, actionᵢ, mᵢ)。

R²-Mem 在此闭环外挂“离线经验构建 + 在线经验注入”两段：

- **离线（经验库构建）**：在少量历史上先跑标准记忆搜索收集完整轨迹（LoCoMo 用 10%，HotpotQA/NarrativeQA 用 20%）。Rubric-guided Evaluator（主实验为 GPT-4o）对每步的 Planning 与 Reflection 模块按多维度 rubric 打分并给出 reason 与 advice；self-Reflection Learner（即执行搜索的骨干模型）据此将步骤蒸馏为抽象经验，按质量标签（score>K_high 为 good，score<K_low 为 bad）与功能标签（P/R）双索引存入两个经验库。
- **在线（经验增强搜索）**：推理时对当前条件做高层 situation 抽象后与经验库做嵌入相似度检索（BGE-M3），Top-K 经验分别注入 f_plan(qᵢ, mᵢ, Eᵢᴾ)（辅助问题分解与工具选择）与 f_reflect(mᵢ₊₁, Q, Eᵢᴿ)（辅助充分性判断与下一请求生成）。

工程上值得强调的属性：全程无梯度更新、无参数改动，仅做提示级注入；离线构库为一次性开销（LoCoMo 上 Evaluator+Learner 合计约 0.53–0.61M token，见第 4 节），可跨后续查询摊销。

## 3. 关键设计

**3.1 步级—模块级 rubric 评分**。Evaluator 的 rubric 分两组共 8 维，每维 0–3 分：Planning 侧为 Info Needs Coverage、Info Needs Non-Redundancy、Tool–Info Alignment、Planning Efficiency；Reflection 侧为 Sufficiency Judgment Accuracy、Minimal Sufficiency Recognition、Follow-up Query Quality、Answer Completeness Awareness（即每个模块聚合分值域 0–12）。对每步每模块输出各维分数、聚合分 score_k、简短 reason 与面向未来的抽象 advice。这组维度把“检索规划质量”操作化为可判定的子指标（如 Non-Redundancy 直接对应论文动机中的“重复无效探索”），是整套方法可复现的锚点。

**3.2 阈值分桶与“中间带丢弃”**。只有 score>K_high 或 score<K_low 的极值步骤才触发经验蒸馏，介于两阈值之间的步骤被直接跳过。这一设计在超参分析中得到双向验证：过松的 (3,12) 会把低质步骤引入库中产生噪声，过紧的 (6,9) 则损失推理多样性且推高迭代数（1.61 次/题）与 token 开销（30.38M）；默认 (5,10) 近似最优。本质上这是用分位数式截断换取经验库的信号纯度。

**3.3 IF–THEN 经验蒸馏与实体抽象约束**。Learner 的 prompt 强制输出形如 “IF \<abstract situation\> THEN \<strategy\>” 的经验，并明确“不得从轨迹拷贝具体表面事实”——situation 必须抽象为查询类型或信息缺口（如“询问关系/归属持续时长且涉及多事件”），经验必须落到 info_need 构造与工具选择策略。论文附录给出的实例（对时长类问题应“以目标时间窗为中心构造单一 info_need，用 keyword+vector 定位相关日期”；对“问题要精确事实而 temp_memory 只有粗时间指代”应“置 enough=false 并以粗线索生成新请求”）显示经验库确实收敛到检索策略层而非事实层。这个抽象约束是经验可跨会话复用的关键——否则检索命中的只是表面相似的旧答案。

**3.4 非对称条件构造 + 双表示检索**。两个库的检索条件设计不同：Planning 库条件仅取当前查询 cᵢ=qᵢ（规划只依赖查询语境）；Reflection 库条件取 cᵢ=[Q+mᵢ]（充分性判断本质上依赖全局问题与累积记忆状态，而非当前查询）。检索时先用 LLM_σ 将条件抽象为高层 situation σᵢ，再对拼接表示 φ(cᵢ+σᵢ) 与库中 φ(cⱼ+σⱼ) 做 Top-K 余弦相似检索——具体 condition 保证相关性，抽象 situation 提供泛化，二者拼接是简单但有效的折中。

**3.5 经验与技能的边界（附录 F.1）**。论文明确区分：技能是可执行的完整程序性例程（分解策略、检索工作流、工具使用策略），而 R²-Mem 的经验是从单个历史搜索步、在评估器诊断下蒸馏出的轻量反射式建议，具有步级粒度、诊断来源、搜索状态依赖三属性，不可作为独立模块调用。这一区分使其区别于 SkillDuet 一类技能库演化路线（见第 7 节）。

**3.6 一个需要标定的监督口径细节**。Evaluator 的 prompt（附录 D.1）要求输入 REFERENCE_ANSWER——即离线 rubric 打分是在参考答案条件下进行的。因此所谓“过程级监督”实际上是**以结果标签为条件的步级诊断**：经验质量锚定在金标答案上。这解释了为何离线诊断可靠，也意味着在无标注生产环境中迁移时，诊断质量将退化为 Evaluator 自身能力（论文的 Self-Evo 变体部分回应了这一问题，见第 4 节）。

## 4. 实验结果

**设置**：LoCoMo（多跳/时序/开放域/单跳四类，10 个会话，经验收集默认用类别构成接近全集平均的 Conv-26，附录验证换用 Conv-41/47/49 结果趋势一致）、HotpotQA（MemAgent 长上下文设定，56K/224K/448K 三档，各 128 题，前 20% 即 25 题收集轨迹）、NarrativeQA（300 题，平均上下文约 87K token，60 题收集轨迹）；骨干 Qwen2.5-3B/7B/14B 与 Llama3.1-8B 作 Learner，GPT-4o 作 Evaluator，BGE-M3 做稠密检索，指标 F1/BLEU1，vLLM + A40 推理。LoCoMo 各会话类别分布不均（平均每会话 154.0 题中 single-hop 占 84.1、open-domain 仅 10.7，Conv-30 无 open-domain 题），Overall 指标实际受 single-hop 主导，读表时需注意。

**跨基准（Table 2，对 GAM 的 F1 提升）**：NarrativeQA 上 Qwen2.5-3B 20.19→23.33（+15.55%）、7B 28.56→31.52（+10.37%）；HotpotQA 上 3B 各上下文档 56K/224K/448K 分别 +12.34%/+7.57%/+6.70%，7B 为 +10.89%/+6.88%/+5.28%——增益随上下文长度与模型规模递减，符合“经验补偿固有能力不足”的解释。

## 5. 消融要点

消融在 LoCoMo / Qwen2.5-7B 上进行（Full 行 single-hop 59.03、token 28.93M、迭代 1.52，与主表一致）：

- **去 Evaluator 或去 Learner 均退化**。去 Learner（保留步级信号但不蒸馏、直接作检索上下文注入）单跳 F1 降至 56.36 且 token 升至 35.01M、迭代 1.88——未抽象成稳定可复用表示的原始信号会向搜索注入噪声，这从反面验证了 IF–THEN 抽象的必要性，也说明“经验 ≠ 检索增强的轨迹片段”。去 Evaluator（Learner 直接从整条轨迹总结）单跳降至 55.74。
- **只用低质经验优于只用高质经验**（单跳 59.00 vs 57.29，多跳 39.33 vs 37.36；Full 为 59.03/41.62）。失败案例提供更强的修正信号——与“失败案例库”直觉一致，也部分解释了为何 K_low 截断不可或缺。
- **规划/反思经验互补**：去 Planning 单跳 58.92，去 Reflection 58.07（Full 59.03），两者各自承担查询分解早期结构与累积状态评估反馈，缺一即退化。
- **阈值鲁棒性**：(K_low,K_high) 在 (3,12)–(6,9) 四档间 Overall F1 仅在 50.17–51.51 内波动，最优 (5,10)；极端档位表现为“松则噪声、紧则多样性不足且迭代/token 双升”。
- **检索数 k=1–5 与指数加权 exp=1–5**（Overall F1 波动 49.35–50.58，exp=3 最优且迭代、token 最低）均不敏感，方法不依赖精细调参。

## 6. 贡献与启示

**学术贡献**：其一，把经验学习的操作粒度从轨迹级推进到“步级 × 模块级 × 质量极性”的三重索引，并用混合质量轨迹的内在结构论证了其必要性；其二，将 rubric 信号从结果评估迁移到中间过程诊断，给出了一套可复用的 8 维检索规划/停止判据 rubric；其三，证明了免 RL、免参数更新的经验外挂可以同时改善精度与成本（LoCoMo 各骨干上 F1 +4.5%~+22.6%，token −3.9%~−14.9%，迭代 −5.2%~−20.2%），且自评估闭环与 GPT-4o 监督差距 ≤1.59 F1。

**对本领域的启示**：（1）过程级监督的价值集中在“早期决策误差沿轨迹累积”的多步系统上，其收益与骨干固有能力成反比（3B 增益约为 14B 的 5 倍），对外挂式增强小型化部署尤其友好；（2）失败经验的修正价值高于成功经验的模仿价值，经验库设计应显式保留 bad 通道；（3）离线一次性成本可摊销的模式为“训练不可行、纯推理增强”的场景提供了范式。

**音视频上下游关联（迁移分析，非论文内容）**：本文的文本管线与长时程音视频理解在问题结构上直接同构。上游看，deep search 的 keyword/semantic/page 三类检索工具可分别映射到视频场景中的 ASR 关键词检索、跨模态语义检索与镜头/片段级定位；LoCoMo 的 temporal reasoning 类别（本文增益最大项，7B 上 +50.4%）与视频时间定位问答同构，附录中“时长类问题应围绕目标时间窗构造单一 info_need + keyword+vector”这类蒸馏经验，几乎可以原文迁移为长视频时间定位的检索规划规则。下游看，跨会话语音助手/会议助手的长期记忆层正是 LoCoMo 场景的音频实例，经验库作为与 ASR/说话人日志上游解耦的检索规划层，可即插即用。成本侧，token −12.9%~−14.9%、迭代 −17%~−20% 的幅度对多路流式媒体问答的服务开销与时延有实际意义。迁移缺口同样明确：管线纯文本，BGE-M3 需替换为多模态嵌入；8 维 rubric 需为视觉证据重定义（如镜头覆盖、时序对齐、视觉充分性）；Evaluator 需具备多模态轨迹判读能力，而 Self-Evo 下小模型自评仅损 0.43–1.59 F1 的结论，对降低多模态评估成本是利好信号。**局限**（论文自述）：方法假设未来场景与历史轨迹分布相似，显著分布漂移下经验相关性下降；离线经验库质量受评估器与自反思质量制约，漂移鲁棒性留作未来工作。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326（FGSE，证伪门控自演化）**：两者解决同一核心问题——“什么才有资格写入 agent 记忆/经验库”。R²-Mem 用离线 rubric 阈值（K_low/K_high 截断 + 参考答案条件下的 GPT-4o 诊断）做准入过滤；FGSE 则把经验教训当作可证伪假设、经三类探针在线验证后入库。互补点明确：R²-Mem 的经验库一旦写入即长期复用，缺少对错误经验的后续剔除机制，FGSE 的证伪门控恰好可补上这一环，尤其在 Self-Evo（自评）设定下误判率上升时。
- **paper:arxiv:2611.12109（SkillDuet，模型-技能库协同演化）**：R²-Mem 附录 F.1 显式划界：技能是可调用执行的程序性例程，并与模型参数通过响应反馈协同更新；R²-Mem 的经验是不可执行的单步反射建议（步级粒度、诊断来源、搜索状态依赖），且完全非参数化。两者构成“外部化知识”谱系的两端——重程序复用 vs 轻行为引导，R²-Mem 的消融（去 Learner 后原始信号注入引入噪声）暗示中间形态（半结构化技能片段）未必更优。
- **paper:arxiv:2611.10787（TRUST，带统计保证的可信递归自改进）**：R²-Mem 的 Self-Evo 结论（自评与 GPT-4o 差距 0.43–1.59 F1）是纯经验性的，未对经验库的错误累积率给出任何保证；TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证。R²-Mem 的“低质经验更有价值”发现恰恰放大了风险——对失败步的误诊会以“错误修正建议”的形式被持久复用，TRUST 式统计检验是天然的加固方向。
- **paper:arxiv:2611.10463（LongCapHarness，长上下文能力挂接）**：两者同为免后训练的推理时增强，且都在长上下文任务上验证（LongCapHarness 于 HELMET/RULER，R²-Mem 于最长 448K token 的 HotpotQA 设定与约 87K token 的 NarrativeQA），但路线相反：前者挂接模型固有的长上下文推理能力，后者在论文 F.2 中明确声明“不依赖更大模型规模或更长上下文窗口”，通过在原始记忆上的迭代搜索替代长上下文持有。两条路线分别压低“读全文”与“压缩损失”两端的成本，可作为长上下文开销问题的互补解。
