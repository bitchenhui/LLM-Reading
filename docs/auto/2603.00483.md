# RAISE: Requirement-Adaptive Evolutionary Refinement for Training-Free Text-to-Image Alignment

> Liyao Jiang, Ruichen Chen, Chao Gao, Di Niu. *arXiv:2603.00483v1 (2026-02-28)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

当前 T2I 扩散模型的瓶颈已从真实感转向提示-图像对齐（prompt–image alignment）：复杂提示涉及多物体共现、精确计数、属性绑定、空间关系与图内文字，单次前向生成难以同时满足。既有解法分四类，各有结构性缺陷：

（1）统一多模态模型（UMM：Qwen-Image、BAGEL、GPT Image 1 等）以大规模多模态预训练换对齐，成本高、数据低效、难以覆盖任意长尾提示。（2）噪声级推理时缩放（Ma et al. 的初始噪声重采样、SANA-1.5 的 VILA-Judge 引导）本质是打分函数引导的随机搜索，无语义反馈回路，对齐改善有限。（3）提示级缩放（TIR 迭代改写、T2I-Copilot 的噪声+提示混合 agent 环）引入了 VLM 反馈，但 T2I-Copilot 每轮仅执行单一动作、依赖固定停止阈值，无法按提示难度分配算力；论文指出的关键失效模式是：此类方法在后续轮次改善微弱甚至为负，多轮精修并未真正累积收益。（4）反思微调类（Reflect-DiT 在 DiT 上加 context transformer 并联合微调；ReflectionFlow 构建百万级 GenRef 三元组后联合微调 DM 与 VLM）效果强但模型绑定、资源密集，易过拟合到采集的反思路径，难以迁移到新基座。

RAISE（摘要展开为 Requirement-Adaptive Self-Improving Evolution）的动机判断有两条：固定预算/固定阈值无法适配提示难度差异；串行单动作精修的搜索空间不足。其方案是把对齐问题重构为“需求工程 + 验证驱动的自适应缩放”：推理时以种群演化方式探索候选，用结构化需求清单做接地验证，仅对未满足项继续投入算力，需求完备即自动收敛。开篇动机案例 "McDonalds Church"（教堂主体 + 金拱门 logo + 人物 + 图内文字 signage 的复合提示）中，噪声采样、T2I-Copilot、ReflectionFlow 多轮后仍缺人物/标识/文字要素，RAISE 经 4 轮需求修正收敛。

对音视频技术的语境定位：T2I 对齐是 AIGC 视频管线中关键帧/分镜质量控制的上游环节，本文的“验证驱动推理时缩放”范式对文生视频的对齐与成本控制有直接可迁移性（见第 6 节）。

## 2. 方法总览

RAISE 是免训练、需求驱动、模型无关的推理时演化框架，由共享同一 VLM 骨干（Mistral-Small-3.2-24B-Instruct-2506）的三个协作智能体构成：

- **Analyzer（需求分析）**：综合用户提示、全局最优候选（提示+图+验证反馈）及上轮最优的补充上下文，输出结构化需求清单 R 及其已满足 R⁺/未满足 R⁻ 划分、一一对应的二元问题集 Q、是否继续的决策变量 d；
- **Rewriter（改写）**：双角色——生成改写器针对 R⁻ 重写 T2I 提示；编辑改写器产出 top/random/comp 三种编辑指令；
- **Verifier（验证）**：基于工具接地的结构化证据，对当轮最优候选逐条回答二元问题，输出（问题、Yes/No、证据解释）三元组与汇总反馈。

每轮循环：需求分析 → 以全局最优候选为父本施加 nᵢ=8 个突变（重采样/重写/编辑）→ 执行（无参考图走生成模型 G=FLUX.1-dev，带参考图走指令编辑模型 E=FLUX.1-Kontext-dev，均 28 步）→ 适应度选择（当轮最优与全局最优双轨存档）→ 仅对当轮最优做结构化验证 → 反馈驱动下一轮。

终止条件三选一：Analyzer 判定主要需求满足、Verifier 判定全部需求满足（d=True 仅当含次要项在内的所有需求通过）、或达 K_max=4；同时设 K_min=2 下限保证充分探索。最终输出按适应度全局最优的图像。动作调度按阶段切换：i ≤ K_min 用 4 重采样 + 4 重写做广域探索，i > K_min 用 5 重写 + 3 编辑做定向修正，构成显式的探索→利用切换。

工程栈全开源可复现：LangGraph 编排、Ollama 本地服务 VLM；适应度函数为 NVILA-Lite-2B-Verifier（2B 量级）；接地工具为 Grounded SAM 2 + Florence-2（字幕/检测）与 MiDaS（深度）。

## 3. 关键设计

### 3.1 需求驱动的自适应缩放

Analyzer 的输入输出（原文式 1）值得注意双上下文机制：除全局最优 c*ᵢ₋₁ 外，若上轮最优 c'ᵢ₋₁ ≠ 全局最优，则额外接收其提示与反馈，以维持需求集演化上下文不丢失。每个需求项被约束为“原子、唯一、可观察、可验证”的单一视觉事实（存在/计数/颜色/材质/动作/关系/风格/光照/环境/文字）。系统提示给出 14 维抽取规范：主体（优先名词、多主体逐项列出）、计数（单数=1、复数推断隐式计数、严格精确、防背景物体混入）、属性与动作、空间关系（具体介词与可度量关系）、背景环境、构图取景、色彩和谐（防颜色泄漏）、光照曝光、焦点景深、氛围、风格（默认 photorealistic）、图内文字（内容/字体/可读性）、歧义项、其他细节。冲突时原始提示优先级高于验证反馈与当前图像；未显式陈述的需求按常识推断——即“隐式需求”抽取，定性结果中给出的消歧示例是 "two wine glasses" 应理解为酒杯容器而非盛着酒的杯子。

停止判据的语义化是本文相对固定预算范式的核心增量：Analyzer 默认 continue，仅当剩余未满足项极少且全部为次要项（光照/氛围/景深/机位/构图）才允许 end，首轮或存在任何主要需求未满足时禁止 end。由此算力分配与提示语义复杂度对齐——实证上 GenEval 平均 18.6 样本、更难的 DrawBench 升至 21.2，GenEval 分域中 Colors/Attribute Binding 各 19.7、Position 18.6，高于 Counting 17.4 与 Two Object 17.7。

### 3.2 多动作突变与种群演化

三种突变的定位互补：

- **重采样**：候选 (ε~N(0,I), x_user, ∅)，保留原始提示仅变噪声，在不改语义的前提下探索布局、构图与物体排布的随机性；
- **提示重写**：(εⱼ, x_rewrite, ∅)，生成改写器以 (x_user, 上一代最优提示/图， R⁺, R⁻) 为条件；系统提示强制 adjusted_prompt 与 current_prompt 显著不同以避免重复生成同图，且要求联动调整物体子类/环境/光照等支持性文本而非仅改目标属性；
- **指令编辑**：编辑改写器先产出原子化 planned_edits 列表，再聚合出三种指令——top（最关键未满足项的原子指令，模板如 "remove X" / "add S at Loc" / "change attribute"）、random（任一未满足项，探索替代修正路径）、comp（全部未满足项合并为单遍编辑指令）。三种均以全局最优图为参考、重采初始噪声，由 Kontext 执行，在保留全局结构的同时做定点/复合修正。

调度逻辑：前 K_min 轮纯生成式突变（重采样+重写），既广域探索又保证后期编辑有可用的优质参考图；后期切入编辑主导。种群每轮均以全局最优为父本并跨轮精英存档，避免轮间退化。相比 T2I-Copilot 每轮单动作串行推进，这一并发多动作设计是搜索空间扩展的主要来源。

### 3.3 结构化工具接地验证

两级评价体系是效率关键：8 个候选全部只经廉价的 2B 适应度打分器（NVILA-Lite-2B-Verifier）做选择排序；昂贵的结构化验证仅施加于当轮最优单个候选。这解释了平均 VLM 调用仅 7.3 次（约每轮 3 次 agent 调用 × 平均约 2.3 轮），对比 ReflectionFlow 的 64 次。

接地证据结构为 G = (检测字幕, 区域集{(自然语言区域标签, xyxy 边界框, 区域均值深度 d∈[0,255])}, 图像尺寸)，验证器的证据用法分工明确：区域标签用于语义核验（物体存在/缺失、计数精确性、颜色材质尺寸状态、动作姿态、图内文字内容）；边界框用于空间推理（左右/上方/包含/接触、布局与尺度一致性、属性是否绑定到正确区域）；均值深度用于三维层叠推理（近物深度值应更小、前后景关系与物理一致性）。验证器被要求保守作答——不可视觉核验或歧义时答 No 并说明缺失；每个 Yes/No 须引用具体视觉线索。这一设计把 VLM 的自由感知判断约束为证据锚定的推理，抑制幻觉，即论文所称弥合 reasoning–perception gap。验证输出（逐条三元组 + 汇总建议）回传 Analyzer，驱动需求集本身跨轮演化（新增/细化需求项），形成需求-验证闭环。

### 3.4 工程实现与成本口径

全开源栈无专有 API 依赖。单轮成本 ≈ 8 次图像生成（各 28 步）+ 约 3 次 VLM agent 调用 + 工具推理。需注意论文的 "VLM 调用" 计数未把 Grounded SAM 2/Florence-2/MiDaS 的推理计入，真实算力开销高于 7.3 这一数字的表面观感，但工具均为小模型，总开销量级仍远低于基线；墙钟延迟未报告，串行轮次结构对交互式应用不友好。

## 6. 贡献与启示

**贡献**（论文主张 + 本笔记评估）：（1）问题重构——对齐被表述为需求驱动的自适应缩放过程，停止判据来自语义完备性而非预算，并在 T2I 上首次展示单调持续的多轮自改进曲线（基线均平台化或退化）；（2）并发多动作种群演化，同时覆盖生成空间与编辑空间，替代串行单动作循环；（3）工具接地验证将 VLM 判断锚定于检测框+深度证据，可解释、可定位，且作为两级评价的效率杠杆（廉价打分全种群、昂贵验证仅最优）。

**批判性评估**（笔记观点，非论文内容）：适应度依赖学习型打分器 NVILA-Lite-2B-Verifier，选择压力实际在优化该打分器；GenEval 采用独立检测器评测缓解了循环论证，但换基准时的 Goodhart 风险论文未讨论。编辑通道收益与 Kontext 的能力绑定，消融中编辑对 Overall 仅 +0.01——在缺乏成熟指令编辑模型的技术栈上该框架需重新设计。Analyzer 的隐式需求推断靠 14 维提示工程模板而非学习，需求抽取质量构成性能上界（DrawBench 0.885 未饱和亦佐证）。成本口径未计工具推理与生成算力，墙钟未报。

**音视频上下游关联**（笔记分析）：下游看，文生视频的关键帧/分镜对齐是同构问题——“需求清单 + 二元验证 + 接地证据”可映射为视频 QA：将 bbox/深度证据替换为时域工具（目标跟踪、动作识别、字幕与语音 ASR 校验）即可构造视频版验证器；“全种群廉价打分、仅最优昂贵验证”的两级经济结构，在视频单样本成本高出 2–3 个数量级的场景下价值更大，自适应早停直接转化为成本控制。上游看，RAISE 属编排层创新，收益随基座进步水涨船高（4 步 schnell + RAISE 亦达 0.93），原则上可包裹任意视频 DM。但需明确其纯单图设计无时序一致性机制，逐帧套用会破坏时间连贯，后续需把种群突改造为共享噪声/latent 的时序保持突变。对 AIGC 内容生产管线而言，验证三元组留痕使每项需求的满足与否可追溯，契合审校与合规场景。

## 7. 与其他论文的联系

清单中确有技术关联的条目及依据：

- **RFG（arXiv:2509.25604）**：同属免训练推理时自改进 + 扩散族生成模型。RFG 用检查点似然比引导扩散 LLM 的文本生成（免奖励模型，至多 +16.1%），RAISE 用需求验证引导 T2I；共同点是把自改进从训练期移到推理期且不更新参数，差异在引导信号来源——似然比 vs 语义验证闭环，后者更适配组合语义类目标。
- **Selective Critique / SAG（arXiv:2610.07335）**：核心同构点是“按需分配批评算力”——SAG 用免训练门控决定何时调用批评，RAISE 用需求满足状态决定是否开启下一精修轮；两者都把 agent 循环成本从固定预算改为任务状态驱动，RAISE 进一步给出“早停判据可由接地验证器客观化”的实现路径。
- **Cycle-of-Thought / Self-RefineVQA（arXiv:2610.32423）**：同样的免训练“生成-批判-精炼”迭代自纠正环（单 VLM），域为文档表格 VQA；与 RAISE 共享批判信号驱动的推理时自纠正模式，且均观察到弱基座获益最大（Self-RefineVQA 的小模型、RAISE 的 4 步 schnell 基座 +0.27）；差异是 RAISE 引入种群与多动作搜索而非单链自精炼。
- **SAGE-VQA（arXiv:2611.19933）**：同为免训练自进化 agent 框架，其 grounded evidence 核验与 RAISE 的工具接地验证直接同构——都把主观判断转为证据锚定核验以抑制幻觉；SAGE-VQA 另有跨任务分层经验记忆，而 RAISE 每提示独立演化、无经验复用，二者是互补的演化轴。
- **SIMIT（arXiv:2611.00053）**：同为测试时自我改进但机制相反——SIMIT 让 VLM 测试时自造训练数据改进模型自身（17 基准平均相对约 +7%），RAISE 不动模型、只演化输出；可视为 test-time self-improvement 的“改模型 vs 改搜索”两条路线。
- **Hippo（arXiv:2610.24453）/ CER（arXiv:2506.06698）**：同属免训练自改进家族，但走外部记忆/经验回放路线实现跨任务自我改进；RAISE 完全没有跨任务记忆，将 Hippo 式经验回放引入 RAISE 的需求模板库（把成功的需求抽取与修正路径沉淀复用）是自然的延伸方向。
