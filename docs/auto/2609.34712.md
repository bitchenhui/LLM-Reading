# RSI-Router: Evolving Subtask-Level LLM Routing and Skills for Cost-Efficient Agents

## 1. 背景与动机

论文要解决的是 LLM 智能体（agentic）部署中最实际的矛盾：长时序任务需要反复调用 LLM，全靠大模型虽然性能好但推理成本高；小模型便宜但在整任务层面能力不足。作者的核心洞察是：agentic 任务内部各阶段的能力需求是异质的——小模型虽然独立完成不了整个任务，但可以可靠地承担其中若干阶段。这决定了协作粒度的选择是问题的关键变量。

按粒度划分，现有 LLM routing 工作有两类，各有结构性缺陷：

- **任务级路由**（HybridLLM、FrugalGPT、RouteLLM、GraphRouter、Avengers-Pro 等）：整个请求分给一个模型。对 agentic 任务而言，这浪费了任务内部小模型可接管的阶段。论文实验里给出了一个很生动的现象学证据：任务级基线普遍出现 "routing collapse"——要么全给大模型要么全给小模型，随性能-成本偏好变化在小模型-only 与大模型-only 之间突变，没有任何中间权衡点。
- **步骤级路由**（MTRouter、Router-R1 等）：每步独立决策。一类从预采集轨迹学习（覆盖面受限），另一类用 RL 探索（逐步探索代价高、且从最终结果反馈做 step 级 credit assignment 困难）。

RSI-router 的动机建立在三个观察上：（1）LLM 对任务目标与流程有先验知识，可以把模型分配的探索组织在可复用的“子任务”而非孤立交互步上，从而给探索提供结构引导；（2）执行轨迹能揭示特定模型在哪里失败、成功、做冗余动作，是修订分配和生成执行指导的具体证据；（3）执行指导本身会改变模型的有效能力边界——小模型原本失败的子任务，配上合适的 skill 后可能就能胜任。因此**模型分配与执行技能是相互依赖的，必须联合演化而非孤立优化**。这一点是全文方法论上最关键的立论。

从音视频技术交叉的视角看，这类“分层降本 + 粒度选择”的问题结构在流媒体/编解码管线中高度同构：类似 per-frame 円滑地切换编码复杂度、或推理服务中按请求段动态调度不同量化档位的模型，RSI-router 提供的“子任务级粒度 + 技能注入”范式对多阶段音视频处理 pipeline（如转码-增强-审核链路）中的大小模型混部有直接的迁移参考价值。

## 2. 方法总览

RSI-router 由一个强 LLM 充当的 proposal agent（实验中用 Codex）驱动，对路由器种群做 G 轮递归自改进演化，每一轮包含四个阶段：

**（1）Subtask Mining（子任务挖掘）**。proposal agent 分析训练轨迹，先按执行目标把轨迹切成段，再跨轨迹定义并聚类出子任务集合 Z_t，每个子任务附带描述定义与识别规则；第二轮起可对已有子任务做保留/拆分/合并并更新定义。挖完后有一个**回放校验**步骤：重放采样轨迹，让小模型 S 在每步仅凭执行前上下文预测子任务标签，与标注标签比对，agent 据此修订含糊的定义或规则——这保证了子任务是“执行前可识别”的，是路由可部署性的前提。Z_t 在本轮内固定。

**（2）Routing Strategy Evolution（路由策略演化）**。在 Z_t 上并行生成 N 个多样化的路由策略，每个候选路由 r_i 指定各子任务由大模型 L 还是小模型 S 执行。生成时参考历史路由器的模型分配、子任务定义及其训练/验证聚合性能与成本。同时从共享技能库（历史路由器技能汇总）中**选择性继承**技能——按与当前子任务定义和模型分配的相关性筛选，子任务拆分/合并后重新评估适用性，每个子任务选零或多个技能，形成 K_i_{t-1}。每个候选在训练集与验证集上评估。

**（3）Model-Specific Skill Evolution（模型特定技能演化）**。对每个候选路由 r_i，将其训练轨迹与**同任务上的大模型-only（r_L）轨迹**对比，结合 per-task 反馈与成本，诊断出该模型特有的失败模式与冗余动作，据此精炼继承技能或生成新技能，更新 K_i_{t-1} → K_i_t，得到路由器 r̃_i，在子任务与模型分配不变的前提下重新评估。这个“以大模型轨迹为参照系做差分诊断”的设计是技能质量的来源。

**（4）Pareto-Optimal Router Selection**。以验证集性能与成本为双目标，联合比较历史路由器（Pareto 种群 P_t ∪ 被支配存档 F_t）与技能演化前后的候选，非支配者进 P_{t+1}，其余进 F_{t+1}。注意**被支配路由器不丢弃**，作为负例保留，继续为后续的分配提案与技能继承提供素材。初始化 P_0 = {r_L, r_S}，F_0 = ∅。G 轮后返回最终 Pareto 种群 P_G。

**推理时形态**与训练解耦：演化由大模型驱动，但线上路由器是小模型 S——每步执行前，S 基于路由上下文 c（用户查询 + 最近若干步交互历史 + 上一步子任务预测）和 Z 的定义/识别规则预测即将到来的子任务，选择该子任务分配的模型，并**只把匹配“预测子任务 + 选中模型”的技能文本**追加到被选模型输入中。整个系统的输出是一组带不同性能-成本权衡的路由器，构成 Pareto 前沿供部署方按预算选用。

数据协议上，训练/验证/测试三集固定且不相交；演化用训练+验证的聚合性能与成本，但轨迹与 per-task 反馈只来自训练集；验证指标用于 Pareto 种群更新；测试集不给任何演化反馈。

## 3. 关键设计

**子任务粒度作为探索的结构先验。** 这是相对 RL 步级路由最核心的差异化。步骤级路由的决策空间是 |steps| 级别的且彼此独立，最终结果的 credit assignment 很难下放；RSI-router 借 LLM 的任务先验把决策空间折叠为子任务级（如 SWE 修复 = 定位 → 实现 → 验证），同一子任务在轨迹内可复现、跨任务可复用，分配策略的泛化性和可解释性都更强。子任务识别回放校验机制则显式保证了“决策粒度可在执行前由小模型可靠判定”，否则整个路由是空中楼阁。

**分配与技能的联合演化环。** 论文方法论上最有价值的论断是二者的循环依赖：技能改变小模型的有效能力 → 影响最优分配 → 新分配产生新轨迹 → 揭示新失败模式 → 催生新技能。四阶段循环正是把这个环显式化：Stage 2 探索分配时可以带着继承的技能（评估“带技能的分配”），Stage 3 在分配固定的条件下优化技能，Stage 4 用同一把尺（验证性能/成本）统一比较，避免两个目标各自漂移。

**差分式技能蒸馏。** 技能不是从成功轨迹盲目总结，而是通过与 r_L 在同任务上的轨迹对齐比较产生——大模型轨迹相当于免费的“专家示范”，小模型执行段相对专家的偏差（失败模式 + 冗余动作）就是技能要修补的内容。技能条目本身带三元组语义：（执行指令，适用子任务，执行模型），保证注入时的精确匹配，不会把大模型技能误注给小模型。这与 RL 蒸馏或 SFT 式轨迹模仿相比，产出的指导更聚焦于“小模型特定短板”。

**Pareto 种群 + 被支配存档的演化记忆。** 双目标（性能、成本）天然没有单点最优，维护种群而非单一是正确形式；保留 F_t 作为负例是防回归和引导探索的手段——被支配路由器的分配方案信息（哪里被证明不行）对 proposal agent 生成新策略有负向参考价值。技能库跨路由器共享，且技能演化前后的候选都参与 Pareto 比较，等效于对“技能更新”这一步也做了选择压力控制。

**工程口径上需要注意的两点。** 一是成本模型：小模型价格不是官方 API 价，而是按 1:30 的固定参考比例从 DeepSeek-V4.1-Flash 官方价折算（输入 $0.30/M、输出 $1.20/M 折到 $0.01/M、$0.04/M），该比例由 H200 上 GPU 小时测量支撑——六个合成负载下总 GPU 小时比实测为 35.96，取整到 1:30；成本口径含全部测试时 LLM 调用与 token（含子任务路由与技能上下文本身的开销）。二是路由上下文极简：仅最近 3 步交互历史，消融证明加长无益，意味着路由决策的信息需求被子任务结构大幅压缩了——这对线上路由开销控制是实质性利好。

## 4. 实验结果

**设置**：五个 agentic 基准——ALFWorld（家居交互）、ScienceWorld（科学实验）、WebShop（网购，指标为 0–1 reward，其余为成功率 %）、SWE-bench Verified（代码仓修复）、Terminal-Bench 2.0（终端操作）。大模型 L = DeepSeek-V4.1-Flash，小模型 S = Qwen3.5-9B；执行 harness 基于 mini-SWE-agent；proposal agent 为 Codex。数据划分：ALFWorld/ScienceWorld/WebShop 各 64 任务/集，SWE-bench Verified 32/集，Terminal-Bench 2.0 为 32/32/25。演化 G=6 轮、每轮 N=4 候选。结果为测试任务 3 次评估重复的平均，学习型基线另加 3 个训练 seed 平均。

**主表关键行**（报告口径：各方法在达到大模型基线性能的策略中取最低推理成本，成本单位 USD）：

核心结论：

- **五个基准全部同时超大模型基线性能且降本**，降幅 8.1–82.2%，平均 51.7%（约为大模型成本 48.3%）。ALFWorld 从 90.62% 提到 98.44% 同时省 75.3%；Terminal-Bench 2.0 相对性能 +16.7%（40.00→46.67%）且成本 −18.0%。
- **对最强步级基线 MTRouter 的差距是全面性的**：性能 +14.5%/+15.6%/+13.0%/+17.4%/+87.5%，成本 −65.1%/−66.0%/−53.7%/+33.6%/+139.7%（后两项为成本变化，SWE-bench 上 RSI-router 更贵但性能也高 17.4 个点；TB 2.0 上贵 139.7% 但性能高 87.5%）。
- **任务级基线的 routing collapse 得到量化确认**：GraphRouter、RouteLLM、Avengers-Pro 在多数基准上与大模型-only 的性能/成本完全相同（即全路由到大模型），印证任务粒度无法利用任务内协作机会。
- **Pareto 前沿**：把各方法全部候选策略画到性能-成本平面上，RSI-router 占据前沿的显著部分；步级基线 Router-R1 与 MTRouter 相对大模型降本但在全部五个基准上性能低于大模型-only。
- **演化迭代收益**：在“保持大模型基线至少 95% 性能”的约束下追踪验证集最低成本，五个基准在首轮后均继续下降、四个基准出现多次下降。WebShop 的成本节省从首轮后 28.5% 逐步增至 65.0%、68.4%、72.5%；最终各基准节省为 ALFWorld 73.6%、ScienceWorld 78.2%、WebShop 72.5%、SWE-bench V 34.5%、TB 2.0 43.6%（性能保持率分别为 104.2%/97.6%/96.3%/95.6%/100.0%）。
- **技能库的复用性**：ScienceWorld 上最后一轮候选所选的 48 个不同技能来源中有 22 个源自更早轮次，说明演化在持续积累而非推倒重来。

案例研究（附录 D）展示了演化的具体形态，例如 SWE-bench 上首轮把“修复验证、回归测试、参考查阅”移给小模型并生成技能“重跑失败用例与邻近输入、使用仓库自带 runner”；TB 2.0 上演化中甚至出现分配的来回迁移（诊断/任务解读先移给小模型后又还给大模型），说明 Pareto 选择在真实地做双向修正。

## 5. 消融要点

三项消融分别检验路由上下文、路由决策方式、技能贡献：

**（a）路由上下文长度**：把交互历史从 3 步增至 4/8/16/全部，五个基准性能均不提升——短历史已足够支撑有效路由。这个结果从信息论上支持了子任务抽象的压缩作用：子任务标签本身就是历史的高度浓缩摘要。

**（b）直接难度判断 vs 步级随机**：给 Qwen3.5-9B 与 RSI-router 相同的路由上下文，让它直接判断下一步难度并选模型，结果在全部五个基准上平均性能低于步级随机基线。这是一个重要的否定性证据：**“判断难度”不是小模型能可靠完成的任务，而“识别子任务”是**——RSI-router 把路由决策重构为子任务识别（分类问题）而非难度估计（回归/比较问题），是其实际可行的关键。

**（c）掩蔽执行技能**（保持子任务定义与分配不变、仅移除技能）：ALFWorld/ScienceWorld/WebShop 性能分别下降 12.4/11.5/7.4 点；但在 SWE-bench Verified 与 TB 2.0 上反而性能提升 9.7/10.5 点，代价是成本增加（相对各自大模型-only 成本的 +33.7%/+33.9%）。结论 nuanced：技能并不一致提性能，而是**改变性能-成本权衡的形态**——在长程交互环境（ALFWorld/ScienceWorld/WebShop）中技能既省动作又提成功率，而在代码/终端任务上移除技能（即更多工作回到大模型）可以买到性能。这也提示部署时应按任务类型从 Pareto 种群中选择带或不带技能的变体。附带一个技能掩蔽下成本变化的对照：五个基准的成本缩减分别为 −66.1/+8.6/−1.3/−33.7/−33.9（% of 大模型成本）。

## 6. 贡献与启示

**贡献可归为三层**：（1）范式层——把递归自改进（RSI）从智能体/harness 演化推广到 LLM 路由本身，路由策略与执行技能通过四阶段闭环联合演化，以验证集重执行 + Pareto 选择控制回归；（2）机制层——子任务级路由粒度（借 LLM 先验给探索提供结构）+ 以大模型轨迹为参照的差分式模型特定技能蒸馏，二者互为因果、闭环互促；（3）实证层——五个基准上 8.1–82.2% 降本、平均 51.7%，且全部同时超越大模型-only 性能，对 9 个任务级/步级路由基线全面占优 Pareto 前沿。

**对领域研究者的启示**：

- 路由问题的正确抽象可能不是“难度估计”而是“能力-需求匹配”。消融证明小模型做不了难度回归判断但做得了子任务分类，这一重构思路对其他分层调度问题（工具选择、模型量化档选择）有普适性。
- 技能与分配必须联合优化。技能改变有效能力边界，任何先固定技能学路由、或先固定路由学技能的两段式方案都会次优。
- 被支配解的档案价值。Pareto 演化里保留负例作为后续提案素材，是多目标自改进系统中低成本防回归机制。
- 局限也应注意：结论基于 1:30 的小模型价格折算假设（实测 GPU 小时比 35.96，含 8 卡 vs 1 卡部署形态差异），若小模型实际服务成本更高，降本比例会相应缩水；proposal agent 依赖 Codex 级强模型，演化阶段的计算开销未在主文报告；测试集规模偏小（TB 2.0 仅 25 任务），虽然做了 3 次重复平均。
- 对音视频方向的迁移意义：多阶段音视频 pipeline（理解→检索→生成→质检）同样存在阶段异质的能力需求，子任务级路由 + 技能注入可以直接映射为“按 pipeline 阶段调度不同规模模型并为轻量模型配备领域技能（如镜头切分规则、编码参数模板）”，其回放校验机制（保证阶段划分可在线识别）也是工程落地的可借鉴模板。

## 7. 与其他论文的联系

（基于相关论文清单中确有真实关联的条目）

- **paper:arxiv:2611.12109（SkillDuet: Co-Evolving Models and Skills through Response Feedback）**：直接的方法论近亲。SkillDuet 用响应反馈协同 LLM 参数更新与外部技能库演化，实现技能级递归自改进；RSI-router 与之共享“技能与模型能力联合演化”的核心命题，但差异在于 RSI-router 演化的是路由分配而非模型参数，且技能是模型特定（model-specific）而非通用——论文第 1 节“技能改变小模型有效能力边界、故需联合优化”的立论与 SkillDuet 的 co-evolving 动机互为印证，二者可视为技能演化思想在“权重空间 vs 路由空间”两个正交维度的展开。

- **paper:arxiv:2611.10787（Trustworthy Recursive Self-Improvement with Statistical Guarantees, TRUST）**：RSI-router 的 Pareto-Optimal Router Selection 阶段（验证集重执行 + 非支配筛选，防性能回归）正是在缺乏统计保证的前提下做 RSI 的工程化风控手段；TRUST 用在线多重假设检验为递归自改进提供错误进化率的统计控制，可作为 RSI-router 演化循环中“候选是否真优于历史”这一判断的形式化升级方向。

- **paper:arxiv:2611.10463（LongCapHarness: Capability-Guided Auto-Harnessing for Long-Context Reasoning）**：同属“免后训练、通过外挂结构释放模型既有能力”的路线。LongCapHarness 以递归自改进挂接长上下文推理底层能力且成本低于基线 50%，与 RSI-router “平均降本 51.7% 同时超基线性能”的结果在成本量级上呼应；区别在于前者作用于 harness 层、后者作用于模型选择与技能层，二者在长时序 agentic 任务上天然可叠加。

- **paper:arxiv:2610.32026（RSI-Opt）与 paper:arxiv:2611.14949（RSI-PDEbench）**：同属 RSI（递归自我改进）方法族在不同任务域的应用——RSI-Opt 用元智能体跨训练运行演化优化器策略，RSI-PDE 面向 PDE 求解的递归自改进智能体；与 RSI-router 共享“强模型驱动的元演化 + 执行反馈闭环”骨架，共同佐证 RSI 范式从训练基础设施、科学计算到推理路由的可迁移性。RSI-router 的特殊性在于演化目标是一个双目标（性能/成本）种群而非单一策略，因此引入 Pareto 机制。

- **paper:arxiv:2610.32326（TGR-EvoDAG）**：同为“用演化方法自动构建多智能体/多阶段系统”的工作（DAG 式多智能体代码演化，腾讯在线 CTR +0.40%），与 RSI-router 的 Routing Strategy Evolution 阶段在“用 LLM 提案 + 执行评估驱动的结构搜索”上同构；TGR-EvoDAG 演化的是多智能体拓扑，RSI-router 演化的是子任务-模型分配表，后者决策空间更受控、且显式引入成本维度。
