## 1. 背景与动机

递归自我改进（RSI）指智能体通过反复自我修改与实证评估获得提升，改进范围可从单次任务解一直延伸到“生成后续改进的过程”本身。当目标从一次性答题转为持续性研究目标时，RSI 退化为一个 test-time scaling 问题：额外投入的推理与实验算力，应当换算成更多假说的并行探索、跨调研的发现共享，还是沉淀为可复用研究流程？论文的问题意识即在此——在不更新 backbone 权重的前提下，如何组织一个常设研究团队（leader agent + 若干 persistent researcher agents），使并行算力变成有效研究进展，同时把协调与评估成本计入账本。

作者把 scale-out 的三个障碍写得很清楚，三者也是全文机制的对应靶点：

1. 早期工件质量 ≠ 调研前景。弱实现可能裹着好想法，早期增益可能依赖脆弱假设；把所有研究员调向当前最高分方向会丢弃有用备选。
2. 经验是有条件的。在某实现或数值区间成立的结论，剥离条件传播会误导他人；广播式共享还会同质化探索（文中引用 Interaction Tax 一类结论）。
3. 单任务进展不会自动改进研究过程本身。已完成调研中可复用的诊断与实验流程，须从任务特异工件与不确定解释中剥离出来。

与既有工作的差异定位：AI co-scientist/Arbor 组织协作调查，CoMem 维护私有+集体记忆，PBT/fluid search 做并行资源再分配，AlphaEvolve 维护程序档案，Hyperagents/Dream-RSI 修改改进过程本身；本文切入三者耦合——证据解读 × 选择性信息交换 × 研究流程复用。与 Darwin Gödel Machine 一脉相承的立场是：权重冻结，改进落在可执行的外部流程（harness）上。

从音视频工程视角，这一选题并非外域叙事：GPU kernel 优化（KernelBench 代表的任务族）正是视频编解码、神经压缩、超分推理的核心工程活动（分块并行、访存合并、算子改写），“多路并行试验 + 按条件沉淀经验”直接对应转码农场中多机并行调参、按码率-分辨率工作点分条件复用结论的痛点，见第 6 节。

## 2. 方法总览

框架按 campaign（战役轮次）组织：一轮 campaign 是在任务 q_n 上的一次完整执行，使用固定的 K 人研究员团队与进入该轮时 harness 库的冻结快照 L_n。整体闭环为：L_n 经任务条件化 select 得到 harness 分配 H_n，团队开展研究并做条件化共享形成公共证据 E_n，探索后做最终验证，leader 进入独立 review 会话提炼可复用修订，经版本一致性检查发布进共享库得 L_{n+1}。两个时间尺度分工明确：campaign 内是“选 harness + 证据驱动指导 + 条件化共享”，campaign 间是“审查-发布”的流程资产演化。

形式化上，作者把 adaptive RSI scaling 写成 per-campaign 的约束优化：max_π E[U_n(x_out(π))] s.t. E[C_total(π)] ⪯ B_n。π 是组织策略，管辖组队、指导与共享；效用中无效输出取该任务的失败值；成本向量 C_total = C_campaign + C_review，覆盖研究员执行、leader 推理、实验与 campaign 后审查（token、模型计费、实验算力等可加项，wall time 单列）。作者明确声明该目标用于定义可比性而非运行时优化器——即论文做的是“给定资源档位下的组织方式对比”，不是在线求解该约束规划。

两个值得注意的架构选择：其一，特化通过 harness orientation 而非任务分解实现——每个研究员调研完整任务、保留本地状态，指导只调整调研焦点，不换人、不切分成不相连的子任务，天然避免流水线式分工的单点依赖与交接损耗，代价是冗余计算，被放进资源额度框架内权衡。其二，“冻结/可演化”资产边界划分得很工程化：可演化的是 harness 三元组内容；模型权重、工具权限、编排逻辑、leader 策略均不动——改进链可审计、库版本化可回滚，把 RSI 的风险面收缩到 harness 资产的语义审查上。

## 3. 关键设计

### 3.1 质量与前景分离下的 leader 协调

协调层核心是区分“工件当前质量”与“调研前景”。形式化定义 incumbent：在已保存、未撤回、通过了已有检查的候选集上取记录分数最大者；论文强调 incumbent 只记录“已执行检查下的观测质量”，既不保证未测条件上的正确性，也不标识最有前景方向。leader 的行动空间为 π_coord 下的四类动作（请求证据/修订计划/建议某研究员/等待反馈），并综合解释、未决测试与剩余资源给出继续/诊断/转向/整合建议。这是对“贪心跟随当前最优”这一朴素并行策略的显式反制，与 3.2 的问题路由限制互为表里。

### 3.2 条件化记忆共享：经验带出处、非对称限传播、接收方自证

经验表示是全文最具迁移价值的设计。一条共享经验为五元组 e = (d, f, c, u, F)：d 观测结果、f 提出解释、c 已测条件（输入、验收标准、评估设置）、u 剩余不确定、F 支撑记录引用；观测与解释分离，使接收方能自行判断证据是否支撑解释。每条经验带稳定标识符、原始来源 o(e)、当前证据来源与标签 κ ∈ {problem, positive}（未解失败/风险 vs 发送方认为已被支撑可用的发现）；标识符、标签、来源、引用是结构化元数据，五个语义字段是消息内容。文中例子具体：某修改降低了执行成本但对部分输入未通过必需检查，“漏掉一个处理步骤”是可能解释——同时共享两种结果、已测条件与该不确定性，支持诊断而不过早否定或采纳该修改。

传播控制的两条规则：

- **问题路由上限**：对带 problem 标签、leader 主动发起的同标识符消息，除原始来源外的接收者数 |R^problem \ {o(e)}| ≤ 1，即 leader 至多再拉一名有相关专长的研究员入场，后续更新只在该接收者与原始来源间流转。动机：未解失败的广播会把全队拖进同一个不确定诊断。
- **正向转播的改标条件**：problem→positive 重标要求新增引用（F_new \ F_prev ≠ ∅），引用须 campaign 内可解析且含来源自有证据。作者如实标注：这些检查只建立出处与增量证据，不为声称的解法背书；解释一致性与跨转述的语义同一性仍归 leader。

边界划得很细：上限只管 leader 主动路由，不管对公共记录/工件的独立检索；例行状态摘要剔除同伴报告以免变相广播未解问题；positive 按相关性选择性路由、不受附加接收者上限约束。接收方适配被定义为“规定行为而非强制门”：接收者对比本地条件后自行采纳/改造/拒绝/搁置，候选可导入新子目录本地测试，建议不覆盖既有工作、不打断实验。本地状态更新融合新观测、投递消息与显式检索的公共记录，不合并全队历史、不要求共识。纠正反馈在同一经验标识符下回报结果与已测条件，供 leader 限定该发现并修正后续共享，同时累积进 3.3 的 harness 修订——标识符在这里起到反馈闭环的键作用。

### 3.3 经验驱动的 harness 演化：跨 campaign 的流程资产化

harness 定义为三元组 h = (p, K, S)：p 研究 orientation（追哪些假设）、K 知识（发现、适用条件、失败边界）、S 技能（可重复流程：输入、步骤、验证标准、支撑脚本）。实现上以 profile 打包，经初始上下文与工作区资源注入。沿用 3.2 的例子：K 记录该修改失败的条件，S 加“全量评估前的定向检查”——可复用产物是“更会调研后续候选的流程”，而非该任务的答案。

审查与发布的机制细节：

- 独立 review 会话在探索与适用终验之后进行，输入为（任务、所用去重 harness 集、经检索访问的完成公共证据、终验反馈）；禁止新实验，空提案合法。修订由 π_review 提出并 Apply 到选中的 harness 上。审查问题清单：哪些 orientation 有效、哪些发现可跨任务泛化、哪些重复操作可固化成技能。提案须附理由、同 campaign 证据引用与资产增/改；须保留适用条件、不确定性与矛盾证据；指令层面排除完整任务答案与隐藏测试信息——作者自认这是语义要求而非形式化保证。
- 发布采用版本化替换：当且仅当提案可接纳且被审版本仍与库中当前版本一致时执行 Replace，否则库不变——一致性检查防陈旧审查覆盖新改动，失败/冲突提案不落库。特化只通过“修订既有身份 + 任务条件化选择”组合实现，更新算子不创建新身份，控制了库膨胀与检索退化。新团队不继承对过往 trace 或完整答案的无限制访问。
- 迁移评估与资源记账被诚实处理：harness 修订的收益须在后续 campaign、以声明的任务划分/库版本/反馈权限评估；源 campaign 终验反馈可入审查，但目标 held-out 结果不得进入用于解该目标的更新（防泄漏规则）。审查成本 C_review 有独立额度并计入总成本。
- 发布门槛刻意轻量：只检查引用、结构与所需资源，既不执行脚本也不要求在未来任务上证明改进。评注：这意味着库修订没有回归门，坏修订理论上可污染后续 campaign；缓解仅靠版本一致性（防覆盖）与旧 campaign 保留快照，工程落地时应补一道冒烟验证。

## 4. 实验结果

## 5. 消融要点

严格说论文未做机制级消融——RQ2 的三配置对比是最接近消融的证据，作者也自认不隔离单机制效应、不度量研究方向多样性，且只在所报告并行度（四 agent）上评估；scaling 曲线、等算力效率、跨 campaign harness 演化增益均未测量（论文自列的开放项）。可提取的消融性结论有三：

1. **共享不是免费午餐**：仅共享在 Luna 两对上延迟 +13.4%/+30.9%，与其在另五对上的改善并存——共享的价值以条件化机制（出处、条件、不确定性随行）为前提。这间接支持条件化表示设计的必要性，但论文未做“广播式 vs 条件化共享”的直接对照，该证据链是间接的。
2. **组合收益稳定且方向一致**（7/7 可比对最低延迟），提示收益来源在“信息复用 × 差异化分工”的耦合，而非任一单独因素。
3. **跨 campaign 演化（第 3.3 节核心机制）在主实验中未单独评估收益**：端到端数字与配置对比都不分离其贡献，读者不应把端到端增益归因于 harness 演化。

## 6. 贡献与启示

论文自述三条贡献： 把 adaptive RSI scaling 形式化为“在声明资源额度下组织常设调研与可复用流程”，区分工件质量与调研前景、区分额外算力的机会与团队组织效率； 条件化记忆共享 + 经验驱动 harness 演化两个机制，分别对应 campaign 内复用与 campaign 间流程变更； 对 CODEX-GOAL 的双骨干、三任务族端到端优势（+2.2pp Terminal Bench、KernelBench 平均加速 +32.2–36.8%）及配置对比支持其协调式扩展设计。

方法学上最值得吸收的三点：其一，经验的五元组与“观测-解释分离”是对多智能体实验系统中最常见的“结论漂移”问题的结构性防御；其二，问题路由 ≤1 附加接收者的非对称传播规则，用极小机制成本抑制未解失败的全队扩散与探索同质化；其三，版本一致性检查 + 不创建新身份的特化路径，给“流程资产库长期演化不退化”提供了可操作约束（库单调膨胀是多智能体记忆系统的通病）。

对音视频技术上下游的关联，可写实的有三条：

- **下游直接受益面**：KernelBench 型 kernel 工程与视频/神经编解码的算子优化（运动估计分块、tile 级并行、深度模型 depthwise conv/resize 算子）同构。AReaL 的 harness 分工（论文图示中即有 formulation / data movement / execution 三类 orientation）几乎可原样映射为 kernel 调优团队的 profile；把“访存合并假设在某工作点成立”这类发现以条件化经验传播，恰好对应编解码调优中按码率-分辨率-ISA 工作点分条件复用结论的实践——脱离工作点共享调优结论是编码器调优的经典坑，AReaL 的（d, f, c, u, F）表示与改标证据要求是该问题的现成模板。
- **中游流程面**：Terminal Bench 的 Terminus harness 优化示范了“研究系统优化的不是模型而是模型运行所依赖的工具环境”；音视频侧等价物是 ffmpeg/dav1d 滤镜链、转码 DAG、封装脚本的自动优化，这类工件同样以执行结果为质量依据，适配 RSI 的“可执行产物 + 实证验收”范式。
- **上游训练面**：RSI Bench 的 nanoGPT 数据策展与自蒸馏任务直接落在音视频多模态基础模型的数据管线与压缩上，harness 演化等价于把策展/蒸馏策略沉淀为可版本化流程资产跨任务复用。另注意其资源记账把 review 成本单列（C_total = C_campaign + C_review），对以 GPU 时计价的转码/训练农场做 agent 化改造时的 TCO 核算是有用的口径模板。

局限（论文自述 + 口径）：无重复运行不确定性、非等算力比较；Terminal Bench 搜索阶段协议不对称；harness 演化的迁移收益未量化；对隐藏测试信息的排除只是语义层要求；库发布无回归门。这些不推翻方向性结论，但限定了可引用强度。

## 7. 与其他论文的联系

- **paper:arxiv:2610.32026（RSI-Opt）**：机制上最近的同类。两者都让元层智能体跨运行演化“研究流程资产”——RSI-Opt 演化优化器策略与代码库并测跨模型迁移，对应本文 3.3 节的 harness 演化与迁移评估；差异在本文把演化限定为既有 harness 身份的修订且需版本一致性，RSI-Opt 走即插即用路线。本文未测的“跨 campaign 演化增益”恰是 RSI-Opt 已量化的部分，可互补阅读。
- **paper:arxiv:2611.12109（SkillDuet）**：同做“技能级 RSI”，但以响应反馈协同更新 LLM 参数与外部技能库；本文与 DGM 同路线、权重冻结、改进全落外部 harness。两者构成“参数内 vs 参数外”自改进的对照面，SkillDuet 的技能库演化相当于本文 S 分量加权的版本。
- **paper:arxiv:2611.10787（TRUST）**：直接补本文短板。本文的条件化共享、出处检查、隐藏测试排除均为语义层机制（作者自认非形式化保证）；TRUST 用在线多重假设检验控制 RSI 错误演化率并给统计保证，原则上可套在本文的 review 与 problem→positive 改标环节，把“改标需新增引用”升级为带错误率控制的接受规则。
- **paper:arxiv:2611.11558（InfraRSI）**：任务邻接。InfraRSI 把 RSI 用于分布式训练基础设施优化（最高 2.75× 加速），与本文 KernelBench 的 GPU kernel 工程同属系统性能类 RSI；其五阶段验证工作流可视为本文 final verification 环节的一种领域特化。
- **paper:arxiv:2611.10463（LongCapHarness）**：共享“harness 中心”改进观——不做后训练、以递归自改进挂接模型长上下文能力（HELMET/RULER 超基线且成本低于基线 50%）。与本文一致表明改进可定位在模型外部的挂具/流程层；差异是 LongCapHarness 挂接既有能力，本文演化研究员自身的调研流程。
- **paper:arxiv:2610.32326（TGR-EvoDAG）**：同为多智能体代码演化 + 验证闭环，但面向线上生产管线（腾讯生成式推荐，在线 CTR 相对 +0.40%），有真实在线指标；可作为本文“条件化共享 + 特化角色”设计在工业生产约束下的参照——线上环境更接近本文强调的“经验条件性”极端情形。
- **paper:arxiv:2611.07319（WeightLoop）**：反向对照。WeightLoop 用有界参数编辑程序在实验反馈下直接改写已部署权重；本文明确定位改进于权重之外。两者共同框定 RSI 改进位点谱系：权重内编辑 vs 外部流程演化。
- **paper:arxiv:2611.14949（RSI-PDEbench）**：范式级弱关联——其为 RSI 提供领域基准与智能体框架（1001 案例、42 方程模板），本文提供 RSI 的扩展组织层；理论上 AReaL 的 leader-研究员组织可包裹其智能体作为研究员实现，但两文无直接实验交集，仅作谱系参考。
