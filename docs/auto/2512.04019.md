# Ultra-lightweight Neural Video Representation Compression

> Ho Man Kwan, Tianhao Peng, Ge Gao, Fan Zhang, Mike Nilsson, Andrew Gower, David Bull. *arXiv:2512.04019v1 (2025-12-03)*

## 1. 背景与动机

INR 视频编码是 autoencoder 之外的第二条神经编码路线：对单个视频实例从零过拟合一个坐标到像素（或 patch）的映射，量化后的网络参数本身即码流。实例级建模天然规避了“大规模离线训练—测试分布失配”问题，且解码端只需前向推理，解码复杂度可大幅低于通用大模型。该方向的 SOTA 是 NVRC：首个对 INR 本身做完全端到端压缩的框架，PSNR 上同时超过 VVC VTM（Random Access）与 autoencoder 系神经编码器。

本文切入的是另一条刚出现的轴线——**超低复杂度**。COOL-CHIC Video、C3 等工作已证明 INR 在 <10kMACs/pixel 的算力预算下仍能保持与基准编解码器相当的效率，开辟了 ultra-lightweight 神经视频编码方向。但作者识别出该 regime 下两个未被解决的问题：

1. **低算力下的质量天花板**：现有轻量 INR 多走 COOL-CHIC 式 pixel-wise 路线，合成变换集中在输出分辨率执行；论文论证在低复杂度下引入多尺度、更高分辨率的 feature grid 是提质的关键杠杆。
2. **熵编码速度瓶颈**：现有 INR 编解码器普遍沿用 autoregressive 熵模型做逐格点串行解码，步数等于 latent 格点总数，实测解码速度慢，与“轻量”目标自相矛盾——算得快但解不动。

据此，NVRC-Lite 对 NVRC 做面向超轻量 regime 的原则性重构：多尺度高分辨率 feature grid 表征 + octree 上下文熵模型，目标是在 <10kMACs/pixel 档位同时拿下压缩效率与实际编解码速度。

## 2. 方法总览

框架完整继承 NVRC 的**分层参数编码**结构：θ 为 INR 参数（视频表征本体），ϕ 为熵模型与量化参数，ψ 为编码 ϕ 的轻量参数集合。编码过程即求解率失真联合优化：

argmin_{θ,ϕ,ψ} L = R + λD，其中 D 取 MSE，λ 为单旋钮控制码率点。

码率损失由两级熵模型估计：R = −Σ_n log₂(p_ϕ̂(θ̂[n])) − Σ_n log₂(p_ψ̂(ϕ̂[n]))（θ̂、ϕ̂ 为量化后参数），再除以 T×H×W 折算 bpp。最高层 ψ 的压缩沿用 NVRC 原文，此处不展开。

在此骨架上有两处核心改动：

- **表征侧（II-A 节）**：以 HiNeRV 为骨干，向不同分辨率 stage 注入多尺度 feature grid 输入；同时削减 block 数与通道数、将 3D 卷积 stem 分解为空间 2D 卷积与时间 1D 卷积之和。全码率点恒定 7kMACs/pixel，对比原版 HiNeRV 的至少 170kMACs/pixel。
- **熵编码侧（II-B 节）**：对高维 feature grid 张量（最大 96×540×960×1，时间×高×宽×通道）提出 octree 熵模型——对时空三维做 2×2×2 八叉树划分，每步编码子块中 2 个值，共 4 步完成，条件分布建模为条件高斯。权重矩阵沿用 NVRC 的 per-axis 编码，patch index 单独解码；另引入块级量化步长与块级辅助条件 latent。

解码数据流：从码流解出 patch index 与各层参数，feature grid 经 octree 模型解码后逐 stage 送入 HiNeRV block，头部输出重建帧。

## 3. 关键设计

### 3.1 多尺度表征：参数预算约束下的计算分配

设计的出发点是对两类 INR 计算实现方式的分析。COOL-CHIC 系的 latent 虽以多分辨率格式存储，但合成变换的计算**全部在输出分辨率**执行；NeRV 系则在多个分辨率上执行变换。论文给出一个简洁的代价推导：对 N 个 stage、通道数 C/2^(n−1)、分辨率 H/2^(N−n−1)×W/2^(N−n−1) 的多分辨率结构，第 n 级线性层（固定 kernel 卷积同理）的算力代价 ∝ (H/2^(N−n−1))·(W/2^(N−n−1))·(C/2^(n−1))² ∝ H·W·C²——即**各 stage 算力恒定**，与所处分辨率无关。

由此形成参数量与计算量的权衡：多分辨率计算让相邻像素有效共享特征，同等算力预算下重建质量更好；但把等量计算放到低分辨率需要更多参数（(C/2^(n−1))² 随 stage 递增）。在参数量不受限的表征学习场景，多分辨率是优选；而在**压缩场景（参数本身要编码传输、预算受限）**，把参数预算花在高分辨率计算上性价比更高——这正是现有低复杂度编码器少用多尺度特征的原因。

论文的关键洞察是：NVRC 这类端到端优化框架能高效压缩参数、压低“多参数”的比特代价，从而使多尺度设计在低复杂度 regime 重新可行。具体做法：

- 向 HiNeRV 的**各分辨率 stage** 都输入 feature grid（注意原 HiNeRV 的多分辨率 grid 只接入第一个 stage）。原模型在高码率下 feature upscaling 容量不足，此改动收益显著，实质上构成 NeRV 风格与 COOL-CHIC 风格的混合架构——现有 NeRV 系模型通常靠“更大模型”支撑更高质量点，该设计让单一紧凑模型也能覆盖高码率。
- 轻量化三板斧：减 HiNeRV block 数、减通道数、3D conv stem 换成空间 2D + 时间 1D 卷积相加。

### 3.2 Octree 熵模型：高维 feature grid 的少步上下文编码

autoregressive 熵模型对 3D latent z∈R^{T_grid×H_grid×W_grid} 逐点估计 p(z_{t,h,w}|z_{<t,h,w}, z_{t,<h,w}, z_{t,h,<w})，产生 T_grid×H_grid×W_grid 个串行编码步——这是 INR 解码慢的根源。图像/视频压缩界已有 checkerboard、quadtree 等少步划分方案，本文将其推广到 3D，得到 octree 结构：

- **划分与步进**：对张量时空维做 2×2×2 子块划分，每个编码步处理各子块中的一个值子集；熵模型将 p(z_{t,h,w}|m_k⊗z) 建模为条件高斯，mask m_k 仅依赖编码步 k，先前步已解码的格点作为上下文。
- **显存工程问题与折中**：多步熵模型需将整张 4D grid 张量一次性驻留 GPU 联合优化。AR 模型可用 masked convolution 缓解显存，但该机制与 octree 方案不兼容；若每步编 1 值则需 8 个串行步，显存与运行时代价都不可接受。折中方案是**每个 2×2×2 子块每步编 2 个值，总步数降为 4**；在本文使用的最大 96×540×960×1 规模下仍可放入 GPU 高效编码。
- **配套设计**：跨通道交织编码顺序（借鉴 spatial prior 类方案）；块级量化步长优化；块级辅助条件 latent 端到端学习并馈入熵模型以条件化局部分布（类比 hyperprior），两者均沿用 NVRC 的块划分方案。

工程含义明确：熵编码从数万步串行过程变为 4 步、可大批量并行的过程，这直接决定了 2.5× 解码加速的达成。

## 4. 实验结果

**设置**：UVG 与 HEVC Class B 的 1080p 序列，每序列 96 帧，YUV4:2:0 经 BT.601 用 FFmpeg 转 RGB 4:4:4，协议沿用 NVRC。基准为 x265（medium 与 veryslow）及 C3（官方开源默认配置，训练缩短为 30k 步——按 C3 原文结论这与完整训练性能相当；adaptive 模式因代码未提供且需对每个 patch 扫 9 个超参数、代价过高而省略）。刻意排除 HiNeRV 与 NVRC 以聚焦低复杂度对比。训练沿用 NVRC 流程，两阶段 1440/120 epochs，batch size 4，MSE 失真。复杂度在单卡 RTX4090 上以 1080p 帧测算，模型压缩 MACs 与编解码时间按含量化与熵编码步骤计。

**BD-rate（各列基准为锚点）**：

| 数据集 | 指标 | x265 (medium) | x265 (veryslow) | C3 |
|---|---|---|---|---|
| UVG | PSNR | −5.27% | +17.02% | −21.03% |
| UVG | MS-SSIM | +3.35% | +20.18% | −23.06% |
| HEVC-B | PSNR | +28.34% | +56.74% | −16.05% |
| HEVC-B | MS-SSIM | +16.36% | +42.00% | −19.40% |

对 C3 的两数据集平均节省为 18.54%（PSNR）/ 21.23%（MS-SSIM），UVG 上最高 21.03%/23.06%。对 x265-medium 在 UVG PSNR 上有最高 5.27% 增益，但 HEVC-B 上仍落后 28.34%（PSNR）——轻量档位与 veryslow 的差距（56.74%）则明确其定位不与 SOTA 比拼。主观对比中，UVG 示例 C3 为 34.23 dB @ 0.1088 bpp，本文 36.43 dB @ 0.0884 bpp；HEVC-B 示例 C3 为 31.62 dB @ 0.0720 bpp，本文 33.12 dB @ 0.0552 bpp，本文纹理更细、伪影更少。

**复杂度对比（RTX4090，1080p）**：

| 模型 | kMACs/pixel | 编码 FPS | 解码 FPS |
|---|---|---|---|
| C3 | 4.4 | 0.0007 | 38.09（实际熵编码：n/a） |
| NVRC-Lite | 7.8 | 0.0059 | 97.28（含熵编码 4.86） |

MACs 略高于 C3（7.8 vs 4.4，仍 <10k），但编码加速 8.4×（0.0059/0.0007）、解码加速 2.5×（97.28/38.09）。需注意口径：C3 的解码实现不执行真实熵编码，NVRC-Lite 的熵编码器本身未优化——即 2.5× 是在 C3“免熵编码”的有利口径下取得；NVRC-Lite 挂上真实（未优化）熵编码后为 4.86 FPS，说明优化空间仍大，也说明 C3 的标称速度目前并不反映可部署的完整解码代价。

## 5. 消融要点

在 UVG 的 Beauty/Jockey/ReadySetGo 三个序列上做 BD-rate（PSNR/MS-SSIM，以完整 NVRC-Lite 为锚）：

| 变体 | BD-rate |
|---|---|
| Baseline（完整 NVRC-Lite） | 0.0% / 0.0% |
| w/ Autoregressive（熵模型换回 AR） | +9.78% / +13.92% |
| w/ Single scale（单尺度 grid，同 NVRC 用法） | −6.27% / −17.68% |

- **Octree vs AR**：AR 变体比 baseline 差 9.78%/13.92%，即 octree 在压缩效率上反超 AR（通常 AR 上下文更强，此处少步 + 条件高斯 + 辅助 latent 的组合并未损失性能）；同时 octree 在未优化实现下已把熵编码时间缩短约 4×。速率与效率双赢，是熵模型选择的有力证据。
- **单尺度变体**：表格显示其在自身覆盖区间内 BD-rate 反而略优（−6.27%/−17.68%），但正文明确指出其质量覆盖范围只有 baseline 的约一半，且文字层面称“BD-rate 增加”。两种口径的张力可以这样自洽理解：单尺度在窄质量区间内可比甚至略优，但单模型无法覆盖完整质量跨度（高码率需更大模型支撑）；多尺度高分辨率 grid 的核心价值在于**单模型宽质量范围覆盖**，而非窄区间内的 BD-rate。读表时须带上这一前提。

## 6. 贡献与启示

**贡献**：(1) 论证并验证多尺度高分辨率 feature grid 是低复杂度 INR 提质的关键，形成 NeRV/COOL-CHIC 混合架构，全码率恒定 7kMACs/pixel（原 HiNeRV ≥170k）；(2) 首个面向高维视频 feature grid 的 octree 熵模型——4 步、条件高斯、通道交织、块级量化与条件 latent，正面解决 INR 熵编码速度瓶颈；(3) 在 <10kMACs/pixel 档位同时取得对最强轻量对手 C3 的 BD-rate 增益与 8.4×/2.5× 编解码加速。

**启示**：

- **熵编码而非 MACs 才是轻量 INR 实用化的第一瓶颈**。AR 熵模型即使算力极低也会拖垮实际解码；少步空间划分（checkerboard/quadtree/octree）迁移到 INR 的 feature grid 是必经之路。
- 端到端参数压缩改变了“参数量 vs 计算量”的传统权衡：当参数比特代价被 NVRC 式分层编码压低后，“多参数、多尺度”在低复杂度下重新划算——这一逻辑对同类 INR 编码器设计具有一般性。
- 部署画像：解码 97.28 FPS（不含熵编码）已超实时，含未优化熵编码 4.86 FPS，优化后逼近实时可期；编码端 0.0059 FPS（96 帧序列折算为数小时级）仍是 per-instance 过拟合的固有代价，适用场景锁定在离线编码、一次编码多次解码的分发链路。
- 诚实的边界：HEVC-B 上对 x265-medium 仍差 28.34%（PSNR），对 veryslow 差 56.74%；作者自陈未来方向为进一步提升压缩性能与低延迟编码场景。

## 7. 与其他论文的联系

- **NVRC（arXiv:2409.07414）**：直接前身与完整基座。本文自述“extend NVRC toward lightweight representations”，分层参数编码（θ/ϕ/ψ）、端到端 RD 优化流程、块划分与辅助条件 latent、训练协议（两阶段 epochs、色彩空间转换）均取自 NVRC；消融中的“w/ Autoregressive”“w/ Single scale”两个变体也分别对应 NVRC 的熵模型与 grid 用法。
- **NVRC++（arXiv:2606.28163）**：同系后续，同样采用“轻量 HiNeRV 骨干 + 多个高分辨率 feature grid”的思路，但把复杂度与质量解耦为 7k–360k MACs/pixel 四档、单模型覆盖全码率区间。NVRC-Lite 可视为该设计哲学在 ultra-lightweight 单点上的先行探索，NVRC++ 将其推广为跨复杂度-质量标尺的可伸缩方案。
- **S-NVRC（arXiv:2609.04273）**：同框架家族，将码率与解码复杂度做成单一嵌入码流上的细粒度可伸缩维度。与 NVRC-Lite 形成互补：后者锚定固定低复杂度工作点（7.8kMACs/pixel），前者把复杂度变成码流内可连续选择的轴。
- **GIViC（arXiv:2503.19604）**：本文在相关工作部分将其作为 autoencoder 路线的 3D 扩展代表引用（文献[17]），且同出 Bristol 团队。二者分别占据质量-复杂度平面的两端——GIViC 追求首个 RA 配置下 BD-rate 超 VVC VTM 的高保真，NVRC-Lite 追求 <10kMACs 的极低复杂度——共同体现该团队 INR 编码谱系的全域布局。
