# ChartEvo: Self-Evolving Agent Harnesses for Long-Tail Chart Reasoning

## 1. 背景与动机

CQA（图表问答）研究中聚合指标掩盖了类型间的巨大性能鸿沟。论文给出锚点数据：在 ChartBench NQA 任务上，Qwen3.7-Plus 在 26 种图表类型上平均准确率 80.0%，其中 17 种类型超过 90%（平均 96.9%），其余 9 种平均仅 48.0%。这批持续表现不佳的类型（ChartBench 上的 Area、3D 条形/堆叠、Ring、Sector、Radar 系列、Stock；ChartX 上的 Radar、3D-Bar、Rose、Bubble、Multi-axes、Treemap 等）被定义为**长尾图表**——视觉编码结构各异（3D 透视、径向几何、离散点计数、面积编码）、推理需求多样，构成异质的能力缺口集合。

补齐长尾有两条路线，各有硬伤：
- **参数路线**：把缺失能力编码进模型权重。对局部化、异质、持续新增的能力缺口，参数更新既不模块化也不可扩展，且冻结基座后不可复用。
- **工具路线**：ChartAgent 类工具增强智能体引入专用视觉操作，但依赖人工预定义工具与使用策略，能力边界受限于人工工程；对异质且持续演化的失败模式，逐个失败模式手工扩展不可规模化。

此外存在第二个动机：**ReAct 式执行开销**。图表推理中，全局推理只需决定“测什么、按什么流程测”，一旦目标与流程确定，剩余计算多为依赖关系稳定的局部结构化视觉操作（定位→定标→测量→计算）。把这些中间步骤逐个路由回 MLLM 再决策，引入不必要的模型-工具交互开销。ChartEvo 因此同时攻击两个问题：能力获取靠 harness 级递归自我改进（RSI），执行开销靠持久化本地工具链（SELT）。

## 2. 方法总览

ChartEvo 将智能体实例化为 **冻结基座 MLLM + 可演化 harness**。harness 含三类资产：
- **Skills**：元数据标注的文本知识，规定适用条件、推理指引、能力选择与使用知识、SELT 路由信息——编码“怎么推理”；
- **Tools**：带显式输入/输出接口的可执行视觉与数值操作——扩展“能执行什么”；
- **SELT**（Self-Evolving Local Toolchains）：经检验的 Tool 调用组合及其执行依赖的持久化结构——组织“能力如何被组合与执行”。

**RSI 外循环**：演化步 t，用当前 harness Ht 求解任务，产出预测与执行轨迹 τt；agentic proposer（GPT-5.6-Sol）联合考察最终答案、任务级评估反馈与执行轨迹（可识别“答案尚可但轨迹不可靠”的情形），提出对 Skills/Tools/SELT 的**协同更新**（单步可跨多类组件）；候选更新通过在更新后 harness 下**重新执行任务**验证，同时检验任务结果与轨迹是否符合意图，通过则持久化为 Ht+1，否则保留 Ht。演化期使用 ground-truth 答案做评估与验证，但不提供 ground-truth 解题轨迹。

**演化数据组织**：长尾类型筛选口径——对每类型随机抽 100 道训练题测 Qwen3.7-Plus，基线准确率低于 85% 者入选，得到 ChartBench 9 类、ChartX 8 类。每类型 100 道训练题切成 10 簇×10 题，按簇顺序推进；簇内可多轮“分析-更新-重执行”，多数失败被解决后进入下一簇。已验证的更新跨簇累积复用。

**初始 harness**：4 个 Skill（chart-evidence-validation、bar-value、line-value、pie-percentage）+ 25 个通用 Tool（OCR/文本/颜色/分割 7 个、轴/坐标/确定性计算 5 个、饼图面积测量 3 个、条形/箱线 4 个、线/面积/散点 3 个、径向几何 3 个），无预定义 SELT。两个基准从同一初始 harness 出发独立演化。

**推理协议**：harness 冻结。Agent 基于问题与执行上下文选用 SELT 或动态组合 Tool；带显式数值标注的图表直接视觉作答；两类回退——Agent 判定 harness 辅助推理无法推进时主动切换直接视觉作答，或触发 15 步动作预算上限。主 Agent 为 Qwen3.7-Plus。

## 3. 关键设计

**Skill/Tool 演化的判定逻辑**。proposer 先归因失败：若现有 Tool 已能提供所需信息但选择、调用或使用方式不支持正确推理，演化主要针对 Skills；若 Tool 集无法提供所需结构化证据，或某 Tool 行为错误、覆盖不足、输出接口不当，则引入/修订 Tools。修订与新增的判据是语义：组件预期语义仍成立则修订，所需推理模式或可执行能力在语义上区别于现有者则新增。Skill 与 Tool 更新可在同一步耦合，使新增可执行能力即刻纳入对应的使用知识。候选 Tools 额外检查可执行行为。失败识别的具体口径：相对误差超 5% 判错（GT 为零单独处理），3%–5% 误差的预测被标记复检（数值正确可能来自不可靠轨迹）；同时检查回退行为与现有 Tool 链的任务覆盖。失败按动作序列、Tool 调用与返回观测聚类，定位三类根因：调用/参数绑定/证据利用不当、缺 Tool、多步执行顺序与信息依赖低效。

**SELT 的功能契约机制**。每个 SELT 是有界可执行变换：显式输入、输出、执行顺序与内部 Tool 依赖；Agent 只负责任务目标的解析与外部参数绑定，内部步骤间的参数解析与中间结果传递由 runtime 承担，无需逐步模型决策——这是对 ReAct 逐步交互的结构性替代。SELT 使用由三方协同中介：Skills 持有路由知识，runtime 按当前问题/执行阶段/累积观测**渐进披露**上下文相关的候选 SELT，Agent 据问题语义与证据选定并绑定参数，runtime 执行时强制调用约束、Tool 版本与执行检查。无可适用 SELT 时回退到动态组合，其成功执行可驱动后续固化为新 SELT——形成“动态组合→验证→持久化”的执行结构演化通道。

**分层检索与渐进披露**（harness 增长后的上下文管理）：
- 两阶段 Skill 检索：先用 frontmatter 元数据（图表类型、问题特征、适用条件）过滤排序，再加载正文；每题至多 3 个 Skill（≤1 个通用 + ≤2 个图表特定），Skill 正文合并预算 1600 token，相似度超 0.80 的近重复被抑制。
- Skill 内容按执行状态分支披露：初始只暴露路由指引，Tool 结果为 accepted/rejected/argument_error 时才触发对应分支（错误处理、恢复指引），未观测条件对应的指令保持隐藏。
- 两级 Tool 目录：概览级列出全部注册 Tool 名称与简述，详情级按需暴露完整接口（输入 schema、输出字段、调用约束、用例）；初始上下文至多 6 个详细接口，上下文刷新后降为 4 个；候选选择综合已检索 Skill、相关 SELT 引用的 Tool、问题语义、近期调用 Tool 与此前失败关联 Tool 等信号。
- SELT 候选先从选中 Skill 收集引用，再按图表元数据、问题语义、参数可绑定性过滤，排除引用未解析、标识歧义、前置条件不满足者。

**运行时契约**。单个 Tool 与 SELT 均受契约校验（接口约束 + 组件功能性要求）；执行成功不等于证据被接受，输出须满足有效性条件，产生 accepted/rejected/argument_error 状态，驱动 Skill 条件披露与 Agent 的改参、换 Tool、重排步骤等响应。

**Harness 增长实测**：ChartBench 上 Skills 4→13、可用 Tools 25→42、活跃 SELT 0→20；ChartX 上 4→12、25→60、0→71。口径说明：可用 Tools 计为最终 harness 中全部 Skills 允许的 Tool 名并集，而非演化期生成的候选版本数。附录给出了一个完整的联合演化样例：dot-ring 图求 Spotify 占比（参考答案 40%），初执行走 annotate_legend→get_marker_rgb→measure_pie_segment_percentage 得 33.68%（像素面积策略与离散点编码不匹配，Tool 本身返回 accepted）；据此联合演化出新 Tool count_ring_dots_and_compute_percentage（同环内目标色点数/总点数）、新 Skill ring-dot-percentage、以及三步 SELT（legend 标注→RGB 提取→点计数），重放得 331/830=39.8795%，按"around"措辞取整为 40%；该持久化能力随后在另外三张 dot-ring 图上复用，分别得 35%、30%、40%。

## 5. 消融要点

**Skill/Tool 演化消融**（5 个 ChartBench 类型：Area、3D-stacked、Ring、Sector、Radar multi-fill；统一 Qwen3.7-Plus 基座与 5% 容忍；无 SELT 的各配置隔离考察）：

| 配置 | 准确率（%） |
|---|---|
| Base MLLM | 42.8 |
| Evolved Skill-only（仅演化推理知识，无 Tool/SELT） | 55.6 |
| Base Harness（初始 Skill+Tool，无 SELT） | 57.2 |
| Evolved Tools（初始 Skill + 演化 Tool，无 SELT） | 84.4 |
| ChartEvo（Full） | 94.8 |

三个层次的解读：其一，Skill 与 Base Tool 两配置总量相近但模式互补——Area 上 Skill-only 92% 对 Base Tools 80%（推理指引的价值），Sector 上 Base Tools 94% 对 Skill-only 60%（可执行数值测量的价值）；但两者在 3D-stacked 上均低于 20%，说明任一单独通道都无法覆盖结构性编码。其二，演化 Tool 带来最大单项跃迁：3D-stacked 16%→90%（专用 3D 测量）、Ring 44%→98%（环点计数）；Sector 维持 94%（所需测量本已被初始 Tool 覆盖），而 Radar multi-fill 停在 52%——作者归因于 Tool 覆盖与有效调用的双重不足，即 Tool 演化的收益取决于“获取能力”与“会用能力”同时成立；完整 ChartEvo（演化 Skill+Tool+SELT）将其提至 88%，验证集成 harness 的必要性。其三，Evolved Tools 相对 Base Harness 提升 27.2 个百分点，是 harness 演化主导项。

**SELT 消融**（同 5 类型，Skills/Tools/基座完全一致，对照配置用动态 Tool 组合替代持久链）：

| 配置 | Acc.（%） | API 调用 | Tool 调用 |
|---|---|---|---|
| w/o SELT | 91.2 | 6.19 | 5.41 |
| ChartEvo（Full） | 94.8 | 2.73 | 5.27 |

API 调用降 55.9% 的同时准确率反升 3.6 个百分点；Tool 调用数基本不变（5.41→5.27），说明收益来自执行结构归并而非少做测量。结合执行统计（链式路径 98.0% 准确率），持久化验证过的组合同时改善了效率与可靠性。

**局限与失败模式**：论文自述演化效果依赖自演化数据的覆盖与多样性——训练样例有限可能导致 harness 组件过度特化，保守的验证与准入准则会限制新能力获取，演化/测试数据分布漂移会削弱 Skills/Tools/SELT 的可迁移性。案例研究给出典型失败：3D 堆叠条形图中约 10 px 的薄层段使端点定位不确定，测量 Tool 正确地返回区间（19.9797–24.5814）并拒绝给出精确值，但 Agent 采用区间中点得 22.2648（GT 20.1 百万，误差 10.77%）——暴露对不确定数值证据的推理仍是短板。错误恢复案例（treemap：矩形分割失败→切换 mask 分割；参数错误→剔除后重调，最终 10.019% 对 GT 10%）则显示契约状态反馈可在不更新 harness 的情况下支撑策略级与参数级恢复。

## 6. 贡献与启示

**方法贡献**：（1）首个面向长尾图表推理的 harness 级 RSI 框架，将能力获取从人工工程转为自主演化，且 Skill/Tool/SELT 可在同一步协同更新、以重执行验证为准入门槛；（2）SELT 把自我改进的对象从“能力集合”扩展到“执行结构”，以功能契约划分 Agent 语义决策与 runtime 预定义过程执行，是对 ReAct 逐步交互范式的结构性替代，实测 API 调用降 55.9% 且不损精度；（3）分层检索 + 渐进披露给出增长型 harness 的上下文管理方案（3 Skill/1600 token/两级目录/6-4 接口上限），是 harness 可持续累积的工程前提。

**工程启示**：Skill（知识）/Tool（能力）/SELT（执行结构）三分实质上是把“提示工程、工具库、宏/缓存计划”解耦为可独立演化、可交叉引用的资产；验证环节相当于软件工程中的回归测试门（失败是否解决、调用是否正确、证据是否可用、原不支任务是否变可解），这一确定性验证使 harness 演化不依赖统计意义上的风险控制。需注意的边界：演化期依赖 ground-truth 答案（数值可验证性是 RSI 在 NQA 上成立的前提）；两基准独立演化意味着产物是数据集特定的，并非通用图表引擎；68.76 s/题的开销定位于离线批处理而非实时场景。

**与音视频技术的上下游关联**（按跨领域视角评估，非论文自述）：本文属文档视觉理解与智能体交叉领域，但与音视频技术存在两条实际接口。其一，**底层视觉原语复用**：harness 中的 25 个初始 Tool（OCR/文本定位、颜色绑定、分割、轴刻度定标、像素-数值投影、径向几何分析）就是经典 CV 测量栈，与视频内容分析中仪表盘读数、HUD 叠加层、比分牌、弹幕/字幕条等结构化图形元素的读取需求同构——ChartEvo 的贡献是给这类原语加上 LLM 编排与自演化包装，这套包装对音视频工具链（ASR/镜头检测/VAD/声纹/OCR）同样适用。其二，**长尾结构与效率问题同型**：视频理解同样面临“头部事件类型饱和、长尾事件/场景持续欠佳”的分布，且工具增强音视频分析智能体的多轮 LLM 交互开销问题与本文动机一致；SELT 式“预绑定工具 DAG、runtime 代管中间传递”的思路，对延迟敏感的流式音视频分析是比整体框架更值得移植的部分。反向上，本文的基座 MLLM（Qwen/GPT 系）本身是音视频多模态模型的同源技术栈，harness 演化可视为多模态基座之上不改权重的垂直适配层。

## 7. 与其他论文的联系

- **paper:arxiv:2611.13524（The RSI Tax）**：该文提出以“RSI 税”核算自我改进的全成本，发现简单有界笔记基线在精度持平时省 65.6–71.0% token。ChartEvo 的 SELT 正是对模型调用税的直接压缩（API 调用 -55.9%），且其成本表（token +18%、时延 +26.05 s）可视为领域实例上的税负量化；两文共同指向“RSI 的执行开销必须被显式设计抵消”这一结论。
- **paper:arxiv:2611.12109（SkillDuet）**：SkillDuet 以响应反馈协同**模型参数更新**与外部技能库演化；ChartEvo 冻结基座、只演化外部 harness。二者是 RSI 作用位置（参数 vs 外部系统）的对照实现，ChartEvo 的 Skill/Tool/SELT 结构化资产可与 SkillDuet 的自由文本技能库互相印证“技能粒度”设计。
- **paper:arxiv:2611.11558（SimplEvo）**：同为免权重更新的自我改进（EBench 46.7%→81.7%），但 SimplEvo 走自写文本记忆与教训精炼路线；ChartEvo 的 harness 是带契约与接口的结构化资产而非自由记忆，代表了“记忆式”与“资产式”两条外部改进路径的分化。
- **paper:arxiv:2611.10787（TRUST）**：TRUST 用在线多重假设检验为 RSI 控制错误进化率并提供统计保证；ChartEvo 的准入用的是确定性重执行验证，其 Limitations 承认保守准入会限制能力获取——TRUST 式统计门控恰好可作为 ChartEvo 验证环节的松弛与风险量化方案。
- **paper:arxiv:2611.10463（LongCapHarness）**：同样主张“演化 harness 而非后训练”，在长上下文推理上以低于基线 50% 的成本超越 HELMET/RULER。两者是同一 thesis 在不同能力轴（长上下文 vs 视觉长尾）上的平行验证，且都以“成本可控”为核心卖点。
- **paper:arxiv:2611.08946（Flex-RSI）**：Flex-RSI 在固定预算下基准化智能体通过递归修订 harness 实现自我改进（视觉与机器人任务）；ChartEvo 可视为该能力范式在图表推理上的深度领域实例，其 SELT 是对 Flex-RSI 所测“harness 修订”维度的执行效率贡献；Flex-RSI 式预算约束评估可用于检验 ChartEvo 演化期（proposer 调用 GPT-5.6-Sol）的成本未在论文中核算的部分。
- **paper:arxiv:2611.14949（RSI-PDEbench）**：递归自我改进在 PDE 求解上的框架与基准（1001 案例、42 方程模板）。与 ChartEvo 的共性在于两者都依赖廉价的数值结果校验（通过率 / 5% 相对误差容忍）作为 RSI 的奖励信号，提示可验证数值输出是 RSI 落地的共同前提。
