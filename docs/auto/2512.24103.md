## 1. 背景与动机

本文来自 Google DeepMind，处理的是 LLM 规划领域一个曾被判“死刑”的问题：**不借助外部验证器、不追加训练，模型能否通过批评自己的答案（intrinsic self-critique）实质提升规划正确率**。

问题谱系如下：早期对 LLM 规划能力的评估基本是负面的（Valmeekam et al., 2023b，"Language Models cannot plan"）；随后 many-shot / few-shot in-context learning 把精度抬了上来（Agarwal et al., 2024；Bohnet et al., 2024），但与经典规划器在复杂问题上仍有差距。另一条自我改进线上，Reflexion、Tree-of-Thoughts、ReAct 等方法大多依赖 oracle（能访问正确答案的验证器）或人工反馈。而针对“内在自纠”的两项标志性负结论构成了本文的直接靶子：Huang et al. (2024) 证明 LLM 无法可靠地自我纠错推理错误；Valmeekam et al. (2023a) 在 Blocksworld 上测得 LLM 自验证的假阳性（FP）率极高、真阴性（TN）几乎全部漏判，据此断言当时的 LLM 不能有效自我批评。此后主流工作转向外部验证信号。

作者的动机逻辑有两层。其一，测试时假设存在 oracle 对大多数实际规划任务不成立，探明“纯内在自改进”的上限有独立价值。其二，也是全文最关键的洞察：**规划与一般推理不同——规划域的状态、动作、前置条件（preconditions）由域定义显式或隐式给定，因此验证输出可以按规则执行**（逐动作查前置条件、推进后继状态）。此前负结论之所以成立，是因为批评提示没有把这套规则检查程序逼出来。论文证明：只要提示工程把验证过程结构化，内在批评即可在多个规划基准上大幅生效。

值得注意的实验口径设定：作者刻意固定使用 2024 年 10 月的模型检查点（Gemini 1.5 Pro 做探索实验，GPT-4o、Claude 3.5 Sonnet、Gemma-2 27B 做确认），以论证方法与具体模型版本无关，而非刷最新模型的榜单。声明的新 SoTA 限定在“该类模型（Oct-2024 检查点）”范围内。

## 2. 方法总览

方法是一个测试时的迭代精修循环（Algorithm 1），基座是 few-shot→many-shot 的 ICL 规划：

1. **PlanGeneration(D, τ)**：以域定义 + 问题实例 + 规划 few-shot 示例 + 历史失败轨迹 τ（此前的 plan 与 critique 拼接，τ ← τ ⊕ plan ⊕ critique）为上下文，采样 1 个 plan。
2. **SelfCritique(D, plan, N)**：同一 LLM 用批评提示（域定义 + 问题 + 待评 plan）生成批评；可选 self-consistency——对同一批评提示采样 N 份（主实验 N=5），对最终判定（correct / wrong / goal not reached）多数投票，**平票判 wrong**（保守策略，触发继续迭代）。
3. 若判定为 correct 则早停返回；否则把 plan+critique 回填进规划提示，回到步骤 1。最大迭代 k=10。

工程护栏：任一步提示超过预设长度上限即终止循环、返回上一步的 plan（该限制实际影响 Minigrid——问题定义冗长——在 10 轮迭代内不影响 Blocksworld）。评测用 VAL（PDDL 验证器）判最终 plan 是否达成目标；规划 few-shot 示例从训练集确定性采样，保证消融间可比。

调用复杂度：每步上限为预测+批评各一次，q = 2×s；加 self-consistency 后 q = s + c×s，但 c 路投票可并行，**不增加延迟**。由于早停，实际调用量远低于上限（见消融节）。

超参选择来自验证集探索：规划提示 16-shot（0–64 shot 扫描，8 shot 后趋平、32 shot 略降，Logistics 超过 2 shot 即停滞，16 为全基准折中）；批评提示主用 0-shot 模板（免自举、可直接迁移到新域），Blocksworld 另做 8-shot 变体；温度默认 0.0。

## 3. 关键设计

方法的全部有效性集中在**批评提示的构造**上，三个要素：

1. **完整域定义（PDDL）**：动作、前置条件、效果。论文明确指出：给出前置条件及后继状态的生成方式，是验证过程一致性的关键。
2. **可选的验证 few-shot 示例**（8-shot）：由单个手工示例自举——在训练集上跑自批评流程，筛选其“对/错”评级与 PDDL 验证器一致的输出作为示例。
3. **逐动作三步验证指令**：“对每个动作：(1) 从域定义取出该动作及其前置条件；(2) 核验当前状态下前置条件是否满足；(3) 应用动作并写出后继状态。不要在核验完每个动作之前停止，不要跳步。”最终必须以字面短语收尾："the plan is correct" / "the plan is wrong" / "goal not reached"。

第三点是全文的灵魂：它把“批评”从一种整体印象式判断改写为**LLM 内部显式执行的符号状态仿真**。附录 D 的轨迹展示了其运作方式：模型逐步维护谓词集合（on/ontable/clear/handempty/holding），例如在一个 3-7 块实例中，第 9 步 `(pick-up b2)` 因第 6 步已 `(on b3 b2)` 导致 `(clear b2)`、`(ontable b2)` 为 false 而被捕获，判定“plan is wrong”并给出原因；随后重规划将失败 plan 与该诊断一起放入上下文，下一版 plan 直接修复了被指出的冲突。字面化结论短语同时服务于程序解析与 self-consistency 投票。

其余关键设计：
- **失败累积机制**：τ 中沉淀的是“错误 + 定位 + 原因”，使重规划条件化于诊断信息而非盲目重采样，这与第一轮迭代贡献最大增量、后续轮次持续小幅改进的实验曲线（Fig. 2）一致。
- **Self-consistency 作用于判定而非内容**：投票对象是三分类结论，平票偏 wrong，等效于抬高接受门槛、压低 FP 接受率。
- **0-shot 批评优先**：8-shot 批评需要按域自举并经 VAL 过滤，0-shot 免去该成本，论文最终在多数数据集上采用 0-shot 批评 + 16-shot 规划的组合。
- 温度 0.0 为默认；有趣的是消融中 0.2 反而略差于 0.5，说明对采样多样性的敏感度不高、非决定性因素。

## 4. 实验结果

数据集口径：Blocksworld 3-5 与 Mystery Blocksworld 各 600 题（Valmeekam et al., 2023b/c）；Blocksworld 3-7 验证/测试集各 1000 题、Logistics 与 Mini-Grid 测试集各 600 题（Bohnet et al., 2024）及其 Hard 变体；AutoPlanBench（Stein et al., 2024）9 个域（剔除 floortile，所有方法均近零）、每域 21 题、最优解长 3–20 步。均用 PDDL 表示。

| 数据集 | Stechly et al. (GPT-4) No-Crit./Crit./Oracle | 本文 No-Critique | 本文 Critique | Critique+SC | 本文 Oracle |
|---|---|---|---|---|---|
| Blocksworld 3-5 | 40 / 55 / 87 | 49.8±4.0 | 85.5±2.8 | **89.3±2.5** | 91.5±2.3 |
| Mystery Blocksworld | 4 / 0 / 8 | 22.3±3.3 | 35.2±3.8 | **37.8±3.9** | 37.3±3.9 |

Mystery Blocksworld（动作/谓词被替换为欺骗性命名，如 attack/succumb/overcome/feast 与 province/pain/craves）上，论文自称是首个让 LLM 取得非平凡精度（22%）的工作，加自批评后到 37.8%，甚至略超 Oracle（37.3，置信区间内持平）——说明在困难域中批评的瓶颈从 FP 转向 FN（早停过早）。

注意 Blocksworld 3-7 上自批评与 Oracle 差距拉大（79.5 vs 92.7）：解越长、FP 接受的代价越高，这是方法精度的真实天花板。Mini-Grid Hard 增益也明显收窄（+3.8）。

**跨模型迁移（Table 5，Blocksworld 3-5，16-shot 规划 + 0-shot 批评）：** GPT-4o 42.8±3.9 → 64.2±3.8；Claude 3.5 Sonnet 68.0±3.7 → 89.5±2.5。Gemma-2 27B 仅在 Logistics 上有温和改善、Blocksworld 无改善——作者据此指出**更强模型才有更强的自我改进能力**，开源小模型不具备此内在循环。

## 5. 消融要点

消融在 Blocksworld 3-7 验证集（1000 题）上进行，报告第 1 步（无批评基线，用于吸收非确定性）与第 11 步精度：

| 消融配置 | 1st step | 11th step | LLM 调用 |
|---|---|---|---|
| 8-shot 批评 + SC 5 票 | 57.1±3.1 | **84.6±2.2** | 14.0k |
| 8-shot 批评 + SC 2 票 | 56.1±3.1 | 84.5±2.2 | 12.2k |
| 8-shot 批评，无 SC | 56.2±3.1 | 79.7±2.5 | 6.3k |
| 0-shot 批评（无示例） | 55.7±3.1 | 79.5±2.5 | 6.1k |
| 温度 0.2；0-shot 批评 | 56.1±3.1 | 76.1±2.7 | 6.4k |
| 温度 0.5；0-shot 批评 | 56.9±3.1 | 78.2±2.7 | 6.1k |
| 去掉域定义 | 56.0±3.1 | 74.4±2.7 | 5.8k |
| 去掉三步指令 | 55.2±3.1 | 64.0±3.1 | 4.1k |
| 去掉“逐动作核验”（改为 CoT 式泛泛评价） | 56.1±3.1 | 57.5±3.1 | 3.4k |

分层结论非常清晰：

- **程序性逐动作指令是第一主导因素**：去掉“verify each action”后退到 57.5，几乎等于基线。这正是对 Valmeekam et al. (2023a) 负结论的机制化解释——泛泛的“请仔细评估/以 CoT 评估”式批评（其 A.5/A.4 模板）天然无效，此前工作失败在提示设计而非能力缺失。
- **域定义贡献次之**（74.4，-10.1）：无前置条件/效果的显式语义，模型只能靠常识猜验证规则。
- **Self-consistency 贡献约 +5 绝对点**（79.7→84.6），且 5 票与 2 票几乎等价（84.5），说明投票收益在 2 票即近饱和，边际成本可压到 12.2k 调用。批评 few-shot 示例本身收益最小（79.7 vs 79.5，区间内），主要价值体现在与 SC 的组合配置中。
- 温度在 0–0.5 区间不敏感（0.2 略差的反常说明这不是关键旋钮）。
- **实际调用量远低于理论上限**：0-shot 配置 1000 题共 6.1k 次调用，即平均每题 6.1 次，远低于 22 次（2×11）的上限——早停有效控制了成本。

**误差结构（Fig. 4/Fig. 7）**：自批评呈现高准确率、高召回、**低精确率**的形态——假阴性（漏判错误）罕见，FP 随迭代轮次累积是最主要误差源，Oracle 曲线即其可视化上界。这决定了方法的失效模式是“错误 plan 被接受后提前停止”，而非“正确 plan 被反复否决”。上下文长度消融（Minigrid，8/16-shot × 32k/1M 上下文）确认提示长度护栏对冗长域的影响。

## 6. 贡献与启示

**对自身领域的贡献**：(1) 在 PlanBench 系基准上以纯测试时、无训练、无外部验证器的方式把 Gemini 1.5 Pro 的 Blocksworld 3-5 从 49.8% 推到 89.3%（Oracle 91.5%），并首次在 Mystery Blocksworld 上报告非平凡精度（22.3%→37.8%），在该模型类上构成新 SoTA；(2) 给出了“LLM 能否自我批评”之争一个可操作的裁决条件——**当且仅当验证规则显式存在且提示强制执行逐规则检查时**，内在自批评有效，这统一解释了正负两派结果；(3) 完整的成本-延迟分析（q = s + c·s，SC 并行、早停）使方法可预算化。

**局限**：FP 累积造成的精度天花板在长解域明显（BW 3-7 距 Oracle 13 点）；小模型（Gemma-2 27B）不具备该能力；方法依赖显式前置条件语义，自然语言表示下增益大幅缩水（20.3→29.7），对隐式约束任务的迁移未获证明；Rovers/Depot 等域仍近零；作者自陈与 MCTS 等搜索方法结合是未走完的方向。

**与音视频技术上下游的关联**（论文本身不涉及 AV，以下为工程迁移视角的分析）：本方法的本质是“生成—按显式前置条件结构化验证—带诊断修复”的循环，凡 AV 工作流中存在机器可检查前置条件的环节均可套用：(a) **滤镜图/转码管线合成**——FFmpeg/GStreamer filter graph 中每个 filter 的输入格式、像素格式、时间基约束就是天然的 preconditions，“逐动作核验 + 写出后继状态”直接映射为逐级格式协商校验，可在不执行管线的情况下发现断裂边；(b) **播出单/导播切换规划**——切换窗口、资源占用、信号通路的约束可编码为域定义，自批评用于修复不可行 rundown；(c) **拍摄机位/云台运动规划**——物理约束（行程、遮挡）显式化的场景与 Blocksworld 同构。上游依赖同样有明确信号：27B 开源模型自改进失败 + Minigrid 的上下文长度截断，意味着 AV agent 栈若走此路线必须配置前沿级长上下文模型，端侧小模型无法闭环；延迟上每轮 2 次调用 + 早停 + SC 并行的结构适合交互式工具链预算，但不适配帧级实时回路。最需警惕的是：AV 中大量约束是感知性、审美性、隐式的（对应论文的自然语言条件），此时应预期 FP 累积与增益缩水——验证应锚定到可机检的规格（EDL/时间码/封装格式规则）而非自由文本审查，这正是论文 NL vs PDDL 实验的直接警示。

- **paper:arxiv:2611.10787（TRUST）**：本文实验定位的主失效模式是自批评判定的 FP 随迭代累积（Fig. 4），其 SC 投票只是压 FP 的粗糙多数票手段；TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证，恰好是对本文所识别瓶颈的形式化补强——可作为本文接受门控的统计替代。
- **paper:arxiv:2611.14326（FGSE）**：两者同属“以自生成验证信号门控状态更新”：本文以批评判定“correct”门控早停（接受输出），FGSE 以三类探针证伪后才将经验写入记忆。本文的 FP 问题即“未证伪的假设被接受”，FGSE 的证伪门控思路可直接移植为本文接受判定的前置过滤器，二者分别守输出端与记忆端。
