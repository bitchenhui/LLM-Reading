# Learning from Failure: Inference-Time Self-Improvement for Computer-Use Agents

## 1. 背景与动机

计算机使用智能体以多模态大模型为策略核心，在“截图观测 → 动作预测”的闭环中完成长程 GUI 任务。当前主流训练范式（OpenCUA、UI-TARS、Mobile-Agent 等）依赖“成功案例循环”：把智能体放进可验证环境 rollout，环境内置 verifier 判定成败，仅保留成功轨迹做 SFT，迭代精化。该范式有两个被本文点名的结构性低效：其一，失败轨迹被整体丢弃，尽管其中携带模型弱点的诊断信号；其二，可验证环境本身需要可观的人工工程投入，丢弃失败轨迹等于浪费了这部分沉没成本的大部分产出。

本文据此提出互补的“失败案例循环”：agent → 环境 → 失败轨迹 → LLM 分析与改进 → 新 agent。关键定位是改进发生在推理时而非训练时——由 LLM 诊断失败模式、提出推理时方案并生成代码补丁（经轻量人工验证），直接注入已训练智能体的执行流程，全程不动权重。主锚点：以当时最强开源模型 OpenCUA-72B 为基线，OSWorld 全集、100 步上限下成功率从 42.3% 提升到 48.9%（+6.6 绝对点，+15.6% 相对），零额外训练成本，运行时开销约 8%，交互步数反而下降约 15%。论文的核心论点是：失败轨迹不是噪声，而是结构化监督源。

对音视频交叉方向的读者，该工作的入口价值在于：OSWorld 任务集本身包含媒体处理类任务（论文自举案例即有从音乐视频提取音轨转 MP3 的 ffmpeg 任务），GUI 自动化与媒体生产工具链（剪辑、转码、导出批处理）的交集正是该方法的直接落点，后文第 6 节展开。

## 2. 方法总览

框架是一个自进化循环（论文 Algorithm 1），每轮三阶段：

1. **失败收集**：当前 agent 在可验证环境中 rollout，环境内置奖励函数判定成败，失败轨迹（含任务指令、动作历史、思考过程）保留入库。
2. **LLM 诊断与提案**：每条失败轨迹以“指令 + 动作历史 + thought”三元组喂给元级 LLM 做上下文内结构化诊断，识别瓶颈（接地缺陷、动作冗余、能力缺口等）；修复提案分三类——概念性修正、替代高层规划、直接代码级补丁。每轮按当前主导失败模式选定一个策略引入，策略跨轮累积，论文实际跑了 4 轮。
3. **应用与再验证**：补丁经轻量人工验证后注入 agent，重新 rollout 产生新的失败集合，回灌诊断循环；失败集为空则提前收敛退出。

**元控制器选型**：候选为 Claude 4.5 Sonnet、GPT-5.2、Gemini 3 Flash、开源 Qwen3-VL-32B-Instruct。论文的对比是定性的：GPT-5.2 与 Qwen3-VL 能识别部分失败模式，但分析全面性与“可实施改进”的提案一致性不足；Gemini 3 Flash 代码级实现能力较弱；元控制器需同时胜任分析、提案与代码实现三职，Claude 4.5 Sonnet 综合最优而被采用。

**人工参与边界**（附录 B.4 口径）：LLM judge 提出候选方案，人只做候选选择，随后补丁由 LLM 自动生成；实际生成的补丁中超过 97% 被直接接受无需修改，人工调整平均只占修改行的 3% 以下（多为语法/运行时小修）。即整个循环名义上人在环、实质上模型主导。

四轮循环的净产出是“四大失败模式 × 四大策略”的映射：接地错误 → 视觉搜索；能力缺口 → 终端执行；知识缺陷 → 知识支持；冗余循环 → 重复警告。

## 3. 关键设计

### 3.1 视觉搜索：后置动作闭环校验

针对高分辨率、视觉杂乱场景下的定位错误。与主流“感知增强/动作前接地”路线不同，本文把视觉搜索做成**动作后**的一等自校验模块：凡执行空间接地类动作（click / moveto / dragto），框架以目标坐标为中心裁出 400×400 图像块、2 倍上采样，并在原动作位置画半径 7 像素的红色空心圆作为视觉锚点；随后以任务指令、动作历史、当前动作（坐标掩蔽，防止模型直接复述原坐标）和标注 patch 组装校验 prompt，让 agent 判断红圈内元素是否是达成目标应交互的元素。动作空间为 `confirm_coordinates()` / `adjust_coordinates([x,y])`（坐标相对裁剪区域）。若调整则替换当前动作后继续。这本质上把“执行—感知”闭合成了单步反馈环。OSWorld small set（30 步上限的轻量迭代子集）上从 41.67 提到 47.22，是单项增益最大的策略之一。论文案例：GIMP 中调低照片亮度时误点上升箭头，放大视图加红圈提示后 agent 反思并给出修正坐标，任务转成功。

### 3.2 终端执行：补齐“绕过像素级操作”的能力缺口

诊断发现 agent 很少利用操作系统提供的高层控制接口（终端），默认走低层鼠标/光标操作，导致执行波动与误差累积。策略是开放终端热键（Ctrl+Alt+T），让 agent 把操作密集型任务翻译成简洁命令序列。对终端能力弱的 GUI-Owl-32B 额外注入三条规则：终端只能经指定热键打开；发出命令前必须先用搜索动作验证语法；所有命令行操作需显式 Enter 执行。small set 上增益 +5.52（41.67→47.19）。论文案例：查找文件并复制路径的任务在 GUI 路径下卡死于复制环节，终端路径下 find + 安装 xclip + xclip 三条命令直接完成。这一“GUI 优先还是 CLI 优先”的取舍对媒体工具链尤其成立——ffmpeg/ffprobe/sox 生态本就是命令行原生的。

### 3.3 知识支持：手册检索 + 受控搜索双通道

针对任务相关知识超出模型内部上下文的情况（应用级流程、命令行语法）。双机制： 其一，软件手册检索器，提供精选的热键参考库——例如 LibreOffice Calc 的 Ctrl+D（向下填充整列）等，刻意不提供完整官方手册以避免冗余噪声； 其二，搜索引擎接口，agent 可向专有搜索模型 GPT-5-mini 发查询，prompt 约束查询必须简洁、具体、动作导向（如 "how to install [tool] on [system]"），且允许单步内多次搜索迭代精化理解。设计动机是“受控搜索引擎”返回聚焦的可执行信息、规避开放网页噪声。small set 增益 +2.77（41.67→44.44）。两个论文案例：conda 报错后经检索获得正确安装命令序列；LibreOffice 到期日计算任务中，原本陷入 Ctrl+C/Ctrl+V 逐格复制循环，注入手册后改用 Ctrl+D 一次填充选定区域。

### 3.4 重复警告：三通道滑窗停滞检测

LLM 判定的**最常见**失败模式是冗余动作循环——操作失败后原样重试、或无视界面未发生变化而继续原计划。检测机制在固定滑动窗口内监控三类信号： 思维重复：语义等价的低层规划语句在窗内复现； 动作重复：相同命令（如同一 pyautogui 交互）高频出现； 屏幕状态重复：每个屏幕状态编码为压缩表示——从 OSWorld 可访问性树抽取相关 UI 节点子树、对结构与文本属性取稳定哈希——若哈希在有动作执行的情况下连续 3 步不变则判定停滞。动作/思维通道的规则口径（附录 A.5）为最近 5 步窗口内同一模式出现至少 3 次即触发；附录 B.3 的示例补丁代码默认 lookback_window=5 / repetition_threshold=2，说明窗口与阈值实为可调超参，正文规则为准。触发后在 prompt 中追加短指令进入恢复模式，鼓励改换 UI 路径、调用辅助工具或转终端。small set 增益 +2.73（41.67→44.40），单项最小但直接决定步数效率。论文案例（音视频直接相关）：从音乐视频提取歌曲存为桌面 MP3，agent 卡在文件定位环节、屏幕状态 3 步不变，恢复模式触发后改用 ffmpeg 命令完成。

### 3.5 失败模式迁移：低层瓶颈清除后的残余结构

按 LLM 分类的失败轨迹分布（单条轨迹可含多类，比例非互斥、总和不必为 100%）：初始阶段由动作循环（43%）、坐标精度（24%）、UI 识别（19%）、多步规划不足（15%）主导；四轮循环后剩余失败转为多步规划不足（28%）、动作循环（24%）、UI 识别（24%）、任务误解（12%）、验证码（12%）。机理含义明确：推理时补丁有效清除了接地、停滞、知识缺失这类“低层/工程层”瓶颈，剩余失败迁移到任务理解、推理一致性这类“认知层”能力——后者恰是补丁式干预边际收益递减的区域，构成该方法的天花板证据。

## 5. 消融要点

OSWorld small set（30 步）逐项消融，基线 OpenCUA-72B：

| 配置 | 成功率 (%) | 单项增益 |
|---|---|---|
| Baseline (30 steps) | 41.67 | — |
| + Visual Search | 47.22 | +5.55 |
| + Terminal Execution | 47.19 | +5.52 |
| + Knowledge Support | 44.44 | +2.77 |
| + Repetition Detection | 44.40 | +2.73 |
| Full Method | 52.74 | +11.07 |

要点：

- **单项贡献排序**：视觉搜索 ≈ 终端执行 > 知识支持 ≈ 重复检测。前两者分别吃掉“接地错误”与“能力缺口”两大失败簇，与 3.5 节初始失败分布（坐标精度 24%、动作循环 43%）中可被工程手段干预的部分对应。
- **组合增益 11.07 低于四项单独增益之和 16.57**（本条为笔记作者按上表数字计算，论文原文仅陈述“组合显著超出任何单项”）。合理的机理解释是四类失败在轨迹层面相互纠缠——例如接地错误常引发重复循环——修复一处即顺带缓解另一处，收益存在重叠；但组合配置的鲁棒性（全集 3 次运行 std 从基线 ±2.6 收窄到 ±1.2）优于任何单项。
- **元控制器消融**为定性结论：换用 GPT-5.2 / Qwen3-VL-32B / Gemini 3 Flash 均在分析全面性、提案一致性或代码实现力上存在短板，无对应数字。
- **结构化顺序更新 vs 临时补丁堆积**：论文强调每轮迭代针对新识别的失败模式而非叠加 ad-hoc 补丁，四个结构化更新的堆叠表现稳定优于任何单个更新——即改进是“可组合、可扩展”的，这是把失败案例循环称为“循环”而非“一次性修补”的实证依据。
- **人工介入量**：修改行占比平均不足 3%，与主结果一并支撑“近乎全自动”的定性。

## 6. 贡献与启示

论文自述三点贡献： 识别现有智能体改进管线对失败轨迹的低效浪费； 提出数据中心、免训练的失败驱动自改进循环（LLM 分析 + 轻量人工验证 + 推理时行为补丁）； 给出（据其所知）首个该范式在计算机使用智能体上的实证，OSWorld +6.6 点。

工程视角的启示：

1. **补丁即代码的交付形态**。改进物化为代码级更新意味着可版本化、可 diff 审计、可回滚，与权重更新相比在工程治理上成本极低；“>97% 补丁直接可用”说明当前前沿 LLM 的代码生成质量已足以承载这类行为工程。
2. **与成功循环的双向协同**。失败循环提升成功率等价于扩大“能产出高质量成功轨迹的环境比例”，直接反哺 SFT 数据供给——两个循环不是二选一，而是同一可验证环境投资的两次变现。
3. **明确的天花板与残留风险**。四轮后失败分布迁移到任务理解/多步规划/验证码，说明推理时补丁对认知层缺陷无能为力；失败分类本身由 LLM 主导，存在分类偏差自我强化的风险（诊断器的错误会直接决定补丁方向）；人工验证环节虽轻但仍是在环的，论文自己提出的扩展方向是用学习型 reward model 自动判错以实现完全闭环。

对音视频技术上下游的关联（本笔记重点）：

- **任务层直接命中**：论文自身的停 stagnation 恢复案例就是“音乐视频 → ffmpeg → MP3 落桌面”这一标准媒体处理任务。对媒体生产自动化（批量转码、剪辑流水线、导出封装）而言，“停滞检测触发模态切换（GUI→CLI）”与“终端优先”两条策略可直接复用——媒体工具链的 GUI 封装（导出对话框、预设面板）恰恰是低层操作误差累积的重灾区，而 ffmpeg/ffprobe 的参数化能力远未被 GUI 层完整暴露。
- **知识注入范式可平移到 DCC/NLE 软件**：LibreOffice 精选热键手册的做法，对应 Premiere / DaVinci / Audition 等音视频工作站庞大的快捷键与渲染参数体系——官方文档冗长、任务相关子集小而稳定，正是“curated manual injection”的适用形态；受控搜索（GPT-5-mini 只回动作导向结果）对应编解码器参数、滤镜语法、错误码排查等查询场景，规避开放网页噪声。
- **后置视觉校验与视频 QC 的 ROI 检查同构**：crop-zoom-verify 的“动作后看一眼”闭环，等价于自动化剪辑/包装流程中对字幕区、台标、播放器 overlay 等关注区的局部放大复核，可捕获错位渲染与错点操作。
- **语义级屏幕指纹**：屏幕状态用可访问性树的结构 + 文本稳定哈希做“无变化”判定，思路与视频分析中的感知哈希/重复帧检测同源，但以语义结构替代像素、天然抗视觉噪声；对以截图为观测的 GUI agent，这类指纹比像素 diff 稳得多，可迁移为“界面未按预期响应”的通用检测器。
- **成本账对批量任务成立**：步数 −15%、运行时 +8% 的净效应意味着按回合计费的 VLM 截图 token 开销下降，对大规模媒体任务批处理是直接的成本杠杆。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326（FGSE，Falsification-Gated Self-Evolution）**：两者都把经验教训转化为可复用改进，且都面对“写入前如何验证”的同一问题域。本文用轻量人工验证兜底（>97% 补丁直接接受、修改行 <3%），FGSE 则把教训当作可证伪假设、经三类探针验证后才写入记忆。FGSE 的证伪门控可视为本文人工环节的自动化替代方案，是直接的方法论互补。
- **paper:arxiv:2611.10787（TRUST）**：关注点同为自改进更新的安全性，但 TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证；本文的补丁累积完全依赖“人选候选 + 极少量行修改”，没有任何统计层面的更新安全保证。若把本文循环真正无人化，TRUST 式的检验框架是必需的补强件。
- **paper:arxiv:2611.12109（SkillDuet）**：同为“把改进外置于权重之外”的路线——本文外置为推理时代码补丁，SkillDuet 外置为可演化的技能库并同时更新 LLM 参数。两者构成“纯外置补丁 vs 参数-技能协同演化”的谱系两端；本文的免训练优势与 SkillDuet 的技能级递归改进各有适用场景。
- **paper:arxiv:2611.10463（LongCapHarness）**：范式同构——都是不做数据合成、不做后训练，以推理时挂接式组件放大基座已有能力，且都以显著低于后训练路线的成本取得超越基线的收益（本文口径：约 8% 运行时开销换 OSWorld +6.6 点）。可归入同一“inference-time harness/scaffold”方法族，区别在于挂接的能力域（长上下文推理 vs GUI 操作）。
- **paper:arxiv:2611.20430（TrainExplorer）**：谱系对照项——TrainExplorer 走自主后训练（改权重），本文走推理时行为工程（改外壳）。二者可级联：本文的失败循环扩大成功轨迹供给，正是 TrainExplorer 式自主后训练的数据上游。
- **paper:arxiv:2611.19230（CompoundingKernel）**：共享“以可执行代码为改进物化载体”的自改进机理（搜索驱动写 GPU 内核 vs LLM 诊断失败生成补丁）；其 GPU 内核优化方向处于音视频编解码与推理的算力上游，与本文在“代码级自改进”方法论上同源。
