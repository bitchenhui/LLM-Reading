## 1. 背景与动机

低延迟 P 帧设定下，神经视频编解码器（SSF-Pred、DCVC 系列等）在率失真上已超过 HEVC(HM)、VVC(VTM) 参考实现，但两类问题使其无法落地移动端：其一，模型是大算力浮点网络，已发表的 runtime 几乎都在桌面/数据中心 GPU 上测量；其二，时间建模普遍依赖稠密像素 warp（scale-space flow）或特征域 warp（deformable 卷积，如 FVC/DCVC 系），这些自定义算子在内存受限设备上难以高效实现。与之相对，标准编解码器有 FFmpeg 这类快速软件实现和消费级专用解码硅片。

此前唯一报告移动端实测 runtime 的工作是 MobileCodec（Le 等，2022）：其核心选择是用一个卷积运动补偿子网络**替换** warp，从而回避端侧实现困难，但代价是压缩性能受损；且只支持 720p RGB，熵解码在手机 CPU 上仅 8 线程并行。本文反其道而行：不回避 warp，而是把运动补偿改造成移动加速器 warp 核上原生可运行的形式（重叠块运动补偿），配合 int8 量化与 GPU 并行熵解码，首次在手机（Snapdragon 8 Gen 2）上实现 1080p YUV420 视频的实时神经解码（>30 FPS）。论文同时回答两个设计问题：warp 算子如何选、mean-scale hyperprior 如何整数化。

## 2. 方法总览

MobileNVC 是 scale-space flow（Agustsson 等）架构的高效变体，输入输出头按 Pourreza 等的方案改为 YUV 4:2:0（YUV 空间距离更贴近感知，色度下采样利用人眼亮度/色度敏感度差异）。整个模型包含三个 mean-scale hyperprior 自编码器和一个 flow extrapolator：第一个 AE 作 I 帧模型压缩 GoP 首帧；P 帧模型由另外两个 AE（flow、residual）加 flow extrapolator 构成。

P 帧压缩三步：(1) flow extrapolator 从上一帧已传输 flow f̂ₜ₋₁（x₁ 时置零）外推 fₜᴾ，发送端用其在原始帧上 warp 得初始预测 xₜᴾ；(2) flow 自编码器以 xₜᴾ 与当前帧 xₜ 的 **Y 通道**为输入，估计并压缩 flow 残差 fₜᴾ−f̂ₜ，重建后加回外推 flow 得 f̂ₜ，用 f̂ₜ warp 上一重建帧 x̂ₜ₋₁ 得精化预测 xʷₜ；(3) residual 自编码器压缩 r = xₜ−xʷₜ，解码端 ᵣ̂ 加回 warped 帧得最终 x̂ₜ。

收发显著不对称：接收端 P 帧仅 6.30M 参数、24.52 kMACs/px，为发送端（64.93）的约 25%，而其他模型收发比通常为 70–80%。部署侧由三件套构成：int8 量化（PTQ+QAT 两阶段）、OpenCL GPU 并行算术解码（512 线程）、落在 NPU warp 核上的 OBMC，辅以跨三个时间步的芯片级流水线。

## 3. 关键设计

### 3.1 重叠块运动补偿（OBMC）

稠密 warp 对每个像素用独立位移从参考帧取值（非整数位移需双线性/bicubic 插值）。由于自然运动中大块区域位移高度一致，块级 warp 将帧划分为 b×b 块、每块共享一个运动矢量，块状内存访问更高效；但相邻块运动不一致时块边界会产生不连续伪影。解法是经典 OBMC（Nogaki 1992 / Orchard & Sullivan 1994）：每个块额外用 N−1 个邻块运动矢量各 warp 一次，以向块边缘衰减的 Gaussian 核 w∈R^{b×b×N} 加权平均。该 kernel 在 Snapdragon 8 Gen 2 神经加速器的 warp 核上原生可用。

第二个收益更关键：块级 warp 使 flow 张量空间分辨率大幅下降，直接缩减 flow 自编码器与 extrapolator 的算力；flow AE 只取 Y 通道进一步省算力。表 6 中运动相关子网（extrapolator 0.21M 参数 / 1.66 kMACs/px，flow AE 收端 2.91M / 9.5）远小于稠密 flow 方案。消融显示 overlap 相对 dense warp 仅 6% BD-rate 代价而 MACs 降 4 倍以上；相对无重叠 block warp 省 19.2%；完全去掉 warp 改用条件卷积（MobileCodec 路线）则损失 51.2% 且更贵。一个值得注意的学习现象：overlap 模型传输的 flow 呈棋盘状纹理——网络学会了利用混合核对邻块运动矢量的合并效应来优化最终结果。

### 3.2 损失函数与训练配方

率损失为三个 AE 的 latent 与 hyperlatent 负对数似然之和。工程上一致性设计：hyper-latent 用零均值、可学习方差的正态熵模型替代 Ballé 的非参数 hyperprior，使 latent 与 hyper-latent 共用同一熵编码算法。量化模拟采用混合方案：率损失用加性均匀噪声，失真损失用 rounding。失真项为 MSE 按 Y:U:V 权重 6:1:1 加权，对齐评测协议；I 帧率损失乘子减半（总损失中 I 帧项为 βR(x₀)，P 帧项为 2βR(x>0)），使 I/P 帧在所选工作点上 PSNR 更一致。

针对小模型低码率下的误差累积，采用指数调制 P 帧损失 D_mod（式 5），以 τ 加权强调 GoP 后段帧；辅以 flow 辅助损失 D_flow(f, x̂ₜ₋₁, xₜ)=D(warp(x̂ₜ₋₁,f), xₜ)，同时作用于外推 flow 与重建 flow。训练共四阶段：(1) fp32 主训练 1M steps（λ=0.1，batch 8，GoP 4）；(2) 微调 250k steps（λ=0，τ=1.2，GoP 7，crop 256×384）；(3) PTQ 30 steps（约 2 分钟，per-layer MSE 拟合量化器，模型参数冻结）；(4) QAT 100k steps（约 1 天，LSQ+STE 联合微调网络与量化参数，lr 5e-7 cosine 衰减至 1e-9）。每个 β ∈ {0.0001,…,0.0064} 单独训一个模型，共 7 档码率。

### 3.3 mean-scale hyperprior 的 int8 量化

权重用对称 per-channel 量化；激活用非对称 per-tensor——per-channel 激活量化需在累加器上做位移，多数定点加速器不支持。

熵瓶颈的计算图：实际传输的不是 latent y 而是减均值后的 symbol s=y−μ，推理时 s 取整到整数格。三类参数的处理截然不同：

- **scale**：采用 Said 等的方案，网络输出 pre-scale ρ∈(0,1]，熵解码端经指数-多项式映射 σ=T(ρ)。定义域固定 → 量化格固定，ρ 以 int8 直接送入熵编码器。消融证明此量化零损失（加 scale 量化后 BD-rate 仍为 +54.2%）。
- **symbols**：因取整到整数格，量化器用步长 1 的对称格。
- **latents y 与 mean μ**：若沿用步长 1 的整数格，性能灾难性崩塌（+243.3%），说明 mean-scale hyperprior 对此处亚整数精度高度敏感，且 latent 取整（或加噪）与激活量化存在相互作用。两种解法：y、ŷ、μ 用 int16；或 int8 但步长取 1/5（最高码率档取 1/3）——该选择既覆盖足够值域，又避免子格点恰好落在粗格两点正中间的 tie-break 问题（如 1/4 会踩坑）。作者观察到精心对齐的固定格优于反传学习量化格；QAT 阶段率损失仍基于加均匀量化噪声扰动后的 latent。

最终 int8 相对 fp32 的 BD-rate 开销为 42.5%（Xiph-5N）；int16 latent 方案可到 25.6% 但增加端侧运行时。

### 3.4 GPU 并行熵解码与芯片级流水线

目标吞吐为 1080×1920 YUV420 下 30+ FPS。流水线将神经网络跑在 NPU、并行熵解码（PEC）跑在 GPU、OBMC 跑在 warp 核、加法跑在 CPU，最多三个时间步同时在飞。NPU 与 GPU 共享内存，无跨处理单元拷贝延迟；熵编码数据元素全部为 8-bit 整数；算术编码用 OpenCL 实现，表足够小使并行度基本由 work item 数决定、work group 组织不敏感。相比 MobileCodec 的 8 线程 CPU 方案，本文 GPU 实现可达数百线程，且可让 GPU 专职熵解码以稳定帧率。代价是并行化引入更大的码流 header 开销：512 线程下 naive header 为 3.9% 码率（优化实现可减半至 2.0%），1024 线程解码更快（6ms）但开销升至 7.0%。解码吞吐受限于网络推理本身，warp 借流水线与 NN 并行、不构成额外开销。

## 4. 实验结果

设置：训练 Vimeo90k，验证 Xiph-5N（超参在此调优），评测 HEVC-B、UVG-1k、MCL-JVC。标准基线为 FFmpeg x264/x265（fast preset、禁 B 帧、GoP=∞）与 HM-16.25（LowDelayP 默认配置），不含 VVC/AV1。神经基线 SSF-YUV/SSF-Pred、DCVC-DC（原论文未报全序列结果，作者重评其多率模型、调低 I 帧与上下文模型量化尺度以补低码率点）、MobileCodec（RGB 训 1M steps 后以 YUV 6:1:1 微调 500k）。GoP：本文与 MobileCodec 为 16，DCVC-DC 为 32，SSF-Pred 为 ∞。指标：Y/U/V 分别算 PSNR 后按 6:1:1 加权，BD-rate 基于 bpp 与 YUV611 PSNR，丢弃码率 >1.3 Mb/s 的点，仅保留各方法 PSNR 区间互相重叠的点。MAC 用 DeepSpeed 统计（warp 不计入）。重要口径差异：MobileCodec int8 报的是 AIMET 模拟 RD，而 MobileNVC int8 是**片上真实编解码**的 RD 结果。

BD-rate（相对 x265 FFmpeg fast，%，越低越好）：

| 模型 | HEVC-B YUV611 | MCL YUV611 | HEVC-B Y | MCL Y |
|---|---|---|---|---|
| MobileNVC int8 | 159.2 | 192.6 | 124.9 | 165.2 |
| MobileCodec int8 | 396.7 | 549.0 | 319.6 | 570.7 |
| MobileNVC fp32 | 50.8 | 56.4 | 32.5 | 41.9 |
| MobileCodec fp32 | 171.6 | 294.4 | 145.2 | 268.8 |
| SSF-YUV | 46.4 | 44.2 | 25.7 | 27.2 |
| SSF-Pred | −10.9 | −0.1 | −24.1 | −10.3 |
| DCVC-DC | −57.1 | − | − | − |

关键结论：fp32 模型以 24.52 kMACs/px（收端，1080×1920 输入计）匹配 SSF-YUV 的 BD-rate 而 MACs 低约 8 倍（SSF 收端 194.72）；DCVC-DC MACs 约为本文 50 倍；fp32 仍逊于 x265（FFmpeg fast）。相对 MobileCodec fp32 省 45% BD-rate 同时收端复杂度降 10 倍以上；相对 MobileCodec int8 省 48%。吞吐：HEVC-B 上收端平均 38.9 FPS（Snapdragon 8 Gen 2）；发端未优化、顺序执行约 3 FPS。熵解码并行化实测：

## 5. 消融要点

架构消融（fp32、1M steps、相对 baseline，Xiph-5N）：

| 方案 | send/recv kMACs/px | BD-rate |
|---|---|---|
| I. OBMC + mean-scale（baseline） | 64.93 / 24.52 | 0.0% |
| II. 无重叠 block warp | 64.93 / 24.52 | +19.2% |
| III. dense warp | 153.67 / 113.59 | −6.0% |
| IV. 条件卷积、无 warp | 80.72 / 57.35 | +51.2% |
| V. scale-only prior | 63.84 / 23.44 | +9.6% |
| VI. baseline + 二阶段微调 | 64.93 / 24.52 | −14.0% |

要点：warp 算子谱系上，OBMC 是精度-算力最优折中（dense 收 113.59 vs overlap 24.52，代价仅 6%）；MobileCodec 式“卷积网络隐式学运动补偿”在算力与压缩两头都不占优。mean-scale 相对 scale-only prior 值 9.6% 而算力几乎不变，说明 MobileCodec 的 scale-only 选择次优。第二阶段训练（更大 GoP + P 帧损失调制）单独值 14%。定性观察：block warp 在物体边缘与块边界不对齐处出现断裂缝隙，overlap 将其消除；无 warp 条件模型的预测明显发糊。

量化消融（相对 fp32 baseline，Xiph-5N）：

| 量化配置 | PTQ | QAT |
|---|---|---|
| 仅 symbols + flow | +11.9% | − |
| + 权重 | +14.2% | − |
| + 激活（瓶颈除外） | +54.2% | − |
| + scale（Said 方案） | +54.2%（零损失） | − |
| 全 int8，latent 步长 1 | +243.3% | − |
| 全 int8，latent 步长 1/5、1/3 | +101.9% | +42.5% |
| latent 用 int16 | +54.2% | +25.6% |

symbols+flow 的 11.9% 损失主要来自 flow 量化，构成量化性能上界；激活量化是主要开销来源；latent/mean 网格失配是灾难项；QAT 显著收窄 PTQ 缺口（101.9%→42.5%）。

## 6. 贡献与启示

本文是首个在手机上实时解码 1080p YUV420 的神经视频编解码器（HEVC-B 38.9 FPS），相对唯一同类工作 MobileCodec 省 48% BD-rate、收端 MACs 降 10 倍。方法论层面的可迁移结论：(1) 不要回避 warp——将运动补偿改造为硬件原生算子（OBMC）即可在 6% 性能代价内换取约 4.6 倍收端算力缩减，且低维 flow 张量连带压缩了 flow 编解码子网的算力；(2) mean-scale hyperprior 的整数化必须区分 symbol 的整数格与 latent/mean 的子整数格，固定格对齐优于可学习格，scale 以 pre-scale 参数化后 int8 无损；(3) 熵解码从 CPU 8 线程迁到 GPU 数百线程是移动端达成实时吞吐的关键工程杠杆，代价为 2–4% 的 header 码率开销；(4) NPU+GPU+warp 核+CPU 共享内存、跨三个时间步的异构流水线是移植神经编解码器的可行范式。局限同样明确：fp32 仍逊于 x265 fast（+50.8%）；int8 相对 fp32 有 42.5% BD-rate 开销；发端 3 FPS 未优化；每档码率需单独训练（7 个 β），无连续码率控制。作者呼吁后续工作在设备上而非仅模拟地评测压缩算法。

## 7. 与其他论文的联系

- **MLVC（arXiv:2606.28027）**：同属“神经视频编解码实时上 NPU”的部署路线。MobileNVC 在单一平台（Snapdragon 8 Gen 2）以 int8 + GPU 并行熵解码实现 1080p 38.9 FPS，且已把 scale 信息以 pre-scale ρ 的整数形式随码流传递；MLVC 则进一步解决跨 NPU（Apple/Intel/Qualcomm）熵解码稳定性问题——将 DCVC-RT 的 scale 参数经 hyperprior 显式传输以避免跨平台熵解码崩溃，并以门控记忆/ReGLU/LTR 恢复码率，达成多平台 100 FPS。两文共同印证：熵编码在加速器上的可实现性与 scale 参数的显式传输，是神经编解码器端侧部署的两大核心议题。
- **Feedback-Driven Rate Control for Learned Video Compression（arXiv:2604.20104）**：MobileNVC 明确为每个 β 单独训练模型，仅覆盖 7 档离散码率点，缺乏连续码率自适应；该文的 log 域 PI/PID 闭环加 GRU 调节器正是面向单模型精准码率跟踪的互补方案，对部署型 NVC 的实用化构成直接补强。
