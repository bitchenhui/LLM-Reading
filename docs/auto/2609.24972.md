## 1. 背景与动机

现代 LLM agent 是系统而非孤立模型：冻结 backbone 策略 π 之外包裹着 harness H——system/task prompts、决定何时规划/行动/反思/终止的控制流、工具接口与描述、memory 与 skill 文件、以及决定每步策略实际可见内容的上下文管理。同一模型是否先读对了文件再编辑、能否从失败命令中恢复、能否维持高效工作上下文、能否把结论写进交付物，全部由 harness 决定；近期的工程报告普遍认为 agent 产品进步中相当部分来自 harness 工程而非新权重。但这条路线是纯人工的：工程师逐条检查失败轨迹并手工修补脚手架，进度受限于人能读多少轨迹。

由此出现了自动化闭环（Meta-Harness、AHE、TTHE、HarnessX 等）：LLM 提议器从任务反馈迭代改写 harness 组件，按基准分数保留编辑。这实质上在 agent 系统层面建立了递归自我改进（RSI）：当前系统产生的反馈被用于改进塑造其后续行为的 harness。论文的核心指控是：该循环在有限 evolve set 上反复“提议-评估-选择”，且 evolve set 被自适应复用——第 t 轮的候选依赖此前各轮在同一批任务上的测量——构成典型的 adaptive overfitting。已有观察表明 evolve 集增益与 held-out 表现差距巨大，表面改进可能只来自任务特定拟合或测试时算力堆叠。论文将泛化明确定义为：进化出的 harness 能否迁移到任务描述、工具接口、verifier 均不同的未见基准。

作者归纳出三种相互耦合的过拟合机制：(i) 搜索编码基准特定模式（benchmark-specific fitting）；(ii) 候选偏好被评估噪声驱动（noise chasing）；(iii) 复杂度累积——提升 evolve 分却不改善底层 agent 机制。三者共同拉大 evolve-to-transfer 差距，理论上正对应自适应数据分析/holdout 复用（Dwork et al., 2015）的经典风险。动机由此成形：把机器学习的正则化原则翻译进对有限、噪声反馈的自适应 harness 搜索——不限制什么可以被改，而是约束“反馈如何转化为永久变更”。这是把泛化治理从参数空间训练移植到程序空间搜索动力学的一次系统化尝试，也是论文在 harness 进化这一拥挤赛道上的差异化立足点。

## 2. 方法总览

**形式化。** Agent A=(π, H)，任务 x 及其环境产生轨迹 τ∼A(·|x) 与交付物，verifier 给出 r(x,τ)∈[0,1]（编码域为单元测试，workspace 域为 LLM judge）。任务集 D 上定义性能与成本：S(H;D)=E_x E_τ[r(x,τ)]，C(H;D)=E_x E_τ[c(τ)]，其中 c(τ) 为轨迹消耗的 policy token 数。标准 harness 进化在第 t 轮执行：当前 H_t 在 D_evolve 上运行得轨迹，汇总为反馈 F_t，提议器生成候选集 H_t ∼ P_0(·|H_t, F_t)，在同一 evolve 集上评估，取 Ŝ 最大者为下一任 incumbent；Ŝ 为每任务 k 次随机运行的经验均值。关键视角转换在于：evolve set 的复用是**自适应**的，因此 harness 进化应被理解为“在异常高表达力搜索空间上的自适应经验优化”，而非普通评测。

**RRSI 立场：正则化转移规则而非假设空间。** 设 Ω(H) 为任意源码编辑可达的 harness 全集，RRSI 完全不收窄 Ω(H)——prompt、控制流、配置、上下文管理、工具、skill、memory、子 agent 均可增删改——转而正则化搜索在该空间中的**转移规则**。框架拆成互补的两侧：**提案侧**约束单轮可动用多少自适应容量、容量花在哪里（鼓励更简单、更可复用的编辑）；**选择侧**约束哪些经验增益有资格固化为永久状态（拒绝由基准特定信号、评估噪声或无谓复杂度驱动的“改进”）。选择侧是**非补偿性多门控**：候选必须先通过泄漏筛查、噪声调整下限、成本条件与域守卫全部检查，其分数才有资格替换 incumbent——这与标准做法中单一 argmax 的补偿性选择有本质区别，任何一项违规不可被高分买断。

**正则化三件套与类比边界。** 编辑预算对应 L0/基数约束（限制单次更新中独立可归因编辑的数量）；结构剪枝对应 Lasso/L1（整体删除持续无产的组件，使保留的 harness 结构性变稀疏）；复杂度感知接受对应 Ridge/L2（以 policy-token 为可测代理，抑制总资源足迹的无界增长，但不要求删除任何特定组件）。作者明确声明这是**角色/功能层面的类比**：RRSI 不优化任何范数惩罚目标，异构 harness 组件也不构成共享连续参数向量的坐标。这个诚实的边界划定本身值得注意——它移植的是“正则化思想”而非“正则化数学”，评价其贡献时应按此口径。

## 3. 关键设计

### 3.1 提案侧：控制搜索容量的使用方式

**L0 式退火编辑预算。** 无约束提议器可把多个不相关修改捆绑进一个候选，这类候选有效容量高：既能拟合当前反馈的更多特异细节，又使任何测量变化难以归因到具体机制。RRSI 将每轮原子编辑池记为 E_t（每轮重新起草，论文实例中起草池约 80 个编辑），候选对应子集指示向量 z_t∈{0,1}^{|E_t|}，施加基数约束 ‖z_t‖₀ ≤ b_t，其中预算按余弦调度退火：

b_t = b_min + (b_max − b_min) · ½(1 + cos(πt/T))

从 b_max（3 或 4）单调降至 b_min=1。注意约束对象是“单次更新中独立可归因编辑的数量”而非“最终可修改的组件集合”——早轮允许少数协同变更以发现新机制，晚轮强制稀疏、可归因；b_min=1 保证收官轮次每个候选只含一个编辑、其测量无歧义。b_max 远低于起草池规模，因此没有任何一轮能制造出测量不可解释的捆绑体。

**证据感知的信用分配。** 限制更新规模只在搜索“记得”此前建立了什么证据时才有意义。对同一有限 evolve set 的每次评估都是一次自适应观察，反复检验已被证伪的假设等于浪费搜索容量。RRSI 为每个被评估候选的每个原子编辑维护七元组历史记录 (轮次 t_i, 组件 ℓ_i, 假设 h_i, 源码 diff d_i, ΔS_i, ΔC_i, 是否随胜出候选被接受 a_i)；捆绑编辑共享候选级测量，因此随着预算退火到 1，证据的可归因性单调提升。提议器在后续轮显式条件化该历史：被拒机制保留为负证据，成功机制保留显式信用。

**结构化探索。** 同一历史还能暴露提议器坍缩到窄编辑族（如反复重写 prompt 而不动结构性机制）。可编辑组件词汇 K={prompt, control_flow, config, output_plumbing, context_mgmt, client_tool, skill, memory, subagent}；记 T_t 为已有测量编辑的组件集，U_t=K\T_t 为从未触及的组件。停滞判定 σ_t=1[Ŝ_t − Ŝ_{t−w} ≤ δ]（窗口 w=3，即近 w 轮改进不超过经验噪声带）。停滞时保留 m_draft=1 个提案槽（占每轮 m=2 个候选的一半）给未探索组件。其作用类似熵/多样性正则：重定向有限提案容量，但不改变 harness 允许包含的机制集合。

### 3.2 选择侧：控制哪些增益可成为永久状态

**泄漏筛查（评估前）。** 审查器（critic）在每个候选**全量评估之前**读取其 diff（而非提议文本），拒绝显式编码任务名、实体名、任务特定取值/答案、evolve 基准特定逻辑以及添加惰性机器的编辑；通用 prompt/工具描述改进仍是合法候选。筛查对象是基准特定内容而非特定组件。预评估筛查的机理很关键：泄漏候选永远拿不到那个会吸引后续轮跟随的虚高 evolve 分，从源头切断泄漏被搜索放大的路径。执法形态（coding 运行的 38 个被筛候选）：候选可以在设计理由中点名预期修复的任务——解释自由——但该内容不得进入交付 diff；唯一的当场 outright 拒绝发生在第 10-B 轮，理由是声明的组件与 diff 实际修改的组件不符。

**噪声调整下限。** 进化开始前对未变的 base harness 重复评估，估计经验噪声带 δ。设 S★ 为迄今观测到的最优 evolve 分（更新规则单调不降：S★←max(S★, Ŝ(H_{t+1}))），候选须满足 Ŝ(H′) ≥ S★ − δ。该下限阻止搜索经由一连串单看都落在噪声内的回落逐级走下坡，是对“同一 evolve 集上重复随机评估”的保守化（Dwork et al., 2015 的工程化对应物）。

**Ridge/L2 式复杂度感知接受。** 记 ΔS=Ŝ(H′)−Ŝ(H_t)，ΔC=(Ĉ(H′)−Ĉ(H_t))/Ĉ(H_t)（policy token 相对变化）。对增益超出噪声带的候选（ΔS>δ），要求成本条件 ΔC ≤ β₀ + β₁·ΔS：β₀ 是无实质增益时容忍的成本增长（三域取 0.10/0.10/0.15），β₁ 控制随实测增益放行的成本斜率（44.5/35.4/24.4）。对落入带内（ΔS≤δ）的候选，改用整形准入规则 w_s·ΔS − w_c·ΔC + w_n·ν_t(H′) > 0，其中 ν_t 只统计从未进入胜出路径的**结构性**组件类型（K_str={client_tool, skill, memory, subagent}；prompt/控制流/配置等编辑不获新颖性加分）。coding 实例取 w_s=0，意味着带内分数增益本身不能成为接受理由，候选必须靠省 token 或结构性新颖性挣得准入；agentic 与 engineering 实例用正 w_s。另有 DomainGuard 承载域特定检查。此分支的意义是把不确定性区域内的接受与“可解释的收益来源”绑定，防止把小幅随机波动当作证据。

**Lasso/L1 式结构剪枝。** 退火预算稀疏化每次更新，剪枝稀疏化保留的 harness 本身。定义 g_t(ℓ)=max{ΔS_i : ℓ_i=ℓ, t−t_i ≤ n_prune}（剪枝窗口 4/4/5 轮，跨多轮以免单次噪声裁定删除）；g_t(ℓ)≤0 的已测组件进入删除目标集 B_t，连同其曾接受的编辑一并交给提议器在后续提案中移除。机理：纯分数驱动的进化没有任何删除激励，机制必须持续“挣得位置”，否则复杂度只增不减；产出的是结构性稀疏而非整体变便宜。

### 3.3 超参校准的方法学立场

论文的超参设定三原则值得单独记录，因为它决定了结果的可信口径。**测量而非挑选**：δ 是未变 base harness 重复评估的离散度——coding 域 178 次 trial（89 任务×k=2）中 3 个 pass（δ=0.017）；agentic 域约 14,100 条判决定语中 60 条（δ=0.004）；engineering 域由半分割 null 的第一百分位读出 244 次 trial 中 5 个 pass（δ=0.020）。作者强调 δ 绝不可调：调低它等于用噪声买 evolve 分。**可归因性**：b_min=1、b_max=3–4（远低于约 80 的起草池）；w=3、n_prune=4–5 跨多轮又远小于 T。**对开局轮校准**：token 许可以基准计分单位表达——coding/agentic 每多 1 个 pass（或 100 条判据）许可 25% 额外 token，engineering 为 10%；由此导出 β₁ 数值（如 coding 域 1 pass=1/178≈0.0056 分数，25%/pass 对应 β₁≈44.5）。校准逻辑的示例：coding 域一个“值 7 个 pass”的候选获 10%+7×25%=185% 成本许可、实测 130% 被接受；一个只值 1 pass 的候选仅获 35% 许可、同样成本被拒。全部超参在运行前固定、无 sweep、从不接触 held-out 或 OOD 基准（各域 T=20/20/40 轮，k=2/2/4 次 trial）。

## 4. 实验结果

**设置。** 三域八基准：coding 域以 Terminal-Bench 2.1（89 个容器化终端任务、隐藏单元测试判定）为 evolve 集，SWE-bench Verified（fail-to-pass 全过且 pass-to-pass 不破）为 OOD；agentic workspace 域以 Harvey LAB（160 任务固定划分为 120 evolve + 40 ID held-out，每任务 20–100 条判据、全量评估约 14,000 条判决定语，Gemini-3.5-Flash 逐条独立评判）为 evolve 集，JobBench（Gemini-3.5-Flash 与 Claude Opus 4.8 双 judge 均分）、GDPval（185 任务、与人类专家交付物成对比较，三 judge panel：Qwen3.6-35B-A3B + Claude Sonnet 4.6 + Gemini-3.1 Pro，双呈现顺序、多数投票，每 judge 每 harness 204 次比较）、APEX-Agents（480 任务 pass@1，基础设施失败记 0 分不剔除）为 OOD；engineering design 域以 EngDesign license-free 子集 61 任务（各自冻结仿真器确定性判分；套件太小不做 ID 划分）为 evolve 集，Frontier-Eng（Medal Score：以 v1 冻结快照每任务前三优可行解为金/银/铜阈值，对应 1/0.67/0.33 记分取均值；47 任务中 38 个可构建环境者计分，两臂同分母）为 OOD。backbone 全程冻结 Claude Opus 4.8；提议器、跨轮失败分析器与泄漏审查器同为 Claude Opus 4.8。base harness：coding 用 Terminus-2，agentic/eng 用 MCP 工具网关上的 ReAct 循环、动态 toolbelt 与 ReSum 风格上下文管理。所有对比臂共享同一 H₀、策略、evolve 集与候选预算，且与 H₀ 在同一窗口评估以排除评测基础设施漂移。

九个 held-out split 无一回归（记忆型 harness 的典型失败模式）。三个 agentic OOD 绝对增益 3.5–4.7 点，相对 7.2%–13.1%；Frontier-Eng 相对提升 24.3%。论文另称 RRSI 在 OOD 环境上最高超出基线均值 12.5%（口径为 APEX-Agents：37.9 对四基线均值 33.7）。**判分器稳健性**：Harvey/JobBench/GDPval 均为 judge 评分，harness 理论上可以“按 judge 偏好写作”刷分；engineering 域关闭了该路径——确定性仿真器判分下增益不变，且测量中不含 judge 方差。

规律清晰：四基线在 evolve 集全部有效、ID held-out 彼此接近，分化出现在 OOD——evolve 集最强的 Meta-Harness 在 OOD 平均只 +0.9；HarnessX 与 H₀ 持平；AHE 与 TTHE 落到起点之下（TTHE 低 1.7 点）；RRSI 的 evolve 增益是所有进化臂中最小的，却是唯一 OOD 平均显著越过 H₀ 的（43.6 对 39.7）——这正是正则化器被设计去做的交换。

**策略鲁棒性与跨模型迁移。** coding 域独立用两个不同家族策略跑进化：Gemini 3.5 Flash 下 Terminal-Bench 64.6→78.7（+14.1）、SWE-bench Verified 76.8→79.0（+2.2）；Claude Opus 4.8 下 74.2→80.2（+6.0）、82.0→83.8（+1.8），强策略起点更接近天花板、空间更小但模式一致。更关键的是把用 Gemini 3.5 Flash 进化出的最终 harness 原封不动交给从未参与搜索的更弱 backbone Gemini 3.1 Flash Lite：Terminal-Bench 11.2→14.6（+3.4，相对 +30.4%）——机制不依赖搜索时的能力水平；绝对增益变小是因为弱 backbone 可及任务更少。这直接支持"harness 是程序而非权重附属物"的论断。

**成本与轨迹。** 在 agentic evolve 集上测量：每 trial policy token，H₀ 为 1.56M、RRSI 为 2.42M、四个先前方法为 2.69M–3.82M（AHE 3.82M，比 RRSI 多 58% 且 OOD 低 4.4 点），全部落在 RRSI 支配区域（更贵且 OOD 更差）；未正则化进化为 3.80M（摘要口径：RRSI 少用 30% policy token）。轨迹长度：H₀ 21.2 步，RRSI 26.3 步，先前方法 27.3–34.6 步。没有任何进化臂比 H₀ 便宜——进化确实在用测试时算力买增益，预算规则决定买多少。

**可靠性。** 两类不确定性分开回答。评估不确定性：任务级配对 bootstrap（10,000 次重采样、按任务而非 trial 重采样以正确处理 k 次 trial 的强相关），上表所有 CI 不含零。搜索不确定性：全量重复进化运行（同 H₀/evolve 集/策略/轮数/预算，仅提议器随机性重画）——OOD 平均 43.6 对 43.7，两 run 最大分歧 1.8 点落在 Terminal-Bench（evolve 集，搜索优化的唯一位置、随机性被放大处），其余八个 split 分歧 ≤0.6 点，均在 CI 之内：轨迹选择的随机性对最终分数的影响小于评估任务集本身的选择。

## 5. 消融要点

**正则器分组消融（agentic workspace 实例）：**

| 变体 | evolve | ID held-out | OOD Avg. | tokens/trial ↓ |
|---|---|---|---|---|
| H₀（不进化） | 89.4 | 86.9 | 39.7 | 1.56M |
| 无正则进化 | 92.8 | 88.9 | 40.3 | 3.80M |
| 去提案侧正则 | 90.7 | 88.8 | 41.9 | 2.69M |
| 去接受侧正则 | 91.5 | 88.7 | 41.0 | 3.59M |
| RRSI | 90.5 | 89.2 | 43.6 | 2.42M |

去接受侧约束使 evolve 分升至 91.5、OOD 跌至 41.0、token 涨约 48%（3.59M 对 2.42M）——无约束的选择规则把大部分被接受的编辑花在噪声与上下文堆叠上。去提案侧约束在 evolve 集几乎无代价（90.7 对 90.5）但 OOD 损失 1.7 点——即使什么都没被拒绝，引导搜索看向哪里本身就在起作用。两组全去的“无正则进化”拿到全场最高 evolve 分 92.8，OOD 却停在 40.3（距 H₀ 一点之内），成本 3.80M——这是“evolve 分数买到的是基准拟合而非机制”的最直接证据。

**规则触发路径的定性样本。** coding 第 0 轮两个表面相似的候选：R0-A 加入有界的提交前验证审计与非阻塞长任务轮询，+3.93 点且超出噪声带，被接受——大而确定的增益可以为较宽的早轮更新正名；R0-B 类似但 +1.69 点、+26.1% 成本，+1.69 恰落在 coding 域 δ=1.7 点的带内，而 w_s=0、ΔC 超 β₀，被成本规则拒绝。第 8 轮 R8-B 把原始任务指令钉进完成门（−2.81 分、−13.6% 成本）被下限拒绝——省 token 不能补偿跌破噪声调整下限。engineering 第 2 轮为反复出现的"workdir must be an existing directory"工具错误加入有界恢复提示，122/244→128/244 pass、+1.6% token，被接受——小而无任务特定性的控制流修复可以低成本保留。四个案例分别命中成本分支、带内分支、下限与低成本接受，展示门控体系各司其职。

**最终 harness 解剖（同 base harness、同 evolve 集同预算下的对照）。** Meta-Harness 累积的是一条 730 词的常驻 system message（item×维度覆盖矩阵），开头即重申“交付物按逐项 rubric 评分、仅读文件”——不含任务名，可通过任何关键词检查，但复述的是 evolve 集的评分方案：拟合 scorer 而非拟合工作本身，故 evolve 最好（93.0）而 OOD 仅 +0.9。TTHE 累积十个命名协议块共约 8,500 词，以 summarization-durable 方式常驻（永不被上下文压缩移除），其中约 1,000 词只在交付物为 redline/markup/tracked-changes 版本时适用——该交付物体裁是 evolve 集的属性而非 agentic 工作的属性，在无此体裁的基准上不触发却每 trial 支付上下文成本，最终低于 H₀ 1.7 点。RRSI 在 20 轮 32 个评估候选中只接受 4 个编辑，全部挂接进 base harness 原有的 pre-finalize bounce：一个覆盖/深度复查加三个标准库探针，读回刚写完的交付物并报告结构性事实（如算术速记未展开、某个源值未出现在任何已写文件中）——探针不携带 rubric 词汇或领域词汇，所以在 JobBench/GDPval/APEX 上照样触发。这一对照把“可复用机制 vs 基准拟合”的抽象区分落到了可审计的 diff 层面。

## 6. 贡献与启示

论文自述三点贡献：识别过拟合为 harness 级 RSI 的关键挑战；提出 RRSI，在保持全部组件可编辑的前提下正则化提案与选择两侧；在八基准三域上同时改善迁移与效率。从方法论层面看，更深的贡献有三处。其一，把“正则化”从参数空间移植到程序空间的**搜索动力学**：不收窄假设空间 Ω(H)，而约束转移规则——这对所有“LLM 提议-评估-选择”式代码/脚手架进化循环都是可复用的治理模板。其二，把自适应数据分析的统计担忧（holdout 复用、噪声追逐）翻译成可操作的工程机制：经验噪声带 δ（测量而非调参）、单调不降的 S★ 下限、七元组证据账本、非补偿性多门控选择。其三，成本被纳入一等公民（ΔC≤β₀+β₁·ΔS 与剪枝），使“自改进”产出的是可部署的 harness 而非测试时算力黑洞。局限也如作者自述：全程冻结 backbone、不涉及权重更新；依赖有限 evolve 集与若干超参，效果受反馈质量与搜索预算制约；对差异更大的 agent 架构、工具生态与更长程自改进过程的泛化待验证。

**与音视频技术上下游的关联。** 本文虽属 agent 系统方向，但其问题形态与治理手段对音视频工程侧有直接的迁移价值。(1) 音视频生产/分发链路正在 agent 化——自动转码与封装编排（FFmpeg 命令/滤镜图构造）、QC 规则配置（黑场、静音、音画同步）、ABR/QoE 调参、直播故障根因分析——这类 agent 的能力同样由 harness（工具描述、错误恢复控制流、日志上下文管理）放大。用有限的历史工单/QA 样本集自动进化此类 harness 时，样本集与线上真实内容/故障分布之间的差距就是论文的 evolve-OOD 差距：泄漏筛查防止把具体服务名/告警值写死进 harness，噪声带对应工单评分的主观波动，成本正则对应运维场景对推理时延与 token 预算的硬约束（无约束进化臂 3.82M tokens/trial 的 harness 在延迟敏感场景不可部署，RRSI 的 2.42M 且 OOD 更优给出了“可部署自改进”的代价-收益参照点）。(2) 论文 engineering design 实例的评测构造——冻结仿真器、确定性判分、Medal 阈值化——与以 VMAF/PSNR/率失真曲线为目标自动搜索编码参数和滤波器链的问题形态同构：在有限内容集上进化出的参数策略能否泛化到新码率段、分辨率与场景类型，正是同一类自适应过拟合，预算退火+证据账本+结构剪枝是现成的搜索治理组件。(3) GDPval 的“与人类专家交付物成对比较、三 judge 双顺序多数投票”协议，对主观质量评估自动化（与人工剪辑/调色/混音结果对比）有直接参照价值。(4) 反向缺口：论文基准不含多模态流式与长时序任务，K 词汇中的 context_mgmt 与 memory 组件在长视频理解、直播事件流持续上下文场景下的进化行为完全未验证，这是音视频侧可以反向供给实验场景的方向。

## 7. 与其他论文的联系

- **paper:arxiv:2611.10787（TRUST）**：与 RRSI 同治 RSI 的可靠性问题，但路线互补——TRUST 用在线多重假设检验为递归自改进提供错误进化率的统计保证，RRSI 用经验噪声带 δ、单调 S★ 下限与泄漏筛查做工程化保守接受。二者共同指向 Dwork 式 holdout 复用风险；RRSI 的下限可视为 TRUST 类检验的可部署近似，把统计保证换成可审计的门控流程。
- **paper:arxiv:2611.12109（SkillDuet）**：RRSI 的组件词汇 K 中含 skill，但其 skill 演化只发生在 harness 侧（skill 文件、权重冻结）；SkillDuet 以响应反馈把技能库演化与 LLM 参数更新耦合，恰好补上 RRSI 在 Limitations 中自述的“不处理权重更新”缺口。两者构成“只改外围 vs 外围与权重协同”的对照实验面。
- **paper:arxiv:2611.07319（WeightLoop）**：权重空间的递归自改进（有界参数编辑程序+实验反馈持续改写已部署权重），与 RRSI 构成“改什么”的正交对照。RRSI 的核心论点——泛化靠正则化搜索动力学而非收窄编辑空间即可保住——对权重空间 RSI 的过拟合治理构成可直接检验的假设。
- **paper:arxiv:2611.10463（LongCapHarness）**：同为冻结 backbone、靠 harness 挂接能力的路线（长上下文推理），其“免数据合成与后训练、成本低于基线 50%”的主张与 RRSI 的成本正则化精神一致；RRSI 的组件词汇中 context_mgmt 与其作用面重叠，且 RRSI 提供的 evolve/OOD 分离协议正是检验此类 auto-harnessing 结果泛化性的度量框架。
- **paper:arxiv:2611.14949（RSI-PDEbench）**：RSI 在 PDE 求解上的基准与框架；其 1001 案例、42 方程模板的划分正是 RRSI 主张的“进化/评估分离”前提。RRSI 的泄漏筛查与噪声带是控制该类领域 RSI 对特定方程模板过拟合的直接候选方案。
- **paper:arxiv:2611.11558（InfraRSI）**：RSI 用于训练基础设施优化的五阶段验证工作流，可视为选择侧正则的领域化实例（验证门控≈泄漏+噪声筛查）；RRSI 的 ΔC≤β₀+β₁·ΔS 接受条件对 infra 场景“验证开销 vs 收益”的权衡有直接参照意义。
- **paper:arxiv:2610.32026（RSI-Opt）**：元智能体跨训练运行演化优化器策略与代码库，与 RRSI 同属“LLM 提议-评估-选择”的代码级进化循环；其跨模型迁移主张与 RRSI 的跨 backbone 迁移实验（进化 harness 在未参与搜索的 Gemini 3.1 Flash Lite 上 +30.4% 相对）互为印证，RRSI 的证据账本与预算退火可缓解优化器进化对特定训练 run 的过拟合。
- **paper:arxiv:2610.32326（TGR-EvoDAG）**：DAG 式多智能体代码演化用于生成式推荐，泛化压力来自线上 A/B（离线管线→在线 CTR）而非 OOD 基准，但其离线-在线差距与 RRSI 的 evolve-OOD 差距同构；RRSI 的泄漏筛查与复杂度正则是离线进化阶段控制“拟合离线指标”的可用手段。
