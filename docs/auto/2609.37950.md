## 1. 背景与动机

长视频问答中，相关事件往往短暂、时间上远隔、且被视觉相似的干扰内容包围，因此智能体必须在“决定怎么答”之前先“决定看什么”。现有 video agent 通过迭代检索、时序导航与工具引导观察（VideoAgent、VideoTree、VCA、DVD、VideoSeek、MR.Video、LVAgent 等）完成证据获取。这些决策由一个**可执行 harness** 统一管辖：它控制证据采集、处理观察结果、支撑后续推理，同时决定了“模型看到什么”与“模型如何使用这些证据”，从而把答案精度与视觉观察成本直接耦合在一起。由此引出本文的核心立场：在不改动模型权重的前提下，改进这一可执行层本身就是提升视频理解的杠杆。

作者识别出 harness 自改进（self-improvement）面临的两个具体障碍，这也是全文方法设计的两个支点：

其一，**执行轨迹的证据不完备**。轨迹只记录当前 harness 已经获取的观察。同一个“关键事件缺失”的失败，可能源于采样空洞（事件落在被抽帧之间）、感知错误（看到了但认错）、或证据使用失败（观察正确但在推理链路中丢失了时序/实体关联）——三种诊断对应完全不同的代码修改，而轨迹本身无法区分它们。仅凭轨迹做修订，修订依据先天不足。

其二，**修复失败不等于产生更好的 harness**。更密的采样可能改善单题答案，却会在大量题目上抬高视觉成本；更好的证据复用则可能避免重复观察。自改进必须把“有证据支撑的失败诊断”与“修订后 harness 在完整执行上的精度与视觉成本评估”连接起来，否则改进不可积累。

定位上，本文处于三条线的交汇处：自动化 agent 设计（ADAS/AFlow/Meta-Harness 把 agent 程序当作优化空间）提供了程序级改进的对象选择；Self-Harness 证明了冻结模型可在终端环境修订自身 harness，Video-RSI 将此迁移到视频域并聚焦 Editor 可获得的证据；与最接近的 VideoHarness-RSI（演化上下文构造程序、按验证精度晋升候选）相比，本文差异有二——编辑前主动回看原视频检验失败解释，以及选择准则同时纳入视觉成本（允许有界成本增长换精度增益，或有界精度损失换成本下降）。

从音视频工程视角看，该问题天然处于 AV 技术上下游的交汇点：harness 的视觉成本以“帧”为单位计量，与视频解码/抽帧/推理预算直接对应；harness 上游消费 ASR 语音转录、OCR 屏上文字等 AV 处理服务，下游对接视频问答、检索与时序定位类应用。本质上是给视频分析系统加一个“计算感知的可进化控制层”。

## 2. 方法总览

形式化地，harness H 支配智能体的证据获取与使用：给定视频 V、带选项的问题 q 与固定模型服务 M，Solver 产出答案 ŷ、执行轨迹 τ 与资源记录 c，即 (ŷ, τ, c) = Run(H, V, q; M)。Editor 可联合修订的 harness 代码范围覆盖五类组件：prompt 构造、工具实现、观察处理、记忆、执行控制。这一划分强调证据采集与决策的耦合——即便观察正确，若在到达答题步骤前丢失时序或实体关联，仍会失败。

框架的运行形态：**同一冻结语言模型（DeepSeek-V4-Pro）同时充当 Solver 与 Editor**，视觉观察由 Qwen3.6-Plus 提供，全部权重冻结。每轮尝试中，Solver 先在训练问题上执行 H_t；Editor 检查轨迹并回看原视频检验失败解释，据此把 H_t 编辑为候选 H̃_t；候选与现任在私有选择集上按精度与视觉成本对比，通过门控则成为 H_{t+1}，否则保留现任。关键数据协议：训练集 D_tr 为 216 条 LVBench 问题（用于调查与修订），选择集 D_g 为另外 72 条与训练视频不重叠的问题，逐题结果对 Editor 保密，Editor 只获得聚合的精度与帧数反馈——这是防止 Editor 过拟合选择集的机制设计。共运行 20 次修订尝试，门控参数 α=0.1、β=0.2、ε=1/|D_g|。最终被接受的 harness 冻结后用于新问题评测。

需要强调两个口径：调查发生在**离线**阶段（额外观察只用于指导可复用的代码修改，不影响部署时的执行方式）；进化只在 LVBench 源上进行，向四个评测基准的迁移依赖修订本身的跨域泛化。

## 3. 关键设计

### 3.1 Active Video Investigation（编辑前主动取证）

这是本文区别于既有 harness 自改进工作的核心机制。Editor 检查训练结果、轨迹与代码，优先挑选“额外证据能够澄清”的代表性失败，然后构造**诊断查询**去区分竞争性失败解释。查询通过改变时序区域、采样密度、模态或感知问题来实现——例如更密的检查可以揭示短事件是否落在被抽帧之间。调查接口支持视频观察、语音转录、屏上文字，以及原封不动重跑现任 harness。查询循环形式化为：u_k = QueryEditor(I_k)，o_k = Investigate(u_k; H_t, D_tr, M)，I_{k+1} = I_k ∪ {(u_k, o_k)}，调查期间 H_t 保持不变。

新证据可能支持、反驳或悬置某个解释，从而重定向后续查询：若找到被漏看的事件，支持修订时序覆盖策略；若事件其实已被观察，诊断则转向其证据如何被表示和使用。调查终止于“有支撑的修订假设”或“无法进一步澄清的悬案”。从 AV 视角看，这一机制本质上是**按需二次取证**：对原视频做可变密度的重采样与多模态证据补采，用于区分“没看到 / 看错 / 没用好”三类失败——这是仅靠日志回放做不到的。

一个关键的防泄漏约束：诊断阶段允许使用训练标注来定位信息区间，但最终修订必须只依赖 Solver 在新问题上可获得的线索——即修订后的代码不能预知答案或事件位置，诊断只负责把失败连接到“如何在未知答案与位置的前提下找到并使用证据”的程序。

### 3.2 Diagnosis-guided Revision（诊断引导的代码修订）

Editor 把诊断映射为代码修改，需明确修改的适用条件与必须保留的成功行为。由于五类 harness 组件相互依赖，一次可复用的修改可能要求工具输出与消费该输出的代码**协同编辑**（例如改变检查线索的同时，保持观察与记忆中的时序关联）。Editor 可在训练侧试运行调试候选，这与编辑前的调查是分开的活动，之后才提交候选进入选择。

### 3.3 Cost-aware Selection（成本感知门控）

视觉成本定义为：完整问答执行中，**成功视觉模型调用所处理的平均帧数**（按题平均）。采用端到端口径的理由在论文中表述得很清楚：一个更精细的工具可能减少后续观察，而一个局部有用的修复可能推高整体视觉用量——只有完整执行口径才能捕捉这种替代效应。

门控规则为双分支 Pareto 准入（α≥0 界定相对成本增长上限，0<β<1 为要求的相对成本降幅，ε≥0 界定精度损失容忍）：

- 分支一（精度增益 + 有界成本增长）：ΔA_t > 0 且 C̃_t ≤ (1+α)·C_t；
- 分支二（成本下降 + 有界精度损失）：−ε ≤ ΔA_t ≤ 0 且 C̃_t ≤ (1−β)·C_t 且 C_t > 0。

实验取 α=0.1、β=0.2、ε=1/|D_g|，即成本下降分支最多容忍少答对一题（72 题选择集）。g_t=1 则候选接任，否则保留现任。这个双分支设计有一个重要的动态含义：它不要求每步更新都降帧，允许后期修订为换精度而有界地上浮帧数，只要相对初始状态保持净效率优势——这一点在演化动态分析中得到了验证。

对照两个同模型复现基线的量化结论：

- **对 VideoHarness-RSI**：每个基准精度更高且帧数更少。精度增益在 Video-MME 最大（80.0 vs 69.7）；EgoSchema 精度接近（78.2 vs 78.0）而帧数 42.4 vs 66.8。

## 5. 消融要点

四个变体共享训练样本、标注访问、初始化、模型与每次尝试的资源上限，仅在“编辑前能否获取新视频观察”（主动调查 vs 仅轨迹）与“选择准则是否含视觉成本”（双分支门控 vs 仅精度）两个维度上变化。

| 变体 | MLVU Acc/Frames | LVB Acc/Frames | Video-MME Acc/Frames | EgoSchema Acc/Frames |
|---|---|---|---|---|
| 初始 harness | 62.4 / 68.5 | 67.7 / 51.6 | 73.4 / 38.6 | 71.4 / 66.0 |
| 仅轨迹修订 | 64.7 / 60.3 | 67.2 / 43.1 | 73.7 / 28.5 | 76.6 / 51.8 |
| 仅精度门控 | 67.1 / 81.9 | 69.5 / 66.4 | 74.9 / 43.1 | 77.4 / 60.5 |
| **Video-RSI** | **72.9 / 61.1** | **71.1 / 41.1** | **80.0 / 21.6** | **78.2 / 42.4** |

- **主动调查的贡献**：终态精度在四个基准上全部高于仅轨迹修订；MLVU 增益最大（+8.2pp，72.9 vs 64.7）且推理帧数相近（61.1 vs 60.3）——即离线阶段的额外取证转化为部署行为的质量提升，而非推理时观察量的增加。机制侧佐证：带调查的运行在 20 次修订中保留了 5 次，仅轨迹修订只保留 3 次，轨迹外证据直接提高了修订命中率。
- **成本感知选择的贡献**：仅精度门控较初始 harness 四基准精度均升，但三个基准帧数上升（如 MLVU 81.9 vs 初始 68.5）；完整 Video-RSI 在每个基准上同时做到精度更高、帧数更少，Video-MME 帧数约为该变体一半（21.6 vs 43.1）。结论：只按精度选保留会系统性积累昂贵行为，双目标选择能以零精度代价保留效率。
- **演化动态**（MLVU 评测为进化完成后回溯进行，未参与选择）：开发集上第一个被接受修订贡献了绝大部分帧数净下降，其后修订持续提升精度、帧数小幅非单调变化。MLVU 轨迹揭示了选择集与真实迁移的偏差：首个被接受修订在开发集两指标均改善，却降低了 MLVU 精度；下一修订恢复，最后两个被接受修订贡献了大部分净 MLVU 精度增益。从 HS2 起MLVU 精度与帧数同步上升，但终态仍同时优于 HS0——与门控“允许有界成本上浮换精度”的设计一致，也说明早期开发集增益不足以预测最终评测行为。
- **演化产物剖析**（对比初始 harness 与被保留修订得到三类变化）：HS2 引入**结构化感知**，自由文本视觉响应改为目标导向的结构化发现，含图像引用与显式不确定性，并把图像引用映射到帧时间戳，保持发现与其时间证据的锚定；HS3 的 **Global-64 路线**对选定的整视频问题将 32 帧初始概览扩至 64 帧；HS4 的**关系图**从累积的视觉/转录/OCR 观察中抽取实体、事件与关系，对合用的关系/时序问题返回证据缺口以引导进一步检查，且图查询本身不处理新帧——证据组织成为观察与再采样之间的零帧中间层；HS5 的**出现次数工具**定义计数单位、验证候选事件并合并重叠证据以避免重复计数。终态 harness 在四基准上较 HS0 少用 10.8%–44.1% 的帧。
- 口径提醒（论文原文明示）：上述节省只计视觉帧，不代表总模型计算量。

## 6. 贡献与启示

论文自述三点贡献：冻结权重下由同一 LLM 担任 Solver/Editor 的视频 harness 自改进框架；连接主动视频调查、诊断引导修订与精度-成本选择的改进闭环；四基准评测加调查/演化动态分析。

对音视频技术侧的工程启示更为实质：

1. **帧预算成为与精度并列的一等进化目标**。视觉帧数是视频服务推理成本与延迟的直接代理指标，双分支门控（有界成本增长换精度 / 有界精度损失换成本）是一套可移植到任何成本敏感媒体 agent 自改进流程的准入模式；配合“逐例结果保密、仅聚合反馈”的评测协议，可直接复用于生产环境的线上 harness 迭代。
2. **证据组织被显式定位为零帧中间层**。HS4 的关系图把视觉+ASR 转录+OCR 的多模态观察索引化，在“再采样”之前先做图查询——这与 AV 系统中多模态索引/检索层的功能同构，且演化自发地产生了这一架构，说明其成本收益在长视频场景是结构性的。
3. **结构化感知接口的时间戳锚定**（图像引用→帧时间戳）把感知输出与视频时间轴绑定，兼顾了后续推理的靶向追问与证据回溯审计，对下游时序定位、可解释视频分析有直接参考价值。

局限与开放问题（均依据原文可查证的表述）：成本口径不含离线调查的帧开销与 Editor 的 LLM 开销（明示排除），即自改进过程自身的总拥有成本未报告；选择集仅 72 题，ε 粒度为一题，门控无统计显著性控制，演化动态中“开发集改善但 MLVU 退步”的实例即为小样本噪声的直接证据；进化源只有 LVBench 216 题，跨域迁移依赖修订的泛化性，论文未验证第二进化源；20 次尝试仅 5 次被接受，修订的样本效率仍有明显空间。

## 7. 与其他论文的联系

- **Flex-RSI（arXiv:2611.08946）**：Flex-RSI 在固定预算下评估前沿智能体通过递归修订 harness 在视觉与机器人任务上的自我改进能力，Video-RSI 正是其所评估的方法类型的视频域实例。二者共享“harness 修订即自改进载体”的前提；Flex-RSI 的固定预算评估视角与 Video-RSI 的帧预算门控互为印证，Video-RSI 类方法可自然成为 Flex-RSI 的被测对象。
- **LongCapHarness（arXiv:2611.10463）**：在文本长上下文推理上以递归自改进方式挂接冻结 LLM 的底层能力，免数据合成与后训练即在 HELMET/RULER 超越基线且成本低于其 50%。与 Video-RSI 构成跨模态平行工作：同为冻结模型 + harness 进化路线，同报“精度提升伴随成本下降”，说明 harness 级 RSI 的精度-成本双赢不是视频域特例。
- **The RSI Tax（arXiv:2611.13524）**：提出 RSI 税以度量自我改进的全成本，发现简单有界笔记基线在精度持平时比三种 RSI 方法省 65.6–71.0% 总 token。这正指向 Video-RSI 的口径缺口：其帧数指标明示排除离线 Editor 调查观察，进化开销（调查帧 + Editor 调用）未计入报告，按 RSI 税的框架应补全总成本核算才能判断 harness 进化相对轻量基线的净收益。
- **TRUST（arXiv:2611.10787）**：用在线多重假设检验为 LLM 智能体递归自改进控制错误进化率并提供统计保证。Video-RSI 的门控建立在 72 题私有选择集上、ε=1/72 粒度，且实验中已出现选择集改善而 MLVU 退步的噪声实例；TRUST 式统计校正是对其接受/拒绝决策的直接加固方向。
- **SimplEvo（arXiv:2611.11509）**：具身智能体用自写文本记忆与教训精炼实现免权重自改进（EBench 成功率 46.7%→81.7%）。与 Video-RSI 同属权重冻结的自我改进，差异在积累介质：自由文本记忆 vs 可执行代码——代码修订可回归测试、可门控验证，但编辑与验证成本更高，二者构成“记忆演化—代码演化”的谱系两端。
- **SkillDuet（arXiv:2611.12109）**：以响应反馈协同 LLM 参数更新与外部技能库演化，实现技能级递归自改进。Video-RSI 是其严格冻结权重的对照面：改进只落在 harness 代码；SkillDuet 的权重-技能协同结果提示，Video-RSI 演化出的 harness 组件（结构化感知、关系图、计数工具）可视为候选技能库条目，是两种路线的潜在接合点。
