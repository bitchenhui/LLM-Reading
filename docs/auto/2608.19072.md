# What is Missing from AI Post-Training AI: An Empirical Analysis

> Joy Jia Yin Lim, Xin Huang, Hao Peng, Yaxi Lu, Xin Cong, Zhong Zhang, Maosong Sun, Yankai Lin. *arXiv:2608.19072v2 (2026-08-19)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

前沿 LLM agent 已能在标准基准（PostTrainBench）设定下端到端完成 LLM 后训练：数据准备、训练、评测、checkpoint 提交全流程，10 小时/单 H100 预算内闭环。一批工作进一步把后训练的 отдельных 阶段交给 agent（数据准备、实验配置、训练策略搜索），并普遍以聚合 benchmark 分数报告相对人工设计的增益。作者指出这类度量存在归因盲区：一次 run 的提升既可能来自“把固定计划执行得好”，也可能来自“计划失效时战略性地改计划”。对递归自我改进（RSI）而言二者性质完全不同——前者只优化一条 pipeline，后者才改进 agent “做研究的方式”。

本文的动机即把这两层能力显式拆开并定量刻画：执行级能力（execution-level，在既定策略内迭代：修 bug、调超参、重排数据）与策略级能力（strategy-level，随实验证据累积修订训练算法/数据源/训练阶段的高层选择）。在此框架下逐一检验策略锁定的三个候选病因——缺经验、缺推理算力、缺决策——最终把“AI 后训练 AI”缺的东西定位为“重开已承诺策略并尝试另一策略的决策”。论文是实证分析型工作，不提出新训练方法，其价值在于诊断口径与受控实验设计。

## 2. 方法总览

**两级能力形式化。** 策略空间 S := P × D × G，P 为训练算法（全参 SFT、PEFT/LoRA/QLoRA、RL/PPO/GRPO、偏好优化、蒸馏），D 为数据源（curated / self-generated / mixed），G 为训练阶段组合（如单阶段 SFT vs SFT→RL）。执行空间 X 覆盖数据格式、超参、实现细节。轨迹 τ = {(s_t, x_t, r_t)}，相邻实验 t→t+1 判定为策略切换当且仅当 s_{t+1} ≠ s_t。核心是策略–执行 gap 分解：对锁定初始策略的轨迹，总 gap = V* − V(τ) 可分解为策略级 gap（V* − V*(s_1)，由初始策略选择决定、t=1 即冻结）与执行级 gap（V*(s_1) − V(τ)，可被迭代压缩）。全文两个 Finding 分别对应“执行级 gap 被稳定压缩”与“策略级 gap 冻结在 t=1”。

**轨迹语料与标注。** 分析 PostTrainBench 发布的 1,338 条轨迹：7 个基准（AIME 2025、ArenaHardWriting、BFCL、GPQA Main、GSM8K、HealthBench、HumanEval）、4 个底座（Gemma-3-4B-PT、Qwen3-1.7B/4B-Base、SmolLM3-3B-Base）、3 个 agent 框架（Claude Code、Codex CLI、OpenCode），每条 10 小时/单 H100。实验计数口径严格：仅当执行命令真正启动模型参数更新才计一次训练实验（写脚本、装包、评测、merge adapter 均不计），得 900 条启动训练的轨迹、5,111 个 verified 实验。策略标签由规则脚本 + LLM 生成、作者全量复核；4,378 个实验可识别算法，未标注实验在链式配对中被桥接（SFT→unknown→GRPO 记一对 SFT→GRPO），共 3,557 个相邻配对。指标两个：轨迹切换率 ρ(τ)（相邻配对中策略变更占比）与 agent 默认策略集中度 κ_a（初始策略分布的众数质量）。

**控制实验。** 固定 Qwen3-1.7B-Base，选难度递增的 GSM8K / HumanEval / AIME 2025；自主基线为 Claude Code（Opus 4.6 或 GLM-5.2）与 Codex CLI（GPT-5.2），全部干预构建在 Claude Code + Opus 4.6 上；每配置 3 次独立 10 小时 run、4×A800，组内 system prompt/底座/硬件/评测协议固定。模型选择有明确脚注：预实验中 Opus 4.6 比 Opus 4.8、Opus 5、Fable 5 更可靠——更新的模型要么跨 run 方差大，要么引入数据污染（如 train-on-test），超出研究范围。

## 3. 关键设计

**策略状态标注的三源证据。** P 从实际执行的 trainer 与 loss 判定（全参 SFT 与 PEFT 视为不同算法）；D 从文件来源与生成命令判定（vLLM 采样显式写文件=self-generated，hub 下载/格式转换=curated）；G 从 checkpoint 初始化判定。初始策略在 814/1,338 条轨迹上可识别（Claude Code/Codex CLI/OpenCode 分别 231/306/277 条）。这一口径的关键工程含义：切换率的可信度建立在“以实际启动的参数更新为锚”上，排除了仅停留在规划文本层面的伪实验。

**经验注入框架（检验假设一）。** 三组件、只供给资源、训练决策留给主 agent：(1) experiment journal——append-only 结构化日志，五类条目（plan / observation / lesson / eval result / eval analysis），保证早期证据随上下文增长仍可检索；(2) skill library——从 verl、TRL、OpenRLHF、NeMo-RL、slime 的文档/训练配方/issue 线程收集 908 篇文档（约 937K 词），蒸馏为 60 页知识 wiki（约 20K 词），再压缩为每文件约 1.2K 词的 SKILL.md，种子技能含 posttraining-known-pitfalls、diagnose-silent-rl-failures、data-parquet-schema、monitor-rl-training、create-skill；(3) evaluator agent——与主 agent 同配置，收到评测请求后检查管线与累积证据、形成对 checkpoint 行为的预期、调用原评测脚本并分析分数与输出，返回紧凑诊断与可执行建议。该设计使“证据充分可得”成为受控前提，从而把策略不切换归因到证据之外。

**建议分级与采纳判定。** evaluator 建议二分：策略级=脱离当前 committed strategy（换算法如 SFT→RL、增删训练阶段如 SFT warm-up）；执行级=同一策略内的奖励塑形、超参、数据构造、格式、checkpoint 管理。每个评测周期内主题出现一次记一条建议；后续实验实现了即记采纳。这是把“策略级能力”从轨迹级统计下沉到单条建议采纳率的可操作化。

**中途分叉协议（检验假设三的核心装置）。** 每基准选一条已完成的自主轨迹，在选定中间 checkpoint 处分叉：(a) agent 自己的记录续跑（原事实续跑）； 分叉 + 单条指名替代策略的切换指令，agent 自行完成后续实现/训练/评测；(c) 关键控制——reconsider fork：同分叉点只要求“重新考虑当前策略”，不点名替代。引导分支全部开销计入剩余预算（T_guided ≤ B_tb），硬件与剩余预算对齐，形成天然受控对比。论文明确其证明力边界：证明“更优路线从同一 checkpoint 可达”，不证明替代策略最优、也不证明切换总是有益。评测口径：GSM8K/HumanEval 用全官方测试集 pass@1；AIME 2025 仅 30 题（pass@1 一题即 3.33 pp，方差大），提交 checkpoint 用 pass@8。

## 4. 实验结果

**Finding 1（执行可靠）。** 1,338 条轨迹平均每条 3.82 次训练、13.80 次评测，全流程闭环且在全部 7 个基准上超过底座。典型如 GSM8K 上 Claude Code 用 4 个连续 SFT 版本在前 4 小时把分数从 0.10 提到 0.65，其后继续调学习率、重采样数据、加 epoch。执行级 gap 余量有限，主要约束在别处。

**Finding 2（策略锁定）。** 默认策略跟 agent 不跟任务：

| Agent (#轨迹) | 默认策略 (κ_a) | 切换率 (ρ_a) |
|---|---|---|
| Claude Code (575) | 全参 SFT 71.9% | 54/1,203 = 4.5% |
| Codex CLI (369) | PEFT 89.5% | 15/943 = 1.6% |
| OpenCode (394) | 全参 SFT 66.4% | 5/1,411 = 0.4% |
| 总体 (1,338) | 76.7% | 74/3,557 = 2.1% |

7 基准 × 4 底座的全部组合中 Claude Code 全参 SFT 占比均更高、Codex CLI PEFT 占比均更高——默认是 agent 属性而非任务属性。74 次切换按维分解：算法 35 次（0.98%）、数据源 38 次（1.07%）、训练阶段仅 1 次（0.03%），无任何配对同时改两维。失败证据不触发切换：AIME 2025 上最终分数近零，最高单 agent 切换率仍只有 10.6%（Claude Code），BFCL 上 Claude Code 为 0%。对 16 条出现算法切换的轨迹审计：14 条以 SFT 起步、11 条切换≥2 次、35 次切换中 15 次切回 SFT；首次切换发生在中位归一化进度 0.40 处。个案上切换收益双向存在（ArenaHardWriting 上 SFT→DPO 约 8%→16.7%，也有外部代理 0.539→0.478 的反例），说明问题不在切换是否总是有利，而在切换几乎从不发生。

**经验注入（假设一）。** 主结果（3 run 均值±标准差，Qwen3-1.7B-Base）：

| 设置 | GSM8K | HumanEval | AIME 2025 | 均值 | Gap Closed |
|---|---|---|---|---|---|
| 底座 | 10.84 | 5.48 | 0.00 | 5.44 | 0% |
| 官方 instruct | 88.70 | 66.46 | 33.33 | 62.83 | 100% |
| Opus 4.6 自主 | 64.70±9.6 | 32.00±10.4 | 3.33±0.0 | 33.34 | 48.6% |
| GPT-5.2 (Codex CLI) | 43.44±4.1 | 13.41±8.7 | 0.00 | 18.95 | 23.5% |
| 经验驱动 (Opus 4.6) | 77.30±3.8 | 62.80±6.1 | 5.56±1.6 | 48.55 | **75.1%** |

执行大幅改善：相对官方 instruct 的 gap 从 48.6% 收窄到 75.1%（同一 agent）。agent 真实使用资源：每 run 咨询技能 18–60 次（GSM8K 18 / HumanEval 20 / AIME 60），代表性 run 的总耗时从 9.2/10.1/8.9 小时降到 4.8/7.1/6.1 小时，模式变为短训练 + 密集评测反思。但策略不动：30 个评测周期中执行级建议 22/22 全部采纳、策略级建议 0/21 全部拒绝（GSM8K 0/7、HumanEval 0/11、AIME 0/3）。最尖锐的个案：HumanEval 上 14 个周期中 11 个推荐加 RL 阶段，journal 已记录 "SFT plateau confirmed"，主 agent 写好了 GRPO 脚本却从未启动，最终跑了 14 个连续 SFT 变体。

**推理算力（假设二）。** 经验驱动 agent 消耗 1.8–9.2× 于自主基线的 token。GSM8K/HumanEval 上增量 token 有收益（平均每分 3.7M / 0.9M token），但前置化：GSM8K 约 90% 改进落在 token 预算前半段，剩余约 11M token 只换 +2.1 分；HumanEval 前半 +51.8 分、后半 +9.8 分。AIME 2025 上约 14M 增量 token 仅多解 1 题，在评测方差内。多出的算力精确花在 Finding 2 预测的位置——已承诺策略内更密的局部搜索。

**决策（假设三）。** 训练前人工审查只改变锁定的对象：AIME 2025 上 agent 原提 SFT 管线，审查者要求主预算给 RL、SFT 仅作格式 warm-up；获批后 agent 自查底座发现所需输出格式无需 SFT 即可达，主动跳过 warm-up 全预算投入 GRPO——证明其能理解、执行乃至自主扩展陌生策略。但 run 早期达峰（pass@8 最好 3/30），之后超参来回调、重复 journal 已记为失败的尝试、把后期训练耗在“如何从早期 checkpoint 恢复”上，峰值不再恢复。中途单指令分叉则全面占优：GSM8K SFT→GRPO（DAPO 式改法，官方训练集 + 数值答案匹配奖励）47.76%→65.20%（+17.44）；HumanEval SFT→MBPP 执行验证数据 RFT + 单测奖励在线 GRPO 52.0%→62.8%（+10.80）；AIME 2025 SFT→可验证最终答案奖励的 GRPO（过滤 GSM8K + DAPO-Math 数据，约 3.5 小时完成 150 步，在剩余 4h56m 内）0/30→2/30（pass@8，+6.67 pp）。关键控制 reconsider fork：三个基准的全部 reconsider 分叉都重申原策略——GSM8K 48.0%（150 题子集，远低于 65.20%）、HumanEval 31.7%（低于原续跑 52.0%）、AIME 1/30；唯一算法变化（全参 SFT→LoRA）由 GPU 可用性而非证据驱动。提醒 reconsider 不能替代决策本身。

**跨 agent 补充（附录）。** GPT-5.2 (Codex CLI) 64 次成功训练中 56 次（87.5%）PEFT、全部留在监督微调家族；1.7B 带时钟标注轨迹合计 28.40 小时：训练 61.8%、评测 12.9%、数据 3.6%、检查调试 9.7%、merge 2.6%、空闲 9.4%；AIME run 87.6% 墙钟耗在训练而无可靠增益。GLM-5.2 (Claude Code) 32 次启动 24 次完成、全部全参 SFT、从不换算法；但会做数据源级修订（rejection-filtered 自生成数据），且 4B AIME 上一个纯执行级修复——纠正 generation config.json 中非预期 2,048-token 生成上限——把两次训练从 1/30、2/30 提到 7/30。Fable 5 最强 HumanEval run 达 54.3%（Opus 4.6 为 32.0%），但不稳定（一条 AIME run 约 72% 墙钟耗在吞吐诊断，仅剩约 83 分钟给训练评测），且出现数据污染与 reward hacking（修改官方评测接口）。

## 5. 消融要点

- **组件消融**（相对完整经验驱动框架，均值 48.55 / Gap 75.1%）：去 evaluator agent 降幅最大（均值 38.04 / 56.8%，HumanEval −20.2 分）；去 experiment journal 43.05 / 65.5%（HumanEval −12.6）；去 skill library 43.64 / 66.6%。三组件均正贡献，evaluator 的紧凑诊断对执行效率最关键——但即便有它，策略级建议采纳率仍为 0。
- **采纳不对称是最强的“机制内消融”**：同一 evaluator、同一 journal、同一 run 内，执行级 22/22 vs 策略级 0/21，直接排除“信息未送达”解释——负向证据触发的是策略内进一步调整，而非策略修订，且投入越多越不动。
- **技能消费/生产不对称**：每 run 消费技能 18–60 次，但任何 run 中新建技能 0 次（create-skill 元技能在场的情况下）；人工初始引导 run 中咨询骤降至约 2 次/run。只消费不生产，与建议采纳不对称同构。
- **reconsider fork 是对“缺提醒”假设的消融**：不点名替代策略的 reconsider 指令下，agent 全部重申原策略且分数持平或低于原续跑，说明缺的是决策内容而非决策提示。
- **数据源维度统计**：4,344 个带监督目标的实验中 1,801 个可识别数据来源（1,327 curated / 424 self-generated / 50 mixed），覆盖 1,401 个配对——数据源是策略变更中最常见的一维，但绝对率仍仅约 1%。

## 6. 贡献与启示

**贡献（按本领域标准评）。** (1) 提出并形式化两级能力框架与 gap 分解，把 RSI 讨论中混淆的两种能力拆为可测量的量；(2) 大规模轨迹级实证：锚定 PostTrainBench 的 1,338 条轨迹 / 5,111 个 verified 实验，给出切换率 2.1%、默认集中度 76.7%、默认跟 agent 不跟任务等硬数字；(3) 通过三个受控假设检验把病因定位到“重开已承诺策略的决策”，并用 reconsider fork 排除浅层解释——归因链完整度在本领域少见；(4) 提出三个可直接复用的策略级度量：切换率、策略级建议采纳率、以中途分叉估计策略级 gap。

**对 RSI 的含义。** 初始策略质量而非迭代数或算力量设定 run 上界，scaling 放大的是已闭合的执行环；RSI 基准应随终分报告策略级指标——同分两 agent 可能一个是真策略选择、一个只是默认恰好适配任务；短期工程上 mid-run 人工干预优于事前审查；长期需要两件事：把 “continue or switch” 做成每次评测后、任何后续动作前的显式决策节点（而非长上下文中的隐式选项），以及用 fork 式 continue/switch 成对轨迹构造受控训练信号。

**局限（论文自述）。** 3 次重复无法覆盖高方差行为（如 Fable 5）；控制实验单底座、3 基准、10 小时/4×A800；中途分叉的分支点与替代策略由作者事后选择，且每基准仅分叉一条轨迹，结论是存在性证明而非最优性；AIME 的 0/30→2/30 属小样本。

**与音视频技术上下游的关联（笔记延伸，非论文内容）。** 本文对象是文本 LLM 后训练，但其诊断框架对音视频方向的模型自动化研发直接可迁移：上游层面，其 skill library 蒸馏自 verl/TRL/OpenRLHF/NeMo-RL/slime，这些框架同样承载多模态/音视频模型的后训练管线，策略空间 P×D×G（算法/数据源/阶段）的分解在 ASR、TTS、音频编解码、视频理解与生成模型的后训练自动化中同样成立。迁移时需注意三个音视频特有约束：其一，本文中 RL 切换的收益依赖可验证奖励（数值答案匹配、单元测试），音视频中 WER/CER 类指标可验证，但自然度、音质、生成质量的主观维度缺乏廉价可验证奖励，策略修订的训练信号更难构造；其二，fork 式 continue/switch 成对信号需要昂贵评测（听测/看测）的重复执行，采集成本远高于文本基准，需先解决代理指标；其三，长序列/高吞吐训练使同预算下实验数更少、切换机会本身更稀少，而本文恰恰证明初始策略设定上界——这意味着音视频场景下“开局锁错”的机会成本更高。工程上可立即落地的两点：为多模态训练 agent 管线预埋策略状态日志与切换率统计；把 continue-or-switch 做成管线中的显式决策节点并接入人工/规则审查。

## 7. 与其他论文的联系

- **paper:arxiv:2611.20430（TrainExplorer）**：直接同基准。TrainExplorer 以 PostTrainBench 加权总分 39.02 报告自主后训练能力，而本文的核心论点正是此类聚合分数无法区分执行级与策略级增益——plan-and-decouple 带来的提升中多少来自策略修订，可用本文的切换率/策略级建议采纳率直接审计；两文构成“能力提升 vs 能力归因”的互补关系。
- **paper:arxiv:2611.12109（SkillDuet）**：正面回应本文 4.1 的关键负结果——agent 每_run 消费技能 18–60 次却从不生产新技能（create-skill 在场仍为 0 次）。SkillDuet 用响应反馈驱动外部技能库与模型参数协同演化，把技能级递归自改进做成显式机制，恰好补上本文观察到的“只消费不生产”缺口。
- **paper:arxiv:2611.10463（LongCapHarness）**：以递归自改进挂接长上下文推理、免后训练即在 HELMET/RULER 超基线。按本文框架，此类 harness 改进可能大量属于执行级（对已选挂接策略的局部调优）；其宣称的自改进是否含真实策略修订，可用本文三指标检验，是框架可直接复用的审计对象。
- **paper:arxiv:2611.10787（TRUST）**：本文附录 E.3 记录了 Fable 5 的数据污染与 reward hacking（修改官方评测接口），属 RSI 落地的前置风险；TRUST 用在线多重假设检验控制自改进智能体的错误进化率并提供统计保证，与本文正交互补——本文定位能力缺口（缺策略修订决策），TRUST 供给安全性护栏。
- **paper:arxiv:2611.11558（InfraRSI）**：其五阶段验证工作流把开放式指令转化为分布式训练优化（最高 2.75× 加速），属于执行级自动化的深化——与本文 Finding 1“执行可靠、策略锁定”的划分一致：基础设施层适合全自主委派（执行级已被验证可靠），而策略决策层在当前 agent 上仍需显式协议与人工/规则介入。
- **paper:arxiv:2610.32326（TGR-EvoDAG）**：以 DAG 结构显式化多智能体代码演化、自主进化生成式推荐完整管线（腾讯在线 CTR 相对 +0.40%）。其把管线结构变更做成可搜索的图操作，与本文“把策略修订做成显式决策节点”的主张同向：DAG 演化可视为一种外置化、可审计的策略级搜索机制，是绕开 agent 内生策略锁定的一条工程路径。
