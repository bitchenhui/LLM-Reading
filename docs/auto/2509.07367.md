## 1. 背景与动机

SAT 是 Cook（1971）首证的 NP 完全问题，也是硬件验证、软件分析、规划与密码学的共同后端。三十年工程脉络——DPLL、CDCL、two-watched literals、动态重启、子句删除、有界变量消去、vivification——造就了能处理工业级实例的现代求解器；SAT Competition（2002 年起）是事实上的严格基准平台。但手工设计已进入边际收益递减区：设计空间由数百个参数、启发式变体与算法创新及其组合构成，直觉驱动的人工导航成本极高、门槛极高。

LLM 编码智能体带来了新变量：AlphaEvolve 证明了“提案—评估”自主循环可超越人类专家，但对象限于自包含算法 kernel（单文件、数百行、加速器上评估）；Sun et al. 对 SAT 求解器启发式模块的 LLM 自动优化同样停留在 kernel 级。真实求解器是数百文件、上万行 C/C++ 的多组件系统，要求启发式整合与严格正确性保证——从“一次性代码生成”到“进化式智能体管理整个仓库”，是本文瞄准的缺口。

SATLUTION 的核心主张：仅以 SC2024 的求解器代码库与基准为训练环境，LLM 多智能体在严格正确性约束与分布式运行时反馈下演化整仓求解器、并同步自演化其策略规则，产物在 SC2025 官方基准上超越人类冠军（且在 SC2024 基准上同时超过 2024/2025 两届冠军）。对音视频技术侧的定位：SAT/CDCL 求解器是 EDA 形式验证（等价性检查、模型检查）的内核，处于编解码 ASIC、NPU、ISP 硅前验证链的上游；同时“仓库级演化 + 形式化验证锚点 + 集群评测”这一范式对音视频侧的大型性能敏感 C/C++ 仓库（编码器、转码栈）具有直接的方法论参照价值，后文第 6 节展开。

## 2. 方法总览

架构为双智能体闭环：Planning Agent（周期 0 分析 SC2024 代码库与性能、提出修改方向；后续周期基于累积变更、性能指标与失败记录制定下轮演化计划）+ Coding Agent（直接编辑仓库、维护 Makefile、修编译错、调试功能性失败与段错误），由 Cursor 环境承载，两个 Claude 模型分工。规则系统按阶段组织（planning、C/C++ 编程规范、评估前验证、评估后奖励分析、长期知识学习），支持 always/自动挂接/手动触发三级作用域，配合分层 token 缓存与文件索引支撑长程演化而不撑爆上下文。整体循环为 Generate→Compile→Test→Analyze & Reason→Evolve，采用 Champion/Challenger 模型：成功的挑战者替换冠军。

初始化设定：五个 SC2024 种子求解器（kissat-sc2024、kissat-mab-dc、kissat-mab-binary、BreakID-Kissat、AMSAT；作者按对求解器实现的有限内部知识与官方 2024 结果选取），全部代码库同时暴露以支持互补策略杂交（含 BreakID 对称破缺预处理器）。硬约束：单线程 C/C++、禁外部库与非标准 API、显式禁止 portfolio/并行求解器构造（严格满足竞赛 sequential 赛道要求）。每个变体强制目录结构（SATLUTION_x 下 bin/ 含可执行与 starexec_run_default、src/、build/、顶层 starexec_build），并以 HYPOTHESIS.md（拟议修改与性能预期）、CHANGELOG.md（实际改动）、RESULTS.md（评估结论）三份强制文档实现谱系与推理可追溯。

相对 AlphaEvolve 的定位差异（论文表 1）：演化对象从单文件/数百行升级为整仓/数百文件/数万行；评估从加速器数小时升级为分布式 CPU 集群 + 领域形式化证明验证；搜索预算从千级 LLM 采样收敛为数十个迭代周期；并新增人工设计的 verifier/evaluator 以及静态 + 动态自演化的规则上下文。

## 3. 关键设计

**3.1 规则系统：静态初始化 + 自演化双态。** 静态规则（论文表 2 六组件）编码：领域知识初始化（重启策略、预处理、in-process 简化、CDCL 核心原理，soundness 检查必须保留、证明验证必须执行）；关键正确性规则（禁实例特定优化、只许确定性 SAT/UNSAT 输出、UNSAT 必产 DRAT 证明、零容忍预测性/仅启发式终止）；仓库结构与追踪；评估前验证（编译 + 115 个 CNF + SAT/UNSAT 输出验证 + 证明验证 + 多基线一致性（如 vs kissat-sc2024），错配立即中断演化）；评估协议；自演化方法论。规则自演化每周期两步： 规则合规验证——脚本强制三文档存在、starexec 打包与品牌正确、对 .c/.h 做禁忌模式扫描（非 kissat 路径的 malloc/free/calloc、静态缓冲/静态指针等），配合 pre-commit hook、周期审计，并周期性质询 Cursor 是否引用并执行具体规则编号； 自动规则演化——post-mortem 分析器解析编译/链接错误、验证不匹配、缺文档事件与新失败签名（如预测性终止变体、启发式结果捷径），以具体 diff 注入规则补丁（向 Rule 04 追加 FORBIDDEN 块 + 代码片段 + 理由、收紧 Rule 01 预评估、强化 Rule 03 日志）并做版本化快照。由此衍生维护 .cursor/rules/ 六个规则文件（00 合规验证、01 预评估测试、02 关键正确性、03 强制日志、04 禁忌模式、05 自动规则演化），全部可被脚本机器执行。作者经验：代码化指令（Bash/显式仓库操作）对 agent 的一致性显著优于自然语言规则描述。

**3.2 两阶段验证流水线（人工预建，非 agent 生成）。** Stage 1：标准编译检查；通过后在 kissat 仓库的 115 个平凡 CNF 上冒烟（单元传播、简单 SAT/UNSAT），监控段错误、断言失败与明显错答，失败即带细节反馈 Coding Agent（如“预处理阶段段错误”）。Stage 2：在已知结果的历史竞赛实例上，凡报告 SAT 者逐实例校验返回赋值满足公式，凡报告 UNSAT 者用外部 DRAT 检查器验证证明，任何偏差判失败并施以惩罚性反馈。仅双阶段全过者进入性能评估并可能获正奖励。全程实验中，通过两阶段的版本从未在竞赛基准上产生错分。（口径注：正文称“两阶段”，讨论部分又将 SAT/UNSAT 正确性称 Stage 2、DRAT 证明称 Stage 3，编号略有不一致，功能上即“编译/冒烟门 + 正确性/证明门”。另 Stage 1 反馈由 agent 自动生成，Stage 2 反馈流由作者人工设计。）

**3.3 分布式评估与反馈指标。** LSF 集群 800 × AMD EPYC 7F72 @3.6 GHz（L1 32KB / L2 512KB / L3 16MB）；每轮并发两个求解器（相继演化变体或 A/B 对）× 各 400 个 CNF 实例饱和全部节点；SC2024 全套 400 实例（application + hard combinatorial）约一小时出全量结果，反馈周转的理论下界 5000 s 恰为超时上限。指标族（论文表 3）：与 VBS（虚拟最优求解器 oracle，含每实例正确答案与基线最优结果）的答案匹配（错配触发失败学习规则）、SAT/UNSAT 分别解决数、多档时间截断（300/600/1000/2000/3000/4500 s）下的解决数分布、平均/峰值内存（捕捉内存爆炸与泄漏）、相对基线的新增解决数（凸显新能力）、总体/SAT/UNSAT PAR-2（超时惩罚因子 2、5000 s 截断，越低越好；奖励近似为其倒数）。关键的防博弈设计：PAR-2 分数反馈仅在第 33 周期之后引入，此前只用解决数与截断分布，防止 agent 针对竞赛分值生成“怪异”优化——先纯粹提升求解能力、再对齐竞赛指标。

**3.4 演化沉淀的求解器设计知识（论文表 4）。** 多 UIP 子句学习（1-UIP/2-UIP/last-UIP 候选按 LBD/size 选择，开销使净收益实例相关）；bandit 调 UIP 深度（以下游子句效用为奖励，较静态策略更稳）；vivification 的 SAT/UNSAT 敏感性（激进 vivification 利 UNSAT 证明、伤 SAT 搜索）+ bandit 自适应分级控制（以 literals removed/clauses checked 为效率信号，配 ADAM 式更新）；奖励设计从“变量覆盖”代理迁移到冲突/传播中心信号、UCB 换为历史感知的 ADAM 式更新（提升噪声非平稳反馈下的稳健性）；自适应滑窗平滑；多域 bandit 并联协调 vivification、重启（VSIDS/CHB）、UIP 深度与子句削减（避免单组件过度优化）；BreakID 静态对称破缺集成（开销换对称搜索空间收缩，并派生多组件调参机制）；压缩 watch list 架构（省内存、提缓存局部性，需防 stale refs）。

## 4. 实验结果

**SC2025 基准（5000 s 超时、竞赛标准 PAR-2；演化全程未接触 2025 实例）。** SATLUTION 产出多个 PAR-2 全场最低的求解器，总体、SAT、UNSAT 三个口径均优于官方金牌 AE kissat2025 MAB 与银牌 kissat-public。解决实例数（作者评测硬件口径；与官方绝对值不同但 top-3 排序与官方结果一致）：

| 求解器 | 解决实例数（作者运行口径） | 官方口径 | 备注 |
|---|---|---|---|
| SATLUTION 最佳三个演化求解器 | 347 / 345 / 344 | — | 全时段累计解决数均超两竞赛冠军 |
| AE kissat2025 MAB | 334 | 327 | SC2025 金牌 |
| kissat-public | 331 | 321 | SC2025 银牌 |

优势在 1000–4000 s 的中-难区最显著：竞赛冠军进入平台期后，演化求解器仍持续收敛额外实例。

**SC2024 基准（演化反馈所用集合）。** SATLUTION 取得最低总体 PAR-2，同时超过 2024 冠军 kissat-sc2024 与 2025 冠军 AE kissat2025 MAB；SAT/UNSAT 分项改进均衡，UNSAT 侧体现为更快的证明搜索。

**演化轨迹（约 70 周期）。** 迭代 0 起点为种子集成，平均 PAR-2 约在基线均值；前 5–10 周期快速下降（主要来自种子互补优势的组合）；约 50 周期起在 2024 基准上超过 2025 人类冠军；终点约 70 周期时稳定超过全部基线。正确性护栏就位后无灾难性回退，累积均值呈单调向好。失败自动剪枝统计：11 个变体在 400 实例测试集上出现部分段错误、4 个未过功能/证明验证、9 个显著性能回退，均被规则-验证流水线检出并逐出后续演化。

## 5. 消融要点

- **静态规则移除**（20 周期无静态规则预实验）：7 个失败案例、8 个周期产生显著性能退化的求解器；典型歧路包括虚假“预测可满足”的早停启发式、意外弱化证明义务的编辑（DRAT/解检查频繁失败）、易 SAT 实例上的退化优化、不可复现的加速。仅依赖动态自演化规则而无静态基线的 agent 同样持续欠佳：修改噪声大、无法维持演化进展——静态脚手架 + 动态细化的组合被证明是必要条件。
- **反馈信号设计**（跨周期对比，非受控实验）：仅以“总解决数”驱动时，演化偏向 UNSAT（UNSAT 实例是瓶颈且直接抬高总数）；引入 PAR-2 与多截断分布后转向 SAT 中-难实例提速。作者手动分析指出 SAT PAR-2 在总分中权重略高于 UNSAT——SAT 大赚、UNSAT 小亏仍净改善；该效应与官方 SC2025 结果互证（冠军 AE kissat MAB 在 SAT 项强于 kissat-public、UNSAT 略逊仍夺冠）。这是“代理指标直接塑造进化搜索方向”的直接证据。
- **验证器消融**：早期仅做基准末尾 SAT/UNSAT 校验时，错误只能在整轮评估后发现，每周期浪费至少 1.5 小时且污染奖励信号；两阶段验证把失败探测前移，稳定了学习回路。
- **组件级消融不可行**：表 4 各技术与系统实现高度纠缠，累计代码改动较初始基线净增逾万行，无法隔离单因子贡献——作者明示此局限。

## 6. 贡献与启示

**贡献**：(1) 首个仓库级（数百文件/数万行 C/C++）LLM 代码自演化框架，在 NP 完全问题上达到冠军级水平；(2) 仅用上一年度基准作反馈，即在次年竞赛基准上泛化超越人类冠军——跨年度分布外泛化的实证；(3) “验证器先行”范式：人工预建的两阶段形式化验证（赋值校验 + DRAT 证明）被论证为进化可行性的锚点而非可选项；(4) 规则库与求解器代码协同演化；(5) 全链路成本透明。

**成本结构**：token 费用 1,938.4 美元（缓存读超 314M、占比逾 93% 且单价低；输出仅约 0.4% 却主导成本；未缓存输入 6.7M、约 2%，对成本贡献显著）；评估消耗约 90,000 CPU 小时，按 AWS 现价 0.1–0.15 美元/CPU 小时折 9,000–13,500 美元；总计不足 20,000 美元、数周内完成人类专家常以月-年计的增量。代码变更量：C/C++ 12,774 行（全部用于求解器实现）、JSON 4,292 行、Markdown 27,593 行（自文档/规则/指标追踪为主体）、Python 约 20,000 行（agent 自生成的特征提取、结果剖析与验证支持）。工程含义：评估算力约占总成本九成，token 经济性取决于压缩高价值 token（输出与未缓存输入）而非原始量。

**诚实的局限披露**：定制"YOLO 模式"全自动化下，agent 在 SAT/UNSAT 正确性检查与深层内存错误上仍常失手，需人工介入保进度；最有效的是半自动分工——人工定向高层策略与“思维”方向、agent 执行底层实现；agent 缺乏 idea 级领域知识。verifier 与评估器均为人工预建；作者将“agent 自建并演化 verifier”列为下一能力里程碑，并点名 EDA（逻辑综合、工艺映射、物理设计）为高价值应用域。

**对音视频技术的上下游关联**：上游方面，SAT/CDCL 是 EDA 形式验证内核，直接支撑编解码 ASIC、NPU、ISP 的等价性检查与模型检查，求解器性能提升等比缩短硅前验证回归周期。方法论迁移（本笔记的推演，非论文主张）：编码器大仓（x264/x265/SVT-AV1/ffmpeg 类）与 SAT 求解器同构性高——启发式密集、C/C++ 大仓、可并行回归评测；本框架三要素可映射为：形式验证锚点 ≈ 码流一致性测试 + 参考解码器校验 + 关键路径精确比对；800 节点 A/B 评测农场 ≈ 逐 clip 编码基准 + 带超时惩罚的聚合分（与 PAR-2 同构）；多域 bandit 协调启发式子系统 ≈ 编码器 feature/tool 自适应控制。两点直接警示：其一，“代理指标塑造搜索方向”的教训对应编码器优化中单指标（PSNR/速度）过拟合的已知坑，PAR-2 延迟引入的“先能力、后分值”策略值得移植到 BD-rate 类指标驱动的自动调优；其二，评估吞吐而非生成能力是此类演化的第一瓶颈，对评测昂贵的长序列编码回归尤其成立。

## 7. 与其他论文的联系

- **MLEvolve（arxiv:2606.06473）**：同属 LLM 多智能体自进化算法发现，均以“渐进搜索 + 记忆/规则沉淀”组织长程探索（其渐进 MCGS + 回顾记忆 vs 本文演化周期 + 规则库）；差异在 SATLUTION 将对象推进到整仓 C/C++ 并以形式化证明锚定正确性，MLEvolve 停留在 ML 算法脚本层。
- **AutoAssumption（arxiv:2611.14844）**：以 Lean 证明图显式化假设、LLM 搜索假设放宽以发现 KV 缓存驱逐与剪枝算法——与本文共享“形式化脚手架保证算法发现可信”的核心命题（Lean 证明 vs DRAT 证明校验），且都面向系统级算法对象（ML 系统服务 vs SAT 求解器）。
- **FGSE（arxiv:2611.14326）**：将经验教训作为可证伪假设、经探针验证后方写入智能体记忆——与本文规则自演化同旨（失败签名 → 禁忌规则 → 合规门禁）；SATLUTION 更进一步把“记忆”落成机器可执行的规则文件与检查脚本，而非仅文本记忆。
- **SkillDuet（arxiv:2611.12109）**：以响应反馈协同模型参数更新与外部技能库演化；SATLUTION 固定模型、仅演化外部规则与求解器代码——两者分别验证了“外部知识库协同演化”在不同自由度（改模型 vs 不改模型）上的收益边界。
- **InfraRSI（arxiv:2611.11558）**：五阶段验证工作流将开放式指令转化为分布式训练优化（其域内最高 2.75× 加速）——同为“人工验证工作流 + LLM agent 优化大型系统”模式，与本文“半自动分工最有效”的结论互为印证。
- **TRUST（arxiv:2611.10787）**：用在线多重假设检验为递归自改进提供统计保证；SATLUTION 用确定性形式验证实现零错分容忍。两者代表 RSI 安全的统计与形式两条互补路线——SAT 场景错解代价不可逆，故必须取形式路线；对可容忍噪声的性能优化任务，TRUST 路线更经济。
- **RSI-PDEbench（arxiv:2611.14949）**：“基准 + 递归自改进智能体”的组合范式与本文“竞赛基准即适应度函数”完全同构，均在固定基准上闭环自提升并报告通过率与调用成本改善。
- **LongCapHarness（arxiv:2611.10463）**：免数据合成与后训练、以评测回路挂接长上下文推理能力并压低部署成本——与本文同属“不训模型、外部 harness + 评估驱动”路线，关联较弱，仅作范式对照（其成本低于基线 50% 的经济性主张与本文 token/算力账本可互相参照）。
