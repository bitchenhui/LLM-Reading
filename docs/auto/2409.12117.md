# Low Frame-rate Speech Codec: a Codec Designed for Fast High-quality Speech LLM Training and Inference

> Edresson Casanova, Ryan Langman, Paarth Neekhara, Shehzeen Hussain, Jason Li, Subhankar Ghosh, Ante Jukić, Sang-gil Lee. *arXiv:2409.12117v1 (2024-09-18)*

## 1. 背景与动机

神经音频编解码器（NAC）的角色正在迁移：从“波形压缩传输部件”变为“语音进入大模型的离散 token 接口”。SoundStream、Encodec、DAC、APCodec 等以 RVQ + HiFi-GAN 式对抗损失在低码率下维持保真度，其离散码已成为 zero-shot TTS、语音到语音翻译等 Speech LLM 任务的表征基座。但此类 codec 帧率普遍很高——DAC 与 Spectral Codec 均为 86 FPS，而自回归语音 LLM 每生成一个 codec 帧需执行一次前向，即合成 1 秒音频至少 86 次 LLM 前向，序列长度同时拖累训练与推理。

论文的核心论断是：当多个码本的码可以并行预测时（FSQ 类扁平码、无需 RVQ 所需的 delay pattern），**帧率对延迟与计算量的影响超过码率**——码率只决定每步输出分布的大小，帧率决定步数本身。而现有文献几乎都在压码率：并行工作 APCodec+AP-BWE 做到 1 kbps / 25 FPS，WavTokenizer 单码本 0.9 kbps / 75 FPS，帧率维度被系统性忽视。

LFSC（Low Frame-rate Speech Codec）将帧率压至 21.5 FPS（较 DAC/Spectral Codec 降 4 倍），码率 1.89 kbps（172 token/秒），在相同的 T5-TTS 框架下实测 LLM 推理加速约 3 倍、可懂度（CER）更优、MOS 与 SOTA codec 相当。对音视频工程侧的直接含义：低帧率同时改善流式 TTS 的首包延迟与服务吞吐，是把 codec 从“压缩工具”重新定位为“LLM 推理预算控制器”的代表性工作。

## 2. 方法总览

LFSC 由全卷积生成器与三个判别器构成。

**生成器**：编码器为 5 个残差块，每块含 3 个 dilation=1 的残差层（结构类似 HiFi-GAN 的 MRF 模块但去掉膨胀卷积），每个残差块后接一个带 stride 的一维卷积，stride 序列 [2, 2, 4, 8, 8]，总下采样倍率 1024；22.05 kHz 输入下帧率为 22050/1024 ≈ 21.5 FPS。量化瓶颈采用 FSQ（有限标量量化，沿用 Spectral Codec 方案）：8 个码本、每码本 4 维、量化层级 [8, 7, 6, 6]，隐式码本大小 8×7×6×6 = 2016。解码器为 HiFi-GAN 结构，上采样率 [8, 8, 4, 2, 2]，与编码器对称还原。通道策略：编码器初始 48 通道、每次下采样后翻倍（共 57.6M 参数）；解码器初始 1024 通道、每次上采样后减半（共 55.1M 参数）。

**判别器**：三路，全部使用 squared-GAN 损失加特征匹配损失——(1) HiFi-GAN 的多周期判别器 MPD；(2) Encodec 的多尺度复数 STFT 判别器；(3) 本文提出的语音语言模型（SLM）判别器：采用 12 层 WavLM（94k 小时数据预训练），训练全程冻结；输入音频重采样到 16 kHz，提取中间层特征送入 4 层一维卷积组成的判别头。该设计明确承自 StyleTTS 2 在 TTS 对抗训练中使用 SLM 的思路，本文首次引入 NAC 训练。

**训练**：两阶段——先关闭 FSQ 预训练、再开启 FSQ 微调，各约 62,000 步（无量化的消融连训 124k 步）；96 块 A100，每卡 batch 16、累积 1536，1.1 秒音频片段，每阶段约处理 9500 万条样本（1536×62k）；Adam（β1=0.8，β2=0.99），初始学习率 2e-4，指数衰减 γ=0.998。

**数据**：沿用 Spectral Codec 的策略获取 22.05 kHz 全带宽语音——对 Common Voice 13 全部 105 语言（270 万句、3.2k 小时、约 10 万说话人）与 MLS 英文 train 集（620 万句、25.5k 小时、4329 说话人）做带宽估计并以 11 kHz 带宽过滤。

## 3. 关键设计

**3.1 帧率的架构化落地：hop=1024。** 帧率不是后处理参数而是网络结构参数：五级 stride [2,2,4,8,8] 之积 1024 即帧移，解码器以 [8,8,4,2,2] 精确镜像。编码器残差层统一 dilation=1，感受野增长完全交由下采样承担（论文未解释此选择，客观效果是编码器为纯判别式下采样栈，生成能力集中于 HiFi-GAN 解码器）。这一“帧率由 stride 决定”的显式设计是与 RVQ 系 codec（帧移通常 320 上下、75–86 FPS）的根本结构差异。

**3.2 FSQ 码本扩容：容量补偿逻辑。** 帧率降 4 倍意味着每秒 token 通道容量等比下降，作者将每码本码数从 Spectral Codec 的 1000 提到 2016（log2(2016)≈11 bit），总码率 21.5×8×11≈1.89 kbps，即以“每帧更粗的量化网格 × 更少的帧”置换通信容量。FSQ 本身是固定层级网格量化，无学习码本嵌入、无码本坍塌问题，8 个码本地位平齐、无 RVQ 的层级依赖——这为并行预测提供了表征前提。消融证实扩容方向正确：1000→2016 使 CER 从 2.61 降至 2.09、SI-SDR 从 4.10 升至 4.45。

**3.3 并行码预测与 delay pattern 解耦：帧率×并行的复合收益。** RVQ 的层级结构迫使 Encodec/DAC 系 TTS 采用延迟模式将多码本序列错位展开；FSQ 扁平码使 LLM 单步同时预测 8 个码。与 21.5 FPS 叠加：每秒音频的 AR 步数 86→21.5（4 倍），且免除 delay pattern 带来的序列延长与首块等待，对流式首包延迟友好。需注意端到端 RTF 实测约 3 倍而非 4 倍，可归因于单步输出 8 个码的输出头开销及 codec 解码等固定成本（论文未逐项拆解，此为基于结果的推断）。

**3.4 SLM 判别器：低帧率下的发音监督。** 动机明确：压缩率升高后发音准确性最难保持（客观指标中 CER 最敏感），而 WavLM 类自监督模型的表征覆盖声学到语义层级，作为判别器可在对抗信号中注入“内容正确性”梯度，且完全不改动量化结构。实现代价低：冻结骨干 + 4 层卷积头，仅在 16 kHz 域对中间层特征判别。消融显示其收益集中于可懂度（CER 2.46→2.09），对 MOS 微升、对时域 SI-SDR 略有牺牲（5.04→4.45）——典型的“语义/感知监督 vs 波形保真”权衡，与 TTS 领域已知现象一致。

**3.5 训练与数据工程。** 两阶段训练解决“先学重建、再学量化”的收敛问题。带宽过滤（≥11 kHz）保证训练分布为全带宽语音，避免窄带数据稀释高频重建；这与 DAC 的多带宽均衡训练形成对照——后者因此对低带宽输入鲁棒（论文用重采样对照实验证实了这一点，见 §4）。

**3.6 评测协议本身是贡献。** 作者重建了 MLS 44.1 kHz 测试集：重新下载有声书，剔除带宽低于 13 kHz 或 CER 超过 10%（Whisper-large v3 计算）的音频，8 语言各随机取 200 句。理由：MLS 测试集样本与说话人不入各受评 codec 训练集，且有声书域与主流 Speech LLM 训练数据同分布。打分时 GT 与重构统一降到 22.05 kHz 以保证跨采样率公平。该测试集已随 demo 页发布，可复用。

## 4. 实验结果

**Codec 客观评测**（MLS 44.1 kHz 测试集 + DAPS F10/M10；Encodec/DAC 用公开 checkpoint 并按原论文方式剪码本降码率，Spectral Codec 用 T5-TTS 论文同一 checkpoint；Squim MOS 为 Torchaudio-Squim 无参考估计）：

|---|---|---|---|---|---|---|---|
| Encodec 24k/6kbps | 600 | 75 | 4.15 / 4.34 | 5.47 / 6.17 | 0.155 / 0.168 | 0.070 / 0.075 | 2.52 / 0.81 |
| DAC 44.1k/7.75kbps | 774 | 86 | 4.45 / 4.65 | 10.54 / 12.62 | 0.110 / 0.108 | 0.054 / 0.051 | 1.57 / 0.61 |
| DAC 24k/6kbps | 600 | 75 | 4.42 / 4.57 | 8.19 / 10.03 | 0.127 / 0.129 | 0.060 / 0.059 | 2.26 / 0.63 |
| DAC 24k/3kbps | 300 | 75 | 4.30 / 4.40 | 4.77 / 5.79 | 0.174 / 0.182 | 0.071 / 0.073 | 3.68 / 0.92 |
| Spectral Codec 22.05k/6.88kbps | 688 | 86 | 4.43 / 4.64 | -20.44 / -20.43 | 0.117 / 0.117 | 0.060 / 0.058 | 1.47 / 0.67 |
| **LFSC（本文）22.05k/1.89kbps** | **172** | **21.5** | 4.43 / **4.68** | 4.46 / 6.93 | 0.147 / 0.142 | 0.061 / 0.058 | 2.09 / 0.86 |

要点：

- **感知质量**：DAPS 上 Squim MOS 4.68 为全场最高；MLS 上 4.43 与 Spectral Codec 持平、仅次于 DAC 7.75 的 4.45——在码率与帧率均为其约 1/4 的条件下取得。
- **可懂度**：MLS CER 2.09，显著优于 3kbps DAC（3.68）、Encodec（2.52）、6kbps DAC（2.26），逊于 Spectral Codec（1.47）与 DAC 7.75（1.57）；DAPS CER 0.86 与 Encodec（0.81）、DAC 7.75（0.61）接近。
- **时域**：SI-SDR 绝对值弱于 DAC 系，但远优于 Spectral Codec 的 -20.44——后者频谱指标良好而 SI-SDR 为深度负值，说明其重建与 GT 存在波形级错位（相位/时间轴），SI-SDR 对此极敏感。
- **公平性对照**：给 DAC 7.75 喂 22.05→44.1 kHz 上采样输入（有效带宽约 11 kHz），Squim MOS 与 Mel 距离完全不变，SI-SDR 10.65 vs 10.54、STFT 距离 0.052 vs 0.054 略升、CER 1.62 vs 1.57 略降——证明 DAC 的强势并非来自高带宽输入，跨采样率对比成立。

**ZS-TTS 下游验证**：完整复刻 T5-TTS（decoder 上下文条件版本）实验。训练数据 1.8k 小时英文（LibriTTS train-clean-360、HiFiTTS、MLS 1000h 子集、63h 两说话人私有集）；3 秒固定说话人上下文；32×A100、batch 192、300k 步、AdamW lr 1e-4；推理 top-k=80、温度 0.85。Encodec/DAC 用 delay pattern，Spectral 与 LFSC 8 码并行；DAC 码取自 22.05→44.1 kHz 重采样音频。评测：VCTK 20 个未见说话人×10 句共 200 条；CER 用 Conformer-Transducer Large 转写；SECS 用 WavLM-base-plus-sv 说话人余弦相似度；MOS 每模型 200 条、每条至少 10 名听者、1–5 分整分打分；RTF 按最快模型归一化。

| Codec | 码率 | MOS(↑) | CER(↓) | SECS(↑) | RTF(↓) |
|---|---|---|---|---|---|
| Encodec | 6kbps | 3.52 ± 0.04 | 2.97 | 0.749 | 2.839 |
| DAC | 7.75kbps | 3.94 ± 0.04 | 2.66 | 0.709 | 3.318 |
| Spectral Codec | 6.88kbps | 3.87 ± 0.04 | 2.23 | 0.794 | 3.255 |
| **LFSC** | **1.89kbps** | 3.95 ± 0.04 | **0.93** | **0.823** | **1.000** |
| LFSC-4032 FSQ | 2.06kbps | 4.02 ± 0.04 | 1.19 | 0.797 | 1.003 |

核心结论：LFSC 将 TTS 的 CER 从次优的 2.23（Spectral）压到 0.93，SECS 0.823 最高，MOS 与 DAC/Spectral 无显著差异，同时端到端 RTF 约为其他 codec 的 1/3。加速是“帧率降低 × 免 delay pattern 并行预测”的组合效果。

## 5. 消融要点

MLS 44.1 kHz 测试集上（同 §2 训练配置）：

| 条件 | 码率 | Squim MOS | SI-SDR | STFT Dist | CER |
|---|---|---|---|---|---|
| 完整模型（2016 码） | 1.89kbps | 4.43 | 4.45 | 0.061 | 2.09 |
| 无量化（上限） | - | 4.45 | 7.06 | 0.058 | 1.73 |
| 去掉 WavLM 判别器 | 1.89kbps | 4.42 | 5.04 | 0.060 | 2.46 |
| FSQ 1000 码 | 1.72kbps | 4.43 | 4.10 | 0.062 | 2.61 |
| FSQ 4032 码 | 2.06kbps | 4.45 | 4.86 | 0.061 | 1.96 |

四条结论：

1. **WavLM 判别器是可懂度主力**：CER 2.46→2.09，MOS 微升（4.42→4.43），代价是 SI-SDR（5.04→4.45）与 STFT 距离（0.060→0.061）轻微劣化——语义监督与波形保真之间存在可测的权衡。
2. **码本扩容路线单调有效**：1000→2016→4032，CER 2.61→2.09→1.96，SI-SDR 4.10→4.45→4.86，MOS 在 4032 时达 4.45。4032 码本下 MOS 已追平无量化模型。
3. **量化是主要信息瓶颈**：无量化上限的 SI-SDR 为 7.06、CER 为 1.73，量化后分别掉到 4.45/2.09——时域损失远大于感知损失，低帧率压缩的代价集中体现在波形对齐精度上。
4. **codec 指标与下游任务失配**：codec 级几乎全面更优的 4032 版本，在 TTS 上 CER（1.19 vs 0.93）与 SECS（0.797 vs 0.823）均差于 2016 版本，仅 MOS 4.02 略高且不显著。作者归因于更小码本带来更好的 LLM 泛化（引 XTTS 中同类现象）。这与 T5-TTS 论文观察到的“7.75kbps DAC 重构更好但 TTS 更差”相互印证：**为 Speech LLM 选 codec 不能只看重构指标，码本几何对自回归建模的友好度是独立变量**。

## 6. 贡献与启示

- **视角贡献**：把帧率确立为 Speech-LLM 导向 codec 的第一设计变量，并给出可复制的配方——stride 1024 卷积骨架 + FSQ 码本扩容 + 8 码并行预测。论文明确指出：在码本可并行预测的前提下，降帧率比降码率更重要，这为后续低帧率 codec 研究设定了议程。
- **方法贡献**：首次将大语音模型（冻结 WavLM）用作 NAC 训练判别器，验证了其在高压缩率场景下对发音可懂度的关键作用，且不引入量化结构改动、推理零开销。
- **工程含义**：约 3 倍的 LLM-TTS 端到端加速直接转化为服务吞吐与流式首包延迟收益；序列长度缩短同步降低 AR 训练开销；1.89 kbps 顺带满足极低码率传输需求。对实时音视频链路（流式 TTS、全双工语音对话）而言，codec token 的帧率是上游表征与下游推理成本之间的接口参数，本文给出了该参数的完整压缩案例。
- **局限**：仅覆盖 22.05 kHz 语音（44.1 kHz 与音乐/音效列为未来工作）；SI-SDR 与顶级 DAC 仍有明显差距；codec 级 CER 高于 Spectral Codec 与 DAC 7.75，说明重建端发音保真尚有余量（尽管 TTS 端反超）；TTS 评测仅英文（codec 训练虽含 105 语言）；codec 级 MOS 为 Squim 无参考估计而非人评。
- **开放性**：模型入 NeMo 仓库，demo 页与 MLS 44.1 kHz 测试集公开，可复现性在同类工作中属上乘。

## 7. 与其他论文的联系

- **HALL-E（arXiv:2410.04380）**：同属压帧率路线，但机制互补——HALL-E 用 MReQ 后训练重量化把现成 codec 帧率降到 8 Hz，LFSC 则从零设计原生 21.5 FPS codec 并重训。前者轻改造、可复用已有 checkpoint，后者在码率-质量曲线上更优；两者共同验证了帧率是 speech LLM 长序列生成的核心瓶颈。
- **Moshi（arXiv:2410.00037）**：Moshi 的全双工实时对话（实测约 200 ms 延迟）建立在 codec token 上的 AR 生成，其延迟预算正是本文动机所分析的对象——每帧一次前向。LFSC 式低帧率 codec 是压缩该项延迟的直接手段，二者分别代表“系统侧全双工架构”与“表征侧帧率压缩”两条正交的降延迟路径。
- **X-Codec（arXiv:2408.17175）**：与本文同解“codec 语义/可懂度不足”问题，但路线不同：X-Codec 修改量化结构（RVQ 前注入预训练语义特征 + RVQ 后语义重建损失），LFSC 用冻结 WavLM 判别器在训练信号层面旁路注入语义监督、完全不动量化前端。两者对合成 WER/CER 的改善方向一致，机制上具备叠加空间。
- **Single-Codec（arXiv:2406.07422）**：token 率削减的另一正交轴。Single-Codec 压码本数（单码本、304 bps），LFSC 压帧率（21.5 FPS × 8 码本并行预测）。两者共同支持同一结论：对 LLM-TTS 而言，token 的组织方式（码本数、帧率、并行性）比 codec 重构质量本身更具决定性。
- **Streaming Endpointer（arXiv:2506.07081）**：同属“以流式低码率神经 codec 作为低延迟对话基础设施”的技术栈——该工作用流式 codec 特征做对话端点检测，LFSC 则为这类流式消费方提供低帧率 token 源。需要指出的是权衡方向不同：端点检测依赖时间分辨率，21.5 Hz 的帧粒度对检测时延的影响是 LFSC 在该类下游任务中的待验证问题。
