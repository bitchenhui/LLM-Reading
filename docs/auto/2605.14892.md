## 1. 背景与动机

单体 LLM agent（推理、记忆、规划、工具使用的模块化组合）在长时程一致性、动态任务适配与跨工具协调上存在结构性瓶颈。随着任务范围扩大，多样化能力难以集中于单 agent 而不引发 prompt 设计、上下文分配与行为目标的冲突——这是转向多智能体系统（MAS）的直接动机：以角色分工与结构化通信换取能力上限。但综述的核心洞察在于紧耦合的代价：一个局部错误（幻觉事实、消息误路由、错误工具调用）会跨 agent、跨交互轮传播为级联失败，遮蔽原始根因；轨迹越长、依赖越深，人工定位责任 agent 与决定性步骤越不可扩展。

在此基础上作者指出两个深度耦合的缺口：无可靠归因则改进缺乏方向；无将诊断转化为结构自适应（重组拓扑、修订角色、精炼协作策略）的能力，则归因无实用价值。二者共同暴露一种不对称：构建复杂 MAS 的能力远超理解其失败并令其自主改进的机制。综述侧写上，既有工作沿三条割裂的线索展开（单体能力 [10,11]、协作 [22,37-41]、自进化 [31,42]），且无任何综述系统覆盖多智能体失败归因这一新兴方向。本文自称首个覆盖 LLM-MAS 完整运营生命周期（单体能力→协作组织→失败诊断→自主结构改进）的综述，组织为因果串联的 LIFE 框架（Lay/Integrate/Find/Evolve），四项贡献：LIFE 视角、分阶段结构化分类学、归因—进化闭环（归因收窄改进搜索空间，协作结构反过来决定可观测的失败集合）、跨阶段挑战与研究议程，并维护开源仓库（github.com/mira-ai-lab/awesome-mas-life）。

## 2. 方法总览

综述的组织原则是"每阶段一个统一形式化，相邻阶段以依赖与约束衔接"，四个形式化构成全篇骨架：

- **单体 agent（式 1）**：a = (X, U, O, M, R, P, T)，即观测空间、动作空间、工具观测空间、记忆空间与推理/规划/工具执行三函数。决策循环六步：上下文检索 c_t=φ(x_t,m_t) → 推理 r_t=R(x_t,c_t) → 规划 u_{t:t+k}=P(g,r_t,c_t) → 动作采样 u_t~π_act(·|u_{t:t+k},r_t,c_t) → 工具执行 o_t~T(·|u_t) → 记忆更新 m_{t+1}=ψ(m_t,h_t)。要点是 π_act 不再是端到端映射，而是功能模块的复合分解。
- **MAS（式 8）**：S=(A,E,C,G,Π)，分解为四组件：Role（谁行动，z_i=ρ(a_i)）、Communication（m_{i→j,t}~Comm_C(·|a_i,a_j,H_{i,t})）、Orchestration（G=(A,E_c)，E_c⊆A×A）、Interaction（协作策略 π_coll 的执行层实现，产生轨迹 τ）。
- **失败归因（式 12-13）**：轨迹 τ=((i_0,u_0),…,(i_H,u_H))，引入判定函数 Z(τ)：仅当 Z(τ)=1 时归因模型 f 以 (Ω,τ,q) 为输入返回责任 agent 与引入步 (I,t)，否则输出空集。该 agent-step 配对式遵循既有设定，可自然扩展至多 agent/多步/因果链归因。
- **自进化（式 14-17）**：S 时变为 S(k)=(A(k),E(k),C(k),G(k),Π(k))；进化机制为转移映射 S(k+1)=Γ(S(k),H(k))，H(k) 是存储执行轨迹与评价反馈（含局部错误归因、同伴批评）的历史上下文池；目标是任务分布 D_task 上的期望效用单调不减（式 16），避免对单一场景过拟合。Γ 分解为三层次（式 17）：Γ_agentic / Γ_systemic / Γ_meta。

## 3. 关键设计

### 3.1 单体智能：四能力分类学

**推理**按信息流三段组织。输入段：知识增强（RAG、Self-RAG 反思词元、SubgraphRAG 子图、Think-on-Graph 实体-关系路径束搜索、Knowledge Card 小模型知识库、RuAG 蒸馏一阶逻辑规则注入 prompt）与模态增强（Multimodal-CoT 证明亚十亿参数模型融合视觉特征即可在科学 QA 显著增益；Visual Sketchpad 提供画布生成中间视觉产物；CogCoM 内化区域 grounding 与缩放等逐步视觉操作）。推理过程：搜索空间扩展（ToT/GoT 拓扑泛化、DeepSeek-R1 大规模 RL 涌现自验证与自发回溯、CPO 从树搜索蒸馏步级偏好对做 DPO）与路径验证（Self-Consistency、Reflexion 情景失败记忆、PRM 逐步打分；Math-Shepherd 用蒙特卡洛 rollout 估计步正确性，免去人工标注并匹配人工 PRM）。输出段：可靠性评估（FActScore 原子声明分解、SelfCheckGPT 跨采样一致性、Semantic Entropy 语义聚类后估不确定性、HaloScope 隐层无监督、CoVe 自动生成验证问题）与行为规制（DoLa 高低层 logit 对比、CAD 有无上下文分布对比、ITI 沿真值方向平移注意头激活、CRITIC 工具交互校验、R-Tuning 越界拒答）。

**记忆**按生命周期三段。形成：直接记录（Generative Agents 时间戳流、MemGPT 自导向函数调用写归档）→ 抽象蒸馏（MemoChat、递归摘要、Mem0 两阶段抽取更新、SeCom 证明话题连贯分段+压缩去噪优于轮级/会话级）→ 类型路由（ENGRAM 将条目路由至情景/语义/程序三分库；CoALA 给出工作/情景/语义/程序四类认知架构的理论 grounding）。形成类型直接决定下游：情景踪迹支撑推理期自纠、语义知识支撑经验驱动规划、程序条目支撑跨任务技能复用。维护：结构上从 flat 到图（Zep 三层子图+双时间线、HippoRAG 开放 IE 构图+个性化 PageRank）、树（MemTree）、A-MEM 卡片笔记演化；动态上从艾宾浩斯衰减（MemoryBank）、LLM 驱动 CRUD（Mem0 四原子操作）、MemOS 将内存提升为一等 OS 资源，到 MemRL 训练 Q 函数估计记忆未来效用做保留/淘汰。检索：从稠密向量到 Generative Agents 的 recency+importance+relevance 三因子、ENGRAM 类型感知 top-k、Zep 语义+BM25+图遍历混合、MemRL 相似度过滤后按 Q 值重排；利用侧从 prompt 注入到 Voyager 检索已验证代码技能组合复用（记忆即可复用动作库）。

**规划**分两范式。分解式：前摄（Least-to-Most、Plan-and-Solve、HuggingGPT 生成任务依赖图分派 HuggingFace 专才模型、LLMCompiler 编译为函数调用 DAG 依赖允许处并行、LLM+P 翻译为 PDDL 交给经典规划器、Skeleton-of-Thought 骨架并行填充降时延、Plan-and-Act 长程 web 任务显式规划优于反应式）与渐进（ReAct 推理-行动交替、ADaPT 执行失败时递归再分解、SelfGoal 动态目标树、Voyager 增量规划+技能库、CodeAct 动作空间即可执行代码、KnowAgent 动作知识约束规划空间）。搜索式：步级（LLM-MCTS、PromptAgent 在 prompt 空间上 MCTS、RAP 中 LLM 兼任世界模型与推理 agent、REST-MCTS* 以 PRM 引导树搜索、ToolChain* 对 API 链做 A*、AFlow 在可复用算子组成的 workflow 层面搜索）与计划级（多计划选择、PlanRAG 检索重排、Agent S 经验增强分层规划）。

**工具使用**按生命周期三段。获取：轨迹学习（Toolformer 自监督标注 API 调用仅保留降低困惑度者、ToolLLM 扩展至 16000+ 真实 API、APIGen 三段验证管线覆盖格式/执行/语义正确性）与协议对齐（Gorilla 检索感知训练使调用以最新文档为条件、ToolkenGPT 工具即特殊词元、EasyTool 统一精简文档显著降 token 且提准确率、MCP 以通用 JSON-RPC 接口替代逐工具连接器）。调用：单次（BFCL 以 AST 匹配评函数调用）、闭环（CRITIC、AnyTool 分层自反思）、工作流（LLMCompiler、WorkflowLLM、GPTSwarm 将编排建模为可优化图、AFlow MCTS 搜 workflow 结构）。泛化：GenTool 零到一+弱到强、TOOLVERIFIER 对比自验、Re-Invoke 无标注多视角相似度零样本工具检索；ToolRet 作为首个工具检索综合基准揭示通用 IR 模型在工具检索上表现差，指出文档检索与工具检索间的显著鸿沟；SkillWeaver/SAGE 将技能抽象为可复用 API 库并加 RL。

### 3.2 协作四组件

**角色**：同构（CAMEL、Generative Agents，差异仅来自 prompt，可控但复杂任务易陷入自一致性循环）vs 异构（X-MAS 显式混用多 LLM 在通用与专门域均超同构；A-HMAD 逻辑推理/事实核查/战略规划分工实测降低事实错误；MAPoRL 以后训练+RL 涌现异构角色）。分配：静态（ChatDev 流水线、CodeDelegator 以角色分离缓解上下文污染、SheetAgent、MARE）可解释但假设任务结构先验已知；动态（AutoAgents 从候选池选角色、AgentVerse 运行时组队、DRTAG&IAAG 由中心会话管理者基于反思按需生成并招募新 agent、MARL 涌现式 Roma、ResMAS 面向故障弹性）适合非平稳环境但引入持续协调开销。

**通信**：显式为主流（MetaGPT 交换 PRD/设计规约等结构化文档、AgentPrune 过滤-摘要-压缩显著降 token、TodyComm 任务导向动态决定通信对象与内容）；隐式（Generative Agents 观察推断、心智理论框架预期队友目标、LatentMAS 借共享环境线索同步意图）。综述明确判断显式通信随 agent 数与轮数增长变得昂贵冗长、且常暴露原始中间推理而非任务相关状态，隐式协调（共享记忆、环境状态、stigmergic 信号）值得更多投入。协议层分内部（A2A 点对点任务移交、ANP 服务发现与路由）与外部（MCP 统一上下文访问）；类比 TCP/IP 与 HTTP 对互联网的意义，标准化协议被视为开放 agent 生态的关键基础设施。

**编排**：集中式（StackPlanner 任务级记忆、Puppeteer 中心节点按实时任务需求重构交互通路、CORL 以 RL 编排器作网关权衡整体性能与预算）有全局监督但有单点与瓶颈风险；分布式（AgentNet 去中心，每 agent 以 Forward/Split/Execute 自主路由、边权以成功率 EMA 更新并剪枝；Symphony 无中心协调瓶颈；AgentFlow 发布-订阅+动态服务选举）可扩展鲁棒但共识与冲突消解困难；混合（ChatDev/MetaGPT 以 SOP 约束角色扮演的去中心执行、AgentOrchestra 规划/功能编排/执行三层、TOA 父节点聚合-叶节点并行、AdaptOrch 任务自适应选拓扑）成为趋势。关键论断：拓扑应被视为随任务复杂度、不确定性与 agent 表现演化的自适应设计变量而非固定架构选择；routing 是编排结构内的操作机制（决定下一个行动者），与编排（定义结构）层级不同。

**交互**：信息流上序贯（可解释、模块化，但早期错误级联；Chain of Agents 接力缓解长上下文信息损失、AnyMAC 下一 agent 预测级联）与并行（多样性、鲁棒性，但聚合冲突；MoA 多 LLM 并发提议迭代聚合、M1-Parallel 多团队并行+早停降时延、AgentGroupChat-V2 任务树、DynTaskMAS 动态 DAG）应互补自适应。模式上合作占绝对主导（COPPER 共享反思器解决信用分配、偏好投票机制缓解简单多数的局限）；竞争（Du 等辩论、GPT-Bargaining、ALYMPICS 博弈场、RTBAgent 实时竞价、ALIGN 带性能保证的委托）作为优化手段仍被低估，且无精心设计的激励与裁决会退化为无效对抗或奖励博弈。

### 3.3 失败归因

**分类学三视角**：系统结构（Pan 等四类：规约与系统设计失败、agent 间失配、任务验证/终止失败；AgentAsk 将分析单元细化为 agent 间信息交接并归纳四类通信失败：Data Gap、Referential Drift、Signal Corruption、Capability Gap；AEGIS 将失败类别转化为可控的错误注入目标）；执行阶段（TRAIL 三类：推理错误、系统执行错误、规划/协调错误；Zhu 等模块级：记忆/反思/规划/动作/系统操作）；因果生命周期（AgentFail 三层：agent/workflow/platform；FailCycle 指出失败起点常与暴露点不重合）。共性局限：多数方法停留在单因-单效假设，无法刻画多因多果与级联。

**方法三族**（非互斥，按主导机制划分）：① 数据驱动——从人读日志转向失败模式的学习与泛化。Who&When 确立 agent+step 联合定位问题并比较轨迹搜索与提示策略；TRAIL 与 TraceElephant 证明通用长上下文模型直接调试复杂轨迹能力有限、且不完整可观测性会系统性偏置归因——这推动专用表示与专用归因模型：AGENTRACER 以反事实重放+程序化错误注入生成可追溯标注并训练轻量 tracer；AEGIS 支持上下文感知错误注入下的 SFT+RL+CL 三种训练范式；Spectrum 借鉴软件故障定位，以跨轨迹覆盖统计+可疑度评分替代逐日志语义判断；CORRECT 基于失败复现结构性模式的假设，以在线缓存的蒸馏错误模式做模式迁移定位；GraphTracer 证明仅按时间序分析动作链不足以恢复真实传播路径，改以信息依赖图建模跨 agent 信息流；在线侧 AgentAsk 学习何时发起澄清、问哪个 agent、如何构造最小必要澄清（在错误扩散前干预），Trajectory Graph Copilot 以历史轨迹概率图+GNN 在动作执行前发风险预警，Traj-Guard 序列感知自编码做低时延实时检测。② 约束引导——将归因重构为显式可验证的诊断流水线以压缩搜索空间：SDBL 两阶段（先划范围后定位）；A2P 三阶段（因果假设生成、最小修正、结果预测），以反事实修正与结果预测而非时间邻近性判定候选步是否因果决定性；DoVer 将日志定位视为未验证假设，用干预-重放-结果比对予以证实或证伪；AgentRx 自动生成约束、逐步检查违例、产出可审计日志。局限是依赖任务特定先验与人工设计程序。③ 因果推断——回答"为何发生、如何传播"：Agent-Specific Effects 证明多 agent MDP 中单 agent 动作的影响非局部、经他人后续响应传播；Triantafyllou 等将动作的总反事实效应分解为经其他 agent 下游行为与经环境状态转移两个分量，统一框架下解耦协作交互链与环境动力学；Ma 等多粒度框架以性能因果反演+Shapley 定位责任 agent、以因果发现定位关键步；CHIEF 将轨迹重构为层级因果图，经层级回溯+渐进因果筛选区分真根因与传播症状；AgentTrace 从日志恢复序贯/通信/数据三类依赖构成的因果图并按结构与位置特征排序候选根因。

**五大挑战**：归因语义未统一（失败暴露点、因果触发因子、责任主体三概念常被混同，跨研究不可比）；异常传播强耦合（可观测点≠源点）；细粒度归因受限（长程依赖衰减、冗余与噪声累积）；数据真实性不足（模板化/规则注入的异常分布规整，与真实部署中缺失上下文、跨模块干扰、多轮累积偏差共同塑造的失败存在分布差）；评测-修复闭环缺失（定位准确率不再是充分指标，归因结果是否足以支撑修复决策缺乏验证）。

### 3.4 自进化

**Agentic 层**（单体组件）：prompt 演化（MorphAgent 以角色清晰度/分化度/任务-角色对齐的量化指标自改写画像；NegotiationGym 以显式效用函数迭代谈判策略；COPPER 共享反思器统一反馈而非各 Actor 独立反思）可解释、无灾难遗忘，但上限受制于模型上下文与参数；memory 演化（AgentCourt 对抗自演构建法条/实务经验/判例三级记忆；Richelieu 持久化子目标评估与对手可信度、语义相似度检索）提供在线持续学习通路，瓶颈移向检索效率并冒历史偏差同质化风险；parameter 演化最重（CoMAS 以 judge 模块评估讨论的内在"交互奖励"驱动优化；MAE 单 LLM 拆 Proposer/Solver/Judge 用 REINFORCE++；AdvEvo-MARL 攻防共进化内化安全；ECL 以辅助 RL 奖励习得辨别可信同伴的能力，使小模型胜过历史无知的大基线；Optima 以任务性能/token 效率/可读性复合奖励做 SFT+DPO，2.8× 性能增益同时 token 降 90%；Towards AGI 分层升级——先工具级动态合成 Python 函数、不足时才 EA+SFT+RL 全参数演化）。关键论断：即便演化对象是个体组件，驱动力仍嵌入多智能体语境（对抗自演、同伴互评、协作知识共享）。

**Systemic 层**（组织结构）：topology（Puppeteer 将协作建模为动态序贯决策、RL 优化中心路由策略并权衡质量与算力成本；G-Designer 以变分图自编码器从 agent 能力嵌入解码任务定制的稀疏拓扑；MASS 三段交错提示精炼-拓扑搜索-全局条件化；AgentNet/SELFORG 去中心路线）；composition（AutoAgents 元 agent 起草+自精化循环；EVOAGENT 对基础 agent 施加文本交叉/变异算子+LLM 质检选优；EvoMAC 引入文本反向传播——gradient agent 借编译器反馈分析各 agent 因果影响、update agent 执行增删 agent 的结构变异；ANN 层级化并在全局/局部双粒度反传）；shared memory（G-Memory 以战略知识/任务元信息/细粒度通信日志三层图管理跨 agent 交互史，框架无关插件形态证明知识演化与结构演化可独立组合；LIET 具身环境协作知识清单）。生命周期二分是本层核心发现：拓扑/组队多为 ephemeral（任务毕即弃），共享记忆为 persistent（跨episode 积累），两周期如何互相回馈是开放问题。

**Meta 层**（以完整系统设计为演化单元）：知识空间型靠增长档案（GPTSwarm 以 REINFORCE 优化 agent 图；ADAS 的 Meta Agent Search 让元 agent 在通用代码空间迭代编程新系统并证明跨域跨模型可迁移；AgentBreeder 以 MAP-Elites 式质量-多样性算法协同优化能力与安全；AFlow 将设计空间约束为预定义算子上的代码化 workflow、以带 UCB 的 MCTS 搜索——小模型以 GPT-4o 4.55% 的推理成本反超；MAS-ZERO 将知识积累移至推理时逐例设计，并在简单策略足够时独特地降级到简单策略）；生成器型将设计知识压缩进参数模型（FlowReasoner 用 RL 训练查询级 workflow 生成；MaAS 的 agentic supernet 由 RL 控制器从习得分布中采样任务特定架构，15% 算力超 SOTA 且零样本迁移未见任务；MAS-GPT 微调 LLM 单次前向直接输出完整任务特定 MAS 的 Python 代码）。开放问题：生成器做快速初稿+档案式搜索做持续精炼的分层组合。

**六驱动机制的 VSR 分析**（Campbell 变异-选择-保留框架横切三层次）：LLM Reflection——变异语义定向、但选择自指（生成与评估同源，谄媚风险；以编译器反馈等客观信号可绕开）、保留为档案式且有饱和上限；RL——可从交互内生选择压力（同伴互评、对抗军备竞赛、复合奖励）、参数化保留不可逆且易灾难遗忘、奖励设计不当会被钻空（多智能体脚手架曾塌缩为平凡安全但无用的响应）；EA——种群多样性最强、经典算子被 LLM 语义重组替代、但逐候选评估成本高；TG（文本梯度）——变异由因果归因直接驱动（哪个子任务失败、哪个 agent 引入错误）、选择最客观（拒绝自评、仅信可验证执行日志）、但保留为 ephemeral、无跨任务积累，是唯一无持久保留的机制；Heur（EMA 边权衰减、Shapley 阈值重构 DAG）计算高效但只是正则滤波器而非生成引擎；SFT 类比水平基因转移，传输已知模式而无开放探索。

## 5. 消融要点

综述本身无消融，但其横向分析承载了同等功能，可迁移的实证信号包括：

- **记忆设计消融**：ENGRAM 的消融证实将类型库合并为单一存储会显著劣化检索质量；SeCom 证明分段粒度本身决定质量（话题连贯分段+压缩去噪优于轮级与会话级）。二者共同说明：形成阶段的设计选择直接约束下游可检索性，而现有工作从不系统研究形成/存储/维护/检索四者的交互。
- **机制×层次矩阵的结构性"消融"**：31 框架 36 交点中，agentic×RL（参数演化）最密集，其次为 agentic/systemic 两层的 LLM Reflection；Reflection/RL/EA 是仅有的横跨三层次机制；TG 与启发式更新仅存在于 systemic 层；机制混合近乎空白（仅 COPPER、Towards AGI 等孤立尝试）——矩阵空洞（TG@meta、EA@systemic、全谱混合）即未来方向的直接指认。
- **进化机制对比证据**（引 [396] 及 AgentBreeder）：EA 产生最高行为多样性；RL 在高难度任务最优；课程式方法跨任务泛化最强。AgentBreeder 进一步显示不安全行为会随能力增益自发涌现，且能力+安全双目标选择的收敛强于单目标优化——进化安全不是事后过滤器而是选择压力设计的论据。
- **归因侧负结果**：TRAIL/TraceElephant 一致表明通用长上下文模型读长轨迹做调试不可靠、不完整可观测系统性偏置归因——这是"专用轨迹表示+专用归因模型"路线（AGENTRACER、Spectrum、GraphTracer）的合法性来源。
- **单体层的耦合盲区**：形式化（式 1）表明四能力每步耦合，但现有方法几乎全部单模块孤立优化，能力失配才是端到端部署的真实瓶颈，而现有基准以单/双能力为主对此不可见。

## 6. 贡献与启示

**学术贡献**：① 首个覆盖 LLM-MAS 完整运营生命周期的综述，且首次系统化失败归因方向（该方向文献密集出现于 2025-2026，此前无综述承接）；② LIFE 因果链与"归因—进化闭环"概念：归因不只是解释失败，更收窄定向改进的搜索空间；协作结构反过来决定可观测与可归因的失败集合——这一双向耦合是全篇最有解释力的框架；③ 跨阶段议程：统一可扩展的失败分类与复合标签体系、兼顾真实性与规模的高粒度归因数据、显式建模消息传递与传播链、从单责任点到责任集/贡献分摊/反事实传播、归因-验证-修复闭环、终身演化双过程架构（快速在线拓扑适配+慢速离线参数固化）、生成器+结构化搜索的分层优化、进化式对齐（安全约束作为内在连续选择压力）、以"进化样本效率"替代"第 K 代任务准确率"的开放式评测。

**与音视频技术上下游的关联**（论文本体未直接讨论音视频，以下为笔记基于原文真实钩子的分析）：上游组件层面，第 2 章的多模态推理增强线——Multimodal-CoT（视觉特征入思维链）、Visual Sketchpad（中间视觉产物画布）、CogCoM（区域 grounding/缩放的逐步视觉操作）、ViperGPT（以 Python 执行做视觉推理）、LLaVA/VisCoT/TopViewRS——即视频/图像理解 agent 的推理栈；HuggingGPT 将用户请求解析为任务依赖图并分派 HuggingFace 上的专才模型，是音视频多模型（ASR/TTS/检测/超分/编解码工具）编排的直接原型；LLMCompiler 的函数调用 DAG 与并行执行、M1-Parallel 的多团队早停，对应批处理与时延敏感的媒体处理调度需求；MCP/A2A/ANP 协议层（A2T/A2A、JSON-RPC/SSE、JSON-LD）为媒体工具生态提供互操作标准。下游场景层面（此为推断性映射），OSWorld/AndroidWorld 以状态验证为主信号的桌面/移动评测范式可迁移到播放端与音视频设备控制验证；长时程多智能体工作流（软件工程、企业、医疗范式）可承载转码、审核、修复、编目类管线——此时第 4 章的 agent+step 归因与因果图回溯（CHIEF、AgentTrace）提供管线可观测性方案，第 5 章的 token 成本敏感进化（Optima -90% token、AFlow 4.55% 成本）契合音视频批量处理的成本约束；AgentBreeder 的安全行为涌现对内容生产管线的合规性是直接警示。

**局限**：综述性质，LIFE 各阶段依赖强度无统一实证验证；归因章文献以预印本为主、成熟度低；对比表维度多为定性勾选（✓/–），缺可量化的跨方法可比指标。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326｜FGSE（证伪门控自进化）**：直接落在综述 5.3.1 的 memory 演化分支——综述明确指出记忆演化的两大风险（历史偏差同质化、检索随知识库增长而退化）且 4.5 节判定"评测-修复闭环不完整"；FGSE 将经验教训作为可证伪假设经三类探针验证后才写入记忆，正是对"记忆写入安全"缺口与"归因-验证-修复闭环"议程的针对性实现。
- **paper:arxiv:2611.10787｜TRUST（带统计保证的可信 RSI）**：对应综述 5.6"安全与对齐"论断——对齐必须从单体静态属性提升为进化过程的动态属性，且 AgentBreeder 证明不安全行为随能力自发涌现；TRUST 以在线多重假设检验控制递归自改进的错误进化率，是综述所呼吁"安全约束作为内在连续选择压力"的一种统计实现路径。
- **paper:arxiv:2611.12109｜SkillDuet（模型与技能共演化）**：耦合综述两条线索——第 2 章工具侧技能库线（Voyager 技能复用、SkillWeaver 技能 API 化、SAGE）与 5.6 呼吁的"参数演化与结构演化混合"（快速在线适配+慢速离线固化的双过程架构）；SkillDuet 以响应反馈同时驱动 LLM 参数更新与外部技能库演化，是 agentic（参数）与 systemic（共享技能资产）两支演化路线的耦合实例。
- **paper:arxiv:2611.10463｜LongCapHarness（免后训练的长上下文能力挂接）**：对应综述 meta 演化中"生成器型"低成本路线（MAS-GPT 单次前向生成、MAS-ZERO 推理时设计）与 AFlow 的成本压缩动机（4.55% 推理成本）；其免数据合成与后训练即超越基线、成本低于 50% 的设定，与综述对"迭代搜索评估成本过高、需分层优化"的诊断同构。
- **paper:arxiv:2611.20430｜TrainExplorer（规划-执行解耦的自主后训练）**：映射到综述 3.3.3 混合编排中的 planner–executor 分层与 ChatDev/MetaGPT 的 SOP 约束式执行范式；其策略规划与执行解耦可视为该协作模式在 LLM 后训练任务上的实例化，落入 systemic 层演化（编排结构作为可优化对象）的讨论范围。
- **paper:arxiv:2611.11558｜InfraRSI（训练基础设施的递归自改进）**：与综述 5.3.1 的 Towards AGI 分层升级策略（先工具级动态合成 Python 函数、不足时升级参数级 EA+SFT+RL）同一路线在基础设施域的延伸；其五阶段验证工作流呼应综述对演化必须配验证机制与交互式评测（rSDE-Bench 类）的强调。
- **paper:arxiv:2611.14949｜RSI-PDEbench / paper:arxiv:2611.19230｜CompoundingKernel**：二者为领域化递归自改进实例，按综述分类学可归入 agentic/meta 层演化；其"显著提升通过率并降低调用成本"的结果与 CompoundingKernel 以搜索+执行反馈驱动的方式，分别对应综述 5.6 的演化成本权衡与 5.4 中 TG 机制"仅信可验证执行日志"的最客观选择信号论断。
