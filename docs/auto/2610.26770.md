# HarnessPro: Recursive Harness Self-Improvement with Pareto Optimization for Performance-Cost Trade-offs

> Zhuoshi Pan, ZhiYuan Feng, Yukuo Cen, Honglin Lin, Junru Lu, Zhongxia Chen, Shuo Yang, H. Vicky Zhao, Jie Tang. *arXiv:2610.26770v2 (2026-10-19)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

Agent harness 是管理 LLM 与环境交互的运行时软件层，涵盖提示、工具与技能、上下文与记忆机制、hooks、验证策略，它决定 agent 接收什么信息、可采取什么动作、动作如何执行，因此同时决定任务成功率与资源消耗。近年递归自我改进（RSI）路线（RHO、AHE 等）用历史执行轨迹诊断缺陷并驱动 harness 更新，但普遍以更强的探索与更强的验证换取性能，token 消耗与时延随之上升；而实际部署中单位任务美元成本与墙钟时延是硬约束。论文的核心问题即：递归 harness 自改进能否在**降低**执行成本的同时提升性能。

形式化为 min_h (−PR(h), C(h))，约束 PR(h) ≥ PR(h0)（h0 为初始 harness，防性能回退）。三项指标口径明确：pass rate 在留出测试集上由官方测试判定（ProgramBench 按其官方协议取每任务通过测试比例的宏平均）；cost 按 uncached/cached/output 三类 token 分别计价折算为每任务均值；latency 定义为 agent 执行起止墙钟（不含评分），因受服务负载波动影响仅作辅助指标、不进优化目标。两大挑战：harness 组件（指令/工具/技能/hooks/规则）组合成巨大离散空间、不可梯度优化；额外推理/探索/验证提性能但烧钱，无差别削减又伤性能，推进 Pareto 前沿必须在轨迹层面区分"必要计算"与"可避免开销"。

按论文的对比表定位：AFlow（workflow 级、需 GT）、SkillMOO（skills 级、Pass+Cost 但需 GT、输出 Pareto 集）、RHO（skills+tools、label-free 但单轮、单目标、单输出）、AHE（harness 级但需 GT）；HARNESSPRO 是唯一同时做到 harness 全范围 + label-free + 递归 + 双目标 Pareto 集输出的组合。

对音视频侧的意义：harness 正是工具密集型媒体生产 agent（长构建/渲染/转码编排、AIGC 视频管线）的运行时底座；论文作者含 Kling AI，其问题设定（每任务美元成本、墙钟时延、超长工具输出）与大规模视频生成/后期管线的服务化 KPI 直接同构。

## 2. 方法总览

数据与防泄漏：任务切分为 train/val/test，test 分别为 59/100/100（TB2/SWE-Bench Pro/ProgramBench）；train 用 DPP 共核固定选 10 任务；val 用于候选评估与选择；test 仅在演化冻结后一次性评估。每个 epoch 分三阶段，候选集 |At|≤3，A0={h0}：

- **阶段 1 轨迹诊断**：每个候选 harness 在共核每任务独立 rollout G=3 次，记录轨迹与指标向量（对生成测试的 Pass、成本、时延）及 token/工具调用明细；analyzer 聚合诊断。
- **阶段 2 候选生成**：planner 按三种优先级指令 I1（成本优先）/I2（均衡）/I3（性能优先）为每个候选产出三份计划，editor 在独立工作区实现为可执行候选并 Git 提交；子代与父代合并进入评估。
- **阶段 3 评估与选择**：在 val 上每任务单次 rollout，用**冻结的 LLM 生成测试** S(x) 判定；先过滤（性能地板 PR_val(h0) + Pareto 支配剪枝），再用归一化加权平方距离准则为 lite/medium/heavy 三模式各选一个代表，构成下一 epoch 候选集。

Epoch 上限 3（TB2、SWE-Bench Pro）/4（ProgramBench）。两条关键不变式：演化全程无 GT 解、官方测试、评分器访问；S(x) 仅在开始时由任务描述与初始轨迹生成一次并全程冻结，保证候选间比较公平。

Label-free 设定下最关键的替换：RHO 用 LLM 自偏好直接比较轨迹选 harness，本文实测 LLM judge 过度乐观，失败召回仅 41.7%；改为“生成测试评估最终产物”后失败召回升至 83.3%（+41.7 pp，TB2 与 SWE-Bench Pro 训练任务合并统计）。这一改动把“选择信号的质量”从 judge 偏好问题转化为可执行 oracle 问题，是全框架的立足点。

## 3. 关键设计

**DPP 共核选择**（沿 RHO）：LM judge 为每任务打难度分 r∈[0,10] 并给出去除任务名后的抽象失败模式指纹 φ；构建难度加权 DPP 核（θ=0.7、ε=0.1），贪心最大化子集行列式取 k=10 并全程固定。难度权重偏向难任务，行列式惩罚冗余指纹；共核选择不接触官方测试与 val 结果。

**四个专用 agent：**

- **Trajectory analyzer**：联合考察同一任务 G=3 条 rollout 而非单条，抑制随机性；输出 z(h,x) 含 问题、 对性能与成本的影响、 来源与证据（轨迹摘要/摘录 + 轨迹文件路径 + 事件区间）。跨任务聚合 z(h) 超 64K token 则二次摘要。附录诊断样例显示其粒度：区分共享瓶颈（如 `make -j$(nproc)` 高并行导致 OOM）与 run 特有绕路（中断下载重试、重复 eval），并对“成功但昂贵”的执行标注百万级输入 token 的低价值探索。
- **Evolution planner**：条件输入为候选 harness 全量实现 + z(h) + 指标 m(h) + 与兄弟候选的代码 diff 及其诊断指标，跨候选证据可识别有效机制与剩余瓶颈；默认不给全轨迹，可经诊断中记录的文件路径按需查看；被要求提出可泛化而非任务特定的修改；val/test 对 planner 不可见。值得注意的涌现现象：I1–I3 明确声明“不预设路由 rubric、固定阈值、profile 分类法”，但演化收敛出的机制恰是“路由 rubric + 固定阈值 + hooks”，即机制从证据中推导而非模板注入。
- **Harness editor**：每份计划独立工作区实现，Git 提交保证可追溯、可回滚。
- **Test synthesizer**：S(x)=TestSynth(x, τ_h0(x))，一次生成全程冻结。实现纪律严格：写 10 个 unittest 用例，在冻结候选的全新容器内经 MCP 工具 `validate_generated_tests` 串行执行（7200 s 超时）；oracle 只能从公开证据导出，禁止从被测产物反推期望常量/哈希/容忍值；status=ok 且 passed=false 视为有效执行（暴露产品缺陷）而非要求修补到通过；配 self-review 与 repair-log。

**过滤与选择**：硬地板 PR_val(h)≥PR_val(h0) + Pareto 支配剪枝后，对幸存集计算归一化偏差 d_perf=(P_max−PR)/(P_max−P_min)、d_cost=(C−C_min)/(C_max−C_min)，模式目标 J_m=α_m·d_perf²+β_m·d_cost²，权重 (α,β) 为 lite (1,2)、medium (1,1)、heavy (2,1)，跨 epoch 固定。平方形式惩罚任一轴上的极端劣化，本质是 min-max 归一化目标上的加权重标量化，在有限候选集中稳定取到三档代表点。

**演化出的机制**（第 5.3 节与附录 D，对理解收益来源至关重要）：

- **任务描述驱动的执行 profile 路由**（TB2/SWE-Bench Pro）：五档 compact/lean/standard/deep/research，各绑定推理档位与工具调用预算（economy/strict/finalize 阈值 + 提醒间隔）。例如 TB2 medium 的 standard 档：medium 推理，14 次调用进入省俭提醒（批量并行检查、不重复读）、26 次进入收敛提醒（停止广探索）、44 次硬拒后续调用。阶段提醒文本**追加到工具结果**而非改写提示前缀，保持 prompt 前缀不变以复用缓存，直接降低按未缓存输入计费的开销（GPT-5.5 未缓存输入 5.00 $/M vs 缓存 0.50 $/M，10 倍价差）。
- **静态冗余削减**：RTK 式工具输出压缩（折叠连续重复行、头尾截断并保留原始日志路径供定点重读）、每输出历史 token 上限（TB2 medium 为 900）、精简开发者指令。
- **三档差异极小**：lite/heavy 相对 medium 仅是 policy.json/rubric 的 diff，lite 压低各档 finalize 阈值（14→8、22→16、44→38、54→48、46→40）并把 deep/research 推理档 high→medium；heavy 扩大预算并把 standard 升为 high 推理。即 Pareto 三档是同一机制族的预算参数化，而非三个独立设计。
- ProgramBench 的 medium 演化结果反而采用固定 high-effort 单 profile、无路由，佐证设计是按基准证据适配，而非通用配方。

## 4. 实验结果

设置：GPT-5.5×Codex 0.147.0 与 GLM-5.2×Claude Code 2.1.231；G=3；epoch 3/3/4；HARNESSPRO 报 3 次运行（TB2、SWE-Bench Pro）或 2 次（ProgramBench）的均值±样本标准差；成本按公开牌价（GPT-5.5 短上下文档 5.00/0.50/30.00 $/M；GLM-5.2 1.40/0.26/4.40 $/M）。GPT-5.5×Codex 主结果关键行（P 为 %，C 为 $，T 为 s）：

| 方法 | TB2 P/C/T | SWE-Pro P/C/T | ProgramBench P/C/T |
|---|---|---|---|
| Vanilla | 69.5 / 0.89 / 260 | 59.0 / 1.88 / 337 | 60.3 / 2.65 / 669 |
| RHO | 76.3 / 1.09 / 354 | 80.0 / 2.68 / 437 | 68.8 / 3.59 / 928 |
| RHO+Iteration | 76.3 / 0.82 / 328 | 80.0 / 1.90 / 375 | 68.3 / 3.13 / 789 |
| HarnessPro-Lite | 72.9±1.7 / 0.43±0.01 / 230 | 72.3±0.6 / 0.80±0.02 / 203 | 64.3±0.04 / 2.18±0.06 / 985 |
| HarnessPro-Medium | 76.3±1.7 / 0.56±0.04 / 253 | 79.0±1.0 / 1.26±0.03 / 326 | 67.9±0.47 / 2.90±0.13 / 745 |
| HarnessPro-Heavy | 80.8±1.0 / 0.72±0.05 / 310 | 80.7±0.6 / 1.97±0.02 / 333 | 69.6±1.03 / 2.95±0.13 / 888 |

要点结论（均带上述口径）：RHO 相对 Vanilla 全面提性能但抬成本，SWE-Bench Pro 上每任务成本 +42.6%（$1.88→$2.68）；heavy 模式在三个基准上全部取得最高通过率且成本低于 RHO，对 RHO 平均 +2.0 pp / −26.1%；单基准看 TB2 +4.5 pp 且 −33.9%，SWE-Bench Pro 80.7 vs 80.0 @ $1.97 vs $2.68，ProgramBench 69.6 vs 68.8 @ $2.95 vs $3.59（−17.8%）。medium 档以 SWE-Bench Pro 最典型：79.0 vs RHO 80.0，成本 −53.0%（$1.26 vs $2.68）。lite 档三基准全面优于 Vanilla 且成本低 17.7–57.4%。对齐迭代预算后仍占优：TB2 上 medium 与 RHO+Iteration 持平（76.3）但成本低 31.7%（$0.56 vs $0.82）；ProgramBench 上 heavy +1.3 pp 且 −5.8%。记忆类基线（Dynamic Cheatsheet/ReasoningBank/Sleep-time Compute）介于 Vanilla 与 RHO 之间且成本普遍高于 Vanilla。GLM-5.2×Claude Code 结论同构：heavy 三基准均以更低成本超过 RHO（81.4/$0.62、77.3/$1.01、64.4/$14.95 vs 78.0/$1.00、75.0/$2.17、63.3/$17.00）；SWE-Bench Pro heavy 平均时延 412 s vs RHO 520 s。时延非优化目标但成本优化在多数场景连带提速；例外如 ProgramBench lite 的 985 s 高于 RHO 的 928 s。

演化动力学（中间 epoch 的 test 指标仅用于可视化、不参与选择）：TB2 heavy 从 epoch 1 的 74.6%/$0.91 到 epoch 3 的 80.8%/$0.72；lite/medium 在 ep2→3 保持通过率同时成本 $0.61→$0.43、$0.68→$0.56。SWE-Bench Pro medium 在 ep1→2 通过率 70.0→77.0 但成本 $1.57→$1.66，直到 ep3 才双改善至 79.0%/$1.26，说明单轮演化可能提性能但抬成本，递归才持续推进 Pareto 前沿。ProgramBench 第 4 轮进一步降成本、通过率持平。

## 5. 消融要点

消融均在 GPT-5.5×Codex 下进行，并附 CoP（Cost-of-Pass = 总执行成本 / 成功任务数）：

- **去 test synthesizer**：两基准三模式通过率一律下降 3.4–10.0 pp（TB2 heavy 80.8→74.6、lite 72.9→67.8；SWE-Bench Pro medium 79.0→69.0），且多数情形成本反升（TB2 medium $0.56→$0.82）。评估信号质量直接决定选择质量，是最大单一组件。
- **去 planner**：多数实验双劣化，如 SWE-Bench Pro medium 79.0→73.0 且 $1.26→$1.42；TB2 heavy 80.8→79.7 且 $0.72→$1.04。
- **机制移植实验**：把演化出的单个机制装回 RHO，+dynamic routing / +budget hooks 各自降成本但在 SWE-Bench Pro 掉通过率（76.0 / 75.0 vs 80.0）；统一 low reasoning effort 省钱最多但性能崩溃（TB2 62.7、SWE-Bench Pro 59.0）。三个变体全部被 HARNESSPRO 演化 harness Pareto 支配，证明收益来自机制协同（路由 × hooks × 输出压缩 × 指令精简），而非任何单一技巧，也排除了“只是压上下文/降推理档”的平凡解释。

## 6. 贡献与启示

贡献三点：首个 label-free + 递归 + harness 全组件范围 + Pass/Cost 双目标的 RSI 框架，输出 lite/medium/heavy 三档 Pareto 部署选项；以冻结的 LLM 生成测试替代 LLM 自偏好评估产物，在无官方测试条件下把失败召回从 41.7% 提到 83.3%；在三个基准、两组模型上实证“性能与成本可以同时改善”，且机制可解释、可审计（Git 追踪 + policy diff 级别的三档差异）。

对本领域研究者的启示：

- **选择层与率失真优化同构**。min(−PR, C) 就是质量-码率型双目标；归一化加权平方距离选择等价于 min-max 归一化后的加权重标量化取点，lite/medium/heavy 三档类似码率阶梯。harness 演化可视为 agent 系统的 RDO，这一视角提示可移植视频编码中成熟的率控制与 lambda 搜索技术。
- **成本必须按 uncached/cached/output 分账**（价差 10 倍）。“提醒追加到工具结果、保持 prompt 前缀稳定”这类看似琐碎的设计有明确经济动因，对一切长会话 agent 服务（包括音视频工具链 agent）都成立。
- **预算 hooks 是运行时准入控制**：分阶段从探索切向收敛，与实时媒体管线中 deadline 感知调度同思路，适合迁移到渲染/转码/长构建类媒体任务 agent。
- **生成测试评估产物本质是无参考评估**，与音视频 NR 质量评估面临同一“无真值构造判据”难题；其“只从公开证据导出 oracle、禁止从被测对象反推期望值”的纪律，对构造无参考媒体质量判据有直接借鉴价值。
- **上下游关联**：下游即工具密集型媒体生产（批量转码、渲染、AIGC 视频编排；作者含 Kling AI 印证该方向），每任务美元成本与墙钟正是其服务化 KPI，长构建与大日志场景直接受益于输出压缩与预算控制；上游则是模型服务的计费结构与前缀缓存机制本身。

边界与保留（基于论文自身口径）：latency 仅为辅助指标，存在成本下降但时延高于 RHO 的个例（ProgramBench lite）；生成测试失败召回 83.3% 而非完美，选择仍可能受测试偏差影响；训练共核仅 10 任务，泛化依赖 DPP 多样性假设；test 集规模 59/100/100，pp 级差异的统计功效有限（作者以多次运行的均值±std 缓解）。

## 7. 与其他论文的联系

- **LongCapHarness（arxiv:2611.10463）**：同属“RSI 挂接底层能力、免数据合成与后训练、显式成本敏感”的 harness 自改进家族（HELMET/RULER 上以低于基线 50% 的成本超越基线）；HARNESSPRO 可视为把该范式推广到通用 agentic 基准，并显式引入 Pareto 三档输出与 label-free 测试选择，两者都冻结模型权重。
- **SkillDuet（arxiv:2611.12109）**：同为递归自我改进，但 SkillDuet 以响应反馈协同更新模型参数与外部技能库（权重级 + 技能级），HARNESSPRO 演化 harness 全组件而权重冻结——同栈不同改进载体的互补关系。
- **TRUST（arxiv:2611.10787）**：针对 RSI 的可靠性，用在线多重假设检验控制错误进化率并提供统计保证；与 HARNESSPRO 的工程性护栏（性能地板 + Pareto 支配剪枝 + 冻结测试）解决同一问题，防劣质更新进入递归环，可视为统计保证路线 vs 测试评估路线的对照。
- **RSI-PDEbench（arxiv:2611.14949）**：RSI 在 PDE 求解垂直域的应用，同样报告通过率提升与调用成本下降；与 HARNESSPRO 共享“性能-成本联合改进”的诉求，差异在于域特定基准/模板化案例 vs 通用 agentic 基准与显式 Pareto 选择。
- **WeightLoop（arxiv:2611.07319）**：以实验反馈持续改写已部署模型权重的自改进；与 HARNESSPRO 构成“改进写在哪一层”谱系的两端（权重编辑 vs 冻结权重改 harness），二者都依赖执行反馈闭环与产物级评估。
- **InfraRSI（arxiv:2611.11558）与 RSI-Opt（arxiv:2610.32026）**：同为“轨迹/实验反馈 → 候选生成 → 基于验证的选择”的元级递归环，只是作用对象分别为训练基础设施与优化器策略；HARNESSPRO 把该模式实例化在 agent harness 层，并补上了多目标 Pareto 选择这一缺失件。
- **TGR-EvoDAG（arxiv:2610.32326）**：工业界（腾讯）以 DAG 多智能体代码演化驱动生成式推荐整条管线、在线 CTR 相对提升 0.40%；与 HARNESSPRO 同属“代码级演化 + 执行反馈”范式，且其媒体/推荐场景恰是 HARNESSPRO 三档预算化 harness 的潜在落点，二者在“演化产物如何按部署预算分层交付”上可互补。
