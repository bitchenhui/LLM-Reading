# Chasing Moving Targets with Online Self-Play Reinforcement Learning for Safer Language Models

> Mickel Liu, Liwei Jiang, Yancheng Liang, Simon Shaolei Du, Yejin Choi, Tim Althoff, Natasha Jaques. *ICML 2026 / arXiv:2506.07468v4*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

**一句话定位**：本文提出 SELF-REDTEAM，首个面向 LLM 安全对齐的全在线（fully online）自博弈多智能体强化学习（MARL）算法——单一策略 πθ 同时扮演攻击者与防御者，在零和红队博弈中通过奖励模型裁决持续共同演化。核心贡献是把“攻-防交替的离线补丁循环”替换为“在线协同进化”，并给出博弈论安全保证：博弈收敛到纳什均衡时，防御者对任意对抗输入的响应均安全。

## 1. 背景与动机

主流 LLM 安全对齐是一个**反应式、解耦的两阶段循环**：先在静态模型上挖掘漏洞（red-teaming），再通过重训练打补丁（defense patching）。这一顺序结构带来两个结构性缺陷：

1. **攻击者过拟合失效漏洞**：固定防御者训练出的攻击者会收敛到少数攻击模式（论文后续量化：Attacker-Only 训练下 86.3% 的攻击坍缩到单一策略"contextualizing the task"），无法持续发现新威胁。
2. **防御者永远滞后**：对静态攻击数据训练的防御者表面指标好，但属于对分布内攻击的过拟合，无法泛化到 OOD 攻击基准。

已有工作要么将自博弈限制在 RNN 语言模型（Perez et al., 2022），要么采用 DPO 等离线迭代方法（SPIN），要么依赖提示微调级的在线对抗训练（每条攻击耗时小时级）。MARL 用于 LLM 的主要障碍是资源开销，常见妥协包括量化、QLoRA、离线迭代更新。本文的动机命题是：**能否在不引入显著计算开销的前提下，让攻击者与防御者在全在线、相互适应的方式下共同进化？**

从音视频技术交叉视角看，这篇论文属于“生成式模型在线对齐/自我改进”方法论文：其核心机制（自博弈生成对抗样本 + 判别器/奖励模型闭环 + 单策略双角色）与音视频内容安全审核（AIGC 音频/视频有害内容防御）、生成模型鲁棒性训练（对抗性 prompt 攻击对多模态生成模型同样成立）存在直接的方法可迁移性——凡是“生成器 vs 审核器”共同进化的系统，都可以套用这套零和博弈框架。

## 2. 方法总览

**博弈形式化**：将红队定义为二人零和博弈。攻击者 πA 生成 prompt yA，防御者 πD 生成响应 yD，奖励模型 rϕ(yA, yD) ∈ [−1, 1] 打分。目标为 min-max：

min_{πA} max_{πD} E[rϕ(yA, yD)]

**理论保证（Theorem 1）**：当 (π*A, π*D) 为纳什均衡时，对任意 prompt yA 有 rϕ(yA, π*D(yA)) ≥ 0，即响应安全。证明采用反证法（附录 B）：若存在 y′A 使 rϕ = −1，则恒输出 y′A 的攻击者策略使 V = −1；而“朴素全拒绝”防御者 π′D 对任意输入安全、获得非负奖励（论文明确假设：朴素拒绝响应得零奖励，即“安全但低质量”，与 RLHF 奖励模型同时评估有害性与帮助性一致），这与纳什均衡定义矛盾。两点关键限定：该定理是**关于均衡的安全性质陈述，不保证收敛到均衡**；且它只针对纯零和收益 rϕ。

**工程实现框架**：单一 LLM πθ 分时扮演两个角色，每轮攻击者先手、防御者后手：

- 攻击者接收种子 prompt s（来自支撑集 S，混合有害/良性种子），在隐藏 CoT 规划后将 s 改写为对抗性变体 yA（有害种子→更隐蔽且保留恶意意图；良性种子→形似有害实为无害的诱导性 prompt）；
- 防御者接收 yA，经自己的隐藏 CoT 后生成公开响应 yD；
- 裁决器（guard 模型）输出三个标签：query 有害性 Qharm、response 有害性 Resharm、response 拒绝 Resrefuse；
- 双方按零和收益 + 塑形项获得奖励，用 Re++（critic-free 的 PPO 变体，Hu et al., 2025a）在线更新共享参数。

**良性种子改写是防退化关键设计**：若防御者面对的全是有害 prompt，会学出“全拒绝”的平凡策略；混合良性种子使攻击者还能通过“诱导防御者拒绝良性 prompt”获胜，从而约束过拒绝。

## 3. 关键设计

### 3.1 Hidden Chain-of-Thought（隐藏思维链）

每个角色的输出统一为 `<think>…</think><answer>…</answer>` 模板，**只有 answer 部分作为公开行动传递给对手，think 部分保持私有且不参与博弈评估**。这使双方都能做策略规划而暴露最少信息——对抗博弈中公开推理等于给对手递刀。即使初始策略不完全支持 CoT 格式，自博弈训练也会在角色指令与格式奖励的引导下自发发展出 CoT 推理（论文在冷启动设置下验证了这一点）。消融显示该设计对 Llama 系模型尤为关键：无 CoT 的自博弈在 Llama3.1-8B-IT 上良性合规崩到 0.528（有 CoT 恢复到 0.936），说明隐藏 CoT 支撑了更细粒度的“拒绝 vs 合规”决策。

### 3.2 奖励结构：零和核 + 约束塑形

**零和核（游戏结果奖励）** R_{P,game} = R_{P,res_harm} + R_{P,res_refusal}：

- 响应有害性子奖励：防御者响应无害得 +r_harm、有害得 −r_harm，攻击者取负；
- 响应拒绝子奖励：以 Qharm(yA) 为条件——有害 query 被拒绝（+）或良性 query 被合规（+）防御者得分，有害 query 被合规（−）或良性 query 被拒绝（−）扣分。攻击者同样取负。**这使拒绝行为本身也成为博弈目标**：攻击者诱导出对良性 prompt 的拒绝即获胜。

**塑形项（约束正则）**：

- CoT 格式子奖励 R_{P,format}：输出可解析为 think/answer 两段得 +r_format，否则 −r_format；
- 改写忠实性子奖励 R_{A,revision}（仅攻击者）：改写后 prompt 的有害性分类与种子一致得 +r_revision，否则 −r_revision。作用是保证防御者看到平衡的 prompt 混合、抑制过拒绝，同时防止攻击者靠“把良性 prompt 改成有害”这种偏离博弈本意的捷径获胜。

**理论与实现的桥接（附录 B.1）是本文方法学上很讲究的一处**：塑形项不是对收益的修改（那会破坏零和结构），而被重解释为对策略空间的约束——约束博弈 min_{πA∈CA} max_{πD∈CD} E[rϕ] 仍保持纯零和收益，Theorem 1 逐字适用；实现的软惩罚是约束的惩罚函数松弛，λ→∞ 时精确恢复约束博弈，有限大 λ 时与约束博弈均衡的逼近误差有界（引用 Bertsekas 1999、Paternain et al. 2019 的标准结果）。

### 3.3 单模型双角色的在线训练算法

训练循环（Algorithm 1）：冻结 πθ_old 生成 N 条自博弈 rollout → 计算双方奖励 → 计算 token 级优势 → M 步梯度累积更新。

**角色专属优势归一化**是使单模型能同时学习两个对立奖励信号的关键工程发现：对 A、D 两角色的优势向量**独立地在各自 batch 内归一化**（Eq. 3，减均值除标准差），再做 PPO 式裁剪目标（Eq. 4）。若不做角色分离归一化，两个符号相反的奖励信号在同一参数上会产生系统性冲突。

Re++ 的优势估计为 reward-to-go 加 token 级 KL 惩罚（对参考策略 π_ref，β=0.01），critic-free 意味着无需价值网络、每条 prompt 只处理一次，这是计算上可行的前提。超参：学习率 5e-7 余弦退火至 5e-8，300 步上限、200 步早停，rollout 温度 1.0，上下文/生成长度均 2048，4×H200-141GB，单实验约 2–4 小时。

**辅助 SFT 正则**：纯博弈奖励训练出的模型安全但对话质量下降（AlpacaEval-2 降低），因此可选地混入自蒸馏 SFT 数据集 D_SFT 共同优化。自蒸馏流程：基模型生成 benign prompt 的 completion → 用同一模型“事后补写”导致该 completion 的推理过程→ 拼成 三元组，经分类器过滤有害/错误拒绝样本（<3%）。

**数据配比**：RL 用 26,000 条 WildJailBreak prompt（vanilla_harmful : vanilla_benign = 50:50），其中实际组成是 25:25:25:25——各 25% 的有害/良性种子直接用、另各 25% 交给攻击者改写，保证防御者对原生与对抗攻击均衡暴露。SFT 用 30,000 例（WildJailBreak benign 15k + HelpSteer3 15k）。

**单模型而非双模型的设计论证**（附录 E.1）：双模型要么翻倍显存、要么大规模参数 offload；单模型让两角色共享同一 vLLM 推理引擎与单份参数，可复用标准安全训练流水线；同时同源初始化使模型暴露并修正自身盲区，而非过拟合外部对手的攻击分布——这是“自我改进范式”的本体。

## 4. 实验结果

**设置**：5 个模型（Qwen2.5-3B/7B/14B-IT、Llama3.1-8B-IT 及其 abliterated 变体-AB），判官默认 WildGuard-7B；11 项静态安全评测（HarmBench/WildGuardTest/WildJailbreak/DAN/OR-Bench/XSTest/StrongREJECT 等）+ 3 项动态攻击（X-Teaming 多轮 agentic、PAIR、AutoDAN）+ AlpacaEval-2 能力保持。

**主表（Table 1）关键行**，以 Qwen2.5-14B-IT 为例（ASR↓ / RTA↑ / AlpacaEval-2 LC↑）：

| 方法 | WG:Test adv harm | WJB adv harm | DAN | HarmBench adv | XSTest vani harm | WJB adv benign | AlpacaEval-2 |
|---|---|---|---|---|---|---|---|
| Qwen2.5-14B-IT | 0.169 | 0.742 | 0.217 | 0.131 | 0.056 | 0.992 | 36.91 |
| + SELF-REDTEAM | 0.080 | 0.372 | 0.106 | 0.064 | 0.010 | 0.969 | 38.09 |

全部 4 个 RLHF 对齐模型的平均相对安全提升：Qwen2.5-3B +33.4%、7B +39.5%、14B +44.7%、Llama3.1-8B +45.2%，同时过拒绝极小（良性合规多数仅降 1–3 个百分点），Qwen 系列 AlpacaEval-2 反而最高 +4.5%。对安全被剥除的 Llama3.1-8B-IT-AB（起点近零安全），全部安全指标大幅改善（如 WJB adv harm ASR 0.991→0.240，OR-Bench RTA 0.014→0.846），证明该方法可作为独立安全对齐管线。**摘要宣称的“up to 95% ASR 降低”对应 IT-AB 与 Qwen 系列多项指标（如 Qwen2.5-14B 的 WJB vani harm 0.022→0.000，+100%；Llama-AB DAN 0.937→0.396，+57.7%）。**

**动态攻击鲁棒性（Table 4，ASR↓）**：

| 模型 | X-Teaming | PAIR | AutoDAN |
|---|---|---|---|
| Qwen2.5-14B-IT → +SRT | 0.76 → 0.66 (+13.2%) | 0.218 → 0.108 (+50.7%) | 0.170 → 0.105 (+38.2%) |

三方法全部下降，平均 31.3%——泛化表明学到的是防御模式而非对特定攻击格式的过拟合。

**相对两个代表性防护基线**（附录 D.2）：LLM-LAT 安全指标近乎完美但过拒绝灾难（Llama XSTest VB 0.924→0.004）；CircuitBreaker 保能力但安全增益有限（Qwen2.5-7B WG:Test AH 0.303→0.297，几乎无效）。SELF-REDTEAM 在保持良性合规（0.948/0.964）的同时取得实质安全提升，是更实用的安全-效用折中。作者还强调跨模型族（Llama→Qwen）迁移时学习率、batch、KL 系数、SFT 系数**零调整**，相比依赖特定层选择的 LoRA 类干预（LAT、CircuitBreaker）更稳健。

**奖励模型无关性与反 reward-hacking 证据（Table 3 + 三重证据）**：把判官从 WildGuard 换成 Qwen3Guard，Qwen2.5-7B 在 11 项安全指标中 8 项进一步改善（平均 +4.0%）。防“只是过拟合训练判官”的三条独立证据：跨判官族训练仍提升 WildGuard 评分；动态攻击用完全独立的判官（HarmBench-Llama-2-13B / GPT-4o）仍降 ASR；XSTest/StrongREJECT/DAN/OR-Bench 用自带标签评分，全部改善。

**计算开销**：自博弈比 Defender-only 多约 44–48% 时间，与训练样本量 50% 的增长几乎线性匹配，无额外 GPU 显存；含 SFT 阶段总时长 3h32m vs 基线 3h35m（Llama3.1-8B-IT），基本持平。

## 5. 消融要点

消融在 5 个模型上系统对比六种配置（Table 2 + 附录 D.1），核心结论：

**（1）自博弈 vs 静态攻击者训练（安全性来源）**。Qwen2.5-14B 上 Self-play + SFT 相比 Defender-only + SFT 额外获得 17.33% 的安全鲁棒性提升，且对话质量更高（AlpacaEval-2 38.09 vs 35.50）。Defender-only 训练曲线快速收敛到近乎完美的无害性胜率，但这是对静态攻击的过拟合，OOD 基准上失效。训练动态分析还显示 Attacker-Only 靠“不忠实改写”维持高攻击成功率（忠实度跌至约 60%），而非真正扩大攻击覆盖。

**（2）攻击多样性：自博弈防坍缩**。基于 1000 个不同种子，Attacker-Only 的攻击（t-SNE + DBSCAN 聚类）收敛到少数主导模式；Self-play 攻击多样性持续保持，摘要口径 +17.80% SBERT 多样性。新颖性量化（Llama3.1-8B-IT-AB 基座，Table 16）：基模型对 Self-play + SFT 攻击的困惑度从 8.62 升至 24.74（+16.12，近 3 倍）；GPT-4o 按 WildTeaming 35 策略分类（Table 17），Attacker-Only 86.3% 坍缩到单一策略，Self-play 无单策略超 30%，有效策略数 4.6 vs 1.9（2.4 倍）——多样性提升是策略级而非表层改写。

**（3）Hidden CoT 的作用分化**。对 Qwen2.5-14B 增益温和（良性合规 0.969 vs 无 CoT 的 0.948）；对 Llama3.1 系是刚需：无 CoT 自博弈在 Llama3.1-8B-IT 与其 AB 变体上良性合规分别崩至 0.528 / 0.470，加 CoT 恢复到 0.936 / 0.806。无 CoT 变体在纯安全指标上往往最低 ASR（如 Llama 8B-IT 的 WJB adv harm 0.024），但代价是严重过拒绝——印证 CoT 支撑“该拒才拒”的细粒度判断。

**（4）辅助 SFT 恢复能力**。纯 RL（Self-play、Defender-only）均显著拉低 AlpacaEval-2（Qwen2.5-14B 分别 20.99 / 22.51 vs 基座 36.91），SFT 共训分别恢复到 38.09 / 35.50。通用能力（IFEval/ARC-C/GPQA/MMLU/TruthfulQA）损失很小，但 IFEval 在纯 RL 下下降明显（Qwen2.5-14B 0.804→0.691），SFT 恢复至 0.743——格式遵循类能力对 RL 安全训练最敏感。

**（5）Llama 特有的攻击者拒绝现象**（附录 E.2）。参数共享使 Llama 基座的安全对齐“泄漏”进攻击者角色：Llama3.1-8B-IT 攻击者拒绝改写率 25.27%（Qwen 全系 <0.11%），abliterated 变体降至 7.21%。有趣的是出现拒绝的 checkpoint 安全指标反而略好（WJB harm 0.262 vs 0.332）而良性合规略差。作者论证这是 Llama 基座过拒绝倾向的个体特性而非框架缺陷。

## 6. 贡献与启示

**方法学贡献**：(1) 首个可扩展、端到端的全在线 MARL LLM 安全训练框架，无量化/LoRA 妥协，单实验 4×H200、2–4 小时即完成，具备工程可复现性；(2) 角色专属优势归一化 + 隐藏 CoT + 忠实性塑形三项设计共同解决了“单模型学对立奖励”这一核心矛盾；(3) 把带塑形项的实际目标与零和博弈理论通过“约束解释 + 惩罚松弛”严格衔接，而非口头宣称博弈论动机——这种理论-实现对齐方式值得同类生成模型对抗训练工作借鉴。

**范式启示**：从“反应式补丁”转向“主动协同进化”。传统 RLHF 优化模型对抗静态人工数据；本框架证明在线生成式对抗交互可以驱动安全与鲁棒性的共同进化。冷启动设置下非推理初始策略 + 简单格式奖励即可自发涌现隐藏 CoT，与 R1 类纯 RL 涌现推理的观察形成安全域的呼应。

**局限与注意点**（基于论文自身口径）：Theorem 1 不保证收敛，且实证中 defenders 未达零危害；安全保证以奖励模型的判断为准绳——判官本身的可操纵性是剩余风险面（论文用三重独立证据缓解但未消除）；攻击者产物具有 dual-use 性质，作者给出系统提示拦截、token 级分类器在线监控、门控发布三层防护方案（附录 F）。对下游应用者，最实用的信息是：该训练可作为标准安全微调的 **drop-in 替代**，跨 Llama/Qwen 族超参零调整，且不依赖架构特定的内部干预（与 LAT/CircuitBreaker 形成对照）。
