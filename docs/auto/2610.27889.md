# Elicitation or Expansion? Demystifying Gains from Agent Harness Optimization

## 1. 背景与动机

Harness 指语言模型智能体中管辖模型输入、上下文组装、工具交互与执行状态的外层程序（prompt、context、agent 代码、执行工作流）。Harness optimization 在不更新求解器权重的前提下反复评测—修订这套外层程序，近期已从 prompt（TextGrad、GEPA）与 context（ACE）扩展到 agent 代码与执行工作流的搜索（ADAS、Darwin Gödel Machine 等），在各类基准上取得大幅聚合分数增益。但聚合分数无法回答增益的性质：是 elicitation（把基线本可解的任务变成更可靠的成功，甚至只是把已有正确答案重排成满足评测格式），还是 expansion（扩大至少一次可解的任务覆盖面）。这一区分对下游并非修辞问题：当成功轨迹用于自训练（STaR 式 bootstrapping）、verifier 选择（Cobbe 式 best-of-n）或递归自我改进/进化搜索时，coverage 决定可用成功经验的广度，稀有地解开此前不可达的任务是后续搜索与学习的种子。

方法论借镜来自 RL 社区的 pass@k 之争：Yue et al. (2025) 发现 RL 后模型的 pass@1 增益会在大采样预算下缩小乃至反转，指向采样效率提升而非覆盖扩张；Wen et al. (2026)、Zhai et al. (2026) 在不同评测口径（有效推理判定、附加工具使用）下报告了更广覆盖；Zhang et al. (2026a) 表明覆盖增益依赖预训练暴露与训练任务难度；Noukhovitch et al. (2026) 记录了 RL 增益偏向初始能力更强任务的 Matthew 效应。Harness optimization 领域此前只有零散分析（prompt 编辑因果归因、执行缺陷修复归因、与简单重试对比），缺少同等级的系统诊断。

本文的贡献不是新优化算法，而是一套诊断协议加系统性实证：以 pass@k 曲线对比优化前后 harness 的可达任务覆盖，叠加“更强参照”（同族更大模型或同模型更高推理努力）与难度分层两个轴，并在静态预测任务与动态任务上交叉验证。对以 LLM 为编排核的多模态/音视频智能体栈而言，这等价于追问“改调用层能否替代换更大基座或加推理预算”——该问题与评测协议均可直接迁移（详见第 6 节映射）。

## 2. 方法总览

形式化上，固定求解器 M，harness 优化求解 max_H J(M,H)=E_{x~X, τ~π_{M,H}(·|x)}[r(τ,x)]。系统定义三组：基线 (M, H0)、优化 (M, H⋆)、参照 (Mref, H0)——参照用 base harness 配更大模型或同模型更高 reasoning effort，为 harness 单独增益提供经验锚点。三组在同一测试集、同一 scorer 下重复完整执行（含全部内部模型调用与工具交互），n 次 rollout 估计 pass@k：静态任务 n=k=64，动态任务 n=k=128。

优化器采用 Meta-Harness：coding-agent proposer（Claude Opus 5）选择性检视历史 harness 代码、验证分数与执行轨迹以诊断失败并提出修订候选，每候选评测后代码与反馈保留进入下一轮；每次优化 20 轮迭代、每轮至多 2 个提案；H⋆ 按验证表现选出（HotpotQA 先验证集 shortlist、再在独立 selection 集上按 EM 终选；AppWorld 在 dev 集终选）。

任务面覆盖静态与动态两类。静态为三套文本分类联合优化（GPT-OSS-20B 基线 vs GPT-OSS-120B 参照，temp 0，medium effort）：Symptom2Disease（症状→诊断）、LawBench（罪名集合预测）、USPTO（反应物 SMILES 集合预测）；H0 为 few-shot harness（每次查询/重复重采样演示），H⋆ 从同一示例池构建 memory 并按测试输入检索构造上下文。动态两块：HotpotQA（Qwen3-8B vs Qwen3-32B，temp 0.6；H0 为 GEPA 的 multihop 种子程序 + 固定 BM25 检索器，两轮检索后作答；优化对象是管辖查询构造、证据处理、答案生成的 harness 代码，资源上限 4 次 solver 调用/2 次检索/每次检索 7 段，与基线对齐）；AppWorld（GPT-OSS-120B medium vs high effort；H0 为基准官方简化 ReAct；每次尝试限 50 次 solver 调用、50 步环境交互、2400 秒超时，high effort 放宽至 7200 秒；重复评估 temp 1）。测试集规模：HotpotQA 300 题、AppWorld test_normal 168 题（均带原始难度标签），静态各 100–212 题。OOD 迁移将 ID 选出的 20B harness 直接用于 FiNER/GoEmotions/Banking77，两种 harness 均提供 200 条目标域标注示例，不做进一步代码优化。

## 3. 关键设计

**pass@k 无偏估计与选点分歧。** 覆盖估计沿用 Chen et al. (2021) 的无偏估计 pass@k = 1 − C(n−c_i, k)/C(n, k)（任务等权，i.i.d. 尝试假设下无偏；k=1 退化为平均任务成功率，k=n 为等规模池下至少成功一次的任务占比）。核心概念区分：pass@1 度量期望成功执行数（mean accuracy），pass@k 度量 k 次内至少一次成功的任务占比（coverage）；一个 harness 可以靠反复解同一批任务获得高 pass@1 而覆盖停滞。作者在一次 HotpotQA 优化 run 内对候选做了 300 题 × k=128 的双指标评测：pass@1 最高的候选与 pass@128 最高者不是同一个——这对以验证集均值选点的自动优化器是直接警告：重复评测可提高 pass@1 精度，但不能替代覆盖测量。

**打分器防伪影（结论成立性的前提）。** 作者显式处理了 scorer 伪影翻转系统排序的风险：HotpotQA 上 EM 产生大量假阴性（完整回复内含参考答案但非逐字匹配，如“Marcy Playground was formed first.”判 EM=0），128 次尝试下 EM 使 Qwen3-32B 的 pass@1 反直觉地低于 Qwen3-8B；改用 Judge = (答案包含 ∧ LLM 正确性判定) 后排序反转。AppWorld 上用 arity-fixed TGC：原成功保持成功，动作尝试仅在全部状态检查通过、无执行错误、且唯一失败检查是“未要求的答案”时才额外接受；原 TGC 在 128 尝试下把 120B 排到 20B 之下，arity-fixed 反转。方法论含义：跨系统 pass@k 比较之前必须先证明打分器本身不翻转系统排序。

**任务级成功集合分解。** 定义 S0、S⋆ 为两 harness 下至少一次成功的任务集，分解为 retained（S0∩S⋆）/new（S⋆\S0）/lost（S0\S⋆），并将 pass@1 增益按 pp 归因到三部分，直接量化“频率提升”与“覆盖变化”各自的贡献；配合任务级成功分数分布（零成功/间歇成功/全成功三分）判断各数据集的 headroom 结构。

**参照系统对齐与预算控制。** 参照与优化系统共享 base harness，资源上限对齐（HotpotQA 同 caps；AppWorld high effort 超时放宽以避免人为压制参照）；另设 relaxed caps（12 次调用/12 检索/20 段 vs tight 的 4/2/7）消融，确认预算不是覆盖瓶颈。

**难度分层与 hard-focused 再优化。** 用基准自带难度标签对 pass@k 曲线分层；并单独做了一组把优化任务 mixture 偏向 hard 的再优化（Qwen3-8B，HotpotQA），检验定向施压能否转化为 hard 覆盖扩张。

**随机猜测对照。** 单标签数据集上解析给出均匀猜测的期望覆盖 1−(1−1/L)^k，排除“大 k 增益来自猜测膨胀”的替代解释：四个单标签数据集上两 harness 在小 k 即全面超过均匀猜测覆盖。

## 4. 实验结果

**静态任务：单次优势随 k 反转。** LawBench 是最清晰的案例：优化 20B harness 的 pass@1 达 44.00%，超 120B 参照（27.95%）16.05 pp，曲线在 k=11 交叉，pass@64 反落 4.00 pp（56% vs 60%）。Symptom2Disease 上 pass@1 与 120B 持平但 pass@64 略低于参照且低于自身 H0；USPTO 上 pass@1 本就低于参照，pass@64 覆盖虽有提升（28→32 任务）但 100 题中 68 题在 64 次尝试内零成功。

| LawBench（静态，n=k=64） | pass@1 (%) | pass@64 (%) |
|---|---|---|
| GPT-OSS-20B · H0 | 18.86 | 53.00 |
| GPT-OSS-20B · H⋆ | 44.00 | 56.00 |
| GPT-OSS-120B · H0 | 27.95 | 60.00 |

成功集分解揭示了增益来源：LawBench 基线 64 次内解出的 53 题中，H⋆ 保留 49、丢 4、新解 7；25.14 pp 的 pass@1 增益中 21.02 pp 来自 retained 任务的频率提升，仅 4.64 pp 来自新解任务（另 −0.52 pp 流失）。Symptom2Disease（203→201 题，+3/−5）与 USPTO（28→32 题，+7/−3）呈同构模式。作者据此类比 RL 中的 Matthew 效应：harness 优化把增益集中在基线已有成功（即存在成功先例可被 proposer 从轨迹中诊断）的任务上。

**动态任务：贴近更强参照但不稳定超越。** HotpotQA 上两个优化的 8B harness 在 pass@1 均超 32B 参照，但 pass@128 仅一个保持领先；附录中 GPT-OSS-20B 优化后 pass@128 达 89.00%，反超 120B base harness 的 85.33%。AppWorld 上两个 medium-effort 优化 harness 在曲线端点均低于 high-effort 参照（其一仅在 k=2 短暂超越），pass@64 为 91.07% vs 91.67%。机制差异在于环境交互：harness 在动态任务中重塑动作进而重塑后续观测。典型案例：HotpotQA 基线 harness 第二轮检索仅复述原问题，导致"George Litto"摘要在全部 128 次 rollout 中不可达、最终回答“Blow Out 制片人未提及”；优化后改为查询已解析的 bridge entity，125/128 次命中该摘要、122 次答对——把不可达的外部证据转化为可用上下文。静态任务没有此类机会，harness 只能重排固定输入的使用方式，这解释了动态任务上优化曲线更贴近更强参照的现象。

**难度分层：聚合掩盖 hard 短板。** HotpotQA hard 子集：优化 harness pass@1 相对 8B 基线有提升，但 pass@128 仅达 70.73–73.17%（两个 run），几乎未超基线的 70.73%，远低于 32B 参照的 78.05%；easy 子集则在整个预算区间持平或超越参照。AppWorld hard 子集：覆盖增益相对自身基线更大（82.54%→88.89–92.06%），但至多追平 high-effort 参照的 92.06%；easy 子集所有系统最终都达到完全观测覆盖。任务级 pass@1 增益散点（harness 增益 vs 模型/effort 规模增益）在三个面板上 hard 组均值一致偏向 scaling。该缺口是系统性的：单次优化 run 的全部 40 个 8B 候选 harness 在 hard 子集上任何 k 处都低于 32B 参照，被选者取得候选中最高的 hard pass@1 但并非最高 hard pass@128。定向 hard-focused 再优化将 hard pass@1 从 56.88% 提至 59.28%（追平 32B 的 59.51%），但 pass@128 停在 73.17%，仍差参照 4.88 pp——显式转向难例换来的仍是频率而非覆盖。

**OOD 迁移：pass@64 三域全败。** ID 选出的 harness 迁移到 FiNER/GoEmotions/Banking77 后，pass@64 分别低于基线 6.00/8.00/11.33 pp；FiNER 与 GoEmotions 上的小幅 pass@1 优势在 k=2 即反转。机制可从代码直接检视：优化 harness 按标签数量与平均标签长度路由 prompt 模板，其 catalog 模板允许多标签分号分隔（兼容 LawBench 多罪名场景），同一启发式误选到要求单一意图的 Banking77——示例查询 "I need a new card and I live in the United States." 被预测为 "order physical card;country support"，金标为 "country support"。领域依赖假设被硬编码进了可检视的路由规则。

## 5. 消融要点

- **记忆策略**：静态任务中 frozen（memory 每数据集构建一次复用）vs rebuilt（每次重复重建）两种策略下结论不变——LawBench pass@1 为 44.00 vs 43.53，pass@64 为 56 vs 53，均低于 120B 参照的 60；Symptom2Disease pass@64 两种策略均低于 H0 与参照。
- **资源上限**：HotpotQA 上 relaxed caps（12/12/20）相对 tight（4/2/7）不产生更高覆盖：3 runs 均值 pass@1 为 73.39±1.60 vs 72.50±1.43，pass@128 为 87.22±1.54 vs 87.78±1.39（n=128，Judge 口径）——覆盖缺口不是预算伪影。
- **更强模型自优化**：GPT-OSS-120B 上重跑优化，LawBench pass@1 从 27.95% 升至 38.66% 而 pass@64 从 60% 降至 59%；Symptom2Disease pass@64 下降、USPTO 全程低于基线——“提频率不提覆盖”不限于小模型。
- **打分器对齐重跑**：将 Judge / arity-fixed TGC 同时用于优化、选择与评测，主结论复现：总体增益从 pass@1 到 pass@128 收窄，且 hard 子集全程低于更强参照。
- **run 间变异**：每基准重复 3 次优化 run；静态任务三个优化系统在 pass@64 全部低于 120B 参照，HotpotQA/AppWorld hard 子集无任何 run 在曲线上任何点超越参照；增益幅度随 run 波动但定性结论稳定（样本 SD 含评测与 preparation 噪声，未单独剥离优化器方差）。
- **随机猜测对照**：四个单标签数据集上两 harness 在小 k 即超过均匀猜测覆盖（如 Banking77 pass@4：猜测 5.09% vs H0 89.73%），大 k 优势不能由猜测解释。

## 6. 贡献与启示

**方法论贡献**：把 RL 领域的 pass@k 诊断协议系统移植到 harness optimization，形成“覆盖曲线 + 更强参照 + 难度分层 + 成功集归因”四件套；并实证了 pass@1 选点与 pass@128 目标的分歧（同一 run 内两个 leader 不重合），对一切以验证均值驱动的自动 harness/agent 搜索方法构成直接警示。**实证结论**：harness 增益的主体是 elicitation——把既有成功变得更频繁；expansion 主要出现在动态任务中信息获取路径被改写的情形（bridge-entity 重查询一类）；hard 任务覆盖缺口是系统性的（跨候选、跨 run、跨 hard-focused 定向优化、跨模型规模），指向瓶颈在模型能力而非编排层。作者在结论中明确将“hard 任务上一致的能力扩张”列为开放问题，并建议搜索与选择方法显式奖励“此前未覆盖难例上的验证成功”、保留成功集互补的候选。

工程层面四条可执行纪律：(1) 部署前按目标尝试预算 k 与目标任务组做 pass@k 审计，勿以 pass@1 外推；(2) 与可行的更大模型/更高 effort 替代方案在同一子集上对比后再下“harness 可替代 scaling”的结论；(3) OOD 部署先跑目标域基线对照，并检视 harness 代码中的领域依赖路由假设做针对性测试；(4) 严格匹配类打分器需先验证不翻转系统排序（Contain+判分器或软对齐），否则排序结论继承打分器伪影。

**音视频上下游映射（引擎解读，非论文原文主张）**：下游看，以 LLM 编排感知工具（ASR、镜头切分、跨模态检索、时序定位、重转写）的音视频智能体，其 harness 层完全可被同类方法优化，本文诊断协议可直接移植到视频问答、音频事件检测与生成式任务的评测——尤其 verifier/best-of-n 选优流水线：可用轨迹池的广度由 coverage 而非 pass@1 决定，本框架给出的成功集分解正是量化“样本池是否变宽”的工具。上游看，对多模态基座选型的含义是：若难样本缺口源于基座感知能力（细粒度时序 grounding、声学事件辨别），改写编排层收益有限，应优先更大/更强基座或更高推理预算；反之，证据获取受限型任务（多跳检索式视频问答、需重看/补采/换查询的交互式定位）是 harness 优化的高杠杆区——对应本文“动态任务中优化曲线更贴近更强参照”的发现。此外，标签统计路由的 OOD 教训直接映射到多标签本体（AudioSet 类）与单标签意图分类间的迁移场景：基于标签数量/长度的模板路由会把源域输出约定（多标签分隔符）硬编码带入目标域；EM 假阴性问题在生成式音视频任务（captioning、开放式问答）中同样普遍，是排序稳健性的第一道关卡。

## 7. 与其他论文的联系

- **paper:arxiv:2611.08946（Flex-RSI）**：其基准以固定预算评估智能体通过递归修订 harness 实现自我改进，修订 harness 正是本文的审计对象。本文结论——增益集中于基线已有成功的任务、hard 覆盖不超过更强参照——提示 Flex-RSI 在视觉/机器人任务上的增益应补做 pass@k 与难度分层诊断；且其任务属交互式动态环境，恰是本文发现 harness 优化最可能逼近更强参照的类别，两者互为验证场景。
- **paper:arxiv:2611.10463（LongCapHarness）**：宣称免数据合成与后训练、以递归自我改进挂接长上下文推理底层能力，在 HELMET/RULER 上超越基线且成本减半。本文提供的正是判定此类“能力级增益”属于 elicitation 还是 expansion 的工具：大 k 覆盖曲线与 hard 子集的更强参照对照，是对其“挂接底层能力”主张的必要后续检验。
- **paper:arxiv:2611.13524（The RSI Tax）**：方法论同构——都以更简单的参照系为锚定（本文用更大模型/更高 effort，彼文用有界笔记基线），要求自改进增益在成本—收益坐标上被审计而非只看聚合精度。本文在其之上补了覆盖维度：pass@1 持平不等于可用成功经验池等宽。
- **paper:arxiv:2611.12109（SkillDuet）**：外部技能库演化与 harness 演化同构（协同或独立于权重更新），本文的成功集分解（S0∩S⋆ 归因、retained/new/lost 的 pp 拆解）可直接用于检验技能获取是扩张可解任务面还是仅稳定既有成功，为其响应反馈驱动的技能演化提供同一套诊断口径。
