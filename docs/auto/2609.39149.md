# Rep2Skill: Representation-Guided Skill Self-Evolution for LLM Agents

> Kaixing Zhang, Changming Li, Yingdong Shi, Zheng Zhang, Kaitao Song, Wenjie Shi, Jingang Wang, Kan Ren. *arXiv:2609.39149v2 (2026-09-30)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

在参数冻结的前提下为 LLM agent 积累可复用程序性知识，「技能」（skills，即文本指令 + 程序规则 + 任务策略的集合）是当前主流载体，相较微调具备无训练成本、可审计、可移植的工程优势。技能获取已从人工撰写走向技能演化：agent 从自身执行经验中迭代精炼技能文本。现有方法的学习信号全部来自**外部可观测产物**——EvoSkill 将失败 rollout 归因于能力缺失并修订模块化技能，Trace2Skill 把轨迹局部经验聚合为可迁移技能文档，SkillOpt 将技能视为可训练文本状态、以有界编辑加验证选择的方式更新。

论文指出这一 text-only 范式存在两个结构性困难。其一是 **credit assignment 粒度粗**：任务级成败信号不指明哪些交互 turn 该对结果负责；其二是**归因推理负担重**：optimizer 需从长轨迹文本推断“哪段执行导致了失败、为什么、技能该怎么改”，且可观测轨迹只暴露动作与环境反馈，决策背后的内部状态是隐式的。在本文采用的自演化设定下（同一 LLM 兼任 executor 与 optimizer，无更强外部模型参与），optimizer 能力有限时这两个困难被进一步放大——论文实验中确实观察到文本-only 基线在弱模型上劣化到低于无技能水平的情形。

与之相对，机制可解释性研究已表明 LLM 内部表征编码真实性、工具调用决策、执行失败等行为信息，且部分信号在行为于轨迹中显式化之前就可在中间激活中检出；agent 场景下内部表征与可观测轨迹构成互补证据源。作者由此提出核心问题：**agent 能否通过反思自身内部表征来改进外部文本技能？** 方法直觉是：同一（任务， 技能）组合下采样多条 rollout 构成组，组内表征动力学的差异提供相对证据，用于定位偏离成功执行动力学的 turn，再落地为可执行的技能修订反馈。作者声称这是首个将 agent 轨迹内部表征引入技能演化循环的工作。

## 2. 方法总览

形式化：冻结 agent πθ、技能 s，执行得轨迹 τ=(o₁,a₁,…,o_T,a_T)~πθ(x;s)，任务级得分 r(τ)∈[0,1]，技能期望性能 J_D(s)=E[r]。标准技能演化即 s_{n+1}=O(s_n,τ)，优化信号限于可观测轨迹。Rep2Skill 在此之上引入每 turn 隐状态 h_t∈R^d（固定层提取），构成表征轨迹 H(τ)=(h₁,…,h_T)，闭环分四步：

1. **组式 rollout 采样**：对每个任务实例 x 与当前技能 s_n，从同一 agent 采样 K=4 条 rollout 构成组 G(x,s_n)，作为受控参照。
2. **表征空间 turn 级归因**：用一个仅在成功 rollout 上离线训练的神经受控微分方程（Neural CDE）建模成功执行的潜状态动力学，对每 turn 以前缀历史预测下一 turn 表征，以预测误差 c_t 作为归因分数，取 top-K_c（K_c=3）为关键 turn。
3. **表征→文本言语化**：同一冻结 LLM 作为 analyzer A_θ，输入（当前技能、任务、完整轨迹、关键 turn 及其分数），产出带证据引用的结构化文本反馈 F^(k)，经程序化校验后保留。
4. **文本空间技能修订**：optimizer O_θ（仍为同一 LLM）整合分组 rollout 与反馈生成候选技能，经 selection split 验证门控决定是否接受。

关键定位：**表征信号从不直接编辑技能，只决定 analyzer 看哪里**；技能更新仍完全在文本空间完成，构成「latent 证据 → 接地文本反馈 → 文本梯度」的桥接结构。唯一额外训练组件是 PCA 投影 + Neural CDE 动力学模型，按（模型， 环境）组合离线拟合，约 50 条成功轨迹即可。

## 3. 关键设计

### 3.1 组式采样：以组内相对比较替代单轨迹归因

动机有实证支撑：空技能下同任务同技能的 4 条 rollout 在 turn-5 动作分歧率达 82.7%、turn-10 组内唯一动作前缀占 98.5%——单条轨迹上的技能修订对偶然行为高度敏感。设计上借鉴 group-relative optimization（DeepSeekMath/GRPO 一脉，论文明确引用 Shao et al. 2024）：组内共享任务与技能上下文构成受控参照，组间暴露行为多样性。K 固定为 4；采样种子由（run seed, 任务, 组内 rollout 序号）确定性派生，保证同种子可复现且组内多样。

### 3.2 表征归因：成功动力学偏离度作为 turn 分数

- **提取防泄漏**：表征提取只回放轨迹本体（reasoning + action + observation），当前技能、任务级奖励、失败信息一律不入 prompt，防止结果泄漏进表征；对冻结 agent 做单次 causal forward，读 decoder 第 24 层，turn 内全 token 平均得 h_t。两个模型（4B/9B）同用第 24 层，论文未做层选择消融。
- **投影**：PCA 降到 64 维并逐维标准化；投影与归一化统计只在成功训练 rollout 的 turn 上拟合，避免失败样本污染统计。每个（模型， 环境）单独拟合一份。
- **动力学模型（Neural CDE）**：turn 序号归一化 u_t=(t−1)/(T_k−1)，对时间增广观测 (u_t, h_t) 用 Hermite 三次插值加后向差分构造控制路径，保证 [u₁,u_t] 段只依赖前 t 个 turn（因果性）；首 turn（任务指令 + 初始观测）经 MLP 编码、经小自治 ODE 传播到 u₂ 作初值，因此首 turn 永不评分，打分从 t≥2 开始。隐状态 m=64，向量场 f_ϕ: R^m→R^{m×65} 与初始编码器均为三层 Softplus MLP，控制门 γ_ϕ 为 tanh 激活、输出 ℓ₂ 归一化的 MLP，Euler 求解器，g_ϕ 线性读出。训练目标为一步预测误差，AdamW（lr 1e-4、wd 1e-5、batch 32）、至多 300 epoch、验证集 20 epoch 无改善早停。
- **分数语义**：c_t=‖h_t−ĥ_t‖₂² 度量的是“偏离成功执行动力学的程度”，而非“动作错误程度”——高分局可能对应有用子目标（首次访问关键物体、必要的状态改变）。这一语义边界被显式写进 analyzer prompt，是防止过度归因的关键。训练数据约 50 条/数据集的成功轨迹，取自与训练/验证/测试均不相交的任务集以杜绝泄漏。演化期间投影与 CDE 全程冻结；过短、不够评分的 rollout 不给表征反馈、直接交 optimizer（优雅降级）。K_c=3，同分取更早 turn。

### 3.3 言语化：结构化诊断 + 程序化 grounding 校验

Analyzer 每 rollout 调用一次，输入为当前技能加结构化证据记录（任务、奖励、带 0 基 step ID 的完整轨迹、全部已评分 turn 分数、关键 turn 集合）；输出为不超过 180 词摘要加至多 3 条诊断，每条必属五类之一：suspect_rule / rule_conflict / execution_deviation / missing_rule / insufficient_evidence，并记录决策上下文、技能原文引用、逐字轨迹证据、反证、适用条件、修改假设与是否建议改技能。

可靠性由**程序化硬校验**保证：技能引用必须是当前技能的精确子串（suspect_rule、execution_deviation 一条，rule_conflict 两条不同引用）；证据必须指向有效 step 且摘录逐字出现；execution_deviation 与 insufficient_evidence 两类禁止 propose_change；任一校验失败则整条响应丢弃，该 rollout 无表征反馈但更新流程照常。Prompt 层还有针对性反偏置条款：“预测误差不等于动作质量或因果”、“首次访问或未找到目标本身不是错误”、“不得臆测未尝试的替代路径会成功”、“修改必须带适用条件而非记忆物体位置”、“空诊断合法、不强迫改技能”。生成上限 2048 token；WebShop 版本替换为域内指引（检查搜索结果、商品属性、选项、价格与购买决策）。

### 3.4 文本空间更新：有界编辑 + 验证门控

沿用 SkillOpt 的「文本梯度 + 有界步长」骨架（关闭其 slow-update 与 meta-skill 模块）。每轮：反思 → 合并（失败/成功驱动 patch 分别按 chunk 4/8 递归层级合并，去重、解冲突、优先保留被多组支持的编辑作为系统性失败证据，最终合并失败驱动优先）→ 编辑选择（按系统性影响、互补性、泛化性、可操作性排序，预算 L=4 恒定，充当文本学习率）→ 应用（精确串匹配顺序执行；replace/delete 目标缺失则跳过，insert_after 锚点缺失退化为 append）→ 门控（在 selection split 上评估，ALFWorld 用成功率、WebShop 用任务分；严格优于当前技能才替换）。另维护 step buffer 记录被拒编辑与失败模式摘要，回灌后续反思以避免重复无效修订；报告口径为演化全程最优技能在测试集上的表现。

## 4. 实验结果

**设置**：ALFWorld 39 训练 / 18 选择 / 134 测试（valid_unseen），每回合 ≤50 步，报成功率；WebShop 25/20/100 条指令，≤15 步，任务分缩放到 [0,100]、成功定义为满奖励。所有 split 对各方法、模型、种子冻结共享。演化 3 epoch（ALFWorld 每 epoch 1 个 iteration 覆盖全部 39 任务；WebShop 每 epoch 10 iteration × 5 任务），K=4，种子 42/43/44 报均值±标准差。模型为 Qwen3-4B（全注意力）与 Qwen3.5-9B（混合注意力，其技术报告定位为原生多模态 agent 模型）；vLLM bfloat16、thinking 关闭，actor 温度 0.4/0.7（ALFWorld/WebShop），optimizer/analyzer 0.6/0.7。

**主结果（RQ1，Table 1 关键行，均值±标准差，3 次独立演化）**：

|---|---|---|---|---|
| Qwen3-4B | No Skill | 22.64±1.76 | 41.86±1.65 | 13.67±1.53 |
| Qwen3-4B | Trace2Skill / EvoSkill / SkillOpt | 47.26 / 43.03 / 46.51 | 45.68 / 49.48 / 39.04 | 13.00 / 13.33 / 11.67 |
| Qwen3-4B | **Rep2Skill** | **58.21±2.66** | **49.79±5.95** | **16.33±3.51** |
| Qwen3.5-9B | No Skill | 28.61±1.55 | 50.07±2.66 | 18.33±0.94 |
| Qwen3.5-9B | Trace2Skill / EvoSkill / SkillOpt | 52.74 / 59.45 / 62.19 | 24.77 / 33.10 / 52.12 | 12.00 / 15.67 / 18.67 |
| Qwen3.5-9B | **Rep2Skill** | **69.90±2.88** | **53.56±2.52** | **23.33±3.30** |

ALFWorld 上超出最强基线 10.95 pp（4B，对 Trace2Skill）与 7.71 pp（9B，对 SkillOpt）；WebShop 9B 上成功率 +4.66、任务分 +1.44；4B 上相对 No Skill 成功率 +2.66、任务分 +7.93。**可靠性观察**同样重要：文本-only 基线在弱 optimizer 下可劣化——4B WebShop 上 SkillOpt 任务分 39.04 低于 No Skill 的 41.86；9B WebShop 上 Trace2Skill（24.77/12.00）与 EvoSkill（33.10/15.67）双指标均低于 No Skill（50.07/18.33）；Rep2Skill 是全部设定中相对 No Skill 双指标均提升的方法，说明表征证据对“纯文本提炼经验失败”这一模式有系统性纠偏作用。

**归因质量（RQ2，Table 2）**：在 100 条 ALFWorld 轨迹上做非进展 turn 检测，GPT6-Astra 逐 turn 标注正/中/负进展（非进展=中+负，仅用于评测标注、不参与演化回路），轨迹内计算后宏平均；执行与 analyzer 模型均为 Qwen3-4B，K_c=3：

| 输入 | AUROC | AUPRC | P@Top-3 |
|---|---|---|---|
| Trajectory Text | 0.494 | 0.736 | 63.66% |
| Rep.（纯表征分数） | 0.592 | 0.789 | 79.26% |
| Text + Rep.（本文） | **0.838** | **0.876** | **88.22%** |

两个结论：(1) 纯表征分数单独作判别器并不强（AUROC 仅 0.592）；(2) 但作为**指引**注入同一个 analyzer LLM 后，AUROC 从 0.494 拉到 0.838、P@Top-3 从 63.66% 到 88.22%——表征的价值在于与文本互补而非替代，这直接证成了“言语化桥接”而非“端到端打分”的设计选择。文本-only 的 AUROC 0.494 甚至低于随机水平，量化了 LLM 直接从整条 rollout 挑非进展 turn 的失效程度。

**组内多样性（附录 D.1）**：84 组 × 4 = 336 条 Qwen3-4B 轨迹、12 个 ALFWorld 训练任务、空技能下，turn-1 动作分歧率 35.3%（尽管观测相同）、turn-5 达 82.7%、turn-10 唯一前缀占 98.5%；表征余弦距离从 turn-1 的 0.040 升至 turn-5/10 的约 0.154/0.151；前 15 turn 内组内动作编辑距离中位数 0.607、TF-IDF 累积前缀距离中位数 0.387——同任务同技能的 rollout 走的是实质不同的路径，为组式采样与相对比较提供了必要性依据。

**案例**：ALFWorld 任务放置干净马克杯，文本-only optimizer 只见“耗尽交互预算”的终局症状，给出泛化修订“更彻底地搜索”，改后 30 步仍以同一模式失败；表征归因在 turns 17–29 的重复橱柜搜索段持续高分，analyzer 结合上下文定位“搜索始终不超出橱柜”，产出条件化规则“柜内未找到则转向台面/抽屉/水槽”，修订后 8 步在 sinkbasin 找到干净马克杯完成任务。机制本质是把“终局症状级”反思压缩为“turn 段级 + 行为模式级”的技能修订。

## 6. 贡献与启示

**贡献**：(i) 首次（作者声称）把 agent 轨迹内部表征引入技能演化循环，确立表征空间作为可观测轨迹之外的互补优化信号；(ii) 提出表征轨迹建模 + 言语化桥接的完整框架，latent 信号经接地校验后才进入文本优化；(iii) 两基准、两模型上稳定优于文本-only 自演化，且弱 optimizer 下相对增益更大（4B 的 ALFWorld 增益大于 9B），契合自演化设定下最需要帮助的场景。

**工程含义**：白盒依赖是硬约束——需隐状态读取加每 rollout 一次额外 causal forward（论文在独立 GPU 的 HF 进程中以同 checkpoint 提取）；黑盒 API 模型不可直接用，作者提出的代理模型方案未经验证。离线成本可控但不可移植：约 50 条成功轨迹加轻量 CDE 训练，但 PCA 与 CDE 均按（模型， 环境）重拟合，且拟合质量依赖成功样本对成功动力学的覆盖度。可靠性由三层机制叠加：程序化 grounding 校验（逐字引用、step 引用、类型化禁改约束）→ 编辑预算 L=4 充当文本学习率 → selection split 验证门控加 step buffer 回灌；这套 gating 模板对任何自反思更新回路都可直接移植。作者自述局限：白盒限制、模型族单一（仅 Qwen）、约 50 条额外 rollout 与轻量训练的额外开销。

**与音视频技术方向的关联**：本文属 LLM agent 自演化方法论文，实验均为纯文本环境，但所用的 Qwen3.5-9B 底座其技术报告即定位“原生多模态 agent”，方法已在多模态底座上完成文本任务验证。机制本身——隐状态轨迹建模 → turn 级 credit assignment → 言语化技能修订——对模态不敏感，天然适配长视野、稀疏回报的多模态 agent 场景：音视频流水线 agent（素材检索 → 转码/剪辑 → 渲染质检）、流媒体运维 agent、具身感知 agent 均属此类。音视频 agent 的可观测轨迹（工具调用日志）对感知状态欠表达，失败归因比文本环境更模糊——渲染失败或质量不达标这类终点信号无法指明是检索、切点、参数还是编码环节的问题，恰是“内部表征偏离成功动力学”这一相对证据的适用区。迁移约束需评估：多模态隐状态的层语义与文本模型不同（第 24 层结论不可直接搬用）；表征提取的额外前向对实时/流式 agent 的延迟预算构成压力；按环境重拟合意味着每条流水线需单独收集成功轨迹。另外，“结构化诊断 + 逐字证据校验 + 类型化禁改约束”的言语化模板可脱离表征信号单独复用，适用于任何将遥测/指标转化为 agent 反馈的管线（如转码 QoE 指标驱动剪辑策略修订）。

## 7. 与其他论文的联系

- **SkillDuet（Co-Evolving Models and Skills through Response Feedback）**：同属技能级递归自改进，但两文正交——SkillDuet 用响应反馈同时更新 LLM 参数与外部技能库（参数 + 文本双演化），Rep2Skill 冻结参数、只演化文本技能、却把参数侧的内部表征引入为学习信号；分别回答“演化什么”与“信号从哪来”，两者原则上可叠加。
- **When Should Agents Remember?（FGSE，Falsification-Gated Self-Evolution）**：共同关切是自生成经验不可靠、直接写入记忆有风险。FGSE 将经验教训视为可证伪假设、经三类探针验证后才写入；Rep2Skill 的对应机制是程序化 grounding 校验 + 诊断类型约束（execution_deviation / insufficient_evidence 禁止提议修改）+ 验证门控。两者同属“先验证后写入”的安全更新范式，FGSE 更系统的探针设计与 Rep2Skill 的表征证据可互相补强。
- **Trustworthy Recursive Self-Improvement with Statistical Guarantees（TRUST）**：为递归自改进回路提供在线多重假设检验的错误演化率统计控制。Rep2Skill 的验证门控只是单 selection split 上的启发式严格改进判据，无任何统计保证；TRUST 式保证是这类门控的自然加固方向。
- **WeightLoop（Weight-Space Programming with Experimental Feedback）**：结构同构的“有界编辑 + 实验反馈验证”闭环，但作用在权重空间（有界参数编辑程序）而非文本空间。Rep2Skill 的编辑预算 L=4 作为文本学习率，与 WeightLoop 的有界参数编辑是“限制更新步长以保稳定”这一思想在不同空间的实例化。
- **LongCapHarness（Capability-Guided Auto-Harnessing for Long-Context Reasoning）**：同属免后训练、免数据合成的自改进路线。LongCapHarness 递归挂接模型长上下文底层能力，Rep2Skill 把执行能力外化为可复用技能；共享“不动参数、以执行反馈驱动、成本低于训练类方法”的哲学。
- **RSI 家族（RSI-PDEbench、InfraRSI、Build, Don't Play/AutoTavern）**：同为无更强外部监督的递归自改进循环，差异在被改进对象（PDE 求解策略、分布式训练基础设施、游戏 AI）。Rep2Skill 的自演化设定（同一 LLM 兼任 executor 与 optimizer）正是这一 regime，其表征侧 credit assignment 信号原则上可注入此类循环中任何“从执行轨迹归因失败”的环节，是对该家族信号来源维度的补位。
