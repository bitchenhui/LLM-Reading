# RSI-Prime: Training Models to Train Models

> Dewu Zheng, Yang Ye, Hongyu Zhang, Jun Yu, Yanlin Wang. *arXiv:2611.23138v1 (2026-11-17)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

模型训练正在从研究者主导的手工训练，经模型辅助训练，走向 LLM 自主规划、执行与迭代实验的范式。当 LLM 的角色从“被训练者”扩展为“施训者”，其模型训练能力本身成为一个需要专门培养的对象，也是递归自我改进（RSI）体系的基础设施。现有自动化后训练研究沿三条线推进：执行框架（AutoTrainess、ImproveAnyTask）、数据构造（DataMaster、ANDES）、训练算法（TREX、Gödel Forest）——这些工作扩展的是智能体可用的工具与方法，而工具的有效使用仍取决于 LLM 能否选择合适的训练路线并根据实验反馈调整。Lim et al. (2026) 的实证结论是关键动机：所研究的智能体能够修复实现缺陷、反复执行训练，却极少根据反馈修订初始策略。即瓶颈在“实验决策质量”而非“执行可靠性”。

RSI-Prime 的切入点是从训练实践本身学习，核心困难在长时程轨迹的监督提取：一条轨迹包含大量实验决策，最终成功不保证每个决策都是值得模仿的行为。论文自己的数据支撑了这一点——即便经过轨迹级过滤，仍有 7.58% 的决策记录被判有问题，其中实现优化类 16.89%、数据源选择类 12.80% 有问题。若整轨迹全量 SFT，会系统性模仿低质量行为。与 RSI-Dojo 的轨迹级收集-过滤路线相比，RSI-Prime 把监督粒度下沉到“决策”：识别决策、沿 Analysis/Choice/Execution 三维度标注质量、以决策级损失掩码做选择性监督，同时保留完整实验上下文。

## 2. 方法总览

流水线分四阶段。

**任务收集与验证**：从 Hugging Face、论文、官方仓库自动收集候选基准，覆盖七个任务类（数学与推理、代码、工具与交互、知识与理解、信息处理、语言与文本、指令遵循），整合进统一任务接口（指定目标模型、资源预算、提交要求，保留各基准打分语义）。预执行验证分三类：协议验证（任务范围、模型身份、提示、生成设置、主指标对齐原始评测要求）、评分器验证（重放可用 Base/Instruct 输出，配正负控制与覆盖检查）、运行时验证（在实际执行主机上测试推理与打分管线）。全部通过才进入轨迹收集，失败需修复并重验。

**轨迹构建与筛选**：长时程实验易中断或提前终止，采用独立监督者监控进度、控制器在剩余预算内恢复中断运行；恢复保留原会话、产物与累计执行时间，监督者干预与智能体动作分开记录。筛选设双门槛：通过 PostTrainBench 的四个轨迹裁判；提交模型满足相对改进 g = (s_post − s_base)/(s_instruct − s_base) > 0.5，即改进须超过参考 Instruct–Base 差距的一半。轨迹保留成功与失败的中间尝试，为决策识别与质量评估提供上下文。

**细粒度标注**：决策识别（窗口化读取 + 跨窗口挂接 + 迭代验证）、质量评估（三维度、三采样、维度内多数投票）、动作标注（人工卡片分类法构建的 5 主类 20 子类体系 + Other，三采样多数投票）。

**决策级掩码训练**：质量判定经源引用映射为消息级掩码，采用保守选择规则，做保持完整上下文的选择性 SFT。

最终规模：350 个基准、350 条完整轨迹、385 个训练段，标注分析覆盖 90,738 条决策记录。

## 3. 关键设计

**决策形式化与粒度选择。** 决策定义为决定实验走向的选择，由 Analysis（解释选择依据）、Choice（指定下一动作）、Execution（记录实施与反馈）构成。核心论据是决策与消息的多对多结构：54.95% 的决策记录引用多条助手消息，57.01% 的被引用消息涉及多个决策，有映射的记录平均引用 1.90 条消息。这直接否定消息级或步级粒度——同一选择的分析、表达与执行反馈分散在多条消息，而单条消息又可能讨论多个选择。决策级是唯一能完整承载“一个选择及其证据链”的监督单元，也是后文压过步级掩码的机理根源。

**质量判定规则。** 每个决策由 GLM-5.3 独立采样三次，沿 Analysis / Choice / Execution 三维度分别多数投票。训练资格判定在维度级判定上做：三个维度均标为 reasonable 或 uncertain 才通过；problematic、not-applicable 或无多数即不合格。用于分析的二元摘要（高质量 92.42% / 有问题 7.58%）是另一套阈值（高质量要求 analysis 与 choice 均 reasonable、execution 为 reasonable 或 uncertain），与分析口径分离——这是易被忽略的实现细节。评估原则明确区分可避免的行为错误与外部环境失败：实验最终成功不自动确立局部决策质量，单次工具调用失败也不自动判定执行有问题；判定只使用决策时点可得的信息，人审同样遵循该原则。

**保守消息选择与损失构成。** 监督选择以源引用将 analysis / choice / execution 内容映射回助手消息，工具结果证据经 tool-call 标识挂到发起调用的消息。多对多关系下采用保守与规则：消息 a 的门控 z_a = ∏_{d∈D(a)} q(d)（D(a) 为其关联决策集，q 为质量通过指示），任一关联决策失败则整条消息掩码，无关联决策的消息（12,094 条、956,754 个目标 token）也一律不监督——论文明确这部分并非因被判错而被掩。最终 token 掩码 m_t = b_t · z_{a(t)}，与原监督掩码相乘，训练目标 L(θ) = −Σ_τ Σ_t m_t log p_θ(x_t | x_{<t})。保留率为 76.25% 消息（68,027/89,211）、75.48% token（33,477,528/44,353,402，按固定渲染器与 GLM-5.3 tokenizer 计）。分动作类看，链接消息内保留率在 68.66%（Other）至 87.77%（评测与诊断）之间。

机理要点：该设计把“条件上下文”与“模仿目标”解耦。失败、修正与环境噪声全部保留为条件输入，模型学习的是“在混乱的真实历史下做出好决策”的条件分布；相对整轨迹过滤（丢弃失败轨迹导致上下文失真）或步级选择（按重要性而非行为质量筛选），它在保持执行分布真实性的同时收紧了模仿目标。代价是召回损失：混合消息中的高质量内容被连带掩码，论文对此直言不讳。

**标注可靠性与验证工程。** 窗口化识别保留完整交互轮，窗口边界关联不明的内容置为 pending、带入后续窗口结合新证据重判，避免因截断强拆决策或错误挂接到前一个决策。迭代验证：每轮对同一版本做三次独立检查（决策完整性、证据支持、边界与证据归属适当性），≥2 通过才保留，否则对相应源区间重识别再验证。人审抽样 400 条记录，双人独立加第三人仲裁：决策识别接受率 98.75%（395/400）、动作分类 99.50%（398/400）、质量评估 97.50%（390/400）；判前原始一致率 99.50/99.75/99.25，Cohen's κ 为 0.831/0.799/0.866。论文诚实声明：人审只评估已有记录，不估计决策识别的召回（漏检率未知）。

**数据分布对动机的支持。** 动作分布上，评测与诊断占 38.43%（34,872 条）、数据准备 27.09%（24,583）、运行时支持 17.85%、模型训练 9.09%、组合与交付 7.23%、Other 0.30%——训练实验的迭代本质集中在数据构造与评测反馈回路，经验远超训练执行本身。而问题记录集中在实现优化（16.89%）与数据源选择（12.80%），“最终分数好”与“局部行为值得模仿”确有错位，为决策级选择监督提供了数据内证。

## 5. 消融要点

监督策略对比在同一语料上进行，各方法均保留完整训练上下文、仅调整助手消息的损失掩码。步级基线改编自 ATLAS 的关键步选择（仅调整步选择预算以对齐保留量），工具失败掩码按显式执行状态（工具报错、非零退出码、超时、信号终止）掩码整条消息。

| 监督策略 | 消息保留 | token 保留 | Overall |
|---|---|---|---|
| Full SFT | 100.00% | 100.00% | 45.61 |
| 工具失败掩码 | 87.69% | 89.15% | 45.12 |
| 步级掩码（ATLAS 改编） | 77.38% | 76.63% | 43.21 |
| Decision SFT | 76.25% | 75.48% | **48.24** |

三点结论：

1. **单纯减少监督不保证收益。** 工具失败掩码与步级掩码均低于 Full SFT（45.12 / 43.21 vs 45.61）；监督选择的粒度与准则才是关键变量。
2. **相近监督量下的粒度对比。** 步级 76.63% vs 决策级 75.48% 的 token 保留，决策级高 5.03 分，五任务占优、HumanEval 打平（83.54）；HealthBench +11.10、Arena Hard Writing +7.57、AIME +6.00。步级在 HumanEval 与 GSM8K 上超 Full SFT 但不具备跨任务一致性。机理差异在于选择准则：步级按“对任务完成的重要性”、决策级按“行为质量”——关键步骤的行为未必适合模仿，二者正交。
3. **显式执行状态不足以刻画决策质量。** 工具失败掩码保留更多监督（89.15% token）却低 3.12 分；执行成功不能确立数据选择、训练方案、评测安排的合理性。它在 Arena Hard Writing 与 GPQA Main 上优于 Full SFT，说明执行状态有部分选择价值但覆盖不全。

行为级分析（用动作分类体系对评测轨迹中的决策质量打分）：整体通过率 Decision SFT 96.11% > 工具失败 91.65% > 步级 90.16% > Full SFT 87.25%；对 Full SFT 在 20 个动作类型中 18 个占优。剔除占比最大的“评测与检查”后重算，95.63% vs 87.40%，说明改进不依赖评测类行为。实质性训练选择提升显著：学习目标 79.27→95.05、数据源选择 84.38→95.73、推理配置 81.77→95.61（Full→Decision）。同时存在诚实负结果：起始权重与存储管理两类的通过率未超过 Full SFT——收益集中在需要结合任务条件做判断的选择上，而非全部操作行为。相对工具失败掩码：推理配置 +10.49pp、样本生成 +6.74pp、数据源选择 +4.97pp；相对步级：17 个动作类型更高，样本生成 +9.49pp、学习目标 +7.40pp。

## 6. 贡献与启示

贡献三层：面向模型训练能力的数据集（350 轨迹 / 385 段 / 90,738 决策，含环境预验证与轨迹过滤）；决策级监督方法（识别 + 质量标注 + 损失掩码，在完整上下文中选择性监督）；PostTrainBench v1.2 上的实证（相对原始 GLM-5.3 +31.95%）。

方法论启示：

- 长时程智能体 SFT 的核心矛盾是“执行分布真实性 vs 监督纯度”。决策级掩码给出第三条路：不清洗、不丢弃轨迹，只在损失层面收紧模仿目标，条件分布保持真实。该思路对一切从工具调用轨迹学习智能体的场景具有直接迁移价值。
- 保守 AND 规则以精度换召回，且无关联消息全部掩码；当决策-消息映射更稀疏时保留率将进一步下滑，方法在更长轨迹上的扩展性值得关注。
- 行为级评测（用动作分类 + 质量判定评估智能体行为而非只看最终分数）把性能增益归因到具体实验行为，是本文被低估的贡献，可作为智能体训练的中间监控指标。

局限（论文披露 + 笔记判断）：质量判定由 GLM-5.3 三采样给出、微调底座亦为 GLM-5.3，自评-自学的循环偏差未被量化；人审不覆盖决策识别召回；HumanEval 存在训练-评测重叠；微调变体未做多运行平均（Arena Hard Writing 的三次运行方差显示单次分数噪声大）；仅验证单一底座，跨智能体泛化未知。

**对音视频技术的上下游关联**：上游可直接复用的技术件——协议/评分器/运行时三重预验证适用于任何以客观指标驱动的自动训练环境；决策-消息多对多映射加消息级保守掩码是模态无关的监督工程，可迁移到音视频模型自动后训练（ASR / TTS / 编解码器 / 视频理解模型微调）的轨迹学习，此类工作同样以“数据配比—训练—评测诊断”迭代为主，与本文 38.43% 评测诊断 + 27.09% 数据准备的分布结构同构。下游能力落点——“有界资源下训练目标模型”的智能体能力，1×H100 / 10h 预算与 4B 级目标模型的设定对中小规模音视频适配任务现实可用；但 PostTrainBench 六任务全部为文本/代码，音视频模态缺席；g>0.5 的轨迹过滤需要 base/instruct 锚定的标量分数（MOS、WER、BD-rate 等可承担但需重设协议），且视频类目标模型的单次训练时长会直接挑战 10 小时累计预算假设。

## 7. 与其他论文的联系

- **TrainExplorer (2611.20430)**：同以 PostTrainBench 为评测场。TrainExplorer 走框架级路线（多智能体规划-执行解耦，加权总分 39.02），RSI-Prime 走参数级路线（轨迹 SFT，48.24），脚手架改进与权重改进互补、可叠加。注意跨文分数对比须对齐基准版本：RSI-Prime 使用 v1.2，其上 GPT-6.1 (Sol)+Codex 为 46.45，与 TrainExplorer 报告的 GPT-5.6 Sol+Codex 36.23 不可直接对齐。
- **InfraRSI (2611.11558)**：同以“自动化模型训练”为目标域但对象不同——InfraRSI 用智能体工作流优化分布式训练基础设施（五阶段验证工作流，最高 2.75× 加速），不改智能体权重；RSI-Prime 改权重以提升实验决策。两者在“分阶段验证保证可靠性”上同构（RSI-Prime 的协议/评分器/运行时预验证 vs InfraRSI 的五阶段工作流）。
- **SkillDuet (2611.12109)**：同为从交互经验做参数学习的路线；SkillDuet 以响应反馈让 LLM 参数与外部技能库在线协同演化（双载体），RSI-Prime 是对过滤后完整轨迹的离线蒸馏（单载体），可视为经验复用载体的两个极端设计。
- **SimplEvo (2611.11509)**：免权重更新的经验积累（自写文本记忆 + 教训精炼，EBench 成功率 46.7%→81.7%），与 RSI-Prime 的权重更新路线正交互补；资源受限场景下记忆演化可作 SFT 的前置替代或数据来源。
- **The RSI Tax (2611.13524)**：从成本会计角度质疑 RSI 循环的 token 开销（简单有界笔记基线精度持平时省 65.6–71.0% 总 token）。RSI-Prime 提供对照面：一次性 SFT 成本换持久能力，且决策级掩码将监督 token 从 44.35M 压至 33.48M（约 −24.5%），训练侧同样存在可压缩的“税”。
- **TRUST (2611.10787)**：RSI-Prime 的多数投票、迭代验证与人审是经验性质控，无法给出错误率界；TRUST 用在线多重假设检验为递归自改进控制错误演化率并提供统计保证。将 TRUST 式保证引入决策质量判定（当前 7.58% 问题记录的漏检/误检无界）是自然的组合方向。
