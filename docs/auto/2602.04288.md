# Contextual Drag: How Errors in the Context Affect LLM Reasoning

> Yun Cheng, Xingyu Zhu, Haoyu Zhao, Sanjeev Arora. *arXiv:2602.04288v2 (2026-02-04)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

本文出发点是当前 LLM 训练与推理管线中广泛存在的 critique–verify–revise 循环（self-refine、多智能体聚合、递归自改进等），其共同隐含假设是：把过往失败尝试放进上下文、让模型复盘，能改进下一次生成。作者从认知科学借来反例——人类锚定偏差（anchoring bias），即已被明确否证的信息仍持续影响后续决策（Tversky & Kahneman, 1974）；而 LLM 已知存在强上下文敏感性（误导提示、用户错误、框架效应可覆盖参数知识并诱发谄媚行为）。

问题被进一步聚焦在推理模型上。从经典 CoT 到 extended thinking（可暂停、验证、回退的 System-2 式深思），一个自然预期是大型推理模型能识别上下文中的错误并避免重蹈。作者提出相反假设：对上下文材料的验证只是一种“局部判断”，即便草稿被准确拒绝，它仍会塑造后续推理轨迹，把生成“拖”向结构相似的错误——即 contextual drag（上下文拖曳）。由此给出两个研究问题：RQ1，带显式验证提示的推理模型对上下文中错误草稿是否鲁棒？若否，草稿如何塑造推理？RQ2，外部反馈或自验证产生的错误信号能否阻止模型重复相似错误？若否，什么方法能削弱影响？

相对既有文献的差异化声称：本文是首个表明错误上下文的影响在显式错误信号之后仍然存在的工作，且影响以推理结构畸变而非仅性能下降的形式呈现；drag 严重的模型在迭代 refine 中会自劣化（self-deterioration）。定位上，contextual drag 被视为推理层面的锚定效应，区别于主要定义在事实/语义正确性层面的 context–parametric 知识冲突研究，也区别于数值提示类锚定实验。

工程意义一句话版本：只要管线把失败尝试留在 prompt 里（自 refine、MoA 聚合、多轮工具调用、递归自改进），就必须面对这个失效模式。

## 2. 方法总览

论文是“现象定义 + 测量协议 + 机理分析 + 缓解验证”的实证研究，不提出新模型架构。

**操作化定义**：contextual drag = clean-slate 生成（DIRECT，仅问题 + CoT 提示）与 error-conditioned 生成（1F/2F，问题 + 1 或 2 条错误草稿，并被显式指示逐步验证草稿后再产新解）之间的性能落差，外加推理模式向错误上下文的系统性偏移。

**测量协议**（11 模型 × 8 任务）：
- 模型：闭源 GPT-5、Gemini 2.5/3 Pro（API 成本原因仅测竞赛数学）；开源 GPT-OSS-20B/120B、OpenReasoning-Nemotron-7B/32B、Qwen3-8B/32B、DeepSeek-R1-Distill-Llama-8B/Qwen-7B。
- 任务：AIME24/25、HMMT24/25（MathArena 无污染竞赛数据）、GPQA-Diamond、MMLU-Redux 2.0、CRUXEval-I、Game of 24。
- 草稿来源：每任务以开源模型在**原始全集**上的 clean-slate 表现选 top-3 作 anchor 模型，其真实响应作草稿，排除低质量 rationale 对下降归因的混淆（anchor 按原始全集选出，故未必是过滤子集上的 DIRECT 前三）。
- 难度过滤：仅保留 anchor 模型“既有成功又有失败”的题（每题至少 2 对 2 错），子集规模如 AIME24 10/30、AIME25 13/30、HMMT25 21/30、GPQA 132/198、MMLU-Redux 569/2629、CRUXEval-I 211/800、Game of 24 653/1362。该子集正是 pass@1→pass@k 差距所在，是 refine 管线最关心的增量区间。
- 判分与采样：解析最终答案经 math-verify 符号验证器比对真值；每题 16 次独立采样保证统计显著性；草稿剥除 `<think>` 段以控上下文长度。

**机理分析**：Game of 24 上每个解可唯一解析为表达式树（叶 = 给定整数，内部节点 = 运算），以树编辑距离（TED，Zhang–Shasha）量化条件生成与草稿的结构相似度；作者强调 TED 非性能指标，仅作结构相似性证据。另设迭代 refine 模拟：首轮无上下文生成，此后上一次输出（对错皆可）作为草稿，16 条轨迹取均值，对照同预算 majority voting。

**错误信号实验**： 外部信号——prompt 中反复显式标注草稿 INCORRECT 并警告 DO NOT COPY； 自检测信号——事后过滤 1F 轨迹，仅保留以结构化标签给出且判定正确的"Incorrect"子集（oracle 过滤，天然偏向更强性能；保留子集因模型/任务而异，不可与全量 1F 直接对比）。

**缓解**： 测试时上下文去噪——REVISE（先改写草稿、再基于改写稿求解，2 步）与 FILTER（先 clean-slate 生成不含中间步骤与答案的高层策略、再按策略过滤草稿保留正确有用步骤、再求解，3 步），逐草稿独立执行，solve 步删去显式验证指令； 定向 SFT——训练“验证后条件回退”：草稿判错则切换到与草稿无关的 clean-slate 轨迹，判对则复用草稿答案。

## 3. 关键设计

**（1）anchor 草稿 + 难度过滤的组合。** 用真实强模型的错误作草稿，把“下降是否源于草稿质量差”这一混淆变量压掉；难度过滤保证题目非平凡且非不可解。代价是任务间 anchor 不同（AIME24 为 Nemotron-7B/32B + Qwen3-32B；AIME25/HMMT24/25 为 GPT-OSS-120B + Nemotron-7B/32B；GPQA/MMLU 为 GPT-OSS-120B、Nemotron-32B、Qwen3-32B），跨任务数值只宜做方向性比较。草稿可能来自被评模型自身或其他模型，因而协议同时覆盖 self-refinement 与 multi-agent 聚合两种部署形态。

**（2）1F/2F 提示的验证强制。** 模板要求逐步检查草稿、发现致命错误即停止检查余下步骤、以 `<overall verdict>` 标签输出判定，然后才生成新解（判错可复用合理思路，判对可直接采用润色）。该设计把“是否验证”从混淆变量变为受控条件——后续 VER 消融即删除验证指令，构成因果对照。

**（3）TED 结构度量的配对设计。** 对每题构造两组配对：草稿 vs DIRECT 解、草稿 vs 1F/2F 条件解，各自解析成树计算 TED 后比较组均值；2F 时取对两草稿的 min-TED。附录进一步删除“可复用合理思路”指令后 TED 差距依旧，排除了指令遵循伪影——结构拖曳是条件生成的内生属性。这是全文最有说服力的机理证据：drag 不是表面 token 抄袭，而是计算路径层面的继承。

**（4）外部信号 prompt 的强度设计。** 不止声明草稿错误，还重复强调、明确禁止复制其最终答案，把“信号不够显式”这一反驳空间压到最小。因而“仍然下降”的结果具有强诊断力：外部错误信号不充分。

**（5）REVISE 与 FILTER 的对照。** REVISE 的改写步本身仍条件于原草稿，drag 在改写中延续，限制其纠正深层概念错误的能力；FILTER 的策略步是 clean-slate 生成，相当于用干净“骨架”重新锚定过滤过程，故更稳。共同软肋：两者都依赖模型自身对草稿的不可靠判断。成本上，每个草稿需多轮推理，测试时开销至少 2×，批处理可部分摊销但牺牲去噪质量。

**（6）定向 SFT 的数据合成。** 问题池：Big-Math-RL-Verified 中 Llama-3.1-8B 求解率 < 0.5 的中难子集采 4 万题（固定来源配比）；草稿由 5 个开源推理模型（GPT-OSS-20B medium、Qwen3-8B thinking、Nemotron-7B、LlamaR1-8B、QwenR1-7B）每题各采 4 条、至多 20 条，math-verify 定对错。监督轨迹 = 验证轨迹（GPT-OSS-20B 生成且判定与符号验证器一致才保留）+ 判错时拼接同题 clean-slate 正确轨迹作回退目标 / 判对时拼接固定模板引导复用草稿答案。正误草稿各 4 万、共 8 万条；全参 SFT 一轮，峰值 LR 5e-5、cosine 衰减、10% warmup，8×H100，LLaMA-Factory。“判对则复用”是关键设计：教条件化回退而非一律忽略上下文（后者无信息量），但也埋下 robustness–utilization 权衡的伏笔。附录 F.7 以同题池做 GRPO 对照（仅最终答案二元奖励，n=8 rollout，batch 64，上下文 16,384）。

## 5. 消融要点

- **规模**：加大模型不能实质缓解（120B 相对 20B 降幅收窄但仍显著）。
- **位置与验证指令**（Table 9，针对 lost-in-the-middle 的 POS：问题前置、草稿居中；VER：删验证指令）：两者部分有利但均不恢复 DIRECT，且效应不稳定——GPT-OSS-120B 在 CRUXEval-I 上 POS 掉至 55.5（DIRECT 89.2）而 VER 达 87.1；Nemotron-32B 在 GPQA 上 VER（39.4）反而低于 1F（49.4）。显式验证既非解药也非主因，drag 是更底层的上下文处理问题。
- **草稿数量与正误配比**（附录 F×T 网格）：纯错误草稿随数量单调恶化（GPT-OSS-120B 在 HMMT25：DIRECT 61.0 → 1F 50.3 → 4F 41.8）；正确草稿带来大幅增益（4T 可至 98.4），但当错误草稿占优时模型仍受损（点名 GPT-OSS-120B、Nemotron-32B 在 CRUXEval-I 与 GPQA）。正误影响的强非对称性支持“对连贯结构的过利用”这一机理解释。
- **复用指令**：删除“可复用合理思路”后 TED 差距不变，排除指令遵循解释。
- **SFT 权衡与 RL 对照**：鲁棒性以利用率为代价（1T 掉 22~28 点）；GRPO 的 outcome-only 奖励不足，暗示需要验证器感知或轨迹级奖励。

## 6. 贡献与启示

**科学贡献**：命名并量化了一个此前散落于 anchoring / noisy-CoT 文献中的失效模式；用 TED 给出结构层证据（错误以计算路径而非表面 token 的形式被继承）；证伪“显式验证足以隔离错误上下文”的强假设（外部信号与自检测信号两组实验）；识别 robustness–utilization 权衡。机理解释指向预训练：ICL 可视为对结构化高质量数据的隐式贝叶斯推断（Xie et al., 2022），模型天然过利用“连贯但错误”的上下文；drag 的顽固性提示当前注意力架构缺乏真正重置推理状态的机制——不是提示工程能根治的问题，可能需要架构级或训练级改动。

**对 LLM 系统工程的直接含义**： 凡把失败尝试写入上下文的管线（self-refine、MoA、多轮 agent、递归自改进）都应先跑 1F/2F 式 drag 压力测试，本文协议（anchor 草稿 + 难度过滤 + 符号判分 + 16 采样）可直接移植为回归测试脚本； drag 严重的模型在迭代管线中应改用 majority voting / 独立采样，而非条件 refine； 去噪可用（FILTER 优于 REVISE）但预算至少 2×，且 best-of-n 无效（pass@5 证据）； 承担“看失败尝试再改”角色的模型选型比预期重要——同档规模下 Nemotron 与 GPT-OSS 表现迥异，事后分析提示推理轨迹蒸馏等训练选择可能是变量； 后训练“重置行为”需与“正确上下文利用”联合配比，否则牺牲 ICL 收益； 安全面上，in-context 伪解构成现实的锚定注入/提示注入攻击面，对接受用户 supplied 上下文的系统尤甚。

**与音视频技术上下游的关联**：下游——LLM/VLM 已深入 AV 链路（ASR 后纠错与字幕润色循环、视频内容理解与时刻定位的 self-consistency、多模型字幕/描述聚合、自动剪辑与审核 agent），其中大量环节正是“上一轮错误输出 + 反馈放回 prompt 再生成”的形态。本文结论表明：错误会以结构相似方式被继承（TED 证据）、外部标注错误也压不住（-34~-41 点的极端例）、正确信号只在部分模型上有效——映射到 AV 指标上即时间轴定位错误、镜头边界误判、模态对齐错误等模式的复现，10~20 点级损失不可忽视。经济性上，AV 是高吞吐批处理场景，FILTER 三步、≥2× 推理开销需按预算权衡；上游——多模态后训练的数据配比应吸收本文权衡结论：教“判错即重置”的数据会同时削弱对正确上下文（正确参考字幕、检索到的正确片段描述）的利用，两类数据需平衡构造。

## 7. 与其他论文的联系

- **paper:arxiv:2611.10787｜TRUST**：TRUST 用在线多重假设检验在“接受/淘汰”层面控制递归自改进的错误进化率并提供统计保证；本文补充了生成层面的盲区——即便草稿被正确判错甚至淘汰，只要留在上下文，后续生成仍被拖曳（外部信号实验）。两者互补：TRUST 式门控应与上下文卫生（不把被拒草稿回灌 prompt）组合使用，统计保证覆盖不了条件生成内部的结构偏置。
- **paper:arxiv:2611.14326｜FGSE**：FGSE 要求经验教训作为可证伪假设经探针验证后才写入智能体记忆，隐含“证伪后即安全”；而人类锚定研究与本文外部信号实验（显式 INCORRECT 标注仍显著下降）共同提示：仅打“已证伪”标记不消除影响——记忆条目的表述方式与回用形态需按 drag 效应重新设计。
- **paper:arxiv:2611.10463｜LongCapHarness**：同为测试时上下文管理，LongCapHarness 以能力引导挂接长上下文推理且成本低于基线 50%；本文的 FILTER/REVISE 则需 ≥2× 开销且无法全恢复。两条路线的对照说明“低成本上下文重构”与“彻底去噪”之间存在张力；本文的 TED 式结构度量可移植用于长上下文轨迹的质量监控。
- **RSI 智能体系列（TrainExplorer arxiv:2611.20430、SkillDuet arxiv:2611.12109、InfraRSI arxiv:2611.11558、CompoundingKernel arxiv:2611.19230、RSI-PDEbench arxiv:2611.14949）**：这批工作的共同隐含假设是智能体条件于自身先前尝试/自生成反馈能持续改进——正是本文量化反例所针对的假设（GPT-OSS-20B 自劣化、多数模型 10~20 点系统性下降）。直接含义：循环中承担“复盘失败再改”角色的模型必须做 drag 筛选（同规模模型间差异可达数十点），或在循环外增加草稿过滤/重置机制，否则自我改进可能退化为自我强化错误。
