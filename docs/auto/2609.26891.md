## 1. 背景与动机

现代 LLM 智能体的技术主线是 agent loop：模型在暴露一组工具的环境中循环执行“动作—观察”。范式沿表达力递进：ReAct 给模型逐步选择动作的自由；CodeAct 把动作泛化为 REPL 中的可执行代码，典型实现允许把用户提供的 Python 对象注入 REPL；RLM（CodeAct+通用子智能体）进一步证明，无任何外部工具与 harness 组件、仅靠递归子智能体，就可在部分长上下文任务上超过长上下文模型本身（其实现是往 REPL 预置一个大字符串，让智能体充当长上下文模型）。但两类能力至今仍由叠加在 loop 之上的专用系统承担：跨上下文窗口的长期记忆靠 Letta/MemGPT 式分层记忆与检索接口；跨任务序列的持续自改进（CSI）靠 ACE 式 reflector/curator 提示演化循环。

论文的核心问题：一个比 agent loop 本身多不了多少的最小 harness，配合纯提示（prompt-only），能否实现这两类能力？作者假说是：瓶颈不在 harness 组件缺失，而在 loop 表达力——只要 模型能写含递归子调用的任意代码； 模型上下文中可见的一切都是代码环境中的变量，那么“记忆管理”与“自我改进”就可退化为“模型自己写程序实现的行为”，而非需要工程化的外部系统。为此构建 JAZ：核心仅一个 LLM 语言原语 `invoke` 加一套监控/约束 hook。

方法论定位上，论文把问题从“框架工程”转为“程序语言设计”：`invoke` 被当作函数体由 LLM 在每次调用时现场生成的语言构造，从第一性原理推导其最小形式。结论导向与 harness 工程相反的 bitter-lesson 式路线：在最小而最大表达力的 loop 内训练模型，让模型自行构造工作流、工具与 harness 组件。

面向音视频交叉读者的相关性预告：论文的 far-recall 任务（细节须跨多个上下文窗口存活）与长视频时序 grounding 同构；code-mode loop 对媒体工具链编排与流水线在线自优化有直接映射，详见第 6 节。

## 2. 方法总览

**invoke 的函数式定义与形式语义。** `invoke(...)` 接受任意命名实参，论文刻意抹平“提示 / 工具 / 普通数据”的界限——task、df、web_search 一律平等绑定为 REPL 变量。执行三步：  serializer 把输入映射 σ=[x⃗:=v⃗] 序列化为紧凑字符串提示 ⟨σ⟩，原则是不倾倒大对象原文、只给足以通过交互提取信息的描述； 模型输出同语言（已含 invoke）的代码 C=π(LM(P))，须可作为以这些实参为形参的函数体； 以实参执行。形式化在 λ 演算上完成：文法加一条产生式 `e ::= … | invoke(x:=e)+`，CBV 操作语义加一条归约规则 `invoke σ → (λx⃗. π(LM⟨σ⟩)) v⃗`。设计自由度被压缩到三处：宿主语言、serializer、parser。JAZ 取 π=恒等——模型整个回复即代码，自然语言散文以行首注释承载，无 markdown 围栏，从根上消除解析失败面。

**最小性与一般性论证。** 通常的 LLM 原语是 string→string，但最简语言（λ 演算）没有字符串类型；由于任何语言的项本身就是串，让 LLM 以项为输入、输出项、且输出项可把输入引用为变量，恰好得到 functional invoke。即 invoke 是“把常见 LLM 原语改造为对一切图灵完备语言通用”的自然结果，形式上仅引入一条语法与一条语义规则——这是标题"Harness as a Language"的实质。

**从函数式 invoke 到 agent loop。** 闭式 agent loop 可表达为尾递归 invoke（把当前输入连同交互历史传给下一次自身调用）。但让模型手写尾递归不现实：Python 下内存低效，且 LLM prompt 前缀缓存要求相邻查询满足精确前缀关系。故由 harness 自动附加尾调用并做尾调用优化，得到实际的 code-mode REPL loop。由此得到 invoke agent loop 的两条定义性质：**P1** 输出语言已含 invoke，递归子智能体（sub-invoke）默认存在；**P2** 模型可见的一切——所有 invoke 输入与 REPL 交互历史 `__history__`——都是 REPL 变量。P2 中“历史是变量”是与 smolagents、RLM 等现有 code-mode 实现的本质分界：后者仅把用户提示与历史当作展示给模型的消息列表，模型无法程序化操作。

**JAZ 框架层。** 三类机制： `scope` 动态作用域：`with scope(web_search=...)` 内所有 invoke（含全部递归 sub-invoke）自动获得该变量。作者论证动态作用域在此唯一正确——invoke 没有静态实现、每次调用生成新实现，不存在“复用”，静态作用域的核心收益不成立。 **hooks** 四类：可观测（PrintLogger、FileLogger、TrajectoryRecorder/DirectoryRecorder、Langfuse/Jaeger tracing）、可恢复、资源约束（BudgetPool、IterationLimit、RecursionLimit、BudgetForcing、ContextWindowWarning）、校验（ReturnType、ValidateReturn、ValidateREPLCode）。hook 位置参数传入为局部（如 ReturnType(float) 只约束顶层），上下文管理器激活为 scoped（如 BudgetPool(max_cost=5) 在整棵调用树共享 $5 预算）。 `Config(llm, repl, protocol)` + ConfigOverride：protocol 定义 LLM↔REPL 缝合层（解析输出、格式化 REPL 输出），同样局部/全局双层——“顶层强模型、子智能体便宜模型”一行可达，CSI 实验正是 scoped GPT-5.4 nano + 顶层局部 GPT-5.4。

## 3. 关键设计

**`__history__` 与按引用传递。** `__history__` 为 list，每 REPL 迭代一项，字段含 `.llm_response`（当轮完整回复）、`.repl_output`（打印输出含 traceback）、`.repl_exception`。它是两个案例研究的支点：值已在进程内存，传递即引用，零 token 成本、零信息损失。对比之下，CodeAct+subagents 中子智能体要“回传自己的历史”只能整段硬编码进 return 或逐轮 append——两者都倾向有损，且额外输出 token 拉高 solver 成本（AppWorld solver 成本 14.3 vs 10.9 美元）。

**长时程：tail-recursive delegation。** 上下文达 70% 阈值时，ContextWindowWarning hook 注入用户消息，要求按模板把剩余工作整体委派给子智能体：`prev_history = globals().get("prev_history", []) + __history__`（引用累积、无损），另传 prev_progress_summary、next_steps 与自定义 state；模板首行 `# timeout: 86400` pragma 防 REPL 默认 30 秒超时截断。论文指出该模式统一了现有上下文管理谱系：compaction 对应只传 summary；过滤式管理（Chroma Context-1 式）对应传过滤后的 `__history__`；本质是“对 invoke 的访问权即对下一次 LLM 调用之输入与上下文的控制权，而 `__history__` + 代码环境使新上下文能就地构造”。检索纪律写在任务无关的 guidance 中：只搜 prev_history（`__history__` 已全量可见，搜之无益）；跳过 repl_output 中含先前搜索结果的条目防自污染；命中处显示 ±(1000/2000) 字符窗口而非截断前缀；搜索步独立成回合。这类模板是“纯提示”路线的实际设计成本所在。

**CSI：meta-agent = 控制输入的顶层 invoke。** 顶层 invoke 决定传给 sub-invoke 的一切输入，天然是 meta-agent：在一串任务上迭代优化 solver 的 prompt 与 meta-authored tools。指导 prompt 编码了一套实验方法论：先以约 5 任务小批跑最小种子；批间读失败轨迹、陈述根因假设、做最小修改、下一批验证、无效即弃；表现好则增大批次、缩小编辑幅度；工具须 100% 可靠、无 leaky abstraction、针对一类错误而非单个任务失败形态，否则删除；每任务单次子智能体调用、meta 不亲自解题。与 ACE 的结构性差异：ACE 每任务固定跑 reflector+curator 且只优化 prompt；JAZ meta-agent 可批处理省调用、选择性读轨迹片段省上下文、并演化工具本身。CSI 实验以 RecursionLimit(depth=2) 封顶，隔离“自改进”与“solver 亦可开子智能体”两个混杂因子；顶层不开 ContextWindowWarning（全部任务可容纳于其上下文）。

**评测协议作为方法贡献。** instructions（环境提供、方法无关：任务指令+环境描述，CSI 下零工作流指导）/ guidance（方法提供、任务无关）强制解耦，防止 (方法，任务) 对 prompt 过拟合与元提示硬编码最优 solver 解。CodeAct 与 CodeAct+subagents 不用现成实现，而在 JAZ 内以自定义 hook 摘除用户提示与 `__history__` 变量、做最小 prompt 改写重实现——除必要差异外与 invoke 版字节级一致。prompt-only 规则四条：仅环境自带工具、禁文件系统/互联网；无环外逻辑修改 loop（监控允许：预算、步数、递归、完成守卫、上下文警告；允许 root 与 subagent 异模型）；系统提示只含 loop 机制与工具 docstring；用户提示＝环境 task prompt＋方法 guidance。成本测量控制缓存命中的系统误差：每 run 独立 prompt cache key、同一 OpenAI 组织 ≤3 并行（实测并行数 n=4→5 缓存命中率降逾 5%，n≤4 波动 ≤2%），故固定 n=3、成本系统误差 <2%；6-run 实验分两批各 3。

**hook 事件模型。** 生命周期事件覆盖 Invoke / LLMQuery / REPLExec 各自的 Enter/Send/Complete/Exit（另有 LLMQueryRetry）。Enter 可改输入，Send 可用给定输出替换整个调用，Complete 可改输出，多数事件可 abort。hook 只发静态可组合效果；多 hook 并活跃时事件一次性分发、效果按最小依赖顺序合成、不可解冲突写报错拒绝——语义与分发顺序无关；hook 间经全局 blackboard 通信，并可读 ambient state。工程含义：监控/预算/校验可正交叠加而不引入顺序耦合。

**REPL 沙箱与渲染。** 仅允许 import re/collections/ast/datetime/textwrap/pprint，禁文件读写；默认 30s 超时 + pragma 可调；print 用于观察中间输出、return 终止会话并交付调用者，二者不得同轮。输入串化默认 50000 字符截断；类渲染为 docstring+公共成员、可调用渲染为签名+docstring——这套 serializer 准则是把大对象（如数据帧、环境句柄）交给模型的安全做法。

## 4. 实验结果

### 4.1 StuLife（长时程远回忆）

设置：1284 个有序任务模拟一学期，939 个计分，其中 207 个需“远回忆”（信息出现于 50+ 个任务之前）；典型 episode 7000–8000 次环境交互、code-mode 智能体 3000–5000 次 LLM 调用。所有方法用 GPT-5.4 nano (high)，n=3 报均值±标准误。

| 方法 | prompt-only | 全集 Pass(%) | 全集 Score(%) | 远回忆 Pass(%) | 远回忆 Score(%) | 成本($) |
|---|---|---|---|---|---|---|
| CodeAct^JAZ（逐任务） | ✓ | 52.5±0.3 | 59.2±0.1 | 24.8±0.6 | 25.8±0.5 | 4.4±0.1 |
| CodeAct+subagents（smolagents） | ✓ | 30.2±4.8 | 33.6±5.2 | 20.6±0.6 | 22.0±0.9 | 9.4±1.4 |
| CodeAct+subagents^JAZ | ✓ | 60.0±1.1 | 68.1±1.0 | 32.0±2.3 | 33.9±2.0 | 13.1±0.9 |
| Letta (MemGPT) v0.16.8 | ✗ | 70.9±0.5 | 81.0±0.5 | 61.8±2.3 | 67.0±2.4 | 42.1±1.6 |
| JAZ invoke | ✓ | 72.6±0.1 | 81.6±0.1 | 69.9±1.8 | 73.6±1.5 | 18.3±0.3 |

要点：全集上 JAZ 与 Letta 基本打平（score 81.6 vs 81.0），优势集中在远回忆子集 69.9 vs 61.8（+8.1 点，即摘要口径"by 8%"），成本 18.3 vs 42.1 美元（约 43%，即"half its cost"）。相对同框架、仅缺 P2 的 CodeAct+subagents^JAZ，远回忆 32.0→69.9 翻倍以上，把决定性因子定位到 P2（尤其 `__history__` 变量化）。JAZ 三 run 方差极小（±0.1），而 smolagents 版 ±4.8。逐任务 CodeAct 的 4.4 美元是“无记忆”下限参照。

定性分析（任务 #1282/1284，虚构协议期末考题，正确选项 D 对应 497 个任务之前 #785 的讲授）：JAZ 到达该任务时递归深度已达 70（69 次委派），prev_history 完整累积，花一回合对协议名做子串检索即命中全部相关讲义、次轮答对。CodeAct+subagents 全程未检索：无历史变量可搜，跨数十次委派手工复制 instructions 有损丢失（含“考的是虚构协议须回忆讲义”的关键指令），最终按现实世界知识选 A（错）。Letta 的 conversation_search（Turbopuffer，BM25+向量混合）返回考题自身或近似命名协议的旧消息——场景需要精确子串匹配，而其唯一检索工具不支持。

## 5. 消融要点

- **核心消融即“性质移除”**：同一 JAZ 实现内，CodeAct+subagents^JAZ＝hook 摘除用户提示与 `__history__` 变量（移除 P2）；CodeAct^JAZ 再以 RecursionLimit 关闭递归（移除 P1）并逐任务独立。StuLife 远回忆 Pass：69.9 → 32.0 → 24.8；AppWorld TGC：74.2 → 71.1 → 67.5。两性质各有独立贡献，P2 在长程记忆上贡献最大。
- **两条可迁移 Takeaway**： 上下文中的一切皆为 REPL 变量 ⇒ 可按引用传递（委派给子智能体、回传给调用者），可靠性高于模型手工复制内容——两案例中所有失败模式都收敛到“复制有损”。 专用/手工 harness 编码的假设在假设破裂处变刚性：Letta 的检索工具缺精确子串匹配；ACE 的固定每任务 reflect/curate 工作流且只优化 prompt。完整代码表达力+invoke 可恢复灵活性。
- **实现质量混杂的量化**：smolagents 版 CodeAct+subagents 仅 30.2±4.8（全集），远低于 JAZ 重实现的 60.0±1.1；论文将其欠performance 几乎全部归因于系统提示缺陷（称子智能体为“真实人类队友”，导致模型一缺信息就开子智能体找“人”问）、受限解释器按模糊匹配解析名字、math 函数硬编码覆盖用户重定义等；以子智能体角色描述覆盖修复的尝试失败。这构成“受控重实现而非借用现成基线”的实证依据。
- **官方 AppWorld 基线差距分解**：48.2 vs 自建 67.5 的 19.3 点差距中，(14.9±1.0)% 的任务因提交格式歧义在任务实际已完成的情况下误交答案而判负（大头）；教学了 `complete_task(status="fail")` 逃生门导致条件分支提前失败约 1%；换清晰 instructions 后 1251 个 CodeAct 智能体（417 任务×3 run）仅 1 个误提交。
- **Letta 配置敏感性**：SQL 检索后端把整条查询做精确子串匹配导致结果大面积为空，改用 Turbopuffer 混合检索；多数 prompt 触发“空描述任务死循环”的不可恢复病态，最终只用唯一不触发的 prompt。领域 harness 的对比结论对其内部配置高度敏感。
- **CSI 隔离与公平化**：depth=2 使 solver 无子智能体，保证与逐任务 CodeAct 的差只归因自改进；ACE 三处改造——删除其提示中硬编码的 AppWorld 失败模式示例与最优应对（违反任务无关原则）、reflector/curator 由同 generator 模型改为 GPT-5.4 对齐 JAZ meta、学习预算限 42 任务；去重阈值取原论文报告不敏感区间 {0.5,0.7,0.9} 的中点 0.7。

## 6. 贡献与启示

**理论**：invoke 的形式化（一条产生式+一条语义规则）把“agent harness 该长什么样”转成语言设计问题；“项即串”的最小性论证给出任何图灵完备语言引入 LLM 原语的规范答案，并顺带解释了为何 P1/P2 是该原语的必然推论而非工程选择。

**实证**：在两类传统上由专用系统承担的工作流上，纯提示的最小 loop 达到或超过专用 harness 且成本减半量级；把能力瓶颈从“组件缺失”重定位到“loop 表达力不足”。

**方法论**：instructions/guidance 解耦、同框架受控重实现（字节级对齐 prompt）、缓存命中受控的成本测量（系统误差 <2%），这套评测协议对 agent 方向论文的可复用价值不亚于结论本身。

**工程启示**：serializer 准则（不倾倒原文、给足以交互提取的信息）；π=恒等的“全回复即代码”协议；动态作用域+scoped hook 使预算/配置在递归调用树上自然继承；hook 效果代数（静态可组合、冲突拒绝、blackboard）保证多策略叠加确定性。

**诚实边界**：StuLife 全集 score 与 Letta 打平，优势集中于远回忆与成本；CSI 单 run 可劣于无自改进基线（64.5<67.5），自改进稳定性是开放问题；“纯提示”不等于零设计——长程检索纪律与 CSI 实验方法论都内嵌在 guidance prompt 中；实验仅覆盖 GPT-5.4 家族；递归深度 70 的委派链在更长任务上的栈与成本外推未讨论。

**对音视频交叉方向的映射（笔者视角，论文本身无音视频实验）**： 远回忆与长视频/多会话流理解同构——数小时视频中“某实体几小时前出现过”的时序 grounding 同样要求细节跨多个上下文窗口无损存活；tail-recursive delegation + prev_history 引用传递给出 compaction 的无损替代，而 Letta 的教训（检索接口缺精确子串即失败）对字幕/日志/元数据检索接口设计直接适用。 code-mode loop 天然适配媒体工具链编排：把 FFmpeg 句柄、probe 结果 DataFrame、QC 函数注入 REPL，用程序控制流写“探测→决策→转码→验证”循环，替代手写 pipeline 或一次性 function-calling；P2 使转码策略、码率决策历史本身可被程序检索。 CSI 模式（强模型 meta+廉价模型 solver、批间读轨迹改 prompt/工具）映射到编码参数、filter 图、QC 规则的在线自优化。 meta/solver 分层成本结构（9.9/10.9 美元）对大规模批量媒体处理的预算模型有参考意义。

## 7. 与其他论文的联系

- **LongCapHarness（arXiv:2611.10463）**：同样质疑“长上下文/长时程能力必须靠专门 harness 或后训练”。JAZ 以最小 loop+提示在 StuLife 远回忆上超过 Letta 且成本约减半；LongCapHarness 以能力引导的自动挂接、免数据合成与后训练，在 HELMET/RULER 超基线且成本低于其 50%。两者分别代表“最小化 harness”与“自动构造 harness”路线，共同证据是：手写 harness 组件可被提示诱导或自动推导的对象替代；JAZ 的表达力论证为 LongCapHarness 的免训练路线提供了一致的理论支撑，二者在成本减半上高度呼应。
- **FGSE / When Should Agents Remember?（arXiv:2611.14326）**：JAZ 证明程序化访问 `__history__` 足以替代记忆系统，但其 CSI 更新仅靠“批验证不奏效即回滚”的启发式；FGSE 把经验教训作为可证伪假设、经三类探针验证后才写入智能体记忆，直指 JAZ 缺失的“更新安全”维度。互补关系明确：FGSE 的证伪门控可移植为 JAZ meta-agent 的探针 hook。
- **TRUST（arXiv:2611.10787）**：JAZ 的 CSI 对“哪些修改应固化”无统计控制，单 run 崩溃（64.5）即为症状；TRUST 用在线多重假设检验控制递归自改进的错误进化率并提供统计保证，可作为 JAZ 批验证层的严格化方案，恰好补上其方差问题的理论工具。
- **SkillDuet（arXiv:2611.12109）**：JAZ meta-agent 只在上下文层演化 prompt+工具（权重冻结），AppWorld 上 74.2 vs 逐任务 67.5 量化了纯上下文层技能习得的增益；SkillDuet 以响应反馈让模型参数与外部技能库共同演化，指出参数层与上下文层联合演化的下一步空间——JAZ 可视为其“仅上下文层”的受控上界实验。
- **InfraRSI / CompoundingKernel / TrainExplorer（arXiv:2611.11558 / 2611.19230 / 2611.20430）**：均为“元智能体+代码/工具创作+测试反馈”模式在具体工程域（训练基础设施最高 2.75 倍加速、GPU 内核登顶 SOL-ExecBench、后训练 PostTrainBench 39.02）的实例；JAZ 把该模式泛化为语言原语并论证其最小性。此为模式层关联（笔者映射），JAZ 未做跨域验证，但为这类系统提供了“通用语言层底座”的候选。
