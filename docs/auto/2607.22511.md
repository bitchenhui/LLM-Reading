## 1. 背景与动机

自动化理论研究的瓶颈已从“生成”移到“评估”。论文的动机证据链很直接：LLM 审稿可被对抗性构造击穿——Jiang et al. 的 BadScientist 评测显示 LLM 审稿接受蓄意伪造论文的比例高达 82%，识别伪造接近随机水平；对 AI-Scientist 系统的独立复评（Beel et al.）报告了幻造数字、频繁的代码失败与新颖性不足。结论：以 LLM 复核 LLM 的软评估不能承担正确性裁决。

替代路线是形式验证：Lean 4 中定理由程序（类型检查）而非审稿人裁决——命题即类型、证明即该类型的项，检查通过则论证逐步对公理验证，推理空洞无法存活。但论文指出由此通向可用自动系统的两个真实障碍，也是全文方法设计的两个支点：

其一，**成本**。从零形式化一个因果推断结果极慢，系统需要一个已证理论库（识别定理、估计量、渐近结果）作为起点，否则每次 run 都要先重建标准理论才能触及新东西。

其二，**忠实性**。Lean 只保证“证的是这个陈述”，不保证“这个陈述是想证的那个”。作者在自己的 run 中记录了两起典型事故：智能体把困难引理直接声明为公理，产出以公理冒充证明、能通过编译的 Lean 代码；模型改动了一条假设，使 Lean 证明的命题弱于论文宣称。两者都编译通过，都不是所宣称结论的证明。

领域定位（论文表1的五轴对照：是否自主命题 / 是否机器检查证明 / 是否陈述审计 / 评估器 / 是否自我改进）：AI Scientist 类无机器检查、以 LLM judge 裁决；FunSearch/AlphaEvolve 谱系有硬验证器但 fitness 预先固定、不涉及陈述语义；AlphaProof 证已知题而不出题；渐近统计多智能体形式化管线（Wei et al.）有 auditor 但只形式化已知理论。CausalSmith 是表中唯一五项全勾的系统。

对本笔记所在领域（音视频工程）的读者，动机层的可迁移判断是：凡存在可机检判定器的评测环节（编解码一致性、协议性质、同步不变量），“LLM 生成 + 判定器裁决 + 陈述审计”的范式对 LLM-as-judge 是结构性替代——此关联在 §6 展开，正文先按形式化方法与因果推断自身的标准解读。

## 2. 方法总览

系统由两部分构成：**Causalean**（Lean 4 因果推断基础库）+ **自我改进智能体管线**。

Causalean：8,179 条机器检查声明（5,375 定理、2,372 定义、432 结构/实例/归纳类型），1,070 个文件、约 30.2 万行，分十簇。库本身由 LLM 辅助建造但分工明确：人类定范围与定义口径，智能体起草陈述/证明/docstring，人类复审陈述是否表达意图。全库 sorry-free、无手写公理，唯一非标准公理来自 native decide（有限图可判定性与若干 minimax 计算，论文明确报告）。

管线四阶段，细粒度编号为 D/F 两段：

- **Discovery（D-1.1 至 D0.5）**：接受研究者给定题目或自主选题；文献侦察 → 提案构造+typed core → 提案审查（新颖性/重复/可行性）→ D0 数学推导（自然语言求解，按依赖图连通分量切分为并发单元）→ D0-max 极大性检查点 → D0.5 推导审查后冻结。产出以**依赖图**持久化：节点为论文的单条陈述（setup/定义/假设/引理/主定理），边分“陈述引用”与“证明消费”两类，节点带 must-prove（本文所证）/cited（取自文献）分类与审计状态。典型完成结果约百节点、数百边。
- **Formalization（F1/F1.5/F2）**：F1 给每节点挂 Lean 4 声明与模块位置（复用 Causalean 或新证），F1.5 做确定性检查（覆盖、节点种类、依赖闭包、被引声明存在性、模块落位）+ 模型判断（复用抽象层级是否合适、是否先检索再重建、缺口是建还是公开携带），F2 产出留 sorry 的骨架文件。
- **Proof Construction（F2.5–F4）**：review-and-fill 循环对活编译器补证明（单 prover 串行，因单一 import 链），配未用假设 lint 与禁用词扫描；F4 双模型收敛审查。
- **Presentation（P0–P6 独立状态机）**：从冻结图生成论文，每条陈述链接到已审计的 Lean 声明。

**两条反馈通道**构成“自我改进”的实质（均为记忆/资产级而非权重级）： run record——144 个 run 无论成败全部入库，Discovery 起草新提案前检索开放缺口与近重复，失败记录阻止后续 run 重复死路，降级结果锐化相关问题的选题靶标； 库通道——run 中识别出缺失的可复用引理时，study mode 按自然泛化度证明并晋升回 Causalean，构建时自动检查强制“论文私有引理不入库”的边界。

模型分工（commit 于源码、可按角色覆盖）：GPT-5.6 Sol 承担硬数学层（提案、推导、裁判审查、Lean 证明填充、收敛审查的一半），GPT-5.6 Terra 承担机械层（骨架翻译、归档、提案初筛、工件发射），GPT-5.5 写作；Claude 承担规划、Lean 代码审查、收敛审查另一半与写作 rubric 评分。

## 3. 关键设计

### 3.1 Causalean：分层结构与覆盖

覆盖自底向上：Graph 簇（可判定边关系 + 存储拓扑序的 DAG、d-separation 实现为 Bayes-Ball 可达性、SWIG、c-分解）→ SCM 簇（干预与 do-算子、semi-graphoid 公理、factored kernels、后门/前门/一般调整准则、ID 算法 soundness）→ PO 簇（精确识别：ATE/ATT/DiD 及 Callaway–Sant'Anna 分组时间细化、LATE、sharp/fuzzy RDD、proximal、动态处理；部分识别：Manski 界及单调处理响应/工具精化、Balke–Pearl 锐界、Lee 修剪界、边际敏感性模型）→ Estimation（ATE/ATT/CATE 的 DML、切空间投影得有效影响函数、structure-agnostic minimax 下界与匹配估计量、NPIV 收敛率）→ Stat（CLT、U-统计量与 Hájek 投影、Glivenko–Cantelli/括号熵、M/Z-估计、局部化集中不等式、bootstrap、局部 Rademacher 复杂度与临界半径）→ Panel（处理路径索引的潜在结果、固定效应、FWL、TWFE 因果/负权分解、event-study 污染）→ Experimentation（随机化推断、Horvitz–Thompson、Neyman 分配、网络干扰下 CLT）→ Discovery（LiNGAM 可辨识性、ICP soundness/线性高斯完备性、线性解缠可辨识性）。旗舰定理均为命名声明并给出源文件与行号（论文表3/表8，如 id_sound_discrete、balkePearl_sharp、dml_ATE_tendstoNormal、minimax_lower_bound_var_causal、twfe_po_decomposition、localDependenceCLT_of_stein），钉在 leanprover/lean4:v4.29.0-rc3。两处外部代码为适配拷贝：KKT 条件来自 OptSuite optlib（供 minimax 下界消费），Rademacher/McDiarmid/对称化/Dudley 熵积分线来自 lean-rademacher。统计为快照，pipeline 持续运行可增长。

### 3.2 检索接口

8,179 条声明全部嵌入 1,024 维向量索引。检索编码器在 Causalean 自身训练：训练对取自关键字索引（定理 docstring ↔ 其构建所依赖的声明；声明 Lean 语句 ↔ 自身 docstring），按模块切分，编码器只在未见模块上评估。三模式检索：concept（自然语言 + 因果同义词扩展）、type-pattern（Lean 4 语法片段对声明符号匹配，仅用关键字索引）、goal-directed（对证明卡住的目标排序候选）。concept/goal 双路排序（关键字 + 嵌入相似度）经互反秩融合合并，concept 头部候选再经微调 cross-encoder 重排。设计逻辑清楚：万级声明库的可用性取决于可发现性，而形式化检索必须同时服务语义与语法两类查询意图。

### 3.3 陈述审计：忠实性的机制化

Lean 类型检查的三个逃逸口：sorry（警告可见）、axiom（#print axioms 可查）、平凡真（Lean 不可见，只能读陈述）。论文表4 将“过类型检查但改变意图”的失败分四族并给出捕获点：错误陈述（逐节点与意图主张比对）、空真（witness 必须携带真实阻碍、不得为 True/空结构；可满足性前移到提案数学审查）、未证步骤（关键字自动扫描 + cited 节点溯源核对）、过窄陈述（假设比对 + 未用假设检查）。

审计两层。机械层：扫描拒绝任何含 axiom/sorry/admit/opaque/unsafe 的成品工件，且传递性施加于其直接/间接依赖的全部库模块；构建本身拒绝未完成证明。语义层：多智能体读编译文件中提取的声明文本，与冻结意图陈述比对、标记 drift。**关键契约设计**：冻结的自然语言陈述全程不被改写——它是审计保护的对象；机械性 mismatch 回 F2 局部修订，而“主张为假或欠规格”升级回 D0 重做，而非悄悄改弱陈述（正是引言第二起事故的对策）。每次通过审计盖内容指纹，节点或其实现变更时该节点及下游全部回炉——这是相对 Wei et al. 全量重审的关键局部化收益，风格上承接 Lean blueprint/proof-flow 的依赖图表示。需注意本设定中比较双方均为模型输出（run 自写非正式主张再形式化之），审计可靠性最终落在 LLM 上，论文未测其错误率。

证明循环的收口条件：成功构建、无 sorry/admit、冻结定理及其依赖闭包已证且 matched、axiom/opaque/unsafe 扫描干净、未用假设 lint 通过。F4 收敛审查由两个独立模型（GPT 与 Opus）对冻结全图复核，含最新变更未触及的节点、不参照此前审查结论——理由是两个不同模型比同一模型问两次共享更少盲区；分歧由 orchestrator 复现投诉，成立则修代码，不成立则把修正写回 reviewer prompt（审查者错误反哺为提示词补丁，一个小型自我改进回路）。外部结果的 cited 纪律：依赖的已发表定理作为主定理的显式假设携带来源证据，使“本工作所证 vs 引自文献”的边界机器可读。

### 3.4 选题与求解

选题模块先声明一行 stance：exploit（扩展已有记录结果或在多接受簇工作）或 explore（去少接受区域）。随后选 1–2 篇带定理的锚论文，子智能体连引文全文深读，产出摘要（核心定理与承重证明步、边界上 1–2 个开放问题、同技术可迁移方向）；起草约 4 个候选，按证据/数学深度/新颖性/可行性/对“具名消费者”（会因结果成立而改变实践的已发表应用或软件默认）的价值排序；首位候选交**不同模型**的对抗性审查（找停下的具体理由：反例、化归平凡、已有文献；核查陈述精确性、目标档位可达性、消费者真实性），模糊候选回炉锐化至多 3 次，被驳倒由 runner-up 顶上，双双落选则带失败模式约束重拟一版。通过者进 presolve：最强模型单次调用内同时尝试结果、以反例和新文献检索攻击自身尝试、写出全精度最强支撑定理并列出全部缺口，返回 launch/pivot/drop——成本逻辑：在此处学到“不可达”花一次模型调用，在推导中学到花一天管线时间。

D0 求解按开放陈述依赖图的连通分量切 unit、并发求解、合并为一张图；经典已发表定理作 cited 叶子入图。主张过强则弱化为真且有趣者、过弱则加强，改动重过审查。D0.5 审查拆分裁判：数学审查者从定义重推每个承重步并与笔记逐项比对；rubric 审查者查结构/新颖性/定位；目标档位需要时 general referee 冷读（只见笔记与档位定义、不见 rubric，以已接受论文及其终评分校准），其档位封顶结果。拆分理由明确：正确性、合规、趣味互相牵制，单一审查者倾向只凭正确性放过“对但无趣”的结果。

### 3.5 study mode：库通道的晋升闸门

证明中遇缺失引理有三条路：记录缺口按条件结果发布、就地证在 run 内 helper 文件、或按自然泛化度建入库；宽缺口/多结果会用到的事实送 study mode。流程：英文需求书（事实、应有泛化度、文献陈述方式）→ scaffolder 规划引理次序、写全陈述留空证明 → prover 对活编译器填充（串行，单一 import 链；至多 10 轮构建）→ reviewer 七项检查须全过（generic：在事实成立的层级陈述；reusable：命名与假设是后续证明会伸手拿的；standard：与文献陈述一致；non-vacuous：假设可被真实输入满足且硬情形保持全强度；fulfills requirement：锐常数保留、允许证明路线不同于需求书草案；sorry-free；layered：import 限于 Mathlib/Causalean/本研究文件——最后一条保护依赖方向，防止库引理把研究文件永久拖入库；至多 3 轮返工）→ coordinator 查重、选最窄落点、仅增量编辑（既有行不动）、写 docstring → 集成闸门（全量构建、重建索引、重建嵌入、文档检查），失败回滚重试至多 3 次，并发 study 串行过闸。

### 3.6 呈现层

P0 文献条目逐条经 Crossref/arXiv/OpenAlex 解析，未解析即剔除，正文引用只能出自验证池。P1 遍历依赖图把每条已验证声明渲染为常规数学记号（拓扑排序，先定义后使用），渲染时刻逐条判定英文与 Lean 声明在假设与结论上的逻辑等价（任一侧更强即停下仲裁），接受后**冻结**——后续 P2 随意改散文，冻结陈述逐字节还原。P3 代码检查（引用键、交叉引用、语序）+ 模型检查（是否有句子主张超过定理所证、引文是否支撑所引句），至多两轮修订。P4 从图装配链接，每条散文陈述逐假设绑定到声明。P5 以期刊裁判视角读全文（定理视为给定），裁决显著性、主张强度匹配与定位，findings 路由到能处理的最早阶段。

全部 14 个接受均为 gap filling（补文献缺口的匹配界、精确率/阶/常数、minimax 最优、显式识别式）。假设弱化类呈“推导对、新颖性输”形态（29 降级 vs 22 失败，审查评语如“泛型 Manski 式外 containment”“标准有限维支撑/投影计算”）——瓶颈在构念不在证明；方法比较与新设定类死得更早（分别 13/15 与 28/34 直接失败，多在提案阶段）。对 14 个接受 run 锚论文的回读：3 个继承文献自陈缺口（Zeng et al. 自留 log² 界闭合与齐性半径上的锐 minimax 依赖；Cortez-Rodriguez et al. 把界的度数缺口归因于“分析中的弱点”），11 个瞄准文献尚未设问的量（staggered PPML 的 pseudo-true estimand、已知 CATE 率的差分隐私对应物、transported complier ACE 的 minimax 置信集长度）。

**旗舰结果**：闭合高维离散混杂下 ATE 估计的 minimax 界隙。设定：n 个 i.i.d. 观测 (X,A,Y)，离散混杂 X∈{1,…,d}，二元处理与结果，严格内部重叠 ε≤Pr(A=1|X=k)≤1−ε；目标 τ(P)=Σₖ pₖ(μ₁ₖ−μ₀ₖ)=E[Y(1)−Y(0)]。Zeng et al. 已证下界阶 n⁻¹+(d/(n log n))²，但既有估计量留有 log² 因子缺口。该 run 构造混合估计量：样本二分，先导计数给每个协变量格贴 heavy/light 标签；heavy 格用 plug-in 比率估计，light 格用格泛函的最佳多项式逼近配无偏阶乘矩提升。主定理：对每个固定 0<ε<1/2，R_{n,d,ε}≍_ε 1/n+(d/(n log n))² 关于 d≲_ε n log n 一致成立；由此 d=O(√n log n) 时 minimax MSE 达参数阶 n⁻¹，且趋于零当且仅当 d=o(n log n)。minimax 下半部分不经本 run 检查，按 cited 纪律作为显式假设挂载并携带 Zeng et al. 来源。

**机器检查健全性**：对每个接受结果从干净构建跑 #print axioms，并以注释感知扫描交叉核对全部记录模块及其 import 闭包——所有接受论文不含 sorry/admit/axiom，定理归约到 Lean 4 标准公理；唯一外部输入（Zeng 下界）以假设形式可见。

**库反馈实例**：旗舰结果需要 Mathlib 没有的 [0,1] 值 i.i.d. 统计量计数的双侧乘性 Chernoff 尾界，run 证出并晋升为 Causalean.Stat.Concentration.TailBounds.BinomialCount（bernoulliCount 上/下尾）；下一个同 estimand 的接受结果（收缩齐性半径下的双侧 minimax 括号）需要更一般的先导论证（任意有限类别集，而旗舰仅两类格），构建了 Causalean.Stat.SampleSplit.FiniteCategoryPilot 导入并复用其矩母函数界——“run 缺引理→证明→晋升→后续 run 复用”闭环的完整单例。另有 28 次库构建产出各自晋升：Fano 不等式、任意多假设的 Bretagnolle–Huber 亲和界（一个 dose-response 逆命题需要、后续 Le Cam 两点化归复用）、KL 密度倾斜展开、支撑一个被接受的 Chebyshev rollout 设计的 Ehlich–Zeller 与 Bernstein–Szegő 工具。

**基座分层**：campaign 期间模型换代无跨版本 run——Opus 4.7 期 81 个、4.8 期 45 个、5 期 18 个；14 个接受 run 中 9 个全程在 4.8、5 个全程在 5（即 4.7 期间零接受）；OpenAI 硬数学层 2026-07-10 由 GPT-5.5 切至 GPT-5.6 Sol。配套站点的单例读数（同一接受 run：证明图 22 节点 29 边、读者已验证 12/22 条陈述、两票四星、17 页 slides）仅说明读接口形态，非系统性评测。

## 5. 消融要点

论文没有组件级受控消融，这是评估上的最大空洞。可用的替代性证据与内生分层：

1. **问题类型分层**（上表）实质是对 Discovery 提案策略的自然实验：gap filling 32% 接受、其余三类 0%；假设弱化类“29 降级 vs 22 失败”进一步把死因定位到选题构念而非证明能力。但未做关闭 Discovery 各子审查的对照，无法归因到具体闸门。
2. **基座版本分层**：Opus 4.7 期 81 run 零接受、4.8/5 期 63 run 产 14 接受，产出与基座强相关；但同期 GPT 侧也在换代，两家贡献未解耦，且无成本-产出曲线。
3. **审计必要性仅有定性证据**：引言两起事故 + 表4 失败模式分类。论文未量化“关闭陈述审计会有多少接受结果漂移”，也未估计审计自身错误率（§7 明确承认 frontier 模型观察中表现好但频次未测）；双模型收敛审查 vs 单模型、F4 独立复核 vs 仅增量审查，均无对照数字。
4. **库反馈收益**是单例链（BinomialCount→FiniteCategoryPilot）+ 28 次晋升清单；“库增长 vs 单结果成本”的权衡论文自认留作未来工作，故 8,179 声明的前期投入摊销无从评估。
5. **检索接口无消融**：RRF 融合、cross-encoder 重排、goal-directed 模式的各自增量未测（编码器只报了未见模块评估的设计，未给具体指标数值）。

复现者应补的对照至少包括：statement-audit-off、library-off（仅 Mathlib 冷启动）、run-record-off、收敛审查降为单模型、检索关闭。可复现性底子较好：源码、库、run record 公开，全部计数可由 lake exe library index 与 bank 目录复核。

## 6. 贡献与启示

按论文口径三条贡献： Causalean——迄今规模最大的因果推断 Lean 4 形式化（8,179 声明，覆盖图模型/do-演算/潜在结果/精确与部分识别/面板/实验/估计/统计理论），且按“可被扩展而非完成品”设计； 端到端研究管线——自主选题、证明、成文，带库反馈回路； 144 run 的 run-record 评估与一个闭合 Zeng et al. 界隙的头条结果。

方法论的真正核心是**三层置信度的显式分离**：证明有效性（类型检查）、陈述忠实性（审计）、重要性（人类判断）——把三者分开“阻止一个有效的证明被读作重要的结果”。这个评测卫生原则对一切自动化科研系统成立。其次，冻结自然语言陈述作为不可改写契约 + 内容指纹触发下游重审，把 autoformalization 的陈述匹配从事后全量比对改造为局部化增量审查，与 blueprint 类依赖图工具兼容；cited 纪律（外部定理作为带来源的显式假设）使学术贡献边界机器可读，是可推广的工程模式。第三，presolve 与 run record 的成本观值得借鉴：用一次模型调用换掉一天管线时间、用失败记录换掉重复死路——自我改进落在资产与记录侧而非权重侧，恰是当前权重更新昂贵语境下的务实选择。

对音视频技术方向的上下游关联（本笔记作者视角，非论文主张）：
- **下游（方法供给）**：该库形式化的方法族正是流媒体/推荐平台在线实验与准实验分析的正确性基础。社交分发下 SUTVA 违背（分享、级联、推荐溢出）是平台 A/B 测试可信度的核心威胁，库中网络干扰下的 Stein 方法 CLT、未知干扰下 Horvitz–Thompson 一致性、两阶段干扰直接效应正是此类估计的可用证书；TWFE 负权分解与 event-study 污染刻画了平台常用 DiD 回归在交错采纳设定下实际回收的估计量；旗舰结果的 d≲n log n 判据为高基数类别特征（内容类目、用户分群）实验给出“何时参数阶可达”的操作性边界。若此类形式化库成为实验方法学的引用基座，实验平台的估计器选型与合规论证可获得机器检查背书。
- **上游**：系统的上游是通用 LLM 基座与 Lean/Mathlib 生态，无音视频专属组件；对本领域的价值集中在方法供给与自动化科研范式两条线。
- **范式迁移**：音视频工程中大量环节存在可机检判定器（编解码一致性比特流校验、协议栈状态机性质、A/V 同步不变量、内核内存安全），“LLM 生成 + 判定器裁决 + 陈述审计”可结构性替代 LLM-as-judge；其中“验证的性质≠想要的性质”（规约写弱/写偏）是形式化工程部署的已知坑，论文的逐节点审计与未用假设 lint 是可直接借鉴的对策。

局限（论文自述）：研究质量由管线自评、LLM 评分无独立人工验证；陈述审计本身是 LLM 任务、错误率未估计；管线大部分领域无关、迁移成本集中在建库与检索接口；更好的新颖性度量与忠实性审计基准留作未来工作。

## 7. 与其他论文的联系

清单中与本文有真实概念关联的条目集中在“自我改进智能体的验证闸门”这一轴线上：

- **paper:arxiv:2611.10787（TRUST，带统计保证的可信递归自我改进）**：同持“自我改进必须带外部裁决”立场，但裁决器不同——CausalSmith 用 Lean 类型检查 + LLM 陈述审计，TRUST 用在线多重假设检验控制错误进化率。互补点直接可见：CausalSmith 自认审计环节错误率未估计，TRUST 式错误率控制正是给这个软闸门加统计硬度的候选方案。
- **paper:arxiv:2611.14326（FGSE，证伪门控的自我演化）**：两者都把“经验写入持久资产”改为假设检验式准入——FGSE 的经验教训须经三类探针验证后才入记忆，CausalSmith 的引理须经七项审查 + 构建闸门才入 Causalean，失败 run 也入 record 作为后续提案的反例约束。差异在证伪手段：探针实验 vs 编译器加审查。
- **paper:arxiv:2611.12109（SkillDuet，模型-技能库协同演化）**：同为“外部能力资产随使用生长并反哺后续任务”的结构，对应 Causalean 的库反馈通道。粒度不同：技能是过程性程序，Causalean 晋升的是带构建验证的数学事实；且 CausalSmith 不动模型权重，自我改进全部落在资产侧。
- **paper:arxiv:2611.19230（CompoundingKernel，GPU 内核自我改进）**：同属“以硬验证器替代 LLM 评审”的 FunSearch/AlphaEvolve 谱系（论文表1 明确对照该谱系：fitness 固定故无需陈述审计）。CompoundingKernel 以执行正确性与榜单为验证器，CausalSmith 以证明检查为验证器；后者多出的陈述审计问题在执行验证范式中由固定任务指标吸收。
- **paper:arxiv:2611.11558（InfraRSI，训练基础设施的递归自我改进）**：同为多阶段带验证闸门的管线把开放式指令转为已验证产出（五阶段验证工作流 vs 本文 D/F/P 阶段流），验证器分别为实测加速与类型检查；两者都以闸门链而非单一终审控制质量。

清单其余条目（TrainExplorer、RSI-PDEbench、LongCapHarness）与本文仅有“智能体自动化”的一般性相似，无机制级对应，不展开。
