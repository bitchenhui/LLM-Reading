# P3: Prompts Promote Prompting

## 1. 背景与动机

当前 LLM 应用普遍采用双段提示结构：system prompt 承担角色、能力边界与全局约束，user prompt 给出单次请求的具体要求。在不动模型权重的“外部调优”路线中，自动提示优化（APO）已演化出两代形态：第一代（DSPy、TextGrad、PromptBreeder、OPRO 类）依靠多轮模型调用做迭代精炼，质量好但单次精炼的计算开销大，不具备实时性；第二代在线提示优化以 BPO（改写用户提示）与 PAS（在用户提示后追加“补全指令”）为代表，采用两阶段范式——先离线收集 (原始提示， 优化提示) 对，再微调一个 7B 级 instruct 小模型，在测试时按查询动态改写或扩展提示。

论文指出该范式存在三个结构性缺口：**Affinity**——system prompt 显著影响输出风格与质量，且两段提示在模型决策过程中相互交织，现有方法固定 system 单边优化 user，结果必然次优；**Diversity**——同一提示存在大量可行的改写/扩展方式，固定策略加单条贪心补全缺乏对解空间的探索；**Inference Cost**——在线优化器需微调 7B 级模型并与主模型串行执行，带来额外显存与时延，阻碍实时应用。

P3 的应答是把“system prompt 适合离线优化（场景级、部署期固定）+ user prompt 补全需在线生成（查询级、动态）”这一分工落实为统一框架：离线阶段联合优化 system prompt 与 user 补全指令，产出的提示资产（最优 system prompt x*_s 与 (query, 补全) 数据集 X*_u）反哺在线提示构造——即 "Prompts Promote Prompting"。在线阶段给出两种实现：微调小模型，或免训练的检索式 in-context learning（P3-ICL）。

从音视频交叉视角看：多模态音视频管线中 LLM 日益充当编排与决策层（视频内容理解问答、流媒体策略代理、审核打标、AIGC 剧本与分镜文本控制等），其提示结构同样是“system 定场景、user 定请求”。APO 提供了不触碰多模态主干权重的低成本增益路径，而在线优化的额外时延与显存开销决定其能否落入直播字幕、实时翻译等时延敏感业务的预算——这正是本文 P3-ICL 变体主攻并量化验证的问题（见第 4、6 节）。

## 2. 方法总览

任务形式化为黑盒优化 x_opt = F(x)，F 由 LLM 驱动实现；论文将提示显式分解为 x = (x_s, x_u)，主张任何“固定一边、优化另一边”的方案都是次优的。整体为离线/在线两阶段闭环：

**离线联合优化**。对数据集中每条 user prompt：(1) 生成 k 个候选补全指令（沿用 PAS 的补全形态，不改写原句以保义），与当前 system prompt 拼接后由 LLM 生成答案，LLM-as-judge 以 1–10 分打分；(2) 以 (候选， 分数) 对作为 few-shot 示例，驱动 LLM-as-optimizer（OPRO 式，Yang et al. 2024b）生成精炼候选，逐轮迭代、每轮合并取 top-k 截断——宽度（k 个候选并行采样）与深度（D 轮迭代）共同扩展解空间；(3) 取终局最高分补全，若分数高于阈值 ε，将 (user prompt, 补全) 收入好样本集 X*_u（供在线微调或检索），否则压入难样本缓冲 X_u。

**难样本驱动的 system prompt 优化**：每隔 T 条查询执行一次。从难样本缓冲采样一个批次，从 system prompt 缓冲 X_s（初始由原始 system prompt 精炼出的 k 个候选构成）采样候选，各候选在批次上取平均分评估；再以 (候选， 分数) few-shot 生成新候选，高分者入 X_s，全局最优更新为“当前 system prompt”并回流至后续 user 补全优化。两个优化进程由此交替咬合：user 侧产出的低分样本喂给 system 侧，system 侧的最优 prompt 又改变 user 侧的生成与评分环境。

**在线阶段**：y = LLM(x*_s, f(x_u | X*_u))。f 的两种实现—— 沿 BPO/PAS 路线在 X*_u 上微调 Qwen2-7B-Instruct 作为在线优化器； P3-ICL，用轻量句向量模型（all-MiniLM-L6-v2）从 X*_u 检索相似 对，按带 complementary_instruction / answer 标签的模板组装 few-shot 演示，免训练。

主实验中 user 补全优化的迭代深度取 1（附录 7.1 给出深度 1→3 的单调增益）；超参全实验统一 ε=6、k=5、c=5、C=3，T=400（PAS 数据与 GSM8k）/ 80（GPQA），其中 ε 为依数据集难度经验调整的量（论文自述）。通用 QA 的离线数据直接采用 PAS 提供的数据集（7729 条）以保证可比性。

## 3. 关键设计

### 3.1 用户提示补全：宽度 × 深度的采样搜索

补全生成的 meta prompt（附录 7.7）给出四条硬约束：只提供可行方向与思路过程、不泄露答案本身；保持简短；与用户提示同语言；用 `<INS>` 标签包裹。补全优化则以历史 (指令， 0–10 分) 为示例，要求“生成优于全部历史的新指令”。其多样采样的动机来自一个关键经验观察（3.3.2 节）：补全指令的生成对数概率与其评测得分之间**不存在正相关**，因此贪心解码不保证得到高质量补全，必须依靠多样采样探索。判分器分两套：通用任务用综合质量判分（helpfulness、relevance、accuracy、depth、creativity、detail），推理任务用带参考答案、聚焦正确性的判分，均为 1–10 分制。分数门控 ε 是整套框架的数据枢纽：好样本养在线优化器，难样本养 system prompt，数据零丢弃。

### 3.2 系统提示优化：亲合性的构造性落实

system prompt 优化同样采用 LLM-as-optimizer 进化式精炼，但评估对象从单条查询变为难样本批的平均分，保证优化目标是“对困难分布稳健”而非过拟合单点。亲合性并非依赖隐式涌现，而是有显式的文本级机制：system prompt 的优化 meta prompt 中明确写有“用户查询中总是含有一条补全指令，务必善用该信息”，即 system prompt 被优化为**适配补全范式**的角色定义。附录 7.4 的对照案例（GSM8k 蜡烛净利润题）给出了失效模式：PAS 的固定 system prompt（"Think step by step"）下，模型先计算可制蜡烛总数、偏离了补全指令规定的“先算成本再算收入”路径，得出错误答案 30 美元；P3 的联合优化 system prompt 使模型严格遵循补全步骤（2 磅蜂蜡成本 20 美元、收入 40 美元），得出正确答案 20 美元。这印证了机制：优化的收益部分来自“模型更听话地执行补全指令”，而非补全指令本身信息量更大。另注意 GSM8k 的优化后 system prompt 中输出格式约束（"Answer: $VALUE"）为手工加入（附录 7.2 自述），非全自动产物。

### 3.3 在线阶段两种 f 的工程取舍

微调版：PAS 数据取 7605/7729 条、GSM8k 取 7361/7473 条（其余被过滤为难样本），全参数 SFT（DeepSpeed Zero，AdamW，lr 1e-5）；GPQA 数据量小（main+extended 去除 diamond 重复后 348 条取 299 条），改用 LoRA+（r=8，LoRA+ 比率 λ=16，lr 3e-4）。在线优化器自身也配有一条固定的 system prompt（“在用户提示末尾追加补充提示”的专家定义）。P3-ICL 版仅依赖 0.02B 参数的检索器。其效率机理（3.3.3 节）值得注意：ICL 只增加 prefill 阶段的 token 数，现代硬件的并行 prefill 可摊薄其影响，端到端时延通常由 decode 阶段的逐 token 生成主导——而 P3/PAS 的小模型需要自回归生成补全文本，恰恰拉长了串行链路的 decode。这解释了为何“更长的输入提示反而更快”。

### 3.4 优化器与主模型配置

通用 QA：GPT-4o-mini 充当提案与优化器模型（弱于 PAS 所用的 GPT-4o，构成“更便宜优化器仍取胜”的对照），GPT-3.5-turbo-1106 作为离线回复生成基座；评测主模型沿用 PAS 的五个：GPT-4-turbo-2024-04-09、GPT-4-1106-preview、GPT-3.5-turbo-1106、Qwen2-72B-Instruct、LLaMA-3-70B-Instruct。推理任务对两个基准分别独立离线优化：GSM8k 用 GPT-4o 优化 gpt-3.5-turbo-0125；GPQA 用 GPT-4o 自优化，评测时以 3 轮测试时更新的多数投票聚合。所有 ICL 方法统一 4-shot。

|---|---|---|---|---|---|

| Alpaca-Eval 2.0 | 34.04 | 38.05 | 47.52 | 57.16 | **59.09** |

关键单点：GPT-3.5-turbo-1106 上 Alpaca-Eval 2.0 从 Raw 9.20 / PAS 15.82 升至 P3 34.53（较 PAS +18.71，原文口径）、P3-ICL 45.77；同模型 Arena-hard 上 P3-ICL 36.81 对 PAS 22.10。Qwen2-72B 上 AE 2.0 从 PAS 45.53 升至 P3 61.37、P3-ICL 64.84。最强模型 GPT-4-turbo 上 AE 2.0 也从 46.12 升至 70.50。论文结论：P3 在除一个“模型-基准”组合（GPT-4-1106 × Arena-hard，PAS 78.80 > P3 77.21）外全面占优；P3-ICL 在 GPT-3.5、Qwen2 等较弱模型上反超微调版 P3；且 P3 使用更弱的 GPT-4o-mini 优化器仍胜使用 GPT-4o 的 PAS。另一个值得注意的信号：BPO 在 Arena-hard 上平均（51.34）低于 Raw（51.90），在 GPT-3.5（15.90 vs 18.90）与 Qwen2（44.40 vs 48.10）上同样倒退，说明改写式在线优化并不稳定。

## 5. 消融要点

**(1) system prompt 联合优化**（表 3，三基准平均，Δ 为相对 Raw 的平均提升）：

| 主模型 | P3 | P3 w/o system | PAS + P3 system |
|---|---|---|---|
| GPT-4-turbo | 68.94 (+9.69) | 67.47 (+8.22) | 65.24 (+5.99) |
| GPT-4-1106 | 68.03 (+9.76) | 66.88 (+8.61) | 63.45 (+5.18) |
| GPT-3.5-turbo | 31.81 (+16.01) | 21.55 (+5.75) | 31.25 (+15.45) |
| Qwen2-72B | 56.64 (+16.96) | 48.82 (+9.14) | 51.20 (+11.52) |
| LLaMA-3-70B | 47.74 (+11.51) | 46.25 (+10.02) | 44.55 (+8.32) |

去掉 system 优化后在全部基准、全部模型上一致下降，且对提示敏感模型（GPT-3.5、Qwen2）降幅最大（GPT-3.5 平均增益从 +16.01 跌至 +5.75）。更关键的对照：把 P3 优化出的 system prompt 单独移植给 PAS，AE 2.0 / AE-LC 有明显增益，但 Arena-hard 严重退化（GPT-4-turbo 上 69.80 vs P3 的 78.00；GPT-4-1106 上 72.25 vs 77.21）——说明“更好的 system prompt”单独不可移植，性能来自**联合优化下的两组件协同适配**，这直接支撑了 affinity 论点。此外在最强模型上，Arena-hard 单项的 system 优化贡献接近零甚至略负（GPT-4-turbo：78.43 → 78.00），增益主要来自 AE 系基准与弱模型。

**(2) 多样采样的独立贡献**（表 4，GPT-3.5-turbo-1106）：即便去掉 system 优化，P3 仍全面高于 PAS——Arena-hard 22.10→23.32、AE 2.0 15.82→16.65、AE 2.0(LC) 23.3→24.7、GSM8k 81.30→83.10，即宽深结合的采样搜索本身即有可分离的增益，与对数概率-分数无相关的观察互为印证。

**(3) P3-ICL vs 原始 ICL**（表 6，平均增益相对 Raw）：GPT-3.5 +25.79 vs +16.09；Qwen2 +19.34 vs +16.33；GPT-4-turbo +5.67 vs +4.55；LLaMA-3 +12.04 vs +9.26；唯一例外是 GPT-4-1106（+6.26 vs +6.56，原始 ICL 略高）。结论：离线构造的补全对用于检索演示时，携带显式推理指引的示例优于普通 QA 示例，且弱模型受益最大。

**(4) 搜索深度**（附录 7.1）：GPT-3.5-turbo-1106 上将 user 补全优化迭代从 1 增至 3，Arena-hard 与 Alpaca-eval 三个基准的分数均单调上升。注意主表全部结果取深度 1，即论文主结果仍是该框架相对保守的下界。

## 6. 贡献与启示

**贡献**与三个问题一一对应：联合离线优化 system×user 补全解决 affinity（并有移植实验证明“联合”不可替代）；k 候选并行采样 × D 轮迭代的 LLM-as-optimizer 搜索解决 diversity（并有对数概率与得分不相关的证据）；P3-ICL 以 0.02B 检索器替代 7.62B 生成式优化器，在单卡 3090 上把额外时延从 530 ms 降到 70 ms、首 token 时延低约 25%，解决 efficiency。难样本回收（不合格样本转投 system prompt 优化）是常被忽视的第三重贡献：数据效率与鲁棒性兼得。

**方法论启示**：其一，离散提示空间中“对数概率 ≠ 质量”，意味着一切基于贪心解码的提示改写都系统性次优，采样+评分+few-shot 进化是更合理的搜索骨架；其二，分数门控做数据分流是好样本养模型、难样本养全局约束的通用模式；其三，在线优化器的学习可以完全摊销到离线阶段，且同一份离线资产同时兼容“微调”与“检索”两种部署形态。

**对音视频上下游的工程含义**（迁移性推断，非论文实验）：上游看，音视频多模态系统中的 LLM 编排层（视频问答、流媒体策略代理、审核打标、AIGC 文本控制）天然是“system 定场景 + user 定请求”结构，P3 的离线联合优化 + 部署期固定 system prompt 的范式与 A/V 场景化产品的配置管理直接同构；补全指令“给方向不给答案”的约束也适配创作辅助类任务（分镜建议、字幕风格指引）。下游看，P3-ICL 的 5000 MiB / 70 ms 额外开销落在直播字幕、实时翻译、端侧语音助手等首包时延敏感业务的可接受区间；免微调还意味着多模态基座升级时，提示资产 (X*_u) 可直接复用而不必重训在线优化器——这对基座快速迭代的多模态 A/V 团队是显著的运维优势。

**边界与保留**：评测集中于偏好类基准（Arena-hard、Alpaca-Eval 系）与两个推理基准，未涉及多模态/音视频任务；优化信号与评测指标同源于 LLM 判分，存在偏好对齐的系统性风险，论文未讨论；LLM-as-judge 阈值 ε=6 为启发式门控，无统计保证；离线搜索消耗的 judge/optimizer 调用成本未报告；论文自述局限包括在线优化器仅试 Qwen2-7B-Instruct 一档、尚未在推理模型（OpenAI O1、DeepSeek-R1）上验证。

## 7. 与其他论文的联系

P3 自我定位为 self-improvement 框架（离线迭代搜索 + 分数反馈闭环），与清单中递归自改进谱系的工作存在机制级关联（非引用关系，属结构对应）：

- **FGSE（paper:arxiv:2611.14326）**：两者都在“自改进回路中什么样的经验允许被写入”上设门控——P3 用 LLM-as-judge 分数阈值 ε 决定 样本进入微调集还是难样本缓冲，FGSE 用三类探针证伪后才将经验教训写入智能体记忆。关联依据：同为“经验写入前的质量门控”结构；P3 的 ε 门是无保证的启发式判分，FGSE 可视为对该类门控可靠性的强化方向，二者对照凸显了提示优化场景下门控信号的可验证性问题。

- **SkillDuet（paper:arxiv:2611.12109）**：SkillDuet 以响应反馈协同演化“模型参数 × 外部技能库”，P3 以 judge 反馈协同优化“system prompt × user 补全指令”，并进一步用产出数据微调在线小模型，同样是“外部资产 + 参数更新”的耦合。关联依据：同为反馈驱动的双组件协同演化框架，且都证明单边优化次优；差异在于 P3 的参数更新只作用于在线优化器小模型、主模型全程冻结，属于更轻量的协同层级。
