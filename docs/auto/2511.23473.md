## 1. 背景与动机

FunSearch 与 AlphaEvolve 确立了“LLM 程序进化”这一数学发现范式：为任务手工设计不可作弊的确定性 evaluator 与初始程序，LLM 以 CoT + SEARCH/REPLACE diff 的方式迭代改写父程序，程序数据库负责保留高分与多样性候选，在若干开放优化问题上逼近或改写 best-known bound。该范式存在三个结构性缺陷：

其一，系统闭源、管线复杂。开源复现（OpenEvolve、ShinkaEvolve）携带大量未经充分消融的超参，哪些组件真正必要并不清楚。其二，工程默认绑定前沿闭源大模型 ensemble（AlphaEvolve 用 Gemini-2.0-Flash/Pro；ShinkaEvolve 用含 Claude-Sonnet-4、o4-mini 在内的六个模型），隐含“小开源模型推不动这些界”的预设。其三也是最关键的：AlphaEvolve 是纯推理系统，权重从不更新，有效探索策略（"search-on-the-edge" 行为）无法被模型内化，全部负担压在推理管线设计上。

另一条线上，RLVR 已证明对推理语言模型的有效性；AlphaProof 进一步表明当任务具备自包含规则验证器（Lean）时，测试时 RL 能超越标准推理时 scaling。作者的关键观察是：程序进化管线天然满足这一条件——候选程序一旦生成，固定 evaluator 可确定性判合法并输出连续目标值（注意 evaluator 常是瓶颈，AlphaEvolve-v2 对 FirstAutoCorrIneq 的超时设到 1000 秒）。于是可把“数据库不断更新的进化管线”整体视为一个 adaptive verifiable environment（Zeng et al., 2025 的 RLve 提法），把 test-time 的 in-context 进化与 RL 参数更新统一进同一循环。ThetaEvolve 即此构想的落地：开源、单 LLM、上下文内学习与测试时 RL 同时可扩展，并首次让 8B 级开源模型在 AlphaEvolve 涉及的开放问题上取得新 best-known bound。

对音视频方向的读者而言，这类“确定性验证器 + 连续标量奖励”的优化问题谱系与编码决策、码控、流控启发式同构，映射见第 6 节。

## 2. 方法总览

ThetaEvolve 在 OpenEvolve 之上构建动态环境，基于 slime 框架做 RL，单步流程：

1. **Prompt Builder**：从数据库采 B=32 个父程序，构造 B 个 prompt（meta-information + 父程序及其分数 + diff 规则指令）；RL 与纯推理共用同一批 rollout。
2. **批量生成**：单一 LLM 对每个 prompt 采 n=16 条响应，共 B×n=512 个子程序/步。
3. **Parser/Verifier**：应用 diff 得子程序；不可变文件中的 evaluator 做合法性检查与打分。
4. **数据库**：子程序顺序插入、逐条重排（开销相对系统其余部分可忽略）；按岛屿模型 + MAP-Elites 特征格组织，超额时按适应度淘汰并保护全局最优与最新程序。
5. **（可选）RL 更新**：同一批响应用于 GRPO。作者刻意不用 dynamic sampling，以保持 RL 与纯推理的样本口径公平。

相对 AlphaEvolve/OpenEvolve 的直接改动：单 LLM 替代 ensemble；prompt 仅含父程序、不再附额外 prior programs（可选配置，缩短 prompt 换效率）；数据库 population size=10000（OpenEvolve 为 70，AlphaEvolve 未披露）；批量采样替代异步串行请求以吃满 vLLM/SGLang 类批式推理引擎；分级负分与懒惰惩罚、可选奖励整形（第 3 节）；meta-information 改为多段固定、带权重的条目池按权重采样（简化 OpenEvolve 的两阶段流程），不做 AlphaEvolve 式 meta-prompt 进化，也未实现其全局最优解复用。

RL 配置：GRPO + 非对称裁剪（clip_low=0.2、clip_high=0.28）与截断重要性采样，lr=1e-6，weight decay=0.1，无 KL/熵正则；rollout 温度 1.0，最大响应 16384 token，最多 16 个 verifier 并发；实验硬件 8×A100-80G。任务五个：CirclePacking-T（26 圆单位方、半径和最大化，带 OpenEvolve 的 1e-6 容差口径）、First/Second/Third AutoCorrIneq、HadamardMatrix（n=29 行列式最大化）。评测口径有两处必须注意：容差差异使 OpenEvolve 与 AlphaEvolve 实为不同优化问题（故单列零容差正式版 CirclePacking，由 CP-T 解整体缩半径 1e-6 换算）；AlphaEvolve 的 ThirdAutoCorrIneq evaluator 有公式 bug（离散验证式缺绝对值），作者改用理论正确公式，故该任务分数与历史值 1.4581/1.4557 不可直接比。

## 3. 关键设计

### 3.1 批量采样
AlphaEvolve 每步只构造一个 prompt、取一条响应，异步管线喂不饱批式推理引擎。ThetaEvolve 每步独立采 B 个父程序、每 prompt n 条响应，天然形成大 batch；数据库侧以“逐条插入 + 重组”保持近似在线性，作者称开销可忽略。吞吐差是量级性的：同为 ProRL-1.5B-v2 在 CirclePacking-T 上跑 400 步（204.8K 程序），OpenEvolve 63.6 小时 vs ThetaEvolve 5.4 小时（4×A6000，vanilla SGLang，相同推理参数）。

### 3.2 早检与懒惰惩罚
分级负分：响应中无 diff 块 -0.4；无有效变更（子程序≡父程序）-0.3；无解（编译/执行错误、超时）-0.2；解非法（如圆重叠）-0.1；否则取 E(cp)。设计要点有二： 所有失败模式在进入昂贵 evaluator 前拦截； 等价判定以“去除注释后等价”为口径，且对数据库内任意历史程序判定而非仅父程序——理由是 RL 训练可能让模型记住库内成功程序而复读。机理：开放问题接近 best-known 时绝大多数修改不涨分，“复读当前最优”是稳定但不产生梯度的行为；不显式惩罚，RL 的优势估计会被大量安全复读淹没。

### 3.3 奖励整形（可选）
部分任务目标值域过窄（如 SecondAutoCorrIneq 约 0.90–0.96），原始分数难以区分解质量。整形规则：R(s)=s（当 s<0 或未启用），否则 k·F(s)，k=3；F(s)={clip(H(s),0,1)}^α，H 将人工指定的 [L,U] 线性映射到 [0,1]（按最大化/最小化取向），α≥1 越大则在逼近 best-known 处奖励越陡。仅用于两个自卷积任务（TACI、SACI）。

### 3.4 防作弊验证器与 prompt 工程
每任务两个 evaluator 辅助函数（合法性、目标分），evaluator 放不可变文件，被评程序必须把解写入独立文件供 evaluator 读取——切断程序内篡改评测逻辑的 reward hacking 路径。meta-info 为多段固定加权条目：CirclePacking-T 沿用 OpenEvolve 两段式（权重 0.3/0.7，一段鼓励显式构造器、一段鼓励突破平台的搜索算法）；FirstAutoCorrIneq 直接沿用 AlphaEvolve-v2 的 prompt 与初始程序；其余任务的改进洞见由 GPT-5/Claude 4.5 生成（仅产洞见不产程序），所有对比运行共用同一套 prompt。

### 3.5 动态环境作为隐式课程
附录 D 的核心论证：设从初始程序 P0 到高级程序 P 需 N 代链 {P0,…,P=P_N}，近似 Markov 假设下 P(P|C,P0) ≈ ∏ᵢ P(Pᵢ|C,P_{i-1})。静态环境（永远从 P0 出发）中该概率 ϵ≪1，奖励极度稀疏；动态环境在中间态 P_{i-1} 上采样 Pᵢ 的概率量级为 Θ(log_N ϵ) ≫ ϵ，训练全程有非平凡信号，且随训练推进各段概率上升、反哺整体 ϵ。这直接解释第 5 节静态环境 RL 的崩塌，是“动态环境 = 免费课程”主张的理论支点。

## 4. 实验结果

设置：ProRL-1.5B-v2 与 DeepSeek-R1-0528-Qwen3-8B（下称 8B），3 个种子（42/1234/3407）；w/RL 与 w/o RL 同步数对比（1.5B@200、8B@65），w/o RL 另给约 3 倍（1.5B@600）或 1.5 倍（8B@100）步数的延长运行；每步对应 512 个新程序。

新 best-known bound（论文表 1）：

| 口径 | Human | AlphaEvolve (Gemini-2.0-Flash/Pro) | ShinkaEvolve | ThetaEvolve (8B) |
|---|---|---|---|---|
| CP (↑, 零容差) | 2.634 | 2.63586276 | 2.63598283 | **2.63598308** |
| FACI (↓) | 1.5098 | 1.503164 | – | **1.503133** |

要点：CP 新界来自 8B 的 w/RL 运行（CP-T 上 best 2.6359857），将全部半径统一缩 1e-6 后仍可证优于 AlphaEvolve；且该程序只需约 3 秒即可稳定复现最优解，ShinkaEvolve 的程序约 75 秒。FACI 的 1.503133 是以 AlphaEvolve-v2 SOTA 解为附加初始化后的微改进；无该初始化时 8B 约 50 步达 1.5068，已超人类 SOTA 1.5097（Matolcsi & Vinuesa, 2010），未超 1.5032。解本身与 AlphaEvolve 不同构：CP 解非对称（仅 19、24 号圆不相切，AlphaEvolve 解近对称、仅 25、14 号不相切）；发现的程序把启发式构造升级为 scipy SLSQP 约束优化（显式非重叠/边界不等式约束，n=26 六边形格点特化初始化，maxiter 5000–15000）。

主结果关键行（mean/best，3 种子）：

| 任务 | 模型 | 初始 | w/RL | w/o RL（同步数 / 延长步） |
|---|---|---|---|---|
| CirclePacking-T (↑) | 1.5B | 0.9598 | @200: 2.3498 / 2.5225 | @200: 2.0265 / 2.1343；@600: 2.0991 / 2.2491 |

两模型四任务上 w/RL 一致胜出，且在更少步数下即超过 w/o RL 的延长运行（1.5B CP：200 步 2.3498 vs 600 步 2.0991）。作者提醒：接近 best-known 后每一点增益都非平凡，且分数相近的解在结构上可能差异显著（8B 在 TACI 构造的函数远比 1.5B 复杂）。

**能力内化与跨任务迁移（4.3.1）**：取 1.5B 在 CP 上最优 w/RL 运行的 step-150 checkpoint（best 2.5225）做纯推理：CP mean 2.3852、best-seed 2.4061，均高于原始模型推理（2.0991/2.2491），mean 甚至超过完整 w/RL 运行（2.3498），best 略低于完整 RL（2.5225）——参数更新确实内化了进化能力。在未见任务上，该 checkpoint 纯推理 mean 为 HM 0.5231（原始模型 0.4920、该任务完整 w/RL 0.4808）、TACI 1.6424（1.6766/1.6412），常匹配甚至超过该任务上的 w/RL 运行，best 亦小幅提升——单任务 RL 习得的进化能力可跨任务迁移，暗示其可扩展为通用后训练配方。

**与 AlphaEvolve-v2 同起点对比（4.4.4）**：FACI 用其提供的初始程序（1.5214）与 prompt，8B 构造出的阶梯函数自卷积曲线与 AlphaEvolve-v2 高度相似（1.5068 vs 1.5032）；SACI 得 0.9469，超人类最好 0.9414（Jaech & Joseph）、低于 AlphaEvolve-v2 的 0.9610，但程序超时仅 350 秒，而人类与 AlphaEvolve-v2 的程序常需数小时。

## 5. 消融要点

**静态环境 RL（4.3.2）**：RL 永远从固定初始程序出发（AlphaEvolve 同款消融）：CP-1.5B mean 1.5985（动态 2.3498）、CP-8B 2.6123434（2.6359840）、TACI-8B 1.6173（1.5210）；静态 RL 甚至差于 ThetaEvolve 纯推理。这是 3.5 节稀疏奖励论证的直接经验证据。

**format reward（4.3.3）**：TACI-1.5B 上仅奖励格式正确（分数非 -0.4/-0.3 即得 1.0）：mean 1.6783/best 1.6744，比 w/o RL（1.6766/1.6123）还差——排除“只学会输出格式”的解释。

**数据库规模（4.4.1）**：Small/Medium/Large = population 70/1000/10000（archive 25/100/1000，islands 5/10/10）。算力小（<40 步或 <20K 程序）时 Small 更快（高分程序被更密采样；Large 需约 10K 程序、约 20 步才填满并开始淘汰）；继续加算力后 Small 几乎停滞，Large 靠多样性持续涨分。

**批量 vs 异步（4.4.2）**：1.5B + CP-T 上，OpenEvolve 默认量级（512 程序）仅 1.0955/1.2634；放大到 307.2K 程序后 2.1313/2.1773，与 ThetaEvolve w/o RL（2.0991/2.2491）同级——测试时算力本身是第一性变量，管线差异次之；ThetaEvolve 的增益主要在 5.4h vs 63.6h 的吞吐。w/RL 307.2K 达 2.3498/2.5225。

**奖励整形（4.4.3）**：TACI 上 8B 用 (U=3.2, L=1.4557, α=3.0) 得 1.5210/1.4930；同配置在 1.5B 上仅 1.6535/1.6231，劣于窄区间低指数 (2.5, 1.5, α=1) 的 1.6412/1.6053。原因：8B 第 20 步即达 1.53–1.57、可吃到陡峭高分区，1.5B 第 20 步仅 1.8–2.0 且从未低于 1.60，α=3 对其过激。处方：先跑 w/o RL 观察分数分布再定参；预算不足时 α=1 + 窄 [L,U] 是稳健缺省。

**数据库管理（附录 E.4）**：把岛屿 + MAP-Elites 简化为纯分数优先队列（单岛、单特征、单格），CP-1.5B w/RL 从 2.3498/2.5225 掉到 2.0486/2.1154——多样性机制在放大数据库后依然必要。

## 6. 贡献与启示

贡献有三： 开源框架把 AlphaEvolve 谱系压缩为“单 LLM + 大数据库 + 批量采样 + 懒惰惩罚 + 可选整形”的最小充分组合，并给出组件级消融； 首次证明 8B 开源模型可刷出开放问题新 best-known bound（CP、FACI），打破“必须前沿 ensemble”的预设； 给出“动态环境 + RL 使模型内化进化能力且跨任务迁移”的系统证据（checkpoint 复用、未见任务提升），并以静态环境、format-reward 两个阴性对照排除伪因。

方法论启示： 动态环境是免费的 RL 课程——程序数据库把“一步跳到 SOTA”的不可达目标分解为可达增量链，奖励密度提升是量级性的（Θ(log_N ϵ) ≫ ϵ）； 懒惰惩罚是 RLVR 在“逼近上界”区域的关键工程件，且等价判定须覆盖全库而非仅父程序（防 RL 记忆性复读）； 评测口径先于可比性——1e-6 容差与 evaluator 公式 bug 都会把“同一问题”变成两个问题； meta-info 对最终性能影响大（承 AlphaEvolve-v2 结论），本文以闭源模型生成洞见后全程固定。

局限：evaluator、[L,U]/α、meta-info 仍是手工件；FACI 新界依赖以 AlphaEvolve-v2 SOTA 为附加初始化；未实现全局最优解复用与 meta-prompt 进化；TACI 因公式修正不可与历史值比；三种子下方差仍可观（1.5B HM w/RL 三种子为 0.3888/0.5635/0.4901）。

对音视频技术上下游的映射（笔者外推，非论文实验）：该框架的适用判据是“确定性验证器 + 连续标量奖励”，编码与流媒体域大量问题符合——编码模式决策与码控启发式（R-D cost 为奖励）、ABR/调度策略、编解码内核与后处理算子微优化，与 AlphaEvolve 谱系做过矩阵乘法内核与调度优化同构；“解写入独立文件、evaluator 不可变”的防作弊设计对应音视频指标必须由独立工具链复核的工程纪律。上游侧，ThetaEvolve 消费的小开源推理模型与 SGLang/vLLM 批式服务栈与多模态模型部署同构，其“批量采样 + 批式验证”的吞吐设计对音视频 Agent 的 rollout 管线可直接移植；“单任务 RL 内化、跨任务迁移”则提示面向编码/流媒体算法的后训练可走“进化环境里做 RL”的路线，而非只在推理时挂搜索。

## 7. 与其他论文的联系

- **SwarmEvolve**：同为 AlphaEvolve 谱系开源变体，走“数百低成本智能体蜂群 + KV 缓存共享信息”的扩路线；ThetaEvolve 反向做减法（单 LLM）并补上权重更新维度，两者分别在“搜索组织”与“学习内化”两个轴上演化同一范式。
- **FrugalEvo**：以“强 LLM 出策略、廉价 LLM 写代码”最小化单位成本；ThetaEvolve 的 8B 结果给出更激进的成本下界证据——配合大数据库与 RL，单个小模型即可触及 SOTA 界，二者在成本-性能权衡上互补。
- **Hill Sampling**：主张冻结 LLM 以当前最优程序为条件的反复采样即可胜过进化搜索与测试时训练；ThetaEvolve 的 w/RL > w/o RL 及动态 > 静态环境的结论与之构成对立证据（任务域不同）。机制上 Hill Sampling 的条件化采样与 ThetaEvolve“prompt 仅含父程序”的迭代精炼配置同族，但缺少数据库多样性与参数更新，适用边界值得对齐实验。
- **ε-MemEvo**：把成功算法策略存为任务无关记忆、经门控注入实现跨任务迁移（8 基准平均 +8.7%）；ThetaEvolve 的跨任务迁移走权重内化路线（CP 上训练的 checkpoint 在未见任务上直接提升），显式记忆与参数两种迁移载体可对照阅读，且理论上可叠加。
- **MLEvolve**：同为 LLM 自进化程序搜索（渐进 MCGS + 回顾记忆），面向 ML 算法自动发现；ThetaEvolve 的差异在于以开放数学问题的 best-known bound 为锚，并引入 RL 训练环。
- **Improving VLMs on Scientific Chart Analysis via Autonomous Evolution**：将 AlphaEvolve 式推理时进化用于冻结 VLM 的图表问答（精确匹配 16.6%→41.3%，快 3.8 倍），是“推理时进化”在视觉任务的落地；ThetaEvolve 恰好补上其缺的一环——测试时 RL 带来的内化与迁移，是音视频多模态方向最直接的参照。
- **AutoAssumption**：将算法写成 Lean 证明图、搜索放宽假设以发现超越已发表方法的 KV 缓存驱逐与剪枝算法；与 ThetaEvolve 同属“机器可验证的 LLM 算法发现”，但验证器类型不同（形式证明 vs 确定性数值 evaluator），决定了可发现算法类的差异；其 KV 缓存驱逐目标本身即音视频流式推理系统的核心组件，是两套方法论在 AV 系统上的天然交汇点。
- **Agentic Algorithm Design**：LLM 提出黑盒优化算法并在 Lean 中机器检验期望运行时间界、无需经验比较；ThetaEvolve 则完全依赖经验目标分数、无形式保证——两条路线在“自动算法设计是否需要形式验证”上互为镜像。
