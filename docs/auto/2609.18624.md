# MoQSplat: Adaptive Progressive Streaming of 3D Gaussian Splatting via MoQ

> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

3D Gaussian Splatting（3DGS）以显式高斯原语集合绕开 NeRF 式神经推理，实现实时高保真新视角合成；但为捕捉视角相关高光需最高三阶球谐（SH，每原语 45 个参数），真实场景由此达到数百万 splats、总量数 GB 量级，对标准网络上的实时分发构成严峻带宽压力。

面向传输的已有 3DGS 工作基本沿用 HTTP 自适应流（HAS）与可分级视频编码（SVC）的思路：LapisGS 用不透明度优化做渐进分层，LTS 把空间 tile 与 DASH 分段结合，L3GS 用视口预测做对象调度。这些方案共同的问题在于传输底座是 TCP：分组丢失触发队头阻塞（HOL），后续所有数据的重传都被拖住；同时 HAS 的粗粒度分段与 3DGS 数据需要的细粒度组织不匹配。HTTP/3 over QUIC 虽通过多路复用 UDP 流缓解了传输层 HOL，但标准 HTTP/3 的客户端拉取分段模式仍会抬高时延。

Media over QUIC（MoQ）是 IETF 正在标准化的低延迟交互媒体传输体系（文中对齐 draft-ietf-moq-transport-18，2026 年 5 月版），核心是发布-订阅架构 + Track/Group/Subgroup/Object 四级内容层次 + 中间 Relay 中继。已有工作把 MoQ 用于点云与体积视频，但尚未处理 3DGS 特有的各向异性尺度、不透明度与球谐系数结构。作者的核心洞察是：MoQ 的四级层次与 3DGS “空间区域—语义对象—质量档—单 splat 属性” 的天然组织方式同构，可以把空间区域与质量档映射为相互独立的 QUIC 流，在消除连接级 HOL 的同时获得优先级感知交付能力。

论文宣称三点贡献：（1）3DGS 到 MoQ 四级内容层次的映射，含语义对象检测与质量细分到 Subgroup；（2）完全无状态、订阅者驱动的适配模型，客户端基于视锥对齐与欧氏距离计算效用，经 SUBSCRIBE 命令动态调整层粒度；（3）基于定制化 moq-lite Pub/Sub 框架与 PyTorch gsplat 渲染器的端到端原型实现。从音视频上下游看，这项工作本质上是把 2D 视频领域成熟的 ABR/DASH 范式迁移到 MoQ 新传输底座与 3D 表征上，属于“新一代传输协议 × 新一代沉浸式媒体表征”的交叉命题。

## 2. 方法总览

MoQSplat 由三个角色组成：Publisher、内容无关的 MoQ Relay（可选）、Subscriber。

- **Publisher**：负责内容预处理、层次映射与会话初始化。将场景做空间与语义分解以适配四级层次，生成包含场景元数据的 manifest（Track 标识与空间包围盒、Group/Subgroup 组织结构、Group 3D 质心与 Subgroup 渐进质量档等结构元数据），并在初始化时把 manifest 与全部预计算的空间/质量变体推给 Relay 缓存。
- **Relay**：内容无关的转发与缓存实体，按 MoQ 层次转发，不做任何场景感知调度，不维护每客户端状态——这一无状态性使其天然支持多订阅者内容分发与边缘缓存。
- **Subscriber**：执行视口驱动的动态订阅循环、渐进渲染与本地缓存管理，是整个适配逻辑的唯一决策点。

四级层次映射是设计骨架：

- **Track（空间区域）**：全局内容划分为多个非重叠空间区域，客户端只订阅与当前视口相交的 Track，避免传输全部 splats；可复用点云领域的 block partition 策略构造，同时降低大规模场景（数百万 splats）的内存与计算复杂度。
- **Group（语义簇）**：Track 内 splats 聚成语义连贯的对象簇，可对 splat 属性直接做空间聚类（K-Means、DBSCAN）或经 2D/3D 目标检测映射回 3D 域。论文特别强调语义感知的必要性：朴素空间划分会把单个对象切进多个簇，独立流式传输时产生视觉伪影。
- **Subgroup（质量档）**：每个 Group 细分为 S1…Sm 渐进质量层（两类构造启发式见 §3），每层对应一条独立 QUIC 流。
- **Object（传输单元）**：最细粒度，封装单个 splat 的属性（几何、不透明度、SH 系数等），自然对应簇内语义对象。

适配哲学上最关键的区分是：与 HAS 不同，MoQSplat 的适配发生在**流优先级层面而非分段选择层面**。Publisher 暴露所有空间与质量变体并给 Subgroup 赋静态基线优先级，但不做运行时调度；Subscriber 利用 QUIC 多路复用流之上的应用层调度，把传输容量分配给当前最相关的流，并经标准 MoQ subscribe update 消息在运行时更新优先级——为视觉重要对象加速、抑制次要对象，且无需重建连接。作者明确将其定位为传统 2D ABR 算法的 3D 视口感知对应物，并指出高级视口感知调度启发式（动态网络与遥测条件下）是后续研究方向。若 Subscriber 不部署任何优先级算法，所有 Subgroup 订阅优先级并列，系统整体回退到 Publisher 定义的渐进优先级：所有可见簇的基级同时发送，随后是所有第一增强层，依此类推，构成基线交付模式。

## 3. 关键设计

### 3.1 Subgroup 的两类构造启发式

1. **独立几何启发式（Independent Geometric Heuristics）**：对 splat 总体按空间显著性（体积 volume 与孤立度 isolation）排序分档，保证基级 S1 最小化视觉空洞；层边界可用百分比阈值或固定基数预算配置，并可与剪枝、压缩方法集成。各层之间无解码依赖。
2. **依赖式属性拆分（Dependent Attribute-Based Partitioning）**：按属性跨层切分——基级 S1 只传几何与 0 阶 SH 漫反射颜色，高阶 SH 系数推迟到增强层。这引入解码依赖：必须先拿到 S1 几何才能渲染增强层。该路径在原型中未实现，属设计层面选项。

### 3.2 优先级模型与 MoQ 语义

MoQ 优先级为 [0, 255] 区间整数，0 为最高。Publisher 为渐进交付赋静态基线优先级：基级取低值（高优先），每个后续增强层取渐高值（低优先）。调度引擎先评估 Subscriber 指定的订阅优先级，Publisher 优先级仅作 tie-breaker——即运行时决策权完整交给客户端。

Subscriber 的效用函数为：

ΔP = W_d·max(0, 1 − min(D, D_max)/D_max) + W_a·max(0, cos θ)

其中 D 为相机位置到 Group 3D 质心的欧氏距离，θ 为相机前向视线向量与相机指向质心向量的夹角，D_max 为预期最大视距，W_d、W_a 分别为邻近性与中心凹对齐的权重。距离项做归一化线性衰减、视角项做余弦截断，两项均为非负贡献的加性模型，计算开销极低，适合高频更新。

### 3.3 Publisher 内容准备管线与复杂度

原型的内容分解管线（注意：原型只组织**单 Track**，覆盖全部内容）分四步：

1. **语义对象检测**：从 N 个视点渲染内容，对生成图像跑 2D 检测（论文正文记为 YOLOv26x，其引文标注指向 YOLO-World 开放词表检测器）。对每个检测框在对应 splats 上估计置信区域以鲁棒定位；检测框可选按预设 padding 因子外扩，保证对底层对象的保守空间覆盖。
2. **合并投票（Merge Voting）**：同一语义对象会被多个视点重复检测，通过对相关 splats 计算 3D Jaccard 指数（IoU）或度量质心邻近度，将重复观测合并为单一包围表示，确保跨视角（如同一辆自行车）归并为统一高斯表示。
3. **聚类**：多视点检测框投影回 splat 空间，对检测出的对象质心跑 DBSCAN，把空间邻近的 splats 归入同一 Group；一个簇可含多个空间相近的语义对象。
4. **渐进 Subgroup 构造**：实现独立几何启发式，以尺度与不透明度为代理度量做几何剪枝，步长 20%，构造 5 个渐进质量 Subgroup。

复杂度口径：多视点渲染 + 2D 检测为 O(N·T_YOLO)；检测框投影回 splat 空间与 DBSCAN 聚类对 M 个高斯质心为 O(M log M)；渐进分层的不透明度排序 O(M log M)。关键是该管线完全离线，作为静态 3DGS 点播场景的一次性内容摄取阶段，不引入流式期间的实时预处理时延。

### 3.4 传输栈工程：对 moq-lite 的 Subgroup 扩展

Publisher 为 Python 实现，经 ctypes 绑定对接 Rust 编写的 moq-lite（基于 QUIC/WebTransport 的 Pub/Sub 框架）。所用 moq-lite 版本原生只支持 Track/Group/Object 三级层次，作者扩展出显式 Subgroup 层，形成 Track→Group→Subgroup→Object 四级；每个 Subgroup 对应一条独立 QUIC 流并按质量档赋初始 Publisher 优先级。高斯属性以**原始 float32 数组**编码——因 3DGS 压缩编解码标准尚未定稿，这是当前的务实选择，也意味着传输体积上限完全取决于 splat 数量。manifest（Catalog）以 JSON 序列化为一条 MoQ Track 发布。Relay 采用 moq-lite 的 Rust 参考实现 moq-relay，内容无关、优先级感知地按层次转发，并向上游中继 SUBSCRIBE_UPDATE 等控制消息。作者提醒 MoQ 传输规范仍在演进（对齐 draft-ietf-moq-transport-18），后续可能需随 RFC 定稿调整。

### 3.5 Subscriber：状态机、控制环与水位内存换页

- **订阅层次与状态机**：连接建立后取回 Catalog 重建 Track/Group/Subgroup 层次；每个 Subgroup 维护轻量应用级状态机（MISSING / DOWNLOADING / CACHED）。传输丢失、丢弃或超时发生在 DOWNLOADING 态时，超时阈值后重新评估并回到 MISSING，经新 SUBSCRIBE 消息重订阅；同时渲染器优雅回退到已缓存的基级 S1 与低序增强层，避免视觉停顿或冻结。
- **视口驱动优先级环**：异步控制环（示例间隔 100 ms）每轮提取当前 6-DoF 位姿，对 Catalog 中全部 Group 计算 ΔP。若所需 Subgroup 处于 MISSING，发起新 SUBSCRIBE 并携带 ΔP；若已在 DOWNLOADING，则下发 **SUBSCRIBE_UPDATE** 在传输线上直接改流优先级而不断开连接——这是 MoQ 相对 HAS 换档（需重新请求分段时间）的核心时延优势。收到的 Object 解包追加进本地内存池，Subgroup 收齐后转 CACHED。
- **水位式内存换页**：两级存储（GPU VRAM / 系统 RAM）+ 水位策略。设定固定 GPU 预算 M_max 与高水位阈值（0.9×M_max）；活跃 splat 内存超阈值时，保护全部基级 Subgroup 不被逐出，增强层按当前 ΔP 排序，最低优先者从 VRAM 降级至系统 RAM（置 CACHED）；用户切换视口使某缓存对象 ΔP 上升时，再将其提升回 VRAM。此举在本地资源受限时避免冗余网络重传，同时维持渲染性能。设计层面还提出可扩展到 storage 的三级层次。

## 4. 实验结果

评估分两阶段，均以 Mip-NeRF360 的 Bicycle 场景为公共参照；Publisher 侧实验运行于 Ubuntu 22.04 集群（Intel Xeon Gold 5218 @ 2.30 GHz，双 NVIDIA Quadro GV100）。

**Publisher 侧内容准备（离线）**：质量指标用 VMAF，采集口径为对目标 3DGS 簇（Bench–Bicycle）做 ±90° 方位角平滑环绕、固定距离/仰角/相机内参，每序列 10 s @ 30 fps（300 帧），以未剪枝模型为参考评估各剪枝模型。结果要点：（1）Bench–Bicycle 对象能从完整 Bicycle 场景中被有效聚成语义连贯簇，验证 Group 策略；（2）不透明度剪枝与尺度剪枝随 splats 渐进到位均提升视觉质量，但在**同等渲染 splat 数量下，不透明度剪枝一致优于尺度剪枝**（VMAF 更高）；（3）每层等量（各 20%）splats 的感知贡献差异显著——先传哪些 splats 至关重要；（4）层累积组合使重建质量自 Q0 至 Q4 渐进提升，但不透明度剪枝下增益在 Q2 之后饱和，额外 splats 边际收益很小；论文补充这些 splats 在典型观看距离下作用有限，但在靠近长凳的近距离视点可能重新变得显著。

**端到端流式交付**（Bicycle 3DGS 内容、四档带宽约束、拥塞由 Relay 隐式处理，高优先 Subgroup 先行）：

| Link BW (Mbps) | Subgroups Delivered | Data Received (MB) | Splats Rendered (Final) |
|---|---|---|---|
| 10 | 397 | 37.4 | 224,710 |
| 30 | 2,432 | 337.8 | 1,400,909 |
| 50 | 2,628 | 363.2 | 1,491,950 |
| 100 | 2,853 | 390.6 | 1,512,214 |

10 Mbps 下收到 397 个 Subgroup（37.4 MB）、约 22.5 万 splats，得到粗但**持续可渲染**的场景表示；升到 30 Mbps 出现大幅跳变（Subgroup 数 397→2,432，splats 约 225K→1.4M）；30→50 Mbps 改善转温和（2,432→2,628，约 1.49M）；50→100 Mbps 带宽翻倍仅换来小幅增长（2,628→2,853，约 1.51M）。论文结论是优先级驱动的 Subgroup 交付在多样网络条件下维持了渐进场景精化。需注意该表为单一内容、单一会话条件的初步结果，论文未给出时延、卡顿率、交互响应等流式 QoE 指标。

## 5. 消融要点

论文未做系统性消融，但评估中内嵌了若干对照，且存在明确的未覆盖面：

- **剪枝度量对照（核心对照项）**：不透明度代理 vs 尺度代理构造渐进层，同等 splat 预算下前者 VMAF 一致更高，且质量在 Q2 后即近饱和——对工程直接的含义是：渐进分层的排序键应选不透明度而非尺度，且三层（BL+EL1+EL2，约 60% splats）即可逼近该簇的感知上限。
- **层边际贡献分析**：等量 20% 的各层感知贡献差异显著，佐证“传输顺序本身即是一种码率分配”。
- **带宽敏感性**：10→30 Mbps 收益陡增、30→50 转折、50→100 趋于饱和，说明该内容组织下有效增量子组的稀缺性随带宽升高而下降，但也可能受单会话、隐式拥塞处理与无压缩 float32 编码的口径影响。
- **未覆盖项**：ΔP 权重 W_d/W_a 的敏感性、语义 Group 与朴素空间划分的对照、依赖式属性拆分路径（仅设计未实现未评估）、多 Track 空间分解（原型仅单 Track）、与 LapisGS/LTS/L3GS 或 HTTP/3 基线的定量对比均缺失；主观质量实验亦未开展。

## 6. 贡献与启示

**主要贡献**：（1）据作者所知首个把 3DGS 内容映射到 MoQ 层次结构的框架，给出了 Track（空间）/Group（语义）/Subgroup（质量）/Object（splats 属性）的完整映射规范及 manifest 设计；（2）无状态、订阅者驱动的适配模型——Publisher 只暴露变体、Relay 零每客户端状态、Subscriber 全权决策，这一职责切分对多订阅分发与 CDN 边缘缓存是结构友好的；（3）可运行的原型（含对 moq-lite 的 Subgroup 层扩展），并以初步数据支撑“不透明度优先的渐进分层”这一可复用结论。

**工程启示**：其一，SUBSCRIBE_UPDATE 允许在不重建连接的前提下改写线级流优先级，把 2D ABR 的“换 representation”变成“改优先级”，时延与信令开销都更优，是 MoQ 生态对自适应流媒体范式的实质性修正；其二，每 Subgroup 一条 QUIC 流消除了连接级 HOL，且对象级粒度远细于 HAS 分段，为 6-DoF 视口自适应提供了正确的调度原子；其三，水位式 VRAM/RAM 换页配合 ΔP 复用本地缓存，把“网络层适配”与“本地资源适配”统一到同一优先级信号上。对音视频上下游而言：MoQ 正在成为低延迟交互视频的统一传输底座，MoQSplat 展示了同一条 Pub/Sub 管道可平移承载 3D 表征，未来 2D tile 视频与 3DGS/体积视频有望共享 Relay 缓存与调度基础设施。

**局限**（论文自陈+可观察）：面向静态点播场景，未涉动态 3DGS 的时间维度组织；原型只实现单 Track 与独立几何启发式；属性以 raw float32 传输，无压缩，带宽效率上限受限；评估为初步性质（单场景、无 QoE/时延指标、无系统基线对比）；MoQ 规范本身仍在演进，实现面临版本漂移风险。

## 7. 与其他论文的联系

- **paper:arxiv:2608.06102（MultiMoQ）**：同以 MoQ 为传输底座做分块自适应流媒体。MultiMoQ 面向 360° 视频直播，用多路径传输与灵活 tile 调度提升吞吐与播放连续性；MoQSplat 的 Subgroup 流在概念上正是 3D 版 tile，MultiMoQ 的多接入调度与路径聚合策略可直接嫁接到 MoQSplat 的 Subgroup 流上，弥补其当前单路径、拥塞仅由 Relay 隐式处理的弱网鲁棒性缺口。两者共同验证“MoQ 层次 + 优先级调度”范式对 2D/3D 沉浸式媒体的普适性。
- **paper:arxiv:2610.21121（ResStreamGS）**：同为 3DGS 流式传输框架，但面向移动端体积视频，按高斯时间特性做双流分流编码。MoQSplat 明确限定于静态 on-demand 场景，ResStreamGS 的时间敏感分流恰好补上时间维度：其按 splat 时间行为划分的流可自然映射为 MoQ 的按时间组织的 Group/Track 结构，是 MoQSplat 向动态场景扩展时的内容侧参考。
- **paper:arxiv:2609.33969（SAGA，稀疏 4D 锚点体积视频压缩）**：与 MoQSplat 正交互补——MoQSplat 因“3DGS 压缩编解码标准未定稿”而以 raw float32 编码 Object，传输效率受限；SAGA 类 4D 锚点 + INR 解码的压缩方案可作为 Object 级信源编码的直接替换，在不动 MoQ 传输与调度逻辑的前提下压低 Subgroup 体积（传输层 × 编码层解耦组合）。
- **paper:arxiv:2610.00195（GS-PQM）**：MoQSplat 的质量评估依赖渲染后图像域的 VMAF（需渲染序列且有参考）；GS-PQM 在高斯参数域直接评估压缩失真、免渲染视点且计算更高效。它可双向嵌入 MoQSplat：Publisher 侧以参数域失真指导渐进层排序（替代/增强不透明度代理），Subscriber 侧做轻量质量估计辅助 ΔP 决策。
- **paper:arxiv:2611.04498（3DGS-VBench+ / 3DGSV-Assessor）**：提供 3036 个 3DGS 视频、9108 个 MOS 的三维（整体/几何/颜色）主观基准与参考灵活（RR/NR）客观评估模型。MoQSplat 当前的 VMAF 口径无法区分几何失真与颜色失真，后续若评估渐进传输的感知质量，该基准与评估模型是更对齐 3DGS 失真特性的替代口径。
