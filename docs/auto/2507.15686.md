# LINR-PCGC: Lossless Implicit Neural Representations for Point Cloud Geometry Compression

> Wenjie Huang, Qi Yang, Shuting Xia, He Huang, Zhu Li, Yiling Xu. *arXiv:2507.15686v1 (2025-07-21)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

本文处理动态点云序列的几何无损压缩（Point Cloud sequence Geometry Lossless Compression, PCGLC），评测锚点是 MPEG WG7 标准生态（G-PCC / V-PCC）及其惯用的 10-bit 人体数据集，属体积视频、6DoF/自由视点与数字人内容管线上游的三维表示压缩环节，与视频编码在熵编码、码率控制与 GoP 组织等基础设施上深度同源。

三条路线的矛盾清晰。G-PCC 以八叉树递归细分直接编码 3D 占用，对稀疏点云（LiDAR 类）有效，但依赖手工工具与参数，几何空间相关性挖掘不充分；V-PCC 将点云切 patch 投影为 2D 图像后复用 HEVC 类视频编码器，适合稠密动态内容但不适配稀疏场景。AI 驱动方法（PCGCv2、SparsePCGC、Unicorn-Part I 等）以稀疏卷积从高维隐空间建模空间相关性，在特定数据集上达到 SOTA，但性能强绑定训练分布。论文给出一个尖锐实证：在 MVUB（平滑表面少、虚拟边缘多、坐标分布与训练集差异大）上，ShapeNet 预训练的 SparsePCGC 做几何无损时 bpp 相对 G-PCC v23 为 100.947%，即劣于传统基线——分布漂移直接吞掉全部学习增益。

INR 路线对目标样本过拟合、把网络参数写入码流，天然分布无关，且无需大规模带属性训练集。现有 INR 点云工作（如基于坐标网络的属性压缩 LVAC、统一 INR 框架、轻量超分网络等）均止步于有损，原因有二：其一，解码端网络必须进码流，故只能用极简网络、拟合能力弱，无损方向空白；其二，过拟合时间计入编码时间，直接过拟合一个 SparsePCGC 级网络近 9 小时、参数达数千万比特（作者训练日志口径），无法实用。LINR-PCGC 的目标即补上这一空白：GoP 级参数共享摊薄模型码率、跨 GoP 热启动压缩过拟合时间（摘要口径约减 60%，初始化策略单项消融为 65.3%），并以轻量多尺度 SparseConv 网络保证解码端小而快。

## 2. 方法总览

编码以 GoP 为单位（实验中每序列取前 96 帧、GoP=32，即 3 个 GoP），三步流水：

- **Initialize**：当前 GoP 网络用上一 GoP 过拟合后的权重初始化；首个 GoP 随机初始化（主实验口径）。
- **Encode**：对目标 GoP 各帧过拟合网络；完成后将网络拆分为 pc-encoder 与 pc-decoder，pc-encoder 对本 GoP 点云做占用概率估计与算术编码，pc-decoder 参数经 AQ 量化、MC 熵编码写入码流。
- **Decode**：Model Decompress 模块解出 pc-decoder 参数并加载，逐尺度重建点云。

最终码流由三部分构成：最低尺度点云字节流（已降至几十个点量级）、解码器参数码流、各尺度占用信息码流。一个关键声明：帧间只共享网络参数，不使用帧间预测与帧间特征，帧顺序对方法无影响——因此 GoP 内每帧可独立乃至并行优化，训练目标无需沿时间维求和。这使方法规避了动态序列编码中最重的 inter 预测复杂度，代价是时间冗余完全未开发（作者明确列为 future work）。

网络为多尺度结构：对点云反复 MaxPooling 降采样（尺度数由首帧降采样至点数 ≤64 确定），自低尺度向高尺度逐级预测占用。由于所有尺度共用同一套权重，用 SCE 注入尺度条件、用 CNP 完成“低→高”上采样（即子节点占用预测）；训练损失为各尺度各 stage 的二元交叉熵（log2 计，即码率估计）之和加 L2 正则。基线选择上，作者用 SparsePCGC 而非 SOTA 的 Unicorn-Part I，理由有二：后者参数量大、结构复杂，不利于轻量化探索；后者本身构建于 SparsePCGC，改进可回溯兼容。

## 3. 关键设计

### 3.1 GoP 参数共享与热启动初始化

模型码率摊销与编码加速是同一机制的两面：GoP 内 32 帧共享一套权重，使每帧分摊的模型码流降到可忽略（MVUB 上解码器参数仅占总 bpp 的 0.73%）；相邻 GoP 内容特性接近，用前一 GoP 权重初始化后一 GoP 显著缩短过拟合。补充实验显示逐 GoP 码流显著递减——同等优化时间下越靠后的 GoP 编码效率越高。首个 GoP 亦可用相似内容热启动（如以 basketball 初始化 dancer，"fur. ini."），这是内容库/序列簇场景下可用的工程选项。

### 3.2 Scale Context Extraction（SCE）

所有尺度共用权重，网络必须显式感知当前尺度。SCE 以尺度嵌入 SEMB(i)（把尺度索引 i 扩展为 8 通道隐式特征，CEMB=8）作全局信息，以每点“前/后/左/右/上/下/自身”7 邻域占用作局部信息，逐尺度经专属 MLP_i 融合出尺度上下文特征 l_t^{i+1} 供 CNP 使用（这些 per-scale MLP 随主网络一并过拟合并进码流）。这是典型的“主体容量跨尺度复用 + 极小条件嵌入”解耦：尺度特异性被压进嵌入与融合层，而非重复的骨干。

### 3.3 Child Node Prediction（CNP）

CNP 是相对 SparsePCGC 最大的结构改动。SparsePCGC 用 transpose 稀疏卷积上采样，需在更高分辨率上执行计算，显存与时间开销大。CNP 的改写是：高尺度点云可建立两层八叉树，它等价于一个“坐标与低尺度点云相同、特征为 8 通道子节点占用”的点云；于是上采样严格等价于在低尺度坐标锚点上预测每个父节点的 8 bit 子节点占用，全部稀疏卷积都在低尺度点数规模上执行。

预测按通道级 8-stage 串行展开（j=0…7）：GDFE 对 l^{i+1} 一次性提取全局特征 Gfeat；j≥1 时 LDFE_{j-1} 从已解码子节点的累积占用 x_cum^{j-1}（按 stage 通道拼接，增至 8 通道）提取局部特征；融合特征 F_merge = Gfeat + Lfeat^{j-1}（j=0 无局部上下文，直接用 Gfeat）经 SConv_j + MLP_j + Sigmoid 输出该 stage 占用概率 P_occ^{i,j}，用于算术编码，其交叉熵同时充当训练中的码率估计。GDFE/LDFE 为含残差连接的 3³ 稀疏卷积（通道 C→C、C→C/2）与 ReLU 堆叠；隐层取 Csconv=8、Cmlp=24。串行解码使已解码子节点成为未解码子节点的条件上下文，等价于把八叉树邻居上下文从手工查找表换成学习到的序贯条件模型。

### 3.4 Adaptive Quantization（AQ）与 Model Compression（MC）

AQ 对 pc-decoder 参数做 min-max 归一化后均匀量化到 B=8 bit。MC 的前提是一个训练侧设计：损失中的 L2 正则（λ=1e-4，即 Adam weight decay）把参数分布整形到接近 Laplace——论文对量化参数的统计给出示例（andrew：μ=142、b=4.24；longdress：μ=154、b=5.05），随后以 Laplace 为先验做算术编码，均值 μ 与尺度 b（平均绝对偏差）作为边信息写入码流。这组“正则→先验匹配→熵编码”链条是模型码率控制的机理核心：消融显示没有正则时 MC 几乎无效（见第 5 节）。码率量级：8bit 量化直存模型参数为 437,762 bits（约 54 KB/GoP，摊到 32 帧约 1.7 KB/帧），Laplace 算术编码进一步压至 240,353–251,360 bits（三数据集口径）。

### 3.5 损失函数

L = Σ_{i=0}^{N} Σ_{j=0}^{7} BCE(x_t^{i,j}, P_occ^{i,j}) + λ‖θ‖²，熵项以 log2 计并逐尺度逐 stage 求和，即以总码率为可微优化目标；因不使用帧间特征，无需沿帧维求和。λ‖θ‖² 名为正则、实为模型熵编码的分布整形项——训练目标直接为码流服务，该机制对一切“模型进码流”的 INR 编码器具有方法论意义。

## 4. 实验结果

配置：8iVFB（4 序列、30 fps、10 s）、Owlii（4 序列、30 fps、20 s）、MVUB（5 序列上半身），几何 bit-depth 均为 10，每序列取前 96 帧，GoP=32；基线为 G-PCC TMC13 v23、V-PCC v23、SparsePCGC（作者提供的 ShapeNet 预训练权重）；单卡 RTX 3090 + AMD EPYC 7502。指标为几何无损平均每点比特与平均每帧编/解码时间（秒）。"ours" 为快速档（首 GoP 6 epochs、后续 GoP 1 epoch，编码时间与基线可比），"ours2" 为收敛档（后续 GoP 6 epochs，正文口径约 10–20 s/帧）。

关键读数：

- **快速档**在三个数据集上 bpp 均优于两个基线，编码时间与 G-PCC/SparsePCGC 同量级；MVUB 上较 SparsePCGC 省 13.33%（0.806 vs 0.930），直接验证分布无关性主张——同口径下 SparsePCGC 反而劣于 G-PCC。
- **收敛档**较 SparsePCGC 分别省 9.70%（8iVFB）/11.40%（Owlii）/21.95%（MVUB），较 G-PCC 省 24.11%/28.40%/21.21%（摘要锚点：MVUB 收敛档较 G-PCC TMC13v23 省约 21.21%）。
- **解码 0.415–0.554 s/帧**，论文口径约为 G-PCC 或 SparsePCGC 的一半、V-PCC 的 1/4–1/6，对下游播放/渲染侧是实质优势，且解码器每 GoP 只需加载一次。
- **时间-码率连续可调**：固定后续 GoP 1 epoch、扫首 GoP 训练数 F∈{6,11,31,61}，r.t. bpp 从 82.925/78.759/87.548 降至 76.311/71.949/79.206（8iVFB/Owlii/MVUB），编码时间相应从 2.464/2.071/2.712 s 升至 15.092/12.958/16.967 s——epoch 数成为连续码率旋钮，是 INR 编码器区别于固定档位编码器的操作维度。
- **纯编码开销极小**：去掉过拟合的时间（w/o over.）仅 0.402–0.57 s/帧；快速档总时间中约八成耗在过拟合上（按 8iVFB 2.464 vs 0.477 推算）。若引入服务端预过拟合/热启动缓存，实际编码开销可逼近传统编码器。
- **码流与时间构成（MVUB）**：解码器参数占 bpp 的 0.73%、最低尺度点云 0.17%、scale 2–6 合计 5.83%、scale 1 18.10%、scale 0（最细尺度）75.17%——模型码流可忽略，码率集中于最细尺度占用；编码时间以分层重建为绝对主体（scale 0 占 45.56%），模型量化/熵编解码与 pclow 处理合计不足 10%。

## 5. 消融要点

- **初始化策略**（三数据集时间-bpp 曲线沿 bpp 轴积分取平均时间，相对“每 GoP 随机初始化”的比值）：首 GoP 随机、后续用前 GoP 初始化（ini.）平均时间为 34.7%，即省 65.3%（8iVFB 36.0 / Owlii 34.4 / MVUB 33.7）；首 GoP 用相似序列初始化（fur. ini.）为 24.0%，即省 76.0%（22.9 / 29.2 / 20.0）。内容库场景下后者的额外收益值得注意。
- **模块叠加**（三数据集平均、时间积分 bpp 相对“仅 CNP”的比值）：+AQ&MC 降至 91.9%（省 8.1%），再 +SCE 降至 88.8%（再省 3.1%）。
- **正则与 MC 的强耦合**：无正则时加 MC 仅省 0.826% 总码流；有正则时 MC 省 8.17%；正则自身仅省 0.092%。结论明确：L2 正则的价值不在自身省流，而在把量化参数分布拉到与熵编码先验匹配——模型熵编码必须与训练正则协同设计。
- **MC 方案对比**（每 GoP 模型参数码流，bits）：8bit 量化直存 437,762；LZ77 压至 250,825–269,554（三数据集平均 268,672）；Laplace 先验算术编码 240,353–251,360，稳定优于 LZ77。
- **CNP 对 8-stage SOPA**（同为 8 隐通道、同 INR 过拟合设置）：时间积分码流比为 0.9238（8iVFB/Owlii 一致），省约 7.62%；峰值显存指标平均由 11.92 降至 4.54（论文口径省约 61.91%），且 8-stage SOPA 在 MVUB 上直接超出 RTX 3090 显存无法运行；原始 SOPA（32 隐通道）过拟合近 9 小时、参数数千万比特，在线训练不可接受——这组数字是“INR 无损必须更换上采样结构”的直接论据。
- **逐点码率分析**：高码率点按 2³ 立方体周期性出现，原因是每个子节点组内先行解码的 stage（尤其 stage 0）缺少当前尺度先验——提示 stage 0 的上下文补强是下一档效率空间。

## 6. 贡献与启示

贡献层面：(1) 首个 INR 无损点云几何编码器，把 INR 压缩从“简单网络+有损”推进到“轻量网络+无损”，补齐 PCGLC 在 INR 谱系的空白；(2) GoP 参数共享 + 跨 GoP 热启动，同时解决模型码率摊销（解码器仅占 0.73% bpp）与编码加速（省 65.3%–76.0%）；(3) CNP 以两层八叉树等价改写替代 transpose 稀疏卷积上采样，同设置下省约 7.62% 码流与约 61.91% 峰值显存，使 INR 过拟合在消费级 GPU 上可行。

对音视频技术链的启示：其一，“计算换码率”的连续操作面（epoch 数/编码时间 vs bpp）不同于传统编码器的离散档位，对离线分发与内容库压缩（体积视频、点云资产、6DoF 内容）是新的率-复杂度权衡范式；其二，解码端轻量（约基线一半时延、每 GoP 数十 KB 模型摊到 32 帧）契合播放侧约束，GoP 共享解码器天然支持一次加载多帧复用；其三，“训练正则为模型熵编码整形分布”的机制可迁移到一切模型进码流的 INR 编解码器（视频 INR、神经场表示同理）；其四，方法刻意回避帧间预测（帧序无关），与视频编码的 inter 路线形成对照——时间冗余完全留给后续工作。

局限与口径提醒：收敛档编码时间 14.2–18.6 s/帧，仍为 G-PCC（2.24–3.95 s/帧）的约 4–7 倍，实时编码不可行；评测限于 10-bit 稠密人体序列，LiDAR 稀疏场景未验证；仅几何、无属性压缩。另外 MVUB 快速档相对 G-PCC 的增益（约 12.5%）明显小于 Owlii（约 21.2%），说明高虚拟边缘内容上最细尺度占用（占 75% bpp）仍是硬骨头。

## 7. 与其他论文的联系

- **paper:arxiv:2606.21655（PaaF）**：同为 INR 编码器的“模型量化+熵编码”问题。PaaF 以改进架构、自适应量化与熵编码缩窄 INR 图像编码器与传统编码器的差距；LINR-PCGC 的 AQ（min-max + 8bit 均匀量化）与 MC（Laplace 先验算术编码）与其同题，且额外证明参数分布整形（L2 正则）是熵增益的前提，两者可互为“模型码率控制”设计的参照。
- **paper:arxiv:2609.04273（S-NVRC）与 paper:arxiv:2606.28163（NVRC++）**：同属 INR 视频编码工程化路线。S-NVRC 用单一嵌入码流同时支持码率与解码复杂度细粒度扩展，NVRC++ 以 feature grid 把质量与复杂度解耦、单模型覆盖全码率区间；LINR-PCGC 的“epoch 数—bpp”曲线提供的是编码侧计算换码率的连续档位，与二者在码流结构内做可扩展互补，共同指向 INR 编码器“复杂度-码率联合可扩展”的命题。
- **paper:arxiv:2609.33969（SAGA）**：同为模型进码流的体积视频 INR 方案（4D 稀疏锚点 + INR 解码 + 记忆模块压缩动态 3DGS）。其记忆模块跨帧复用历史表示，与 LINR-PCGC 的“上一 GoP 权重初始化下一 GoP”同属跨时间单元复用模型状态以摊销模型成本、加速收敛的设计；差异在 SAGA 服务有损渲染质量、LINR-PCGC 服务几何无损码率。
- **paper:arxiv:2605.18006（Inter-LPCM）与 paper:arxiv:2607.03576（运动估计属性压缩）**：同属动态点云序列压缩，但均走帧间预测路线（前者为球面坐标下 LiDAR 帧间几何预测、对比 G-PCC PredGeom；后者为图上运动估计 + 分数体素细化，属性压缩较 G-PCC 平均省 55.3%）。LINR-PCGC 显式不使用帧间预测（帧序无关）、把时间冗余列为未来工作，这两篇正构成其 inter 扩展的直接参照——几何与属性两侧的帧间增益上限已有量化证据。
- **paper:arxiv:2604.08329（DiV-INR）**：INR 紧凑表示 + 扩散先验在 <0.05 bpp 极低码率区间的有损感知压缩，与本文无损几何压缩构成 INR“模型容量-码率-保真”谱系的两端：前者以生成先验换感知质量，后者以逐 stage 条件熵编码逼近无损熵下界，而模型参数码率控制（本文 MC 链路）是两端共享的基础设施问题。
