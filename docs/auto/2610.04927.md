# Assembling Insights for Agentic Machine Learning Engineering Systems

## 1. 背景与动机

论文研究对象是 agentic MLE（智能体化机器学习工程）：LLM 编码智能体端到端完成“数据集 + 建模目标 → 可执行 ML 解”的闭环，涵盖数据勘察、模型选型、验证协议设计、调试与算力分配。它与常规代码生成基准的本质差异在于 ML 解没有测试 oracle：质量是未知数据上的指标值，只能靠执行长耗时训练代码来估计、靠反复修订来提升。这决定了任务形态必然是“写—执行—改”循环加候选解搜索（AIDE 的解树、ML-Master 的 MCTS、LoongFlow/FM Agent 的种群演化）。该方向进展极快：论文引述 MLE-bench 上最优系统获牌率从 2024 年底的 17% 升至 2026 年初的 60% 以上。

近期系统普遍强调从相近 MLE 任务收集并注入洞见，分两条路线：外部知识（求解时 web 检索，如 MLE-STAR、MARS；或离线知识库 + RAG，如 DS-Agent、MLEvolve、AutoMLGen、KAPSO、AIBuildAI-2、FM Agent）与跨任务自我改进（从自身历史运行蒸馏记忆，如 Agent K 的经验记忆、ML-Master 2.0 的 prior wisdom）。作者指出两个结构性缺口：

- **注入过程 ad hoc**：每个系统绑定一种来源、一种表示、一种注入方式，消融只整体移除洞见源（删知识库或记忆缓存），只能证明“洞见整体有用”，无法回答哪类洞见贡献什么、应如何注入。
- **评测不控制洞见来源 → 数据泄漏威胁效度**：求解时 web 检索可直接检索到被评测比赛自身的获奖 writeup；按比赛名排除挡不住同系列后续届——论文给出的实锤是 AIMO Progress Prize 1/2：PP2 描述声明基于 PP1 构建，且其金牌 notebook 复用了 PP1 获胜方案的代码；若 PP1 为目标赛而仅按名排除，PP2 仍是泄题通道。这类公平性质疑已导致 MLE-bench 官方榜单暂停接收新提交。

工作定位由此明确：固定一个 agentic MLE 系统，在洞见来源受控的基准上，把“洞见类型 × 注入方式 × 后端 LLM”作为受控变量做因果研究，而非再提一个新 scaffold。

## 2. 方法总览

整体为“基准 + 装配智能体 + 受控注入评测”三件套。

**MLE-InsightBench 构建**：经 Meta Kaggle / Meta Kaggle Code 采集 2020 年及以后、使用 Python、数据可下载、且拥有“高性能自包含”人类解（金牌且只用比赛自身数据集）的 Kaggle 赛事，排除 playground；191 个中人工剔除 18 个不训练 ML 模型的（模拟与优化谜题类，如 Santa 系列），得 173 候选。域聚类用 harrier-oss-v1-27b 嵌入赛事描述（overview + 数据描述），UMMAP（cosine 距离、20 邻居、降至 11 维）后 HDBSCAN（最小簇 5、min samples 3），得 12 簇 + 7 离群点，簇标签结合成员赛事与 class-based TF-IDF 人工命名；离群的 WiDS Datathon 2022 手工归入含其往届的簇。再剔除整体无合格目标赛的 Audio Recognition 簇（8 个赛事）、4 个无金牌区 writeup 的赛事、数据集已下架的 Jane Street，最终 160 赛事 / 12 域。

**留出划分**：每域留出 1 个目标赛（共 12），其余 148 个为源赛。目标赛合格线为所采集解的平均运行时间 ≤ 全体解运行时间的 75 分位（25.5 分钟），另手工判定一批环境难复现者为不合格（AMP Parkinson's、Drawing with LLMs、Bengali.AI Speech、Cornell Birdcall、BirdCLEF 系列等）；在域内最近一年的合格赛中选解运行时间最短者为核心原则是**因果非后代**：任何源赛都不可能是目标赛的因果后代（不得为同系列后续届、不得复用其方案）。相比“每域取最新赛”的纯时序划分，该原则在排除泄漏的同时保留了更多可用源赛。

**泄漏控制三点**：装配阶段屏蔽目标赛全部材料；recurring 系列的早期届仍为合法源（与从业者实际可得信息一致，不算泄漏）；求解智能体无 web 检索工具、只见目标赛公开数据，私有测试集仅在终评时挂载换入、标签永不暴露。

**MLE-InsightForge 装配**：ReAct 智能体（后端 gpt-5.6-sol-pro），读 148 个源赛的描述、数据集、金牌方案 notebook 与 writeup，产出 12 条域洞见、148 条比赛洞见、16 条改进洞见，总 API 成本 903 美元（三类分别 565/22/317 美元，按 gpt-5.6-sol-pro 牌价）。

**注入与评测**：对某目标赛注入其所在域的域洞见 + 同域源赛的比赛洞见 + 全部改进洞见。基座系统为 ReAct 式解树智能体（失败可回退到早期候选分支，类 AIDE），预算为 12 小时 / 250 步 / 单张 RTX A6000，最终解在智能体环外用私有测试集重跑评分。主指标是各任务私有测试分数的 min-max 归一化均值：归一化区间取 Baseline、Full-skill、Full-playbook 三条件在各自任务上运行的最差/最好值，且**所有条件共用同一区间**（故消融条件可被归一化到 0 以下或 1 以上）。统计口径：每条件 72 次运行（12 任务 × 6 重复），均值 ± 95% t 区间，双侧 Mann–Whitney U（α=0.05），逐条件 12 任务做 Holm–Bonferroni 校正。

## 3. 关键设计

**洞见表示（trigger–action）**：比赛/域洞见由若干条目构成，每条含触发器（行动前可检查的任务/数据条件）、单一推荐动作、预期效果的理由。触发器用一般性任务与数据属性表述，使不适用条目可被直接跳过；冲突结论以互斥触发器并存。条目按 ML 解的五个方面（数据模态、数据、模型、训练、其他）分组，组内按**执行代价升序**排列——给智能体一个按预算贪心消费洞见的默认次序。改进洞见是单项：触发器为观察到的具体问题，动作为修复，并附局限、代价与“如何验证是否生效”。

**证据约束与反泄漏装配**：源材料只读挂载，工作区不含任何目标赛材料；web 访问经 1,985 条 URL 模式黑名单（从目标赛描述/writeup/notebook 抽取，Kaggle/GitHub 链接封禁至全站子页，库文档、Wikipedia 等通用资料手工豁免）。提交校验器强制“所有必读源已完整读过”否则打回重修，且每条洞见必须附 evidence record（列出所依据的原文段落），保证可回溯、抑制幻觉。

**三类洞见的装配逻辑**：
- *比赛洞见*：组织于“区分获胜方案的决策”及其成立条件，而非复现某个具体解——完整解绑定源赛的数据与指标，对其他任务不可迁移。notebook 与数据集用于消歧实现细节、核验 writeup 声称的技术确实存在。
- *域洞见*：读本域全部源赛的描述与比赛洞见，调和重复、互补、冲突的建议，把比赛特定处方改写为条件化指导（如把某验证策略关联到“分组主体/时序部署”条件而非普适规则）；仅由单一比赛支撑的建议被丢弃。
- *改进洞见*：先用 LLM 过滤 writeup（须同时报告具体问题与可行动解决，且结果被直接报告），逐条独立装配得 1,068 条原始改进洞见；再以与域聚类同款管线聚类（harrier-oss-v1-27b 嵌入 + UMAP 15 维/20 邻居 + HDBSCAN 最小簇 20、min samples 5；超参经网格搜索，判据为跨随机种子稳定、与数据模态和解阶段对齐、覆盖率高），得 15 簇加 4.9% 离群残差簇，逐簇合成共 16 条；manifest 记录簇成员与证据，保持端到端可追溯。

**注入模式**：skill 模式（Agent Skills 式渐进披露，初始上下文只放名称 + 简短描述，按需 read_skill 读全文）vs playbook 模式（ACE 式，全文直接渲染进系统提示）。域洞见因短且最相关，两种模式下都置于初始上下文。**可扩展性**：新赛事只需经描述嵌入归入最近簇即可复用该域洞见与全部改进洞见；赛后入源走增量更新——装配新比赛洞见、重综合该域域洞见、新原始改进洞见归入现有簇并仅重综合受影响的簇，只有大量新增才需重聚类。

**运行样例的机理**（Energy Behavior of Prosumers，时序预测域目标赛，MAE，经 time-series API 逐日供数，揭示目标与客户数据滞后预测时点两天）：同域 4 个源赛（COVID-19 病例、GoDaddy 微商业密度、零售销量等）无一涉及能源，但域洞见的三条触发条件在本任务成立——① 目标滞后与滚动基线锚定至少一个 horizon 之前；② 比率目标分母随时间变化时按预测期分母归一（对应随装机容量增长的生产量）；③ 外部特征按其发布 vintage 对齐（对应客户数据两天滞后）。无洞见解把滚动均值锚在预测前 2 小时、按当天拼接客户数据，训练侧留出验证无法察觉该错配（验证 MAE 29.24），预测时滚动均值与容量缺失填零，私有 MAE 飙至 234.15；有洞见解改为滞后 ≥48 小时、按单位装机容量学习生产率再回乘、客户数据按 as-of 两天前拼接，验证 MAE 31.91（更差但诚实反映部署分布），私有 MAE 57.12。六次重复口径：无洞见 228±76.8、有洞见 64.8±6.15，且有洞见的每一次运行都优于无洞见的最好运行。该样例浓缩了全文机理：洞见的最大作用点在“验证设计必须匹配部署契约”这类无法从训练数据内部发现的决策上。

## 5. 消融要点

**类型互补性**：单类型条件（+96.9%/+101.4%/+102.1%）均低于全量组合（+122.8%），显著任务数 9/8/8（校正后仅 2/4/0）vs 全量 11（校正后 10）。组合收益非加性但更稳：Full-playbook 在 7/12 任务上均值高于全部单类型，最优单类型随任务漂移（Ariel 2025 与 CSIRO Biomass 上改进洞见最优、PhysioNet 上比赛洞见最优）。互补性的直接证据是“独有正确预测”：在 5 个按条目判分的任务上（CAFA 5、Jigsaw、March Mania、NFL、RSNA，口径为至少 4/6 次运行判对），C/I/D 与 Baseline 分别有 12,345 / 4,566 / 1,238 / 1,184 条其他条件全错的条目；Full-skill 与 Full-playbook 亦分别独有 5,376 / 4,918 条（Baseline 3,838）——不同条件拿到的正确集合实质不同。过程曲线上，三种单类型开局领先幅度相近（首 100 分钟 3.0/2.2/3.1 点），之后比赛洞见甩开，终局领先 Baseline 6.1 点（改进洞见 4.4、域洞见 3.2），即**比赛洞见主要贡献后期精修**。另值得注意：单类型 playbook 条件的输出 token 反而升至 231.9–258.2K（全量仅 123–129K），说明信息不完整时智能体以更多自行推理填补。

**注入模式**：总分持平（0.676 vs 0.673），逐任务 6:6 互有胜负；POG 上 playbook 跌破 Baseline 而 skill 保持其上——playbook 保证可见但可能把系统带向不适配洞见，skill 依赖检索决策。成本差异明确：输入 token +7.7%（skill）vs +25.2%（playbook），因 playbook 全文随每次模型调用进入上下文；单任务成本仅 $1.7–2.0，多数输入命中 prompt 缓存。**关键反直觉发现**：deepseek 下 72 个 Full-skill run 仅 19 个调用过 read_skill（14 次读比赛洞见——典型是读最相似源赛如 Image Matching Challenge 2024 对应 Image Matching 2025，5 次读改进洞见），即 Full-skill 的增益几乎全部来自每次运行初始上下文中必然出现的**域洞见**（D-playbook 单独即 0.595）加 **skill 元数据描述**（描述写明各洞见何时适用），而非检索到的全文。换成 GPT-6.1-Sol 后主动检索恢复（12/12），Full-skill 在两个任务上都胜 playbook。工程结论：skill 模式在此设置下是“廉价正则化”，但其收益是否兑现取决于后端 LLM 的工具调用倾向，选模式前应先观测后端检索行为。

## 6. 贡献与启示

三点贡献：（1）受控洞见源基准——把“哪些材料可作为洞见之源”从系统自选变为基准属性（因果非后代划分），是首个显式治理求解时信息泄漏的 agentic MLE 评测环境；（2）证据约束的装配智能体（全文必读 + evidence record + URL 黑名单），使 LLM 装配的洞见可回溯；（3）类型 × 模式 × 后端的系统消融，把社区里“删掉知识库掉多少分”式的粗粒度证据推进为机理级结论。

方法论启示：其一，数据泄漏治理从“预训练污染”扩展到“求解时可得信息”层面，LiveCodeBench 的“只用训练截止后发布题”原则在此被翻译为“只用因果非后代赛”，对一切从公开社区材料取知识/取评测任务的智能体系统均适用。其二，min-max 归一化共用区间设计，使含消融条件的跨比较在同一标尺上成立。其三，成本经济学：装配 903 美元为一次性、按域摊销；运行期因缓存命中单任务仅 $1.7–2.0，“离线装配重、在线注入轻”是可行配方。局限（论文自述）：Kaggle 不覆盖生产 ML 的可维护性/监控/公平/隐私；域划分依赖聚类表示选择；洞见质量系于装配 LLM；后端 LLM 预训练可能见过目标赛公开解（对所有条件含 Baseline 同向膨胀绝对分）；装配侧只用一个后端未做敏感性分析；12 小时 GPU 预算抬高复现门槛。

**与音视频技术的上下游关联**：基准域构成本身即横跨 AV 相邻领域——Video Recognition（NFL Player Contact，MCC）、Medical Image Recognition（RSNA Aneurysm，AUC）、Physiological Signal Processing（PhysioNet ECG 数字化，SNR）、Scientific Signal Processing（Ariel，GLL）、Geography 的 Image Matching 2025（多视几何定位）。尤其值得注意的是 **Audio Recognition 簇因 8 个赛事全部不满足目标赛合格线（运行时长/环境可复现性）被整体剔除**——音视频任务在“可控运行时长 + 可复现执行环境”上的工程困难（数据集体积、GPU 时长、解码栈固定化）被这次剔除显式暴露，是音视频社区构建同类洞见基准前必须先解决的基建问题。方法迁移面：trigger–action 条件化洞见与“部署契约回测”（Prosumers 样例的 as-of 对齐、信息边界匹配）与音视频工程中“离线指标 vs 在线延迟/QoE 契约错配”问题同构，可直接平移到编解码参数搜索、流媒体 QoE 优化、实时推理管线的智能体化调优；从人类金牌 writeup 挖掘结构化经验的范式，对应到 AV 领域即挖掘 ffmpeg 邮件列表/Discourse/工程博客中的专家经验库，而 URL 黑名单 + 因果非后代式的泄漏控制同样约束任何基于公开赛事或论坛语料构建的 AV 智能体评测。

## 7. 与其他论文的联系

以下均为本文发表后同一“智能体递归自改进”脉络中的工作，与本文构成对照或互补（非互引关系）：

- **paper:arxiv:2611.13524（The RSI Tax）**：同为自我改进机制的“成本会计”。本文结论与之结构性互证：deepseek 后端下，初始上下文内的域洞见 + skill 元数据即可拿到全量组合的大部分收益（D-playbook 单独 0.595 vs 全量 0.673），Full-skill 以 +7.7% vs +25.2% 的输入 token 增量达成与 playbook 持平的分数——与 RSI Tax“简单有界笔记在精度持平下省 65.6–71.0% 总 token”的发现一致，即知识注入的边际收益递减，机制选择应按 token 成本而非仅看增益。
- **paper:arxiv:2611.11509（SimplEvo）**：洞见来源的对照极。SimplEvo 从自身 episode 自写文本记忆并精炼教训、免权重更新实现自改进（EBench 成功率 46.7%→81.7%），本文则从人类书写方案与 writeup 装配；本文相关工作一节明确将 Reflexion/ExpeL/AWM 式“自身轨迹记忆”与“人类制品装配”划为两类洞见来源，二者叠加可分离“经验来源”与“经验表示”两个变量。
- **paper:arxiv:2611.12109（SkillDuet）**：技能库演化机制对照。本文的 insights-as-skills 加增量更新（新赛入源后仅重综合受影响簇）是一种免参数更新的技能库维护策略；SkillDuet 用响应反馈让 LLM 参数与外部技能库协同演化，恰好补上本文“纯上下文侧”之外的参数侧闭环。
- **paper:arxiv:2611.08946（Flex-RSI）**：评测方法论同路人。Flex-RSI 以固定预算评估智能体在视觉与机器人任务上修订 harness 的自我改进能力，与本文“固定 12 小时/250 步预算 + 洞见源受控”分别治理自我改进评测效度的两大威胁——预算公平与信息泄漏。
- **paper:arxiv:2611.10463（LongCapHarness）**：同为“免后训练、靠上下文/挂接层获得能力增益且成本更低”的证据。本文以 7.7% 输入 token 开销换取 123.9% 归一分提升，LongCapHarness 在 HELMET/RULER 上以低于基线 50% 的成本超越基线，共同支持“上下文工程是权重更新之外的廉价杠杆”这一判断。
