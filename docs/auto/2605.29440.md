# SkillBrew: Multi-Objective Curation of Skill Banks for LLM Agents

## 1. 背景与动机

检索增强的 LLM agent 在长程开放任务上越来越依赖“技能库”：一组可检索、可复用的文本化程序性知识条目，用于指导重复出现的任务模式。该抽象已被 Anthropic 的 Agent Skills 规范标准化并被 Claude Code 等现代 agent harness 采纳，是跨 episode 积累程序性知识的主流载体。但技能库不是一次性蒸馏产物——同时做到有用、多样、覆盖广需要迭代精炼，而“如何把建库/改库/删库作为一个整体来优化”在此前基本未被审视。

作者将既有工作归纳为两类建库范式。其一是**蓄积式扩展**（accumulative skill expansion）：只增不删，如 Voyager 的自验证技能库、Trace2Skill 对轨迹局部教训的层级化整合、SkillRL 与 RL 策略更新耦合的失败驱动技能演化。其二是**局部技能级优化**（local skill-level optimization）：基于单一标量策展信号对每条技能独立裁决，如 ExpeL 基于投票的 ADD/EDIT 操作、EvoSkill 在 held-out accuracy 上的 top-k 前沿选择、Skill-Pro 的非参数打分门控。两类方法的共同缺陷是：策展准则坍缩为单一标量，库级属性（多样性、覆盖）的权衡在原则上不可解——扩覆盖必然引入冗余、降多样性；为保多样性而剪枝又必然损失长尾覆盖。

形式化地做全局库级策展面临三重耦合挑战：（i）质量多维且互斥，不可无损标量化；（ii）信用分配困难——单条技能的贡献只能通过昂贵的 rollout 观测，且被共同检索的其他技能混淆，难以把结果归因到具体条目；（iii）目标不可微、查询昂贵，且编辑空间开放（新技能由轨迹证据合成而非从固定池选取），排除梯度优化与穷举搜索。这三点解释了为何先前工作默认退化为“只增不删”或“单标量裁决”。论文据此提出第三范式——**全局库级优化**，将其形式化为效用约束下的 Pareto 多目标优化，用双层 propose-then-verify 循环求解，全程 training-free、worker 冻结。

## 2. 方法总览

**形式化**：技能空间 $\mathcal{S}$，技能库 $B \subseteq \mathcal{S}$，冻结 agent $\pi_{agent}$，检索器 $\text{RET}$ 对任务 $t$ 返回 $R_t \subseteq B$，agent 条件于 $R_t$ rollout 出轨迹 $\tau_t$。策展问题写成约束多目标优化：

$$B^\star \in \text{Pareto-argmax}_{B \in \mathcal{F}} \; (J_{util}(B), J_{div}(B), J_{cov}(B)), \quad \mathcal{F} = \{B \subseteq \mathcal{S} \mid J_{util}(B) \ge \eta\}$$

关键的不对称设计：**效用是硬约束**，多样性/覆盖是结构正则。理由是一个库必须先对 agent 有用，其组织性（多样性、鲁棒性、泛化）才谈得上——这与把三维目标加权合成一个标量的做法形成方法论对立。

**support/query 数据切分**是防过拟合的骨架：任务分布切分为 $D_{support}$ 与 $D_{query}$，前者仅供内环从轨迹证据提出候选编辑，后者专供外环做三目标评估与选择，避免库过拟合到“诱发其编辑的那批轨迹”。

**双层循环**：第 $i$ 轮，内环 $K^{(i)} = \text{Plan}(\text{Distill}, \text{Diagnose}; B^{(i)}, D_{support})$ 由当前库生成 $K$ 个候选库；外环 $B^{(i+1)} = \text{Select}(K^{(i)}; \eta, D_{query})$ 在查询集上做 Pareto 感知选择。冷启动阶段从无检索轨迹（成功+失败）经 Skill Distiller 蒸馏出初始库 $B^{(0)}$（沿用 ExpeL 式蒸馏思路：从失败模式结合成功轨迹合成 ADD 型技能）。三个 LLM 策展模块（Distiller / Diagnoser / Edit Planner）统一使用 GPT-5.4，agent worker 保持冻结，整个框架不含任何参数更新。

## 3. 关键设计

### 3.1 三目标的计算口径

- **效用（反事实信用分配）**：对检索到技能 $s$ 的轨迹 $\tau$，做 leave-one-out 重放（移除 $s$ 后同环境重跑），得 $\Delta(\tau, s) = r(\tau, s) - r(\tau, \setminus\{s\})$，$r \in [0,1]$ 为任务级奖励。技能效用 $J_{util}(s)$ 为其全部检索轨迹上的平均；库级效用按检索频次加权聚合：$J_{util}(B) = \sum_s w_s J_{util}(s)$，$w_s = |T_s|/N_R$（$N_R$ 为非空检索轨迹数）。这直接回应了“共同检索技能混淆信用分配”的挑战。
- **多样性（结构度量，无需 rollout）**：$J_{div}(B) = \det(G + \varepsilon I)^{1/|B|} \in (0,1]$，$G$ 为 L2 归一化技能嵌入的 Gram 矩阵。这是体积式（DPP 同族）度量，惩罚高相关技能。
- **覆盖（仅检索，无需 rollout）**：$J_{cov} = \text{density} \times \text{usage}$。density 为 $D_{query}$ 上平均检索槽位填充率（$\text{top-}k_{top}$ 槽位中实际填满的比例），usage 为至少被检索一次的技能占比。两项乘积同时惩罚“检索不到”与“库膨胀但休眠”。

### 3.2 内环：四象限证据划分 + 三算子候选生成

在 $D_{support}$ 上带检索 rollout，按（结果 × 是否检索）划分四象限：无检索失败 $T^-_{\bar R}$ 暴露库的能力缺口，交 Skill Distiller 聚类失败子模式、以无检索成功 $T^+_{\bar R}$ 为正参照，合成 ADD 候选（每个“真正不同的失败机制”产出一条技能，含有序子步骤与显式禁忌项）；有检索轨迹 $T^\pm_R$ 提供反事实证据，交 Skill Diagnoser——对每条被检索技能做 LOO 重放，将证据按 组分组，签发 KEEP / REWRITE / REMOVE 三种裁决。

Diagnoser 的裁决偏置值得注意：**REMOVE 的证据门槛显式高于 REWRITE**（管道内 REMOVE 不可逆，后续轮次无法自动恢复），证据不足默认 REWRITE；REWRITE 要求给出整段 principle 替换文本（非 patch），且 flaw 必须定位到具体句子序号或 when_to_apply 条件，不许笼统归咎于“principle 整体”。这把“库槽位稀缺、每条技能必须挣得自己的槽位”写进了裁决准则。

最后 Edit Planner 以全局视角（当前库 + 三个编辑池 + 全部裁决）将编辑组合为 $K$ 个候选库。它不是机械套用每个裁决，而是要求每个提案是一个可用一句话表述的“编辑哲学”，需满足一致性、Pareto 相关性（占据不同编辑方向）、grounded（只能引用三池内的编辑）、按子集组合区分；KEEP 技能作为受保护槽位不可被改写或删除。

### 3.3 外环：Pareto 感知选择与构造性保证

每个候选库（含 **null 候选**，即维持当前库不变，允许“本轮不编辑”）在 $D_{query}$ 上评估目标向量 $\Phi(B) = (J_{util}, J_{div}, J_{cov})$。选择分两步：先取非支配 Pareto 前沿；再以 $J_{util}$ 字典序优先——由于开放技能空间下先验阈值 $\eta$ 不可定，替换为**前沿自适应阈值** $u_{max} - \epsilon$（$\epsilon = 0.03$），并列集内以 散 hypervolume 贡献破平。由此得到构造性的**逐轮效用不退化保证**：$J_{util}(B^{(i+1)}) \ge J_{util}(B^{(i)}) - \epsilon$；null 候选获胜则原库带入下一轮；固定预算 $T = 10$ 轮终止。

### 3.4 工程实现要点

- 技能为结构化三元组：title / principle / when_to_apply；检索 top-3，混合打分 $0.30 \cdot \text{BM25}$（min-max 归一）$+ 0.70 \cdot$ dense cosine（text-embedding-3-small），综合分低于 0.30 直接丢弃。
- **内容寻址反事实重放缓存**：LOO 重放在两处都要用（support 上 Diagnoser 裁决、query 上候选库 $J_{util}$ 估计）。缓存键为 SHA-256(task id + 按检索序排列的被检索技能规范化内容)，并携带 worker 配置版本标签（模型或 prompt 模板一变即整批失效，防止陈旧 rollout 污染信号）。同轮 $K$ 个候选库仅差少量编辑、获胜库又延续到下轮，故第 2 轮起命中率 **>60%**。
- 数据口径：ALFWorld 从官方 train 抽 200 条作 $D_{support}$（seed 42），full valid_seen 作 $D_{query}$，full valid_unseen 作测试；WebShop 标准 test 500 条，另从 training/evaluation 池（goal id ≥ 500）抽 500 / 250 条作支持/查询集，三者两两不相交（seed 42）。worker 为 ReAct 式：ALFWorld 每集 50 步、条件于全历史；WebShop 每集 15 步、仅条件于最近一步；单步生成上限 2048 token。全部实验单节点 8×A800。

## 4. 实验结果

基线共十个、三家族，统一冻结 Qwen2.5-7B-Instruct worker；作者明确不与 SkillRL 等训练式方法比较（其联合更新 worker 与库，改变了底层 agent，对闭源 worker 不适用）。

**主结果**（关键行，ALFWorld 为六类任务平均 Success%，WebShop 报 Score / Succ.）：

| 方法 | ALFWorld Avg. | WebShop Score | WebShop Succ. |
|---|---|---|---|
| ReAct | 31.2 | 46.2 | 19.5 |
| Reflexion（最强记忆类） | 42.7 | 58.1 | 28.8 |
| Voyager（append-only） | 47.0 | 50.0 | 26.4 |
| ExpeL | 46.3 | 30.9 | 11.2 |
| Skill-Pro（最强技能类） | 49.3 | 38.7 | 23.2 |
| **SkillBrew** | **59.0** | **59.3** | **38.4** |

SkillBrew 对最强技能类基线 Skill-Pro 提升 9.7 个百分点，对 append-only 的 Voyager 提升 12.0，对 ReAct 提升 27.8；相对 ReAct 六类任务全升，最大增益在 Heat（13.2→60.9，+47.7）与 Cool（18.2→57.1，+38.9）。其余记忆类基线明显更弱（Mem0 33.6 / MemP 41.4 / SimpleMem 29.7 / EvoSkill 37.3）。WebShop 双指标第一，且 Succ.（全属性精确匹配率）大幅领先——作者解读为策展出的技能带来的是精确购买而非赚取部分奖励的近似匹配。

**跨 worker 泛化**（五个 worker，含三个开源 Qwen 与 GPT-4o、Gemini-2.5-Pro）：

| Worker | ReAct→SkillBrew（ALFWorld Avg.） | ReAct→SkillBrew（WebShop Succ.） |
|---|---|---|
| Qwen2.5-7B-Instruct | 31.2→59.0 | 19.5→38.4 |
| Qwen3-4B-Instruct-2507 | 38.8→60.4 | 16.8→36.6 |
| Qwen3-30B-A3B-Instruct-2507 | 55.2→75.4 | 14.0→56.2 |
| GPT-4o | 46.4→88.1 | 27.2→65.0 |
| Gemini-2.5-Pro | 61.8→89.6 | 38.1→72.0 |

每个 backbone 上都超过 ReAct，ALFWorld 增益从 +20.2（Qwen3-30B-A3B）到 +41.7（GPT-4o）；闭源 worker 增益最大（GPT-4o WebShop Succ. +37.8）。值得注意的是 Qwen3-4B 策展后达 60.4，接近未策展 Gemini-2.5-Pro 的 61.8——**良好策展的技能库可部分补偿模型规模**。

**策展循环动力学**：库规模从冷启动的较大值收缩到紧凑库并在 9–10 轮内稳定（不无界增长，收敛跨所有 worker）；测试成功率全程上升（轮间小幅波动）；第 1 轮（仅冷启动蒸馏输出）即已显著高于各 worker 的 ReAct 基线，说明冷启动是强起点，后续循环进一步改进。

## 5. 消融要点

**库跨 worker 迁移**（ALFWorld Avg. SR%，三源 × 三推理 worker）：

| bank 源 \ 推理 worker | Qwen3-4B | Qwen3-30B-A3B | GPT-4o |
|---|---|---|---|
| 无库 | 38.8 | 55.2 | 46.4 |
| Qwen3-4B 策展 | 60.4 | 71.6 | 78.4 |
| Qwen3-30B-A3B 策展 | 52.2 | 75.4 | 82.8 |
| GPT-4o 策展 | 53.7 | 73.9 | 88.1 |

对角线（自库）总是该 worker 最优（60.4 / 75.4 / 88.1），说明策展向源 worker 特化；但离对角损失很小：最小 worker 策展的库把 GPT-4o 从 46.4 提到 78.4（仅比自库低 9.7），GPT-4o 策展的库把 Qwen3-4B 从 38.8 提到 53.7（仅低 6.7）。结论：策展出的技能编码的是**可迁移的程序性知识**，而非特定 worker 的伪影，库可双向复用。

**目标消融**（策展管道不变，仅改 Pareto 选择器输入）：

| 目标组合 | ALFWorld Avg. | WebShop Score | WebShop Succ. |
|---|---|---|---|
| $J_{util}$ 单目标 | 45.8 | 48.2 | 28.4 |
| $J_{util}+J_{div}$ | 51.4 | 47.6 | 36.5 |
| $J_{util}+J_{cov}$ | 52.6 | 51.0 | 37.6 |
| 三目标全开 | 59.0 | 59.3 | 38.4 |

仅用效用比全目标分别低 13.2 / 10.0 个百分点；两正则互补——多样性防冗余，覆盖惩罚休眠膨胀技能。

**编辑算子消融**：ADD-only 47.0 / 26.4（库单调增长，休眠或有害技能挤占检索槽）；ADD+REWRITE 53.5 / 37.6；ADD+REMOVE 48.3 / 34.5；三算子全开 59.0 / 38.4。ADD+REMOVE 逊于 ADD+REWRITE 的原因被归结为操作过粗：被标记技能必须整体丢弃，包括部分正确、可经小幅改写挽救的策略。机制解读：**REWRITE 是默认救援路径**（Diagnoser 标记的多数技能可修补），**REMOVE 保留给核心前提错误、任何编辑都无法修复的少数**。

## 6. 贡献与启示

**贡献**：（i）范式级——提出技能库策展的第三范式“全局库级优化”，与 append-only 和单标量技能级裁决形成清晰对照；（ii）形式化——效用为约束、多样性/覆盖为正则的约束多目标 Pareto 优化，明确三原则的不对称性；（iii）机制——LOO 反事实信用分配、四象限轨迹证据划分（无检索失败→能力缺口→ADD；有检索轨迹→反事实证据→KEEP/REWRITE/REMOVE）、null 候选与前沿自适应阈值 $\epsilon$-容差选择、构造性逐轮效用不退化保证；（iv）实证——两个公开基准上大幅超越十个 training-free 基线，且库可跨 worker 迁移、可部分补偿模型规模。

**工程含义**：检索槽稀缺经济学（“每条技能必须挣得自己的槽位”）与 REMOVE 不可逆性对应的保守裁决偏置，是任何外挂知识库系统可直接借鉴的策略；内容寻址 + 版本失效标签的 rollout 缓存（第 2 轮起 >60% 命中）是 rollout 驱动自改进系统的通用降本模式。作者自述局限：worker 冻结、agent-库协同适应未探索；反事实 rollout 在更大规模仍昂贵；假设任务分布相对静态，开放世界持续漂移场景未覆盖。

**与音视频技术上下游的关联（引擎补注，非论文内容）**：本文评测环境为纯文本（ALFWorld / WebShop），无任何多模态或音视频任务验证，这是 AV 方向读者需知的前提。但其框架对 AV 链路上的 agent 化系统是直接可迁移的外挂知识管理层：转码参数决策、流媒体 QoE 调优、视频剪辑 pipeline 编排、内容审核 agent 等长程决策场景，同样面临“经验条目只增不删、检索槽被冗余条目挤占”的问题。方法论上，utility/diversity/coverage 的约束式 Pareto 建模与音视频编码中 rate-distortion-complexity 的多目标权衡同构；LOO 反事实评估等价于逐组件在线消融。迁移的主要障碍在成本侧——音视频环境单次 rollout（渲染/转码/推流验证）远贵于文本环境，本文的缓存设计与“多样性/覆盖免 rollout 的代理度量”正是针对该瓶颈的可借鉴方案；此外技能嵌入对程序化 pipeline 型技能的表示（本文用通用文本嵌入）在 AV 工具链场景需要重新审视。

## 7. 与其他论文的联系

- **SkillDuet（arXiv:2611.12109）**：SkillBrew 在 Limitations 中明确把“worker 与演化中技能库的联合协同适应”留作 future work；SkillDuet 恰以响应反馈驱动 LLM 参数更新与外部技能库协同演化，实现技能级递归自改进。两者在同一“技能库演化”轴上互补：SkillBrew 给出库级多目标策展准则与反事实 LOO 证据（可视为 SkillDuet 响应反馈的结构化替代），SkillDuet 打开 SkillBrew 关闭的参数侧耦合。
- **FGSE / When Should Agents Remember?（arXiv:2611.14326）**：同属“经验写入 agent 记忆前的门控验证”主题。FGSE 把教训作为可证伪假设、经三类探针验证后写入（条目级）；SkillBrew 用 LOO 反事实重放产生 KEEP/REWRITE/REMOVE 证据并在库级用 Pareto 选择把关。两者的 REMOVE 不可逆性与 FGSE 的更新安全关切指向同一问题：自改进系统的写入门控粒度与证据标准。
- **TRUST（arXiv:2611.10787）**：同属自改进安全性保证。SkillBrew 只提供构造性的逐轮效用不退化（≥ −ε），且仅覆盖 utility 单目标、依赖 rollout 点估计；TRUST 用在线多重假设检验控制错误进化率并提供统计保证——若 SkillBrew 的三目标评估引入 rollout 采样涨落，TRUST 式检验可作为其选择层的形式化加固。
- **LongCapHarness（arXiv:2611.10463）**：同为免训练、外挂式增强冻结 LLM 能力的路线（技能库策展 vs 能力引导挂接），且都显式关注成本（LongCapHarness 成本低于基线 50%；SkillBrew 靠 >60% 缓存命中率压制反事实 rollout 开销），代表“不动参数、动外挂”这一谱系下的两种互补实例化。
