## 1. 背景与动机

商用大模型（GPT-4o、Gemini 等）以 API 交付，权重、结构乃至输出 logits 均不可访问，任何需要触碰参数的领域适配路线（微调、RLHF 到 logits）直接失效；而推理、长程规划、个性化恰是黑盒模型相对薄弱且最依赖任务校准的高阶能力。论文把既有黑盒增强方法归为两类并指出各自结构性缺陷：(1) ICL 类——精心构造的指令或少样本示范，依赖人工 prompt 工程，提示刚性静态、不可学习；(2) Adapter / best-of-N 类（Bbox-Adapter、MedAdapter、HYDRA 等）——利用黑盒生成随机性采 N 个候选再用轻量适配器挑最优，性能天花板被黑盒自身合成能力锁死，存在“差中选差”风险。两类方法共同短板是缺乏环境交互能力，在多步推理、长程规划这类 long-horizon 任务上系统性失效。

M-Pilot 的切入点：既不碰黑盒参数，也不在候选集里做选择，而是训练一个轻量白盒控制器（LLaMA-3-8B-Instruct，LoRA 微调）主动“驾驶”黑盒生成器——将复杂任务外化为中间引导（子问题分解 / 高层计划 / 用户历史摘要），以 prompt 注入黑盒，再以黑盒输出的最终正确性为奖励对控制器做迭代偏好优化。概念上相当于把 o1-preview 的 scratchpad 从模型内部剥离出来，变成一个独立、可训练、可迁移的模块。三点自我声明的贡献：i) 首批用白盒 LLM 驱动大规模黑盒 LLM 的模块化框架之一；ii) controller-generator + 环境反馈的 MDP 化表述，支撑长程可控多轮生成；iii) on-policy 迭代数据自举加参考策略滚动，实现中间引导的内在自我改进。

## 2. 方法总览

**形式化。** 给定任务描述集 $\{x_i\}_{i=1}^N$，将黑盒原始输出与目标解视为联合空间 $\mathcal{Y}_{org}\times\mathcal{Y}_{sol}$ 中的分布对，目标是在不可访问参数的前提下把 $\hat y$ 拉向隐含解 $y$。白盒控制器 $\theta$ 生成 $T$ 步中间引导 $\{g_t\}\sim f_\theta(x)$，黑盒生成 $\hat y\sim g_{\mathrm{LLM}}(x,\{g_t\})$，轨迹 $\tau=(x,\{g_t\},\hat y)$，自回归分解为 $p(\tau|x)=\prod_t p(g_t|x,g_{<t})\cdot p(\hat y|x,\{g_t\})$（式 2）。优化目标是带间隔项 $\zeta\ge 0$ 的轨迹级对比目标 $\max\ \mathbb{E}[\log p(\tau^+|x)-\log p(\tau^-|x)-\zeta]$（式 3）；奖励 $u(\tau)=\mathrm{eval}(\hat y,y)$：QA 任务为指示函数 $\mathbb{1}(\hat y=y)$，规划任务为执行成功指示函数。

**MDP 化与双层循环。** 黑盒 LLM 被建模为环境：动作 $a_t$ = 控制器输出的引导 prompt；环境先执行内环多轮交互（黑盒依据引导迭代调整执行步骤并返回观测 $o_t$），问题未解则控制器发起外环交互、依据反馈修正指令，状态更新 $s_t=(s_{t-1},a_t,o_t)$。关键工程含义：梯度无法穿过黑盒，但 outcome 反馈足以支撑策略优化。

**训练管线三段。**
1. **SFT 热身（行为克隆）**：用更强模型在小样本上生成期望引导做监督微调——ALFWorld 上让 GPT 闭环跑 400 个训练样本、取 277 个成功轨迹抽取规划部分；GSM8K 上采样 216 个代码解抽取规划部分。若初始控制器足够强可跳过。
2. **交互式数据采集**：控制器与黑盒环境做至多 $T$ 步多轮交互（负观测时下一步动作基于反馈修正引导），注入随机性重复 $K$ 次，得到 $K\times T$ 条轨迹及 0/1 观测，从中取 $\tau^+\sim\{\tau:o=1\}$、$\tau^-\sim\{\tau:o=0\}$。这直接化解两大难点：中间引导无 ground-truth 可监督；何种引导能可靠提升下游性能不可先验判定。
3. **迭代 DPO（IDPO）**：第 $m$ 轮以 $\theta^{(m)}$ 生成新轨迹，按 STaR 式自举 $D^{(m)}_+=\{\tau^{(m)}:o=1\}\cup D^{(m-1)}_+$（负例同理，式 8）；同 prompt 的正负引导构成偏好对，Bradley-Terry 建模序列级偏好；由 KL 正则规划的闭式解 $\pi^*\propto\pi_{\mathrm{ref}}\exp(\eta u)$，参考策略取上一轮模型 $\pi_{\mathrm{ref}}=\pi^{(m)}_\theta$，得到式 10/12 的 IDPO 损失。参考策略滚动 + 数据池跨轮累积即其“自我改进”机制：控制器逐步逼近“黑盒执行器所理解的 good guidance”，弥合控制器与生成器之间关于好引导的语义鸿沟。

## 3. 关键设计

**3.1 不可学习项的消去——可以对黑盒做偏好优化的枢纽。** 将式 2 代入式 10 后，似然比 $\pi^{(m+1)}/\pi^{(m)}$ 中 $p(\hat y|x,\{g_t\})$ 一项与 $\theta$ 无关（论文在式 7 中显式标注为 Non-learnable），在正负轨迹中同样地消去，最终损失（式 12）只含控制器对引导序列的对数似然比。工程含义深刻：梯度完全不必穿过不可微的黑盒环境，环境退化为偏好对构造的标注预言机，问题从 RL 梯度估计降维为离线偏好学习；这也解释了为何框架对具体损失不敏感（见 ISimPo 消融）。附带一提，式 3 中的间隔 $\zeta$ 只出现在动机性目标里，最终 IDPO 损失以 $\eta^{-1}$ 缩放、未含 $\zeta$。

**3.2 同一框架三种引导实例。** 推理（GSM8K）：控制器把问题分解为子问题串，黑盒按 PAL 范式将子问题转成可执行代码，控制器只做高层规划不碰底层执行——这是“GSM8K 上训练、GSM-Hard 上评测”跨数据集迁移的依据。规划（ALFWorld）：高层计划 = General Plan + [Step xx] 步骤清单，黑盒基于计划生成代码式解（内嵌 assert 自检与 agent API 调用）。个性化（LaMP）：控制器对 BM25 检索的用户历史做摘要（最常写类别 top-n / 标题模板 1–4 / 正负评论最常见评分等），摘要与输入拼接交给黑盒。

**3.3 防过拟合与奖励黑客的措施（最值得移植的实现细节）。** 交互阶段对全部训练集只过一遍；每个数据点以温度 1.0 做 10 次交互采样、至多抽 2 个对比对（LaMP-1/2M/2N/3/4 对比对总量分别为 5410/2850/2548/4320/12518）；DPO 训练加 label smoothing 0.1。正负判定：分类任务 = 最终答案与真值精确匹配；生成任务（LaMP-4）无二值真值，按指标分数排序取 top 为正、bottom 为负。

**3.4 训练与推理配置。** 控制器 LLaMA-3-8B-Instruct + LoRA(r=8, α=16, dropout=0.05)；LaMP 侧 lr 1e-5、2 epochs、max len 8192、bf16、seed 42；ALFWorld SFT lr 2e-5、batch 64、3 epochs。ALFWorld 数据流：8810 训练样本 × 8 次执行 → 4844 正负对（第 1 轮 DPO）→ 用 DPO 后模型重采得 1586 对、累计 6430 对（第 2 轮）；重采对数下降本身即正例率上升的旁证。推理为闭环协议：黑盒对错误反思至多 6 次，仍失败则控制器重新分解一次、再给 6 次反思；ALFWorld 以 50 步动作未完成任务为失败判据。检索条数 k：LaMP-1 全量、2N 120、2M 150、3 为 30、4 为 50。

## 5. 消融要点

- **IDPO 是主要增益源且随轮数单调上升**：ALFWorld 全量 96.27 → 去第 2 轮（SFT+1 轮 DPO）94.78 → 仅 SFT 88.06 → 未调优 LLaMA 81.34；LaMP-4 BLEU 4.298 → 1.341（w/o IDPO，几乎跌回裸 gpt-4o-mini 的 0.992 水平）；GSM8K 0.931 → 0.896。

- **样本效率**：仅 25% 训练数据即达 94.78，超 AdaPlanner 6.7 点，显著降低对专家轨迹的依赖。
- **内环轮次可剥离**：DPO 后开环推理（inner loop M=1）即超 95%，8 轮闭环 97%——训练后的引导质量足以单次驱动执行器，闭环反思沦为保险机制而非必需。

## 6. 贡献与启示

方法层面，本文最硬的一步是把“对不可微黑盒做策略优化”化为“环境只当标注预言机的离线偏好学习”：利用轨迹分解中 $\hat y$ 项与 $\theta$ 无关而在偏好似然比中消去，梯度封闭在白盒控制器内部。其次是把中间引导从人工 prompt 工程对象变成可训练的策略输出，并用参考策略滚动 + 数据自举构成自改进闭环。局限亦应如实记录：所有任务为纯文本，无多模态验证；正负信号依赖可自动化的 eval()，论文以单遍数据、每点 ≤2 对、label smoothing 等启发式手段压 reward hacking，无理论保证；作者自述风险——白盒控制器可被用于操纵黑盒模型越狱/产出有害内容，个性化场景存在用户历史隐私泄露面。

**音视频上下游关联（本引擎视角）**：
1. **架构同构**：controller-generator 解耦 = 本地小模型策略层 + 商用黑盒生成引擎。A/V 生产中大量能力以黑盒 API 存在（视频生成、大型多模态理解服务），M-Pilot 给出的范式是：本地 8B 控制器负责任务分解（分镜/剪辑步骤清单）、风格与用户画像摘要、prompt 优化，全部训练信号来自可执行反馈——eval() 可直接替换为 A/V 客观指标（渲染/合成成功率、VMAF、ASR-WER、字幕对齐分），偏好对构造协议（式 8、排序取 top/bottom）原样可用。
2. **成本结论直接可用**：−30%（ALFWorld）/−65%（vs self-consistency）API 开销伴随性能不降反升，对推理调用密集的批量内容流水线（生成、审核、打标）是直接 OPEX 信号；且一次性数据采集 + LoRA 训练成本（百美元级 + 个位数 GPU 时）远低于微调或包时部署。
3. **个性化任务同构**：LaMP-4 新闻标题生成与视频标题/标签/封面文案生成结构一致；其 profile 数量鲁棒性结论（2M 上 PAG 恶化而 M-Pilot 稳定）对长历史行为流场景是关键选型依据。
4. **长程规划协议可迁移**：外环重分解 + 内环 6 次反思 + 50 步失败判据的双层闭环，是多步剪辑/渲染 agent 的现成调度模板；开环 M=1 即 >95% 意味着训好后可去掉在线反思、满足实时性约束。
5. **边界**：A/V 侧 eval() 的可靠性与开销是落地瓶颈（视频质量自动评估远比答案匹配噪声大），需先解决评估器才能复用其偏好对构造；内容安全上需对控制器输出加独立护栏。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326（FGSE，证伪门控的自我演化记忆）**：M-Pilot 的 IDPO 同样以 outcome 验证门控参数更新——只有 eval() 判定过的轨迹才进入偏好对；但其“经验”以参数更新形式一次性固化、以单遍数据等启发式手段防退化。FGSE 将同类已验证经验外化为可证伪假设、经三类探针再写入智能体记忆，可视为对 M-Pilot 这类“验证即写入”更新方式在记忆层面安全性的补强。
- **paper:arxiv:2611.12109（SkillDuet，模型与技能库经响应反馈协同演化）**：两者共享“环境/响应反馈驱动递归改进”的骨架，但演化对象不同——M-Pilot 冻结黑盒、只滚动更新控制器参数与参考策略，粒度是轨迹级偏好对；SkillDuet 同时演化模型参数与外部技能库，粒度是技能级。M-Pilot 的式 12 消去不可学习项的推导，对 SkillDuet 类含外部组件的环路如何切割可训/不可训部分有直接参考价值。
- **paper:arxiv:2611.10787（TRUST，带统计保证的可信递归自我改进）**：M-Pilot 的“迭代参考策略滚动 + 数据自举”本质上是一条无统计控制的递归自改进回路，其防退化手段（单遍交互、每点 ≤2 对、label smoothing）全为启发式；TRUST 用在线多重假设检验控制错误进化率并提供统计保证，恰是 M-Pilot 这类迭代 DPO 回路在部署安全上缺失的控制层，二者构成方法论上的先后互补。
