## 1. 背景与动机

目标场景是“像刷 2D 视频一样刷体积视频”：自由视点、可流式、跨设备实时渲染、即时分享。论文对既有路线为何不成立做了逐层排除：动态网格+纹理可流式，但在遮挡、弱纹理、头发等区域精度受限；动态 NeRF 系（形变场、时空网络、显式体素、多平面分解等）质量尚可，但普遍不支持长序列与流式，逐帧流式辐射场方案计算开销在移动端不可行；VideoRF 首次实现移动端动态辐射场流式渲染，但体素表征导致细纹理区模糊。动态 3DGS 系质量与训练速度兼备，但逐帧存储使其无法承载长序列；可驱动人体高斯方案计算过重，仍不适配移动端；Web 端 3DGS 光栅化实现与静态场景属性压缩已有生态，但在动态流式场景下算力与存储双不足。由此论文归纳出两个硬需求：高效的训练过程产出紧凑高斯表征；产出资产必须兼容移动端硬件视频编解码与 shader 渲染。

从音视频技术视角看，核心矛盾可以一句话概括：动态 3DGS 逐帧独立存储时帧间冗余完全未被利用，而视频编码生态（硬编硬解、CDN 分发、码率控制）最擅长的恰是吃帧间冗余——缺的是把高斯属性组织成视频信号、并让训练过程主动生产低熵残差的那座桥。V³ 的答卷：将动态高斯序列形式化为“2D Gaussian Video”（原文亦称 2D Gridded Gaussians），逐属性维度烘焙为 2D 视频像素，直接接入 H.264 硬件编解码；配合运动/外观解耦的两阶段训练压低帧间残差熵与时间不一致；再以多平台播放器（免 CUDA、Metal shader 渲染）完成闭环。论文自称是首个在移动端流式传输动态高斯的方法。

上下游定位：上游是密集多目采集（自采数据为 81 视角、3840×2160@30fps）与 NeuS2 关键帧重建；中游是一套“训练式预测 + 标准视频编码器”的混合编码方案；下游是常规网络流 + 硬件解码 + 着色器渲染。对 AV 研究者而言，其价值不在重建质量本身，而在表征与编码器的协同设计范式——与 V-PCC 把点云拆成几何/纹理视频再走标准编码器的思路同构（此为本笔记归纳，原文未提及）。

## 2. 方法总览

**表征**：t 时刻高斯属性记为旋转 R_t、尺度 S_t、位置 x_t、不透明度 o_t、颜色 c_t、球谐 SH_t，总维数 N = d(R)+d(S)+d(x)+d(o)+d(c)+d(SH)，N 即视频路数——每一路属性维度对应一路 2D 视频 {V_i}，帧 I_i^t 是 t 时刻该维度全体 splat 取值的 2D 排布。渲染时按当前帧索引取回各路图像，同步遍历像素坐标 在所有图像上取值，经映射 φ 直接拼出每个 splat 的完整属性组（原文式 2）。关键性质：点云无序 ⇒ 重建无需特定顺序，按像素读取顺序直接构建 3DGS，从而**消除 2D→3D 映射表**（VideoRF 体素表征必须存储映射表），解码显著提速。渲染本体是标准 3DGS：协方差 Σ=RSS^TR^T 经 JWΣW^TJ^T 投影后做有序 alpha blending。

**离线训练管线**：长序列切帧组（组内 20 帧）以应对拓扑变化与无限长度；每组首帧为关键帧，用 NeuS2 网格采样初始化做静态 3DGS 重建，按不透明度迭代“剪枝+微调”把 splat 数控制在 100k 以内；组内其余帧逐帧串行走两阶段——阶段一用多分辨率 hash 编码+浅 MLP 只估计位置增量 Δx（splat 数恒定冻结），阶段二以残差熵损失+时间损失微调其余属性；最后烘焙：量化（位置 uint16、其余 uint8）、Morton 排序、边长为 8 倍数的自适应方形排布、FFmpeg H.264 编码为多路 2D Gaussian Video 上传服务器。

**在线播放**：拉流 → OpenCV 硬件解码 → 反量化重建点云 → shader 渲染；桌面/笔电多线程（拉流解码与反量化渲染分线程），移动端 Swift + Metal compute shader 做图像→点云回变换、Metal shader 做 alpha blending，全程无 CUDA 依赖。

设计逻辑一句话：训练端刻意制造“帧间可预测性”（同一表面 splat 跨帧落在同一像素位、残差低熵、量化鲁棒），编码端用成熟视频编码器吃掉时间/空间冗余，播放端以最简数据通路换跨平台性。

## 3. 关键设计

### 3.1 帧组划分与关键帧重建

帧组是“拓扑适应”与“时序压缩”的分界：组边界允许点云重建（关键帧重训），组内强制 splat 数恒定。论文明确指出，组内若做 densify/prune 会丢失运动估计建立的 splat 对应关系，且帧间数量变化破坏烘焙后的像素级连续性、引入抖动伪影——这是该表征成立的最硬约束。关键帧以 NeuS2 三角网格采样为初始点云，静态 3DGS 优化后按 opacity 排序剪枝（每轮剪掉最低 30%，依据 compact-SOG 结论：剪 30% 最低不透明度高斯不影响场景质量），在不做致密化/克隆的条件下微调，迭代直至 splat 数 ≤100k。组大小取 20，为训练速度与质量的折中（消融见第 5 节）。

### 3.2 快速运动估计（阶段一）

多分辨率 hash 网格 h(x)={h_1(x),…,h_L(x)}，位置增量 Δx = M_LLP(h(x_{t−1}))，x_t = x_{t−1} + Δx；损失为 (1−λ)L_photometric + λL_D-SSIM，λ=0.2（该阶段不含熵/时间正则项）。超参（实验节）：hash 16 级、每级 4 特征；浅 MLP 每层 64 神经元、2 隐层。论文称两帧间位置变化可在数秒内估出。机理要点：只动位置、属性冻结到阶段二，运动估计天然产出跨帧 splat 对应关系——既复用上一帧属性、压低属性残差，又保证同一 splat 在帧组内所有帧映射到同一像素坐标，这是后续视频编码帧间预测有效性的前提。

### 3.3 残差熵损失与时间损失（阶段二）

视频编码器对残差做熵编码：值出现越频繁，编码比特越少；残差分布越集中，码率越低。论文统计发现 R/S/o/SH 的帧间残差近似高斯分布，遂为每个属性设可学习 μ、σ 建模残差分布；量化过程为 Δy_t = y_t − y_{t−1} 按属性量化区间 q_i 归一并叠加 U(−1/2, 1/2) 均匀噪声模拟取整，PMF 由相邻两个 CDF 之差近似，熵损失即比特消耗的直接近似：L_entropy = (1/N)·Σ −log2 P(Δ̂y_t)，作用于 {R,S,o,c,SH}（位置不在此列）。该设计承自 HAC 与动态 NeRF 码率优化工作的熵建模思想，但作用对象是帧间残差。时间损失在属性图像域做 L1 平滑：L_temp = (1/(W·H))·Σ‖y_t − y_{t−1}‖_1。总损失 L = (1−λ)L_photometric + λL_D-SSIM + λ_e·L_entropy + λ_t·L_temp，全序列统一 λ_e=1e-4、λ_t=1e-3。工程含义：这是 compression-aware training 在动态高斯上的实例——损失函数里显式出现“比特数”项，等价于对生成残差分布施加可微码率约束；取整噪声仿真同时提升低码率下的量化鲁棒性（论文明确主张“低比特率下维持高质量”由此而来）。

### 3.4 烘焙与编码器协同

四个互相咬合的细节：

- **量化位宽分配**：位置对点云最敏感，用 uint16 并拆成高/低两个 uint8 通道（高 8 位无损保精度）；其余属性 uint8；以 uint8 PNG 承载。
- **自适应分辨率**：取能容纳全部高斯的最小方形、边长为 8 的倍数（原文称对编码器更友好），最小化空网格。
- **逐属性 QP 分配**：实验发现 QP 超过 22 后 RGB/Scale/Rotation 三属性渲染质量陡降，故采用阈值策略——QP≤22 时全属性同 QP；QP>22 时上述三属性钉死 22、其余属性继续升 QP。这是 3D 语义粒度的率控制雏形。
- **Morton 排序**：坐标从 float 量化到 2^21 范围整数后计算 Morton 码排序，空间相邻 3D 点映射为 2D 图像相邻像素；空间相近的点属性相似，排布成空间平滑图像后利于编码器利用空间冗余（承自 SOG）。

与经典混合视频编码框架逐项对应（本笔记归纳）：阶段一运动估计 ≈ 帧间预测；阶段二+熵损失 ≈ 残差分布整形与率约束；Morton ≈ 重排/扫描；H.264 ≈ 变换+熵编码。V³ 本质是“学习式预测器 + 标准编码器”的混合编码架构，这也是它能全链路吃到硬件编解码生态的原因。

### 3.5 播放器

FFmpeg H.264 编码上传资源服务器；播放端 OpenCV 硬件解码。桌面双线程（线程 1 拉流+解码，线程 2 反量化+重建点云+渲染）；移动端 Swift 实现，Metal compute shader 完成图像→点云回变换，Metal shader 实现 alpha blending，摆脱 CUDA 依赖。Apple 统一内存架构免去内存拷贝，compute shader 并行解码耗时与桌面相当。三线程异步并行，FPS 按渲染线程耗时计。支持自由视角、时间轴拖动、播放/暂停。

## 5. 消融要点

在固定存储档（论文消融口径约 600KB，另一处定性对比口径约 500KB）下逐项去除组件：去掉 hash 运动估计 → 几何错误+外观模糊；warp 后不做微调 → 衣物纹理等细节无法重建；去掉帧组划分 → 长序列训练显著退化；去掉时间损失或残差熵损失 → 表征对视频编码器不友好，同存储条件下质量下降。率失真曲线显示全模型在各 QP 档位均居上方——两类损失的收益本质是“编码友好性”而非直接提升渲染保真度，印证第 3.3 节“率约束搬进训练端”的定性。

## 6. 贡献与启示

论文自述四项贡献：首个移动端动态高斯流式渲染方案；2D Gaussian Video 紧凑表征（高斯属性烘焙为 2D 视频、适配硬件编解码）；运动-外观解耦+残差熵损失+时间损失的高效训练策略；多平台实时流式播放器。

对 AV 领域的方法论启示（本笔记归纳）：

1. **表征×编码器协同设计**：把非视频信号烘焙为 2D 视频以复用硬件编码生态（硬解、CDN、标准封装、封装协议），与 V-PCC“3D 拆 2D 视频+标准编码器”同构。代价是排布/量化/QP 等自由度必须与编码器咬合设计——本文的 Morton、8 倍数边长、逐属性位宽与 QP 阈值就是这层咬合的具体形态。
2. **训练即码控**：−log2 P 项等价于可微比特数约束，与 R-D 优化中的拉格朗日乘子同源，但作用点在“生产残差”而非“编码残差”，为“神经表征生成 + 传统编码器”级联系统提供了通用的率失真训练范式。
3. **免映射表解码**：利用点云无序性实现“像素读取顺序即重建顺序”，相比需要 2D→3D 映射表的体素类流式表征（VideoRF）少一份元数据与一次查表。
4. **常数高斯数**：组内 splat 数恒定 ⇒ 固定内存布局与稳定 shader 管线，是移动 GPU 友好性的来源；代价是拓扑适应只能发生在组边界。

局限（论文自述）：依赖密集视角采集（自采数据 81 视角），前景分割质量差会引入伪影；大动态场景（30 人舞台、人物-物体交互）困难；无法实时重建（论文对比 GPS-Gaussian 并列为未来方向）。本笔记补充两点工程观察：手机端 27fps 裕量小；按每帧 682KB×30fps 折算码率约 160Mbps 量级（推算值、非论文原文），远超常规公网 2D 视频流带宽，当前定位是内网/高带宽高质量档而非窄带流——带宽自适应是其明显缺口（第 7 节相关工作正好补位）。

## 7. 与其他论文的联系

- **QUEEN（arXiv:2412.04469）**：同属“动态高斯流式自由视点视频”主线。QUEEN 逐帧学习高斯属性残差并配量化-稀疏化框架，追求小体积与实时编码，与 V³“残差熵损失+量化鲁棒”动机同源；分工上 QUEEN 主攻编码侧（码率/编码延迟），V³ 主攻播放侧（硬件解码+免 CUDA 渲染），可视为该主线的两翼。
- **DualGS（arXiv:2409.08353）**：同期工作、同为人体体积视频，同样以运动/外观解耦为归纳偏置，但用皮肤/关节双高斯分层实现 120× 压缩、面向 VR 实时自由视点播放；V³ 则用 2D 视频烘焙+H.264。两者共同佐证“运动-外观解耦是动态高斯压缩的有效先验”，分歧在码流形态与目标终端。
- **ResStreamGS（arXiv:2610.21121）**：直接延续 V³ 开辟的移动端 3DGS 体积视频流媒体问题设定；按高斯时间特性分流编码传输，相对 V³“按属性维度切流”提供了按时间稳定性切流的另一种流组织粒度，主打重建质量与带宽效率。
- **SAGA（arXiv:2609.33969）**：以 4D 稀疏锚点+INR 解码压缩动态 3DGS，BD-rate 大幅占优；相对 V³，INR 解码牺牲了硬件编解码兼容与免映射表优势——体现“压缩效率 vs 解码生态通用性”的路线权衡，V³ 明确站在生态兼容一侧。
- **Adaptive 3D Gaussian Splatting Video Streaming（arXiv:2507.14432）**：以高斯形变场+混合显著性分块构建带宽自适应流式框架；恰好补上 V³ 率控制仅有逐属性 QP 阈值、缺乏 ABR 级带宽自适应的缺口。
- **HiReFF（arXiv:2606.29333）与稀疏视角重建系（arXiv:2610.25887、arXiv:2610.04606）**：V³ 自述依赖密集视角（81 视角）是生产侧瓶颈；HiReFF 以无标定四视角前馈实现 2K 级 360° 人体重建，另两篇分别以少样本学习正则与时空先验+扩散生成辅助缓解稀疏视角 3DGS/4DGS 重建的过拟合与质量崩塌，均属内容生产上游的互补路线。
