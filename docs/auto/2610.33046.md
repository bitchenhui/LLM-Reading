## 1. 背景与动机

论文处理的任务族是“以程序为候选解、以计算评估为目标函数”的自动科学发现：给定程序空间 X、官方评估器 f:X→R（越大越好）、起点程序 x₀ 与候选生成预算 B，搜索返回全程最高分候选。这是 FunSearch / AlphaEvolve 一脉的 LLM 引导进化搜索范式，其核心机制——父代选择、变异、记忆组织、资源分配——均为设计时固定的显式流程。

作者将现有工作的局限归为三层递进的失效模式：

1. **固定流程的进化搜索**：策略有效性随搜索进程非平稳漂移，早期快增益策略会把后续努力锁死在窄解族内，长时程停滞。
2. **受限自适应框架**（ShinkaEvolve、PACEvolve、AdaEvolve、EvoX、Dream-RSI）：允许运行时调整种群采样、上下文管理、探索调度、资源分配，或如 EvoX 直接演化选择/变异/灵感上下文策略。但可适应范围被限定在设计时选定的组件子集与固定更新程序内——当瓶颈落在指定杠杆之外、或落在修订程序自身时，系统既无法诊断根因也无法重构自身操作。
3. **决策级自主研究 agent**（Autoresearch 的单冠军工作流、CORAL 的多智能体共享笔记、SwarmResearch 的集中编排）：逐步决策带来灵活性，但无约束的上下文内微观决策在长时程上表现出对熟悉候选与当前领先者的认知偏置——leader-following、过早共识、近贪婪的分支分配；且编排器对自身的决策偏差是盲的。可配置的反思与停滞触发只能提供重定向机会，不能纠正维持无效搜索的机制本身。

由此引出核心命题：**决策级自主性不充分，需要（a）能暴露搜索病理的诊断工具，（b）显式、可修订的机制来支配选择、反思与协调，且（c）修订能力本身必须落在可修订范围内（递归性）**。Organon（命名取自 Bacon《新工具》Novum Organum，“发现的艺术随发现一同进步”）以单一持久 agent 修订其全部操作栈——进化循环、父代选择、候选变异、种群管理、记忆、工具、资源分配、worker 协调——修订在运行时生效，并延伸到用于诊断自身局限与评估后续修订的诊断工具与决策程序。

## 2. 方法总览

**形式框架。** 任务三元组 (x₀, f, B) 在整个调查期间固定；x₀ 的评估不消耗预算 B，任何候选尝试（含开发/评估失败）各消耗一单位。返回 x̂ ∈ argmax over H（含 x₀）。

**Agent 组合与持久状态。** 经过 r 次采纳的能力修订后，agent 为 A_r，其可编辑组合 C_r = (L_r, T_r, M_r, W_r, Φ_r)：L_r 为进化搜索能力，T_r 为工具与技能（含内部诊断），M_r 为记忆与上下文管理，W_r 为 worker 子代理协调规格，Φ_r 为执行循环与指令。与之分离的是跨修订持久的种群与历史 H = (P, R_cand, F_work, R_rev)：活动种群、完整候选记录（程序、官方分、评估反馈、父代-后代谱系、生存状态）、worker 发现、修订史。**C 定义“当前如何研究与如何自我改进”，H 保存全部经验证据**——这一解耦是后文状态保持撤回的前提。

**搜索循环。** L_r = (Sel_r, Var_r, Eval_r, Surv_r)。每次候选尝试是 worker 子代理在隔离工作区（由所选父代初始化）中的委托开发任务：Organon 依据 H 提供 prompt、角色、工具与上下文；Eval_r 调用固定官方评估器 f 取得官方分与执行反馈（连同 T_r 中的辅助测试），失败同样记录为尝试结果；Surv_r 更新种群并追加记录。初始组合 C₀ 中 Sel₀ 按适应度权重采样。

**双层进化与研究视界。** 候选进化在当前组合下更新 H；能力进化依据 H 中的证据执行 C_r → C_{r+1}。调度单位是“研究视界”：agent 自选 k ∈ {1,…,B_remaining}，视界内 C_r 冻结、搜索循环执行至多 k 次尝试；视界返回后 agent 检查 H′（分数进程、谱系集中度、评估反馈、worker 发现），在“继续 / 修订 / 结束”三者中选择。多个视界可在同一组合下运行。这一“有界调用间修订”的结构把自改时机本身变成受控决策，而非任意时刻的竞态修改。

**效果代数与可逆性。** 设 Γ_r 为实现 C_r 的运行时上下文。组件 p 声明依赖（coeffects）满足后即可参与；激活 p 施加效果 e_p(Γ_r) = (Γ_{r+1}, u_p)，u_p 为被跟踪的回退操作，满足 u_p(Γ_{r+1}) ≃ Γ_r（撤回 p 的注册贡献后上下文等价）。Reactive coeffects 在依赖变化时自动协调组件激活，revertible effects 使任何已采纳修订可在后续视界证明无效时被干净地替换或撤回。跨修订不变量为：H′、B′_remaining 与官方评估器 f。

**递归性落点。** 诊断与评估程序 ∈ C_r ⊂ 可修订对象——修诊断工具会暴露此前未识别的瓶颈或选择偏差，进而触发对支配机制的重写与后续能力开发方向的调整。这是“递归自我改进”在本文中的实质含义：不是无限自改奇观，而是**评估与改进机制本身处于改进回路之内**。

## 3. 关键设计

**（1）注册表化的操作栈。** 实现基于 DeepSeek Harness 的动态组合运行时，作者在其上添加一个进化搜索服务，暴露五个可替换 provider 接口：进化循环、父代选择、候选变异、评估、种群生存。这些接口与技能、记忆、worker 子代理等并列，同属活动组合。agent 通过“定义带服务依赖声明的动态组件并在会话中激活”来修订 provider；组件以 tracked effect 注册贡献，**最近注册者生效**；去激活即撤回注册并恢复前一可用 provider。工程上这是一个带审计轨迹的服务定位器 + 热更新语义：无重启、变更边界清晰（修订只发生在有界调用之间）、优先级规则极简（注册序）。对想复刻该范式的系统，这是成本最低的路径——不需要任何模型训练，只需把操作栈服务化。

**（2）状态保持的撤回。** 可逆性的价值不只是回滚：Cloudcast 案例中 agent 恢复了自身某组件的早期版本，同时**保留该版本替代者运行期间积累的种群与诊断**——即“拒绝一个操作假设，而不丢弃在该假设下获得的经验”。组合可回滚与 H 单调累积的分离，使试错成本从“丢失搜索进度”降为“丢失一段机制假设”。

**（3）诊断作为一等能力。** 19 个任务上 agent 自建测量工具决定了下一步修订什么：per-case profiler（AHC011/AHC015/AHC016/AHC039/AHC046）、对官方分校准的开发评分器（AHC008 精确复现、AHC027 偏差约 0.36%）、独立合法性检查器（AHC039）、可行性与带宽探针（PRISM/EPLB/Cloudcast/LayerNorm）、held-out 实例生成器（PRISM 加 5 个种子、Cloudcast 加 21 个配置）、逐内核时间分解（ConvMax：约 71% 内核时间在库卷积、16% 布局转换、12% 融合 epilogue、每次调用约 0.43 ms 非内核开销，随后要求每个 worker 从该分解中选单一变更）。关键的递归性体现在：这些工具本身被修订——Heilbronn 的父预算读取器两次被修正（曾把 205 s 读成 50 s、又读成无关常数 999 s），每次修正都先于一次新纪录；AHC011 修正确“完成树”定义的回归检查后，暴露出一条子代丢失 12 棵完成树的回归，并改变了后续 worker 指引。

**（4）协议约束下的能力自建。** 公平性设计值得注意：worker 子代理在沙箱中无 shell、无网络，只能编辑自己候选的源码，**不能编译、执行或测试**——与对比方法的“LM 提议代码但不运行”对齐，防止 worker 用本地试错替代被评估的候选尝试。因此一切执行类检查（编译前验证、回归修复、重复测量）只能是 agent 在搜索中自发引入的能力（分别为 6 个与 5 个任务），而非实验者预置。另按脚注，AHC016、AHC046 与三阶自相关三任务共 300 个候选中有 38 个被 agent 路由到 DeepSeek-V4-Pro（独立评测排名低于 V4.1-Flash），作者以此说明不构成骨干优势。

**（5）预算会计与自调度。** agent 每次调用自选 k，可查余量与当前 provider；搜索调用中位数 13 次（范围 2–18），首次调用小（中位 4 次尝试），21 个任务中 19 个的后三分之一调用平均大于前三分之一——自我评估频率随组合稳定而降低，但首次后的 244 次调用中 196 次（80%）仍跟随至少一次修订。

## 5. 消融要点

须先声明：**论文没有受控消融**——作者在结论中将“通过重复运行与受控消融隔离单次修订的贡献”列为 future work。起消融作用的是对 21 条单 run 轨迹的解剖（附录 A），且作者明确：修订与后续进展是时序关联而非因果；报告分数为搜索期记录口径（ALE 为公共分、内核为搜索内 speedup），与第 4 节 Modal / 私有复测不同。

**修订行为统计。** 21 个任务全部发生自我修订；首次修订中位发生在第 4 次尝试（范围 1–8）；每 run 激活 2–22 次修订（中位 11）。三种模式清晰可分：7 个任务上初始组合 C₀ 无任何候选超过 x₀（全部进步来自自我修订）；14/21 任务 ≥70% 的总改进发生在首次修订之后；另一极端（圆装箱 ρ=0.01、PRISM ρ=0.00）中起点程序极弱，前几个候选即闭合大部分差距，后续修订集中于打破平台期。

**修订类别矩阵。** 无两个 run 修改相同的能力类别集合（AHC016 改满全类别，EPLB 只改 worker 方向与循环并发）。每 run 均修订候选变异、维护持久记忆、且至少一次纠正自身工具或修订。按类别计：选择 19、诊断工具 19、循环/并发 16、重组 14、种群策略 10、验证/修复 6、重复测量 5、worker 模型 3、显式撤回 12。

**搜索策略共演化的量化证据。** AHC024 观察到交叉平均父代相对增益 +4.3（其他算子 +0.5）后，把交叉占比从 1/3 提至 2/3。AHC008 按编辑尺寸测产：≤20 行 11/18 改进父代（平均分比 1.013）、20–140 行 24/61（1.06）、>140 行仅 1/11（0.68），据此约束边界编辑尺寸。AHC026 发现全部大幅重设计收益均出自 ≲27 KB 父代（≥28 KB 的 10 次重设计零增益），建立尺寸感知选择；并发从 8 个 worker 回退到 5 个，依据实测 0.205 vs 0.269 candidates/min。选择压力修复：AHC027 发现三路锦标赛仅约 27% 概率选中最优，rank 加权恢复到约 58%。

**研究手段自建的关键解锁。** LayerNorm 将前 8 次失败中的 7 次归因于 KernelBench harness 用“行首非缩进 import”规则检测 Triton 内核——缩进/守卫式 import 使候选被静默路由到内核失效路径；给出精确评估契约后下一视界产出 15.98× 内核（搜索期）。ConvDiv 同因三个初始候选被记 0 分而 agent 自行评测为 1.08×/1.50×/0.98×；再测同一未改程序得 3.02/3.02/3.22/3.15（记录 3.29），确认 ±5% 计时噪声下单次评估是差的排序信号，改用重复均值后搜索期加速从 3.29× 升至 5.93×（Modal 终测 5.58×）。圆装箱：诊断出时间依赖的构造器无法从代码复现边界（重跑最佳程序得 2.627558/2.628678，记录 2.628570），改为把最佳 26 圆排列作为经验证的数值数据供给每个 worker 作为保底，17 次尝试近零进展的平台在下一视界即录得 2.635024，保底值随捕获升至 2.6352。饱和诊断：PRISM 用 5 个附加种子共 250 实例验证四程序逐实例同值、可行性搜索以 2×10⁻⁹ 相对精度复现已达值，判定目标饱和后将搜索转向同分更简洁、对未见输入形状更稳健的程序。

**自我纠错与撤回。** AHC025 的生存规则被写反（每次淘汰保留的是最弱 5 个存活候选），纠正并复兴被误删候选后，最终赢家正是其后代。AHC024 统计实际指派方向发现 28/32 尝试都拿到 repair 而非预期混合。12 个任务显式移除/停用/回退既有修订；AHC016 实测替代模型路由的 10 个候选落在同分带（估计 36.2–36.9M）但每批耗时 45 vs 20 分钟，遂放弃路由（“更强的模型在此买不到质量”）。同时作者如实记录自监控不完备：LLM-SQL 速度机会比较中的符号错误、部分 Cloudcast worker 指令的算术不一致未被 agent 检出。

## 6. 贡献与启示

**贡献**（原文三条）：(1) 递归自我改进的发现 agent——从积累经验修订自身搜索、诊断与修订程序；(2) 状态保持修订——借助时空可组合性，能力在搜索中增删替换而不丢种群与历史；(3) 21 任务评测与能力演化分析。

**方法论启示。** 第一，“适应范围设计时有界”问题的工程解是把整个操作栈服务化为注册表化的 provider（五接口 + 最近注册者生效 + tracked 回退），无需任何训练即可获得机制级开放适应域——这与其他“自适应进化”工作在预设杠杆上做调度有本质区别。第二，组合可回滚与状态单调累积的分离，使机制假设的试错代价趋近于零，撤回因此成为高频且理性的结果（12/21 任务）。第三，多个最大解锁来自**理解评估语境**而非更强变异（harness 契约、评估噪声、目标饱和），提示在算力受限的自动优化中，构建测量能力往往优先于构建搜索能力。第四，吞吐瓶颈在 worker 生成（EPLB 约 3 分钟、ConvDiv/ConvMax 约 6、LLM-SQL 约 9、AHC024/AHC039 10–13 分钟；评估仅秒至约 1 分钟），agent 自行推导出批式→流水线→流式补给的演进（VGG16 首次流水线化后吞吐 2.4×；AHC024 批内 8 个尝试约 8.3 分钟 vs 单 worker 10–13 分钟），对一切“LLM 生成 × 计算评估”耦合的优化管线有直接参考价值。

**局限。** 无受控消融、每任务单 run、时序关联不能归因单个修订；数学几何类任务仍落后于 EvoX/ShinkaEvolve；自我纠错不完备（符号错误等未检出）；跨任务的能力复用（自改进跨问题复利）尚未实现。

**与音视频技术链的上下游关联。** 本文不属音视频领域，但其上下游与音视频工程高度重叠。上游（算子/内核层）：KernelBench 结果即 GPU kernel 自动优化——音视频编解码与前处理管线（转码算子、视频 Transformer / 视频 LLM 推理栈，LayerNorm 18.70× 正属该栈）可直接迁移其方法论：评估契约优先诊断、可达内存带宽上界测定（LayerNorm 判定领先设计已距实测可达带宽约 4%）、计时噪声下的重复测量排序。下游（系统层）：PRISM/EPLB/LLM-SQL/Cloudcast 是 LLM 推理基础设施优化，与音视频 AI 服务（转码调度、内容理解、前缀缓存）的问题结构同构；Cloudcast 的逐配置成本分解 + 瓶颈链接分析 + held-out 配置生成模式对 CDN/源站传输优化可平移。迁移推断（非论文内容）：codec 参数与码控搜索（如 AV1/x265 参数空间的进化搜索）符合本文“程序/参数候选 + 计算评估”范式，且该域同样具备本文识别的三个自适应触发条件——评估噪声、强局部最优、目标饱和——故 Organon 式经验驱动策略自适应预期优于固定进化流程；但需注意其 worker 级生成成本（分钟级/候选）对 codec 全参数搜索的预算含义。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326，证伪门控的自进化记忆）**：两者同拒“无条件经验累积”，但门控位置相反——FGSE 在写入前以三类探针验证经验教训，Organon 在写入后以后续视界结果监控修订并可撤回。Organon 的反面案例正好构成 FGSE 动机的证据：AHC027 的记忆摘一度只存每份报告的样板首行（无信息），AHC008 的 topic 标签因解析不匹配使 novelty 选择在空数据上运行——未经验证的记忆/能力写入会静默失效，只能靠事后自检发现。互补方向是把 FGSE 的写入门控前置于 Organon 的组件激活阶段。
- **TRUST（arXiv:2611.10787，带统计保证的 RSI）**：直接对位 Organon 自我评估层的缺口。Organon 判定修订有效性用的是非正式统计（重复均值、肉眼分带、间隔比较），论文自承单 run、时序关联非因果、且有未检出错误（LLM-SQL 符号错误、Cloudcast 算术不一致）；TRUST 的在线多重假设检验与错误进化率控制可外置地加固 Eval_r / 重复测量类修订的“采纳-保留-撤回”决策。
- **SkillDuet（arXiv:2611.12109，模型与技能库协同演化）**：改进载体谱系的两端。Organon 冻结模型权重，全部自改发生在组合/harness 层（仅 3 个 run 尝试过 worker 模型路由，其中 AHC016 实测后放弃；三阶自相关保留路由，25/100 worker 用 V4-Pro 且最终纪录出自其中）；SkillDuet 将改进下沉到参数与技能库协同。两者共享“工具/技能库为一等可演化对象”（Organon 的 T_r：开发评分器、profiler、探针）。Organon 的 LayerNorm 轨迹（搜索期 0.99×→19.35× 全凭 harness 层修订）为“权重冻结下 RSI 的可达上限”提供了一个数据点。
- **InfraRSI（arXiv:2611.11558，RSI 用于训练基础设施）**：域上部分重叠（Organon 的 PRISM/EPLB 为推理侧系统优化，InfraRSI 为分布式训练优化），且都以显式验证工作流约束自改；对照点在于 Organon 的验证工作流（编译前检查、回归修复、重复测量）是 agent 在搜索中自建并自我纠错的，而 InfraRSI 的五阶段验证是预设流程——分别代表“验证即被演化对象”与“验证即护栏”两种设计取向。
