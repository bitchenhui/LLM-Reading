# Build, Don't Play: Self-Improving LLM Research Agents Develop a Hearthstone Battlegrounds AI That Rivals Top Players

## 1. 背景与动机

从 Go、星际Ⅱ、Dota 2 到扑克、麻将、Stratego，超人类游戏 AI 历来是大团队先手工构建环境、再设计学习算法、再逐项调试“仿真训练世界与真实游戏不一致”的产物。本文追问的问题是：LLM 智能体能否独立完成这条链路——从原始数据出发，造出一个能在**真实对局**中与人抗衡的系统，且最终性能以真实天梯而非离线基准衡量。既有 LLM 研究智能体的证据多来自基准任务或论文复现，缺少“真实现场”的闭环检验。

任务选型是炉石传说酒馆战棋（Hearthstone Battlegrounds）：八人自走棋，每回合用金币（第 1 回合 3 枚、上限 10 枚）在共享卡池的随机商店中买入/卖出/刷新/冻结、升级酒馆等级（1–7）、布置至多 7 个随从的战队，随后与一名对手自动战斗（随机目标），败者掉血淘汰至剩一人。形式化为部分可观测随机博弈（POSG），终局效用为名次 1–8；玩家仅见自身状态、公开排行榜与上次交战时对手的战队。当前版本（patch 36.6.3）含 978 个游戏对象（随从、英雄与英雄技能、法术、饰品等），一局约 15 回合、每名玩家约 450 个原子动作，奖励只在终局。战棋此前**没有**忠实仿真器：MCTS 助手建立在简化仿真器上且只在前几回合评估；BGSimulator 不含英雄；Firestone/Bob's Buddy 只模拟战斗阶段；DeepBattler 是无环境无智能体的实时建议工具；LLM-as-player 基准则普遍缺少环境、可验证标签与实时视角。

方法论的靶子是自研究系统的两类失效：**代理漂移**（proxy drift，内部代理指标Ĵ提升而真实表现J不提升，因为环境E或对手模型O有错且策略在 exploiting 它）与**虚假结论**（false findings，噪声/泄漏/选择偏差被当作发现写入共享状态并误导后续工作）。全文架构——现实回锚环 + 验证门禁——均由此推出。

## 2. 方法总览

AUTOTAVERN 将研究状态定义为工件集合：环境 E_t、对手模型 O_t、考试集 X_t、策略 π_t，外加研究过程本身——发现与教训的记忆 M_t 和门禁 G_t。目标 J(π) 是天梯期望名次，只能通过少量慢速昂贵对局观测；环内只能优化代理 Ĵ(π; E,O,X)。系统用三个机制压住两类失效：**现实环**（live 对局回放进仿真器、定位差异、修复后重训）压制代理漂移；**五道验证门禁**压制虚假结论；两者都作用在唯一的共享通道——类型化研究记忆上。自改进的含义是双层的：一次迭代既更新工件，也把捕获的错误转写为教训（每次会话加载）或新门禁，使同一错误不为第二次买单。

组织上，六个长时研究角色智能体（research lead 选问题派活、environment 造规则修差异、opponent modelling 造拟人对手、training 设计训练配方、evaluation & audit 复测审计、deployment 维护客户端控制器与输入格式）加短命子智能体，**互不直接对话**，只读写版本化类型存储：编号发现的台账（更正是回指旧条目的新条目，发现永不被抹改）、220 条已确认规则裁定注册表与未决问题清单、交接便签、约 10,000 条实验注册表（含模块/资源/优先级/依赖/后继）、教训库。迭代按八步执行（Observe→Diagnose→Plan→Implement→Train→Evaluate→Deploy→Reflect），以三个时间尺度运转：训练环（秒到分钟级 PPO 更新）、研究环（小时级实验与发现）、天梯环（天级真实对局反馈）；调度器在资源预算内执行已注册实验并保持后继排队，可在无人值守下连跑数日。人类只在两处介入：设定目标，以及对游戏数据留白机制做裁定。

20 天产出三个工件：TAVERNGYM（Rust，63k 行，全量 978 对象的忠实复现，单核 190–280 完整八人局/秒）、TAVERNAGENT（18M 实体 transformer，PPO 训练，23 个交付版本）、TAVERNBENCH（40 场景 960 任务的决策基准）。人工投入仅 418 条消息（占全部消息的 0.6%），其中 42% 要进度、24% 定目标、5% 裁定机制。

## 3. 关键设计

**3.1 TAVERNGYM：确定性高保真引擎。** 关键决策是招募与战斗共用**单一效果上下文**：每张卡是事件钩子表，两阶段语义一致，避免双份规则实现漂移。状态是整数 id 的实体 arena，拷贝廉价、可序列化为 JSON；所有随机性来自**单一种子化 RNG**，故“种子 + 动作序列”可逐比特复现一局。卡牌表由游戏自带数据文件生成、后续补丁以 overlay 叠加；每个 build 有源码哈希与规则哈希，且异哈希 checkpoint 不允许续训——这是 G2 契约门的技术基础。正确性保障为三层：375 条逐机制校验记录与 220 条裁定、每机制单元测试、fuzzing 每步动作后校验状态不变量，外加 245 个离散动作的**精确合法掩码**。RL 接口提供玩家视角观测（对手仅见上次交战战队）、批处理环境（Python 绑定释放 GIL）与运行中对局的精确存取（供前瞻与回放）。性能口径：单核完整八人局 3.6–5.3 ms（190–280 局/秒），后期战斗 13–19 µs（52–76 千次/秒）。

**3.2 TAVERNAGENT：实体 transformer + PPO 课程。** 每个己方随从、手牌、商店offer、待定选择、对手各占一个 token（至多 56 + 1 全局 token）；卡的表示为恒等嵌入 + 静态特征投影 + **规则文本嵌入投影**之和——后者让稀有卡获得合理先验。磁力附属并入宿主随从 token，饰品与持久效果池化进全局 token，数值输入对称对数压缩。指针头在 245 个掩码动作上打分，值头与辅助名次头共享主干（d=384，8 层 8 头，18M 参数，为同配方三规模早期对比的最优）。PPO 配置（最终阶段）：每成员 512 局 × 256 步、每迭代约 1.05×10⁶ 决策、每阶段 300 迭代（约 3.1 亿决策、57 万局），阶段起点做 100 迭代 KL 锚定（系数 0.1），γ=1.0、λ=0.995、clip 0.2、目标 KL 0.05，终局名次效用。课程为：简化规则集从零 → 全量内容 → 玩家视角 → 对拟人对手的首胜目标 → 库对手。

**3.3 现实校准对手库。** 不用自博弈，而用七个“库席位”：库条目是某席位某回合的完整局面（含手牌与隐藏计数），初版由顶级人类玩家统计（种族占比、升级曲线、购买率、逐回合战力）与录像构建，每回合取匹配目标战力曲线的条目。两处关键校准：其一，**在智能体实际遇到的对手分布上而非均匀抽样上**度量库强度并重校准；其二，分级库从对齐人类到含剧毒后期阵容、手牌与上限构建的更难库。考试库绝不用于训练（训练用其他来源同法构建的孪生库），杜绝考训泄漏。

**3.4 门禁与记忆语义。** G1 build：代码改动过全量测试套件才进共享 build；G2 contract：模型与所训仿真器 build 绑定，控制器拒载错配模型（后扩展为两个输入编码器的逐比特比对，见消融）；G3 comparison：只在同一 build 内、多种子比较；G4 delivery：仅在**未参与选择的种子**上复测通过才交付；G5 reality：交付模型上天梯，对局在仿真器中重放。记忆的 append-only + 回指式更正使“结论如何演变”与“结论是什么”同时可追溯——这本身就是对虚假结论的制度性防御。

**3.5 线上闭环。** 控制器以环境自身编码向策略喂真实局面，策略决定每个操作并**指名**快捷键，由人按下（游戏官方插件功能，人不做任何决策）；提案非法（编码或控制器错误）即弃局修复再继续。客户端故障（96/388 局）仅凭控制器日志标记、在看结果之前判定，不混入智能体归因。每局对局记录与决策日志链路化，评测智能体在 TAVERNGYM 中重放真实战斗与招募步，输出仿真-现实分歧报告驱动修复——20 天共 184 项修复（35 项游戏规则/卡牌行为 + 11 项卡牌数据与 offer 规则、73 项输入编码、51 项客户端控制器、14 项对手与考试再校准）。

## 5. 消融要点

- **对手现实校准是单项最大增益**：同一 checkpoint、同等 150 迭代预算，校准库使主考试首胜率 20.9%→27.2%、难考试 10.3%→13.5%（名次 2.74→2.65 / 3.64→3.59）——注意增益来自“校准到学习者实际遇到的对手分布”，而非库本身更强。
- **模型规模**（第 3 天、同配方从零、各 400 迭代）：3.5M/8M/18M 主考试名次 3.84/3.77/3.67、前四 73.9/75.6/78.5%，最大规模占优；该实验首胜率普遍近零系因先于成熟对手与环境，仅作规模间对比。
- **同厅八版对打**（无库席位、每局各版本一席、3 种子、每版本 24,576 局，公平均值 4.5/12.5%/50%）：TA-23 名次 3.95、首胜 26.2%（约为公平份额两倍）、前四 57.9%；TA-1 为 5.10/0.6%/38.2%，版本序列单调。
- **逐类剥离决策的价值**（主考试、3 种子、每条 24,576 局）：永不取暗影礼赠 +1.94 名次、Discover 随机化 +1.64、目标随机化 +1.45、饰品随机化 +0.56、英雄技能弃用 +0.26、隐藏对手战队仅 +0.14、英雄随机 +0.13——信息优势与长线规划类动作价值远低于即时组合执行类动作。
- **英雄偏好与人类几乎不相关**：111 英雄均匀发放（每英雄 24,576 局），智能体名次与人类公开统计名次的 Pearson r=0.13（均值 2.46 对 4.02，注意对手为库席位）；智能体偏爱人类评价低的首胜型英雄，弱于需要跨回合规划的英雄——策略风格与人类系统性不同。
- **方法论层面的“负结果消融”**（第 8 节六案例，皆为环内发现）：(i) 复制局泄漏未来——对局副本搜索表观 +23.6 首胜点，实为副本携带 RNG 状态看到真实未来商店/战斗，逐样本重播种后增益消失（−0.65±1.14）；(ii) 双错相消——考试一度与线上吻合只因后期对手过强与智能体成长被高估两个错误对消，双修后考试首胜升至 43–49%；(iii) 胜者诅咒——多样本快照最优者在选择种子上虚高 +1.2–2.1 点、未见种子 −0.7 点，直接催生 G4；(iv) 库强度须在学习者所遇对手上度量；(v) TA-10 考试首胜近乎翻倍（24.2% 对 12.8%）但天梯 32 局内评分 8,968→7,658（其中 18 局含客户端故障），溯源为客户端故障 + 被考试掩盖的前中期弱点，停测修复后 TA-11 复升——仿真所夸者需真实现场证伪；(vi) 双编码器漂移——线上重放显示智能体整队变卖频率异常，根因是饰品选择后一个输入旗标在控制器与仿真器中编码不一致，修复后 G2 增加逐比特编码比对。六例中两例固化为门禁、两例固化为常设规则，即“过程级”自改进的直接证据。
- **标签自洽性**：策略类任务标签来自 TA-21 的 128 次 play-out（保留条件：最佳方案超次优 0.25 名次且两倍标准误），标注者 TA-21 自答 73%、被评的 TA-23 达 75%、TA-1 仅 57%——标签是博弈结果而非标注者偏好，且留有超越标注者的空间。

## 6. 贡献与启示

**贡献**：(1) TAVERNGYM，首个全内容、与线上逐规则对齐、可批量训练的战棋环境（将开源）；(2) TAVERNAGENT，首个独立打完整天梯对局且达到服务器顶尖水平的战棋 AI（评分约 15,000、前 100，近 20 记录名次 1.60）；(3) TAVERNBENCH，首个带仿真器验证标签、强专用参照与实时视角的战棋决策基准；(4) 可复用的方法论——“现实锚定的自改进”：类型化共享记忆 + 逐主张证伪门禁 + 真实环境回锚 + 错误→教训/门禁的固化机制。

**核心启示“Build, Don't Play”**：建造了天梯级系统的前沿 LLM，亲自决策时远逊于所造系统且慢 50–800 倍。这为智能体系统给出明确分工——LLM 作为研究与工程智能体负责造世界（环境、对手、训练配方、评测），执行层交给 0.03 秒/决策的紧凑专用策略；时延与链式错误复合两重约束使“LLM 直接下场”在实时对抗场景不可行。工程上值得记住的三件事：错误要改变过程而非仅修正结果（不为同一错误付两次钱）；代理指标必须以固定节律向真实环境回锚，且校准分布应取部署分布而非均匀采样；append-only 记忆 + 回指更正是多智能体协作中对抗虚假结论的低成本制度。

**与音视频技术的上下游关联**（笔记作者分析，非论文主张）：上游，这套“角色智能体 + 类型化记忆 + 门禁”骨架是领域无关的工程自动化设施，可直接映射到编解码/转码流水线的自动构建与调优——G1 对应全量回归 CI，G2 的 build 哈希绑定对应“模型↔编解码器版本/码流参数集”契约（防训推不一致这一音视频部署常见坑），G5 对应真机播放与线上 A/B 闭环；TAVERNGYM 的单 RNG 确定性重放与运行中存取，正是可复现 A/B 与二分定位所需的确定性媒体流水线特性（类比参考解码器一致性测试）。中游，“代理漂移”与音视频中的**指标漂移**同构：优化 PSNR/VMAF/BVMAF 而主观质量或 QoE 停滞时，需要的正是本文式的重锚环——以主观 MOS 研究或真实用户指标（卡顿率、观看时长）周期性校验并局部化分歧源；“在所遇对手上校准”对应评测集须对齐线上流量分布而非均匀采样。下游，0.03 秒对 1.4–26 秒的实时性论证与“链式决策错误复合”结论，对 RTC 自适应码率、实时编辑与直播控制等有秒级预算的场景是直接论据：用蒸馏小策略做执行器、LLM 做离线建造者。实体 token + 精确合法掩码 + 规则文本嵌入（稀有卡先验）的组合，也可迁移为结构化媒体元数据的表示方案（合法掩码 ≈ 约束解码到有效参数/操作空间）。

**局限**（论文自陈）：单游戏、单补丁、单一账号 solo 模式；仿真内对手为库席位而非真人；天梯评分随对局数累积，跨玩家比较依赖排行榜统一口径的估计而非真实对局计数；英雄相关性 r=0.13 提示策略风格与人类差异显著，泛化到其他.patch/游戏未验证。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326）**：最直接的平行工作——FGSE 把经验教训作为可证伪假设、经三类探针验证后才写入记忆；AUTOTAVERN 的五道门禁 + append-only 回指式台账是同一原则（“先证伪、后入册”）在工程研究系统中的实例，且其第 8 节案例（复制局泄漏、胜者诅咒）正是门禁拦截的典型“伪经验”。
- **TRUST（arXiv:2611.10787）**：TRUST 用在线多重假设检验为递归自改进提供错误率统计保证；AUTOTAVERN 的 G4（未见种子复测）是对同一问题——选择偏差导致的虚假改进——的工程化（非统计保证）解法，胜者诅咒消融（选择种子 +1.2–2.1 点、未见种子 −0.7 点）恰是 TRUST 所控误差类型的实证样本。
- **Organon（arXiv:2610.33046）**：同为递归自改进研究智能体，分歧在“改进什么”：Organon 持续自改写自身代码，AUTOTAVERN 明确不改写自身代码，而以“教训 + 新门禁”改变研究过程，并以真实天梯而非任务基准作为改进判据——两者构成 RSI 范式内“改代码 vs 改流程记忆”的对照。
- **InfraRSI（arXiv:2611.11558）**：同为“RSI 用于建造训练基础设施”的实例——InfraRSI 把开放式指令经五阶段验证工作流转为分布式训练优化，AUTOTAVERN 则由智能体建造并持续修复 RL 训练世界（仿真器/对手/编码）；两者的分阶段验证工作流与本论文门禁链结构同源，差异在 AUTOTAVERN 有真实环境（天梯）作最终仲裁。
- **SkillDuet（arXiv:2611.12109）**：SkillDuet 用响应反馈让 LLM 参数与外部技能库协同演化；AUTOTAVERN 演化的是工件集（环境/对手/策略）与研究流程而非权重或技能库，且其策略由 PPO 训练、不由 LLM 反馈直接更新——代表 RSI 中“改进对象”光谱的另一端。
- **RSI-PDEbench（arXiv:2611.14949）**：以基准（1001 案例、42 方程模板）度量自改进智能体；TAVERNBENCH 与之同为“RSI 配套基准”，但 TAVERNBENCH 额外引入仿真器验证标签、实时性维度与真实部署闭环，可视为对“基准内自改进”范式的现实化补充。

（LongCapHarness 与 WeightLoop 与本文仅共享“递归自改进”大类标签——前者免后训练挂接长上下文能力、后者编辑模型权重——改进对象与本论文的环境/流程工件无实质技术交叠，不展开。）
