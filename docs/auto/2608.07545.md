## 1. 背景与动机

LLM agent 的能力由模型权重与 harness（提示词、工具、技能文档、记忆、控制流）共同决定。自改进研究沿两条轴展开：编辑什么（prompt → 技能文档 → workflow → agent 自身源码，如 SICA、Darwin Gödel Machine/DGM），与如何搜索（单谱系 keep-best 对比种群/档案）。作者观察到几乎所有近期工作收敛到同一个内环：批量 rollout → 反思 → 提出一个有界编辑 → 用 held-out/回归信号门控。DarwinX 问的是正交问题：对这个共享内环，正确的**选择过程**是什么。

两大失败模式驱动设计。其一，路径依赖：单谱系自编辑器被早期编辑偏置并进入平台期（Robeyns 等报告 SICA 的 early-edit plateau）。其二，跨任务干扰：修复一族任务的编辑会静默回归另一族，混合任务分布上的进化因此停滞；分布越宽病理越尖锐——许多 prompt/工具改动在小子集上赢、在全基准上输，故选择准则必须反映最终基准而非窄的局部目标。

既有系统的缺口被明确刻画：DGM 采用开放式档案但单亲突变、子代只与亲代比较，互补谱系永不汇合，且一次晋升不承担“保住其所替代者”的义务；HarnessX 用变体隔离容纳干扰，但阈值以下的回归仍会累积，专家留在孤立谱系中互不可见。DarwinX 把该义务显式化：只搜 harness 而非全 agent 代码；子代仅在 preserve-and-extend 契约下准入；跨谱系重组互补专家。适应度纯粹来自被测基准自带的 verifier（avg@k 通过率），无 gold 解、无人为挑选赢家——标题的“自然选择”是字面意义而非比喻。命名口径：Monet 是 Salesforce 私有 agent，DarwinX 是进化其 harness 的过程；全文所有 matched 对比中基模型一律冻结。

从音视频工程视角看（本笔记定位注记）：终端/浏览器操作 agent 正是媒体流水线自动化的执行主体，本文处理的失败模式（环境 setup、依赖安装、输出验证、多步工具链）与该场景高度同构，详见第 6 节。

## 2. 方法总览

DarwinX 把 agent 改进表述为**选择问题而非训练问题**。基模型永不变；可变的是 harness 的两个可编辑层——skill 层（prompts、记忆、提炼知识）与 code 层（工具、控制流、agent loop）。系统反复提出小编辑、在真实任务上运行编辑后的 agent，仅当测量证据显示“解开了新任务且未破坏已解任务”时保留该编辑。

数据结构上，一次运行维护一棵**档案树**，每个节点是 harness 快照加上其编辑增量、逐任务分数、试验证据与提炼教训，分支可在很久之后被重访。与爬山的两点本质区别：其一，编辑是加性的，谱系累积能力而非交换能力；其二，什么都不丢——总体更差的变体仍被保留，因为它可能持有那“单独一条与别支合并后解锁双方都解不开的任务”的编辑。因此选择运行在种群上而非单系血统上。

方法由三部分组成：单分支进化环、种群级继承环、模块化学习信号环。中央设计选择是**探索与确认分离**：selector 以有界回归风险晋升增益、让树持续移动；更严格的 avg@k 复测与 preservation probe 决定哪些变体可导向后续搜索并支撑最终声明。相对 Table 1 中的定位：prompt/workflow 优化器（OPRO/PromptBreeder/TextGrad、ADAS/AFlow/GPTSwarm、SkillOpt）不搜工具与控制流；自改脚手架系（SICA、DGM、HarnessX）缺跨谱系合并或有界回归约束；DarwinX 是唯一在种群档案、跨谱系合并、有界回归、噪声感知 avg@k、三类信号上全满足的系统。值得注意的脚注：遗传式 prompt 优化器重组的是字符串，而非“因解互补任务而被选中”的变体。

## 3. 关键设计

**适应度与 preserve-and-extend 契约。** 每个变体按逐任务通过率 p̂t(v)（avg@k）打分。子代 c 对亲代 p 的逐任务变化 Δt = p̂t(c) − p̂t(p)，汇总为净增益 g(c) = ΣΔt 与有界回归 R(c) = Σ(−Δt)+。fitness enabler 的准入条件是 g(c) > 0 且 R(c) ≤ δ。一个“有理由的” verifier agent f 两阶段裁决 verdict(c) = f(g, R, E, Kg) ∈ {promote, revert}，其中 E 是子代试验证据、Kg 是共享记忆；被晋升的子代还须以更高保真度复测并通过 preservation probe 才能导向搜索。每个节点携带谱系累计增益 G(c) = G(p) + g(c)，用于父选择。直觉表述：enabler 对“尝试一个编辑”宽容、对“信任一个编辑”严格——变体可凭有前景但含噪的信号进入树，但只有通过更严探针后才能获得塑造后续搜索的权利。这个两速度设计让搜索快速移动而不让运气累积。

**分支进化与父选择。** 每一代：从档案选亲代 → 为搜索分支分配能力簇（TB2.1 上为数值 ML、底层系统、bio/汇编、解析/文本工具、数据库/数据五簇）→ proposer 产出加性编辑，被要求保住亲代已解任务并扩展到当前脆弱或失败任务。selector 有意做 enabler 而非纯 critic：高精度准入会在互补变体出现前冻结谱系。父选择按 p* ~ (1−β)·argmax_{v∈S} G(v) + β·Broaden(P) 采样：概率 1−β 利用确认集 S 中最高累计增益节点，否则在更宽种群 P 上扩展。按累计增益 G 而非原始分排序有明确理由：变体在不同任务子集上被筛查，原始分不可比；在已改进亲代之上再加真实改进的子代应排在根与亲代之前，即使其自身子集更难——这保证过程复合改进而非反复从基线重启。

**种群、变体分类与重组算子。** 每个被评分变体都是一等档案节点。按解集关系分四类：improver（S(c) ⊋ S(p)）与 neutral（S(c) = S(p)）保留全部继承解、具继承资格；其余不具资格、只回馈提炼教训——stepping stone（严格子集）与 archived node（以部分解换部分解）。specialist 定义为额外解开某个无任何兄弟可解任务的变体。当 v1,…,vn 解互补任务时，从共同祖先 H0 物化继承子代 H = H0 ⊕ Δcode ⊕ Δskill ⊕ Δprompt ⊕ Δtool，当且仅当 S(child) ⊇ ∪ᵢ S(vᵢ) 才保留——**合并只能增加覆盖**。源池宽于根级胜者：各自贡献唯一已解任务的档案专家即使单独全局不获胜也是有用的遗传物质。合并算子搜索互补加性专家、可多于两方合并，并在同一套生存与 avg@k 规则下确认子代。

**学习信号接口。** 这是接口而非固定配方：任何能解释“harness 应如何变”的证据源都可成为进化压力。三类原生信号：failure-derived（∇）总结失败轨迹并定位缺失能力；teacher-derived（π*）把参考求解器的成功轨迹蒸馏为可复用方法；self-derived（A）对比 agent 自身在同任务上的通过/失败 rollout 组以识别使成功可靠的因素。全部翻译为 harness 编辑，零权重更新。与任务域的映射：普通变异默认 failure 信号；walls（无任何成功 agent rollout 的任务）用 teacher 信号增强 analyzer；variance-band 任务（k 样本组内成败并存）用 self 信号。可靠解 / 方差带 / wall 的动态划分使三信号按构造互补——proposer 永远拿到当前任务所能提供的最具信息量的证据，无论是反复出现的失败模式、一条走通的参考，还是自身的 near-miss。

**测量、确认与共享记忆。** 全程二值 avg@k；任务声明预算内的 agent 超时计为真实失败，真实基础设施故障按评估协议分离。晋升子代成为祖先前，preservation probe 对该谱系已知已解集重采样；延迟候选以完整 avg@k 确认。开销是故意的：噪声 agent 基准上单次幸运 rollout 可伪装为能力增益（文中引用 SWE-V 上 2.2–6.0 点的 pass@1 随机摆动作动机）。失败模式分类器为每次试验打标（timeout-setup、wrong-output、tool-error 等）并聚合基准级主题；共享记忆按 Kg+1 = Agg(Kg, worked, regressed, themes) 更新，同时被 proposer 与 verifier 读取。主导主题注入促使搜索发明针对系统性瓶颈的全局能力（例：“setup 成本主导超时 → 构建高效 setup 能力”）而非逐任务补丁。

## 4. 实验结果

**评估阶梯设计**是本文的方法学贡献之一：四个基准按“进化信号与测试的分离度”递增排列，用以区分“学到可迁移的 harness 行为”与“优化了评估集本身”。RQ1 TB2.1 同域（冻结 GPT-5.5，89 个 verifier 任务上进化：avg@3 旋转子集筛查、avg@5 全套确认，报告官方 avg@5）；RQ2 TerminalWorld held-out（冻结 Opus 4.8，94 个训练任务上进化后冻结，41 个不相交 held-out 任务单次 pass@1）；RQ3 WAI 合成到真实（冻结 GPT-5.5，300 条合成意图上以 LLM judge 信号进化，报告 1,260 个真实任务的确定性 pass@1）；RQ4 TB2.1→SWE-bench Verified 跨基准迁移（冻结 Opus 4.8，500 题官方测试 pass@1）。主对比一律 matched-model（同冻结基模型、同任务、同 verifier，仅 harness 不同）；公开榜单行使用不同模型与力度，只作情境不作控制。TB2.1 上环内从不消费基准参考解，唯一监督是任务级 verifier 结果加 agent 自产轨迹，因此 harness 无法编码答案、只能改变 agent 的工作方式。

## 5. 消融要点

**技能包 diff。** 进化谱系相对 base Monet 新增 7 个 harness 技能，全部属于单一“验证/工件契约”家族：verifier-contract / contract-candidate（finalize 前推导任务验收契约并对照检查）、graded-artifact-final-check / artifact-verification-loop（验证被评分工件——输出文件、格式、数值——并迭代修复-复查）、real-tool-artifact / tool-grounded-artifact（把输出锚定在真实工具执行而非断言或模拟结果）、security-contract-repair（对照安全与契约检查修复解）。无一注入领域知识。作者明确这是**共选择下的组合归因**，非逐技能因果隔离（技能未被独立随机化）。

**增益落点与保存行为。** 增益精确落在冻结基模型余量最大处：ML/科学计算 +14.8（60.1→74.9）与数据/数据库 +13.8（83.9→97.8），其难度是过程性的（长依赖安装、环境 setup、输出验证、多步工具使用）而非知识性的；基线已强的簇基本不动（系统管理 92→98、安全 85→84，在逐任务噪声带内），无任何簇回归超噪声——这是 preserve-and-extend 契约的经验足迹。配对测量的 88 个任务上：36 升 / 43 平 / 9 降；以 10 点变化为阈值则是 30 升对 6 降。

**跨基准交叉验证。** WAI 上新增的是同族技能（状态/动作契约），confirmed invalid 从 23.5% 降至 1.4% 的同时 audit-clean pass@1 升 49.5 点；TW 上机制则是种群多样性而非单技能。作者将 verification-before-finalization 与 contract-aware tool use 提为跨基准的 plausible 共享机制，并指出两个层面执行同一纪律：先陈述验收条件、提交前对照检查——agent 对其输出如此，搜索对其变体也如此。

**自陈局限。** 实验评估的是完整系统：archive、父选择器、合并算子、推理力度均未独立随机化，matched 增量支持系统级 harness 主张，任何单一算子的贡献仍是 plausible 而非因果；重组相对单谱系变异的贡献需受控消融；TW 仅 41 个 held-out 任务；SWE-V 迁移带窄（80.8–84.2）；WAI 的行为学共同改善不排除 runtime 守卫与 harness 编辑双因素叠加；静态+LLM 审计强于关键词启发式但非形式化沙箱。

## 6. 贡献与启示

三点贡献：（1）把自进化重构为 harness 上的种群选择——preserve-and-extend 契约晋升有界回归的赢面，档案保留替代谱系供继承与重组；（2）把 failure / teacher / self 三类证据统一到单一 harness 级编辑接口，均不触碰权重；（3）四档递进分离度的评估体系 + 组合归因消融，把“学到什么”与“优化了什么”显式拆开。

方法学上，本文对噪声的处理姿态是“校准每个决策需要多少证据”而非消噪：有界下行赢面可成为祖先、严格 avg@k 确认才可作为结果、已解集上的保存检查约束晋升代价——并显式接驳 bandits/racing/successive-halving 的评估分配传统。工程上三个含义值得音视频侧注意。其一，**harness 是可审计资产**：每次晋升留下人可读的 diff 与其依据证据并排（WAI 的技能表与 prompt 对照表即该记录），这是权重空间自改进放弃的监督原语。其二，**harness 可能跨基模型代际摊销**：同一选择程序已跑过 GPT-5.5、GPT-5.6 Sol、Opus 4.8，跨基模型迁移（GPT 基上选出的 harness 直接跑 Opus 基）已发生一次；模型换代远快于脚手架重写，暖档案重选择的成本问题是开放的廉价实验。其三，**preservation probe 可作策略接口**：有界回归读作“对既往正确行为的回归上界”，探针集不必是基准任务，可换成任何合规/运维要求，把运营方约束变成选择约束而非事后过滤。部署边界（附录 E）：生产任务少有 verifier，且 avg@k 每候选每任务 k 次 rollout 的成本只适合周期性离线作业——推荐“对刷新的代理套件离线进化、部署所选 harness”而非在线自改；WAI 的结果（进化从未见过真实任务）支持维护代理套件的可行性。

**与音视频技术的上下游关联（本笔记解读，非论文主张）。** 本文进化的终端/浏览器 agent 能力族与音视频工程的自动化痛点直接同构：转码流水线搭建、编解码一致性与合规测试跑批、集群编码任务运维、基于 ffprobe/媒体检签的质检脚本，其失败模式（长依赖安装、环境 setup、输出验证、多步工具链）正是 TB2.1 上增益最大的两个簇的过程性难度。“验证/工件契约”技能族可直译为媒体 QA 门禁：encode→decode→checksum 回环验证、客观质量指标（PSNR/VMAF 类）达标后再 finalize、以 ffprobe 等真实探测输出替代 agent 断言的结果。更结构性地，音视频领域天然富集**确定性 verifier**（一致性测试套件、解码校验和、延迟/质量 SLO），恰是 preserve-and-extend 选择最适配的适应度源——“无 gold、只有 verifier 即可把评估算力转化为持久能力”这一结论，对 verifier 密集而标注稀缺的媒体工程场景是最有利的前提。TB2.1→SWE-V 的零反馈迁移则暗示：在通用终端任务上进化出的 harness 可望直接接入媒体 CI 流水线。WAI 的两阶段机制级审计（JS 去混淆 + 评分字段污点追踪 + 独立 LLM 裁判）对会直接写文件、改状态的媒体处理 agent 是可复用的反作弊范式。

## 7. 与其他论文的联系

- **FGSE（arxiv:2611.14326，证伪门控自进化）**：同为对抗自进化噪声/运气的“门控”路线——DarwinX 用 avg@k 确认加 preservation probe 门控档案节点的晋升，FGSE 用三类探针证伪后才允许经验教训写入记忆。门控对象不同（harness 编辑对记忆条目），但共享“候选改进须作为可证伪假设经复核才可固化”的机制立场，且二者可嵌套组合（记忆门控内嵌于 harness 进化环）。
- **TRUST（arxiv:2611.10787，带统计保证的可信递归自改进）**：DarwinX 承认其统计处理止于启发式——TW 上 McNemar p = 1.0 / 0.45 仅 suggestive，并以 SWE-V 2.2–6.0 点随机摆动为噪声动机；TRUST 以在线多重假设检验控制错误进化率并提供统计保证，正是 DarwinX 两速度确认所缺的形式化层，可直接加固其 promote/probe 决策。
- **SkillDuet（arxiv:2611.12109，模型与技能共演化）**：DarwinX 附录 E 明确设想 harness 选择与权重更新的耦合（档案天然是 verifier 认可的新解任务课程生成器；建议交替冻结一层以保归因），但未评估；SkillDuet 以响应反馈实现外部技能库与 LLM 参数的协同演化，是该设想的一个实例化，也正对应 DarwinX 指出的“两层同动则保存探针无法定位成因”的归因代价问题。
- **LongCapHarness（arxiv:2611.10463，能力导向的自动挂接）**：同一“模型冻结、harness 为可学习面、免数据合成与后训练”命题在长上下文推理域的单点实例（HELMET/RULER 超基线且成本低于基线 50%）；DarwinX 提供的是种群级通用选择框架，LongCapHarness 可视为其域特化对照，共同支持“harness 层增益可跨能力域复现”的外推。
- **InfraRSI（arxiv:2611.11558，训练基础设施递归自改进）**：域重叠——终端环境下的分布式训练基础设施优化 agent；DarwinX 在 TB2.1 上进化出的 setup/验证/多步工具技能族正是此类 infra agent 依赖的过程性能力，两者共享“批 rollout-反思-有界编辑-门控”内环，且 DarwinX 的 TB2.1→SWE-V 迁移为这类 agent 的跨任务泛化上限提供了参照。
- **TrainExplorer（arxiv:2611.20430，规划-解耦的自主后训练）**：权重轴（自主后训练）与 harness 轴的互补对应物；DarwinX 附录 E 划出两层自改进空间并指出耦合方向与代价，TrainExplorer 的策略规划与执行解耦是权重侧的自动化对应，两者合起来恰好覆盖该空间的两个正交维度。
