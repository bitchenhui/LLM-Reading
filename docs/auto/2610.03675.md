# FrugalEvo: Towards Cost-Aware LLM-Guided Program Evolution

> Hui Chen, Xuan Qi, James Xu Zhao, Zhaopeng Feng, Shilong Liu, Kuang Xu, Pang Wei Koh, Bryan Hooi. *arXiv:2610.03675v1 (2026-10-02)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

LLM 引导的进化程序搜索沿 FunSearch → AlphaEvolve → OpenEvolve / ShinkaEvolve → AdaEvolve / EvoX / 多智能体方法（SwarmResearch、CORAL）一路演化，其标准范式是：维护程序池，选父本、提示 LLM 变异、评估器打分、回填数据库；性能以固定迭代数（或 LLM 调用数/评估器调用数）后的最终得分衡量。论文的核心批评指向这个评价口径：在 test-time scaling 普遍成立的当下，“固定迭代数下的性能”把性能与开销混为一谈——更高的分数可能只是更高的花费（API 费、LLM 推理 GPU 费、评估器 CPU/GPU 费）。作者主张把目标从“每次迭代的增益”改写为“每单位成本的增益”，即在固定成本预算 B 下最大化历史最优得分 s*。

第二个动机是模型能力的非对称分配。现有方法用单一（通常是强且贵的）模型同时承担“算法策略构思”与“代码实现+修错”两类工作，而后者调用次数多、输出 token 长、但认知密度低——用旗舰模型做实现是对预算的浪费；反之，弱模型做策略探索又识别不出有前景的机制。第三个动机是提示缓存（prompt caching）这一被进化框架忽视的降本杠杆：支持前缀缓存的 API 对重复前缀的 KV 状态按折扣计费，但现有进化框架的提示构造方式导致前缀高度漂移，缓存基本失效。

围绕这三点，论文提出 FrugalEvo（强模型探索策略 + 弱模型实现精化 + 缓存高效的进化过程），并引入 Budget-Aware AUC（BA-AUC）作为预算内解质量的过程性度量。就其自身领域（LLM 进化搜索/自动化算法发现）的标准看，这是把“评估口径”本身当作贡献点的工作：先重构问题定义（预算约束下的优化），再给方法与度量。

## 2. 方法总览

**形式化**：评估器 E(x) = (s(x), a(x))，s 为任务得分、a 为辅助反馈；初始程序 x₀ 经评估后初始化数据库 D₀。第 t 轮由搜索策略构造上下文 C_S(D_t)（任务描述与分析 + 父本 + 采样参考程序及其评估结果 + 历史尝试摘要），LLM 生成候选 x_{t+1} ~ G(·|C_S(D_t))，评估后并入 D_{t+1}。优化目标改为**预算约束下**数据库内最大得分。

**BA-AUC**：令 q(c) 为累计 LLM 成本 c 处的 best-so-far 得分，BA-AUC(B) = ∫₀^B q(c) dc。为使不同方法在同一区间 [0, B] 可比：运行提前结束则将 best-so-far 得分保持到 B（补平），超出 B 则截断。这把“最终得分”与“到达该得分的成本路径”压缩为单一标量，直接惩罚“先烧钱后见效”的轨迹。

**框架**：六组件闭环——(1) 冷启动：低成本低模型把初始程序爬坡到停滞，产出初始 incumbent；(2) 上下文构造器：开场用高成本 LLM 对任务描述与评估器代码做一次性分析（识别优化目标与评估约束），随后持续把最新 incumbent、尝试过的程序/策略/失败反馈并入上下文；(3) 策略探索器（高成本 LLM）：单次 API 调用提出 K 条设计策略；(4) 解生成器（低成本 LLM）：先每策略一次试实现并按得分排序，再按排序做迭代精化；(5) 评估器；(6) 搜索记忆：island-based MAP-Elites 维护多样性，同时记录策略史与失败反馈。循环直到剩余预算不足以覆盖下一次 LLM 调用，返回最优程序。

整体可概括为一条设计原则：**把稀缺的强模型推理集中在“每 token 信息量最高”的策略层，把高频的实现调用交给廉价模型，并通过提示布局把整条进化管线变成缓存友好的**。

## 3. 关键设计

### 3.1 冷启动与一次性任务分析

策略探索器的输入是父本程序；用弱初始程序做父本会产生低质量策略、浪费预算。冷启动阶段由低成本 LLM 迭代精化初始程序直至得分不再提升（算法中为 COLDSTARTANDCHEAPCLIMB，带开跑上限 N₀、连续无效上限 F、容差 ε），最优者成为初始 incumbent。ANALYZEONCE 用高成本 LLM 对任务与评估器做一次分析并将结果缓存复用——这同时是质量措施（策略提示获得评估器感知的引导）与缓存措施（分析结果进入所有后续提示的稳定前缀）。

### 3.2 策略探索器的“策略契约”

策略提示规定每条策略必须包含四要素：**机制族**（mechanism family 的短标识）、**替换范围**（替换哪个函数/阶段/块）、**计算预算**（额外计算的显式上限）、**增益机制**（针对的瓶颈或引入的新自由度），并以“增益检查”（有依据的得分估计或绑定到具体新机制的可检验假设）收尾；明确禁止把随机种子、容差、迭代次数层面的变化当作“不同策略”，禁止把 fallback / accept-only-if-better 规则当作改进证据。K ≥ 3 时强制覆盖局部精化、子系统替换、结构探索三类机制，并要求利用先前结果避免重复已穷尽的思路。这些约束直接针对进化搜索的两大失效模式：伪多样性（参数级抖动）与不可检验的“乐观叙事”。探索器还可按需返回一个完整可执行的组合参考程序（portfolio reference），作为不隶属于任何策略的独立候选，评估后若改进则直接成为共享父本——相当于从一次昂贵调用里额外白拿一个候选。

### 3.3 试实现排序 + 顺序精化

Phase III（PARALLELTRIALS）对 K 条策略各做一次试实现（共享同一父本），按试实现得分稳定排序；Phase IV（SEQUENTIALIMPROVE）按排序逐策略精化：每轮锁定一条策略与当前 incumbent 为父本，最多 M 次顺序尝试，失败反馈逐次注入后续提示而父本不变；一旦某次尝试改进 incumbent，本轮结束、改进程序成为新 incumbent、**同一策略**开新一轮；若一轮全局改进 Δ ≤ ε 则切换下一策略。这个“父本不变 + 尾部追加反馈”的循环与缓存设计是协同的：M 次尝试共享同一长程序前缀，反馈以追加方式放在提示尾部（实现提示明确要求“先前尝试不替换父本作为编辑目标”），前缀命中率随尝试次数线性积累。实现提示本身是一份弱模型可靠性规约：忠实实现指定机制、删除被取代的代码、不得替换成无关想法/仅做表面改动/再附加一条完整流水线、机制必须在正常返回路径上执行、计算量不得超过策略预算、若父本已实现该机制则精化而非复制、试实现阶段输出“能够跑通该机制 distinctive 部分的最小可执行版本”、超时则削减工作量但保住增益机制、SEARCH/REPLACE 块须从当前父本精确拷贝。

### 3.4 缓存友好的提示布局与计费结构

提示按变化频率分层排布：固定内容（任务指令、输出要求）在最前，其次是低频变化内容（上下文示例，island 最优与精英程序排在随机采样程序之前），最后是高频变化信息；每次尝试的反馈追加到提示末尾。论文附录给出计费表（2026-09-04 自 OpenAI/OpenRouter，美元/百万 token）：

| 模型 | 输入 | 输出 | 缓存读 | 缓存写 |
|---|---|---|---|---|
| GPT-5.6-Terra | 2.00 | 12.00 | 0.20 | 2.50 |
| GPT-5.6-Luna | 0.20 | 1.20 | 0.02 | 0.25 |
| GLM-5.3 | 1.15 | 3.50 | 0.10 | — |

笔记分析（基于该表的推断，非论文原文）：Terra 缓存读为输入价的 10%（0.20 vs 2.00）且**缓存写带 25% 溢价**（2.50 vs 2.00），意味着前缀一旦漂移就是净亏损——分层布局的本质是最大化“每次写入的读取次数”；同时 Terra 输出价 12.00 vs Luna 1.20（10 倍），把长输出的代码生成移到 Luna 是输出侧的量级降本，这与消融中“仅用强模型时均值掉得最多、因为实现调用吃掉预算”的发现互为印证。

### 3.5 搜索记忆

island-based MAP-Elites 维护程序多样性；策略史 H 记录每条策略的尝试结果与全局改进量 Δ，与失败反馈一起回流到下一轮策略提示（“避免重复已穷尽的思路”），构成策略层的负知识积累。

三条结论：(1) **模型协作**——全强模型均值掉幅最大（Signal Processing 从 0.77791 跌到 0.68534），作者归因于实现调用吃掉预算、留给探索的份额不足；全弱模型则压低最优解（0.75973），归因于弱模型识别不出有前景的策略。即“强模型定价的是策略选择质量，弱模型定价的是实现吞吐”，二者不可互换。(2) **冷启动**——去掉后两任务均值与最优同时下降，说明先用低成本模型把父本抬到可用水平是策略探索的高杠杆前置投资。(3) **顺序反馈**——去掉后均值下降且跨运行标准差增大（与实现提示中“不重复失败补丁、用评估指标修错”的机制对应），反馈链既是效果项也是稳定性项。值得注意的是 Circle Packing 上各消融的最优值多为 2.635983（即基线可达水平），说明均值差距主要来自搜索效率而非上限。

## 6. 贡献与启示

**贡献**：(1) 把 LLM 进化搜索的评价从“固定迭代数的性能”重构为“固定预算下的性能轨迹”，BA-AUC（含补平/截断约定）是可直接复用的协议；(2) 强/弱模型按“策略—实现”切分的非对称分配，配合冷启动、试实现排序、父本固定的顺序精化，构成一套可复制的成本感知 harness；(3) 提示分层布局 + 尾部追加反馈，把进化循环本身改造成前缀缓存友好的——在带缓存写溢价的计费结构下这是必要条件而非锦上添花；(4) 在 $0.55–$2 量级预算上于 Circle Packing 等任务追平/超越 AlphaEvolve 报告值与约 $50 的多智能体方法。

**对音视频技术的上下游关联**（笔记视角）：其一，ADRS 任务族本身就是 LLM/VLM 推理服务层优化——PRISM 是 GPU 上模型放置、目标为最小化 SLO 加权请求负载对 KV-cache 剩余内存之比的最大值；EPLB 是 MoE 专家复制与放置（主流开源 VLM 多为 MoE，直接影响流式多模态服务的吞吐与首包延迟）；LLM-SQL 是最大化共享前缀缓存命中的序列化顺序——这些正是承载视频理解、字幕/弹幕生成、多模态 Agent 的推理集群所依赖的问题，FrugalEvo 表明此类系统算法可在 $1 级预算内自动进化得到。其二，“固定头 + 低频段 + 高频尾”的提示布局对任何多轮音视频 Agent 管线（逐帧/逐片段携带稳定系统提示、仅尾部变化）是同构可迁移的降本手段。其三，Signal Processing 任务进化出的滤波器组合与音视频降噪/后处理链路搜索同源；只要评估器可自动执行（VMAF/PSNR/延迟/卡顿率等客观指标），cost-aware evolution 范式可平移到编码器模式决策、码控与流调度策略搜索（此为迁移推断，非论文内容）。

**局限**（论文自述）：方法要求候选的生成与评估完全在代码环境内自动完成，不适用于需湿实验等物理世界交互的科学领域；策略探索指令为人工设计、未按任务自动生成。笔记补充两点观察：BA-AUC 的量纲是“得分×美元”，其绝对值随任务得分尺度变化，只支持任务内横向比较；基线均为单模型配置，框架效应与模型对效应有耦合，但 Terra+Terra / Luna+Luna 消融基本封住了这个口子。

## 7. 与其他论文的联系

- **paper:arxiv:2611.08483（SwarmEvolve）**：同属“低成本化 LLM 进化搜索”轴线，且都以 KV 缓存为核心杠杆，但用法相反——SwarmEvolve 把 KV 缓存共享作为蜂群智能体间的信息传递介质以提速进化，FrugalEvo 把前缀缓存当作 API 计费折扣对象以压低单位成本；FrugalEvo 文中对同族多智能体基线（SwarmResearch、CORAL，均约 $50）在 Circle Packing 上的成本对比（$0.55 追平），构成对“堆智能体换性能”路线的直接质疑，也预示了与 SwarmEvolve 这类低成本蜂群路线的正面竞争点：BA-AUC 口径下谁的成本轨迹更优。
- **paper:arxiv:2611.14844（AutoAssumption）**：领域重叠在“LLM 自动发现系统层算法”——AutoAssumption 搜索 KV 缓存驱逐与剪枝算法，FrugalEvo 的 ADRS 任务族（PRISM 涉及 KV-cache 压力、EPLB 涉及 MoE 专家放置）是同类推理系统优化对象。机制对比鲜明：AutoAssumption 用 Lean 证明图显式化假设、搜索放宽后重推导，依赖形式化约束；FrugalEvo 依赖自动评估器打分 + 成本预算硬约束，无形式验证。可视为“形式化假设空间搜索”与“评估器驱动进化”在同一问题域的两条路线，前者的可证性与后者的低成本互补。
- **paper:arxiv:2610.08483（Agentic Algorithm Design）**：共同点是对“进化产物的计算成本”施加显式约束——FrugalEvo 的策略契约强制每条策略声明 compute budget，靠运行时评估兜底；该文在 Lean 中机器检验期望运行时间界，无需经验比较。软约束（提示级+评估器）对硬约束（证明级）的对照，直接可比。
- **paper:arxiv:2610.35077（VLM 图表分析自主进化）**：同属 AlphaEvolve 式“冻结大模型、进化外围推理程序”的应用范式；其报告口径为精确匹配率 16.6%→41.3% 且快 3.8 倍——已开始同时报告速度，但仍是“性能+单一速度比”的离散表述，FrugalEvo 的 BA-AUC 恰好提供把这类权衡统一为预算内积分度量的口径，是该工作评价体系的直接补强方向。
- **paper:arxiv:2610.24970（PRECOCIAL）**：同属 FunSearch/AlphaEvolve 谱系（其自比超越 FunSearch/AlphaEvolve），但成本发生阶段不同——PRECOCIAL 优化合成数据生成程序以减少 9–33% 微调步数（训练侧成本），FrugalEvo 优化推理侧 API 成本；两者共同印证“按成本而非迭代数/步数计量进化收益”正在成为该谱系的共识性转向。
- **paper:arxiv:2611.14326（FGSE）**：方法学上的远亲——FrugalEvo 的搜索记忆记录失败反馈并在策略提示中注入“避免重复已穷尽思路”，FGSE 则把经验教训作为可证伪假设经三类探针验证后才写入记忆。二者同处“失败/经验信息如何进入记忆并影响后续搜索”的问题空间，差异在 FrugalEvo 以评估器结果为准、无证伪门控，FGSE 以验证门控换取更新安全性。
