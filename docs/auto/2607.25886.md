## 1. 背景与动机

递归自我改进（RSI）要求系统反复“把关于模型失败的证据转化为有效的模型改进”。在 post-training 语境下，这条链路中最可自动化、也最少被单独评测的一环是数据中心研究：形成能力缺口假设 → 设计并验证训练数据策略 → 从 checkpoint 证据中修订策略。论文将承担该闭环的 LLM agent 称为 data-centric researcher agent，核心研究问题是：前沿 LLM agent 能否可靠地自动化这一研究过程。

作者指出现有基准的两难格局：DataComp / DataComp-LM 一系控制了学习栈但只考固定候选池上的数据选择；DataEnvGym、Curation-Bench 引入学生模型/基准反馈形成闭环，但未隔离研究决策本身；PostTrainBench、Agent2 RL-Bench 把数据、优化、超参、实现的控制权整体交给 agent，研究能力与基建、服务、评测、系统实现纠缠，性能差异无法归因。RSIBench-Data 取中间立场：固定目标模型、有界训练接口、共享 train/serve 服务、沙箱化官方评测与预算，只放开“训练数据策略”这一个研究自由度。按论文的协议级对比（六项标准：可执行经验合成、可复用数据合成策略、能力缺口诊断、反馈驱动修订、训练/评测数据隔离、服务隔离的 train/serve/eval），RSIBench-Data 是唯一全项达标的基准。

动机上的关键区分：RSIBench-Data 评测的是迭代式训练数据研究过程，而非一次性 imitation 式数据集生成——官方分只落在最终选中的 checkpoint 上，但全过程（假设、策略、修订、选点）被结构化记录以支持归因与诊断，不设主观过程分。

## 2. 方法总览

形式化：固定基座 M0、基准证据 S、资源预算 C。研究者策略 π 在第 t 轮观察 S 与尝试历史 H<t，提交训练数据 D_t 与白名单训练配置 c_t：(D_t, c_t) = π(S, H<t)；M_t = Train(M0, D_t; c_t)。每个 M_t 由固定评测服务给出“允许的选择反馈” h_t = Eval_sel(M_t)，含分数、任务轨迹、verifier 结果、执行/基础设施错误、token 用量、训练与采样成本、耗时。agent 在预算内决定修订或停止；T 次尝试后仅凭 H_T（未见官方结果）选出 M_t*，官方评测 s_off(π) = Eval_off(M_t*)，并报告相对基座的 Δ_off。

两条归因隔离贯穿设计：其一，agent 只通过有界接口修改训练经验（数据加白名单配置），不得替换优化后端、服务路径、评测沙箱、verifier 与打分规则，提交的是训练工件而非训练代码；其二，迭代与最终选点只使用 selection feedback，不接触官方结果。注意口径：由于白名单内配置可变，论文的比较对象是“经共享有界接口体现的数据中心研究”，而非完全冻结训练配方下的纯数据变量。

实例化为 4×6 受控矩阵：研究员 agent（Claude Code Opus-4.8 / Claude Code Sonnet-5，high effort；Codex gpt-5.6-sol / gpt-5.6-terra，max effort）× 目标基准（SWE-bench Verified / Multilingual / Pro、Terminal-Bench 2.0、GPQA Diamond、AIME 2026）；目标模型固定为 Qwen/Qwen3.5-35B-A3B-Base，经共享 Tinker 后端做 LoRA SFT；rollout 模型（生成推理轨迹/工具序列/完整轨迹供数据构造）固定为 Claude Opus 4.8；每 run 名义预算 16 小时墙钟 + $500 Tinker。SWE 三变体统一用 Mini-SWE-Agent 作评测 runner，其余用 Terminus-2；SWE 变体与 GPQA 用固定 100 题子集（对原集覆盖率分别为 20.0% / 33.3% / 13.7% / 50.5%），Terminal-Bench 2.0 用全量 89 题，AIME 2026 用全量 30 题、每题 4 次解码。

## 3. 关键设计

**固定基础设施与服务边界。** agent 提交 message-format 监督数据加白名单训练配置；runner 校验工件后从固定基座调用同一 Tinker LoRA SFT 后端训练，checkpoint 经同一 sampler 接口供评测方查询，执行交给 Harbor 在 E2B 沙箱内完成（benchmark 环境、runner、verifier、打分规则归服务所有）。由此每次尝试走完全相同的“提交数据→训练→服务→评测”路径，并留下链接“数据策略↔checkpoint↔评测行为”的结构化记录——这是可审计性与归因能力的机制来源：优化、服务、评测对所有 agent 逐比特一致，自由度只剩提交的数据分布与白名单内配置。

**输入与数据完整性约束。** agent 获得目标基准描述与成功标准、任务匹配的公开种子仓库/种子样本、工具与环境 schema、可用基座诊断、预算契约，构成 S 但不含现成训练语料。种子仓库的作用是锚定目标分布（SWE 三变体可用 SWE-smith、SWE-Gym、swe-factory；TB 用 endless-terminals、tmax；GPQA/AIME 用 synthetic-data-kit），防止合成坍缩为与真实任务脱节的规则样本。每个基准显式规定哪些种子/公开源可用于构造数据；评测专用任务、标签、轨迹等受保护材料不得作为监督——允许“用评测信息诊断失败”，禁止“把评测信息转成训练数据”。

**闭环内动作空间完全交给 agent。** 外环只固定顺序与服务边界；过滤、验证、课程设计、数据混合、失败归因、是否继续搜索都不是规定阶段而是策略选择。附录 B 的代表性动作空间包括：诊断下一个数据需求（按能力/错误类型/工具/交互长度组织失败，区分“上一数据集的预期教训”与“训练实际改变的行为”——同一总分下不同失败原因意味着不同修订方向）；合成定向经验（合成任务及可执行初始状态；成功/失败/恢复轨迹；监督表示粒度——完整轨迹、决策点、final action、批评、修复续写及混合，并可决定哪些消息计入 loss）；验证与组织（可执行环境校验、答案一致性、schema 校验、去重，长轨迹的截断/压缩/重构，难度估计、课程与 mixture）；修订与搜索管理（换源、收放覆盖、改表示、强化检查器、回滚、停止、最终选点——预算分配与选点同属一个迭代策略）。这实质是把“数据工程”升格为可审计的研究决策序列。

**选点协议。** 预算只约束总量，agent 自主分配；最终从已产 checkpoint 中选出一个后，才在目标基准测试集上以固定协议做独立官方评测。选点本身被论文明确识别为一项效率决策（见实验节）。

**设计自省（作者于 Discussion 承认）：** 每设置只取一次预指定的代表性 run；选点与官方评测使用同一任务子集，故测的是 fresh environment 表现而非统计 held-out 泛化；研究员身份捆绑底层 LLM、agent scaffold 与 reasoning effort，主矩阵比较的是完整研究员系统而非单一组件。

## 4. 实验结果

主结果关键行（官方分；基座行为未适配 Qwen3.5-35B-A3B-Base 同一切分同采样协议得分；加粗为该基准内最佳）：

| 基准 | 基座 | 最佳 agent（官方分） | 四 agent 极差 |
|---|---|---|---|
| SWE-bench Verified | 12.00% | **Claude Code Opus-4.8，46.00%** | 13.00 pp |
| SWE-bench Multilingual | 7.00% | **Claude Code Sonnet-5，22.00%** | 17.00 pp |
| SWE-bench Pro | 0.00% | **Codex gpt-5.6-sol，9.00%** | 8.00 pp |
| GPQA Diamond | 61.00% | **Codex gpt-5.6-sol，65.00%** | 13.00 pp |
| AIME 2026 | 30.00% | **Codex gpt-5.6-sol，53.33%** | 20.00 pp |
| Terminal-Bench 2.0 | 1.12% | **Codex gpt-5.6-sol，20.22%** | 14.60 pp |

要点与口径：

- **行级天花板低且呈共性**：最佳 agent 在 SWE-bench Pro 仅 9.00%、Multilingual 22.00%、Terminal-Bench 2.0 20.22%。训练还可能中性或有害：GPQA 上 Opus-4.8（56.00%）与 Sonnet-5（52.00%）低于基座 61.00%；Multilingual 上 Opus-4.8（5.00%）与 terra（6.00%）低于基座 7.00%。
- **无 agent 全面占优**：gpt-5.6-sol 领跑 4 项（Pro、GPQA、AIME、TB），但三项 SWE 任务分属三个不同 agent；极差从 8.00 pp（Pro）到 20.00 pp（AIME）。目标模型、接口、评测栈完全相同，故差距只能来自“研究员策略 × 基准结构”交互——宽任务族相似性不产生稳定排名。
- **资源剖面（24 个主 run）**：有效候选中位数 4.5 个（范围 2–15），有效候选 Tinker 成本中位 $62.51（$4.80–$363.77），墙钟中位 6.55 h（1.14–14.91）。高分不必贵：terra 在 GPQA 1.14 h / $4.80 得 64.00%，sol 2.42 h / $10.37 得 65.00%；低分可很贵：Sonnet-5 在 TB 8.87 h / $156.93 仅 5.62%，sol 在 Pro 花 $300.49 得 9.00%。官方分必须与搜索成本联合解读。
- **迭代有效性**：14/24（58.33%）设置中后续有效候选超过首个有效候选；其余 10 个设置首选即最佳。
- **迭代可靠性（核心发现）**：23 个达峰后继续搜索的设置中，18 个（78.26%）以低于历史峰值的最终尝试收尾，其余 5 个仅回到同一峰值——无一个案达峰后再创新高。历史最优选点可保住早中期发现，但反馈驱动的修订大多无法刷新候选前沿。
- **迭代价值强依赖基准与 headroom**：AIME 上 4 个 agent 中 3 个改进，首选→最佳增益中位 25.42 pp（Sonnet-5 前 8 个有效候选选择分 ≤15.00%，第 9 个跳至 55.00%、第 10 个 55.83%；terra 首选即最佳）；GPQA 起点前沿高（56.00–65.00%），中位增益仅 4.00 pp，但四个 agent 都刷新过首选分数。
- **选点 vs 官方**：12 个 GPQA/AIME/TB 设置全部选中取得历史最优选择分的 checkpoint（选择规则未漏掉已测前沿），但选择峰值与官方分平均差 3.89 pp（Sonnet-5 GPQA 64.00→52.00；sol AIME 48.33→53.33；sol TB 15.73→20.22）。效率上，TB 各 run 在首次达峰后又投入 $23.79–$96.74 而未刷新前沿——停止与选点决定搜索开销能否兑现为最优已发现模型。

## 5. 消融要点

论文无传统因子消融，最接近消融的是三项受控分析。

**（1）推理努力诊断**（SWE-bench Verified，Claude Code Sonnet-5，high vs max；固定 rollout 模型、目标模型、子集、预算与训练评测管线）。max 把前四个可比尝试的平均选择分从 35.5% 提到 44.0%，首候选 25%→36%，历史最优 44%→49%，官方 35%→52%（作者注明单 run 差异不作完全隔离的因果估计）。机制上是深度–广度权衡：max 少完成一个有效尝试，但所选数据集显著更大——149 vs 50 条训练记录、2,681 vs 595 个可训练 assistant turn、候选环 Tinker 成本 $401.70 vs $181.70。结论：effort 应被视为改变数据研究策略的研究变量（更早找到更强候选、构造更重的数据程序），而非仅是 agent 侧额外算力。

**（2）跨案例机制**（对每次尝试按“诊断的能力缺口/数据源/验证信号/监督形式”编码后与分数对照；论文明确为过程级观察、非单因子因果）：① 诊断真实能力缺口——AIME 晚跳案例提示 agent 应识别“局部修订未改变有效数据策略”并转向质变的能力假设；② 嵌入验证信号——AIME 用答案一致性过滤、Pro 用环境成功轨迹、TB 用沙箱执行显式任务结果，即可执行/可判定检查优于模型自判；③ 监督与目标行为对齐——Pro 上合成 finish 动作监督回退到 7.00%，真实成功轨迹中的提交行为达 9.00% 并被选中送官方评测；Verified 上 final-action 数据选择分 39.00%，而 all-turn 与 safe 变体仅 8.00% / 9.00%；TB 上聚焦候选 15.73%，后续 stop 导向修改回退 13.48%；④ 保留历史最优——继续搜索与显式停止/回滚策略需并存。

**（3）早期 RSI 实验**（主矩阵外、同族探索）：Claude Code harness + kimi-k2.6 作研究员，目标为指令版 moonshotai/Kimi-K2.6（Tinker LoRA SFT），Mini-SWE-Agent 经 Harbor–E2B 在固定 100 题 SWE-bench Pro 子集评测（并发 64、200 步上限、32,768 上下文 / 28,671 prompt 上限 / 4,096 输出上限）；预算 20 h / $2,000，实用 12.3 h 与约 $738.69，共 7 次 LoRA 尝试：首轮将 1,500 条 SWE-smith 已解决轨迹转为完整 assistant–tool 对话、排 1,000 高学习率步，于 679 步中断未评测；缩短到 200 步得 8%，检查发现转换器丢失 tool-result 消息、监督畸形；改用 300 条 gold-patch 派生 SWE-Gym 轨迹并修复工具配对后，简洁轨迹 10%，更长多步轨迹配合更低学习率与 LoRA rank 达 21%；随后以 10 条未适配模型成功 rollout 作模仿数据，因覆盖过窄回落 16%；为检验训练本身是否具破坏性，构造 39-token 单样本、单步、rank 1、近零学习率的 no-op adapter，得 22% 并被选中；末轮回到 300 条 SWE-Gym 轨迹、命令批成 1,800 个规范工具对并将标识符从 bash:0 改为 functions.bash:n，得 21%。结论：合成数据管线确有演化（8%→21%），但所有 checkpoint 均低于 33% 的未适配模型参考——当目标已是能力较强的指令模型且基准为 agentic 任务时，当前研究员找不到改进性训练分布。

## 6. 贡献与启示

按本文自身领域（自动化 ML 研究 / agent 评测）标准评估：

- **评测对象的再定义**：把 post-training 数据合成形式化为可自动化的研究循环（能力假设 → 数据策略设计与验证 → checkpoint 证据学习 → 预算内候选管理），并给出首个在协议层同时强制“可执行经验合成、可复用数据策略、能力诊断、反馈修订、数据隔离、服务隔离”六项的基准。
- **归因基础设施**：共享 Tinker 训练/服务 + Harbor–E2B 官方评测 + 统一预算的服务边界，使分数差异可归因到数据研究策略；结构化留痕使“为何改进/为何回退”可事后分析——这部分的方法学价值不亚于排行榜本身。
- **核心实证贡献：discovery–reliability gap。** 发现能力已经出现（58.33% 设置迭代超过首试；AIME 晚跳、行为对齐监督、验证信号嵌入等机制可复述），可靠性缺失（78.26% 达峰后以更低分收尾，无一再创新高）。工程含义直接：RSI 系统必须把停止、回滚、checkpoint 保全做成一等策略，“继续搜索”默认不等于“继续改进”；报告 RSI 结果应同时给出搜索成本与候选轨迹，而非只报最终分。
- **局限（作者自述）**：单次代表性 run；选点与官方评测同子集（测新鲜环境而非 held-out 泛化，需重复试验、评测方私有切分与任务刷新）；研究员系统整体比较（LLM / scaffold / effort 捆绑）。

**与音视频技术的上下游关联（笔记视角外推，非论文主张）**：上游，该范式可直接迁移为多模态音视频 post-training 的数据研究评测——固定训练/服务/评测栈（类比固定口径的客观音质/画质评测 harness），只放开数据策略（合成音视频语料、增广与混合配方、难度课程），考察 agent 为 ASR / TTS / 视频理解模型做数据中心研究的能力；selection feedback 与 official eval 的分离对应开发集调参与正式主观/客观评测的分离。下游，音视频基础模型每次训练尝试的算力成本远高于文本 LoRA，本文“达峰后继续投入大多不刷新前沿（TB 各 run 达峰后 $23.79–$96.74 无效投入）”的量化结论对自动化数据闭环的预算控制是直接警示；TB 式“终端 + 沙箱 + verifier”评测形态也适合把 ffmpeg / 编解码 / 质量评估流水线封装为可复现的 agent 任务环境；“受控 LoRA API + 沙箱评测边界 + 策略↔checkpoint↔评测行为结构化留痕”的工程模板对多模态受控 post-training 实验同样成立。

## 7. 与其他论文的联系

- **Trustworthy Recursive Self-Improvement with Statistical Guarantees（TRUST）**：本文 78.26% 的达峰后回退正是 RSI 可靠性问题的量化呈现；TRUST 用在线多重假设检验控制 LLM agent 递归自改进的错误进化率并提供统计保证，直接对应本文 discovery–reliability gap 中 reliability 一侧的解法，可视为对本文核心发现的方法学回应。
- **RSI-Opt**：同为把 post-training 栈的某一组件交给 RSI agent 演化——RSI-Opt 由元智能体跨训练运行演化优化器策略与代码库，RSIBench-Data 则固定优化器、只放开数据策略；两者是对同一栈的正交分解，可在 RSIBench-Data 框架内构造“数据研究 vs 优化研究”的能力对照。
- **InfraRSI**：RSIBench-Data 在动机部分明确把 infra 研究列为需剥离的纠缠变量（固定 Tinker/Harbor/E2B 边界正是为此）；InfraRSI 走相反方向，把分布式训练基础设施优化交给 RSI 智能体。两者共同支撑“按组件拆解并单独评测 RSI 能力”的研究议程。
- **SkillDuet**：改进介质不同——SkillDuet 以响应反馈协同 LLM 参数更新与外部技能库演化（技能级递归自改进），本文在 SFT 数据分布层闭环；两者都依赖反馈驱动的协同演化，构成 RSI 干预落点（数据 vs 技能）的直接对照。
- **RSI-PDEbench**：同属 RSI agent 基准，但 RSI-PDEbench 评测端到端自改进智能体在 PDE 求解上的通过率与成本，RSIBench-Data 刻意隔离数据研究能力并固定外环；一个测系统整体收益、一个测研究环节能力，评测口径互补。
- **LongCapHarness**：以能力引导挂接长上下文推理、免数据合成与后训练即在 HELMET/RULER 超越基线且成本减半，恰是本文“能力缺口诊断”机制的非训练路线对照；本文数据显示训练数据路线在 AIME 上中位增益 25.42 pp 但强烈非单调，两条路线的可靠性—成本权衡值得在同一受控框架下对照。
- **WeightLoop**：同用实验反馈闭环，但干预介质是权重空间的有界参数编辑而非训练数据；与本文“数据分布 + 白名单配置”的有界接口在设计哲学上同源（有界干预 + 固定评测以保归因），构成 RSI 的两种最小干预接口。
- **TGR-EvoDAG**：工业级端到端推荐管线演化（DAG 多智能体代码演化），属于本文所批评的“变量全放开”极端——以研究/基建/服务纠缠换取端到端工程收益；作为音视频内容推荐侧的演化系统，与 RSIBench-Data 的受控归因哲学互为对照，也提示 RSI 评测需在“可归因”与“端到端收益”之间明示取舍。
