# A Streamable Neural Audio Codec with Residual Scalar-Vector Quantization for Real-Time Communication

> Xiao-Hang Jiang, Yang Ai, Rui-Chen Zheng, Zhen-Hua Ling. *arXiv:2504.06561v1 (2025-04-09)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

神经音频编解码器已在整体质量上超越 Opus/EVS 等传统方案，按编码对象分两支：波形域编码（SoundStream、Encodec、HiFi-Codec、AudioDec、DAC）直接在时域离散化波形，需要大量上/下采样卷积堆栈，复杂度高、效率低；频谱域编码中 APCodec 以双路结构并行编解码幅度谱与相位谱提升生成效率，作者团队此前的 MDCTCodec 进一步论证 MDCT 谱更适合神经音频编码，用单路结构与简化损失做到轻量高质量。

面向实时通信（RTC）场景，论文指出两个未解问题：
1) **因果性缺口**：多数神经编解码器采用非因果结构，延迟过高难以用于 RTC。SoundStream/Encodec 虽支持流式推理但质量与效率不满意；AudioDec 流式版依赖 HiFi-GAN 声码器，APCodec-S 依赖知识蒸馏，工程链路复杂。
2) **RVQ 码本坍缩**：以 MDCTCodec 为例，VQ 平均码本利用率（CUR）不足 30%，码本资源浪费严重，限制编码质量上限。

StreamCodec 的核心命题由此确定：在 MDCTCodec 基础上做全因果化（论文实测直接因果化会让 LibriTTS 1.5 kbps 上 ViSQOL 从 4.320 掉到 3.985），再用新量化器 RSVQ 把这个因果化质量缺口补回来，同时顺带解决码本坍缩。上下游定位清晰：这是面向 RTC/WebRTC 生态（传统由 Opus/EVS 占据的 20ms 级低延迟语音档位）的端到端神经编解码方案，token 输出形式又与语音大模型的 tokenizer 需求相邻。

## 2. 方法总览

整体流水线：波形 → MDCT 谱 → 因果编码器 → RSVQ → 因果解码器 → IMDCT → 波形。编码器与解码器完全对称、完全因果，不依赖任何未来帧信息。

**因果编解码器**：输入/输出端各一个 1D 因果卷积负责维度变换；中间为 8 个因果化 MCNX2（modified ConvNeXt v2，承自 APCodec/MDCTCodec）块 + 线性层 + 因果 1D 下采样卷积（降采样率 R）；解码器镜像，下采样卷积换成因果上采样反卷积。训练沿用 MDCTCodec 的 MDCT 域对抗训练策略，叠加本文针对码本的两项训练策略（见第 3 节）。

**RSVQ**：Ns 个标量量化器（SQ）在前、Nv 个改进矢量量化器（IVQ）在后，按残差串联：首个 SQ 消费编码器输出 z，后续量化器消费前一级的量化残差，最终量化结果 ẑ 为所有量化器输出之和。

**码率公式（式 4）**：bitrate = fs/(ws·R) · (Σᵢ Σ_b log₂ l_b⁽ⁱ⁾ + Σⱼ log₂ K⁽ʲ⁾)。实例化配置：Ns=1、Nv=2、D=32，ws=40、R=8（均继承 MDCTCodec）。由此可推得 token 帧率：16 kHz 下 16000/40/8 = 50 帧/秒，48 kHz 下 150 帧/秒。低码率档 SQ 取 B=5、各维级数均为 4（每帧 SQ 贡献 10 bit），两个 IVQ 各 K=1024（各 10 bit），合计 30 bit/帧 → 1.5 kbps；高码率档 SQ 取 B=6、级数 [11,11,10,10,10,9]（约 20 bit），合计约 40 bit/帧 → 约 2 kbps；48 kHz 下同 bit 数按 150 帧/秒得 4.5/6 kbps。IVQ 码向量维 M=32，Lbalancing 权重设为 1。

**算法延迟**：全因果意味着算法延迟即一帧 token 覆盖时长 ws·R = 320 采样，16 kHz 下 20 ms、48 kHz 下 6.67 ms，与论文对流式系统统一采用的固定评测延迟一致——延迟由结构参数直接决定，无前视项。

## 3. 关键设计

### 3.1 标量量化器：粗层搭轮廓

SQ 先用可训练权重 Ws∈R^{B×D} 降维到 B 维，再逐元素量化：对每维做 tanh 压缩（带偏移补偿）后取整，落到 [-1,1] 区间上 l_b 个等距实数构成的子集 S_b 上（式 1）。其中 h_b = 1.001·(l_b−1)/2、o_b = |l_b mod 2 − 1|/2：按定义，级数为偶数时 o_b=0.5（网格不含零点），奇数时 o_b=0（含零点），配合 1.001 的微扩因子保证取整结果严格落在等距格点上。整个码本是笛卡尔积 S=S₁×…×S_B，**不可训练**，共 ∏l_b 个 B 维向量。token 生成是把各维的级别索引按混合进制打包成单个整数（式 2，l₀=1）——工程上等价于定长位平面打包，**按构造不存在码本坍缩**。输出经 Us∈R^{D×B} 升回 D 维。设计血统明确：FSQ（Mentzer et al.）的有限标量量化思想 + squashed weight distribution 的 tanh 压缩取整。

### 3.2 改进矢量量化器：细层补细节

IVQ 结构上是经典 VQ：Wv∈R^{M×D} 变换后在可训练码本（K 个 M 维码向量）中做最近欧氏距离检索（式 3），Uv 升回 D 维。相对传统 VQ 的差异全部在**训练层面**，针对码本坍缩：(a) **码本聚类策略**（承自作者团队 ERVQ）：每个训练步强制重置非活跃码向量，并将其聚类到待量化的特征空间中；(b) **码本均衡损失** Lbalancing：后验码分布（以训练中各码被选频率近似）与均匀先验的交叉熵，权重 1。消融显示这两点把 VQ 的 CUR 从 20%–57% 区间拉到 100%，是利用率提升的主引擎。

### 3.3 粗细分工与因果化代价补偿

RSVQ 的分层原则：SQ 简单高效、天然满利用率，适合构建大颗粒轮廓；VQ 精度高、容量大，适合拟合细节残差。粗层 SQ 先把残差分布“整形”得更集中，细层 IVQ 再逐级拟合——消融证明这个次序不可交换，且 SQ 与 VQ 的利用率存在相互拉动效应（见第 5 节）。传输码流即 SQ 的混合进制整数位串加各 IVQ 的码索引，按式(4) 直接折算位率，全程不引入熵编码（最终位率效率 BE 达 98.5%，无损压缩的剩余空间本就不大）。

## 4. 实验结果

**设定**：LibriTTS 16 kHz（约 263 h，train-clean-100+360 训练、dev-clean 验证、test-clean 测试）；VCTK 48 kHz（约 43 h，100 人 40936 句训练、8 个未见说话人 2937 句测试）。对比项：非流式 DAC/APCodec/MDCTCodec，流式 Encodec/AudioDec/APCodec-S，以及作者自制的 MDCTCodec-S（把 MDCTCodec 直接全因果化，构成“只因果化、不换量化器”的关键对照）。流式系统统一固定延迟 16 kHz 20 ms、48 kHz 6.67 ms。指标 LSD/STOI/ViSQOL；效率在 Nvidia RTX 3090 与 Intel E5-2680 v3 CPU 上测 RTF，另报 FLOPs 与参数量。所有对比项基于开源代码复现。

要点：
- 全数据集、全码率下，StreamCodec 一致超过非流式 DAC 与 APCodec 的全部三项指标；与非流式 MDCTCodec 基本持平——16 kHz 两档略低（ViSQOL 差 0.019/0.041），48 kHz 4.5 kbps 反超全场（4.048 vs MDCTCodec 4.023），6 kbps 基本持平（4.176 vs 4.181）。
- **因果化代价与补偿的因果链**：1.5 kbps 上 MDCTCodec→MDCTCodec-S 掉 4.320→3.985，StreamCodec 靠 RSVQ 回到 4.301；按表内数字折算，0.335 的 ViSQOL 降幅被补回约 94%。APCodec-S 反而全线垫底，说明蒸馏辅助的流式化没有触及量化效率问题。
- AudioDec 的 STOI 明显异常（LibriTTS 1.5 kbps 仅 0.709），其 HiFi-GAN 级联路径的可懂度损失在流式阵营中突出。

## 5. 消融要点

**量化器组合消融（LibriTTS 1.5 kbps，表 III）：**

| # | 粗层 | 细层 | ViSQOL↑ | CUR/% (三个量化器) | BE/%↑ |
|---|---|---|---|---|---|
| 1 | SQ | IVQ+IVQ | 4.301 | 100/100/100 | 98.5 |
| 2 | SQ | SQ+SQ | 4.247 | 100/100/100 | 97.6 |
| 3 | IVQ | IVQ+IVQ | 4.090 | 100/100/100 | 96.5 |
| 4 | SQ | VQ+VQ | 4.172 | 43.75/51.95/57.12 | 87.8 |
| 5 | VQ | VQ+VQ | 3.985 | 20.80/15.72/21.67 | 74.4 |

- **分层有效性的直接证据**：作者将单 SQ、SQ+首 IVQ、SQ+两 IVQ 的量化输出分别送入解码器重建并分析频谱——SQ 单独解码只保留总体轮廓，同一音素的高频能量分布近似均匀、细节模糊；后续 IVQ 逐级恢复出不同频带上的可分辨纹理。这解释了“粗—细”分工的物理含义。
- **粗细次序不可交换**：#2（细层换 SQ）与 #3（粗层换 IVQ）的 ViSQOL 与 BE 均低于 #1，且两者 CUR 都是满的——说明损失来自量化器类型与层的错配，而非利用率问题。结论：标量适合粗量化，矢量适合细量化。
- **IVQ 训练策略是利用率主引擎**：#1→#4 仅去掉码本聚类与均衡损失，VQ 的 CUR 从 100% 掉到 43.75/51.95/57.12，ViSQOL 掉 0.13。#5（纯 RVQ）全面最差，CUR 15.72–21.67%，与论文开头对 MDCTCodec “平均利用率不足 30%”的诊断同量级，将 RSVQ 相对 RVQ 的优势同时定在质量与码本利用两个维度。
- **标量与矢量的相互依赖**：对比 #1 与 #4，VQ 利用率崩塌会反过来拖累 SQ 的 CUR（100→43.75）；对比 #4 与 #5，SQ 的存在又把首层 VQ 的 CUR 从 20.80 提到 43.75——粗层对残差分布的整形同时影响细层的学习难度，二者是耦合系统而非独立模块。

## 6. 贡献与启示

**贡献**：
1. 在 MDCTCodec 谱系内给出首个无需 HiFi-GAN 声码器、无需知识蒸馏辅助的全因果可流式神经编解码器，算法延迟固定为 20 ms（16 kHz）/6.67 ms（48 kHz）。
2. 提出 RSVQ：将 FSQ 式标量量化与改进 VQ 按残差次序混合，实现 100% CUR 与 98.5% BE，并把因果化质量缺口几乎补平（1.5 kbps ViSQOL 3.985→4.301，逼近非流式 4.320）。
3. 轻量高效：7.21M 参数、2.51 GFLOPs、CPU RTF 0.051（约 20× 实时），显著优于 Encodec/AudioDec/APCodec-S 的 CPU 路径。

**工程启示（音视频上下游）**：
- 对 RTC/会议系统：MDCT 单路结构同时回避了波形域的深层上采样堆栈与 APCodec 的双路相位估计，复杂度落到纯 CPU 可部署档位；20 ms 帧化延迟与 Opus 低延迟模式及主流 RTC 20ms 打包节奏对齐，具备替换传统编解码器的延迟资格；1.5–2 kbps（16 kHz）/4.5–6 kbps（48 kHz）覆盖窄带到全频带语音常规档位。
- 码流为定长结构（每帧 30/40 bit），按构造恒定码率，利于抖动缓冲与带宽估计；可变码率须走结构性路径（调 B、级数 l、K），而非熵编码。论文未涉及丢包隐藏与错误韧性，这是 RTC 落地尚缺的一环。
- 对下游 token 消费方：RSVQ 输出是异构三层流（1 个 SQ 标量 token + 2 个 VQ 索引），对 LM 建模不如平坦 RVQ/单码本友好；其价值主张在传输侧而非 LM 词表侧。流式全双工对话系统若采用，需另行处理 token 的 LM 适配。
- 局限（含论文自述）：进一步降码率与提升压缩性能列为未来工作；实验域限于语音（LibriTTS/VCTK），音乐/环境声未验证；16 kHz 下 LSD/STOI 仍略低于非流式 MDCTCodec，因果缺口未完全闭合。

## 7. 与其他论文的联系

- **UniStream (arXiv:2609.09866)**：同赛道直接对照——同为全因果流式神经编解码器且覆盖 48 kHz 语音/音乐/环境声。其扩容路径是多专家残差矢量量化（ME-RVQ），StreamCodec 则是标量+矢量混合的 RSVQ；两者共同出发点都是“因果结构导致量化容量与质量不足”，分别在码本结构与量化器类型上发力，可视为因果流式编解码的两条技术路线。
- **BAMU (arXiv:2608.08432)**：面向冻结预训练编解码器做 RVQ 深度的逐输入动态分配，在字节预算内提质量。与 StreamCodec 的固定层级（1 SQ + 2 IVQ）互补：RSVQ 证明层级“类型”重要，BAMU 证明深度“可分配”；二者结合指向 RTC 拥塞控制所需的可变码率流式编码。
- **Moshi (arXiv:2410.00037)**：实测约 200 ms 延迟的全双工语音对话基础模型，以神经编解码 token 做语音到语音生成。StreamCodec 的 20 ms 算法延迟与 CPU 约 20× 实时落在此类系统对 tokenizer/编解码回传的预算内，是低延迟 token 通道的合格候选；但其异构三层 token 流对 LM 建模不如平坦 RVQ 友好，直接接入有权衡。
- **LFSC (arXiv:2409.12117)**：以 1.89 kbps、21.5 fps 的低帧率设计换 LLM 语音推理约 3× 提速；StreamCodec 保持 50 fps（16 kHz）高保真并主打 RTC。二者共同刻画“帧率×码率×质量”三角中面向不同下游（LM 推理 vs 实时通信）的两个设计点。
- **Single-Codec (arXiv:2406.07422)**：以单码本单序列（304 bps）服务 LM 语音生成，与 RSVQ 的多层异构量化是相反的量化哲学；但两者共享同一痛点起点——多码本 RVQ 的利用率低下/坍缩与 token 序列冗余，可视为“修码本训练”（RSVQ+聚类+均衡损失，100% CUR）与“砍码本数量”（单码本）两种解法。
