## 1. 背景与动机

不完美信息博弈上的 MARL 进步，历史上高度依赖对算法基线的人工迭代打磨。以 CFR 家族为例，CFR+ 的 regret 下界截断与线性加权、DCFR 的正/负 regret 非对称折扣、PCFR+ 的预测式更新，都是研究者在巨大组合空间里凭直觉与试错选出的“数学上易处理”的启发式；PSRO 的元策略求解器同样长期停留在 Uniform/Nash/AlphaRank/PRD 等少数固定选项上。论文的核心动机：这类结构性选择（折扣方式、平均策略权重、元求解器调度）本质上是一个可程序化的设计空间，适合交给 LLM 驱动的进化编码智能体做语义级搜索，而非仅做超参数扫描。

作者将 AlphaEvolve（Gemini 2.5 Pro 为骨干）部署到 CFR 与 PSRO 两个范式上，得到 VAD-CFR 与 SHOR-PSRO 两个原始发现。但论文真正的重心在其后：进化智能体为最大化训练集 fitness 会叠加高度协同但过拟合的复杂机制（如 VAD 的波动率追踪），作者通过系统的 train-test 消融审计，把可泛化的“最小算法核”剥离出来，蒸馏为 WOP-CFR 与 PM-PSRO。这构成一条“LLM 提议—消融审计—人工蒸馏”的人机闭环方法论，是本文区别于以往 AutoML-Zero、符号化 RL 算法发现等工作（后者直接交付原始产物或仅做一次性手工简化）的关键增量。对音视频技术侧的读者而言，本文的价值主要不在博弈论本身，而在“LLM 程序进化 + 归因式消融蒸馏”这套管线范式——它与下游系统中用 LLM 搜索编码策略、KV 缓存驱逐、码率调度等问题的做法同源（见第 7 节）。

## 2. 方法总览

**搜索骨架。** 种群 P 以基线实现初始化（CFR 侧用 CFR+，PSRO 侧用 Uniform）；每代按 fitness 采样父代（AlphaEvolve 支持多目标，每轮随机选一个目标），父代源码连同提示 "Modify the following code to improve fitness (reduce exploitability)" 喂给 LLM 产生候选，候选在代理游戏上执行并按最终负可利用率 打分，有效者入种群循环。

**适应度设计。** 手选训练集 G_train（3 人 Kuhn Poker、2 人 Leduc、4 牌 Goofspiel、5 面 Liar's Dice），fitness 为 |G_train|+1 个分数：每个训练游戏 K 次迭代后最终策略的负 exploitability，加上其平均。CFR 取 K=1000，PSRO 取 K=100。

**可进化接口（搜索空间设计）。** 不让 LLM 从零写整个求解器，而是把算法抽取为固定签名的 Python 类：
- CFR：RegretAccumulator（瞬时反事实 regret 如何折扣/截断后累加）、PolicyFromRegretAccumulator（从累积 regret 导出当前策略的投影机制）、PolicyAccumulator（当前策略如何加权进入最终平均策略）。该空间足以覆盖全部已知 CFR 变体为特例（标准 CFR 即式 (1)(2)）。
- PSRO：TrainMetaStrategySolver 与 EvalMetaStrategySolver 两个完全解耦的类，前者决定 oracle 训练所针对的元策略，后者决定汇报 exploitability 用的元策略。解耦使 LLM 可自由探索训练/评估非对称调度。

**评测协议。** 全部基于 OpenSpiel，确定性算法、均匀初始策略、精确遍历博弈树计算 exploitability（无蒙特卡洛噪声）。主文测试集为 4 个更大更难的游戏（4 人 Kuhn、3 人 Leduc、5 牌 Goofspiel、6 面 Liar's Dice），附录给出 4 训练 + 14 测试的全 18 游戏扫描（2–4 人，信息集数 2 至 347,810，分支因子 1 至 66，五个游戏族）。

**审计与蒸馏。** 定义单游戏 log-improvement 分数 s_g = log10(Expl_raw) − log10(Expl_abl)：s_g>0 表示去掉该组件后可利用率反而更低（组件是过参数化的泛化惩罚），s_g<0 表示性能退化。跨游戏聚合用 IQM（截去上下 25%），并按 Train/Test/Total 三个切面报告。逐组件消融定位“地基性机制”后，仅保留这些机制得到最小化求解器。

## 3. 关键设计

**VAD-CFR 的原始机制堆栈**（Listing 3）：以 EWMA（decay 0.1）跟踪瞬时 regret 的 L∞ 幅值作为"波动率"，归一化后同时调制三个部件：(a) RegretAccumulator 中正/负 regret 的折扣指数（base_alpha=1.5、base_beta=−0.1，波动率敏感度 0.5），并叠加 1.1 倍正瞬时 regret 增益与 −20 的负 regret 下限；(b) PolicyFromRegretAccumulator 用“预测本次更新后 regret”的乐观投影（乐观因子 1/(1+t/100) 衰减，正部 1.5 次幂非线性缩放）导出当前策略；(c) PolicyAccumulator 前 500 迭代硬暂停平均，之后用波动率自适应的多项式权重（gamma 基线 2.0、上限 4.0）并乘以 regret 幅值稳定因子与幅值加权因子。

**WOP-CFR 蒸馏结果**可写成对标准 CFR 的三处形式化修改：其一，非对称极端折扣累积 regret：d⁺_t = t^1.5/(t^1.5+1)（旧 regret≥0），d⁻_t = t^−0.1/(t^−0.1+1)（否则）——负指数使负 regret 的折扣乘子随 t 快速趋于 0，成为近乎即时的“遗忘门”，防止 regret 锁死，比人工调参的 DCFR 激进得多。其二，当前策略由乐观预测导出：σ ∝ max(0, d·R_t + (1/(1+t/100))·r_t)^1.5（注意 d 的符号判据改为当前 R_t）。其三，前 500 迭代硬 warm-start 暂停策略平均，之后以静态权重 w_t = t² 累积。整个求解器约 20 行代码。

**SHOR-PSRO 的原始机制堆栈**（Listing 4）：核心是 ORM+ 内环（乐观 regret matching+，带 momentum 的乐观增益、增益归一化、多样性加成），外加与 softmax 平滑最优纯策略的混合插值（blending 因子随 PSRO 外层迭代从 0.3 退火到 0.05，温度 0.5→0.01，多样性系数 0.05→0.001，退火窗 75 轮），内环迭代数随种群线性增长（基线 1000 + 每策略 20，上限 5000）。训练/评估解耦到近乎病态：EvalMetaStrategySolver 用完全不同的超参（基线 8000 迭代、+50/策略、上限 15000、blending 0.01、温度 0.001、momentum 0.2）并显式返回 last-iterate 而非时间平均。

**PM-PSRO 蒸馏结果**只保留三条：(a) 把 regret matching 中的 regret 信号替换为切空间投影效用 g = (I − (1/|Π|)11ᵀ)u（即按种群均值中心化），在 normal-form 层面跑标准 RM；(b) 内环预算随经验博弈规模线性增长（1000 + 20×(n−1)）；(c) 训练与评估统一用时间平均求解器。均值中心化使每个策略严格相对种群平均被评估，配合 RM 的正部截断，“瞬间遗忘”低于平均的策略，对极端 payoff 离群点具有几何免疫。该投影与演化博弈论中的 projection dynamic 共享同一几何步骤，但离散更新仍是 RM 式而非投影动力学规则。

**实验卫生。** PSRO 用精确 BR oracle（值迭代、同值动作均匀分配），payoff 张量逐项精确计算，剥离 RL 方差以孤立考察元求解器；RM 基线每 PSRO 迭代跑 10⁴ 步。

## 4. 实验结果

**CFR 侧**（K=1000，基线：CFR、CFR+、LCFR、DCFR、PCFR+、DPCFR+、HS-PCFR+(30)）：VAD-CFR 在 18 个游戏中全部进入前三，其中 15 个取得最低 exploitability；3 人 Kuhn 上显著低于全部基线；3 人 Leduc 上 VAD-CFR 降到 10⁻³ 以下而多数基线停在高得多的平台；6 面 Liar's Dice 上与 DCFR 等持平。蒸馏版 WOP-CFR 同样 18 局全进前三、14 局最低，Test IQM 相对原始 VAD-CFR 为 **+0.119**（即在测试游戏上普遍更低可利用率），在 3 人 Leduc、4 牌限信息 Goofspiel 等局上以不可忽略幅度反超 VAD-CFR。

**PSRO 侧**（K=100，基线：Uniform、LP-Nash（2 人）、AlphaRank、PRD、RM）：SHOR-PSRO 在 3 人 Kuhn 上以快于 PRD/RM 的速度达到 <10⁻³；3 人 Leduc 的混沌元博弈中仍持平或超过最强基线；6 面 Liar's Dice 上有明显优势。SHOR-PSRO 与 PM-PSRO 均 18 局全进前三、12 局最低。蒸馏版 PM-PSRO 的 Test IQM 相对 SHOR 为 **+0.059**。

**随机 NFG 补充实验**（脱离具体扩展式结构、剥离进化隐式过拟合）：每配置采 1000 个 N 人常和 NFG（payoff 张量取 N(0,1) 或 U[−1,1] 再跨玩家中心化），N∈{3,4,5}、A∈[20,100] 共六配置，跑 A 轮外层迭代；IQM 报告、5 万次 run 级 bootstrap 置信区间。定性结论在全部配置与两种分布下一致：SHOR/PM 持续压过所有基线且差距随迭代拉大；基线通常在 A/2 之前平台化；PM 前 ~5 迭代起步偏慢（切空间投影信号需累积），但在大配置（3P/50A、3P/100A、4P/50A）中程即追平或反超 SHOR。

## 5. 消融要点

三条结构性结论：

**其一，泛化引擎收敛于极小的机制核。** VAD-CFR 侧，去掉波动率追踪或 regret 增益只损失训练拟合（train −0.842 / −0.954）而对 held-out 泛化影响很小（test −0.029 / −0.204）——它们是分布内协同件，不是泛化驱动器。真正承载泛化的是三个地基性机制：硬 warm-start（test −2.003）、极端非对称折扣（test −1.065）、乐观预测（test −0.905），去掉任何一个都造成可利用率崩塌。同时剥离全部次级启发式（即 WOP-CFR）后 train 掉 0.802 但 test 反升 0.119，是“过参数化泛化惩罚”的直接证据。PSRO 侧同理：ORM+ 环是不可替代的引擎（no_blending_pure 崩塌至 test −1.268），而纯策略混合插值与动态退火在测试侧反而为正收益（+0.020/+0.016），坐实为过拟合产物；固定内环迭代数有轻微负作用（−0.031），说明预算随种群增长是真机制。

**其二，LLM 会构造“看似深刻”的非对称设计，其中相当部分是无用甚至有害的。** SHOR 演化出的训练/评估双求解器中，把评估求解器塞回训练端造成全面退化（eval_as_train test −0.541）；反过来把训练求解器用于评估反而略好（train_as_eval test +0.021）。蒸馏时统一为时间平均求解器即来自这一发现——last-iterate 评估是过拟合伪迹。

**其三，单特征消融会破坏协同、但协同本身不等于泛化。** 这是审计方法论的微妙处：no_volatility/no_boost 单独去除时性能略降（系统失去内分布协同），但成套蒸馏去除后泛化更好，说明“训练拟合—泛化”之间存在可分离的结构层次，逐项消融与整体蒸馏需配合使用。

## 6. 贡献与启示

**方法学贡献**：(1) 证明 LLM 进化搜索可在 CFR 与 PSRO 两个结构迥异的范式上得到与人工 SOTA 持平或更好的算法，且搜索对象是“多组件交互的算法骨架”而非单一损失或更新规则；(2) 提出 train-test 消融审计管线（IQM log-improvement + 三切面报告）作为 LLM 产物的系统性“算法审计”工具，显式诊断 LLM 的过工程化倾向；(3) 交付两个极简、可解释、无隐式状态的最小求解器（WOP-CFR 约 20 行、PM-PSRO 约 50 行），其 Test IQM 均优于原始发现。

**工程与跨域启示**：对音视频技术侧，CFR/PSRO 本身关联较弱，真正可迁移的是管线形态——“固定签名接口圈定搜索空间 + LLM 语义变异 + 精确小规模代理评估 + train-test 消融蒸馏”。编码器模式决策、码率阶梯、缓存驱逐这类“小规模可精确评估、部署端需极简规则”的问题与该形态高度同构：本文的“精确 exploitability 把评测限制在 <350K 信息集”正对应“用小规模代理任务进化、蒸馏出轻量核心再上量”的工程路径；“LLM 叠加协同复杂度、蒸馏后泛化反升”这一结论对任何用进化搜索产线规则的团队都是直接的警示与操作指南。

**局限**（作者自陈，六条）：单条 AlphaEvolve 轨迹、未刻画独立进化运行的方差；headline IQM 以同族泛化为主（Blotto/Battleship 跨族证据限于附录 7.4）；蒸馏需人判断、非全自动；无收敛性理论（PM 的切投影 ≠ projection dynamic，WOP 的组合是经验性的）；仅对比表格型基线、未含 deep CFR 与神经 auto-curricula PSRO；精确 exploitability 限制评测于 <350K 信息集的博弈，规模化及对 LLM 骨干/提示的依赖未验证。

## 7. 与其他论文的联系

本文处于“LLM 程序进化发现算法”这一快速扩张的家族中，清单内各条与其关联均真实且可操作化：

- **paper:arxiv:2611.08483（SwarmEvolve）**：作为潜在蜂群式进化后端，自称速度与得分超 AlphaEvolve 类系统；本文局限 明言对骨干与提示的依赖未验证，更换/升级进化引擎是直接后续方向。
- **paper:arxiv:2610.35595（Agentic Algorithm Design）**：在 Lean 中机器检验进化算法的期望运行时间界、无需经验比较；为本文“经验 fitness + 消融审计”补上理论保证缺失的一翼，尤其适合审计出的三个地基机制（warm-start、非对称折扣、乐观预测）的收敛性论证。

- **paper:arxiv:2610.03675（FrugalEvo）**：成本感知 LLM 进化（强模型出策略、廉价模型写码）；本文用 Gemini 2.5 Pro 做全流程变异，成本高昂，分级模型架构可直接对冲其规模化顾虑。
- **paper:arxiv:2609.25510（Hill Sampling）**：主张以“冻结 LLM 条件化重采样”替代进化搜索且效果更优；若成立，可作为本文变异算子的低成本替代，尤其适合消融审计阶段大量变体的批量生成。
