## 1. 背景与动机

o1 类推理模型推动的 inference-time scaling 范式，本质是让模型在作答前通过 self-reflection、self-correction、self-critique 等机制拉长思考链。但这类机制有一个常被绕过的前提假设：模型能够准确评估自身输出的正确性。论文开篇即点出该假设在三个维度上失效——初始准确率不足、题目难度过高、缺乏外部反馈。这与"LLM 无法真正自我修正推理"一系的既有结论一致：没有可靠的自我评估，加大推理算力只会让错误被更自信地复述，性能天花板不会随计算量上移。

本文的切入点是 two-player 范式（可扩展监督，scalable oversight 的技术路线）：把推理与评判解耦为 actor 模型 πθ 与 critique 模型 πϕ，由 critique 模型对思维链提供步骤级自然语言反馈，并在两个时间尺度上监督 actor——测试时作为推理增强器，训练时作为自我改进循环中的定向探索信号。论文围绕三个递进的研究问题展开：

1. 如何在无人工标注条件下规模化构造高质量步骤级 critique 数据并训练 critique 模型；
2. 测试时 critique 监督的增益分布在哪些难度的题目上、是否随推理算力扩展持续放大；
3. 将 critique 监督引入 self-improvement 的训练循环，能否缓解尾收缩问题并训练出更强的推理模型。

其中问题 2 的发现（增益集中于难题、随算力扩展持续放大）直接为问题 3 的设计提供动机，构成“测试时分析 → 训练时方法”的论证链。此外论文附带了第四项探索：用 critique 数据合成步骤级 self-talk 数据，训练单一模型在推理过程中自我反思修正，逼近 o1 式输出形态。实验域为 GSM8K 与 MATH 纯文本数学推理，骨干为 Llama3-8B-Base（actor）与 Llama3-8B/70B（critique），算力环境为 NVIDIA A100 与昇腾 910。

## 2. 方法总览

**形式化。** 论文将 two-player 设定拆为三个任务。推理任务：y = πθ(x)，由奖励函数 r(x, y) 评判；批评任务：c = πϕ(x, y)，且当 oracle 奖励不可得时，批评内含两个子任务——判别（解是否含错）与反馈生成（给出建设性自然语言反馈），这一分解与后文 Discriminability / Helpfulness 双指标评测严格对齐；精炼任务分条件精炼 y′ = πθ(x, y, c) 与直接精炼 y′ = πθ(x, y)（即 self-correction）。多轮交互下，第 i 轮批评与精炼均以完整交互历史为条件，形成 actor–critique 交替的迭代轨迹。

**方法栈共四层。**

第一层是数据合成框架 AutoMathCritique：以 GSM8K 与 MATH 训练集题目为锚，通过三路受控错误合成（RG1/RG2/RG3）构造缺陷推理路径，由 GPT-4o 担任标注者生成步骤级 critique，再经蒙特卡洛软过滤去劣。产出的 MathCritique-76k 含 76,321 条 critique，覆盖 15,973 个 query 与 15,971 条金标准推理路径（GSM8K 侧 7,473 query / 37,873 critique；MATH 侧 7,500 query / 38,448 critique）。

第二层是双模型训练。critique 模型以 MathCritique-76k 做标准语言建模损失 SFT：Lcritique(ϕ) = E log πϕ(c|x, y)。actor 模型（Llama3-8B-Base）用 GSM8K/MATH 训练集的推理数据 Dreason 加上 GPT-4 标注的 8k 条精炼样本 Drefine（两数据集各半，最终答案经正确性验证）联合微调：Lactor(θ) = E_{Dreason} log πθ(y|x) + β · E_{Drefine} log πθ(y′|x, y, c)，β 为权衡推理与精炼学习的超参（论文未给出取值）。

第三层是测试时监督：actor 作答 → critique 反馈 → actor 条件精炼，围绕准确率、判别力、帮助度以及难度分层、Maj@K 扫描展开系统评测。

第四层是训练时监督，即 critique-in-the-loop self-improvement：在自我改进的探索步中，对错误响应追加 L 轮 critique–refinement 以提高难题解的覆盖，正确响应直接入训练集；配合难度感知的算力分配，运行 T = 3 轮探索–学习迭代，每轮均从原始模型 π0 而非上一轮模型微调以抑制过拟合。

最上层延伸是 self-talk-via-critique：将 critique 反馈逐步插入推理路径、迭代精炼与再批评直至无错、再由 LLM 平滑为自然 self-talk 文本，从 MATH 训练集构建 4k 样本微调单一模型。

整体逻辑是清晰的“数据 → 评判器 → 测试时验证 → 训练时内化 → 单模型化”递进管线，每一层的结论为下一层提供设计依据。

## 3. 关键设计

**3.1 受控错误合成（RG1–RG3）。** 这是整条数据管线的核心。三种策略按“提供的错误元信息量”递增：

- **RG1（从零采样）**：直接对 query 重复采样取错误响应。错误来自模型自然错误分布，但不含任何位置/内容提示，critique 标注难度完全压在标注者能力上。它的价值在于保留错误的“自然性”。
- **RG2（错误位置感知生成）**：先采样一条正确解，从指定步骤起提高最终 softmax 的温度续采。效果是错误点之前的步骤与正确解严格一致、错误集中在其后，且错误起点位置已知。这是一种“前缀锚定的扰动采样”：以推理连贯性换取错误位置的可控标注。若采样仍正确，则换一步并进一步提高随机性。
- **RG3（显式注入详细错误）**：指示模型在正确解的指定步骤注入枚举的错误类型（prompt 中含 few-shot 五元组：query、正确参考解、注入位置、错误类型、缺陷解），并从错误步骤续推至最终答案，失败则重采最多 16 次。同时拿到位置与内容双重元信息。

设计逻辑是信息量的分级交易：构造侧的元信息越充足，标注侧难度越低、critique 质量越可控；同时 RG2/RG3 的副产品（正确解）又被复用于“全对才收”的正确路径 critique 构造，一套采样服务两类数据。

**3.2 Critique 生成的两种策略与信息分级。** 标注者（GPT-4o）可采用整体审视定位首个错误，或逐步检查、检出首错即停并给出反馈——后者将整解评判分解为步级序列，显著降低任务难度。对不同来源的响应提供分级提示：正确响应不给提示、逐歩标注，仅当每一步都标对才保留（否则视为 false positive 或标注错误，直接丢弃，这是一道硬关卡）；RG1 错解提供正确参考答案；RG2 错解提供参考答案 + 疑似错误起点；RG3 错解提供精确位置 + 错误内容明细。

**3.3 蒙特卡洛软过滤。** critique 质量无法静态判定，论文以“actor 是否能据此修正”为动态锚点：每个（query, response, critique）三元组交 actor 精炼 10 次，修正率超过阈值 τ = 0.3 才保留（软过滤）。与硬过滤（k 次中至少一次修对即保留）相比，软过滤有两重作用：避免高质量 critique 因 actor 偶发失误被误删；压低“actor 无视反馈、靠自己知识修对”的伪有效数据混入。作者随机抽检 5 × 100 条，人工核验低质率约 1.2%，即质量–数量折中下的残留水平。需要强调的工程细节：软过滤的有效性锚定在特定 actor（Llama3-8B 系）的遵循能力上，critique 的“有效性”与下游 actor 绑定，更换 actor 底座时阈值需重标。

**3.4 训练时：critique-in-the-loop 与难度感知算力分配。** 朴素自我改进的探索–学习循环存在已知痛点“尾收缩”：模型对简单题过采样、难题欠采样，迭代后训练集长尾缺失难题解，性能平台化甚至退化。本文的修正有两点。其一，探索步引入 critique 定向修补：由于训练集可假设存在 oracle 奖励函数，critique 只施加于错误响应（正确响应直接入集），从源头避免低质 critique 污染本来正确的解——这是对“监督信号副作用”的显式防护。其二，难度感知的算力分配：初始响应错误 → 判为难 → 追加 L 轮 critique–refinement；初始正确 → 判为易 → 零额外开销。该策略是二值化的（一次采样的对错即难度信号），作者明确注明基于多次采样准确率的更细粒度策略预期更优，但简单版已足够有效。学习步以 Dreason ∪ Dcorrect ∪ Drefine 微调，学习率 2e-5、1 epoch，探索温度 0.7、采样数 N 取 5 或 10。

**3.5 Self-talk-via-critique 三步合成。** 第一步将步骤级 critique 反馈插入对应推理步骤，形成“推理—反思”交替的初始思考链（此时结构生硬）；第二步对含错路径从首个错误步骤起精炼，再由 critique 模型对精炼后的区段重新批评，发现新错则迭代，直至全部错误经反思修正；第三步由 LLM 添加过渡词与连接语将链条平滑为自然 self-talk（"wait""alternatively"一类标记的风格），并验证最终答案后才入库。该管线本质是把 two-player 交互轨迹折叠为单模型的思维链训练数据。

## 4. 实验结果

**测试时 critique 监督（actor 为 Llama3-8B-Base 微调；评测贪心解码，扩算力时温度 0.7）。** 表 2 关键行如下（Helpfulness 指将错误推理路径修对的能力）：

| Critique Model | GSM8K Acc / 判别 / 帮助度 | MATH Acc / 判别 / 帮助度 |
|---|---|---|
| No Critic | 54.81 / – / – | 17.22 / – / – |
| GPT-3.5-Turbo | 58.38 / 62.9% / 13.3% | 25.56 / 51.3% / 14.3% |
| GPT-4-Turbo | 77.86 / 91.6% / 57.5% | 36.00 / 87.6% / 26.2% |
| GPT-4o | 79.52 / 91.5% / 59.7% | 39.98 / 85.4% / 30.9% |
| Critique Model-8B | 63.31 / 79.4% / 31.0% | 24.26 / 75.7% / 16.2% |
| Critique Model-70B | 76.88 / 92.3% / 55.3% | 33.94 / 82.3% / 23.9% |

要点：8B 专门 critique 模型的判别准确率（GSM8K 79.4%、MATH 75.7%，正文精确值 79.37%/75.74%）超过 GPT-3.5-Turbo 16.5 / 24.5 个百分点，帮助度高 17.7 / 1.9 个百分点；70B critique 在 GSM8K 判别上（92.3%）反超 GPT-4-Turbo 与 GPT-4o，端到端准确率 76.88 / 33.94 逼近 GPT-4 系列。结论是：针对批评任务做数据合成 + 定向 SFT，可以用 8B–70B 的专用小模型逼近乃至局部超越通用旗舰模型的评判能力。

**难度分层增益。** 论文按每题 100 次采样中的正确数将 query 分为 5 个难度级。报告的分难度增益显示清晰的单调结构：GSM8K 训练集从 L1 到 L5 依次为 +3.0/+19.0/+27.0/+29.0/+23.0，测试集为 -2.0/+6.0/+15.0/+17.0/+11.0；MATH 训练集 -2.0/+10.0/+18.0/+19.0/+11.0，测试集 -3.0/-2.0/+5.0/+12.0/+7.0（百分点量级）。简单题增益趋零甚至微负，难题增益显著；且训练集上的增益整体大于测试集——后者直接构成“把 critique 监督搬进训练循环”的动机。

**扩算力下的表现上限。** 相同计算预算下，critique 加持的 Maj@K 超纯采样基线 12.4%（GSM8K）与 14.8%（MATH）；纯采样的 Maj@K 在 2×、3× 采样量下迅速饱和，而 critique 持续抬高上限。

**训练时 + 测试时组合（表 3 关键行，Acc / Pass@5 / MV@5）：**

| 训练方式 | 测试方式 | GSM8K | MATH |
|---|---|---|---|
| SFT | response only | 54.8 / 75.2 / 54.5 | 17.2 / 35.0 / 15.6 |
| SFT | w/ critique model | 63.3 / 87.6 / 75.4 | 24.3 / 47.4 / 30.7 |
| Self-Correction FT | self-correction | 60.1 / 81.5 / 67.2 | 24.2 / 41.7 / 26.1 |
| Vanilla SI | response only | 64.6 / 83.4 / 70.6 | 20.2 / 38.5 / 23.0 |
| Critique-in-the-loop SI | response only | 75.5 / 89.1 / 80.1 | 31.3 / 51.0 / 35.1 |
| Critique-in-the-loop SI | w/ critique model | **75.8 / 91.8 / 82.8** | **31.4 / 53.1 / 36.8** |

四点发现：(1) 测试时 critique 对 SFT 模型的 MV@5 提升达 10.9 / 15.1 点；(2) 训练时已用 critique 监督的模型，测试时再叠加 critique 的边际收益收缩至 0.3–1.7 点——监督信号已被“蒸馏”进 actor 权重；(3) self-correction 基线（单模型自我修正，训练数据由精炼数据剥离 critique 重构）全面弱于独立 critique 模型方案，且推理与修正双能力共训存在冲突；(4) “SFT + 测试时 critique”（省训练、多推理算力）在 MATH 上反超“vanilla SI + response only”（多训练、省推理算力）的 MV@5（30.7 vs 23.0），给出训练/测试算力分配的实证参考。自我改进迭代曲线上，N = 10 时 critique-in-the-loop 相对 vanilla 的优势在两个数据集均达 11.1%，且 vanilla 在约 3 轮内即触及瓶颈或回落，本文方法饱和显著更晚。

**Scaling 性质（Qwen-2.5 系列 1.5B/3B/7B/14B actor，单一 3B critique）。** 三条结论：3B critique 可跨尺度有效监督至 14B 的更大 actor；提供 oracle 奖励辅助时（critique 免做判别、只对错解出反馈）增益更大；随 actor 规模增大，GSM8K 上的增益边际化，而 MATH 上对最大模型仍保持显著——critique 监督的价值与任务难度正相关。

**多数投票机制分析（每题并行采样 1,000 次）。** 无 critique 时的典型失败模式：正确答案出现频率约 40%，但某个特定错误答案以约 45% 的频率占优，MV 系统性选错。critique 通过判别能力压制高频错误答案、通过反馈抬高正确答案的相对频率，双向修复该模式。

**串行 vs 并行扩展。** Pass@K 上并行（并行采样多条 response–critique–refinement 三元组）略优于串行（初始解后迭代批评精炼）——并行给 actor 更多从 query 直接生成原始解的机会，采样多样性更高；串行只有一次原始推理机会，后续全依赖反馈修正。答案选择策略上，串行取第 K 次精炼的最终答案（sequential final）整体最弱，源于修正过程偶发“改对为错”；小 K 时并行 MV 占优，K 增大后串行 MV 反超（MATH 上更明显），构成随算力预算变化的权衡，作者将其留作探索策略自适应设计的方向。

**Self-talk 初探（仅 MATH 训练，Llama3-8B，Acc / Pass@5 / MV@5 / Pass@10 / MV@10）：** 轨迹级 self-correction 21.08 / 38.12 / 20.56 / 46.64 / 30.90；步骤级 self-talk 24.90 / 45.48 / 28.44 / 54.48 / 31.28；two-player 的 SFT + 测试时 critic 27.22 / 49.16 / 32.24 / 58.86 / 35.92。步骤级 self-talk 显著优于轨迹级自修正（Acc +3.8 点），但仍落后 two-player 设定，单模型化方向尚有差距。

## 5. 消融要点

对 critique-in-the-loop self-improvement 的两项消融（Acc，GSM8K / MATH）：

| 方法 | N=3 | N=5 | N=10 |
|---|---|---|---|
| Ours | 69.1 / 25.5 | 72.3 / 28.0 | 75.4 / 31.3 |
| w/o Difficulty Aware | 65.8 / 23.9 | 69.4 / 26.6 | 70.1 / 27.9 |
| More Refinement | 68.8 / 25.5 | 71.2 / 27.7 | 73.8 / 31.6 |

(1) 去掉难度感知算力分配在各 N 下一致下降 3.3–5.3 点，是最大单项贡献，印证“算力应向难题倾斜”而非均匀铺开；(2) 将同等算力改为对同一 critique 生成多次精炼、而非生成多样化 critique，全面小幅下降（N=10 GSM8K 75.4→73.8），说明 critique 本身的多样性是有效监督信号的来源，仅堆精炼次数收益有限。

机制侧验证：对比两种方法的探索数据分布，critique-in-the-loop 显著提升难题解占比——MATH 上 L5 难度解的相对占比 +27.9%、GSM8K +16.3%，同时 L1 占比分别 -13.2%、-28.0%，训练集分布被实质重平衡，尾收缩被直接缓解；对应到测试集，增益同样集中在难题（GSM8K L4 +20.5%、MATH L4 +15.4%），简单题仅 +2.0/+2.7。

数据管线侧（RG 信息分级、软/硬过滤取舍、正确路径“全对才收”）以设计论证加人工抽检（低质率 1.2%）支撑，未做对照性数值消融，属设计层面的消融而非实验消融，复现时应注意这部分结论的可验证边界。迭代设置上，T = 3 沿用“3 轮饱和”的既有经验，N 从 1 增至 10 时方法优势单调放大（N=10 达 11.1%），表明方法收益与探索算力正相关。

## 6. 贡献与启示

**贡献可归为四点加一项延伸。** 其一，给出可复制的无人工步骤级 critique 数据合成管线：受控错误注入（自然分布 / 位置锚定 / 内容注入三档）+ 信息分级标注 + 蒙特卡洛软过滤，76k 规模、人工抽检低质率 1.2%。其二，系统刻画了测试时 critique 监督的增益规律：增益集中于难题、随推理算力扩展持续放大（同预算 +12.4%/+14.8%）、机制上通过压制高频错误答案修复多数投票的失败模式。其三，提出 critique-in-the-loop 自我改进：oracle 引导的定向修补 + 二值化难度感知算力分配，实测重平衡了探索数据的长尾分布，N=10 下 +11.1%。其四，给出训练/测试算力分配的实证证据：critique 监督可从测试时“蒸馏”进权重（边际收益收缩现象），且“省训练、多推理”配置在难任务上可与“多训练、省推理”互换甚至更优。延伸项 self-talk-via-critique 验证了以批评数据合成反思式思维链的可行性（相对轨迹级自修正 Acc +3.8 点）。

**工程启示。** 判别力与帮助度分离的评测口径应成为 critic 类组件的标准验收协议：判别错解只是必要条件，能否驱动下游 actor 修正才是价值锚点；蒙特卡洛精炼通过率是比人工评审便宜得多且与下游绑定的 critique 质量度量，阈值 τ 与精炼次数构成质量–数量的可调旋钮。难度感知分配用“一次采样对错”这一零成本信号即拿到主要收益，工程上极轻，可直接嵌入任何拒绝采样式训练管线。critique 只施加于错误响应的防护设计，是所有“引入外部监督信号”类系统值得默认采纳的工程约束。

**与音视频技术上下游的关联（迁移视角，非论文实验范围）。** 本文虽在纯文本数学域验证，但其两个核心组件对音视频技术栈有直接的迁移接口。下游（多模态推理）：视频/音视频理解大模型的长思维链同样面临自评失准与多模态幻觉问题，two-player critique 与难度感知的推理算力分配可平移到多模态 CoT 的验证器设计与流式推理调度上；“串行 vs 并行随预算反转”的结论对有延迟约束的交互式音视频应用（实时对话、直播审核）具有直接的调度含义——小算力预算选并行 MV、大预算转串行迭代。上游（生成侧）：text-to-video / 音频生成管线中的过程验证器同样面临“缺陷样本难获得、标注贵”的问题，RG2 的前缀锚定扰动采样与 RG3 的受控缺陷注入（枚举错误类型 + 位置注入 + 续推到终态）是可迁移的负样本合成范式——例如在视频生成中锚定前 k 帧后扰动后段、在音频合成中注入时序/语义类缺陷，再以“下游修复通过率”软过滤构造 verifier 训练数据。此外，critique 监督可被蒸馏进 actor 权重的现象，对音视频生成模型的“在线评判器 + 离线内化”混合部署策略同样适用。

## 7. 与其他论文的联系

- **paper:arxiv:2611.10787｜Trustworthy Recursive Self-Improvement with Statistical Guarantees（TRUST）**：同属递归自我改进的质量控制问题域。本文靠蒙特卡洛软过滤（τ=0.3、10 次精炼）+ oracle 奖励把关自改进数据质量，并以 critique 定向修补缓解尾收缩导致的迭代退化；TRUST 则用在线多重假设检验控制错误进化率并提供统计保证。两者互补：本文给出数据面上“监督信号在环”的方案，TRUST 给出决策面上的错误率统计控制，可视为同一自改进安全性问题的两个正交控制点。
- **paper:arxiv:2611.14326｜When Should Agents Remember? Falsification-Gated Self-Evolution（FGSE）**：机制逻辑同构。FGSE 要求经验教训作为可证伪假设经三类探针验证后才写入记忆；本文的软过滤同样是“验证关卡 + 软保留”哲学——既阻止低质 critique 入库，又防止高质量数据因偶发失败被误删，且对正确响应一律绕过 critique 以防污染。两者共同支撑一个设计原则：自进化系统的写入操作应设经验证的门控，且门控应容忍噪声（软保留）而非二值硬裁。
- **paper:arxiv:2611.12109｜SkillDuet: Co-Evolving Models and Skills through Response Feedback**：同为“反馈驱动的外部组件与模型参数协同演化”结构。本文是 critique 模型（外部监督者）与 actor 在探索–学习循环中交替迭代；SkillDuet 是外部技能库与参数更新以响应反馈共演化。本文表 3 的“蒸馏”现象（训练时引入 critique 后，测试时 critique 的边际收益收缩）为这类外部组件提供了一个额外证据：外部协同组件的监督能力可被逐步内化进权重，提示外部组件存在“退役/轻量化”路径。
- **paper:arxiv:2611.14949｜RSI-PDEbench**：同为递归自我改进在特定推理域的实例化——本文落在 GSM8K/MATH 数学推理，RSI-PDEbench 落在 PDE 求解（1,001 案例、42 方程模板）。关注点互补：本文聚焦监督信号设计（critique 数据合成与在环分配）和探索效率，RSI-PDEbench 聚焦基准构建与调用成本削减，可作为自改进范式在不同推理域上“信号质量 vs 调用成本”两条工程主线的对照样本。
