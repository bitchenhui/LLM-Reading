## 1. 背景与动机

本文出自 Ellenberg（FunSearch 原始论文作者之一）等人，主题是对 FunSearch——Romera-Paredes et al., *Nature* 625 (2024) 提出的 LLM 驱动遗传算法——的一次面向实战的重实现与系统基准化。原始 FunSearch 已在极值组合领域取得实质成果（8 维 cap set 大小 512 的纪录），但其实现并未以“在职数学家可直接使用”为目标。本文的定位非常明确：让没有任何机器学习背景、没有高性能计算资源的数学研究者，通过修改一小段 Python 配置文件并从第三方 API 选一个大模型，就能把 FunSearch 用到自己的问题上；同时给出一组跨模型、跨问题的基准指标，为后续应用提供参照。

FunSearch 的适用问题类是“逆问题”：验证/打分一个候选解是多项式时间可做的，而发现好解本身是超多项式难的，典型如组合优化。作者特别强调 "hard-soft" 设定的价值：LLM 生成的程序允许在某种意义上“不精确”，因为存在一个严格的 evaluate 函数作为监视器兜底。附录给出的素数判定示例过于简单（正确程序常在第一代就被找到），而脚注指出一个耐人寻味的对照：问“一个数是否比素数小 5”，形式复杂度与素数判定同级，FunSearch 却困难得多——这已经预示了全文的一个核心论点：问题的呈现方式（而非其渐近复杂度）主导搜索难度。

另一个动机层面的预警：原始 FunSearch 论文发表之后训练的模型，可能已把破纪录的 cap set 程序吞进训练数据。作者明确承认这使得 cap set 作为 LLM 基准的效度存疑，并指出这将是未来 LLM 数学评测的普遍性难题。

## 2. 方法总览

FunSearch 的骨架是一个以 Python 脚本种群的遗传算法：外部评估器为每个脚本打分，下一代脚本由 LLM 生成——prompt 中放入按分数选出、同时保证种群多样性的上一代脚本。具体采用岛模型（island model）：种群划分为独立进化的子种群，周期性淘汰最高分最低的一半岛，用幸存岛的脚本重新初始化。选择时先选岛，再在岛内按分数加权随机选程序。构造 prompt 时从单一岛抽出 n 个脚本（本文与原论文均取 n = 2），按分数排序后将第 k 个重命名为 `priority_v⟨k−1⟩`，连同新函数 `priority_vN` 的头部一起送入 LLM——这一步对应传统遗传算法的杂交与变异。

问题规格由三个函数构成：
- **evaluate**：对 solve 的输出打分；
- **solve**：确定性构造过程，人在演化全程保持不变、完全掌控；
- **priority**：唯一被 LLM 进化的函数，作为引导 solve 的启发式。

以“N 点无 4-环图”为例：priority 给每个候选边赋实数，solve 是贪心算法——按优先级依次尝试加边、跳过会形成 4-环的边、无可加边时终止；evaluate 返回边数。同一问题可以有多种 solve 设计（加边时跳过 vs 直接终止；从完全图删边；priority 甚至可吃入当前图 Γ 而非仅顶点对），因此 priority 没有绝对好坏，只相对特定 solve 成立。

本文实现（github.com/kitft/funsearch）在原始 FunSearch 之上新增五项工程特性：(1) 支持任意类型签名的程序搜索，突破 priority-函数范式；(2) 集成 Weights & Biases 实时监控；(3) 经 OpenRouter 支持多 LLM 平台及运行内混用模型；(4) 并行化——多 CPU 核评估 + 异步 API 调用；(5) 安全加固——LLM 代码运行前静态检查危险操作（如 shell 调用），支持进程级与容器级沙箱。配置文件以装饰器标记 `@funsearch.run` 与 `@funsearch.evolve`（见附录 A 素数示例），三个基准问题的配置随仓库分发。

## 3. 关键设计

**solve/priority 的控制面分离**是整个框架最重要的语义设计。solve 归人管：任何硬约束（如要求解具有特定对称性）直接写进 solve 即可强制满足；priority 归 LLM 管，人对它的影响手段仅限于会进入 prompt 的注释与 docstring。这把“规范性”与“启发性”切开：LLM 只需要在启发式层面大体正确。

**三个基准问题**的设定各有讲究：

- **cap set（n = 8）**：priority 吃入整数 n 与 (Z/3Z)^n 中的向量返回实数；solve 从空集按优先级加点、跳过会造成三向量和为零的点；evaluate 返回集合大小。n = 8 时环境规模约 10^760，精确结果仅知至 n = 6。已知最优 512（即原 FunSearch 成果），故存在前述训练污染疑虑。
- **narrow admissible tuple（直径上界 n = 5000）**：admissible k-元组指不占据任何素数 p 模每个剩余类的递增整数列，其直径下界直接给出“无穷多间隔 ≤ d 的 j 素数组”的可证结论（DHL[k,j] 谱系：Zhang 的 DHL[3 500 000, 2] → Polymath8 的 DHL[50, 2]（k=50 最优直径 242）；j = 3 方面 Polymath8 的 k = 35 410 → Stadlmann 的 k = 35 265，对应最窄已知直径 d = 396 504）。k = 35 265、d ≈ 396 504 时候选元组超过 10^50000 个。本文的搜索表述别出心裁：不固定 k，而是固定直径上界 n，对 [0, n] 筛除——对每个素数 p ≤ n 删去一个剩余类，priority(p, n) 返回要删的剩余类 r。初始 priority 恒返回 1，常数 priority 最多产出 2-元组，于是形成对非常数函数的强选择压力——作者明言这是为测试进化能力而刻意为之的设定，并对比了替代表述（按 cap set 方式对整数排名，常数 priority 在小 n 时已近最优）。
- **no-isosceles（n = 64）**：n×n 网格中无三点构成等腰三角形的子集（含共线三点等差数列情形）。已知下界 ~n/√log n、上界 n^{2−ε}（由每列是无 3-AP 子集的平凡观察），上下界鸿沟巨大，适合机器搜索；且约束是六坐标二次型取零，与 no-three-in-line 同族，可作为一般二次型问题的试验田。同时提供了与另一条技术路线 PatternBoost 的直接可比对象。

**相对 token 度量**是基准方法学的核心发明：n_R = (p_O/p_I)·n_I + n_O，其中 n_I/n_O 为输入/输出 token 数，p_I/p_O 为现价。所有基准固定相对 token 预算，使其与模型单价波动和延迟解耦。

**基准协议**：每个模型 8 次独立运行、每次 2×10^6 相对 token、16 个采样器、16 个评估器、岛重置周期 15 分钟；成本为 2025 年 2 月经 OpenRouter 的实付均价（开源自托管模型成本随 provider 波动，文中加星号标注）。

## 4. 实验结果

三个问题的 8 次重复基准（口径同上：2×10^6 相对 token/次）关键行如下。cap set（n = 8，已知最优 512）无任何模型触及 512：

|---|---|---|---|---|
| codestral-mamba | 390 | 448 | 2 | 0.5 |
| mistral-tiny | 387 | 448 | 1 | 0.8 |
| gpt4o | 388 | 397 | 1 | 20 |
| gemini-2.0-flash | 348 | 379 | 1 | 0.5 |

（其余：claude-3.5-haiku 382/$8、llama-3.3-70b 375、deepseek-chat 368。）

narrow-admissible-tuple（n = 5000，已知最优 672）：全部模型 ave 落在 503–561，距 672 甚远；claude-3.5-haiku 最稳（560–564），gemini-2.0-flash 均分最低（503）却取得全场最高单次 582，方差极大；deepseek-chat 与 llama-3.3-70b 各有 4 次触顶（561）。

两条跨表结论：**其一，成本与效能基本不相关**——最贵的 gpt4o 在三个问题上分别是最好、居中、接近最差。**其二，长跑无益**。用 gemini-2.0-flash 做 10^8 相对 token（$25）的单次长跑：

| 问题 | n | 短重置(15min) best | 长重置(1h) best |
|---|---|---|---|
| cap-set | 8 | 370 | 349 |
| narrow-admissible-tuple | 5000 | 498 | 561 |
| no-isosceles | 64 | 90 | 86 |

三个问题上，8 次短跑（合计 $4）的集成最优都显著好于单次长跑。作者给出的解释是**路径依赖**：prompt 中包含自身历史输出，LLM 受其影响过强；提高温度或可缓解，但会损害早期性能并降低有效响应比例（所有模型都会偶尔返回非法 Python）。

**泛化实验**（mistral-tiny，10 岛/10 采样器/8 评估器，30 分钟，结束后取最优 priority）：solve 固定、只学 priority 的结构意味着可以直接把训练好的程序跑到训练范围外的 n 上。结果：(1) 所有训练出的 priority 在远超训练范围的网格尺寸上仍胜过随机 priority——跨尺寸泛化确实发生；(2) 但在 basic 设定下，多 n 联合训练并不改善泛化；(3) n ≥ 12 后无一达到最优（SAT 求解器可精确算到约 n = 32；16×16 最优为 28，n = 16 训练的 basic 模型只得 26）。

**可解释性发现**：直接检视学到的 priority 函数，可见其几乎总是偏爱网格边界点——作者尝试过的所有机器学习方法在该问题上都产出偏边界的点集。机理自洽：等腰条件是 Q−P、Q−R 坐标的一个二次型取零，坐标越大该二次型取零的启发式概率越小，故拉大点距有利，而贴边布局恰恰拉大两两距离。作者坦承这是看到机器输出后才想明白的。手工构造的“l2 距中心距离”priority 也胜随机，但 n = 9 训练的模型泛化还略好于它——说明除边界效应外还有别的可泛化战术被学到。

对称性实验（把 (Z/2Z)² 或 Z/2Z 翻转对称写进 solve，priority 只对部分网格赋值，solve 按轨道整组加点）在训练值上明显占优：

| 设定 | n=12 | 13 | 16 | 21 | 23 | 25 | 27 | 32 | 64 |
|---|---|---|---|---|---|---|---|---|---|
| 已知最优 | 20 | 22 | 28 | 36 | 40 | 44 | 48 | 56 | 110 |
| basic | 20 | 20 | 26 | 34 | 36 | 40 | 40 | 46 | 86* |
| 对称模型 | 20 | 22 | 28 | 36 | 40 | 40 | 44 | 52 | 96 |

（*：86 可通过加大算力提升到 96（见表 3 的 gpt4o 单次），但对称化以更省算力的方式达到 96，且在 n = 16 等训练值上直接命中最优 28。）

## 5. 消融要点

第 4.2 节实质上是一组围绕“同一数学问题的不同呈现方式”的系统消融，结论是**数学等价的表述给出显著不同的性能**：

- **加边 vs 删边**：把 solve 从“从空网格按 priority 加点”改为“从满网格按 priority 删点、删到无等腰为止”，二者数学表述等价，但平均而言随机删点反而优于学习到的删点顺序；且删点方式产出的集合甚至不是极大的——许多本可加入而不破坏性质的点因被优先删除而不在集合中。
- **环面变体** ((Z/NZ)²)：把网格对边相接、消灭边界，即消灭了唯一已知的可泛化战术。训练模型对随机 priority 的优势大幅缩水但仍然可见（priority 热区转而聚集在中心附近）；此处最好的泛化模型是“在 [0,50] 随机取 n 训练”的，且与 basic 设定相反，多 n 训练确实改善环面上的泛化——课程设计与问题结构存在交互。
- **对称性注入**：三种对称（中轴双翻、x = y 翻转、x = ±y 双翻）全部提升泛化，幅度与最佳 basic 模型（n = 9 训练）相当；在训练值上对称模型一致更优（见上表）。
- **负向 evaluate**：奖励“极大无等腰集尽可能小”，即搜索极小极大（small maximal）无等腰子集——这是一个此前无人研究过的新问题（no-three-in-line 的类比问题则是老问题）。附带一个方法论警告：n = 16 训练的模型对奇偶性敏感、偶数 n 上表现显著更好，故做泛化评测时测试参数不应全落在同一个等差数列上。
- **预测式 priority**：把 priority 从“点 → 分数”改为“当前子集 → 下一个点”（solve 跳过会造成等腰的建议点，并设建议次数预算）。理论上这更合理——作者用国际象棋作比：预先把所有走法排好序、再在每个局面下走优先级最高的合法着法的引擎必然下得很差。实验上预算从 3n（依据最大子集约 ~1.7n 的增长趋势设定）放宽到 O(n²) 后更好，性能方差更大，但**仍不如静态打分式 basic 模型**。
- **预算维度**：8×短跑 vs 单次长跑、岛重置 15 分钟 vs 1 小时（表 4），均已证短跑重启占优。

## 6. 贡献与启示

按本文自身领域（LLM 驱动程序搜索 / 自动化数学发现）的标准评估，贡献有四层。**工程层**：一个开箱即用、配置驱动的 FunSearch 实现，五项新特性中“任意类型签名搜索”最具一般性——它把 FunSearch 从 priority 范式解放为通用程序搜索框架；“多模型运行内混用 + OpenRouter 路由”直接落实了成本-效能解耦的结论。**方法学层**：相对 token 度量提供了一个对价格/延迟波动鲁棒的算力口径；“多次短跑优于单次长跑”与路径依赖诊断，是任何 LLM-进化搜索系统都适用的运维准则。**科学层**：no-isosceles 上的表述敏感性消融证明“对数学家而言不重要的区分可能对算法性能影响巨大”，即问题呈现本身应被视为超参数；priority 作为人可读工件反向输出了边界启发式这一数学观察，展示了“机器生成 + 人读出”的可解释性红利；并开辟了极小极大无等腰子集这一新问题。**警示层**：cap set 类基准的训练污染问题被明确摆上台面。

局限同样清晰：三项基准均未破纪录（512、672、110 都未达到）；no-isosceles 上 96 vs PatternBoost 的 110（后者起点是非 LLM 方法生成的大量 108 规模集合，算力投入也大得多，口径并不对等）；8 次重复、2×10^6 相对 token 的基准规模本身有限，跨模型差异未必统计显著。

**与音视频技术的上下游关联**：本文是“LLM 生成启发式代码 + 确定性评估器闭环”这一范式的工程化与基准化样本。其下游在通用算法设计领域已外溢为 EoH、FunBO 等自动化启发式设计（AHD）方法；映射到音视频工程，对应的正是“可学习打分/决策启发式 + 规范性构造过程”的组合——例如编码器模式决策、快速块划分、码率控制启发式的自动搜索，evaluate/solve/priority 三分恰好提供“规范性由码流合规的过程保证、启发式交由搜索学习”的安全结构。相对 token 预算口径、多模型混用、重启优先于长跑、温度-有效性权衡、静态危险操作检查与沙箱等结论和工程实践，可直接移植到任何 LLM 驱动的音视频算法搜索流水线；基准污染的警示也同样适用于编解码与质量评测基准的构建。

- **paper:arxiv:2406.04824（FunBO）**：直接把 FunSearch 框架用于自动发现贝叶斯优化采集函数，是本文所复现框架的直接下游应用；本文“任意类型签名搜索”的泛化恰好覆盖 FunBO 这类非 priority 式用途，其“多次短跑、多模型混用”结论可直接指导 FunBO 式搜索的算力分配。
- **paper:arxiv:2412.20694（QUBE）**：QUBE 用质量-不确定性权衡准则（QUTC）重定义 FunSearch 的选择标准，改动的正是本文第 2 节描述的“按分数加权岛内选择”环节；本文观测到的大方差现象（如 gemini-2.0-flash 在 tuple 问题上均分最低 503 但单次最高 582）正是此类不确定性感知选择的动机所在。
