# AutoAssumption: Searching over Assumptions Discovers ML-Systems Algorithms

## 1. 背景与动机

论文出发点是对 ML 系统领域演进模式的一个观察：该领域的实质性突破大多来自推翻前代方法默认成立的前提——投机解码放弃了“每个 token 需要大模型一次前向”的假设，PagedAttention 放弃了“请求的 KV cache 必须连续”；作者统计，KV-cache 驱逐方向上 H2O 之后的七次纪录中有五次引入了新假设。然而已发表算法极少显式陈述假设：它们散落在论文一句话、代码细节或专家直觉中，带来两个后果——专家无法“有意地”改变假设；AlphaEvolve/OpenEvolve/AIDE 等 LLM 发现引擎只能搜索程序空间，单次代码编辑同时触及多个设计决策，性能增益无法归因到具体设计选择。

作者由此提出核心命题：**假设而非代码才是算法设计的生产力单元**。技术路径是把每个算法写成逻辑证明：假设（A）、定义（D）、定理（T）构成有向无环图（proof graph），边为引用关系，终点是问题陈述 P，由 Lean 4 完整机器检查（无 sorry、无未证命题）。算法设计由此被转化为一个小而结构化的搜索空间：每次只改一条假设，只重推其影响集内的定理，LLM 负责探索、证明检查器负责审计、基准分数负责引导。

对音视频技术方向的意义在于：本文三个领域（KV-cache 驱逐、LLM 权重剪枝、投机解码）正是流式/长程多模态大模型推理效率的上游底座——小时级视频理解与流式语音对话的显存瓶颈在 KV cache，交互式语音生成的延迟（TPOT/TTFT）直接受益于投机解码，端侧音视频模型部署依赖免再训练剪枝。同时“假设级搜索 + Lean 审计”是领域无关的元方法，对神经编解码、超分、波束成形等同样“多变体共享一个基准”的音视频子领域有直接迁移价值（见第 6 节）。

## 2. 方法总览

**Proof graph 形式化。** 每个算法被写成一张 DAG：节点为假设 A（论证所默认的前提）、定义 D（程序所计算的对象）、定理 T（由 A、D 推出的结论），边为引用，整图收敛于该领域共享的问题陈述 P（算法的“契约”）。以投机采样（SpS）为范例：A1/A2 声明目标与 drafter 是同一有限词表上的分布；D3 定义单步 accept-or-resample（以 min(1, p(x)/q(x)) 接受，拒绝则从残差分布 p′ ∝ max(0, p−q) 重采样）；T1 在 A1–A3 下证明单步输出严格服从目标分布 p；C1 将精确性推广到整个解码循环；T2（每目标前向期望产出 token 数 (1−α^{γ+1})/(1−α)）**只**依赖 A5（固定草稿长度 γ）。这一依赖结构正是方法的核心资产：SVIP 打破 A5 时，图上立即显示仅成本声明 T2 受影响，精确性证明原样保留。全部节点在 Lean 4 + Mathlib 中逐条证明，主定理只依赖 Lean 标准基础（propext、Quot.sound、Classical.choice）。

**三阶段流水线。** Stage 1 从领域基准出发（KVPress、Spec-Bench、SparseGPT/Wanda 协议）沿引文网络收集算法，人工筛除不可运行项，重写为可复现基准分数（或原论文部分结果）的自包含 Python 文件；LLM 提出一个所有算法都能被证明解决的共享问题陈述，随机抽样算法试形式化，Lean 文件全部编译通过则保留，否则要求重新表述。Stage 2 用两个 agent（固定 prompt）形式化每个已发表算法：第一个 agent 以代码哈希确认版本后从代码（而非论文）出发写证明文档，每个逻辑行对应一个定义，附覆盖率测试；论文只用于提示假设。第二个 agent 将文档转录为 Lean（axioms.lean 冻结假设与主定理陈述，proof.lean 补证明），编译通过才算数。全部假设按其回答的设计问题归类，汇成一个跨论文的假设池。Stage 3 派生变体：agent 读父代代码/证明/分数与假设池，在一条假设上做一次“移动”（放松/加强/借用/组合等），先写新假设与假设检验再写代码；GPU 之前必须通过查重、归约检查（拨盘参数取父代恢复值时输出复现父代）与分离检查（某些输入上输出确实不同）；证明只在变更假设的影响集内编辑，其余逐字保留；在父代评测设定下打分，分数引导下一个父代与假设的选择，形成搜索链。

**语料。** 共形式化 89 个算法：KV-cache 驱逐 44（30 个 KVPress 内置 + 14 个移植）、投机解码 26（5 个 Spec-Bench 内置 + 18 移植 + 3 基线）、LLM 权重剪枝 19（含 dense 模型基线）；其中 34 个驱逐算法在全部 12 个 RULER-4K 格上完整运行。复现质量有锚点：驱逐分数与 NVIDIA KVPress 排行榜 41 个点全部相差 0.4 分以内，Spec-Bench 重跑与排行榜 #MAT 相差 0.2 以内，剪枝 perplexity 与原论文报告格相差 0.1 以内。

## 3. 关键设计

**覆盖率测试。** 每个逻辑代码行必须映射到证明文档中的定义/假设/定理之一（双向核对），管理性行（初始化、日志、数据搬运）显式豁免；任何未覆盖的行都意味着证明没有描述代码，文档不算完成。这是“Lean 证明是关于代码的证明”这一链条的形式保障——若定义转述的是论文而非代码，Lean 证书一文不值。

**假设池与影响集。** 假设池按设计问题分组（如模型架构、压缩输入与时机、预算与保护、打分、数值与选择），使不同算法对同一问题的不同回答可以直接互换——变体生成的主要策略就是“借用”池中他法的答案。影响集在父代干净证明上计算：直接引用变更假设的语句、其下游语句、仅在假设区间内提及它的语句、提及它的表格与索引行；只有这些允许变红，其余逐字复制。这实质上是把 proof repair（只重证受影响部分）工程化为搜索算子。

**三个发现算法的机理**（各自距父代仅一个假设，均带拨盘参数）：

- **RestoreKV GM**（驱逐）：变更假设为“一个缓存对被保留的条件是共享其 KV head 的 G 个 query head 平均意义上关注它，而非任一单 head 关注”。机理上利用 GQA 分组结构：逐 query head 的重放注意力峰值 m_hg(i)=max_t a_hg(t,i) 在 KV head 组内取均值 (1/G)Σ_g m_hg(i) 得分，再按全局预算（跨全部层/head/位置联合排序的 ⌊r′·LHn⌋ 个三元组）淘汰；聚合算子 ∈ {mean, max}，取 max 即恢复父代 RestoreKV。工程上等价于把驱逐粒度从 per-head 校准到 per-KV-group，直接适配 GQA 模型的注意力几何。
- **Pruner-Zero LG**（剪枝）：变更假设为“权重分数在整个矩阵内比较，而非在每个输出行内”。评分 S_ij=|W_ij|²·G̃_ij（|W| 取 fp16、平方在 fp32；G̃ 为全矩阵 min-max 归一化的梯度范数，α=100，无激活值输入），淘汰 ⌊sRC⌋ 个全局最低分（行内平局按行主序先者）；比较粒度取行即恢复 Pruner-Zero。本质是把稀疏度分配从“行内均匀”改为“矩阵内自由流动”，高稀疏度下边际收益递增。
- **SVIP LK**（投机解码）：SVIP 以熵检验 √(cH)>h（c=0.15, h=0.3, 草稿上限 40）提前终止草稿；LK 在终止时从 s·d 中查找当前后缀更早出现的 ν′-gram（ν′ 从 3 降至 1），追加其后至多 Λ=10 个查找 token（截断到首个 EOS），这些 token 不经 drafter 前向；Λ=0 恢复 SVIP。验证逻辑不变，故分布精确性证明在所述缓存/平局/精确算术假设下原样成立。

**变体有效性门控。** GPU 前的三重门（查重、归约引理、分离引理）加上 Lean 全检，把无效或等价的候选挡在评测预算之外——这是该方法在等预算下能与代码级进化引擎竞争的关键成本结构。

## 5. 消融要点

**变异研究（证明层 vs 基准层的检出能力）**：对 5 个已验证驱逐算法注入 14 个真实缺陷（多留/少留一个缓存对、排序反转、跳层、漏保护 sink token 等），5 个等价改写/纯注释作对照；每设计 4 个设定（两模型 × 16×/64×），共 56 个变异评测、20 个对照评测：

| 检测器 | 变异检出 | 漏检 | 对照误报 |
|---|---|---|---|
| Lean 证明检查 | 56/56（100%） | 0 | 0/20 |
| 基准分数下降 | 30/56（53.6%） | 26/56 | 2/20（10%） |

26 个漏检中部分缺陷小到不移动分数，另一部分反而提分——如“保留全部缓存对”这类静默突破内存预算的 bug 会被基准奖励。工程含义：证明检查是零 GPU 成本的硬门，基准不是可靠的正确性过滤器。

**假设级 vs 代码级搜索动力学**：代码级编辑一次触及多个设计决策，允许早期大跳变但对下一步缺乏指引；假设级每步单一归因、持续爬升（后八步 +8.6 vs +3.6/+3.1）并追平终分——这是“假设是生产力单元”这一命题最直接的实验支持。

**方差口径的诚实性**：本文 harness 无随机种子，三次重复大体重放同一移动序列，作者自承极差与 SD 均低估了独立搜索间的真实波动（附录 G.3）；引用 0.75 vs 1.39/4.09 时应带此口径。

**搜索外推**：搜索用 200 问子集嵌套于 6,500 问全集（seed 42），全量分数对搜索非留出；泛化证据来自搜索未见的设定（8K/16K 上下文、LongBench、LLaMA-2-7B、其余稀疏度、batch ≥1 的 TPOT）。

**形式化的边界**：Lean 只检查证明对问题陈述的效力，陈述是否符合领域本意需人工确认；证明只能覆盖数学可表达的性质（内存用量、分布精确性），训练动力学与生成质量仍只能靠基准；假设切分非规范——LLM 自选粒度，重复形式化得到不同假设池的稳定性未测量。另注意附录 H 明言 C1 的 Lean 证明覆盖理想化循环，“不担保任意停止规则或实测 SVIP 的 cap 分支”，故 SVIP LK 的精确性是在其声明的缓存/平局/精确算术假设下成立。

## 6. 贡献与启示

**三条贡献**：(1) 两个新 SOTA 算法——驱逐侧 RULER-4K 75.7 vs 已发表最佳 74.1（两模型、2×–64× 平均），剪枝侧 LLaMA-7B 50% 稀疏 WikiText-2 ppl 6.78 vs 6.89 且四个 LLaMA 模型全胜——及一个有竞争力的解码器；(2) 假设级算法搜索蓝图，等预算下与 OpenEvolve 打平（−0.4 分）、胜 AIDE（+0.8 分）、重复方差更低；(3) 89 个算法的 proof-graph 形式化与统一假设池。

**工程启示**：增益可归因——每个变体距父代一个假设、带拨盘（归约引理天然给出剂量-响应曲线）；GPU 前四重门（查重/归约/分离/Lean）显著压低无效评测成本，这是等预算竞争力的来源；正确性结构性继承——SVIP LK 提速且精确性证明原样保留，对需要“无损”语义的流水线（流式字幕、翻译）是硬保证；系统代价贴近父代（TTFT 1.03×、显存相同、TPOT ≤batch 16 差 4% 内、剪枝 48 s vs 53 s），变体不是纸面算法。

**与音视频技术的上下游关联**：上游看，LLM 推理栈就是音视频大模型的公共底座——RestoreKV GM 的增益集中在 16×–64× 高压缩区（32× 上 +12.0/+10.5 分），恰对应小时级视频理解、长会话流式语音在显存受限下的服务形态；TTFT 即交互式语音/会议系统的首响延迟指标；投机解码的分布精确性是“输出 law 严格等于目标模型”的无损流式生成前提；剪枝在 13B 上 5.83 的结果说明路径可平移到端侧多模态模型的中小骨干。下游/方法迁移看，假设池 + 影响集修复 + 覆盖率测试是一套领域无关的算法资产化方案，前提仅是“共享基准 + 可形式化的问题陈述”——神经编解码器的码率-失真控制、视频编码阶梯决策、超分/去噪流水线、阵列波束成形与回声消除均呈“数十变体共享基准”的同构形态；论文自己的展望（形式化更多领域、寻找跨领域 principal assumptions 并统一之）与该迁移方向一致。局限方面，除作者自述三条（人工审校、可形式化边界、假设非规范）外，所有发现均为“单假设距离”，多假设组合搜索与跨领域统一仍是开放问题。

## 7. 与其他论文的联系

- **paper:arxiv:2610.35595（Agentic Algorithm Design）**：同属“LLM 提出 + Lean 机器检验”的算法发现家族。该文在 Lean 中机器检验黑盒优化算法的期望运行时间界、全程不做经验比较；AutoAssumption 则把 Lean 证明当作搜索空间本身（假设即搜索节点），证明管输出契约（分布精确性、内存用量）、基准管性能。两者互补：一个先验地证复杂度性质，一个在证明约束下做性能搜索，且后者提供了与 OpenEvolve/AIDE 的等预算受控比较。
- **paper:arxiv:2611.08483（SwarmEvolve）**：SwarmEvolve 用潜空间智能体蜂群与 KV 缓存共享加速程序空间进化，速度与得分超 AlphaEvolve 等 SOTA；AutoAssumption 的对照组 OpenEvolve 正是 AlphaEvolve 的开源实现，结论是假设级搜索等预算打平（79.3 vs 79.7）但每步可归因、方差更小。两文合并的启示：进化搜索的下一档增益可能来自“搜什么”（假设空间）而非“搜多快”（蜂群并行化），二者正交。
- **paper:arxiv:2610.03675（FrugalEvo）**：成本感知 LLM 程序进化的代表（强模型出策略、廉价模型写代码、按单位成本收益最大化）。FrugalEvo 在模型调用层省成本，AutoAssumption 在评测层省成本（查重/归约/分离/Lean 全部发生在 GPU 之前）；对预算敏感的音视频工程化搜索，两套降本机制可叠加。
- **paper:arxiv:2610.35077（Improving VLMs on Scientific Chart Analysis）**：不改冻结 VLM、用 AlphaEvolve 式自主进化搜索推理程序，图表问答 EM 从 16.6% 升至 41.3%。它是“模型冻结、进化外围程序”范式在视觉-语言任务上的实例，也是本文方法向音视频多模态迁移时最接近的代码级基线；本文恰从归因性与可审计性角度指出了此类纯程序搜索的结构缺陷。
- **paper:arxiv:2611.14326（FGSE）**：机制同构的“验证门控自演化”——FGSE 把智能体经验教训作为可证伪假设，经三类探针验证后才写入记忆；AutoAssumption 把算法变异作为待证命题，Lean 全检通过后才进入基准与假设池。一个保记忆更新的安全，一个保算法变体的正确性，“完整验证通过前不接受更新”的门控设计一致，可作为自演化系统安全设计的共同范式参照。
