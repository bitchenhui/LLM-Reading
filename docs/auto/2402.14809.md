# CriticBench: Benchmarking LLMs for Critique-Correct Reasoning

> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

LLM 的自我评估与自我改进（self-refine、RLHF 中的批判/奖励信号、LLM-as-judge 评审）都隐含同一假设：模型具备“批判-修正”推理能力——能在给定响应中定位错误（critique）并给出可用的修改（correct）。但该假设长期缺乏系统实证：先前工作要么模型与数据集覆盖窄（Lightman et al. 的过程监督、Auto-J、Critique Ability 等），要么结论互相冲突——Self-Refine 报告自反馈涨点，Huang et al.（ICLR'24）则给出“LLM 尚不能自我修正推理”的否定结论。症结在于没有把“生成（G）、批判（Q）、修正（C）”放在同一题库、同一响应集上可比测量的基准，导致三个关键问题悬空：G/Q/C 三能力的相关结构是否同源；任务类型如何调制修正增益；模型间互评（强评弱/弱评强/自评）呈何种模式。

CriticBench 补的正是这层测量基础设施：5 个推理域（数学/常识/符号/代码/算法）、15 个公开数据集、3825 条实例，待批判响应由 GPT-3.5/GPT-4 与 LLaMa-2、Vicuna 三族 8 个模型生成，17 个模型在 GQC 三相位下评测。对下游自改进系统而言，这层测量直接标定了“自我修正环路在什么条件下净收益为正”——本文给出的平均答案（无 oracle 自我修正 −1.91 分）本质上是对 self-refine 类管线可行性的量化裁决。

## 2. 方法总览

基准构建为三段管线：

**问题收集**：优先复用已有子集（GSM8K/MATH 取自 Shi et al. 2022 与 Lightman et al. 2023 的子集，分别 250/500 条）；AQuA（254）、StrategyQA（229）、Penguins（146）、Colored Object（250）、Date（250）、HumanEval（164）、Object Counting（250）、Repeat Copy（32）全量纳入；CSQA/AmbigNQ/HotpotQA/TabMWP/MBPP 各随机 300 条。合计 3825 条。

**响应收集**：GPT-3.5、GPT-4、LLaMa-2（7/13/70B）、Vicuna（7/13/33B）共 8 个模型以 greedy decoding 生成答案；规则过滤无效推理（如循环复读型退化输出），再随机采样使各数据集内不同模型来源的响应数均衡。

**响应标注**：三层流水线——规则匹配初判（数学答案匹配、代码执行 check 函数）→ GPT-4 精判（专抓“答案对但推理错”与近义正确的常识答案）→ 分歧人工复核。人工复核还逆向发现 Date 数据集中"Jane and John married on Jan 2, 1958"一类题目所有选项皆错（5 周年应为 01/02/1963，数据集提供的答案却是 1961）。

**评测协议**：三相位串行，全程温度 0。批判相位以基准内固定响应集为输入（保证跨模型可比），提示三种：ZS-AO（仅输出裁决）、ZS-CoT（要求分析并以 JSON 输出 {"analysis","verdict"}）、4-shot FS（指令跟随弱的 BASE 模型只测 FS）；裁决格式为 [[correct]]/[[wrong]]。修正相位把批判文本拼入提示（输出 JSON {"solution","answer"}），设 ZS-CoT、FS、FS(oracle) 三档，oracle 档仅对真错响应触发修正。批评专用模型 Auto-J/UltraCM 以规则抽取其判别结论计分。

**指标**：G/C 用准确率 Sa=c/N；Q 用以“判错”为正类的 F1（Sp=判为错中真错占比，Sr=真错中被检出占比），以规避类别不平衡、LLM 评审偏置与不可复现问题。

## 3. 关键设计

**同源解耦的 GQC 测量**。批判相位输入的是基准固定响应集而非被评模型自生成的响应，使 G/Q/C 落在同一题目分布与同一响应质量分布上——这是 RQ2 相关性分析成立的方法论前提，也是与既有 critique 数据集（FEVER、DebateAgreement 等单任务集）的本质区别。

**Oracle 修正设置：检错与改错的解耦**。非 oracle 修正是“盲改”（检错错误会把对的改错），oracle 只对真错响应触发，二者差值即检错质量对修正的制约程度。这是全文最有复用价值的诊断设计：任何自改进系统都可以用该对照分离“感知瓶颈”与“行动瓶颈”。

**判错 F1 而非 rubric 细粒度评分**。作者在 Limitations 中给出明确权衡：细粒度评估原则任务特异性强且不可穷举；人工金标成本高；以 GPT-4 验证会引入其自身偏差并使其无法被评。二值判据牺牲批判细粒度，换取跨任务通用性与可复现性——对评审类基准设计有直接参考价值。

**任务类型学（核心自变量）**：detail 导向（算法类：数物品数、按指令重复变换词序）、logic 导向（代码生成：正确性主要由代码内嵌逻辑决定）、混合型（数学兼具细节与逻辑；符号推理偏细节）。该归类构成 RQ3 全部结论的解释框架。

**标注管线的非平凡收益**。GPT-4 精判修正了纯执行/匹配金标的两类系统性错误：假阳性——AQuA 题推理算得 120 分钟、答案却写 C（=36 分钟），规则按选项字母匹配判对，GPT-4+人工改判错；HumanEval 题用 `[2,3,5,7]` 判质数长度、通过了给定 check 函数，但漏掉两位数质数长度，同样改判错（暴露 check 用例覆盖不足）。假阴性——HotpotQA 中 "Polk County" 与金标 "polk" 字符串不匹配被误杀。这说明可执行校验在代码域与开放问答域都不充分。

**训练形态覆盖**：BASE/SIFT/RLHF/CT（critique training）四型同台、参数量从 2.7B（Phi-2）到 GPT-4 跨四个数量级，使训练策略与规模效应可直接对比。

**RQ1 关键因子**：(1) 规模阈值——超过 13B 参数的模型才具备超越随机猜测的批判力；Mixtral-8×7b 及以上才能实现有效修正（超过原始响应准确率 48.37）。(2) Phi-2 反例：生成 45.23 与 LLaMa-2-13b/Vicuna-33b 相当，但 FS 批判仅 25.78——教科书合成数据训练强化了生成却未带出批判，证明只评生成会系统性高估小模型的知识掌握。(3) RLHF 存在生成端 alignment tax，但批判/修正一致优于 BASE（LLaMa-2-70b chat 的 ZS-AO 批判 67.64，+16.84 vs 随机基线）；CT 在 13B 上批判超过 GPT-3.5 的 FS（65.29 与 61.11 对 59.88）。(4) 提示敏感性极端：Vicuna-13b 的 ZS-AO 判错率 22.04%、ZS-CoT 骤降至 4.8%，而真实错误率 51.63%——要求显式分析反而使判错召回崩塌；整体 FS 优于 ZS，但强 RLHF 模型例外（GPT-3.5 的 ZS-AO 69.94 高于其 FS 59.88）。(5) Oracle 反馈平均 +6.69，是唯一平均超过原始准确率的修正档；但强模型（LLaMa-2-70b 至 GPT-4）oracle 修正总体仍不及直接重新生成（Mixtral-8×7b 56.16 对 58.43、GPT-3.5 61.22 对 62.72；GPT-4 基本持平 74.80 对 74.33），说明错误响应文本本身即是强误导源。

**RQ2 相关性**：G-Q 呈正相关线性且提升速率几乎一致（尽管训练几乎只针对生成）；G-C 线性不显著，弱模型修正后准确率反而低于原始响应；C-Q 表明“能判出”不等于“能改对”。

**RQ3 任务类型**（附录分任务均值）：

| 任务域 | 生成 | 批判 | 修正 | 原始响应准确率 |
|---|---|---|---|---|
| 数学 | 35.09 | 48.29 | 37.12 | 33.51 |
| 常识 | 49.13 | 54.13 | 43.51 | 55.98 |
| 符号 | 70.12 | 49.68 | 68.67 | 65.48 |
| 代码 | 37.95 | 49.24 | 39.48 | 37.07 |
| 算法 | 65.30 | 26.81 | 62.08 | 65.96 |

算法类批判均值 26.81 远低于生成 65.30（Vicuna-7b 仅 2.04、Mixtral-8×7b 21.43、GPT-3.5 亦仅 46.15、GPT-4 63.51）；符号类同样批判弱于生成。代码类相反：批判 49.24 高于生成 37.95（GPT-4 代码批判 91.36、数学批判 92.55、符号批判 90.75）。修正端的结构更关键：数学与代码超过基线，常识与算法反而受损——原始响应越准，“全量重写式”修正越容易把对的改错。论文报告两个门槛：数学任务修正增益只在模型直接生成准确率超过 41% 时出现；代码任务只要生成超过原始响应准确率即有增益。机理归纳：批判/修正易被 detail 类错误文本带偏，而 logic 类错误可被结构化推理定位。

**RQ4 知识一致性**：三能力的知识集不一致在所有模型上存在，随参数规模增大一致性提升、三能力全错的占比下降；“仅批判正确”子集始终占显著比例——存在大量只能经判别通道表达、无法经生成/修正表达的知识；反向反例也存在：生成与修正都正确却在批判相位判错。这与人类“生成⊂批判”的能力包含结构（West et al. 的 generative AI paradox）形成对照。

**RQ5 互评模式**：强模型批判更强；弱模型的响应更易被准确批判（其错误更显性）；部分弱模型对强模型的批判可接近甚至超过后者的自评分数；CT 后的 UltraCM 对 GPT-4 响应的批判接近其自评水平。

## 5. 消融要点

论文无传统消融，但 RQ1 构成一组系统的控制变量分析：

- **提示策略消融**：批判均值 ZS-AO 48.19 / ZS-CoT 41.02 / FS 50.65；修正 ZS-CoT 35.46 / FS 46.46。ZS-CoT 的“先分析再裁决”在 Vicuna 系上灾难性退化（Vicuna-13b 批判 40.99→11.84，Vicuna-7b ZS-AO 仅 6.45），机理是 SIFT 模型无示例时倾向输出“无问题”裁决，判错召回崩塌——工程上意味着批判组件的提示必须随模型指令跟随能力分级配置。
- **Oracle 消融**：FS→FS(oracle) 平均 +8.60。即使检错完美化，强模型修正仍不敌直接生成，从而定位出两个独立瓶颈：检错召回不足、错误上下文对修正过程的干扰。
- **训练形态消融**：BASE/SIFT/RLHF/CT 四型对比给出两个可操作结论——RLHF 牺牲生成换批判/修正表达；CT 可把检错能力在 13B 规模上做到超 GPT-3.5，即检错器可专业化、小型化、从生成模型中解耦。
- **规模消融**：批判（>13B 超随机）与修正（≥Mixtral-8×7b 超原始准确率）出现双阈值，为部署自修正环路给出最小模型规格。
- 缺项评注：未设“无批判直接 refine”对照，无法量化批判文本本身的边际贡献；oracle 只测了“全真错触发”一种粒度，未做触发策略网格；响应源模型构成对结论的影响未单独消融。

## 6. 贡献与启示

**学术贡献**：首个同源可比的 GQC 基准及四条可复用结论——G/Q 近似同速线性增长、修正增益受任务 logic/detail 属性强调制、GQC 知识不一致随规模收敛、弱评强的互评模式。其中“平均无 oracle 自我修正为负收益（−1.91）”为 self-refine 与 Huang et al. 之争提供了统一口径下的裁决数据。

**对自改进系统的工程标定**：修正增益存在双重门槛——模型自身生成能力（数学 41% 阈值；代码需超过原始响应准确率）与任务的 logic 属性；检错是可独立优化的模块，可用 CT 小模型或可执行校验置换；错误上下文污染使得“改”不如“重生成”在强模型上常态成立，修正环路应设计为“高置信判错才触发”。

**评测方法学**：固定响应集 + 温度 0 + 判错 F1 的组合可直接迁移为 MLLM 评审类基准的模板；“GPT-4 精判 + 人工复核”对“答案对推理错”噪声的清理、以及对源数据集缺陷（Date 无正确选项）的逆向发现，是数据质量管线的示范。

**对音视频技术链路的映射（本笔记延伸分析，非论文内容）**：AV 工程任务可按本文 logic/detail 轴重新归类——管线脚本、转码配置、剪辑 DSL、DSP 参数代码生成属 logic 导向，与 HumanEval/MBPP 同构，是自修正环路的合理落点；时轴对齐、帧计数、声道/采样率映射、字幕序列拷贝校验属 detail 导向，与 Object Counting/Repeat Copy 同构，是批判脆弱区（该类任务上 GPT-3.5 批判亦仅 46.15），应外置为可执行校验器（解码一致性检查、PSNR/VMAF 回读、EBU R128 响度核查）充当 oracle 信号源——恰与本文“可靠外部反馈是修正增益前提（+6.69）”的结论闭环。此外，弱评强现象支持内容生产线上“小评审模型监控大生成模型”的异构级联，用于成本敏感的 QA/合规筛查；MLLM-as-judge 用于生成视频/语音质量评审时，判错 F1 的偏差控制方法与“评审者 detail 判据系统性偏弱”的警示直接适用。

**局限**：二值判据丢失批判细粒度（作者自认）；部分子集极小（Repeat Copy 仅 32 条）；模型与响应谱系截至 2024 年初，对新一代推理代际模型的外推需重测。

## 7. 与其他论文的联系

清单所列均为递归自我改进（RSI）系统框架，CriticBench 恰是其底层的“批判-修正能力测量层”，关联为能力实证与系统设计的上下游关系：

- **FGSE（arxiv:2611.14326）**：其“经验教训作为可证伪假设、经探针验证后才写入记忆”的门控设计，正是对 CriticBench GQC 知识不一致发现（判对≠能改对、生成对≠能判对）的工程化防御；CriticBench 同时给出探针设计的边界警示——detail 类任务批判 F1 极低（算法类均值 26.81），探针应避开模型批判盲区。
- **TRUST（arxiv:2611.10787）**：以在线多重假设检验为 RSI 控制错误进化率提供统计保证。CriticBench 量化了其必要性基础——无 oracle 自我修正平均 −1.91、批判信号提示敏感且判错召回可低至 4.8%（真实错误率 51.63%），即 critique 是低召回有偏检验，需要统计层兜底。
- **SkillDuet（arxiv:2611.12109）**：以响应反馈协同模型参数与技能库演化。CriticBench 中 CT 的效果（Auto-J 13B 批判 65.29 超 GPT-3.5）证明反馈信号可训练出专项检错小模型，为技能级反馈闭环的可行性提供实证支点。
- **WeightLoop（arxiv:2611.07319）**：以实验反馈驱动权重空间持续改写。对应 CriticBench 的 FS(oracle) 结论——可靠外部反馈平均 +6.69、是唯一使平均修正超过原始准确率的设置；实验反馈即“oracle 化”的实例化路径。
- **AutoTavern（arxiv:2610.33845）/ InfraRSI（arxiv:2611.11558）/ LongCapHarness（arxiv:2611.10463）/ RSI-PDE（arxiv:2611.14949）**：均为特定任务域的 RSI 系统。CriticBench 的任务类型结论可解释其可行性分布——代码/模拟器构建（AutoTavern）与训练基础设施优化（InfraRSI）落在 logic 导向、修正友好区，只要生成能力超过原始产出即有自改进增益；长上下文推理（LongCapHarness）与 PDE 求解（RSI-PDE）依赖外部基准验证通过率，恰是在 CriticBench 所示“detail 密集、批判脆弱”域中把检错外置为可执行 oracle 的正确设计。
