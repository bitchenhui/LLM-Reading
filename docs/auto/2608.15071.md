## 1. 背景与动机

本文处于 LLM 智能体自进化方向，切入的是经验学习方法与现实部署条件之间的结构性错位。既有工作（Reflexion、EXPEL、AWM、Dynamic Cheatsheet、Voyager 及各类技能库/记忆系统）多在离线设定下从累积轨迹池中挖掘可复用知识，介质覆盖反思、记忆、规则与技能。作者指出三个被普遍忽略的现实约束：

1. **一次性改进机会**：真实环境中任务以流式到来，每次执行通常只提供单次学习机会，不存在“先攒够轨迹池再离线蒸馏”的阶段；
2. **高噪声上下文**：真实执行上下文将泛化有用的教训与任务特定细节、局部失败、偶发工具痕迹深度纠缠，直接检索或追加会污染后续行为；
3. **验证与归因缺失**：前人工作很少在复杂真实任务上严格验证有效性，更少系统隔离“到底是什么驱动了智能体改进”——多数工作只报总体成功率。

据此提出 **online harness learning** 形式化：冻结求解器不改参数，靠在顺序任务流上增量更新一个外部结构化 harness（可复用指导条目集合）获得能力增长。概念上区分两条路线：experience reuse（检索过往案例注入上下文）与 harness skill evolution（把经验编译成可复用指导，结构性塑造后续的规划、执行、验证与恢复）。本质区别在于学习介质从“被动信息存储”升级为“主动控制脚手架”。

从音视频交叉视角看，这一动机对 AV 领域有直接接口：转码集群运维、封装/DRM 流水线、直播事故处置、QC 关卡正是论文刻画的“CLI/工具密集 + 环境验证器丰富 + 单次执行高噪声”环境的典型实例，AV 智能体化改造可直接借用本文的问题形式化与结论边界（详见 §6）。

## 2. 方法总览

**形式化设定**：任务批次流 {B1,…,BK}，批次 Bi 含 mi 个任务。当前 harness Hi 为结构化指导条目集合，外置于冻结求解器。每个任务先经 Select(x, H; b)（注入预算 b，|S|≤b）选出紧凑条目子集，Inject 融入任务输入后由冻结求解器 A 执行，得到轨迹 τ、结果 y 与可用反馈 f（验证器结果、单测输出、工具诊断、judge 评分等），构成执行上下文 c=(x, τ, y, f)。harness 更新 Hi→Hi+1 仅依赖这些上下文，求解器参数全程固定。

**两阶段编译**是方法核心：

- **Execution reflection（反射提取）**：每个完成的执行上下文，仅当执行失败或收到负反馈时才产生候选记忆 r=Reflect(c)，结构为 (lesson, trigger, evidence, scope_hint)。反射输入为执行后即时可得的全量任务侧上下文。该阶段刻意不与当前 harness 比对——输出只是以失败为锚的候选信号，不是最终更新。
- **Harness evolution（演化整合）**：批次结束后，候选记忆集合 Ri 连同当前 harness Hi 送入 evolver，产出编辑集 Oi，每条编辑 o∈{ADD, MERGE, REVISE, SKIP}；evolver 过滤噪声与冗余、合并兼容信号、修订既有指导、按需晋升可复用教训，最终 Hi+1=ApplyEdits(Hi, Oi)。关键性质：候选记忆不被直接追加，而是被编译成能改变未来行为的指导——这是与记忆库类方法的本质分界。

**双层 harness 结构**：cross-task patterns（跨任务比较候选记忆、提取共享操作结构）与 task-type procedures（沉淀面向重复任务格式/接口/领域的局部程序性知识）。作者强调两层不是对单次执行预定义的标签，而是从 evolver 的过滤、比较、整合过程中涌现。

**更新粒度**取批级（默认批大小 16），动机是 evolver 既需要批内跨任务比较才能提炼 cross-task 模式，也需要局部程序沉淀；|Bi|=1 时公式退化为任务级更新。设计上刻意解耦求解器、evolver、反馈源与初始 harness 四要素，使框架成为受控实验载体——这是论文“用 harness 做改进归因研究”的方法论支点。

## 3. 关键设计

**失败聚焦反射。** 只有失败/负反馈执行触发候选记忆生成。理由：失败暴露求解器当前边界——错误假设、缺失约束、低效工具使用、弱验证、失败恢复缺失——使候选信号更靶向；成功执行往往携带任务特定细节，纳入会稀释 harness。这一选择与 RQ4 的“反馈必须外部接地”互为呼应：反射的原料是环境证据，而非模型自评。

**提议—策展两级过滤。** 这是应对单次执行高噪声的核心机制：

- Solver 侧 proposal prompt：对每个独立问题识别“错在哪 + 缺失的具体动作/命令/工具调用/导航步骤/领域规则”，提出可复用技能（选择宽泛 topic，判定 NEW/ENHANCE/NONE，写 trigger 式描述，给出短小要点化内容），并要求“激进过滤”——跳过泛泛建议、基础工具用法、对具体任务的重放、对未见任务无用的技能。
- Evolver 侧 curator prompt：对每个提案判 ACCEPT/MERGE/SKIP，偏好合并而非重复、遵守容量预算、要求清晰 trigger、内容短且可执行，并施加泛化性测试（“对多个未见任务是否有用”）。
- General skill curator 进一步要求模式必须跨多个上下文复现、禁止上下文特定引用，只编码能指导跨任务规划/验证/恢复/工具使用的程序。

**容量预算与工件形态。** harness 以 Markdown 技能文件 + 轻量 YAML 元数据存储，每条目含 trigger（何时检索）、短可执行规则/程序、可选 evidence（链接先前执行）、scope（cross-task 还是 task-type）。容量约束：general skills 上限 5、每个 task-type topic 下上限 5；预算刻意逼 evolver 合并重叠指导、抑制过细任务特定记录堆积。技能检索在所有实验中固定用 Claude Sonnet 4.5，与求解器解耦。工件可检视、可跨 run/跨模型迁移——这是后文 transfer 实验的工程基础。

**编译产物的实际形态**（附录中经匹配 fail-to-pass 案例支撑，论文明确声明非单技能因果、多技能可同时注入）：

- WebArena：学到“创建新自动标签与禁用既有标签是两个独立操作，编辑后须回到设置列表核验终态”（案例 h10）；“收件人取自权威角色源并跨应用保真精确邮箱域名”（案例 h65，基线把 acmecorp.com 误写为 acme.com）——学到的是身份接地而非邮件撰写。
- TerminalBench：学到“同类失败反复出现时停止重跑同一命令，缩小用例、构造最小复现、修核心问题后再逐步加回复杂度”——可执行反馈回路下的恢复策略（案例 adaptive-rejection-sampler）。
- SWE-bench：学到“编辑前读完整失败测试断言、精确匹配期望字符串/错误标识/输出结构，提交前跑定向测试”（案例 django__django-11133，FAIL_TO_PASS 1/1、PASS_TO_PASS 64/64）。
- τ-bench：学到“枚举每个被请求的操作、按订单状态选工具、核验响应覆盖完整清单”（案例 retail_task_5）。

这些示例显示 harness 编译出的不是任务复盘，而是操作层面的程序性知识。

## 4. 实验结果

**设置**：五个真实基准，统一在线协议（任务按流处理，求解器用当前 harness，evolver 观察到结果后更新）；固定随机种子 42 做任务洗牌，结果为三次运行平均；默认求解器与 evolver 均为 Claude Opus 4.6。基准概况：WebArena-Infinity 80 个困难任务（邮件中心的 superhuman-general 设定，程序化状态验证器）；TerminalBench2 89 个 CLI/脚本任务（任务级 Docker 镜像内可执行验证器）；SWE-bench Lite 300 个真实 GitHub issue、12 个 Python 仓库（单测评估）；CL-Bench 1899 个自适应推理任务（DKR/EDS/PTE/RSA 四类，rubric judge）；TAU-Bench 165 个客服工具使用任务（航空+零售，数据库终态验证）。

### 4.1 总体有效性（RQ1）

主结果（成功率 %，Claude Opus 4.6 求解器）：

| 方法 | CL-Bench | TerminalBench-2 | SWE-bench Lite | τ-bench | WebArena-Inf. |
|---|---|---|---|---|---|
| No Evolve | 29.54 | 62.92 | 63.67 | 72.73 | 72.50 |
| AWM | 28.91 | 62.92 | 62.67 | 70.91 | 70.00 |
| Evo-Memory | 29.38 | 64.04 | 64.00 | 72.12 | 72.50 |
| ACE | 29.70 | 61.80 | 63.67 | 72.73 | 71.25 |
| XSkill | 31.44 | 66.29 | 64.67 | 73.94 | 73.75 |
| **EVO-HARNESS** | **34.02** | **73.03** | **67.00** | **76.97** | **76.25** |

（DC-Cu/DC-RS 两个 Dynamic Cheatsheet 变体在多数基准亦低于 No-Evolve。）三点结论：

1. EVO-HARNESS 在全部五个基准同时超过 No-Evolve 与最强基线 XSkill；对 No-Evolve 的绝对增益（由报告数字相减）为 TB2 +10.11、CL +4.48、τ-bench +4.24、WebArena +3.75、SWE +3.33。
2. 增益最大的 TerminalBench2 恰是需要检查文件、执行命令、解读报错并从失败操作恢复的环境——harness 演化在任务暴露可复用程序性结构时最有效。
3. **外部经验复用并非天然有益**：AWM、DC 变体、ACE 在部分基准低于 No-Evolve，说明检索/演化出的指导可能噪声大、过于特定或与求解器失配——这是论文主张研究“什么因素让在线更新有效”的直接实证依据。

### 4.2 类别与模型泛化（RQ1）

| Opus 4.6 | 29.5 | 34.0 | +4.5 | +9.8 | −2.5 |

规律：(a) 所有模型总体均提升，但增益随求解器能力递增（Claude 系 +3.7~+4.5，开源系 +0.8~+1.1），提示强求解器更能解释、遵循并受益于演化出的指导；(b) Procedural Task Execution 是唯一全模型提升的类别（Opus 4.6/4.5 各 +9.8），再次印证程序性结构假设；(c) Empirical Discovery & Simulation 提升不稳（Opus 4.6 −2.5、GPT-OSS −1.0），探索型任务对过于特定的指导更敏感。

### 4.3 harness 内容与改进热点（RQ2）

内容分布呈基准特异性而非泛化说教：WebArena-Infinity 主要产出工作流/流程技能，TerminalBench2 集中于验证与恢复，τ-bench 混合工具/API 操作与领域推理，CL-Bench 分布更宽（含领域推理与输出约束处理）——编译过程自适应于各环境的操作结构与失败模式。

匹配 fail-to-pass 案例分布（论文口径：描述性统计，非单技能因果）：WebArena 中设置态任务占 fail-to-pass 的 24%、相关 UI 技能出现于 72% 的改进 run，身份接地失败占 32%；TerminalBench2 中可执行反馈/恢复模式占 fail-to-pass 的 100%；SWE-bench Lite 改进集中于约定稳定的成熟仓库，Django+Sympy 占 66.7%；TAU-Bench 中零售工作流占 85.2%、“完整工具调用执行”指导出现于 100% 的改进 run。改进热点与验证器类型强耦合：状态验证器奖励“程序记忆 + 精确终态确认”的组合，可执行验证器奖励“降范围—最小复现—再验证”的恢复策略。

## 5. 消融要点

诊断实验聚焦 CL-Bench 与 SWE-bench Lite（前者异质自适应推理、局部 task-type 指导重要；后者仓库级调试/验证、宽泛可复用指导更关键），求解器均为 Opus 4.6。

**组件消融**（通过率 %）：

| 配置 | CL-Bench | SWE-bench Lite |
|---|---|---|
| No Evolve | 29.54 | 63.67 |
| No Propose（去掉 solver 侧候选记忆提案） | 33.28 | 65.33 |
| General Only（仅跨任务指导） | 30.28 | 66.67 |
| Topic Only（仅任务类型指导） | 33.70 | 64.33 |
| EVO-HARNESS 完整 | 34.02 | 67.00 |

双层指导均有效但重要性依场景反转：CL-Bench 上 Topic Only（33.70）逼近完整方法而 General Only 掉至 30.28——异质推理任务靠局部 task-type 手册；SWE-bench Lite 上 General Only（66.67）更接近完整方法而 Topic Only 仅 64.33——仓库级调试/验证/巡检程序更可迁移。No Propose 高于 No Evolve 但低于完整方法，说明 solver 侧提案与 harness 级编译互补。

**迁移与在线更新**（SWE-bench Lite）：No-Evolve 68.8；Train-Split Transfer 73.4（Claude Sonnet 4.5 在训练分裂上演化技能、Opus 4.7 求解器在测试分裂上消费）；Online-Updated 75.0（测试任务流中原位更新）。两个结论：技能可跨任务且跨模型迁移——较小/异构模型演化的技能对更强求解器仍有效；原位更新再 +1.6，说明在线演化更能贴合测试流的局部分布与失败模式。

**求解器—演化器配对**（SWE-bench Lite）：Opus 4.7 求解器下，Cross（Sonnet 4.5 做 evolver）76.0 略高于 Same（Opus 自演化）75.3，明显高于 No-Evolve 70.7；但 Sonnet 4.5 求解器下 Same 55.3、Cross（Opus 做 evolver）55.7，双双低于 No-Evolve 58.0。即“Sonnet 演化的技能能帮 Opus、却不帮 Sonnet 自己”：harness 迁移不仅取决于技能工件质量，还取决于下游求解器是否有能力可靠遵循、上下文化并适配指导——求解器能力不足时，演化甚至负收益。

**反馈接地**（通过率 %）：

| 反馈层级 | CL-Bench | SWE-bench Lite |
|---|---|---|
| No Evolve | 29.54 | 63.67 |
| Self-Generated（LLM 自判成败与教训） | 27.96 | 61.67 |
| Minimal（仅环境级成败信号） | 29.86 | 67.33 |

三个发现：(1) Self-Generated 在两个基准均低于 No-Evolve（CL 29.54→27.96、SWE 63.67→61.67）——无外部执行证据接地的自我判断会把误导性更新写进 harness，这是全文最重要的负面结果；(2) 环境信号（Minimal/Standard）整体可靠；(3) 有效粒度依基准而异：rubric judge 的 CL-Bench 上 Standard（34.02）显著优于 Minimal（29.86），理解失败原因有助于编译更好的指导；而单测环境的 SWE-bench Lite 上 Minimal（67.33）反略高于 Standard（67.00），论文给出的解释是详细错误信息可能让 harness 过度绑定任务特定失败、稀疏 pass/fail 反而促泛化——反馈不是越细越好，取决于失败原因的结构。

## 6. 贡献与启示

**贡献**：(1) 形式化 online harness learning——冻结智能体 + 外部结构化 harness 在顺序任务流上增量更新，替代“离线攒轨迹再蒸馏”范式；(2) context-to-harness 技能编译机制——失败锚定候选记忆 + evolver 两级策展 + general/topic 双层结构，把单次高噪声执行转化为可复用行为指导；(3) 把 harness 当作可解释分析透镜，系统隔离 evolver 设计、反馈类型、迁移设定对在线自改进的影响。方法学价值在“归因”：多个经验类基线部分基准负增益的事实（呼应作者团队另一工作“harness updating is not harness benefit”的命题）说明自进化研究必须回答“何时/为何有效”，本文给出了受控框架。

**工程含义**：(a) 技能工件（Markdown+YAML、容量受控、可检视）可跨模型搬运——便宜模型离线演化、强模型线上消费是可行部署形态（73.4 vs 68.8），但须校验目标求解器的指导遵循能力（Sonnet 案例的负增益警告）；(b) 在线原位更新优于冻结迁移（75.0 vs 73.4），持续任务流场景应保留演化回路；(c) 反馈回路的接地方式决定系统成败：自评闭环有净负风险，环境验证信号是必需品。

**对音视频技术的上下游关联**：

- 上游（可迁移到 AV 的方法资产）：AV 生产/运维链路——FFmpeg/转码集群、封装与 DRM、直播事故处置、QC 关卡——与本文最优收益环境（TerminalBench2，+10.11）结构同构：CLI 密集、失败可恢复、容器化验证器闭环。“可执行反馈→恢复策略技能”的编译模式（停止重跑、最小复现、修核心、逐步加回）可直接移植为 AV 运维智能体的故障处置 harness。SWE-bench 增益集中于约定稳定的成熟仓库（Django+Sympy 占 fail-to-pass 的 66.7%）提示 topic skill 适合沉淀编解码/封装规范（HEVC 参数语法、HLS/DASH 打包规则、EBU R128 响度工作流），形成跨任务、跨模型复用的“编解码迁移手册”。
- 反馈设计：AV 恰是外部验证器最富集的领域（ffprobe 元数据、编码器退出码、VMAF/SSIM 阈值、响度表、解码一致性校验），Standard 反馈天然可得；但 SWE-bench 上 Minimal≥Standard 的结果提醒：应向 evolver 喂 QC 失败类别与阈值偏差摘要而非原始日志全文，避免 harness 过拟合到单条流水线的偶发失败。
- 下游（AV 对该方法提出的扩展需求）：本文 harness 为纯文本+YAML，而 AV 轨迹包含媒体工件（帧、波形、manifest、码流样本），多模态技能表示是必补缺口（论文 limitation 明确未覆盖非自然语言 harness 形态与多模态/具身设定）；其次本文验证器多为二值判定，AV 质量验证是连续度量带容差（VMAF 阈值、响度 ±LU），“带度量区间的反馈→技能编译”尚属开放问题。成本口径（全套实验 API 开销约 $100K 量级、单次完整 run 约 2–8 小时、16 并发 worker）为工业界评估该范式投入提供参照。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326，证伪门控自进化）**：处理同一核心问题——高噪声经验写入智能体记忆的安全性。Evo-Harness 用 evolver 策展（ACCEPT/MERGE/SKIP + 泛化性测试）做启发式过滤，并以 Self-Generated 实验（CL 27.96 < No-Evolve 29.54）实证未接地自评更新的净负风险；FGSE 把教训当作可证伪假设、经探针验证后才写入。二者互补：Evo-Harness 证明过滤必要性并给出经验边界，FGSE 提供更严格的写入验证机制，“探针门控 + 双层策展”是自然组合。
- **SkillDuet（arXiv:2611.12109，模型-技能协同演化）**：同属技能级递归自改进但位于谱系两端——Evo-Harness 冻结模型参数、只演化外部技能库；SkillDuet 用响应反馈同时驱动参数更新与技能库演化。Evo-Harness 的模型泛化结果（增益随求解器能力递增，开源模型仅 +0.8~+1.1）恰好标定了纯上下文侧演化的能力上限，为参数侧协同演化提供动机证据。
- **TRUST（arXiv:2611.10787，统计保证的递归自改进）**：直接回应 Evo-Harness 的负面发现。Evo-Harness 观察到误导性更新可被写入 harness（Self-Generated 双基准劣于不演化）；TRUST 用在线多重假设检验控制错误进化率并提供统计保证，可作为 harness 演化管线的安全层，把启发式策展升级为有保证的更新准入。
- **LongCapHarness（arXiv:2611.10463，能力引导的自动挂接）**：同一“harness”研究谱系——冻结模型 + 自动合成外部脚手架、免数据合成/后训练。分工不同：LongCapHarness 挂接长上下文推理底层能力（以低于基线 50% 的成本在 HELMET/RULER 超越基线），Evo-Harness 做在线程序性技能编译；二者共同主张 harness 是比后训练更廉价的适配基底，且 Evo-Harness 的相关工作章节亦引用了同谱系 auto-harness 系列文献。
- **WeightLoop（arXiv:2611.07319，权重空间编程）**：自改进介质的对极——Evo-Harness 全部适配发生在上下文侧（外部技能注入），WeightLoop 让 LLM 生成有界参数编辑程序、以实验反馈直接改写已部署权重。两者构成“上下文侧 vs 权重侧”免重训练自改进的对照轴；Evo-Harness 的 solver-evolver 配对实验（技能工件可跨模型迁移）展示了上下文侧独有的可移植性优势。
- **InfraRSI（arXiv:2611.11558，训练基础设施的递归自改进）**：方法论同构的工程化实例——Evo-Harness 用受控实验证明改进回路必须锚定外部接地验证（RQ4），InfraRSI 用五阶段验证工作流把开放式指令转化为分布式训练优化（最高 2.75 倍加速）。两者从实证与架构两个角度支持同一设计原则：递归自改进的更新准入应以可执行验证而非模型自评为准。
