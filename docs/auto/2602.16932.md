# RankEvolve: Automating the Discovery of Retrieval Algorithms via LLM-Driven Evolution

> Jinming Nian, Fangchen Li, Dae Hoon Park, Yi Fang. *arXiv:2602.16932v1 (2026-02-18)*

## 1. 背景与动机

BM25 与 Dirichlet 平滑查询似然（QL-Dir）至今仍是强而高效的一阶段排序器。数十年来的改进——BM25T、BM25-adapt、BM25+、BM25L、Jelinek–Mercer 平滑等——本质上是在固定函数族内做参数调优与针对个别打分分量的人工直觉修正。论文提出的核心问题是：能否自动化发现**更好的词法检索算法**，即不是调参，而是发明新的打分函数（乃至新的文档/查询表示）本身。

作者梳理了三条已有自动化路线及其局限：

- **遗传规划（GP）**：ARRANGER（Fan et al., 2004）在算术原语（+、×、log）与 IR 特征（tf、idf、dl）上进化排序函数；Cummins & O'Riordan（2006）用同类设置进化词权重。GP 的变异是随机子树交换，不“理解”表达式在计算什么。
- **网格搜索**（Taylor et al., 2006）：只能在固定函数上扫多参数，天花板低。
- **学习排序（LTR）**：学习固定特征的组合权重，不发明新特征，更不动打分函数结构。

RankEvolve 的差异化定位：以 LLM 作为**变异算子**作用于完整 Python 程序（约 300 行，覆盖分词、索引、检索全流程），可执行“推理驱动的编辑”——文中给出的例子是 LLM 识别出“缺少文档对查询覆盖度的信号”并主动引入一个；搜索空间从表达式树扩展到整个可执行检索系统。方法学上承接 AlphaEvolve / Evolution of Heuristics / ShinkaEvolve 一脉（已在数学与组合优化上验证），据作者所知是首次应用于信息检索。

从音视频技术侧看，词法一阶段召回是视频搜索、时刻定位、多模态 RAG 管线中文本侧（ASR 转写、字幕、元数据）的标准组件，本文的召回导向目标设定与该场景直接对齐（详见第 6 节）。

## 2. 方法总览

RankEvolve 是构建在 OpenEvolve（AlphaEvolve 的开源复现）之上的程序进化系统，候选排序算法是自包含可执行 Python 程序，由评估器在多数据集上打分驱动迭代。闭环为：选父本 → 组装结构化提示（逐数据集指标、fitness、参考程序、历史尝试）→ LLM（GPT-5.2，temperature 0.85）给出 SEARCH/REPLACE diff → 评估器执行全流程（分词→索引→检索）→ 按指标入种群库。

四个组件：

1. **搜索空间**：种子程序 + 系统提示词共同划定；
2. **种群库**：岛屿模型 + MAP-Elites 维持多样性；
3. **变异提议**：结构化提示引导的 LLM 编辑；
4. **评估器**：返回逐数据集 nDCG@10、Recall@100、延迟。

**fitness 定义**：`0.8 × Avg Recall@100 + 0.2 × Avg nDCG@10`（跨数据集平均）。权重理由是第一阶段检索定位：主目标是最大化供下游 reranker 使用的召回，nDCG@10 作为检索集排序质量的次级信号。该单一标量同时用于种群管理、采样优先级与优化目标，避免三者口径分裂。

**数据协议**：共 28 个数据集（BEIR 14、BRIGHT 12、TREC DL 2019/2020），剔除 BEIR GitHub 上不可得的 BioASQ、Signal-1M(RT)、TREC-NEWS、Robust04，MSMARCO 因充当 TREC DL 语料而省略。其中仅 12 个进入进化评估（BEIR：ArguAna、FiQA、NFCorpus、SciFact、SciDocs、TREC-COVID；BRIGHT：Biology、Earth Science、Economics、Pony、StackOverflow、TheoremQA），其余 16 个完全 held-out、只用于泛化测试。

**进化规模**：BM25 种子跑 300 步（最优程序出现在第 293 步），QL-Dir 种子跑 200 步（最优第 182 步）。

## 3. 关键设计

### 3.1 可进化接口与搜索空间

种子程序显式划分 LLM 可修改的代码区域（可进化接口），系统提示词规定设计原则：鼓励信息论、概率式与根本性新思路，反对无理由的 ad-hoc 约束；同时写明优化目标、指标、数据集与可进化/受限区域——目标是最大化自由度的同时保证每个候选都是合法可执行的完整检索系统。

- **BM25 种子**：三个可进化抽象组件——文档表示、查询表示、打分函数。初始行为复现经典 BM25（k1=0.9、b=0.4，Pyserini 默认）。
- **QL-Dir 种子**：额外加入第四个组件——集合语言模型，初始 μ=2000（Pyserini 默认）。

这一“接口抽象层”是后文消融的核心变量：接口划在哪里，直接决定搜索空间的上界。

### 3.2 种群管理：岛屿 × MAP-Elites

- 种群分为 K=3 个独立进化的岛屿，程序继承父代所在岛屿、保持谱系隔离；每 M=20 代，各岛前 γ=15% 程序迁入相邻岛屿，已迁移个体排除以防重复。
- 每岛维护独立 MAP-Elites 网格，两个描述维度：复杂度（代码长度）与多样性（与种群的编辑距离），各 B=12 个分箱，每岛 144 格。入格条件：格子空置，或新程序优化目标分严格高于在位者。

作者的工程判断：该机制是对抗局部极小/停滞的关键——若总是挑最优个体变异，搜索会迅速停滞；MAP-Elites 按结构多样性存档，保证变异素材不坍缩到单点。

### 3.3 变异提议

每轮按随机选定的三种策略之一选父本：exploration（概率 p_e，岛内均匀随机）、exploitation（概率 p_x，精英档案）、weighted（1−p_e−p_x，性能比例采样）。提示上下文还包括同岛 T=4 个最优程序与 S=4 个随机采样程序（各配完整逐数据集指标）以及此前尝试过的改动——历史失败记录用于防止 LLM 重复无效方向。输出形式为 SEARCH/REPLACE diff。

### 3.4 评估器

导入候选程序并执行完整管线（分词、索引、检索），产出逐数据集 nDCG@10、Recall@100 与延迟测量，随程序一起入种群库。值得注意的工程含义：由于 freeform 设置下分词/索引也属于可进化区域，评估器实测的是端到端检索系统而非孤立公式。

## 4. 实验结果

### 4.1 基线与口径

基线：BM25；BM25+（下界 TF 归一，解决长文档过罚）；BM25-adpt（文档自适应 k1）；QL-Dir；QL-JM（线性插值平滑）。主结果为 16 个 held-out 数据集（BRIGHT 6、BEIR 8、TREC DL 19/20）上的宏平均；显著性为相对各自种子的 per-query paired t-test（p<0.05）。

### 4.2 主结果（held-out 宏平均）

| 方法 | BRIGHT nDCG@10 | BRIGHT R@100 | BEIR nDCG@10 | BEIR R@100 | DL nDCG@10 | DL R@100 |
|---|---|---|---|---|---|---|
| BM25 | 10.55 | 32.11 | 48.16 | 70.95 | 62.16 | 46.02 |
| BM25+ | 9.72 | 31.54 | 45.71 | 69.93 | 61.07 | 46.69 |
| BM25-adpt | 11.05 | 34.67 | 44.62 | 69.55 | 60.90 | 48.23 |
| **BM25★** | **11.79†** | **37.51†** | 47.90 | **72.43†** | **64.57†** | 47.10 |
| QL-Dir | 9.52 | 32.48 | 44.15 | 68.72 | 57.03 | 46.69 |
| QL-JM | 10.17 | 31.08 | 40.61 | 65.79 | 56.65 | 41.05 |
| **QL-Dir★** | **11.42†** | **36.33†** | **46.46†** | **70.22†** | **60.68†** | **47.96** |

要点：

- BM25★ 在 BRIGHT 两项指标与 BEIR R@100 上超过全部 BM25 族基线，并取得 TREC DL 最高 nDCG@10；对种子在 BRIGHT 双指标、BEIR R@100、DL nDCG@10 上显著。
- **诚实的不显著项**：BM25★ 的 BEIR nDCG@10 为 47.90，未超种子 BM25 的 48.16（也不及消融中 constrained 变体的 48.27）——与 0.8 权重压召回的目标设定自洽。
- QL-Dir★ 在全部六格上显著超过 QL-Dir 与 QL-JM，是更干净的全胜。
- 全部增益出现在进化未见过的 16 个数据集上，作者据此论证发现的是泛化的算法而非对评估信号的过拟合。

### 4.3 进化轨迹行为

Recall@100 近似单调上升；nDCG@10 会在 Recall 跳变最大的同一步骤回退——因为加权和目标显式授权了“以小 nDCG 损失换大 Recall 增益”的交易（作者比喻：弃卒保帅），进化只是把这笔交易显性化；组合分全程单调（由选择机制保证）。

### 4.4 进化所得 BM25（第 293 步）：多通道乘性调制打分

顶层结构为四路并行 token 空间共享同一核打分函数 R：

`S(q,d) = R(q_base,d_base) + 0.1·R(q_pfx,d_pfx) + 0.08·R(q_bi,d_bi) + 0.12·G(q)·R(q_mic,d_mic)`

- base：Lucene 分词；prefix：每词截前 5 字符（廉价词干近似）；bigram：相邻词对拼接；micro：滚动字符 3-gram 子词匹配，由 `G(q)=σ((IDF̄(q)−2.2)/1.0)` 门控——仅对平均 IDF 高的稀有/技术查询激活子词通道。
- 共享核：`R = ln(1+E)·B_cov·B_spec·B_coord·B_anc / B_len`，其中 `E = Σ_{t∈M} w(t)·ln(1+tf)`；外层 ln(1+E) 与内层 ln(1+tf) 构成**双重对数压缩的饱和**，对离群词频稳健。
- 词权重 `w(t) = qtf(t,q)^0.5 · IDF(t) · (IDF/(IDF+1))^0.6 · IDF/(IDF+1.25)`，其中 `IDF(t) = −ln((df+1)/(N+2))`（更接近传统 TF-IDF 而非 BM25 的 IDF）。三个 IDF 的函数叠乘构成**软停用词过滤器**：IDF≈1 的类停用词被三重压制，IDF≈8 的稀有词几乎无衰减——进化从未被告知停用词概念。
- 有界乘子链：B_cov = 1+0.25·W_M/W（查询重要性覆盖率，全命中 1.25× 增益，BM25 无显式等价物）；B_spec = 1+0.10·Σ w(t)·min(PMI,3.0)/W，基于点间互信息 `PMI = ln(tf·N/(max(|d|,25)·df))`（封顶 3.0、文档长度下限 25 防短文档极端值），奖励查询词超频出现的文档——与概率检索中集合语言模型的思想暗合；B_coord = 1+0.20·(τ/(τ+ln(1+W)))·|M|/|q|（τ=2.5），校准因子随查询总权重收缩以防与 B_cov 双重计分；B_anc = 1+0.14·ln(1+A)，仅取 IDF>4.2 中最稀有的命中词做稀有锚定，保证有界。
- B_len = 1+0.15·ln(1+(|d|+1)/(avgdl+1))：对数长度阻尼，两倍均长文档约罚 10%，对比 BM25 b=0.4 下最高 40%——独立对齐了 Lv & Zhai 关于 BM25 过罚长文档的已知结论。

作者的元观察：词干近似、软停用词、PMI≈集合 LM、对数长度归一这些被充分研究的概念在纯指标驱动搜索下自然涌现；据作者所知不存在与进化结果完全一致的既有公式。两种解释：这些思想在 LLM 训练数据中密度足够高而在参数化知识中留下强印记，或它们本就是词法检索问题的必然解，或两者兼有。

### 4.5 进化所得 QL（第 182 步）：加性架构 + 分层惩罚

`S(q,d) = Σ_{t∈q_u} ω(t)·s̃(t,d) + Σ m(t,d) + AND(q,d) + LP(d)`

保留加性语言建模骨架（核心仍是带 Dirichlet 平滑的对数似然），但加入标准 QL 完全没有的协调与惩罚机制：

- **三段增强集合语言模型**：①幂回火——集合概率取 0.85 次幂后重归一，压平分布、把概率质量移向稀有词（呼应 Clinchant & Gaussier 的 information-based 模型）；②与文档频率语言模型 P_df=df/N 按 0.90/0.10 插值（每文档只计一次，对爆发式文档更稳）；③混入 3% 均匀分量兜底防零概率。
- **逐词自适应 TF 指数**：tf^β(t)，`β(t)=1−0.30·(1−IDF01) ∈ [0.70,1.0]`——常见词饱和至 0.70 次幂、稀有词保留完整线性 TF。标准 Dirichlet 无饱和、BM25 为均匀饱和、进化版 BM25 为均匀对数饱和，逐词自适应指数在表达力上严格更强。
- **门控 Dirichlet 对数似然**：μ=1750（因背景模型已更平滑而低于默认 2000）；门 g(t)=1+0.45·clip(log(P_df/P_C), −2.5, 2.5)（界 [−0.125, 2.125]，Entity Dispersion Ratio）——文档散布广而总频低的词上调为独立信息源，集中于少数文档的高频词下调。
- **查询权重** ω(t)=(qtf·r)^0.6，r(t)∈[1.0,1.9] 奖励散布广的查询词，外层 0.6 幂对重复查询词做次线性衰减。
- **双粒度惩罚**：leaky rectifier 保留 12% 负分强度（部分匹配但弱）；缺失词惩罚 `m = 1[tf=0]·0.07·ω·log(μP_C/(|d|+μ))`——字面上是 tf=0 处的 Dirichlet 分数打 0.07 折（完全缺失惩罚）。小系数说明进化发现“召回是脆弱的，惩罚必须保守”。
- **软 AND 覆盖奖励**：AND = 0.14·(1/|q_u|)·Σ tanh(ω·max(s̃,0)/3.0)，tanh 近似二值“匹配好”信号，对分值尺度鲁棒，覆盖分数纯反映广度而非深度。
- **文档长度先验**：LP(d) = −0.06·(log|d|−log avgdl)²，双向二次惩罚（10 倍均长约 −0.32），与进化版 BM25 只罚长文档形成对照——超短文档同样有害。

### 4.6 跨种子收敛

两条起点迥异（概率 LM vs TF-IDF）的轨迹独立收敛到同一组抽象原则：TF 饱和、软停用词过滤、显式协调机制、温和长度归一；但实现范式不同——乘性调制 vs 加性惩罚、多通道分词 vs 单空间门控、均匀对数饱和 vs 逐词自适应指数。且 QL 轨迹选择“增强而非抛弃”概率基础（缺失惩罚就是 tf=0 的 Dirichlet 分数），BM25 轨迹则更激进地重构。作者推断：这些原则不是特定打分框架的产物，而是有效词法检索的基本必要条件。

## 5. 消融要点

种子结构自由度消融：三个**功能等价**的 BM25 种子（constrained：公式固定，仅调参+预定义组件变体选择，如 Lucene vs Robertson IDF，等价于自动化网格搜索；composable：模块化原语可改写、管线骨架固定；freeform：仅三个抽象组件+评估器接口，其余全部可进化）。各跑 200 步（freeform 另有主实验 300 步）：

| 代码结构（最优步/预算） | BRIGHT nDCG/R@100 | BEIR nDCG/R@100 | DL nDCG/R@100 | 目标分 Seen(12) | 目标分 Unseen(16) |
|---|---|---|---|---|---|
| Original (step 0) | 10.55 / 32.11 | 48.16 / 70.95 | 62.16 / 46.02 | 40.30 | 49.77 |
| Constrained (115/200) | 11.36 / 34.68 | 48.27 / 70.75 | 61.86 / 45.44 | 42.87 | 50.47 |
| Composable (185/200) | 11.97 / 37.27 | 46.95 / 70.30 | 63.07 / 48.62 | 43.31 | 51.33 |
| Freeform (177/200) | 11.39 / 36.92 | 46.87 / 71.27 | 61.17 / 45.40 | 44.35 | 51.20 |
| Freeform (293/300) | 11.79 / 37.51 | 47.90 / 72.43 | 64.57 / 47.10 | **44.58** | **52.22** |

- **结论一（天花板）**：结构自由度对 seen 与 unseen 目标分均单调抬升；constrained 最早收敛（115 步）但增益最小（40.30→42.87），证实纯调参潜力有限；composable 靠新打分原语进一步改善但被固定管线锁死；freeform 收敛最晚、双口径最高。种子设计设定了 RankEvolve 能发现什么的上界——受限种子把搜索 biased 到原公式附近的局部最优。
- **结论二（互补性）**：无任何结构配置在所有指标上占优。freeform(293) 拿下 BRIGHT R@100、BEIR R@100、DL nDCG@10，但 DL R@100（47.10）落后 composable（48.62），BEIR nDCG@10（47.90）不及 constrained（48.27）甚至种子 BM25（48.16），BRIGHT nDCG@10（11.79）也不及 composable（11.97）。作者归因于不同结构施加的归纳偏置：constrained 的保守性使其在经典公式近最优的切片上免于退化；composable 发现了召回导向改写（激进长度归一、替代 TF 饱和曲线）从而推高 DL R@100。工程含义：从多种子结构并行进化、按部署场景挑选或集成，把进化轨迹当作**结构化探索**而非单目标优化。
- 交叉印证延迟表：constrained 仅 +1.78 ms/query，说明其增益几乎全来自调参；也说明“最简版 RankEvolve ≈ 自动调参”这一档本身已零成本产生价值。

## 6. 贡献与启示

**原文三项贡献**：(1) 首次用 LLM 引导的程序进化演化完整检索算法；(2) 系统研究种子程序设计（结构自由度与抽象层级）对进化结果的影响；(3) 发现可迁移到未见数据集的新打分 motif。

**科学层面**：两条独立轨迹对已知 IR 概念（词干近似、停用词过滤、集合 LM、长度归一）的重新发现与异构重组，为“LLM 参数化知识中印记了领域解空间”或“词法检索存在一组准必然解”提供了证据；同时也实证了 evaluator-guided evolution 能突破调参层级、触及算法结构层——这是与 GP/LTR 划界的关键。

**工程警示**（读者视角归纳）：①延迟不在目标内的后果被精确量化（11×），任何要上线的复用必须先把效率写入 fitness（作者自认 future work）；②进化产物复杂度无约束，“定义并鼓励优雅”是作者自认的下一步；③论文未报告 LLM API 调用成本，也未报告多次独立进化运行的方差（每种子单次运行、单一 LLM），显著性完全依赖检索指标的 per-query paired t-test；④绝对延迟数字依赖其 Python 评估实现，横向比较应以相对倍数为准。

**与音视频技术的上下游关联**：

- **下游直接性**：视频/时刻检索、多模态 RAG 的文本侧一阶段召回普遍以 BM25/QL 处理 ASR 转写、字幕、标题/标签语料，再交给跨模态精排或时刻定位模型。本文 fitness 恰以一阶段召回为重（0.8×R@100），与“召回喂下游”的架构目标一致，进化产物可直接作为该层的替换候选，其提升直接抬高下游任务上界。
- **机制可迁移性**：BRIGHT 式推理密集查询的词表失配（查询词与文档表层不重合），与长视频语义检索中 ASR 错词、专有名词、形态变体问题同构。进化出的前缀通道（廉价词干近似）与按查询 IDF 门控的字符 3-gram 通道（仅对稀有/技术查询启用子词匹配），是对这类失配的直接机制响应，可作为多模态检索稀疏分支与混合检索中 sparse 侧的设计参考。
- **范式可迁移性**：框架优化“评估器定义的任意目标”——凡是可写成自包含程序、且有廉价自动指标的 AV 管线组件（ABR 码率决策、编码模式选择、关键帧采样策略、混合检索融合权重等）都在打击范围内；论文结论也明确指出可扩展至 dense retrieval、learned sparse 与 LLM reranking。
- **反面教训**：对交互式/实时 AV 检索（直播字幕检索、边看边搜），648.89 ms/query 的一阶段召回不可用；延迟感知目标（成本感知进化）是落地前提。

## 7. 与其他论文的联系

- **FrugalEvo（arxiv:2610.03675）**：以单位成本收益为目标的成本感知 LLM 进化（强 LLM 出策略、廉价 LLM 写代码）。RankEvolve 用单一 GPT-5.2 完成全部变异且目标函数不含任何成本项，结果是 11× 查询延迟与“后期精修昂贵”的失衡；FrugalEvo 的成本感知目标正是 RankEvolve 自认 future work（效率约束）在搜索成本与程序效率两个层面的现成方案。
- **ε-MemEvo（arxiv:2608.12522）**：将成功算法策略存为任务无关记忆并经门控自适应注入。RankEvolve 第 4.6 节实证两条独立轨迹收敛到同一组抽象原则（TF 饱和、软停用词、协调机制、温和长度归一）——这恰是 ε-MemEvo 记忆机制应捕获与跨任务迁移的对象；本文两次运行彼此隔离，显式记忆共享是显然的加速杠杆。
- **SwarmEvolve（arxiv:2611.08483）**：声称速度与得分均超 AlphaEvolve 的进化搜索框架。RankEvolve 的搜索后端是 OpenEvolve（AlphaEvolve 开源复现）且仅用 K=3 岛的小配置；引擎可替换性意味着 SwarmEvolve 可直接接入以压缩数百步进化的墙钟时间。
- **Hill Sampling（arxiv:2609.25510）**：冻结 LLM 以当前最优程序为条件反复采样，声称测试时优于进化搜索。RankEvolve 的岛屿+MAP-Elites+迁移全套机制是为对抗停滞而设；Hill Sampling 提供了“最简对照”——本文未做此类对照，是评估复杂种群管理必要性的缺口。
- **AutoAssumption（arxiv:2611.14844）**：在 Lean 证明图上搜索放宽假设并重推导，自动发现 KV 缓存驱逐与剪枝算法。同为“LLM 自动发现超越已发表方法的算法”，但路线是形式化假设搜索+机器检验 vs 本文的经验 fitness 程序进化；分别代表“形式保证”与“经验最优”两极，在系统类算法（缓存/调度/检索）上互补。
- **Agentic Algorithm Design（arxiv:2610.35595）**：LLM 智能体在 Lean 中机器检验进化算法的期望运行时间界，全程无需经验比较。RankEvolve 的延迟失控（177→293 步再增 3.8×）是事后测量才暴露的；若变异阶段附形式运行时间界，复杂度爆炸可在搜索中被剪枝——两法可组合：fitness 管效果、Lean 界管复杂度。
- **VLM 图表分析自主进化（arxiv:2610.35077）**：冻结 VLM、用 AlphaEvolve 式搜索进化推理程序（精确匹配率 16.6%→41.3%、快 3.8 倍）。与 RankEvolve 同属“冻结模型 + 进化外挂程序”范式，分别作用于感知推理与检索排序，共同佐证该范式跨任务族的可移植性；其效率叙事恰是本文缺失的一翼。
- **MLEvolve（arxiv:2606.06473）**：通用 ML 算法自进化（渐进 MCGS + 回顾记忆）。RankEvolve 可视为其在 IR 排序函数上的特化实例；MLEvolve 的渐进式搜索空间扩张与本文“种子结构自由度决定天花板”的消融互为印证——结构/复杂度分级是进化式发现的通用控制变量。
