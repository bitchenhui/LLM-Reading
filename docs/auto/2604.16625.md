# AdaExplore: Failure-Driven Adaptation and Diversity-Preserving Search for Efficient Kernel Generation

## 1. 背景与动机

论文研究的任务是 GPU kernel 运行时优化：输入高层实现（如 PyTorch 原子函数），输出低级语言（Triton）kernel，要求 在保语义正确性这一硬约束下 最小化目标硬件上的运行时间。这一定位区别于以功能正确为终点的常规代码生成，性能目标天然提供了可执行的反馈信号，但搜索空间本身极其困难。

作者将瓶颈归纳为两条：

- **C1 可行性瓶颈**：可行性边界极其尖锐。语法、内存访问、并行化上的微小错误即导致编译失败或运行时报错；Triton 等 DSL 在预训练数据中欠表征，模型对有效实现的先验很弱，导致大比例生成样本直接落入不可行域（论文给出单 pass 下 GPT-5-mini 在 KernelBench Level-2 正确率仅 22%）。
- **C2 局部性瓶颈**：性能地形高度非线性、组合性强。有意义的提升往往需要 tiling 策略、内存布局、并行方案等相互依赖的结构性修改序列，局部编辑易困于局部最优，本质上是一个长时程搜索问题。

对音视频技术栈而言，这一问题处于典型上游位置：LLM/VLM 推理服务的算子层（论文在 FlashInfer-Bench 上实验的 fused add RMSNorm、GQA paged decode 正是生产 serving 框架如 SGLang 所用的 kernel）、神经编解码与视频生成模型的底层实现都依赖此类 kernel 优化；而其方法论（失败驱动记忆 + 保多样性搜索）对 AV 领域自身的 DSL 代码生成（FFmpeg CUDA filter、shader、TensorRT plugin、编解码 intrinsics）具有直接可迁移性——这些场景同样呈现“可行性边界尖锐 + 性能地形崎岖”的双特征。

论文的路线选择是**纯测试时自我改进**：不做微调、不引入外部知识，通过累积执行反馈与结构化探索逐步变强，与 Kevin/CUDA-L1/CUDA Agent 等 RL 训练路线以及依赖专家分析的 KernelSkill 形成对照。

## 2. 方法总览

AdaExplore 由两个互补阶段构成，分别对准 C1 与 C2：

- **Adapt（失败驱动适应）**：以少量与测试集不重叠的种子任务为起点，基于算子文档持续合成训练任务，作为 agent 的“游乐场”；收集执行失败，聚类出反复出现的失败模式，蒸馏为跨任务技能记忆（一组简洁的约束规则），以 system prompt 注入后续生成，使探索大体保持在可行域内。记忆以在线演化方式构建：随任务迭代流式增补，并暴露给后续任务。
- **Explore（保多样性搜索）**：将候选 kernel 组织为搜索树而非单链，动作空间交替“小步局部补丁”与“大步结构重写”；上下文由近期分支历史（working memory）与历史强候选代表池（representative kernels）双源构成；节点选择采用带显式扩展项的 UCT 式规则。返回树中性能最高的正确 kernel。

两阶段在成本上解耦：Adapt 是一次性开销（论文实测约 $201，见第 4 节），且产出的技能记忆可被并行采样、迭代精修等任意搜索策略复用（论文据此构造了 PS w. SM、IR w. SM 基线）；Explore 是按任务、按步数支付的推理时开销。

## 3. 关键设计

### 3.1 Adapt：从失败中学习技能

**任务合成**。采用 Evol-Instruct 风格的变异式提示：每轮采样 3 个种子任务示例 + PyTorch 文档中的算子，提示 GPT-5 通过变异与重组生成新的 PyTorch 模块（保持 Model/get_inputs 等接口结构、3–6 个算子的复杂度带），执行合成代码并丢弃报错样本，共得到 200 个训练任务。作者的经验观察值得注意：变异式合成数据比直接堆高层 building block 提供了更丰富的失败信号——它把 agent 逼进底层算子的边缘用例，更容易暴露可记忆的错误。

**经验→规则→记忆**。对每个合成任务运行 agent（25 步/任务）收集失败生成及其执行反馈；每条失败被摘要为一条“you cannot …”式约束规则（例如“不能在向量化 load 内生成 Triton 指针类型”），由 LLM judge 做语义匹配去重并累计频次；仅保留频次 ≥ 阈值 O（设 3）的规则。最终压缩比非常可观：200 任务产生 1178 条原始经验 → 去重后 174 条 → 保留 78 条高频可迁移提示。类别分布上，Kernel Syntax & DSL 占 37.2% 居首，其后依次为 Python & Env 19.2%、Memory & Indexing 17.9%、Launch & Compile 15.4%、PyTorch Tensor Op 10.3%。这一高冗余本身就是论文的一个论点：kernel 生成失败集中于少数反复出现的约束，解释了记忆为何能跨任务、跨模型泛化。

**设计假设与证据**。频率被当作通用性代理：高频规则对应跨任务稳定失败模式，低频规则多为噪声或任务特例（附录的低频条目样例包括“不能向 0.0.0.0:12017 建 HTTP 连接”这类明显是一次性噪声的摘要）。对照实验（静态文档基线，见第 5 节）进一步表明价值不在于罗列 API：由同一 Triton 3.1.0 安装内省得到的 142 个符号签名参考（1616 cl100k tokens，与技能记忆的 1655 tokens 规模相当）效果显著弱于技能记忆——即定向的失败模式知识优于同等预算的通用文档。

### 3.2 Explore：保多样性的树搜索

**树结构与双动作**。每个节点 s 是一个 kernel 候选，扩展节点即执行后产生子候选。动作二选一：

- **Small step**：基于 old_str/new_str 的补丁式局部精修，先（条件性地）生成评审指导再实施编辑，保持整体结构、修正错误或调优局部选择；
- **Large step**：结构级重写，提示模型生成与代表池结构不同的新 kernel。

动作以概率 p_large=0.2 采样为 large。链式轨迹的隔离案例给出了两类动作的定量画像：large step 的代码变更相似度仅 19%–20%，伴随加速比跳变（某轨迹中第 5 步 0.85×→1.91×、第 20 步 2.42×→3.61×）；small step 相似度 60%–88%，产生增量收益。

**双记忆上下文管理**。这是控制上下文预算与多样性的核心机制。扩展节点 s 时，模型条件于： 根到 s 路径上最近 Crecent=5 个状态的 working memory（近期编辑与执行反馈）； 从早期搜索阶段抽取的代表 kernel 池。为避免近重复 kernel 占位，路径被切分为连续 small-step 构成的连通段，每段至多贡献 1 个代表，再均匀采样至多 Cpool=5 个。两类记忆的清空规则构成对称设计：**large step 清空 working memory**（帮助脱离当前精修链），**small step 清空代表池**（更新紧贴当前分支、鼓励增量改进）。这把“长程搜索信号”压缩为代表解而非全轨迹，回避了全历史爆上下文与激进截断丢信息的两难。

**UCT 式节点选择（含显式扩展项）**。对已有子节点 a：UCT(s,a) = Q(s,a) + c_explore·sqrt(ln N(s)/N(s,a))；对“新建子节点”：Expand(s) = Q_expand(s) + c_expand·sqrt(ln N(s)/|C(s)|²)，其中 Q_expand(s)=max_{a∈C(s)} Q(s,a)。显式扩展项的存在是因为可用的精修/重写分支集合不可预先枚举——这是把 MCTS 从博弈树迁移到开放动作空间的一个必要改造。超参：c_explore=0.3；c_expand 在 Level-2 取 0.3、Level-3 取 0.15，作者的理由是更难的任务需要把预算更集中在当前分支。

**条件性评审指导**。small step 中先生成抽象修改指导可拓宽编辑范围，但复杂抽象指令会降低正确率。因此按工作记忆状态门控：当工作记忆中全部 kernel 都有正确性问题时禁用指导、专注用执行反馈修错；存在至少一个正确 kernel 时启用，鼓励更全局一致的编辑。这是对“指令遵循可靠性”与“编辑视野”之间权衡的一个工程化折衷。

**设置口径**：主测试床 KernelBench Level-2（简单融合 kernel）与 Level-3（ResNet/LSTM 等模型级负载），Level-1 用于数据合成种子；A6000 GPU 定频 1500 MHz；multi-pass 基线（DR. **FlashInfer-Bench 案例**（B200，50 步，GPT-5-mini，真实部署 shape）：

| Kernel | 正确 / 编译错（50 步内） | vs PyTorch | vs 专家实现 |
|---|---|---|---|
| fused add RMSNorm (h2048) | 16 / 34 | 7.22× | **1.75×**（超 FlashInfer CUDA） |
| GEMM (n128, k2048) | 23 / 25 | 0.42× | 0.42×（vs cuBLAS） |

RMSNorm 生成 kernel 以单 tile（BLOCK=2048）载入整个 hidden 维，残差加、方差归约、缩放全部在寄存器内融合完成，证明对 memory-bound 负载 agent 可超越专家调优 CUDA。GEMM 输给数十年工程化的 cuBLAS 属问题内在难度。GQA 的差距则具体可归因：生成 kernel 用两遍 softmax 逐头扫两遍 KV，而 FlashInfer 在 B200 上用 warp-specialized XQA、4 个协作 CTA、单遍 online softmax、TMA 加速分页 KV 访问、FP8 注意力量化与 Blackwell QMMA 指令——compute-intensive 与硬件专用指令类 kernel 仍是明显短板。

SM/PS w. SM 用同一记忆。搜索阶段 L2 为 T=50 $61、T=100 $122、T=200 $244（L3 减半）。等开销对比下 AdaExplore 更省：达到同一加速比，$323（T=100）对 IR w. SM 的 $445（T=200）。墙钟时间受 kernel 计时而非推理支配：两块 A6000、每卡同时计一个 kernel，100 任务×25 步需 4–5 小时。

## 5. 消融要点

KernelBench L2、50 步口径下的组件消融：

| 变体 | Acc | Speedup | Fast@1.2 |
|---|---|---|---|
| 去 Small Step | 99% | 2.35× | 60% |
| 去 Large Step | 100% | 2.60× | 69% |
| 去技能记忆 | 99% | 2.23× | 55% |
| 去代表 kernel 池 | 100% | 2.30× | 63% |
| 去 MCTS（链式搜索） | 100% | 2.45× | 64% |
| 完整 AdaExplore | 100% | 2.63× | 69% |

解读： **技能记忆去掉后掉幅最大**（2.63×→2.23×），可行性是搜索效率的前置条件； **去 Large Step 几乎无损**（2.60×），作者的解释是树分支本身已提供多样性，大步与分支功能部分冗余——这说明“多样性”有多个冗余供给渠道，结构重写并非唯一来源； **去 Small Step 伤害正确率**（99%）与性能（2.35×），结构级变更需要局部精修兜底才能可靠落地； **去 MCTS 退化为链后 2.45×**，多分支存活的收益真实但中等； 代表池作为长程进度存储贡献 0.33×。

另一个有工程价值的旁证是**代码膨胀观察**：迭代精修在预算增大时 kernel 尺寸从 1.8K 增至 7.7K token（4.3×），prompt 从 10.3K 涨至 36.6K（steps 51–200），因为它沿单链不断打补丁、代码只增不减；AdaExplore 的 kernel 尺寸基本持平（1.5K→1.9K，1.25×），原因是 p_large=0.2 的步骤从零重写重置尺寸，且树保留早期候选可供回选。这构成本文对“精修 vs 搜索”行为学差异的一个干净刻画。

## 6. 贡献与启示

**贡献**： 对 kernel 优化的双瓶颈分析（尖锐可行域 C1 + 崎岖性能地形 C2），并有单 pass 正确率数据支撑； 针对性的两个免训练机制——失败驱动的跨任务技能记忆（把原始诊断转为可执行约束、以频率阈值压缩至 78 条）与保多样性的树搜索（双动作 + 双记忆 + 显式扩展 UCT）； 证明二者互补而非冗余：技能记忆抬正确率，搜索在正确率达标后继续抬性能，GPT-5-mini 底座 100 步内 L2 3.11×、L3 1.62×。

**工程启示**：这是一条不碰权重的即插即用路线，适配只能 API 调用闭源模型、无法微调的团队；一次性记忆成本 $201 且可跨 GPU 代际（A6000→GB200）、跨 benchmark（TritonBench-T）、部分跨模型复用；3B 激活参数的小模型经此流程也能达 96% 正确率，说明瓶颈主要在知识与流程而非模型规模。对音视频方向：FlashInfer-Bench 的 RMSNorm 案例直接展示了 agent 优化推理 serving kernel 超越专家实现的可能，对部署视频理解/多模态 LLM 的推理成本优化有直接参考；而“失败→高频规则→上下文注入”与“局部精修/结构重写交替”的组合，可平移到 FFmpeg CUDA filter、shader、TensorRT plugin 等同样具有尖锐可行域的 AV 代码生成场景。

**局限与保留**：compute-intensive 与硬件专用指令类 kernel（GEMM 0.42×、Blackwell QMMA 类 GQA 慢 6.5×）仍远逊专家库，作者自己将“引入参考技能/知识”列为未来工作；跨模型记忆迁移依赖模型相似性（DeepSeek-R1 无收益）；正确性判据 1×10⁻² 容差较松，对数值敏感算子未必够用；加速比按 10 截断使数字不可与未截断的先前工作直接横向比较（作者明言此前工作常报未截断均值、易被极端值主导）；主要评测在 A6000 定频下进行，跨硬件绝对数字不可直接比。

## 7. 与其他论文的联系

- **paper:arxiv:2611.19230（CompoundingKernel）**：同属 kernel 生成的自我改进智能体，任务域直接重合。AdaExplore 是测试时双阶段（记忆+搜索）框架、不改权重；CompoundingKernel 主打从零起步的自我改进闭环并在 SOL-ExecBench（B200）登顶。二者可视为同一任务域上“上下文侧技能累积”与“端到端自我改进闭环”两条改进轴的对照，且评测硬件口径（A6000 vs B200）与基准（KernelBench vs SOL-ExecBench）不同，结果不可直接比。
- **paper:arxiv:2611.14326（FGSE，证伪门控自演化）**：都将经验教训写入 agent 记忆，机制上形成清晰对照——FGSE 要求经验作为可证伪假设经三类探针验证后才写入，AdaExplore 仅用频次 ≥3 的统计过滤。论文附录自认低频条目含噪声甚至错误指导，说明其记忆无证伪保证；FGSE 的验证门控正是针对这一风险的更严格替代，但以额外验证开销为代价。
- **paper:arxiv:2611.12109（SkillDuet，技能-参数共演化）**：SkillDuet 用响应反馈驱动外部技能库与 LLM 参数双向共同演化；AdaExplore 的跨任务技能记忆是纯上下文侧技能、参数冻结。二者构成“技能只进上下文”与“技能-参数共演化”谱系的两个端点，AdaExplore 的跨模型迁移实验（GPT-5 受益、DeepSeek-R1 不变）恰好暴露了纯上下文技能对底座模型相似性的依赖，这是共演化路线宣称要解决的问题。
- **paper:arxiv:2611.10787（TRUST，带统计保证的可信递归自改进）**：TRUST 用在线多重假设检验控制记忆/更新中的错误进化率；AdaExplore 的记忆随合成任务流在线增长，错误规则的累积风险客观存在（其频率过滤只是启发式），TRUST 的统计框架可作为给该技能记忆加装准入保证的直接补强方向。
- **paper:arxiv:2611.20430（TrainExplorer，自主后训练）**：路线级互补——TrainExplorer 以规划-执行解耦实现自主 LLM 后训练（改参数），AdaExplore 明确选择不改参数的测试时适应。对只能 API 访问模型或需快速适配新 DSL/新硬件的场景，AdaExplore 是低成本替代；对可训练自有模型的团队，二者可级联（先记忆适应、再后训练固化）。
- **paper:arxiv:2611.11558（InfraRSI）**：同为系统层负载的智能体优化（分布式训练基础设施 vs GPU kernel），AdaExplore 的“执行反馈驱动 + 结构化搜索”与 InfraRSI 的五阶段验证工作流分别代表了搜索范式与流程化验证范式在系统优化任务上的两种解法。
