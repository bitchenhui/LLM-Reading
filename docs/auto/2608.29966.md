# DataFoundry: Evolving Data Preparators via Recursive Self-Improvement

> Cehao Yang, Xiaojun Wu, Xueyuan Lin, Chengjin Xu, Xuhui Jiang, Hui Xiong, Jian Guo. *arXiv:2608.29966v1 (2026-08-30)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

LLM 的领域适配依赖把原始语料重构为与目标任务对齐的 SFT 数据，合成指令生成使这一过程可规模化。但现有数据制备管线几乎都遵循 construction-then-filtering 范式：先大规模生成候选池，再用过滤器做事后清洗。论文指出的核心结构性错位是：**质量缺陷产生于构建过程本身，而质量控制只作用于产物样本**——既有管线（论文列举 MagPie、CoT-self-instruct、Infinity-Instruct 等一系）常丢弃 50%–90% 的生成数据，却不去修正反复产出劣质样本的上游过程。

把质量干预前移到规模化生产之前，论文识别出两个工程障碍：其一，数据构建工作流往往是长链条、多阶段、以独立代码形式实现（DataFlow、SynData-Toolkit、AutoData、DataMaster、DeepPrep 等），难以诊断与迭代更新；其二，即便定位到问题阶段，跨域（数学/金融/法律/医学）缺乏“该优化什么、怎么优化”的可操作指引。这两点合起来构成 DataFoundry 的动机：在最终大规模生产前，用递归自我改进（RSI）演化“数据制备器”本身。

与三条相关工作线的区分要交代清楚：(1) 相对数据构建线——DataMaster 在累积数据状态上结合下游训练反馈做搜索（成本高昂，需要完整训练回路）、AutoData 迭代修订合成数据 recipe，DataFoundry 则在**可执行运行时规范**层面做组件级适配，评估锚定在小规模 pilot 集而非下游训练反馈；(2) 相对 prompt 迭代优化线（如 Automatic Instruction Evolving），DataFoundry 递归修改的是可执行构建运行时而非生成 prompt；(3) 相对技能演化线（CoEvoSkills 的协同验证器、Skill-R1 的奖励训练、SkillOpt 的有界文本空间优化），DataFoundry 把领域性修改隔离为**可检视的规范适配器**，而非直接改写技能本体。

从音视频技术视角标注上下游关联：视频/音频基础模型（video-LLM、ASR 后处理、codec 语言模型）的 SFT 数据工厂同样普遍采用“字幕/QA 大规模合成 + 去重过滤”范式，同样存在丢弃率高、上游过程不自新的错位。本文虽是纯文本方法，其“演化制备器而非过滤产物”的思路对 AV 数据管线是直接可迁移的上游技术。

## 2. 方法总览

形式化上，数据构建运行时 R 把领域语料 K_d 映射为 SFT 数据集；construction-then-filtering 范式下先得候选池 D̃（体量 Ñ），再经过滤器 F 选出子集 D（N ≤ Ñ）。DataFoundry 把适配环节从 F 前移到 R：

- 初始规范 φ_base 描述通用生产工作流，编译为在线构建运行时 R̃ = Compile(φ_base)；
- 第 t 轮：当前规范 φ_d^(t) 编译为 R̃_d^(t)，以小生成预算 b_N 在 K_d 上构造 pilot 集 P_d^(t)；
- 领域化评估器按领域适配准则 C_d 出评估报告 a_d^(t) = Assess(P_d^(t); C_d)；
- 演化算子更新规范 φ_d^(t+1) = Evolve(φ_d^(t), a_d^(t))，φ_d^(0) = φ_base；
- T 轮后将演化后的规范编译为最终领域适配运行时，做全规模生产。

闭环即 φ → Compile → R̃ → Construct(P) → Assess → a → Evolve → φ'。关键在于：所有诊断与修订发生在小预算 pilot 上，最终一次性全量生产，避免了“边生产边丢弃”的浪费。主实验固定 T=2，依据是 pilot 评估结果在两轮后开始劣化——即停机信号来自在线评估而非固定配方。

架构实现为 Skills-as-Modules：一个由编码智能体 G（GPT-5.6 Sol，经 Codex CLI 执行）驱动的主 CONTROLLER，编排三个模块化技能分别实现 Compile / Assess / Evolve：CONSTRUCTION-RUNTIME-COMPILER 负责规范到可执行运行时的翻译；CONTEXTUALIZED-DATA-ASSESSOR 负责准则选择与 pilot 评估；EVOLUTION-ADAPTER-DESIGNER 负责把诊断归因到组件并写成规范适配器。

## 3. 关键设计

**3.1 运行时规范与稳定接口。** 规范 φ 定义四个稳定组件接口：corpus chunk manager（从 K_d 采样源 chunk 作为知识上下文）、instruction builder（把上下文转为领域相关、格式合规的指令）、response generator（在指令+源上下文条件下生成格式化响应）、batch generation service（并发调用外部模型）。编译器额外提供冒烟测试与结构化日志等工程约束，保证每次编译出的运行时稳定可观测。具体实例化：chunk manager 按 markdown 标题层级分区，长度约束 min_chars=1200 / max_chars=3000，过短合并、过长切分；batch service 以 DeepSeek-V4-Flash 为外部生成模型，最大并发 32。初始指令/响应生成 prompt 明确要求“可由上下文回答但不提及、不依赖上下文访问”——这一自包含约束正是后续演化要反复强化的目标。

**3.2 情境化 pilot 评估。** 准则库 L_crit 覆盖六个互补质量信号：instruction alignment（响应是否直接、准确、充分地回应指令）、self containment（样本脱离缺失上下文是否完整可理解）、information density（领域信息量与冗余控制）、factual grounding（是否被源上下文支撑、无捏造）、domain utility（对下游领域适配的概念/推理模式价值）、numerical correctness（数值、计算与算术推理的内部一致性）。给定领域后情境化选取 C_d ⊆ L_crit，逐样本独立判定，再聚合成数据集级的 recurring deficiency 模式；报告格式固定为“准则统计表 + 优先缺陷（附代表性样本编号与摘录）”，且诊断停留在数据质量层，供下游演化模块消费。

**3.3 适配器式规范演化。** 演化不是就地改写 φ，而是维护一个增量 Δ_d^(t) = Trace(φ_base, Δ_d^(t-1), a_d^(t))，下一轮规范由 φ_d^(t+1) = Adapt(φ_base, Δ_d^(t)) 重构。适配器可修订组件级策略、prompt、配置或协调逻辑，也可新增模块（需声明职责/输入/输出/工作流位置/必需行为），但必须保持编译器强制的稳定接口。设计意图有二：一是**可归因、可检视**——领域性修改以独立文本形式存在，基线行为与领域增量分离；二是防“规范坍缩”——迭代更新若直接累积在 φ 上会引入不可控修改，隔离到 Δ 并显式向前合并（adapter-designer 工作流第 5 步要求把上一适配器的适用要求合并进各模块的最终有效需求）可缓解。adapter-designer 的完整流程为：读基线规范+当前报告+先前适配器 → 按普遍性/严重度/对数据质量的可能影响选优先问题 → 追溯问题首次出现的构建环节并锁定责任模块 → 写出编译器可实现程度的模块级修改。

**3.4 有界递归与预算。** T 固定为 2，理由是 pilot 评估在两轮后典型地开始劣化（论文观察）。pilot 预算 b_N 很小——金融域案例中 pilot 为 100 条，数值正确性仅在 22 条含数值内容样本上评分。

**AV 工程映射（笔记视角，非论文主张）**：四个稳定接口与 AV 数据流水线同构——chunk manager 对应镜头/转录文本分段（1200–3000 字符约束类比分段时长/字数窗口），instruction builder 对应字幕/QA/时序定位问题合成，response generator 对应有据可依的响应合成，batch service 对应推理侧并发调度；self containment 准则直接对应“字幕/QA 数据不得引用未随样本提供的帧、音轨或片段上下文”这一 AV 合成数据的常见缺陷类型。

## 4. 实验结果

**设置**：领域语料沿用 DataPrep-Bench（Liang et al., 2026）——数学 136 篇、金融 80 篇、法律 53 篇、医学 154 篇文档。下游主模型 Qwen2.5-7B，所有生成器产出的领域数据与 Dolly-15k（15,011 条）联合做全参 SFT（LlamaFactory：cutoff 4096、ZeRO-3、FlashAttention-2、bf16、per-device batch 1、梯度累积 4、lr 5e-6、3 epoch、cosine、warmup 0.1，8×H800）。基准与基线实现均取自 DataPrep-Bench：数学 7 项（GSM8K/AMC23/AIME24/MinervaMath/MATH-5000/Gaokao24/OlympiadBench）、金融 3 项（CPA-KQA/FinEval-KR/XFinBench）、法律 2 项（LegalBench/LexGLUE）、医学 3 项（MedCaseReasoning/MedMCQA/MedR-Bench）。基线含 DataFlow 系（预定义算子工作流/算子组合）、LLM 直生成、ReAct 编码智能体、技能增强智能体四类。

**主结果（Qwen2.5-7B，域平均分）关键行**：

| 生成器 | Math | Finance | Law | Medical |
|---|---|---|---|---|
| Dolly-15k only | 23.6 | 57.8 | 74.5 | 36.3 |
| DataFlow | 17.8 | 54.9 | 77.2 | 34.3 |
| DataFlow-Skill | 19.0 | 64.8 | 74.7 | 33.9 |
| LLM-based 最优（Gemini 3.0 Pro） | 23.9 | 52.2 | 74.7 | 29.1 |
| Agent-based 最优（GPT-5.6 Sol） | 25.4 | 51.7 | 73.8 | 34.9 |
| DataPrep-Skill（GPT-5.6 Sol） | 25.0 | 59.9 | 70.7 | 40.1 |
| **DataFoundry（GPT-5.6 Sol）** | **28.8** | **66.1** | **78.6** | **46.0** |

DataFoundry 四域平均分别领先最强竞争生成器 3.3 / 1.3 / 1.4 / 2.2 分（按表列数据，最强对手分别为 Math 的 Agent-GPT-5.6 Sol 25.4、Finance 的 DataFlow-Skill 64.8、Law 的 DataFlow 77.2、Medical 的 Agent-Gemini 3.0 Pro 43.8）。子项上有亮点：AIME24 达 6.7（多数基线为 0.0–3.3），GSM8K 75.1、AMC23 27.5、Gaokao24 44.7 均为列内最高或并列最高。

**同骨干受控比较**（均以 GPT-5.6 Sol 为骨干）：相对 Agent-based Generator，域平均提升 Math +3.4、Finance +14.4、Law +4.8、Medical +11.1；相对 Skill-based（DataPrep-Skill）再提升 +3.8 / +6.2 / +7.9 / +5.9。这说明增益不能归因于更强骨干、agentic 执行或可复用技能本身，而来自框架级设计（RSI 闭环 + 组件级适配）。

**由表可算的一个补充观察**：多数基线相对 Dolly-15k-only 存在域级负迁移（如 DataFlow 数学 17.8 < 23.6、医学 34.3 < 36.3；Agent-GPT-5.6 Sol 法律 73.8 < 74.5、医学 34.9 < 36.3），而 DataFoundry 是表中唯一在四个域上全部超过 Dolly-only 的生成器——即演化后的运行时在所有测试域避免了合成数据“越训越差”的风险。

**产率口径**：DataFoundry 全域共合成 87,566 条（Math 32,692 / Finance 15,689 / Law 17,474 / Medicine 21,711），远低于 DataFlow 的 509,242 与 DataPrep-Skill（GPT-5.6 Sol）的 307,252，却在下游效用上全面领先——单位样本训练效用显著更高，也侧面印证“上游修正替代下游大比例丢弃”的效率主张。

## 5. 消融要点

**RSI 轮数（GPT-5.6 Sol 骨干，Qwen2.5-7B 下游）**：Math 平均从 Round 0 的 25.6 升至 Round 1 的 28.4、Round 2 的 28.8，Round 3 回落到 26.1；Finance 轨迹非单调但同样在 Round 2 达峰（66.1），追加一轮大幅跌至 58.3。结论：递归优化有效但有界，过度自改进会给运行时引入不良修改、导致部分系统坍缩——这与主实验固定 T=2、以 pilot 评估劣化为停机信号的做法自洽。

**跨下游模型泛化（Llama-3.1-8B，训练与评测设置不变）**：

| 生成器 | Math | Finance | Law | Medical |
|---|---|---|---|---|
| Dolly-15k only | 11.7 | 15.1 | 69.5 | 20.4 |
| DataFlow-Skill | 6.1 | 36.5 | 73.1 | 36.0 |
| LLM-based GPT-5.2 | 9.2 | 27.4 | 76.4 | 32.4 |
| Agent-based GPT-5.6 Sol | 9.7 | 30.7 | 70.2 | 34.0 |
| DataPrep-Skill（5.6 Sol） | 9.2 | 36.1 | 72.8 | 33.6 |
| **DataFoundry（5.6 Sol）** | **13.6** | **41.3** | 71.1 | **39.9** |

Math / Finance / Medical 分别领先最优基线 2.6 / 4.8 / 3.8 分；Law 为 71.1，未达最优（LLM-based GPT-5.2 为 76.4），是全部实验中 DataFoundry 唯一未取胜的域×模型组合，提示法律域增益的部分模型依赖性。总体结论：制备数据的训练效用可跨模型家族迁移。

**案例一（金融域，机制级证据）**：pilot（100 条）评估报告中各准则均分：instruction_alignment 8.78、self_containment 6.93、information_density 8.55、factual_grounding 8.96、domain_utility 7.36、numerical_correctness 7.02（仅 22 条含数值内容）。优先缺陷被定位为：100 条指令中 84 条使用“所给文本”“上表”等回指性引用（如样本 52 要求“根据所给表格”计算周转组合值而指令中并无表格），以及部分 chunk 不完整/跨练习边界导致无法有据作答。适配器据此做三处组件级修订：chunk manager 增加业务语料准入门控（拒收仅含标题的 chunk 与不含完整命题/定义/程序/例题/问题陈述的 chunk）；instruction builder 禁止输出指示性短语；response generator 强化任务类型与子部分完成的校验、要求每条事实/法律/会计/量化断言由确切源 chunk 支撑、并对计算施加确定性检查（小计/总计对账、终值与所示算术一致）。这是“输出缺陷 → 组件归因 → 局部修订”闭环的完整实例。

**案例二（数学域，样本级证据）**：同一傅里叶分析语料下，DataPrep-Skill 产出通用低推理量 QA；DataFoundry 基线版显著更丰富，但指令仍以“所给文本式 (11.28)”形式依赖外部上下文（评估识别的自包含缺陷）；演化后变为完全自含的 2p-周期 |x| 傅里叶系数计算题（要求给出 a_0/a_n/b_n 及偶奇 n 的化简式），响应约 3500 字符、含完整积分与分部积分推导、可独立验证。即递归演化同时提升了推理强度与单例完备性。

## 6. 贡献与启示

**贡献**：(1) 把领域数据制备的质量干预从“过滤产物”前移到“演化制备器”，并以可执行运行时规范 + 稳定接口使长管线变得可诊断、可增量修订；(2) Skills-as-Modules 架构把 RSI 的 Compile/Assess/Evolve 三算子落成可由编码智能体驱动的模块，评估锚定在领域情境化多准则 pilot 诊断上，而非昂贵的下游训练反馈；(3) 适配器隔离（Δ 相对 φ_base）给出防规范坍缩的工程机制；(4) 实证表明两轮有界 RSI 即可在四域取得一致下游增益，且数据效用跨模型家族迁移，同时给出“过度演化致退化”的边界证据。

**局限与工程注意**：(1) 停机准则是启发式的——T=2 基于“pilot 评估两轮后劣化”的观察，而该信号本身由 LLM 评估器给出，存在评估器与演化器同源的自指风险，论文未报告人工金标校验；(2) RSI 开销（编译/评估/演化各轮的 token 与算力）未做核算，无法直接回答“收益/成本比”；(3) pilot 规模小（金融案例 n=100），评估统计量的方差与准则选择的敏感性未讨论；(4) Law×Llama-3.1-8B 一格失利，领域泛化非绝对；(5) 产率仅 87.6k，规模化行为（更 corpus、更大量产）未验证。

**对音视频技术上下游的启示**：本方法处于“语料 → SFT 数据 → 领域模型”链路的最上游，对 AV 领域（视频理解、字幕生成、ASR 纠错、codec 元数据理解等模型的适配数据工厂）是范式级输入。可直接移植的是闭环结构：把 AV 语料的分段器、指令合成器、响应合成器、批量推理服务固化为四个稳定接口，在小时级 pilot 数据上以模态化准则（时序自包含——不得引用未附带的帧/音频上下文；事实接地——断言须有转录/字幕支撑；数值正确性——时间码、帧率、码率算术一致）做诊断，再以适配器形式局部修订。相较“先合成百万级再过滤”的现行做法，该路线把修正成本从全量数据移到小 pilot + 规范层，与 AV 数据生产中高丢弃率的痛点正对齐。需警惕的同样是其消融所示的有界性：无停机准则地持续演化会在两轮左右见顶回落，AV 场景部署时应预设轮数上限与 pilot 评估监控。

## 7. 与其他论文的联系

- **paper:arxiv:2611.13524（The RSI Tax）**：本文 Round 3 上 Math 28.8→26.1、Finance 66.1→58.3 的退化是“RSI 不总值得其成本”的经验实例；RSI Tax 提出的全成本度量（有界笔记基线在精度持平时省 65.6–71.0% 总 token）恰好指向本文未做的开销核算，二者互补——DataFoundry 以固定 T=2 + 适配器隔离控制风险，RSI Tax 提供成本侧的量化框架。
- **paper:arxiv:2611.12109（SkillDuet）**：更新面（update surface）的直接对照。DataFoundry 冻结外部生成模型（DeepSeek-V4-Flash）与下游模型，仅演化外部技能/规范工件；SkillDuet 让 LLM 参数更新与外部技能库协同演化。两者分别代表“纯外部技能演化”与“权重+技能共演化”两条技能级 RSI 路线。
- **paper:arxiv:2611.10787（TRUST）**：DataFoundry 防“规范坍缩”靠基线保持 + 稳定接口 + 适配器隔离，属启发式机制；TRUST 用在线多重假设检验为 RSI 控制错误进化率并提供统计保证，可作为适配器接受/拒绝门控的形式化补充层。
- **paper:arxiv:2611.10463（LongCapHarness）**：同属 harness 级 RSI——不改权重、不做后训练，通过修改运行时挂接模型底层能力；DataFoundry 是该思想在数据构建运行时上的实例化（其相关工作亦援引 harness engineering 谱系），LongCapHarness 则作用于长上下文推理能力，二者共同支撑“外部运行时是有效更新面”的论断。
- **paper:arxiv:2611.11558（InfraRSI）**：同为 RSI 作用于训练基础设施工件——InfraRSI 将开放式指令转化为分布式训练优化（最高 2.75× 加速），DataFoundry 将领域需求转化为数据构建运行时优化；两者共享“验证工作流门控的工程工件演化”模式，分别覆盖训练算力侧与训练数据侧。
- **paper:arxiv:2611.11509（SimplEvo）**：同为免权重更新的外部状态自改进。SimplEvo 以自写文本记忆 + 教训精炼实现（EBench 成功率 46.7%→81.7%），DataFoundry 的累积适配器（含“向前合并先前要求”步骤）结构上等价于一种带组件归因的演化文本记忆，且两者都观察到改进窗口有界、需抑制无益累积修改。
