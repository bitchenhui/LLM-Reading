# Cloak of Invisibility: Real-Time Privacy-Preserving Volumetric Video Streaming

> Hossein Khalili, Philip Do, Alexander Vilesov, Achuta Kadambi, Kittipat Apicharttrisorn, Nader Sehatbakhsh. *arXiv:2608.11645v2 (2026-08-12)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

体积视频流（VVS）管线的一般形态是：V 台标定 RGB-D 相机同步采集 → 边缘设备预处理 → 云端融合为时变点云/网格 → 面向 6DoF 遥现、远程协作与混合现实分发。已有系统（Holoportation、MetaStream、Vues、M5、Habitus、FarFetchFusion、Theia、ImmerScope、MagicStream 等）只优化重建质量、带宽、时延与渲染，完全不处理隐私问题。论文指出的核心事实是：**隐私失败发生在管线最早期**——只要原始 RGB-D 帧离开相机侧进入服务器，事后的模糊或访问控制都无法撤销初次暴露。因此需求是 privacy-from-source：私有内容在离开可信边界之前被滤除，同时公共场景仍保有可供实时重建的可用性。

与 2D 视频逐帧脱敏相比，VVS 引入三个本质性的新难题：

1. **跨视角复现**：某一视角漏掩或仅部分移除的私有目标，会在多视角融合后的 3D 场景中重新出现——信息在一处删除后可经另一视角“复原”，这使 2D 逐帧处理的 recall 语义失效。
2. **RGB 掩蔽残留几何泄漏**：仅模糊 RGB 外观，深度图与点云中仍保留目标轮廓与体素几何，下游检测器仍可检出“此处存在一个人”。
3. **同类公私歧义**：遥现场景中前景参会者是 public、背景同类路人是 private——类级策略要么删除所有人（毁掉效用），要么泄漏私有无辜者。这要求实例级隐私策略在融合前跨视图一致地执行。

已有隐私视觉方法（像素化、混淆变换、安全推理、相机内过滤，如 Fawkes、Pinto、PECoM、CamPro 等）均为单相机、单帧、2D、类级别设计，不处理标定多视角 RGB-D 融合。从音视频技术链条看，本文填补的是**采集端与体积视频融合/编码之间的前置过滤层**，该层此前在 VVS 栈中是空白。

## 2. 方法总览

InViStream（Invisible Volumetric Streaming）的核心思想是联合三个单独都不充分、联合后有效的线索：

- **目标身份**：COCO 预训练、免微调的现成检测器，只在分块（chunk）首帧触发，不进入逐帧关键路径；
- **目标几何**：检测框中心邻域的深度统计（均值/方差），用于把粗框细化为贴合目标的掩蔽；
- **多视角一致性**：利用标定相机变换，把参考视图中用户声明的 public 实例投影到其余视图，同步同类实例的公私标签。

数据流为：每路相机流在边缘本地完成检测（chunk 首帧）→ 深度条件掩蔽构造 → 参考视图公私判定 → 跨视图标签传播 → chunk 内复用深度剖面与检测框 → 净化后的 RGB-D 帧上行 → 云端只做点云转换、私有像素点删除、坐标变换、合并与分发。下游点云渲染与流媒体格式**完全不变**——隐私机制改变的是“什么数据被允许进入云端”，而非渲染器或码流格式。

威胁模型（论文表 1）值得注意：可信源端（相机侧边缘设备执行检测、深度掩蔽与隐私策略）；诚实但好奇的云端与接收端（遵守融合协议，但可检查收到的任意 RGB、深度、掩码标记色、点云数据）；私有资产定义为私有实例的 RGB 外观 + 深度几何 + 3D 点。明确不承诺密码学隐私，范围外包括被攻陷传感器、恶意边缘设备、音频/元数据泄漏、对抗样本与物理攻击。隐私目标受限于检测器与深度质量的上界。

## 3. 关键设计

**3.1 分块检测与候选生成。** 逐帧逐相机跑实例级检测对边缘设备过于昂贵。InViStream 在长度为 N 的 chunk 首帧运行检测器（实现为 Faster R-CNN + ResNet-50-FPN 或 MobileNetV3 主干；另评估 Tiny YOLOv2 式轻量检测），分数 ≥ θ 且标签属于敏感类集合 C（人、屏幕、手机、相框等）的框成为敏感候选。检测器在合成与真实场景上均**不做微调**，这既是泛化证据，也决定了性能上界。

**3.2 深度条件掩蔽（方法核心）。** 检测框本身不是隐私掩码：整框掩除会删除过多公共内容，通用分割网络又无法区分同类公私实例且逐帧开销大。对每个敏感框 b_i = (x, y, w, h)，取框中心，提取 w×w 深度窗口 V_i，计算深度剖面：μ_i（均值）、σ_i（标准差）、阈值 τ_i = ασ_i。掩蔽判据为：

M_i(u,v) = 1{(u,v) ∈ b_i} · 1{|D(u,v) − μ_i| ≤ τ_i}

两项约束严格互补：**框约束**防止与目标深度相近的框外背景（如墙面）被误删；**深度约束**防止整框过掩——只保留深度与目标剖面一致的目标本体像素。本质上这是用“检测框 + 一阶深度统计”构造的免分割网络伪实例分割，逐像素仅一次深度比较，无逐帧 DNN 推理，边缘设备可负担。掩码在 chunk 内的所有帧上复用，检测开销被 N 帧摊销。

**3.3 跨视图公私同步。** 隐私是实例级而非类级：参考视图（配合用户指定的工作区）声明各类的 public 实例（如遥现前景参会者）。每个 public 实例中心的 3D 坐标 (r_x, r_y, r_z) 经标定变换 T_{r→w} 齐次投影到目标视图 w；目标视图中同类检测框中心与投影点最近者标为 public，**其余所有同类敏感框一律标 private**。这一缺省是刻意偏向隐私的保守规则：任何未被匹配到已声明 public 实例的目标都被掩蔽，因此参考视图中不可见、但其他视图可见的私有目标也会被正确处理（不匹配即掩）。标定误差在多人靠近时会导致公共中心误投影——这是论文自述的主要失效模式之一。

**3.4 云端私有点删除与融合。** 掩码信息以标记色 c_priv 的形式**带内**编码在净化 RGB 帧中上行。服务器将每视图转点云后，凡 Color(q) = c_priv 的点坐标置为 (∞,∞,∞)，随后用 Open3D 的非有限点过滤高效删除，再经外参变换到全局坐标系合并。这种实现让掩码随标准 RGB-D 数据走，无需额外码流层，保持与现有 VVS 系统（含其压缩与传输环节）兼容。

**3.5 时域优化与运动有效性条件。** 设私有目标沿深度轴的平均速度为 v̄，帧间隔 Δt，检测周期 N 帧，则复用掩码的有效性条件为深度位移 δz = v̄·N·Δt ≤ ετ（ε 为容差因子，τ 为深度阈值）。该条件给出部署准则：快速运动需要小 chunk，静态/慢速场景可用大 chunk 换吞吐。

**3.6 线索互补性。** 论文系统分析四种公私布局：不同深度的分离框 / 不同深度的重叠框 / 相近深度的分离框 / 相近深度的重叠框。深度项可分离图像空间重叠但深度不同的目标；框项在深度相近时限制掩蔽溢出；最坏情形（框重叠且深度相近）只有参考视图公私选择 + 跨视图传播能解。结论明确：**没有任何单一线索在所有布局下可靠**，这是方法必须三线索联合的机理依据。

## 4. 实验结果

**数据集口径。** 合成：3 个开源 3D 室内场景 × 8 个虚拟视角，插入 V-Sense/8i 人体模型（最多 2 public + 2 private 人），共 400+ 配置；通过对 3D 模型预着色获得逐像素精确实例级 GT。真实：Intel RealSense D435，5 类环境（会议室、开放办公区、走廊、室外露台、客厅）× 8 个标定视角 × 4 种活动（交谈、行走、坐、站立），150+ 场景实例，6 名成年受试者（知情同意）；真实 GT 由 SAM 人工提示生成，且 InViStream 检测器**未**在这些掩码上训练。硬件：边缘为 Jetson Orin Nano（6 核 ARM、1024 核 Ampere GPU、8 GB RAM），云端为 2×A6000（NVLink）+ 10 核 Intel CPU。

SSIM > 0.98、点距 ~1e-4 量级说明公共 3D 内容几乎无损。真实场景内部呈现清晰的隐私/效用权衡：Office 召回最高（0.981）而 Dice 最低（0.736）——偏隐私的过掩行为；Living room Dice 最高（0.849）但召回最低（0.839），源于反射面与杂物导致深度剖面估计困难。

**同类公私压力测试（≥3 人场景，论文表 4）：**

| 构成 | Dice↑ | Recall↑ |
|---|---|---|
| 1 public / 2 private | 0.695 | 0.932 |
| 2 public / 1 private | 0.684 | 0.799 |
| 2 public / 2 private | 0.656 | 0.960 |

这是论文最重要的实例级隐私测试：所有人类共享同一检测标签，类级掩蔽器要么全删要么泄漏。Dice 下降不矛盾——当投影的 public 中心靠近 private 框时系统保守过掩，作者明确表示宁删邻近多余像素也不暴露私有人。

InViStream 以 90 ms 达到接近 SAM 的 Dice（差 5 个点）且快 ~15 倍，同时全面超过轻量级方案。注意这些基线本身不解决实例级公私策略问题，此对比仅隔离“私有目标分割精度/时延”单变量。

**隐私攻击测试（PODR）**：用 Faster R-CNN 人体检测器攻击输出，掩蔽前所有场景 PODR = 100%。掩蔽后合成均值 6.3%（逐场景 1.0%–12.5%），真实均值 14.3%（逐场景 1.0%–25.0%）；最差真实场景为 Living room 25% 与 Conference room 21%。这是作者自称的悲观测试——仅检出“存在私有人”即算泄漏。

## 5. 消融要点

**Chunk 大小 N（隐私–吞吐主旋钮）**：ResNet-50 合成数据上，Dice/Recall 从 N=1 的 0.808/0.904 衰减到 N=20 的 0.695/0.735，机理即 3.5 节的 δz = v̄NΔt ≤ ετ 有效性条件——私有目标在两次检测刷新之间移出复用掩码的深度容差。对应的时延收益：MobileNet 掩蔽时延 77.5 ms（N=1）→ 17.4 ms（N=5），吞吐 12.9 → 57.5 FPS；ResNet-50 在 N=20 达 41.2 FPS。部署准则：按预期私有目标运动速度选 N，且**无需改云渲染、无需重训检测器**即可在工作点间滑动。

**深度阈值 ατ 敏感性**：增大阈值通过过掩提升 Recall，但会删除非私有内容而压低 Dice——与真实场景中 Office/Living room 的权衡表现一致，说明该参数是隐私/效用的直接控制量。

**几何布局四象限**（不同/相近深度 × 分离/重叠框）：验证 3.6 节的线索互补性——不同深度重叠框由深度项解决，相近深度分离框由框项约束溢出，最坏情形（重叠+相近深度）只能靠参考视图公私传播。这是对“为什么必须多视角推理”的受控验证：单帧 RGB 在同类歧义下信息量不足。

**真实场景误差结构**：反射面（镜子）、玻璃、杂波、光照变化与深度抖动是真实误差的主要来源；Living room 的镜像反射与远距离小目标（深度不稳定 + 目标像素占比小）被论文列为两类典型硬例。真实数据采用顺序静态采集纪元而非完全同步的多相机硬件——多视图几何与掩蔽逻辑得到验证，但**部署级相机阵列的同步误差未被测量**，这是实验侧最重要的口径限制。

## 6. 贡献与启示

**问题形式化贡献**：首次将“标定 RGB-D 体积视频的源端隐私”形式化，包括诚实但好奇云模型与同类公私实例策略，指出这是系统级问题——涉及掩蔽施加位置（边缘 vs 云）、决策跨视图传播方式、掩蔽数据与 3D 重建的交互、以及与时延/吞吐/体验的权衡，与孤立的分割精度正交。

**系统/工程贡献**：(1) 检测框 + 深度剖面构造的伪实例分割，把逐帧 DNN 开销降为 chunk 级，边缘 90 ms 内完成掩蔽；(2) 标定投影驱动的跨视图公私同步，缺省保守（不匹配即掩）；(3) 掩码以标记色带内传输 + 非有限点过滤的云端删除，对下游点云管线完全透明；(4) 参考视图 + 工作区构成简单可审计的策略接口，可替换 UI 而不动核心管线。

**对音视频链路的启示**：隐私过滤层必须位于任何 3D 融合/体积编码**之前**——这是次序约束而非可选优化；“一处删除可经另一视角复原”的跨视角泄漏论证对所有多目采集系统（光场、NeRF/3DGS 采集阵列）普适。掩码质量上界决定隐私上界：Dice ~0.8、残差 PODR 6.3%（合成）/14.3%（真实）意味着**非绝对隐私**，作者明确警示部署风险是“虚假信心”。运行时结果应读作工作点菜单而非单一配置，且隐私/时延旋钮与隐私策略解耦。

**局限**：依赖检测器、深度与标定质量；消费级 RGB-D 在反射/透明/弱光/远距下失效；标定误差在多人靠近时造成公私误标；不保护音频、元数据及公共物体上可见的私有信息；真实评估未覆盖硬件同步场景。

## 7. 与其他论文的联系

- **paper:arxiv:2610.21121（ResStreamGS）**：按高斯时间特性分流编码传输的移动端 VVS 框架，属于本文明确划为“互补”的 VVS 传输优化类工作——InViStream 决定“什么内容可离开源端”，ResStreamGS 类系统决定“如何高效传输”。技术衔接点：若下游表示从点云换成 3DGS，净化必须发生在任何跨视图高斯优化**之前**（多视角外观被烘焙进高斯基元属性后无法事后剥离），而 InViStream 的逐视角掩蔽恰在 RGB-D 层生效、与表示无关；但其评估仅覆盖点云融合，向 GS 融合管线移植是明确的开放问题。
- **paper:arxiv:2609.33969（SAGA，4D 稀疏锚点体积视频压缩）**：压缩器会忠实保留输入的全部几何与外观并追求 BD-rate 最优——若私有内容漏入融合结果，压缩反而将其高效传给接收端。因此“源端净化先于压缩”的次序约束对 GS 体积视频编码管线同样成立；InViStream 输出的净化点云可作为此类编解码器的合规输入。
- **paper:arxiv:2607.28144（ReGenVC）/ paper:arxiv:2607.22772（GenVC）**：生成式/语义码流（首帧 + 姿态关键点、扩散一步解码）与 InViStream 共享同一设计哲学——改变“离开源头的码流内容”而非事后处理。对照价值在于：语义参数本身构成新的泄漏面（姿态关键点属生物特征数据），恰好落在 InViStream 威胁模型声明的范围外边界（元数据泄漏）上；二者共同提示未来体积视频编码标准中源端隐私与超低码率生成表示需联合设计。
- **paper:arxiv:2606.28027（MLVC）**：关联在部署生态层面——InViStream 的边缘掩蔽同样受端侧算力约束（实验平台 Jetson Orin Nano，检测分块触发即为算力妥协），MLVC 验证的消费级 NPU 百 FPS 神经推理与跨平台熵解码规避方案，为掩蔽模块向异构端侧芯片迁移提供了工程参照。
