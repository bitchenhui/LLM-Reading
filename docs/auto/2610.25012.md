# Conjugate Compilation: Self-Improving Agentic Co-Compilation for Speculative Decoding

> Annabelle Sujun Tang, Rohan Mahapatra, Christopher Priebe, Hanyang Xu, Manya Ghobadi, Christopher Rossbach, Hadi Esmaeilzadeh. *arXiv:2610.25012v1 (2026-10-18)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

论文的出发点是服务侧的“存量容量回收”而非扩容。作者用一组企业级实测数据锚定问题：2026 年 5–8 月间，通过 Systalyze Utilyze 对 350 个企业用户采集的 6000 次小时级 GPU 计算利用率测量，平均利用率仅 17.6%，94% 的用户平均低于 50%。在此背景下，如何在已部署 GPU 上榨出有效吞吐，成为与加卡互补的路线。

投机解码是论文选定的载体：小 draft 模型连出 γ 个 token，大 target 模型一次前向完成验证，以此减少 target 前向次数。但当前部署惯例（CONVENTIONAL）将两模型各自独立编译、串行执行，单轮时延为 T_conventional = γ·T_D + T_V。批内存在真依赖（验证必须等本批 draft token 就绪），但依赖不跨批：target 验证第 b 批时，draft 可为第 b+1 批生成提案——这暴露出可合法并发的结构性空间，常规编译流程完全没有利用。

相关工作被作者归为两类：多卡/解耦的并行投机解码（PEARL、MineDraft、SwiftSpec）与单卡 profile 驱动的运行时调度（FASER），共同点是都在“已编译产物”之上做调度、放置与资源分配，draft 与 target 的共享执行始终在编译器优化边界之外。论文由此提出核心研究问题：在不改变两模型任何计算的前提下，将其共置同一 GPU 并联合编译，能否回收独立优化时被搁浅的容量？

支撑整个方法的关键洞察是收益的不可分解性：一个孤立更快的 kernel，放进联合执行后可能加剧资源竞争、破坏有利重叠或引入同步开销。论文用公式显式陈述了这一点——T_round(θ) 一般不等于 T_round(∅) 减去各共轭组孤立时延差之和，因为共享执行本身已掩盖部分操作时延，且联合计划中的决策会改变轮内其他位置的资源竞争与同步。结论是：跨模型编译必须以“共置共享执行的实测性能”为目标函数，而不是 kernel 级孤立延迟。

## 2. 方法总览

Conjugate Compilation 由三层构成：执行基底、计划抽象、搜索系统。

**执行基底：依赖保持的多流 co-scheduler。** 将 draft 与 target 各自切分为有序段（粒度从整层、attention/MLP 半层直至单个投影阶段），分别提交到两条 CUDA 流；流内保序，流间仅在存在跨流依赖处插入 CUDA event（形式化为 G_σ = (V, E_σ)，σ=∅ 即纯 co-scheduling）。整轮（含两流与依赖边）捕获为单张 CUDA graph 一次回放，消除 host 侧 launch 开销。这个“仅 co-scheduling、无共编译”的版本同时充当后续一切评估的锚点。

**计划抽象：联合优化计划 θ 的四要素。**（1）共轭算子组 G(θ)：每组 g = (f, {o_k}) 取自同一 kernel family f（GEMM 及 RMSNorm、残差加、softmax 等行算子）的 K_g 个跨模型独立算子，2 ≤ K_g ≤ K_max，组外算子保留独立 kernel；（2）交错比例：GEMM 中各成员按算术工作量份额 π_k = F_k / ΣF_r 分派，是派生量而非搜索维度；（3）kernel 配置：经 TVM 暴露多后端配置，选择依据是整轮实测而非孤立时延；（4）调度安排：共轭组诱导 target 段 i 与 draft 段 j 的联合映射 i→j，要求单射且沿两条执行链严格递增（防环），联合节点 J(i,j) 是共编译工作的调度容器，通过 join/fork 与两流衔接。

**优化目标与搜索。** 在静态合法计划集 Θ_legal 上求 θ* = argmin T_round(θ)，其中 T_round 为完整共享执行的实测时延；候选先过数值校验再计性能。由于该空间组合爆炸且单次评估需真实编译与 GPU 执行，论文构建了自改进 agent 环路：MCTS 选择待细化的已探索计划，LLM 提出结构化编辑，编译器与 GPU 作为环境返回三元组 E(θ') = (r_t, v_t, c_t)——全轮奖励回传 MCTS 树，kernel 级判定与编译反馈进入 LLM 的累积经验。计划历史、调优后的 kernel、测量结果跨阶段与跨运行持久复用，且全程不改 LLM 权重。

## 3. 关键设计

**3.1 共轭算子组与交错 kernel（interleaved kernels）。** 这是论文真正的编译层创新：一种操作数内存布局变换，把两模型的工作交织进同一 kernel 的公共 tile 内。对 GEMM，每个成员被分解为 output-tile 与 reduction-slice 单元，一张 descriptor 表记录每个单元的成员归属、tile 坐标、归约切片与操作数地址——使得形状互不相关、操作数分开存储的操作能在同一次 launch 中共存执行。关键约束是每个单元只读写并累加自己操作的数据，数学完全保持。这一变换的直接收益机制是“填 partial wave”：单个操作的输出 tile 数填不满 GPU 的 wave 量化粒度时，混合多操作的工作可吃掉彼此闲置的执行容量。同一原理扩展到 RMSNorm、残差加等行算子。交错只是联合计划可选的一种变换，而非计划本身的定义——即便两模型保留独立 kernel，其 kernel 配置也可按联合执行表现联合选择。

**3.2 MCTS 选择与 LLM 提议的分工。** 树上每个节点是一个完整可执行的联合计划，根为空计划 ∅（即 co-scheduling 锚点），每条边是一次 LLM 编辑。选择用 UCT：Q(θ') + β·sqrt(ln(N(θ)+1)/N(θ'))；progressive widening 限制新分支引入速率（|ch(θ)| < ⌈κ(N(θ)+1)^α⌉）。LLM 不直接生成 GPU 代码，只在计划抽象上操作，动作空间为 add/merge/split/remove 四类，每条编辑可携带 target 层与 draft 步的范围以一次覆盖多个位置；编辑类型、算子标识、范围、合法放置全部取自编译器枚举，故每个提议要么可直接解释、要么带具体反馈码被拒。LLM 的 prompt 不只含被选计划，还含其祖先链、各代实测轮性能、累积 kernel 判定、编译反馈、合法放置、以及代表性 draft–target 段对在“分别/并发/常规”三种执行方式下的测量——通过 plan 与祖先及反馈的对照，agent 能把共享执行的变化归因到产生它的决策上。

**3.3 三级反馈门。** 环境评估的护栏设计相当细：（i）静态合法性预检——共轭算子间有依赖、联合放置成环、组跨段、超内存预算等在编译前即拒并返回错误码；（ii）kernel 增益门——每个新共轭组以捕获 CUDA graph 交替计时块方式与其成员的独立 kernel 对比，测量间将权重轮换刷出 L2，仅当 v(g) = Στ(o_k)/bτ(g) > 1 + max(δ, z·b_s) 才准许入轮（bτ(g) 含该组 launch 的全部工作，δ 为最小增益裕度，b_s 为配对计时相对 bτ(g) 的标准误）；（iii）数值校验——整计划编译进完整轮后逐 draft step 对照参考执行，要求相对一致在 10⁻² 内，argmax 差异仅当参考 logits 本身近平局时豁免，失败位置或联合集被隔离并回报 agent。过门只说明局部有希望，最终裁决仍是全轮实测。

**3.4 计量学与奖励定义。** 全轮计时采用锚点—候选—placement control—候选—锚点的交替块结构：placement control 保留候选的 join/fork 依赖但执行原始独立 kernel，从而把“调度安排的收益”与“编译变换的收益”解耦为两个可分别测量的差分。奖励取配对锚点/候选时延比的中位数，再乘以锚点对两个常规基线（独立编译背靠背执行、单 CUDA graph 内串行）中较快者的加速比；该缩放因子在配置内固定，不影响 MCTS 排序。

**3.5 搜索空间扩展与终选纪律（附录 A）。** 进度平台期依次执行：以更大预算重调近失 kernel → 扩大候选组与合法放置 → 将 co-schedule 细化到投影级分段使联合节点可选更精确的工作 → 暴露更多 kernel 模板。为排除“调优努力差异”这一混淆解释，终选计划中每个跨模型 GEMM kernel 的调优预算不低于其替换的各 kernel 预算之和。终选另做严格复测：ABBA 块重测最强候选，同窗口重测常规与双流基线，接受条件为数值通过、配对 95% 置信区间增益排除零、且超过噪声阈值；最后对每个联合节点范围做留一增益检验，不达标即剪除（除非全计划显著快于剪除版）。

## 4. 实验结果

**设置。** B300 SXM6 上四对配置：Llama-3.1-8B/3.2-1B、Qwen3-14B/0.6B、Qwen3-32B/Instruct-2507-4B、Llama-3.1-70B/3.1-8B；RTX 5090 上两对：Llama-3.2-3B/3.2-1B、Qwen3-Instruct-2507-4B/0.6B。统一 batch 8、γ ≤ 6、输入 1024 token、FP16。实现基于 Apache TVM v0.25（从 PyTorch 导入）、CUDA 12.8，agent 为 OpenAI gpt-5.6-luna。每项实验 50 次取中位数，归一到 CONVENTIONAL；利用率用 Nsight Compute，kernel trace 用 CUPTI。

**总吞吐（B300，四对，相对 CONVENTIONAL 的 target 验证吞吐）：**

| 配置 | CC + Interleaved |
|---|---|
| Llama-3.2-1B / Llama-3.1-8B | 1.59× |
| Qwen3-0.6B / Qwen3-14B | 1.55× |
| Qwen3-4B / Qwen3-32B | 1.43× |
| Llama-3.1-8B / Llama-3.1-70B | 1.34× |
| 四对平均 | 1.47×（CC 单独 1.38×） |

按摘要口径，跨 B300 与 RTX 5090 共六个单卡配置的几何平均每轮加速为 1.37×，加交错核升至 1.45×，最佳 1.59×。Llama-3.2-1B（draft，γ=4）+ Llama-3.1-8B 的单轮时延从常规 31.3 ms 降至 co-compilation 的 22.0 ms、再加交错核的 19.7 ms（按 31.3/22.0 ms 折算，CC 单独约 1.42×）。

**利用率与 roofline。** 交错核版在 B300 四项上平均将利用率提升 50%（摘要口径：RTX 5090 平均 1.46×、B300 1.50×）；Llama-3.1-8B/3.2-1B 从 11.6% 升至 18.7%，61% 的利用率增幅支撑了 59% 的吞吐增幅。Llama 下投影（down projection）两 kernel 串行合计 17.9 TFLOP/s，交错后单 kernel 达 46.5 TFLOP/s（2.6×），roofline 上明显贴近 8 TB/s HBM 带宽屋顶（B300 峰值 2.25 PFLOP/s）——印证交错收益主要来自带宽受限 regime 下的有效带宽利用。

**敏感性（相对 CONVENTIONAL）：**

| 条件 | 配置 | CC | CC + Interleaved |
|---|---|---|---|
| RTX 5090 | Llama-3.2-1B / 3.2-3B | 1.33× | 1.38× |
| RTX 5090 | Qwen3-0.6B / Qwen3-4B | 1.37× | 1.41× |
| batch 16（B300） | Llama-3.1-8B / 3.1-70B | 1.20× | 1.22×（batch 8 时为 1.27×/1.34×） |
| γ=6（B300，b8） | Qwen3-0.6B / Qwen3-14B | 1.32× | 1.37×（γ=4 时为 1.45×/1.55×） |

RTX 5090 上常规基线利用率已较高（Llama 对 50.4%、Qwen 对 46.2%），交错版仍提至 73.2% / 67.9%，但交错本身的边际增益收窄为 4.1% / 3.3%。draft 长度方面，实测接受率 α=0.73 下 γ=4 生成 852 token/s、γ=6 为 713 token/s，联合编译实际上改变了该工作负载下 γ 的最优选择。

## 5. 消融要点

论文的“消融”主要由敏感性分析与机制性对照构成，而非组件级拆除：

- **交错的边际贡献**：B300 上从 1.38× 到 1.47×（平均 +7%），RTX 5090 上 +4.1%/+3.3%——收益随常规基线利用率升高而衰减，符合“填补闲置容量”的机制解释；真正的上限场景是低占用、小 batch 的单卡部署。
- **batch 维度**：70B/8B 对上 batch 16 将增益从 1.34× 压到 1.22×，说明 batching 自身供给的并行度与跨模型联合编译是互补关系，两者收益部分重叠。
- **γ 维度**：γ=4 优于 γ=6，长草稿增加串行 draft 步并改变可重叠工作的平衡。
- **placement control 对照**：测量设计层面把调度安排与编译变换两个效应解耦，是论文方法论上最值得借鉴的“内置消融”。
- **抗混淆机制**：调优预算 effort floor、平台期扩空间、终选 ABBA 重测 + 95% CI 排零 + 噪声阈值 + 留一剪枝，共同排除“编译努力差异”与“噪声过拟合”两类假阳性。

缺口（笔记视角）：没有“LLM 编辑 vs 随机/启发式编辑”“MCTS vs 贪心搜索”的组件级对照，无法量化 agent 与树搜索各自的贡献；搜索成本（候选计划数、编译与调优墙钟、LLM token 开销、摊销周期）全文未量化；γ、batch、序列长度的扫描很窄（γ∈{4,6}、batch∈{8,16}、1024 定长、仅 FP16），也未讨论动态负载/多租户下计划的泛化。

## 6. 贡献与启示

**贡献可归为四点。**（1）问题重述：把投机解码从运行时调度/放置问题改为跨模型编译问题，将 draft–target 共享执行纳入编译器优化边界；（2）目标函数修正：以共置共享执行的全轮实测为目标，并形式化论证孤立 kernel 改进的不可加性；（3）交错操作数布局变换：descriptor 驱动的跨模型 tile 交织，数学保持、支持 GEMM 与行算子；（4）自改进 agent 编译器：LLM 编辑 + MCTS 探索 + 三级反馈门 + 持久经验资产，改进完全发生在 LLM 权重之外的计划/kernel/记忆层面。从作者谱系看，这是其 REASONING COMPILER（NeurIPS 2025）路线从单模型 serving 优化向跨模型联合编译的自然延伸，也与 LLM kernel 优化工作（KernelBench、STARK 等）形成“从单 kernel 到多模型”的对照定位。

**方法论启示**：测量即目标函数、锚定 ABBA 计量、统计门控接受、留一剪枝，这套实验卫生对任何“以 noisy 端到端指标驱动的自动搜索”都成立，包括音视频侧的编码器参数搜索与感知质量优化。局限方面，除前述搜索成本未披露外，数值一致性的 10⁻² 相对容差与 argmax 平局豁免以 FP16 参考执行为基准，对采样温度敏感的生成任务是否够严未讨论；结论限定于单卡、固定 batch 的投机解码形态。

**对音视频技术链路的关联（笔记视角，非论文结论）**：其一，音视频推理管线大量存在“多模型共驻单卡”结构——VLM 视觉编码器与语言头、ASR→LLM→TTS 级联、视频超分与编码协同，只要模型间存在固定的依赖与可并发窗口，本文的“跨模型联合编译、以共执行实测为准”范式即具备迁移条件，交错布局对带宽受限算子的 2.6× 提升（贴近 HBM 屋顶）与 codec 内核优化的 roofline 逻辑同构。其二，投机解码正被用于流式多模态 token 生成（语音 token、视频 latent 流），每轮时延直接对应首包与交互延迟，1.37–1.45× 的每轮加速即对应可感延迟与单卡并发路数的改善。其三，RTX 5090 这类消费级卡正是端侧实时音视频 AI 的主力硬件，论文数据显示基线占用已高（约 50%）时 co-location 仍有效但交错边际收益仅 3–4%，对音视频管线（常已是高占用）的收益预期需据此校准。

- **paper:arxiv:2611.14326（FGSE）**：FGSE 要求经验教训作为可证伪假设通过探针验证后才写入记忆；本文的共轭组须先过增益门与数值校验、终选阶段还需留一检验证明每个联合节点范围有可测增益，才被保留进最终计划与经验库——“可证伪证据先于信念写入”的模式在系统层复现。
- **paper:arxiv:2611.11558（InfraRSI）**：同属“递归自改进 agent 下沉到基础设施/系统层优化”的路线：InfraRSI 以多阶段验证工作流优化分布式训练基础设施，本文以编译器+GPU 为环境优化推理编译计划，二者都以真实执行结果而非模型自评为验收标准，只是优化对象分处训练与推理两端。
- **paper:arxiv:2611.12109（SkillDuet）**：SkillDuet 让 LLM 参数与外部技能库协同演化；本文是刻意的不对称对照——LLM 权重冻结，改进全部沉淀为外部资产（计划历史、调优 kernel、测量结果、跨运行复用），说明在系统优化任务中“改进应驻留在可执行工件而非模型权重”是一条可行设计。
