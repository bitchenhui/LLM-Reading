## 1. 背景与动机

长上下文推理增强的主流路线是“合成长语料 → LLM 后训练”：NExtLong 以难负例干扰项拼接长序列，PolicyLong 用持续演化的模型刷新 on-policy 数据，EntropyLong 以预测不确定性筛选有效上下文，另有 LongFilter、LADM、Quest、LiteLong 等。论文对该路线的批评有两点：其一，数据合成策略与后训练配方彼此解耦、经验驱动，难以判定哪些数据性质对长上下文推理是本质的；其二，算力密集、难以规模化。成本锚点（作者估算口径：H100 租金 $3.85/GPU 小时）：NExtLong 报告的 64 GPU×15 小时训练配置折合 960 GPU 小时、$3,696.00；PolicyLong 按训练 FLOPs 近似式缩放（参数项 6TP 与序列相关项 L·s·d，并假设各 GPU 有效吞吐相同）估为 482.81 GPU 小时、$1,858.82；而 LongCapHarness 的开发期 API 支出估算为 $541.47——论文摘要称不足上述两条训练线各自估算成本的一半。

LongCapHarness 的立论基于一个关键观察：未经显式长上下文预训练的 LLM，只要被适当“装配”上长上下文推理能力，就能在长上下文基准上取得强表现。即把“能力”视为模型中已潜伏、可由外围可执行工作流激发的对象，而非必须以梯度注入的参数性质。

在此基础上，论文重新定义了问题中心：长上下文推理的核心困难不是把输入塞进上下文窗口，而是任务求解所需的结构性操作——识别任务结构、定位相关证据、选择性保留中间结果、整合为全局一致的答案——在单体端到端调用中保持隐式，模型难以在一次性处理全长输入时协调它们。能力分解将潜在任务结构显式化为有定义输入/输出的操作；harness 跨操作保存共享状态、每次模型调用只供给其所需上下文，从而解耦任务总输入长度与单次调用的上下文预算。这条“解耦”既是性能来源（规则显式的任务可跨长度稳定近满分），也是成本来源（推理期输入 token 膨胀）。一个值得注意的工程事实：执行模型的窗口全程保持原生规模——Llama3-8B 用 8K、Qwen2.5-3B 用 32K——完全不做任何上下文扩展。

## 2. 方法总览

整体为“开发集构壳 → 冻结入库 → 测试期选择执行”三段式。

形式化：能力 C 定义为从输入 I 到输出 O 的抽象变换 O=C(I)（I≠O），与具体问答对无关——两个问答对若需要同一变换即共享同一能力。每个能力对应一个能力 harness H_C：完成该变换的外围具体可执行工作流（代码、prompt 模板、执行规则）。构壳时将 C 分解为能力原语集合 {CP₁..CP_m}，每个原语 O_i←CP_i(I_i) 刻画一个子变换；harness 输出由控制逻辑 F 组装：A←F({H_CP_i(I_i)})。以正文给出的 Reranking 能力为例：分解为 Relevance Judgement（输入 prompt，LLM 实现，输出相关性分数）与 Ordering（输入分数，代码/LLM 实现，输出 top-1），二者顺序衔接。

构壳的 RSI 循环（开发集上）：harnessing agent（论文采用 GPT-5.6-Sol）研究问答对的任务描述，识别输入输出形态，决定新建能力或复用既有能力；随后分解原语、确定控制逻辑、逐个实现原语使其成为可执行操作；按控制逻辑执行得到 harness 生成答案，与参考答案比较，据此递归修订三类对象——原语实现、控制逻辑、能力状态——直到差异足够小（停止条件由 agent 自行决定）。随后冻结 harness 存入能力库，并附带一段文本描述（能力摘要、输入输出信息）供测试期选择。

测试期执行：执行 LLM（Llama3-8B / Qwen2.5-3B）将问题与库中各 harness 的文本描述比对完成选择；运行时加载其代码、模板与规则，将问题连同源文本与任务信息交给工作流；控制逻辑为每个输入初始化全新运行态并调度原语：LLM 原语由模板 + 问题相关字段 + 所需段落/中间结果构造有界 prompt；代码原语直接操作存储记录；中间结果保存在 LLM 上下文之外、按需注入后续原语，直至产出最终答案。

数据与开发配置：开发集 2,242 条、测试集 59,826 条、零重叠（HELMET 2,080/27,035；RULER 112/32,388；LongBench-v2 50/403）；HELMET+RULER 覆盖 34 个子任务 × 5 个基准输入长度（8K–128K，共 170 个任务-长度单元格）。开发期 LongCapHarness 与 RRSI 均以 GPT-5.6-Sol 为开发者模型、Llama3-8B 做候选执行；RRSI 中 GPT-5.6-Sol 兼任 proposer/selector/critic/pruner。

## 3. 关键设计

（1）能力契约与原语体系。HELMET/RULER 共 harness 了 11 个原语：keyword matching、lookup、relation following、state tracking、counting、ordering、relevance judgement、rule inference、classification、evidence selection、evidence integration，按变换族归并为六组并映射任务：匹配检索 → Recall 与 RULER 大海捞针；关系/状态追踪 → RULER 变量追踪；频次统计 → RULER 常词/高频词抽取；重排 → Reranking；示例分类 → ICL；证据式回答 → RAG/LongQA/RULER QA。原语名只描述变换、不绑定具体实现，多个任务族共享同一分解——这是“库”可复用性的来源。

（2）原语实现的代码/LLM 二分。执行规则显式无歧义的操作（赋值、出现计数、排序）用代码实现；输入输出可由文本表示的原语用 LLM 调用实现，此时 agent 只需指定供给文本、prompt 模板与响应格式。这条二分线是全文性能与成本的分解轴：代码原语的跨长度不变式成立（Recall 两种执行模型均 100.00），语义原语则把性能上限交还执行模型。

（3）控制逻辑。负责编排原语执行次序、管理原语间输入输出、决定工作流停止条件——即把分解出的操作图编译为可执行程序。

（4）能力状态与每输入运行态的分离。能力状态是能力内可复用的协议：规定新输入如何转换为原语可直接使用的格式、哪些中间原语输出需要保留以推导最终答案，且对开发集具体输入不感知；每输入的实际问题与中间结果每次运行新建，不计入能力状态。功能上能力状态是共享工作区，使各组件交换输出而不丢失源身份（source identity）——对需要回报证据位置的检索/召回类任务是决定性设计。

（5）RSI 的搜索空间约束：能力引导。论文最有信息量的机理对比是 RRSI：RRSI 在可用开发轮次内把问题当作上下文溢出来处理——其中间开发代码反复出现 token 上限与字符级切块的修订痕迹，即“按输入的物理组织来组织算子”；LongCapHarness 从任务求解操作的逻辑组织出发，能力分解的约束使操作及其依赖显式，从而引导 RSI 在任务的计算结构上、而非输入的物理切分上做搜索。这是作者对两者 Avg 相差 39.65/40.27 分的归因（基于对 RRSI 中间代码的检查，属解释性证据而非受控实验）。

（6）库化与跨模型迁移。harness 冻结后与执行模型解耦，从 Llama3-8B 迁移到 Qwen2.5-3B 时仅需对模型、tokenizer、证据预算与 serving 配置做适配：代码原语执行规则跨模型不变，语义原语更换“判官”。这一性质把“能力”的载体从参数彻底移到了外围软件。

## 5. 消融要点

论文无独立消融章，等效消融证据有四组。

（1）能力原语 RSI 轨迹（HELMET 重排；500 条记录、每长度 100 条 8K–128K；实现先冻结后评测，在执行模型单次调用上下文预算内处理完整候选集）：

| 版本 | 8K | 16K | 32K | 64K | 128K | 均值 |
|---|---|---|---|---|---|---|
| V0：BM25+排序（初始，代码实现） | 53.26 | 45.44 | 39.52 | 34.66 | 28.85 | 40.35 |
| Llama V1：LLM 打分+排序 | 65.51 | 51.88 | 36.50 | 22.95 | 17.89 | 38.95 |
| Llama V2：比较+归并 | 57.79 | 47.48 | 36.70 | 30.85 | 25.51 | 39.67 |
| Qwen V1：LLM 打分+排序 | 68.14 | 55.13 | 37.06 | 25.12 | 17.08 | 40.50 |
| Qwen V2：比较+归并 | 71.76 | 64.48 | 55.50 | 45.85 | 43.83 | 56.28 |

V0→V1 将相关性判断从词法匹配换成 LLM 语义打分（排序仍由代码完成）：两模型在 8K–16K 改善，但 32K–128K 反而劣于 BM25——语义原语随输入长度衰减快于词法。V1→V2 同时改变判断输出与下游组合：LLM 表达段落间相对偏好，排序原语据此对小组排序并归并成全序。Qwen 上均值 +15.78 至 56.28 且各长度全面最优（128K 对 V1 +26.75）；Llama 上仅 +0.72 至 39.67，收益集中在 32K–128K。结论：原语 RSI 通过“局部判断 + 组合方式”的联合精修获得增益，且增益依赖执行模型与输入长度——语义判断能力是约束项。（Qwen V2 均值 56.28 与主表 Rank 列一致，可交叉印证。）

（2）跨模型迁移作为组件类型消融：代码组件跨模型不变（Recall 恒 100.00），语义组件随模型漂移（重排 +16.61 / LongQA −10.39），直接验证了设计（2）中二分线的预测。

（3）RRSI 作为“无能力分解的 RSI”对照：Avg 39.67/38.46，结合其中间代码的物理切块痕迹，支撑“能力契约约束 RSI 搜索空间”这一核心主张。

（4）构壳模型依赖（Limitation，定性）：换用 Llama3-8B / Qwen2.5-3B 自任构壳 agent 时性能骤降；弱模型独立构壳被明确列为开放问题。

## 6. 贡献与启示

贡献三条： 提出无数据合成、无后训练的长上下文推理框架 LongCapHarness； 在 HELMET/RULER 上以两种执行模型验证性能与成本优势，并在 LongBench-v2 上界定适用边界； 倡导“激发显式训练之外的潜在能力”这一研究方向。

方法学启示：能力契约的本质是给 RSI 提供搜索空间的结构先验——参考答案差值是唯一外部监督，若无分解约束，RSI 会坍缩到对输入做物理重组织（RRSI 的教训）。“比较答案 → 修订实现/逻辑/状态 → 冻结入库”的循环把传统上人工编写 pipeline 的过程变成以参考答案为奖励的开发期搜索，单次成本在数百美元量级。

工程含义： 推理期输出 token 压缩近一个数量级（Llama 89.55M→1.87M），但输入膨胀约 1.7–1.9 倍；当输入单价不低于输出单价时总成本反超（Qwen $53.74 vs $29.39），对输入侧昂贵的场景（如多模态/视觉 token）该权衡需整体重估。 冻结库跨模型迁移只需 model/tokenizer/证据预算/serving 适配，3B 执行模型 + 8K/32K 原生窗口即可服务 128K 输入，对端侧与低成本部署有直接价值。 局限清晰：构壳依赖 GPT-5.6-Sol 级强模型；语义整合型任务（LongQA、LBv2 Long 子集）仍落后训练路线；开发集对每类任务有暴露、测试为未见输入，但 RULER/HELMET 中合成任务占比高，向真实任务的泛化未在本文验证。

与音视频技术的上下游关联（本段为笔记作者的技术推断，非论文结论）：上游上，本文属 LLM harness 工程 / RSI / 模型-程序计算（相关工作引 LOTUS、SUQL 语义算子）这一供给侧，为 A/V 管线提供“可执行能力库 + 自动构壳”的方法学。任务级映射高度同构：Recall/RULER 类的 keyword matching / lookup / state tracking 原语对应媒体档案中基于字幕、ASR 转写、元数据的实体与属性检索（本文中此类任务近满分且跨长度稳定，提示以文本代理做多模态检索时管线化收益最大）；重排能力的 V0→V2 演化正是文本到视频检索“粗排→精排”的设计空间，V2 的成组相对比较 + 归并排序在候选集规模扩展上的表现（Qwen 均值 40.50→56.28、128K 段 +26.75）对视频候选池精排的规模化有直接参考价值；LongQA 的弱势与 LBv2 Long 子集落后 3.65 分，恰对应长视频叙事理解中证据选择与整合的语义瓶颈——提示 A/V 长视频 QA 不能只靠 harness，仍需多模态对齐训练配合。架构上，“单次调用有界上下文 + 状态外置 + 控制逻辑编排”与视频理解的分片-聚合管线（镜头切分、片段检索、时序定位、证据整合）天然同构，能力原语体系可视为该类管线的形式化描述，按文本描述选择 harness 则对应查询路由。成本结构上，开发期 API 搜索 vs 训练 GPU 的对比对应 A/V 工业系统中“离线管线自动构造”vs“模型训练”的投入抉择；而推理期输入膨胀在视觉 token 昂贵的多模态场景会被放大，需重新核算。

## 7. 与其他论文的联系

- **MaD-RSI（arXiv:2610.28201）**：关联最强。两者都以“可跨异构 LLM 复用的 harness”为优化对象与产物——LongCapHarness 的跨模型迁移（Llama→Qwen，Avg 仅 −0.59）与 MaD-RSI 的“模型即数据、跨模型共享外壳”目标直接呼应。差异在监督信号：LongCapHarness 用开发集参考答案做差值驱动，MaD-RSI 用多模型失败轨迹做训练证据，二者可互补（失败轨迹可解释 RSI 为何停在次优 harness）。
- **TRUST（arXiv:2611.10787）**：LongCapHarness 的 RSI 停止条件由构壳 agent 自行决定、无错误率控制，冻结入库的 harness 存在开发集过拟合风险；TRUST 的在线多重假设检验为 RSI 提供统计保证，可直接用于硬化本文的停止判据与入库判据。
- **SkillDuet（arXiv:2611.12109）**：同为“外部可复用能力库 + 执行反馈演化”（技能库 vs 能力 harness 库，响应反馈 vs 参考答案比较），但 SkillDuet 同步更新模型参数、走内外协同路线，LongCapHarness 明确拒绝后训练——两者构成外部能力积累路线上“纯外壳 vs 参数+技能共演化”的两个极点，可对照检验“参数冻结是否为长上下文任务的可行约束”。
- **TGR-EvoDAG（arXiv:2610.32326）**：以 DAG 式多智能体代码演化构造生成式推荐完整管线并经在线验证（CTR 相对 +0.40%），与本文“控制逻辑即原语编排、由 LLM 递归改写”同构；其在工业在线约束下的成功为 harness/管线演化范式在（含视频）推荐系统的可部署性提供了外部证据。
- **RSI-Opt（arXiv:2610.32026）**：同为“元智能体跨运行演化代码工件（优化器策略与代码库 vs 能力 harness）+ 执行反馈”模式，且都报告产物跨模型复用（RSI-Opt 的优化器策略跨模型迁移、LongCapHarness 的 harness 跨执行模型迁移），共同支撑“RSI 产物可脱离特定模型复用”这一关键假设。
- **WeightLoop（arXiv:2611.07319）**：反向对照——同属免重训练的自改进，但 WeightLoop 用有界参数编辑程序直接改写已部署模型权重，LongCapHarness 把一切改进留在外围软件、权重完全冻结；两者界定“权重内 vs 权重外”自改进谱系的两端。
- **InfraRSI（arXiv:2611.11558）与 RSI-PDEbench（arXiv:2611.14949）**：同属递归自改进范式家族（前者以五阶段验证工作流优化训练基础设施，后者提供 PDE 求解的 RSI 基准与智能体），与本文无任务级重叠，仅作为 RSI 作为通用开发范式的平行证据。
