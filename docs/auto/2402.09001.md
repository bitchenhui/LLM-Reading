## 1. 背景与动机

视频通信的流量与能耗双重压力是本文的直接动因。按 Ericsson 报告口径，全球移动数据流量将从 2019 年的 39.5 EB/月增至 2028 年的 472 EB/月，不足十年十倍；其中视频流媒体占 2023 年总流量的 71%，预计 2028 年达 80%。另一项研究估计 2018 年视频通信贡献了全球温室气体排放的约 1%。终端侧，已有工作证明视频播放会显著缩短移动设备续航。因此解码能耗与压缩效率并列成为编解码实现的硬约束，且二者存在内生张力：标准组织（ISO/ITU 与 AOM）每一代格式（AVC 2003、HEVC 2013、VVC 2020；VP9 2013、AV1 2018、AVM 计划中）均以同等主观质量下码率减半为目标，而压缩增益通常以解码复杂度/能耗为代价，代价大小又强烈依赖实现路径（参考实现 vs 优化实现）、指令集（SIMD）与执行载体（SW vs HW）。

既有文献的局限清晰可辨：Laude 等以编/解码时间作为复杂度代理，未做能耗实测；Kränzler 等此前的对比仅覆盖 HEVC/VVC 参考解码器；Khernache 等研究 HEVC SW vs HW 解码对整机能耗的影响（SW 解码能耗最高为 HW 的 4 倍；HW 解码器至多占设备功耗 30%，SW 解码占 50%），但其口径为含静态功耗的全设备功耗，本文明确只考察动态能耗；其余工作或为两两格式对比（VVC vs HEVC、AV1/VVC vs HEVC），或尝试用单一指标统一描述能耗与码率。缺口在于：没有一项研究在同一码流集、同一锚点（VP9）下，同时横跨 6 种格式、11 个 SW 实现、SIMD 开关与 HW 解码四个维度做压缩-能耗联合评测。本文即填补该缺口，并额外给出 SW 与 HW 解码的直接能耗比。

## 2. 方法总览

**评测矩阵**：6 种格式（AVC/VP9/HEVC/AV1/VVC/AVM）× 3 类解码载体。SW 实现共 11 个：参考实现 JM 19.1 / HM 16.23 / VTM 19.0 / libvpx 1.10 / libaom 3.3 / avm 3.0，优化实现 FFmpeg 4.4（AVC）/ openHEVC 2.0 / VVdeC 1.6 / FFmpeg 4.4（VP9）/ dav1d 1.0（AVM 无优化实现，故 6+5=11）。HW 解码仅 4 种格式——Rock 5B 的 VPU 只支持 AVC/VP9/HEVC/AV1。编码器为 x264 r3065、x265 3.5.1、VVenC 1.7、libvpx 1.10、libaom 3.3、avm 3.0（libaom 与 avm 用同一命令行）。

**码流生成**：采用 AOM CTC 序列集，取类 A1（4K）、A2（全高清）、A3（高清）、B（全高清）（分辨率描述按论文原文口径）；编码条件为 random access（RA）与 low delay B（LB）。QP 点位：x264/x265/VVenC 用 22/27/32/37/42/47，libvpx/libaom/avm 用 23/31/39/47/55/63。关键设置：x264/x265 preset=placebo、tune=psnr、10bit（high10 / main10、x265 另加 rd=6、rect、amp）；VVenC 用 randomaccess_slower.cfg（RA，IntraPeriod=65）/ lowdelay_slower.cfg（LB）并开 QPA；libvpx cpu-used=1、profile=2、10bit；libaom/avm cpu-used=0、固定 QP offset、deltaq-mode=0、关 TPL；各编码器统一 GF 间隔 16，RA 下 keyint/IntraPeriod=65 且允许 lag-in-frames=19，LB 下 keyint 置 infinite/9999、lag-in-frames=0。序列专属参数按 CTC 逐条设置（文中略）。

**能耗测量协议**：先测解码过程能耗、再测 idle，二者相减得纯动态能耗，方法沿作者此前工作；统计上以置信区间检验约束测量序列——99% 概率下偏离真值小于 2%。所有 SW 解码器限制单线程执行以保证可比。SW 平台为 Intel i7-8700 桌面机（CentOS），经 CPU 内建 RAPL 直读能耗，且先前实验已验证 RAPL 与外置功率计高度一致。HW 平台为 Rock 5 Model B 单板机（八核 ARM + VPU，Ubuntu，经 FFmpeg 调用 VPU），整机经主电源口接 ZES Zimmer LMG 611 外置功率计测量。

**指标**：质量用 YUV-PSNR（按 ISO/IEC 23002-8 实践）；压缩增益用 BD-Rate（BDR），解码能耗增益用 BD-Decoding-Energy（BDDE）——二者均采用作者团队"Bjøntegaard bible"工作中的改进插值框架计算。负值表示节省。锚点全程为 VP9，但按组分离：参考解码器组锚 libvpx，优化组锚 FFmpeg，HW 组锚 VPU 上的 VP9。BDR 只依赖编码器输出，与解码器无关，故结果表中单列。SW 与 HW 直接比较用逐码流能耗比 Δe = (1/M)·Σ E_HW,i/E_SW,i。

## 3. 关键设计

**BDDE 的构造与 Pareto 分析**。BDDE 把经典 BD 框架中与 PSNR 并置的第二条曲线换为解码能耗曲线，在等视觉质量点上积分平均得到“同等质量下的解码能耗差”。由此每个解码器可在 (BDR, BDDE) 平面上画成一个点，SIMD 开/关两种形态各一点，对每组求 Pareto 前沿——sweet spot 即前沿上压缩-能耗折中占优的格式。全文两个核心结论（SW 侧 AV1 sweet spot、HW 侧 HEVC sweet spot）都由该坐标系产出：以优化组 SIMD-on 为例，AV1 (-43.95%, +16.55%) 在两个坐标上同时优于 HEVC (-17.47%, +18.29%)，HEVC 被支配而跌出前沿，这正是论文判定“SW 解码应选 AV1 而非 HEVC”的量化机理。

**三套锚点隔离“格式差异”与“实现差异”**。每组 BDDE 只在组内比较格式（参考组锚 libvpx、优化组锚 FFmpeg、HW 组锚 HW VP9），避免实现成熟度污染格式结论。代价是三列 BDDE 数值互不可比，跨组比较必须另行使用 Δe。

**SIMD 作为一等信息轴**。JM/HM 本身不含 SIMD 优化，对应格式的 SIMD-on 项标 N/A。关键语义：SIMD 开关同时作用于被测解码器与锚点（如优化组锚为 FFmpeg 的 VP9 路径），因此 BDDE 随 SIMD 的变化度量的是“相对 SIMD 收益”，不是绝对加速比——这解释了消融中 AVC/HEVC 关 SIMD 后相对 BDDE 反而改善的反直觉现象。

**HW 侧的数据清洗与外推逻辑**。6 条序列（MINECRAFT、Mission Control、Wikipedia、Vertical Bees、Vertical Carnaby、WalkingInStreet）无法被 VPU 解码，从 HW 指标中剔除（论文未说明失败原因）。VVC/AVM 无 HW 解码器，论文以 VVC 优化 SW 关 SIMD 的 BDDE 241.18% 作为未来 VVC HW 能耗量级的外推依据。

**口径界定**。全文只测动态能耗（解码减 idle），明确与文献中含静态功耗的全设备口径区分。需注意（笔记评述）：SW 侧用 RAPL 读 CPU 域能耗、HW 侧整机外测再减 idle，两侧测量域不对称，且 Δe 跨越 i7-8700 与 RK3588 两个平台——Δe 更宜解读为“桌面 CPU 单线程实现 vs SBC VPU 整机”的部署级对比，而非工艺级 SW/HW 内禀差异。

**压缩效率（BDR，AOM CTC 序列、RA/LB、YUV-PSNR、锚 VP9）**：RA 下 AVC 最差（+27.09%），HEVC -17.47%，AV1 -43.95%，VVC -52.07%、AVM -48.38%——VVC/AVM 相对 VP9 实现约码率减半。LB 下增益整体收窄：HEVC -16.39%、AV1 -28.90%、VVC -33.45%、AVM -33.40%，即低延迟结构削弱新一代格式的压缩优势。

**SW 解码能耗**：参考实现（JM/HM 无 SIMD，仅 S.off 有值）AVC -6.34%（较 VP9 略省）、HEVC +34.93%、AV1 +95.31%（近翻倍）、VVC +500.31%、AVM +247.15%。优化实现 SIMD-on：AVC -27.56%、HEVC +18.29%、AV1 +16.55%、VVC +198.29%（VVdeC 约为 FFmpeg VP9 能耗的三倍）；SIMD-off：AVC -33.05%、HEVC +6.07%、AV1 +82.29%、VVC +241.18%。核心判读：dav1d+SIMD 把 AV1 从参考实现的近翻倍拉回与 HEVC 优化实现同一量级，同时携带 -43.95% 的 BDR，构成 (BDR, BDDE) 平面上的 sweet spot；AVC 始终位于 Pareto 前沿（能耗最低但压缩最差）；VVC/AVM 随 BDR 下降能耗陡增，表明 VVC 新工具的 SW 复杂度无法靠实现优化消化到 VP9 水平。

**HW 解码能耗（Rock 5B VPU，锚 HW VP9）**：AVC -24.47%（LB -26.74%），HEVC +6.06%（LB +6.69%，与优化 SW 的 18.29% 接近），AV1 +117.50%（LB +109.06%）。即该 VPU 上 AVC 最省能、HEVC 与 VP9 基本持平、AV1 翻倍；论文指出 HW AV1 的 BDDE 量级与优化 SW 关 SIMD 的 82.29% 相当。据此推断：未来 VVC HW 的能耗很可能显著高于 VP9，甚至超过 AV1 HW。

## 5. 消融要点

本文没有经典消融实验，但其四维评测矩阵天然构成系统性的受控对比，要点如下：

- **SIMD 的非对称影响**：对 AV1 是开关级变量——优化实现 BDDE 从 SIMD-on 的 16.55% 跳到 SIMD-off 的 82.29%。反直觉处在于 AVC（-27.56%→-33.05%）与 HEVC（18.29%→6.07%）关 SIMD 后相对 BDDE 反而改善。机理（笔记推断，论文未展开）：锚点 FFmpeg VP9 同步失去 SIMD，若 VP9 解码的 SIMD 化程度高于 AVC/HEVC 路径，则关 SIMD 后锚点能耗膨胀更多，AVC/HEVC 的相对值随之变好。使用 BDDE 时必须意识到这一“相对 SIMD 收益”语义。
- **实现成熟度 vs 工具内禀复杂度**：AV1 从参考 95.31% 降到优化 16.55%，是 dav1d 成熟度的红利；VVC 从 500.31% 只降到 198.29%，说明其能耗代价主要来自编码工具本身的 SW 复杂度，优化空间有限。
- **RA vs LB**：LB 使压缩增益收窄（VVC -52.07%→-33.45%，AV1 -43.95%→-28.90%），AV1 优化实现能耗也从 16.55% 升至 30.78%；HW BDDE 在两条件间基本一致（HEVC 6.06% vs 6.69%）。
- **载体切换改变最优格式**：sweet spot 随执行载体迁移——SW+SIMD 是 AV1（BDR -43.95%、BDDE +16.55%），HW 是 HEVC（+6.06%），且 HW 上 AVC 以 -24.47% 成为最省能格式。格式排名不存在跨载体的不变量。

## 6. 贡献与启示

**贡献**：首次在统一码流（AOM CTC、RA/LB、10bit 编码链）、统一 VP9 锚点下，给出 6 格式 × 参考/优化实现 × SIMD 开关 × SW/HW 的完整压缩-能耗矩阵，并量化 SW→HW 的能耗比；方法论上示范了基于改进插值的 BDR/BDDE 联合计算与 Pareto 前沿分析，能耗协议（idle 相减、99% 概率/2% 偏差置信检验、单线程限定）可直接复用。

**部署级启示**：纯 SW 播放且 SIMD 可用时选 AV1（-43.95% BDR 仅付 +16.55% 能耗代价，优于 HEVC 的 -17.47%/+18.29% 双坐标）；走 HW 解码路径则选 HEVC（+6.06%）而非 AV1（+117.50%，在所测 VPU 上翻倍）；VVC 当前不适合能量受限的 SW 部署（VVdeC 为 FFmpeg VP9 三倍能耗），其 241.18%（优化 SW 关 SIMD）的外推对 VVC 硬件 IP 的功耗设计是明确警示。HW 卸载把动态能耗压到 9% 以下，是电池设备的最强论据，但前提是 VPU 覆盖目标格式（VVC/AVM 当时缺失）。

**局限（含笔记评述）**：Δe 跨平台、跨测量域（RAPL 的 CPU 域 vs SBC 整机外测），属部署级而非工艺级结论；单线程口径排除了真实多线程播放形态；HW 侧仅一块 SBC 且剔除 6 条序列；编码器预设对解码能耗的影响论文自述留作未来工作。
