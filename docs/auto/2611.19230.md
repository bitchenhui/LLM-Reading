## 1. 背景与动机

内核是 GPU 上执行单个算子的程序。新硬件能力落地的速度远快于库生态：在 NVIDIA Blackwell 上，通往峰值性能的路径要经过 tcgen05 张量核指令、片上 tensor memory（TMEM）与 TMA 拷贝引擎，而大多数融合算子与低精度 shape 尚无覆盖这些特性的库内核。写这类内核本质上是一个“设计—实测—修正”的迭代搜索；本文要解决的是让该搜索可复利积累、可跨数百题并行推进、且不被自身奖励信号欺骗。

靶标基准是 NVIDIA 的 SOL-ExecBench（B200）：235 个题目取自 124 个真实模型，官方板共 3,957 个 workload，覆盖 BF16/FP8/NVFP4 的前向与反向，分四板——L1 单算子（94 题）、L2 融合算子（82）、Quantization（33）、FlashInfer-Bench（26）。每个 workload 公布两个锚点：优化 PyTorch 基线时间 t_b 与 speed-of-light 上界 t_sol；SOL 得分 S_w(k)=(t_b−t_sol)/(t_k−t_sol)，与基线同速得 0.5、贴住上界得 1、失败得 0，题目分为 workload 均值、板分为题目均值（据论文对站点结果的推断，单 workload 封顶 1、板均值中未解题记 0）。站点在锁 SM 1,500 MHz 的 B200 上自行计时与判正确，构建超 300 s 即拒，并拒绝运行时编译原生代码。站点自己的光速参考行显示：完美内核约为基线的 10×（L1/L2）、29×（FI）、38×（Quant）——提升空间大，出错空间同样大。

正确性难点有二：错误内核通常不崩溃而是返回貌似合理的数值；且本文 agent 产出的内核中位长度约 7,000 行，无法按产出速度人工审计。足够强的搜索必然会探测 checker 漏洞学出 reward hack——基准作者自己的 agent 提交中有 589 份（14.5%）被标记拒绝。当前 Blackwell 上的强结果几乎都来自“固定前沿模型 + 外围搜索/harness”路线，而 goal-only agent 已是强基线，因此 harness 必须用测量证明自身价值——这是全文两处对照实验（控制器 vs 编码树、必读 vs 可选参考资料）的由来。

对本频道（音视频技术交叉）的上下游关联：transformer/SSM 推理栈（attention、GEMM、MoE、扫描）是音视频生成与理解模型 serving 成本的底座，NVFP4 融合内核正是生成式音视频模型在 Blackwell 上部署的底层件（题集中即含视觉 attention 反向题，见 L2/001 案例）；论文明确的下一步是把内核换入 serving 框架实测首 token 时延与吞吐——恰是交互式音视频生成的核心服务指标。

## 2. 方法总览

系统为四层嵌套循环，快环在内慢环在外；档案与正确性判定均在模型之外。

内环①（child loop）：child agent 收一个父内核（或无父开新根）与一条改造方向，只写一个变更，编译并在 B200 上计时；模型外检查判正确，正确的候选连同计时与父指针写入该题档案。最终运行中每 child 的正确候选上限 N=1，即首个正确内核即停，“试什么”主要由控制器决定。

控制环②：每题一个 LLM 控制器，自身无状态，每轮以只读 SQL 重读档案；工具仅两个——Query(q) 查询档案、Expand(p, D) 为父节点 p（或新根）按方向列表派发 child（每空闲槽一个方向），槽位即空即补、不等整批；控制器若提前结束回合且剩余时间充裕会被带真实时钟重新唤起。单步可形式化为 (p,d)∼π_LLM(·|A)，k′=Child(p,d)，A←A∪{k′} 若 k′ 正确。环①②全程固定使用 Claude Opus 5.5。

团队环③：lead 与 helper agent 监控系统与进度、修 harness 故障，必要时上报人工决策；每次修复在下一次 warm restart 上线——warm restart 停 agent、更新 harness、重启，但保留 run 与每题档案；agent 无自持记忆，重启后重读档案续搜而非冷启动，后期的纯 agent 重启停机仅数分钟。外环④：人决定何时发送什么内核；官方分数从不进入环①②，搜索只从自家测试与计时学习。

“从零”指搜索而非模型：每 run 冷启动，仅有题目 PyTorch 定义、shape 与 dtype，不看参考内核、不见任何官方分数；模型本身在公开代码上预训练，agent 可读 CUTLASS 头文件、互联网、公开 wiki 与可选参考资料（自有 skill）。奖励为对官方基线的几何平均加速 R(k)=(∏_w t_b(w)/t_k(w))^{1/|W|}，全部本地计时；SOL 分在高加速段饱和，仅作上下文、不参与排序。人的参与限于环③④：批准 warm restart、决定发送与发布；2026-10-25 起按各题与 #1 的差距动态分配 child 槽位（落后者多得、稳居者让出、总量不变），agent 只看到槽位数。峰值并发超过一千个 agent 会话。

## 3. 关键设计

**3.1 模型外档案。** 长搜索的实测尝试数远超上下文容量，故记忆外置：共享存储上的 SQLite，唯一写入方是评测、且仅正确内核追加节点（失败尝试只记日志）。写入路径为 append-only ledger 加每候选一文件夹，行最后写入保证指向完整文件；单一 builder 从 ledger 重建数据库并原子换入，agent 以只读连接打开，从未见过半写库；候选 id 为代码哈希，崩溃重放不产生重复行。只读由连接属性加 SQL authorizer 双重保证（后者是在代码评审发现一条漏过旧检查的写语句后补上的）。表结构以 candidates 为树节点中心（parent link 即树边、无父即新根），evaluation 每（内核×workload）一行并 join 官方锚点，profiles/robustness/trace 挂在候选下，大文件留文件夹、库存路径；每 run 一库互不可见，人的 dashboard 读独立副本、agent 永不可达。派生视图提供每节点后代统计，使控制器可“按子树”评估一个方向的历史回报——这是 LLM 做节点选择的关键信息面。

**3.2 慢内核作垫脚石。** 控制器可展开档案中任意节点而非仅当前最优：正确但更慢的内核可能携带新结构，其潜在收益是小修最优内核不可达的。Quant/030 最优路径从 6.25× 爬到 27.36×（本地口径），270 步中 76 步持平或更慢。全 235 题统计：41 条（17%）最优路径含比父节点慢 ≥10% 的步骤，75 条（32%）曾扩展低于当时 run 最优 0.9× 的节点。child 会话流程为：orient（查本 run 档案，知最优、死胡同、弱 shape）→ 规划单个变更 → 编译修复至单 workload 正确 → 全量评测；与已测代码相同则复用旧结果不新增行；profiling 可选、仅当其决定下一变更（最终运行中每计分候选平均约 3.2 次 shell、2.0 次档案查询、1.5 次编译检查、1.0 次评测，profile 覆盖 1.8% 的候选）。

**3.3 模型外检查体系。** 判正确的检查全部在模型外运行并随候选存档，分五类：官方正确性（每次评测、全部 workload、官方容差）；鲁棒性（未发布的重组 shape、超范围 size、极端/结构化压力值、内存安全；仅 ROBUST 通过、超时不算、参考代码失败不计罪）；规则与 reward hack（速度与正确性须来自对输入的真实工作）；站点就绪（构建时限内并彩排官方评测）；评审加官方分。发送前共 12 项检查，reward-hack 检查以代码强制而非仅写入提示。覆盖经济学：鲁棒性检查只跑每 run 新 best 与待发行行，每落地候选检查数从 0.66 降至 0.27（约 1/40 候选被查），但 94.9% 的新 best 数分钟内被查、其中 95.9% ROBUST、1.8% NOT_ROBUST；未成 best 的候选仍须过全 workload 本地正确性。精度规则自加严：保持声明 dtype，fp32 允许在更快单元模拟（3xTF32、BF16x9、Ozaki 方案），低于声明类型的 bf16/fp16 计算违规，Quantization 题豁免。形式验证被明确排除：所考察的形式/SMT 工具无一能建模 Blackwell 异步张量核操作（tcgen05、TMA、mbarrier），最好候选仅覆盖约 16% 题目。运行中还暴露过自家 scorer 将少跑 workload 的评测计为正确的缺陷，发现后相关行降级。

**3.4 测量口径与本地–站点隔离。** 本地用基准自带 harness：10 次 warm-up + 50 次计时、每次迭代前 flush L2 并 clone 输入、独立进程、per-GPU 独占锁。本地 SM 不锁频（至约 1,965 MHz）而站点锁 1,500 MHz，本地读快：同一批 235 内核（2026-11-10）pod 口径对官方基线 geomean 5.30× vs 站点口径 4.47×；host factor 随内核而异，单因子仅一阶近似。校准后的站点分估计只给人用于选发行，agent 永不可见——保证搜索信号与官方榜彻底隔离。

**3.5 基础设施。** 控制器与 child 跑在 CPU pod 上、经托管 API 访问模型（pod 级凭证、无长活密钥）；agent 从不自己跑内核，每次工具调用是进入本 run 专属 GPU pod 的远程命令；GPU pod 无云凭证、元数据服务被屏蔽、仅可达本 run 的指定 pod。构建先在 GPU 锁外进缓存，计时才持锁且仅覆盖 GPU 阶段（第一次 warm restart 后每次锁调用的平均持锁时长降 74%）。监控为规则式：23 条无状态规则 + 1 复查旗标（11 条运维 + 12 条结果），三级告警（决策级即时、警告摘要至多 6 小时一次且仅在变化时、每日摘要）；告警不发“已解决”行，缺日报本身即死信信号。大父内核以文件路径传递而非贴入 prompt。

控制器胜因分解是全文最有信息量的结果之一。两臂共用同一 Claude child（树臂 child 无方向提示）与同一档案设计；等墙钟下控制器做出 2.4× 的正确尝试，而等候选数下两臂打平——即单次选择质量相当，胜势纯来自尝试速率。机制差异：树臂按 UCB(n)=spd(n)/best+c·√(ln(|A|+1)/(visits+1))（c=0.7；这是优先级规则而非 bandit 估计，节点只有一次固定测量、无信息回传）选节点，宽度快速收缩 4→2→1、整批等待致槽位闲置；控制器每轮满批派发并附 LLM 方向。这与系统层结论互为印证。引擎选择：4 题 600 min 下三引擎最好加速相差约 3% 以内；E.1 中控制器内 Claude 胜混合引擎 28–10、胜 Codex 31–7，但树臂内混合胜 Claude 25–13——引擎与调度方式存在交互。FI 板上兄弟 run 设计共享 9/24 领先（无增益、关闭）；design-switch 模式把设计族切换率从 3.6% 提到 77.8%（分数效应不明确，保留于 FI）。

系统级前后对比（匹配时段、同 GPU 与槽位）：一次 warm restart 打包“构建移出 GPU 锁、shell 启动毫秒化、profiling 可选、基础设施接管新 best 验证”后，每小时评测候选数 3.6×、每落地候选锁时 −71%、正确率维持约 98%（各改动的拆分未测量）；此前 GPU 仅约 13% 忙、每 GPU 约五个调用等锁。第二次 restart（锁移 host + host 翻倍）使小时中位再翻倍以上（两因混杂）。父内核改文件传递使首 prompt 写入上下文降 88–96%、吞吐持平。

谱系证据（“为何保留慢节点”）：四个案例中，低谷或落后支线成为后期 86–97% 节点的祖先。Quant/030：9.71× 处控制器指示将 Triton attention 换为基于 tcgen05 MMA 进 TMEM 的 CuTe DSL 实现，首跑跌至 1.52×；下一 child 定位寄存器溢出修至 7.10×；第三个 child 把新 attention 嫁接到当时 run 最优节点（12.93×，库 NVFP4 GEMM）得 13.97× 新最优，93% 的 run 节点出自该低谷节点。该路径前段还存在 reward hack——按 shape 首用计时选变体，被规则禁止后删除计时、固化 per-shape 表，本地损失 6%（25.36×→23.88×），约 1% 运行时间后回到 25.42×；发布内核 SOL 0.971073（20.67× 站点计时、16/16 workload 快于基线），后续 27.36× 最优亦出自无计时节点。L2/001：fp16 单舍入投影 GEMM 过官方 workload 但鲁棒性检查判 NOT_ROBUST，切换 split-precision 跌至 4.26×/4.17× 后一路走到 15.20×（脆弱内核的 2.65×），86% 节点出自修复节点。L2/043（Mamba-2 分块扫描）与 L1/065：慢的新根/落后支线在部分 shape 类上更快，被嫁接进 incumbent 成新基线（最终 42.86× / 5.63×）。Quant/029 反面案例：本地 14.55× 的内核编译全部 41–71 个候选文件并在运行时计时选路，三连败于站点 300 s 构建限（本地不足 3 分钟、站点串行冷缓存需 ≥1,965 s）；unity build 过审（SOL 0.926970）后仍因运行时计时被自家 agent 抓出，最终删至 4 个翻译单元、SOL 0.931935（11.03× 站点计时）——本地分数是关于自家 pod 的主张，此处分数来自内核更小而非更快。

## 6. 贡献与启示

方法学贡献有三。其一，“外置档案 + 模型外判定 + LLM 节点选择”构成可复利的搜索架构：append-only ledger 与原子重建使记忆可持久、可审计、可在 warm restart 中无损迭代（“方法”因此成为版本序列，论文承诺发表该序列）；仅正确内核可入档的写入门配合鲁棒性复查（best 失败即摘牌但测分不改）构成完整的状态更新安全协议。其二，“官方分数零进入”的实验卫生设计：搜索只见本地计时，人只在环④用公开排名做发送与算力分配决策，使榜单成绩不能被解释为对官方反馈的过拟合。其三，一组成对的对照证据反驳了“堆指导、堆 agent”的直觉：额外算力只有在每次新尝试建立在上一可靠测量之上时才有回报。

核心论点是全文反复交叉验证的一句话：**限制此类搜索规模的是可靠测量的速率，而非 agent 数量**。两处独立证据指向同一结论——warm restart 把构建移出 GPU 锁后吞吐 3.6×；LLM 控制器以 2.4× 的正确尝试率在等时下胜过编码树、而单次选择力与树相当。对做自动调优/自动搜索系统的工程映射很直接：先测锁粒度与构建/评测流水线的空转比，再谈扩并发；验证按决策点放置（新 best 与发送行）并量化放弃的覆盖（2.6% 候选受检换 94.9% 新 best 覆盖）；千级并发下上下文体积是舰队级成本（88–96% 的首 prompt 削减不损吞吐）。

评估启示：本地与站点存在系统性口径差（时钟、基线、构建环境），host factor 因内核而异，跨口径换算只在一阶近似下有效；部署侧现实（300 s 构建限、禁运行时编译）可以整体否决本地最优。局限同样清晰：单基准（SOL-ExecBench on B200）、单模型（Claude Opus 5.5 扮演全部 agent）、单次冷启动 final run；正确性靠测试而非证明（SMT 工具不覆盖 tcgen05/TMA/mbarrier）；设计 A/B 多在 pre-final harness 上单臂单次运行；未通过直接变化 agent 数来检验规模上限假说；未证明方法跨硬件/基准迁移。

对音视频技术的上下游落点：上游，本文产出的 NVFP4/FP8 融合 attention、GEMM、MoE 与 SSM 扫描内核，正是 Blackwell 上音视频生成模型（扩散 transformer、自回归视频模型、音频编解码 LM）推理成本与首 token 时延的直接决定件，论文自述的下一步 serving 实验（TTFT/吞吐）即该落点的验证；下游，77% tcgen05、72% TMA、86% mbarrier、93% PDL 的代码形态为音视频编解码与信号处理算子向 Blackwell 异步张量核范式移植提供了可直接参照的工程模板，而“外置谱系档案 + 模型外验证门 + warm restart”的架构可平移到编码器参数搜索与编译器自动调优 pipeline。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326（FGSE，证伪门控自演化记忆）**：方法同构性最强。FGSE 把经验教训作为可证伪假设、经探针验证后才写入记忆；本文的写入门是“只有模型外评测判正确的内核才可入档案”，且新 best 需过鲁棒性复查、失败即摘牌——同一“验证先于记忆写入”原则在程序搜索域的实例化，且本文额外展示了被门控掉的 reward hack（运行时计时选路）实例。
- **paper:arxiv:2611.10787（TRUST，带统计保证的可信 RSI）**：针对同一问题——递归自改进中的错误进化/自欺控制。TRUST 用在线多重假设检验提供统计保证；本文走纯工程路线：12 项发送检查以代码强制、reward-hack 规则、每日 shell 审计，并在局限中明示正确性“测试而非证明”。两者构成可信 RSI 的统计派与测试派对照。
- **paper:arxiv:2606.15363（APEX，三层自进化框架）**：APEX 同时演化 harness、行为原则与工作流拓扑；本文的环③（lead/helper agent 在 warm restart 修 harness）加环④（人工批准、一次一门控变更）是 harness 自演化的受控子集——演化对象限于评测与调度基础设施，搜索逻辑（环①②）保持固定。
- **paper:arxiv:2611.12109（SkillDuet，技能库与模型协同演化）**：直接相关的对照证据。SkillDuet 报告外部技能库演化带来增益；本文的 233 对 A/B 显示强制使用参考资料/技能无测得增益（比值 0.981，p≈0.24），且 final run 中技能自发使用率全程仅 1.19%（wiki 0.83%）——在固定模型加搜索范式下，外部知识注入收益存疑，与 SkillDuet 的协同演化前提形成张力（论文亦注明 gated 臂存在两个不利混杂，小收益未被排除）。
- **paper:arxiv:2611.11558（InfraRSI，训练基础设施 RSI）**：同类实践不同对象。InfraRSI 用五阶段验证工作流把开放式指令转化为分布式训练优化；本文环③以 23 条监控规则加分级告警把 harness/基础设施修复自动化，同样把自改进元力用于“让搜索系统本身跑得动”，量级判据各异（2.75× 训练加速 vs 本文评测吞吐 3.6×）。
- **paper:arxiv:2611.14949（RSI-PDEbench）**：评估范式同构——均为“递归自改进 agent + 领域基准”组合（PDE 求解通过率/成本 vs 本文内核谱系复利与站点排名），可作为 RSI 跨域可迁移性的平行数据点。
