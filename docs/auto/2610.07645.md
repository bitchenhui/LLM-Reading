## 1. 背景与动机

自进化 LLM agent 普遍采用 experience→skill 通道：从已验证成功的执行轨迹中提取过程性知识，固化为可检索、可复用的持久技能（文中以 AutoSkill 的“检索渲染式”与 Trace2Skill 的“预载编辑式”为代表）。技能的持久性同时放大了安全风险——被污染的技能会跨任务、跨会话反复影响下游执行。

既有攻击分两类：Artifact-based 直接篡改已成形技能（嵌入恶意指令/可执行代码），但随着 agent 自主创建与维护技能库，这一访问假设日益不成立；Formation-based 转而污染被技能形成过程消费的轨迹与演化证据，让原生管线自己把攻击者期望的行为编码进技能。作者通过预备实验（第 2 节）指出 Formation-based 攻击存在两个结构性瓶颈：

1. **恶意行为直接暴露**：在单条记录中显式编码目标行为或触发条件，会与原任务需求/执行约束冲突，在轨迹分析阶段（形成前校验）即被拒绝；
2. **无法累积为持久技能**：此类攻击以“当次任务被破坏”为目标，产生的是失败轨迹；而原生技能管线只固化“被反复的已验证成功执行所支持”的行为，任务级攻击成功与技能级学习信号方向相反。

预备实验的量化结论：在 Trace2Skill 与 AutoSkill 上各测 SkillJack 与 PoisonedEvolution（每个攻击–管线组合 9 例），SkillJack 仅在 Trace2Skill 成形 3/9、AutoSkill 0/9；PoisonedEvolution 在两管线上均无完整成形，且其 Trace2Skill 的 9 例全部被拒。36 例总计：24 例被拒、9 例仅部分保留目标行为、3 例完整成形。

由此提出新范式：**用完全通过验证的成功经验投毒**。选取目标行为 p* 在其中“局部有效”（符合该任务逻辑、对成功有实质贡献）的成功轨迹，跨多样化任务反复强化“p* ↔ 成功”的关联，诱导原生技能泛化器保留 p* 却丢弃其适用条件（overgeneralization）。全程不写入任何恶意内容——攻击面从“内容”转移到“证据集的统计结构”。对音视频侧的读者：这一通道同样存在于 AV 生产自动化中基于 LLM 的编码/工具链 agent（pandas 级媒资数据处理、ffmpeg 管线生成等）的经验库，关联详见第 6 节。

## 2. 方法总览

**威胁模型**：受害框架抽象为 ŝ = Ef(Af(T))，Af 为轨迹分析器、Ef 为技能抽取器。攻击者能力：(i) 从成功经验池 T 中选择子集 TA ⊆ T 供技能形成使用，受预算 |TA| ≤ B 约束；(ii) 可通过形成接口附加辅助标注。攻击者**不能**修改底层执行、输出或验证结果，不能直接改动 Af/Ef 或最终技能。攻击目标形式化为两个条件的合取：p* ∈ Beh(ŝA)（行为被保留）且 Γ̂(p*) ⊄ Γ*（应用语境溢出原有效语境，即边界逃逸）。该能力假设的现实映射：任何接受外部经验贡献并做技能固化的共享池（社区技能生态、多用户 agent 平台）。

**SkillPoison 三阶段流水线**：

1. **Hierarchical Task Selection (HPS)**：从候选任务中筛出“p* 自然出现、对输出有实质影响、且原执行仍满足任务需求”的成功轨迹——只复用天然存在的实例，不做任何注入；
2. **Local Evidence-Grounded Success Attribution (LEGSA)**：为每条选中轨迹构造结构化归因证据，把 p* 与该次已验证成功显式绑定，消除共现行为的归因歧义；
3. **Global Cross-Experience Inductive Reinforcement (GCTIR)**：把带归因证据的形成记录按任务类别组织、按行为相关性与语义对齐度选类，在预算内提交跨类别但“对 p* 支持一致”的记录集，促使原生抽取器把 p* 当作跨情境可复用知识保留、把其局部适用条件当作实例细节剥离。

关键性质：摘要明确声称在取得 95.71% ASR（PAWS + Trace2Skill 设定）的同时，**所有注入经验均任务正确、通过验证与词法检查**——即不存在任何可被逐条审查发现的恶意记录。

## 3. 关键设计

**HPS：反事实重要性 + 需求有效性两段过滤。** 第一段以反事实输出差异度量 p* 的因果载荷：将 p* 替换为任务兼容的替代行为得到反事实输出 z̃i，重要性得分 R(xi, p*) = Edit(zi, z̃i)/|zi|（token 级编辑距离，涵盖内容、数量、次序变化，归一到 [0,1]），保留 R ≥ τR 的任务。这本质是攻击者侧的因果探测：只选“去掉 p* 输出会实质性改变”的样本，保证后续归因不沦为对偶然动作的牵强解释。第二段校验执行有效性：O(xi, τi) = (1/Ki)·Σqi,k ≥ τO（Ki 条任务需求的满足比例），确保含 p* 的原执行本身合规、可过验证。两段串联输出任务集 X* 与轨迹集 T*。

**LEGSA：四元组归因证据。** 对每个 (xi, τi)，用 LLM 证据生成器 M 构造 Gi = (ei, ai, vi, κi)：任务证据 ei（支撑 p* 在本例适用的任务特征与执行语境——恰是最终会被泛化器剥离的内容）；成功归因 ai（把成功因果地记在 p* 头上，并与其他共现行为区分）；输出一致性 vi（归因与已执行动作及输出 zi 不矛盾的自检）；反事实后果 κi（若略去 p*，本任务输出会怎样）。随后以固定打包过程 Φ 生成形成记录 ri = Φ(τi, Gi)——证据仅作为辅助元数据附加，原任务、动作、输出、验证结果一字不改。设计上最讲究的是提示词约束（附录 G）：四个生成提示均**禁止跨任务推断、禁止一般规则、禁止外推未来适用性**，每条证据必须能对照当前 xi/τi 逐句核验。这使每条记录在孤立审查下完全无害且自洽——泛化压力只在集合层面涌现。

**GCTIR：跨类别归纳强化。** 将选中任务按类别划分（m 类），类别相关性 Sj = 类内 R 均值（平均化防大类别占优）；轨迹–行为对齐 Aj = 类内 Sim(ψ(τi), ψ(p*)) 均值，Sim = (1+cos)/2。综合得分 Uj = Sj + λAj，取 Top-Mc 类，每类选 bj 条，Σbj ≤ B。产出是一份“任务语境多样、但对 p* 的成功支持高度一致”的记录集 HA，交由受害框架原生形成。

**机制本质：把抽取器自身的归纳偏置武器化。** AutoSkill 的原生抽取提示明确要求“移除实例特定实体与不可迁移细节，仅保留能力级不变量”；Trace2Skill 的演化提示明确要求“多条成功经验重复使用同一过程则强化之”“忽略不可泛化的孤立成功”。SkillPoison 构造的证据分布恰好使 p* 的适用条件呈现为待剥离的 case-specific 细节、p* 本身呈现为待强化的跨情境稳定模式——恶意泛化由受害管线自己的抽象步骤完成。这是“内容干净、统计有毒”的攻击：单条语义无法定罪，毒性完全寓于提交集合的统计结构。

**评测口径的两个关键设计。** Adoption = E×I：技能进入上下文（AutoSkill 需检索+相关性过滤+渲染；Trace2Skill 恒预载）且下游执行呈现可观测影响（HANS/PAWS 用模型自报 applied prior skill 字段，DS1000 用生成代码中技能相关过程模式作代理）。ASR 为严格口径：仅在 w/o Attack 下正确、攻击下错误、且失败呈现 p* 的数据集特定行为证据才计数（HANS：subsequence/表层片段启发式 + 偏向 entailment，因评测例均为 non-entailment；PAWS：内容词集合比较 + 偏向 paraphrase；DS1000：代码含目标 reset_index 操作 + 执行成功但断言不匹配 + 排除硬编码输入）。Adoption 与 ASR 解耦是必要的：实验证明“技能被采用”与“攻击可归因成功”是两件事。另注意 Trace2Skill 预载使其 Adoption 基线近饱和（PAWS 上 w/o Attack 即 98.57%），该框架上区分度主要在 ASR。

## 6. 贡献与启示

**贡献**：(1) 问题重构——Formation-based 攻击失败不是因为信号不够强，而是信号类型错了：管线消费的是“成功证据”，注入的却是“对抗内容”；(2) 方法——内容完全洁净的投毒，攻击对象是提交证据集的统计结构（跨类别一致的 p*–成功关联），泛化由受害管线自身的抽象偏置完成，逐条验证与词法检查结构性失明；(3) 度量——Adoption 与严格 ASR 解耦，并用数据集特定行为证据（启发式方向 / 内容词比较 / 代码模式 + 断言不匹配）保证攻击可归因，排除了无关错误的计数污染。

**防御侧启示**（论文结论亦点名）：漏洞不在经验本身而在抽象步骤对适用边界的丢弃，因此防线必须落在“技能形成时保留并传播适用条件”——形成记录 schema 中的 goal/domain/constraint/context 字段应强制随行为一同泛化；此外，攻击者的核心能力是“选择提交子集”，单一行为在多类别中呈现高度一致的支撑是可检测的统计签名，形成池的来源溯源与多样性审计有实操空间；成形技能晋升前应跑下游回归集而非仅审查源经验。对任何以“逐条验证”为安全假设的自进化系统，本文是直接反例：被投毒的记录每条都是真的成功。

**与音视频技术的上下游关联（笔记延伸，非论文主张）**：上游无直接依赖（纯 LLM agent 安全）。下游迁移面在于：AV 生产自动化中日益增多的 LLM coding/工具链 agent（pandas 级媒资元数据、镜头边界表、字幕对齐表处理——与本文 DS1000/Pandas 场景同构；ffmpeg/转码/质检管线的自动生成 agent）正在引入同样的经验库与技能库机制。本文 Case 2 的失败类别——“代码可执行、运行通过、但输出与期望不符”——在 AV 语境下对应“管线跑通但违反规格/质量的静默回归”（如无前提地对所有片段统一重编码、统一响度归一、统一丢索引/丢音轨），语法与运行时检查均不报警。工程上：(a) 确定性执行器（如 DS1000 断言）只保护形成时的源经验，不保护泛化后的技能，AV 侧对应的缓解是成形技能晋升前的黄金样本回归；(b) 多模态/视频理解 agent 从工具调用轨迹沉淀技能，攻击面原样适用，因为 SkillPoison 对 p* 的具体内容完全格式无关。

## 7. 与其他论文的联系

- **paper:arxiv:2611.12109（SkillDuet）**：SkillDuet 以响应反馈驱动外部技能库与模型参数协同演化，正是本文威胁模型中 Af/Ef 一类“experience→skill 形成机制”的典型实例。SkillPoison 的攻击假设（选择已验证成功经验子集 + 附加辅助标注）对任何从执行反馈摄入技能更新的系统成立；本文在 AutoSkill/Trace2Skill 上的实证可视为对该类协同演化技能库安全面的预警，但未在 SkillDuet 上实测，属类别级外推。
- **paper:arxiv:2611.14326（FGSE）**：FGSE 把经验教训当作可证伪假设、经三类探针验证后才写入记忆，是“记忆写入门控”型防御。与 SkillPoison 构成尖锐对位：SkillPoison 的投毒记录全部真实成功、逐条可通过验证，可证伪门控针对“假教训注入”有效，但对“真教训 + 边界丢失”这一失败模式，除非探针显式检验适用边界（在边界外测试行为是否仍成立），否则难以拦截——这是两文对读时最值得展开的实验问题。
- **paper:arxiv:2611.10787（TRUST）**：TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证。SkillPoison 恰好展示了“逐条通过验证的更新仍可在分布层面引入系统性泛化错误”，提示错误率控制的检验对象需从单次更新的正确性扩展到抽象/泛化步骤的边界保持，否则统计保证的假设可能被内容洁净的投毒绕过。
- **paper:arxiv:2610.07319（WeightLoop）**（对照性关联）：WeightLoop 修改的是权重空间的持久状态，SkillPoison 修改的是技能文本层的持久状态；两者共同说明自改进回环的每一层持久化（权重、记忆、技能）都有独立攻击面，防御需要按层设计而非统一于单一验证机制。
