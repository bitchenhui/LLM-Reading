# EvoTool: Self-Evolving Tool-Use Policy Optimization in LLM Agents via Blame-Aware Mutation and Diversity-Aware Selection

> Shuo Yang, Soyeon Caren Han, Xueqi Ma, Yan Li, Mohammad Reza Ghasemi Madani, Eduard Hovy. *arXiv:2603.04900v1 (2026-03-05)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

工具增强的 LLM agent 需要将目标分解、工具选择、参数构造、结果接地合成四类相互耦合的能力编排为一条可执行的策略。真实任务具有长时序、紧耦合的决策链，任一环节出错即可导致整体失败；同时监督信号通常只在交互终点出现，多个错误源被坍缩为一个终端标量——这是典型的延迟监督下的 credit assignment 困境：既难以定位失败组件，也难以做到只修该组件而不破坏其他行为。

论文把现有工具策略优化梳理为三档，并逐一指出结构性缺陷：

- **手工策略**（ReAct、CoT、Plan-and-Solve）：人工成本高、控制流刚性，未预期错误会引发系统级崩溃，跨域泛化差。
- **训练式内化**（SFT/RL，如 Toolformer、ToolRL 路线）：静态权重 + 大数据需求，对演化中的环境适应成本高。
- **免训练策略优化**，又分裂为两个极端：**整体式**把 agent prompt 当作单一黑盒对象做全局搜索（OPRO、PromptBreeder、EvoPrompt），异构行为互相纠缠，修复一处错误可能扰动其他能力并引入回归；**单方面式**孤立优化规划或调用等个别组件（AdaPlanner 只精化规划，DRAFT/EasyTool 分别改工具文档与工具指令，AnyTool 精化选择与合成），忽略长轨迹中的跨模块误差传播。

相关工作定位上，作者将 EvoTool 置于自进化 agent 谱系（Reflexion/Self-Refine 式自反思、TextGrad/GEPA 式文本反馈、ADAS/DSPy 式组件累积）之中，并指出该谱系普遍依赖贪心选择、过早收敛到窄策略、丢弃异质任务分布所需的多样行为。论文的核心判断是：**没有任何现有范式同时具备“定向纠错”与“多模块协同”**，EvoTool 的全部设计都围绕这一空白展开。

## 2. 方法总览

**形式化**：任务 x∼D，工具集 T={τ1,…,τK}，每个工具含名称、参数 schema 与文档。第 t 步 agent 观察状态 st、输出动作 at（中间推理、工具调用或终止作答），环境执行调用并返回观测 ot，完整 rollout 构成变长轨迹 τ={(st,at,ot)}，由终端答案 ŷ 依任务相关成功函数 R(x,ŷ)∈[0,1] 评估（实例化为 pass@1、success rate、F1 等），汇总为 episode record e=(x,τ,ŷ,R)。

**模块化策略**：策略显式分解为四角色的固定复合 Π = πsyn∘πcall∘(πsel∘πplan)：Planner（子目标分解）→ Selector（当前状态下是否调用、调用哪个工具）→ Caller（构造合法参数并执行）→ Synthesizer（把工具输出接地整合为最终回答）。四模块共享同一权重冻结的骨干 LLM（W），可演化的只有各模块规范 Θ={θplan,θsel,θcall,θsyn}——提示、工具模板与轻量格式规则。优化目标为 J(Θ;W)=E_x E_τ[R(x,ŷ(τ))]，全部学习只发生在 Θ 上，权重不动。

**自进化循环**（每代四阶段，维持候选种群 P={Θ(i)}）：

1. **轨迹采集**：按 winner 频率从 P 采样父代，在训练池 Strain 的 mini-batch（B=3）上执行实例化策略，收集 episode records；
2. **责任归因**：Blamer LLM 基于轨迹诊断事件产出模块级 blame 分数，argmax 选出唯一变异目标 π*；
3. **定向变异**：Mutator LLM 生成自然语言反馈 F(e,π*)，据此只编辑 θ_{π*}，子代与父代**恰好相差一个组件**；当且仅当子代 mini-batch 平均奖励超过父代才入种群；
4. **多样性选择**：在 held-out 选择集 Ssel 上对全部候选做实例级赢家筛选，删除从未取得实例级支配者，并按 win frequency w(Θ)=(1/|Ssel|)ΣI[Θ=W(x)] 更新父代采样概率。

固定代数预算（G=8）后返回 Ssel 上平均奖励最高的候选。整个范式 training-free、gradient-free：不依赖可微性，仅靠交互轨迹驱动的语言空间编辑。

## 3. 关键设计

### 3.1 Trajectory-Grounded Blame Attribution：终端信号 → 模块级责任信号

长时序多工具失败是多因异构的：分解不当、工具选错、schema 违例、合成不接地都可能独立或联合导致负结局；无显式诊断机制时，自进化退化为全局盲搜。EvoTool 分两步：

先从轨迹抽取**结构化诊断事件**，包括工具选择结果、参数合法性信号、工具执行结果、合成接地信号四类；再将完整 episode + 诊断摘要交给 Blamer LLM，输出四模块各自的 blame 分数 bπ(e)∈[0,1]（输出格式为分数、逐模块证据、一句诊断）。归因准则的三个关键约束：优先以抽取事件为证据、再以轨迹证据复核；**优先归因最早的因果错误**；多因情形强制选择单一主责模块。

工程含义：这相当于让 LLM 充当“伪梯度估计器”，把一个标量终端奖励反传为四个离散坐标上的责任分布。需要保留的疑点是：归因质量完全取决于 Blamer 判断，论文未提供 blame 准确率的外部金标验证。

### 3.2 Feedback-Guided Targeted Mutation：最小编辑 + 接口契约保持

给定被问责 episode 与目标模块，反思式 Mutator LLM 生成自然语言反馈 F(e,π*)：从该模块视角解释错误模式，结合当前规范与轨迹证据提出具体、局部化的编辑（输出格式：目标模块、诊断的错误模式、最小编辑摘要、修订后规范）。元提示写死的硬约束：只编辑目标模块规范；不得新增工具或环境；编辑必须轨迹接地；做能修复错误的最小改动并保持模块接口契约与输出格式。并内置四类错误→编辑启发映射：schema/格式错→加参数检查清单与 schema 校验；选错工具→加子目标到工具的决策规则；规划错→加显式子目标、状态字段、顺序约束与前置检查；合成不接地→强制对工具输出归因、禁止无支撑事实。

子代接受采用经验门控（mini-batch 均值奖励比较）。配合“只改一个模块”的结构约束，未被判责的能力在本轮更新中被物理隔离——这是对整体式全局编辑回归问题的直接规避。

### 3.3 Diversity-Aware Population Selection：实例级赢家准则

作者观察到工具使用能力可分解为多个部分竞争的技能，按全局平均贪心选“最优”父代会丢弃互补行为、过早收敛。替代方案是在 Ssel 上的实例级准则：每代评估种群全部候选，只有在至少一个实例上取得全场最高分者保留；父代采样概率正比于 winner frequency。效果是更新集中于广泛有效策略，同时保留覆盖任务分布不同区域的“专家”变体；最终仍返回 Ssel 平均奖励最高者，兼顾利用。

### 3.4 实现细节、演化产物与案例

骨干为 GPT-4.1 与 Qwen3-8B，权重冻结；G=8 代、B=3。初始四模块提示均为单句级极简指令（如 Planner 仅“把用户复杂指令分解为顺序子目标列表”），说明最终增益基本来自演化而非手工初始化。附录展示的演化后 Planner 规范已达接口契约密度：仅允许引用 TOOL_INDEX 内能力、禁止幻觉 ID/参数、原子化步-能力映射、依赖优先（尽早获取必需 ID）、STATE 变量命名与复用规范、关键约束验证、每步至多一个轻量回退，以及带 arguments_template/store_as/fallback 字段的 JSON 计划 schema——演化产物可读、可审计。

定性案例（ToolBench）：初始 Selector 规范只有语义相关性三条规则，episode 100 在需要 Census Bureau 地理编码时错选 Weather API 的 getForecast；环境反馈“required tool not used, expected Geocoder, observed Weather”经变异生成 Selector v1（硬约束：用户显式要求的工具必须选用并保序；启发式：先识别缺失变量、再选产出该变量的工具），episode 101 依序调用 TrueWay Places 与 Census Bureau geocoding 成功。即“单例错误 → 局部规则化修复”的可复现路径。

## 4. 实验结果

**设置**：四基准按官方口径——ToolBench（RapidAPI，3,451 工具 / 16,464 REST API，G1/G2/G3，Pass Rate）、RestBench（TMDB 51 API、Spotify 40 API，Success Rate）、τ-Bench（retail 1,000 订单、airline 2,000 预订，有状态长时序，以最终数据库状态判对，Pass^1）、BFCL（5,551 实例 + 8 API 套件 / 1,000 查询的多轮套件，Accuracy）。公平性控制：所有方法同骨干、同工具环境、同单实例交互预算；凡做提示搜索的方法统一以 Ssel 最优选最终 prompt，再上官方评测切分。

**主结果（四基准总均值）**：

| 方法（范式） | GPT-4.1 Overall | Qwen3-8B Overall |
|---|---|---|
| ReAct（手工） | 60.6 | 49.0 |
| Plan-and-Solve（手工） | 54.4 | 43.7 |
| OPRO（整体式） | 62.1 | 50.2 |
| EvoPrompt（整体式） | 63.8 | 51.4 |
| AdaPlanner（单方面） | 57.5 | 46.3 |
| EasyTool（单方面） | 64.4 | 51.1 |
| DRAFT（单方面） | 64.9 | 51.8 |
| **EvoTool** | **70.6** | **57.0** |

GPT-4.1 上超最强单方面基线 DRAFT 约 5.7 分、最强整体式 EvoPrompt 约 6.8 分；Qwen3-8B 上超次优（DRAFT）5.2 分。

**GPT-4.1 分基准关键行**：

| 基准（均值口径） | EvoTool | DRAFT | EvoPrompt | ReAct |
|---|---|---|---|---|
| ToolBench Avg | 77.7 | 75.8 | 66.4 | 63.6 |
| RestBench Avg | 86.2 | 84.8 | 76.9 | 73.4 |
| τ-Bench Avg | 52.0 | 38.8 | 48.6 | 47.9 |
| BFCL Avg | 63.1 | 54.9 | 62.1 | 56.0 |

优势结构清晰：在工具选择/schema 密集的 ToolBench、RestBench 上领先幅度中等；真正的分化在有状态长时序 τ-Bench——DRAFT/EasyTool 掉到 38.8/40.6，孤立优化暴露跨模块依赖缺失，EvoTool 达 52.0。BFCL 上 EvoTool 单轮 83.9 略低于 EvoPrompt 的 84.2，但多轮 42.3 为最高（次优 EvoPrompt 39.9），总均值优势来自多轮，说明规划灵活性与语法精度可以兼得。学习动态上 EvoTool 单调上升并保持最高终值；成本-性能对比中持续占据“高性能-低 token”象限，作者将 token 经济性归因于变异被限制在目标组件、使能力增长与 token 膨胀解耦（论文未给出具体 token 计数，此处不引数字）。

## 5. 消融要点

**（1）Blame 定位消融**（Qwen3-8B，四基准均值）：

| 变体 | ToolBench | RestBench | τ-Bench | BFCL | Avg |
|---|---|---|---|---|---|
| Static（不演化） | 55.9 | 65.5 | 21.0 | 52.0 | 48.6 |
| Random（随机目标） | 45.8 | 52.7 | 15.9 | 43.6 | 39.5 |
| Plan-only / Sel-only / Call-only / Syn-only | 51.2 / 63.1 / 57.4 / 55.0 | 58.6 / 70.8 / 66.3 / 65.1 | 24.7 / 20.4 / 20.2 / 21.2 | 50.1 / 48.2 / 55.6 / 50.7 | 46.2 / 50.6 / 49.9 / 48.0 |
| Monolithic（同时优化全模块） | 59.6 | 67.2 | 20.6 | 48.8 | 49.1 |
| **EvoTool** | 66.2 | 74.6 | 25.8 | 56.7 | **57.0** |

三个结论：随机变异比不进化还低 9 分以上——错误方向的变异是纯破坏性噪声；单模块变体各有单项强点（Sel-only 在 ToolBench 63.1）但泛化差（τ-Bench 仅 20.4）；整体式仅 49.1，粗粒度更新无益于模块纠错。基于 blame 的目标选择贡献了主要增益。

**（2）变异引导消融**（Qwen3-8B，成功率；论文未标注数据集，full=74.6 与主表 RestBench 均值口径一致）：去轨迹证据 −4.4（70.2）；去显式自然语言反馈 −9.4（65.2）；全去 −11.8（62.8）。显式批评比原始轨迹上下文信息量更大，但二者互补：轨迹提供接地，反馈指明优化方向。

**（3）父代选择消融**（同预算同变异设置）：Static 48.6、Greedy 52.0、Top-k 52.7、多样性感知 57.0；τ-Bench（25.8 vs 23.6/22.1）与 BFCL（56.7 vs 54.3/54.6）上差距最大，验证保留互补变体对异质分布的价值。

**（4）误差演进诊断**（Blamer 逐代分解）：ToolBench 总错误率三代内从 77.6% 降至 38.0%，主要由 Caller/Selector 错误减少驱动（与该基准强调工具选择与参数合规一致）；随后残余向 synthesis/planning 集中，第 8 代降至 20.2%。τ-Bench 全程 Planner 主导，总错误降至 33.3% 后仍呈规划重分布——多步依赖追踪与状态维护是残余瓶颈。

**（5）迁移性**：GPT-4.1 下 ToolBench↔RestBench 跨数据集双向正迁移（以默认静态基线为参照）；跨模型迁移中，Qwen3-8B 上演化的策略在 GPT-4.1 上超基线 4.7 分，GPT-4.1 上演化的策略迁回 Qwen3-8B 提升 12.7 分——策略文本与骨干弱耦合。

## 6. 贡献与启示

**贡献**：模块化工具策略的无梯度自进化框架；轨迹接地责任归因 + 定向变异实现局部化更新；实例级赢家的多样性种群选择；跨四基准、双骨干的一致 >5 分增益，附带 token 效率与跨数据集/跨模型迁移性。

**方法论启示**：(a) 用 LLM 做模块级 credit assignment 是对“延迟监督 + 稀疏终端奖励”的语言空间解法，不需要可微性，与 RL 式信用分配互补；(b) spec-only 演化把策略外置为可读文本，部署、回滚、审计成本远低于权重更新，也解释了跨骨干迁移（12.7 分）的可行性；(c) “最小编辑 + 接口契约保持 + 单模块冻结”的组合是控制自进化回归风险的结构性手段，比软性约束（如提示中“注意不要破坏其他能力”）可靠。

**保留意见**：子代接受检验基于 B=3 的 mini-batch，统计效力极弱，多代累积存在假阳性接受风险；Blamer/Mutator 依赖 LLM 判断且无金标验证；作者自述局限包括迭代推理延迟（不适合严格实时场景）、仅覆盖文本/API 环境、未扩展到多模态工具与具身智能体。

**对音视频工程侧的关联**：工具调用型 agent 与媒体处理链路（转码、切片、抽帧、ASR/OCR、审核、流诊断等 API 化工具）结构同构——长管线、终端指标（端到端成功 / QoE）同样面临“哪个环节该为劣化负责”的定位问题，模块化 blame 机制可类比于逐级故障归因；多样性种群选择类比于保留面向不同内容类型的处理策略池；而“多模态工具未覆盖”这一自述局限，恰是以视觉/听觉输入为前置的媒体工具链的直接扩展方向。

## 7. 与其他论文的联系

- **FGSE（arxiv:2611.14326）**：同题于自进化的“更新安全”。EvoTool 的写入闸门是子代在 mini-batch 上的奖励提升（经验性 A/B），FGSE 则把经验教训当作可证伪假设、经三类探针验证后才写入记忆（证伪式闸门）；两者在“防止坏更新固化”上互补。
- **TRUST（arxiv:2611.10787）**：EvoTool 逐代以 B=3 小样本接受子代，跨代累积的多次比较缺乏错误率控制；TRUST 用在线多重假设检验为递归自改进提供统计保证，直接指向 EvoTool 接受准则的统计短板，是最顺的机制补强方向。
- **SkillDuet（arxiv:2611.12109）**：同属响应反馈驱动的递归自改进，但 SkillDuet 让外部技能库与模型参数协同演化；EvoTool 冻结权重、只演化模块规范。二者构成“参数空间演化 vs 提示/规范空间演化”两条互补轴线。
- **WeightLoop（arxiv:2611.07319）**：WeightLoop 用有界参数编辑程序 + 实验反馈直接改写部署权重；EvoTool 的“目标模块最小编辑 + 奖励门控”流程与其同构，差异在编辑对象是 spec 而非权重，部署风险与可回滚性显著不同。
- **LongCapHarness（arxiv:2611.10463）**：同为免后训练、低成本的能力自挂接路线；EvoTool 优化工具使用策略，LongCapHarness 挂接长上下文推理底层能力，均以递归自改进替代训练并强调成本优势（EvoTool 的 token 效率 vs 其低于基线 50% 的成本），可视为同一范式在不同能力面上的并行实例。
