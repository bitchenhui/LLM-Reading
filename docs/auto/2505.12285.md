# CALM: Co-evolution of Algorithms and Language Model for Automatic Heuristic Design

> Ziyao Huang, Weiwei Wu, Kui Wu, Jianping Wang, Wei-Bin Lee. *arXiv:2505.12285v1 (2025-05-18)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

自动启发式设计（AHD）的目标是在启发式函数空间 H 中寻优：给定问题输入空间 I、解空间 S、训练集 D 与目标 f，启发式性能定义为 g(h)=E_{x∈D}[−f(h(x))]，AHD 即求 h* = argmax_{h∈H} g(h)。经典 AHD（如遗传编程）仍依赖人工定义的问题特定组件，搜索空间受限。LLM-based AHD 将 LLM 作为启发式生成器、进化计算作为搜索框架：生成的启发式在预定义仿真环境中评估，精英启发式回注 prompt，形成“生成—评估”闭环。FunSearch、EoH、ReEvo、HSEvo、MCTS-AHD 均属此范式。

本文抓住的核心缺口是：现有方法全部冻结底层 LLM，仅靠 prompt 文本操控（即 ReEvo 所称 "verbal gradients"）引导启发式进化，完全放弃了“用启发式设计质量反哺生成器”的通道。作者的关键观察是：进化循环天然产出大量 prompt–response–performance 三元组——每条启发式的有效性都是对生成过程效用的隐式信号，这些数据是免费的 RL 训练素材。据此提出 CALM：verbal（prompt/算子进化）与 numerical（以启发式质量为奖励、用 GRPO 微调 LLM）双通道联合优化，实现 LLM 与算法的共进化。同期工作 EvoTune 也在进化框架内微调 LLM，但 CALM 与之有三点区分：(i) 同时适配 prompt 生成过程；(ii) 给出逐响应的连续标量奖励以鼓励开放式探索，而 EvoTune 只有二元偏好反馈（指出两条响应谁更好）；(iii) CALM 以紧凑模型击败多种依赖更强 API 模型的主流方法，EvoTune 仅在同用紧凑模型对比 FunSearch 时报告改进。工程层面的动机同样明确：全流程在单张 24GB GPU 上以 7B INT4 模型完成，摆脱对商业 LLM API 的依赖。

## 2. 方法总览

CALM 维护一个启发式池（每条含 idea、code、performance 三要素）。每轮：按权重抽取一个进化算子 → 由算子与池中采样的基启发式构造 prompt q → 从本地 LLM πθ 采样 G 条响应 → 逐条解析、评估可行启发式 → 依奖励函数赋分 → 用 (q, O, r) 执行一步 GRPO 更新 LLM → 可行新启发式入池。跑满 T 轮后返回历史最优。

numerical 通道选用 GRPO：每个 prompt 采样 G 条响应，token 级优势为组内归一化奖励 Â_{i,t}=(r_i−mean(r))/std(r)，目标函数为裁剪比率项加对参考模型 π_ref 的 KL 正则（式 1）。选型理由有二：GRPO 只需每条 prompt–response 对一个标量信号（区别于 DPO 类偏好信号，天然匹配启发式性能评估的输出形态）；组均值基线省去辅助价值网络，降低显存，使单卡 INT4 微调可行。

工程栈：Unsloth + INT4 量化 Qwen2.5-7B-Instruct，仅微调 1.15% 权重；学习率提高到 5×10⁻⁵ 以加速适配；G=4（每个 prompt 采样 4 条响应，在固定查询预算下换取更多进化步）；T=500 轮；每条启发式评估限时 60s；硬件为 24GB NVIDIA A30 + Xeon Gold 5220R。作者明确交代了模型能力位次（据 Qwen2.5 技术报告）：GPT-4o-mini ≈ Qwen2.5-Turbo > Qwen2.5-14B-Instruct > Qwen2.5-7B-Instruct > Qwen2.5-7B-Instruct-INT4，即 GPT-4o-mini 基线在原始精度上对本地设置保有明确优势——这是后续结论（本地模型反超）的公平性前提。

预算口径：非 OBP 任务，基线统一 1000 次启发式评估，CALM 固定 2000 次 LLM 查询；OBP 上以往 AHD 方法典型需 2000 次评估、超过 4000 次查询，CALM 仍只用 2000 次查询。所有 LLM 基线共享种子启发式与训练数据集。

## 3. 关键设计

### 3.1 提示生成与进化算子（verbal 通道）

**池采样**：除交叉外，启发式按性能排名采样，概率 ∝ 1/rank，排名低于种群规模阈值者概率清零（沿自 EoH）；种群未满时提升 injection 的采样权重以鼓励扩张期探索。算子采样比例为 简化:注入:替换:交叉 = 1:1:2:4。

**细粒度变异算子（Injection / Replacement）**：设计动机直接耦合 GRPO 的信用分配机制——token 级优势来自整条响应相对同 prompt 其他响应的奖励差，若响应间差异过大，对同一 token 的奖惩归因就不可靠；细粒度算子迫使 LLM 保留大部分共同结构、只做局部改动，使“单一结构变更”与奖励差更可对齐（同一段代码出现在不同响应中时，累积梯度更新本可纠正错配，细粒度算子加速该过程）。Injection 要求向既有启发式注入新组件，且响应中须用名词短语描述该组件；组件描述全局保存，后续注入须区别于已存组件，prompt 中列出最近 10 条以显式排除。相对以往以整段代码为输入的变异：改用紧凑摘要以在上下文窗口内容纳更多启发式、组件库全局可及（不限于当前采样到的启发式）、只做粒度更细的修改而非整启发式重写。Replacement 每次随机取一组指令对：改写关键超参数为理论/实践上有依据的常量（沿自 EoH 系工作）；把实例无关的固定决策规则改写为由当前输入实例确定性推导的规则；把对多候选拉平/近似拉平信用的片段改写为按上下文表现区分信用（后两条为 CALM 新增）。

**多样性感知交叉**：每次以 50% 概率双亲均按性能排名采样；否则第一亲本按性能、第二亲本按多样性排名采样，多样性定义为 div(h_{c,1},h)=|idea_token(h)\idea_token(h_{c,1})| / |idea_token(h)|（idea 唯一 token 集合的差集占比）。这保证至少一个亲本高质量，另一亲本要么高性能要么结构新颖，让早期表现欠佳但结构新颖的启发式有机会被利用。附录 D 中作者指出：MCTS-AHD 允许越过 top 种群选启发式但未显式建模多样性，HSEvo 强调多样性但未进入交叉且种群定长——CALM 补上了“多样性显式进入交叉”这一格。

**简化算子**：抵消注入/交叉/替换反复叠加造成的冗余膨胀；**初始化算子**用于空池时从函数签名模板冷启动。

### 3.2 坍缩机制

动机：prompt 含更优启发式会引导 LLM 生成更强启发式，这一自强化回路同时导致近交与早熟——种群被当前最优的微小变体主导，陷入局部最优。机制：池达目标规模后启动无突破计数 c_n，一轮（G 条响应）未出现全局更优则 +1，出现则清零；每轮末若 random(0,1) < c_n·δ₀ 或 c_n ≥ C 则触发坍缩——丢弃池中全部启发式，仅保留原始种子与当前最优作为新一轮的双种子。重建期临时放宽选择压力：经注入/替换/交叉产生的新启发式只要可行即可入池（直至恢复种群规模），让结构性新颖但暂劣的组件得以传播——这在正常选择压力下不可能发生。触发时机的期望轮数有解析近似 E[c_n | collapse, C > 1/δ₀] ≈ √(π/(2δ₀))（附录 E 给出尾部和推导），便于超参选择。主配置 δ₀=5×10⁻⁴、C=25。

### 3.3 奖励函数（numerical 通道）

不可行响应按失败模式分层给 progressively 提升的负奖励：缺 idea（−1.0）、缺代码块（−0.95）、函数格式非法（−0.9）、运行时错误或超时预算（−0.85）、检出随机性（−0.75，r_rand<0，同时作为其他不可行惩罚的上限）——分级设计引导 LLM 即便达不到可行也先朝语法/语义正确推进。惩罚随机组件的理由（附录 F）：随机启发式的评估开销与噪声显著增大。

可行响应的信用不按绝对性能、而相对 prompt 中的最优基启发式 h_t_base 分配，避免把基启发式本身的质量归因于 LLM。记 Δ = clip(|g(h_new)−g(h_t_base)| / min{|g(h_new)|,|g(h_t_base)|}, 0, 1)，则（式 4）：与某条基性能相同 → 0.8·r_rand（抑制平凡复现）；劣于基 → 0.5·r_rand·Δ；优于基 → 1+Δ（严格正且从 1 起）。初始化算子无基参照，奖励恒为 0。两条性质被显式满足：任何可行响应奖励高于任何不可行响应；奖励主项由“是否改进基”决定，相对差距调节强度。

## 4. 实验结果

任务选取刻意避开 LLM-based AHD 已近最优的 TSP-ACO 与背包问题，聚焦仍具挑战性的四类：OBP（在线装箱）、TSP 逐步构造、CVRP（ACO 框架，训练/测试均固定 30 蚁×100 迭代）、OP（ACO，20 蚁×50 迭代）。基线含手工启发式（Best Fit、Greedy-Construct、ACO）、NCO（POMO、DeepACO）与 LLM-based AHD（FunSearch、EoH、ReEvo、HSEvo、MCTS-AHD、EvoTune）。ReEvo/HSEvo 在 TSP 上因过早停滞（MCTS-AHD 所发现）未报告结果；AlphaEvolve、EvoTune 代码/数据不可得，EvoTune 系将其报告的启发式迁入本文设置并用 Optuna 调参 2000 次后对比。下表汇总关键行（gap 为相对最优/下界的差距，三次运行平均）：

| 任务 / 平均 gap 或分尺度 gap | 最强 LLM 基线（GPT-4o-mini） | CALM（API, w/o GRPO） | CALM（7B-INT4, w/ GRPO） |
|---|---|---|---|
| OBP 六测试集平均（MCTS-AHD） | 0.89% | 0.82% | **0.71%** |
| TSP N=50 / 100 / 200（MCTS-AHD） | 9.69 / 11.79 / 13.71% | 10.54 / 11.88 / 13.56% | 10.04 / 11.58 / **13.41%** |
| CVRP N=50 / 100 / 200（MCTS-AHD） | 5.44 / 6.98 / 4.70% | 5.81 / 7.46 / 5.72% | **3.83 / 5.44 / 3.95%** |
| OP N=50 / 100 / 200（MCTS-AHD） | 25.27 / 17.12 / 16.34% | 24.41 / 16.76 / 16.22% | 24.22 / **15.43 / 12.58%** |

要点与口径：

- **OBP**：训练 4 个不同规模实例、6 个测试规模中 2 个为分布外（Weibull）。CALM 本地版在全部测试集上超过 EvoTune（其平均 2.36%，且用了 Phi3.5-mini + DPO、超 10 倍 LLM 查询），在 1k_500 上取得零 gap（精确最优）。以“各测试集上对 FunSearch 的平均改进幅度”计，CALM 提升 38.69%，而 EvoTune 论文口径下同 LLM 对 FunSearch 仅提升 2.88%~15.29%。
- **TSP**：训练 64 个 N=50 实例，测试为 N=50/100/200 各 1000 实例（最优解由 LKH 求得）。本地 CALM 在两个分布外规模全面领先所有 LLM 基线，域内 N=50 为第二（次于 MCTS-AHD 的 9.69%）；N=200 时 gap 13.41%，同时超过需逐规模训练的 POMO（20.45%）。
- **CVRP/OP**：本地 CALM 在 CVRP 三个规模上全部超过所有 LLM 基线（含域内）；OP 上分布外规模全面领先，域内 N=50 仍胜 EoH 与 MCTS-AHD（但 ReEvo 23.98%、HSEvo 24.08% 略优于 CALM 的 24.22%）。
- **verbal 通道单独评估**（切到 GPT-4o-mini、G=1、T=4000/OBP 与 2000/其他，对齐既有方法查询预算）：无 RL 的 CALM 在 OBP 上以平均 0.82% 领先全部 GPT-4o-mini 基线，在 5k_100 与 10k_100 上取得最低 gap；在全部 OP 规模上超过 MCTS-AHD；TSP 上 N=200 反超 MCTS-AHD。说明即便不引入反思、树搜索等机制，其算子设计本身已属一线。
- **训练动态**：训练曲线显示本地 CALM 早期落后（GPT-4o-mini 的先天优势），GRPO 适配后收敛并反超全部基线。运行开销（T=500 轮）：OBP/CVRP/OP/TSP 分别约 6.8/7.2/5.3/5.5 小时（24GB A30）。

## 5. 消融要点

消融在 OBP 与 OP 上进行（表 4，三次平均）：

- **RL 组件影响最大**：去掉 GRPO（本地模型）后 OBP 0.71%→1.78%、OP 17.41%→19.89%，是所有消融设置中最大跌幅；本地 7B-INT4 + GRPO 反超 GPT-4o-mini 版本，证明性能来源是共进化而非模型本身。
- **奖励设计**：换成纯性能奖励（相对种子算法的性能给正奖励）后 OP 21.30%，甚至差于完全不用 RL 的基线（19.89%）；换 {0.5r_rand, 1} 二元改进奖励为 1.04%/17.44%，仍逊于原设计（0.71%/17.41%）。结论：相对 prompt 内基启发式的信用分配与平凡复现惩罚是 RL 生效的前提，盲目加 RL 可能负收益。
- **坍缩机制**：默认 0.71/17.41 vs 无坍缩 0.98/19.57；但最不容忍停滞的配置（δ₀=0.005, C=15）反而崩到 1.93%/27.22%——OP 一次运行自第 132 次 LLM 查询起再无突破；C=∞ 的各配置亦略逊于默认。对“无突破容忍度”需在耐心与早停收益间折中。
- **算子**：去除任一算子均降质；去除简化算子致 OBP 0.71%→1.35%（算子中降幅最大，因其独占“降复杂度”方向）；最关键的发现是去掉多样性感知的交叉（OBP 1.05%、OP 19.44%）比完全去掉交叉（0.88%、18.49%）更差——无多样性意识的交叉是净负组件。

## 6. 贡献与启示

**贡献**：(1) 首个联合优化 prompt 生成与 LLM 参数的 LLM-based AHD 框架，把评估循环的副产品转化为训练数据，打通 numerical 通道；(2) 以单卡 24GB、7B INT4 的资源画像全面超过依赖 GPT-4o-mini 的 SOTA，验证“共进化可补偿模型代差”；(3) 一组可复用组件：细粒度变异、多样性感知交叉、带解析期望公式的坍缩机制、相对信用奖励。

**方法论启示**：(a) 任何“生成→仿真评估→筛选”闭环都存在加装 RL 反馈的机会，瓶颈不在算力而在奖励的信用分配口径；(b) 奖励设计比“是否用 RL”更关键——performance-based 奖励劣于不用 RL 的结果值得所有尝试把 RL 塞进进化搜索的工作警惕；(c) 细粒度算子与 token 级优势的耦合论证提示：prompt 侧的变异粒度应与梯度侧的归因粒度匹配；(d) 坍缩机制（保留原始种子+当前最优、重建期放宽选择）是通用的反停滞器件，且 √(π/2δ₀) 的期望公式让超参可先验设定。

**局限（附录 H）**：奖励依赖 prompt/响应中存在显式启发式，无启发式产出的轨迹不产生训练信号；仅在紧凑模型上验证，更大模型的扩展性未证。

**对音视频侧的迁移（引擎视角）**：编码器内部大量组件与本文启发式同构——QP/模式决策、码率阶梯、复杂度预筛、感知质量评分，都是“输入实例特征、输出打分、可在编码仿真环中用 RD 成本闭环评估”的函数，恰是 LLM-based AHD 的标准作用对象。CALM 的可迁移件包括：以 GRPO 适配生成器本身（而非仅进化 prompt）、相对基启发式的奖励口径（对应“相对当前编码器默认策略的 RD 改进”）、固定查询预算与 60s 评估上限的实验纪律，以及坍缩机制；其单卡资源画像与典型编码研究组的算力条件匹配。

## 7. 与其他论文的联系

- **paper:arxiv:2401.02051（EoH）**：CALM 的直接基线[8]。传承关系明确：性能排名采样（概率 ∝1/rank）、“改写超参数”替换指令均沿自 EoH；CALM 的注入/替换算子是对 EoH 变异算子的细粒度化（摘要替代整码、全局组件库、局部修改）。实验上，OBP 平均 gap EoH 1.17% vs CALM 0.71%/0.82%，CVRP N=50 上 11.32% vs 3.83%。
- **paper:arxiv:2412.14995（HSEvo）**：直接基线[10]。CALM 附录 D 明确对比：HSEvo 强调多样性驱动（和声搜索+GA）但多样性未进入交叉、种群定长；CALM 把多样性显式建模进交叉第二亲本的采样。消融中“无多样性交叉劣于无交叉”恰是对 HSEvo 路线的补充论证。数字：OBP 平均 HSEvo 1.13% vs CALM 本地 0.71%。
- **paper:arxiv:2609.12286（T-GADE）**：同以在线装箱（OBP）为主战场、同以 EoH 为对照并强调调用/查询效率（CALM 固定 2000 查询 vs 以往 OBP 4000+）。机理上构成两条不同的反早熟路线：T-GADE 用热力学自由能最小化统一存活选择，CALM 用概率坍缩+种群重置+重建期放宽选择；二者作用层面（选择算子 vs 种群级重启）不同，原则上可叠加。
- **paper:arxiv:2512.09209（算法与提示词共进化）**：同名“共进化”但共进化对象不同——该文让群智能算法与引导提示词协同进化（LLM 权重仍冻结，即 CALM 批评的纯 verbal 通道），CALM 共进化的是算法与模型权重。二者正交：提示词层面的协同进化可作为 CALM verbal 通道的升级，与其 GRPO 通道复合。
- **paper:arxiv:2508.03082（EoH-S）**：EoH 谱系向“启发式集合”扩展（互补集合覆盖多样实例）。与 CALM 的多样性感知交叉同属对 LLM-AHD 多样性缺口的回应，但层级不同：集合级覆盖 vs 交叉亲本对级的多样性采样；CALM 的坍缩-重建机制与集合维护如何兼容是自然的后续问题。
- **paper:arxiv:2603.02787（重思代码相似性）**：直接对照 CALM 的多样性度量。CALM 的 div() 是 idea 文本的 token 集合差（静态词面度量），该文指出词面相似性不足以刻画算法行为，提出求解轨迹 DTW 对齐的行为相似度并可增强 FunSearch/EoH——行为相似度可直接替换/增强 CALM 交叉中的 div() 及坍缩的停滞判据。
- **paper:arxiv:2510.14150（CodeEvolve）**：同属 LLM+EC 算法发现生态（AlphaEvolve 谱系）。CALM 引用 AlphaEvolve 但因其代码/数据不可得未纳入对比（附录 G.2）；CodeEvolve 以开源与岛屿模型推进该谱系的可复现性，与 CALM 的全开源栈（Unsloth/Qwen）方向一致。
- **paper:arxiv:2606.20847（VVenC 逐帧 QP 启发式进化）**：CALM 范式在音视频编码侧的下游实例——同一“LLM 闭环进化 Python 启发式”架构，把决策函数落到 VVenC 逐帧 QP 选择、评估信号换成 RD 成本（报告较固定 QP 平均省约 1.26% 码率，并自动发现熵约束 RDO 式结构）。CALM 对该方向的增量价值明确：其 GRPO 生成器适配、相对基启发式的奖励设计、固定查询预算纪律与坍缩机制均可移植；且编码器在环评估远比 OBP 仿真昂贵，CALM 的预算/评估时限口径设计对编码侧更具参考意义。这是本篇非核心论文与音视频技术上下游最直接的接口。
