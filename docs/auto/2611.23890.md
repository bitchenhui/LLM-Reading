## 1. 背景与动机

视频评估器在生成管线中处于承上启下的位置：它既作为 RL 奖励直接塑造生成器的优化方向（VideoReward、Flow-GRPO 一类工作），又作为训练数据过滤器决定 SFT 数据的分布。因此评估器对时序质量的盲区会被系统性传递给生成器。论文开篇给出两个量化案例说明问题的严重性：Qwen3-VL-8B 对一段干净片段与其“人物突然冻结”的编辑副本给出完全相同的物理合理性评分（4.49/4.49）；VideoReward 作为 Wan2.1 的唯一 RL 奖励训练 50 次更新后，"a boat accelerating to gain speed" 这类提示词生成出的视频运动消失甚至主体丢失——按论文 Table 6 的口径，无惩罚项的压力测试设置下动态度从起始模型的 0.579 跌至 0.289（50 更新）和 0.095（120 更新），视频塌缩为面部静止特写。

直接监督训练的障碍是运动质量的人类标注稀缺。递归自我改进（RSI）在数学与代码上已被验证可行，但其前提是存在可靠 verifier（单元测试、证明检查器）。视频评估对 RSI 提出两个结构性困难：其一，没有原生 verifier，评估器自身的打分不可信，不能既当运动员又当裁判；其二，评估是多目标问题——物理合理性、平滑性、动态性、语义一致性必须同时判断，某一维度的改进常以另一维度退化为代价（论文的消融证实了这一点：单次 LoRA 训在全部数据上，运动分数上升但人类偏好跌破下限）。论文的核心问题是：在没有 verifier、目标相互竞争的前提下，RSI 能否改进一个视频评估器。

这个问题对音视频技术栈的实际意义在于：动态视频生成的对齐瓶颈当前很大程度卡在奖励模型侧。VBench 等基准用光流等独立工具测动态度，VideoScore/VideoReward 等学习型评估器在动态性子集上与人类评分相关性很低（VideoReward 在 VideoScore-Bench 动态子集的 Spearman 相关为 −0.311，即反相关），而奖励的错误方向会直接导致 RL 训练生成器“学会不动”。

## 2. 方法总览

EVA-RSI 是一个多智能体外环搜索系统，被改进对象是评估器本身（起点 Qwen3-VL-8B-Instruct，一个以单 token 输出 A/B、1–5 评分或多选字母的 VLM，可经 LoRA 微调并调整推理设置）。整体循环为：当前 champion → 智能体团队提出并训练候选评估器 → 冻结 checker 在固定考试上打分 → Nash bargaining 接受规则决定候选是否取代 champion → 全部结果写入共享记忆供下轮读取。

两个核心构件回应两个困难：

- **构造目标的代理考试**：对干净片段施加受控编辑（时间反转、丢帧、物体消失/复制/瞬移、场景切换、闪烁等），以原片段作为 pairwise 目标，从而在没有人类标注的情况下获得确定性监督信号；再用少量人类标注的真实生成视频（VideoPhy-2、VideoFeedback 中人类分差 ≥2 分的配对）把合成监督锚定到真实感知判断上。
- **维度级智能体 + Nash 接受规则**：每个质量维度一个 proposer 智能体，leader 协调提案，基于 Nash 讨价还价解的接受规则保证只有“均衡进步”的候选胜出，禁止用某一维度的大损失换取另一维度的收益。

三个顶层设计选择值得注意： verifier 先于智能体存在且在各阶段内冻结，使候选分数可比； 智能体可控制评估器的数据、训练配方、架构与推理设置，但 verifier 不可触碰； 人类负责考试设计、候选变更审查与阶段间课程修订——这是“智能体搜索 + 人类课程设计”的混合范式，而非全自主。

计算口径：全程两阶段共 88 轮、170 个候选、产生 8 个 champion，消耗 944 B200 GPU 小时（阶段一 358、阶段二 586）；智能体运行于 Claude Opus 5.5（有限额时降级到 GPT-5.3-Codex / Sonnet 5.5 / Opus 4.6），阶段二智能体调用成本约 1,700 美元。每个候选在 4 GPU 上训练至多 1.5 小时，含打分单候选周期约 2 小时。

## 3. 关键设计

### 3.1 构造答案与考试银行

考试覆盖四组九个维度。**注入缺陷组**（物理、一致性、平滑、质量）为每个干净片段配一个含单一缺陷的副本：物理含倒放、物体冻结/消失/复制；一致性含背景替换、插入场景切换、色彩突变；平滑含帧冻结/丢帧/抖动/闪烁；质量含模糊、噪声、重压缩。每种缺陷另设细微版本（如仅冻结 2–3 帧）。**动态组**用光流差异 ≥2.5× 的片段配对（困难对 1.5–2.5×），以高光流片段为目标——注意这是“运动量”的构造代理，与物理维度的“运动合理性”互补。**真实视频组**（阶段二引入）用人类分差 ≥2 分的生成视频对，检验注入缺陷上的增益能否迁移到真实分布。**守卫组**（语义、人类偏好、general）用 caption 匹配、VideoGen-RewardBench 专家偏好对、MVBench/TempCompass 视频问答，防止灾难性遗忘。

打分方式三种混合：pairwise 正确率（tie 记 0.5）、归一化评分一致度 1−|E[r]−t|/4（评分经 next-token 概率取期望）、多选准确率；先族内平均再维度平均，主均值为五个主维度（物理、一致性、平滑、动态、真实）的平均。数据结构上，两个开发银行各约 2.9k 问题驱动循环；隐藏测试银行 3,450 题，与开发银行不共享任何问题、源片段或提示词，且加入开发银行中没有的缺陷类型，只用于给 champion 打分、从不参与接受决策，智能体无法访问。这一“开发/测试隔离 + 分布外缺陷”的设计是论文可信度的关键支撑。

### 3.2 智能体团队

四个角色由无头 coding-agent 会话承担。**Proposer** 每维度一个（五个主维度 + 四个守卫，阶段一为四主 + 三守卫），职责是审查 champion 的分数、最弱问题族与历史候选，每轮最多提两个实验，并对其他提案标记风险——它在中是其所代表维度的“谈判代言人”。**Leader** 选择、合并或修改提案（每个空闲 GPU 槽一个实验），以最大化期望 Nash 积为准则，并保证每轮覆盖多维度、含一个大胆想法和一个保护最接近 floor 的守卫维度的提案。**Engineer** 把一份规格转成代码与训练配方、从当前 champion 出发训练；训练失败时读日志修复一次。**Reviewer** 审查通过规则的候选的代码 diff，可因违规（如在银行问题上训练）否决。共享记忆账本记录每个候选的想法、提议角色、各维度开发分、决策与拒绝原因，proposer 与 leader 每轮读取——配合“从 champion 出发训练”，这构成递归性的来源：每轮搜索建立在先前所有轮次的发现之上。

### 3.3 Nash bargaining 接受规则

每个维度 i 视为谈判方，效用 uᵢ = sᵢ − dᵢ，其中分歧点 dᵢ 为起始模型（Qwen3-VL-8B）该维度分数减容差（0.02，人类偏好 0.015）。候选取代 champion 需同时满足四条：每个维度高于 floor（uᵢ > 0）；主维度均值提升 ≥0.01 且配对 cluster bootstrap 的 90% 下界大于零；任一主维度下降不超过 0.03；加权 log Nash 积严格上升，即 Σᵢ wᵢ log(sᵢ−dᵢ) > Σᵢ wᵢ log(s_champ,i−dᵢ)。主维度权重 1，语义/质量/general 权重 0.5，人类偏好 0.75。另有饱和规则：主维度饱和后，接受主分数在 champion 0.005 以内、其余维度加权增益 ≥0.005（bootstrap 下界 >0）的候选——最后一个阶段一 champion（c046）即经此路径通过。阶段二追加族级守卫：≥40 题的缺陷族下降不得超过 0.12，VideoGen-RewardBench 各 aspect 下降不得超过 0.05。

选择 Nash 积的两个数学理由：log uᵢ 在 uᵢ→0 时急剧下降，天然惩罚逼近 floor 的维度；Nash 比较对每个效用的正尺度变换不变，避免维度间分数尺度不可比的问题。floor 与下降上限则独立显式地规定容差。这个规则把“多目标不塌陷”从软约束变成了接受决策的硬门槛。

### 3.4 人类监督与四层搜索控制

人类构造考试、给起始模型逐族打分、替换已饱和或噪声大的族、审查拒绝决策，并在阶段间修订课程。两个具体修订事件具有代表性：阶段一某候选以提高平滑度均值为代价放弃时间反转族（均值升、单族崩），促使人类加入单族守卫；阶段一增益无法迁移到真实生成视频，促使人类加入真实视频维度——公开基准的增益几乎全部出现在阶段二，直接归因于这次课程修订。

搜索控制分四层： 双而多样的考试——64 种问题类型、九维度、两个来源不重叠的开发银行，每个配对以两种顺序及单独评分两种形式提问以测顺序敏感性； floor 与族守卫约束分数下降； 隐藏测试银行——一个阶段二提示词点名了阶段一测试银行观察到的弱点（慢片段反转），剔除这 36 题后最终主均值从 0.906 升至 0.916，说明考试对特定弱点的针对性； 12 个公开基准检验考试之外的迁移。verifier 边界本身也被审查：打分器与规则从冻结副本运行、程序拒绝任何引用开发/测试资产的代码变更、reviewer 可否决、人工检查每个 champion 的配方。

### 4.4 下游一：RL 奖励

用 Wan2.1 T2V-1.3B + Diffusion-ART（组内策略梯度）做 RL，所有 run 共享同一超参（EVA-RSI 试点选定），仅换奖励。EVA-RSI 奖励 = 动态/物理/平滑（权重 1）+ 质量（0.5）的 1–5 评分和，加 flicker 与全局 judder 两个惩罚项（阈值高于起始模型均值故只作用于明显缺陷），锚损失无 KL 项。对比 Qwen3-VL-8B 同读 54 帧（两者仅权重不同）与两种设置的 VideoReward。测试集 630 视频（VBench+VidProM 提示），MovieGenBench 300 提示复验：

| 奖励 | 更新 | 动态度↑ | 光流↑ | 物体运动↑ | Adh↑ |
|---|---|---|---|---|---|
| 无（起点） | 0 | 0.579 | 13.77 | 1.43 | 3.668 |
| Qwen3-VL-8B（seed 1/2） | 50 | 0.790 / 0.749 | 15.64 / 14.97 | 1.67 / 1.49 | 3.741 / 3.684 |
| EVA-RSI（seed 1/2） | 50 | 0.848 / 0.892 | 17.64 / 19.81 | 1.76 / 2.03 | 3.730 / 3.714 |
| EVA-RSI（seed 1/2） | 100 | 0.913 / 0.892 | 20.53 / 17.59 | 1.88 / 1.62 | 3.675 / 3.519 |
| VideoReward (fair，seed 1/2) | 50 | 0.351 / 0.271 | 7.94 / 7.33 | 0.82 / 0.69 | 3.041 / 2.956 |
| VideoReward（无惩罚） | 50 / 120 | 0.289 / 0.095 | 6.73 / 4.06 | 0.70 / 0.52 | 2.575 / 1.690 |

32 个预登记运动检验（两 seed × 两更新数 × 两提示集 × 两个对照）全部通过 Holm 校正（31 个中 4,000 次重采样无一跨零，p<0.0005）。adherence 在 50 更新时与 Qwen3-VL-8B 持平，更长训练下降（seed 2 在 100 更新显著 −0.15）。全预算压力测试（约 500 GPU 小时）下 EVA-RSI 动态度达 0.987、光流 26.34，而 Qwen3-VL-8B 基线 adherence 崩至 1.841——基线退化更快。盲测人类研究（6 名评价者，update 50、训练 seed 1，48 对 vs Qwen3-VL-8B、24 对 vs fair VideoReward）：EVA-RSI 视频被认为“运动更多”的份额 0.77 [0.68, 0.85] / 0.85 [0.75, 0.94]，“总体更好”0.73 / 0.69，视觉质量与 adherence 亦占优；在光流差 ≥2× 的 27 对中，89% 的非 same 答案选择光流更大的视频，且评价者看出更多运动的答案中约九成同时偏好该视频总体——运动量与偏好在人类侧并未对立。另一个有工程价值的对照：纯光流奖励在 50 更新时运动更多（动态度 0.932 vs 0.848）但抖动更严重，100 更新时在运动与 adherence 上均被 EVA-RSI 反超——流奖励只测运动量，会诱导出偏离提示词的抖动运动。

### 4.5 下游二：数据选择

Wan2.1 在 50k 经“流阈值 + caption 过滤 + EVA-RSI 排序”选出的片段上 SFT，对比 50k 随机片段（两训练集约 1/5 重叠，同配方，300 提示评估）：3,000 步后动态度 +0.277（picked 0.873 vs random 0.597，95% 区间不含零）、光流 +7.38，adherence 差 +0.03 且区间含零；选中数据训出的模型 87% 视频含运动 vs 随机臂 60%。1,500 步时增益 +0.143/+3.47 同向显著。

## 5. 消融要点

论文的对照实验把“递归协调搜索”拆解为可归因的成分，结论密度很高：

**递归性不可或缺。** 非递归控制中，同一批智能体从 Qwen3-VL-8B 训练每个候选、同样的数据与接受规则，但看不到分数与结果（只见提案标题与角色）：10 个提案中 1 个未过预算检查，其余 9 个全部跌穿人类偏好或 general floor，212 GPU 小时后因停滞终止。**配方依赖继承的能力**：把 c033 的完整配方直接从 Qwen3-VL-8B 复现（两个 seed），测试主均值仅 0.757/0.756，平滑只有 0.514/0.505；沿 champion 链训练的 c033 为 0.902、平滑 0.850——配方本身不迁移，迁移的是链上累积的视觉与运动能力。

**数据聚合不等于协调搜索。** 一次性在全部循环训练数据（含阶段二池）上训练单个 LoRA（Union SFT，384 GPU 小时）：测试 0.889、人类偏好 0.558（跌破下限）、public 0.53，对比 EVA-RSI 的 0.906/0.660/0.71，且 EVA-RSI 在测试与人类偏好上的优势经 95% 区间检验显著。加锚的 Union（每 seed 352 GPU 小时）可通过规则但测试分落后 EVA-RSI 0.058/0.062，最大差距同样在平滑。这组对照精确刻画了论文的核心论点：把数据全喂进去能提运动分，但技能保留需要搜索过程中的配方选择。

**Nash 条件的实际作用。** 事后在隐藏测试银行上重放被 Nash 积拒绝（但开发增益 ≥0.01）的三个候选：其测试均值与父代差距在 −0.002 到 +0.003 之间，但物理分均更低；去掉 Nash 条件会把这三个决策翻转为接受。反例是 c006（前十个阶段一候选中开发增益最佳者）：仅按均值增益它会被接受，但 public score 只有 0.40、不迁移。Nash 规则在测试分布上的诊断性有限（重放的是固定轨迹），但方向上一致地阻止了以物理换均值的候选。

**智能体模型影响搜索质量。** 换用 Grok 作为智能体（同起点、同考试、同规则）全程未产生新 champion；Claude Opus 5.5 产生 8 个。

**收益递减与考试边界。** EVA-RSI 之后被打分的 14 个阶段二候选全部落在其 −0.004 到 +0.001 之内；第三阶段 100 个候选无一通过冻结规则（放宽后通过的两个与 EVA-RSI 持平）。真实视频分数在阶段一被钉在 0.700–0.755，考试加入人类标注真实视频后第一个 champion（c001）单步升至 0.852——“verifier 限定结果上限”是论文最明确的经验结论。

**成本结构。** 阶段二智能体成本约 1,700 美元，其中一半耗在 engineer 会话反复重读增长的账本（10k–28k token）与堆叠的 champion 代码；第三阶段用 ≤700 词的滚动 lessons 文件、代码地图与死代码剪枝将 context 压平。170 个候选中 52 个因训练作业失败、20 个因实现被拒而未获打分——工程可靠性损耗约占一半搜索预算。

## 6. 贡献与启示

方法论上，论文给出了把 RSI 扩展到“无 verifier、多目标竞争”领域的完整模板：verifier 外置且冻结（构造编辑提供确定性目标 + 人类标注锚定感知有效性）、改进单元细化到维度并由维度级智能体代言、Nash bargaining 把多目标不塌陷编码为接受规则、隐藏测试银行与公开基准双层检验过拟合。其中“构造编辑作为免标注监督”与“人类只在课程层介入”两点对标注稀缺的时序质量维度（运动、物理、平滑）有直接的迁移价值——这类维度恰恰是现有人类偏好数据覆盖最差的。

资产层面，一个 8B 开放评估器在两个公开动态子集上取得 21 模型中的最高点估计（含专有模型），且在 12 基准总排名上领先全部开放模型；作为 RL 奖励，经 32 个预登记检验与盲测人类研究确认能提升生成运动且不牺牲早期 adherence；作为数据过滤器带来 +0.277 动态度。对音视频工程而言，这验证了一条具体因果链：修复评估器的时序盲区 → 奖励方向修正 → 生成器运动能力提升，评估器可靠性是动态视频对齐的可操作杠杆。

局限同样清晰：构造编辑简化了运动失败模式，与真实生成视频分布（缺陷与场景内容、意图交互）存在差距，复杂交互失败仍未覆盖；文本对齐维度没有任何候选被接受，公开基准上 EVA-RSI 在 VideoScore-Bench-v2 文本对齐低于起点且低于 VideoScore2；RL 长训下 adherence 下降（seed 2 在 100 更新显著）；收益在固定考试上快速饱和，继续改进依赖人类扩展考试——搜索的上限由 verifier 设计决定，这既是局限也是论文最诚实的方法学结论。

## 7. 与其他论文的联系

- **paper:arxiv:2611.10787（TRUST，可信赖 RSI 的统计保证）**：同一核心问题的两种解法。TRUST 用在线多重假设检验控制 RSI 智能体的错误进化率并提供统计保证；EVA-RSI 在无 verifier 领域用工程化手段达成同类目标——冻结外置 verifier、floor/族守卫、接受规则中的 90% bootstrap 下界、champion 步进的 Holm 校正。两者互补：EVA-RSI 的机制是启发式门控 + 事后统计检验，TRUST 提供的形式化框架或可用于加固 EVA-RSI 的接受规则。
- **paper:arxiv:2611.12109（SkillDuet，模型与技能协同演化）**：SkillDuet 把递归自改进的粒度设为技能级（参数更新与外部技能库共同演化）；EVA-RSI 同样把改进粒度从整体分数细化到维度/技能级（九个维度各有 proposer 代言），但其“技能保留”不靠外部库而靠 Nash 规则与守卫维度的硬 floor。两者共同指向一个结论：粗粒度的单一总分驱动 RSI 会导致技能间倾轧。
- **paper:arxiv:2611.20430（TrainExplorer，自主 LLM 后训练）**：TrainExplorer 以规划与执行解耦的多智能体实现自主后训练；EVA-RSI 本质上是面向视频评估器的自主后训练——leader 规划、engineer 执行训练、冻结规则验收，完整搜索了数据、配方、架构（时间反对称 vision tower、分辨率）与推理设置。差异在于 EVA-RSI 的被优化目标是评估器而非生成器，且必须在多目标间谈判。
- **paper:arxiv:2611.11558（InfraRSI，训练基础设施的 RSI）**：InfraRSI 把开放式指令转化为分布式训练优化并经多阶段验证工作流验收；EVA-RSI 的 engineer 角色执行同构任务（规格 → ≤1.5 小时 4 GPU 训练作业，失败读日志修复一次），且同样依赖验证门控（冻结 checker + Nash 规则）过滤不可靠产出。两者共同凸显训练作业失败（EVA-RSI 中 52/170）是 agent 驱动训练工程的主要损耗点。
- **paper:arxiv:2611.07319（WeightLoop，实验反馈的权重空间编程）**：WeightLoop 让 LLM 生成有界参数编辑程序、以实验反馈迭代改写已部署权重、免重训练；EVA-RSI 同属“实验反馈驱动的权重演化”，但每步经 LoRA 梯度训练并维护 champion 链（含权重 soup 与组件组合），反馈信号是构造考试分数而非部署指标。可视为同一外环范式在“程序化编辑 vs 梯度训练”两条实现路径上的分野。
- **paper:arxiv:2610.32326（TGR-EvoDAG，腾讯生成式推荐的 DAG 式多智能体代码演化）**：TGR-EvoDAG 自主演化完整推荐管线并以在线 CTR 验收；EVA-RSI 的 champion 谱系呈现类似的组合结构（c007 权重 soup、c029 组合 c022 的 vision tower 与 c021 的 LM），均为多智能体自主搜索训练/系统配方并以业务外部指标（在线 CTR / 隐藏测试银行）约束搜索方向，区别在 EVA-RSI 需处理连续多维质量的讨价还价而非单一业务指标。
