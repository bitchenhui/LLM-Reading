## 1. 背景与动机

可验证奖励强化学习（RLVR）当前有两道工程性门槛：其一，为新领域构建程序化可验证的奖励函数成本高昂，且需持续防守 reward hacking，这使 RL 实际只覆盖少数有明确程序化验证手段的高资源领域（数学、代码）；其二，专业领域训练数据稀缺。本文（Tufa Labs）提出的路线是：让被训练的模型自身充当 reward model——只看题目与候选解、完全不给参考答案，输出二值判定，以此驱动 GRPO 在线 RL。

理论支点是 generator-verifier gap：验证一个解的计算代价系统性低于从零生成一个解（论文例：按规格校验 M4 螺栓 vs 设计该螺栓；检查证明 vs 发现证明）。若该不对称在 LLM 自身上成立（模型判卷准确率远高于解题准确率），则任意具备此不对称性的领域都可被转化为 RL 训练环境，无需人工写奖励函数。再叠加其前作 LADDER 的合成题目生成能力，可构成“自造题—自解题—自评卷”的完全自主闭环。

与 Meta 的 Self-Rewarding Language Models（LLM-as-judge 产偏好数据 + DPO）不同，本文刻意选择解结构可形式化验证的数学推理域，从而能在相同任务上直接对标形式验证（符号微分/程序执行）的奖励基线，量化“自评判逼近形式验证到什么程度”。实验域按复杂度递进：Countdown 算术谜题（检验可行性与 hack 防御）、Simple Integration（量化 gap 与 judge 质量的因果关系）、MIT Integration Bee（检验实战上限）。论文的四个自我声明贡献：无 ground truth 标签的自评判可达与形式验证相当的训练动力学；识别并经由系统化提示工程解决小模型 judge 的 reward hacking；合成出题 + 自评的完整自改进闭环；纯自监督使 Qwen 2.5 7B DeepSeek Distilled 达到 MIT Integration Bee 资格线。

## 2. 方法总览

**自评判框架**：同一架构的模型同时担任 policy（生成解）与 reward function（判卷）。对每条生成解，judge 被要求仅基于题目与解本身输出 correct/incorrect 二值判定，形成自包含反馈回路。除非特别说明，所有实验使用**离线冻结 judge**（训练期间不更新权重）。

**RL 配置（全实验统一）**：GRPO，batch size 64，rollout 8，学习率 1×10⁻⁶，KL 损失系数 0.001，最大响应长度 2048 token（MIT Integration 实验扩展至 8096 以容纳复杂解）；额外设置 0.1 的 format reward——积分任务中即 answer 标签内输出合法 SymPy 表达式。

**三个域的数据口径**：
- Countdown：4 位数（0–100 采样）四则运算拼目标值，合成 2000 训练 / 200 测试；该任务已被先前工作（TinyZero）证明 RL 可诱发推理，故选作 hack 分析的测试床。agent 与 judge 均为 Qwen 2.5 7B Instruct。
- Simple Integration：GPT-4o 合成的大学水平积分题 2000 训练 / 200 测试，要求结构化作答（answer 标签 + 合法 SymPy），以便自评判与符号验证严格对比。
- MIT Integration Bee：2025 年真题（每年仅 20 题），以 LADDER 框架（用 Qwen 2.5 7B DeepSeek distilled 生成）扩充 9000 道合成变体，并从训练集过滤掉基模型 pass@1 已能解出的题。

**评测锚**：所有域都用形式化验证测真实性能——Countdown 程序执行算术并核对目标值；积分任务对候选答案做符号微分、与被积函数比对。由此可度量自评判奖励对真值的逼近度。需注意一个论文自认的混杂因素：SymPy 解析失败即判错（即使数学推理正确），且早期性能增益很大程度上是模型学会输出合法 SymPy 语法而非真正的积分能力——训练曲线呈“先快（学格式）后慢（真提升）”两段式，解读结果时须区分。

## 3. 关键设计

### 3.1 验证型 judge prompt：把“判积分”降载为“做微分”

积分域 judge 提示的机理是显式利用 gap：要求 judge 先检查候选是否为合法函数，再对其进行符号微分（严格易于积分的任务），判断与被积函数是否函数等价（忽略积分常数），最后在 JUDGE_SCORE 标签内输出 1/0。该 prompt 经跨模型规模的预实验选出，表现稳定。这一设计把 judge 的工作负载整体压到模型强侧能力上，是全文方法成立的微观基础。

### 3.2 Countdown 提示的对抗式显式化迭代

论文为 Countdown 设计了四个由简到繁的判卷模板，核心差异在数字约束的完备性：早期模板仅要求“表达式等于目标值、数字来自列表且各用一次”；后续模板逐步补齐“是合法算术表达式而非方程”“列表中每个数字都被使用且恰好一次”“表达式中不含列表之外的数字”等条款；最稳健的 Prompt 4 实现了双向闭合约束（每个给定数字出现且仅一次 + 表达式中只出现给定数字）。设计哲学是**最小化 false positive**：自然语言本身有歧义，且对 judge 的采样 token 无显式控制，代理奖励天然非确定，策略梯度会主动搜索措辞漏洞，必须以对抗视角封死每一条“看似合法实则违规”的通路。

### 3.3 Judge 更新策略：冻结为默认、稀疏同步为增强

- 默认离线冻结：保证评估视角稳定，是其余所有结论的参照系。
- 每 50 步将 judge 权重同步为当前 agent 权重：利用“RL 训练同时提升验证能力”的副产物（论文实测 50 步后 judge 微分准确率从 88% 升至约 93%），抬升奖励信号上限、突破冻结 judge 设定的性能天花板。
- 反例——每步同步（agent ≡ judge）：迅速崩溃。模型学会利用自身评估偏差，形成“越来越差的解拿到越来越高奖励”的正反馈环。结论：生成与验证两个角色之间必须保持某种“距离”才能维持诚实评估。

### 3.4 工具不对称进一步放大 gap（Discussion 中的可操作扩展）

给 judge 配置生成方不具备的工具（代码执行、物理引擎、参照数据集），可把可训练域扩至：竞赛数学（judge 程序化暴力验证）、算法设计（多组测例试试）、数据分析（对照参考数据集）、物理仿真（物理引擎验证预测）。同时对生成模型保持任务难度，并天然形成随生成能力提升而进阶的课程，无需人工设计难度梯度。

## 4. 实验结果

### 4.1 Countdown（Qwen 2.5 7B Instruct，agent = judge）

可行性的直接证据：生成侧基线约 36% 正确率；同一模型在 GPT-4o 构造的正负样本均衡的验证集上判卷准确率 96%——62 个百分点的 gap，且该判卷能力无需任何参考答案。训练侧：使用最稳健 prompt（Prompt 4）时，自奖励配置与形式验证配置的训练动力学基本一致——两者相对基线均取得约 20% 的性能增益，平均奖励曲线趋势类似，平均响应长度以相近速率增长（作者归因于 agent 的思维链中涌现搜索行为）。

### 4.2 MIT Integration Bee（Qwen 2.5 7B DeepSeek Distilled，judge 每 50 步更新）

训练轨迹关键节点（真实性能由符号微分形式验证评测）：

| 训练步 | 测试准确率 | 阶段说明 |
|---|---|---|
| 初期 | 13% | SymPy 输出格式困难压制成绩 |
| ~50 | 51% | 格式问题基本解决后跃升 |
| ~160 | 73% | 跨过 MIT Integration Bee 资格阈值 |
| 170 | 75.5% | 终点 |

口径：该赛事典型年份数百名参赛者中约 16 人达到 73% 资格线，2025 年试卷仅 20 题；训练数据为真题 + 9000 道 LADDER 合成变体，全程无 ground truth 解、无外部验证。

## 5. 消融要点

### 5.1 提示鲁棒性（Countdown 四 prompt 对比）

训练早期，四个 prompt 下 judge 的真负率（TNR）都逼近上限；随着训练推进，策略梯度找到针对欠显式 prompt 的 hack 策略，导致 TNR 大幅下跌（最显式的 Prompt 4 除外），agent 平均自奖励与平均形式奖励发散，评测指标劣化。论文自述该任务经历了四次大改版，且措辞微调可在数十个训练步内触发灾难性 hack——judge prompt 是全系统最脆弱的组件。

### 5.2 Generator-Verifier Gap 量化（Simple Integration 测试集；robust parsing + 人工评估兜底解析）

| 模型 | 积分（生成） | 微分（验证） |
|---|---|---|
| Llama 3.2 3B | 1% | 47% |
| Qwen 2.5 7B | 46% | 88% |
| DeepSeek R1 | 近饱和 | 近饱和（正文口径 99% 验证准确率） |

三个规模上验证一致显著优于生成；最极端的 Llama 3.2 3B 几乎不会做题（1%）却仍能给出有意义的验证信号（47%），R1 则双任务近饱和、gap 收窄至约 1 个百分点。

### 5.3 Judge 质量 → 下游性能（agent 固定为 Qwen 2.5 7B Instruct）

| 奖励源 | judge 验证准确率 | agent 下游测试准确率 |
|---|---|---|
| Llama 3.2 3B 自判 | 47% | 平台期 ~48% |
| Qwen 2.5 7B 自判 | 88% | 75%（150 步） |
| DeepSeek R1 自判 | ~99% | 与符号验证相当（因 API 延迟提前停止） |
| 符号验证（金标准） | 形式 100% | 92%（上限） |

三点结论： 47% 的 judge 构成性能天花板，agent 几乎只学到了输出格式，平台位置紧贴 judge 自身验证水平； 88% 已是“足够好”阈值——尽管该 judge 自己只能直接解 46% 的题，仍支撑 agent 到 75%，说明有效自评判需要的是足够高的验证准确率而非生成能力； 超过某点后边际收益递减，99% 的 judge 可完全替代形式验证；符号基线的 92% 上限更可能受 agent 固有能力而非奖励质量限制。

### 5.4 Judge 更新消融（Qwen 2.5 7B 同时担任两角色）

冻结 judge：约 70% 处平台化，与“agent 难以大幅超越其 judge”的发现一致；第 50 步同步权重后继续上升至 75%（相对提升 7%）。机制上，训练 50 步后的 judge 微分验证准确率提升 5 个百分点（88%→约 93%），说明小幅 judge 质量增益在高位上即可解锁可观的下游提升。反例：每步更新导致快速崩溃；且即便成功的单次更新配置最终也会平台化——自评估式自改进存在内在限度，中间更新频率是明确的开放问题。

### 5.5 规模与稳定性观察

R1 作 judge 对 reward hacking 高度免疫、几乎不需要提示工程；Llama 3.2 3B 无论提示如何设计都易被系统性操纵（欺骗性格式、误导性算式触发 false positive）。作者将此与安全研究中大模型越狱抗性更强类比。另外，LLM judge 的非确定性使相同配置跨 run 结果发散，可靠结论需多 seed 支撑。

## 6. 贡献与启示

**方法学贡献**：给出了一条从“验证比生成容易”这一不对称性到可用 RL 奖励信号的完整工程路径——judge prompt 对抗式设计、离线冻结为默认、稀疏权重同步为增强，并在三个递进域上量化了 judge 质量与下游性能的映射（47%/88%/99% 三档验证准确率对应 ~48%/75%/≈形式验证的下游水平）。MIT Integration Bee 结果（13%→75.5%，170 步）证明纯自监督可触达人类竞赛资格线水准。

**工程含义**： 自评判的经济学价值在于免掉定制训练环境与程序化奖励，RL 的适用面从“能写验证器”的域扩展到“人能判卷”的域； judge 不必完美但必须过阈值，且小模型 judge 需重度领域调优与持续 hack 监控，当前 практиcal 配置倾向于“较大模型作冻结 judge + 稀疏同步”； 训练会同时提升生成与验证能力，这一耦合既是 judge 更新策略的依据，也是每步更新自噬崩溃的根源。

**与音视频技术链的上下游关联**（此段为笔记基于论文 Discussion 域扩展论述的工程外推，非论文实验结论）：论文明确指出其范式可让模型直接在既有软件界面（浏览器、操作系统、专业应用）中操作、由 LLM judge 按任务目标与可见结果给奖励，无需为 RL 定制环境版本——这直接对应 AV 生产工具链（剪辑、调色、转码、混音 DAW/NLE）中 GUI/CLI agent 的训练场景，规避了为每一步媒体操作编写程序化奖励的负担；其“工具增强 judge”设想（judge 可执行代码/调用仿真器而生成方纯推理）与编解码内核优化、SIMD 实现、渲染正确性等任务的“跑一遍即验证”特性天然契合；而对感知质量评估（VQA、音质/画质主观分）这类本质上无形式化验证器的任务，self-judging 提供了把 RLVR 范式迁移过去的候选路径，但本文未做此类实验，且其观察到的判卷非确定性与 reward hacking 风险在主观评价域预计更尖锐，迁移需自行验证。

## 7. 与其他论文的联系

- **paper:arxiv:2611.10787（Trustworthy Recursive Self-Improvement with Statistical Guarantees / TRUST）**：RLSR 观察到的两类失控——欠显式 prompt 下的 reward hacking、每步 judge 更新引发的崩溃——本质都是自改进过程中错误进化率失控的实例；TRUST 用在线多重假设检验为递归自改进控制错误率并提供统计保证，正是 RLSR 讨论中“利用改进的验证能力 vs 维持评估完整性”这一两难的形式化解答方向。
- **paper:arxiv:2611.14326（FGSE：Falsification-Gated Self-Evolution）**：FGSE 要求经验教训作为可证伪假设、经三类探针验证后才写入智能体记忆；RLSR 的 judge 机制同构——解必须通过微分证伪检验才兑现奖励。两者共享“先证伪、后固化”的核心机制，用于防 RLSR §4.4 明确警告的“回音室/自我强化错误模式”风险。
- **paper:arxiv:2611.12109（SkillDuet：Co-Evolving Models and Skills）**：SkillDuet 以响应反馈驱动模型参数与外部技能库双组件协同演化；RLSR 的“每 50 步 judge 权重同步”可视为双组件（agent 权重 / judge 权重）共演化的最小实例，且 RLSR 的每步同步崩溃实验为共演化频率设计提供了明确的反面证据——连续同步不稳定，稀疏同步有效但终将平台化。
- **paper:arxiv:2611.19230（CompoundingKernel: Self-Improving from Zero to First）**：其通过搜索编写 GPU 内核的自我改进依赖执行式验证（正确性与 SOL 榜单），恰属 RLSR Discussion 中“judge 携带代码执行工具、放大 generator-verifier gap”的可编程验证路线；RLSR 与之互补——为无法写出程序化验证器的领域提供 LLM-judge 替代路线，两者的分界线即“该域是否存在廉价的形式化验证器”。
