# Useful Memories Become Faulty When Continuously Updated by LLMs

> Dylan Zhang, Yanshan Lin, Zhengkun Wu, Yihang Sun, Bingxuan Li, Dianqi Li, Hao Peng. *arXiv:2605.12978v2 (2026-05-13)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

论文研究的对象是 LLM 智能体中“情景记忆 → 抽象经验”的持续整合范式：智能体完成任务后，将轨迹蒸馏为文本“经验/工作流/策略”写入持久记忆库，并在新经验到来时反复重写。这类系统（CLIN、AWM、Dynamic Cheatsheet、ACE 等）的设计前提是：每次 consolidation 至少是无害的，经验越多记忆越好。本文系统性挑战这一假设。

核心实验设计上的关键控制：作者刻意让输入轨迹“先验有用”——要么来自智能体无记忆时已解决的问题，要么直接提供 ground-truth 解。在此条件下发现整合后的记忆反而变差，从而把失败归因于 consolidation 步骤本身而非经验质量。

最干净的一组证据（ARC-AGI Stream）：GPT-5.4 无记忆时对一个 19 题 ARC-AGI 切片 100% 正确；将这些题的 ground-truth 解逐题流式灌入整合循环后，同一批题正确率跌至 54%（Fig. 2）。十次重复实验，批量整合 70.0±7.8 vs 流式 55.8±7.1（Table 19）；扩展到 33 个无记忆可解任务后，pass@10 从 100%（33/33）跌至 epoch 1 的 66.7%（22/33）、epoch 10 的 60.6%（20/33），pass@1 均值从 58.5 降到 38.5（Table 2/20）。即退化不是采样噪声，且表现为“覆盖损失”。

与灾难性遗忘的区分（§L.4）值得注意：任务分布固定时仍发生退化（~46% 已解问题变得不可解）；混合任务批次比同质批次更糟（与灾难性遗忘下 interleaving 应有益的预期相反）；同一批轨迹一次性整合优于流式整合，说明伤害来自“重复重写”而非证据本身；且损坏形态是“扭曲”（任务族被合并、规则越界泛化、虚构流程），不是旧知识淡出。这提示补救手段应是“门控/延迟抽象 + 保留原始情景”，而非 rehearsal 或漂移正则。

## 2. 方法总览

论文不是提出新记忆系统，而是做一个受控的失败归因研究，方法论上有三条主线：

**(1) 多基准 + 多整合框架的观察性验证。** 覆盖 ALFWorld、ScienceWorld、WebShop、AppWorld、Mind2Web，以及 4 个代表性蒸馏式记忆方法（CLIN/AWM/Dynamic Cheatsheet/ACE），后扩展到 7 个框架（LangMem、Mem0、ProPlay、ACE、AWM、Letta、Dynamic Cheatsheet）× 2 个骨干（GPT-5.4-mini、Claude Sonnet 5）。三种记忆构建 regime：Static-All（全池一次性抽象）、Static-Group（按任务类型分组抽象后拼接）、Stream（分批持续更新），三者输入轨迹池完全一致，只改变呈现方式。评估时所有记忆条目全量进上下文，每题平均两次重复。

**(2) ARC-AGI Stream 受控测试床（核心技术贡献）。** 基于 ARCGEN 生成器（Moffitt, 2025）与 ConceptARC 概念分组，构建三重控制： 潜在任务分类学完全已知——6 个 family（选择规则：颜色属性/最大物体/关键标记/形状频次众数/框内包含/双面板子图）× 7 个 skill（固定变换：keep/border/recolor/translate/flip/mark_center/hollow），两轴正交； 程序化 ground-truth； 暴露结构化记忆操作词表可逐步审计。由此可以按 family 追踪记忆演化、统计误分组率、审计缓冲区构成——这些在 ALFWorld/ScienceWorld 上不可测。双存储结构直接对应 CLS（互补学习系统）框架：Episodic buffer 存题-解对，Abstract store 存整合后的策略条目；每步模型可选 Retain / Delete / Consolidate。三个控制回路：**Force**（每轮强制整合、episodic 条目不跨轮保留）、**Auto**（模型自选保留原始或抽象）、**Episodic Management Only**（只允许 retain/delete，禁用抽象）。两个轨迹 regime：GT（灌入真值解）与 Running（自求解在线学习）。

**(3) 归因消融。** 固定批次顺序，只改变整合步骤“能看到什么/能做什么”，把退化拆解为三个可分离机制：初次压缩误差、跨更新条件化（早期不完美抽象作为上下文污染后续整合）、破坏性原地重写。

## 3. 关键设计

**让失败可归因的实验构造。** 全文的方法论杠杆在于“输入有用性由构造保证”：GT regime 下每条输入轨迹都是真值解，退化的唯一嫌疑人是整合算子。这个设计使得"memory erosion"与"garbage in garbage out"解耦。

**Memory surgery（记忆手术）。** 从 WebShop 整合记忆快照中删除单条 workflow（W8）并固定其他一切重新评估：W8 把 `click[Next >]` 翻页原语升格为一等工作流，无停止准则、候选占位符从不绑定具体 ASIN。删掉 W8 后，gpt-5.4-mini wins 7/50→14/50、mean reward 0.23→0.37；gpt-5-mini 18/50→23/50、0.49→0.59，步数上限触顶数 22→17（Table 15）。行为层面：保留 W8 时翻页动作计数是删除后的 2.3×（gpt-5.4-mini 421 vs 181；gpt-5-mini 559 vs 246），发出至少一次 Buy Now 的回合数从 14/50→21/50 与 28/50→33/50。这证明单条抽象条目可以内容级地劫持动作分布。

**策略谱系追踪。** 整合器输出的每条 JSON 条目携带 lineage 字段，通过 from_existing 指针跨快照回溯，可以逐轮追踪一条策略如何被重写。附录 C 的实做例子展示了典型侵蚀路径：根节点含“水平镜像坐标公式”，中间节点丢掉镜像子句、加上统一重上色，末端又把重上色换成统一平移——骨架保留、决策相关的具体操作在每次重写中被替换。附录 D 则给出定性故障分类：空洞抽象（“先复制输入再修改再返回”这类任何嵌套列表程序都成立的 Python 惯用语）、具体词汇侵蚀（50 轮重写后 "max size" 这一唯一可计算特征被抹成“派生数值属性的派生数值属性最大值”）、异族注入（inside-frame 任务条目混入 group-by-shape 与 key-marker 家族的步骤）、失败尝试的幻影策略（从失败代码中的 `out[r][min(cols)] = 0` 片段蒸馏出虚构的“字形规范化”规则）。

**变长上下文对照（§L.5）。** 用随机训练题填充 prompt 到 ~790K token（不含解）或 ~733K token（含解），GPT-5.5/GPT-5.4/Claude Opus 5 的精度下降仅 1.6–3.6 分且统计不显著（t 检验 p≥0.14），排除"context rot"作为替代解释。

## 4. 实验结果

**非单调效用曲线。** ScienceWorld（CLIN，批大小 4）：效用约在第 20 步达峰后持续下滑至第 100 步，各记忆容量（16/50/∞）下形态一致，有时跌破无记忆基线（Fig. 1a）。WebShop（AWM，50 回合 held-out）：从 8 个样本的 0.64 跌到 128 个样本的 0.20，与无记忆持平——规模化记忆最终抹掉自身收益（Fig. 1b）。

**强起点记忆不是不动点。** 用 GPT-5.4 按 Static-Group 构建高质量 ALFWorld 记忆，再让 GPT-5-nano 在同池上分批继续更新，三个 solver（Qwen3.5-27B/9B/4B）下效用一致下滑，且相邻评估步之间可出现大幅跳水（Fig. 4）。

**流式 vs 整合的量化差距。** 跨 5 个骨干（GPT-5-Nano、Qwen3.5-27B/9B/4B 等），Stream 相比整池 Pool 损失 17–38 分；按任务族分组（Static-Group）一致优于跨族联合整合（Fig. 3）。

**前沿自主管理也难幸免。** OpenCode harness 下让 4 个前沿骨干以最大推理预算全权检查/修改/删除记忆（ARC-AGI Stream，50 题）：全部先升后降，GLM 5.2 回落到无记忆水平（22.0%）、DeepSeek V4 Pro 跌破（18.0% < 28.0%），GPT-5.5 与 Claude Sonnet 5 分别回落 12/10 个百分点但仍高于基线（Table 3/30）。

**最关键的归因消融（Table 5/22/23）：流式更新的哪一部分造成损坏？** ARC-AGI Stream、GPT-5.4、批大小 1、强制更新、step 400：

|---|---|---|
| 默认整合（原地重写） | — | 43.2 |
| A：仅追加，先验库可见 | 原地重写 | 50.0 |
| C：增 + 删，无原地编辑 | 原地重写（保留修剪） | 64.0 |

| 原始轨迹（不整合） | 全部整合 | 76.6 |

三个机制均可分离且有贡献： 跨更新条件化在高频 regime 确实有害（批 1 时隐藏先验库 Force 50.0→70.0），但在批 8 时反转为有害（52.0 vs 60.0）——条件化兼具“污染下一批整合”的成本与“告知新材料归属”的收益，其符号取决于更新次数（批 1 有 400 次更新 vs 批 8 只有 50 次）； 初次压缩误差无法消除：批 1 的 B 条件是最干净流式设定，70.0 仍低于原始轨迹（GT 代码 76.6、自然语言 70.4，Table 17 十次运行均值，且两者全程不退化）； 原地重写是单一最有害成分（C 优于 A 且两者均优于默认），而删除/修剪实际有益。注意 B 不可部署：无法去重导致条目数多 4.83×、文本量多 3.81×，批 8 时超出上下文窗口（缺失的 step-400 单元格）。

**批大小与更新模式的网格（Table 18，十次运行均值±std）。** 批 32 Force 终态 59.0±4.9 优于批 1 Force 的 43.2±6.8——更大批次让任务类型分割更可靠，与 §6.1 的“正确分割需要时间”机制一致。延迟压缩（§L.3）：自主模式下批 32 的累计整合事件 183/400（46%）远高于批 8 的 74/400（18.5%）——一旦分割可靠，模型自己也更愿意整合。但即使批 32 仍追不上保留原始经验。

**组件消融（§K.1，Fig. 17）。** GT-400 流上四个检查点：Episodic Only 与 Auto 差距在数分内，Abstract Only 不超过 zero-shot；两者结合在每点加几分，但 400 步处的滞后下滑追踪抽象库的渐进侵蚀。

**三种失败模式的量化证据。** 误分组（§6.1）：Auto 模式最终收敛到覆盖全部 6 个问题族的干净 episodic store，但需要 71 步（568 个样本）才把六个族全部纳入缓冲；Force regime 下误分类（合并 ≥2 个问题类的操作）频繁发生——瓶颈不是识别类结构，而是强制抽象破坏了模型本来具备的分割能力。干扰（§6.2）：15 任务 ScienceWorld 切换序列上，Cumulative（对任务 1..t 联合整合）最终落后 Fresh（只对当前任务 t 蒸馏）+203 分；LLM judge 标注显示 Cumulative 以约 5× 速率积累过度泛化条目（94 vs 18）、约 20× 速率积累垃圾条目（217 vs 11），差距单调扩大（Fig. 18）。过拟合（§6.3）：单一策略族重复输入下，记忆在精确重复题上稳定但在同族简单变体上崩溃（Fig. 11：更多蒸馏轮次使共轭任务精度从 70.4%/37.0% 分别跌至 22.2%/11.1%）；抽象朝表面规律而非底层求解策略偏移。

**单阶段塌缩案例（§G.2）。** ALFWorld 迭代整合中，S=168→169 一步把 50 条结构化条目（48,506 字符）合并成单条“统一循环”（1,960 字符），三个 rollout 尺寸各损失 6–13 wins，且损失随 rollout 强度单调放大（Qwen3.5-4B −6、9B −10、27B −13，单次运行）。侵蚀的内容形态（§G.1）：stage 200 的 38 条中 22 条提及 desklamp、21 条以同一 desklamp 开场句开启——该指令只适用于 8/48 的 look-at-in-light 评测回合，却占据 >55% 的上下文槽位；stage 20 的“冷却/加热不对称”等可分离洞察在 50 条上限的 FIFO 淘汰中被挤光，两条条目字节级相同。ExpeL 案例另揭示投票计数陷阱：top-1 槽位 99 票横跨三个不同概念（具体交互模式→泛化启发式→同义反复），EDIT 计票不随概念替换重置，票数追踪的是编辑量而非当前内容质量。

## 6. 贡献与启示

**核心论断。** 当前 LLM 不是可靠的记忆整合器：每次整合是有损重写，有用细节被丢弃、虚假规则被引入、曾有用的抽象偏离任务结构；错误经重复重写复利放大。文中给出三条失败机制（误分组、过度泛化剥离适用条件、窄流过拟合），并通过受控消融把损伤进一步定位到“破坏性原地重写 + 跨更新条件化 + 初次压缩误差”三个可分离成分，其中原地重写单一最有害、删除/修剪反而有益。

**对记忆系统设计的直接处方。** 原始轨迹应作为一等证据保留，整合必须显式门控而非每次交互后自动触发；episodic 与 schema 形成两个角色应在架构上分离，不应折叠进单一重写循环。Auto（门控）与 Episodic Management Only（完全禁用抽象）均匹配或超过 Force，指向“强制逐条重写——而非抽象本身——是决定性失败模式”。

**方法论贡献。** ARC-AGI Stream 作为可审计测试床（已知分类学 + 真值 + 结构化操作词表）本身是可复用资产；“情景-only 基线应当是蒸馏式记忆方法的必测对照”是一个容易被社区采纳的评测规范——多数已发表方法在其自身输入原料面前并不占优，这是相当尖锐的隐含批评。

**边界与局限。** 作者明确承认 episodic 积累不是长期答案：原始历史无界增长、抗组合复用；压缩与迁移终究需要抽象。GEPA 实验显示“绕开记忆”可部分止损，暗示当前抽象质量的提升空间在 solver 端的信任校准而非记忆端的重写逻辑。从音视频技术交叉视角看，本文的价值在于给出一个通用的“有损文本重写退化”分析范式：任何以 LLM 反复改写中间表示（如视频理解经验、跨会话检索摘要、多模态技能库条目）为机制的管线，都可直接套用这里的归因消融设计（分离压缩误差/条件化/原地重写）与“保留原始证据 + 门控抽象”的架构约束——特别是长时程多模态智能体系统中，情景证据的存储成本远高于文本，何时值得压缩、压缩后如何验证不覆盖证据，是同一问题的更高代价版本。

## 7. 与其他论文的联系

相关论文清单中的条目与本文属同一“LLM 智能体自我进化/递归自我改进”研究脉络，且多篇正面处理本文识别的核心风险：

- **paper:arxiv:2611.14326｜When Should Agents Remember? Falsification-Gated Self-Evolution for LLM Agents**：与本文结论构成最直接的“诊断—处方”配对。本文证明逐交互整合会产生错误记忆并主张“门控式 consolidation"；FGSE 恰好实现了这一处方的一种形式——经验教训作为可证伪假设，经三类探针验证后才写入记忆，把写入时机从“每次交互后”改为“证伪通过后”。可视为对本文 Force-vs-Auto 对照实验的系统化延伸。

- **paper:arxiv:2611.10787｜Trustworthy Recursive Self-Improvement with Statistical Guarantees**：本文的 GEPA 消融显示 prompt 优化只能教 solver 不信任记忆、无法修复记忆本身，即自监控回路不可靠；TRUST 用在线多重假设检验从统计上控制递归自改进中的错误进化率，是对“LLM 无法可靠监控自生成抽象”这一本文指出缺陷的外部控制论式补救，与本文“门控而非信任模型自判”的架构主张互补。

- **paper:arxiv:2611.12109｜SkillDuet: Co-Evolving Models and Skills through Response Feedback**：本文研究的 AWM/skill library 类系统正是“外部技能库演化”路线，且本文 Table 4 显示 AWM 在 ALFWorld/AppWorld 上被自身输入轨迹基线击败（65 vs 92、68 vs 76 等）；SkillDuet 以响应反馈协同参数更新与技能库演化，其“响应反馈”信号提供了本文缺失的技能条目外部验证锚点，可视为对“蒸馏值不值得”这一本文质疑的回应路径。

- **paper:arxiv:2611.10463｜LongCapHarness**：本文 §L.5 证明 ~790K token 长上下文下精度降幅仅 1.6–3.6 分且不显著，即“上下文长度不是瓶颈、整合才是”；LongCapHarness 免数据合成与后训练、直接挂接长上下文推理底层能力即超越基线，其成立前提正是本文实证支持的“原始证据直接进上下文仍然强于压缩后的抽象”——两文共同支持“保留而非压缩”在当前模型能力下的现实可行性。

- **paper:arxiv:2611.14949｜RSI-PDEbench、paper:arxiv:2611.11558｜InfraRSI、paper:arxiv:2610.33845｜AutoTavern**：三者均为递归自我改进智能体的具体实现（PDE 求解、训练基础设施、游戏 AI）。与本文的关联在于：这类系统的迭代改进若依赖持续重写的经验库，就暴露在本文识别的侵蚀机制下；其“显著提升通过率/加速 2.75 倍/超越前十玩家”的结果是否经历或规避了记忆侵蚀，需要本文式的 trajectory-log 基线与 pass@10 覆盖率追踪来检验。本文为其提供了必要的阴性对照方法论。

- **paper:arxiv:2611.07319｜WeightLoop**：本文研究的是无参数更新的上下文记忆自改进，并证明其重写环节有损；WeightLoop 走另一条路——LLM 生成有界参数编辑程序、用实验反馈持续改写模型权重。两者共同框定“递归自改进”谱系的两端（权重空间 vs 文本记忆空间），本文的结论（文本重写复利劣化）为该谱系中“何时应转向权重空间编辑”提供了动机性证据。
