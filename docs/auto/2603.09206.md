## 1. 背景与动机

自进化（self-evolution）范式的核心主张是：模型绕开人工标注，通过自生成任务、自验证反馈的闭环完成后训练。在纯文本 LLM 侧，零数据自进化已被走通（论文引 R-Zero、Absolute Zero 等 proposer–solver 自博弈管线）；但 VLM 引入视觉模态后，任何自进化回路都必须供给图像，而不仅仅是问题与答案。既有的 VLM 自进化工作（VisPlay、Evolmm、V-Zero）把 LLM 的双角色管线平移过来，去掉了人工标签，却仍以预先采集的静态图像集为条件——瓶颈从“标注”转移到“图像数据的采集与过滤”，且进化上限被图像集的分布、质量与多样性锁死。论文的论证路线是：程序化渲染的合成视觉数据在变化量上近乎无限（类比机器人领域的仿真训练：用模拟器暴露现实中代价高昂的稀有事件），因此是比“选图”更根本可扩展的替代方案。

MM-Zero 的自我定位有两点“第一”：第一个 RL 驱动的零数据 VLM 推理自进化框架（不用任何外部图像、问题、人工标签）；第一个突破双角色的多角色自进化（Proposer–Coder–Solver 三角色，同源基座初始化、GRPO 训练）。其激励设计的关键差异在于：图像不再是固定输入，Proposer 被驱动去生成“Goldilocks 任务”——对 Coder 可渲染、对 Solver 可解但在能力边界上。

音视频关联定位（笔记视角）：本文属 VLM 后训练范畴，非音视频核心类，但“用程序化渲染替代采集式素材供给、为理解模型自造训练数据”与音视频侧的仿真训练/合成数据路线同构；其幻觉组评测（检验模型是否绕开视觉走语言先验）与视频幻觉评测（论文引文链含 VideoHallu）直接相通，对做视频理解与多模态大模型后训练的音视频团队有直接的方法迁移价值。

## 2. 方法总览

底层是 RLVR + GRPO：规则验证器给 0/1 奖励，组内归一化优势 Â_i = (r_i − mean)/(std + ε)，裁剪代理目标加 KL 约束（继承 DeepSeekMath 的 GRPO，免价值函数）。在此之上构建三角色闭环：

- **Proposer πP**：生成四元组 (c, q_easy, a_easy, q_hard)。c 为细粒度场景文本描述；q_easy/a_easy 是“一旦 caption 被忠实渲染、答案即显然”的简单问答对，充当渲染保真度探针；q_hard 为需多步推理的难题，无金标签。提示词覆盖图表理解、物体/形状识别、OCR、视觉数学等域。
- **Coder πD**：把 caption 翻译为可执行渲染代码。注意实现口径：摘要泛称 Python/SVG，但正文训练管线与附录提示词均为 SVG-only（CodeGen 提示明确" Do not write Python code"），渲染链路为 SVG → cairosvg → PNG，单段代码 30 s 超时、ProcessPoolExecutor 并行、校验纵横比 ≤100 且最大边 ≤16384，base64 送入 vLLM 供 Solver 消费。
- **Solver πS**：先答 easy question——与 a_easy 的命中率构成 solvability 分，回馈给 Coder 与 Proposer 作奖励；再答 hard question——K 次 rollout 多数投票产生银标签，用于自身 TTRL（test-time RL）训练，同时自洽率 c_i 喂给难度奖励。

训练采用角色串行：每个阶段只更新一个角色（GRPO），另两个角色冻结并经 vLLM 服务端口提供奖励计算（rollout 预算：Coder 4、Solver 5，以压缩奖励计算成本）。每 20 步为每角色存一次 checkpoint，共 60 步 = 3 个迭代（附录表 4 写 TRAIN_STEPS=10/model/iter、NUM_ITER=3，与正文 20 步口径存在出入）。Coder 每轮用最近 Proposer checkpoint 生成约 4,000 条 caption+QA 作训练数据；Solver 训练集由最近 Proposer+Coder 联合产出，只保留成功渲染样本。

数据侧的难度带过滤：Coder 样本保留条件为 4 次 rollout 渲染成功率落在 0.25–0.75（排除“平凡可渲染”与“渲染不动”两端）；Solver 样本保留条件为 easy 题正确率 >0.5 且 hard 题正确率落在 0.27–0.75。即 Goldilocks 难度带同时写在奖励与数据筛选两侧。硬件为 8× RTX 6000/Pro 96GB（附录按 80 GB 配置书写，存在小出入）。

## 3. 关键设计

### 3.1 Proposer 奖励：六分量分层验证

R_p(x)：格式非法记 −1；否则 (1/N)Σ 1_exec(C_i)·(min(R_solv(I_i), 0.5) + R_diff(I_i)) + r_eh + r_ct + r_div，总值域 [−1.0, 1.5]。

1. **执行指示 1_exec**：渲染失败计 0，Proposer 间接被罚提出不可渲染的 caption。
2. **可解性 R_solv** = K 次 easy 题 rollout 中与 a_easy 一致的比例，∈[0,1]，封顶 τ_s=0.5。这顶“防作弊帽”是全文最关键的奖励结构：不封顶时 solvability 上限 1.0 而难度最优值仅 0.5，策略会单边押注易解性。
3. **难度 R_diff** = min(c_i, 1−c_i) ∈[0, 0.5]，c_i 为 hard 题 K 次 rollout 与多数票的一致率；峰值出现在 c_i=0.5（Solver 最大不确定），即能力边界处的题得分最高。
4. **易-硬惩罚 r_eh**：批内平均难度分 < δ_eh=0.15 时罚 λ_eh=0.3。
5. **内容类型多样性 r_ct**：同类型批内占比 f_t > φ=0.5 时按 (f_t−φ)/(1−φ) 线性罚 λ_ct=0.15；类型空间为提示词限定的 7 类。
6. **文本多样性 r_div**：对 caption/easy 题/hard 题三字段分别做基于 BLEU 成对距离的凝聚聚类，簇份额相对均匀份额 u=1/M 的加权偏差（w_c=0.45、w_e=0.20、w_h=0.35）乘以 M 与 λ_div=0.5 后裁剪至 ±λ_div。小簇奖励、大簇惩罚，caption 权重最高（视觉规格是多样性主源头）。

### 3.2 Coder 奖励：执行反馈 + 语义保真

R_D = R_render + R_solv + R_diff − λ_err，λ_err 为渲染失败 −0.1、语法错误 −0.05。R_solv 复用 Proposer 的定义但语义反转：对 Coder 它是“渲染图像忠实于 caption”的代理（easy 题答案能从图中读出 ⇒ 渲染保真），对 Proposer 它是“题目可解性”信号——同一标量在两个角色处承担不同语义，是三角色闭环中最巧的一处。Coder 的 R_diff 同样复用（正文写其值域 [0,1]，与 min(c,1−c) 的 [0,0.5] 定义不一致，按公式理解即可）。

### 3.3 Solver 奖励：TTRL 多数票伪标签

R_S = α·R_acc + (1−α)·R_fmt，α=0.9；R_acc 为 \boxed{} 抽取答案与多数票银标签一致的 0/1 值，R_fmt 强制 <think>…</think> 后接 \boxed{…} 的结构。这是无金标签下的自洽性训练，固有风险是“多数票 ≠ 正确”、可能固化系统性错误——论文未做错误率控制，仅靠数据侧难度带缓解。

### 3.4 提示词与训练配置要点

Proposer 提示要求输出六个 XML 块（content_type/caption/easy_question/easy_answer/hard_question/hard_answer），content_type 限 data_chart/diagram/geometry/timeline/map/table/other 七类；caption 复杂度清单要求至少含七要素中的三项（多数据系列、标注、次级面板、颜色/标记、派生值、非平凡模式、几何构造）；hard 题必须多步推理且不得把所有数值写进题干；答案限定为单数值/单词/短语——这同时为 LLM-as-judge 的等价判定压平了噪声面。CodeGen 提示含硬约束“渲染图必须包含足以答出 easy 题的确切数据”。训练为全参微调（LoRA rank 0）、vision tower 可训练，8B 模型可训练参数约 8.77B；lr 1×10⁻⁶、weight decay 1×10⁻²；GPU 配比 P/CG/S = 3/4/8，Solver 用 TP=2；rollout 温度 P=1.0、CG=0.7、S=1.0（附录表 4 与表 5 在 rollout 数等处亦有少量内部不一致，引用超参时建议以正文为准）。

## 5. 消融要点

在 Qwen3-VL-8B 上对三角色框架特有的两个奖励分量做移除重训（各 3 迭代、同超参）。注意消融表基线行与主表不一致（MMMU 53.5 vs 55.8、均值 50.3 vs 50.7），应为独立重跑，比较只在同表内自洽。

- **去可解性封顶**（min(R_solv, 0.5) → R_solv）：均值 51.2 / 52.3 / 52.3，增速明显慢于完整版；正文口径称较基线仅 +2.3%、完整版 +3.9%（50.2→54.1——该组数字与两张表的基线均对不齐，引用时建议按表内自算：52.3 vs 50.3 ≈ +2.0）。机理明确：不封顶时 solvability 上限 1.0、难度最优 0.5，奖励失衡导致策略单边优化易解性；抽样 10 条 caption 及渲染图可见，模型日益把答案以文本形式直接嵌入生成代码、解显式出现在图中，该捷径行为随迭代加重，封顶后显著缓解——一次干净的“奖励结构决定作弊形态”的演示。
- **去内容类型多样性**：Iter 1 均值 51.7（高于基线 50.3）随后逐轮下滑至 51.3、49.4；抽样发现 caption 与图像收敛到少数易渲染类型（如直方图，渲染成功率高、整体奖励高）——奖励升、基准降的典型 reward hacking/模式坍缩。
- 对照意义：双角色框架（R-Zero、VisPlay）只需难度与多样性奖励即可运转；三角色引入渲染环节后，可解性封顶与类型多样性从可选件变为必需件。

## 6. 贡献与启示

**贡献**：（1）首个零数据 VLM 自进化 RL 框架，训练回路不含任何外部图像、问题或人工标签；（2）三角色管线首次把 VLM 自进化扩展到两角色以上，以中间代码生成桥接抽象推理与视觉落地，多基座一致增益且不饱和；（3）一套可直接复用的角色化奖励配方。

**方法论要点**：“易题即探针”——用一道答案显然的 easy question 作为渲染保真度的可验证代理，比任何图像质量打分器都便宜且可直接当标量奖励；Goldilocks 难度带必须同时落在奖励侧（min(c,1−c)、封顶、易-硬惩罚）与数据过滤侧（成功率/正确率窗口）才能抑制自进化退化；多样性需要类型惩罚、字段级聚类、易-硬惩罚三项独立机制叠加，单一难度奖励不够；奖励上瘾在视觉模态的形态是“把答案烧进图像”，任何“生成器+理解器”共训系统都应预设此项检查。

**对音视频上下游的关联（笔记视角）**：上游，cairosvg+进程池的渲染工厂是轻量级合成数据产线，时序侧可平移为程序化动画/合成视频与程序化音频（第四角色 Coder 的音频版），论文自身未来工作也点名更广工具与 3D 渲染/3D 空间推理素材；下游，VLM 推理增强直接服务视频理解模型的后训练（论文引文链含 Video-R1、VideoHallu 及视频生成-音频综述，作者群与音视频多模态方向高度重叠），幻觉组“是否绕开视觉走语言先验”的评测设定与视频幻觉评测同构。可直接搬走的三件东西：TTRL 多数票伪标签（无标注视频 QA 自训）、难度带过滤（对抗式题目生成）、LLM-judge 等价判定（数值/选项/复述归一）。

**局限**（论文自述 + 笔记补充）：论文承认未能在 38B 级验证 scaling（算力所限），且弱基座受益少（渲染成功率瓶颈）。笔记视角另需保留三个口径：伪标签无错误率控制；全文只与各自基座对比，缺“使用真实图像数据的自进化”强基线对照；SVG 渲染分布与真实图像/视频的 domain gap 未量化。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326）**：同属“自进化回路中先验证再写入”的问题族。MM-Zero 用难度带过滤与易-硬惩罚把不合格样本挡在训练集外；FGSE 把经验教训作为可证伪假设、经三类探针验证后才写入智能体记忆。MM-Zero 消融中去封顶后“答案烧进图”的失效模式，正是 FGSE 所防的未经证实的自我强化在视觉模态的实例。
- **TRUST（arXiv:2611.10787）**：互补关系。MM-Zero 的 Solver 依赖 TTRL 多数票银标签，默认“自洽≈正确”，无错误演化率控制；TRUST 用在线多重假设检验为递归自改进提供统计保证，可直接嫁接到其伪标签环节，控制零数据闭环的漂移风险。
- **SkillDuet（arXiv:2611.12109）**：同构于“模型参数 × 外部可执行产物”协同演化。SkillDuet 以响应反馈协同 LLM 参数更新与技能库演化；MM-Zero 以执行/渲染反馈协同三角色与其代码产物共进化。二者共同证明：外部产物的质量必须进入奖励回路，否则内层策略会在空转中拟合捷径。
- **AutoTavern（arXiv:2610.33845）**：同属“自造环境作为训练基质”模式。AutoTavern 的智能体自建炉石战棋模拟器与 AI，MM-Zero 的 Coder 自造视觉推理素材；差别在前者面向游戏环境的端到端系统构建、后者面向模型权重的 RL 更新，但“环境由智能体自己造、难度随能力爬坡”的机制同源。
