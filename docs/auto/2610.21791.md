# RSIFlow: Adaptive Self-Improvement Workflows with an Evolving Meta-Agent

> Huan Zhang, Mingju Chen, Dongxu Zhou, Can Lv, Sen Cui, Faguo Wu, Shiji Zhou. *arXiv:2610.21791v2 (2026-10-15)*

## 1. 背景与动机

LLM 智能体自改进研究已有三条组件级路线：模型参数优化（STaR 类自生成 rationale 微调）、执行 harness 演化（AFlow 的代码化工作流搜索、Recursive Harness Self-Improvement 的 prompt 级规格精修、DSPy/GEPA/ADAS 等）、可执行工件精修（AlphaEvolve 的执行评估驱动程序演化）。递归自改进（RSI）进一步把优化对象扩展到"生成后续改进的机制本身"。按优化范围可分三层：组件级（单点优化 model 或 harness）、系统级（Co-Harness/HarnessForge 的模型–harness 联合更新、SIA 的反馈驱动更新目标选择）、元级（Hyperagents 的任务/元程序共演化、MetaSkill-Evolve 的双时间尺度技能递归）。

论文的核心论点是：**可编辑范围更大 ≠ 工作流有效命中当前瓶颈**，并形式化两个耦合难题：

1. **瓶颈漂移**。瓶颈类型随任务需求与智能体能力态变化，且成功的更新会重塑瓶颈——开篇的演化链条（执行错误 → 修复后暴露上下文丢失 → 再修复后暴露工具使用偏差）说明同一固定工作流数轮内即失配；预定交替顺序的联合更新（Co-Harness/HarnessForge 类）同样没有回答"编排目标如何适配漂移的瓶颈"。
2. **编排能力滞后**。SIA 的 harness/权重选择依赖冻结的语言模型先验，编排本身不随经验变强；而成功（正向可复用证据）与失败（反例）的编排尝试在既有系统中证据多被丢弃。

由此提出中心问题：RSI 系统如何让自改进工作流适配演化中的瓶颈，同时让"组织这些工作流"的能力随经验提升。二者必须耦合处理——任务层更新重塑改进需求，工作流经验反过来精炼编排机制，形成闭环。

## 2. 方法总览

**形式化**：第 t 轮系统态 X_t=(T_t, M_t)。Task-Agent T_t=(θ_t, H^Task_t, A^Task_t)，即模型参数、外部 harness、任务级交付物（可执行代码/解答）；Meta-Agent M_t=(φ, H^Meta_t)，其中元模型 φ（GPT-5.6 Sol）全程冻结，元演化完全发生在 harness 层。两类 agent 共用同一 harness 抽象 H=(Action, Skill, Planning)：Action 组织执行与信息动作，Skill 存放可复用经验与原则，Planning 做目标分解。

**每轮闭环**（R=5 轮，每轮至多 L=2 次尝试，Algorithm 1）：
1. 冻结轮次父本 P=T_t，在训练批 B_t 上执行，收集轨迹、环境反馈与基线分 J⁻；
2. Meta-Agent 诊断瓶颈假设（绑定轨迹引用）→ 从技能库 K_t 检索适用技能 → 选 a∈{Model, Harness, Artifacts}，且在构造候选前先落一份决策记录（预期行为效应 + 保持约束）；
3. 候选与父本共享同一评估批做配对评估，首个"有效且配对增益 ΔJ>0"的候选被接受为 T_{t+1}，否则 T_{t+1}=T_t（拒绝的编辑不累积）；实现检查失败与评估不增益的尝试全部写入经验 e_t；
4. 从 e_t 蒸馏组件特定技能 S_t 与跨组件原则 P_t，经四操作维护 K_{t+1}，并改写消费这些知识的 Action 接口/检索调用/阶段指令，得 H^Meta_{t+1}。

递归性落在第 4 步：工作流编排的结果精炼编排机制本身。防泄漏边界明确：增益验收只作用于训练批；汇报评测时模型、双 harness、技能库全部冻结，唯一例外是 Artifacts 路线允许至多一次基于许可环境反馈的输出修订。

## 3. 关键设计

### 3.1 三条组件工作流

**Model（默认 SFT replay）**：把执行轨迹转化为参数更新。复用任务执行中已验证成功的调用作训练数据（来源检查、去重、长度过滤；监督目标仅为每个 eligible call 的最终 assistant 响应，环境观测只作上下文），从轮次父本出发一 epoch LoRA。4B 记录配置：lr 2e-6、LoRA rank 8 / α 16、dropout 0.05、max length 16,384、global batch 8 calls、warmup ratio 0.03。早期轮次的成功调用可复用，显著降低探索成本。GRPO 变体：每任务采 2 条完整轨迹（group size 2）、二元任务奖励、clip ε=0.2、KL 系数 0、观测 token 不入损失、零方差组计入 rollout 但不产生梯度（max length 32,768）。候选继承 θ′ 与父本的 harness/artifacts。

**Harness**：localize–refine–generate–validate 流程。局部化对象是"出错的机制"而非文件列表；选定组件集 I⊆{Action, Skill, Planning}，替换算子 H′=H[I←Ĥ_I] 只重写选中组件、保持其余与 θ、A 不变。可改范围含 prompt、上下文组织、记忆检索、规划推理规则、工具编排、内部校验，受接口与权限约束。候选须通过语法/导入/构造/接口/目标行为检查（预算内修复重检），再过同批复评的配对增益验收。

**Artifacts**：Meta 只产出诊断指引 δ_{t,x}，Task-Agent 经既有接口基于 (x, A, τ, f, δ) 自改输出，j≤L 有界修订，首个有效且 ΔJ>0 者胜出。关键的训练/汇报协议区分：训练态修订留在原任务（不迁移到未见任务），其结果仅作元技能演化证据；汇报态在冻结系统上允许至多一次（L_report=1）基于许可环境反馈的修订——许可反馈限于上下文超限、输出长度/格式违规等执行接口信号，评测分数、参考答案、隐藏测试结果一律不进入修订与输出选择。因此该路线的汇报增益反映"推理时反馈引导纠错"，而非修复工件的迁移，这一点论文在附录 C.3 明确澄清。

### 3.2 诊断状态与决策分解

可见错误不唯一决定干预：无效代码可能源于缺失提交检查、语义弱点或局部可修缺陷。诊断状态形式化为 z=(c, ε, ℓ, s, Γ)（任务契约、观测错误、局部化执行阶段、任务态、须保持行为）。决策因子化 π(a,δ|z,K)=π(a|z,K)·π(δ|a,z,K)：通用原则引导跨路由的诊断比较，组件技能引导路由内的可行编辑；无独立拟合的路由分类器，由提示+检索实现。检索打分给出显式实现：r(k,z)=|Q∩B|+3|Q∩B∩F|，错误 token 命中权重为普通命中的 4 倍；返回上下文限 24,000 字符、每桶至多 1 条，全记录按 ID 可取。该分数只检索证据，不估计干预收益。

### 3.3 技能表示与证据驱动维护

技能/原则为六元组 k=(Ω, a, ρ, Γ, r̂, E)：适用条件、干预范围、条件指引、保持要求、预期行为响应、支持/反驳证据。证据单元 u_i=(z_i, a, δ, τ⁻_i, τ⁺_i, y⁻_i, y⁺_i)：父/候选轨迹按共享子目标、工具事件或错误签名对齐（不要求等长），保留全任务成功指标；二元成功下配对增益 ΔJ=(n01−n10)/N。库维护四操作：Add（未覆盖策略建条目）、Supplement（追加结果证据而不改指引）、Revise（linked successor 版本更新条件/步骤/不变量）、Merge（合并重复或被取代条目并保留证据来源），K_{t+1}=(K_t\R_t)∪C⁺_t。集成不是"文本集合变大"：Meta 实际改写消费这些知识的 Action 接口、检索调用与阶段指令，H^Meta_{t+1}=(Action^{t+1}, K_{t+1}, Planning^t)。提示协议中显式写入维护纪律：一次干预只算一次支持事件，复用不算独立重复；不按分数符号机械过滤教训、不从单次非改进推断组件耗尽——这是防止技能库置信膨胀的制度化设计。

## 6. 贡献与启示

**贡献**：(1) 把"动态工作流适配"形式化为 RSI 的核心挑战，指出瓶颈演化与编排能力精炼的耦合性；(2) 提出 RSIFlow：瓶颈感知的三路工作流编排 + 证据驱动的 Meta-Harness 演化（含六元组技能表示与四操作维护）；(3) 六基准 × 双骨干实证，11/12 设置领先，消融同时支撑两机制。

**工程含义**：
- **配对增益验收 + 父本冻结 + 失败入经验**是低成本的防退化机制，可移植到任何"候选生成–评估"回路；n01−n10 的配对分解比均值比较更抗噪。
- **技能库是跨轮资产**：证据链 + linked version + "一次干预一次支持事件"的纪律，针对的是自改进系统常见的库膨胀与置信膨胀两类失效。
- **成本结构不对称**：收益高度依赖强 Meta 骨干（GPT-5.6-Sol +24.39% vs DeepSeek-V4.1-Flash +4.88%），且后期轮次 token 陡增（单轮 160.8M）；论文自述局限包括仅验证 4B/8B Task 骨干、未探索集群规模、经验驱动 Meta-Harness 更新的稳定性未充分研究。
- **Artifacts 路线的汇报态"一次反馈引导修订"**实质是带技能检索的推理时自修复，与训练态完全解耦，可独立于 RSI 框架复用。

**对音视频技术上下游的启示（工程迁移视角）**：媒体工具链任务与本论文三域形态高度同构——FFmpeg/编码器参数与转码流水线 API 的编排属 tool-use 形态（对应 BFCL/ACEBench 类任务），转码/渲染脚本生成与调试属 code+artifacts 形态；媒体任务的执行反馈（codec 报错、封装失败、码率超标）天然可得、无需隐藏标签，恰好满足 Artifacts 路线"许可环境反馈"的闭环假设；SearchQA 域中检索条件与证据组织规则的 harness 演化，可类比视频多跳检索/时序定位管线的 evidence organization 规则演化。瓶颈漂移现象在媒体管线同样典型（先契约/格式错误、后码控语义错误、再局部参数缺陷），"诊断→路由→配对验收"的闭环与其运维逻辑一致。上游依赖方面，强 Meta API 的累计 token 成本（5 轮 252.6M）对媒体业务是显著开销，而 4B/8B Task 骨干的设置反而契合边缘/端侧媒体 agent 的资源约束。

## 7. 与其他论文的联系

以下条目与 RSIFlow 同属 2026 年下半年的递归自改进研究波次，未见互引；关联依据为技术结构上的可比性。

- **RSI-Opt（arXiv:2610.32026）**：结构同构性最强——均为"元智能体跨运行演化策略与工件代码库 + 任务级训练被其编排"的双层递归结构。RSI-Opt 演化优化器 agent 的策略与代码库用于模型训练，RSIFlow 演化的是 Model/Harness/Artifacts 三路工作流与元技能库，二者可互相印证元层收益的来源。
- **SkillDuet（arXiv:2611.12109）**：同样维护外部技能库并让响应反馈驱动库演化；差异在耦合方式——SkillDuet 同时更新 LLM 参数（技能级递归含参数更新），RSIFlow 的元模型参数冻结、仅演 harness。RSIFlow 的 Add/Supplement/Revise/Merge 四操作提供了显式的库维护机制，可与 SkillDuet 的响应反馈粒度对照。
- **TRUST（arXiv:2611.10787）**：直接对应 RSIFlow 自述的稳定性局限——经验驱动更新可引入回归（案例中 R4 配对净增仅 1/600），TRUST 用在线多重假设检验控制错误进化率并提供统计保证，是给 RSIFlow 这类递归闭环补保障的自然路径。
- **InfraRSI（arXiv:2611.11558）**：五阶段验证工作流将开放式指令转化为分布式训练优化（最高 2.75× 加速），与 RSIFlow 的 localize–refine–generate–validate + 配对增益验收在"候选必须通过执行验证才被接受"上同构，领域不同。
- **WeightLoop（arXiv:2611.07319）**：权重空间编程（有界参数编辑程序 + 实验反馈）是 Model 路线的免重训替代方案，可与 RSIFlow 中 GRPO 的高采集成本（≥1,162.2M vs SFT 257.1M tokens）形成互补取舍。
- **LongCapHarness（arXiv:2611.10463）**：证明 harness 单路线免数据合成与后训练即可在 HELMET/RULER 超基线且成本低于其 50%，对应 RSIFlow 消融中固定 Harness 路线 Code 域最强（63.42）的现象，也为其 Meta 开销问题提供低成本参照。
- **TGR-EvoDAG（arXiv:2610.32326）**：DAG 式多智能体代码演化在腾讯生成式推荐场景取得在线 CTR 相对 +0.40%，是"演化式管线编排"在真实生产系统（含大规模媒体/推荐服务）可行的工业证据；RSIFlow 在其上增加了瓶颈诊断路由与元技能库。
- **RSI-PDEbench（arXiv:2611.14949）**：提供 PDE 求解域的 RSI 基准（1001 案例、42 方程模板）；RSIFlow 评测限于代码/工具/搜索问答三域，向科学计算域扩展可直接借用该基准。
