## 1. 背景与动机

LLM 驱动的自动启发式设计（AHD）将 LLM 作为“启发式设计器”嵌入迭代搜索框架——进化搜索（EoH、FunSearch、ReEvo）、邻域搜索、MCTS——已在组合优化、数学与机器学习方向广泛落地。但无论搜索骨架如何，主流范式的目标函数是同一个：在训练实例集合上找**平均性能最优的单条启发式**。作者指出该范式有两个结构性失败模式，并分别给出文献依据：其一，实例分布足够异质时，“在所有实例上都最好”的单条启发式可能根本不存在（Sim, Renau, Hart 2025）；其二，即便训练平均冠军，在分布或规模偏移的未见实例上也常失效（Shi et al. 2025）。

本文表 1 给出直接证据：直接搬用各原论文发表的最优单启发式（带 \* 行）在分布/规模偏移后大幅劣化——FunSearch\* 在 OBP 测试集 n1k/c500 上 gap 高达 0.6169，而手工 Best Fit 仅 0.0124；MEoH\* 在 n1k/c200 上为 0.1037，劣于 Best Fit 的 0.0220。论文并援引算法组合文献（HYDRA, Xu/Hoos/Leyton-Brown 2010）指出“单一算法跨配置失稳”是早已被观察到的现象。

对策来自算法组合思想：用一组互补算法而非单一算法（Gomes & Selman 2001 的 algorithm portfolio）。但实例数 m 通常巨大，逐实例配置启发式不可行，于是作者提出 AHSD（Automated Heuristic Set Design）：自动生成一个小规模互补启发式集合 H（1 < k ≪ m），使每个实例至少被集合中一条启发式优化好。与神经组合优化的跨分布/跨规模泛化路线相比，该路线保留 Python 代码可解释性、无需架构设计与训练算力，代价是把泛化问题显式转化为“集合覆盖 + 实例选择”问题。

从音视频技术视角预置一句：编码器工具级决策（帧级 QP、模式粗剪、tile 比特分配等）面对的“内容类型 × 分辨率 × 码率档”异质性与此同构，单规则在训练语料平均最优而跨内容失效是同一失败模式的 AV 版本（第 6 节展开）。

## 2. 方法总览

**形式化。** 给定任务 T 与 m 个实例 I，集合 H ⊆ D 的逐实例成绩 f\*_{H,i} = min_{h∈H} f_i(h)；向量目标经线性标量化为 F(H) = (1/m)·Σ_i f\*_{H,i}，作者命名为互补性能指数（CPI）。k=1 退化为经典 AHD（平均最优单启发式），k=m 退化为逐实例最优，本文关注非平凡区间 1 < k ≪ m。

**三条定理。** 定理 1（NP-难）：取特例 f_i(h) = dis(h\*_i, h)（到实例 i 理想启发式的距离），目标变为给 m 个点选 k 个中心，与离散聚类问题 DCP 等价，而 DCP 在 k>1 时 NP-难。该归约同时给出几何直觉：AHSD 本质是对“各实例理想启发式”做 k-medians 式聚类，集合成员即簇中心。定理 2（单调 + 超模）：对 U ⊆ V ⊆ D 与 h′ ∉ V，有 F(U) ≥ F(V) 且 F(U) − F(U∪{h′}) ≥ F(V) − F(V∪{h′})，证明是对“最优成员落在哪个子集”的分情况穷举；F 是 f\*_{H,i} 的凸组合，两性质均被保留。含义明确：往集合加成员只会不变好或更好，但边际收益递减——这正是贪心具备近似保证的结构性条件。定理 3（贪心保证）：在固定候选池 P（n > k）内，贪心输出 Hga 满足 F(H1) − F(Hga) ≥ (1 − k/(ek−e))·(F(H1) − F(Ho))，其中 H1 为池内最优单条、Ho 为池内最优集合；k=10 代入系数约 0.59（按公式直接计算）。注意保证是**池内**口径的常数因子近似，全局质量依赖进化循环持续向池内注入高质量候选。

**EoH-S 框架。** 继承 EoH 的“思想描述 + 可执行 Python 代码”双表示。初始化 n=10 条启发式；每代以等概率用两个算子生成 n 个子代；子代在 m 个训练实例上评估并保存**逐实例性能向量**；互补种群管理（CPM）从 2n 候选中选出 n 条进入下一代；达到 Nmax=2000 次评估终止，最终种群即交付的启发式集合（≤10 条）。

**核心表示层变化只有一个**：适应度从标量（平均）变为 m 维逐实例向量。这一变化同时改写了父代配对（CS）、存活选择（CPM），而个体改进压力（LS）仍按平均排名——所有机制都建立在向量适应度之上。

## 3. 关键设计

### 3.1 互补感知搜索（CS）

父代配对在当前种群中取逐实例性能向量 Manhattan 距离最大的一对：(hp1, hp2) = argmax_{ha,hb∈P} Σ_j |f_ij(ha) − f_ij(hb)|。Manhattan 距离在此充当“行为互补性”的代理度量：两条启发式在同一批 m 个实例上的得分差异总和越大，其覆盖倾向越互补。提示词将两条父代（思想+代码）一并给出，并告知 LLM 这两条算法"effective for solving different instance distributions"，要求创造一条**与两者都不同**的新算法；思想描述强制写入 `{{}}` 内、附加 "Do not give additional explanations" 保证解析鲁棒。机理上，这是把多样性生成从随机扰动改为有引导的**行为空间外推**：以两个互补专家为参照，要求第三个落在外部。注意论文存在术语漂移：摘要称 complementary-aware search，贡献列表与附录提示词称 diversity-aware search，指同一算子。

### 3.2 局部搜索（LS）

单父代，按 m 实例平均性能排名做加权随机选择（沿用 EoH 的 rank-based 策略），提示词要求给出改进版本。作用是维持个体质量下限：CS 负责覆盖广度，LS 负责单点深度，防止种群退化为“互补但平庸”。每个子代以 50/50 概率来自 CS 或 LS。

### 3.3 互补种群管理（CPM）

候选池为 2n（父代+子代）。先入池平均性能最优者为 h1；随后迭代选取最大化 ΔCPI 的候选：ΔCPI(hi | Hk) = Σ_j max(f\*_{Hk,ij} − f_ij(hi), 0)，即**只累计能把某些实例的当前最好成绩再压低多少**，已被覆盖得同样好的实例不重复计分（冗余候选 ΔCPI=0），选后更新参考成绩 f\*。这正是定理 3 的贪心实现，因此种群管理自带常数因子保证；论文附录据此解释 EoH-S 收敛曲线稳定，而 EoH/ReEvo 的互补性能在搜索中波动、ReEvo 末段 top-10 反而劣于中段。复杂度上每代仅 O(2n·n·m) 的算术比较，相对 LLM 调用与实例仿真可忽略；且与所有基线共用 Nmax=2000 预算，**不引入额外评估开销**——这是与朴素“多算法组合”实现的关键工程区别：复用任何已有 LLM-AHD 流水线，只要保留逐实例评估明细（而非只存平均分），即可低成本加装 CPM。附录展示的进化产物（OBP 中带动态目标填充率、分层权重与吸引-排斥项的 priority 函数；TSP 中随构造进度调节九项评分权重的 select_next_node）仍是可读 Python，但形式日趋复杂。
