# ImprovEvolve: Basin-Hopping Meets LLM-Guided Evolutionary Search

> Alexey Kravtskiy, Valentin Khrulkov, Ivan Oseledets. *arXiv:2602.10233v2 (2026-02-10)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

AlphaEvolve（Novikov et al., 2025）确立了"MAP-Elites 外循环 + LLM 变异算子"的程序进化范式：进化一个直接输出候选解的单体程序。作者指出该范式在极崎岖优化地形（以装箱问题为代表）上的结构性缺陷——LLM 必须一次性产出端到端优化器并自创非平凡初始化；实践中生成代码只能挂靠 L-BFGS-B 等现成局部例程，而全约束施加后的非凸、非光滑地形恰是这类例程的盲区，最终产物沦为"数学洞察 + 启发式"的混合而非严格求解。

核心观察：当不完美解已存在、或领域专家已构造高质量解时，局部搜索几乎总能再挤出改进。据此 ImprovEvolve 把 LLM 的任务从"进化一个解生成器"改写为"进化三类作用于任意解的算子"——generate_config(seed)（可行初始解）、improve(x)（契约：返回 x′ 的适应度不低于 x）、perturb(x, σ)（强度 σ 的探索）——再由固定的 basin-hopping 骨架（Wales & Doye, 1997）以 T=0 单调接受驱动搜索。

两条对照路线构成动机坐标：其一，Berthold et al. (2026) 把同一批组合几何问题（含六边形装箱）写成非线性规划交给 FICO Xpress/SCIP 商用求解器并取得 SOTA，本文从相反方向切入——将经典全局优化技术内嵌进 LLM 引导进化，声称经轻量人工调整可匹配乃至超越形式化求解器输出；其二，开源 AlphaEvolve 生态（OpenEvolve、ShinkaEvolve、GigaEvo、CodeEvolve 等）多改造外循环或换用 RL，本文自称是首个针对"被进化程序接口本身"做重构的工作。工程底座选用 GigaEvo（Khrulkov et al., 2025）。

【笔记注·音视频关联】本文属 LLM for Math / 进化计算（引擎非核心大类），按其自身领域标准评估；但其基准对象与音视频技术存在明确上下游映射——球码与矢量量化/预编码码本设计同构，自卷积不等式属卷积算子范数的调和分析基础设施，详见第 6 节。

## 2. 方法总览

**Basin-hopping 视角的映射**：perturb(x,σ) 对应随机坐标步（σ 控强度）、improve(x) 对应局部极小化器、T=0 对应 Monotonic Basin-Hopping。LLM 的任务从"设计端到端优化器"收缩为"产出领域专用的 improve/perturb 算子"——搜索严谨性移交经典全局优化，LLM 只负责编码数学结构与启发式。

**验证方案（Algorithm 1）**分两阶段。Stage A：以 K 个不同种子调 generate_config 并立即 improve，取适应度最高者为 x*（对"落在哪个盆地"的初始敏感性做对冲）。Stage B：R 轮 × M 次迭代，σ 在轮内从 σmax 几何衰减至 σmin，x′ = improve(perturb(x*, σ))，单调接受（判据 fitness(x′) ≥ fitness(x*)）；每轮重启 σ 调度，使搜索反复尝试大跳同时持续精修现任解。默认超参 K=10、M=10、σmax=100、σmin=0.001；问题级覆盖（论文表 2）：HEX 11 为 K=10、R=15、M=11、σ 十一档 [1e2, 5e1, 1e1, 5, 1, 5e-1, 1e-1, 5e-2, 1e-2, 5e-3, 1e-3]、单次调用超时 5 min；ACI 2 为 K=3、R=5、M=6、σ 六档 [1e2,…,1e-3]、超时 20 min。

**双层嵌套优化**：外层 MAP-Elites 维护程序种群（GigaEvo：Redis 候选存储、异步 DAG 评估引擎；单岛、fitness 为唯一行为描述子、150 bins——未调参即够用，预实验中加"代码复杂度"第二描述子的多岛无增益只增系统复杂度）；每代按 fitness 比例采样 Nelites=6 精英、均匀取 Nparents=2 交 LLM 生成 Noffspring=10 后代。内层即 Algorithm 1：进化期用较小 R 快速估分，终验用大 R；程序 fitness = 该次运行找到的最优解质量。GigaEvo 基线则是单次调用程序直接产出候选解——这是唯一受控差异。

**LLM 成本分层**：全程用旗舰模型不可承受（引 Georgiev et al., 2025），故 Gemini 3 Pro 生成 N=5 个初始程序并在同一 chat 内迭代修复校验错误，进化交给 Gemini 3 Flash Preview（openrouter，T=1）；作者引 Gideoni et al. (2025) 指出同 prompt 初始程序已天然多样且开箱有竞争力。变异管线沿用 GigaEvo 仓库默认：InsightsStage（LLM 改进提示）+ LineageInsights（父子 fitness 反馈）+ 聚合统计，系统提示不改。

**有效性纪律与成本**：进化期 improve 返回非法配置即整程序废弃；终验期放宽（长跑中可靠优化器也会在一次倒霉扰动后发散）。墙钟由 improve 调用主导：HEX（3n 维约束问题）单跑约 10 h（单机）；ACI 2 每次 improve 是上万参数步函数的高维 L-BFGS，单跑约 40 h。

## 3. 关键设计

**3.1 接口分解的三重收益**： 认知负载切分，初始化/局部改进/探索各自成为可注入领域知识的独立槽位； 模块化使程序对人可编辑、对 LLM 可解释——后文 +E 的外科式微调之所以可行，正因编辑点局部化； 最关键的是 resume-from-input：进化出的类可作用于任意起点解，包括超出 LLM 即时理解能力的专家构造。ACI 2 的 +E 从 AlphaEvolve 的 5 万步极值函数热启动、球码验证直接以 Cohn 目录最优配置替换 Stage A 的 K 个种子，都是该接口的直接兑现。

**3.2 σ 调度与接受准则**：几何衰减默认覆盖 5 个数量级（100→0.001），早大晚小。作者明确论证放弃 T>0：理论上模拟退火更优，实践中高温阻碍精修、低温几乎不增加逃逸概率，且会丢弃"通往全局最优路径上的次优构型"（HEX 17 的 L=4.6188 排布即反例）；当 improve 昂贵（ACI 2）时找回代价过高，故取 T=0。

**3.3 HEX 11 进化算子解剖**（产物 Program ID e98264be…，进化 fitness −3.92467，第 13 代）：
- generate_config：预生成六角格中心（|q+r|≤5），按"到原点距离 + U(0,0.5) 扰动"排序取前 n 个，角度取 U(0,π/3)——隐式利用正六边形 π/3 旋转对称。
- improve：JAX value_and_grad + scipy L-BFGS-B，变量为展平的 [centers, angles, L]；containment 用顶点在容器法向投影的 relu² 惩罚，overlap 用 SAT 分离轴间隙的 relu(margin−gap)² 成对惩罚；关键技巧是 graduated hardening——四级惩罚 (w_cont, w_ov, margin) 从 (1e3,1e2,1e-3) 逐级加硬至 (1e9,1e8,1e-7)，先松后紧把构型逼入可行域深处。
- perturb：intensity>2.0 触发"结构交换"（随机交换两六边形的位置与角度），随后中心加 N(0, 0.05σ)、角度加 N(0, 0.02σ) 并 mod π/3——大强度走离散结构跳变、小强度走连续微扰的双模设计。

**3.4 ACI 2 算子**（Program ID b8dadcb7…，fitness 0.9512，第 11 代）：以 f=w² 参数化保证非负，自卷积走 FFT；L∞ 用稳定化 LogSumExp(β) 代理（β 越大越逼近真 max）；improve 为多网格 jaxopt.LBFGS，分辨率/β 联合调度 4096/800 → 16384/5000 → 32768/50000；perturb 为镜像翻转 + intensity·0.1 均匀噪声后 clip≥0；generate_config 为均匀噪声 + 32 随机尖峰 + 高斯平滑。

**3.5 球码算子**（进化于 (N,d)=(600,11)，附录 D.1 载明提议模型为 Gemini 3.5 Flash）：improve = 对 max 内积的 LogSumExp 延拓（α: 100→25600 五档）+ L-BFGS-B（maxiter 500、gtol 1e-9）；perturb = 活跃集排斥（对距当前最大内积 0.005(1+σ) 边际内的点对施加排斥 + 切向噪声）+ Riesz s-energy 松弛（s=d+20(1−σ)）+ intensity>0.3 时随机子集 SO(d) 旋转（QR 造反对称阵后 expm）。ImprovEvolve+E（Gemini 3.1 Pro 以"最小编辑"提示产出）改动集中三处：上三角化 LSE/s-energy（消除成对重复计数与 −inf 掩码的数值敏感）、α 延拓扩为 10→40960 七档并加内层预算（maxiter 500→1500、gtol 1e-9→1e-10）、扰动改为并发活跃集累积 + 测地更新 x·cosθ+v̂·sinθ + 半球扭转（保局部簇、破全局对称）。ImprovEvolve++（独立进化的通用改进器）：LSE 建立在测地距离 arccos⟨xi,xj⟩ 上，α=geomspace(20, 1.5e5) 八档、切空间投影梯度、callback 全程追踪历史最优 μ；perturb 为半球扭转 + softmax 加权并发测地排斥（权重 exp((10+50σ)(ips−max))）+ destroy-and-greedy-reinsert（摧毁最差 max(1, ⌊0.15n·σ⌋) 个节点、从 max(200, 5n) 候点贪心重插）+ Riesz 抛光。

**3.6 人机分工的 +E 编辑**：HEX——L-BFGS-B→SLSQP（逐步解二次子问题、更契合约束几何但数值稳定性差）、首级惩罚权重软化（1e3/1e2 → 1e2/10）、变量界放宽 + maxiter 800→10000 / ftol 1e-10→1e-11。ACI 2——多网格上限从 32768 改为自输入分辨率渐进至 160 万步（否则无法精修 5 万步输入）、删除 1e-10 下限 clip（否则抹掉输入函数的小台阶）、提高 L-BFGS 迭代上限。三处编辑均不动 LLM 产出的算法骨架，是"模块化使专家编辑可行"的实证。

## 4. 实验结果

**口径**：HEX n——外接半径 1 的单位正六边形装入平顶正六边形容器，最小化边长 L（=容器外接半径），适应度 −L，任何包含/重叠违规抛异常弃置，进化只在 n=11。ACI 2——最大化 C(f)=‖f∗f‖₂²/(‖f∗f‖₁‖f∗f‖∞)，已知 0.88922 ≤ C₂ ≤ 1，输出分辨率 N≥1024。球码——最小化 μ(X)=max⟨xi,xj⟩，适应度 −μ(X)，基准为 Cohn 目录 90 个配置（d∈[8,16]、N∈[26,1021]）。

## 5. 消融要点

**Stage 消融**（HEX 11，σ 自 100 几何衰减至 0.001，论文表 5）：

| 变体 | Best L | K | R |
|---|---|---|---|
| A only | 3.9282 | 1000 | 0 |
| B only | 3.9269 | 1 | 100 |
| A+B | **3.9245** | 100 | 5 |
| A+B+LLM 编辑 | 3.9270 | 100 | 100 |
| Lat.+B² | 3.9310 | 100 | 100 |

² 仅采用 Gemini 3 Pro 编辑版程序的 generate_config。结论：Stage A 能产出最优解原型但无法精修；Stage B 能抛光单一初始化但缺多样起点则命中全局最优概率低；二者缺一不可。有趣的是 A only（K=1000）优于 B only（K=1），侧面说明盆地选择比抛光更深地决定上限。

**LLM 能否替代人工调参**：以"最小编辑"提示（只许改常数/参数/实参，禁止重构）让 Gemini 3 Pro 复刻 +E。对 GigaEvo 基线（batch 96 vmap + Adam + Langevin 噪声 + 二次权重爬坡的端到端 JAX 程序），LLM 把 Langevin 温度从 1e-3·exp(−4t) 提到 2e-3·exp(−3.5t)（方向错误——该降反升）、batch 96→256，结果六边形重叠。对 ImprovEvolve 程序，编辑包括软化惩罚权重、容器格从 point-topped 改 flat-topped；后者在 n=13/21/31 的稠密排布确有帮助，却破坏了 Stage A 依赖的随机探索，完全编辑版与混合版均劣于未编辑版（3.9270 vs 3.9245；仅换 generate_config 的 Lat.+B 更差至 3.9310）。结论：先进 LLM 也会给出"貌似合理、实证有害"的编辑；单体程序受损更重、模块化缓解；进化回灌验证结果可部分补偿，但模型对优化超参缺乏可靠直觉——作者判断带经验评估的 agentic 回路（在多配置下实测候选编辑）更可行。

**球码预算与协议消融**：fitness 关于算力单调——规范单链评估器（R=1、M=10、单调接受）在 3540 s 墙钟下复现面板 fitness 0.4645%，600 s 降至 0.4125%，即"每配置预算是买改进的第一杠杆"。固定墙钟扫 basin-hopping 旋钮：每轮更少 noising 步恒优（同墙钟容纳更多独立跳盆）、fresh-restart 周期无关紧要，得 P*（无界重启、M=10、σ: 1→1e-6、每 5 轮重启、T=0）：同为 3540 s 时 0.4797% vs 0.4645%，纯协议增益 +3.3%（相对）。

## 6. 贡献与启示

**贡献**： 接口级创新——首个在 LLM 引导进化中重构被进化程序接口的工作：三算子类 + 固定 basin-hopping 骨架，把搜索严谨性从 LLM 移交经典全局优化； 实证——HEX 11/12/15/16 新 SOTA（+E 再添 14/17/23 及 25–30 首报）、ACI 2 下界 0.96102→0.96258、球码 53/90 配置改进（均值 0.1765%、单点最高 2.4%）； 统计严谨性——3×100 代独立复跑 + Welch 检验（p=0.0086 / 0.0493），在 LLM 进化文献中少见； 人机分工实证——LLM 产算法骨架 + 专家外科微调优于任一单独，LLM 独立调参被证伪。

**启示**： 接口即归纳偏置——improve/perturb 契约把单调性与结构保持变成硬约束，换来零再进化的跨规模迁移（n=11 程序覆盖 n≤30，(600,11) 改进器覆盖 90 配置）；resume-from-input 把 LLM 进化与专家构造的关系从竞争改为可叠加——进化产物是可作用在任何现有最优解上的"改进器"，T=0 保证不劣于输入，这对必须向后兼容的工程标准（码本、编解码工具）尤其可贵； 稀疏奖励警示——复现 592 球 11D 吻合数构造需约 20 轮 Gemini 3 Pro 对话外加原文 LaTeX 源，中间版本合法球不足 100 个，此类复杂构造不可能靠进化独立涌现，分解与人工介入必要； 局限（作者自述）——仅三类数学优化问题，除多跑研究外头条 SOTA 均为单跑最优，受进化与 basin-hopping 随机性影响。

【音视频上下游】（引擎注，非论文内容）
- 下游·码本设计：球码 μ(X) 最小化与 VQ/RVQ 码本、波束成形与预编码码本、HOA 方向集设计同构；"目录热启动 + 单调接受"可直接移植为标准码本的增量精修流水线（输入现有码本，输出有保证不劣化的改进版）。
- 下游·卷积域优化：ACI 2 的 ‖f∗f‖ 范数权衡属卷积算子调和分析基础，更紧的 C₂ 收紧卷积类处理（滤波、混响建模）能量-范数权衡的可解边界；其多网格 + LogSumExp L∞ 代理 + graduated β 的数值配方可迁移至可微 DSP 的卷积目标优化。
- 下游·管线自动化：improve/perturb 分解适用于音视频工程中"已有可运行流水线、只需单调改进"的场景（码控、模式决策、调度）；GigaEvo 单体程序跨 n 失败的教训直接对应"让 LLM 重写整条流水线泛化差"的风险。
- 上游·推理基础设施：此类进化循环吞吐受 LLM serving 成本支配，本文两层模型（Pro 初始化/Flash 进化）与 KV 缓存类系统算法的程序化发现（见下节 AutoAssumption）构成"程序搜索反哺推理基础设施"的闭环。

## 7. 与其他论文的联系

- **FrugalEvo（arxiv:2610.03675）**：同为 LLM 程序进化 + 装箱类基准（圆形装箱 SOTA）；其"强 LLM 出策略、廉价 LLM 写码"的成本分层与本文"Gemini 3 Pro 初始化 / Flash 进化"两层结构同源同目的。成本分层（模型维度）与接口分解（程序维度）是两条正交轴，可叠加。
- **Hill Sampling（arxiv:2609.25510）**：以"冻结 LLM 反复采样、以当前最优为条件"替代进化。本文 Stage A 多种子生成 + 择优在结构上就是采样-后选择，但 Stage B 的 σ 调度结构化扰动（结构交换、测地更新、destroy-reinsert）超出自回归重采样的表达能力；两者对"分解后算子是否仍需进化"提供互补证据。
- **ε-MemEvo（arxiv:2608.12522）**：显式跨任务策略记忆迁移（8 基准平均 +8.7%）vs 本文的隐式接口迁移（n=11 程序零再进化覆盖 n≤30；(600,11) 改进器覆盖 90 配置）——前者迁移"策略知识"，后者靠接口契约获得行为泛化，机制互补。
- **SwarmEvolve（arxiv:2611.08483）**：改造搜索架构（潜在空间智能体蜂群 + KV 缓存共享），与本文改造程序接口属于不同轴；其低成本多智能体底座可承载 improve/perturb 接口，且 KV 共享直接命中此类进化循环的 serving 成本瓶颈。
- **AutoAssumption（arxiv:2611.14844）**：同样重构"LLM 搜索的对象"（Lean 假设图 vs 优化算子），其产出的 KV 缓存驱逐与剪枝算法正落在音视频流式推理的上游基础设施；两文共同支持"接口/假设层创新比外循环改造更根本"的判断。
- **Agentic Algorithm Design（arxiv:2610.35595）**：让 LLM 提出黑盒优化算法并以 Lean 机器检验期望运行时间界、全程无需经验比较；ImprovEvolve 走相反路线——不证算法性质，而把搜索严谨性外包给 basin-hopping 骨架、以经验验证筛算子。"证明算子"与"脚手架化算子"是 LLM 生成优化代码可信化的两条对立路线。
- **MLEvolve（arxiv:2606.06473）**：LLM 自进化多智能体 + 渐进 MCGS + 回顾记忆做 ML 算法发现，同属程序进化范式；本文的内层经典搜索脚手架可用于稳定其在外部目标噪声大、地形崎岖（如研究级 ML 训练管线）场景下的适应度信号。
- **Improving VLMs on Scientific Chart Analysis via Autonomous Evolution（arxiv:2610.35077）**：将 AlphaEvolve 式进化用于感知/推理程序（图表问答精确匹配 16.6%→41.3%，快 3.8 倍），证明该范式可移植到多模态流水线；ImprovEvolve 的算子分解是其向视频分析等长流水线扩展时的自然改造——对候选输出或中间表示定义 improve/perturb 而非进化整条推理程序。
