# The RSI Tax: When Recursive Self-Improvement Is Not Worth the Cost

> Yitong Zhang, Ang Li, Yisen Wang. *arXiv:2611.13524v1 (2026-11-10)*

## 1. 背景与动机

递归自我改进（RSI）指智能体利用自身任务经验更新其在后续任务中携带的持久状态，本文限定在**骨干模型权重固定**的前提下，按更新对象分两类：一是演化记忆/技能库（ReasoningBank、Dynamic Cheatsheet、EvoSkill、SkillOpt），二是演化 harness——即提示、工具接口与控制代码（GEPA、Meta-Harness、RRSI、HarnessPro）。

动机来自一个被普遍忽视的会计缺口：**改进过程本身有成本，且该成本在改进价值显现之前就已支付**。在任务流上，每次更新都发生在其收益未知时；任务执行的 token 需求本身又随任务、运行、模型大幅波动。既有评测协议对这一点处理不一：ReasoningBank 在相邻任务间更新记忆；EvoSkill/RRSI 在固定任务集合上优化后在 held-out 上评测；EvoTest 只看同任务重复episode；ServeLearnBench 虽把学习调用计入资源，但未做成本分解。HarnessPro 与 RRSI 虽在选择目标中部分计入执行成本，却没有联合优化“获取更新的成本”与“服务持续任务流的期望成本”。

论文提出 **RSI Tax** 概念：自改进过程的 token 成本，包括最终未被采纳的更新尝试。端到端成本 = 任务执行 token + RSI Tax，二者耦合——更新可能缩短后续执行，也可能因注入上下文或诱导更长轨迹而增加成本。核心问题是：在这套完整口径下，主流 RSI 方法的精度增益是否还撑得起其开销。作者的隐性赌注是：一个不做搜索、不做候选验证的有界笔记基线（SRN）可能已经足够，从而构成对“昂贵更新流程必要性”的反例。

## 2. 方法总览

**流式评测协议。** 对有序任务 x₁,…,x_T，先记录任务结果再将其反馈用于更新：执行产生轨迹 τₜ ∼ π_θ(·|xₜ, sₜ) 与二元验证结果 yₜ = V(xₜ, τₜ)；更新只能读取已完成历史 Hₜ 中的公开指令、可见轨迹与标量结果，禁止访问未来任务、参考解与隐藏测试。对完成任务的重跑（用于验证候选）计入 RSI Tax，且不替换该任务的原判定。这一“先评分、后反馈”的边界是防止信息泄漏的关键设计。

**任务流。** 仓库流取 SWE-Chain-Evo 的 7 条 15 任务链（Click、CoreDNS、NATS、Fiber、Loki、Istio、Prometheus），共 105 个位置；学习状态链内保持、链间重置，每任务从基准规定快照起步，不移植此前补丁。终端流为 Terminal-Bench 2.1 全部 89 个任务、固定顺序、状态全程保持。骨干为 DeepSeek V4.1 Flash 与 GPT-6 Luna（high reasoning，名义 262,144 上下文、65,536 单次输出上限、≤100 轮、无累计任务级 token 上限），共 6×2×(105+89)=2,328 个评分方法-任务对，各方法共享任务顺序、初始 KIRA 执行策略与名义执行限制。

**方法与更新节奏。** 对比六法：Static（无跨任务状态）、ReasoningBank（逐任务记忆工作流，去掉其独立的记忆感知 test-time scaling 分量）、Meta-Harness、EvoSkill、RRSI、SRN。除 ReasoningBank 外，周期方法每 4 个完成任务获得一次更新机会（每链 3 次、终端流 22 次），窗口内状态冻结；支持集为最近 2 个任务（仅 DeepSeek/SWE 设定）或最近 4 个。

**成本口径。** N_task（任务执行调用，含读取已学状态）、N_RSI（自改进调用，含嵌入 token）、税率 ρ_RSI=N_RSI/N_task、N_total=N_task+N_RSI。跨方法比较用净 token 溢价 ΔN。在此基础上做 Verify/Explore/Write/Other 四分量的后续使用归属（N_{p,d} 与未使用份额 r_no-use）。

## 3. 关键设计

**3.1 计账边界。** 任务执行调用与自改进调用集合不相交；验证期对支持任务的重跑归 RSI Tax；执行期读取已学状态（检索注入上下文）归 N_task；缓存输入计入，provider 已计入的 reasoning token 不重复计。这套口径直接决定了“省略 RSI Tax 会反转成本排序”这一核心发现的成立——例如仅看执行 token，Meta-Harness 在某些流上反而比 SRN 便宜。

**3.2 三分量分解与操作映射。** Verify = 在位/候选验证、smoke test、技能 frontier 重评（原任务执行期内的验证留在 N_task）；Explore = 额外 rollout、提案生成、轨迹判读、ReasoningBank 的嵌入调用；Write = 持久状态的物化与修订（harness 代码、技能、笔记、记忆）。映射逐方法固定且每项只计一次：Meta-Harness 的轨迹分析与候选搜索归 Explore、候选代码编辑归 Write；SRN 的联合笔记分析与修订整体归 Write；EvoSkill 将技能提案与物化分离。另有 Other 残差（如 Meta-Harness 提案会话中 26.24M）。

**3.3 后续使用归属。** 每个成本项按其关联的状态/工件标注 d(c)∈{0,1}，归属不限于最终写入调用——验证与探索成本跟随其记录关联的候选。“使用”定义为在下次重置或流结束前，该状态被后续任务实际采用：运行更新后的 harness、执行中调用技能、笔记/检索记忆进入上下文。标签只记录使用，不度量对精度的效果——作者明确承认这是描述性归属而非因果结论。

**3.4 SRN 基线。** 每 4 任务窗口，用官方标量结果挑出窗口内失败任务 Fₜ；Fₜ 为空则保持笔记 m 不变，否则 m⁺ = Limit₂₀₄₈(G_θ(m, Excerpt(Fₜ)))。生成器输入为旧笔记、公开指令、失败轨迹固定头尾摘录（前 20,000 + 后 10,000 字符）与标量结果；有效非空响应直接采纳，无效则保留旧笔记。笔记上限 2,048 token，超限由分词器截断。无额外采样、无候选验证、无检索。终端提示词明确约束：不臆测隐藏测试、区分观察事实与假设、标量零分不构成根因证据、允许空更新。SRN 的总成本包含笔记构建与带笔记执行的完整执行成本，未做任何成本豁免。

**3.5 流式适配的透明度（外推关键条件）。** EvoSkill 原算法用固定验证集，此处改为滚动支持集上重打分 frontier，成本全额计入；原提案器可查看 ground-truth 答案，此处收紧为仅公开信息。Meta-Harness 采用单轮原生搜索 + 严格改进选择器（验证精度必须严格更高，并列保留在位），窄于原文的种群搜索——“饱和选择器”下的决策不变评估病理部分源于此实现。这些适配使结论严格对应“本文的流式实现”，而非各方法原版。

**口径反转实例（论文最有说服力的一行）：** DeepSeek 终端流上，Meta-Harness 任务执行 token（184.13M）其实少于 SRN（214.37M），但其 578.45M 的 RSI Tax 使总数达 762.57M（SRN 为 214.65M），而精度反而略低（77.5% vs 78.7%）。ReasoningBank 税负小（税率 4.53–7.39%）但精度不稳定超过 Static。三个重型方法的税率（100·N_RSI/N_task）：Meta-Harness 109.06–329.15%、EvoSkill 144.35–393.10%、RRSI 125.79–346.68%——**在全部四个设定中其自改进开销超过甚至数倍于执行整个任务流的开销**；SRN 税率 0.04–0.36%。

**税负分解（四设定聚合）：** Verify 占 Meta-Harness 税负的 74.83%、EvoSkill 的 78.13%、RRSI 的 93.58%。EvoSkill 另花 455.29M 于额外 rollout 与提案（Explore），技能物化仅 4.59M——搜索与验证是数量级大头，产物写作几乎免费。ReasoningBank 的 48.98M 税负几乎对半分为判读/嵌入（24.61M）与记忆抽取（24.37M）。DeepSeek 终端流上 EvoSkill 仅刷新旧 frontier 就花 497.45M，超过其执行 89 个任务的 182.26M。记录的输入 token 约占 Meta-Harness 与 EvoSkill 税负的 98.1%，指向对不断增长的执行上下文的重复处理。

**未使用份额（r_no-use）：** Meta-Harness 52.78%、ReasoningBank 63.57%、EvoSkill 37.91%、RRSI 23.70%；SRN 为 0（全部更新成本对应的笔记均供入后续执行）。构成差异显著：Meta-Harness 的未使用部分为 564.85M Verify + 217.60M Explore + 69.22M Write；ReasoningBank 则是 15.51M 判读/嵌入 + 15.63M 记忆抽取——同为“未使用”，病理来源完全不同。

## 5. 消融要点

论文没有传统消融（作者明言 SRN 未隔离各设计选择的独立作用），替代性分析有三层：

**其一，事件级诊断**（单位不可加、不可由阶段总量推断普遍性）：(a) *无提案搜索*——DeepSeek 终端流 EvoSkill 第 68 任务后一轮：旧 frontier 重评（3 程序×4 支持任务）44.88M + 追加 2 条采样 13.28M（均成功，无失败样本可触发提案器），整轮 58.16M token 零新提案，部署保持 iter-skill-7；(b) *决策不变评估*——GPT-6 Luna Meta-Harness 第 72 任务后：在位者支持集精度 100%，严格改进规则下任何候选分数都不可能被接受，仍花 69,715 smoke + 534,126 进一步验证 = 603,841 token（该更新全轮 4,002,438）；(c) *未检索记忆*——DeepSeek 终端流任务 55（caffe-cifar-10）：判读 117,631 + 抽取 124,108 = 241,739 token 生成 1 束 3 条记忆，其后 34 个任务零检索。将未检索谓词施于全部记忆记录，ReasoningBank 的 RSI token 中 53.1–61.5% 满足该谓词（终端流为 5.16/8.61M 与 3.62/5.88M）。

**其二，口径敏感性。** 池化 token 总量仅描述性（跨模型 tokenizer 无共同物理计算单位），均值比较一律在设定内成比值后再平均；Task+RSI 与 Total 受显示舍入影响（RRSI 任务执行 ≈956.56M 系 2,727.06−1,770.50 差分所得）。

**其三，归属的描述性边界。** “有后续使用”不证明精度收益，“未使用”不证明可删而不改变后续更新或任务结果；需要受控干预才能度量削减各分量的效果。此外流式适配引入实现依赖：EvoSkill 滚动刷新成本、Meta-Harness 严格选择器的饱和病理，都是本文实现而非原算法固有；评测仅覆盖 2 模型、7 链、1 种终端排序、无重复运行；token 量≠货币成本（输入/输出/缓存定价不同）。

## 6. 贡献与启示

三点贡献：(1) 首个把更新开销全额并入端到端 token 口径、在公共任务流上做成本-精度联合评测的工作；(2) SRN 作为反例基线，证明该实验观察到的性能水平不需要昂贵的候选搜索与验证流程；(3) Verify/Explore/Write 分解 + 后续使用归属，把“RSI 贵”细化为“贵在哪、浪费在哪”。

对更新策略设计的直接含义：目标函数应联合优化当次更新成本、期望任务执行成本与剩余流上的后续更新成本——即决定**何时更新、在提案与验证上花多少、保留哪些工件**。验证主导（74.8–93.6%）意味着支持任务选择与 frontier 维护是第一降本目标（自适应验证任务选择是现成路径）；输入占 98.1% 指向上下文重复处理的结构性浪费；未使用份额 23.7–63.6% 则要求技能/记忆的选择性构造。作者定位该工作与 RRSI/HarnessPro 的执行成本目标是互补关系，而非替代。

**与音视频技术方向的上下游关联（引擎跨域评注，非论文内容）：** 本论文属 LLM 智能体方法论，不涉及音视频数据，但其评测对象（Loki/Prometheus 等基础设施仓库的持续维护链、终端任务流）与音视频软件工程智能体化的作业形态同构——编解码器仓库、FFmpeg 工具链、流媒体服务的持续修复任务流可直接套用本文的流式协议与税率口径。下游看，多模态/音视频智能体（视频理解管线、AIGC 工具链）正引入记忆-技能-harness 式 RSI；本文揭示的 Verify 主导病理在音视频场景预计更严重，因为该领域的候选验证往往意味着真实执行转码/解码/管线运行，token 之外还有真实算力开销。工程上建议把 ρ_RSI 类指标纳入智能体服务的成本 SLO，并优先审计“未被后续任务复用的技能/记忆”的构造开销。

## 7. 与其他论文的联系

- **Flex-RSI（arXiv:2611.08946）**：同为 RSI 的预算约束评测路线。Flex-RSI 在固定预算下评测智能体递归修订 harness 的能力，本文把“预算”口径细化为任务执行与 RSI Tax 的显式分账，两者在协议层面互补，本文进一步给出预算去向（Verify 主导）的解释。
- **SimplEvo（arXiv:2611.11509）**：与 ReasoningBank/SRN 同属免权重更新的文本记忆自改进（EBench 46.7%→81.7%）。本文对 ReasoningBank 测得 63.57% 的税负与未使用状态关联、未检索谓词覆盖 53.1–61.5% 的税负，直接提示此类记忆演化方法需在同一端到端口径下复核其增益是否覆盖构造成本。
- **TRUST（arXiv:2611.10787）**：正交的控制轴。TRUST 用在线多重假设检验控制 RSI 的错误进化率（质量约束），本文控制的是 token 成本（经济约束）；二者可叠加为更新策略的双约束，分别对应作者呼吁的联合优化目标中的“能力持续增长”与“成本受控”两侧。
- **LongCapHarness（arXiv:2611.10463）**：harness 演化路线中显式做成本控制（成本低于基线 50% 且免数据合成与后训练）的实例，正是本文所呼吁的“成本受限 harness 选择”方向的证据；与 Meta-Harness/RRSI 在本文中的高税负形成对照。
- **InfraRSI（arXiv:2611.11558）与 RSI-PDEbench（arXiv:2611.14949）**：二者报告 RSI 的正面收益（训练加速最高 2.75 倍；PDE 求解通过率提升且调用成本下降），与本文的否定性结论构成对话——分歧点很可能在任务复用密度与验证开销结构；本文的贡献恰是提供了统一的端到端记账框架，使这类正面主张可以在“增益是否覆盖改进过程开销”的同一口径下被复核。
