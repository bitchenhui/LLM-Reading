# ClawLoop: Self-Improving Agents via Harness-Native Training Loop

## 1. 背景与动机

LLM 代理的部署形态正经历从聊天机器人、RAG、工具调用代理向 harness 增强通用代理（OpenClaw、OpenAI Codex、Claude Code 等）的迁移。与通过预定义工具 schema 交互的 tool-use 代理不同，harness 代理在审计过的可扩展权限下直接操作真实文件系统与 shell。论文将 harness 界定为沙箱执行环境：Docker 容器 + shell + 文件系统 + 包管理器 + 网络访问，外加工作区供给与轨迹记录 API。权限扩展使代理可承接远超工具调用框架的复杂任务，但把后训练的数据瓶颈推到极致：harness 内的现实任务是文件操作、shell 命令、技能执行与多步推理的开放式组合，现有任务合成管线（多为固定工具域内构造）与人工标注均无法覆盖。

论文指出现有 harness 代理后训练管线的两个结构性缺陷：（1）教师依赖——需外部更强模型（如 MiniMax-M2.5、GLM-5.1）充当任务合成器或轨迹收集器，天然引入能力天花板；（2）一次性——任务基于人类先验合成一次、代理训练一次、评测结果只汇报给人类研究者而不回流驱动改进。作者梳理的先前工作中，ClawGym 是唯一在现代 harness 环境内同时做任务合成与训练的工作，但未跳出这两点。

核心观察是：harness 环境本身已具备闭环自改进的全部要素——LLM 可实例化任意工作区、执行代理轨迹、以代码与规则双路校验结果；缺的不是基础设施，而是“识别自身弱点→生成针对性练习→迭代改进”的机制。据此提出 ClawLoop：无外部教师、先验依赖极小、任务合成—训练—自诊断三位一体的闭环框架。

形式化上，任务定义为五元组 τ = ⟨p, s₀, A, F, Vτ⟩：自然语言指令 p（代理的初始 user prompt）、初始工作区状态 s₀（文件/环境变量/已装工具）、动作空间 A（shell 命令、文件编辑、工具调用）、确定性转移函数 F、验证器 Vτ: S→{0,1}。相较 tool-use 任务文献，状态空间与动作空间均因 harness 显著扩张。轨迹 ξ = (s₀, a₁, s₁, …, a_T, s_T)。工程上强调：训练 rollout 与评测使用同一 harness 底座，保证训练—推理分布一致。

## 2. 方法总览

ClawLoop 从部署于 harness 沙箱的预训练代理 π₀ 出发，执行 K 轮迭代（主实验 K=3）。第 k 轮基于 π_{k−1} 依次经过三阶段：

1. **任务合成与选择**：生成任务池 Pk，切分为训练集 Tk 与留出评测集 Ek = Pk\Tk；对 Tk 收集 rollout 轨迹。
2. **训练**：在 Tk 轨迹上以 SFT（成功轨迹）和/或 RL（GRPO）更新 π_{k−1}→π_k。
3. **诊断与反馈**：π_k 在 Ek 上 rollout，失败轨迹由代理自身总结、聚合成循环失败模式，形成诊断报告反馈给下一轮任务合成。

整个环路无任何外部教师：同一个 27B 模型既是任务合成器、轨迹执行者，也是诊断器。环路级配置：每轮合成 1,024 个候选任务，每任务 N=8 次 rollout，准入带 [Nl, Nh] = [1, 5]。

一个关键的成本设计是 rollout 三重复用：同一批 N=8 rollout 同时充当 agent-based 验证的准入信号、SFT 成功轨迹来源、GRPO 组内基线，这是环路算力可控的前提。按附录实测（32×H800），单轮迭代总成本 74.23 小时墙钟 / 2,375 GPU 时，其中验证 rollout 30.76h / 984 GPU 时（约 41%，超过 SFT 8.03h/257 与 GRPO 18.52h/593 之和），任务合成 15.98h/511，诊断 rollout 仅 0.94h/30（Ek 为小留出集）。该成本结构刻画了 harness 原生训练的本质：每个奖励信号都要求真实环境执行，而非静态输出打分。

## 3. 关键设计

**3.1 双路由种子任务合成**

能力驱动合成以能力目录而非工具集组织。每个条目将一种工作流模式（对账、跨源审计、多文档合并、领域计算）绑定到目标能力，分分析轨（交付结构化工件）与终端轨（交付工作区终态），再跨大量领域实例化，刻意覆盖长尾（蜂群库存清单、步道维护记录、业余无线电通联日志）。能力骨架与领域表面解耦——变领域、保能力——迫使代理学习底层工作流而非领域表面线索。该路由最关键的设计判断是：合成 LLM 从不直接写任务数据，而是写可运行生成器 build(seed)→(s₀, y, C)，由 TaskForge 在沙箱执行得到多源证据环境 s₀、答案键 y 与答案契约 C。y 由代码在合成源数据上执行得到而非模型断言，答案键锚定于计算而非模型信念。生成器必须以种子保证可复现，且必须创建至少两个需交叉引用的源。契约 C 解决更微妙的问题：仅答案键欠定任务——计算 y 所用的规则（过滤准则、取整约定、tie-break、join key）往往无法通过检查环境反推；C 显式声明这些隐藏决策及交付物 schema 与数值容差，但不含答案值。

领域落地合成面向需专业知识的职业域（数据库管理、工作负载规划等）。可执行域 = schema 暴露给代理的可执行工具集合 + 能完整描述域环境并支撑工具执行的数据库，可源自现有 MCP server 或既有工具代理数据合成工作。构造流程：AST 检查 + LLM 分析抽取三元图（工具—原子参数/返回字段—数据库表），按共享图节点的加权亲和度将工具聚类为技能；聚类结果作为先验提供给自进化代理，允许附理由推翻。每个被接受的簇固化为：数据库访问重写为操作状态快照的可执行命令行脚本 + 技能文档 + 从生成代码（而非文档）抽取的能力规范。任务构造分两阶段：先按结构特征（长程依赖、分支、汇合、错误恢复路径、多子目标）采样抽象任务图——节点为知识状态（如“订单详情已知”），边为状态转移动作；图不含业务内容与工具名，结构先于语义确定。再将图落地到具体域：初始工作区只播种使任务成立所必需的背景/参照数据；覆盖性检查拒绝技能无法支撑的任务图；指令生成置于信息屏障下——只给初始参数、以引用方式提及背景记录（不复制内容，迫使检索）、定义目标状态但隐去流程/执行顺序/分支条件。终态表示为最终数据库状态上的结构化谓词，编译为可执行测试套件；测试只评终态、以业务语义键定位记录而非硬编码 ID，保证任何正确解都能通过。

**3.2 诊断条件化的难度增长**

先导研究表明零起点种子任务推理深度有限。论文给出两种加难手段。多跳抽取将任务提升为多步检索结构：工作区由构造强制包含三类源——索引文件（只列实体 ID 与文件名、不含答题所需值）、每实体明细文件（任何单个均不足以算出答案）、至少一个横切参照源（如费率表/阈值表）；解题必须读索引→逐实体取数→跨三类源 join，结构由构造强制而非 prompt 描述。脏数据注入向工作区注入受控噪声：干扰项、缺失字段、schema 不一致、单位不匹配；注入受约束使真值解逻辑在扰动数据上仍良定义，任务可解而有摩擦。交付物格式在结构化 JSON、CSV、多文件输出与自由报告间轮转；最后一种配机器可判的 sidecar 评分标准文件，保证自由文本输出模态也可确定性验证。

**3.3 两阶段验证与准入带**

agent-free 验证含两项：Oracle——合成 LLM 写参考解与确定性测试 verifier，oracle 必须运行并通过自身 verifier；泄漏审计——确定性检查指令不泄漏答案键、verifier 不接受平凡解，凡在初始状态即通过测试的任务（无需代理做任何事即得奖励的假阳性）直接丢弃。agent-based 验证将当前代理部署到并行沙箱容器池，每任务 N 次试验，仅保留通过次数落在 [Nl, Nh]（Nl>0, Nh<N）内的任务：Nl=0 会留下代理无法完成的任务（太难或不一致），Nh=N 会留下恒可完成的易任务。其 RL 机理（附录 C）在于：组内全对或全错时组标准差塌缩、优势为零，任务只耗算力不产梯度；[1,5]/8 恰保留结果不确定的任务。且准入带相对 π_{k−1} 定义、随代理移动——上轮有信息量的任务本轮被全解即自动出局，形成内生课程而无需外部调度。

**3.4 训练：自蒸馏 SFT + GRPO**

SFT 只用验证通过任务的成功轨迹（r=1），属自蒸馏而非模仿教师。损失在 token 级清零环境观测位（工具输出、文件内容），只在代理自身动作 token 上算交叉熵；这在 harness 场景比常规多轮对话关键——单次 harness 观测（大文件读取或冗长构建日志）可跨数千 token，否则主导损失。轨迹打包至最大序列长度而非截断——截断会删掉最终验证轮次，那正是要学的行为。GRPO 用结果奖励，组即验证阶段同一批 N=8 rollout，优势按组均值归一（论文式 2），KL 罚 β=0.04。超参：SFT lr 2e-5 / batch 128 / 3 epoch / wd 0.1；GRPO lr 5e-7 / batch 64 / 1 epoch / wd 0.0；两者最大序列长 65,536，AdamW，cosine 调度，采样温度 1.0。

**3.5 诊断与反馈闭合**

更新后的 π_k 在 Ek 上 rollout，除逐任务通过率外，每条失败轨迹由代理自身产出结构化摘要：失败点（偏离成功路径的具体动作/决策）、根因（误解任务/选错工具/错误编辑/过早终止）、缺失能力（本应如何做）。作者强调轨迹摘要远易于解题本身——只需事后分析具体执行痕迹而非开放式规划。摘要按技能类别归类、按根因聚类，高频失败模式汇成诊断报告。文中实例：多文件重构能力下反复出现“代理改了目标文件但未更新依赖模块的 import”。报告驱动下一轮任务合成定向打击已识别弱点。

**3.6 基础设施细节**

三阶段跑在同一 OpenClaw harness 底座。每 rollout 一个隔离 Docker 容器（POSIX shell + Python 3.11 + 标准 CLI + 包管理器），与外网隔离，任务所需包预装或生成时 vendored 入工作区——保证可复现且防代理从公网取解。容器预算：墙钟 24 小时 + 最多 300 代理轮次，超限终止并记为失败（不终止被显式惩罚而非静默丢弃）。rollout 在 32 个并发容器实例上并行收集。评测协议固定 harness 配置跨方法一致；SkillsBench 报 Avg@5（86 任务规模小，5 次独立采样降方差），另两基准用各自官方 grader 平均分；解码温度 0.7、top-p 0.95；三个外部基准在整个环路中不参与训练、任务选择或难度调度，诊断只见 Ek——这是基准能作为独立检验的前提。

## 4. 实验结果

主实验以 Qwen3.6-27B 为环路模型（OpenClaw 实现，K=3），对比基座与教师依赖单轮管线 ClawGym：

| Benchmark | Base | ClawGym | ClawLoop |
|---|---|---|---|
| SkillsBench (Avg@5) | 46.3 | 52.6 | **57.2** |
| Claw-Eval-Live (Avg Score) | 69.3 | 74.6 | **76.9** |
| ClawGym-Bench (Avg Score) | 67.6 | 61.9 | **68.4** |

三点值得注意：ClawLoop 三基准全面领先；论文指出在 ClawGym-Bench 上的增益与另两基准相当，说明真实能力提升而非分布特化过拟合；且 ClawGym-Bench 任务由与 ClawGym 训练任务相同管线构造、属 ClawGym 的分布内评测，而 ClawGym 在此反而低于基座（61.9 vs 67.6），教师依赖单轮管线在同分布评测上退化，自改进闭环则没有。

数据质量迁移实验将 ClawLoop 合成任务转训小模型，作为独立数据质量探针（改进不能归因于合成器自身容量）。对照组 ClawGym 用 MiniMax-M2.5+GLM-5.1 做教师、SFT 训练；ClawLoop 无教师、RL 训练：

| Scale | Pipeline | Teacher | 训练算法 | SkillsBench | Claw-Eval-Live | ClawGym-Bench |
|---|---|---|---|---|---|---|
| 4B | Base | — | — | 5.8 | 32.4 | 33.0 |
| 4B | ClawGym | MiniMax M2.5+GLM-5.1 | SFT | 6.2 | 36.8 | 34.6 |
| 4B | ClawLoop | None | RL | **8.4** | **48.0** | **44.1** |
| 9B | Base | — | — | 6.4 | 58.3 | 32.0 |
| 9B | ClawGym | MiniMax M2.5+GLM-5.1 | SFT | 6.7 | 64.3 | 35.3 |
| 9B | ClawLoop | None | RL | **10.8** | **71.7** | **43.6** |

4B 上 ClawLoop 较 ClawGym 在 Claw-Eval-Live 提升 11.2 分、ClawGym-Bench 提升 9.5 分。附录 C 解释为何小模型增益主要归于 RL 阶段：27B 环路模型每轮产出 892–1,978 条成功轨迹，足以支撑 SFT 稳定梯度；小模型在同池上成功率过低，SFT 正例稀缺、更新噪声大且偏向最易任务，而 GRPO 从组内对比取信号——8 次中成功 1 次的任务仍产生可用优势估计（SFT 只留那 1 条、丢 7 条有信息量的失败）。作者同时给出两点边界声明：三个规模共用同一 27B 环路模型，无法分离“课程消费者规模效应”与“生产者规模效应”；4B/9B 从不运行自己的诊断阶段，继承的是 27B 弱点画像塑形的课程——其增益是课程质量的证据，而非完整自改进的实例。

环路内部动力学（1,024 候选/轮）：

| 量 | k=1 | k=2 | k=3 |
|---|---|---|---|
| 过 agent-free 验证 | 897 | 910 | 913 |
| 过 agent-based 验证 | 672 | 469 | 567 |
| 准入率 (%) | 65.6 | 45.8 | 55.4 |
| SFT 保留轨迹 | 1,978 | 892 | 1,694 |
| 平均轨迹轮次 | 5.6 | 11.4 | 8.7 |
| 平均轨迹 token | 1,207 | 2,946 | 1,899 |

agent-free 通过率稳定在约 89%，说明合成基础质量不随环路劣化；准入率非单调——k=2 难度增长对第一轮增益反应过激、大量候选冲过 Nh 上界（准入率跌至 45.8%，幸存任务显著变长），k=3 阻尼校正落回 55.4%。环路以“从两侧穿越”而非单调逼近的方式收敛到合适难度。

案例研究（同族两实例）给出难度吸收位置的直接证据：难实例（难度分 0.53）15 轮、24 次工具调用、9 次 shell 执行、67,994 推理 token，其中 6/15 轮（40%）花在验证；易实例（0.14）6 轮、14 次调用、2 次 shell、4,067 推理 token，1/6 轮（17%）验证。轮次 2.5×、工具调用仅 1.7×、shell 执行 4.5×、推理 token 近 17×——更难的任务不是要求更多动作，而是每动作远更多深思，且大半深思用于确认已做动作的正确性。难实例验证段中最有信息量的行为是“审计自己的审计”：代理独立重算全局营收得 6984.997、确认取整到 6985.00 与报告一致；排序审计报出疑似违规后，查明是自己的检查脚本对相同中位数一律拒绝而未验证字母序 tie-break，判定解正确而检查有错。这正是准入带要筛选的行为：首试即过无验证内容的任务、与完全解不开的任务，都不产这类轨迹。作者亦如实说明两实例非受控对比（同族不同任务），其量化形式即上表轨迹长度随准入率的联动。

## 5. 消融要点

合成路由消融（Qwen3.6-27B 环路内）：

| Benchmark | 仅能力驱动 | 仅领域落地 | ClawLoop |
|---|---|---|---|
| SkillsBench | 54.5 | 55.9 | **57.2** |
| Claw-Eval-Live | 73.2 | 70.1 | **76.9** |
| ClawGym-Bench | 67.2 | 67.8 | **68.4** |

去掉任一路由都退化，但影响不对称：去能力驱动对 Claw-Eval-Live 伤害最大（76.9→73.2），去领域落地主要伤 SkillsBench 与 ClawGym-Bench（57.2→55.9、68.4→67.8）。与基准性质吻合——Claw-Eval-Live 考宽域通用代理能力，SkillsBench（86 任务、11 个职业域）与 ClawGym-Bench 围绕技能类别构建。两路由分别供给广度与技能深度，不可互相替代。

难度增长消融：加难立即显著拉长平均轨迹，但更长轨迹不等于更好训练信号；温和调度（每轮至多提升一级）最佳——轨迹足够挑战以驱动改进，同时保持足够成功率以有效学习。

迭代数 K 消融：性能早期稳定爬升后以不同速率饱和，Claw-Eval-Live 与 ClawGym-Bench 约在 K=3 平台化，SkillsBench 持续受益——归因于其域覆盖更宽、课程可探索空间更大。主实验取 K=3 平衡算力与终性能。

环路动力学本身构成一次内消融：约束不在合成候选数（固定 1,024/轮）而在落进准入带的比例（45.8%–65.6%），即三分之一到一半的合成预算不产任何训练信号；被丢弃的是全解/全不解任务（组一致→零优势）。k=2 过冲说明让候选留在带内需要合成例程跟踪一个移动的策略，且当前跟踪不精。论文明确把难度控制器、而非迭代数，判定为限制因子——能把更大部分输出放进带内的例程将从同一预算榨出更多。

## 6. 贡献与启示

贡献可归为三层：（1）范式层——首个 harness 原生、无教师、闭环迭代的通用代理后训练框架，任务合成、轨迹收集、弱点诊断全部由代理自身在同一 harness 内完成；（2）机制层——多阶段任务合成（双路由种子 + 诊断条件化加难 + 双阶段验证），兼顾代码级可验证性与深度推理所需复杂度；（3）证据层——27B 环路内三基准一致提升，合成数据跨 4B/9B 规模全部有效，将数据质量验证与环路模型容量解耦。

方法论上最可迁移的设计判断： 答案键锚定于“代码执行合成源数据”而非模型断言，从根上规避合成任务的标签噪声； 答案契约 C 显式声明数据无法反推的隐藏决策（过滤准则/取整/tie-break/join key），解决“答案键欠定任务”这一合成管线普遍存在却常被忽视的病态——若无此声明，任务多解、verifier 精确比对会惩罚指令从未约束的选择； 准入带 [1,5]/8 以零优势论证为依据做难度筛选，且随策略移动形成内生课程； N=8 rollout 三重复用（验证/SFT/GRPO 组基线）是闭环算力可行的关键工程决策。

对音视频技术上下游的映射（笔者工程视角推断，非论文内容）：其一，案例研究的聚合-报告任务族与媒资运营任务结构同构——订单账本×商品主表的 join 与分组统计，对应转码账单×母版元数据的对账与按编码档位分层；脏数据注入的“单位不匹配”直接对应媒体元数据中码率/时码单位不一致的现实痛点；契约 C 的数值容差机制可自然映射为质量指标（如 VMAF/PSNR 区间）的验收带宽。其二，领域落地路由以 MCP server 为可执行域入口，ffmpeg/ffprobe、转码阶梯、响度归一等工具链可按论文流程（三元图抽取→技能聚类→CLI 脚本固化）包装进任务合成，为零标注构建音视频工程代理训练数据给出直接路径；其“终态谓词编译为可执行测试、以业务语义键定位记录”对应 ffprobe 探测输出文件（时长、流数、编解码、码率在容差内）的确定性验收。其三，多跳抽取结构（索引→分实体明细→横切参照表）与媒体工作流（manifest/播放列表→分片明细→码率阶梯表）同构。其四，成本结构有直接警示意义：验证 rollout 占单轮约 41% 算力，而音视频任务的终态验证需真实解码/探测、执行开销更重，论文的 rollout 复用与“只评终态”谓词设计是控制该成本的可借鉴范式；诊断反馈的失败模式（“改了目标文件未更新依赖模块 import”）在媒体流水线中的对应物（如“重编码了分段未更新 playlist manifest”）正是该机制可预期的攻击面。

局限（多来自论文自述）：单一环路模型驱动所有规模的课程，规模效应混杂；4B/9B 非完整环路实例；难度控制器跟踪移动策略不精（k=2 过冲，1/3–1/2 合成预算空转）；两基准 K=3 即饱和，作者将更长训练视野与自适应停止留作未来工作。

## 7. 与其他论文的联系

- **SkillDuet（arxiv:2611.12109）**：ClawLoop 的领域落地路由将工具簇固化为静态技能工件（CLI 脚本+技能文档+能力规范），但技能库本身不随环路演化——诊断反馈只作用于任务合成；SkillDuet 以响应反馈让技能库与模型参数协同演化，恰好补上“技能库进入优化回路”这一环。两者共享“技能即训练接口”的立场。
- **FGSE（arxiv:2611.14326）**：同为自改进回路的质量门控设计——ClawLoop 用 oracle 自证+泄漏审计+准入带过滤进入训练的数据（其泄漏审计将初始状态即通过 verifier 的任务判为奖励假阳性，与 FGSE 的证伪探针思想同源）；FGSE 门控的是记忆写入条目，ClawLoop 门控的是训练样本。
- **LongCapHarness（arxiv:2611.10463）**：同属 harness 原生、免数据合成的自改进路线，但 LongCapHarness 固定权重、挂接长上下文底层能力，ClawLoop 更新权重（SFT/GRPO）——对应论文相关工作自述的“权重固定优化非参数 harness（ACE、Self-Harness）vs 权重更新”两条轴，同一环境范式下互补。
- **WeightLoop（arxiv:2610.07319）**：同为实验反馈驱动的权重级自改进，差异在更新机制——WeightLoop 生成有界参数编辑程序、免重训练反复迭代；ClawLoop 走标准梯度更新，奖励来自 harness 内真实执行轨迹。
- **TRUST（arxiv:2611.10787）**：ClawLoop 的回路质量控制全为启发式（agent-free 通过率约 89%、准入率 45.8%–65.6%、k=2 难度过冲），无统计保证；TRUST 的在线多重假设检验为 RSI 错误进化率提供统计控制，正是 ClawLoop 难度控制器精度不足问题的潜在补强方向。
- **InfraRSI（arxiv:2611.11558）**：同一递归自改进范式作用于栈的不同层——InfraRSI 将开放式指令转化为分布式训练优化（五阶段验证工作流），ClawLoop 优化代理策略本身（两阶段任务验证）；两者都以多阶段验证保证进入回路的改进可执行、可检验。
