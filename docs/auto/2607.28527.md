## 1. 背景与动机

LLM 多智能体系统（MAS）的通信拓扑决定了谁与谁通信、信息如何路由、验证发生在哪个位置、中间产物如何被精炼。但现有工作把拓扑要么当作设计期常量（CAMEL/ChatDev/MetaGPT 等预定义角色与交互模式；Debate/EoT/MALLM 等固定交互范式），要么当作离线优化目标：AFlow 用算子搜索工作流、ADAS 用元智能体迭代设计、AgentSquare 做模块化搜索、MASS 联合优化 prompt 与拓扑——共同点是选出的结构在任务执行开始前即冻结，靠聚合验证性能而非当前实例的过程证据来定型。

论文用七层自改进谱系定位问题：L0 输出（Self-Refine）、L1 提示（APO/APE/DSPy/MIPRO/PromptBreeder/TextGrad/GEPA）、L2 推理轨迹（CoT/Self-Consistency/ToT/GoT）、L3 技能/工具（ReAct/Toolformer/Voyager）、L4 记忆（Reflexion/Generative Agents/A-MEM/AWM/ACE）、L5 智能体角色（CAMEL/ChatDev/MetaGPT/Debate 系）、L6 拓扑、L7 权重（RLHF/SELF）。其核心论断：L6 层的自改进几乎只在离线发生，"拓扑能否在求解单个任务的过程中在线自改进"是未被回答的问题。

在线拓扑自改进需要三项此前不具备的能力：(i) 实例条件化的初始拓扑规划（而非离线搜索出的通用工作流）；(ii) 由中间协作轨迹触发的测试时拓扑变异；(iii) 跨运行迁移结构经验而不更新权重。工程动机同样明确：静态拓扑无论任务难易都执行固定配置——过配置浪费 token（论文表 4：群聊辩论每运行 201,651 token），欠配置产生结构性错误（缺验证、检索覆盖不足、重复写状态）。

方法论上的关键立场：审计只看过程信号、不判答案正确性，整个学习闭环（含长期记忆写入）不接触基准判分。这使方法在无真值标注的生产环境可用，也是它与离线工作流搜索的根本区别。

## 2. 方法总览

MANTA 是双层架构：目标 MAS 负责任务求解（推理、工具调用、消息交换）；编排层负责结构，由三个 LLM 元组件（Topology Planner、Trace Auditor、Skill Reflector）加确定性代码（拓扑校验、智能体执行、消息路由、修复控制、停止判据）构成。"LLM 提议、代码裁决"的分工贯穿全系统——所有 LLM 产出（计划、审计 flag、变异、教训）都经确定性验证或保守回退，非法提案不进入执行。

单任务生命周期：Planner 依据任务与经验库产出紧凑计划（根交互模式、智能体数、可选 verifier/嵌套子组）→ 确定性代码扩展为完整拓扑并做结构校验（Planner 返回不可解析计划时回退到 coordinator–worker 星型或 singleton）→ 按 group 结构递归执行一个协作回合，智能体间以结构化 relay packet（答案、证据、置信度、未决问题）通信而非原始 transcript → Auditor 扫描结构化工件产出过程风险报告 → Controller 要么终止（对历史各回合最优候选投票出终答），要么放行一次有界修复并执行最终回合。

修复门控：初始审计存在至少一个中等/高严重度且可修复的 flag 才触发（定义为 flagged run）；每次运行至多一次变异、每次变异至多 3 个算子；变异施加在拓扑副本上并全量校验，非法提案回退到保守修复编译器或跳过。

记忆双时程：短期 playbook 记录本运行每回合的拓扑、flags、建议修复与控制器决策（让 Planner 知道哪些结构已试过、各自产生了什么可观测异常）；长期 playbook 是跨运行的“拓扑规划技能”文档，初始规划与修复时均完整读取，由 Skill Reflector 批量重写（主实验批大小 12 次运行）。学习闭环只用过程标签：procedurally clean = 审计无 flag 且以 decision-grade consensus 终止；基准真值只用于事后评测。

执行底座：智能体跨回合无状态，全部会话状态在三个 append-only 共享存储（packet store、evidence ledger、turn candidates），可见性在读时由共享上下文控制器按当前拓扑规范解析——因此拓扑变异只是“重指向”规范，零状态迁移、零信息丢失。

## 3. 关键设计

**3.1 拓扑表示与结构校验。** 版本化的 MAS 规格。每个智能体有结构角色（coordinator/worker/verifier/debater/voter，决定图位置）与阶段角色（worker/critic；worker 产出有证据支撑的贡献，critic 检查并修订可见声明），可加领域 persona 与工具白名单。模式组可嵌套（树状委托 + 直接连边补充）；context policy 控制可见的消息/发送者/共享证据、消息传播距离、全文或摘要，策略在读时代码强制。执行前校验组成员唯一性、附着无环、角色合法性、智能体预算。根模式五种（singleton/star/chain/debate/voting），配置为初始最多 5 个智能体、修复后总数上限 10。表达力覆盖单智能体与六个静态基线工作流为特例——这也是与静态基线公平比较的结构基础（基线使用与 MANTA 相同的角色集合与代理数上限）。

**3.2 审计器：确定性分类法 + 开放集 LLM。** 确定性部分扫描 11 类过程异常：tool_error_cascade、branch_collapse、unsupported/unverified_impossibility（声明/共识任务不可解但无证据/无独立验证）、evidence_lost_before_synthesis、premature_consensus、message_compaction_loss、insufficient_search_coverage、duplicate_state_mutation、missing_validator、give_up_shaped_candidate。每个 flag 携带严重度、涉案智能体、可修复性。开放集 LLM 审计可新增分类法之外的 flag，但受硬约束：每条新发现必须附对 trace 引用的逐字引文并经代码比对，编造引用即整条拒绝；中/高严重度可修复发现需至少两个不同引用佐证；任务与智能体文本被当作不可信数据（防提示注入）；禁止使用或推断基准真值。这套“引用可验证 + 双引用佐证”把开放集审计的幻觉风险压到可控，是在线结构干预可信的前提。

**3.3 修复语言与检索收缩路径。** Planner 语言七个算子：add_agent、expand_agent_to_group（把一个智能体变成新嵌套子组的 hub）、set_group_pattern、add_edge/remove_edge、set_context_policy。修复 prompt 中显式写入“反事实信息增益”原则：若现有智能体已穷尽某只读源，禁止再加同质访问的智能体——“更多智能体修不好数据源没返回的数据”。检索型任务走独立的确定性变异（不在 Planner 语言内）：资源守卫选择发起搜索调用最多的非协调者，把拓扑收缩为含该智能体的 singleton，授予全局证据访问并注入证据回收指令——首轮扇出检索失败后不再重新扇出一组搜索者，该路径不增加智能体。

**3.4 双时程 playbook。** 长期技能文档两个小节受保护（Standing principles、How to choose a topology，只许润色不许删），“Lessons”小节由 Reflector 从过程标签化的运行摘要重写；规则要求教训按任务特征（类型/工具/规模/状态变更/检索广度）泛化、引用过程证据、合并去重、删除被新证据推翻的条目。示例教训：无工具推理场景 voting/3 与 voting/4 干净运行 35/35，而 singleton、debate/2、star/2 多次触发过程失败。写入门槛比“审计干净”更严（还需 decision-grade consensus 终止）：满足该条件的运行正确率 85.8%（全集 74.0%），作者明确指出残余 14.2% 错误率说明它是高产出的过程过滤器而非正确性标签。

**3.5 无状态智能体与读时上下文控制。** 三个 append-only 存储：packet store（全部 relay packet）、evidence ledger（全部声明与支撑证据，按智能体/回合/声明文本去重）、turn candidates（每回合最优组输出）。读时流水线：选出面向该智能体的 packet → 按 kind/turn/sender 过滤 → 每 sender+kind 只留最新 → 校验发送方 share scope → 施加读取方边界（摘要化、字符预算）→ 把证据账本渲染为有界 digest（scope 随读者策略）；最终合成阶段始终拿到全局 digest。变异 = 副本上应用算子 + 全量校验 + 控制器重指向新规范：旧拓扑下写入的状态全部保留并被下一回合经同一读路径继承；新智能体由确定性规则注册（骨干、消息预算、persona），首 prompt 由任务 packet + 可见 packet + 证据 digest 组装；被移除智能体的贡献不丢失。两项防回退机制：审计建议以“不可信诊断”身份注入修复回合的每个 stage directive（要求验证而非盲从）；终答对历史各回合最优候选投票，变异使答案变差时不会覆盖更优 incumbent。

**3.6 共享 harness 与确定性护栏。** 每 stage 8 次工具迭代，仅保留最近 2 次原始工具消息，更早迭代压缩为确定性摘要（6,000 字符预算；检索文档正文在摘要中保留至 12,000 字符），并显式告知模型摘要是压缩的、冲突时最新原始消息优先。护栏包括：同 stage 内重复相同工具调用直接复用早前结果；搜索结果停滞则引导转读取/作答；同工具连续失败熔断（一般 3 次、搜索 2 次，只丢弃该智能体贡献、任务继续）；搜索过但未打开文档者不得返回 blocked 答案；预算耗尽/超时强制一次无工具 best-effort 作答并记录 typed stop reason。stage 后去重已执行过的相同调用（保证重放的状态变更只应用一次）并把声明与证据追加进共享账本；运行时从不事后伪造工具调用，模型声称的未检索证据会以无支撑形式留在工件里、对 Auditor 可见。指令优先级固化：结构 stage 契约 > 工具契约 > 任务/基准指令 > 领域 persona；置信度用固定五档标准（0/0.25/0.5/0.75/1.0）作为审计输入信号。

## 4. 实验结果

口径：五基准（BrowseComp/StableToolBench/PlanCraft/WorkBench/MATH）各 30 题、3 次独立重复，成功率均值±std，骨干统一 Gemma 4 31B（medium reasoning effort）；公平性约束为所有 MAS 相同代理数上限与可比推理预算，优化类基线按原流程并尽量匹配搜索预算。

| 类别 | 方法 | BrowseComp | StableToolBench | PlanCraft | WorkBench | MATH | 平均 |
|---|---|---|---|---|---|---|---|
| 单智能体 | Single Agent | 34.4 | 74.4 | 61.1 | 41.1 | 85.6 | 59.3 |
| 静态 MAS（组内最高） | Orchestrator w/ Discussion | 64.4 | 80.0 | 73.3 | 20.0 | 93.3 | 66.2 |
| 自适应 MAS | ADAS | 48.9 | 77.8 | 57.8 | 66.7 | 90.0 | 68.2 |
| 自适应 MAS | MASS | 50.0 | 50.0 | 70.0 | 46.7 | 95.6 | 62.5 |
| 本文 | MANTA | **76.7** | 82.2 | **76.7** | 43.3 | 91.1 | **74.0** |

MANTA 平均 74.0±1.8，领先次优 ADAS（68.2±3.2）5.8 点，且在全部五个基准上超过 Single Agent。但需诚实读表：优势集中在 BrowseComp（76.7，较最优基线 Orch w/ Discussion 的 64.4 高 12.3 点）与 PlanCraft（76.7）；StableToolBench 82.2 低于 AgentSquare 的 88.9；WorkBench 43.3 显著落后 ADAS 66.7、AgentSquare 62.2、AFlow 61.1；MATH 91.1 落后 96.7 三方并列组。WorkBench 上离线搜索出的工作流经聚合验证已很强、实例级修复未能补足差距，论文正文未解释此落差，是应保留的疑点。

机理对比（BrowseComp）：AFlow 的 answer-review-revise 后段复用初始证据，ADAS 保留单推理智能体且无独立检索路径，MASS 重复辩论在同一证据上互相强化——执行前定型的结构无法对当前实例做结构性干预，MANTA 则可为受影响实例添加独立检索/验证路径。

Token 开销（四基准每运行均值）：MANTA 总 77,652（输入 63,724 + 输出 13,928，无离线成本），为全部评测 MAS 中最低；其中元层（规划/审计/反思）9,416，约占推理预算 12%，内层智能体 68,236。对照：Voting 80,781、Group Chat 201,651；AFlow 离线 132,517 + 推理 18,553 = 151,070；ADAS 离线 247,675 + 27,728 = 275,403；MASS 53,148 + 127,878 = 181,026。静态 MAS 因固定配置付出高推理成本，离线搜索法把成本挪到搜索/验证段。

Playbook 迁移（变异预算 0，即差异只来自初始拓扑；30 源任务构建、每 10 次运行更新后冻结，迁移前数值取三次运行中位数）：跨域 PlanCraft↔WorkBench，MANTA 平均 +3.3（43.3→50.0；70.0→70.0），是唯一正迁移；ADAS −3.3、AgentSquare −13.3、MASS −58.3（两向均跌至 0.0）——固定工作流对训练任务过拟合，MANTA 保存的是可继承的结构性知识。域内迁移各 +3.3（70.0→73.3；43.3→46.7）。

审计质量（450 次运行 = 5 基准×30 题×3 次）：初始审计无 flag 的运行正确率 83.2%，被 flag 的 62.5%，间隔 20.7 点——过程质量对答案可靠性有信息量且与真值独立。以基准判错为正类的代理指标（作者强调非真实过程检测分数）：flag 200/450，全局精度 0.38、召回 0.64、F1 0.47。分布高度不均：WorkBench F1 0.78（空分支与重复状态变更留下清晰过程证据），PlanCraft F1 0.09、MATH F1 0.20（错误推理常无协作症状），BrowseComp FPR 0.90、精度 0.25（检索异常常见但多可恢复，推高假阳）。修复效果：151 次修复中 60.9% 减少 flag 总数、17.9% 持平、21.2% 反而增加；59.6%（87/146）具名修复目标在下轮审计中消失；修复后运行 69.5% 得到正确终答。算子分布（162 个操作）：确定性检索收缩 42.0%、set_group_pattern 27.2%、expand_agent_to_group 20.4%、add_agent 仅 9.3%、add_edge 为 0；140 次修复单算子、11 次双算子，无一次触顶 3 算子。症状→修复命中率：重复状态变更→chain 序列化 33/39，缺验证→插入 critic 15/19，工具失败分支→扩组 28/51。“修复更多是改执行结构而非加智能体”有分布层面的证据。案例研究给出五类修复，仅“分支扩展”使系统变大；典型如 PlanCraft 轨迹中三星型拓扑首轮即一致但置信度不足、问题未决，被判 premature_consensus，仅补一条 worker–verifier 直连边变成全连接辩论，次轮审计通过、置信度 1.0、判分 1.0；数学轨迹中单智能体低置信无检查，仅插入一个从不自行解题、只核查既有答案的 critic，次轮判分 1.0。

## 5. 消融要点

四基准（BrowseComp/WorkBench/PlanCraft/StableToolBench）各 30 题平均，token 含批量 playbook 更新摊销：

| 变体 | 成功率(%) | 总 token |
|---|---|---|
| Full MANTA | 71.7 | 100,315 |
| 去初始拓扑规划（固定 coordinator–worker） | 57.5 | 112,040 |
| 去拓扑变异 | 60.8 | 72,105 |
| 冻结长期 playbook 更新 | 67.5 | 102,620 |
| 去长期 playbook | 66.7 | 78,356 |

三个结论：(1) 初始规划贡献最大（−14.2 点），且其缺失变体同时更贵（+11,725 token）——固定拓扑既差又浪费，任务条件化规划是“免费午餐”式组件；(2) 修复贡献次之（−10.9 点），去掉后省 28,210 token，即修复以约 28k token 换近 11 点，单位 token 收益最高；(3) 跨运行学习贡献最小但方向一致（更新相对冻结 +4.2，存在 playbook 相对没有 +0.8）。变异预算 0→3 的渐进评测（预算 b 下统计任一 ≤b 预算曾成功的任务覆盖）显示四基准随预算单调改善，第一次变异贡献最大边际增益，2–3 次仅覆盖最难任务——支持“有界修复”而非无限重规划的设计选择。

模式级消融（全 450 次）：Table 10 覆盖九个模式，七个与更低成功率相关，最强四个负缺口超 30 点（evidence_lost_before_synthesis −60.7、missing_validator −46.1、branch_collapse −38.6、give_up_shaped_candidate −32.1）；message_compaction_loss（+2.2）与 tool_error_cascade（+5.4）与成功率无负相关——属“能被合格拓扑吸收的可恢复事件”，作者指出在严重度门控中下调二者权重是提升审计精度的直接手段。

## 6. 贡献与启示

问题层：把“协作结构本身作为执行期可自改进对象”形式化为 topology-level self-improvement（谱系 L6 的在线化），并给出完整最小实现（规划—审计—有界修复—双时程记忆—防回退）。方法层三条可迁移启示：(1) 过程信号足以驱动结构学习——不接触真值，仅凭“无 flag + decision-grade consensus”过滤即获得 85.8% 正确率的记忆写入集，且跨域迁移为正，对无标注生产环境意义重大；(2) 修复≠扩规模——算子分布（add_agent 9.3%）与五个案例中仅分支扩展增大系统，序列化、重连、插入 critic 都是零/低成本结构手术，“由 trace 可见的结构性失败决定修复，而非系统大小”；(3) “LLM 提议 + 代码裁决”的全链路（结构校验、逐字引用比对、读时上下文策略、确定性护栏）是在线结构变异不失控的前提，元层开销可压到推理预算约 12%。

局限（论文自述与数据可见）：审计全局精度仅 0.38，两个可恢复模式是假阳主源；审计盲区明确——PlanCraft/MATH 的错误推理无协作症状（F1 0.09/0.20），即拓扑级自改进对“纯推理错误”基本无杠杆，clean trace 只是可靠性信号而非正确性保证；评测规模 30 题×3 次，部分单元格 std 较大；缺人工过程标注与配对重放对照（同 trace 前缀下推荐变异 vs 等预算续跑），作者列为后续工作；WorkBench 落后自适应基线 23 点以上未获解释。

对音视频工程的上/下游关联（笔记作者视角，非论文内容）：论文与音视频无直接关系，但编排层设计对“LLM 智能体驱动的音视频生产/审核流水线”有直接可迁移性。(i) 媒体流水线（素材检索/转码/审核/QC/打包发布）可建模为多智能体拓扑，MANTA 的“审计—有界修复—历史候选投票防回退”提供了长链路工作流在线换接线而不丢中间产物的模板；(ii) duplicate_state_mutation→chain 序列化直接对应媒体域非幂等操作（发布、写媒资库、配置生效）的并发防护；(iii) 无状态智能体 + append-only 证据账本 + 读时可见性控制天然适配审核证据链/溯源需求：重接 DAG 无需迁移媒资状态，被移除环节的产出仍留在账本；(iv) 检索收缩路径（扇出失败后收缩到最强单检索者 + 全局证据）是多路素材/片段检索失败后的聚焦策略；(v) 元层约 12% 的开销为在既有 A/V 工具链外包一层智能体编排提供预算参照。上游依赖是骨干 LLM 的规划与审计质量，全部元组件与任务智能体同骨干（Gemma 4 31B、温度 0）。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326（FGSE，证伪门控自演化记忆）**：两者处理同一核心问题——“经验何时写入记忆”。MANTA 的写入门是过程内生的（无过程 flag 且 decision-grade consensus，写入集正确率 85.8% 对全集 74.0%）；FGSE 要求教训作为可证伪假设通过三类探针后才写入。MANTA 的门控没有外部证伪机制，Reflector 仅按过程标签增删教训；FGSE 的探针思路可用于加固其 playbook 的写入与保留判据。
- **paper:arxiv:2611.10787（TRUST，统计保证的递归自改进）**：MANTA 的变异接受/拒绝只有结构校验与保守修复编译器，无统计控制——151 次修复中 21.2% 反而增加 flag 数。TRUST 的在线多重假设检验可直接移植为变异接受门（以 flag 增减为统计量控制错误进化率）；两者同为权重冻结的推理期自改进，MANTA 补统计保证、TRUST 补结构化变异语言，是自然互补。
- **paper:arxiv:2611.12109（SkillDuet，模型—技能协同演化）**：都以执行反馈驱动外部经验库演化但粒度不同——SkillDuet 用响应反馈耦合参数更新与程序性技能库，MANTA 冻结权重、演化的是“结构选择知识”（何种任务特征配何种拓扑）。MANTA 的长期 playbook 可视为架构粒度的技能库；SkillDuet 的双轨机制提示了 playbook 学习与权重更新的正交组合空间。
- **paper:arxiv:2611.10463（LongCapHarness，能力挂接式长上下文自改进）**：同为免后训练、免数据合成的推理期递归自改进，且都强调元层成本可控（LongCapHarness 成本低于基线 50% 以上，MANTA 元层占推理预算约 12%）；差异在被改进的层——前者挂接长上下文底层能力，后者改进协作架构，在自改进层级谱系上互补（分别对应能力层与结构层）。
