# More Memory, Worse Agents: Error Reproduction and Anti-Persistence in LLM Agents

> Ruhan Wang, Kishan Panaganti, Dongruo Zhou. *arXiv:2610.27406v1 (2026-10-19)*

## 1. 背景与动机

本文研究参数冻结下的记忆型自改进：智能体把自身执行经验存入外部记忆，检索复用以指导后续任务，再用新经验更新记忆，跨任务形成反馈回路。核心设计问题是持久化内容的粒度——只保留观测到的轨迹与结果（事实记录），还是同时保留从轨迹蒸馏出的规则、摘要、技能（推断抽象）。抽象的优势是压缩与易检索，但压缩本身需要对"哪些细节重要、模式在何种条件下成立"做判断：一条在某任务成立的规则可能依赖另一任务不具备的条件。

论文的概念贡献是区分两条错误扩散路径：**error propagation**（已存错误条目经检索复用直接影响行为，复用单元是示例级/轨迹级）与 **error reproduction**（错误经由"抽象→执行→再抽象"回路在新抽象中被重新生成，复用单元是规则级、可跨任务类型泛化）。后者的机理链为：存入的抽象 s_parent 进入执行上下文 → 影响轨迹 e_j → 该轨迹（含受污染的动作）作为记录进入后续综合的检索集 H → 新综合产物 s_candidate 再现原错误。关键在于：即使原抽象被删除或不再被检索，受其影响的轨迹仍在库中；附录 A 的 Remark 1 形式化指出，仅删除父抽象的删除式操作满足 S⁺=S⁻\R、D⁺=D⁻\R、M⁺=M⁻——后代与轨迹均不受影响。这解释了为何记忆维护（打分、剪枝、精炼）不能根治：维护作用于抽象库，而污染源已沉淀在轨迹库。

作者立场克制：再生产是"可能的反馈"而非必然放大，论文不提供增长系数或长期退化保证。由此引出研究问题：如何在记忆型自改进中从抽象获益，同时限制误差再生产。

## 2. 方法总览

形式化设置：骨干参数 θ 固定；轨迹记忆 M_k={(τ_j, e_j, y_j)}；综合算子 s=φ(H)，H⊆M；保留抽象的方法按 S_{k+1}=U_k(S_k, A_k; M_{k+1}) 更新抽象库。Anti-Persistence 的唯一结构性约束是 **S_k≡∅**：综合产物 σ_τ 只服务当前任务，执行后丢弃；持久化的只有 M_k 与结果日志 L_k（记录模式选择及其反馈）。与持久化抽象的流程对照：`trajectory→abstraction→storage→reuse` vs `trajectory→storage→retrieval→on-demand abstraction`。

每任务的数据流分两阶段检索：

1. **模式选择检索**：从 L_k 取 B̂=10 近邻。任务嵌入由 Qwen3-Embedding-8B 单次调用产生，输入为 instruction ∥ "Initial state:" ∥ truncate(obs, 500)；相似度为余弦（分母加 ε=10⁻¹²）。初始观测前缀用于区分同目标模板但起始状态不同的任务。
2. **加权效用估计 + UCB 选模式**：条目权重 w_i=max(sim(τ_i,τ),0)·γ^{t_max−t_i}（γ=0.998，锚定邻域内最新时间戳 t_max）；代价调整奖励 r=clip(y−λκ, −1,1)（λ=0.05，κ 为该次尝试实际额外综合调用数）；模式效用 U(μ)=r̂(μ|τ)+c·√(log|N|/max(n_μ,1))，c=0.5。
3. **模式特定内容检索**：从 M_k 按 B=5 预算取记录。none 不过滤；imitation/strategic 取 top-B 成功轨迹；corrective 取 top-B 失败轨迹 + 1 条对照成功（可得时）。
4. **综合或透传**：三综合模式调 φ（temperature 0，1024 token），输出以模式专属 markdown 头注入系统提示；none 直接注入"Retrieved Factual Context"。κ 约定：none=0；三综合模式调用时 κ=1，所需记录不可用时返回 ∅ 且不计调用。
5. **更新与丢弃**：(τ, e, y) 入 M_k；合格条目（模式、代价调整奖励、原始结果、时间戳）入 L_k；σ_τ 丢弃。

安全保障：前 3 迭代轮转选择、每模式至少 3 次强制 warmup、ε=0.1 的 ε-greedy、邻域平均相似度低于 ρ=0.7 时回退全局最优策略、嵌入失败当轮降级 none 不重试。L_k 为 append-only JSONL，七字段 schema（embedding/mode/reward/raw_success/task_type/task_id/instruction≤500 字符）；三条写入跳过规则：k=0（空记忆时所有模式退化为基线，会把基线噪声归因到所选模式）、嵌入失败、基础设施失败。

## 3. 关键设计

**(a) 结构性保证的精确边界。** S_k=∅ 使"准入持久抽象库"事件 W 不可能，故对任务时综合有 Pr(A∩W)=0（A 为候选被标记事件）。但论文明确不给 Pr(A)=0：临时指导会塑造被存储的轨迹，间接反馈通道保留。附录 A 把过程分解为暴露 q=Pr(C)、条件标记生成 α=Pr(A|C)、条件准入 η=Pr(W|A∩C)，命题 1 给出 Pr(A∩C)=qα、Pr(A∩W)≥qαη 的概率分解——是分解而非跨维护策略的普适下界（排除全部暴露记录可置 q=0，拒绝全部被标记候选可阻断准入）。对 α 未定义情形的处理很诚实：q=0 时 α 未定义而非 0，因此 anti-persistence 全新运行（无存储祖先）的结构保证仅限"无存储抽象及其直接复用"，性能优势是经验结论而非定理。

**(b) corrective 的无回退设计。** 无失败轨迹可用时 φ 返回 ∅ 而非回退到 strategic——否则 strategic 指导的效果会被记入 corrective 臂的 bandit 统计，污染模式归因。这是把 bandit 测量的干净性置于单任务收益之上的取舍。

**(c) 时间戳锚定不变性。** γ 衰减锚定邻域内 t_max 而非当前更新索引，所有权重同乘正常数，归一化奖励估计不变。衰减只作用于模式选择反馈、不影响轨迹检索，理由是旧模式评估会随记忆增长失代表性，而旧轨迹作为示例仍可能有效。

**(d) 奖励与结果分离记录。** L_k 同时存 r（含 λ 惩罚）与 raw_success（裸结果），使模式选择的代价敏感与任务性能度量解耦；reward clipping 到 [−1,1] 为奖励/代价尺度变化预留空间。

**(e) 代价核算口径。** κ 只计综合相对直接复用的额外调用；λ 把调用数拉到与成功值同尺度。none 模式在九个设置均有非零选择占比，加上部分设置执行轨迹更短，抵消了综合调用——这是总调用均值反而最低（见第 4 节）的机制来源。

**(f) 运行标签 vs 因果。** 附录 E.3 的"operationally biased"标签基于对比"检索过该抽象 vs 未检索"的 held-out 平均成功率差（b̂(s)=1{ȳ⁻−ȳ⁺≥δ}，n_min=3，δ=0.05，两组都必须存在），并反复声明这是未调整关联：检索可能把某些抽象集中到更难任务，不能识别因果。测量口径上的这种自律在智能体记忆文献中少见。

## 6. 贡献与启示

三条贡献：概念上区分并形式化了传播 vs 再生产（含删除作用域的 Remark 与 q/α/η 分解）；设计上把经验积累与抽象持久化解耦——固定综合过程、按需生成、即弃；经验上给出 3×3 网格 + 溯源审计 + 受控内容研究三重证据。

方法论启示：(1) **"存事实、弃推断"应作默认**——在无验证机制时，推断内容持久化是负期望选项（7/9 设置抽象/联合记忆劣于轨迹记忆；persist 消融 4/4 劣于 discard）。(2) **维护不能替代结构**——删除不回收已污染轨迹也不删后代，维护只能改变未来暴露 q、生成 α、准入 η 的分布；受控研究进一步显示，即便外部强模型过滤后的技能作为冻结层回灌仍使性能从 56.0% 跌至 44.0%。(3) **测量卫生可直接移植**：奖励与裸结果双字段、三条日志跳过规则、append-only 日志、held-out 全冻结评估，适用于任何经验积累型系统。(4) 论文自划边界：间接反馈仍在；三个文本基准、固定改进过程；辅助分析无任务级/种子级不确定性；丢弃也放弃了可靠知识复用，"何时验证可证成选择性持久化"留作开放问题。

对音视频技术侧的关联（本引擎定位注记，论文本身不涉及 AV）：LLM 智能体编排音视频工具链（转码参数决策、剪辑流水线、滤镜图生成、流媒体 QC）是本文上游骨干/嵌入模型的直接下游场景，其经验记忆设计正面对同一问题。迁移推论：(i) 应优先持久化原始运行记录（命令、参数、输出指标、QC 判定）而非蒸馏出的编码/响度/码率"经验规则"——错误启发式会经运行日志被再抽象固化，与本文 s_parent→e_j→H→s_candidate 链路同构；(ii) 任务前按需综合临时指导（如按分辨率档位/时长/目标平台合成转码策略）即 anti-persistence 模板；(iii) 代价调整 bandit 与 AV 中昂贵操作天然对齐——每次转码/全参考质量评测都是真实成本，λ 项提供了调用预算与成功率的统一权衡旋钮；(iv) 多模态观测会数倍放大轨迹体积，"存轨迹弃抽象"对存储与检索预算的压力在 AV 落地时必须重估。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326）**：同问"什么该写入智能体记忆"。FGSE 走准入控制路线——教训作为可证伪假设经三类探针验证后才入库；本文走结构非持久化路线。本文 F.2 的结果（验证过滤后的技能作为冻结层回灌反使 56.0%→44.0%）提示验证式准入未必能安全嫁接到非持久设计，两条路线的兼容性是直接后续问题。
- **TRUST（arXiv:2611.10787）**：用在线多重假设检验为递归自改进控制错误进化率并提供统计保证。本文附录 A 只给 q/α/η 概率分解，并明言 UCB 式选择规则无置信界/遗憾保证、溯源审计无不确定性程序——TRUST 恰好补上这块统计地基，二者构成"结构隔离 vs 统计控制"的对偶方案。
- **SkillDuet（arXiv:2611.12109）**：持久技能库与模型权重协同演化的另一极端设计。本文"抽象/联合记忆在 7/9 设置劣于纯轨迹记忆"的结果对持久技能库构成压力；但 SkillDuet 耦合了参数更新，反馈回路形态不同，不能直接外推。
- **WeightLoop（arXiv:2611.07319）**：把自改进持久化到权重空间（有界参数编辑程序 + 实验反馈）。与本文共享"生成内容反馈影响后续生成"的回路担忧，但载体从外部记忆换成参数——对照说明误差累积风险正交于持久化载体本身。
- **InfraRSI（2611.11558）、RSI-PDEbench（2611.14949）、AutoTavern（2610.33845）**：同属递归/经验驱动自改进回路（训练基础设施优化、PDE 求解、游戏 AI 与模拟器构建），其多轮执行日志同样构成"执行→综合→再执行"的反馈面；本文的再生产分析、溯源审计与"存事实弃推断"策略可作为这类系统经验库写入与审计的直接模板。
