# Language Imbalance Driven Rewarding for Multilingual Self-improving

> Wen Yang, Junhong Wu, Chen Wang, Chengqing Zong, Jiajun Zhang. *arXiv:2410.08964v3 (2024-10-11)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

预训练与后训练语料的语言分布失衡使 LLM 的能力高度集中于英语、汉语等“一等语言”，其余语言用户直接承受质量风险。既有应对路线有两条：其一，多语言训练（补充多语言指令/偏好数据），但低资源语言的高质量偏好数据稀缺且昂贵；其二，跨语言对齐（把非主流语言能力向主流语言拉齐），其性能上限被主流语言初始能力锁死，且若对齐过程损耗主流语言，迭代式提升便无从谈起。论文证据（作者给出的 SFT 对齐对照）：以英语响应自译成其他语言做 SFT，非主流语言上涨但英语 win rate 从 24.90% 跌至 21.88%（-3.02%），这种主语言退化恰恰阻断了进一步迭代。

本文的立场反转是：语言不平衡本身构成模型内部天然的偏好序，可作为免费的奖励信号用于自提升。置于 LLM 自提升谱系中看：self-synthetic 路线（Self-Instruct、指令回译）与 self-critical 路线（LLM-as-judge、Self-Rewarding）都要模型自己产出质量判断，而 judging 能力在非主流语言上同样不可靠；本文改从模型的跨语言能力结构性差异中提取奖励，不依赖裁判能力，且偏好序是双向互利的——主流语言也能从中拿到有效负样本，这是迭代闭环得以成立的前提。

动机层面还有一个具体的工程痛点：Llama-3-8B-Instruct 在部分语言上存在严重的 off-target 问题（以目标语言提问、模型以错误语言作答），论文表1 的 GPT-4 打分中 ja 仅 0.76、ru 仅 2.21（0-10 分制，100 条多语言 Alpagasus 指令），这类失败模式正是该方法在后训练中顺带修复的对象。

## 2. 方法总览

框架为两阶段迭代：给定指令模型 M0 与平行多语言 prompt 集 X，第 t 轮执行：

** 自我多语言偏好对生成。** 当前模型 Mt 对任意语言指令生成响应；再用 Mt 自身做双向互译（自译 prompt 见附录 H.4）：将主流语言响应译为各非主流语言，并将每个 prompt 下随机选取的一条非主流语言响应译入主流语言。偏好赋值依据两条序关系：对主流语言指令，原生主流响应 ≻ 非主流语言生成后译入主流的响应；对非主流语言指令，主流响应译出的目标语言版本 ≻ 原生非主流响应。由此构造双向数据集 D = Ddl ∪ Dnl，两集合内 chosen/rejected 同语言、同指令，只差“内容源头来自哪种语言”。

** 多语言偏好优化。** 采用 DPO 变体加 chosen 侧 NLL 项：L = L_DPO + α·L_NLL。参考模型为冻结的 Mt，KL 系数 β=0.1，α=1；实现细节上 NLL 项按 chosen 长度归一化而 DPO 项不归一化。每轮训练 1 个 epoch，Mt+1 即训练后的 Mθ，作为下一轮数据生成器。指令跟随任务 LR 5e-7、batch 16；推理任务 LR 5e-6、batch 64（SFT 基线为 1e-5/128/3 epoch）。

方法成立依赖两个经验前提，论文均在 Llama-3-8B-Instruct 上验证（100 条多语言 Alpagasus 指令，GPT-4 打分）：

1. **能力差距存在**：en 9.60 vs es 8.34 / fr 6.43 / it 6.66 / de 4.69 / ja 0.76 / ru 2.21；GPT-4o 复评结论一致（ja 2.97、ru 4.51），排除裁判模型偏置。
2. **翻译保持偏好序**：英译外的自译响应质量为 es 9.32 / fr 9.17 / it 8.72 / de 8.96 / ja 7.89 / ru 7.75，全面高于对应语言的原生生成质量；外译英为 8.03，低于原生英语 9.60。即“源自主流语言”的质量优势穿透了翻译层。进一步对构造出的偏好对做 GPT-4 成对裁决，奖励准确率（win rate）全部 >0.50，从 es 的 0.57 到 ja 的 0.79——模型越弱的语言，不平衡给出的奖励信号越强。以 0.60 为阈值划分低奖励语言（es/fr/it）与高奖励语言。

## 3. 关键设计

**双向偏好对是迭代可行性的核心。** 若只给非主流语言供正样本（即 SFT 式对齐），英语必然受损。Ddl 中以“非主流语言生成后译入英语”的响应作 rejected，其携带翻译伪影（质量 8.03 vs 原生 9.60），为英语提供了真实有效的负样本；DPO 的负梯度同时压制翻译腔与原生弱点。实验印证：Llama-3 上英语 M1 vs M0 的 ΔW-L +15.3%，M2 vs M1 再 +14.6%（805 条 X-AlpacaEval 测试 prompt，GPT-4 gpt-4-1106-preview 裁判）。对非主流语言侧，chosen 是“英语内容+自译载体”，本质上是用偏好优化而非 SFT 蒸馏英语能力，同时负梯度惩罚原生失败模式——MGSM 上 off-target 率的塌缩（如 ja 0.280→0.004、th 0.124→0）即来源于此。

**奖励强度的语言异质性。** 奖励准确率刻画了各语言可挖潜力：第一轮中高奖励语言（ru/de）增益显著大于低奖励语言（ΔW-L 最高 61.5%@ru vs 15.3%@en），第二轮各语言增益收敛，说明语言间差距收窄、信号趋于饱和。这给出语言子集选择的先验准则（0.60 阈值），也是该奖励自限性的体现：非主流语言的 chosen 质量上限被自译质量封顶（ja 仅 7.89），迭代收益天然衰减。

**DPO+NLL 的引用式设计。** NLL 项沿用 Pang et al. (2024) 迭代推理偏好优化的结论（对性能关键），防止 chosen 似然在纯 DPO 目标下塌缩。论文未对 NLL 项做开关消融，属设计迁移而非本文验证。

**自译与外译的可换性。** 自译保持生成空间一致性，英语侧收益更好（低资源实验中英语 39.27% vs 38.38%）；但对 bn/sw/th 这类模型生成/翻译能力极弱的语言，外部 Google 翻译提供更高质量数据，低资源语言收益更高（bn 5.99% vs 4.49%）。范式允许按语言混用两种翻译源。

**推理任务的适配。** 多语言 GSM8K（7,473 条训练指令经 Google Translate 翻译）上，先用“英语回答正确”过滤样本再构造偏好对，等价于把语言不平衡作为英语正确性的放大器；prompt 中显式约束响应语言（附录 H.5），并以 LangDetect 度量 off-target 率。

**评测公平性工程。** 三个针对性措施：偏好对验证全部在同语言内成对比较，规避 LLM-as-judge 跨语言打分偏置；head-to-head 双向交换位置取“两胜或一胜一平”消位置偏置；translationese 风险靠训练数据（LLM 自译）与基准（机器翻译）分布分离、且 LLM 翻译伪影更少来缓解。这套协议本身是多语言主观评测的可复用资产。

## 5. 消融要点

- **SFT 对齐对照（同数据同基座）**：增益确来自偏好目标而非数据暴露。英语一升（+9.19%）一降，归因于负样本与偏好目标；英语退化阻断迭代，属范式级差异而非调参差异。
- **MAPO†/MAPO‡ 双控**：分别固定采样量与训练数据量，剥离“偏好数据规模”与“奖励机制”两因子，结论指向奖励机制本身占优。
- **自译 vs 外译**：自译护主流语言（生成空间一致）、外译救低资源语言（数据质量），二者可按语言混用。
- **奖励信号动力学**：逐轮测量训练/未见语言的奖励准确率——训练语言中高奖励语言（除英语）在第一轮后降档，低奖励语言维持低位波动，自提升得以持续；未见语言 ja 的奖励准确率在第一轮后骤降，与 off-target 响应大幅减少相对应，说明“控制目标语言”这类偏好经 DPO 迁移到了未参与训练的语言。
- **裁判鲁棒性**：GPT-4o 复评 X-AlpacaEval（M0 19.84%→M2 32.00%）与 GPT-4 Turbo 结论一致。
- **未覆盖的消融**：α、β、NLL 开关、偏好对构造方向（单向/双向）均无系统消融；语言组合选择仅有高/低奖励二分启发式，是复现与后续工作的注意点。

## 6. 贡献与启示

**贡献**： 把语言不平衡从“待修复问题”重构为零标注成本的偏好信号源； 首个多语言维度上的迭代自提升方案（作者自称 initial exploration），主流语言不降反升，突破跨语言对齐法的主语言天花板，且对未见语言有正迁移； 交付了 AlpacaEval 2.0 工具链的多语言化扩展（X-AlpacaEval），连同同语言内成对评测协议，是多语言主观评测的社区资产。

**工程含义**：数据成本近乎为零（多语言 prompt + 模型自生成/自译）；off-target 修复（MGSM 多语言 off-tag 归零）对多语言产品是即取即用的属性；语言子集可用奖励准确率做入场筛选。局限同样明确：奖励粗粒度；自译伪影仍会污染 chosen；增益随语言差距收窄而饱和；对预训练覆盖极弱的语言（bn/sw），作者明示后训练增益无法突破预训练上限；要求种子模型具备基本多语言生成能力。

**与音视频技术的上下游关联**：本文属 NLP/多语言对齐，但其机理与音视频链路直接相通。(i) 多语言语音交互与字幕/配音管线（ASR→LLM→TTS）中，文本骨干的多语言指令跟随与目标语言控制决定下游 TTS 的语言一致性与本地化质量；该方法提供了免标注后训练路径，off-target 抑制直接对应语音系统的语言 ID 稳定性。(ii) 多语言音视频理解大模型的指令数据同样英语主导失衡，“翻译保持偏好序”原理可迁移为跨语言/跨模态一致性奖励——以英语响应为锚构造多语言音频描述、视频问答的偏好对，绕开多语言人工偏好标注。(iii) 同语言内成对裁判协议可直接移植到多语言字幕、音视频描述质量的主观评测，规避裁判模型跨语言打分偏置。(iv) 多语言 prompt 用 Google Translate 构造的做法，提示语音翻译系统中现成 S2T/MT 组件即可承担平行指令生成。
