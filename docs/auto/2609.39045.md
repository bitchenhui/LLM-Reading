## 1. 背景与动机

自动游戏生成随长程生成、多模态理解与工具调用能力提升已具可行性：GameCraft-Bench、GameDevBench、OpenGame-Bench 等基准表明 VLM agent 能把自然语言规格转成机制可辨识的可玩游戏。但游戏开发是代码、视觉/文本资产、配置文件深度耦合的多模态工程，人类成熟团队也普遍存在意外 bug、缺失功能与边角案例，行业标准解法是“测试—反馈—修订”的迭代工作流，可自然形式化为递归自我改进（RSI）：P0 → P1 → … → PT，每轮基于新观测证据在上版基础上改进。

论文诊断的核心病灶是：朴素迭代精修容易过拟合少量测试用例（尤其是随项目打包、供评测重放的演示轨迹），产出“恰好过检”的脆弱游戏——未测 bug 留存、行为缺失、对更广玩家交互泛化差。形式化地，生成策略 πθ 从规格 x 产出项目 P0（源码+资产+配置），质量由重放演示轨迹、对照隐藏任务 rubric 评分体现，开发循环要把 P0 推向整体质量而非局部过拟合。

既有工作的空档：现有基准只给单一提交版本打分；Play2Code、VibeGame、OpenGame 等系统引入了迭代本身，但没有回答“迭代收益如何在长程上可靠维持”。RSIGame 的核心主张（后被实验直接证实）：收益来自开发过程的组织方式——剩余空间判定、最优检查点保持、饱和检测与重启——而非迭代本身。两个量化反例支撑该判断：Play2Code 在 Codex+GPT-5.5 强初始化上仅 +0.48 分（烧 3.20M token）；八角色、自带验证与优化角色的 VibeGame 团队在 40 个 Phaser 任务上得 30.5，低于单次生成参考分 46.0。

论文在 RSI 谱系上的定位：训练无关（上下文优化）与训练内化（参数优化）双层结合，把 agentic 游戏开发做成可控、可复现的 RSI 过程。

## 2. 方法总览

RSIGame 由三层构成：局部循环、全局循环、经验内化。

**局部循环**实现 explore-diagnose-improve，由四个互补 agent 与一个共享状态驱动。给定规格 x、当前项目 Pt、检查表 Ct 与可选阶段指导 γs：控制器决定开发方向 dt ∼ πcontroller(·|x, Pt, Ct, γs)；探索器与可执行游戏交互产出轨迹 τt ∼ πexplorer(·|Pt, dt)；编辑器把问题与交互证据转成具体修改 Δt ∼ πeditor(·|Pt, dt, τt)，Pt+1 = Apply(Pt, Δt)；验证器与更新后项目交互，判断目标是否达成、有无回归，产出 vt ∼ πverifier(·|Pt+1, dt, τt)。检查表按 Ct+1 = U(Ct, dt, τt, Δt, vt) 更新，记录已发现问题、改进机会、优先级与验证结论，使每轮建立在已验证进展上而非从零重启。

**全局循环**跨轮治理：质量监视器在 checkpoint 处按 P⋆s ← SelectBest(P⋆s, Pt+1) 保持最优检查点；连续 K 个 checkpoint 无新 champion 判为饱和，此时要么终止返回 P⋆s，要么引入高层指导 γs+1（人写或更强模型写，给战略方向而非编辑指令）并从 champion 重启下一阶段。运行参数 E=3（每 3 轮一个 checkpoint）、K=3。关键隔离约束：监视器只读独立代理 rubric，与基准评测器（隐藏 rubric、分数、judge 反馈）完全隔离，不导入 judge 模块。

**训练内化**把成功开发轨迹转成监督信号：收集三类数据——GPT-5.5 构建 Godot/Phaser 游戏的 2,213 条生成轨迹、2,108 条规划轨迹、GLM-5.3-Flash 运行 RSIGame 产出的改进轮（4,003 候选中验证通过 2,013），只保留可执行且编辑后交互验证未破坏既有功能的样本；对 Qwen3.8-27B 做 SFT，loss 仅施加于 assistant 输出。目标是同时提升初始生成质量与减少精修所需轮数，并打开“新经验持续内化”的通道。

**角色分配**（口径：除生成器逐行组变化外，其余角色在所有行固定，使行间比较隔离出开发方法变量）：Controller/Editor/Verifier = GLM-5.3-Flash（OpenRouter，T=0）；Explorer = Qwen3.8-27B（本地 vLLM，TP=2，T=0）；全局监视器 = Qwen3.8-Flash；资产生成 = Seedream-5.0-lite；评测 judge = Qwen3.8-27B（本地，T=0，thinking off，输出 ≤2048）。凡输出是“对游戏的断言”（坐标、裁决、rubric 条目）一律贪心解码。

## 3. 关键设计

**信息隔离的模块化提示契约。** 五个 LLM 模块各自只被告知回答自身问题所需的信息，刻意隐瞒其余，以阻断自我确认偏置：Controller 只决定“去查明什么”，输出 reuse/explore/escalate 三选一与最廉价探查模式（重放既有 demo / 扩展既有 demo / 定制探针），且明确允许 escalate——“该方向无证据支撑的未决问题”而非硬造工作；Editor 被告知“问题已确立”，直接从“代码在哪”开始，禁止改 harness 与 demo_outputs（改后者是改考卷不是改游戏）；Verifier 知道本轮目标（它要核验的断言），并严格区分“游戏从未有过的功能”（任务需求，非损坏）与“输入无任何响应”（损坏），unclear 是合法输出；监视器的比较器是全系统唯一读像素的组件，且不知道哪个 build 更新、不知道发生过改进。这一“隐瞒即防偏”设计是方法可靠性的工程核心。

**演化检查表。** 作为四模块共享的工作状态，跨轮累积问题、优先级与验证结论；Controller 读它定方向，Explorer 补证据，Verifier 回写状态——相当于一个带验证门控的外部记忆。

**全局质量监视器的机理。** 它从不单独给版本打分：每个 checkpoint 用同一组演示（≤3 条）重放 champion 与候选，逐场景配对帧，只问“什么变了”。每条代理 rubric 准则按三档锚定读数（1.0 如描述工作 / 0.5 部分或间歇工作 / 0.0 不工作），且只在两次录制都能触达的准则上读——保证差异来自游戏而非重放路径。加权总值 ∈ [0,1] 分两半报告：当前阶段 brief 准则半区 + 任务文档准则半区。采纳规则：候选在 brief 半区至少 +0.05 且任务半区下降 ≤0.05 才替换 champion（任务半区是下限不是目标）；无阶段准则时退化为整体值 +0.05。E=3 的理由是最短能容纳“一次改进+其验证+一次重放”的窗口。内部再隔离：比较器看像素，决定方向与停止的上层只读结构化计数，任何一层都不能既解释图像又依自己的解释行动。从音视频视角，这实质是一个重放视频对的变更检测问题，且显式处理了录制时序抖动——“第二帧即消失的差异是时序，持续到末帧的差异才是 build”，等价于一条时间对齐鲁棒性判据；每条演示仅采样 16 帧供判读。

**高层导演接口。** 仅在饱和后触发。人与模型导演共用同一工具、同一预算（60 个动作 + 2 次 reset，观看免费），分别经浏览器与命令行客户端驱动同一会话对象；界面只给活游戏、任务文档与极简进展摘要（轮数、champion 时刻、功能/表现工作量分配），刻意不显示任何分数——分数回答的是“上一轮是否奏效”，是循环已在优化的货币，而导演要回答“游戏下一步需要什么”。Brief 为四字段：stage_objective、why_now、1–3 条方向性优先级、0–3 条保留项；被 planner、阶段排序、改进与美术提示词消费，且监视器的阶段准则重建时给 brief 准则最高权重。Alley Brawlers 案例中两位导演针对同一树（hash c12fe90b30b6c176）各写 brief，人用满 60 动作、Claude Opus 5 用 25，诊断完全不同（表现问题 vs 机制问题），后续分支分别到 62.0 / 61.5，无 brief 对照分支 60.0。

**验证审计。** 编辑前（40 个会话）：证据接地的目标筛选相对自由批判，grounded precision 从 58.6% 提到 72.3%，每轮无据目标从 1.93 降到 0.50；编辑后（48 个裁决轮）：基于重放的验证对失败改进的召回 76.2%、特异度 92.6%、平衡准确率 84.4%，而仅检查可构建的基线召回为 0%（编译通过完全看不见行为级失败）、平衡准确率 50%。裁决由 Claude Opus 5 独立完成、每例两次、分歧人工复核，与基准评测完全隔离。

**训练语料工程。** 底层语料为 1,998 个去重游戏（Godot 1,446 / Phaser 552），其中 1,070 个配生成轨迹，另含 910 棵完整试验运行树。规划不是自由书写：1,237 条从成品文件树蒸馏，870 条来自早期规划集且仅当所引路径全部存在于对应游戏时保留。改进轮仅在被独立编辑后验证判定达成目标时记正例（Godot 1,869/3,730，Phaser 144/273），负例发布而非丢弃。决策行采用 32k 预算的“固定前缀+近期完整决策+目标决策”窗口；全项目 diff 压缩为实际改动的源码 hunk（中位数约缩 48×）；冗长工具输出中段截断。污染控制：140 个基准任务 id 在构建期排除，事后对 2,511 个任务 id 并集复扫，13 个配置零重叠。已知录制缺口显式打标而非隐藏（284 条 Phaser 生成轨迹 20.2% 行受影响；某一 Godot 改进臂 31.7% 多轮行）。数据清洗：403,280 处路径改写、13,610 处署名脱敏、26,577 个配置字段中和、删除 26 条进程列表，由独立扫描器（47 种身份/凭据模式 + 植入泄漏自测，零命中）验证。微调配置：QLoRA（r=16，α=32，dropout 0.05，全部线性投影，rsLoRA），基座 4-bit NF4 双重量化，bf16 计算，最大上下文 57,344，Ulysses 序列并行度 4，4×H100 80GB，1 epoch，fused AdamW，lr 5e-5 余弦，warmup 0.03，wd 0.01。三个训练变体为嵌套语料 S1⊂S2⊂S3（1,294 → 1,602 → 2,111 行），消融差异可归因于新增阶段。

## 5. 消融要点

**全局监视与开发期缩放**（40 任务，Godot/Phaser × 强/弱初始化，30 轮预算下相对 P0 增益，三方法依次为 Play2Code / RSIGAME 无监控 / RSIGAME 有监控）：Godot 强初始化 −0.4 / +16.9 / +19.1；Godot 弱 +5.3 / +13.7 / +15.3；Phaser 强 +0.9 / +2.7 / +15.7；Phaser 弱 +7.0 / +10.0 / +11.3。局部循环单独已有大幅增益但轨迹波动，监视器通过保持最优版本把追加预算单调转化为质量；Play2Code 快速平台化且常回归。保持检查点紧密跟随各预算内 oracle 最优，防止后期编辑抹掉早期收益。

**停止参数 K**：K=1 最快停止但收益低，K=4 以更多轮次逼近固定预算得分，K=3 位于拐点——饱和感知停止以远少于固定预算的轮数达到可比质量。

**自适应方向策略**（16 对同基座游戏、30 轮、唯一变量是方向选择）：构建失败后下一轮转向改进的比例显著上升（论文报告约 +35 个百分点）；当视觉/艺术成为滞后维度时，自适应策略把艺术方向轮次占比从轮询的约 19% 提至 74%。63 次位置随机化的盲评配对中自适应获偏好 59%、轮询 37%，四维度净值优势 +6%～+21%。状态条件统计仅用于事后分析，不暴露给开发循环。

**验证门控**（见第 3 节审计数字）：编辑前过滤无据目标（58.6%→72.3% grounded precision，无据目标 1.93→0.50/轮），编辑后检出 76.2% 的失败改进与回归——两个方向的可靠性都来自“重放交互”而非源码或编译检查。

**训练数据消融**（Godot 一次性生成，140 任务）：BASE 37.07 → +GEN 41.45 → +GEN+PLAN 41.77 → +GEN+PLAN+IMPROVE 48.22。仅生成轨迹的增益维度不均；加入规划与验证改进轨迹后 Mechanics +14.9、Depth +14.1、Visuals +11.2、Art +6.5、Overall +11.1——规划/改进轨迹提供的可复用知识超出对成功成品的模仿。

**多阶段指导**：各阶段 champion 的盲玩配对显示后期阶段被一致偏好（stage2>stage1、stage3>stage2、stage3>stage1），指导可在饱和后反复打开新的改进空间（Wilson 区间较宽，作者如实标注）。

**案例给出的机制级证据**：Lawn Guardians——进展非单调（R6 美术轮、R18 反馈轮均降分且未被采纳），champion R12（61.7→86.1）被保持到 R21 饱和停止，省 9 轮；同时暴露两个失效模式：验证重放过短看不见真修复（R26）、官方 judge 会奖励遮挡玩场的美术（R27）；Play2Code 峰值 81.5、终值 65.7。Alley Brawlers——30 轮自主开发画出竞技场却把角色渲染弄坏，交付分恰好等于基座 56.6；“没人能赢”这一诊断只被实际玩了两局的导演产出，brief 分支 61.5/62.0 对无 brief 对照 60.0；第二份 brief 用 1.5 分换来了可读的攻防交互——可玩性与 rubric 得分的分离。Block Cascade——规格内全部机制首版即通，循环无可改进，R09 即停止并交付 R00（省 21 轮）；重启本身即 +12.8（对照分支同样到 50.0），brief 改变的是到达速度（第 6/9 轮 vs 第 12 轮）而非终点——指导价值可分解为“方向”与“重启”两个成分。此外，末轮改进大量落在帧采样评测覆盖不到的维度：hitstop、屏震、连击计数、专属音效替换 1.8 秒共用循环——音频部分任何帧级监视器/judge 均不可见。

## 6. 贡献与启示

**贡献**： 把 agentic 游戏开发重构为带显式控制结构的可控 RSI：局部证据接地循环 + 全局 champion 保持与饱和控制，并用 Play2Code/VibeGame 两个对照证明“迭代≠改进”、组织方式才是预算→质量转换率的决定项； 验证门控与演化检查表构成可审计的外部记忆，审计给出量化可靠性（失败召回 76.2%、平衡准确率 84.4%）； 打通训练无关→训练内化的连续谱，验证过的开发轨迹 SFT 进生成器（one-shot +11.1、token 降 11×），提出持续内化的闭环愿景； 评测方法论本身可复用：冻结 P0 克隆 + 匹配预算 + judge 全隔离 + 稳定性/自由游玩/跨 judge 三重稳健性检查。

**对音视频技术上下游的启示**：本框架的验证与监视层本质是视频理解模块——重放配对帧的变更检测、16 帧/演示的均匀采样、“第二帧消失即录制时序、末帧仍在才是行为”的抖动判别规则、以及跨 judge 绝对分仅 ρ=0.64 而序稳定的结果，对一切基于视频回放的自动化评测与游戏 QA（回归检测用前后帧对）都有直接参考价值。重放方差按游戏族的分解（证据到达时刻早晚，而非游戏快慢）提示：判据确定性到达的品类（rhythm/racing，中位极差 0）适合全自动视频回归，晚判据品类（sports 4.66、horror 3.37）需要更长或受控的重放。音频是明确盲区：案例终轮改进的一半是音频（配乐、逐事件音效），帧级监视器与 judge 均无感知，hitstop/屏震等“手感”属性也被 16 帧采样欠覆盖——含音频的多模态验证是该方法留给音视频研究的天然接口。上游看，AIGC 图像模型（Seedream-5.0-lite）作为资产生产者嵌入循环，“随项目发布但从未被引用的资产”（46 张图仅 4 张被用）与接线后（46→114 张被引用）的对比，给出“资产利用率”这一可操作信号。工程侧的成本结论同样重要：同一模型在不同 harness 下缓存命中率 94% vs 42%、账单差 8 倍，RSI 系统的成本核算必须落在 harness 缓存行为上。

**论文自述局限**：四维度不覆盖原创性、叙事质量、长期玩家粘性；实验限于可在实用预算内迭代开发的紧凑游戏；何时触发指导、指导量多少、人与模型指导的差异仍是开放问题；brief 追求的属性可能与 rubric 低相关（可读性提升 86.1→85.5 反而持平略降）。

## 7. 与其他论文的联系

- **paper:arxiv:2611.12109（SkillDuet）**：同属把 RSI 从上下文层推进到参数层的工作。RSIGame 用 2,013 轮验证改进轨迹做一次性离线 SFT，one-shot 37.07→48.22、生成 token 降 11×；SkillDuet 以响应反馈闭环协同演化 LLM 参数与外部技能库，实现技能级递归自改进。差异在于闭环性（RSIGame 的持续内化仅是愿景）与内化对象（全链路开发决策 vs 可复用技能条目）。
- **paper:arxiv:2611.11509（SimplEvo）**：RSIGame 训练无关一半的演化检查表（问题、优先级、验证结论跨轮累积）与 SimplEvo 的自写文本记忆+教训精炼同属“外部记忆自改进、免权重更新”设计空间（后者在 EBench 上 46.7%→81.7%）。RSIGame 进一步实证了该路线的失效边界——证据耗尽即饱和（Block Cascade 交付 R00 本身），并以参数内化补足，可视为对“记忆型 RSI 何时不够用”的领域化补充证据。
- **paper:arxiv:2611.13524（The RSI Tax）**：RSIGame 的成本口径（billable=未缓存输入+输出、cache 价计入成本、逐任务开发成本 $0.88–$1.75）与匹配预算协议正是 RSI 税度量所需的领域实例；“Play2Code 在强初始化上 +0.48 分耗 3.20M token”是高税低回报的典型样本，内化后 token 降 11×/2.6× 则给出降低 RSI 税的具体路径。
- **paper:arxiv:2611.10787（TRUST）**：两者处理同一问题——RSI 循环中的错误演化与回归控制。RSIGame 用经验机制（重放验证 76.2% 失败召回 + champion 保持 + 0.05/−0.05 手工采纳阈值），TRUST 用在线多重假设检验提供统计保证；RSIGame 监视器的手工阈值恰是 TRUST 式形式化保证可接入的位置。
- **paper:arxiv:2611.08946（Flex-RSI）**：同为固定预算下评估感知密集域的 RSI 能力（视觉/机器人 vs 可执行游戏）。RSIGame 的开发期缩放实验量化了预算→质量转换率随循环组织方式的变化（30 轮、Godot 强初始化：Play2Code −0.4 vs RSIGAME +19.1），其“同 P0 克隆、同每轮工具预算”的归一化比较范式与 Flex-RSI 的基准目标互补。
- **paper:arxiv:2611.10463（LongCapHarness）**：路线平行——不靠数据合成与后训练，靠递归修订 harness 实现自改进且成本减半。RSIGame 的训练无关路径验证了同一论点，其 SFT 路径则标定了 harness-only RSI 的饱和边界并给出越界手段，支持“harness 重组 + 选择性参数内化”的互补性解读。
