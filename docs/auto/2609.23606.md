# Beyond UV Mapping: Mesh Texture Compression via Surface-Aligned Texture Fields

> Jianqiang Wang, Junhui Hou, Siyu Ren, Weiyao Lin, Wenping Wang. *arXiv:2609.23606v2 (2026-09-20)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

带纹理三角网格是沉浸式媒体与空间智能的基础资产形式，其码率大头往往不在几何而在外观纹理。现行主流管线（MPEG V-DMC、AOM 网格编码、游戏资产管线）统一以 2D UV 图集承载纹理：曲面分 chart、展开、装箱后交给 HEVC/AV1/ELIC 等图像视频编码器压码流，或交给 ASTC/NTC 等格式压 GPU 显存。作者指出该范式存在两层结构性损耗：其一，chart 切割把曲面上相邻区域拆入不同 chart，chart 边界两侧本可互相预测的内容互不可见，削弱了 2D 编码器可利用的空间相关性；其二，装箱引入 padding，且 UV 坐标与映射索引必须显式传输/存储，在纹理码率降低或几何复杂的资产上这笔固定开销占比急剧放大（论文实测 AOM 数据集上 UV-Source/HEVC 的映射负载占比在低码率端高达 82%，随纹理码率上升降至 23%）。此外 UV 重参数化预处理代价高昂：UVAtlas 在 AOM 资产上约 1700 s/个。

已有 UV-free 纹理表示——mesh-attached（Ptex、Mesh Colors）、volumetric（octree texture、Shell Maps）、神经隐式——主要服务外观建模与创作渲染；其存储压缩尝试（3D Haar 子体积编码、SVDAG + Morton/Hilbert 序列化后接 2D 编码器）并不必然优于 UV 管线：序列化打乱相关性、显式索引引入额外开销，可能抵消甚至反超去掉 UV 映射的收益。由此作者确立核心论点：网格纹理压缩必须联合设计"纹理组织方式"与"编码工具的相关性模型"，具体路径是让网格曲面本身决定纹理属性存放位置与访问方式，即表面对齐的 3D 纹理场。该工作直接面向 MPEG 与 AOM 两套网格压缩基准，属于沉浸式媒体编码（音视频技术上游）中纹理表示层的重构。

## 2. 方法总览

**表示。** TexF 在网格规范化轴对齐包围盒上定义 K×K×K 体素网格，仅保留与网格曲面相交的"活跃体素"集合 Q，每个体素存纹理属性 t(q)（默认 RGB，可按通道扩展至 roughness/metallicity 等 PBR 材质），即 T = {(q, t(q)) | q∈Q}。因属性只挂在表面上，体素数随 K 近似二次增长（与 2D 贴图 texel 数同阶），以与 2D 纹理相当的采样量支撑 4K 及以上分辨率，回避稠密体积表示的内存爆炸。网格与场共享坐标系，曲面点无需中间参数化即可直接查询。

**构建。** 从 UV 纹理网格直接迁移：对曲面采样，重心坐标同时给出 3D 位置与 UV 坐标，UV 坐标查询源材质图，属性按 3D 位置写入对应体素（同体素内取均值）。反向亦可栅格化目标 UV 布局并在对应曲面位置查询场，烘焙回标准 UV 纹理，保持与既有渲染管线的兼容。

**可微渲染与逆渲染（IR）精化。** 渲染先光栅化网格得可见曲面位置 p，再在 p 的 2×2×2 邻域内对活跃角点做三线性插值（权重在可用体素上重归一化；无活跃角点时回退最近活跃体素），数学上类比 UV 渲染的双线性采样但在 3D 中进行。实现基于可微光栅化与稀疏网格插值算子，支持反向传播到体素属性。以源网格多视角渲染为参考，最小化 ℓ1 + (1−SSIM) 光度损失，在固定几何与体素支撑下优化 t(q)，补偿迁移与体素离散化误差；该目标同时用于后续精化压缩神经场。

**两条压缩通路共用该表示。** 码流压缩：复用既有 3D 属性编码器（主后端为不做微调的公开预训练 Unicorn，辅后端为 G-PCC RAHT），体素集合由解码端对重建网格执行同一体素化过程重建，纹理码流只携带属性，不传体素坐标也不传 UV；显存压缩：提出 3DNTC，将表面外观压入 INT4 量化的多分辨率哈希特征表加轻量共享 MLP，渲染时在曲面位置按需解码，无逐体素查找表。

## 3. 关键设计

**（1）以解码网格为共享边信息的隐式定位。** 编解码两端对重建网格执行相同体素化得到同一 Q，属性—体素对应关系无需任何信令，相当于把"表面到纹理的映射"完全外包给几何码流——UV 管线中必须显式传输的 UV 坐标/索引在 TexF 中为零。论文的负载分解表明这是低码率与复杂几何场景收益的主要来源之一（UV 映射在 AOM/HEVC 码流中占比 82%→23%，在 AOM/ASTC 显存中 53%→16%）。接口本身编码器无关：任何接受"坐标—属性"结构的点云属性编码器都可即插即用，表示可自动继承该方向的后续技术演进——这与 UV 管线中 HEVC→AV1→ELIC 的后端更替逻辑完全同构。

**（2）3D 原生属性编码。** Unicorn（多尺度神经变换 + 条件熵模型）直接作用于体素属性的 3D 原生邻域，使用公开预训练权重零微调，工程上零训练成本；G-PCC（RAHT 路径）作为传统后端验证增益不依赖单一编码架构。操作点：Unicorn 用 K∈{1536, 2048, 2560, 3584} 配 λ∈{1K–8K}，G-PCC 用 K∈{1024, 1536, 2048} 配 QP。

**（3）3DNTC 显存压缩。** 论文明确未压缩 TexF 的显存实现为每体素 3 字节 RGB 加 64 bit 查找键，高分辨率下依然可观。3DNTC 用两级空间下采样哈希网格（分辨率 ⌈K/sᵢ⌉，(s₁,s₂) 取 (6,12) 或 (4,8)；K 按源纹理最长边取 2048/4096；表容量 2¹⁴–2¹⁷ 项，随纹理面积最多扩 4 倍）存 INT4 共享潜特征（F=16–32 通道），配全资产共享的 FP16 MLP（隐层 64/48/32，hardGELU，线性输出层）。查询时对每级 8 个网格角点哈希取特征、三线性插值后跨级拼接为 Φ(p)∈R²ᶠ，再与 18 维位置编码 γ(p) 拼接，单次前向得颜色——先插值后解码，避免逐角点解码 8 次再插值。哈希寻址同时替代了显式查找键与逐体素索引；查询相互独立、无需顺序熵解码，满足随机访问。每查询算术成本 C = 144F + 6272 MACs（含潜特征插值），MPEG/AOM 平均 8.96/9.96 KMACs，与 NTC 的 8.28 KMACs 同量级，增量来自更宽解码输入与三线性插值。训练先用 100K 步 MSE 拟合精化后 TexF 的属性（训练中模拟 INT4 量化；batch 65,536/262,144 对应 K=2048/4096；Adam lr 潜表 0.1、解码器 0.005，余弦衰减），再用同一光度目标对真值多视角渲染做 100 次迭代精化压缩场本身。

**（4）图像空间监督的作用边界。** IR 在渲染域显式建模采样与插值行为，因而能补偿直接迁移误差。评估用 16 个 Fibonacci 球面正交视角（2048²）与训练用随机透视视角（1024²、45° FOV、方位角/正弦俯仰/距离分别均匀采样于 [0,2π)/[−1,1]/[1.2,3.0]，30 迭代 × 8 视角共 240 视角）在视角方向与投影上完全分离；LPIPS 与 3D-PSNR 的提升超出损失函数直接优化范围，说明是真实保真度改善而非对训练视角/指标过拟合。增益在低分辨率显著、4K 处趋于饱和（密集采样已高保真）。

## 4. 实验结果

**设置。** MPEG 网格压缩基准 8 个人体模型 + AOM 网格编码测试集 32 个资产（扫描物、动植物、DCC 创作、建筑），共 40 资产、2K–4K 纹理；AOM 几何显著更复杂（平均 410K vs 37K 面）。所有方法共用 V-DMC 无损编码的同一几何，仅比较纹理相关负载（UV 法含映射数据）。质量指标为 PSNR/SSIM/LPIPS（16 正交视角 2048² 渲染）+ 3D 点采样 3D-PSNR，率失效用 BD-BR（码流锚点 UV-Source/HEVC，显存锚点 UV-Source/ASTC），硬件 RTX A6000。码流操作点：HEVC QP 45–25、AV1 CQ 55–25、ELIC 质量 1–6；显存操作点：ASTC 块 12×12–5×5、NTC 1.11–5.00 bpp；UV 坐标量化 QT=12（2K）/13（4K）。

**表示保真度与构建效率。** 以实际 texel 数计量容量，TexF 在同等容量下保真度不低于 UVAtlas 重参数化纹理，IR 平均再提升 PSNR/3D-PSNR 1.4/1.2 dB。构建代价差距悬殊：

| 构建耗时 | MPEG 1K/2K/4K | AOM 1K/2K/4K |
|---|---|---|
| UV-Reparam（UVAtlas） | 97/109/113 s | 1674/1724/1716 s |
| TexF w/o IR | 0.04/0.14/0.43 s | 0.05/0.16/0.45 s |
| TexF w/ IR | 4.90/5.45/7.29 s | 5.37/6.75/9.83 s |

渲染吞吐（2048²）：TexF 在 MPEG 190–222 FPS、AOM 107–127 FPS，接近 UV 渲染的 227–231/135 FPS，满足实时。

**码流压缩（BD-BR，负为节省）关键行：**

| 方法 | MPEG PSNR | MPEG LPIPS | AOM PSNR | AOM LPIPS |
|---|---|---|---|---|
| UV-Reparam/HEVC | −28.2 | −27.3 | −45.4 | −42.1 |
| UV-Reparam/AV1 | −33.8 | −30.0 | −48.4 | −45.0 |
| UV-Reparam/ELIC | −32.8 | −25.2 | −52.4 | −47.1 |
| Serialized-Morton/HEVC | +111.9 | +54.6 | +20.8 | +35.0 |
| Serialized-Hilbert/HEVC | +77.6 | +28.8 | +4.9 | +12.1 |
| TexF/G-PCC | −32.8 | −52.0 | −55.1 | −68.0 |
| TexF/Unicorn | −46.7 | −45.5 | −63.3 | −70.1 |

TexF/Unicorn 相对锚点在 MPEG 节省约 46%–49%、AOM 53%–70%（四指标），全面超过含 AV1/ELIC 后端的最强 UV 配置；UV 重参数化本身带来 MPEG 27%–30%、AOM 42%–45% 节省，说明基线已充分优化。TexF/G-PCC 在 LPIPS 上尤其强（AOM −68.0%），多数情形与最强 UV 基线持平或更优，证明增益跨编码后端成立。序列化基线大幅劣化（Morton 在 MPEG PSNR +111.9%），说明"去 UV + 成熟 2D 编码器"本身不构成竞争力。时间上：TexF 预处理约 5–8 s（IR 主导，无 IR 时 <1 s），UV-Reparam 需 111–1716 s；Unicorn 编码（15.1/38.8 s）快于 HEVC（41.1/64.6 s），解码 8.1/20.0 s 略慢于 HEVC 的 6.7/10.5 s，ELIC 编解码最快。

**显存压缩（BD-BR 相对 UV-Source/ASTC）关键行：**

| 方法 | MPEG PSNR | MPEG LPIPS | AOM PSNR | AOM LPIPS | 帧时间 |
|---|---|---|---|---|---|
| UV-Source/NTC | −6.8 | +2.5 | −4.1 | −2.2 | 8.9/21.3 ms* |
| UV-Reparam/ASTC | +15.2 | +65.5 | +12.2 | +50.5 | — |
| Serialized-Morton/ASTC | +223.0 | +290.2 | +589.9 | +650.3 | — |
| TexF/3DNTC | −33.2 | −7.4 | −31.0 | −12.0 | 10.8/23.1 ms |

*NTC 用官方 SDK 渲染器测量，管线不同限制直接比较；A6000 无原生 ASTC 支持故未测。

值得注意的反转：码流场景有效的 UV 重参数化在显存场景全面变差（等 PSNR 显存多 12%–15%，重采样误差在固定码率格式下无法被相关性收益抵消）；NTC 在源图集上仅省 6.8%/4.1%。3DNTC 等质量省 33%/31% 显存，四指标平均全面占优。序列化 + ASTC 即使不计寻址开销也已劣于 3DNTC，计入 counted DAG 寻址（最低码率端占驻留内存 80% 以上、最高端约 50%）后差距达数百个百分点。3DNTC 每帧 10.8 ms（MPEG，93 FPS）/23.1 ms（AOM，43 FPS），其中属性解码 6.5/15.8 ms，实现随机访问实时渲染。代价在编码侧：每资产拟合约 17 min（MPEG）/28 min（AOM），对比 NTC 的 35 s（后者已用定制 CUDA 获约 10× 训练加速）。

## 5. 消融要点

- **IR 对码流作用有限且非单调。** 去掉压缩前 IR，TexF/Unicorn 四指标平均 BD-BR 变化 <2 个百分点；MPEG PSNR 上 w/o IR 反而 −51.7%（优于 w/ IR 的 −46.7%）——IR 提升输入保真度，但保住恢复的细节需更多比特，对码流 R–D 净效应混合。给 UV-Reparam/HEVC 加 IR 的辅助实验同样只获适度增益。IR 默认开启，预处理时间敏感时可省略。
- **IR 对显存是纯增益。** 3DNTC 在固定驻留尺寸下直接精化压缩场，相对未精化版本 PSNR BD-BR 再省 3.1%（MPEG）/10.5%（AOM），AOM 上 SSIM/LPIPS 亦显著改善。
- **资产依赖性有明确判据。** 定义 ρ_face = N_texel/N_face（源 UV 覆盖 texel 数/面数）：TexF 在 ρ_face ≲ 100 时优势大，高于此 UV 转强；40 资产中 TexF 码流 PSNR BD-BR 为负者 32 个、显存 30 个。失败集中于 5 个 DCC 创作动画资产（粗网格、UV 映射本就高效），如 Winter_girl（93K 面、4096×3510）码流 +34.7%、显存 +45.9%；成功案例如 Orbiter_space（150K 面）−46.6%/−10.2%。提示资产自适应表示选择。
- **UV 兼容路径近乎无损。** 解码后可选烘焙到新生成 UV 图集（不传生成 UV 数据与烘焙纹理）：两数据集平均 BD-BR 节省仅减少 1.4 个百分点，一次性转换 1.6 s（MPEG）/19.8 s（AOM），损失主要在高码率端 PSNR。
- **有损几何下增益保持。** 按 V-DMC CTC 中间几何码率点，TexF/Unicorn vs UV-Reparam/HEVC：MPEG PSNR −26.5%、AOM PSNR −18.0%、AOM LPIPS −34.3%（MPEG LPIPS −0.8% 基本持平）。
- **PBR 扩展可行。** 通道扩展后 3DNTC 联合压缩材质通道：WaterBottle 未压缩 TexF 50 MB（49.7 dB）压至 3.95 MB（47.7 dB），FlightHelmet 161 MB 压至 3.95 MB。共享体素网格亦可与 SDF 隐式几何耦合（Marching Cubes 后按顶点色渲染），在 MPEG 上保持对 UV 基线的压缩优势，但 PSNR/3D-PSNR 较默认管线下降。

## 6. 贡献与启示

贡献可归纳为三点：一是将网格纹理从 UV 图集迁移到表面稀疏体素场，用一个可微渲染器同时服务构建精化与直接渲染，使表示、压缩、渲染共享同一空间基底；二是证明该表示对码流（Unicorn/G-PCC）与显存（3DNTC）两类压缩机制同时有效，且接口编码器无关、可持续吸收 3D 属性编码的进展；三是给出资产特性驱动的 TexF/UV 相对性能分析（ρ_face 判据），把"哪种表示更好"转化为可测量的资产属性问题。

对编码研究的方法论启示：压缩增益并非来自"去掉 UV"这一动作本身——序列化基线共享了无 UV 的输入却大幅劣化——而来自纹理空间组织与编码器相关性模型的匹配；UV-Reparam 在码流（−28.2%）与显存（+15.2%）两个场景的表现反转进一步说明，表示选择必须与目标编码机制联合评估。"以解码几何为边信息免传定位/映射信息"的范式，对更广的 3D 媒体编码具有参考价值。

工程定位：码流路径零训练成本、秒级构建、编码快于 HEVC/AV1 实现，接近可部署；3DNTC 编码 17–28 min/资产，当前只适合离线资产准备，但逐查询算力与 NTC 同量级，且 NTC 定制 CUDA 实现 10× 加速的先例表明提速空间明确。局限（论文自述）：粗体素分辨率下近邻曲面区域落入同一体素/插值邻域造成属性混叠，需曲面结构感知的表示与插值；原生渲染缺乏成熟 UV 管线完整的纹理滤波功能栈。对音视频链路而言，该工作落在 MPEG V-DMC 与 AOM 静态网格编码的纹理轨道上（纹理常为网格码率大头），显存路径直连游戏/VR 实时渲染，UV 烘焙回退保证了与既有解码/渲染生态互通；作者展望几何—纹理联合率分配与共享渲染目标的联合优化。

## 7. 与其他论文的联系

- **OctMesh（arXiv:2610.04281）**：同为三角网格压缩但组件正交——OctMesh 在共享八叉树层次上无损压缩几何与连接性（较 V-Mesh 省 12.8%），TexF 则假设几何由既有网格编码器（V-DMC）处理、专攻纹理轨。二者的耦合点是 TexF 的体素支撑恰由解码网格导出，几何码流的保真度直接决定纹理定位（论文已验证有损几何下增益保持）；"八叉树无损几何 + 表面对齐纹理场"是自然的完整资产码流组合。
- **3DGS 双阶段 Morton 排序（arXiv:2609.29041）**：该文将 3DGS 属性经 Morton 排序转为强局部相关的 2D 特征图再交给标准视频编码器，正是 TexF 中 Serialized 基线所代表的"序列化 + 2D 编码"范式。TexF 对该范式给出强否定证据：同样的无 UV 输入下 Morton/HEVC 在 MPEG PSNR +111.9%、序列化 + ASTC 显存 +223%~+650%，主因是相关性被打乱与 DAG 寻址开销。对照差异可解释：3DGS 属性随高斯散布、缺乏即插即用的 3D 属性编码后端，序列化到 2D 为正收益；TexF 的支撑是表面对齐稀疏体素、可直接复用 Unicorn/G-PCC，3D 原生编码更优——组织方式的选择应以"是否存在与数据支撑匹配的成熟编码后端"为判据。
- **CASR（arXiv:2609.37328）**：范式同构——都在预训练压缩骨干上做逐内容神经过拟合（CASR 用 LoRA 对超分网络逐视频序列过拟合作 VVC 后滤波；3DNTC 逐资产拟合潜表并以 IR 精化压缩场），均验证内容自适应优于固定模型且开销可控。差异在作用位置与码流形态：CASR 是标准码流之外的解码端增强、LoRA 增量经 NNR 压缩信令；3DNTC 的量化潜表本身即负载，IR 属编码端精化。
- **体积视频属性运动估计（arXiv:2607.03576）**：同属 G-PCC 族的 3D 属性压缩；该文以图上帧间运动估计与免插值细化处理动态点云（平均省 55.3%），TexF 处理静态网格表面纹理的帧内相关。二者互补，动态 TexF 的时域相关利用是本文未触及的开放方向。
