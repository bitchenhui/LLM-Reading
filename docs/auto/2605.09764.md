## 1. 背景与动机

LLM 引导的进化搜索（FunSearch / AlphaEvolve 范式）已在数学发现、代码优化、启发式设计、系统研究与提示词优化等“易验证、难搜索”领域证明了有效性。该范式的成本结构是：用户给出问题定义与打分函数，进化循环用 LLM 做候选解变异、评估并维护解数据库。但现有框架的单次运行成本可达 $30，且高度依赖 Claude Opus / Gemini Pro 一级的前沿模型——论文引用了 OpenEvolve、ShinkaEvolve、AdaEvolve、EvoX、GEPA 等框架的公开成本数据作为佐证。这种门槛限制了范式在研究者群体中的普及。

作者的核心论点是：这种对前沿模型的依赖并非范式的固有属性，而是搜索架构投资不足的产物。原文给出的证据是：初代 FunSearch 在未使用前沿规模 LLM 的情况下即产出 cap set 改进等数学成果。作者将现有框架的低效拆解为三条正交的成本轴：

1. **每次评估轴（per-evaluation）**：解数据库无法在运行全程保持解多样性。现有框架几乎都从单一种子程序出发（论文点名 OpenEvolve、ShinkaEvolve、AdaEvolve、GEPA 均如此），早期预算浪费在逃逸单一吸引盆地上，后期多样性靠前沿模型调用、岛屿机制、新颖性拒绝、嵌入过滤器或 LLM 裁判等事后修补机制恢复。
2. **每美元变异轴（mutations per dollar）**：盲目使用大模型——变异调用表面同构（父代进、子代出），但工作量分布极不均衡。大多数调用是局部精修（调常数、换数据结构、内联辅助函数），小模型足以胜任；少数是改变算法高层形态的结构重写，才真正需要规模带来的先验覆盖。现有框架对两者统一支付前沿模型价格。
3. **每次 rollout 轴（per-rollout）**：全量评估浪费 rollout。提示词优化中每个候选提示需在验证集上做完整 rollout，GEPA 一类方法将预算的大头花在重复验证上。

LEVI 的赌注是：更强的搜索架构可以替代甚至超越更大的 LLM。需要强调的是，该工作与音视频技术的关联属于上下游传导型：其评测的 ADRS 系统研究基准中，EPLB（MoE 推理的专家并行负载均衡）、LLM-SQL（面向 LLM 推理的表格行列重排、以提升 KV cache 前缀复用为优化目标）、Prism（多 LLM serving 的模型放置）三题直接作用于音视频场景下多模态/生成模型的推理服务栈——即音视频应用所依赖的 LLM 推理基础设施的调度与缓存层。LEVI 提供的廉价自动化启发式发现手段，可降低这类推理侧系统策略（负载均衡、缓存友好的数据布局）的优化成本，属于“用更便宜的搜索架构为音视频后端系统研究降本”的间接关联。

## 2. 方法总览

LEVI 是一个 harness-first（先行投资于执行框架）的进化框架，针对上述三条成本轴各设一个组件，三者在同一初始化阶段完成标定，随后进入异步 AlphaEvolve 式主循环：

**Phase 1（种子与标定，Algorithm 1）**：大模型 Ml 生成 n_s 个结构互异的种子（每个种子以已有种子为上下文、显式要求算法范式不同，失败与报错信息作为反馈传入），小模型 Ms 将每个种子扇出 n_v 个变体；全集评估后，这批数据同时完成三件事：(a) 用 Welford 在线统计 + sigmoid 变换标定描述符几何，构建 K 个质心的 CVT-MAP-Elites 档案并插入初始解；(b) 若提供发现集 D，构建 m×n 标定矩阵 M（种子×样例的得分），贪心列子集选择抽出 K_proxy 个样例构成代理基准，将打分函数限制在代理上；(c) 弱但结构独特的种子被保留，用于扩展描述符观测范围。

**Phase 2（进化主循环，Algorithm 2）**：W 个异步 worker。默认路径：softmax-over-scores（温度按 worker 区分）从档案精英中抽父代，小模型做单点定向编辑；触发路径（每 τ 次评估或停滞时触发 punctuated equilibrium）：对已占据质心的行为向量做 k-means（k=3），取每簇最高分精英作为互相远离的代表集合，大模型被要求提出不属于任何现有家族的候选；接受后由小模型扇出 3 个变体。子代评估后 TRYINSERT：更新在线统计、映射到最近质心，仅当该胞空或得分更高时替换。

三条设计轴的耦合关系是理解 LEVI 的关键：强档案多样性让小模型的坍缩倾向变得无害（近重复输出落入已占据胞被直接丢弃，坍缩压力转化为冗余而非档案漂移），大模型的范式转移为档案注入真正的新家族，代理基准则在 rollout 侧压缩验证开销。三者各自针对一条成本轴，但相互放大。

## 3. 关键设计

### 3.1 CVT-MAP-Elites 档案：种子引导标定 + 混合描述符

档案采用 CVT-MAP-Elites（质心 Voronoi 划分替代规则网格），继承其在高维描述符空间中无指数胞数爆炸的优势。LEVI 在 QD 谱系上添加两个工程件：

**引导式标定**：种子分布估计出各描述符维度的 z-score 与 sigmoid 变换，将值域压入 [0,1] 后放置 CVT 质心；新候选到来时在线更新统计，使描述符几何随新行为体制的出现自适应。这解决了 MAP-Elites 在描述符分布未知时边界设置随意的问题——种子 pass 的成本被复用为标定数据。

**混合输入/输出描述符族**：输入侧描述符直接从代码计算（代码长度、圈复杂度、循环数、算子数等 AST 特征），适用于行为输出稀疏的场景；输出侧描述符从执行行为计算（运行时、数据集上的逐实例得分剖面），能暴露样例间权衡，尤其适合提示词优化。现有框架各自锁定一族——OpenEvolve/ShinkaEvolve 用输入侧，GEPA 通过逐实例 Pareto 前沿隐式用输出侧——LEVI 允许任意混合。实测配置（附录 Table 4）显示按问题结构选配：Spot-S 用"tight/loose deadline 得分”两列做 score-key 描述符，Cloudcast 用 5 列逐云成本，Spot-M 甚至为状态机结构定制了 5 个 AST 提取器，而 Txn Sched 不用任何 AST 描述符。

关键设计哲学：探索/ exploit 由采样器负责，多样性由档案结构强制执行——两者解耦。插入时保多样性（而非事后修补）是 LEVI 与岛屿/新颖性过滤器路线的根本区别。

### 3.2 角色感知路由：局部精修 vs 范式转移

约 90% 的变异调用路由到小模型（实验中为 Qwen3-30B-A3B，配合 {0.3, 0.7, 1.0, 1.2} 四档 softmax 温度）。小模型易坍缩到常见模式的弱点由档案吸收。约 10% 的范式转移调用路由到大模型（Gemini Flash 3），且其提示结构本质不同于普通变异：不是“改进这个父代”，而是把多个互相远离的档案簇代表一起作为上下文，要求提出不属于任何家族的候选——模型操作的是种群的结构而非单个父代，其角色是扩展值得占据的胞集合而非改进已占据的胞。附录 G 的 EPLB 精英（SIBP，谱启发均衡划分：sqrt 阻尼的副本分配 + 互质步长的循环锯齿形物理布局）是这条路线的产物——三个 no-large-models 种子全部收敛到贪心装箱家族，而范式转移发现了结构不同的家族。

### 3.3 秩保持代理基准

初始化阶段用种子×发现集的标定矩阵 M，贪心前向选择大小为 K_proxy 的子集 S，边际得分：

score(j|S) = λr·R(S∪{j}) + λs·A(S∪{j}) − λc·C(j,S)，固定权重 (0.5, 0.5, 0.15)。

三项的机理：**秩忠实度 R** 奖励代理诱导的候选排序与全集排序一致的子集（度量上，双侧平局计为一致、单侧平局部分计分、反序计为不一致）——这直接匹配进化选择真正消费的信号：选择只需要“选优弃劣”，不需要每个个体的精确得分。**分离度 A** 用标定候选上列标准差的平均归一化值，惩罚所有候选表现趋同的样例（有代表性但无选择信号）。**冗余度 C** 用平均绝对 Pearson 相关惩罚与已选样例高相关的候选列。附录 I 的消融验证了目标设计的必要性：在 24 提示×150 问题的 IFBench 得分矩阵上（60 次随机划分），CSS+mean 在每个等成本轮廓上压制 k-medoids+加权均值与随机子集+ridge 两类基线，峰值 Spearman ρ 分别为 0.70 / 0.40 / 0.07；固定约 2,500 次 LLM 调用预算（N_init=5, K_proxy=35）下为 ρ≈0.61 / 0.31 / 0.04。ridge 崩溃的原因是 K_proxy 个自由权重由 ≤15 个标定样本欠定；k-medoids 形式正确但目标错误——选了“有代表性”的问题却没优化“候选排序信号”。

**工程启示**：这个秩保持代理基准的适用条件在论文中写得很清楚——只要能拿一批初始标定候选在更大样例池上评估即可构造，本质是把“验证集压缩”问题转化为“列子集选择”问题，凡 rollout 成本主导的场景（如音视频链路中需要对大量测试片段做端到端评估的策略调优）均可类比迁移。

### 3.4 编排细节

默认配置（附录 B）：4 个 LLM worker + 4 个评估进程并行、eval_timeout 60s、max_tokens 16,384、单父代+1 个 inspiration（20% 概率丢弃）、punctuated equilibrium 每 10 次评估触发一次（k-means k=3、每触发产 3 个变体，实际各基准按预算松紧在 5–18 区间覆盖 interval）、每 50 次评估注入一次 meta-advice（400 token）。成本核算基于 OpenRouter 牌价（附录 Table 6）：Qwen3-30B-A3B 输入 $0.09/输出 $0.30 每百万 token，Gemini 3 Flash 为 $0.50/$3.00——两档模型输出价差 10 倍，这是路由收益的经济学基础。

## 6. 贡献与启示

**核心贡献**是把“进化搜索成本”显式分解为三条正交轴（每次评估、每美元变异、每次 rollout），并证明三者均可由 harness 侧组件而非模型规模解决——七题中六题以 3.3–6.7× 更低成本超越前沿模型已发表结果，受控同模型对比下最高 15× 样本效率。三条轴的解法（CVT-MAP-Elites + 种子标定、角色路由、秩保持代理基准）均为可独立采纳的工程组件，且代理基准选择被验证为通用技术（附录 I）。

**对实践的启示**：（1）模型分配应条件化于变异角色而非全局统一——何时需要大模型是问题体制的函数（局部精修主导 vs 结构跳跃需求），EPLB 与 Txn Sched 的对照给出了判断依据（档案家族数、精英结构同一性可作先导指标）；（2）“选择只需要排序信号”这一观察将验证集压缩与列子集选择等价起来，rank faithfulness 目标优于代表性目标（k-medoids）与回归式预测（ridge）；（3）多样性应在插入时由档案结构强制，而非事后修补——且“档案更宽”不等于“更好”，no-boot 变体的宽档案充斥低分解。

**局限性**（论文自陈）：成本从前沿调用转向更多次评估，评估廉价时（多数系统基准）有利，单次评估数小时的场景（如模型训练）不划算；未将 wall-clock 效率作为独立轴研究；仍保留小部分前沿模型调用，纯廉价开源模型体制是未决问题。

## 7. 与其他论文的联系

- **paper:arxiv:2610.35077｜FrugalEvo**：最直接的同类工作——同为“LLM 进化搜索降本”命题，FrugalEvo 的方案是强 LLM 出策略、廉价 LLM 写代码的分工，与 LEVI 的角色感知路由（小模型做局部精修、大模型做范式转移）在“按角色分配模型档次”这一核心思想上同构；差异在于 LEVI 进一步将成本分解到评估轴（档案）与 rollout 轴（代理基准）两条 FrugalEvo 未覆盖的维度。
- **paper:arxiv:2609.25510｜Hill Sampling**：构成方法论上的直接对照——Hill Sampling 主张冻结 LLM 反复采样并以当前最优为条件即可在测试时超越进化搜索与测试时训练，即“不需要更复杂的搜索架构”；LEVI 则主张“更强的搜索架构可替代更大的 LLM”。两者共同指向同一结论的不同侧面：LLM 搜索的成本效率瓶颈更多在预算分配策略而非模型规模本身，但给出的解法方向（更简单的采样 vs 更结构化的档案/路由）相反，适合作为互为基线的参照系。
- **paper:arxiv:2608.12522｜ε-MemEvo**：互补性关联——ε-MemEvo 解决跨任务迁移（成功策略存为任务无关记忆、门控注入），LEVI 解决单任务内的三条成本轴；LEVI 的角色路由与代理基准组件理论上可与 ε-MemEvo 的记忆迁移叠加（例如用历史家族作为种子 pass 的先验，进一步摊薄初始化成本），但论文本身未做跨任务实验，此为组合方向而非已验证结论。
