# Promptbreeder: Self-Referential Self-Improvement Via Prompt Evolution

**领域定位说明**：本文属 LLM 提示工程 / 进化计算交叉方向，非音视频核心大类。以下按提示优化领域自身标准评估，并在第 1、6 节显式梳理其与音视频技术链路（多模态大模型调度、内容审核、字幕与元数据管线）的上下游关联。

## 1. 背景与动机

提示词已实质上成为基础模型的“控制面”：CoT、Zero-shot CoT、Plan-and-Solve（PS/PS+）等策略对推理、多模态处理与工具使用能力有显著影响（论文引 Wei et al. 2022；Yang et al. 2023b 即 MM-ReAct；Wang et al. 2023d 等）。但所有这些策略都是手工设计的，而 prompt 措辞的微小差异即可显著改变效用（Madaan & Yazdanbakhsh 2022），因此手工策略几乎必然次优。自动化的第一次尝试是 APE（Zhou et al. 2023）：用生成 prompt 产出候选、用变异 prompt 迭代改良，但作者观察到“三轮选择后质量趋于稳定、收益递减”，从而放弃了迭代式搜索。这一“收益递减”正是本文的切入点：问题的本质不是搜索轮次不够，而是**多样性坍缩**——解法是把多样性维持机制（进化算法 + 显式多样性算子）引入 prompt 搜索。

第二个动机来自自指自改进谱系。Schmidhuber 一系（1990/1993/2003）主张“神经网络的程序就是其权重矩阵”，进而让网络修改自身权重乃至“修改权重的方式”；Irie et al. 2022、Kirsch & Schmidhuber 2022 沿此推进。但参数级自改进需要额外参数修改全部模型权重，随模型规模增长不可扩展，且对 API 封装的模型完全不可行。本文的关键迁移是：**把 prompt 视为 LLM 的“程序”**，让 LLM 修改 prompt，同时修改“修改 prompt 的 prompt”——自指改进的基底从权重空间换到自然语言空间，零参数更新。与并行工作 OPRO（单一固定变异 prompt、固定小训练集评估）和 EvoPrompt（固定变异/交叉 prompt、手工初始种群）相比，Promptbreeder（PB）的差异点在于：mutation-prompt 本身在线进化、上下文也参与进化、以及系统性多样性维持。

对音视频交叉方向的读者，这篇论文的动机有两点直接关联：其一，多模态大模型的推理链路（视频问答、描述、工具调度）同样由 prompt 驱动且同样对手工措辞高度敏感，PB 提供的是一条免训练、可直接作用于 API-only 前端模型的自动化路径；其二，其 ETHOS 仇恨言论分类实验（见第 4 节）示范了在“审核规则难以言明”的任务上，进化式 prompt 归纳可显著超过人工规则，这对音视频内容审核（语音转写文本、弹幕、评论的多标签分类）是可迁移的范式。

## 2. 方法总览

PB 维护三层语言对象：

- **task-prompt P**：条件化 LLM 上下文的字符串，置于输入 Q 之前；
- **mutation-prompt M**：指导 LLM 改写 P 的指令，变异操作定义为 P′ = LLM(M + P)；
- **hyper-mutation prompt H**：指导 LLM 改写 M 的指令，M′ = LLM(H + M)。

对 M 的进化即“改进改进方式”，构成自指闭环。**演化单元**由两个顺序应用的 task-prompt（沿用 PS 的两段式结构：P1+Q 生成中间推导，推导+P2 生成最终答案）、一个 mutation-prompt（与 task-prompt 一一绑定）组成；few-shot 场景下再加 2–3 个曾产出正确答案的 working-out 作为 context。

选择框架为二元锦标赛遗传算法（microbial GA，Harvey 2011）：随机配对两个个体，取 fitness 较高者，变异后覆写败者。**fitness 定义为从整个训练集随机抽取的 100 个 Q&A 对上的准确率**——注意是每次评估重抽样，而非 APE/OPRO 的固定小训练集，这本身是一种抗过拟合到特定批次的设计。运行规模：种群 50，通常 20–30 代，约 1–2k 次 fitness 评估（附录 J.2）。

初始化由问题域描述 D（如 GSM8K 的 "Solve the math word problem, giving your answer as an arabic numeral"）拼接一个随机抽取的 mutation-prompt 与一个随机抽取的 thinking-style（认知启发式文本，共 39 条，含 "Let's think step by step"），加上 "INSTRUCTION:" / "INSTRUCTION MUTANT=" 控制串送入 LLM 续写，得到初始 task-prompt。每个单元做两次，得到两个初始 P。

实现上 LLM 以三种角色采样（附录 J.2）：**Redescriber**（生成/变异 prompt，最多 50 token，温度从 U(1.0, 2.0) 初始化且作为超参随演化调整）、**Inducer**（用 P1 生成中间推导，最多 30 token，温度 0）、**Evaluator**（用 P2 出最终答案，最多 5 token，温度 0）。温度演化采用 population-based-training 式机制：每次复制事件对 Redescriber 温度加 U(−0.2, 0.2) 扰动。

## 3. 关键设计

九个变异算子分五类，每次复制事件以均匀概率选用其一。设计理念来自洞察学习研究：多样化的表征重描述是问题求解的关键（Öllinger & Knoblich 2009），九算子本质上是用自然语言重建这一过程。

**（1）直接变异**。零阶：D 拼接 "A list of 100 hints:" 取首条生成 hint 作为新 P，完全不依赖任何父代——类比课程学习中的均匀重采样，当进化发散时提供“回到问题本源”的锚点。一阶：M + P 送 LLM 得 P′，是标准无性变异，也是遗传算法的核心操作。

**（2）分布估计（EDA）类**，条件于种群而非单亲：
- *EDA Mutation*：将当前种群 prompt 列表送 LLM 让其续写。列表先经 BERT 嵌入余弦相似度过滤（相似度 >0.95 的个体剔除，quality-diversity 思想），随机排序，且**不给 fitness 数值**——预实验发现 LLM 无法理解这些数值，反而退化为直接复制列表条目（作者注明这与 Mirchandani et al. 2023 的发现相反，留作 future work）。
- *EDA Rank & Index*：按 fitness 排序列出 prompt，但前缀文字谎称列表为“降序”且末位最优，实际是升序。这是一个刻意利用 LLM recency bias（Liu et al. 2023）的对抗性设计：模型倾向于模仿列表尾部条目，谎言迫使这种模仿偏向低 fitness 端，从而提升外推多样性。
- *Lineage Based Mutation*：向 LLM 提供该单元历代精英的时间序列（表头 "GENOTYPES FOUND IN ASCENDING ORDER OF QUALITY"），期望模型沿“坏→好”的梯度方向外推——比当前种群快照信息量更大的进化轨迹信号。

**（3）超变异（演化“演化能力”）**：零阶超变异用 D + 随机 thinking-style 生成全新 M；一阶超变异用固定 H（"Please summarize and improve the following instruction:"）改写 M 得 M′，随后 M′ 立即作用于本单元的 task-prompt，其效果一次性传导到下游 fitness。这使变异算子本身与被变异对象同池接受选择压力，是自指闭环的工程实现。

**（4）拉马克变异**：用成功的表型反推基因型——把一条曾得到正确答案的 working-out 与模板 "I gave a friend an instruction and some advice. Here are the correct examples of his workings out … The instruction was:" 拼接，让 LLM 逆向归纳出 task-prompt。与 APE 的指令归纳同构，作者强调其价值在**问题域描述缺失、不足或误导时**（第 5 节 ETHOS 压力实验将验证这一点）。

**（5）交叉与上下文洗牌**：变异后以 10% 概率按适应度比例选择从其他个体换入 task-prompt（mutation-prompt 不交叉）；few-shot context 池只收录正确 working-out，池满后每次在新批次上评估完以随机替换一条的方式更新，另以 10% 概率触发整个 context 列表重采样。

**多样性维护三机制**（系统陷入局部最优时启用）：prompt 前部拼接约 50 字符的随机字符串；基于 BERT 相似度的 fitness sharing（Shir & Bäck 2005 的 niching）；以及前述 Redescriber 温度演化。

值得记录的两点机制性观察：其一，附录 F 明确指出 PB 的**非自指之处**——它发明新的变异生成方式，但不发明新的评估方式，fitness 函数始终外部给定（对比 Jaderberg et al. 2017b 的辅助任务自生成）；其二，作者讨论了递归 prompt 的病理学：无约束的自反馈会脱轨或陷入吸引子，更高采样温度有利于逃逸吸引子——这解释了温度为何要作为可演化超参而非固定值。

5. **APE 指令归纳 24 任务**：PB 所用 PaLM 2-L 未做指令微调，仍在 21/24 任务上 match or surpass APE（text-davinci-002），最高提升达 21%（如 Synonyms：APE few-shot 14 → PE 43）；另一个对照是把 PB 换成 APE 的初始化与变异 prompt，多数任务大幅退化（如 First Letter 100 → 1），说明增益主要来自 PB 的进化机制而非模型本身。

## 5. 消融要点

**算子有效率**（GSM8K，Table 8，指标为该算子产出后代 fitness 超过父代的比例）：

| 变异算子 | 产出更优后代比例 |
|---|---|
| Zero-order Hyper-Mutation | 42% |
| Lineage Based Mutation | 26% |
| First-order Hyper-Mutation | 23% |
| EDA Rank & Index Mutation | 12.7% |
| Direct Mutation | 12% |
| EDA Mutation | 10.7% |
| Lamarckian Mutation | 6.3% |

自指类算子占据前三位中的两席（42% 与 23%），“改进改进方式”并非概念装饰而有实测增益。值得注意的是 Lamarckian 均值最低（6.3%）——但其价值在特定条件下才激活（见下）。

**进化出的最优 mutation-prompt**（GSM8K，Table 7，得分为其应用后产出更优 task-prompt 的概率）：榜首是 "Please summarise and improve the following instruction"（24.13%）——这正是一阶超变异的固定 H 被进化重新发现并固化；其余高分项（"Simplify this instruction by breaking it up into separate sentences…" 17.8%、"As a really good teacher, explain the instruction, as if you are explaining it to a child" 16.2%）共性是**简化、分解、教学式改写**。自指进化的收敛方向与人类 prompt 工程直觉（分解 + 循序善诱）一致。

**自指组件消融**（附录 L，种群 10、200 次评估、与同规模完整算法对比，Figure 4）：逐项移除超变异、Lamarckian、thinking-style 引导的初始化重描述、随机初始 mutation-prompt，在全部 7 个数据集上几乎都有害；**收益最大的单一组件是初始化阶段的 task-prompt 重描述**。唯一例外：GSM8K 上初始化时随机抽取 mutation-prompt 反而有害——作者给出的图像级数据显示该消融项在该数据集为正向偏移。

**欠规格压力测试**（ETHOS，问题域描述换成空泛的 "Solve the Problem"）：完整 PB 81.6%；移除 Lamarckian 算子跌至 **64.6%（最大退化项）**，验证了 working-out 反推 prompt 的价值集中在描述缺失/误导场景；同时移除随机初始 prompt、随机初始 mutation-prompt、超变异（只留 context 变异）→ 68.7%；仅加回在线变异 → 70.4%；再加回随机 mutation-prompt → 73.7%。各算子间存在明显互补，无单一银弹。

另一处值得工程注意的退化观察（附录 J.5）：few-shot 进化中 **context 逐渐主导 fitness，task-prompt 漂移成无意义字符串**（如 ADDSUB 进化出 "The mutant" / "mutant" 这类 prompt 仍伴随高分 context 存活），即进化压力在 few-shot 下主要作用于示例而非指令。

## 6. 贡献与启示

**核心贡献**（按论文自述）： 提出自指自改进机制——同时进化 task-prompt 与 mutation-prompt； 在常用算术/常识推理基准上超越 CoT、PS+、APE、OPRO 等 SOTA prompt 策略； 对各自指组件的贡献做了系统消融。

**方法层启示**： 收益递减的正确解法是显式多样性机制（重采样锚点、相似度 niching、温度演化）而非更多选择轮次； LLM 作为变异算子可用但有明确短板——无法消化数值 fitness，需要 Rank & Index 这类把选择压力编码进文本结构（甚至说谎）的迂回设计； 进化产物与语义质量解耦（`SOLUTION"`、日期串、经文段落均有效），提示 prompt 搜索地形的非语义结构值得专门研究； 成本结构：每 run 1–2k 次 fitness 评估 × 每次 100 题 × 二段式推理，外加种群维护——免训练的代价是可观的推理算力，工程上需权衡“一次性进化 + 零成本部署”与“每次调用多付 token”的摊销曲线。

**对音视频交叉方向的映射**： ETHOS 范式直接可迁移至音视频内容审核：转写文本/弹幕/评论的仇恨言论与多标签分类同样是“规则难以言明、但有可自动判分的历史标注”的任务，PB 证明了欠规格描述下 Lamarckian 归纳可补救 17 个百分点量级的差距（81.6 vs 64.6 的口径）； 指令归纳 24 任务覆盖翻译、情感分析、句相似度——正是字幕生成、多语种配音、元数据抽取管线的原子任务，PB 的 few-shot context 进化展示了“示例比指令更决定性能”的这一管线上可资利用的性质； 零参数更新意味着该机制可原样套用于 API-only 的多模态大模型（视频问答、时序定位、工具编排），前提仅是能构造可自动判分的训练批——论文自身引用 MM-ReAct 与 Describe-Explain-Plan-Select 佐证 prompt 对多模态与 agent 行为的影响，机制上是同构的。局限亦需正视：prompt 拓扑固定（两段式不变）、评估方式不自指（fitness 外部给定）、进化结果跨模型/跨域迁移性未验证、100 样本批的 fitness 噪声无任何统计控制。

## 7. 与其他论文的联系

相关清单呈现一个清晰的递归自改进研究簇，PB 是其中 prompt 空间分支的奠基工作，可按基底选择与安全保障两条轴组织：

**基底谱系的两端与中间地带**。PB 论文明确论证参数级自改进不可扩展且对 API 模型不可行，从而选择自然语言基底；WeightLoop（arxiv:2611.07319）恰好走向另一端——让 LLM 生成有界参数编辑程序、用实验反馈改写已部署权重，无需重训练即可反复自改进。两者构成“prompt 空间 vs 权重空间”两个极端，而 SkillDuet（arxiv:2611.12109）以响应反馈协同 LLM 参数更新与外部技能库演化，正是对这两个极端的折中，其技能条目对应 PB 的演化单元（task-prompt + context），可视为对“纯外置基底收益上限”的回应。

**安全保障缺口**。PB 的 fitness 是 100 样本批上的准确率，无误差控制，伪适应度可被锦标赛选择固定——TRUST（arxiv:2611.10787）用在线多重假设检验为 RSI 控制错误进化率并提供统计保证，直接填补这一缺口。FGSE（arxiv:2611.14326）则将经验教训作为可证伪假设、经三类探针验证后方写入记忆，对照关系非常具体：相当于给 PB 的 Lamarckian 通道（正确 working-out 直接反推 prompt 入库、无任何门控）加装 falsification gate。

**垂域实例化**。RSI-PDEbench（arxiv:2611.14949，PDE 求解）、InfraRSI（arxiv:2611.11558，分布式训练基础设施）、LongCapHarness（arxiv:2611.10463，长上下文推理）、AutoTavern（arxiv:2610.33845，自主构建炉石战棋 AI）共同把“可自动判分的任务 fitness 驱动递归改进”这一 PB 核心环路落到具体垂域；与 PB 的差异在于进化对象换成了技能、基础设施配置、能力挂接策略或整套模拟器与代码。其中 AutoTavern 的开放式自主构建与 PB 结论中设想的 self-play Socratic 对话同属 open-endedness 谱系——PB 自己承认其“思想的拓扑固定、只改内容不改算法”，这一自我批判正是后续各垂域工作突破的起点。
