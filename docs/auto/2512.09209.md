## 1. 背景与动机

论文切入 LLM 驱动的自动算法设计（AHD）这一脉络。EoH、FunSearch、ReEvo、AlphaEvolve 等框架已在 TSP、CVRP 等经典问题上超越人工设计并刷新 SOTA，但作者从实验中归纳出两个被忽视的失效模式：

其一，在约束复杂或问题新颖的任务上，这些框架生成的纯在线构造式方法经常失效，被迫回退到群体智能算法的搜索策略甚至直接调用求解器。作者据此论断：完全依赖在线构造不现实，基于种群的搜索机制仍是刚需——这构成其“群体智能优化为自动设计提供更一般化、更有原则性基础”的核心论点。

其二，主流 AHD 框架的 prompt 模板完全由人工固定，每次交互只有代码部分在变。由于不同 LLM 对措辞偏好差异显著，静态模板实质上封顶了对模型能力的榨取。已有的 prompt 进化工作（PromptWizard 的整段 prompt 批评-合成迭代、TextGrad 的文本梯度、GradPromptOpt 的内部梯度诊断）面向的是任务 prompt，而非嵌入在进化循环内部的算法设计 prompt，二者场景不同。

群体智能与 LLM 结合的先行工作（作者课题组 CEC 2025 的 LLM 可定制烟花算法 FWA，以及多模态 LLM 决策方向）同样未触及 prompt 模板。选择 FWA 作为载体有明确理由：FWA 是框架导向型算法，爆炸/变异/选择三类算子提供了丰富的算子定制空间，且常规 FWA 与 LLM 增强变体在多任务上已被验证强于同类。本文主张：将 prompt 模板本身作为一等可进化对象，与群体智能算法在同一进化过程中用同一个冻结 LLM 协同演化（方法记为 LLM+FWA+P）。

## 2. 方法总览

框架为双耦合进化循环，共享一个冻结 LLM 作为变异算子：

**算法侧循环**（外层，FWA 算子种群）分四步：
- 算法选择：按性能排名的概率选择，p(A_i) = (n+1−rank(A_i)) / Σ_j rank(A_j)，rank ∈ {1..n}，rank 越小越好；变异算子取一个父代，交叉取两个以上。
- 关键组件生成：明确“生成对象与粒度”——可只改 FWA 单个算子、整体重设计全部算子，或改 PSO 单条速度更新方程。论文将 PSO/FWA/ACO 的更新规则抽象为函数（f1/f2、g1/g2/g3、h1/h2），它们既是 LLM 的设计目标（可单独或联合演化），本质上也是可独立复用的启发式规则。前作中的 "novel helper" 算子允许 LLM 在给定 prompt 下自由实现代码。
- 任务评估：多次评估、可并行；为控制算法池复杂度采用时间受限评估，保证最终算法在计算效率与解质量间平衡。
- 算法更新：默认贪心保留 top 性能；论文同时指出不同算法经 LLM 迭代改进时探索的是不同“算法空间”，当前次优者可能属于含高潜力变体的空间，并提及 MCTS 式方法可平衡即时性能与未来回报（引述既有研究，正文未锁定自用策略）。

**Prompt 侧循环**（内层，prompt 模板池）：模板分为 mutation 型（指定重设计某算子、不给方向）与 crossover 型（对两个算法的算子做融合、不给方式）两类，初始版本为人工编写的三段式生成函数。每轮按性能排名用与算法侧同构的机制选出模板，注入任务描述、代码、性能指标拼成完整 prompt 喂给 LLM；周期性地通过元 prompt（prompt4prompt）让 LLM 重写模板生成函数本身。

**关键的粒度决策**：以模板而非完整 prompt 为进化单元。论文论证：以整段 prompt 为设计单元会因组合爆炸导致计算开销剧增并损害通用性；模板级方案使 prompt 组件可复用、可扩展。这是相对 PromptWizard 整段优化路线的方法论分野。

此外论文给出两种使用模式：Type I（Solution = SIOA(problem)，TSP/CVRP/装箱/SAT 直接编码求解）与 Type II（Solution = Tool(SIOA, problem)，将群体智能算子思想作为增强模块嵌入含大量启发式的专业工具，如 EDA 领域的 DreamPlace）。这一定位把群体智能从“完整优化器”解放为“算子级组件”，显著扩展了适用面。

## 3. 关键设计

**3.1 Prompt 模板适应度归因**。核心公式：Perf(Prompt_t) = E_{A_t∼p(A)}[A_{t+1}(task) − A_t(task) | A_{t+1} = LLM(A_t, Prompt_t)]。由于应用期 LLM 冻结、模板与 LLM 内在耦合，性能增量可整体归因于模板。论文进一步宣称该式天然压低弱算法上的改进权重（改弱算法易、改强算法难，故弱算法上的增益应低权），并以此作为无需额外 LLM 评审调用的可解释评估手段。需要指出，这一“内在一致”的论证在文中是定性陈述，未给方差或显著性分析——模板适应度本质上是从噪声性能差分中估计的标量。

**3.2 元 prompt 与接口冻结**。prompt4prompt 强制三条约束：只能改 introduction / current_fwa / requirements 三个字符串字段，不得改函数输入输出；必须保证返回代码落在 `<code>xxx</code>` 标签内以便解析；自身返回须包裹在 `<prompt>xxx</prompt>` 中。这种“接口冻结、内容开放”的合同是双循环可组合性的工程支点——模板无论怎么演化，下游解析与算法侧调用协议不变。

**3.3 无惩罚约束策略**。所有实验不用罚函数，违反约束的解直接判无效、不得分。这把可行性处理内压给演化出的算子（后文 GPT-5 生成代码中的修复机制印证了这一点），也使与基线的对比在可行性口径上更严格。

**3.4 GPT-5 演化出的最优 FWA 解剖**（aircraft landing 任务，完整代码在附录）。编码上，初始 FWA 将飞机降落调度编码为起降次序排列，固定序列下的时间指派转化为线性规划求解（sequence2time 调用 LP），待设计的三个算子全部面向排列空间。演化结果的技术构成：
- 爆炸算子：以“当前序列相对目标序列的位置偏差 × (1+罚率)”构造引导扰动权重；多模态扰动按 swap 50% / insertion 30% / reversal 20% 采样，步数与幅值正相关；插入操作朝目标位置加高斯抖动；不可行解经至多 3 次相邻交换修复；附带至多 3 次邻接交换的轻量局部改进（以 LP 成本下降为准入）；哈希集合去重避免重复评估。
- 变异算子：复合变异体系 swap 35% / insertion 35% / reversal 20% / or-opt 块移动 10%；60% 概率优先选位置偏差最大飞机做引导式插入；修复采用“引导插入（70% 聚焦最大偏差飞机）+ 随机相邻交换”混合；按 20% 变异率作用于火花总量。
- 选择算子：三轮递进——精英轮按哈希去重保留 60% 种群规模的最优解；多样性轮以位置映射向量平均绝对差为距离、自适应阈值 max(1, n/12) 过滤过近个体；补足轮按适应度填充允许适度相似；适应度清洗将非有限值置 inf 保证数值稳定。
- 外层：自适应爆炸幅值 amp = clip(init_amp×(1.5 − f/max_fit), 1, fw_size)，即适应度越好幅值越大——与规范 FWA“好烟花小幅值多火花”相反，是演化自发偏离经典设计的例证；连续 10 代无改进即停。

工程含义：LLM 并未发明超出领域词汇表的数学，而是自动编排了引导式加权局部搜索、or-opt、多样性保持选择这些组合优化标准组件，且可行性修复被内化为算子职责。默认参数 fw_size=5、sp_size=20、max_iter=200，每候选解需一次 LP 求解，评估成本不可忽略。

## 4. 实验结果

设置：从 CO-Benchmark 取四类任务——单跑道飞机降落调度（|R|=1，作者注明跑道数增多会更易满足约束）、8 组公平划分、流水车间调度（makespan 最小化）、无容量 p-中位（对称最短路距离矩阵）。性能为相对参考解的比值（最大化取 Best/Reference，最小化取 Reference/Best，可大于 1）。公平性控制：每次实验 LLM 生成算法数上限 200（防单轮多生成的不公），跑 5 次取最优。基线为 EoH、ReEvo、FunSearch 及 PSO、DE（EPP/PMP/FSS 上 PSO、DE 采用与初始 FWA 相同的表示）。

**主结果（gpt-4o-mini，四任务平均性能）**：

| 任务 | EoH | ReEvo | FunSearch | PSO | DE | Ours (LLM+FWA+P) |
|---|---|---|---|---|---|---|
| 飞机降落（11 实例） | 43.04% | 56.04% | 56.04% | – | – | **105.66%**（表1；表6 同配置记 105.34%，两表略有出入） |
| 公平划分（10 实例） | 92.35% | 78.09% | 97.28% | 37.56% | 25.62% | **100.00%** |
| 流水车间（10 实例） | 96.14% | 97.19% | **97.29%** | 94.80% | 96.04% | 97.24% |
| p-中位（19 实例） | 98.46% | 99.82% | **99.88%** | 89.83% | 89.12% | 99.87% |

要点解读：约束最重的飞机降落任务上基线全面崩塌，且 ReEvo 与 FunSearch 逐实例数值完全一致（如 Airplane1 均为 57.85%）——论文明确指出二者“经各自搜索独立收敛到相同启发式规则”，而 Ours 在 11 例中 8 例达 100%、Airplane9 119.63%、Airplane11 142.42%（超参考最优）。公平划分上 PSO/DE 在前五例与后五例间的巨大落差（如 PSO 7.18% vs 57.29%）暴露其对数据分布不适应；FunSearch 演化出的“贪心分组初始化+模拟退火”配置在前五例完美但 epp6–epp8 失守（88.5%–94.8%），Ours 十例全 100%。流水车间与 p-中位属强基线近饱和任务，EoH/ReEvo/FunSearch 头部算法均含复杂搜索机制（FunSearch 混合 NEH + 2-opt + 模拟退凉），Ours 分别 97.24% / 99.87%，以 0.05pp / 0.01pp 之差略逊于 FunSearch——增益并非全域领先。

**跨 LLM 对比（飞机降落任务，平均性能）**：

| LLM | EoH | ReEvo | FunSearch | Ours |
|---|---|---|---|---|
| GPT-4o-mini | 43.04% | 56.04% | 56.04% | **105.34%** |
| Qwen3-32B | 56.03% | 59.42% | 93.35% | **109.36%** |
| GPT-5 | 109.36% | 110.34% | 111.07% | **112.57%** |

用 GPT-4o-mini 时 Ours 约为次优方法的两倍；换到 GPT-5 各框架差距收窄（Airplane9 四法 137.50%–139.86% 挤在一起）但 Ours 仍居首，Airplane11 达 154.34%。结论：框架对弱模型有放大/补全效应，与强模型有正协同，降低了对前沿 LLM 的依赖，支撑低成本部署主张。

**Prompt 侧证据**：单次 LLM+FWA+P 在一个 p-中位实例上的共演化轨迹显示，大量局部极大值恰出现在 prompt 模板更新时刻，最终最优模板 m4 取得峰值 0.9993。三个模型演化出的高质量 mutation 模板风格显著分化：GPT-4o-mini 偏概念创新、约束宽松、鼓励自适应与混合化；Qwen3-32B 强调理论与实践基础、可测试性与可复现性；GPT-5 产出九条款规格书式模板（复用基线 RNG 与种子、禁新增 import/全局状态/依赖、复杂度不得超线性增长、同种子确定性、标签输出格式精确）。作者以此论证不存在普适 prompt，须按模型条件化适配——共进化机制的必要性依据。

## 5. 消融要点

三档递减消融（gpt-4o-mini）：LLM+FWA+P / LLM+FWA（去 prompt 共演化）/ 初始 FWA（去 LLM），关键行：

| 实例 | LLM+FWA+P | LLM+FWA | 初始 FWA |
|---|---|---|---|
| Airplane8 | **97.08%** | 94.82% | 78.63% |
| Airplane11 | **142.42%** | 132.99% | 128.69% |
| Epp8 | 100.00% | 99.02% | 95.94% |
| Pmu10 | **99.78%** | 98.82% | 63.13% |
| Pmu15 | **99.71%** | 98.34% | 67.57% |

三个结论：(1) P 组件在复杂任务上关键，去掉后 Airplane11 掉 9.43pp；(2) LLM 组件是根基，缺失时 p-中位灾难性退化（Pmu10 从 99.78% 跌至 63.13%）；(3) Airplane/Epp 使用了增强初始化、Fss/Pmu 使用直接编码，方法在两种初始化策略下均保持优势，说明有效性不依赖人工初始化技巧，构成通用求解框架。

## 6. 贡献与启示

**范式贡献**：把 prompt 模板提升为 AHD 中的一等可进化对象，与 EoH/FunSearch/ReEvo 只进化算法结构的路线形成根本分野；模板级（而非整段 prompt 级）粒度是对组合爆炸的务实折中。模板适应度采用冻结 LLM 下的性能差分归因，绕开了 ReEvo 式反思机制所需的额外 LLM 评审调用，是可解释性与成本的折中方案。

**对演化计算领域的意义**：实验证实了作者的两个前提判断——强约束任务上纯在线构造失效（ReEvo/FunSearch 收敛到同一平庸规则）、静态模板封顶模型能力（三模型演化出截然不同的模板风格）。同时 GPT-5 演化 FWA 的解剖表明，LLM 的价值在于按任务上下文自动编排领域标准启发式组件（引导权重、or-opt、多样性阈值、修复机制），而非凭空创造新数学；这对“LLM 自动算法设计究竟在设计什么”给出了可检验的实证注脚。

**诚实读法**：增益高度集中于飞机降落与公平划分两类任务，FSS/PMP 上仍以毫厘之差落后 FunSearch；模板适应度是无方差报告的标量估计；SIOA 载体仅 FWA 一例；prompt 进化引入的额外 token 开销未披露；论文自认群体智能算法收敛理论长期欠发达，本文亦无理论分析。

**与音视频技术的上下游关联**（本文属非核心大类，按其自身领域标准评估后，音视频侧的接口如下）：下游，凡可表述为组合优化的音视频问题都是该框架的潜在落点——最直接的锚点是相关清单中 VVenC 逐帧 QP 启发式的 LLM 闭环进化工作（固定 prompt 协议下即取得比固定 QP 平均约 1.26% 的码率节省），本文的 prompt 模板共演化正是其下一步可移植的增强轴。Type II 模式（算子嵌入专业工具、外循环归工具所有）对应把演化算子嵌入编码器内部决策模块（模式决策、CU 划分、参考帧选择）；时间受限评估对齐编码器逐调用时延预算；无惩罚硬约束处理与码率/时延/缓冲的硬约束语义一致。上游，群体智能已渗透 NAS、超参搜索与低显存 LoRA 微调（论文引用其课题组 TASLP 工作），视频理解/生成模型的训练侧资源优化可复用同一套演化基础设施；对冻结 LLM 的低依赖意味着 gpt-4o-mini 级模型即可驱动，离线编码器调优的推理成本可控。

## 7. 与其他论文的联系

- **EoH（arxiv:2401.02051）**：直接对比基线与思想前身。本文算法侧的“关键组件”演化与 EoH 的 idea-code 共演化同构，增量在于 prompt 轴；飞机降落任务上在三种 LLM 下全面压制 EoH（43.04%/56.03%/109.36% vs 105.34%/109.36%/112.57%）。
- **HSEvo（arxiv:2412.14995）**：同属 AHD 家族，在搜索侧（多样性驱动和声搜索+遗传算法平衡探索/收敛）增强 EoH 式演化，与本文在 prompt 侧增强构成互补正交的改进轴；二者共同预设“纯 EoH 式演化会饱和”，但对瓶颈归因不同。
- **EoH-S（arxiv:2508.03082）**：把演化对象从单一启发式扩展为互补启发式集合（AHSD），与本文把演化对象从算法扩展到 prompt 模板，都是对 EoH 固定设计位点的放宽，可视为“设计单元选择”这一维度的两条分支。
- **ε-MemEvo（arxiv:2608.12522）**：以跨任务记忆注入增强 LLM 程序进化，与本文同样服务于“更充分榨取冻结 LLM”这一目标，但机制正交（记忆 vs 模板），二者原则上可组合——模板池 + 策略记忆的双通道进化。
- **代码行为相似性工作（arxiv:2603.02787）**：用求解轨迹 DTW 度量算法行为相似性以改进 FunSearch/EoH 的种群管理；本文算法侧仅用排名选择与哈希去重（演化出的 FWA 内亦只有序列级去重与位置偏差距离），行为级相似性度量可直接替换/强化其选择与多样性维护环节。
- **FunL2O（arxiv:2607.27389）**：将 FunSearch 式程序进化迁移到学习优化的特征函数设计，验证了 AHD 向新组件类型的可迁移性，与本文的 Type I/Type II 一般化定位互为印证。
- **CodeEvolve（arxiv:2510.14150）**：开源岛屿模型进化编码智能体，在 AlphaEvolve 基准上 9 题中 5 题持平或超越；其开源基础设施是本文 prompt 共演化机制落地的天然载体。
- **VVenC 逐帧 QP 启发式进化（arxiv:2606.20847）**：音视频侧最直接的应用对偶——DeepSeek 闭环进化 Python 启发式为 VVenC 逐帧选 QP、自动发现“熵约束 RDO”、比固定 QP 平均省约 1.26% 码率，但其 prompt 协议固定，恰是本文所指出的能力封顶点；将模板级 prompt 共演化移植到编码器启发式进化是最具体、风险最低的跨域升级路径，且该场景的硬码率/复杂度约束与本文无惩罚约束策略同构。
