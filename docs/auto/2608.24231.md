# RecurSE: Bounded Recursive Self-Evaluation for LLM Rubric Judges

## 1. 背景与动机

定位说明：本文属 NLP/LLM 后训练与评测交叉方向（本引擎非核心大类），按 LLM-as-judge 与 RL 训练的领域标准评估；其与音视频技术链的关联点在于 judge 模型是 AIGC 内容质量评估与偏好对齐信号的上游组件，映射在第 6 节展开。

核心问题：LLM-as-judge 已是开放文本评测与 post-training 引导的主力范式，但提升 judge 本身通常依赖昂贵人工标注、辅助 reward model 或更强教师蒸馏——成本高且循环依赖。本文将这些外部锚从 RL 训练 reward 中全部移除：judge 自身的评价能力产生其优化所需的学习信号，构成作者所称 bounded recursive self-improvement（RSI）的闭环，命名为 Recursive Self-Evaluation（RecurSE）。

动机上的关键观察是“双变量难度耦合”：与数学/代码等单变量任务（难度仅由 query 复杂度决定）不同，rubric judging 的有效梯度要求 同时是可判别规则、 是处于模型决策边界附近的 borderline 响应；响应明显正确或明显错误都产生接近零的修正梯度。这一结构性差异使静态教师蒸馏低效——固定三元组随学生进步退化为平凡样本（RQ4 中 ≈17k 轨迹蒸馏仍全面落后是直接证据）。而“评价候选响应”与“审计评价推理”共享同一 rubric 校验能力基础，提示两角色可在单一策略上互促闭环。

两个治理问题贯穿全文： 自改进何时可能发生——共享读出接口会产生 token 复制捷径，必须接口解耦； 自改进何时必须停——无外部金标锚的递归优化固有有界，自产 reward 饱和后 OOD 迁移退化，需要无偏监控器定位早停窗口。

与前作的差异：Self-Taught Evaluators、Meta-Rewarding、SELF-JUDGE、Grad2Reward 等自改进评测器均在 RL 闭环中保留外部锚（合成偏好对、外部 meta-judge、冻结参考模型、执行结果或参考 RM）；RecurSE 的 RL reward 中零金标、零教师，人工监督仅出现于一次性紧凑 holdout（100 prompt 的 SV-HARD）用于早停。

## 2. 方法总览

闭环结构（单共享策略上的 judge–checker 递归）：

- **Pass 1（可训练 judge π_θt）**：对 rubric 实例 x=(h, y, r_{1:K})（h 任务上下文、y 候选响应、r_{1:K} 共 K 条规则），逐步 CoT 推理后输出带索引的二值裁决，格式 `1:<ans>YES</ans> … K:<ans>NO</ans>`；每 prompt 采样 n=8 rollouts。
- **Pass 2（reward-only checker C_θ̄t）**：与 π_θt 权重同步的独立 vLLM 快照（θ̄t←θt 每步刷新，无梯度、无优化器状态），以 meta-rubrics（形如 "k: Did the AI correctly judge the following rubric ⟨r_k⟩"）审计 judge 的完整推理轨迹，输出独立的 5 档标量 s_i∈{0,…,4}，作为唯一 RL reward，R_i=s_i。
- **更新**：组内标准化 Â_i=(R_i−μ)/σ（GRPO 式组相对优势），GSPO 序列级 clip 策略损失更新 θ（clip 0.005），随后 θ̄_{t+1}←θ_{t+1}。格式不合规 rollout 记零奖励并从组统计中剔除。
- **早停**：每 10 步在人工校验集 SV-HARD 上计算 judge 规则准确率、checker 保真度与 PAV 复合指标 V̂_t，在有效性高原内留存 checkpoint。

训练数据为 RubricHub 经 cluster-split 的实例，候选响应由 16 模型三层能力池按 Low:Mid:High=1:2:1 合成（低层常违反细粒度负约束、中层 borderline、高层提供难规则张力），训练与评测零重叠，金标不进 RL reward。审计对象是推理过程而非重新判题——即使二值裁决碰巧正确，伪推理仍被扣分，这是过程监督免金标训练的核心机制。

## 3. 关键设计

### 3.1 surface coupling 与接口解耦（自改进何时发生）

若两 pass 共享相同 YES/NO 读出模板，reward 取 S=(1/K)Σ_k 1(Checker_k=YES)。作者将自产分数分解为 S=aU+bB+ε（U 真实推理质量、B 表面裁决 token 偏置如 ΔP_YES、ε 噪声）。在权重同步 θ̄←θ 下，任何强化 Pass 1 中 YES 发射的梯度同时改变 Pass 2 的 YES 发射概率，形成 b>0 的闭路捷径：优化器抬升 B 即可收割近满额自奖励（S→1.0）而 U 停滞。附录以 SCM 形式化：judge 发射 Z_1=f_1(U,B;θt)，checker 分数 S=f_2(Z_1;θ̄t)；耦合读出下 f_2 直接解析 Pass 2 的 YES token，构成后门捷径。作者强调这与经典 reward hacking 不同：经典是 actor 对冻结 RM 的静态代理失配，surface coupling 是 reward 函数随权重同步被策略更新实时改写——属于自改进递归特有的失效模式。

解耦设计：输入侧保留共享证据块布局（系统指令、会话上下文、AI 响应、编号 rubric），保证 checker 观察与 judge 相同的证据——checker 模板的 conversation-history 槽放入完整 judge 输入 x，AI-response 槽逐字放入 judge rollout z，rubrics 槽放入 meta-rubrics；输出侧结构性分离：judge 出结构化裁决 token，checker 出自由标量 Final Score（0–4，带 5 档锚定语义：0=全错且解释极差……4=全对且分析清晰）。这使 ∂S/∂verdict token≈0，切断直接 token 复制通道。论文明确不宣称 b=0、也不声称标量接口杜绝一切捷径——这是实证有效的设计。又因组相对优势对正仿射变换 R→αR+β（α>0）不变，0–4 量程本身不重要，决定策略梯度的是 n 个 rollout 间的有效相对排序。

配套格式门防 prompt-injection 捷径：要求恰好 K 个可解析裁决，且禁止 judge rollout 内出现 checker 保留分隔符（如提前输出 `<|AI's Response End|>` 或伪造 `<|Final Score|>4` 块）；违规样本零奖励+零响应 mask，排除于组统计。

### 3.2 PAV：成对优势有效性监控（自改进何时停止）

在紧凑人工校验集 D_val（SV-HARD：100 prompt，五域各 20 条，均值 2.5 条难规则，共 ≈250 条人工核验规则；每 checkpoint 以每 prompt n=4 rollouts 共 400 条 judge–checker 轨迹）上构造 PAV：

- A_t=E[Y_t] 为 judge 规则准确率；checker 标量 S_t∈[0,4] 对照金标参考 U=4×(正确规则数/总规则数)，归一化误差 e_C,t=E[|S_t−U_t|/4]。
- 组相对学习真正依赖的是成对差 (S_i−S_j) 而非孤立绝对分。三角不等式给出 |(S_i−S_j)−(U_i−U_j)|/4 ≤ |S_i−U_i|/4+|S_j−U_j|/4；对可交换 rollout 对取期望，成对排序误差 ≤2e_C,t。
- 复合代理风险 (1−A_t)+2e_C,t 归一化为 **V_t=(A_t+2(1−e_C,t))/3**；checker 误差权重 2 由上界先验固定，非经验拟合。

统计性质：两成分为 D_val 上的样本均值，仿射组合保证 E[V̂_t]=V_t 在任意固定 checkpoint 无偏；95% 置信区间用 1 万次 prompt 级 cluster bootstrap（保持 prompt 内 rollout/规则相关性）。作者坦承在线序贯挑选存在 FWER 膨胀，但实证 V̂_t 形成稳定高原（Qwen-9B 步 120–140、Gemma 150–170），窗口内任意 checkpoint 迁移收益基本一致——PAV 是停止视界监控器而非脆弱单点 arg max。权重敏感性：广义监控器 M_t(λ)=Â_t+λ(1−ê_C,t) 的最优停止区在 λ∈[1.59, 11.03] 全程稳定（步 130 附近 ∇Â_t≈+0.02/10 步进入平缓平台，ê_C,t 其后陡峭凸升 ≈+0.15/10 步，误差惩罚梯度主导精度增益）；三折子集重采样下停止区稳定于 Qwen {130,140}、Gemma {160,170}。

### 3.3 工程实现

训练用 verl+FSDP+vLLM：Qwen-9B/Gemma batch 32、n=8、lr 3×10⁻⁶、clip 0.005、无 KL 惩罚（27B：batch 48、KL 0.005）；judge 最大 prompt/response 长度 8192/32768，checker 生成预算同为 32768。checker 为共置 vLLM 实例纯推理（无反向/优化器开销），参数经 NVLink/InfiniBand 点对点张量广播每步同步：Qwen-27B（TP=4）下 ≈1.2 秒/步，而 rollout 生成占 ≈45–60 秒/步，同步开销 <2.5% 步时——权重绑定的通信瓶颈在多 GPU 分布式下可忽略。Qwen-9B/Gemma 训 200 步、每 10 步监控；27B 训 75 步、每 5 步。

## 6. 贡献与启示

按 LLM 评测领域标准，本文贡献有四： 形式化零外部金标的 bounded RSI judge 训练（on-policy 过程检查）； 揭示并结构化解决 surface coupling 捷径（接口解耦）； 理论动机明确（成对分数差误差上界）的无偏早停监控 PAV； 三架构至 27B 的 OOD 泛化与下游偏好对齐闭环验证。最值得移植的两点：其一，“审计推理过程而非重判结果”——即使二值裁决碰巧正确，伪推理仍被罚，为过程监督免金标训练提供了可行路径；其二，解耦原则可推广（附录已给出 holistic 评分平移方案：Pass 1 出 1–10 整体分、Pass 2 出解耦 0–4 审计分、holistic PAV 监控）。局限（论文自陈）：仅英文 rubric 基准、≤27B；SV-HARD 需一次性人工核验（远小于全量标注但非零）；序贯监控的 FWER 形式化留待后续；checker 系统性偏置理论上可给伪推理高分；bounded RSI 固定任务规格/优化器/检查协议，不涉及开放式自改写。

对音视频技术链的映射（笔者视角，非论文实验结论）：
- **上游·评测器自产**：音视频 AIGC（生成视频/语音/字幕/本地化）的质量评估正快速 rubric 化（时序一致性、音画同步、字幕忠实度、安全合规等 checklist），人工金标极贵是共性痛点。RecurSE 的“零金标 RL + 一次性紧凑人工校验集做早停”配方直接对症；其“静态蒸馏维持不了双变量张力”的结论提示：给视频评测器蒸馏大模型轨迹，不如让评测器对 borderline 生成样本做 on-policy 自审。
- **下游·偏好信号**：视频/语音生成模型的偏好对齐管线与 RQ5 同构——judge 合成偏好对→DPO。RecurSE 显示劣质 judge 标签可令下游能力净下降（GPQA −1.85），这对音视频生成模型用弱 judge 批量造偏好对的做法是直接警示：judge 不自证有效，偏好数据可能在负向对齐。
- **工程栈同构**：verl/FSDP+vLLM、组相对优势、reward-only 同步快照（<2.5% 步时开销）与多模态 RLHF 栈一致；但多模态下 n=8 rollouts×32k 预算的成本结构会数倍放大。接口解耦（verdict token vs 标量）与 PAV 成对保真监控原则上可无损平移——论文亦将多模态 judging 列为 future work，本文可视为其文本域先导验证。
- **训练数据构造**：16 模型三层池 1:2:1 合成 borderline 响应的做法，可平移为用不同档位视频/语音生成模型构造“合规-边界-违规”候选分布，为多模态 judge 训练提供难度谱。

## 7. 与其他论文的联系

- **TRUST（arXiv:2611.10787）**：关联依据是两者处理 RSI 循环的统计有效性问题且互补。RecurSE 的 PAV 逐 checkpoint 无偏，但作者在 Limitations 中明确承认在线序贯挑选存在多重检验问题、把“带 FWER 控制的形式化序贯停止边界”列为改进方向；TRUST 恰以在线多重假设检验为 RSI 控制错误进化率并提供统计保证，可直接为 PAV 的高原式窗口选择补上序贯检验层。
- **WeightLoop（arXiv:2611.07319）**：同属“有界 RSI”路线——RecurSE 靠接口解耦+PAV 早停限制自改进范围，WeightLoop 靠有界参数编辑程序+实验反馈约束权重自改写。对照点在反馈源：RecurSE 的 reward 完全自产（同步自身快照），故必须显式解耦并监控自奖励有效性；WeightLoop 引入外部实验反馈作锚，天然规避 surface coupling 类自奖励捷径。两条路线互证：无外部锚的自改进必须显式监控 reward 有效性。
- **SkillDuet（arXiv:2611.12109）**：关联依据是“共演化”机制。RecurSE 的 RQ4 消融证明 judge–checker 权重绑定共演化优于冻结 checker 与外部 27B checker（HealthBench 85.9 vs 79.8）；SkillDuet 同样以响应反馈驱动“模型参数↔技能库”的递归协同演化。差异在演化对象拓扑：RecurSE 两角色共享同一权重（同步快照、无独立梯度），SkillDuet 演化异质组件（外部技能库）；两者共同支持“递归改进收益来自双组件贴 on-policy 边界共演化”的判断。
