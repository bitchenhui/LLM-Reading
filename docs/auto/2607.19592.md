## 1. 背景与动机

自我改进系统的一个根设计问题是：当系统通过解题积累经验后，什么应当持久并随时间改进。主流路线（prompt/workflow 优化、harness 搜索、agent 代码自改写，如 DGM、HyperAgents、Meta-Harness）默认答案是把 agent 本身作为持久改进对象。论文指出该路线的结构性代价：改进与特定 agent 设计、任务分布、适配 run 绑定，难以维护与迁移；单一持久 agent 必须吸收大量局部经验，其中任务特定、冗余、互相矛盾者众多，有用行为被冲突更新稀释，且每次新适配可能损害旧任务表现。

本文提出反转设计——knowledge-centric self-improvement：agent 保持通用、无状态、可抛弃，唯一持久且改进的对象是一个经策展的共享知识库。agent 从知识库读取蒸馏 bundle，用标准工具执行一次任务，把证据写回；改进被封装在知识而非 agent 状态中，因而可检视（每条结论带证据链）、可压缩、可跨任务与跨 LLM 家族复用。

与两类最近邻工作的区分要抓准：记忆架构系（MemGPT、Mem0、LoCoMo/LongMemEval 等）解决的是“连续性”问题——如何长期存取维护上下文，本文把记忆仅当存储基础设施；经验复用系（Voyager、Expel、Agent Workflow Memory、Agent KB 等）虽把经验外化为 artifact，但依赖单 agent 对自身轨迹做抽象。本文把可靠性负担从 agent 侧移到证据过程：知识由多尝试、多 agent 的论坛讨论裁决，分歧被当作证据而非不稳定信号。

方法学立场值得强调：这是一个受控实验框架。作者刻意将 agent 固定为最简形态（每次全新上下文、无私有记忆、无角色专化、无定制编排、无修改过的 prompt），使跨代增益只能来自策展知识本身；协议自述“刻意简单、不声称最优”。代码开源于 github.com/recursive-knowledge/KSI。论文本体属 LLM agent 自改进方向，与音视频无直接交集，其对本领域的意义在 §6 单独讨论。

## 2. 方法总览

**运行时形态**：Engine 将任务派发给 Host launcher，后者拉起一次性 Worker 容器；容器内 agent-runner 驱动 provider 查询循环，经 MCP 工具（knowledge / query / forum_post）访问知识库与论坛，工具事件写入统一 tool_trace。Host 对返回的 JSON 状态信封做归一化，空的“成功样”信封被重分类为 silent_failure，避免假通过或假零分。任务执行期只暴露 provider 原生编码工具面（Read/Edit/Write/Bash/Glob/Grep），不设 benchmark 专属任务 API；benchmark 差异全部由 workspace 预置、trace 捕获与事后评测吸收。

**知识库三类 artifact**：typed attempt table（每次尝试及结果）、forum posts（把执行轨迹转为证据接地的 claims）、distilled bundles（存活 claims 压缩为未来 agent 的种子）。

**世代循环**：编码与抽象推理类各维护 50 任务池（Terminal-Bench 2 用全部 89 题）；每代对每个未解任务 spawn 一个新 agent，其输入为该任务的 attempt table、该任务的 per-task 蒸馏 bundle、全局 cross-task bundle（经 runtime/seeding.py 渲染进 workspace 的 MEMORY.md）；执行后经三阶段策展写回。已解任务移出活跃池，不再消耗 token。每基准 10 代，本文方法 3 seeds。提交预算遵循各基准官方口径：ARC 每个测试输入两次盲试、无单次反馈；Polyglot 会话内 tries=2（失败可见测试输出末 50 行后同会话再试一次）。

**模型分工**：任务执行用 Claude Agent SDK（Haiku 4.5）或 OpenAI Agents SDK（GPT-5.4-mini，medium reasoning）；论坛与蒸馏阶段调用同族 LLM 的直接 API 循环、不带 agent 工具。

**三阶段策展构成“抽象阶梯”**：任务级论坛把轨迹变为带局部证据的 claim；跨任务论坛检验哪些 claim 在跨任务辩论中存活；蒸馏把存活 claim 固化为类型化 bundle。核心机制是把“分歧→裁决→范围收窄”变成协议内的一等公民。

## 3. 关键设计

**任务级论坛六字段 schema（附录 E.1）**：load_bearing_assumption 必须点名具体 tool/API/文件/数据形状/不变量，明令禁止"read more carefully"类空话；evidence 为 1–2 句轨迹/模型输出/引用帖原文；evidence_post_id 绑定引用；proposed_change_for_next_gen 必须点名文件/工具/API/决策点且与已试内容不同，搜索空间穷尽用字面哨兵 EXHAUSTED 标记；predicted_outcome 必须可证伪；confidence 三档。关键工程点是检索门：MCP 服务器在 agent 未先于同会话调用 knowledge(task_id) 与 query(task_id,...) 时直接拒绝 forum_post——从机制上把发言绑定到已检索证据，压制散文式复盘。

**跨任务论坛 schema（附录 E.2）**：round 0 播种 concrete_primitive，要求是从 Phase-1 任务或引用帖逐字提取的具名对象（操作、API 调用、错误类型、文件路径、语言特性、数值不变量），schema 明确拒绝 'separation of concerns'、'pattern'、'strategy'、'architecture' 类元话语；task_grounding 中的引文须 ≥40 字符且包含 primitive 的非停用词；round ≥1 的 transfer_claim 必须引用 peer post id 并取 AGREE|DISAGREE|SYNTHESIZE 立场，且 evidence_task_ids 必须非空（服务器拒绝缺省或引用未知任务的 round-1 帖）；anti_meta_self_check 是 schema 字段而非提示建议，蒸馏期未通过元检验的帖被丢弃。整套 schema 的设计目标只有一个：阻止泛泛建议在知识库中积累。

**分歧即证据的实测画像（附录 C，Haiku 4.5、seed 1）**：跨任务论坛 round≥1 共 1,354 帖，其中 AGREE 512、DISAGREE 73、SYNTHESIZE 861（列不互斥）。直接分歧罕见（73/1354），这正是协议意图：让冲突显式并强制携带证据，而非制造冲突。GPT-5.4-mini 在相同提示下以自由文本表达对比、不输出字面关键词，故关键词统计仅限 Haiku。三个端到端案例刻画了机制闭环：
- ARC 任务 b548a754（gen 1）：round-0 帖把失败过度泛化为“marker 不控制几何”；round-1 帖引用同代已解任务 05f2a901 反驳；蒸馏器把证伪收窄到实际测过的参数化（“marker 在矩形上方→矩形不变”，score 0.0），把假设族其余参数化保留为 UNTRIED 并列出四条系统化检验次序。gen 2 的全新 agent 据此以 marker 指示方向扩展矩形的规则解出该题（1.0）。若采纳 round-0 共识，该假设族即被封死。
- Polyglot java__react / rust__react（gen 1）：同一 agent 读到 Rust 尝试帖后自我反驳 round-0 的“两语言同一守卫”主张；蒸馏产出条件化 claim（同步立即传播用就地 equals() 检查；循环传播需循环前快照+循环后比较）外加一条 FALSIFIED。rust__react 于 gen 2、java__react 于 gen 3 解出，解法精确实现了 scoped guard。
- go__connect（六边形棋盘连通性，seed 1 十代未解）：行奇偶邻居偏移 vs 一致 8 邻接两种立场的跨代争论未决，知识库将两立场连同支持/反对证据以 FALSIFIED/UNTRIED 标记保留，不强行折中——协议在证据真正冲突时的职责是把冲突保持可读，而非平均化。

**蒸馏是选择而非摘要（附录 E.3）**：指令要求保留 actionable、证据接地、scoped 的 claim，丢弃不写明适用条件的模糊建议。Insight 为 typed dict：text（"when X, do Y" 形式）、applies_when、does_not_apply_when（反例/边界）、evidence（{task_id, post_id, quote} 列表）、confidence。PerTaskBundle 与 CrossTaskBundle 六字段同构（transferable_insights / confirmed_constraints / rejected_hypotheses / pitfalls / checks / next_steps），但输入严格隔离：per-task 蒸馏只消费该任务帖，cross-task 蒸馏只消费跨任务帖，防止跨任务猜测污染任务内策展。

**缓存工程（附录 E.4）**：Anthropic prompt cache 按至 cache_control 标记处的内容哈希命中，任何前缀字节变动都会打穿缓存。论坛提示构造器因此返回二分结构：cacheable_prefix（agent 与世代不变的内容：任务标识、描述、MCP 工具表、轮次指令、JSON schema，cache_control 只挂此块）+ variable_suffix（该 agent 历史尝试与当轮 peer 帖）。这是论坛轮调用量巨大时美元成本仍可控的关键杠杆。

**预算与公平性细节（附录 I/H）**：主 run 每任务 1800s 上限，冻结基线 sweeps 放宽到 3600s（两倍于自家上限，方向对基线有利）；TB2 唯一例外，以原生 task.toml 超时为准；Polyglot 测试执行 180s，SWE-bench Pro harness 3600s；论坛与跨任务作业各 900s；所有直连 LLM 调用 temperature 0.0；≤25 并发任务容器；瞬时基础设施失败（超时/容器崩溃）重试 ≤3，已完成的尝试无论成败绝不重试且失败 token 计入成本。成本核算覆盖 run 内全部 LLM 调用（任务执行、反思、两轮论坛、蒸馏），基线重跑同样计入其元环 token，并按含 prompt-cache 读写费率的公开 API 价折算美元。

## 4. 实验结果

设置：ARC-AGI-1/2 各 50 题（官方 exact-grid-match）；Polyglot 50 题（沿用 DGM/HyperAgents 子集）；SWE-bench Pro 从 731 个公开实例固定种子随机抽 50；Terminal-Bench 2 全部 89 题。所有 agent 中心基线从 fork 重跑、不改其核心优化算法，统一替换为 Haiku 4.5，加信息平权门（自改/诊断 LLM 只见 solved/unsolved 标量而非金补丁与隐藏测试；Polyglot workspace 的 git 历史擦除；零测试执行的评估记为失败）与网络出口隔离（仅允许 provider API 与 PyPI 的白名单代理）。注意：DGM 原文用 Claude 3.5 Sonnet/o3-mini，此处 LLM 已替换，数字不可与原文发表值比较；TB2 各基线行为各家 harness 下的已报告分数（Meta-Harness 行为 Opus 4.6 proposer + Haiku 4.5 base 的组合），非重跑。

**对 agent 中心自改进（表 1，Haiku 4.5，10 代，OURS 为 3 seeds 均值±std，基线单跑）：**

| 方法 | ARC-AGI-1（Solve/Cost） | ARC-AGI-2（Solve/Cost） | Polyglot（Solve/Cost） | SWE-bench Pro（Solve/Cost） |
|---|---|---|---|---|
| OURS | 86.7%±4.2 / $76±16 | 82.7%±6.1 / $80±1 | 68.0%±2.0 / $126±6 | 64.0%±2.0 / $208±19 |
| HyperAgents | 70% / $234 | 60% / $188 | 52% / $190 | 42% / $431 |
| DGM | n/a | n/a | 58% / $281 | 54% / $713 |

Terminal-Bench 2：OURS 43.8%±3.4，对比 OpenHands 13.9%、Terminus 2 28.3%、Mini-SWE-Agent 29.8%、Terminus-KIRA 33.7%、Goose 35.5%、Meta-Harness 37.6%。结论：在四个自改进对比基准上同时取得最高解决率与最低成本；TB2 上以“最简 agent + 知识策展”超过一排 harness 工程系统。成本优势来源可分解为：无自改元环 token、已解任务出池、蒸馏的失败签名复用避免重复踩坑。

**对提示优化（表 2，美元预算对齐主实验实际开销）**：GEPA 跑 15/7 次迭代（ARC-AGI-1/Polyglot），OpenEvolve 81/46 次。OURS 86.7%±4.2 / 68.0%±2.0 对 GEPA 44% / 36%、OpenEvolve 54% / 46%。该对照隔离了改进载体这一轴：优化可复用 policy prompt 显著弱于优化可复用知识 artifact；作者因提示优化收益有限，未将其扩展到更贵的基准。

**跨 LLM 家族（表 3）**：GPT-5.4-mini（medium reasoning）在四个基准上均更高且更便宜——Polyglot 72.7%±2.3 / $56±1、SWE-bench Pro 70.7%±2.3 / $157±11、ARC-AGI-1 93.3%±7.0 / $16±3、ARC-AGI-2 90.0%±5.3 / $20±1；Haiku 版仍以零头成本超过表 1 全部 agent 中心基线。协议不绑定单一 LLM 家族，幅度依赖 LLM。

**冻结知识 artifact 的 held-out 转移（表 4）**：donor 在 50 题自改进 split 上跑满 10 代，冻结 gen-10 资产；评测集为 20 题 disjoint split，按“两个 recipient 在 seed-0 无知识单跑中均失败”的失败集交集随机抽取（选择 run 与评测 3 seeds 分离）。recipient 为 zero-shot、仅任务执行、无新论坛无蒸馏；由任务条件化 adapter（单次 temp 0.0 调用，明令禁止解题）把共享资产转为短 memo，六个列表字段各限 0–3 项、弱相关时允许返回空/短列表以防空知识噪声，任务证据与先验冲突时以任务为准。20 题 zero-shot 解决率：

## 5. 消融要点

## 6. 贡献与启示

**范式贡献**：用受控实验给出强主张——自主推理的瓶颈可能不在 agent 架构复杂度，而在其可访问并持续迭代的信息质量与结构。最简无状态 agent 配策展知识，即在四个基准上超过 agent 中心自改进、在 TB2 上超过 harness 工程系统，且成本更低。

**工程含义**：改进外置带来三个可操作的属性——可检视（每条 insight 带证据链与适用/不适用边界）、可迁移（跨任务 zero-shot、跨 LLM 家族双向为正，防 LLM 特定过拟合）、即插即用（不同 LLM 与 agent 变体向同一知识体贡献与消费）。成本结构上无元环、已解任务出池、失败签名复用。对构建多模型 agent 团队的组织，这意味着“换底层模型不丢工程经验”有了实证支持的实现路径。

**对音视频技术上下游的含义（本笔记外推，非论文内容）**：本文属非核心大类，判读按其自身领域标准执行；对本领域的可迁移点在工程形态而非算法本体—— 媒体工程中大量任务是“容器内终端作业 + 验证测试”形态（转码集群运维、滤镜链调试、编解码构建回归、流媒体 infra 配置），与 TB2 / SWE-bench Pro 同构，三阶段策展协议可直接挂接，把环境假设、依赖坑、验证策略沉淀为跨任务 bundle，替代每个 run 重新踩坑； 编码器参数搜索与质量回归这类测量有噪声的经验域，天然适配"FALSIFIED/UNTRIED + 证据引文"的假设台账——b548a754 案例展示的“收窄证伪而非杀死假设族”正是防止单次坏测量误导调参方向的机制； GPU 内核自动优化域（自改进 agent 已进入编解码内核类 workload）中，跨搜索 run 持久化知识 bundle 与“把教训固化进某个 agent”是两条明确分岔，本文为前者提供了协议模板。

**局限与判读**：基线经 LLM 替换与信息平权重跑，数字不可与各原文发表值直接比较，且基线获得两倍超时上限（对基线有利的方向，说明结果非超时挤压所致）；50 任务池小、基线单跑无方差；转移矩阵一格方差大、Polyglot 转移非练习离散；无人类专家贡献的研究（作者自列为未来工作）；协议自认非最优。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326）**：同为“经验写入前的证伪门控”。KSI 在 schema 层实现证伪台账（rejected_hypotheses 的 FALSIFIED/UNTRIED 标记 + 证据引文 + EXHAUSTED 哨兵），FGSE 则把经验教训作为可证伪假设经三类探针验证后才写入记忆；FGSE 的探针机制恰好可加固 KSI 蒸馏写入路径的更新安全性，二者互补。
- **TRUST（arXiv:2611.10787）**：KSI 用论坛裁决（AGREE/DISAGREE/SYNTHESIZE + 蒸馏选择规则）非形式化地控制“坏经验进入知识库”的速率；TRUST 以在线多重假设检验为递归自改进提供错误进化率的统计保证，是 KSI 蒸馏接受规则的形式化升级方向。
- **SkillDuet（arXiv:2611.12109）**：同样把改进外化为可复用 artifact（外部技能库 vs 知识 bundle），但 SkillDuet 以响应反馈驱动 LLM 参数与技能库协同演化；KSI 恰好冻结权重、只让 artifact 变化——两者构成“外置改进 ± 权重更新”的对照设计，KSI 的转移矩阵（表 4）为“artifact 独立于模型”提供了 SkillDuet 框架下不易获得的隔离证据。
- **CompoundingKernel（arXiv:2611.19230）**：搜索中心自改进的极端形态（agent 搜索编写 GPU 内核登顶 SOL-ExecBench）。与 KSI 的知识中心路线互补而非竞争：内核优化域正是跨 run 知识持久化的自然落点，KSI 式 bundle 可在搜索 run 之间保存已证伪的优化假设。
- **InfraRSI（arXiv:2611.11558）**：以五阶段验证工作流把开放指令转化为分布式训练 infra 优化，与 KSI 的 Terminal-Bench 2 轴同属终端/基础设施自动化；KSI 蒸馏产物的环境假设、pitfalls、checks 字段正对 infra 运维知识的形态，可作为 InfraRSI 类系统验证工作流的经验沉淀层。
- **LongCapHarness（arXiv:2611.10463）**：harness 中心改进的当代代表（免数据合成与后训练挂接长上下文推理能力），对应 KSI 基线中 Meta-Harness 所在的“改进载体 = harness”一轴；KSI 在 TB2 上超过 Meta-Harness（43.8% vs 37.6%）构成两轴的直接对照，反衬把载体换成知识 artifact 的差异。
