# Live-SWE-agent: Can Software Engineering Agents Self-Evolve on the Fly?

## 1. 背景与动机

软件工程智能体的演进已形成两条主线：一是 agentic 路线（SWE-agent、OpenHands、AutoCodeRover、Trae Agent），为 LLM 配备终端/编辑器/搜索等多步工具使用能力；二是“去 agent 化”流水线（Agentless、Moatless），主张用专门的提示与工作流替代复杂脚手架。两条主线共享同一结构性缺陷：**动作空间是静态的**——工具集与 scaffold 实现在任务开始前即被固化，即便当前任务本可受益于定制化动作；而 scaffold 设计空间近乎无限，人工穷举代价极高（论文以 Devin 2024 年 3 月首发时 SWE-bench 13.86% 的成绩说明脚手架工程至今仍是性能主变量）。

近期出现的自改进智能体（SICA、DGM、HGM）试图让 agent 修改自身实现，但依赖**离线进化**：在特定 benchmark 上以评测分数为选择信号迭代演化，产物是一个静态 agent。代价高昂——论文引用 DGM 原文口径，在 SWE-bench 上一轮运行约 $22,000；且学到的 agent 可能对训练 benchmark 与底层 LLM 双重特化，跨 LLM/跨 benchmark 泛化存疑。

本文的切入点是一个朴素但未被利用的洞察：**软件 agent 本身即软件**，现代 LLM agent 已具备在运行时修改自身实现的内在能力。Live-SWE-agent 据此把改进信号源从“离线 benchmark 分数”迁移为“任务内环境反馈”，实现首个在求解真实 issue 过程中在线自进化的软件智能体。作为第一步，进化范围聚焦工具创建（agent 动作空间中最关键的组件），不动 agentic loop 本身。

## 2. 方法总览

实现载体为 mini-SWE-agent（约 100 行代码、仅访问 bash），沿用其默认超参：每题步数上限 250、成本上限 $3、每题采样一个 patch；默认后端 Claude 4.5 Sonnet（claude-sonnet-4-5-20250929）。

对基础框架的修改只有两处，均为 prompt 级：

1. **初始 prompt 增补工具创建指令**：告知 agent 可用 Python 创建自己的工具，要求工具具备信息量输出与错误信息、可命令行运行；明确“工具可服务于任何目的、无需通用”，并建议“至少先创建一个简单编辑工具替代 bash 编辑”，附创建与调用示例（写脚本文件即创建、带参运行即调用）。
2. **每步环境反馈后追加反射消息**：要求 agent 反思历史轨迹、判断是否应创建或修订工具，并显式提示“能用 bash 不代表不该建工具”。工具创建由此与跑测试、看文件等普通动作并列为一级决策点。

反馈通道保留 mini-SWE-agent 的截断逻辑：命令输出达 10000 字符时只保留头 5000 + 尾 5000 并报告 elided 字符数，警告文本中亦引导“可创建工具选择性查看少量行”。任务提交以固定命令（`echo COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT && git add -A && git diff --cached`）终止。整体设计零离线训练、不强加工作流、与底层 LLM 无关；唯一的 benchmark 适配是 SWE-Bench Pro 场景下提示中的主目录由 testbed 改为 app（对应其 docker 环境布局）。

## 3. 关键设计

**反射触发是主引擎。** 消融表明，仅在初始 prompt 中声明可建工具（无逐步反射）只能把子集成绩从 62.0% 提到 64.0%（平均工具数 2.92），加入逐步反射后才达 76.0%（工具数 3.28）。反射把工具合成从一次性前置动作变成与问题求解交织的持续迭代决策——论文明确反驳“开头一次性生成全部工具”的设计：工具需求在求解过程中才显形；固定全集会造成工具过载、淹没并误导 agent；且工具常需在运行时迭代修订，固定工具集不具备此能力。这也是“在线”相对“离线进化出静态 agent”的结构性差异：**每个任务获得定制的动作空间**。

**工具形态学：通用与任务特定两类。** 通用类以 edit/view/search 为主。示例编辑工具支持 replace/insert/delete 三种操作，且在替换目标 `old_text` 未命中时打印 Warning——直接对位 `sed` 的静默失败缺陷（目标串不存在时无告警仍返回成功码，agent 可能误判编辑已生效）。示例搜索工具默认排除隐藏目录、`__pycache__`、`node_modules`，显示命中行前后上下文，并将结果截断至 top-20 以控制上下文膨胀；其等价 bash 命令需长串 flag 链接（`grep -RIn --include --exclude-dir ... -C2 | head`），还存在老版本 grep 不支持 `--exclude-dir` 之类的兼容性风险。任务特定类是方法收益的核心证据：MARC 文件（书目记录格式，含二进制）分析器把二进制/XML 测试用例转为可读字段输出，帮助 agent 理解 issue 并评估 patch——这类功能用简单 bash 或通用工具难以达成；go_analyzer.py 按 Go 语法正则实现结构体/函数定义定位、标识符引用与 import 提取的轻量静态分析，脚本化后可多次复用，论文称靠它解出了此前最强基线未能解出的 SWE-Bench Pro 任务（navidrome__navidrome-10108c63c9b5bdf2966ffb3239bbfd89683e37b7）。

**效率机理。** 多步 bash 链被压缩为单次工具调用，上下文长度与步数双降；GPT-5 后端甚至出现单题均成本微降（$0.28→$0.27），说明工具合成可同时改善有效性与效率，而非纯开销。

## 4. 实验结果

设置：SWE-bench Verified（500 题，人工校验描述信息充分）、SWE-Bench Pro 公开集（731 题、11 仓库、Python/Go/TypeScript/JavaScript 四语言）、SWE-bench Multilingual 随机 50 题子集；单次尝试、无测试时扩展。温度按官方推荐/支持情况设置：Gemini 3 Pro 为 1，Anthropic 为 0.0，OpenAI 因不支持 0 而取 1。

**SWE-bench Verified 主结果**（同一脚手架家族内对照）：

| 后端 LLM | mini-SWE-agent | Live-SWE-agent |
|---|---|---|
| GPT-5-Mini | 59.8% ($0.04) | 63.0% ($0.05) |
| GPT-5 | 65.0% ($0.28) | 68.4% ($0.27) |
| Claude 4.5 Sonnet | 70.6% ($0.56) | 75.4% ($0.68) |
| Gemini 3 Pro | 74.2% ($0.46) | **77.4%** ($0.48) |

论文口径：77.4% 为撰写时 Verified 榜单（含商用闭源脚手架在内）最佳成绩，成本增量可忽略。

**Verified-60 子集对照离线自改进系**（GPT-5-Mini，子集沿用前工作选定）：

| 方法 | % Resolved | 离线成本 |
|---|---|---|
| SICA | 50.0% | 死循环 |
| DGM | 53.3% | 1231 h |
| HGM | 56.7% | 512 h |
| Live-SWE-agent | **65.0%** | 0 h |

较此前最佳提升 8.3 个百分点且零离线开销，直接证伪“离线进化是自改进必要条件”。

**SWE-Bench Pro**（Claude 4.5 Sonnet，SWE-agent 为该榜最佳基线，约 7000 行手写脚手架）：SWE-agent 43.6% vs Live-SWE-agent **45.8%**（$0.73/题），论文称此为撰写时已报道的最佳成绩。**Multilingual 50 题子集**（Claude 4.5 Sonnet）：40.0% ($0.59) → **46.0%** ($0.66)。

**工具分布分析**：以工具脚本体为文本用 OpenAI text-embedding-3-small 嵌入，先 PCA（n_components=50）再 t-SNE（max_iter=1000），按工具文件名串匹配归类。发现：edit/view/search 形成簇但簇内弥散——同名工具随任务变形而非收敛为单一模板；存在 others 类（跨文件补丁施打器、diff 检查器等）；按仓库切分时 openlibrary（处理专有书目数据格式）形成独立簇；按语言亦分化。这为“全任务统一工具集次优”提供了实证支撑。

## 5. 消融要点

基于 SWE-bench Verified 随机 50 题子集（附录给出完整清单），默认 Claude 4.5 Sonnet：

- **组件消融**：去掉工具创建（即退回 mini-SWE-agent）62.0%、0 工具；保留初始 prompt 声明但去掉逐步反射 64.0%、2.92 工具；完整版 76.0%、3.28 工具。反射环节贡献 +12pp，是设计的关键增量；论文同时指出工具数量与解题性能不必然相关，反射的价值在于诱导出任务定制工具而非堆量。

- **后端 LLM 扫描**（同 50 题，Live 相对 mini 的变化）：

| LLM | mini-SWE-agent | Live-SWE-agent |
|---|---|---|
| GPT-5-Nano | 44.0% | 14.0% (↓68.2%) |
| GPT-5-Mini | 60.0% | 58.0% (↓3.3%) |
| GPT-5 | 60.0% | 68.0% (↑13.3%) |
| Claude 3.7 Sonnet | 46.0% | 50.0% (↑8.7%) |
| Claude 4 Sonnet | 58.0% | 64.0% (↑10.3%) |
| Claude 4.5 Sonnet | 62.0% | 76.0% (↑22.6%) |

存在明确能力门槛：GPT-5-Nano 轨迹检查显示其不理解工具创建目的、频繁陷入循环导致大幅负迁移；越过门槛后增益随模型强度单调放大（Claude 4.5 Sonnet 相对 +22.6%）。工程含义有二：一是该设计对模型迭代是顺风布局（模型越强收益越大）；二是部署侧需按模型分级启用，弱模型应回退固定工具集。

## 6. 贡献与启示

**方法论贡献**：证明 prompt 级最小修改即可释放 LLM agent 的运行时自进化能力，无需改动 agentic loop、无需离线训练；改进信号源从离线 benchmark 分数变为任务内环境反馈，从机制上规避了 benchmark 过拟合与对特定 LLM 的特化。与 SICA/DGM/HGM 的对照（65.0% vs 53.3%，离线成本 0 vs 1231h）是“在线优于离线”在该子域内的清晰证据。

**工程与评测贡献**：机制与任何 agent loop、任何 LLM 正交，成本增量可忽略；论文据此提出将其作为统一开放脚手架做模型横评（替代各家私有 harness，保证 apples-to-apples），并同时联评“工具创建能力”——这一维度在现有评测中缺失，GPT-5-Nano 的失败案例说明它恰是区分模型高层推理能力的有效探针。团队维护在线 leaderboard。

**论文自述的边界**：进化范围目前限于工具层，系统 prompt、环境交互方式、整体工作流的在线修改属展望；工具在任务结束后即被丢弃，跨任务序列化（借 Anthropic Skills 类概念）与训练期自进化（让 LLM 在训练中学会创建工具与修改脚手架）均为 future work；弱模型存在负迁移风险。

**对音视频技术上下游的关联**（笔记作者视角，非论文内容）：其一，代码库维度——媒体基础设施（编解码库、容器/封装库、GStreamer 类框架、播放器、流媒体服务端）多为 C/C++/Rust/Go 大型仓库且具备构建-测试回路，与 SWE-Bench Pro/Multilingual 的任务形态同构；本方法 LLM/scaffold 无关，可直接迁移到媒体库的 issue 修复场景，免去为每个媒体子域手工定制 agent。其二，工具维度——论文中最有说服力的收益形态是“专有二进制格式分析器”（MARC 例）与“面向目标语言的轻量静态分析器”（go_analyzer 例），媒体域恰好密集存在同构需求：码流/容器探针（NAL/SEI 解析、封装盒结构 dump）、filter graph / pipeline 配置分析、trace 与模糊测试驱动，均属“通用 bash 难以表达、任务特定收益大”的区间。其三，下游编排——A/V 生产管线（转码、剪辑、质检自动化）正被 LLM agent 接管，运行时工具合成直接降低为每个工作流环节维护定制工具集的工程成本，契合媒体生态工具链碎片化的现状。其四，评测启示——媒体领域若构建 agent 评测基准，“统一开放脚手架 + 工具创建联评”是避免被私有 harness 噪声污染的可借鉴范式。

## 7. 与其他论文的联系

- **FGSE（When Should Agents Remember? Falsification-Gated Self-Evolution）**：Live-SWE-agent 的工具仅任务内有效、无留存验证环节；若落地论文展望的跨任务工具/经验序列化，FGSE 的“经验作为可证伪假设、经探针验证后才写入记忆”恰好补上留存安全层，防止错误工具累积污染后续任务。二者为在线进化与更新安全的互补件。
- **SkillDuet（Co-Evolving Models and Skills through Response Feedback）**：Live-SWE-agent 在 future work 中明确提出训练期自进化与工具的 Skills 化序列化；SkillDuet 以响应反馈协同 LLM 参数更新与外部技能库演化，正是该展望的一种实例化路径——两者分别覆盖推理期（Live）与训练期（SkillDuet）的自进化。
- **TRUST（Trustworthy Recursive Self-Improvement with Statistical Guarantees）**：Live-SWE-agent 的每任务环境反馈没有任何统计控制，GPT-5-Nano 相对 -68.2% 即失控例证；TRUST 用在线多重假设检验控制错误进化率，是 Live 从“单任务瞬态进化”扩展到“持续留存、持续进化”时缺失的统计保障层。
- **LongCapHarness（Capability-Guided Auto-Harnessing for Long-Context Reasoning）**：共享同一论点——固定人工脚手架次优、按能力自适应挂接的方案在成本与效果上双赢；作用轴不同（长上下文能力 vs 工具动作空间），构成“能力引导式自适应 harness”谱系在不同能力维度的平行验证。
- **InfraRSI（Harnessing Recursive Self-Improvement for Training Infrastructure）**：同属“agent 修改自身工作的软件系统”的 RSI 实例；对照在于 InfraRSI 以五阶段验证工作流做离线式把关后产出优化，Live-SWE-agent 靠任务内反馈即席进化，验证粒度与时间尺度互补。
- **WeightLoop（Weight-Space Programming with Experimental Feedback）**：自修改作用面在权重空间（有界参数编辑程序 + 实验反馈、免重训练）vs 本文的脚手架/工具空间；二者是同一递归自改进栈的不同层，原则上可叠加。
- **AutoTavern（Hearthstone Battlegrounds AI）**：同为 LLM agent 自主构建软件制品（20 天内自建模拟器与 AI、天梯约 15000 分）；时间尺度形成对照——Live-SWE-agent 是单任务内的瞬态工具合成，AutoTavern 是长周期的制品累积，后者正对应 Live 展望的跨任务连续自进化方向。
