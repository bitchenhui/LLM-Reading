# FunL2O: LLM-Guided Feature Function Design for Learning to Optimize

## 1. 背景与动机

Learning-to-Optimize（L2O）利用“同一数学结构、不同数值数据被重复求解”的规律，在历史实例上训练模型以预测解、热启动迭代算法、选择单纯形基/pivot 或引导混合整数搜索。无论学习组件扮演何种角色，所有 L2O 方法都始于同一个设计决策：如何用特征把优化实例表示为模型输入。论文将管线形式化为 x →φ→ X →M→ a →S→ ŷ：特征函数 φ 决定哪些数值与结构关系对学习器“直接可见”——有用的关系若未显式给出，模型只能从输入中间接推断，因此仅改输入表示就能同时影响模型表达能力与下游性能。

现状缺口：φ 通常由人工设计并在训练前固定，研究重心几乎都放在模型架构、学习目标与求解器接口上。而自动化特征设计并非简单的特征选择问题——L2O 特征函数是作用于结构化优化数据的**可执行程序**，必须： 保持模型特定的张量接口； 满足语义与维度不变量（确定性、有限输出、保留种子通道）； 只依赖部署期可得信息（禁止访问参考解、训练标签、文件、网络、额外求解器调用）； 其质量只能在**重训学习器并测量下游优化表现之后**才能判定，且评价指标随角色而变（预测类看可行性与目标质量，求解器策略类看迭代数、pivot 数、搜索代价、wall time）。这种“评估即重训”的昂贵黑箱结构使常规 AutoML/特征选择手段不直接适用。

FunL2O 的定位：第一个以 LLM 驱动程序进化（FunSearch 式循环）自动设计 L2O 可执行特征函数的统一框架，在 8 条 L2O 管线上验证，且不改模型、损失、训练流程与求解器接口。

## 2. 方法总览

**搜索问题形式化。** 给定管线 P、学习模型 Mθ 与手工特征 φ0，候选 φ: XP→ZP(dφ) 替换 φ0 后诱导一个全新训练问题 θ*φ = TrainP(φ; Dtr)（若 dφ 与原宽度不同，仅机械重建输入层宽度；模型模板、隐层架构、损失、优化器与调度均不搜索）。训后在验证集上度量 mP(φ) = Agg_{x∈Dval} μP(x, ŷφ(x))，其中 μP 由原管线定义（可行性率、约束违反度、目标间隙、迭代数、运行时间、pivot 数等）。候选间通过管线特定排名键 ρP(φ) = (bP, vP, qP) 按**字典序**比较（取小优）：bP 为可行性条件是否被违反的判定，vP 为不可行程度，qP 为目标质量或求解器代价（符号统一为越小越好，如目标间隙、迭代数、pivot 数或“迭代节省量的负值”）。字典序设计防止“不可行但目标值好看”的候选胜出，并使同一外层问题统一覆盖解预测质量、热启动有效性与学习型求解器决策：φ* ∈ argmin_{φ∈ΦP} ρP(φ)。

该问题有两大难点： 可采纳空间 ΦP 因管线输入与模型接口而异； 外层目标是昂贵黑箱（一次评估 = 一次重训，可能外加一次完整求解器运行）。FunL2O 分别以**语义特征契约**与**基于实测结果的反馈式搜索**应对。

**搜索循环。** 先评测 φ0，其源码、特征宽度、实测结果与排名键初始化搜索记忆（φ0 同时充当性能基线与契约的首个合法样例）。每代：由契约与当前记忆构造提示 → 提案模型采样候选种群 → 通过验证器者进入 Φg（失败者收到被违反条件并回修，至多 3 次）→ 每个合法候选替换 φ0 进入管线副本，按原数据/损失/调度重训并以 μP 评测（代内候选在给定记忆下条件独立，可并行）→ 记忆更新，TopK 最低排名键者作为下一代精英上下文。搜索结束返回记忆中排名最低的合法特征函数——它就是一段普通可执行预处理代码，部署期既不需要 LLM 也不需要搜索记忆。

## 3. 关键设计

**语义特征契约 CP = (UP, ZP, IP, VP)。** UP 为部署期可用的实例字段或求解器状态信息；ZP 定义返回类型、维度朝向与最大特征宽度；IP 描述必须保持的性质（确定性、有限输出、必留的手工种子通道）；VP 为可执行验证器。可采纳空间定义为：φ 属于受限执行环境 Hsafe 中的可执行函数，且 Fields(φ)⊆UP、φ(x)∈ZP(dφ)、不变量成立；候选可重组原方法已有的信息，但不得访问参考解、训练标签、文件、网络或外部求解器。常见 append-only 情形下候选形如 φ(x) = Concat(φ0(x), ψ(x))，结构化输出则对 variable/constraint/edge/global 各通道分别施加保留要求——这使 FunL2O 能共享一套搜索流程而不强迫异构 L2O 方法进入统一表示。

**两级验证。** VP 先对候选源码做静态守卫（清洗 import，禁止外部 I/O、动态代码执行、可变全局态与不可用信息源），再在小探针实例上动态执行，检查函数签名、返回结构、行/批对齐、特征宽度、数值有限性与必需种子通道。通过 VP 只确立**接口有效性**；是否有用完全由重训与下游评测决定。论文表 6 给出接口实例：IPM-MPNN 的 compute_features(A,b,c,sense,lb,ub) 须保留每类节点前两通道并输出变量/约束/全局张量；FSNet 的 compute_fsnet_input_features(problem,state) 输出 B×F 稠密张量且原始状态张量为前置通道；DC3 的 compute_dc3_extra 输出 B×K（K≤64）追加于宿主输入；Smart Initial Basis 输出 n×K 与 m×K（K≤32）追加于锁定种子通道；Learning to Pivot 输出 (n+m)×K（K≤32）追加于 11 维宿主输入；两个 MILP 宿主共用 compute_variable_features(model,relaxation) 输出每变量 n×F 张量。

**标准化提示构造。** pg = T(R, CP, G, Eg, Fg)：R 为共享规则（只改特征函数、返回确定性可执行函数）；CP 提供可用输入、函数签名、输出结构与管线原生评测规则；G 为共享词汇表，按“原始问题量、尺度、残差、曲率、界、锥、图统计”等宽泛关系分组引导提案（不构成固定特征库）；Eg 含当前精英函数的源码、特征宽度与验证结果；Fg 含契约错误或上一代是否改进当前最优的摘要。关键信息隔离：提案模型只收到聚合验证结果与候选源码，**不接触验证实例、目标解或测试结果**——LLM 提议的是特征计算方式，而非对其性能的预测。记录的 API 模型为 claude-opus-4-8、azure/gpt-5.5、gcp/gemini-3.1-pro-preview、DeepSeek-Math-V2，最大补全长度 16,000 tokens。

**搜索预算与精英制。** 每次搜索 8 代 × 6 提案槽 = 48 个 LLM 候选；每代取排名最低的 2 个程序作为精英上下文；φ0 全程保留在记忆中，无候选在验证排名键上超越它时直接返回 φ0（种子保留使“等号结果”可解释为成功保住强原始表示，而非被迫替换）。

**八宿主管线实例化（论文表 1/4）。** 连续侧：IPM-MPNN（LP 解预测，监督，80 epochs，hidden 128）；FSNet（QP/QCQP/SOCP 约束解预测，自监督，40 epochs，hidden 1024）；DC3（约束 QP，200 epochs）；PDHG-Net（PageRank LP 原对偶热启动，300 epochs）；Smart Initial Basis（集合覆盖 LP 初始基状态，200 epochs）；Learning to Pivot（集合覆盖 LP pivot 分数，20 epochs）。MILP 侧：Predict-and-Search 与 Learned Backdoors（CA/MIS/MVC，300 epochs，k=8，CPLEX）。各宿主的主/次指标不同（如 IPM-MPNN 看目标间隙↓/可行性↑，P&S 看 primal gap↓/primal integral↓，backdoor 看 wall time↓/win rate↑），但提议、验证、重训、选择流程完全共享，仅 CP、μP、ρP 随宿主替换。

## 4. 实验结果

**设置口径。** 连续实验用四个前沿 LLM（Claude-Opus-4.8、GPT-5.5、Gemini-3.1-Pro Preview、DeepSeek-Math-V2），MILP 用前两个；每个“手工 vs 进化”对比为 3 次独立种子配对重复的算术均值（同初始化种子、数据序种子、划分与求解器参数），主表连续结果是四个提案模型配置（各自先做 3 次配对平均）之后的中位数。训练/验证/测试实例三级不相交，搜索期排名只用验证指标，测试集仅在选定程序后评估一次。P&S 用 CPLEX 1000 s 时限，backdoor 分支用 600 s。提升率 IR：低优指标 IR = 100(B−F)/|B|，高优指标分子取 F−B，正值恒为改进。

## 5. 消融要点

**等宽随机投影对照（append-only 宿主）。** 将搜索到的追加通道替换为同宽度固定随机投影、其余训练设置不变：PDHG-Net 迭代节省为手工 35.59% → 随机 45.19% → FunL2O 47.99%；六个支持的 LP/PDHG 设置中 FunL2O 在五个上最优（IPM-MPNN set cover 0.00855/0.00588/0.00300；唯一例外是 combinatorial auction，随机 0.01221 优于 FunL2O 0.01398，论文如实披露）。结论：收益主要来自优化相关的语义结构而非单纯加宽输入维度。

**等预算进化反馈对照。** 同一提案模型、同样 48 次 LLM 调用与 48 次候选重训、同契约同评测器，仅移除精英记忆与实测结果反馈（每次提案只以手工种子为条件）：PDHG 迭代节省 44.42%（独立采样）vs 52.23%（完整进化），**7.81 个百分点**可归因于实测进化反馈本身，剥离了泛泛的 best-of-48 效应。

**种子保留语义。** 手工函数始终是合法候选，替换仅在验证排名键改善时发生；这使等号结果可解释、也使“多候选评估”不强制替换。

**搜索成本。** 每次搜索 48 个候选：LLM API 约 $4/提案（合计约 $192）；重训约 15 GPU-min/候选（合计 12 GPU 时）；下游 CPU 评测约 1000 s/候选（合计约 13.3 CPU 时）；单 GPU + 单 CPU 无并行串行约 25.3 小时（不含 LLM 响应延迟）。成本随 pipeline×task×提案模型组合数线性扩展，但候选可并行；部署期零 LLM 成本、仅标准预处理开销。

**进化程序的可读结构。** set cover 程序按列覆盖度归一化变量成本、按行覆盖度归一化约束信号（log1p 度数、系数范数、tanh 压缩的 cover_ratio/obj_eff）；PageRank 程序区分行/列质量与度（torch.log1p + tanh 共享），显式暴露有向图的不对称性；非线性任务的程序构造多尺度表示（幅值、符号、对数、平方、归一化、局部差分）；MILP 程序组合变量类型、目标系数与 LP 松弛值、分数性、reduced cost、行列统计与归一化约束信号。这些均为可直接检查的预处理代码。

## 6. 贡献与启示

**方法论贡献。** 其一，把特征函数设计形式化为原 L2O 管线内的程序搜索问题，并给出覆盖异质图、稠密张量与求解器状态的语义契约体系——这是让“一套搜索流程服务八种异构接口”的关键抽象。其二，L2O-in-the-loop 评测：候选价值由重训后的原生下游指标（而非 LLM 判断）决定，配合字典序排名处理可行性优先。其三，可解释副产品：每个进化程序即“原表示缺了什么信息”的可检验假设，兼具可部署性与可审计性。

**工程含义。** 离线搜索成本以重训为主且线性扩展，但部署零额外开销，适合重复求解场景摊销；论文刻意采用简单进化环（Top-2 精英 + 验证反馈），以便把性能增益归因于特征质量而非搜索工程，作者明示更复杂的选择/变异/交叉机制为互补性未来工作，且不主张对任意 AutoML/遗传编程/固定库系统的普适支配。泛化风险通过“仅验证集选择 + 不相交测试集报告 + 三次种子配对”控制。

**与音视频技术上下游的关联。** 本工作属 LLM×优化的方法论文，但对音视频系统的直接关联在于“同结构重复求解”这一 L2O 前提在媒体管线中大量存在：编码器参数/RD 模式决策、码控与比特分配、流媒体缓存与调度、实时资源分配等均可视为结构固定、数值变化的重复优化，其中嵌入的 learned 组件（如学习型码控、GNN 视频分区、QoE/卡顿预测器）同样依赖手工输入表示。FunL2O 的“语义契约 + 重训评测 + 原生下游指标”搜索范式可迁移到这类媒体侧预测器的特征设计；需注意其成本模型以“每候选一次完整重训”为瓶颈，对训练昂贵的音视频大模型需先解决代理评测问题。

## 7. 与其他论文的联系

- **EoH（arXiv:2401.02051）**：论文相关工作直接引用（Liu et al. 2024a）并将其列为 FunSearch 同族系统。关联与差异：两者同属“LLM 提案 + 外部评测器定适应度”的演化范式，但 EoH 搜索启发式算法本体，FunL2O 搜索 L2O 管线中的表示函数，且每次适应度评估需完整重训宿主模型——这一更贵的评测结构正是其引入语义契约与 append-only 接口约束的动因。
- **FunBO（arXiv:2406.04824）**：同为 FunSearch 式程序搜索用于发现领域函数（贝叶斯优化采集函数）。FunL2O 将该范式推进到“重训在环”的表示设计，并以语义契约约束候选接口、以字典序排名处理可行性，可视为 FunSearch 方法族向带训练闭环的 ML 组件设计的扩展。
- **QUBE（arXiv:2412.20694）**：用质量-不确定性权衡准则（QUTC）重定义 FunSearch 的选择标准。FunL2O 刻意只用 TopK 验证排名 + 字典序键；在每候选评估昂贵（15 GPU-min 重训）的场景下，QUBE 式选择准则改进是论文自述的互补方向。
- **HSEvo（arXiv:2412.14995）**：以和声搜索 + 遗传算法平衡多样性与收敛。FunL2O 无显式多样性管理，代际信息仅靠精英源码与聚合反馈；对本文观察到的提案模型间方差（如 CA 上 GPT 变体劣于手工）与部分任务零改进现象，多样性驱动机制是直接对症的后续选项。
- **ε-MemEvo（arXiv:2608.12522）**：将成功算法策略存为任务无关记忆并跨任务注入。FunL2O 的搜索记忆严格按 pipeline×task×提案模型独立、互不复用，每次搜索都从手工种子冷启动；ε-MemEvo 的跨任务记忆迁移恰好指向本文最大的工程痛点（48 候选 × 重训的离线成本），例如把 set cover 族学到的 coverage 归一化策略迁移到新 LP 分布。
- **LLM 驱动的群智能算法-提示协同进化（arXiv:2512.09209）**：让算法与引导提示词共同进化。FunL2O 的提示模板除精英上下文与反馈摘要外完全固定，提示侧不参与进化；该文的协同进化思路可作为 FunL2O 在弱提案模型（如 DeepSeek-Math-V2 仅改进 6/20 单元）场景下的扩展方向。
