# HALL-E: Hierarchical Neural Codec Language Model for Minute-Long Zero-Shot Text-to-Speech Synthesis

> Yuto Nishimura, Takumi Hirose, Masanari Ohi, Hideki Nakayama, Nakamasa Inoue. *arXiv:2410.04380v1 (2024-10-06)*

## 1. 背景与动机

LLM-based TTS 的主流范式（VALL-E 一系）是“冻结神经音频编解码器（NAC）+ 解码器式语言模型”：AR 模型自回归生成 RVQ 第一层 token，NAR 模型逐层补全其余量化层，最后由 codec 解码器重建波形。该范式的长语音瓶颈不在语言模型容量，而在**序列长度正比于第一层帧率 × 时长**。以 Encodec 为例，原始帧率 75 Hz（stride 320），本文作者将其改造为 48 Hz（stride 500）后，180 秒语音的第一层 token 已达 8640 个，远超 VALL-E 系模型通常的训练分布（数秒至数十秒）。

直接在 codec 侧降帧率并不可行。论文的预实验（Encodec 在 LibriSpeech 上以 PESQ/WER 随帧率扫描）显示：帧率降到 48 Hz 以下重建性能显著恶化，8 Hz 下训练完全失败（后文 Table 3 中该配置 WER 100.0、PESQ 1.25）。此前的帧率下限是 Défossez et al. 2024（Moshi 的 codec）的 12.5 Hz。

由此论文提出核心判断：**降帧率不是单纯的 codec 压缩问题，而是 codec 与 LLM-TTS 之间的联合设计问题**——第一层 token 既要承载足够的语言学信息供 AR 建模，又要在低帧率下保持可训练性。据此贡献三件事：(1) MReQ，对预训练 NAC 的后训练框架，把第一层帧率降至 8 Hz；(2) HALL-E，预测层级 token 的 LLM-TTS 后训练方法；(3) MinutesSpeech，40k 小时训练 + 8 小时专业转写测试的长语音基准。

## 2. 方法总览

整体方案是“两级后训练”，均以预训练模型为起点而非从头训练：

**Codec 侧（MReQ）**：在预训练 48 Hz Encodec 的 RVQ 位置替换为多分辨率残差量化模块（MRVQ）——由 4 个低帧率残差量化块（LRVQ）嵌套组成，各块帧率 8/16/24/48 Hz。原 RVQ 冻结为教师，MRVQ 为学生，在特征级蒸馏（FLD）与隐状态重建（HSR）两项损失约束下继续训练（encoder/decoder 复制权重继续训）。最终第一层量化帧率 8 Hz，重建质量与 48 Hz 原始模型基本持平。

**LM 侧（HALL-E）**：AR 模型在 8 Hz token 序列上自回归（6 层 token 以 MusicGen 式 delay pattern 交错排列，序列长度维持在近 8 Hz）；NAR 模型不直接学习跨帧率映射，而是**复用冻结的 MRVQ 子模块**（子解码器、PostQ、PreQ、子编码器、主量化器）作为确定性变换桥，把 NAR 的学习任务退化为 VALL-E 式的同帧率层间映射。HALL-E 同样从预训练 VALL-E 继续训练。

**数据侧**：播客来源、时长 3–180 s 均衡分布的 40k 小时训练集（自动转写）与 CC 许可、双专业转写员制作的 90 s / 180 s 两个测试子集，使“单次推理合成分钟级语音”第一次有了直接可评的基准。

推理链路：文本 + 3 s 音频提示 → AR 生成 8 Hz 六层 token（b₁）→ NAR 借 MRVQ 子模块迭代 4 个 block 补全至 48 Hz 域全层 token → codec 解码器输出波形。全流程单步完成，无拼接。

## 3. 关键设计

### 3.1 MRVQ 的嵌套结构与三种 token 的分工

每个 LRVQ 块 k 包含五部件：预量化器 PreQ(α 层 RVQ)、子编码器 E_k（卷积 + 两层 bi-LSTM，按 stride 从 48 Hz 降到 s_k）、主量化器 Quant(β 层 RVQ)、子解码器 D_k（两层 bi-LSTM + 转置卷积）、后量化器 PostQ(γ 层 RVQ)。块间以残差级联，块内量化路径为 a_k → b_k → c_k：

- **b_k ∈ N^{β×n_k}**：低帧率（s_k Hz）主 token，是 AR 模型的建模对象与块间信息载体；
- **a_k（48 Hz 域）**：PreQ 输出，是 NAR 模型的预测目标；
- **c_k（48 Hz 域）**：PostQ 输出，作为 NAR 的输入特征，仅服务于下游 TTS 训练。

具体配置：k=1（8 Hz，1-6-1，stride 6）、k=2（16 Hz，2-6-2，stride 3）、k=3（24 Hz，2-4-2，stride 2）、k=4（48 Hz，3-0-0，仅保留 PreQ，E/D 与 Quant/PostQ 退化为恒等）。这一设计的关键在于：**降帧率只发生在块内（b 域），而块间的残差累加与教师 RVQ 的层间累加同构**，使 8 Hz 信息被强制压入第一块而非被绕过。各块 α 累积为 1/3/5/8，与教师 8 层 RVQ 逐级对齐。

### 3.2 为什么必须蒸馏：FLD 与 HSR 损失

从头训练 MRVQ 时，附录 C.1 明确指出 8 Hz 一级的 LRVQ 会被忽略，学习过程退化为“全部信息由高帧率层补充”。MReQ 用两个损失扭转这一动力学：

- **FLD（特征级蒸馏）**：MAE(学生累积 embedding Σ c̃_k, 教师累积 embedding Σ z̃_l)，配对集 P={(1,1),(2,3),(3,5),(4,8)}——即学生累积到第 s 块的层数（1/3/5/8）逐级对齐教师前 t 层，权重 (λ¹,…,λ⁴)=(8,6,4,2) 递减。这保证了第一块 8 Hz token 被约束去复现教师前层（富含语言+声学）的表征。
- **HSR（隐状态重建）**：MAE(ã_k, D_k(b̃_k))，驱动每个块内部“低帧率码 → 升采样 → 还原 a_k”路径自洽，权重同为 (8,6,4,2)。

总损失 L = L_NAC（原 codec 损失）+ L_FLD + L_HSR；用教师权重的副本继续训练 encoder/decoder。架构上 MReQ 只假设量化器为 RVQ，与 encoder-decoder 结构解耦——论文据此把它无缝叠加到 SpeechTokenizer（仅权重不同，结构同 MReQ-Encodec），这是该框架工程可迁移性的核心论据。

### 3.3 HALL-E 的 AR：8 Hz + delay pattern

b₁ 有 6 层（β₁=6）。若扁平拼接训练，序列长度等价于 48 Hz，降帧率失去意义。HALL-E 沿用 MusicGen 的延迟模式把 6 层 token 交错排布，在 next-token prediction 框架内一次生成六层，序列长度维持在近 8 Hz——90 s 音频的音频 token 上限仅 720（Table 2），AR 建模难度大幅下降。训练目标为对 b₁ 的交叉熵，从预训练 VALL-E 权重继续训练。

### 3.4 HALL-E 的 NAR：把跨帧率映射外包给冻结子模块

NAR 的一个候选设计是内嵌可学习上采样层直接预测 b_{k+1}←b_k，论文明确否决：单一 NAR transformer 难以处理不同帧率，且子编/解码器夹在中间使层间关系复杂化。实际方案是三步循环：

1. ĉ_k = PostQ_γ(D_k(b̃_k))——冻结子模块把低帧率码升回 48 Hz 域；
2. NAR transformer 从 ĉ_k 预测 â_{k+1}，需执行 α_{k+1} 次（逐层预测 PreQ 的每一层，层 id ℓ 取累积 PreQ 层数编码，复用 VALL-E 式层间条件）；
3. b̂_{k+1} = Quant_{k+1}(E_{k+1}(ã_{k+1}))——再经冻结子模块压回低帧率。

如此 NAR 的输入输出都停留在 48 Hz 域，学习的映射关系“形似原始 VALL-E NAR”，训练效率高（消融见第 5 节）。

### 3.5 文本注入改 cross-attention 与滑窗推理

NAR 在 48 Hz 域工作，90 s/180 s 全长 token 难以整段训练，因此训练时把音频裁剪到 28 s/54 s 等效长度。但裁剪后音频与文本无对齐，VALL-E 原有的“文本拼接输入”方式失效。HALL-E 的对策是在 NAR 每个 transformer 层插入 cross-attention 子层注入文本 token，由注意力自动学习对齐（论文称 VALL-E 框架内尚无先例，Small-E 有更精炼的类似设计）。推理时 NAR 以 5 s 滑窗逐段推进。

### 3.6 MinutesSpeech 的管线与“等 token 预算”设计

训练集管线：296,464 个播客文件（10–90 分钟，约 186k 小时）→ 按 30 s 分段计算 PESQ，保留均值 >2.5 且标准差 <0.6 的文件（约剩 25%）→ Whisper distil Large v3 转写 + pyannote 3.1 说话人分离，切出单说话人 3–90/180 s 段 → 按文本长度分布过滤 → 40k 小时。测试集为 CC 许可播客人工挑选，两位英语母语专业转写员制作转写：test-90s 共 685 条 / 8.61 h，test-180s 共 536 条 / 8.45 h。

一个值得注意的实验设计细节：为 VALL-E 准备的 train-28s（48 Hz）与为 HALL-E 准备的 train-90s（8 Hz）最大 token 总长被刻意配平（1658 vs 1655；音频 token 1344 vs 720、文本 314 vs 933），使“帧率收益”与“序列长度预算”解耦。同时这一数据也暴露了新瓶颈：8 Hz 下音频 token（1440@180 s）已短于文本 token（1733），AR 序列长度开始由文本侧主导——论文在 limitation 中明确指出，并指向 Small-E 的 cross-attention 架构为解决方向。

## 4. 实验结果

评测口径：WER 用 NVIDIA conformer-transducer 大模型转写计算；SIM 用 WavLM-TDNN；DNSMOS 用 ITU-T P.808 真值训练的模型；WD 为生成与真实语音的时长分布 Wasserstein 距离；QMOS/SMOS 每测试集随机 40 条、3 位英语母语者评 1–5 分。音频提示固定 3 s。

**语音重建（LibriSpeech 测试集）**：MReQ 在把第一层帧率压到 8 Hz 的同时基本无损：

| NAC 模型 | 帧率 | WER↓ | PESQ↑ |
|---|---|---|---|
| GT | – | 1.96 | 3.56 |
| Encodec | 8 Hz | 100.0 | 1.25 |
| Encodec | 48 Hz | 2.00 | 3.45 |
| + MReQ | (8,16,24,48) | 2.02 | 3.47 |
| SpeechTokenizer | 48 Hz | 2.00 | 3.52 |
| + MReQ | (8,16,24,48) | 1.99 | 3.53 |

直接 8 Hz 训练的 Encodec（WER 100.0）与 MReQ（WER 2.02）之间就是“层级重组 + 蒸馏”的全部价值所在。

**MinutesSpeech test-90s / test-180s（零样本 TTS，关键行）**：

| 配置 | WER↓ | SIM↑ | WD↓ | DNSMOS↑ | QMOS↑ | SMOS↑ |
|---|---|---|---|---|---|---|
| test-90s GT | 10.30 | – | – | – | 3.79±0.24 | 3.83±0.30 |
| VALL-E / train-28s | 39.77 | 0.726 | 23.62 | 3.84±0.19 | 2.29±0.32 | 2.04±0.25 |
| VALL-E / train-90s | 16.14 | 0.712 | 2.68 | 3.87±0.17 | 2.48±0.28 | 2.36±0.26 |
| HALL-E / train-90s | **9.79** | 0.685 | 4.00 | **3.91**±0.21 | **3.35**±0.26 | **3.15**±0.26 |
| test-180s GT | 10.20 | – | – | – | 3.78±0.25 | 4.26±0.22 |
| VALL-E / train-54s | 36.52 | 0.706 | 25.66 | 3.55±0.53 | 1.68±0.25 | 1.70±0.26 |
| VALL-E / train-180s | 21.71 | 0.702 | 12.52 | 3.76±0.30 | 2.11±0.26 | 2.15±0.26 |
| HALL-E / train-180s | **10.53** | 0.660 | 5.79 | **3.91**±0.19 | **3.38**±0.25 | **3.31**±0.23 |

三个结论：(1) HALL-E 的 WER 与 DNSMOS 达到甚至优于 GT（GT 自身 WER 10.30 来自播客自发语音的 ASR 难度）；(2) VALL-E 单纯换长训练数据不够——train-90s 下 WER 仍 16.14，因为高帧率 AR 训练本身不稳定；(3) SIM 上 VALL-E 略优（降帧率牺牲声学细节），但 SMOS 反超，说明听感上时长/停韵等风格要素的权重更高。定性分析显示 VALL-E 生成的波形几乎无静音且反复重复呼吸声/填充词，HALL-E 的时长分布系统性更贴近 GT。

**LibriSpeech test clean（≤35 s 朗读语音）**：VALL-E 的 WER 随训练音频长度单调恶化（train-28s 4.05 → train-54s 6.03 → train-90s 7.17 → train-180s 95.46，后者近乎崩溃），HALL-E 则稳定在 4.63（train-90s）/ 4.49（train-180s）；WD 也从 VALL-E 的 0.442/0.414 降到 0.196/0.166。与 GT（WER 1.74）的残差被归因于朗读语音域偏移——平衡朗读与自发风格是遗留问题。

**换底座 codec（test-90s）**：MReQ-SpeechTokenizer 全面优于 MReQ-Encodec（WER 9.12 vs 9.79，WD 3.09 vs 4.00，DNSMOS 3.95 vs 3.91），且 SpeechTokenizer 版 HALL-E 相对 VALL-E+SpeechTokenizer（WER 35.62）的改善幅度与 Encodec 版一致。这与 SpeechTokenizer 第一层偏重语言学信息的特性吻合：帧率压缩时丢的更多是声学信息，语义保持型 codec 受益更大。

**计算效率**：RTX 4090 上、LibriSpeech 4–10 s 段测量，RTF 从 VALL-E 的 0.213±0.020 降到 HALL-E 的 0.062±0.003（约 3.4 倍加速），来源是 AR 生成 token 数减少 6 倍（48→8 Hz），而 AR 恰是 LLM-TTS 的推理瓶颈。

## 5. 消融要点

**层级结构必要性**：在 test-90s 上，两段式 (8,48) WER 10.27、(8,16,48) WER 10.71，均劣于完整四段 (8,16,24,48) 的 9.79。更强证据在训练动力学：(8,48) 配置在约 60% 训练进度后损失发散——预训练模型与后训练模型在第一层的分布突变导致不稳定，逐级升帧的层级建模正是为了吸收这种分布漂移。代价是 48 Hz 层数减少导致 SIM 轻微下降（0.685 vs 0.693），即 WER-SIM 存在 trade-off。

**MReQ 组件消融（重建，LibriSpeech）**：完整方案 2.02/3.47；去预训练 2.08/3.44；去 FLD 2.03/3.47；去 HSR 2.15/3.44。HSR 与预训练对重建影响直接；FLD 对重建影响微小但**对 TTS 至关重要**——codec 层级有冗余，第一层丢失的信息可由后续层补偿，但 AR 模型只看第一层，FLD 是保证第一层信息充分的前提。

**FLD 的重建/TTS 分离现象（test-90s）**：去掉 FLD 后 TTS 的 WER 反而降至 9.07、SIM 升至 0.704，但 WD 恶化到 4.51、DNSMOS 降到 3.88。解释：无 FLD 时声学信息丢失更多、语言信息相对保留更好（WER 受益），但整体自然度下降。FLD 本质是在 8 Hz 码本里强制保留教师第一层的语言+声学混合表征，以 WER/SIM 换自然度。

**HALL-E 组件消融（test-90s）**：完整方案 WER 9.79/SIM 0.685；去预训练（不从 VALL-E 续训）WER 崩至 49.80/SIM 0.647——LM 侧后训练是硬前提；仅训 PreQ 域 10.36/0.682、仅训 PostQ 域 10.11/0.683，均劣于完整的三步循环，验证了“冻结子模块做跨帧率桥”的设计。论文据此强调 codec 设计必须考虑下游任务的输入输出接口。

**更低帧率 4 Hz**：(4,8,16,24,48) 使 WER 恶化到 20.07——音素平均时长约 100 ms（对应约 10 Hz），4 Hz 低于该物理尺度、被认为根本性困难；但 WD 从 4.00 大幅改善到 1.95，说明更低帧率确有捕获更长时程动态的收益，只是当前代价过高。

**降码率（β 减半，3.84→2.64 kbps）**：重建 WER 2.02→2.13、PESQ 3.47→3.42；TTS WER 9.79→13.31，但 SIM（0.713）、WD（2.76）反而改善（AR 层数 6→3 更易训、块间差异更小利于 NAR）。总体结论：帧率与码率不宜同时压，MReQ 框架内最好保持原码率，码率优化应回到 NAC 侧解决。

**α-β-γ 超参鲁棒性**：四种等 bps 组合 (1,1,2,4)/(1,1,3,3)/(1,2,2,3)/(1,2,3,2) 在两个数据集上互有胜负，唯 α₄=2（48 Hz 块的层数被削）一致最差（test-90s WER 10.58、LibriSpeech 5.68），呼应 Figure 1 中 48 Hz 起质量骤降的拐点——48 Hz 域的容量应尽量保留。推荐 (1,2,2,3)。

**长提示与填充词**：test-90s 中 >25 s 段上，提示从 3 s→10 s→20 s，SIM 0.663→0.734→0.815，显示 8 Hz AR 有消化长提示、逼近 fine-tuning 级克隆的潜力。填充词统计（词表含 so/you know/like/um/uh 等 12 词）：test-90s 上 GT 3.74±3.66、HALL-E 3.45±3.35、VALL-E 3.22±3.30 个/条；test-180s 上 VALL-E 方差膨胀到 ±7.05（AR 重复生成填充词），HALL-E（4.19±4.66）无此现象——低帧率对抑制 AR 重复的直接证据。

## 6. 贡献与启示

**方法层面**，本文把“降帧率”从 codec 训练问题重构为**预训练模型之上的中间层重组问题**：MReQ 只假设量化器为 RVQ、不绑定 encoder/decoder 结构，HALL-E 从既有 VALL-E 续训。8 Hz 相对此前 NAC 最低帧率 12.5 Hz 约再降 1.5 倍，且重建无损（SpeechTokenizer 版 PESQ 3.53 甚至略高于原模型 3.52）。这一“后训练改造 token 体系”的范式意味着：生态中已有的 codec 权重与 TTS 权重不必推翻重训，换 token 层级即可获得长程建模与 3.4 倍推理加速（RTF 0.062），对语音对话/流式系统的实时预算是实质性利好。

**信息结构层面**，论文给出了帧率压缩下语言/声学信息再分配的细致刻画：FLD 消融中 WER 与 WD/DNSMOS 的反向变化、SpeechTokenizer 底座的全面收益、SIM 的系统性小幅损失，共同指向“8 Hz 第一层应优先保语言信息、声学信息下沉到后续高帧率块由 NAR 恢复”的分工原则。4 Hz 实验中 WER 崩溃与 WD 大幅改善的并存，则标定了帧率下界（约音素尺度 10 Hz）与时程建模收益的分离。

**数据层面**，MinutesSpeech 是首个面向分钟级 TTS 的开放基准（40k h 训练 + 8 h 双人专业转写测试，CC 许可，自发对话风格），其“等 token 预算”的子集设计（train-28s@48Hz ↔ train-90s@8Hz）为后续帧率类研究提供了可控对照范式；同时其数据揭示 8 Hz 之后**文本 token 成为 AR 序列长度新瓶颈**（180 s 时 1733 vs 1440），架构上需要 Small-E 式的 cross-attention 融合。

**局限与遗留**：SIM 一致低于 VALL-E；朗读风格上 WER 与 GT 仍有差距（4.5% vs 1.74%，域偏移）；验证范围限于 TTS，作者指出扩展到 AudioLM/SpeechGPT/PSLM 等语音语言模型、以及替代 SSL 特征/ASR encoder 的可能性。从音视频技术上下游看：MReQ 在固定 bps（3.84 kbps）下把帧率变为可后训练调节的自由度，与可伸缩编码中“分层码流、逐级精化”的思想同构（8/16/24/48 Hz 逐级上采样即时间轴上的嵌入式分层）；其低帧率 token 体系也是语音对话基础模型（全双工、低延迟语音到语音生成）上游表征的候选——RTF 0.062 与 8 Hz 序列为长时程语音 LM 的上下文管理提供了表征基础，而语音侧分钟级单步合成正对应视频侧长时程生成的同类序列长度困境，方法有可类比性（层级降帧 + 后训练蒸馏）。

## 7. 与其他论文的联系

- **paper:arxiv:2410.00037（Moshi）**：本文相关工作部分直接引用其 codec 成果为此前最低帧率 12.5 Hz，并以 8 Hz（约再降 1.5 倍）作为对标；两者同属“低帧率 token 服务实时/长程语音生成”路线，Moshi 面向全双工对话（约 200 ms 延迟），HALL-E 面向分钟级 TTS，前者是本文设想的下游扩展方向之一。
- **paper:arxiv:2409.12117（LFSC）**：同为“降 codec 帧率 → 加速 LLM-TTS”的路线，LFSC 从头设计 21.5 fps / 1.89 kbps 的 codec 换来约 3 倍推理提速，与本文 RTF 0.213→0.062（3.4 倍）结论互相印证；差异在 LFSC 重新训练 codec，而 MReQ 是对预训练 codec 的后训练重组，可直接叠加于 SpeechTokenizer 等语义增强底座，二者是“设计期 vs 后训练期”解决同一瓶颈的两条路径。
- **paper:arxiv:2408.17175（X-Codec）**：X-Codec 论证 codec 语义能力不足会推高 LLM-TTS 的 WER；本文 Table 6 从帧率压缩场景给出同向证据——MReQ-SpeechTokenizer（第一层偏语义）WER 9.12 优于 MReQ-Encodec 的 9.79，且 FLD 消融显示语言/声学信息的保留权衡直接决定 WER 与自然度，两文共同支撑“codec 第一层语义容量是下游 TTS 质量的决定变量”。
- **paper:arxiv:2406.07422（Single-Codec）**：以单码本单序列（304 bps）消除 RVQ 多码本的建模复杂度，是简化 LLM 侧 token 结构的另一条路线；HALL-E 的 AR 侧仍需处理 6 层 token（依赖 delay pattern 维持序列长度），若与单码本思路结合，理论上可进一步压缩 AR 序列并绕开本文“文本 token 成为新瓶颈”的问题，属互补性设计。
- **paper:arxiv:2303.02939（FoundationTTS）**：以分层 VQ-GAN codec 提取离散 token 并用 LLM 自回归生成的早期先例；HALL-E 可视为将该“层级化 codec + LLM 生成”思想从 codec 设计期前移到预训练模型后训练期的延续，并把目标从 ASR 定制转向分钟级零样本 TTS。
