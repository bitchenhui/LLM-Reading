# The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements

> Yuanhao Zeng, Shaocheng Lan, Ao Lu, Kuang Yan, Heng Lin, Xinang Xu, Yuan Luo, Yueting Wang, Yexin Li, Ruo Shan, Kan Ren. *arXiv:2611.23068v1 (2026-11-17)*

## 1. 背景与动机

本文研究的对象是"冻结权重的 LLM 智能体进化"（agent evolution）：不更新模型参数，而是通过进化循环维护持久化的外部 artifact——prompt、技能文档、记忆库乃至整个 agent harness。循环结构为 proposer 写候选 artifact → 在任务集上评估 → selector 接受得分更高者。GEPA、SkillOpt-Lite、Trace2Skill、ReasoningBank、Meta-Harness、AHE、HarnessLens 等方法均属此范式。

社区面临一个持续的困惑：同类方法在不同论文间排名翻转；在 Terminal-Bench 等编码基准上进化被反复报告“停滞”，而在另一些基准上每个新方法都声称超越前作。方法是否有效取决于 setting，且当前无法预测。作者将这一不稳定性的根源归结为一个此前未被检验的隐含前提——评估分数能够识别进化带来的改进——并证明该前提在分数被使用的两个层面上均不成立：

- 方法层面（排名方法）：典型方法间差距（几个百分点）小于同一方法两次独立运行的差异，单次运行的排名很大程度上由噪声决定。
- 候选层面（选择 artifact）：selector 从两个候选中挑出更好者的概率不优于随机，误差逐轮累积。

由此提出 **Resolution Hypothesis**：agent evolution 的瓶颈不是提出改进，而是识别改进。其机理性论证是：权重冻结时，artifact 只能通过改变推理时行为起效，而 LLM 轨迹本身每次执行都有随机性，因此“真实行为改变”与“评估噪声”难以区分。作者据此定义评估管线的**分辨率**为它能从噪声中可靠分辨的最小真实改进；真实改进低于分辨率时，候选选择退化为随机。提案决定市面上的改进有多大，分辨率决定多小的改进仍能被保留。

论证规模是该文的核心竞争力：7 种进化方法 × 6 个模型（GPT-5.4 nano、GPT-5.6 Luna/Terra、DeepSeek-V4-Flash、Kimi-K3、GLM-5.2）× 4 个 agent 基准，外加对 9 个额外基准的历史增益审计，共 1,030 次独立进化 run、超过 210 万条测试轨迹、超过 1,000 万次 LLM 调用、40 万 CPU core-hours——作者称为迄今最大的 agent evolution 可复现性研究。

## 2. 方法总览

**方差分解框架。** 设 artifact A 的单次评估得分为 Ŷ(A)，真实质量 Y(A)=E[Ŷ|A]，则 Ŷ=Y+ε（零均值评估噪声）。跨独立进化 run 产生的 artifact 质量方差记 τ²。由全方差定律：

Var(Ŷ) = σ²（artifact 内评估噪声）+ τ²（跨 run 的 artifact 真实质量方差）

关键洞见在于**分辨率取决于所回答的问题**：识别单一固定 artifact 相对参考的增益只受 σ² 限制；识别两方法的差异（每次 run 抽取新 artifact）受 τ²+σ² 限制。标准实践只报告“一次进化、一次评估”的分数，恰好把两个来源混在一起。

**估计器。** 对每个配置（方法×模型×基准）：独立进化 R=8 次（text-artifact 方法在 GPT-5.4 nano 上 R=16），每个产出的 artifact 在 held-out 测试集上评估 M=16 次（Terminal-Bench 与 harness 方法 M=8，因单条轨迹成本高）。σ̂² 取 within-artifact 样本方差的均值；τ̂² 用随机效应方差分析的矩估计扣除各 run 均值中残余的 σ̂²/M，二者均无偏；负的 τ̂²（117 个方法配置中出现 9 次）记为 0。识别真实差距 Δ（80% 功效、α=0.05）所需独立 run 数为 N ≥ 2(z_{1-α/2}+z_{1-β})²(τ²+σ²/M)/Δ²。

**四组实验映射到两层假设。** （1）方差测量：7 方法在 ALFWorld、SpreadsheetBench、OfficeQA、Terminal-Bench v2.1 上估计 σ 与 τ，共 150 个配置；（2）增益审计：对 12 个基准上历史报告的大增益（10–40 pp），做“单句规则复现”与“评估修复”两个对照实验；（3）候选池：两个各 n=100 的固定技能池，分别隔离测提案质量（P1）与选择可靠性（P2）；（4）轨迹重评估：SkillOpt-Lite 与 GEPA 各 8 个 run（×2 模型）的全部 119 个中间 artifact 版本，以每对 8 rollouts 独立重评，观察误差跨轮累积（P3）。

**统一协议的关键细节。** 每个方法内所有角色（解题、反思失败、重写 artifact）使用同一模型，杜绝“更强模型写 artifact”的混淆。更重要的是附录 Table 2 的注记：**所有方法的验证分数均为每任务单次 rollout**——进化循环内的 selection 是在 18 个任务的验证集、单 rollout、σ≈3–4 pp 的条件下做贪心接受，这是候选层面分辨率崩塌的直接结构性原因。

## 3. 关键设计

**增益审计。** 对 GEPA 与 SkillOpt-Lite 发布的 artifact 及作者自进化产物，先用 LLM agent 逐条标记可能解释增益的指令，再逐条人工核查，把最负责的一条写成单句规则追加到未进化 baseline 上（one-rule test，规则写定后不得修改）；同时修复各基准评估（恢复官方评估，或以“双 LLM 判官语义评分”替换表面形式匹配），对同一批 artifact 重打分。该设计证明的是“一句话足以获得该增益”，而非“artifact 中不含其他内容”。这一对照把“大增益”二分为：要么是评估捷径（修复后消失），要么是真实小改进（修复后存活且来源可指认）。

**Proposal Pool 与等质量零假设。** 从 10 个 Terminal-Bench v2.1 训练任务的 78 条执行轨迹离线生成 n=100 个独立技能（用基于 SkillOpt-Lite 的并行研究子代理，要求先以本地可执行探针验证失败机制、剥离训练实例字面量再写技能），在 10 个不相交测试任务上每对 16 rollouts（共 16,000 次）评估。核心统计陷阱：Quality@K（K 个候选中最佳者的期望成功率）在 K 个噪声评估上取 max 本身就会随 K 上升——即使 100 个技能真实质量完全相同。因此每条曲线都配一个 **matched equal-quality null**：在所有候选同质的模拟池上重跑同一套经验贝叶斯估计器，观察曲线与零曲线的垂直差才是真实差异。估计器为任务级 Beta 先验的分层模型，先验浓度 κ 上限取 κmax=100（主设定），并对 κmax∈{30,100,300,∞} 做敏感性分析，避免近同质任务上的点质量退化。

**Selection Pool 与独立参考协议。** n=100 技能来自 6 个 Terminal-Bench 任务与 3 个 DeepSWE 任务的轨迹，在 11 个跨五个难度级的 Terminal-Bench 任务上评估（每对 8 rollouts，每任务前 10 高分 artifact 扩至 15）。selector 只观察到每对的第一条 rollout（SkillOpt-Lite/GEPA 原生算子两条），真值用 selector 未见的 held-out rollouts 拟合后验质量，保证对 selector 的评判独立于其可得信息。指标以后验概率定义：成对准确率（选中者真实质量更高）、误接受率（被接受为 baseline 替换者中实际更差的比例）。LLM 判官用 DeepSeek-V4-Flash 在 1,111 个 artifact–任务对上做 pointwise（1,111 次调用）、成对双向（1,100 对 ×2 顺序）与改编自 ACE Reflector 的无真值模板三种条件。

**轨迹重评估。** 8+8 个进化 run 的全部中间 artifact，在与进化相同的 18 任务验证集上以每对 8 rollouts 重评（进化时只有 1）。τ̂ₜ² 用 8 个 run 的任务均值样本方差扣除评估噪声均值估计；此处保留负的校正值而非截断，因为跨轮比较时截断会使早期小方差估计偏上。

**Terminal-Bench 划分。** 89 任务按难度分层切为 18 训练/18 验证/53 held-out 测试；评估在官方任务镜像的独立沙箱中离线运行，每个 artifact 的测试开销为 53×8=424 个容器化 episode。

## 4. 实验结果

**方法层面：单次报告无法排名方法。** σ 在 SpreadsheetBench/OfficeQA/ALFWorld 上为 1.0–3.7 pp，Terminal-Bench 上达 4.5 pp；τ 为 0–12.3 pp。“一次进化+一次评估”的单 run 得分标准差按各基准配置中位数为 1.7–4.1 pp。同模型同基准的 341 个配置对中，217 对（>60%）的全 run 均值差距低于单次比较的一个标准差；逐方法看，每个方法 53%–79% 的比较低于该阈值。

对照文献现状：9 篇 agent 进化论文主表的 171 个含优化竞争者的列中，提出方法领先最强竞争者的中位 margin 为 3.4 pp（IQR 1.2–6.6），178 列无一报告误差条或方差，仅 6 列（Trace2Skill，3 seeds）平均了多次进化 run。识别中位 margin 所需独立 run 数：

| 真实差距 Δ (pp) | SpreadsheetBench | OfficeQA | ALFWorld | Terminal-Bench |
|---|---|---|---|---|
| 1.2（文献下四分位） | 33 | 75 | 152 | 181 |
| 3.4（文献中位） | 5 | 10 | 19 | 23 |
| 6.6（文献上四分位） | 2 | 3 | 6 | 6 |

模拟单 run 排名（每方法抽一次进化+一次评估，与全 run 均值排名比对）：四个 text-artifact 方法中 top-1 命中率仅 67%/51%/73%/33%（四基准，随机 25%），完整排序命中率 33%/29%/24%/8%（随机约 4%）——Terminal-Bench 上单 run 选对最佳方法的概率（33%）仅比随机猜高 8 个点。

**增益审计：大增益来自评估捷径。** 27 个报告增益 >3 pp 的模型–基准对上，单句规则恢复中位 90% 的增益；修复评估后中位增益从 17.6 pp 跌至 0.8 pp。捷径的形态高度一致：SpreadsheetBench 发布版 grader 不重算公式单元格（所有公式记空，修复=LibreOffice 重算）；AIME 2025 解析器只接受裸整数；LiveMathematicianBench 的"stronger result"选项在出现的 85/177 题中全部为正确答案（106 道测试题中出现于 46 题，恒选即全对）；DocVQA 要求 ANLS≥0.999 的近精确匹配；OfficeQA 发布版删掉了官方“以裸值作答”的指令；SearchQA 精确匹配。SearchQA 更极端：语义评分下去掉全部检索片段，分数仅从 84.2→81.9（nano）、89.4→90.2（DeepSeek）、89.8→90.7（Luna），基准实际在测闭卷知识。修复后重新进化，text-artifact 方法在 OfficeQA/SpreadsheetBench 上增益不超过 1.9 pp（唯一例外 SkillOpt-Lite×DeepSeek 在 SpreadsheetBench +5.8 pp，机制是避开 LibreOffice 不支持的函数）。反例是 HotpotQA：GEPA 在语义评分下保持 5.5–7.6 pp，且可归因于支持文章召回率提升约 10 pp。ALFWorld 上 harness 方法对 DeepSeek/Luna 的 +16~32 pp 修复后增益同样源于单一可识别的大改变（初始 harness 只保留最近两步历史，仅改这一项即 +29 pp）——完全符合假设：只有超过分辨率的单一大改进才可被噪声评估下的进化捕获。

**候选层面 P1：有用的 artifact 确实存在。** 2 小时执行预算下 Quality@K 从 K=1 的 49.2% 升至 K=100 的 61.8%；原生超时（900–1800 s）下从 39.7% 升至 51.6%。相对 matched null 的净超出在 K≥5 起分离，K=100 时 +3.3~3.4 pp，且在全部五个超时截断（原始/2×/3×/4×/2h）下稳定为 +3.22~3.41 pp。超时本身是重要混杂：K=1 成功率从原始超时的 39.69% 升至 2h 的 49.23%，主要由多步编译/渲染任务（path-tracing-reverse 4.8%→41.4%，rstan-to-pystan 23.2%→62.4%）解释。单个可跨全部 10 个测试任务共享的技能也拉开超过 15 pp 的谱系：最强共享技能达 57.5%（池均值 49.2%，+8.3 pp），最弱 41.9%。提案不是瓶颈。

**P2：选择机制无法识别它们。**

| 选择机制 | 成对准确率 (%) | 误接受率 (%) |
|---|---|---|
| 随机 | 50.0 ± 0.0 | 30.5 ± 14.0 |
| 执行分数（1 rollout） | 49.7 ± 1.9 | 62.1 ± 42.9 |
| SkillOpt-Lite 原生算子（2 rollouts） | 48.6 ± 2.6 | 59.4 ± 46.2 |
| GEPA 原生算子（2 rollouts） | 48.6 ± 2.6 | 31.6 ± 14.5 |
| LLM 判官 | 45.4 ± 4.5 | 39.9 ± 17.5 |
| LLM 判官（成对双向） | 49.0 ± 2.2 | 57.6 ± 23.3 |
| LLM 判官（ACE 模板） | 46.9 ± 3.5 | 39.0 ± 15.6 |

回归占池 30.5%，却占执行选择接受候选的 62.1%——选择不但不过滤回归，区间宽到不能排除比随机接受更差。单次执行分与后验质量的秩相关仅 0.054。随候选预算 K 从 1 增至 100，oracle 持续爬升，而所有实用 selector 的选中增益平坦在随机选择基线附近；看完全部 100 个候选，没有任何 selector 达到 oracle 在 K<5 内就到的质量。判官读全轨迹也无济于事——判官自身的阅读噪声与执行噪声独立、叠加而非抵消。

**P3：误差跨轮复合。** 进化 run 自己记录的 in-loop 增益增长到 6.9–9.0 pp，独立重评估后增益仅 +0.4~−3.2 pp。机制是贪心接受规则持续接受噪声分布上尾的幸运抽样（论文引 Cawley & Talbot 的模型选择过拟合与 PACE 的 false-commit 分析）。从同一初始 artifact 出发（τ²₀=0），噪声校正后的 run 间方差 τ̂ₜ² 到末轮增至 4.2–24.5 平方 pp——独立 run 之间的离散程度达到文献级方法差距的量级，正是方法层面排名不稳定的微观来源。

## 5. 消融要点

**估计器敏感性。** κmax=30 会给同质零池强加分散，使 2h 预算下 K=100 净超出压缩为 +2.20 pp 且置信带重叠；主设定 κmax=100 为 +3.41 pp（K≥4 分离）；放松到 300/∞ 平滑扩大到 +4.75/+6.42 pp。κmax≥100 的所有取值下“提案有余量”的结论不变；κmax=∞ 在近同质任务上有先验坍缩为点质量的退化，故有限正则是必要的。

**验证 rollout 数量直接决定进化上限。** 把 SkillOpt-Lite 的验证从 1 rollout 平均到 16 rollouts（16 个独立 run，最终 artifact 32 rollouts 测试）：平均最终测试分 61.4%→64.4%，最佳 artifact 64.8%→72.7%。机理清晰：单 rollout 验证下，普通候选偶尔靠运气拿到高验证分成为 incumbent，后续候选打不过这个虚高阈值，4 轮内停滞；平均化压掉假峰后真实改进才能沉淀。代价是 16× 验证开销且贪心接受在强 incumbent 后更保守——这正推动第 6 节的廉价行为诊断方向。

**M 只缩 σ²。** 每个方法在三个较便宜基准上 σ² 是 τ²+σ² 的主导项；充分重评估下，识别中位文献 margin 所需 run 数从 5/10/19/23 降到约 1/5/9/3。降低评估噪声即直接降低方法比较成本。

**one-rule 的例外谱系。** 增益分散在多个策略时单句失效：HoVer 多跳检索增益一句话只恢复 43%/41%（nano/Luna；DeepSeek 因单条检索规则即可恢复 91%）。更微妙的是“模型不执行规则”：LiveMathematicianBench 上带规则后模型在正确时选 stronger-result 选项的比例仅 4%/54%/27%，而进化出的技能达 67%/86%/92%——技能给出理由、设为默认、列举出现措辞、在最终答案前重复指令，即**进化同时优化了捷径的内容与表述方式**。AIME×Luna 上规则（69.3）反超 artifact（51.0）；SearchQA 语义评分下“只写最短片段”的规则反使 nano 降 2.0 pp（语义评分宽恕带限定的答案）。IFBench 与 LiveBench-Math 增益（2.7–3.8 / 0.9–3.9 pp）本身与单 run 噪声同量级，是“非捷径小增益”的另一极样本。

**修复下捷径为何不再被学到。** SpreadsheetBench：发布 grader 下“写计算值不写公式”值约 30 pp，SkillOpt-Lite×nano 的 8 个 run 全部发现；修复后同一行为只值约 6 pp（39 任务验证集上即 2–3 个任务，与 run 间噪声同量级），12 个修复下重进化的 artifact 仅 2 个保留该行为——尽管一半在文本里写了这条规则。可识别性直接决定行为是否被进化保留，这是分辨率假设最干净的一次因果验证。

**过程指标 vs 终局判决。** 在复用方差实验轨迹的对照中（DeepSeek-V4-Flash，基线+全部 7 方法），“未屏蔽失败诊断的检查命令占比”这一过程指标的评估噪声比终局 pass/fail 低 13–57 倍（基线 57×、SkillOpt-Lite 56×、HarnessLens 13×）。且过程指标能看到终局看不到的行为位移：Trace2Skill 使 post-edit 验证率 +8.73 pp（z=2.17）、AHE 使其 −17.98 pp（z=−4.19），二者在同期终局成功率中均不可见。作者明确其定位是廉价诊断而非 selector（触发更多检查不必然多解题），过程指标自身也有分辨率问题。

**Headroom 与收益的错配。** Terminal-Bench 留有最大余量（DeepSeek 28 pp、Luna 46 pp），但最好方法只涨 1.0/3.6 pp，低于单 run 标准差——改进空间大而可识别的改进小，是分辨率瓶颈最直观的画像。

## 6. 贡献与启示

**核心贡献。** 其一，把 agent evolution 的失败归因从 proposer 侧（“LLM 写不出好 artifact”）系统性移到 selector 侧，并用受控池实验把两者干净解耦——P1/P2/P3 三条预测全部得到支持。其二，给出可直接复用的 σ²/τ² 分解与功效公式，把“需要多少次 run 才能识别 Δ”变成可计算的工程问题。其三，增益审计揭示文献中大增益的主体是评估捷径，且修复后可复现地消失——这同时是对基准污染和方法评估双重问题的警示。

**方法论处方。**（1）报告点分数必须附带 σ̂ 与 τ̂，让读者判断声称的 margin 是否超过分辨率；（2）组件化评估：proposer 用 Quality@K 曲线（配 matched null）、selector 用固定池上的 selected-artifact 质量曲线，把一个低于分辨率的端到端比较拆成两个超过分辨率的问题；（3）在候选层引入低方差过程指标做行为诊断，在方法层报告方差。

**工程含义。** 对构建自进化 agent 系统的团队：in-loop 验证分数的上升可能是噪声开采而非真实改进，上线前必须独立重评；验证 rollout 数是进化系统的第一超参数（本文 1→16 rollouts 带来最佳 artifact 64.8%→72.7%）；贪心接受阈值应做统计检验而非点比较。成本意识也来自本文测量：TB 上一次进化 run 约 4,300 万 tokens、一个 artifact 测试 424 个容器化 episode，harness 进化单 run 中位 2,600 万 tokens。

**与音视频技术的上下游关联。** 本文虽属 LLM agent 方法学，但其方差分解与功效框架与音视频质量评估方法学同构：主观 MOS 实验中“同一编码器重复评测的评分方差”即 σ²、“不同码控种子/搜索随机性下的质量方差”即 τ²，BD-rate 比较中的配对检验与置信区间对应本文的 runs-per-method 公式；神经编码器引入的编码随机性正在放大 τ²，使“小于噪声的压缩效率改进不可识别”成为同一形态的问题。下游看，若用 agent 进化优化音视频工程任务（转码流水线、FFmpeg 命令构造、编码参数搜索），目标函数为确定性可测量（编码时间、PSNR/VMAF、文件大小）时落在本文所指“程序进化”一侧——廉价并行重评可把 σ 压到近零，进化更可能累积；若落在 LLM-as-judge 自动画质/音质评分上，则同样暴露于本文识别的分辨率瓶颈，应先测判官噪声再谈增益。

**局限（作者自陈）。** 只覆盖冻结权重的 artifact 进化，RL 权重更新有不同动力学；候选层面证据仅限 Terminal-Bench v2.1（两个百规模池、两种方法两个模型的重评估）；网格未穷尽；程序进化（GPU kernel、ARC-AGI-2、Atari 策略搜索）结构上降低评估噪声，是否受同样约束是开放问题。

## 7. 与其他论文的联系

- **TRUST（arxiv:2611.10787）**：本文 P3 证明贪心接受规则逐轮收纳噪声上尾样本、τ̂ₜ² 增至 4.2–24.5 pp²，并把 PACE 的 anytime-valid 接受检验引为对策；TRUST 用在线多重假设检验控制递归自改进的错误进化率并提供统计保证，正是把本文“接受决策应升级为统计检验”这一处方推向系统化的直接后续。
- **FGSE（arxiv:2611.14326）**：本文 Table 1 的误接受率指标（执行选择 62.1%）量化了噪声验收放行回归、污染记忆/技能库的问题；FGSE 将经验教训作为可证伪假设经三类探针验证后才写入记忆，可视为 selector 侧提高分辨率的具体机制，直接针对本文识别的 false-accept 失效模式。
- **CompoundingKernel（arxiv:2611.19230）**：本文 Limitations 明确指出 GPU kernel 搜索这类程序进化通过确定性代码的廉价并行重评结构性压低评估噪声；CompoundingKernel 在 SOL-ExecBench 全榜登顶可读作分辨率假设的正面证据——评估确定性高，小改进即超过分辨率而可累积。
- **RSI-PDEbench（arxiv:2611.14949）**：PDE 求解具有可执行数值验证、确定性评分，与上条同属“分辨率友好”的确定性验证域；其递归自改进框架的提升空间应按本文框架重新审视增益是否超过 σ。
- **InfraRSI（arxiv:2611.11558）**：训练基础设施优化以可精确测量的运行时间/加速比为目标（最高 2.75×），评估噪声天然低，是本文“目标确定性决定进化可累积性”论断在训练系统域的对应案例。
- **TrainExplorer（arxiv:2611.20430）**：属权重更新方向，在本文明确排除的范围（RL 梯度动力学 vs 外部 artifact 进化）之内；但其 PostTrainBench 上的方法排名（39.02 vs 36.23）应按本文 runs-per-method 功效分析检验该 margin 是否超过单 run 分辨率。
- **Do LLM Agents Still Need to Be Told How to Self-Improve?（arxiv:2611.23219）**：本文 P1 证明 proposal 不是瓶颈；该文研究的自主构建自我改进算法若沿用噪声贪心验收，仍受 P2/P3 约束——其结论需在本文分辨率框架下解读。
- **SkillDuet（arxiv:2611.12109）**：其外部技能库演化组件（text artifact）直接暴露于本文识别的选择分辨率瓶颈；其响应反馈机制可视为为技能选择引入额外低噪声信号的一种尝试。
