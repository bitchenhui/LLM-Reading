## 1. 背景与动机

流媒体是互联网第一大流量应用，而高质量分发的根本瓶颈在带宽：论文引用口径为 4K 视频每用户需 40 Mbps 以上。超分辨率（SR）被视为“以端侧算力换传输带宽”的核心路径，但把现有 VSR 方法搬到真实在线流媒体上存在两个结构性障碍，这也是本文的问题设定起点：

**延迟与因果性约束。** 视频会议、云游戏等在线交互场景对增强模块的单帧耗时极其敏感；而 SOTA VSR（BasicVSR++、TTVSR 等）依赖双向传播，需要缓存未来帧，且光流对齐、可变形卷积、transformer 等模块计算过重。在线设定下模型只能使用历史帧——这直接排除了绝大多数现有 VSR 架构。

**退化的时空双重非平稳性。** 时间维度上，WebRTC 等流媒体协议的 ABR 机制随实时网络状况逐帧调整码率与 QP；空间维度上，编码器对帧内不同宏块施加不同压缩配置；论文还观测到 WebRTC 的默认策略在帧均 QP 过大时会直接降低分辨率，且低带宽下丢帧频发，GT 对齐必须按编码时间戳进行。这意味着退化既不是固定的（不能按单一退化训练），也不是帧级均匀的（需要块级甚至像素级自适应）。

由此引出双重缺口：**数据侧**，现有 VSR 数据集要么是原始帧、要么是固定预设压缩（如固定 QP），统计特性不反映上述动态退化；**方法侧**，SR-LUT、SPLUT 等查表方案从单一简单网络蒸馏单张 LUT、逐像素小 patch 查询感受野极小，无法覆盖动态退化。本文相应给出三项贡献：online streaming VSR 的问题设定、LDV-WebRTC 基准数据集、以及 Conv-LUT 混合架构 ConvLUT。

## 2. 方法总览

ConvLUT 的整体流程分“离线专家蒸馏”与“在线双分支推理”两段。

**离线阶段：** 在压缩配置空间（以量化参数 QP 为主变量，范围 [0, 50]）中均匀采样 N 个代表性静态退化，生成 N 个训练子集，分别训练 N 个 SISR 教师网络（结构不限，实验用 SRResNet / CARN / RCAN），再把每个教师蒸馏为一张 4D 专家 LUT。这样每张 LUT 专精一类量化退化。

**在线阶段（双分支并行，输出相加）：**
- **空间分支（MoE-LUT）**：轻量权重预测器（4 层卷积 + InstanceNorm + LeakyReLU）以整帧 LR 为输入，输出逐像素的 n 维 LUT 组合权重；在查询像素值邻域的 4D 格点（16 个相邻采样点，四面体插值实际只用 5 顶点）上对 n 张专家 LUT 加权融合后插值。关键点是融合只在查询点邻域格点上计算，不构造显式融合全表。
- **时域分支（卷积）**：仅 4 层普通卷积 + LeakyReLU，融合前一帧与当前帧，并把码流中解码端可直接提取的运动矢量作为附加特征图加入——零额外计算成本的粗运动先验。

**核心机理**：本文把“退化自适应”从一个训练问题（训练一个鲁棒大模型）转化为推理期的逐像素低维权重预测问题——权重只有 n 维、预测器极轻，而表达能力来自 N 个强教师蒸馏出的 LUT 基；同时查表 + 四面体插值把每像素计算压到极少量的查表与乘法（见表 II 口径：9 次查询 + 5 次乘法 + 0 分支）。权重预测器以整帧为输入、感受野大，恰好弥补了 LUT 逐 2×2 patch 查询感受野小的固有缺陷——这是它区别于 SR-LUT/SPLUT 的本质设计。

## 3. 关键设计

### 3.1 专家 LUT 的蒸馏与压缩

教师训练：QP 从 [0, 50] 均匀取 N=6 个值（实验为 0/10/20/30/40/50），对应 6 个退化视频子集，各训练一个 SISR 网络。蒸馏：枚举 2×2 LR patch 的全部 256⁴ 像素值组合（[0,0,0,0] 到 [255,255,255,255]），教师网络对每个组合输出 r×r 的 HR patch 存入表中，得到尺寸 [256,256,256,256,r,r] 的 LUT；再沿 SR-LUT 的做法按间隔 16 对每维均匀采样，压缩为 [17,17,17,17,r,r]。存储口径：表 IX 记 2⁴ 采样下 LUT 部分 7.644 MB，表 IV/V 含卷积分支与预测器共 8.65 MB；存储随专家数线性增长（表 VII：1/3/6/12 张对应 2.32/4.84/8.65/16.27 MB）。这一设计的价值在于**把教师网络容量与推理成本解耦**——教师可以是任意 SOTA 结构，推理端仍是查表。

### 3.2 逐像素自适应 LUT 融合

权重预测器 f_w 输出 W ∈ R^{h×w×n}。对像素 X_{i,j,k}，查询所用等效 LUT 为 Σ_k W_{i,j,k}·LUT_k，但只在该像素值周围的 4D 格点上求值。由于门控权重来自大感受野的整帧内容，模型能同时对帧内不同宏块的退化差异与帧间 ABR 引起的退化变化做时空双自适应——这是 mixture-of-experts 思想在 LUT 上的实例化：专家 = 专精特定静态退化的表，门控 = 像素级权重场。

### 3.3 无控制流的四面体插值（并行加速）

这是让方案真正能在 GPU 上跑起来的工程关键。8-bit 输入拆为高 4 bit（MSB，定位格点锚）与低 4 bit（LSB，插值距离）。标准四面体插值只需 4-simplex 的 5 个顶点、5 次乘法，但需要在 24 种 LSB 大小关系分支（即 SR-LUT 文中所列 24 条件表）中选择顶点；if-else 控制流在 CUDA 类并行加速器上代价极高——论文实测未加速时 SR-LUT 在 GPU 上 381.89 ms、ConvLUT 516.21 ms（表 VIII），完全不可用。

本文观察：24 种条件分支等价于对 4 个 LSB 排序，而排序结果与所需顶点索引全部可枚举，因此预存一张 [16,16,16,16,7] 的排序表（存排序后 LSB 及 O2/O3/O4 的二进制索引；O1、O5 固定为 0000 与 1111）。推理三步：① 拆 MSB/LSB；② 查排序表；③ 按统一公式计算权重 w1=W−L'x, w2=L'x−L'y, w3=L'y−L'z, w4=L'z−L'u, w5=L'u（W=16），输出 Output = (1/W)·Σ w_i·O_i。操作量对比（表 II）：三线性 16 查询/16 乘/无分支；四面体 5 查询/5 乘/24 分支、不可并行；本文 9 查询/5 乘/0 分支、可并行。N 张 LUT 的加权融合同样并入并行流程。加速后 ConvLUT 10.23 ms，反超 SR-LUT 的 11.60 ms——论文解释为 SR-LUT 受感受野限制每输出像素需重复查表 4 次，而 ConvLUT 只查询一张融合表。

### 3.4 时域分支与码流先验

在线设定禁止未来帧、光流/可变形卷积/transformer 又过重，故时域分支取最简配置：4 层卷积融合前帧与当前帧；运动矢量直接取自流媒体系统解码侧先验（类似光流的 patch 级粗对应关系，但无任何额外计算），作为附加特征图加入。这是“码流先验是免费午餐”这一工程原则的直接体现。

### 3.5 训练配置

专家 LUT 冻结，其余部分联合训练：48×48 随机裁剪、batch 16、最终输出上施加 Charbonnier 损失、Adam（β1=0.9, β2=0.999）、初始学习率 1e-4，Tesla V100 训练；空间/时域分支通道数均为 64，预测器输出通道 6（等于专家数）。

## 4. 实验结果

**基准数据集 LDV-WebRTC**：基于 WebRTC 搭建真实流媒体原型（服务器—路由器—笔记本客户端），路由器用 Linux tc 限定带宽为 100 kbps / 500 kbps / 1 Mbps 三档；取 LDV 2.0 全部 335 个 960×512 视频做 HR，双三次 4× 下采样得 240×128 LR，FFmpeg-H.264 编码后由服务端推送；WebRTC ABR 在 QP∈[0,50] 内按带宽/编解码延迟自适应调质量；客户端解码帧按编码时间戳与 HR 对齐，同时采集解码端运动矢量。统计上（表 I）：100 Kbps 档实际码率约 82–85 Kbps、平均 QP≈30、PSNR≈23.3–24.4 dB；500 Kbps 档约 322–340 Kbps、QP≈19–21；1 Mbps 档实际码率仅约 476–497 Kbps、QP≈16–18、PSNR≈24.3–25.2 dB——即编码器并未打满配置带宽，且 QP/PSNR 逐帧剧烈波动。

**评测设置**：仅用 1 Mbps 档的 LR-HR 对训练，在三个带宽测试集上评估（跨带宽泛化设定）；×4；速度为 RTX 2080Ti 上 320×180 → 1280×720 的单帧耗时。按 FPS 分档：<30 为高延迟（不可用于在线流媒体）、30–60 中延迟（满足 30 FPS 视频）、>60 低延迟（满足 60FPS 游戏）。VESPCN 因依赖未来帧被改造为只用前帧；BasicVSR++/TTVSR 作为不可部署的性能上界。

要点结论：
1. **低延迟组内全面占优**：三个 ConvLUT 变体在所有带宽上 PSNR/SSIM 均超过 PAN 与 SR-LUT/SPLUT，同时 10.23 ms / 97.75 FPS 为全场最快；1 Mbps 上较 SR-LUT 高 0.40–0.45 dB、SSIM 高约 0.036。
2. **以小代价逼近中延迟组**：ConvLUT-SRResNet（23.78/24.54/24.87）在三个带宽上持平或超过 CARN（23.77/24.50/24.74）与 RRN（23.48/24.48/24.84），耗时约为后两者的 40%。
3. **对上界的折价**：1 Mbps 上 BasicVSR++ 25.11 dB 对 ConvLUT-SRResNet 24.87 dB，差 0.24 dB，但速度差约 41 倍（418.5 ms vs 10.23 ms）——即用 0.2–0.3 dB 换取在线可部署性。
4. **教师结构的影响随退化加重而显现**：100 Kbps 重退化下 RCAN 教师变体最优（23.82），说明强教师在重压缩退化上蒸馏收益更大；轻退化下三变体接近。
5. 视觉对比（100 Kbps/1 Mbps 测试帧）：SR-LUT/SPLUT 呈现块效应类伪影，ConvLUT 伪影更少、锐度与 CARN/RRN 相当而速度显著更快。

**静态退化实验（NTIRE 2022 Track3 协议，QP=37，LDV 2.0）**：将三种结构教师（RCAN+SRResNet+CARN）在**同一静态退化**上训练所得的 3 张 LUT 作为融合基，得 ConvLUT-RCAN+SRResNet+CARN：23.32 dB / 10.23 ms（2080Ti），超过三个教师本体（RCAN 22.96 @ 205.4 ms、SRResNet 22.93 @ 75.8 ms、CARN 22.89 @ 25.3 ms）与 LUT 基线（SP-LUT 22.87、SR-LUT 22.61），仍低于 NTIRE 冠军 GY-Lab（BasicVSR++ 系，24.23 @ 11.5 s，V100）。两点含义：LUT 融合维度可以沿“教师结构”展开而不仅沿“训练退化”展开；结构互补的融合甚至能超过任一教师单模型且快一个量级。

## 6. 贡献与启示

**基准层面的贡献**：LDV-WebRTC 是首个由真实流媒体系统产生的 VSR 数据集，对音视频上游的价值在于明确刻画了“解码后增强”必须面对的退化统计——帧内逐块 QP 差异、帧间随 ABR 的 QP/码率波动、WebRTC 高 QP 触发的降分辨率、低带宽丢帧及按时间戳对齐的必要性。这些统计（100 Kbps 档平均 QP≈30、PSNR≈23–24 dB；1 Mbps 档实际码率仅约 497 Kbps）本身即可作为流媒体 QoE 研究的实证素材。

**方法层面的范式**：其一，MoE-LUT 把逐像素退化自适应压缩为“n 维权重预测 + 邻域格点加权”，在保持查表级速度的同时获得大感受野门控；其二，LUT 蒸馏将教师容量与推理成本解耦，任何 SOTA SISR 都可作教师；其三，排序表消分支是通用 GPU 工程技巧，适用于一切分支敏感的查表插值场景（颜色 3D LUT 变换同理）。

**工程部署含义**：模块位于解码后、渲染前，对 ABR 与编码器完全透明；8.65 MB 存储、720p 单帧 10.23 ms / 97.75 FPS 满足 60 FPS 交互档；专家数与采样间隔提供两级显式的存储/速度/质量调节旋钮。

**可扩展方向（依论文证据推论）**：运动矢量作为零成本码流先验已被验证有效，顺理成章的下一步是把逐块 QP map 也作为输入先验喂给权重预测器或时域分支——本文仅用 QP 离线构造专家划分，未将其作为在线输入特征，这是与 compressed video SR 中 bitstream-prior 路线衔接的明确空间。

**局限**：指标仅 PSNR/SSIM，无感知质量与主观评价；固定 ×4；训练仅用 1 Mbps 档（跨带宽评估本质是泛化测试，100 Kbps 上 PSNR 掉约 1 dB 系退化加重所致）；LUT 容量受 2×2 patch 索引上限约束，高频细节依赖时域分支与教师先验补偿；与双向 VSR 上界仍有 0.2–0.3 dB 差距。

- **paper:arxiv:2306.01194（无应用层头的 WebRTC QoE 指标估计）**：该工作仅凭 IP/UDP 头与流量统计逐秒估计帧率/分辨率等 QoE 指标；LDV-WebRTC 提供的帧级 QP/PSNR/码率波动统计正是这类估计器需要追踪的对象。两者在“WebRTC 质量动态的可观测性”上互补：一个面向网络侧推断，一个给出端侧逐帧真值口径。
- **paper:arxiv:2209.10507（Gemino）**：同属“以神经计算换带宽”的实时视频路线。Gemino 在发送侧做神经压缩并配高频条件超分，极低码率下实现 720p 级实时会议；ConvLUT 位于接收侧、编解码器无关，并显式处理 ABR 动态退化与逐块 QP 差异。两篇对照呈现“编码侧改造 vs 解码侧增强”的工程取舍。
- **paper:arxiv:2607.28144（ReGenVC）/ paper:arxiv:2607.22772（GenVC）**：超低码率生成式视频编码是同一“算力换码率”轴线的激进端——以扩散模型/关键点码流换取感知质量优先的重建；ConvLUT 则保持在失真优化、非生成、约 100 FPS 与 8.65 MB 的轻量端。生成式解码器如何应对本文刻画的时空动态退化（尤其逐块 QP 差异与 ABR 切换）仍是开放问题，LDV-WebRTC 基准与 ConvLUT 可作为该方向的对照基线。
