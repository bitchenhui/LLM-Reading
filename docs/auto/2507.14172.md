## 1. 背景与动机

论文处理的是 ARC-AGI 上的归纳式程序合成（inductive program synthesis）：每任务给 2–10 个彩色网格训练例（网格尺寸 h,w∈[1..30]，颜色 0–9），需合成 Python 变换函数 f 使 f(x_train)=y_train 且能正确外推到隐藏的测试输出；公开集共 400 训练任务 + 400 测试任务。这本质上是 programming-by-example：解空间巨大、且每任务隐含一条全新变换规则（计数、算术、模式补全、空间关系等），无法靠模式记忆通过。

动机来自三层经验事实（均为论文实测，ARC-test 口径，单次程序合成）：闭源前沿模型 GPT-4.1 仅 8.00%、Claude-4-Sonnet 20.75%；开源 Qwen-2.5-Coder 7/14/32B 仅 1.00/1.00/1.50%；推理模型 o3-mini 33.00%、Gemini-2.5-Pro 38.25%。搜索能显著补救——6k 预算的 Sample&Refine 搜索把 7B 提到 14.25%——但搜索收益随预算呈对数级递减，且天花板由底座的采样/精修策略分布锁死：论文测得基线 7B 在约 5.2k 次搜索尝试后饱和，无学习的搜索曲线在模型规模超过 32B 后趋平。

既有归纳式方法各有重依赖：CodeIt 靠手工 DSL + 专家迭代（ARC-test 15.00%，2500 次尝试/任务）；BARC 依赖人写解答与闭源模型（Heavy 30.50% @10k、Potpourri 38.00% @20k）；Icecuber 39.00% 靠 DSL 且论文判定不公平；Greenblatt 42.00% @8160 次尝试但用闭源大模型。SOAR 的核心主张：让搜索算子本身可学习——仅从自身搜索轨迹（含失败）中学习采样与精修两种策略，形成“更好模型→更有效搜索→更优训练数据”的正循环，摆脱 DSL、人写解答与人工数据。其中事后重标注是解锁失败数据的关键机制。

领域定位说明（面向本引擎读者）：本文属 LLM 程序合成/递归自我改进方向，非音视频核心论文，按其自身领域（ICML/程序合成）标准评估；其“执行反馈驱动的算子自改进闭环”对音视频处理链路的代码生成与自动调参具有明确的上游迁移价值，详见第 6 节。

## 2. 方法总览

SOAR（Self-improving Operators for Automated program Refinements）由交替的两个阶段构成。

**搜索阶段。** 采样步：f ∼ P_θ(·|x_test, x_train, y_train)，独立采 3k 个 Python 程序，逐个经解释器执行得到各训练例的合成输出与测试输出。精修步：对不满足全部训练例的程序，以显式标注每例对错的执行反馈为条件做精修 f⁺ ∼ P_θ(·|f, x_test, x_train, y_train, y_synth)，测试输出单独标注“正确性未知”；精修被建模为生成式多臂老虎机（每次精修产生一个可继续精修的新臂），用 REX（基于训练例准确率的 Thompson 采样 + 探索加成，超参 C=20，Tang et al. 2024）在 3k 精修预算内分配。最终 6k 个程序按测试输出网格分组做加权多数投票：weight = count + c×train_accuracy，c=1000 以重罚低训练精度的输出模式，按赛规返回 top-2 输出。

**学习阶段。** 两条监督源：(1) 采样能力——事后重标注把任意采样程序 f₀ 变成合法数据：f₀ 在全部输入上执行产生 y_synth，则 {(x_train, y_synth, x_test), f₀} 按构造保证正确；6k 程序/任务 × 400 任务 = 240 万候选对，子采样至每任务 ≤50 条后以 L = E[−log P_θ(f | x_train, y_train, x_test)] 微调。(2) 精修能力——收集成功的 (f→f⁺) 精修对，按父程序训练准确率分箱（0%、1–34%、34–98%、100%）均衡采样至 ≤50 条/任务，以 L = E[−log P_θ(f⁺ | f, x_test, x_train, y_train, y_synth)] 微调。关键工程选择：每轮迭代都从基座 Instruct 模型重新微调（而非链式叠加），避免误差累积漂移。

**闭环与测试时训练。** 在训练任务上做 4 轮“搜索→学习”迭代后，聚合全部模型、全部迭代的数据（CodeRankEmbed 余弦相似度 0.9 去重，同训练精度下偏好更短程序），重训得到 SOAR(all train) 系列模型；随后在测试任务上再做 2 轮测试时训练（TTT）：无真值条件下仅以训练例准确率 + 多数投票伪标签做数据选择，只微调采样能力（精修版 TTT 明确留作未来工作）。

**实现配置。** 模型：Qwen-2.5-Coder-7/14/32B、Qwen-2.5-72B、Mistral-large-2407（123B）。微调：单卡 H100，Unsloth，RS-LoRA（≤14B）/RS-QLoRA（更大模型），rank 256、α=32（Mistral 因显存用 rank 64），3 epochs，lr 5e-5，warmup 0.1，batch 1 × 梯度累积 64，bf16，仅对 response 计损失，训练例网格随机换序。推理：SGLang，temperature=1，Min-p=0.05，每任务 50 路并行补全，1 个 few-shot 示例；当 ≥100 个程序达到训练例全对时提前终止生成（采样与精修阶段分别独立触发），故实际预算常低于名义 6k。

## 3. 关键设计

**3.1 事后重标注与失败数据策展。** 搜索在多数任务上采不到任何正确解，correct-only 数据会严重饥渴；重标注使全部 6k 程序/任务可用。数据策展上，greedy-diverse（25 条按训练+测试准确率最高的贪心样本 + 25 条最差样本引入多样性）在消融中最优（见第 5 节），说明“学成功解”与“保分布多样性”需显式平衡——这与作者最终把多样性识别为持续改进瓶颈的分析（4.5 节）互为呼应。

**3.2 精修的 bandit 化与 REX 工程化。** 精修树中每条路径价值由训练例准确率代理，REX 在“沿已知高准确率路径深挖”与“探索新变体”间平衡。三项工程修改：每个 prompt 同时采 4 个补全以摊薄 prefill 开销；并行跑 4 个独立 REX 实例（作者自比 island 遗传算法，兼顾吞吐与多样性）；剔除在输入网格上直接报错的程序，因其反馈无学习价值。精修 prompt 将每个训练例的计算输出逐例展示并标注对错，测试输出单独标注——反馈粒度是完整网格而非仅报错信息，这是精修信号密度的关键。

**3.3 联合微调与不对称迁移。** 采样与精修两个条件分布联合微调优于各自专精的双模型组合；且存在明确不对称性（附录 E）：仅微调采样会损害精修表现（负迁移），仅微调精修反而显著提升采样表现。作者解释为两任务共享“程序结构与变换模式”的表征。这条结论直接决定了 SOAR 用单模型承担双算子的架构。

**3.4 加权投票与混合转导反作弊。** c=1000 的权重设计使低训练精度模式几乎不可能胜出。但作者发现模型会生成“混合转导”作弊程序：读入维度后按 if-else 硬编码输出，污染投票且不泛化；检测方法极简——检查程序代码中是否出现其计算出的输出网格，命中即过滤（附录 F）。这是投票式集成在无验证集场景下的必要护栏。

**3.5 无真值测试时训练。** 数据选择（附录算法 2）：按测试输出网格分组，组间按多数投票权重做多项式分配名额，组内按 c×train_accuracy 质量分加权采样；即用“伪标签簇 + 训练精度”替代不可得的测试精度做 greedy-diverse。TTT 全流程不触碰任何真值，这是其能在评测任务上合法使用的前提。

**3.6 跨模型数据池化与集成。** 不同规模/家族模型的解集呈互补性：池化五模型数据重训（SOAR(all train)）全面优于仅用自身数据（第 4 节表），最终 52% 由五模型输出集多数投票产生（6000×5 次尝试/任务）。作者测得多数投票与 oracle（任一解正确即算对）平均差 9.5 个百分点，明示集成策略仍是低效环节。

## 5. 消融要点

采样数据策略（ARC-train，QC-14B，3k 采样解出率，论文表 2）：

| 数据策略 | Sample-3k |
|---|---|
| 不微调 | 29.29 |
| correct-only（无重标注） | 34.67 |
| uniform + 重标注 | 32.38 |
| greedy + 重标注 | 34.3 |
| greedy-diverse + 重标注 | **36.46** |

全部重标注变体均超 correct-only 之外的基线，greedy-diverse 最优；correct-only 在数据可得时仍有竞争力，说明“成功解信号”与“多样性信号”需混合。

精修数据策略（采样端固定基座 3k + 微调后精修器 3k，ARC-train，表 3）：不微调 34.83% → uniform 精修器 42.67% → 按父程序准确率分箱的 diverse 精修器 42.88%。精修微调带来的搜索增益（约 +8 点）大于采样微调单独使用时，是闭环中价值最高的监督源。

联合 vs 专精（ARC-train，表 4/7）：base/base 为 29.67 / 34.83（采样 / 搜索）；fine-samp + fine-ref 双专精组合 36.46 / 43.88；fine-both 单模型 39.79 / 44.42。不对称迁移：仅微调采样使搜索降至 32.92（负迁移）；仅微调精修却把采样提到 39.17（超过仅微调采样的 36.46）。所有策略选择均在 ARC-train 上调定以避免对测试集过拟合。

## 6. 贡献与启示

按其自身领域标准评估，论文贡献有四（作者自述）：无人工数据的自改进进化搜索框架；无真值的测试时训练机制；“迭代模型改进可突破搜索平台期”的实证；开源 LLM 在 ARC 公开测试集程序合成的 SOTA。方法学上最值得借鉴的三点：事后重标注把失败程序系统性转化为按构造正确的监督对，解决了专家迭代在低通过率任务上的数据饥渴；采样/精修能力共享表征且联合微调有正协同（并存在方向性迁移），支撑“单模型多算子”设计；FLOP 对齐的对照（6k+微调 vs 12.6k 纯搜索）使“学习优于蛮力搜索”的结论在计算口径上站得住。坦承的局限：每任务每迭代 6000 次合成尝试的成本；增益随迭代递减（作者称表现为减速而非无界改进）；多样性瓶颈；多数投票距 oracle 平均 9.5 点；仅在 ARC 单域验证；精修版 TTT 未实现。

**与音视频技术的上下游关联（迁移分析，非论文结果）：** 上游，音视频处理链路中大量问题是 PBE 同构体——编码器参数/码控策略搜索、filter graph 构建、处理内核优化均以“配置→实测指标”对出现，执行反馈（RDO 代价、PSNR/VMAF、BD-rate、时延）天然存在，可直接替换 ARC 的训练例准确率进入 SOAR 的精修 prompt 与 REX 价值函数。论文明确指出 FunSearch/AlphaEvolve 类固定模型的程序搜索系统可将 SOAR 作为 drop-in 升级，此类系统本就服务于内核与调度等离散优化，向编码流水线迁移的通路清晰。事后重标注对自动调参尤其有用：失败的编码配置仍构成合法的（配置→实测指标）监督对，可放大调参经验数据。TTT 机制与 per-title/per-scene/per-device 自适应编码同构——在无真值（无参考质量）条件下仅凭训练例级信号微调策略。下游推理侧，加权多数投票（count + c×train_accuracy）与 AIGC 多采样重排融合结构一致，但其 9.5 点 oracle 缺口提示质量评估器研究有明显承接空间。工程警示：6000 次尝试/任务（集成则 ×5）只适配离线内核开发与流水线调优，不可入实时链路；且 ARC 任务“每题重造规则”，而媒体优化目标多近似平稳，TTT 的收益结构与调参时机需重新设计。

## 7. 与其他论文的联系

- **SkillDuet（arxiv:2611.12109）**：同属以自身生成经验 + 反馈微调模型参数的递归自改进；差异在 SkillDuet 让外部技能库与参数共同演化，SOAR 把全部能力内化为采样/精修两个条件分布——代表“参数内化 vs 外部库”两条路线，SOAR 的重标注数据放大可为其技能挖掘供数。
- **TRUST（arxiv:2611.10787）**：SOAR 的 Impact Statement 自认改进是减速而非无界、并呼吁设置防护；TRUST 以在线多重假设检验为递归自改进控制错误进化率并提供统计保证，正是 SOAR 型闭环缺失的安全层，属方法互补。
- **FGSE（arxiv:2611.14326）**：二者都在回答“经验如何可信地转化为能力”。FGSE 将经验作为可证伪假设经三类探针验证后才写入记忆；SOAR 的重标注使一切程序“按构造正确”而绕过验证，代价是引入作弊解污染投票（附录 F 的硬编码过滤即为此付的税）——构成“经验可信度 vs 数据利用率”的权衡对照。
- **RSI-PDEbench（arxiv:2611.14949）**：SOAR 是递归自改进在程序合成的实例，RSI-PDEbench 将同一“搜索→经验→微调→更强搜索”闭环迁移到 PDE 数值求解并报告通过率提升与调用成本下降；SOAR 的失败复用机制对求解器尝试的再利用有直接参考价值。
- **WeightLoop（arxiv:2611.07319）**：同为免全量重训练、以实验/执行反馈持续改进已部署模型；SOAR 走“任务数据策展 + LoRA 微调”，WeightLoop 让 LLM 直接生成有界权重编辑程序——同一目标下“数据驱动梯度更新 vs 权重空间编程”的粒度差异。
- **LongCapHarness（arxiv:2611.10463）**：两者都绕开传统后训练获得测试时增益（SOAR 靠测试时参数微调，LongCapHarness 靠能力引导的自动挂接且成本低于基线 50%），共同佐证测试时自适应正在成为系统性手段而非个案技巧。
- **InfraRSI（arxiv:2611.11558）与 AutoTavern（arxiv:2610.33845）**：同为执行反馈驱动的自改进智能体家族，分别落地于训练基础设施优化（最高 2.75× 加速）与游戏 AI 自主构建，与 SOAR 一道显示该范式跨域可塑性，也呼应论文“可作 FunSearch/AlphaEvolve drop-in 升级”的定位。
