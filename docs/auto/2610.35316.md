# RSIV-Harness: A Recursive Self-Improvement Harness Framework for Open-Domain Conversational Text-to-Visualization

## 1. 背景与动机

论文针对的是开放域对话式 text-to-visualization 的真实形态：用户请求图表时并不知道数据在哪个库哪张表；请求常含歧义（毛利还是净利、按月还是按季聚合）；用户会多轮深化分析或迭代改图，且早期轮次确立的约束（排除某记录、以某维度着色）必须在后续轮保持。作者将其归纳为 ODAC（Open-Domain, Ambiguous, Conversational）任务族。

部署侧的核心观察：现有可视化智能体都把 LLM 包在 agent harness（挂接层）里——系统规则、工具接口、控制策略，管辖 schema 访问、SQL 生成与图表渲染——但 harness 一次性人工写就、发布后冻结。由此产生三个适应性问题：其一，跨任务反复出现的失败模式（过早生成代码、schema 检索误用、跨库边界违规）无法被清除，因为没有机制从累积轨迹反哺 harness；其二，提升可靠性通常要重训或更换基座模型；其三，直接从失败任务学习可能引入回归，让 harness 在原本能做对的任务上翻车。

基准侧同样碎片化：nvBench/VisEval 假定已知目标表；nvBench 2.0/CLARITY 注入类型化歧义但 schema 已给定且止步 SQL；Dial-NVBench/Text2Vis/PMVisBench 支持多轮但表上下文固定；TACO 面向未指定库的跨库 SQL 组合却没有可执行图表监督。文中明确主张：没有一个公开基准同时覆盖全库集合暴露下的源发现、类型化歧义澄清对话、跨库 SQL 组合与逐代码轮的查询+图表可执行监督。

方法定位上，作者把递归自我改进（RSI）分三条线并指出空白：权重中心路线（AREX，靠 agentic mid-training/RL 改参数）；harness 演化路线（测试时程序搜索、弱点驱动提案+回归测试、可观测性驱动的组件编辑）；推理时自纠（Reflexion/Self-Refine/DSPy，只改单条轨迹、不提交持久化 harness 修订）。RSIV-Harness 的差异点：在开放库集合上支持澄清对话，并对多轮场景下“查询+图表”耦合执行做回归校验的 harness 提交。

对音视频方向的读者，本文的结构意义在于：LLM 生成 Plotly 代码并执行，与 LLM 编排生成模型调用、时间线编辑脚本、渲染质检的 AIGC 生产管线同构（冻结基座 + 可演化挂接层 + 执行反馈）；其“锚点 + 受保护记录回归门”为音视频生产智能体的免训练持续适应提供了可直接移植的提交协议。

## 2. 方法总览

论文是“基准-方法”协同设计：ODAC-Vis 供评测，RSIV-Harness 供求解。方法侧为冻结 LLM 权重 + 双层递归结构。

**内层（任务环）**：ReAct 模式处理一个 assistant 轮。轨迹 h_t = (m_i, a_i, o_i)_{i=1..t}（决策摘要/动作/观测），策略 π_H 与环境算子 T_H 由当前 harness H 参数化；每步从封闭动作集发出一个动作——调用注册工具集 T(H) 中某个工具，或以合法澄清终止本轮。停止条件：合法澄清、产出完整程序、或用尽 m(H) 步策略预算。程序在沙箱执行，失败留作修复证据：同轮内首次生成后至多 K(H) 次修复（即至多 K(H)+1 次执行），第 j 次生成的可执行概率 p_j 条件于此前观测错误 e_{<j}，至少一次可执行的概率为 q = 1 − Π_{j=0}^{K(H)}(1−p_j)；每次修复复用轨迹中已存的源证据，只重写程序、不动 harness。middleware 一旦被引入，可将原始轨迹压缩为短上下文（最近刷新 z_τ = f_H(h_τ) 拼接其后增量），并保留后续仍需要的观测——包括排除某数据源的证据——即面向 schema 证据与对话状态的自主上下文更新。

**外层（自改进环）**：把 harness 当作递归算子 Φ 的状态。固定分层训练面板 S（48 个仅训练域任务）与固定验证锚点，V(H) 为 π_H 在锚点上的任务成功率（计分极严：任务内每个 assistant 轮都须采取参考立场且完成，每个金标代码轮都须执行且结果表与参考表在执行等价比较器下等价）。一轮流程：评估 τ(H)=Evaluate(π_H, S) → 分析 G(τ(H), R)（R 为上一轮被拒候选的裁决集；先把违反同一任务契约的轨迹聚类，再让提案模型对每簇有界样本解读）→ 产出 (P, I)，其中 P 是有界受保护记录记忆（任务、轮、维度、已提交 harness 达成的基线分），I 是未解决失败簇 → 提案 H′ = Improve(g(H), H)，至多 E 条编辑，每条编辑必须指名改动组件与所针对的失败证据 → 提交谓词 Accept(H′) = MC(H′) ∧ AC(H′)：通过则 H_{n+1}=H′，否则回滚到冠军 H★_n。

设计哲学有两点值得注意：种子 harness 刻意最小化——若种子已对 ODAC-Vis 调优，后续每个编辑的归因都会被污染；外层不遵循预定义编辑规则，自主决定改哪个组件、怎么改，稳定性完全交给四层规则做硬约束。

## 3. 关键设计

**3.1 ODAC-Vis 构造**。206 个 Spider 测试集 SQLite 库、139 个域作为原子分配单元，15 个域独占测试；640 任务按 14:3:3 分为 448/96/96，drilldown/iterate 场景各半，复杂度单表：单库连接：跨库 = 3:5:2（192/320/128）。槽位配额用嵌套最大余数法自顶向下求解（先定 split，再在 split 内平衡场景，再在场景格内配复杂度），保证各边际配额同时满足。跨库任务把库集合建模为可组合性图 G=(D, Π)，边为组合计划 π=(ρ, B, κ)（SQL 关系类型/参与库/可执行程序骨架），关系类型覆盖 equi-join、semi-join、union、标量子查询；候选经三阶段过滤——名称相似度/值重叠/覆盖率/键唯一性/连接膨胀的分级质量测试（strict/relaxed1/relaxed2 阈值）、保留库上的执行探针、参与库同 split 约束（规划时留 α=3 安全冗余）；金标从 Π_s 均匀采样、经 ATTACH 落地为 SQL，查询后 pandas 变换仅限对最终结果集的一元清洗——强制 SQL-only 组合，杜绝事后 Python 拼接。歧义共 8 个模板类型（数据语义：列选择/聚合粒度/过滤逻辑/单位刻度；可视化语义：图表类型/编码映射/轴标签/交互性），每个歧义点至少两个 schema 支持的备选，且原始结果、清洗结果、图表三个指纹两两可区分——澄清必须改变下游金标而非表面措辞；澄清对话不暴露库名表名。轮数与歧义数耦合（1 个歧义 3–4 轮、2 个 5–6 轮、3 个 7–8 轮，相邻歧义轮至少隔一个无歧义轮），全局类型配额用单位容量二部图最大流指派（每任务一个主类型、对话内不重复）。生成管线为模板编译（产出结构化查询/清洗/图表规格与可执行 SQL/Plotly 代码，执行或歧义校验失败即丢弃）+ DeepSeek-V4.1-Flash 改写为自然对话 + 终验器拒绝违反 clarify-and-code 语法的对话。质量审计：固定种子各抽 100 题，与 Dial-NVBench、NVBench 2.0 双盲对比，专家盲审下 ODAC-Vis 得 93.6/82.1/87.3（相关性/合理性/可读性），LLM 评审得 91.8/78.7/86.2，全维最高，优势在可读性最明显。

**3.2 四层稳定性规则与形式保证**（方法核心）。规则集 R = {RF, RS, AC, MC}：

- **RF（精炼）**：接受后受保护记录经 Refresh_C = Cap_C(Merge(P, A)) 折入容量 C 的记忆（按任务×轮×维度键合并，已存键保留旧基线）；下一轮分析聚焦仍未解决的簇；接受清空上轮拒绝裁决。
- **RS（重启）**：拒绝即回滚部署到冠军 H★；拒绝裁决（哪个谓词失败、哪些抽样记录回归）保留给下轮分析；记忆冻结——被拒候选不添加任何已解任务。
- **AC（锚点校验）**：相对准入 V(H′) ≥ (1−ε)B；严格冠军更新（仅当接受且 V(H′)>B 才更新 B 与 H★）；带内部署——通过 AC 的候选即使未破纪录也成为当前部署 harness，但冠军不动，后续重启直接回冠军。“部署≠冠军”的分离允许在 (1−ε)B 带内探索而不污染回滚目标。轮内还允许至多 ℓ 个有界补救周期：AC/MC 失败先带裁决返回 Analyze 重新提案，全部周期失败才终止拒绝——把“一次否决”改造成“定向重试”。
- **MC（记忆校验）**：分层抽样 Q = Cycle(P, Γ(P)) 按“指标维度×对话场景×复杂度层”组轮转取样，回归计数 Reg_Q(H′) = Σ 1[s_d(H′;x,t) < b]，容忍 δ；轮转设计避免回归检测集中于单一组。

记录入库门槛本身编码了“强行为”：stance/executability/routing/execution accuracy 须满分 1 入库，clarification 须正分，chart structure 须 ≥0.75。四条定理：T1 接受 ⇒ 记忆刷新且裁决清空；T2 拒绝 ⇒ 冠军恢复 + 记忆不变 + 裁决保留；T3 冠军分 B 单调不降且轮末部署 harness 满足 V(H̃_n) ≥ (1−ε)B_n；T4 接受 ⇒ Reg_Q ≤ δ（防振荡）。须注意这些是关于部署状态转移的确定性不变量，不是对任务分布上误差率的统计保证。

**3.3 评测口径**。六指标：Executability（程序可跑通）；Database Routing（访问库集合须与金标完全一致 D(p̂)=D★，开放域下错库会产出流畅但无关的图）；Stance（每轮该澄清还是该写代码）；Execution Accuracy（预测结果表在行列置换 π 下与金标表等价）；Clarification Quality（轮级 BLEU-4，无 brevity penalty，参考集含金标澄清与标注备选，该澄清未澄清记 0）；Chart Structure（把图约简为 8 元签名：标记类型、x/y 每条 trace 的编码角色序列、多 trace/图例标志、轴题匹配、交互种类集相似度 J(I, Î)、绘制行多重集等价，8 项均分）。测试采用 model history 协议：每轮条件于模型自己在本任务内的历史输出，而非金标历史。

## 6. 贡献与启示

**贡献**：(1) 首个联合覆盖开放域源发现、类型化歧义澄清、跨库 SQL 组合与逐轮可执行查询/图表监督的对话式 text-to-vis 基准（640 任务、域级 held-out）；(2) 冻结权重下从自身轨迹递归演化 harness 的框架，内环 ReAct 求解、外环聚类失败并自主提案；(3) 四层稳定性规则及四条形式保证——这是相对既有 harness 演化工作最独特的部分；(4) held-out 域上的实证 + 跨骨干迁移 + 双消融。

**工程解读**：这本质上是“智能体挂接层的 CI/CD”——锚点即冒烟测试，受保护记录即回归测试向量，冠军即可回滚 release，带内部署即预发环境；编辑预算 E、每条编辑绑定失败证据、拒绝裁决回灌下一轮分析，把开放式 LLM 提案约束成可审计的差分变更。该协议可移植到任何“冻结基座 + 脚手架”的系统。

**局限**（均可从文本核实）：实验只跑了一轮 RSI（N=1），定理所覆盖的多轮动力学（B 单调、带内探索、补救周期）没有实验证据；ε/δ/C/E/ℓ/K(H)/m(H) 取值未披露，而锚点仅 48 题（每题约 2 个百分点的分数粒度，1/48≈2.08），接受域宽度对这些超参与锚点方差高度敏感；全文无 token/成本报告，而稳定性规则本身会放大评测开销（每候选在面板+锚点+回归抽样上反复评测，轮内还有 ℓ 次补救）；Clarify 用 BLEU-4 且全场 ≤5.15，语义等价的澄清问法会被 n-gram 口径惩罚，该指标天花板存疑；单种子、无方差报告。

**与音视频技术的上下游关联**（此段为迁移性解读，非论文结论）：上游，Plotly 代码生成属程序化图形合成，与 LLM 驱动的音视频生产脚本（ffmpeg 滤镜链、时间线/EDL 生成、生成模型调用编排）同构；harness 五组件可映射到 AIGC 生产智能体的工具接口、资产记忆与渲染反馈环——“middleware 单项增益最大”的发现提示音视频侧的实施排序：先把渲染/解码/编码反馈环做进挂接层，再谈 prompt 调优。中游，ExAcc 的“结果表置换等价”与 Chart 的 8 元签名为可执行监督提供了模板：音视频可用解码输出比对、镜头表/EDL 结构比对替代 n-gram 或人工打分。下游，8 类类型化歧义（尤其编码映射、交互性、单位刻度）可直接迁移为创意简报澄清类型学（分辨率/宽高比/时长/音轨/编码档位）；多轮约束保持（排除项、着色编码在后续轮不丢）正是对话式剪辑助手的核心难点。此外，锚点 + 受保护记录的提交门等价于编解码工具链发布中的 BD-rate 护栏——任何提交不得使受保护测试向量上的指标回退超过容忍 δ——RSIV 把这套纪律形式化成了定理，可作为音视频生产智能体持续演化的治理模板。

## 7. 与其他论文的联系

- **LongCapHarness（arXiv:2611.10463）**：同属“冻结基座 + 递归自我改进挂接层”范式。LongCapHarness 挂接长上下文推理底层能力，免数据合成与后训练即在 HELMET/RULER 超基线且成本低于基线 50%；RSIV 把同一范式推进到多轮对话 + SQL/图表耦合执行场景，并显式引入回归校验的提交门。对照点在于：LongCapHarness 给出了成本核算，RSIV 未报告任何 token 开销，这恰是下一条论文批评的缺口。
- **The RSI Tax（arXiv:2611.13524）**：直接构成对本文的成本质询——该文发现简单有界笔记基线在精度持平下比三种 RSI 方法省 65.6–71.0% 总 token。RSIV 的稳定性规则（每候选的面板+锚点+回归抽样评测、轮内 ℓ 次补救）会系统性放大评测成本；其 +34.01 的 Chart 增益只有在披露总 token 开销并与之对冲后才具成本效益结论。
- **TRUST（arXiv:2611.10787）**：用在线多重假设检验为 RSI 控制误差进化率并提供统计保证；RSIV 的四条定理是部署状态转移的确定性不变量，不约束任务分布上的误差率。两者互补：把 TRUST 的统计检验嵌入 RSIV 的锚点校验，可为 48 题小锚点上的接受决策提供置信度校正。
- **SkillDuet（arXiv:2611.12109）**：以响应反馈协同“模型参数更新 + 外部技能库演化”，走权重参与的技能级 RSI；RSIV 严格冻结权重、只演化挂接层。RSIV 的跨骨干实验（GPT-6 Luna 上 Executability 仍差最强基线 4.67）恰好为 SkillDuet 的动机提供了证据：纯 harness 演化的收益部分绑定演化时的骨干，权重与技能协同演化可能补足这部分。
- **SimplEvo（arXiv:2611.11509）**：同样免权重更新，靠自写文本记忆与教训精炼实现自我改进（EBench 成功率 46.7%→81.7%）；RSIV 的受保护记录记忆是其回归校验版本——SimplEvo 没有“接受 ⇒ Reg≤δ”类形式保证，RSIV 的 T4 补上了这一层，但其记忆构建门槛（满分/0.75 入库 + 容量上限 C）与维护成本也更高。
- **InfraRSI（arXiv:2611.11558）**：其五阶段验证工作流将开放式指令转化为分布式 LLM 训练优化（最高 2.75 倍加速），与 RSIV 的“提案—锚点校验—记忆校验—提交/回滚”在结构上同源：都是用验证门约束开放式 LLM 提案；差异在 RSIV 额外维护跨轮冠军与受保护记录，支持多轮递归下的回滚语义。
- **Flex-RSI（arXiv:2611.08946）**：在固定预算下评估智能体通过递归修订 harness 在视觉与机器人任务上的自我改进能力，与 ODAC-Vis 同属“为 RSI 造评测”的努力；Flex-RSI 把预算约束显式化，而 RSIV 的实验未披露预算，二者对“RSI 值不值”的回答方式形成互补。
