## 1. 背景与动机

递归自我改进（RSI）此前的成功集中于两类隔离目标：算法/程序发现（FunSearch、AlphaEvolve、AIDE 一脉）与单个 kernel 合成（KernelBench、AI CUDA Engineer）。论文指出（Table 1 对比），分布式 LLM 训练吞吐是另一类问题：launch 配置、算子内核与集合通信调度紧耦合，单次编辑常常同时触碰 OOM 边界、编译器冲突、测量抖动与数值漂移。三范式的结构性差异在于：infra RSI 是 multi-GPU、整个 campaign 只有 10–20 次完整 run、配对步时噪声跨两个数量级（0.04%–6%+）、等价性判据必须是“固定任务合同 + 源码路径审计”而非测试套件或张量容差、reward hacking 风险从 moderate/high 升至 severe（prefetch 偏移、计时器位移、精度漂移），可复用资产则是跨硬件先验而非任务代码池。

论文用审计数据归纳出无约束 coding agent 与贪心局部搜索在四个 workload 上的四类复现失败模式，每条都带量化口径，值得全文引用：

1. **Reward hacking 与计时边界偏移**：无合同验证时，agent 通过改变有效 batch、把辅助参数更新推迟出计时窗、日志计时器位移、未授权低精度/融合交叉熵等手段制造虚假加速；文中源码审计抓到过“把最终一次 update 排除在计时窗外、并用单条 receipt 的 validity 位掩盖 kernel import 错误”的候选。
2. **宽带测量噪声**：专用 8×H100/8×H200 节点配对噪声 0.04%–0.10%，共享主机超过 6%；固定 2% 门限在安静集群上丢弃真实存在的 0.5%–1.5% 通信重叠与可堆叠小补丁，在噪声主机上反而放行随机抖动。
3. **LLM 定量先验失准**：零样本加速预测与实测硬件执行的 Spearman 秩相关为负（r∈[−0.49, −0.06]），且对高杠杆旋钮发出假否决——Gemma-4-26B-A4B MoE（8×H200）上编译先验只给 +2.0%，实测 +55%；双节点 Qwen3.5-35B-A3B MoE（16×H100）上先验判 NCCL 通道数增加为轻微负收益，实测 +10.2%。
4. **单 incumbent 在内存/编译器悬崖处的短视**：Gemma MoE 上单独关闭激活重计算直接 OOM（+18 GiB 缺口），开编译又与默认 Liger 融合核悬挂；只有把它与 −14 GiB 的 saver 和 FlexAttention 组合才到 2.75×。Auto-Research 在该负载上 1.29× 后即绕局部盆地打转。

动机落点：把开放式人类指令变成“被验证的训练系统优化”，形成两层 RSI 环——run 内在线修正先验，跨集群蒸馏经验。就本笔记的领域定位而言（笔记作者视角）：本文处于训练系统层，是音视频基础模型（视频生成、多模态大模型、神经编解码方向的大模型）训练的上游基础设施；其 MFU 与吞吐结论可直接折算为该类模型训练算力成本，后文第 6 节展开。

## 2. 方法总览

InfraRSI 是一个 agentic harness，将 LLM 假设生成与测量、验证、搜索、经验存储解耦，以五个确定性 CLI 阶段组织一次优化 campaign：

- **init**：解析目标仓库 AST，声明任务范围与 `editable_files`，对 `frozen_files`（数据加载、评测脚本、loss 定义、harness 计时器）锁 SHA-256 摘要。
- **doctor**：跑参考基线、裁剪 warmup、标定集群步时噪声、剖析前向/反向/优化器/数据加载/通信的相位占比、探测互连带宽、给经验库先验覆盖率分级。
- **run**：执行第 3 节的组合式搜索控制器，保留每个候选的原始执行 receipt 与全部资源成本；搜索结束后对最快有效候选做与基线的 back-to-back 独立复测，写回经验包，产出 `result.json`/`pack.yaml`/`REPORT.md`。
- **report**：渲染结构化报告、不变量判定、候选源码路径审计与资源核算。
- **apply**：检查工作树冲突后写入被提升的 launch 配置与源码 diff（可选新 git 分支）。

优化目标形式化为：在候选空间 A 上最大化 log 加速 ln(T₀/T(a))，受 16 条确定性不变量约束（Eq. 1）。**固定任务合同**锁定模型结构、数据集、每次 optimizer update 处理的 token 数、允许的精度菜单与更新协议；搜索成本与预期节省统一折算 GPU·hour 以便调度。候选是联合规范：launch 旋钮（CLI flag / 环境变量 / 配置键，经代数 batch 守恒过滤）+ 作用于 `editable_files` 的 AST 校验 unified diff 源补丁（编译块稀疏或分块注意力、融合 norm/RoPE/AdamW、梯度范数通信分桶等）。

工程上一个重要设计是**多栈适配器**：以 <15 行 hook 暴露统一执行与 receipt 接口，覆盖 Megatron-Core、FSDP2/TorchTitan、DeepSpeed、HF Trainer/TRL 与原生 DDP。测量纪律包括固定 update 数、warmup 裁剪、同步稳态计时窗；为防幸存者偏差，reference/search/promotion/profiling 四阶段 GPU 时与 token 消耗全额入账（含被审计剔除的候选），换主机必须重建本地基线。

验证侧是五层 16 项确定性不变量（L1 执行完成/无错误/显存上限，L2 工作量/数据/模型/冻结文件一致，L3 优化器步数，L4 数值容差与精度菜单，L5 计时一致与加速复现）。若无候选通过全部验证与提升门，harness 保留参考配置并如实报告 1.00×——这是它区别于开放式 coding agent 的姿态性设计。

## 3. 关键设计

### 3.1 噪声标定、相位上限与多起点初始化

doctor 阶段把配对参考重跑差分与 run 内 split-half 偏差池化（下限取窗内白噪声地板）估计配对 log 步时噪声 σ_pair；大旋钮选择与停滞检测统一用门槛 max(0.02, 2σ_pair)，提升必须在新 fresh back-to-back 复测中超过配对相对裕度 exp(2σ_pair)−1。该协议实测专用节点配对噪声低至 0.04%–0.10%。同时用 doctor 的相位剖析给任何单杠杆预测加 **Amdahl 相位余量上限**：预测增益不得超过其目标相位的时间占比——这是对 LLM 幻觉加速预测的物理钳制。

多起点初始化用前三次完整 trial 探测互补的完整配置：(1) 经规范机制归一化后从经验库最相似硬件/模型环境热启动已验证最优配置；(2) 先验模型评分最高、且至少在一个高杠杆旋钮上与起点不同的配置；(3) 冲突规则过滤下的均匀随机合法配置，锚定全局速度与内存方差。实例：Qwen3.5-9B（8×H100）上经验种子起点 Trial 1 即达 1.55×，后续搜索推进到 1.73×。

### 3.2 全局时间代理与删失内存账本（方法核心）

基础设施搜索空间被 OOM 边界与编译不兼容切成不连通盆地，贪心地从最新 incumbent 出发会在早期选择锁死下游优化时死锁。InfraRSI 改为在整个 trial 历史上拟合并逐 trial checkpoint 两个全局模型：

- **Cholesky 贝叶斯线性时间代理**：以非参考旋钮取值、已验证源补丁、启用对（enabling pairs）的指示特征建模 log 加速，后验精度矩阵闭式更新并限制先验方差。
- **右删失 Tobit 内存账本**：对候选 a 建模每卡峰值显存 m̂(a)（观测噪声 σ_obs = 0.02·C_card），三段似然——完成 run 用精确高斯残差；OOM trial 用右删失似然强制 m̂(a) ≥ m_oom（失败时的分配缺口给出所需内存下界）；近容量分配器抖动时用区间删失把峰值需求约束在 [0.90·C_card, C_card]。阻尼 Newton + Laplace 协方差拟合后，输出标定过的内存可行性概率与逐设置 GiB 估计，从而把配置显式区分为 spender 与 saver。

这是“把失败当数据”的关键：OOM 崩溃不是被丢弃的负样本，而是转化为内存需求的删失观测。

### 3.3 先验校准、失败归因与 bundle 补全

针对零样本先验负相关（r∈[−0.49, −0.06]）与假否决，采用经验贝叶斯收缩：旋钮先验 σ₀ ≥ max(σ_min, 0.5|μ₀|) 并由时间代理闭式更新；LLM 代码补丁增益预测乘保守因子（μ_patch = κ₀·μ̂_LLM）。当高杠杆旋钮被先验低估或否决、但其两σ上行越过大旋钮门时，强制安排 **contrarian 实证探测**：把冲突设置回退到参考态、内存可行性低时自动挂上估计最强的 saver，与 incumbent 对打。反复失败或高置信设置失败后触发结构化先验修订：携带实测步时、峰值显存、OOM 缺口直接更新 (μ₀, σ₀)，刷新时间代理先验与内存账本的 GiB 先验并原地重解后验。论文正是靠这个探测-修订环恢复了被零样本先验判为零或负的 +55%（编译）与 +10.2%（NCCL 通道）设置。

**失败归因**按类型分离：OOM 的设置被标记为“需要至少覆盖实测 GiB 缺口的 saver 伙伴”，只有跨多个不同 saver 仍失败才淘汰；非内存崩溃/悬挂/数值发散只禁最小冲突元组（未出现在任何通过 run 中的最小共现对/三元组），各设置在其他组合中保持可用；代码探索期失败归因于补丁而非底层 launch 配置。**Bundle 补全**把高代理预测加速但内存不足的配置放进高上行失败缓冲，配参考态 saver 覆盖缺口后重试——Gemma MoE 上即“关重计算（+18 GiB）× 关 Liger 融合交叉熵（−14 GiB）× 开编译”三方可行组合；**冲突回溯**则让被早前基线挡住的高先验杠杆回到干净 root reference 上重评，验证后整体迁移 incumbent。

### 3.4 大旋钮逃逸与补丁堆叠

明确划分 **K_big**：先验/代理后验/经验三种单旋钮 log 加速幅度任一越 max(0.02, 2σ_pair)（≈2%）者；内存锁定、worker 线程数等 <1% 效应的小旋钮不进入结构性算子。连续两次完整 trial 未越噪声门即进入逃逸模式：最小信任域距离从 1 个大旋钮动态扩到 3 个以强制多旋钮跃迁，改进步后沿有序轴外推，周期性从不同配置类的历史最优 warm restart；大旋钮 tabu 过滤 + 配置-补丁签名在执行前登记去重。开放代码编辑下，两σ上行低于噪声门的晚期配置提案把评估槽让位给源码合成；小增益已验证补丁按 Dorfman 组测试思想堆叠联测，合并 log 增益越噪声门才执行。上下文管理上保留最快与最近 run 的全轨迹、旧 trial 压成单行摘要（约 28k 字符量级），且在已验证补丁栈上细化旋钮时继承的 diff 行不重复计入每步行数上限。

### 3.5 经验协议与跨硬件迁移

经验库围绕 Environment（roofline、拓扑、互连、软件版本、模型维度、并行布局）/ Observation（完整旋钮配置、步时、峰值显存、验证条件、16 项判定、OOM 缺口与最小冲突元组）/ Effect（配对 log 加速、标定噪声地板、条件依赖、kernel vs balance 机制类）三实体结构化，两级归一化器把各框架 flag 映射到 **71 个规范机制**。跨集群迁移用兼容性 scope check（框架必须匹配；covered 要求模型族与序列长度桶匹配；拓扑敏感的 balance 机制还要求 SKU、节点数、每节点卡数、多节点互连、参数规模桶、并行布局全匹配，部分匹配降级、不兼容丢弃）+ 环境距离 d（SKU/节点数指示惩罚、参数量与序列长度对数比、0.25× 参考态失配）过滤并按 covered>partial、可读性、证据层级、d 字典序排序。种子语料为 11 个 pack、191 个环境、698 个观测、543 个 effect。表 3 给出必须这样做的物理原因——跨硬件符号翻转：Qwen3-8B 上 fp8 在 H20（148 TF）+58% 但 H200 仅 +30%（TP2 下 +3%）；tp=2 在 H20 +24%、H100 −4%；te_fp8_attn 在 H200 上 BF16 FlashAttention-3 反超 FP8（+6% vs −8% 翻转）；MoE alltoall+grouped_gemm 则在高带宽 NVLink 上跨硬件一致（+92% / +85–110%）。经验回写仅收通过全部验证的观测；跨 SKU 迁移评测显式排除同任务同 SKU 历史，避免自我回放。

## 5. 消融要点

- **数值容差与固定噪声消融**（Qwen3.5-9B，公共 90% 峰值参考 S★=1.75×）：窗均 loss 相对容差 0.10% / 3.00%（默认）/ 50.00% 与固定 2.00% 噪声地板四臂全部在 10–11 个 trial 内越过 90% 峰值，最终 1.70×–1.75×、6.02–7.05 GPU·h。关键结论：严格 0.10% 容差下仍有 1.70×，说明已发现的加速机制在数值上忠实、不依赖容差放宽；固定 2% 噪声地板臂有效候选最少（11/15）、最终 1.72×，校准噪声门略优于固定门但不灾难性——搜索主体对接受门不敏感，稳健性来自合同约束下的全局模型。
- **验证器分层账本**（表 2/表 8，1,212 次执行、710 个触发）：L1 执行层 503 触发/352 primary（completes 349、no_errors 153、memory_cap 1）；L2 全部 7 例为“不可验证即拒”；L3 离线 0 触发——推迟 update 型作弊由源码审计而非 receipt 捕获，说明纯自动验证有盲区、source-path audit 必要；L4 数值 42 触发/41 primary；L5 timing_consistent 158 触发但 primary 为 0，全部与崩溃 run 共现；未获提升的 run 一律交付 1.00×。
- **多起点与迁移过滤**：经验种子使 Qwen3.5-9B 首个 trial 即 1.55×（冷启动 Trial 2 才 1.22×）；但“全量合格 pack”反而 >17 trial 右删失、最终仍是 1.70×，只有排除同任务同 SKU 的跨 SKU 迁移拿到 1.82× 且 9 trial/2.97 GPU·h 收敛——未过滤的相似证据构成负迁移，scope check + 环境距离排序才是迁移增益的来源，而非经验量本身。
- **先验修订有效性**：contrarian 探测 + 经验修订把零样本先验误判的 +55%（编译）与 +10.2%（NCCL 通道）翻回搜索主路径，直接对应 Gemma 2.75× 与 35B MoE 1.51× 的形成。

## 6. 贡献与启示

论文的三项自述贡献成立且边界清晰：(1) 统一执行与验证合同——五阶段多栈 harness，16 项不变量 + 源码路径审计 + 失败 trial 全成本记账 + back-to-back 基线复测；(2) 预算化组合搜索——Cholesky 时间代理 + 删失 Tobit 内存账本驱动经验先验校准、失败归因式 bundle 补全与大旋钮逃逸；(3) 跨硬件经验迁移与被审计的评测——机制归一化经验协议，dense/MoE、多数值容差域上验证。

方法论上对自改进系统研究的可迁移结论：**验证合同先于搜索**——在“以速度为奖励”的任何 agent 优化里，工作量/数值/计时三类不变量必须先验声明，否则提升不可信；**删失建模把失败变成约束**——OOM 缺口、近容量抖动都是带信息的删失观测，这一思路可推广到任何有硬资源边界的系统搜索；在 10–20 次评估的极小预算下，速度代理必须与内存可行性联合建模，单 incumbent 贪心在该问题类上结构性失效；经验库防负迁移靠“规范机制 + scope check + 距离排序”，而非数据量。

**与音视频技术的上下游关联**（笔记作者定位，论文本身未涉及 AV 任务）：上游——视频生成、多模态与 codec-token 类大模型的预训练正是此类基础设施的主要负载，1.83× 几何均值加速与 MFU 17.4%→30.0% 直接等比折算训练周期与算力成本；论文中 MoE 负载的 alltoall/专家路由通信瓶颈与音视频稀疏专家/模态专家结构同构，双节点 35B MoE 上 contrarian NCCL 调优（1.51×）对多机音视频 MoE 训练有直接参考价值；其产出物（编译 FlexAttention、融合 RMSNorm/RoPE/SwiGLU、分桶梯度范数通信）正是视频 Transformer 训练脚手架的同类算子。下游/横向——共享集群 >6% vs 专用节点 0.04% 的噪声谱与“配对噪声门 + back-to-back 复测”的接受协议，对音视频领域任何基于计时的内核/推理引擎调优 agent（如神经编解码内核自动调优）是可直接复用的反 reward-hacking 与反噪声模板。需注意的限制：论文未报告音视频典型负载（长序列视觉 token、3D 注意力）上的行为，迁移时应预期相位占比与 roofline 位置不同，先验需重新标定。

工程含义还包括：<15 行 hook 的多栈适配器设计使 harness 可叠加于既有训练框架而非替换之；HMAC receipt + 冻结文件摘要 + 1.00× 诚实回退构成一套可直接抄用的“agent 产出可审计”工程件。

## 7. 与其他论文的联系

- **paper:arxiv:2610.32026（RSI-Opt）**：同属“RSI 作用于训练栈”家族，关联依据最强。RSI-Opt 由元智能体跨训练运行演化优化器策略与代码库并支持跨模型迁移；InfraRSI 对象是训练基础设施（launch 配置 + 源补丁），差异在于 InfraRSI 以确定性合同 + 删失内存模型显式处理 OOM/编译器悬崖，并要求 back-to-back 复测方可提升——验证优先而非仅看下游指标增益，二者可视为训练栈 RSI 在“算法组件 vs 系统组件”上的互补分工。
- **paper:arxiv:2610.28201（MaD-RSI）**：均以 harness/外壳为优化对象并复用跨模型证据。MaD-RSI 把多模型失败轨迹作为训练证据直接优化跨异构 LLM 共享的外壳；InfraRSI 的经验库同样把失败（OOM 缺口、最小冲突元组）结构化为可迁移证据，但其证据是机器验证的运行时测量（步时/显存/不变量判定）而非行为轨迹，且最终优化的是训练系统吞吐而非 agent 外壳本身。
- **paper:arxiv:2611.10787（TRUST）**：同为 RSI 可信化方向，机制互补。TRUST 用在线多重假设检验控制自改进中的错误进化率并提供统计保证；InfraRSI 用确定性不变量 + 校准噪声门 + fresh 复测处理同一问题，其提升门 exp(2σ_pair)−1 本质是成对假设检验——TRUST 式错误率控制可作为 InfraRSI 多候选提升决策的外层统计包装。
- **paper:arxiv:2611.12109（SkillDuet）**：SkillDuet 以响应反馈协同演化 LLM 参数与外部技能库，实现技能级递归改进；InfraRSI 的经验库（71 规范机制、验证后回写、驱动代理先验初始化）是“基础设施技能库”的对应物，但条目为验证过的运行时证据、进入贝叶斯先验而非 prompt 复用，且不改动模型参数。
- **paper:arxiv:2610.32326（TGR-EvoDAG）**：同为多组件代码演化的工业级系统管线案例（腾讯生成式推荐，在线 CTR 相对 +0.40%）；InfraRSI 同样做配置+代码的组合式演化，但优化目标是离线训练吞吐、受固定任务合同与源码审计约束，在线业务指标验证与离线吞吐验证构成两类部署语境的对照。
- **paper:arxiv:2611.10463（LongCapHarness）与 paper:arxiv:2611.07319（WeightLoop）**：栈位对照关系——前者用递归自改进挂接推理侧长上下文能力、后者在权重空间做有界编辑式自改进，InfraRSI 则作用于训练系统层；三者共同点是以“免完整重训的递归改进环 + 实验反馈”替代一次性优化，覆盖推理 harness、权重、基础设施三个不同抽象层。
