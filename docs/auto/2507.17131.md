## 1. 背景与动机

论文切入的是部署期知识持续漂移的场景：监管合规、用户风险筛查等领域中 P(y|x) 随法规更新、名单变化与口径调整而演化，而现有 LLM 智能体部署后基本冻结——遇到新规则或未见场景即不可靠，除非离线重训。载体任务是 TikTok Pay 的客户尽职调查（CDD）名单筛查：智能体接收（用户开户信息，风险名单命中条目）二元组，判定 Match / Non-Match，Match 判定通常阻断开户。该任务有三个结构性难点： 双侧数据残缺且不一致——姓名变体、跨文字音译、马来语 patronymic（bin/binti）、DOB 残缺或日月换位等； 筛查规则模糊且频繁变更； 把全部政策文本塞进 prompt 不可行，复杂监管文本的歧义与规则间冲突使 LLM 难以一致解释执行。行业现状因此是绝大多数案例依赖人工复核。

既有路线的失效模式论文逐一交代：离线微调知识滞后、需重训；ICL/RAG 的知识库静态预填，运行期无法消解冲突；test-time fine-tuning 逐 prompt 改参数，与合规场景的可审计要求相悖；自主自我改进类智能体（Self-Refine、Reflexion、Multi-Agent Debate）缺乏外部真值锚点，错误可能自我强化。ARIA（Adaptive Reflective Interactive Agent）的定位由此明确：人介导的测试期持续学习闭环——结构化自评发现知识缺口、在预算内定向求助于真人专家、将反馈整合进带时间戳并可消解冲突的演化知识库。工业背书：ARIA 已部署于服务超 1.5 亿月活用户的 TikTok Pay；该业务此前线上方案为纯人工，专家单案平均处理时长（AHT）约 12 分钟。

对音视频技术侧的定位说明：本文属 LLM 智能体/测试期学习方向（非音视频核心大类），按其自身领域标准评估；但其问题结构——规则口径持续漂移 + 机审不确定样本转人审 + 人工裁决回流为先例与规则——与音视频平台的内容安全审核、直播风控、分区合规判定在工程形态上同构，且部署主体位于字节生态，第 6 节展开迁移分析。

## 2. 方法总览

形式化（论文第 3.2 节）：智能体处理流 X=(x₁,…,x_N)，内部状态 Θᵢ 按 Θᵢ₊₁ = f(Θᵢ, xᵢ, ŷᵢ, qᵢ, hᵢ) 逐例更新——学习发生在推理期、逐例进行。每步先做决策 dᵢ∈{predict_only, query_expert}；若查询，从预定义查询类型集 Q 中选 qᵢ，成本 c(q)>0（实验可简化为 1），全程受 Σc(qⱼ)≤B 约束；专家 oracle 返回 hᵢ=O(xᵢ,qᵢ)。目标是在预算约束下联合设计策略 π 与更新函数 f，最大化整流累计性能。ARIA 的关键实现选择：Θ 不落在模型参数上，而是完全非参数化地实现为结构化知识库 KR（Θᵢ≈KRᵢ），底座 LLM（GPT-4o 或 Qwen2.5-7B）全程冻结——所有“学习”表现为 KR 条目的增补、状态迁移与检索加权。

单例处理闭环四步：
1. **初判**：以当前 KRᵢ 检索出的知识子集 + 冻结底座生成初步判决 ŷᵢ 与理由 rᵢ；
2. **IGS（Intelligent Guidance Solicitation）**：对 (ŷᵢ, rᵢ) 做结构化自评，产出三档置信度与知识缺口；若置信度∈{Moderate, Low} 且预算允许，将缺口转写为定向查询；
3. **专家交互**：真人专家（TikTok 合规团队）给出反馈 hᵢ；
4. **HGKA（Human-Guided Knowledge Adaptation）**：以 (KRᵢ, xᵢ, ŷᵢ, qᵢ, hᵢ) 更新知识库至 KRᵢ₊₁，即形式化中的 f。

知识库条目为六元组 k=(k_id, K, ts_added, ts_validated, S, M_meta)：K 为知识内容（规则/解释/事实陈述/案例样例 (x_j, y*_j, reason_j)），两个时间戳分别记录入库与最近验证时刻，S∈{Valid, PotentiallyOutdated, Superseded} 为有效性状态，M_meta 记录来源（专家/自推导）、使用频次与 superseded_by 关联指针。

CDD 实例化（第 3.3 节）：输入字段含姓名、别名、本语言名、国籍、地址、出生日期、身份证件，命中侧另含职位、列名原因等敏感字段；输出 {Match, Non-Match}；查询类型覆盖标签请求、决策解释、规则澄清、冲突消解。数据流为 N=11,846 条按时间排序的真实案例，极度不平衡（156 Match / 11,690 Non-Match，正负比约 1:75），故分列 Sensitivity（正类召回）与 Specificity（负类召回）而非总体准确率。

## 3. 关键设计

### 3.1 IGS：以可追溯自对话替代置信度阈值

不使用固定启发式或标量置信度门限，而是对每个初步判决执行一组预定义反思问题（数量记为 NRQ，论文未给出具体值）的自问自答，逐题由底座 LLM 生成答案，构成自对话 D_self。问题设计（附录 A.2）覆盖五个探测面：证据复述（哪些输入与存量知识证据支持该判决）、隐式假设识别、领域知识熟悉度（例：“我对公司关于可接受 DOB 偏差的政策有多熟悉？是否掌握中文名变体匹配规则？”）、与历史相似案例的一致性、KR 中相关知识的时效状态（“最近被验证还是可能过时”）。随后输出三档置信度；触发规则为置信度∈{Moderate, Low} 且累计成本加拟发查询成本不超 B。

查询内容由 D_self 中的缺口类型直接决定：证据歧义→请求正确标签；特定领域规则缺失→请求规则或解释。两个工程要点： verbalized confidence 从无根据标量变为可逐条追溯的自问自答链，不确定性被归因到具体假设或具体缺失规则上； D_self 随查询一并提交给专家——专家面对的是已收敛到具体不确定点的定向问题而非整案从头复核，这直接对应效率实验中“专家答题远快于独立审案”的设定。

### 3.2 HGKA：时间戳知识库与冲突状态机

反馈 hᵢ 到达后的四段式处理：
1. **知识断言抽取**：从自由文本反馈解析出显式知识断言（除案例判决外常含政策式规则，且往往携带版本化标识）；
2. **时间戳初始入库**：每条断言生成新条目，ts_added=ts_validated=当前时刻，S=Valid，附来源元数据；
3. **冲突检测与消解**：对每条新知识，先以语义相似度超过阈值 τ_sim 检索相关旧条目，再由 LLM 比较函数 Comp 判定关系∈{supersedes, conflicts, updates, consistent}。supersedes→旧条目置 Superseded、回填 superseded_by 指针并刷新 ts_validated；conflicts（新知识使旧条目真伪存疑）→置 PotentiallyOutdated。论文附录给出的典型场景：旧规则“中文名需拼音精确匹配”被新规则“其他标识符（如 DOB）紧密匹配时允许轻微拼音变体”显式取代，前者被标记 Superseded 并链接至新条目；
4. **主动澄清查询**：当比较暴露不可自动消解的歧义——典型如新规则是条件式例外还是全面替代（“仅当 DOB 精确匹配时允许 Zhang/Zang 变体”究竟取代还是修订旧的精确匹配总则）——生成澄清查询反问专家，同样计入预算。

状态机的审计意义：Superseded 条目检索权重归零但不删除，保留完整取代链，满足合规场景的回溯与问责要求；PotentiallyOutdated 是“存疑降权、待人工裁决”的中间态，避免未确认知识被硬性清除或继续全权使用。

### 3.3 时间感知检索：乘法评分

处理新例 x_j 时，对 KR 条目按 Score(k, x_j, t)=WS(k.S)×ST(k,t)×SR(k,x_j) 排序，取 top-N 或超阈值 τ_score 的子集进入 prompt。三因子：有效性权重 WS（Valid=1.0、PotentiallyOutdated=w_po、Superseded=0.0）、新旧衰减 ST=exp(−λ·(t−ts_validated))、语义相关性 SR。乘法组合意味着任一因子趋零即整体出局——有效性是硬门控（Superseded 直接出局），时效性与相关性做软调制，使“最新、有效、相关”三者同时满足的知识主导决策。上述超参数（w_po、λ、τ_sim、τ_score、top-N）在提供的文本中未给出取值。

### 3.4 查询成本结构与漂移注入（CUAD 口径）

公共数据集实验把 Q 实例化为四类并赋予差异化成本：条款类型标签 c=1、类型解释 c=2、规则结构化摘要 c=3、冲突澄清 c=2，预算按成本累计。动态环境以 K 个阶段模拟四种漂移：条款类型分布漂移、条款释义性文本漂移、oracle 口径变更（模拟政策漂移，如 Governing Law 条款解释从“选择法律绝对适用”变为“新判例下公共政策例外扩张”）、新（子）类型突发引入。其中政策漂移直接压测 HGKA 的冲突消解路径。

### 3.5 开销构成

每例成本 = 初判（KR 子集注入 prompt）+ NRQ 轮自对话；查询例再加 HGKA 的断言抽取、语义检索与逐条 LLM 比较。论文在 Limitations 中自认：自反思、语义检索与冲突消解的开销在高吞吐、强实时约束的应用中需进一步优化，本文侧重学习有效性而非重载下的计算性能。

- 弱底座增益显著：ARIA（Qwen2.5-7B）在 B=100 即达 0.7756/0.7154，双指标同时超过全部 GPT-4o 底座的自我改进基线（Self-Refine 0.7244/0.6821、Reflexion 0.7692/0.6902、MAD 0.7628/0.6970），而 Qwen2.5-7B 静态仅 0.6474/0.6124。对照 Offline FT（Qwen2.5-7B）：即便用满 B=1000 等价数据，Sens 0.6987 仍不及 GPT-4o 零样本静态的 0.7051（Spec 0.6791 反超 0.6539）——弱模型+等价数据的离线微调在 Sens 口径追不上强底座冷启动，ARIA 则让弱底座整体反超。

## 5. 消融要点

消融在 TikTok Pay、B=100 口径下进行（表 2；完整 ARIA 0.8333/0.7423，与表 1 中 ARIA（GPT-4o）B=100 对齐）：

| 变体（B=100） | Sens | Spec | 相对完整版 |
|---|---|---|---|
| ARIA | 0.8333 | 0.7423 | – |
| Labels-Only | 0.7949 | 0.7139 | −3.8pt / −2.8pt |
| w/o Self-Dialogue | 0.8141 | 0.7319 | −1.9pt / −1.0pt |

- **Labels-Only**（只允许请求标签，退化为经典主动学习反馈）损失最大：解释与规则类反馈的迁移价值显著高于裸标签——单条规则可覆盖后续同类案例，标签只影响当前例。
- **w/o Self-Dialogue** 仍达 0.8141/0.7319，高于同预算 Simple Uncertainty（0.8013/0.7218），说明 HGKA 对查询质量不足有部分补偿；但差距存在，结构化自评对“问对问题”有独立贡献。
- **w/o KR Conflict Resolution** 掉至 0.8012/0.7128，Spec 降幅最大：冲突/过时规则不加管理会对后续决策产生系统性污染，在规则漂移环境里这不是中性冗余而是活跃噪声源——动态环境中知识库治理必要性的直接证据。
- **w/o Temporally-Informed KR** 的 Sens 不变、Spec 仅 −0.8pt：时间/有效性加权在本任务上作用温和，主要作用于负类判定精确度；作为无额外标注成本的机制仍值得保留。

## 6. 贡献与启示

方法学贡献： 给出 LTT+HITL 的统一形式化——预算约束下联合优化决策策略 π、更新函数 f 与查询策略，把“何时问、问什么、如何消化”纳入同一目标； IGS 用可追溯的结构化自对话替代置信度阈值，使不确定性来源（缺失规则/隐式假设/先例缺失）显式化并直接映射到查询类型； HGKA 的带时间戳知识库 + 三态冲突状态机，把知识演化从 RAG 的静态装库变成可审计的增量过程； 真实工业部署（TikTok Pay，>1.5 亿 MAU）与公共数据集双重验证。

工程启示：
- 非参数化状态（KR）= 可审计、可回滚、可问责。合规场景下“为什么这么判”可落到具体知识条目及其验证时间戳，这是参数更新路线给不了的属性。
- 专家经济学被重新定价：从逐案整审（12 min/案）转为定向答题，预算 B 成为运营侧显式的成本-性能旋钮——B=50 即可用（0.8013/0.7151），B=3121 封顶 0.9428/0.8814；预算-性能曲线本身即是部署决策依据。

对音视频技术上下游的关联（结构同构性分析）：
- **下游同构场景**是音视频平台内容安全与风控审核：内容分类标准、未成年人保护口径、版权与 AIGC/深伪判定规则随分区法规与平台政策持续漂移；生产中的“机审+人审”混合流水线（机审不确定样本转人审、人工裁决回流为可检索先例与规则）正是 IGS+HGKA 的镜像。可直接搬用的三件东西：三档自评触发转人工的门控逻辑、带取代链的知识条目状态机（政策改版时旧口径自动降权而不删除）、以及 AHT 口径下的效率论证方法（12 min → 0.2 min 量级的差距在内容审核运营中同样成立）。
- **上游关联**：ARIA 冻结底座、只演化外部知识库，意味着同一框架可套在多模态底座上做音视频内容的合规判定口径更新，无需重训多模态编码器或 LLM；TikTok Pay 与 TikTok 音视频平台同属字节风控合规体系，其部署经验（专家接入方式、预算设定）对同生态的多模态审核有直接参考价值。
- **局限对齐**：论文自认自对话+语义检索+冲突消解的开销在高吞吐实时场景待优化——对实时流式音视频审核，落地顺序应是异步/离线审核位与复审队列，或压缩反思问题数与比较调用；专家可用性假设在审核洪峰（热点突发事件）下也需弹性专家池设计。

论文自述局限还包括：KR 规模增大后细微/上下文相关冲突的整合难度与长期连贯性；仅在结构化领域（CDD、法律文本）验证，常识推理、创作、物理交互等域的反思问题与查询类型需重设计；CUAD 用 LLM 模拟专家，可能未覆盖真实人机协作中的噪声、偏差与错误。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326，When Should Agents Remember? Falsification-Gated Self-Evolution）**：同属“记忆写入前设闸”路线。ARIA 用语义检索+LLM 比较+人工澄清对 KR 写入与旧条目状态迁移把关，PotentiallyOutdated 本质是“待验证假设”中间态；FGSE 把经验教训当作可证伪假设、经三类探针验证后才入记忆。关联依据是二者共享“更新安全性”问题；互补点在于 ARIA 的冲突判定是启发式 LLM 比较，FGSE 的系统化证伪流程可充当其 KR 更新的质量闸。
- **TRUST（arXiv:2611.10787，Trustworthy Recursive Self-Improvement with Statistical Guarantees）**：直击 ARIA 自认软肋——专家反馈可能延迟/不一致/出错，LLM 冲突判定无保证。TRUST 的在线多重假设检验可为 ARIA 的知识断言写入提供错误进化率的统计控制：ARIA 是机制层（怎么整合），TRUST 是保证层（整合多可信），二者可叠加。
- **SkillDuet（arXiv:2611.12109）**：同为“外部库演化”式自改进（技能库 vs 知识库），差异在反馈源与更新位置——SkillDuet 以响应反馈耦合 LLM 参数更新，ARIA 以真人专家反馈完全冻结参数。ARIA 的结果（Qwen2.5-7B 借纯符号层更新反超 GPT-4o 自改进基线）为“不动权重、只动外部库”路线提供了合规场景的正面证据。
- **WeightLoop（arXiv:2611.07319）**：适应位置对偶——有界权重编辑 vs 符号空间 KR 更新，均免重训、支持反复自改进。取舍明确：WeightLoop 行为级全局生效但不可逐条审计，ARIA 逐条可回滚但仅通过检索影响上下文。
- **LongCapHarness（arXiv:2611.10463）**：同为免后训练/免数据合成的测试期挂接式增强，但方向相反——LongCapHarness 挂接模型内部的长上下文底层能力（HELMET/RULER 口径超越基线且成本低于其 50%），ARIA 挂接外部演化的领域知识并引入真人闭环；前者挖内潜能、后者补外知识，在“预算受限的测试期增强”命题下互补。
- **InfraRSI（arXiv:2611.11558）**：结构同源——把开放式输入经分阶段验证转化为可执行变更；其五阶段验证工作流是 ARIA“专家裁决”环节的自动化对应物。二者优化的成本维度不同：InfraRSI 压机器调用成本（最高 2.75× 加速），ARIA 显式为人类注意力定价（预算 B 与 AHT）。
- **对照参照**：AutoTavern（arXiv:2610.33845）与 RSI-PDEbench（arXiv:2611.14949）分别代表无人类 oracle 的自主改进与标准化评测两端——前者以环境回报替代人工裁决，误差校正来源与 ARIA 根本不同；后者则凸显 ARIA 这类 HITL 框架目前尚缺可复用的公开基准（其 CUAD 流程为自建且 oracle 为模拟），是后续工作的明显缺口。
