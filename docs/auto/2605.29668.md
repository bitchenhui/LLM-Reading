# GRASP: Gated Regression-Aware Skill Proposer for Self-Improving LLM Agents

> Johannes Moll, Jean-Philippe Corbeil, Jiazhen Pan, Martin Hadamitzky, Daniel Rueckert, Lisa Adams, Keno Bressem. *arXiv:2605.29668v3 (2026-05-28)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

本文属于 LLM 智能体自改进方向（非本引擎核心大类），按该领域自身标准评估：核心问题是结构化环境（EHR/FHIR、数据库、Web 接口）中的智能体可靠性。此类环境中智能体的失败是操作性的而非对话性的——检索错资源、漏掉时间资格条件、重复下单、写后不验证——且失败反映环境结构而非个案，因此可靠性取决于对特定环境的程序性知识，而非通用语言能力。

既有自改进方法（Reflexion 式逐条反思、ExpeL 式跨轨迹规则抽取）的共同缺陷是：每条自然语言指导一经生成就立即写入记忆，从不校验新条目是否保住了原本正确的轨迹——修好一条轨迹的笔记可能让另一条悄然回归。同时单调累积会稀释任务相关内容、污染上下文（文中引用 irrelevant-context 与 lost-in-the-middle 的已知结论）。作者由此推出两个必要条件：对每个候选更新做 held-out 校验（含对既有正确行为的保护），以及一个支持修改与删除、容量有界的库，而非只增不减的记忆。

定位上，GRASP 借用 prompt 优化（DSPy 系）的 held-out 验证思想，但作用对象不同：不是扁平 prompt，而是带 ADD/MODIFY/REMOVE 三类编辑算子的结构化技能库，且接受准则显式约束回归上界——相当于把持续学习中的灾难性遗忘问题移到 prompt 层（作者表述：prompt 智能体经由稀释而非参数漂移遗忘）。需注意其评测口径：基准打的是对 FHIR 状态的程序性可靠度，不是临床正确性或患者结局，这一限定贯穿全文。

## 2. 方法总览

GRASP 不更新参数，把自改进建模为“对一个有界技能库的已验证编辑序列”。技能是注入推理上下文的结构化行为指令，Markdown 文档加 YAML frontmatter（name/description/tags/version/provenance，provenance 记录触发它的失败模式、接受时的 probe 分数、替换了哪条旧技能），正文分 Trigger / Rule / Verification / Example 四节，天然可审计、可回滚。库从空开始，容量上界 10，训练结束平均约 5 条技能、5.6k tokens。

每个 dev 批次（B=48 episode）的更新环： 运行智能体、记录逐条正误； LLM 分类器给失败轨迹打“机制特定”的开放词表标签并分组； 技能写作模型按组从大到小轮转，产出至多 K=4 个候选编辑（ADD/MODIFY/REMOVE；库满时 ADD 被阻断，除非配对一个 REMOVE 腾位）； 构造平衡探针（N=36，18 条先前失败 + 18 条先前通过，取自本 epoch 更早完成的 episode、按任务类型分层，相对产出候选的批次永远出样）； 先用当前库 S 重跑探针得到新鲜因果基线 F0/R0（因探针标签反映的是旧库状态），基线运行中环境侧出错的样本 E0 剔除； 在 S 的 fork 上逐一评候选，接受准则为净改进 (F(c)−F0)−(R(c)−R0)>0 且硬回归预算 R(c)≤R0（未加权计数）；若胜者仍有回归则触发对比修订（收窄触发条件/加 guard），仅当修订分严格更高且仍满足预算才替换； 中选编辑提交为新版本库，否则库不变。

成本画像：每批次 6 次写作调用 + 411 次探针调用（N=36 × (1+候选均值 3.68) × 每 episode 2.44 次 LLM 调用），总计 534 次，约为最简记忆基线（145 次）的 3.7 倍——验证环节主导训练开销；推理侧反转：注入 5.6k tokens，而无界记忆基线达 34–53k，仅 GRASP 与 ExpeL（1.2k）低于 10k。作者明确警示"无参数更新"不等于"无成本"，成本只是从梯度换成了推理。

## 3. 关键设计

**机制特定的失败分类。** 开放词表标签须满足“两个标签蕴含两个不同纠正动作”的约束：漏掉日期过滤标 `date_filter_omitted` 而非 `wrong_answer`，因为前者指向可写技能、后者不指向。历史标签作为候选优先复用，无匹配才铸造新标签；分组无最小规模门槛。附录给出词汇动力学：首批即出现 11.6–13 个标签，训练中边际新增降至每批 1–2 个，batch 9 时累计 22.2（MAB）/30.6（v2）；轨迹级标签复用率从 batch 1 的 63.9% 升至 batch 7 的 97.5%——词表收敛、失败机制复现，这是技能写作器需要的性质。

**分组比较式提案。** 每次写作调用注入：单组失败轨迹、通过轨迹样本、带出处与效果统计的活跃技能摘要、其他活跃失败模式的标签（用于抑制对无关任务的回归）。比较式选择被消融证明关键：K=1 时门退化为二元接受/拒绝，测试精度跌至 73.4（±23.1）；K=8 则因固定探针预算被稀释降至 84.4，故默认 K=4。

**新鲜因果基线。** 探针标签是旧库状态下记录的，直接对比会引入库漂移混杂，因此先重跑 S 得 F0（旧失败现通过数）与 R0（旧通过现失败数）再评候选；E0 剔除避免把环境侧错误计入候选账。

**接受门与硬回归预算。** 净改进条件保证期望收益，R(c)≤R0 把“新回归”设为硬约束而非标量权衡中的软项——这是与 ExpeL 式按累计操作数排序的根本区别。无效动作回归（畸形工具调用、解析失败）在分数中按 λ=2 加权（接口级失败一票否决整个 episode，且迁移时单次被拒调用即终止轨迹），预算保持未加权以维持可解释性；λ∈{1,2,4} 结果不敏感。

**门的选择性。** 5 个种子下，64% 的批次实际应用编辑、36% 全拒；全部候选中仅 16% 被接受，平均每批 1.3/4 个通过预算；被接受者的分数中位数高出阈值 3 例、均值 4 例（长尾 15），在 18 个正例的探针上远高于 1 例的判定底线——这解释了 N 从 36 提到 72 无增益（附录 E.3）。

**注入协议受控。** 所有方法的习得内容注入同一 `behavior_skills` 字段（首个决策轮），隔离位置效应；GRASP 库在 episode 内固定不重注入，而记忆类方法逐查询刷新——剩余差异（内容与更新规则）恰是实验要检验的变量，且注入量上 GRASP 反而少 6–9 倍，增益不可能来自多注文本。

## 4. 实验结果

设置：3 个 FHIR 临床基准（MedAgentBench/MAB、MAB-v2、FHIR-AgentBench）+ 4 个 AgentBench 环境；MAB 为 10 类任务、300 样本、活体 Docker FHIR 服务、对答案与 FHIR 状态精确匹配，OOD 为留出任务类型（MAB 留 6、7；v2 留 5、7）；切分 dev 96 / val 80 / test 64 / OOD 60。5 个底座（gpt-oss-120b、DeepSeek V4 Flash 自托管；Gemini 3.1 Flash Lite、GPT-5.4 low、GPT-4.1 走 API），agent 温度 0.0、写作器 0.7。开源模型 5 种子、闭源 3 种子；5 epochs、B=48，按 val 最优存档。

**主结果（MAB，Test / OOD，%）：**

| 底座 | 无技能 | 最强基线 | GRASP | Test 增益 |
|---|---|---|---|---|
| gpt-oss-120b | 40.6 / 8.7 | Evo-MedAgent 67.8 / 31.3 | **88.8 / 56.3** | +48.2 |
| DeepSeek V4 Flash | 47.7 / 3.1 | SkillX 55.9（OOD 最强 Evo 20.0） | **70.0 / 52.3** | +22.3 |
| Gemini 3.1 Flash Lite | 54.2 / 18.1 | Evo 55.2 / SkillX 38.3 | **71.4 / 41.7** | +17.2 |
| GPT-4.1 | 45.5 / 0.3 | Batch 47.4 / 2.2 | **84.9 / 27.2** | +39.4 |
| GPT-5.4 (low) | 45.1 / 1.7 | Seq 47.4 / 16.7 | **85.4 / 80.6** | +40.3 |

GRASP 在全部 5 个底座、域内与 OOD 均列第一（MAB 上）；对最强基线的领先在 gpt-oss 上为 21.0 分（Δ=+21.0，95% CI [10.3, 33.8]，p=0.008，d=1.94）。OOD 领先在 gpt-oss 上 +25.0（CI [3.7, 44.0]；Evo 种子方差 21.7 拉宽置换检验零假设至 p=0.087）。学习动态上 GRASP 近单调提升、epoch 3 起稳在 85% 以上；Seq/Batch 记忆随累积反而跌破无技能基线（Batch 34.4 vs 40.6），Evo 相邻检查点震荡超 20 分、种子标准差 14.1 对 GRASP 的 5.8。

**MAB-v2 上结论有节制。** 域内 GRASP 在 3/5 底座领先（gpt-oss 61.1→76.9，对最强基线 ExpeL 67.8 领先 9.1，p=0.008；DeepSeek 30.9 vs 25.3；Gemini 67.2 vs 65.1）；GPT-4.1/GPT-5.4 上与最强基线在噪声内——主导失败是两个分页搜索任务类型上耗尽 8 动作预算（GPT-5.4 约 37–40% 尝试触顶），任何方法都未能缓解。v2 OOD 上 GRASP 86.0 对 SkillX 87.1，标准差重叠，作者明示不作优越性声明。

**交叉模型迁移（MAB，冻结库直接换执行器）：** GPT-5.4 写的库应用到 gpt-oss：OOD 77.8 对自训 56.3（+21.5），域内代价 88.8→76.0（−12.8）；应用到 Gemini：OOD 41.7→71.1（+29.4）、域内 71.4→76.6（+5.2）。方向不对称：弱写者库配强执行器一律差于自训。该不对称性为 GRASP 独有——同一跨写者协议跑全部 5 个基线无一复现，基线迁移库 OOD 最高仅 35.0（SkillX→Gemini）。

**跨基准迁移（gpt-oss）：** MAB↔v2 双向正迁移（MAB 库在 v2 上 78.1/86.7，反超 v2 自训 76.9/86.0；v2 库在 MAB 上 51.6 对基线 40.6，OOD 34.4 对 8.7 但 ±22.8）。FHIR-AgentBench 自训 51.5→58.2（Δ+6.8，CI [3.7, 10.0]，p=0.008），而一切外来库均使其退化（47.2/45.7/48.3）——归因于接口失配：库绑定 REST/FHIR 工具调用约定，遇 FHIR-AB 的 Python 工具 + 自由文本接口即发出畸形调用。DBBench 非临床对照迁移为负或中性。

**非临床环境（gpt-oss，3 种子）：** ALFWorld 23.3→51.7（+28.4）、WebShop 20.7→41.3（+20.6）、DBBench 65.6→70.6（+5.0）、OS Interaction 48.6→49.5（+0.9，噪声内）。边界清晰：任务复现且结构可验证处有效，动作空间开放处失效。

## 5. 消融要点

**组件消融（MAB，gpt-oss，3 种子，Test）：**

| 变体 | Test | 相对全法 |
|---|---|---|
| GRASP 全法 | 88.8 ±5.8 | — |
| 去失败分组 | 84.4 ±3.1 | −4.4 |
| 去回归预算 | 81.8 ±1.8 | −7.0 |
| 仅修复集选择（不含通过例） | 80.2 ±13.7 | −8.6（最不稳） |
| 仅 ADD | 80.2 ±9.4 | −8.6 |
| 去接受门 K=4 | 63.5 ±3.9 | −25.3 |
| 去接受门 K=1 | 40.1 ±11.3 | −48.7（≈无技能 40.6） |
| 等算力（跑满探针、弃用其判定，按写者偏好/随机选） | 70.8 / 67.2 | −18.0 / −21.6 |

三条主结论：其一，保住门的任何单组件移除都仍 >80，高于表 1 所有对照——门是承重墙；去掉门，K=1 时技能写作管线与不用技能等价，“写作本身”不贡献任何差距。其二，等算力变体花掉全额探针预算却丢弃判定，精度落回无门水平——计算量不能替代判定结果。其三，把同一门授予全部 5 个基线（5 种子）：K=1 下各基线域内 +1.6~+15.0，OOD 均值变化 −0.1、无一超种子噪声，而 GRASP 在同门下 +33.3/+23.7；K=4 完整配置下无基线超过 62.2 Test / 26.1 OOD。共享 GRASP 节奏/门/探针/注入字段的 Batch 记忆以略高探针开销（439 对 411 次调用）仅得 62.2/22.0，逐 episode 方法更花掉 29×/51× 探针调用——收益被定位到“门 × 有界可编辑库”这个组合，而非 held-out 验证本身或验证算力。

超参敏感性：B∈{24,48,96} 变动 ≤2.1 分；N 地板在 16（82.3）、36 饱和、72 无增益；λ∈{1,2,4} 带 83.9–88.8 内重叠；唯 K 敏感（如上）。

** Ground-truth 审计：** 106 个习得库全查，held-out 切分的任何真值未出现在任何库的承重节（Trigger/Rule/Verification）；30 个 episode 特定值全部为 dev 切分来源（时间戳与单个 MRN）且都处于示例/对比演示上下文；与隐藏切分仅有的碰撞是 4 个低熵领域常量（钙单位换算系数、钾参考区间）。典型技能如 `iso8601_datetime_with_timezone`、`require_fhir_query_before_answer` 编码的是环境 I/O 契约事实；且 GRASP 最大优势恰在记忆无法触达的 OOD 任务类型（gpt-oss +25.0；GPT-5.4 上 80.6 对 16.7），排除了背答案解释。

## 6. 贡献与启示

**方法学贡献：** (1) 把智能体自改进从“单调累积指导”重构为“对有界库的门控编辑”，并指出静默回归是言语反馈类方法的共性失败模式；(2) 因果定位干净——增益归因于接受门作用于有界可编辑库，而非技能写作（无门=无技能）、非验证算力（等算力消融）、非 held-out 验证本身（门授予基线只买域内拟合、不买泛化）；(3) 迁移证据支撑“技能编码环境程序性知识而非模型特定模式或通用领域能力”：强写者→弱执行者的单向蒸馏式增益为 GRASP 独有，跨基准迁移被工具调用约定而非领域划定边界；(4) 适用边界明确：复现任务 + 可验证信号处有效，开放动作空间处平坦，资源上限（动作预算）是另一类任何适配都无法修复的边界；(5) 工程性质好：注入量少 6–9 倍且不随训练长度增长、技能带版本与出处可审计、单条行为可回滚无需重训。

**对本领域（音视频工程侧）的迁移含义（笔记作者引申，非论文主张）：** GRASP 的门本质上是把回归测试抬升为自改进循环的准入判据，这与音视频基础设施里跑一致性/浸泡测试的工程直觉同构。AV 工具链智能体（转码农场调度、MAM/DAM API 操作、打包/origin 配置、广告插入、编解码参数检索）恰好命中其适用判据：任务复现、失败可机制化（像素格式失配、时间戳不连续、GOP/关键帧对齐错误、HDR 元数据丢失）、结果可硬验证（ffprobe 探测流、退出码、一致性检查器判定、checksum）。其结论对这类系统的直接教益有三：无界记忆劣于无记忆（Batch 34.4 对 40.6），长时程媒体运维智能体必须做有界注入；技能绑定工具调用约定而非领域，跨 SDK/CLI 方言（不同厂商转码 API 方言、不同 API 版本）复用技能库前须先做接口归一；探针成本主导（411/534 次调用每批），在 episode 昂贵的实时流场景须压缩探针规模——论文自己给出 N=16 的地板（82.3）作为代价参考。

**局限（论文自陈）：** 基准度量的是对 FHIR 状态的程序可靠度，技能是面向基准的策略而非医学专业知识，临床落地需逐条技能的临床审查、前瞻对照与在线监控；仅英文 FHIR 数据；门控基线与跨写者实验只在 MAB + gpt-oss-120b 上做过，未扩展到其他基准与底座；迁移不对称意味着冻结库并非完全模型无关，写者选择无自动判据，只能“用最强可用”。

## 7. 与其他论文的联系

- **FGSE（arxiv:2611.14326）**：方法学上最近的同类——两者都拒绝“生成即写入”，把记忆/技能更新条件化于可证伪探针：FGSE 将经验教训作为可证伪假设经三类探针验证后写入记忆，GRASP 用平衡探针（旧失败+旧通过）加硬回归预算做同类准入。二者独立收敛于“先证伪后写入”，互为该设计判据有效性的佐证。
- **TRUST（arxiv:2611.10787）**：为 GRASP 的门补上它没有的东西——统计保证。GRASP 的逐编辑判定建立在 N=36 的小探针上（16% 候选接受率、无显式错误演化率控制），TRUST 用在线多重假设检验控制递归自改进的错误进化率，是 GRASP 接受准则的天然形式化升级方向。
- **SkillDuet（arxiv:2611.12109）**：共享外部技能库基底（Voyager/SkillX 谱系），但以响应反馈把库演化与 LLM 参数更新耦合；GRASP 是“零参数、门控”的反事实对照——其消融证明纯技能写作等于无技能、门才是活性成分，为任何参数耦合的技能演化方法设定了必须超越的基线。
- **CompoundingKernel（arxiv:2611.19230）与 RSI-PDEbench（arxiv:2611.14949）**：二者领域（GPU 内核编译执行、PDE 求解通过率）满足 GRASP 自陈的适用判据——任务复现、结构可验证；GRASP 的边界分析预测门控技能编辑可与此类递归自改进循环叠加，其探针/回归预算设计正对应此类循环在多轮累积记忆/规则时面临的回归风险。
- **InfraRSI（arxiv:2611.11558）与 TrainExplorer（arxiv:2611.20430）**：同为结构化环境自改进；InfraRSI 的五阶段验证工作流是同一回归安全本能在工作流粒度的体现；TrainExplorer 走参数级后训练，而 GRASP 刻意停留在上下文级——GRASP 的成本核算（成本从梯度转移到推理、每批 411 次探针调用）标出了两种基底之间的代价轴。
- **LongCapHarness（arxiv:2611.10463）**：同属免后训练、经上下文注入获得增益的路线；GRASP 的有界注入结果（5.6k tokens 胜过 34–53k 无界记忆）为同一设计方向提供了反向证据——改进来自注入什么与如何筛选，而非注入更多。
