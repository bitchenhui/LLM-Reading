# AutoDataBench: Can Agents Write the Data That Feeds the Self-Improvement Loop?

## 1. 背景与动机

论文的出发点是一个产业事实与评估范式之间的错位。语言模型近年的能力增益更多来自数据而非架构；对 agentic 训练而言，数据的单元不是文本对，而是一个可执行任务——它需要环境、一个判定工作是否完成的 verifier、以及与被训模型能力相匹配的难度。这类任务的生产目前仍依赖专家，要么直接写任务，要么构建并维护生成管线，两种模式下都必须由人定义“正确结果长什么样”。这限制了训练数据的产量，且每个新域都要重新配备专家。自动化任务创建因此具有双重价值：让数据产量随算力而非专家人数扩展，同时构成递归自我改进（RSI）的关键一环——模型为自己后继者的训练撰写数据。

作者指出的核心测量缺口在于：现有对“智能体写任务能力”的评估，全部通过“用其产出训练后模型提升了多少”来间接度量，而数据产业的实际运作是逐样本交付、逐样本按验收标准判收或退回，任何训练运行发生之前就完成裁决。两种度量单位不兼容：数据按单样本计价交付，训练则整批消费、只返回一个批级分数，该分数无法归因到任何单样本的贡献。因此每个样本必须在训练前按三类要求单独裁决：其一可用性（在套件自有格式内可运行、verifier 能拒绝错误答案、是真正的新问题而非复述）；其二难度落在目标模型的“有时能解”区间（永远解不出与永远解出都被丢弃）；其三行为覆盖（新任务必须能激发与原任务相同的行为模式，mode 定义在套件层级而非任务层级）。

作者逐项排查了既有工作：AutoBencher、BenchAgents 面向评估项构造，难度被最大化而非落入区间；InnovatorBench、PostTrainBench 交付的是研究产物或训练后 checkpoint；RSIBench-Data 最接近，但智能体附带提交训练配置、监督内容由固定外部 rollout 模型生成，checkpoint 分数无法隔离智能体的写数据能力。闭环研究（Absolute Zero 等）仅覆盖数学与逻辑推理，且报告的是下游增益。据此论文把评估对象收敛为一个此前无人测量的量：单个合成任务，在训练前、以其自身为单位，是否可用、难度是否落带、是否命中被委托针对的 modes。

从音视频技术交叉的视角看，这一范式与音视频工程数据的形态高度契合：转写任务的 WER、编码任务的客观质量指标、实时性任务的延迟与丢帧判定，天然构成“可执行、机器可裁”的 verifier，正是该基准要求的任务形态；论文选用的 Terminal-Bench 子集中也确实包含一个媒体域任务（satb-audio-transcription，见第 4 节）。这使该基准的结论对音视频 agentic 数据生产具有直接可迁移的参考价值。

## 2. 方法总览

AutoDataBench 的评估单元是 episode。一个 episode 中，被评估的 author agent 接收一个公开套件中的原任务（seed）以及目标模型尝试该任务的脱敏记录，必须为同一套件撰写一个新任务。整体流水线由四个角色构成，其中只有 author agent 变动，是测量对象；其余角色全部固定以保证分数可比。

**角色设置。** 目标模型全程为 deepseek-v4-pro，作为被改进对象，其行为是训练数据必须瞄准的靶。在任何 episode 运行前，目标模型对 24 个原任务各独立闭卷尝试 K=6 次，共 144 条 transcript（每条附带 verifier 输出），是后续所有环节的证据底座。Analyst 固定为 claude-opus-5（40 分钟预算，与 author agent 同一 agent 框架运行，与目标模型不同家族），读取目标模型在某原任务上的 transcripts，写出隐藏 rubric——一份 3–5 条 modes 的清单，author agent 永远看不到。Judge 同样是 claude-opus-5，在目标模型对新任务尝试完毕后运行：gate 依据交付物本体裁决，mode 覆盖则依据目标模型在新任务上实际做了什么裁决。

**流程。** Episode 把原任务、套件子集与行为记录渲染进容器，author agent 在固定 wall-clock 预算（默认 45 分钟）内工作，留下一个任务目录。随后目标模型以新任务自带的 verifier 尝试 K=6 次；judge 最后运行，因为它的主要证据是这些新 transcripts——覆盖是从交付任务让目标模型做了什么来判，不是从任务文本读起来像什么来判。

**评分。** Episode 分数为三项之积：

score = gate × difficulty × quality

gate 与 difficulty 是二值项，采用乘法而非加法，因为一个泄露答案的任务和一个目标模型必解的任务无论 quality 多高都不可用。三项分别对应引言的三条验收要求。所有 agent 为同一目标模型、同一批 rubrics 写作，分数差异即作者能力差异。

**任务面。** 基准实例化在三个套件、各手工挑选 8 个任务共 24 个：Terminal-Bench 4.0（终端工作与软件工程，commit 624df06）、Terminal-Bench-Science（科学计算，commit c5e5036）、AutomationBench（跨应用商务工作流自动化，commit c5e5036）。三者以相同的原生目录布局描述任务，交付任务必须遵循。选择时剔除无法在主机构建运行的任务（仅发布 x86-64 镜像、无 aarch64 wheel、GPU 需求、测试数据未提交上游），并记录配置与 commit 以便精确复现。Terminal-Bench 的 8 个任务按其自带 domain 标签分布，其中包括媒体域的 satb-audio-transcription——这是该基准与音视频处理唯一直接相接的触点。

**实验设置。** 评估五个前沿 agent 作为 author：kimi-k3、gpt-5.6-sol、qwen3.8-max、glm-5.3、deepseek-v4-pro。每个原任务在默认预算下撰写两次，所有数字为两 episode 均值。deepseek-v4-pro 同时是目标模型，该行是唯一“为自己写数据”的设置。

## 3. 关键设计

### 3.1 Gate：八种取消资格的缺陷与 surface-swap 的机械化

Gate 在八种缺陷任一存在时归零，覆盖三类：artifact 本体（verifier 从不检查结果、不做任务即可得到答案、任务不可解、交付不恰好是一个任务）、来源（抄袭、调用了未被允许的模型）、与其他任务的关系（原任务表面换皮、同次运行内重复）。每条被触发的缺陷必须对应文件与行号或字段给出证据，证据不足不触发——因为误报会丢弃 agent 的工作，且下游无法察觉该方向的偏差。

surface-swap 是整个基准的支点：既然每个原任务只要求一个新任务，克隆就是最显然的捷径。该缺陷禁止“同一问题换个数值与名称重述”，但明确允许留在原问题族内、围绕同一决策构造——因为瞄准一个 mode 本就意味着复用决策结构。判定的机械化部分：harness 对两份 instruction 做词级 diff（记录按序共享词比例与所有差异 span）并作为事实挂载；若每个差异 span 都是重命名，缺陷仅凭此即触发；交付的 verifier 仅改名字与 docstring、或参考解与原任务字节一致，同样独立触发。超出这两类条件后由 judge 实质裁决，问题是“原任务的求解者是否仍无任何新东西可推导”。校准记录给 judge 提供两端锚例：十个 span 全为名词替换→触发；三十六个 span 删除浏览器运行时、去掉确定性时间戳、加入身份去重→不触发。这一机械化测试的由来是早期运行中较软的措辞被推理绕过——被判“同族但实质不同”的交付中，事后独立测量发现八个里有六个与原 instruction 按序共享 74%–94% 的词。基准自带的共享脚手架文件（跨任务字节一致）与仅“名字相似”不计入判断。

### 3.2 Difficulty：纯执行判定的通过率带

难度项完全无模型参与：目标模型以交付任务自带 verifier 尝试 K=6 次，观测通过率落在区间 [0.125, 0.75] 内即得 1，否则 0。按 K=6 换算即至少解出 1 次、至多 4 次。带外交付无论其余多好都不可用作训练数据——必解的任务教不会模型任何东西，必败的任务对“该修什么”不提供任何信息。这项设计是基准“无训练 run”属性的关键支撑：难度不需要训练来暴露，只需要目标模型在该任务上的实证通过率。

### 3.3 Quality：隐藏 rubric 与部分覆盖满分

Quality 是对 author agent 不可见的 rubric 的覆盖率。一个 mode 命名目标模型在执行任务时表现出的一种行为，表述在套件层级，使原任务之外的任务也能激发它——例如“当两个来源冲突时，通过比较时间戳而非读取显式替代声明来决定哪个生效”是 mode；“混淆了某个豁免日期”是某一 mode 的症状；“犯了推理错误”则因过于笼统而无法据以构造任务。检验标准是：一个从未见过原任务的读者能否刻意构造出一个不同的任务激发它。Modes 来自三类证据：直接导致尝试失败的 outright failure、走错后恢复的 detour、以及每次都处理正确但存在诱人错误替代路径（该替代会失败 verifier）的 error-prone point。第三类要求最严：所有尝试都做同样事情的位置不是 error-prone，只是任务本身；analyst 必须具体指出诱人替代路径并说明它会挂掉哪条 verifier 检查。Harness 故障与原任务自身的缺陷记入独立字段、永不成为 mode。24 个任务共产生 125 条 modes（均值 5.2/任务；20 个任务 5 条，4/6/7/8 条各一任务），分布为 86 失败、20 绕行、19 处理点。

Judge 对每条 mode 回答“交付任务是否让目标模型处于该 mode 描述的决策点”，回答 present 必须引用一次尝试、一个步骤与一段逐字引文；无法举证即 absent。因与任务设计无关的原因不可能出现的 mode 判为 unreachable，从分子分母同时剔除。最终计算：

quality = min(1, modes_covered / ⌈aN⌉), a = 0.6

即五条 mode 的 rubric 覆盖三条即满分（a=1 退化为原始比例）。不要求全覆盖的理由是结构性的：一个新任务若能搬演原任务的每一条 mode，它必然就是原任务——早期运行中每个达到全覆盖的 episode 同时被 gate 判为克隆。Judge 从不知道 a，逐 mode 作答，算术留给 harness。

### 3.4 Author agent 的权限与工具面

Author agent 在容器内拥有 shell、自己的容器运行时与预算告知，其余不受数据工程师会受的约束：可经搜索工具读 web、可直接驱动任务 runner、可调用目标模型来探测其对草稿问题的推理。两条最关键的命令：其一将候选任务跑过自带的参考解与 verifier，不调任何模型、零成本，用于确认可解性与 verifier 接受预期答案；其二将候选任务按官方测量方式对目标模型运行——这是交付前获知通过率落点的唯一途径，其 transcript 与 reward 同等有价值。唯一全局限制：目标模型是唯一允许调用的模型（任何途径），路径上的 runner 拒绝其他模型，所有调用与搜索留痕供 judge 判来源缺陷。Agent 被明确告知通过率要求（K 次中解出几次的形式）与评判导向，但从不看 rubric，也只拿到当前任务的六条 transcripts。

### 3.5 聚合与不可评分 episode

同一原任务的 episode 先平均，任务均值再平均为套件分，避免重复数多的任务权重偏大。无 quality 信号的 episode（rubric 为空、或全部 mode 判 unreachable）从均值中排除并单独计数而非记零——零是交付挣来的分数，排除是关于运行而非交付的事实。Judge verdict 先经 schema 验证（每 mode 一个覆盖条目、gate 条目携带缺陷名而非编号、每项数值分数），不匹配则该 episode 重判；这是为了杜绝静默回退——早期一个 verdict 因键名不同被记为零质量，而 judge 实际标了每条 mode present。

## 4. 实验结果

主结果（每原任务两次撰写、取均值，48 episodes/agent）如下：

| author agent | In band | Gate passed \| in band | Quality | Score |
|---|---|---|---|---|
| kimi-k3 | 21.3% | 90.0% | 0.967 | **0.184** |
| gpt-5.6-sol | 21.3% | 100.0% | 0.833 | 0.177 |
| qwen3.8-max | 14.6% | 100.0% | 0.952 | 0.139 |
| glm-5.3 | 21.7% | 90.0% | 0.700 | 0.130 |
| deepseek-v4-pro | 25.0% | 41.7% | 0.931 | 0.097 |

在 quality 被咨询之前，难度项已淘汰 75%–85% 的交付；没有 agent 达到 0.20/1.0。

**Finding 1：约束瓶颈是难度校准而非 mode 覆盖。** In band 比例区间 14.6%–25.0%；幸存交付的 rubric 覆盖率达 0.700–0.967。各 agent 能读行为记录并瞄准它，但不能把任务放在目标模型“有时能解”的位置上。这与作者预期的失败模式相反。对撰写轨迹的人工阅读给出同向证据：跨五个 agent 复现的十四种行为中八种关乎通过率，仅一种关乎 rubric 覆盖。

**Finding 2：两类失败方式彼此独立，且各有一个 agent 体现。** qwen3.8-max 落带最少（14.6%）但落带者 7/7 全部干净过 gate、quality 0.952；deepseek-v4-pro 落带率最高（25.0%）但 12 个落带交付仅 5 个过 gate——把任务放在原任务通过率附近的最廉价方式就是贴近原任务，gate 正是为捕获这一点而设。其幸存交付 quality 达 0.931，损失不在瞄准而在克隆。

**Finding 3：排名跨域不稳定。** 分套件分数（同一套 48-episode 口径）：

| suite | kimi-k3 | gpt-5.6-sol | qwen3.8-max | glm-5.3 | deepseek-v4-pro |
|---|---|---|---|---|---|
| AutomationBench | 0.312 | 0.125 | 0.000 | 0.250 | 0.125 |
| Terminal-Bench 4.0 | 0.062 | 0.133 | 0.188 | 0.133 | 0.062 |
| Terminal-Bench-Science | 0.178 | 0.271 | 0.229 | 0.000 | 0.104 |

没有任何 agent 在超过一个套件上领先；qwen3.8-max 在 AutomationBench 上全军覆没（无一落带）却是 Terminal-Bench 第一；glm-5.3 在前两个套件进前二、在 Science 上因唯一落带交付 rubric 覆盖为零而得零分。工程含义直接：用 agent 写训练数据时不存在可全局标准化的“最佳作者”，应按域选型。需注意每套件仅 8 任务，套件内数字应视为对该固定子集的估计。

**时间预算扩展。** 对 kimi-k3 将预算从 45 分钟提至 180 分钟（其余全部固定），总分从 0.184 升至 0.541（2.9 倍），三个套件同向：AutomationBench 0.31→0.56、Terminal-Bench 0.06→0.44、Terminal-Bench-Science 0.18→0.62。起步最差的 Terminal-Bench 增益最大。落带交付的 gate 通过率从 90% 升至 100%——延长预算不是靠复述原任务挤进带内。作者定位：额外预算买到的是难度校准，这恰是 author agent 唯一无法靠推理获得的一项——获知草稿通过率的唯一途径就是运行目标模型再调整。180 分钟档同时使用了最大推理努力度，两变量耦合，论文明确将该对比读作方向性结论而非倍数测量（见第 5 节）。

**经济学。** 每可用（落带且未 gate）交付的成本（48 episodes 分母；金额为 author agent 自身 token、按 2026 年 9 月牌价，不含校准用目标模型调用、官方 K 次尝试与 judge）：

| author agent | min/episode | $/episode | min/usable | $/usable |
|---|---|---|---|---|
| deepseek-v4-pro | 42.7 | 0.50 | 410 | 4.81 |
| qwen3.8-max | 41.2 | 1.53 | 283 | 10.49 |
| kimi-k3 | 45.7 | 2.23 | 244 | 11.88 |
| glm-5.3 | 48.4 | 3.50 | 258 | 18.69 |
| gpt-5.6-sol | 42.0 | 5.77 | 202 | 27.69 |
| kimi-k3 (180 min) | 139.0 | 7.62 | 230 | 12.62 |

三个结构性观察：其一，分数序与成本序不一致——kimi-k3 与 gpt-5.6-sol 分数差 0.007 而单位成本差 2.3 倍。其二，每 episode 时长五个 agent 相互差距在 18% 以内（41.2–48.4 分钟），花费却差 11 倍；每可用交付的时长差 2 倍（202–410 分钟），且几乎全部来自存活率而非会话时长——时间花在失败尝试上，不在长会话上。其三，glm-5.3 一行经过修正：其缓存从未生效，实测花费 $746.55，表中数字按其他 agent 在同一框架下的中位命中率修正为 $168.20。deepseek-v4-pro 的 $4.81 需谨慎读：它把廉价 token 与自身高 gate 率的惩罚合并在同一分母里。180 分钟档花费 3.4 倍、可用任务约 3 倍，两项单位成本几乎不变（$11.88 vs $12.62；244 vs 230 分钟）——更大预算买到的是产量而非效率。

## 5. 消融要点

论文没有传统意义上的模块消融，其设计敏感性证据分散在正文与附录中，值得整合的四组如下。

**预算-努力度混淆。** 180 分钟档同时启用 agent 最大推理努力度，默认档全部用默认努力度，两变量一起移动，对比无法分离归因。干净的归因需要“默认预算 + 最大努力度”一臂，论文未跑；仅有的直接证据是 gpt-5.6-sol 上的一次早期努力度实验，效应与噪声同量级且不保证迁移到其他 agent。加上 180 分钟档 AutomationBench 有四次重复、按固定种子采样两次带来的少量额外方差，作者把 2.9 倍读作跨三套件一致的方向性结论。这是对自身 headline 数字的诚实降级，使用该数字时应保留此口径。

**a=0.6 的部分覆盖满分。** 该参数的经验依据是早期运行中全覆盖与克隆判定的完全重合：每个达到满覆盖的 episode 同时被 gate 为 clone。a=0.6 使得 5 条 rubric 覆盖 3 条即满分，直接塑造了“保留决策结构但不必复刻全部场景”的激励面；a=1 的纯比例会系统性地奖励靠近原任务。论文未给出 a 的扫描，这是设计参数而非测量结果。

**机械判定的校准锚例。** 指令 diff 的两个端点（10 个纯名词替换 span 触发；36 个 span 的结构性增删不触发）连同早期软措辞被绕过、事后测得 74%–94% 按序词共享的教训，构成该机械测试的校准闭环。附录 I 的接受案例进一步给出 diff 判定的实质边界：glm-5.3 的交付与原指令按序共享 62% 的词却未被 gate，因为五个差异 span 增加了待推导的工作（日期算术、两级限额覆盖、由邮箱而非表格驱动的状态变化、跨两源 netting）；而 gpt-5.6-sol 的交付仅共享 5.5%，靠保留“评估便宜、优化难、最坏情况准则、全局最优藏于局部最优之后”的难度形状达成 3/6 通过率。Gate 问的是求解者要推导什么，不是复用了多少文本。

**定性行为目录的结构性结论。** 附录 H 逐一阅读全部撰写轨迹，记录跨全部五个 agent 复现的行为十四项（目录为定性记录、不带频率）。八项关乎通过率，与主结果定位一致。框架性的两项：C1 是各 agent 分差的主要解释——贴近原任务保住 modes 可达但同时招致 surface-swap gate，拉远则连 modes 与其依赖的结构一起丢失；C2 指出逃脱该权衡的做法（保留原场景与工具、增加一个原任务缺少的约束）在数据中确实出现，但从未被任何 agent 采纳为默认策略。最锋利的单项机制是 C14：agent 加入一个区分性条件、随后出于“公平/可解性”把它写进 instruction，难度直接归零而覆盖不受影响。C5 是设计属性而非 agent 缺陷：难度校准环能否闭合由“单次目标模型尝试耗时 / 预算”之比决定——attempt 慢的套件等于向作者收取一笔其无法测量的难度税。C11/C13/C15 共同刻画时间分配失衡：行为记录阅读占满会话、校准被压缩到最后一分钟甚至任务未落盘、测量的版本不是交付的版本。C9 记录覆盖错位：agent 声称瞄准的 mode 常被判缺席，覆盖分来自它未瞄准的 modes。Gate 侧 C8（验证止于 verifier 通过，无人检查 verifier 在失败路径上是否真的打分）与 C12（重启会话从头重设计、留下首次尝试目录，是 surface-swap 之后第二大零分来源）最具工程可操作性。

## 6. 贡献与启示

**测量范式贡献。** 论文把“单个合成任务的验收”本身变成评估目标，确立四项同时成立的属性：弱点定向（瞄准被指定模型实测表现出的行为）、per-artifact verdict（分数附着于单个产物而非数据集或 checkpoint）、难度落带（在该模型上实测且必须落在区间）、无训练 run。相比 RSIBench-Data 一类以 checkpoint 分数为终点的方案，它把作者能力从训练配方与外部 rollout 模型中解耦出来。隐藏 rubric + 逐 mode 举证（attempt/步骤/逐字引文）+ 机械化 diff 事实挂载的组合，为“用 LLM judge 又防其被表面文本说服”提供了一个可复用的工程模板。

**对 agentic 数据生产的直接工程含义。** 其一，当前前沿 agent 在 45 分钟预算下能瞄准行为（覆盖近饱和）但校准不了难度（约五分之一落带），且这两种能力在乘积里几乎从不同时满足；瓶颈是“必须实测才能知道”的校准环，不是理解能力。其二，作者选型必须按域进行，全局排名在三个套件间完全翻转。其三，预算翻四倍、分数翻近三倍而单位成本不动，说明“更长思考”在当前成本结构下是划算的扩产杠杆，但不是降本杠杆。其四，按样本口径的单位成本 $4.81–$27.69、202–410 分钟，为“用 agent 生产线替代数据团队”的盈亏平衡测算提供了首批公开锚点。

**对音视频技术上下游的映射（本笔记的领域引申）。** 该基准的任务形态——指令 + 可执行环境 + 自动 verifier——与音视频工程任务天然同构：ASR/转写任务的 WER 阈值判定、编码任务对 PSNR/VMAF/码率约束的机器裁决、流媒体与实时交互任务的延迟/丢帧/同步容差检查，都是无需人类评审即可执行判定的 verifier。Terminal-Bench 子集中的 satb-audio-transcription（媒体域）说明该范式已实际触及音视频工作负载。两点迁移判断值得音视频团队预先纳入：第一，C5 揭示的结构约束在音视频侧会更尖锐——转码、渲染、长视频推理类任务的单次 rollout 时长远超文本终端任务，在同等 wall-clock 预算下难度校准环几乎无法闭合，意味着音视频 agentic 数据的自动合成需要远高于 45 分钟的预算档或异步校准基建；第二，难度带 [0.125, 0.75] 的按模型实测口径，对应音视频训练中常见的“客观指标阈值如何随被训模型能力重标定”问题，该基准的做法（以目标模型 K 次实测通过率二值化）给出了可直接照搬的判定形式。同时应指出空白：三个套件均无视频理解、多模态感知或生成式媒体任务，多模态 agentic 数据合成尚无基准覆盖，AutoDataBench 的 rubric-by-analyst + 执行判定骨架是向该方向扩展的现成起点。

**论文自认的未检验假设。** Quality 项之下整个基准悬置了一个前提未验证：锻炼到实测 mode 的任务，其训练数据是否真的修复该 mode。这需要训练 run 才能回答，而正是基准刻意绕开的东西——作者在结论中明示这一点，使用者不应把高分外推为训练收益。

## 7. 与其他论文的联系

基于相关论文清单中确有主题关联的条目：

- **The RSI Tax: When Recursive Self-Improvement Is Not Worth the Cost (arXiv:2611.13524)**：直接的互补关系。该文提出 RSI 税以核算自我改进的全部成本（发现简单有界笔记基线在精度持平时省 65.6–71.0% 总 token）；AutoDataBench 第 4 节正是对 RSI 环路中“数据撰写”这一环做的单价核算——每可用任务 $4.81–$27.69、且预算扩大四倍单位成本不变。两者共同指向同一结论的不同侧面：RSI 各环节的可行性最终由单位产出的成本决定，而非由能力上限决定。
- **LongCapHarness: Capability-Guided Auto-Harnessing for Long-Context Reasoning (arXiv:2611.10463)**：路线对照关系。LongCapHarness 走“免数据合成与后训练”的递归自我改进路线（在 HELMET/RULER 上超基线且成本低于其 50%），恰好绕开了 AutoDataBench 所测量的环节；AutoDataBench 的数据（45 分钟预算下仅约五分之一交付落带）为这类绕行路线提供了动机侧注——当数据合成环节的单位经济性尚差时，直接挂接底层能力是合理的替代路径。
- **Flex-RSI: Benchmarking Recursive Self-Improvement of Frontier Agents (arXiv:2611.08946)**：基准设计方法论上的呼应。Flex-RSI 在固定预算下评估智能体通过递归修订 harness 实现自我改进；AutoDataBench 同样以预算为核心自变量（45 分钟默认档、180 分钟扩展档），并且其最强结论正是预算敏感的——四倍预算带来 2.9 倍分数。两者共同确立了“预算内交付”而非“无约束能力”作为 RSI 评估的正确口径。
- **RSI-PDEbench (arXiv:2611.14949)**：同类环节基准化。该文把 PDE 求解这一具体能力域做成含 1001 案例、42 方程模板的基准并配套 RSI 框架；AutoDataBench 则把“写训练数据”这一 RSI 环节本身基准化。两者的共同方法论是：将 RSI 环路中某一环节抽出、固定其余变量单独测量——AutoDataBench 通过固定目标模型、rubric 与 judge 实现可比性，与 RSI-PDEbench 固定方程模板控制方差的做法同构。
- **Trustworthy Recursive Self-Improvement with Statistical Guarantees (arXiv:2611.10787)**：质量控制层面的关联。TRUST 用在线多重假设检验控制自产数据/自改进过程中的错误进化率；AutoDataBench 在评估侧对应地采用了严格的证据纪律——gate 缺陷必须落到文件行号、mode 判 present 必须附 attempt/步骤/逐字引文、机械 diff 作为事实挂载。两者分别从统计与流程证据两个角度应对同一问题：RSI 自产工件的可信裁决。
