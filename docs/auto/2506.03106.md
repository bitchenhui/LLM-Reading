## 1. 背景与动机

R1-Zero 范式确立后，以二值标量奖励（答案对/错）驱动的在线 RL（GRPO/PPO 系）成为 LLM 推理能力后训练的主流路径。其隐含假设是"试错 + 奖励"足以让策略覆盖解空间。本文第一项工作就是系统证伪这个假设，给出三条实证限制（主实验在 Qwen2.5-7B-Base / Qwen3-8B-Base / Qwen3-8B 上以 GRPO 训练，训练集取自 OpenR1-Math-220k 经 Yan et al. 2025 重组织的 46k 子集）：

1. **性能平台期与数据/算力规模无关**。Qwen2.5-7B-Base 在验证集上约 120 步达峰（约 45–46% 准确率），此后训练 prompt 从 4k 扩至 32k（8 倍）、或将训练延长至 420 步，峰值均无显著改善；Qwen3-8B 约 200 步后平台于 65–67%。
2. **自发"顿悟式"自反思对解题成功贡献甚微**。作者用 GPT-4o 作自动判官，把 RL 中涌现的六种认知行为分为规划类（子目标设定、总结化）与自反思类（验证、回溯、反向链、预期），在"仅 RL 后才解出"的问题上（Qwen2.5-7B-Base：Minerva-Math 87 题、GPQA-Diamond 37 题）归因，发现规划行为是成功主因，自反思行为在数学域几乎不贡献；Qwen3-8B 因预训练见过多样化推理演示而有一定自反思贡献，但回溯/反向链/预期仍显著偏低。即 R1 报告的 "Aha moment" 并非性能提升的主要来源。
3. **持久失败**。最优 RL 微调模型在训练集上仍有一批问题 Pass@4=0：Qwen2.5-7B-Base 29.07%、Qwen3-8B-Base 17.18%、Qwen3-8B 3.75%。

根因被归结为反馈的信息量而非优化算法本身：二值奖励下一个失败样本只能排除其自身，既不指明错在哪一步，也不说明如何改。论文用探索复杂度语言重述：长度 L、单步空间 S 的解序列，纯结果奖励下有效搜索空间是 |S|^L 量级。

自然语言反馈（NLF）本可补上这一表达力缺口，但既有用法（Refinement FT、Critique FT、CITL-FT 等）全部是离线 SFT——模仿预收集的静态批评或精炼样本，缺乏在线探索能力，也无法适应训练中遇到的特异性错误。**把批评接入在线 RL 回路**在本文之前是空白，这就是核心动机。

支撑该动机的关键实验：在持久失败子集（Pass@4=0）上注入三类批评并要求模型精炼——（i）指示性批评（仅"解法错误"，约 7 token）；（ii）带真值的指示性批评（约 15 token）；（iii）CoT 批评（GPT-4o 分步评估 + 正确性结论，约 683 token）。结果（Qwen2.5-7B-Base）：即使最贫乏的指示性批评也带来 2.09% 有效精炼率（自发反思在此子集上是 0）；CoT 批评有效精炼率达 36.47%，成功精炼 55.37% 的持久失败问题（批评本身有效生成率 60.06%）。值得注意的是，仅附真值答案（w/GT，有效精炼率 1.98%）相对纯指示性（2.09%）几乎无增益——**光给答案不给归因，指导价值有限**；逐步归因才是关键。这为"verbal credit assignment 经由 in-context learning 触达标量奖励不可达轨迹"提供了直接证据，也与 Xu et al. 2025 关于信息性语言反馈可指数级降低样本复杂度的理论相呼应。

## 2. 方法总览

Critique-GRPO 是 GRPO 的在线扩展，遵循 Dr.GRPO 的修正（去掉长度归一化 1/|y| 与奖励 std，避免偏置梯度），每个训练迭代分三步：

**Step 1 初始响应采样与双通道评估**。对每个 query 采 n 个初始响应，奖励系统同时产出标量奖励与自然语言批评。支持两类奖励系统： rule-based：答案字符串匹配（is_equivalent(y, y_GT)），并启发式构造指示性批评 cI 与带真值批评 cGT； model-based：奖励模型 πRM 生成 CoT 批评 c_CoT ~ πRM(·|I_c, q, y)，其末尾二值正确性标签反推标量奖励。训练时采用"model-based 出批评 + rule-based 出二值奖励"的组合，且**只保留与规则验证结论一致的批评，不一致则要求重新生成**（质量门控）。

**Step 2 批评引导的自精炼**。为控制算力，仅当该 query 的初始响应组内**零正确解**时才触发精炼；对每个失败响应以 (q, y, c) + 精炼指令为条件，经 in-context learning 生成精炼响应 y_refined，再由奖励系统打分。随后从精炼全集中采 k 个子集**优先保留正确解**（若无正确精炼则随机采），与初始响应混合成最终训练组。

**Step 3 在线策略优化**。目标 J = J_init + J_refi，两支均为 clipped 形式（ε-clip），关键差异在基线与比率函数：优势统一用混合组奖励均值做基线，Â = R − mean({R_init} ∪ {R_refine})，使初始与精炼响应在同一尺度上竞争；初始响应用标准重要性采样比 r_t = πθ/πold，精炼响应改用 shaping 比率 ρ_t = πθ/(πθ+γ)，γ=0.1，并去除 KL 惩罚。

方法有效性的机理论证分三层：

- **梯度可用性**：全错组原本 σR=0、无有效梯度（Proposition F.9），精炼恰好只在这些组注入新信号，算力与信号增量精准对齐。
- **轨迹质量**：把正确解出现概率从策略自身的 p* 提升到批评机制成功率 P_crit（Lemma F.10），策略改进下界 ∆J ∝ 观测到最优轨迹的概率（Theorem F.11），收敛加速因子 O(P_crit/p*)——本质是在 RL 回路里嵌入了"动态生成最优数据的 SFT"（Theorem F.12）。
- **复杂度**（Proposition 4.1，Transfer Eluder Dimension 框架，把批评形式化为 Reward-Informative Feedback）：二值奖励的 Eluder 维度约 O(|S|^L)；指示性反馈最坏情况仍为 O(|S|^L)，但起剪枝作用（把搜索约束到与批评一致的子空间）；CoT 批评若能定位首个错误步，问题分解为 L 个规模 |S| 的子问题，复杂度线性化 O(L|S|)；若再给出首错步的修正建议则降至 O(L)。在 L|S| ≪ M ≪ |S|^L 的预算区间内，成功概率 P ≈ 1−exp(−M/d) 从约 0 变为约 1。

## 3. 关键设计

**3.1 零正确解条件触发 + 批评质量门控**。精炼只作用于标准探索完全失效的组。这带来两个耦合收益：一是把昂贵的"批评生成 + ICL 精炼"算力压缩到失败组（对 Qwen3-8B 这类持久失败仅 3.75% 的高基线模型，开销天然很小）；二是避开"有正确解的组再做精炼"引入的冗余分布漂移。批评门控（批评结论必须与规则验证一致）是防止错误语言信号污染训练的第一道闸，后文对抗实验证明其必要性。

**3.2 统一基线的混合组优势**。初始与精炼共享组均值基线意味着：在高失败组中，一个正确精炼（R=1）获得显著正优势、自动成为主导梯度来源；错误精炼（R=0）与失败初始同权受罚——这正是"强化成功但陌生的精炼、惩罚错误尝试"的机制落点。

**3.3 分布漂移控制：7:1 锚定比**。精炼是带批评的条件生成，相对初始响应分布是显著 off-policy 的漂移源，全量混训会导致熵爆炸。两个手段：只采 k=1 个精炼对 n=7 个初始（公平对比下 R1-GRPO 用 8 rollouts/prompt，总样本量对齐）；正确精炼优先入选。理论依据是 anchor 条件（Theorem F.15）：对 KL 做二阶 Taylor 展开得 ≈ ½∆θᵀF∆θ，总更新是 (1−λ)g_init + λg_ref（λ=N_ref/N）；g_init 被 clip 天然有界，而 g_ref 高方差且与当前策略流形的 Fisher 结构（F 的特征向量）不对齐，λ 必须小到让 g_init 起"锚"的作用、g_ref 作为小幅扰动旋转策略而不撕裂流形。实验上在 1:1–7:1 扫描中 7:1 训练最稳，更低比例在训练后期出现熵损失激增与性能退化。

**3.4 Policy shaping：放大"低概率但正确"的修正 token**。精炼支路不用标准 IS 比率而用 ρ_t = πθ/(πθ+γ)。对 π_t 求导得 ∇ρ = Ψ(π_t)·∇log π_t，其中调制系数 Ψ(π_t) = γπ_t/(π_t+γ)²：当 π_t→1（模型已掌握的 token）时 Ψ→γ/(1+γ)²，梯度强抑制；Ψ 在 π_t = γ 处取极大——即显式把更新集中在"当前策略认为不太可能、但出现在正确精炼里"的 token 上。γ=0.1 使峰值落在 0.1 概率处，作者将其类比 Focal Loss 的 hard-negative mining，但作用于策略梯度。配合优势符号，shaping 同时实现对"陌生且正确"的强化与"陌生且错误"的强惩罚。这里还有一个常被忽视的问题被点破（Proposition F.14）：g_init 强化分布当前模式，g_ref 把概率质量搬向新模式，二者梯度内积常为负（⟨∇J_init, ∇J_refi⟩ < 0）；clipping 只限制步长不纠正方向，因此 off-policy 精炼的安全性必须靠"锚定比 + shaping"而非 clip 单独保证。

**3.5 去 KL 的取舍**。移除 KL 惩罚是为了允许策略向陌生但正确的精炼做大幅移动；在精炼质量有门控、数量有锚定的前提下，这一"松约束"在消融中带来 +1.5 个平均点（41.18→42.66，见第 5 节）。

**3.6 批评源解耦与自监督闭环**。框架对批评源不敏感（GPT-4o / Llama3.1-405B / DeepCritic-7B 均可）。两个自批评变体尤其值得注意：self-critique——策略自身参考真值答案生成 CoT 批评（外部输入仅 GT，无专家推理）；self-critique & self-evaluation——完全无参考、凭内部知识自评。后者构成零外部监督的自我改进闭环，是与递归自改进（RSI）主题对接的关键接口（见第 7 节）。

## 4. 实验结果

设置：训练仅用 4k prompt；8 项基准（ID 数学：MATH-500、Minerva-Math、OlympiadBench、AMC23、AIME24；OOD：TheoremQA、GPQA-Diamond、MMLU-Pro）；贪心解码（温度 0），pass@1 为三次运行均值；奖励二值；40×A800-80G；Critique-GRPO 为 7 rollouts + 1 精炼，R1-GRPO 为 8 rollouts（公平对齐）。

**主结果（平均 pass@1，%）**：

| 方法 | Qwen2.5-7B-Base | Qwen3-8B |
|---|---|---|
| base | 32.04 | 53.23 |
| SFT | 33.04 | 56.25 |
| RAFT | 34.27 | 54.84 |
| Refinement FT | 35.21 | 59.45 |
| Critique FT | 34.76 | 54.23 |
| CITL-FT | 35.66 | 55.84 |
| R1-GRPO | 41.18 | 63.75 |
| R1-Dr.GRPO | 42.66 | 64.46 |
| Critique-GRPO（指示性） | 44.62 | 66.03 |
| Critique-GRPO（w/GT） | 45.30 | 66.29 |
| **Critique-GRPO（CoT）** | **47.08** | **68.26** |

四点结论：

1. **NLF 增强在线 RL**：CoT 变体对 R1-Dr.GRPO 提升 +4.4（42.66→47.08）与 +3.8（64.46→68.26），对 R1-GRPO 为 +5.9 / +4.5。
2. **在线压倒离线**：超最强离线基线 CITL-FT +11.42 / +12.42，超 Refinement FT +11.87 / +8.81——离线模仿静态精炼替代不了在线探索中的实时纠错。
3. **批评丰富度单调有益**：CoT 比指示性变体高 +1.8–2.4（7B）与 +2.0–2.3（8B）。
4. 摘要口径的总增益（对各自 base 的绝对提升）：Qwen2.5-7B-Base +15.04、Qwen3-8B +15.03、Qwen2.5-Math-7B-Base +21.60、Llama-3.2-3B-Instruct +7.34。

**数学专用骨干上的数据效率**（Qwen2.5-Math-7B-Base）：仅 4k prompt 的 Critique-GRPO（CoT）平均 51.06，除 AIME24（30.00，低于 Oat-Zero 的 33.40）外全面超过用 46k prompt 的 SimpleRL-Zero / PRIME-Zero / Oat-Zero（MATH-500 84.20 对 76.00/81.40/78.00；OlympiadBench 48.60 对 34.70/40.30/43.40；AMC23 70.00 对 54.90/54.00/61.20；GPQA-Diamond 40.40 对 23.20/18.20/23.70）。特别地，它大幅超过使用稠密过程奖励的 PRIME-Zero——**在此设置下 verbal credit assignment 优于数值化的过程 credit assignment，且数据量仅为对方约 1/11.5**。

**自批评与自我改进**（Qwen3-8B）：self-critique 平均 68.13，比 R1-GRPO +4.5、比 SFT +12.0；AIME24 pass@1 50.00→60.00，AIME25 Avg@32 43.30→46.70；AIME24/25 上 pass@k（k=1–256）全程压过 GRPO 与 SFT，k=1–4 区间相对提升 10–16.7%（摘要所引 +16.7% 即该口径上限）。完全无参考的 self-critique & self-evaluation 平均 66.09，仍超 R1-GRPO +2.3——纯自监督闭环成立。

**架构与批评源泛化**：Llama-3.2-3B-Instruct 上 GRPO 24.79→29.86（+5.1）；Qwen3-32B（解码预算 16,384 token）73.68→77.60（+4.0）。批评模型可替换：Qwen2.5-7B-Base 上 Llama3.1-405B / GPT-4o / DeepCritic-7B 分别得 46.79 / 47.08 / 47.98（对 GRPO 的 41.18 提升 +5.6–6.8）——**7B 本地批评模型即可闭环，无 API 依赖**。

**弱到强泛化**（Qwen3-8B-Base 作弱教师、基于 w/GT 批评产精炼去教 Qwen3-8B）：平均 65.55，对 base +12.3，且高于 R1-GRPO 的 63.75。

**在线联合 vs 两阶段解耦**：GRPO 收敛后批评/精炼/SFT 的顺序基线平均 43.15，显著低于联合优化的 47.08（p<0.01）；重 OOD 的 GPQA-Diamond 上顺序基线几乎无迁移（34.34 对 GRPO 的 33.33），联合优化推至 37.88——增益来自联合优化机制本身，而非批评数据。

**熵动力学**：R1-GRPO 训练初期即熵坍缩并单调降至近零（R1-Dr.GRPO 前 50 步较高，150 步后同样近零）；Critique-GRPO 全程维持更高熵，200 步前出现熵峰（自生成精炼显著偏离初始分布所致），随后回落对应精炼被快速内化——与"稀有高优势动作升熵、常见高优势动作降熵"的既有观察一致。但熵并非越高越好：weak-refinement 变体熵更高却更差（65.55 对 68.13），说明**探索信号的质量重于探索的量**。

## 5. 消融要点

**目标函数逐项累加**（Qwen2.5-7B-Base，平均 pass@1）：

| 配置 | 平均 |
|---|---|
| R1-GRPO | 41.18 |
| + 去 KL（对应 Dr.GRPO 配置） | 42.66 |
| + 语言反馈（初始 + 1 个随机精炼） | 43.26 |
| + 质量选择（优先正确精炼） | 43.95 |

shaping 是最大单项（+3.1），说明**放大低初始概率、高成功率的推理模式是 RL 微调的关键杠杆**；去 KL（+1.5）不可忽略；质量选择与语言反馈各贡献 +0.6/+0.7。

**初始:精炼比例**：1:1–7:1 扫描中 7:1 最优；更低比例在训练后期因精炼引入的分布漂移导致熵损失突增而退化——直接印证 anchor 条件。

**批评长度**（Qwen2.5-7B-Base）：指示性 7 token 得 44.62，w/GT 15 token 得 45.30，CoT 683 token 得 47.08，而把 CoT 拉长到 2079 token 反降至 46.00——信息密度重于长度，过长上下文提高关键信息提取难度。

**对抗批评**：反转"正确/错误"标签后出现熵爆炸与性能退化，证明增益来自批评的有效引导而非任意语言信号——这是批评质量门控必要性的直接证据。

**计算开销**（300 步口径，论文以 GPU-hours 计）：Qwen2.5-7B-Base 240→245（+5，约 2%）；Qwen3-8B 296→315（+19，约 6.5%）。VERL 异步 rollout 摊薄了批评/精炼的额外推理开销；换来的是平均 +6.0 / +4.5 个点且仅需 4k prompt。

**响应长度与定性**：Qwen2.5-7B-Base 上长度几乎不增，Qwen3-8B 上反而变短——Critique-GRPO 修正了 Qwen3-8B 冗余无效的自反思习惯（论文案例：base 模型因错误公式设定反复"Wait…"输出逾 6000 token 仍答错；微调后正确且精炼）。Minerva-Math 100 条响应在正确性/事实性/简洁性/逻辑性四维 GPT-4o 评分全部最优；SFT 在逻辑性与简洁性上吃亏，因其模仿了专家演示中的冗余自反思。

## 6. 贡献与启示

**贡献**可归为三层：（i）对纯数值 RL 的三大限制给出可复现的实证刻画，把"RL 为什么停"归因到反馈信息量而非优化器；（ii）提出批评→ICL 精炼→安全内化的在线闭环，核心洞察是把自然语言反馈当作**探索扩增器**而非蒸馏对象——精炼产生 off-policy 但高质量的轨迹，经锚定比、shaping、统一基线安全注入策略更新；（iii）用 Transfer Eluder Dimension 把"反馈信息量—探索复杂度"定量化，给出反馈设计的第一性指导：**能定位首错步的反馈价值最高**（O(|S|^L)→O(L|S|)→O(L) 的递降阶梯）。

**工程含义**：4k prompt 全面超过 46k 数值 RL 基线（数学骨干上），叠加 2%–6.5% 的额外 GPU 开销，对算力受限的后训练团队是高性价比路线；批评源可本地化为 7B 模型（DeepCritic-7B 在对比中甚至最高），可全离线闭环；弱到强结果表明多模型协同（弱教师产精炼）是可行分工。作者自述局限：策略缺乏专门的精炼遵循训练，有时无法照 CoT 批评改错；把专家演示塞进批评收效不佳——模型倾向直接抄结论而非分步重推；最优批评形态（类型/详细度）仍待系统探索。

**与音视频技术上下游的关联**（本笔记视角，部分为推断，已标注）：本文作者之一 Kaituo Feng 即 **Video-R1**（Neinforcement Learning for video reasoning in MLLMs, NeurIPS 38, 2026, pp. 99114–99137）的第一作者，且本文正文/附录直接引用 Video-R1 作为"RL 增强多模态推理"的代表工作——同一团队正把该后训练范式推向视频推理，这是最直接的组织与文献纽带。技术迁移逻辑上（推断）：视频时序推理的奖励信号天然更稀疏（答案匹配、时序 IoU 阈值），本文诊断的平台期/持久失败问题在视频域只会更尖锐；Critique-GRPO 的组件可近乎原样映射——rule-based 奖励 ↔ 视频 QA 答案匹配或时序定位 IoU 判定，CoT 批评 ↔ 对时间戳证据链的分步核查（定位从哪一秒起推理出错），而零正确解条件触发、7:1 锚定与 token 级 shaping 均与模态无关，可直接挂在 VERL 的多模态异步 rollout 上。下游场景上，论文结论明确指向"部署后用多样实时反馈做 RL scaling"——对在线音视频内容理解/审核类 LLM 服务，人工复核结论与用户纠错可作为批评信号回流微调。需要正视的模态差异（推断）：视频上下文 token 量大，683 token 级文本批评的相对开销占比更小，但批评模型必须具备时序定位能力，现有文本奖励模型不可直接复用，可能需要多模态批评模型或规则化时序对齐度量来承担 reward system 角色。

## 7. 与其他论文的联系

清单中条目集中于递归自我改进（RSI）主题，与本文真实交集在于"**自我生成的反馈信号如何安全驱动自我改进**"，以下三条有实质关联：

- **paper:arxiv:2611.14326｜When Should Agents Remember? Falsification-Gated Self-Evolution（FGSE）**：FGSE 要求经验教训作为可证伪假设经探针验证后才写入智能体记忆。Critique-GRPO 对自我/模型生成信号采取了同构的验证门控——只保留与规则验证（Math-Verify）结论一致的 CoT 批评、不一致则重新生成，且精炼采样优先正确解。二者的共同前提是"错误的自改进信号会污染后续学习"：本文对抗批评实验（反转标签 → 熵爆炸 + 性能退化）正是这类门控必要性的经验证据。差异在信号落点：FGSE 存入外部记忆，本文内化为策略权重。
- **paper:arxiv:2611.10787｜Trustworthy Recursive Self-Improvement with Statistical Guarantees（TRUST）**：TRUST 用在线多重假设检验为自改进控制错误进化率并提供统计保证。本文只对批评正确率做了经验性检查（批评-验证一致性门控），未提供任何错误率的统计控制；其对抗实验说明 RSI 回路中反馈信号正确率没有内生保证。TRUST 的检验框架恰好是本文质量门控环节可借用的形式化补强方向。
- **paper:arxiv:2611.12109｜SkillDuet: Co-Evolving Models and Skills through Response Feedback**：SkillDuet 以响应反馈同时驱动 LLM 参数更新与外部技能库演化。本文 self-critique 变体同样以自身响应的反馈（批评 + 标量奖励）驱动在线参数更新，且 self-critique & self-evaluation（平均 66.09，超 GRPO +2.3）验证了无外部监督反馈闭环的可行性。差异在改进信号落点：纯参数内化（改一次训练完成）vs 参数 + 外部技能库双通道（可跨任务累积复用）。

其余条目（RSI-PDEbench、LongCapHarness、InfraRSI、WeightLoop、AutoTavern）与本文在任务域和反馈机制上无实质交集，不构成有效关联。
