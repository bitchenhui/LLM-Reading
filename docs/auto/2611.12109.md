# SkillDuet: Co-Evolving Models and Skills through Response Feedback

## 1. 背景与动机

LLM agent 的经验保留存在两条通常被割裂研究的路径：training-free 路径将交互经验沉淀为可检索、可编辑的外部文本技能，training-based 路径通过 SFT/RL 将经验内化进参数。文本技能可以同时扮演两种角色——既作为参数更新的监督信号（如技能条件化的蒸馏），又作为后续任务的执行引导（如 SkillRL、Trace2Skill、SkillGLoW、SEED、OPD-Evolver 等一系列工作所展示的）。但论文指出一个被普遍忽视的时变性问题：**技能的效用随参数更新而漂移**。一个对当前参数更新有监督价值的技能，未必对更新后的模型仍具引导价值；模型习得某能力后对应技能变得冗余，模型行为分布改变后技能相关性下降，留存技能还可能与新学到的行为冲突。

论文用两个受控实验将这一动机量化。实验一（§3.1，固定技能探针）：在 ALFWorld 上以 GRPO 训练 150 步，训练前从 base model 轨迹提取技能集并全程冻结；每步由同一 pre-update 模型生成 8 条无引导 rollout（进入 GRPO 更新）外加 4 条固定技能引导 rollout（仅作对比、不进参数更新），取任务配对的成功率差并按连续 50 步区间平均。结果：步骤 1–50 平均增益 +26.98 个百分点，51–100 为 +9.64，101–150 为 **-2.00**——技能文本完全未变，增益却从强正转为负。实验二（§4.6，固定参数跨模型迁移）：将 SkillDuet 学到的 Global 技能集注入另一个训练好的 SEED-API 模型，成功率反而下降 4.05 个百分点（bootstrap 95% 区间 [-8.45, 0.47]）。两个实验共同说明：留存技能的价值同时取决于技能内容与当前模型的兼容性，因此技能选择必须贯穿训练过程持续重估。

实现这种重估面临三个具体困难：模型每步都在变；通过任务执行评估技能价值代价高昂；RL 训练目标本身不提供"哪些技能值得保留"的判据。SkillDuet 的核心主张是用**模型响应反馈**（response feedback）作为这个缺失判据的低成本代理，把参数内化与技能演化耦合进同一交互闭环，即所谓"技能级递归自我改进（skill-level RSI）"。

## 2. 方法总览

SkillDuet 维护一个双路径闭环（论文 Figure 3 所述流程，此处以文字复述）：

- **交互与提取**：agent 在 prompt 中携带 Global 技能集，每个训练步对每个任务采样 8 条轨迹；外部分析器（Qwen3.8-27B）从这些 on-policy 轨迹中提取 Local 技能。形式化上，记参数 θ、Global 为 G、近期 Local 候选窗口为 W，初始 G₀ = ∅；ALFWorld 按六类任务各维护一个 Global，WebShop 全任务共享一个 Global。
- **参数学习路径**：所有合格 Local 技能为当前步的 on-policy 蒸馏（OPD）提供 token 级监督，与 PPO 结果奖励目标联合优化（§3.4）。关键性质：**所有合格 Local 都参与当步 OPD，无论其 Strength 排名如何、无论其是否最终入选 Global**——选择只作用于长期留存，不削减即时监督。
- **技能演化路径**：每个 Local 在生成时刻、于 held-out 轨迹上以 Strength（当前模型响应 log 概率偏移的幅度）打分并缓存；每 10 步的窗口边界，去重后按缓存 Strength 降序保留 Top50%，与当前 Global 一起交给合成器（含分层压缩）产出新 Global 并部署；窗口随即清空。
- **闭环**：更新后的策略与新 Global 共同引导下一窗口的交互，从而决定后续可提取的经验——内化与巩固互为因果。

这一设计的机理要点在于时序安排：Strength 评分在技能生成步、参数更新**之前**、在策略 π̄k = πθ(k-1) 下完成并缓存，窗口边界只读取缓存不重评。因此每个技能的分数反映的是它被提取时刻的策略状态，恰与"技能证据来自该策略的轨迹"保持一致。评分复用已采样轨迹，不需要额外环境交互，只增加模型打分计算——这是相对执行式评估（如每步跑验证任务）的关键成本差异。

## 3. 关键设计

### 3.1 Local 提取：成功–失败对的优先利用

每步 8 条轨迹按环境反馈定成败。若组内同时存在合格成功与失败轨迹，分析器取轨迹顺序中的第一条合格成功与第一条合格失败，仅接收任务描述与两条轨迹的观察–响应历史，被要求"定位最早分叉决策，将其转化为策略可执行的规则"，产出一条共享 Local。该共享技能监督组内全部合格轨迹的 OPD（含两条源轨迹），并在剩余至多 6 条 held-out 轨迹上接受 Strength 评分（源对被排除以避免自评偏置）。若无合格成功–失败对，则逐轨迹提取 Local：成功轨迹提炼可复用流程，失败轨迹提炼纠错指引；单轨迹 Local 只监督自己的源轨迹且**不进入** Global 选择。工程上，技能须含可解析、非空的 episode_skill 字段且不少于 5 个空白分词（排除纯标点与占位符）方为合格。

### 3.2 Local 引导的 OPD：同一策略充当 teacher

参数更新目标为 L = L_PPO + λ_OPD·L_OPD + L_reg。OPD 分支中，teacher 不是外部模型而是策略自身：student 分支在 (C, G) 条件下对采样响应各 token 打分（log 概率 s_i），teacher 分支在同一响应上加 Local 文本 L 于上下文（C, G, L）打分（t_i），差值经置信门加权：g_i = sg[σ(β(t_i − s_i))]，β = 5，L_OPD = Σ M_i g_i (sg[t_i] − s_i) / Σ M_i。实现上 teacher 分数在 actor 更新前缓存、下一步刷新，student 分数在优化中重算，teacher 分数与置信门均 detach。当 teacher–student 差为零时 sigmoid 门为 0.5，故零损失值不意味着零梯度——这是一个容易被忽略的实现细节。λ_OPD 在 ALFWorld 取 0.05、WebShop 取 0.03。

### 3.3 Strength：以响应偏移幅度替代执行评估

选择机制的直觉：若一个 Local 几乎不改变当前模型对自身响应的概率分布，其指导可能已内化于参数；偏移大则标识了尚未内化、值得留存的信息。形式化上，评分集 H_L 为未参与该技能生成的 held-out 轨迹，评分时固定参数、交互上下文、已采样响应与 Global。关键实现：参考上下文不是"无技能"，而是**token 长度精确匹配的中性文本 NL**（重复/截断一段无任务语义的填充文本，主 WebShop 配置允许至多 2 token 差且不得超长度上限），从而剥离长度效应只留内容效应：

Δr(L) = (1/Tr) Σ_{i∈r} [log π(a_i | C, G, L, a_<i) − log π(a_i | C, G, NL, a_<i)]

Strength(L) = (1/|H_L|) Σ_{r∈H_L} |Δr(L)|，即先取轨迹级均值的绝对值、再对轨迹等权平均。**刻意不使用方向信息**：论文明确不把概率偏移方向当作收益度量。附录中与两个备选准则对照——Utility 以轨迹优势 A_r 加权偏移、Contrast 取成功/失败子集偏移均值之差——论文的论证是：轨迹奖励与成败标签描述的是技能引入**之前**的行为，不能度量技能对未来执行的价值，用轨迹质量加权会把轨迹质量与技能效应混叠。无有效评分的 Local 仍可提供即时 OPD 监督，只是不参与 Global 竞争。

### 3.4 周期性 Global 合成

每 10 步（w=10）对每个 Global 执行：窗口内候选按空白归一化文本去重并检查合格性与有效分，保留数 m_b = max(1, ⌈ρ|E_b|⌉)（ρ=0.5），按缓存 Strength 降序取头部。合成器输入为选中技能 + 当前 Global；若超出上下文预算则分层压缩（至多 5 层），摘要须保留适用条件与 source_ids 溯源。主 WebShop 记录配置的合成上下文预算 24,000（以 UTF-8 字节估算，输出预留 12,288、安全边际 1,024、输入 10,688）；一个真实两层级联实例：37 个选中 Local 经 4 批产出 14 份摘要、再 2 批归并为 8 份，与 5 条既有规则合成 5 条更新规则，全程 8 次请求含 1 次超长修复，初始输入估算 22,280 压至最终 9,287。结构约束：Global 至多 6 条技能、每条至少 5 词、总长 2,400 字符、目标约 45 词/条；合成检查（可解析、非空、结构与长度合规）失败则保留旧 Global。更新后清空窗口，新 Global 在下一 rollout 步前部署。附录还测试了可选的执行式验收 Commit（32 任务×2 rollout×两条件，均值奖励差非负才部署），但无显著性检验且主配置弃用（见 §5）。

## 6. 贡献与启示

**方法论贡献**：(1) 给出了模型–技能共进化的完整闭环机制——不是"训练后固化技能"或"训练中冻结技能"，而是让留存技能的取舍由当前策略的响应反馈在每个窗口重新裁决，直接回应了固定技能增益转负（-2.00pp）这一被量化的问题；(2) Strength 是一个可推广的判据设计：用"策略自身条件化分布的偏移幅度"这一零环境交互的信号替代昂贵的执行式评估，且实验证明它优于天然的替代方案（奖励加权、成败对比、随机）；(3) 消融体系严谨——匹配基线（SEED-API）、固定参数干预、长度匹配中性对照、配对 bootstrap，把"内容效应/长度效应/上下文条件化效应"三者在统计上拆开，这种干预设计本身值得同类工作借鉴。

**工程含义**：外部文本技能是可审计、可回滚、可人工编辑的工件，SkillDuet 的分层合成（保留 source_ids 与适用条件）使其天然适配生产管线中"可审查的经验沉淀"需求；成本结构上 35,036 次 Local 调用对应 145 次 Global 调用，说明主要开销在逐轨迹分析而非巩固，前者有明确的缓存与批处理优化空间。局限同样清晰：每个配置单次训练运行（表中的三种子仅是固定检查点的重复执行评估，不是训练方差）；ALFWorld 保留比例研究中 97.14 与 98.57 出自不同评估协议，论文虽作了披露但提醒读者引用数字须带口径；Commit 验收无显著性检验且实证不利；分析器端点别名 edu-vlm-rm 无法锁定不可变后端权重版本，复现性存在缺口；全部实验限于文本单模态、合成预算以字节估算而非精确 token。

**与音视频技术上下游的关联**：本文属 LLM agent RL 大类，与音视频无直接实验交集，但其机制对音视频工程中的 agent 化环节有三点可迁移的上下游意义。其一，音视频系统中大量调优任务的评估信号昂贵（全参考质量评估、端到端播放 A/B、主观测试），SkillDuet"以模型响应 log 概率偏移替代任务执行评估做经验保留决策"的思路，可迁移为在转码参数搜索、流媒体 QoE 调优 agent 中用轻量代理信号裁决哪些调优经验值得沉淀为规则库。其二，Global 的"≤6 条、限长、保留适用条件与溯源"的工程化约束，为音视频生产环境中将运维/调优经验固化为可审计规则集（而非不可解释的参数）提供了可直接借鉴的形态。其三，论文的教训同样适用：技能与策略强耦合（跨模型迁移 -4.05pp），意味着音视频场景中替换底层模型（如换用新一代多模态基座）时，既有技能库必须随模型重新评估甚至重训，不能视为资产直接继承；且文本环境 512 token 响应上限与 24k 合成预算在长视频多步交互（分段理解–剪辑–编码决策链）下会首先成为瓶颈，迁移需重新设计轨迹分段与技能粒度。

## 7. 与其他论文的联系

- **paper:arxiv:2610.28201｜MaD-RSI**：两者同属"把轨迹证据转化为跨更新持久的外部 agent 结构"这一轴线——MaD-RSI 把多模型失败轨迹作为训练证据直接优化跨异构 LLM 共享的智能体外壳，SkillDuet 的 Global 本质上也是 prompt 层外壳的持久件，证据同样来自成败轨迹（成功–失败对比较提取）。但两者的证据选择机制与目标相反：SkillDuet 由当前策略的响应反馈驱动、只消费自身 on-policy 轨迹，其实证结果（同一 Global 给 SEED-API 带来 -4.05pp）表明技能与策略深度共适配；MaD-RSI 则以跨异构 LLM 共享为目标。这构成一组直接的方法论张力：技能要"贴合当前策略"还是要"跨模型泛化"，SkillDuet 的数据为前者提供了量化证据。

- **paper:arxiv:2611.10787｜TRUST**：SkillDuet 的可选 Commit32 验收（均值奖励差非负即部署、明确"不使用显著性检验"）与 TRUST 用在线多重假设检验为递归自改进控制错误进化率的目标同源——都是为自改进回路加装部署闸门。SkillDuet 的实证（Top50%+Commit32 在 WebShop 从 92.97 降至 85.94）说明无统计保证的粗糙闸门会滤掉与参数更新耦合的正收益更新；TRUST 的统计保证框架正是更严格的替代路径，两者的组合（响应式选择 + 有统计基础的部署验收）是自然延伸。

- **paper:arxiv:2611.07319｜WeightLoop**：WeightLoop 在权重侧用实验反馈持续改写已部署模型且免重训练，SkillDuet 从技能侧给出了互补证据——固定技能在训练后期增益转为 -2.00pp，说明任一侧单独演化都会使另一侧失效：权重演化使文本技能冗余，技能演化又改变响应分布使旧参数次优。SkillDuet 的响应偏移信号与 WeightLoop 的实验反馈同为"低成本评估信号驱动自改进"的实现，差异在于 SkillDuet 显式要求两侧闭环耦合，而 WeightLoop 只覆盖权重侧、把文本层留作程序输入。
