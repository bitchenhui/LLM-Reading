# Do LLM Agents Still Need to Be Told How to Self-Improve?

> Shobhita Sundaram, Cansu Sancaktar, Phillip Isola. *arXiv:2611.23219v1 (2026-11-17)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

论文的问题意识源于自我改进方法不断把机器学习流程的环节下放给模型本身，作者追问这一下放的极限：当模型足够强，人是否还需要规定“如何自我改进”。作者以四条轴为现有工作定位——经验来源（外部给定 vs 自生成）、流程结构（外部规定 vs 学习者自组织）、反馈来源（外部奖励/评估器 vs 自交互所得）、更新对象（权重 vs 文本上下文）。非对称自博弈系（Absolute Zero、R-zero、SPADE 等）自生成训练经验但在权重空间优化，任务采样与教师奖励的调度仍被外部规定，且存在多样性/性能坍缩风险；GEPA/ACE 等上下文优化保留外部任务分布与预定义优化流程；DGM、Hyperagents 逐步扩大模型可自改的范围，但仍运行在外部规定的任务与评估设定上；Open-Ended Optimization 允许自组织流程但评估限于同分布 held-out；并发工作 ASPIRE 允许外部数据与隐藏评估的聚合分。本文占据该谱系最激进的一端：无真实数据、无外部验证分数、无规定循环，仅给原语工具、资源预算与一般性目标，并以“跨引擎、跨视界、跨表征迁移”作为成功判据。

测试域为机制未知的回合制游戏：玩家需在回合与 token 双预算内完成高效探索、目标发现、多步规划与世界建模，构成对复合推理能力的压力测试。动机同时指向能力（前代模型是否依赖脚手架）与安全（不提供循环并不阻止自我改进发生——作者明言 "self-organized improvement is not a discovery waiting to happen"，即这一能力已在受控条件下被观测到，而非等待被解锁）。

## 2. 方法总览

**形式化。** 游戏建模为 POMDP：状态 s_t、观测 o_t、动作 a_t，转移 s_{t+1}~P_g(·|s_t,a_t)、观测 o_{t+1}~O_g(·|s_{t+1})；奖励二元（到达获胜态为 1），至多 H 回合终止。玩家策略 a_t~π_θ(·|h_t,c)，h_t 为交互历史，上下文 c=(c_P,c_L) 由玩家提示词与辅助文本文件（技能文件）组成。教师是同一冻结模型的另一实例，负责修改 c；“一次更新”定义为对 c 中单个文件的一次编辑工具调用。自我改进判据为 J(c_final)−J(c_0)>0，J 为 held-out 测试集上的 Monte-Carlo rollout 平均回报。

**教师环境。** 持久沙箱 harness 会话（Claude 系用 Claude Code v2.1.232，其余模型用 Pi v0.85.1 经 OpenRouter），运行于 Singularity 容器：替换默认系统提示、禁用自动记忆、web 检索、子代理与任务管理等全部扩展，工具仅经白名单授予。工具集 {Read/Write（含 Edit/Glob/Grep）, Bash, Gameplay}。Gameplay 工具接收游戏源文件与可选玩家工件目录，在全新外部玩家会话（仅 Read/Glob 工具）中执行，返回玩家得分、结束原因（获胜/回合耗尽/token 耗尽）、双预算余量与 transcript 路径。合法性校验：PuzzleScript 游戏须通过编译且 BFS 验证获胜态可达（BFS 超时则放行）；Python 游戏做编译与安全检查（网络/文件访问等）。

**双预算。** 更新预算（默认 20 次编辑）与对局预算（默认 150 局），任一耗尽即终止；提前停止会收到续跑消息。GPT/GLM 教师因初期误读预算反馈，系统提示中额外写明 "150 game plays and 20 revisions" 的计数规则。

**Canonical 设定。** PuzzleScript 游戏、20 回合视界、每局 25k token；师生均低推理强度、单次响应 20k token 上限；每模型 3 个独立种子。六个模型跨三族：Claude Opus-{4.6, 5}、GPT {5.6-Sol, 6-Astra}、GLM-{4.7, 5.3}。

**评估基准族**（按与自学习设定的“距离”递增，评估口径来自论文 Table 2）：

| 基准 | 关卡数 | 回合 H | token/局 | rollout/局 |
|---|---|---|---|---|
| PuzzleScript-t20 | 20 | 20 | 25,000 | 4 |
| PuzzleScript-t30 | 20 | 30 | 31,250 | 4 |
| ARC-AGI-3 (L1) | 17 | 30 | 31,250 | 4 |
| MazeBench | 16 | 100 | 75,000 | 2 |

构造口径：PS-t20 从 500 个人写关卡中采样，先按最优解 ≤12 回合过滤、再剔除 Opus-5 于 8/8 rollout 可解者，留 20 关（各来自不同底层游戏），过滤后重跑基线；PS-t30 同法但最优解 13–22；ARC-AGI-3 取 25 个游戏的 Level 1、同法过滤留 17，初帧为 64×64 十六进制网格、后续观测仅列变化格；MazeBench 为 3D 开放世界房间完成制（256 房中滤 50 回合内可解、随机取 16），等距 ASCII 投影并允许旋转相机，度量用 SPL。

## 3. 关键设计

**为何选文本空间优化。** 兼容闭源模型（仅 API 访问即可）；梯度学习绑定预定义奖励且在连续空间进行，而文本更新让教师可基于 rollout 反思动态决定生成任务、经验或知识更新，且玩家行为的变化保留可读解释——这同时使人工审计成为可能。

**工具即信息通道。** 这是本文最具方法论价值的设计杠杆。评估设定的信息可经两条通道进入教师：其一是上下文（提示词中的语义描述），其二是环境约束（Gameplay 工具被施加的回合/token 预算，或允许教师自选预算）。第 5.2 节的正交实验分别操纵这两条通道，量化“评估信息量 → 近似/泛化”的权衡。

**提示的极简性。** 教师提示只规定两级目标：主目标（写文本工件提升玩家在单人游戏上的表现）与泛化目标（工件须迁移到未见游戏）；不规定工件结构。PuzzleScript 运行附官方文档于沙箱。

**SRL 量化协议。** 将 Zimmerman 自我调节学习循环功能适配为 13 个子过程（原 17 个中剔除 4 个判官恒判为不可评估项）的行为 rubric，0–3 分制；以教师-玩家系统为分析单元，一批次=一轮动作（对局、反思）终止于一次工件修订；GPT 6-Astra 作判官（medium reasoning effort），两遍协议：第一遍仅索取证据（工具调用全文、对局 transcript），第二遍给分并附证据/反证与理由。同模型不同种子得分一致（附录 D.2），说明被测行为跨 run 稳定。rubric 对“指令≠执行”“批次边界后不计入证据”“不奖励冗长”等判定规则做了显式约束，控制 LLM 判官漂移。

**可算法化行为度量。** A/B 测试（同一自生成游戏在有/无工件下分别对局）；平凡游戏率（最优解长度 <5 且教师观测胜率 100%）；更新幅度；批次化有效更新数（至少提升一个自生成游戏观测胜率的更新）；replay 率对教师观测胜率的分布（观测胜率取每游戏前 k 局，k∈[2,6]）——用于检验 learnability 型任务选择（倒 U 曲线）是否自发出现。

**GEPA 对齐比较的严格性。** 训练/验证各 10 关与测试集无共同底层游戏；GEPA 用 Opus-5 同时作玩家与反思模型、默认超参、预算约束与自组织设定完全对齐（150 局上限前截断）。该比较把“自发流程”与“规定流程”放在同一计算预算下，校准了增益尺度。

## 4. 实验结果

**代际效应（第 4.1 节）。** PS-t20 上新一代模型显著自改进（相对默认上下文基线，3 种子）：Claude Opus-5 +20%、GPT 6-Astra +10%、GLM-5.3 +6%；三族旧一代（Opus-4.6、GPT 5.6-Sol、GLM-4.7）几乎无提升（GLM-4.7 有一个种子完全未使用对局预算）。作者据此提出“模型正在变得更会自我改进”的元能力代际轨迹。

**增益尺度校准（第 4 节开头）。** 同为 150 局对局预算下，Opus-5 的自组织学习（自生成游戏）在 PS-t20 上达到与 GEPA 在 20 个真实分布内游戏上爬山相当的性能——无数据、无规定流程的自发优化可追平规定式文本优化。

**策略形态（第 4.2 节）。** 三族有效自学者收敛到可识别策略：更频繁 A/B 对照；生成更少平凡游戏（生成游戏的最优解长度分布更长，Opus-5 与 GPT-6 Astra 分离最强，部分教师会写过程式游戏生成器并用 BFS 求解器过滤校准难度）；Opus-5 与 GLM-5.3 偏好小步更新，GPT-6 Astra 与 GLM-5.3 有更多批次化有效更新。SRL 判分上，自改进模型在大多数子过程得分更高（作者明示这不是因果解释）。任务选择呈倒 U：多数生成游戏偏易但被快速弃置，观测胜率 100% 的游戏极少被重玩，replay 集中于 20–60% 观测胜率区间（Opus-5、GLM-5.3 尤甚）——与无监督环境设计/非对称自博弈的 learnability 奖励及 Vygotsky 最近发展区概念同构，且未经任何引导。

**跨环境迁移（第 5.1 节）。** Canonical 设定（Gameplay PS-t20）优化的上下文在四个基准上的增益：

| 基准 | 增益 |
|---|---|
| PuzzleScript-t20 | +20% |
| PuzzleScript-t30 | +9% |
| ARC-AGI-3 (L1) | +21% |
| MazeBench | SPL +0.15 |

**跨模型迁移（第 5.3 节，Table 1）：**

| Player | 工件来源 | PS-t20 胜率 (%) |
|---|---|---|
| Claude Opus-5 | 无 | 25.4 ± 3.6 |

双向成立：在 GPT-6 Astra 的高基线（67.1%）之上，Opus-5 写的工件仍带来约 5 个百分点的提升，说明文本工件承载的是跨模型通用的经验，而非对特定模型生成经验的过拟合。

## 5. 消融要点

**工具丰富度五档（附录 C.2）。** Read-Write → +Bash → +Gameplay(PS，教师自选回合/token，总算力对齐 canonical：3000 回合/3.75M token) → +t20 token 预算 → +t20 回合预算（canonical）。结果：性能随工具丰富度先升；Read-Write 已超基线（部分增益来自教师对先验知识的自反思），但在 MazeBench 之外的所有基准上其增益不足 Gameplay 教师的一半；Read-Write-Bash 介于其间；值得注意的是 t30 对局设定的教师在所有基准上最好，甚至在 PS-t20 上超过 t20 教师——更宽的训练分布优于与测试设定的精确匹配。

**涌现的替代实现（附录 E.2）。** 一个 Read-Write-Bash 会话在提示完全未提游戏的情况下自写 20 回合市场模拟并在 Bash 中对照策略：naive 均分 102.0，而其 playbook 仅 77.1——教师据此诊断"commit big / invest early"建议有误，定位到“升级陷阱”（buy-low 无升级 154.2 vs 带升级 102.9），再做 400 种子的参数扫描（仓位 frac∈{0.5, 0.75, 1.0} × 观察期 warm∈{0, 3, 5}，最优组合 frac=1.0/warm=5 达 189.0；50–75% 保守仓位得 166–183 且最差情形更优），最后把证据数字回写工件（"UPGRADES ARE OFTEN TRAPS"、50–75% 仓位规则）。这是“自造评估环境 + 定量证伪 + 证据回写”完整闭环的样本，表明对足够强的教师，显式 Gameplay 工具可能并非必需。

**引擎无关性（第 5.1 节）。** Python-Gameplay 在 4 例中 3 例恢复了 PuzzleScript-Gameplay 的几乎全部增益——PuzzleScript 先验不是自改进的关键因素。

**上下文信息量（附录 C.3）。** Python 工具下向教师提供 PuzzleScript-Narrow（9 个 Sokoban 型游戏）的摘要，token 数 {0, 234, 659, 1519, 3313, 6551}。近似任务（PS-Narrow）与泛化任务（ARC-AGI-3）先随信息量同升；到最高档时近似继续升、泛化平台化并略降——语义信息过多诱导任务特化。

**工具信息量（第 5.2 节）。** 对两个基准都有利的工具（教师自选预算的 PS Gameplay）同时抬升 t20 与 t30；一旦施加 t20 特定的 token/回合预算，t20 升而 t30 迁移降。结论：对评估设定的感知是双刃剑——引导生成相关经验，同时鼓励特化。

**预算扩展（附录 D.3）。** 增加更新预算（对局预算相应放大）性能先升后平台化；性能随对局经验量单调改善；不同资源 regime 下教师的更新幅度行为不同。

## 6. 贡献与启示

**贡献一：最小规定范式的实证。** 仅原语工具 + 预算 + 一般目标，胜任模型可自组织出有效学习流程并在 held-out 任务上自改进；与 GEPA 的同预算对齐比较提供了增益尺度锚点。

**贡献二：元能力的代际性。** 自我改进能力随模型代际提升，脚手架需求递减——从需要显式 Gameplay 工具，到 Read-Write-Bash 下自写模拟器，作者并推测下一代可能在思维链中直接执行游戏。

**贡献三：策略可识别性。** SRL 框架（13 子过程）与 learnability/ZPD 型任务选择在无引导下自发出现，为理解与审计自我改进行为提供了人类可读坐标系；这也意味着审计者可用成熟的行为科学 rubric 对黑盒自改进流程做半结构化评估。

**贡献四：泛化与信息泄漏的系统刻画。** 文本工件跨视界、引擎、表征、模型迁移；评估设定信息经上下文或工具约束泄漏会诱导过拟合——为部署自我改进系统时“允许它知道什么”给出了可操作的设计准则。

**局限（作者自陈）。** SRL 对齐非因果；不可人类解读的行为未被测量；游戏域有大量课程设计文献可能已被模型吸收，弱先验开放域是否外推未知；20 次更新即现平台效应——这是上下文学习的容量限制还是自改进能力限制、能否像传统学习算法那样持续优化至目标最小化（100 或 1000 次更新），是开放问题。

**对音视频技术上下游的关联（笔记推断，非论文主张）。** 本文机制对仅经 API 使用闭源模型的音视频工程链路（编码参数整定、流媒体 QoE 诊断、无参考质量评估 agent 等）是可直接移植的自我改进形态：冻结权重、文本工件、零训练基础设施。教师“过程式游戏生成器 + BFS 难度校准”的自发行为，与媒体测试中“程序化生成压力测试序列 + 可验证参考指标校准难度”同构，为编码/处理类 agent 自造评估内容提供了范式证据。第 5.2 节的评估信息泄漏结论对围绕已知测试序列或已知指标（PSNR/VMAF 类）自调优的媒体 agent 是直接警示：教师上下文与工具约束本身就是过拟合通道。跨模型迁移结果则提示技能文件可在异构后端模型间复用，适用于多模型混部的媒体处理管线。此外，“机制未知游戏下的盲玩”设定在结构上类似于无参考条件下对环境动力学的在线辨识，但其结论向真实媒体处理域的外推仍需独立验证。

## 7. 与其他论文的联系

- **paper:arxiv:2611.23068（Resolution Hypothesis）**：该文实证指出智能体进化的瓶颈是噪声评估下无法可靠识别改进，而非提不出改进。本文从另一端提供互补证据：胜任模型会自发构造改进识别机制——A/B 对照、回归测试、验证套件（附录 D.5 证实教师观测增益与实测增益平均一致）。但自发 A/B 每条件仅一至数局，恰落在该文所指的噪声评估区；两文合读提示自发测量行为方向正确而统计强度不足。
- **paper:arxiv:2611.14326（FGSE）**：FGSE 把“经验教训作为可证伪假设、经探针验证后写入记忆”设计为硬性框架。本文教师自发出现同型行为：针对 "never idle" 建议专门构造需要等待的反例游戏、终局前做回归测试（第 4.2 节示例）。二者构成“规定式门控 vs 无框架涌现”的直接对照。
- **paper:arxiv:2611.10787（TRUST）**：TRUST 用在线多重假设检验为递归自改进提供错误进化率的统计保证。本文的自发更新流程（20 次更新、小样本逐条对照胜率）没有任何错误率控制，且第 5.2 节展示了过拟合通道；TRUST 类统计层可作为自发流程的外挂安全组件，二者互补。
- **paper:arxiv:2611.12109（SkillDuet）**：同样以外部文本技能工件为优化媒介，但规定了响应反馈驱动的技能库与模型参数协同演化机制（含权重更新）。本文证明冻结权重、无规定流程下文本工件本身即可带来跨基准迁移增益，可视为 SkillDuet 类系统的“最小条件”基线；其跨模型迁移结果也直接关联技能库可移植性问题。
- **paper:arxiv:2611.20430（TrainExplorer）、paper:arxiv:2611.11558（InfraRSI）、paper:arxiv:2611.14949（RSI-PDEbench）、paper:arxiv:2611.19230（CompoundingKernel）**：四者均为“规定式”自我改进工作流（规划-执行解耦、五阶段验证工作流、RSI 框架、搜索式内核编写）。本文的问题意识正是对这类脚手架必要性的检验：代际对比（第 4.1 节旧模型失败）与 Read-Write-Bash 会话自写模拟器（附录 E.2）共同表明，对足够强的模型，显式规定的流程与工具可能可省；反过来，这些框架在结构化域上对中等能力模型的收益，与本文旧代模型无自改进的结果相互印证。
