# SkillMaster: Toward Autonomous Skill Mastery in LLM Agents

> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

LLM 智能体在具身操作（ALFWorld）、网页交互（WebShop）、检索问答等任务上已具备较强的单任务能力，但本质上是情景式的（episodic）：跨任务经验复用能力弱。已有两条改进路线各有缺陷： 纯记忆方法（Mem0、SimpleMem、Reflexion 等）存原始轨迹，冗长且噪声大，难以提炼可复用原则； 技能方法（Voyager、SkillRL 等）把经验抽象为紧凑的过程性知识，效果显著——OpenClaw、Claude Code 等部署系统均依赖技能机制——但技能的创建、修订、选择由外部教师 LLM、固定规则或辅助模块控制，主策略只负责检索与调用。结果是技能管理始终是外挂维护机制，而非策略的可学习组成部分。

论文将“自主技能掌控”拆为三个具体困难：

1. **外部管理 vs 内化**：现有训练教智能体调用技能，几乎不教它把技能库当作可以从自身经验中主动改进的对象。
2. **技能质量评估难**：任务级结果奖励稀疏且粗，无法归因到某一次具体的技能编辑——无法区分“真有用的技能”与“看起来合理的技能”。论文的核心洞察是：高质量技能应在需求相似的任务上产生两个可测的下游效应—— 原本失败的任务更可能成功； 原本已可解的任务步数减少。
3. **联合优化难**：技能管理（优化长期技能库质量）与任务执行（优化即时环境反馈）目标异构，单一策略混训时优势归一化互相干扰，训练不稳定。

SKILLMASTER 的解法是把技能管理同时写进策略的动作空间（工具集成推理 TIR 的技能编辑调用）、奖励（同族探针任务上的反事实效用）与优化算法（按 token 类型解耦的双流优势 GRPO），在单一策略内端到端联合训练。相比教师驱动的 SkillRL，ALFWorld 成功率从 89.9% 提至 98.7%，且去掉了外部教师。

## 2. 方法总览

框架由三个模块构成，训练回路如下。

**两阶段轨迹设计**。每个 episode 分为： **Acting Phase**——智能体逐步与环境交互，每步按当前任务从技能库 B 检索相关技能注入观测 prompt，输出动作并获得标量环境奖励 r_env； **Skill-Mastery Phase**——episode 终止后，系统构造 skill-review prompt（任务描述、检索到的技能、完整动作-观测轨迹、最终环境反馈），策略须先在 `<think>` 中简短推理（prompt 约束 1–3 句），再输出恰好一个工具调用：`propose_skill`（新增）、`update_skill`（修订）、`keep_skill`（不变）。三个工具以 OpenAI 兼容 function-calling schema 注册：propose 要求 category/title/principle/when_to_apply/evidence 五字段，update 要求 skill_id 加修订字段与 reason，keep 只需 reason。evidence/reason 字段从结构上强制每次编辑锚定于轨迹证据。

**反事实技能效用奖励**。当策略调用 propose/update 时，系统选出 K 个与当前 episode 语义相关的探针任务（probes），对每个探针 p_i 先用原技能库 B rollout，再施加候选修改得到临时库 B' 并重复 rollout，逐探针比较得分差 δ_i。效用奖励 R_utility = δ̄ + α·(w−ℓ)/K，其中 δ̄ 为平均改进幅度，(w−ℓ)/K 为方向一致性项（正差探针数减负差探针数）。**训练期候选修改仅在 R_utility > 0 时提交持久化，否则丢弃；评测期无任何效用反馈，所有合法技能管理调用直接执行并持久化**。技能阶段总奖励 R_skill = R_format + R_utility，R_format 对合法工具执行给小额正奖励，对解析错误、缺失 `<think>`/`<tool_call>` 标签、占位符内容施以惩罚。

**DualAdv-GRPO**。标准 GRPO 在组内归一化奖励时隐含假设奖励同尺度同语义，此处不成立：acting 阶段是二值任务奖励，skill 阶段是连续的工具合法性+探针效用。解法是对每个 prompt 的 G 条轨迹分别从 {r_env^(j)} 与 {R_skill^(j)} 估计 (µ_act, σ_act) 与 (µ_skill, σ_skill)，在 token 级按所属阶段赋优势——acting token 得 A_act，skill token 得 γ·A_skill（γ > 0 为可调权重）——再进标准 PPO-clip 目标加 KL 正则。这样保留了类型内偏好序，同时允许动作学习与技能管理学习更新同一策略。

## 3. 关键设计

### 3.1 评审规则对决策空间的压缩

skill-review prompt（模板见附录 A）不是自由复盘，而是一组强约束：成功本身不是 keep_skill 的理由（成功 episode 若依赖未被覆盖的可复用战术/顺序规则/搜索启发式，应 propose/update）；失败本身也不是修改的理由（失败未揭示超出已检索技能的具体教训时用 keep）。对失败 episode，重复无效循环、"Nothing happens" 后的重复无效动作、漏看可见目标、错误子目标切换、丢失物品计数被列为强证据。同时禁止写入任务实例细节（物体实例、房间名、receptacle ID、商品标题/价格）与元评论。这组规则把“何时写记忆”从开放问题压缩为受证据约束的二选一/三选一决策，是后续 RL 能学出稳定策略的前提。

### 3.2 探针式反事实评估的构造细节

探针得分函数为 score(p, B) = 1[success] + (M − steps)/M · 1[success]，M 为最大步数：第一项捕捉“使失败任务变成功”，第二项捕捉“使已成功任务更省步”；失败探针一律 0 分——不能促成成功的技能无论省多少步都无收益。效用项 α·(w−ℓ)/K 的设计意图是降低单探针离群敏感度，优先奖励被多个探针一致支持的编辑。实验配置 K = 4、α = 0.3。

探针选择的三种实例化：ALFWorld 按任务族（微波炉技能应影响所有 heat 任务而与 clean/pick 无关，任务族即天然的技能共享边界）；WebShop 按商品类别（apparel、footwear、electronics、accessories、home decor、beauty、health 七类）；SearchQA 无预定义分组，用 Qwen3-Embedding-0.6B 对训练问题建离线语义索引，预先存储每个问题余弦相似度最高的 K 个近邻 ID（排除自身），训练时直接查表，无在线嵌入计算。两个防泄漏设计值得注意：探针池全部取自训练 split，验证/测试样本绝不参与探针选择或效用评估；探针 rollout 使用独立环境池，种子在当前任务种子基础上偏移 50,000，选择种子由任务 ID 确定性派生以保证可复现。“探针池与当前任务同分布但 held-out”是效用信号度量真实迁移而非记忆的关键。

### 3.3 双流优势的机理

异构性来源不只是奖励尺度：acting 决策的回报在本 episode 内兑现，而技能写入的价值只通过后续多个 episode 的行为间接体现——两类决策的信用分配结构本质不同，共享单一组归一化会破坏类型内偏好序。DualAdv-GRPO 的处理是“归一化解耦、策略共享”：每条轨迹内按 token 所属阶段切换优势来源，skill 段乘 γ 控制技能目标相对权重，最后统一进 PPO-clip + KL。这是一个处理单轨迹内多奖励语义混训的通用技巧，对“格式奖励+任务奖励+记忆奖励”并存的其他 agent RL 设定同样适用。

### 3.4 提交门控与训练/部署的不对称

训练期的 R_utility > 0 提交门相当于给技能库上了一道反事实回归测试闸门；部署期则完全没有探针与效用反馈，技能库的完整性全凭训练出的策略纪律——附录分析显示训练后期 keep_skill 占比升至 97.66%，即“学会不动手”成为主导行为。这是一个重要的工程假设：线上没有廉价的反事实评估机制时，防止技能库腐化的负担全部转移到策略本身。冻结 checkpoint 的测试时管理实验（见第 5 节）对该假设提供了部分支持。

## 4. 实验结果

**设置**：骨干 Qwen2.5-7B-Instruct；沿用 SkillRL 的冷启动 SFT 管线（Claude 教师生成技能增强推理轨迹）；Verl 框架 + vLLM rollout，8×A100；GRPO 组大小 G = 8，KL 系数 0.01，学习率 1×10⁻⁶；所有结果为三次独立运行平均。初始技能库取自 SkillRL（轻量去重）。公平协议（附录 J）：所有 RL 方法同骨干、同初始技能库、同 rollout 预算，测试期技能检索 top-K 与模式一致；SkillRL/RLOO/GRPO/ReAct/Reflexion 数字取自 Xia et al. 同协议复现。

**ALFWorld / WebShop 主结果（关键行）**：

| 方法 | ALFWorld All (%) | WebShop Score | WebShop Succ. (%) |
|---|---|---|---|
| GPT-4o | 48.0 | 31.8 | 23.7 |
| Gemini-2.5-Pro | 60.3 | 42.5 | 35.9 |
| GRPO | 77.6 | 79.3 | 66.1 |
| SimpleMem+GRPO | 62.5 | 67.8 | 46.9 |
| SkillRL | 89.9 | 85.2 | 72.7 |
| **SkillMaster** | **98.7** | **95.0** | **82.0** |

两条基线趋势得到确认：RL 训练显著优于闭源 LLM 与 prompt 方法；结构化技能库显著优于通用记忆增强（过程性抽象优于原始轨迹存储）。SkillMaster 在 ALFWorld 六族中 Pick/Look/Clean/Pick2 全部 100%，Heat 97.1%、Cool 95.7%，无一族低于 95%——增益广泛分布而非拟合特定模式。相对 SkillRL 平均提升 8.8 个百分点，且是在其已近 90% 的高基线上取得。WebShop 上 score（95.0）与 success（82.0）的差距提示成功任务的决策质量（属性匹配等）也更高。

**SearchQA（七个检索增强 QA 数据集）**：总体 48.0%，超 SkillRL（47.1）0.9 个百分点；七个数据集中五个超过 SkillRL，NQ（49.1）与 HotpotQA（45.6）为全场最佳；TriviaQA（62.9 vs 63.3）与 Bamboogle（70.7 vs 73.8）小幅落后。相对 EvolveR（43.1）、ZeroSearch（39.1）优势明显。多次运行标准差：ALFWorld 98.7±0.4，WebShop 95.0±1.0 / 82.0±0.8，SearchQA 48.0±0.1。

## 5. 消融要点

**组件消融**（ALFWorld + WebShop，文中为定性结论）：去掉效用奖励在两基准均明显下降——反事实探针评估是区分“有用编辑”与“格式良好编辑”的关键信号；以单一耦合归一化组替代按类型归一化同样降低性能，验证解耦对联合优化的必要性；随机探针一致差于同族探针，任务相关的探针选择对技能质量反馈的可辨识性至关重要；去掉冷启动 SFT 降幅最大，说明基础工具使用与任务执行能力的初始化不可省。

**技能管理必要性**（附录 L，排除两个替代解释）：

| 方法 | ALFWorld (%) | WebShop Succ. (%) |
|---|---|---|
| GRPO | 77.6 | 66.1 |
| GRPO + Review-Only | 78.4 | 66.9 |
| SFT + GRPO（静态技能库） | 92.2 | 75.8 |
| SkillMaster | 98.7 | 82.0 |

仅追加评审回合各提升 0.8 个百分点——收益不能归因于“多了一次复盘计算”；在同 SFT 初始化、同初始技能库的 SFT+GRPO 对照下，完整框架仍高出 6.5 / 6.2 个百分点。

**弱初始技能库鲁棒性**（附录 M，ALFWorld）：初始库 100%/50%/25%/0% 下 SkillRL 为 89.9/84.6/78.8/74.8，SkillMaster 为 98.7/94.1/92.5/89.4——空库时仍达 89.4%，增益不能由继承强初始库解释。

**测试时技能管理**（附录 N，冻结策略参数）：恢复原始初始库（丢弃训练期全部技能库演化）后 ALFWorld 仅降 0.3 个百分点（98.4），WebShop score 降 1.9（93.1）而成功率反升 2.7（84.7）。WebShop 上空库启动：启用技能管理 78.45 分 / 71.88% vs 禁用 72.35 / 65.63（+6.10 分 / +6.25 个百分点），证明冻结策略可从评估轨迹在线构建并跨 episode 复用技能记忆；但仍低于满初始库+管理（93.55 / 85.16）约 15.10 分 / 13.28 个百分点——显式技能记忆仍然重要，在线重建只能部分补偿。

**技能演化动力学**：训练早期主动修改（propose+update）占 18.76%，随训练 keep_skill 从 81.25% 升至 97.66%、修改决策降至 2.34%；技能库从 58 个初始技能增长到训练后 118 个。呈现“先探索新技能、后巩固已有知识”的收敛模式。

**计算开销**（附录 K，ALFWorld）：启用效用后每步训练时间 12.13 → 16.00 分钟（+3.87 分钟，约 +31.9% 墙钟时间），平均 GPU 显存 33.51 → 34.57 GiB，峰值 61.29 → 70.49 GiB。成本主要来自每次技能突变 O(K) 次额外探针 rollout；在 episode 更长或突变更频繁的环境中会进一步放大（论文在附录 F 讨论了重要性采样、跨候选突变摊销评估、学习值函数近似探针得分等降本路径）。

**案例**（附录 H）：Case 2 中智能体发现现有技能 "Open Then Heat"（先把物体放进微波炉再加热）与实际环境行为矛盾——加热仅在手持物体时成功——遂修订为 "Heat While Holding Target"；同族探针任务（加热苹果后放冰箱）从旧技能下的 8 步微波炉困惑循环（放入→加热无效→反复开关门→取回→重加热）降为 2 步正确执行，消除 6 步。这正是效用奖励设计所度量与强化的直接效率收益。

## 6. 贡献与启示

**论文自述贡献**： 单策略内联合优化任务执行与学习到的技能管理决策的框架； 以探针任务反事实影响评估候选技能修订的下游效用奖励； 通过分离优势归一化解耦动作优化与技能管理优化的 DualAdv-GRPO； 三个基准上的整体最优表现。

**方法论层面**，本文最有价值的两点： 其一，把“记忆写入门控”从外部规则变成可学习动作 + 可测奖励，核心突破是找到了密集的技能质量代理信号——同族探针上的（成功 + 步数）反事实差——从而给原本只有 episode 级稀疏回报的记忆写操作装上了直接信用分配； 其二，“训练期带反事实门控、部署期纯策略纪律”的非对称设计，是 self-improving agent 在无法在线评估写入价值时的一种务实工程折中，其可靠性依赖策略收敛到高 keep 率（97.66%）这一经验事实。

**局限**（论文自述）：探针选择依赖预定义任务分组，开放环境需要自适应相似度或学习到的任务表示；探针评估成本随 episode 长度与突变频率增长；验证仅覆盖两个结构化基准，软件工程、开放网页等场景待验证。未来方向含技能删除、多智能体技能共享、分布漂移下的持续学习。

**与音视频技术的上下游关联**（本段为笔记作者的迁移分析，非论文内容）：本篇属 LLM 智能体 RL 方向，但其机制前提——“可重置、可廉价并行 rollout 的环境 + 确定性评分”——在音视频工程中天然成立：固定测试集上的编码/转码实验（BD-rate、时延、QoE）即可视为可重置模拟器。由此“探针式反事实评估”可直接映射：把技能实例化为编码参数 recipe、滤镜链配置、推流故障处置预案，把探针任务实例化为锚点片段集，则 R_utility > 0 的提交门等价于“未过锚点集回归测试不得提交配置变更”。下游场景上，媒体生产/分发链路的自主运维智能体（FFmpeg 滤镜图构建、直播故障诊断、ABR/CDN 参数调优）是典型的长时程、经验可复用任务，紧凑技能库比原始轨迹记忆更适合沉淀“处置预案”类过程知识。成本上需注意：每次技能突变 O(K) 次探针 rollout 在视频中意味着 O(K) 次编码作业，远贵于文本环境，论文讨论的摊销评估与学习值函数近似在此场景更为必需。

## 7. 与其他论文的联系

- **paper:arxiv:2611.12109（SkillDuet）**：同为“LLM + 外部技能库”的协同演化工作，但 SkillDuet 以响应反馈耦合模型参数更新与技能库演化，实现技能级递归自改进；SkillMaster 则训练行动策略自身内化管理决策，用反事实效用显式定价每次编辑、以双流优势稳定混训。两者分别回答“技能库与模型如何共演化”与“策略如何学会自己管理技能库”，问题正交、机制可组合。
- **paper:arxiv:2611.14326（FGSE）**：共享“先验证后写入”的记忆安全关切。FGSE 将经验教训作为可证伪假设经三类探针验证后才写入记忆；SkillMaster 用同族探针反事实效用（R_utility > 0 提交门）实现同类门控。关键差异在于 SkillMaster 把“写与不写”本身做成 RL 学习的动作，而 FGSE 的门控是框架侧固定流程。
- **paper:arxiv:2611.10787（TRUST）**：SkillMaster 的提交门是 K=4 探针上的点估计，无统计保证；TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证。小 K 下探针噪声可能放行坏技能，TRUST 的方法是对此类效用门控自然的统计加固方向。
- **paper:arxiv:2611.19230（CompoundingKernel）**：在 GPU 内核编写这一具体域验证自我改进智能体（SOL-ExecBench B200 榜单登顶）；从音视频视角看 GPU 内核优化是编解码算力上游。SkillMaster 的探针效用 + 双流优势是域无关机制，但其评分函数（成功 + 步数）与验证环境均为结构化文本任务，向内核/性能工程这类连续指标域迁移（评分需改为性能达标 + 加速比）是明确的开放问题。
- **paper:arxiv:2611.11558（InfraRSI）**：以五阶段验证工作流将开放式指令转化为分布式 LLM 训练优化（最高 2.75× 加速），与 SkillMaster 同属“验证闸门 + 自改进”范式，分别作用于训练基础设施层与智能体技能库层，闸门设计可互相参照。
