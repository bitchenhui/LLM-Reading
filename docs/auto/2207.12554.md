# Inter-Frame Compression for Dynamic Point Cloud Geometry Coding

## 1. 背景与动机

动态稠密点云是 VR/MR、体积视频与远程呈现的核心数据形态，典型规格为每帧约 80 万–100 万点、30 fps、10-bit 精度，几何码率极高，压缩是落地前提。MPEG 已确立两条标准路线：G-PCC（TMC13）以八叉树几何编码为主、trisoup 面片与预测几何为辅，八叉树路径更适配稀疏 LiDAR 数据；V-PCC（TMC2）把 3D 点投影到 2D 补丁后复用 HEVC 等成熟视频编码器，面向稠密动态内容，同时提供 intra 与 inter（P 帧、low-delay）两种模式。

深度学习侧的点云几何压缩已形成四条主线：体素化方法（Quach、Wang、Guarda 等）切 64³ 块做 3D 卷积自编码，因空体素占多数而计算/显存低效；八叉树熵建模（MuSCLE、OctSqueeze、VoxelContext-Net、OctAttention）以父子/邻域上下文预测占用概率，无损编码，偏向稀疏 LiDAR；点基方法（PointNet++ 系 patch 方案）率失真性能与向大尺度稠密内容的泛化较弱，前后处理负担重；稀疏张量方法（PCGCv2 等）在稠密真实感内容上表现最好。论文指出的关键缺口是：**现有全部深度学习方案均为帧内编码**，动态序列的时域冗余在学习式框架中完全未被利用——而这恰是视频编码中增益最大的来源。

不能直接照搬视频帧间范式的机理原因：点云相邻帧点数不同、无显式点级对应，且时空采样非均匀，光流估计+双线性 warp 这类运动补偿在坐标域没有可操作的对应载体。本文的破局思路是把运动补偿**整体搬入特征域**：不在点坐标层面建立对应，而在最粗尺度的隐空间中，用一次输入/输出坐标可异的广义稀疏卷积（GSConv）把前帧特征“搬运”到当前帧坐标上，实现隐式运动补偿。范围明确限定为 MPEG 分类中的稠密动态点云（人形序列、VR/MR、telepresence），稀疏 LiDAR 场景排除在外。结果经 MPEG 3DG EE 5.3 专家交叉验证——在学习式 PCC 文献中这属于少见的高可信度报告口径。

## 2. 方法总览

整体是一个闭环 P 帧预测结构，编码端与解码端各持一套**完全相同**的 Encoder 与 Predictor（复用权重以省参数）。设当前帧 P²、前一重建帧 P̃¹：

1. P̃¹ 过 Encoder 得四个尺度的稀疏张量特征（P¹₀ds 至 P¹₃ds）；当前帧 P² 过同一 Encoder，但只取三次降采样张量 P²₃ds = {C²₃ds, F²₃ds}（坐标+特征）。
2. Predictor 以前帧四个尺度的特征与当前帧三次降采样坐标 C²₃ds 为输入，输出预测特征 ŷF²₃ds，即 ŷP²₃ds = {C²₃ds, ŷF²₃ds}——输出坐标被强制对齐到当前帧坐标，这是运动补偿的落点。
3. 残差 R²₃ds = F²₃ds − ŷF²₃ds 经量化后，由全分解因子化熵模型估计分布并算术编码，有损传输。
4. C²₃ds 用 G-PCC 八叉树**无损**传输：在 8iVFB 上约为原始坐标数据量的 1/16，代价约 0.024 bpp。
5. 解码端以 P̃¹ + C²₃ds 驱动同一 Predictor 得预测特征，加反量化残差得 P̃²₃ds，再由 Decoder 逐级上采样重建 P̃²。

码流因此分成两支：**无损的粗尺度坐标锚 + 有损的特征残差**。这个“坐标当锚、特征做残差”的分配构成全框架的率失真骨架：低码率端坐标比特形成硬地板，高码率端特征比特主导，而帧间预测只削减特征支，故增益随码率升高而放大（实验节验证）。编解码网络本身不带预测模块即可退化为纯帧内方案（即 PCGCv2 形态），帧间能力由 Predictor 独立叠加。

Encoder/Decoder 骨架继承 PCGCv2：稀疏卷积多尺度下采样（16/32/64 通道级别，Inception-Residual Block 堆叠，每个 IRB 含三个 IRN）；Decoder 用转置卷积逐尺度上采样，每级接“分类+剪枝层”输出占用概率并取 top-k 保留。几何输入初始化为占用坐标特征恒等于 1 的稀疏张量，基于 Minkowski Engine 实现，仅处理占用坐标，故两帧同入网络的算力仍可控。

训练目标为拉格朗日 J = R + λD：失真 D 为三个尺度（2ds、1ds、原尺度）上体素占用 BCE 损失之和（多尺度真值由原始点云体素/量化降采样得到）；率项由熵模型给出 R = (1/N)Σᵢ log₂ p(f̄ᵢ|φ)。量化不可导，训练期以 U(−0.5, 0.5) 均匀噪声近似。**无显式运动估计损失**，运动补偿权重完全由端到端训练习得。训练时对相邻两帧做同一 kd-tree 划分分块以降显存；推理可整帧处理。

## 3. 关键设计

**GSConv：特征域运动补偿的算子化。** Minkowski 广义稀疏卷积把一切离散卷积作为特例：xᵤ^out = Σ_{i∈N^D(u,C^in)} Wᵢ x^in_{u+i}，u ∈ C^out，其中 N^D(u,C^in) = {i | u+i ∈ C^in, i∈N^D}，输入/输出坐标集 C^in、C^out 预先给定且**不必相同**。论文使用两种实例，核形状均为 3×3×3 立方体：Conv（C^in=C^out）贯穿 Encoder/Decoder/Predictor 主干；GSConv（C^in=C¹₃ds、C^out=C²₃ds）**仅在 Predictor 末端使用一次**，把前帧粗尺度坐标上的特征场卷积映射到当前帧粗尺度坐标上。这一步就是“运动估计+运动补偿”的合体算子：不估计显式运动向量、不要求点级对应，靠核窗口内的特征加权聚合完成跨帧特征搬运。工程上这是算子级解耦——Predictor 是独立模块，作者明确其可移植到其他网络骨架。

**Predictor 的条件化结构。** 其输入包含 C²₃ds（码流中本就要无损传输的当前帧粗几何），因此这是一个“条件于当前帧粗几何”的运动补偿，而非盲时域外推——这是它比纯外推稳定的结构性原因。内部对输入做三次降采样、逐级与前帧对应尺度特征拼接，末端 GSConv（16 通道）+ IRB + 8 通道卷积输出预测特征。

**分类+剪枝层。** 每级上采样后，候选体素经通道数为 1 的卷积得占用概率 pᵥ，按概率取 top-k 保留真体素、剪除假体素；k（该尺度占用体素数）由编码端计算并作为元数据无损传码流，开销很小。BCE 施加在概率图上，驱动真体素概率升高、假体素概率降低。论文给出的实例：输入稀疏张量 139,244×3 坐标、139,244×64 特征，经该层取 k=52,612。该层同时承担解码端“生成新体素”与“剪枝去伪”两个职责，是逐尺度重建的执行机构。

**率模型与坐标锚。** 残差特征用全因子化熵模型 p(f̄|φ)（Ballé 式）逐通道独立建模，无超先验、无自回归上下文——刻意保持轻量：全网约 203.3 万参数（PCGCv2 约 77.8 万）。坐标支走 G-PCC 八叉树无损编码，8iVFB 上约 0.024 bpp，构成 RD 曲线低码率端的硬地板，也决定了本方法相对帧内方案的收益集中在中高码率段。

**闭环漂移控制。** 预测基于重建帧 P̃¹ 而非原始帧，编解码两端跑同一 Predictor，符合视频 P 帧闭环范式；GoP 结构为每 32 帧插入一个 I 帧（由 PCGCv2 编码），其余 31 帧为 P 帧，以此限制误差传播链长。

## 4. 实验结果

**设置。** 训练集：longdress、loot（8iVFB v2）与 queen（Technicolor），各 300 帧@30 fps、10-bit、每帧约 80–100 万点。评测集：redandblack、soldier（8iVFB v2）与 basketball、exercise、model（Owlii），10-bit。指标：bpp、D1/D2-PSNR（MPEG pc_error 工具，峰值 1023；D2 所需法向用 Open3D 以 20 近邻协方差分析估计），BD-Rate 基于 D1 计算。基线：G-PCC TMC13-v20（octree 与 trisoup）、V-PCC TMC2-v18（intra 与 low-delay P 帧 inter，HEVC，另为 V-PCC 补两个高码率点）、深度帧内基线 PCGCv2。

几个关键判读：

- **基线版本敏感性**：论文早期版本对 TMC13-v14 的数字是 −91.68%（octree）/−84.41%（trisoup），换到 v20 后 trisoup 差距从 84.41% 大幅收缩至 56.69%。引用学习式编解码器对标数字时必须锁死测试模型版本号。
- **运动量与增益的交叉规律**：soldier 运动最小，对帧内 PCGCv2 增益最大（−40.16%）；redandblack 运动最大，增益最小（−28.31%）。对 V-PCC inter 恰好反向（soldier −43.60% 最差、redandblack −55.58% 最好），因为 V-PCC 的 P 帧模式在运动小时才充分发挥。两组交叉印证“特征域运动补偿在时域变化小、前帧特征可迁移性强时收益最大”的机理。
- **RD 形态**：与 PCGCv2 在低 PSNR 端接近——两者都传输同样的无损粗坐标（约 0.024 bpp 地板）；高 PSNR 端显著拉开——帧间只传特征残差而帧内传全量特征。G-PCC trisoup 优于 octree，与“trisoup 适配稠密、octree 适配稀疏”的共识一致。
- **视觉质量**：soldier 序列上，本方法 0.129 bpp 达平均点距误差 0.124 mm、D1 73.74 dB；G-PCC trisoup 0.125 bpp / 0.271 mm / 69.22 dB；G-PCC octree 0.223 bpp / 0.609 mm / 63.20 dB；本方法离群点少、重建点贴近原始表面。
- **复杂度**（8iVFB，逐帧平均）：本方法 GPU 上编码 0.364 s、解码 0.714 s；PCGCv2 0.258/0.537 s；G-PCC octree CPU 1.50/0.42 s；trisoup 5.625/1.61 s。跨平台（CPU/GPU、C++/Python）差异明显，仅作量级参考。相对帧内 PCGCv2，编码时间约增 41%、解码约增 33%，代价来自一次推理处理两帧；峰值显存 15 GB，这也是作者建议输入精度上限 10-bit 的直接原因。
- **训练配置**：RTX 3090（表 II 记 3090 Ti）/ i9-11900F / PyTorch / Ubuntu 20.04；约 40,000 batch、batch size 5、Adam、学习率 0.0008 衰减至 0.00001；λ 七档扫出 RD 曲线。注意一个报告内不一致：表 II 记 λ = 1/10, 1/9, 1/6, 1/4, 1/2.5, 1/1.7, 1/1.1，而正文训练策略一节写作 …, 1/2.5, 1/1.5, 1，末两档两处不一致，复现时需自行确认。

## 5. 消融要点

- **分块消融**（soldier，kd-tree 分块独立编码）：1/2/4/8 块对应 PSNR 74.56/74.52/74.48/74.35 dB，bpp 0.1944/0.1987/0.2055/0.2158。PSNR 损失极小；码率上升部分来自纯工程开销——每块独立写四类文件（坐标流、特征流、点数、熵模型头；8 块共 24 个文件 vs 整帧 4 个），合并码流即可压缩。结论：分块是可行的显存/并行伸缩手段，RD 代价可控。正式评测均用整帧推理。
- **缺失的对照消融**：论文没有提供“去掉 Predictor 纯帧内”的直接量化对照（即 GSConn/GSConv 必要性的消融）。其有效性由三方面间接支撑：与共用编解码骨架的 PCGCv2 的整体 BD-Rate 差、增益随序列运动量的系统性变化规律、以及 MPEG 交叉验证。复现者若要做归因分析，需自行补 predictor 开/关对照。
- **率分配未做分解统计**：低码率端坐标地板的分析依赖 0.024 bpp 这一单点数字，论文未给出不同 λ 下坐标/特征比特占比、残差稀疏度等分解数据；对“坐标锚是否应转有损编码”这一明显优化方向，文中只留下定性空间。

## 6. 贡献与启示

**贡献定位**：首个面向稠密动态点云几何的深度学习 P 帧编码框架。核心创新是把运动补偿改写为“特征域、输入输出坐标可异的稀疏卷积映射”，从算子层面绕开了点级对应这一长期障碍；Predictor 为独立模块、可移植；网络仅约 2M 参数，属于该方向上的轻量设计。

**方法论启示**：其一，“最粗尺度坐标无损锚 + 特征残差有损”是可复用的动态 3D 数据压缩模板——把时域预测限制在特征支，从根本上回避了坐标域的对应难题，代价是接受低码率端的坐标地板。其二，GSConv 的“任意输入/输出坐标”性质是比 flow/warp 更适合非对应点集的跨帧变换算子，可推广到其他跨坐标集的特征传输任务。其三，闭环重建帧预测 + 固定 GoP（32 帧）是常规漂移控制手段，但论文未量化 31 帧 P 帧链上的误差累积，长序列部署前需自测漂移曲线。

**工程含义**：解码 0.714 s/帧（PyTorch/GPU）距 30 fps 实时仍有数量级差距，作者指出 C++ 迁移与框架简化是压缩空间；15 GB 峰值显存同时限制了输入精度上限（10-bit）与分块策略。系统本质是混合方案——I 帧依赖 PCGCv2、坐标支依赖 G-PCC 八叉树、熵模型为学习式——标准化接口（如 MPEG PCC 框架下的 AI 工具类别讨论）是其工程归宿之一。

**对音视频技术上下游的意义**：上游看，这是对 V-PCC inter（投影+HEVC）路线的 3D 原生学习式替代，−52.44% BD-rate 说明在稠密几何上绕开投影失真与 2D 编码器约束有真实收益，为体积视频分发提供了“不经过 2D 化”的压缩路径；下游看，本框架只覆盖几何，颜色等属性编码与几何-属性联合帧间预测仍是空位，且整条流水线的实时化（编码器侧两帧同入、解码器侧逐尺度重建）是落地前必须解决的工程问题。报告规范度方面，MPEG EE 交叉验证、锁版本的基线（TMC13-v20/TMC2-v18）、CTC 数据集口径，使其数字在该方向文献中可信度较高。
