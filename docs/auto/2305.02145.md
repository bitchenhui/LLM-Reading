## 1. 背景与动机

主流图像编码器，无论是经典的 JPEG、WebP、BPG 还是学习式的变分自编码系方法（Ballé、Minnen、Cheng 等），几乎都默认完整码流可用后才可解码。在慢速网络、可变带宽（蜂窝链路）或任务有截止时间的场景下，这一假设导致用户或下游系统必须等待整个文件传完才能看到图像或执行后续处理。

渐进式压缩让解码端在只收到一小部分数据时即可得到低质量预览，随比特继续到达逐步细化。但学习式阵营中的渐进方法稀少，且几乎都是为渐进性专门设计的架构：Toderici 等的迭代 LSTM 残差编码（2015）及其 Pixel-RNN 改进（2017）、Cai 等的两级编码–解码（基础层+增强层，2019）、Gregor 等的 GAN+RNN 概念压缩、Lee 等基于 trit-plane 的 DPICT（2022）。这些方法结构复杂、可伸缩级数有限（通常 T 步或两级）。另一条可变码率路线（调制网络、条件自编码动态量化、slimmable 子网络）解决的是"一个模型多码率工作点"，并不保证码流前缀可解码，因此不构成渐进传输。

本文的出发点是一个被已有研究（Koike-Akino 的随机瓶颈、PCA/非线性 PCA 谱系）反复印证的观察：压缩模型瓶颈中存储的信息重要性不均，各元素对重建的贡献差异显著。由此推出一个朴素而有效的构造：若在训练中强制模型把信息按重要性沿瓶颈通道索引排序，那么"按索引顺序发送通道"就天然形成渐进码流，每个前缀都是一个合法的低码率工作点。

据此，ProgDTD 的定位不是新架构，而是一种训练方法：把现成的非渐进学习式压缩模型转化为渐进模型，不增加任何参数，渐进范围可通过一个均匀分布的区间定制，并以 scale hyperprior（Ballé 2018）这一大量后续模型的公共底座作为验证载体。这个定位决定了它的工程吸引力：渐进能力以零推理代价获得，且方法声明适用于任意具有多级隐表示的 CNN 压缩模型。

## 2. 方法总览

**载体模型与记号。** 沿用 hyperprior 形式化：y = g_a(x; φ)，ŷ = Q(y)，x̂ = g_s(ŷ; θ)；超先验侧 z = h_a(y)，ẑ = Q(z)，条件分布 p(ŷ|ẑ) 由 h_s(ẑ) 预测，取零均值高斯 N(0, σ²)（即 Ballé 的 scale hyperprior，仅预测标准差；Minnen 扩展为 N(µ, σ²)，Cheng 用 GMM，本文不采用）。变换由卷积/反卷积与 GDN/IGDN 构成。训练中以均匀噪声 U(−1/2, 1/2) 模拟量化，率失真损失为 L = R(ŷ) + R(ẑ) + λ·D(x, x̂)，λ 决定码率锚点。

**渐进性的形式化。** 定义保留瓶颈前 K 个通道时的损失为 L(θ, φ, K)，理想的渐进模型要求解多目标问题：∀K∈{0,…,N} min L(θ, φ, K)。朴素的加权和标量化需要对每个 batch 以不同 K 计算 T 次损失，复杂度为 O(epoch · batch · T · C_loss)。Koike-Akino 等的 tail-drop 指出：训练期随机丢弃瓶颈尾部可解释为对上述目标的隐式权重 ω_L，但其方案面向 MLP，逐 batch 迭代计算代价高，且未考虑带辅助自编码器与 RD 损失的多级自编码器。

**ProgDTD 的核心机制。** 对 batch 内每一张图独立采样 K ~ U(u1, u2)，将该图 latent 瓶颈与 hyperlatent 瓶颈的通道尾部同步置零 K%，一次前向传播即可让同一 batch 同时覆盖多个前缀长度——相当于对式中的多目标做了一次随机标量化，各前缀工作点的梯度信号在同一 batch 内并存。复杂度降至 O(epoch · T · C_loss)。作者实验结论：在常见分布中，均匀分布表现最佳。逐图采样的统计语义是：通道被丢弃的概率随索引线性增长，知识在瓶颈中按 U(u1, u2) 的 CDF 分布——首部通道几乎总在场、尾部通道经常缺席，梯度倾斜自然形成重要性排序。

**传输与解码协议。** 训练完成后按通道索引顺序发送；解码端依据索引协议知道缺失位置，将其零初始化后送入 synthesis 网络。码率控制器决定截断点，即目标码率。可伸缩台阶数为 C·(u2−u1)（B_lat[C,M,M]）；在改编自 Ballé 的实现中，U(0,1) 对应 196 级、U(0.3,1) 对应 129 级（照录论文数字；按公式 C=196 推算 U(0.3,1) 应约 137 级，论文未解释该出入，引用时需注意）。

## 3. 关键设计

### 3.1 双尾丢弃与共享随机数

ProgDTD 在两处插入 tail-drop：ImageAnalysis 之后的 latent 瓶颈 B_lat[C,M_l,M_l]，与 HyperAnalysis 之后的 hyperlatent 瓶颈 B_hp[C,M_h,M_h]，两处使用同一个 K、同一个随机数发生器（例如保留 30% 的 latent 同时保留 30% 的 hyperlatent）。作者对比了两个独立发生器的方案，结论是单发生器更好，机理解释是：渐进截断要求两级瓶颈的重要性前缀对齐——若重要信息在 hyper 侧位于尾部而在 latent 侧位于头部，则任何截断比例下的前缀组合都不是最优子集。同步丢弃强迫模型把两级瓶颈的重要性排序耦合起来，使任意 K% 前缀自洽。

### 3.2 熵模型与码率项的一致性修正

丢弃的通道既不传输也不应计入码率预算，否则 RD 目标与实际码流失配。做法是把丢弃区间的估计概率 P_lat[K:C] 与 P_hp[K:C] 直接置 1（−log₂1 = 0 bit），等价于把式(13)中的 p(ŷ)、p(ẑ) 替换为修改版 p′：R + λD = E[−log₂ p′(ŷ)] + E[−log₂ p′(ẑ)] + λ·E‖x−x̂‖²。这一步保证率项只统计实际发送的通道，防止模型为"不可见"通道分配码率。完整训练流程（对应论文 Algorithm 1）：ImageAnalysis 得 B_lat → HyperAnalysis 得 B_hp → 采样 K → 两级尾部置零 → HyperBottleneck（量化+概率估计）→ HyperSynthesis 得 σ → ImageBottleneck（以 σ 为条件的量化+概率估计）→ 概率掩码置 1 → 重建 → RD 损失 → 反向传播更新参数。

### 3.3 渐进范围 (u1,u2) 与 λ 的二维设计空间

U(u1,u2) 的区间直接定义可伸缩范围，并构成明确的折衷：设 (0,1) 时模型可从低于 0.01 bpp 起伸缩，但整体 RD 性能有损；设 (0.3,1) 时范围收窄、性能恢复到与非渐进集成持平。λ 则决定质量–码率锚点并与范围耦合：高 λ 带来更宽的伸缩上限但低 bpp 段退化，低 λ 在同 bpp 下质量更好但渐进范围受限。部署时可根据应用的带宽区间先验，先选定目标码率范围再训练——这是论文强调的"可定制渐进范围"卖点。

### 3.4 解码端与码率控制器

解码端无需额外信令：通道索引即协议，缺失位置零填充后走原 synthesis 路径。码率控制器退化为对截断点的标量选择，编码/解码网络结构与原模型完全一致。渐进浏览时如需逐级细化可迭代执行解码器（与其他渐进方法一致）；在时间关键场景下也可在截止时刻只跑一次解码器得到当前前缀的预览——这是非渐进模型做不到的（后者缺任意一部分比特都无法给出有意义重建）。

### 3.5 与其他渐进/变码率机制的本质差异

相比 RNN 迭代残差（级数=T 次迭代）、两级编码（2 级）与 trit-plane（值域比特级），ProgDTD 把伸缩维度放在瓶颈通道维，台阶数等于参与采样的通道数（百级），粒度显著更细；相比 slimmable 类"网络宽度子集"方案，它裁剪的是隐表示而非网络权重，因而码流本身分层，而非仅推理时省算力。

**精度实验的动机与含义：** 面向边云分工场景（边缘设备无算力跑分类、经可变带宽链路上传、任务有截止时间）。值得注意的是，小伸缩范围的 ProgDTD 在 Rate-Accuracy 曲线上反超由五个模型构成的集成——论文未对该现象给出机理解释；一个合理推测（笔记解读，非论文结论）是尾部丢弃的隐式正则迫使前缀通道承载任务相关信息，低码率下有效信息密度更高。

**效率小节：** 渐进浏览需迭代解码器（与 DPICT、Toderici 系一致）；时间关键下可截止后单次解码取预览。附带一个由配置即可读出的工程事实：non-progressive-Ballé 的 RD 曲线由五个独立模型拼接而成，而 ProgDTD 单模型覆盖整个码率区间，存储与部署代价差异显著。

## 5. 消融要点

论文虽无独立消融章节，但多处对比构成事实消融：

- **伸缩范围消融（U(0,1) vs U(0.3,1)）**：同一 λ 下，宽范围换取全程可用性但整体 RD 受损；窄范围可完全追平非渐进集成（MS-SSIM 口径，λ=0.05）。这是范围–性能折馀的最直接证据。
- **λ 与范围的耦合（λ∈{0.01, 0.05, 0.1, 1.0} 自对比）**：高 λ 扩大伸缩上限但牺牲低 bpp 段性能；低 λ 在同 bpp 下更优但渐进受限。两旋钮（λ、区间）联合定义设计空间。
- **随机数发生器结构**：双瓶颈共享单发生器优于两个独立发生器，验证两级瓶颈重要性前缀需对齐的假设。
- **丢弃分布**：均匀分布在作者测试的常见分布中最佳（未给出其余分布的具体名称与数据）。
- **核心因果隔离**：standard-Ballé 与 ProgDTD 使用相同架构、相同"按索引发送"协议，唯一差异是是否经过 DTD 训练——前者的崩溃与后者的平滑退化把渐进性归因干净地钉在训练方法上，这是全文最重要的对照。
- **结构性代价的确认**：作者在讨论节明确自述：尾部通道参与训练少、获得梯度少，瓶颈容量未被充分利用，这是 PSNR 无法追平非渐进版的根因，属方法内生限制而非实现问题。

## 6. 贡献与启示

**方法层面**，ProgDTD 把"码率可伸缩"从架构问题降维成训练正则问题：通过瓶颈通道的随机前缀丢弃，将多目标优化 ∀K min L(θ,φ,K) 以逐图随机标量化的方式廉价求解，得到嵌套的前缀码流——每个前缀都是有效工作点，无需多模型集成即可画整条 RD 曲线。通道前缀排序本质上是把经典可伸缩编码的"质量层"概念搬到学习式隐空间，且台阶数达通道量级（实现中 196/129 级），远细于 RNN 类有限级渐进。

**工程层面**，三点直接可用：其一，零参数、零推理结构增量，编解码耗时不变，可平移到任何具有多级隐表示的 CNN 压缩模型（作者声明，尚未在其他架构上验证）；其二，码率控制退化为通道截断点的标量选择，与算术编码流水线兼容（丢弃通道概率置 1 的技巧可直接复用）；其三，面向机器消费的 Rate-Accuracy 评价表明，在可变带宽+截止时间的边云分工场景，渐进码流不只是体验优化，还能在低码率段取得比集成非渐进模型更高的任务精度。

**局限与警示**：尾部通道欠训练导致的容量浪费是结构性代价，PSNR 口径存在不可忽略的差距；训练数据仅 30k patch、评测仅 KODAK 24 图加 ImageNet 精度，且全文无 BD-rate 定量，横向结论（"相当或更优于 DPICT 等"）以曲线目测为准，复现引用时应自行补测；验证仅在 scale hyperprior 上完成，向上下文模型（Minnen/Cheng 系）、注意力机制乃至 Transformer 架构的外推是作者自列的未来工作。

## 7. 与其他论文的联系

- **paper:arxiv:2610.30966（BLI: Bound-Conditioned Latent Inference for Progressive Image Compression）**：同为学习式渐进图像压缩。ProgDTD 把伸缩维度放在瓶颈通道维（嵌套前缀），BLI 则把渐进编码重构为区间收缩下的序贯隐变量推断，并宣称在 BD-rate、参数量与延迟上优于现有渐进编码器；DPICT（本文直接基线）的三态平面谱系恰是 BLI 的改造对象。两文共同勾勒了"通道维伸缩 vs 隐变量值域伸缩"两条路线，后者在解码延迟与参数效率上的主张可视为对前缀截断类方案（含 ProgDTD 谱系）的针对性改进。
- **paper:arxiv:2610.27037（Channel-Level Mask Guidance for Slimmable Image Compression）**：同在通道粒度做码率伸缩，机制对照鲜明——ProgDTD 强制嵌套前缀（通道全序、只允许连续前缀子集），该文用可学习通道掩码实现非连续通道选择并兼得稳定的变码率控制。非连续选择恰好绕开 ProgDTD 的结构性代价（尾部通道欠训练、容量浪费）；且 slimmable 路线（Yang 等 2021）在本文相关工作中已被引为变码率参照，通道掩码可视为该路线在瓶颈通道维的深化，两者互补地印证"通道子集=码率旋钮"。
- **paper:arxiv:2611.10073（Noise-Regularized Training for Learned Image Compression）**：同属"只改训练、不动架构"的学习式压缩干预家族：ProgDTD 以瓶颈尾部随机置零重组信息以换取渐进性，该文以编码器输入端注入高斯噪声作为结构化正则以提升率失真。两者目标不同（渐进能力 vs RD 增益），但共享同一方法论判断——训练侧干预可以在零架构代价下重塑瓶颈的信息组织，且两者理论上可叠加（在 DTD 训练基础上再加输入噪声正则）。
