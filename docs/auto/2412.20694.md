# QUBE: Enhancing Automatic Heuristic Design via Quality-Uncertainty Balanced Evolution

## 1. 背景与动机

NP-complete 问题“难求解、易评估”，长期依赖手工启发式。超启发式路线用进化算法（EA）从平凡启发式出发自动优化；LLM 代码生成能力成熟后形成 LLM+EA 范式：冻结 LLM 作为 EA 的变异算子，以 few-shot 父代为条件生成新程序。EoH、ReEvo 等方法规模多在 1 万样本以内；FunSearch 将规模推至约 250 万进化步，配合多种群（岛）框架，在 cap set、admissible set 等数学难题上取得 SOTA，是 LLM+EA 的规模化标杆。

作者的切入点是：在“函数空间”中优化启发式，方法必须同时做好利用（在已知高价值区域深化搜索）与探索（开拓未知区域），而 FunSearch 的优先级准则在这两方面都有系统性缺陷。该准则以样本自身得分为准（父代被选概率正比于得分的指数；岛重置按岛内最高得分是否落后于半数岛判定），问题有二：

1. **利用侧偏差**：父代自身得分 s(c) 并非“以其为父代的子代期望表现”的无偏估计——高分父代未必高产。后果是 FunSearch 的 Recent Best Score（近 K=500 个样本中的最高得分，论文定义的利用性诊断量）在进化后期出现平台，挖掘停滞。
2. **探索侧无差别**：多种群机制的探索是随机、不加区分的，不考虑当前区域是否还值得探索。其 Recent Proportion of Change（近 K 个正确程序与其最近父代的 token 级编辑距离、按样本长度归一化的均值，论文定义的探索性诊断量）全程低且恒定。理想策略应前期广探索、随高价值区域被逐步确认而衰减转向利用。

由此动机明确：把优先级准则从“个体自身得分”替换为“作为父代的期望产出 + 该估计的不确定性”，即对进化选择压力做 UCB 化改造。

## 2. 方法总览

QUBE 完整保留 FunSearch 的宏观骨架：n≥1 个岛独立进化，岛间仅在重置时通信；每个进化步随机均匀选一个岛，从中选两个父代样本作为 few-shot 示例提示 LLM 生成新程序；新程序在预定义测试实例集上确定性执行得分，抛 Python 异常或超时的样本直接丢弃；每 T_reset 个样本周期性重置表现差的岛。QUBE 的全部改动集中在被优先级准则控制的两处机制——父代选择与岛重置判定——统一改用 QUTC（Quality-Uncertainty Trade-off Criterion）裁决，其度量为 UIQ（Uncertainty-Inclusive Quality）。

数据库以“簇”组织：在全部测试实例上输出完全一致的程序归入同簇、共享得分 s(C)。UIQ 的两个统计量（期望子代质量 Q_t(C)、累计被选为父代次数 N_t(C)）均以簇为单位维护；作者观察到同簇样本高度相似，簇粒度兼顾效率与可扩展性。

UIQ 定义：Q̃_t(C) = Q_t(C) + k·√(ln t / N_t(C))。第一项是簇的“进化质量”——以 C 中样本为父代产生过的全部子代的平均得分，是子代期望表现的无偏估计；第二项是 UCB 式不确定性加成，低频被选的簇获得抬升。k 为超参，与任务分数量纲强耦合，论文中 OR 数据取 0.0008、Weibull 取 0.0001、cap set 取 32.0、TSP 取 1e-5。

工程实现为异步系统：单服务器 8×NVIDIA A100 + 2×Xeon Platinum 8358，每卡用 SGLang 起本地推理服务，16 个采样器与 50 个评估器多进程并发、共享数据库。主 LLM 为 OpenCoder-8B-Instruct，另用 Deepseek-coder-6.7b 做模型无关性消融。

## 3. 关键设计

**3.1 簇级统计与 UIQ 机理。** Q_t(C) = (1/Σ_{c∈C}|P_{c,t}|)·Σ_{c∈C}Σ_{a∈P_{c,t}} s(a)，其中 P_{c,t} 是 t 步前以 c 为父代生成的全部样本。关键性质：该估计复用进化过程必然产生的子代评分，**零额外评估开销**；而 s(C) 虽直观却是有偏的父代质量代理。不确定性项中 ln t 随全局时间步增长，未被访问的簇加成持续上升，保证不永久饿死任何簇。k 的标定是落地最大摩擦点：OBP 的超额率是比例量纲而 cap set 得分是数百量级的集合大小，k 跨任务相差 5–6 个数量级。论文附录网格搜索口径：OR3 上 k∈[0.0001, 0.01]，最优 0.0008（best 2.59% / avg 2.79%）；Weibull5k 上 k∈[0.00001, 0.001]，最优 0.0001（best 1.54% / avg 1.72%）；cap set 上 k∈{16,32,48,64}，最优 32（UIQ-only 变体，5 次运行 best/avg 均为 464）。

**3.2 父代选择。** 每步在被选岛内取 UIQ 最高的 2 个簇，每簇选 1 个样本作父代。簇内选择概率 ∝ exp(l̃_c/T_prog)，其中 l_c 为字符数，l̃_c = (max_{a∈C} l_a − l_c)/(min_{a∈C} l_a + 1e-6)，T_prog=1.0——同簇程序在所有测试实例上行为等价，越短的样本被选概率指数级越高，即在等价行为中偏好紧凑代码。对比 FunSearch 的“得分指数 softmax”，选择压力从个体自身分转移到簇级“期望产出+不确定性”。

**3.3 岛重置。** FunSearch 重置“当前最高得分落后于半数岛”的岛；QUBE 以岛内最高 UIQ 簇代表岛质量，低于全岛中位数者被重置，重置时从随机保留岛的最佳簇中随机取一样本重新初始化。语义差异关键：重置“不太可能再产出高分程序”的岛，而保留“当前分低但探索未完成（不确定性项大）”的岛，修正 FunSearch 的短视砍岛。

**3.4 评估协议与提示。** 三个任务的演化目标与评分：OBP 在局部搜索算法内演化 priority(item, bins)→各箱得分，评分为相对最优离线解 L2 下界（Martello–Toth）的超额箱数比例；cap set（n=8，n≤6 已被解出）演化对 Z_3^n 向量的 priority 以引导贪心构造，得分为找到的 cap set 大小；TSP 沿用 EoH 设置，演化引导式局部搜索（GLS）扰动阶段的 update_dist 函数，评分为与 Concorde 最优解的相对距离（亦称 excess ratio）。提示模板统一为：父代 1、2 分别置于 priority_v0/v1，要求补全“v1 的改进版 priority_v2”，只允许输出函数体、禁用 print。安全上，作者在实验中观察到 LLM 生成代码尝试读写本地文件，以磁盘权限限制 + 安全命名空间运行缓解。

**3.5 预算与超参口径。** OBP 的 OR 与 Weibull 各 80K 样本、10 岛、T_reset=32768；cap set 2M 样本、T_reset=262144、评估超时 90 秒；TSP 仅 2K 样本、单岛、关闭岛重置（论文指出 TSP 少量样本即可得较好结果）。每提示采样数：OBP/cap set 为 4、TSP 为 1；nucleus p=0.95，温度 1.0。基线 FunSearch* 与 QUBE 共享实现与超参，仅准则不同——即等预算对照。

## 4. 实验结果

设置：每实验 10 次运行、报告最优（消融另报均值±标准差）；基线含 FunSearch 原文报告数（其 LLM 与硬件不同）、FunSearch*（同 LLM/同硬件复现）、EoH（Weibull 与 TSP）。

| 方法（OBP/TSP 为超额比率↓，cap set 为规模↑） | OR1 | OR2 | OR3 | OR4 | W-1k | W-5k | W-10k | cap set n=8 | TSP100 |
|---|---|---|---|---|---|---|---|---|---|
| QUBE | 4.06% | 3.73% | 1.79% | 1.75% | 1.54% | 0.41% | 0.29% | 480 | 0.023% |
| FunSearch* | 4.48% | 4.07% | 3.02% | 2.06% | 1.99% | 0.55% | 0.31% | 464 | 0.029% |
| FunSearch（原文） | 5.30% | 4.19% | 3.11% | 2.47% | – | 0.68% | 0.32% | 512 | – |
| EoH | – | – | – | – | 2.24% | 0.80% | 0.61% | – | 0.025% |

关键结论（均论文原文口径）：

- OBP 超额率比 FunSearch* 低 9.36%~41.73%；在 OR 数据上比 FunSearch 原文报告值低 10.98%~42.44%。Weibull 上基线已很强（FunSearch 原文 5k/10k 为 0.68%/0.32%），QUBE 仍全面占优。
- TSP20/TSP50 所有方法均 0.000%（达理论最优）；TSP100 上 QUBE 与最优路线的差距比 FunSearch* 小 20.69%、比 EoH 小 8.00%。
- cap set n=8：QUBE 480 > FunSearch* 464（+16），但未达 FunSearch 原文 512。作者给出的复现成本口径：单次 cap set 实验需生成评估约 250 万程序、在其 GPU 服务器耗时 3 天以上；FunSearch 原文 140 次 n=8 实验中不足 5% 超过 480，故同条件可复现对比以 FunSearch* 为准。
- 进化过程统计：10 次运行平均意义上 QUBE 早期即领先 FunSearch*；其 Recent Best Score 全程高于 FunSearch* 且后期持续提升（对照 FunSearch* 的平台化）；其 Recent Proportion of Change 更高且随时间逐步下降——即探索自动退火、逐步让位给利用，与设计意图一致。

工程含义：在 80K（OBP）/2M（cap set）相同样本预算、相同 LLM 与硬件下，收益完全来自选择准则的替换，属于纯样本效率增益。

## 5. 消融要点

OR3 数据集、10 次运行，逐步分解准则的三个成分：

| 变体 | 父代选择 | 岛重置 | Best | Avg±std |
|---|---|---|---|---|
| FunSearch* | s(C) 指数 softmax | 按岛内最高得分 | 3.02% | 3.07%±0.0008 |
| Quality Only | Q_t(C) top-2 | FunSearch 式 | 2.74% | 2.98%±0.0012 |
| Parent Selection Only | UIQ top-2 | FunSearch 式 | 2.65% | 2.89%±0.0018 |
| QUBE（完整） | UIQ top-2 | 按 UIQ 中位数 | 1.79% | 2.76%±0.0016 |

- s(C)→Q_t(C)：best 3.02%→2.74%，验证“用子代期望产出的无偏估计替代自身得分”修复利用侧。
- Q_t(C)→UIQ：best 2.74%→2.65%，不确定性项让低频簇获得繁殖机会，长线收益（与完整版差距一并体现）。
- 引入 UIQ 岛重置：best 2.65%→1.79%，是最大单项增益；按“进化潜力”而非“当前得分”砍岛，避免误杀探索未尽的岛。
- 标准差量级（0.0008~0.0018）远小于变体间差距，改进稳健。
- LLM 无关性（OR3）：OpenCoder 下 QUBE 1.79% vs FunSearch* 3.02%（best）；换用更弱的 Deepseek-coder-6.7b 后仍稳定占优（2.69% vs 3.09%）；更强 LLM 绝对性能更好，暗示 cap set 这类难题的上限受 LLM 代码能力约束，换更大模型仍有空间。

## 6. 贡献与启示

**方法学贡献。**（i）诊断：把 LLM+EA 的利用/探索失衡定位到“优先级准则”这一具体机制（父代选择 + 岛重置），并给出两个可复用的量化诊断量（Recent Best Score / Recent Proportion of Change，K=500）；（ii）方法：将多臂赌博机 UCB 引入进化选择压力，统计粒度放在行为等价簇上，且全部统计量复用既有评估、零额外评估成本；（iii）工程：对 FunSearch 是微创改造——不动提示、不动 LLM、不动评估协议，仅替换准则。

**局限（原文自述）。** cap set 未超 FunSearch 原文 512（480 vs 512），大规模难题上的优越性存疑，作者以同条件复现对比自辩；最优启发式的发现依赖 LLM 选择、样本量与随机因素；LLM 生成代码存在不可预测行为（实验中观察到试图读写本地文件）。

**与音视频技术的上下游关联（笔记者视角，论文本身不做 A/V）。**
- *下游·决策函数自动设计*：A/V 管线大量模块本质是“资源约束下给候选动作打分的优先级函数”——编码模式决策与 CU 划分剪枝、参考帧选择、GOP/场景切换判定、码控与比特分配、ABR 码率-缓冲调度、360° 视频 tile/viewport 优先级、实时通信 jitter buffer 与帧调度、per-title 编码参数搜索。论文演化的 OBP priority(item, bins)→scores 与该形态同构；FunSearch 式接口（@evolution 打分函数 + @run 确定性评估）可直接承载此类任务，且编码指标（PSNR/VMAF/编码时间）在固定输入与配置下确定性可评，与框架假设兼容。
- *下游·评估成本*：与 OBP 毫秒级评估不同，A/V 一次评估是完整编解码运行，评估是瓶颈。QUBE 的价值恰在等样本预算下更优（同 80K/2M 预算对比 FunSearch*）且 UIQ 统计零额外评估——直接降低自动设计的样本预算压力；行为等价簇把选择压力施加到行为语义而非代码文本，对昂贵评估任务还能抑制同行为程序的重复统计与膨胀。
- *下游·在线自适应亲缘*：UIQ 就是 UCB，而 bandit 方法本就是 ABR 与在线编码参数调整的主流工具；论文展示的“探索比例随时间自动衰减”正是流媒体在线调参期望的退火行为。但 QUBE 是离线进化，面对网络/内容非平稳漂移需另行引入滑窗或周期重置。
- *上游*：LLM 代码模型（OpenCoder-8B-Instruct、Deepseek-coder-6.7b）与 LLM+EA 做 NAS（论文引用 EvoPrompting）是音视频模型结构自动设计的同骨架上游，QUTC 可替换其中的适应度比例选择。
- *部署警示与算力口径*：媒体生产管线涉及内容资产，LLM 生成代码必须沙箱执行（论文已观察到文件读写尝试）；参考成本——8×A100 服务器上 OBP 80K 样本、cap set 单次 2M 样本 3 天以上，迁移 A/V 需重算预算。

**对本领域启示。**“父代自身适应度 ≠ 父代产出”的有偏性诊断同样适用于其它以个体适应度为选择压的 LLM+EA（EoH、ReEvo 等）；簇=行为等价类，提示代码空间搜索应以行为语义管理多样性；k 与分数量纲强耦合、跨任务需重调，是落地的主要摩擦点。
