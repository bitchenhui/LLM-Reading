# Contextual Experience Replay for Self-Improvement of Language Agents

## 1. 背景与动机

LLM 智能体在网页类序贯决策任务上与人类差距悬殊：论文给出的口径是 WebArena 上人类成功率 78.24%、VisualWebArena 上 88.70%，而无人工介入的前沿方法普遍在 20% 左右或以下。作者把瓶颈归因于**环境特定先验的缺失**：复杂多步任务高度依赖对具体站点结构与交互惯例的了解，逐环境微调代价高昂，而现有智能体缺乏推理期持续积累环境经验的机制，导致每个任务都从零开始探索。

既有“从记忆/经验学习”路线存在明确缺口：ExpeL、Synapse 要么只在较简单的 WebShop 类环境验证，要么直接以冗长的原始观测-动作对作示范，难以扩展到复杂环境；AutoGuide、AutoManual、Agent Workflow Memory 思想相近，但机制上需要先拿到 ground-truth 奖励才能运作（真实环境通常没有即时奖励信号），且设计偏简单——例如 Agent Workflow Memory 无检索模块、以整体重写方式更新 workflow 记忆。“无奖励依赖、可在线持续积累、可检索复用”三者同时满足的框架在当时是空位，CER 正是补这个位。

方法论来源上，CER 松散借自强化学习中的经验回放（Schaul et al. 2016 的 prioritized experience replay、Rolnick et al. 2019 的 experience replay for continual learning），但把“回放”从参数更新搬进上下文窗口：从过去轨迹（含成功与失败）蒸馏环境动力学与决策模式，存入动态经验缓冲区，新任务时检索相关经验并以自然语言注入上下文。全程免训练，蒸馏、检索各模块均由 VLM（GPT-4o）提示实现。

从本引擎的音视频交叉视角定位（笔记分析，非论文主张）：其一，本文实验载体 VisualWebArena 是纯多模态 GUI 导航任务，其观测管线（截图 + Set-of-Mark 标注 + 元素 ID 跨模态对齐）直接消费屏幕内容理解与视觉 grounding 组件，是音视频感知栈的下游集成场景；其二，“上下文内经验回放”这一免训练自改进范式对音视频工具链智能体（非线性剪辑、媒体资产管理控制台、直播运营后台的自动化操作）具有可迁移性，见 §3、§6 展开。

## 2. 方法总览

形式化：智能体 A 由语言模型 M 与上下文窗口 C 驱动。CER 由四个模块构成——蒸馏模块 D、检索模块 R、动态经验缓冲区 ε、基础决策智能体 A 本身。给定任意轨迹集合 T = {τ1,…,τn}，蒸馏模块逐条产出经验 Ei = (Di, Si)：

- **Di（dynamics，环境动力学）**：不同网页的摘要 + 对应 URL + 推断的可能用途。作用有二：支撑状态感知决策；或直接经 URL 直达状态，把多步探索压缩为单步跳转。
- **Si（skills，决策模式）**：技能概要（如 "navigate to forum {forum name}"）+ 分步指南；每步同时含自然语言说明与具体动作示例（click/fill 等代码片段）。

按轨迹来源分三种设定：**online**——零经验冷启动直接推理，每解完一个任务即蒸馏其轨迹并入缓冲区，下一任务检索 + 回放，循环演化；**offline**——预先采集一批轨迹（人工标注黄金轨迹或 LLM 探索器生成），一次性蒸馏入固定缓冲区，测试期不再学习；**hybrid**——先离线热启动再在线自演化。

关键机理：整个闭环没有梯度。“经验回放”被实现为**结构化存储 + 列表式检索 + 程序化提示拼接**三段式——选定 k 条经验后经程序化映射 f 转为自然语言描述，注入上下文得 C′ = g(C, f(E))，由 in-context learning 改变底层决策策略。各模块系统提示在论文附录中给出。

## 3. 关键设计

**3.1 状态先验与动作先验的双通道解耦。** 动机：单步状态/动作空间极大，但目标导向轨迹实际触达的状态与使用的动作只是极小的信息量高的子集；把它们显式抽出，dynamics 承载状态侧启发式（页面内容 + URL 直达锚点），skills 承载动作侧启发式（可复用操作模式），二者协同（消融见 §5）。作者以 Klein 的 Recognition Primed Decision 模型类比——人在复杂环境下靠识别“有希望的动作”决策。dynamics 中的 URL 字段本质是 O(1) 状态跳转锚点，与视频交互中的 seek/章节锚点在机制上同构。

**3.2 技能的参数化抽象与双模态表示。** 蒸馏提示强制将非固定元素（论坛名、选项、输入文本等）抽象为描述性变量，输出 "navigate to forum {forum name}" 而非绑定具体实例的版本——这是跨任务模板泛化的直接机制来源（由 §5.2 的 ct-SR 实验验证）。分步指南的“自然语言摘要 + 具体动作示例”双模态各有分工：前者提供灵活的高层指令，后者帮助理解步骤并规整输出格式（动作示例与 ReAct 输出格式对齐）。

**3.3 增量蒸馏与写入端去重。** 蒸馏提示中附带缓冲区内现有经验，要求“已总结过的不重复总结”，实现经验跨时间持续累积而非重复膨胀。注意这是纯提示层的去重，没有嵌入索引或相似度合并机制。

**3.4 检索 = 列表式 VLM 选择，而非向量检索。** dynamics 与 skills 各有独立检索提示：输入通用指令 + 当前任务目标 + 站点描述 + 缓冲区内全部同类经验，VLM 先将任务分解为若干步骤，再输出 top-k（实验取 kd = 5、ks = 5）。工程含义：无需训练检索器，且能做任务分解级的语义相关性判断（精度导向）；但提示长度随缓冲区规模线性增长，长程部署需引入合并/压缩机制。论文未报告缓冲区规模上限与检索随规模的表现，这是落地扩展性的主要开放问题。

**3.5 无奖励蒸馏：成功与失败轨迹一视同仁。** 这是相对 AutoGuide/AutoManual/AWM（需 ground-truth 奖励才能运作）在适用性上的核心区分。代价是失败轨迹会引入误导性动作序列，但 §5.6 显示（WebArena 全量、纯文本观测）混合蒸馏 31.4% vs 仅成功轨迹 33.5%，仅差 2.1pt；作者归因于经验的灵活自然语言表示与模型隐式推理的过滤能力。

**3.6 多模态观测管线（VisualWebArena）。** 沿用 Set-of-Mark：对截图上每个可交互元素画高亮框并在角标注唯一元素 ID；同时提供文本观测（accessibility tree），其中 ID 与 SoM 标注严格一致，实现图文跨模态的 ID 对齐锚定。BrowserGym 本身不支持视觉评测，作者自行实现了该环境。对音视频侧的意义：这是“元素检测 + ID 标注 + 跨模态 ID 一致性”的典型 GUI grounding 管线，元素检测的召回与 ID 稳定性直接上限了 skill 中动作示例的可锚定性，属于音视频感知技术的直接下游消费场景。

## 4. 实验结果

**设置。** WebArena 全量 812 任务、5 站点；VisualWebArena 910 任务、3 站点，任务目标大量依赖视觉输入，因成本原因仅做 online。骨干 GPT-4o-2024-0513，temperature 0.1；环境 BrowserGym（文本 + 视觉观测，accessibility tree 附加可点击/可见元素信息）；每任务最多 30 步。WebArena 离线训练任务每站点 5–10 个、约为测试集 5%，由不熟悉 WebArena 的人员经 3 小时浏览后设计、过滤与测试集重叠后人工标注黄金轨迹。基线为作者自行复现的 GPT-4o w/ BrowserGym。

**弱开源模型。** Llama-3.1-70B 在 Gitlab 分片：ReAct 17.3% → CER_hybrid 22.0%（论文口径相对提升 26.53%）。增益明显小于 GPT-4o，作者归因：弱模型在大动作空间任务上输出格式化能力差，既影响执行鲁棒性，也影响多步、格式良好的技能蒸馏质量——即**经验库质量与骨干模型的格式能力正相关**，小模型端部署的明确警示。

**与采样方法协同**（Forum 分片，online）：CER w/ ReAct 37.7%；轨迹采样 + 重排（每任务采 3 条、最多 20 步、LLM 打分选最高）43.1%；CER w/ 采样 52.6%，相对 CER w/ ReAct 再 +39.5%。机理为正循环：更强方法产出更高质量轨迹 → 蒸馏出更高质量经验 → 经验反哺该方法更鲁棒。

## 5. 消融要点

**(a) dynamics/skills 解耦**（Forum 分片）：CER 37.7%；去 skills 33.3%（−4.4pt）；去 dynamics 35.1%（−2.6pt）。两类经验均必要：dynamics 提供页面内容感知与 URL 直达，skills 提供动作启发，分别对应状态/动作两侧先验且协同增效，去 skills 的损伤更大。

**(b) 跨模板泛化与稳定性-可塑性**（Forum 分片）。WebArena 任务按模板设计、每模板至多 5 个任务。定义 ct-SR = 解出（至少 1 题）的模板数 / 总模板数：基线 44.7% → CER 60.0%。以基线为 100% 基准，CER 稳定性（保留基线已解任务）93%、可塑性（新增解题类型）141%，即新增 41% 的新问题类型。证明提升并非整条轨迹的记忆化，而是细粒度经验的跨模板泛化；同时，stability/plasticity 这对持续学习指标被引入作为自改进系统评测协议，方法论上有独立借鉴价值。

**(c) 奖励信号可得性**（WebArena 全量、纯文本观测）：混合蒸馏 31.4% vs 仅成功轨迹（用环境 ground-truth 评估器过滤）33.5%。有真值奖励更好——成功轨迹信息质量更高、失败轨迹的误导动作序列被剔除——但 2.1pt 的可接受差距证明了无奖励条件下的鲁棒性。

**(d) 离线数据来源**（Forum 分片，附录 A.5）：基线 22.8%；offline 用人工标注 33.3% vs 自引导探索（LLM 逐步提议多样化动作，10 条轨迹、最多 30 步）31.6%；online-only 37.7%；hybrid 人工 41.2% vs hybrid 探索 35.1%——后者甚至低于 online-only。分析：探索式轨迹高度非结构化、动作间缺乏目标关联，蒸馏模块难以抽出有效模式，甚至产生误导性经验。结论：**轨迹的目标导向性是经验质量的瓶颈**；鉴于真实场景高质量人工轨迹难获取，online 学习仍是主要形态。

## 6. 贡献与启示

贡献归纳：(1) 提出免训练、无奖励依赖的自改进框架 CER，经验同时覆盖环境动力学与决策模式，统一支持 offline/online/hybrid 三种设定；(2) 在两个高难度真实基准上取得竞争力结果（WebArena 36.7%、VisualWebArena 31.9%），与采样类方法正向叠加，且与多数既有方法正交；(3) 以 token 效率、ct-SR、stability/plasticity、奖励依赖性、离线数据来源等维度做了系统分析。

方法学启示：上下文窗口本身可作为学习基底——“经验回放”被落地为“结构化存储 + 列表式检索 + 提示拼接”，完全绕开梯度更新；其能跨模板泛化的机制内核有三：状态/动作先验分通道表示、变量化抽象的技能表示、自然语言 + 动作示例的双模态承载。评测协议上，stability/plasticity 值得被所有记忆型智能体工作沿用。

局限（论文自述）：需要目标导向轨迹，随机探索轨迹反而劣化；dynamics 的价值部分依赖 URL 直达这一 web 特有可供性，向真实世界导航等其他智能体任务的迁移待研究；online 设定冷启动阶段（首个任务）无法利用经验，offline/hybrid 仍依赖人工标注轨迹，如何高效生成轨迹是开放问题。

对音视频技术侧的映射（笔记分析，非论文主张）：

- **下游应用**：音视频生产/运营工具的自动化智能体（NLE 软件、DAM 控制台、直播后台、转码/QC 平台管理界面）与网页智能体同属 GUI 上的序贯决策。dynamics 可类比为“面板/页面索引 + 直达锚点”（对应视频章节、时间轴 seek 点），skills 类比为参数化操作宏（如“按 {preset} 批量转码并写回元数据”的逐步操作模板）。免训练意味着无需为每套内部工具单独微调模型，经验库随使用持续生长——对工具碎片化严重的音视频产线尤其现实。
- **上游依赖**：VWA 管线的 SoM 标注 + 图文 ID 对齐是屏幕内容理解/元素 grounding 的直接消费场景；若迁移到含视频时间轴、波形编辑器的界面，需把“元素 ID 引用”扩展为“元素 + 时间区间引用”，URL 式状态直达需替换为 seek/章节锚点。
- **成本参考**：+5.8%~+17.3% 输入 token 开销换取 36.7%~52.5% 相对成功率提升（WebArena 口径），可作为多模态智能体系统中“记忆增强模块”的预算基准；弱模型蒸馏质量下降（Llama-3.1-70B 增益缩水）提示小模型端部署时需对写入经验库的内容做额外校验。

## 7. 与其他论文的联系

- **Hippo（arXiv:2610.24453）**：同谱系工作。CER 明确以 RL 经验回放（Schaul et al. 2016；Rolnick et al. 2019）为灵感、免训练从经验自改进；Hippo 进一步引入海马体式选择性编码与回放，可视为对 CER“全量蒸馏 + 列表式检索”在写入选择性上的强化，二者对比焦点在记忆写入端的选择性策略。
- **HASP（arXiv:2605.17734）**：技能表示的升级路线。CER 的 skills 是“自然语言摘要 + 动作示例”的上下文内软引导；HASP 将经验技能固化为可执行程序函数并在易错状态主动干预，可理解为 CER 技能通道向可执行化、强干预方向的演化，代价是更高的程序合成与维护复杂度。
- **FGSE（arXiv:2611.14326）**：直接回应 CER 暴露的噪声经验问题。CER 的实验显示失败轨迹蒸馏带来 2.1pt 损失（§5.6 口径）、非结构化探索轨迹甚至误导决策（A.5）；FGSE 将经验教训作为可证伪假设、经探针验证后再写入记忆，正是 CER 缺失的写入端质量控制机制。
- **SkillDuet（arXiv:2611.12109）**：谱系另一端。CER 刻意纯上下文演化（零参数更新），SkillDuet 以响应反馈联合模型参数更新与外部技能库演化，实现技能级递归自改进；两者构成“上下文内经验 vs 参数 + 技能库协同”的对照，CER 的结果（上下文内即获 +51.0% 相对提升）为免训练路线提供了成本侧论据。
- **SAG（arXiv:2610.07335）**：同为 token 效率导向的在线自提升工作。CER 的 token 分析（输入开销 +5.8%~+17.3%）与 SAG 的免训练门控按需调用批评，在“以最小 token 开销换成功率”的目标上一致且机制互补（经验增强 vs 过程批判）。
- **Self-Improving for Zero-Shot NER（arXiv:2311.08921）**：跨任务域的同范式实例——免训练自改进 + 可靠样本筛选 + 检索式 ICL 增强；与 CER 的“无奖励蒸馏 + 检索回放”共享“以上下文为学习基底”的设计哲学，差异在 NER 侧以自一致性做可靠性筛选，而 CER 依赖自然语言经验的隐式过滤。
