## 1. 背景与动机

短视频流（TikTok、Kwai 一类）与传统长视频点播在传输控制问题上的本质差异，源于交互模式：用户随时滑动切换内容，客户端必须在**推荐队列**上做预取，而非在单一视频的码率阶梯上做选择。这使问题从经典 ABR 的"下一 chunk 选哪档码率"扩展为一个三元联合决策：**下载哪个视频、该视频选哪档码率、还是休眠等待**。预取过多虽能保障 QoE，但用户划走后该视频已下载未播放的 chunk 会被直接清空，造成带宽浪费；预取不足则在滑到未缓存视频时产生明显起播延迟与卡顿。因此 SABR（short video adaptive bitrate）的优化目标必须同时纳入 QoE 与带宽效率两项，论文沿用 ACM Multimedia 2022 短视频流大赛（MMGC2022）的 utility 口径：

U_i = Σ_m (R_m − S_m) − Σ_n μ·T_n − Σ_n ν·b_w_n

其中 R_m/S_m 为被播放 chunk 的码率及其波动，T_n 为卡顿时长，b_w_n 为下载 chunk n 的带宽占用，系数 μ=1.85、ν=0.5 按 MMGC2022 设定，所有对比方法保持一致以保证公平。这一目标函数本身就是音视频链路上下游信号的汇合点：码率项 R_m 由编码侧多码率阶梯决定，T_n 受 CDN 分发与网络吞吐约束，而预取价值则依赖推荐系统侧提供的用户留存率统计。

论文对现有两条技术路线的失败模式给出明确诊断。**规则/MPC 路线**的代表 PDAS（MMGC2022 总排名第一）将用户留存率引入 QoE 预测并用 MPC 穷举未来动作组合，但其超参数高度依赖上下文，在分布外网络与用户偏好下泛化能力差；且作为 MPC 变体，其贪心启发式搜索的推理时间随优化时域长度呈指数增长。**学习路线**的代表 DAM（MMGC2022 学习类第一，DRL + action masking）对"视频 ID × 码率档"的联合离散空间直接输出组合概率，动作空间大小与队列视频数和码率级数强相关，导致训练收敛极慢并易陷入次优。Incendio 的动机即在于此：通过子任务分解压缩动作空间、通过专家规则引导规避早期无效探索，同时保住 DRL 方法的泛化性与推理常数复杂度。

## 2. 方法总览

系统设定沿用 MMGC2022：每个短视频切为 1 秒 chunk，多码率版本存放于 CDN 节点；客户端维护一个含 5 个视频的队列（1 个当前播放 + 4 个推荐候选），**每个视频拥有独立 buffer**。用户滑动时，队列第二个视频开始播放，前一视频已下载未播放的 chunk 被清除（即带宽浪费的来源），同时新的推荐视频入队。码率阶梯为 {750, 1200, 1850} kbps 三档。

Incendio 的策略由两个层级 agent 顺序构成，对应 SABR 决策的两次解耦：

1. **BM-agent（buffer management）**：基于过去吞吐测量与队列中各视频的状态（留存率、剩余 buffer、chunk 平均大小），决策"休眠固定时长 τ=200 ms"或输出一个最需要缓冲的视频 ID；休眠则暂停整个预载过程。
2. **BA-agent（bitrate adaptation）**：在 BM-agent 给定视频后，结合该视频的码率历史、上次卡顿等信息，从三档码率中为下一个 chunk 选定码率。

客户端随后携带 组合向 CDN 发请求，进入下一轮交互。这一顺序分解使动作搜索从联合空间降为两个低维子空间：按论文动作定义推导，MMGC2022 设定下联合原子组合为 (5+1)×3 = 18 种（E2 设定 7 视频 6 档下为 8×6 = 48 种），分解后 BM 与 BA 仅各自面对 6 与 3（8 与 6）个动作——由乘性耦合降为加性，这是收敛加速的结构性来源。

训练采用两阶段范式：第一阶段以手工专家策略（基于 PDAS）做模仿学习预训练，把两个 agent 从随机初始化拉到专家水平；第二阶段用 MAPPO（multi-agent PPO）在共享奖励下联合微调至全局最优。整体采用 CTDE（centralized training, decentralized execution）：训练期两 agent 通过共享 critic 协作，推理期各自独立前向。训练完成后策略冻结，部署阶段纯前向推理。

## 3. 关键设计

### 3.1 状态与动作的差异化裁剪

全局状态 s_t = (b_t, l_j, g_j, u_j, h_j, q_j, f_j)，包含七类分量：

- **b_t**：过去 K=5 个 chunk 的吞吐测量（chunk 大小除以下载时长），K 为经验设定；
- **l_j**：视频 j 的条件观看概率，l_j = p_j^n / p_j^m，其中 p_j^m 为按 chunk 粒度统计的用户留存率（由内容提供商提供），m 为当前播放 chunk（推荐视频取 m=1），n 为目标 chunk。这一项把推荐系统的行为先验直接编码进传输决策输入，是 SABR 区别于经典 ABR 的核心状态量；
- **g_j**：视频 j 的当前 buffer 占用；**u_j**：视频 j 下一 chunk 在各码率下的平均大小（来自编码侧的 chunk 尺寸信息）；**h_j**：下载视频 j 最后一个 chunk 引发的卡顿时长（无则 0）；**q_j / f_j**：最后下载 chunk 的码率及其波动，f_j = |q_j − q_{j−1}|。

值得注意的是两个 agent 的状态视图刻意不同：BM-agent 只取 (b_t, l_j, g_j, u_j)——预取"选哪个视频"只关心队列级因子；BA-agent 在选定视频 j 上额外引入 (h_j, q_j, f_j)——码率决策需要感知卡顿历史与码率平滑约束。状态按 agent 职责裁剪，而非两者共享同一大向量，这与动作分解的设计哲学一致。

动作侧，BM-agent 输出长度 6 的 one-hot（5 个视频 ID + 1 个休眠，τ=200 ms）。休眠时长的设定是计算资源利用率与不错过理想决策时机之间的折中。BA-agent 从三档码率中取一。

### 3.2 网络结构

两个 agent 均为 actor-critic 架构。BM-agent 的 actor 用 **GRU（64 units）** 从过去 5 步吞吐序列提取时间特征；同时用**三层 2D 卷积**（kernel 5×5，输出通道 64/16/4）在按状态定义堆叠的多路输入向量（吞吐历史与各视频的 5 维因子向量构成的空间结构）上提取向量间"空间"特征；两路输出拼接后过 64 单元全连接，输出层 SoftMax 给出 6 维动作概率。全程 leaky-ReLU 激活。BA-agent 的 actor 把卷积部分替换为全连接层，其余保持一致，输出 3 维码率概率。

**Critic 由两 agent 共享**：拼接 BM 与 BA 各自 actor 的最后隐藏层，输出未激活的标量价值估计。这一共享 critic 是 CTDE 的具体实现——训练时集中式价值函数吸收了联合动作信息，使 MAPPO 的优势估计对非平稳环境（每个 agent 视另一 agent 的策略变化为环境变化）更稳健；推理时只需两个轻量 actor 前向。

### 3.3 阶段一：模仿学习预训练

专家策略的构造方式：用 PDAS 的 QoE 估计模型，基于**未来 chunk 上的真实吞吐**（训练期可得）对优化时域内所有可能动作组合估计 utility，取最大者作为专家动作；再将专家轨迹**拆分为视频 ID 轨迹与码率轨迹**两份子集，分别监督两个 agent。这个"轨迹拆分"步骤是动作分解思想在监督信号侧的对应物。

损失函数为标准交叉熵形式：L_IL = −Σ_t Â_t log π_θ(s_t, a_t)，其中 Â 为专家动作的概率指示列表（专家动作取 1、其余 0）；训练采用策略梯度方法，学习率 α=0.0001，BM 与 BA 使用相同损失。论文还提及引入了一种新的经验回放机制以提升样本利用效率，但正文未给出细节，复现时需注意此处信息缺口。

两个工程要点值得强调：其一，专家策略的作用被明确限定为**加速早期探索**，论文声明 PDAS 可替换为任意优秀规则方法——专家引导是初始化手段而非性能上限（上限由 RL 微调阶段突破，实验部分证实最终性能显著超过 PDAS 本身）；其二，该设计延续了 Loki（规则模型与学习模型融合）的思路，即在规则方法强的地方借规则之力，在其泛化弱的地方靠 RL 补足。

### 3.4 阶段二：MAPPO 微调与 reward shaping

微调使用 MAPPO（PPO 的多 agent 协作版本），损失为 clipped surrogate 目标加 GAE 优势估计，并附加策略熵正则项（权重 β，当奖励连续 100 个 epoch 无增长时衰减 β），以避免训练早期塌缩到次优确定策略。k ∈ {bm, ba} 对两个 agent 的损失求和。

Reward 设计是本论文最值得细读的机制点。训练奖励并未直接照抄评估用的 utility（式 1），而是改造为：

r_t = w_n · l_n · (R_n − S_n) − μ·T_n − ν·b_w_n

即在质量项上乘两个整形因子：**l_n**（chunk n 的条件观看概率）与 **w_n**（0/1 指示量，标记最后下载的 chunk n 最终是否被用户观看；训练时从用户留存率 trace 中随机采样用户行为，评估时则改回式 1 原始口径）。其机理是：若待下载 chunk 的留存概率显著低于当前播放位置，意味着用户大概率在播放到它之前就划走，质量收益项被压低，agent 为提高奖励会学会**暂停下载、等待条件概率回升**，从源头减少注定被清空的无效预取。这实质上把"带宽浪费"的惩罚从静态系数 ν 前移为对质量收益的概率性折扣，给了策略更密集的学习信号；同时训练目标与评估目标刻意解耦，避免整形项污染评测口径的公平性。

## 4. 实验结果

**设置**：使用 MMGC2022 提供的多视频模拟器，随机组合视频 trace（chunk 各码率尺寸 + 逐 chunk 用户留存率）与网络 trace。训练语料由 Oboe 与 FCC 公开数据集的网络 trace、以及 DUASVS（含数百万条记录的视频 chunk 统计与用户留存率）构成；语料随机 80% 用于训练（DAM 用同一训练集保证公平）、20% 用于测试。MMGC2022 自带数据集规模较小，仅用于评估（其网络 trace 分高/中/低带宽条件）。基线三个：MPC+fix-preload（RobustMPC + fix-preload 休眠机制，MMGC2022 官方 baseline，5 chunk 窗口）、DAM（学习类第一）、PDAS（总排名第一）。

**总体性能**：跨 MMGC2022 与 DUASVS×Oboe/FCC 两组测试条件，Incendio 平均 utility score 较 PDAS 提升 **53.2%**；卡顿（rebuffering）降低 **39.1%–61.8%**，带宽浪费降低 **34.9%–59.2%**（论文报告的相对基线方案的降低区间），在码率与平滑度分量上亦居首；CDF 曲线在全程保持领先，未见仅在某分段占优的锯齿现象。结论部分以"对 SOTA 超过 2 倍提升"概括该结果。

**基线失败模式分析**（这部分对理解设计动机很关键）：

- PDAS 在多数指标上优于 MPC+fix-preload（可视为更先进的 MPC 变体），但其 max-buffer 手工模型在带宽节省与码率波动控制上不如 DAM；更关键的是，在 DUASVS 视频 + Oboe/FCC 网络的分布外组合下 PDAS 表现为全部方案中最差——其在 MMGC2022 上精调的超参无法刻画新网络动态与新用户偏好分布，泛化短板被定量坐实。
- DAM 呈现明显的分段不稳定：QoE 高段（约 >0.8）性能尚可，低中段（<0.8）显著落后。训练日志给出直接证据：DAM 因多维探索空间过大而丢弃部分动作——**始终给推荐视频选中档码率、从不给当前播放视频选最低码率**。偏好高码率 chunk 直接推高了卡顿概率。这为大动作空间导致探索不全、陷入行为偏置提供了实例。

**训练效率**：DAM 在训练早期即落入次优策略，收敛到最终策略耗时漫长；Incendio 借助 IL 在约 **4k epochs** 内即达到专家级策略，随后 RL 微调阶段在此之上仍取得可观增益——两阶段训练的价值在此得到直接验证（专家不是终点，而是起点）。

**推理时间**（Intel Core i5-12500 @3.00GHz，重复数千次取均值，毫秒）：

| 环境 | MPC+fixed-preload | DAM | PDAS | Incendio |
|---|---|---|---|---|
| E1（5 视频 / 3 码率） | 0.6 | 0.4 | 7.1 | **1.0** |
| E2（7 视频 / 6 码率） | 11.8 | 0.4 | 318.1 | **1.1** |

MPC 类方法（MPC+fix-preload、PDAS）推理时间随队列视频数与码率级数增长呈指数级膨胀（PDAS 在 E2 达 318.1 ms，移动端不可接受），因为其决策需要穷举未来动作组合的期望收益；神经网络前向的 Incendio 与 DAM 则保持 1 ms 量级且对动作维度不敏感——Incendio 以与 DAM 同数量级的推理成本，换来显著更高的 SABR 性能与训练效率。

## 5. 消融要点

需要如实指出：论文**没有对 Incendio 自身组件做受控消融实验**（如"去掉 IL 只跑 MARL""合并两 agent 为单 agent"的对照组），消融性证据均来自与外部基线的间接对照，阅读时应注意证据强度：

- **两阶段训练的贡献**：训练日志对照显示，纯集中式 RL 的 DAM 早期陷入次优且收敛极慢，而 Incendio 经 IL 初始化后 4k epochs 达专家级、RL 阶段继续爬升。IL 的作用被论文定位为"减少早期无效试探 + 缓解次优风险"，但"无 IL 的 Incendio 会收敛到何处"未单独量化。
- **动作分解的贡献**：DAM 的行为偏置证据（固定中码率、从不最低码率）反证了联合大空间下探索不充分的代价；Incendio 的分解设计在结构上规避了该问题，但同样缺少"单 agent Incendio"的直接对照。
- **reward shaping 的贡献**：w_n/l_n 折扣因子对带宽浪费指标的作用有机理解释（暂停下载等待留存概率回升），且评估口径改回原始 utility 规避了自证循环，但论文未报告去掉 shaping 后的奖励曲线差异。
- **动作维度敏感性**：E1→E2 的推理时间对比可视为对决策空间维度的消融——MPC 类从 7.1→318.1 ms（约 45 倍），NN 类几乎不变（1.0→1.1 ms），支撑了"分解 + 神经网络策略天然可扩展"的论断。
- **未触及的超参敏感性**：K=5（吞吐窗口）、τ=200 ms（休眠时长）、熵权重 β 衰减策略、以及专家策略质量对最终性能上界的影响均未做敏感性分析，属复现与后续改进的开放点。

## 6. 贡献与启示

**贡献可归纳为四点**：(1) 首次将 SABR 的联合决策按"buffer 管理 / 码率适配"做层级化子任务分解，以 MARL（MAPPO + CTDE）实现分离决策下对系统级复合奖励的联合优化，动作空间由乘性降为加性；(2) 用 PDAS 式规则专家做 IL 预训练 + RL 微调的两阶段训练，同时解决收敛速度与次优风险，且最终性能大幅超越专家本身（53.2%）；(3) 训练奖励与评估目标解耦的 shaping 设计（w_n·l_n 概率折扣），把带宽效率约束转化为稠密的学习信号；(4) 在分布外网络/视频组合上验证了泛化性，并以 1 ms 级、维度无关的推理成本证明移动端可部署性。

**对音视频技术链的启示**：本文处在编码—CDN—推荐—客户端的交汇处。向上，它把推荐系统的用户留存率（内容提供商以 chunk 粒度统计提供）作为一等公民状态量与奖励信号，示范了"传输决策消费推荐先验"的标准做法；向下，其码率动作直接绑定编码侧三档阶梯与 chunk 尺寸表 u_j，方法对阶梯配置（如 E2 的 6 档）不敏感，意味着编码侧升级（更多码率档、更细 chunk 粒度）不会造成策略推理退化，这是相对 MPC 穷举类方案的关键工程优势。reward shaping 的"训练目标 ≠ 评估目标"做法，对任何需要在线指标公平对比的 ABR 研究都有方法论参考价值。

**局限**：专家策略质量仍是隐性变量（尽管论文声明可替换，未验证弱专家下的性能下界）；全部结论基于 MMGC2022 模拟器与公开 trace，与真实短视频客户端的 gap（推荐队列动态、真实留存率噪声、CDN 缓存命中）未讨论；推理期策略完全冻结，不具备在线适应能力；休眠为固定 200 ms，未学习可变等待时长。

## 7. 与其他论文的联系

- **paper:arxiv:2509.10486（SABR: Stable ABR via BC Pretraining and RL Fine-Tuning）**：与本论文构成同一训练范式的先后呼应——两者均采用"模仿/行为克隆预训练 + 强化学习微调"解决 SABR 任务中纯 RL 的慢收敛与泛化不稳问题，且都把对未见网络条件的泛化稳定性作为核心评价指标。本文可视为该范式在短视频 ABR 上的早期实证（2023），后者进一步以宽分布基准系统化检验了该范式的泛化收益。
- **paper:arxiv:2405.07759（MADRL-Based Rate Adaptation for 360° Video）**：同样以 MAPPO 作为码率自适应的多 agent RL 框架（结合多视点预测），与本文在算法选型上直接同源；两者共同印证 MAPPO 在流媒体多决策体分解场景（本文的 BM/BA 分解 vs 其视点级分配）中的有效性，但任务目标不同——本文是预取-带宽权衡，该文是视口内 tile 码率分配。
- **paper:arxiv:2610.13698（DIA: Interest-Aware ABR for Cloud Gaming）**：同属"用户兴趣信号驱动 ABR"路线——本文将用户留存率编码进状态与奖励，DIA 将用户兴趣（对象级显著度）编码进云游戏码率分配，均突破了传统 ABR 只看网络与 buffer 的信息边界；差异在于本文的兴趣信号用于跨视频预取取舍，DIA 用于单画面内的对象级码率分配。
- **paper:arxiv:2404.09905（QoE-Oriented Cross-layer Optimization for Real-time XR）**：在"用策略优化 RL（Transformer PPO）做码率自适应 + 引入额外层信息辅助决策"两点上与本文方法同构（本文的额外层是应用侧留存率统计，该文是基站侧无线调度信息）；但场景约束相反——XR 是超低延迟上行/下行实时流，本文是预取式点播流，延迟项在目标函数中的地位不同。
