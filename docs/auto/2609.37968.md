## 1. 背景与动机

LLM 编码智能体已经具备检视并改写约束自身行为之实现（指令、工具、执行流程）的能力，由此衍生出 DGM/HGM/Hyperagents 一类**评估引导的智能体搜索**范式：提出修改 → 在开发集上评估候选 → 用分数反馈指导后续搜索。论文指出该范式有两个结构性代价：其一，评估开销随任务覆盖与重复次数增长——每个候选都要在开发集上反复执行；其二，改进信号被绑定到被评估的任务分布上，搜索方向受开发集偏置。

本文的核心洞察是：一次自我修改除了产出候选智能体，还产出一份**修改过程记录**——其中包含智能体如何识别缺陷、构造修订、检验效果、应对失败。这份记录本身就是经验证据，可在没有任何下游评估信号的情况下指导后续自我改进。作者借元认知（Flavell, 1979）框架提出问题：智能体能否利用"自我改进这件事本身的经验"变得更擅长改进自己？

支撑这一设计的机理假设是：自我修改所锻炼的能力与下游任务能力存在重叠——检视陌生代码、诊断失败、实施变更、验证效果。episode 记录把这些活动的痕迹固化为可读证据，因此即使智能体从未接触下游任务，这些证据也已足以驱动有用的修订（典型例子：检视超长记录被截断的困难，会促使智能体发展出可复用的检索工具）。

需要精确理解的口径：SelfSearch 的 "reward-free" 指搜索期间不使用任何下游基准任务或评估结果来指导修订，也不做基于分数的候选选择；但 episode 内智能体仍可使用工具交互结果与本地检查来验证自己的修改。下游评估与选择整体后置到检查点冻结之后——这把"候选生成"与"下游评估"解耦，使评估成为一次性、外置的步骤。

## 2. 方法总览

**形式化**：B₀ 为初始智能体，实现为一个仓库（指令、工具、执行逻辑、代码组织）；模型权重固定，仓库全量可编辑。第 k 回合满足 (B_{k+1}, e_k) = SelfImprove(B_k; E_k, d)：B_k 收到自身仓库的**可编辑副本**与此前回合的**只读记录** E_k，检视记录、决定改动、编辑并验证。正在运行的智能体在回合内保持不变（编辑作用于副本），其编辑定义后继 B_{k+1}；回合产出记录 e_k = 轨迹（推理、工具动作及其结果）+ 代码变更。d 为定性搜索方向。关键闭环在于：后继 B_{k+1} 执行下一回合，因此它对自己工具与流程的修改会反过来改变后续自我修改的执行方式——"经验"与"改进能力"共同演化。

**世代与谱系**：每个世代每条谱系执行一个回合。系统维持两条并行谱系——capability（能力）与 adaptive（适应）——各自保留自己的实现，但**共享上一世代的全部（两条）回合记录**，使每条谱系能吸收另一方向的发现而不合并实现。为给第一世代提供具体经验，先用 B₀ 在两个方向下各跑一次产生初始记录 E₀，保留记录但丢弃编辑出的实现，两谱系从同一 B₀ 出发。共运行十个世代；所有生成个体进入档案 C 备评估。评估只取每条谱系的最终世代个体（不按下游表现挑选检查点），报告个体结果与总体均值（两谱系成功率之均值）。

**搜索环境与边界**：episode 在无网络访问的隔离容器中执行，支持并行工具调用。模型-工具交互循环运行于可编辑仓库之外的**固定 runtime**，由 runtime 锁定模型、推理力度、输出上限与执行预算，智能体经共享接口 respond(message) 调用。轨迹由 runtime 在可编辑仓库之外记录，连同修改前后的源码快照存档，后续回合以只读方式挂载。该边界设计一石二鸟：实现持续演化时轨迹捕获方式保持稳定；同时搜索完整性有保障——智能体无法篡改推理设置、资源预算与自己的证据链。

**可移植性**：同一冻结实现跨基准评测不改源码；基准适配器提供任务指令与环境访问，环境搭建与评分均在智能体仓库之外。

## 3. 关键设计

**双搜索方向**。capability 方向要求从"低效行为、失败动作、难以完成的操作"中识别能力缺陷并发展可复用工具或流程，并明确两条纪律：当指令本身无法提供缺失的操作时优先做机制而非加指令；避免把智能体特化到自我改进 episode 上。adaptive 方向要求改进"当动作失败、证据与假设矛盾、或更优策略显现时如何调整方法"，强调保持跨任务灵活性、不得用关键词或固定工作流做行为路由。两个方向只引导调查范围，不对改动打分——这是与评估引导搜索的本质区别。

**搜索提示的工程契约**。提示由目标 + 设计指导 + 方向三段拼装。环境契约规定：智能体包必须从 `__init__.py` 导出 `agent`（`Agent` 实例）；`agent.run(task: str)` 接收任务并返回字符串；每次评估在全新隔离执行中导入返回的包；`@tool` 由名称、类型标注与 docstring 定义 schema；`/app/agent` 为当前正在执行的只读智能体，`/workspace` 起始为同源可编辑副本，编辑只影响返回的后继而不影响当前执行。流程段规定证据访问路径：`/evidence/0` 与 `/evidence/1` 存放前两次编辑执行，入口 `index.json` 链接事实摘要、最终陈述、编辑、轨迹与源码快照；要求"基于证据确定最有后果的缺陷或机会，开发一个连贯修订（必要时可跨组件）"。提示中的反过拟合条款值得注意："保持行为跨任务广泛有用，不要把一次执行的情境变成普适要求"；"谨慎使用额外的 self.respond 通道（每次都带来大量经常性成本）"。

**模型差异化目标与设计指导**。GPT 目标聚焦"提升改进智能体（含自身）的能力"；DeepSeek 目标为"提升预期任务求解能力（含改进智能体的能力）"，并附加设计指导：新增模型可见工具时必须验证智能体实际会产生的**精确调用形态**（"有效的实现或 schema 本身不充分，优先选择模型能可靠使用的接口"）；簿记与规划应与任务规模成比例；不得在返回的智能体内复现宿主的搜索/评估/编排。这些条款是对自改写智能体典型失败模式（造出自己用不上的工具、复制宿主逻辑）的直接防御。

**预算与配置**。搜索期每回合上限 513 次模型调用、512 工具步、4 小时；单次调用输出上限 GPT-5.6 Sol 为 8,192 token、DeepSeek V4 Pro 为 16,384；均 medium 推理力度、温度 1。下游执行用 GPT-5.6 Luna / DeepSeek V4 Flash，medium、温度 1、单次输出 16,384。

**初始智能体**：改自 DGM 发布实现，保留 shell 执行与文件编辑器（view/create/整文件替换），新增可编辑策略库（通用任务、编码、自我改进三类指令）；episode 开始时下发策略目录，按任务加载相关指令与配套工具。同一实现同时承担下游任务与自我修改——这是"统一元智能体与任务智能体"的落点（附录 F 的对比表中，SelfSearch 是唯一同时满足"演化任务智能体 + 演化元智能体 + 角色统一 + 免奖励搜索"四项的方法）。

**评估集**：SWE-bench Verified 120 题（DGM small+medium 子集 60 题 + 从其 large 子集抽 60 题）；SWE-bench Multilingual 60 题（seed 42，八语言：C 6 / C++ 2 / Go 8 / Java 9 / JavaScript 9 / PHP 9 / Ruby 8 / Rust 9）；Terminal-Bench 2.1 全部 89 题。

**评估引导基线**：linear search（始终修改最新候选）与 archive search（父代从 B₀ 与已完成候选中选；首次修订共享，此后偶数次修订均匀采样父代、奇数次选最高分父代、平局取最早）。两基线用 DGM 十题 small 子集做开发集，编辑者可读父代在该集上的完整记录（题面、轨迹、补丁、结果、官方测试及输出，官方测试仅在任务执行后可得），做十次修订，按开发分最高选择（平局取最晚）；GPT 下选中修订号为 8/10，DeepSeek 为 6/9。对比时从 120 题 Verified 评测集中剔除这十题开发任务（剩 110 题）。

**成本口径**：单任务平均执行成本 = 总模型执行成本 / 尝试任务数（**含失败尝试**）；共享成功成本降幅只在两智能体均解出的任务子集上计算。定价（每百万 token，输入/缓存输入/输出）：GPT-5.6 Luna $0.20/$0.02/$1.20；DeepSeek V4 Flash $0.15/$0.003/$0.60。执行成本不含搜索成本；基线搜索成本含编辑 + 开发集评估，SelfSearch 搜索成本只含自我改进 episode——两端口径不同但各自完整。

## 5. 消融要点

两个机制消融在 SWE-bench Verified 上进行（第 10 世代个体）：

| 方法 | GPT c / a / 均值 | DS c / a / 均值 |
|---|---|---|
| 初始 B₀ | 75.0 / 75.0 / 75.0 | 81.7 / 81.7 / 81.7 |
| 去除 episode 记录 | 75.0 / 73.3 / 74.2 | 82.5 / 85.0 / 83.8 |
| 固定改进者（B₀ 永远当编辑者） | 73.3 / 75.8 / 74.6 | 82.5 / 85.0 / 83.8 |
| 完整 SelfSearch | 77.5 / 75.0 / **76.2** | 86.7 / 86.7 / **86.7** |

按论文文本口径：去除记录使均值降 2.1 pp（GPT）/ 2.9 pp（DeepSeek）；固定改进者降 1.7 / 2.9 pp（表中四舍五入均值分别为 76.2−74.2 与 76.2−74.6）。两点解读：其一，"经验通道"与"演化改进者"两个机制各有独立贡献且方向一致，支持"后继自己做下一轮编辑"这一设计（即改进过程中发展出的工具会反哺改进过程本身）；其二，效应量仅 2–3 pp，且每条件只跑一次搜索、无方差信息，论文讨论亦自承"增益在独立搜索间的一致性"是待检验问题——消融结论应作方向性而非精确量级解读。另注意 GPT 固定改进者在 adaptive 谱系上略优于完整版（75.8 vs 75.0）。

**改动谱系分析**给出机制层面的证据。GPT 谱系：第 6 世代 capability 引入带输出上限的文本搜索、adaptive 引入结构化轨迹读取器；第 7 世代两谱系通过对方的 episode 记录互相吸收对方的工具（adaptive 甚至用自己的轨迹读取器先检视 capability 的记录再复制其搜索实现与测试）；第 8 世代发现"多个短摘录拼接仍可超长"进而加总体输出上限；第 9–10 世代继续加过滤、工具名查找、调用参数与结果的跨页链接。DeepSeek 谱系呈现典型的"失败驱动的交叉修复"：第 5 世代 adaptive 用保头保尾截断长行，可能截掉行中匹配文本；第 6 世代 capability 读其记录后将摘录改为以匹配位置为中心；第 7 世代 adaptive 复现该失败、吸收修复并验证匹配文本可见。后续世代处理文件操作的保真问题（tab 保留、换行符保留、二进制文件检查、临时文件碰撞修复）。

**演化工具的下游复用**（两终末个体在 269 题上的调用统计，按任务计一次）：文本搜索工具在 GPT / DeepSeek 智能体的任务上分别用于 8.6% / 23.6%（两谱系均值），行区间文件查看用于 40.3% / 33.8%，且跨基准分布；精确文本替换在 SWE-bench 两基准上使用率达 72.5–100%。相反，GPT 的轨迹读取器在下游评估中零调用——部分演化产物是纯元能力（只服务自我改进）。这构成"自改写经验迁移到任务能力"假设最直接的证据链：一个为检视 episode 记录而生的搜索工具，后来被用于在下游代码库中定位函数引用与相关测试。

## 6. 贡献与启示

论文的三项自述贡献：（1）把自我改进过程本身当作经验源，提出不依赖下游评估的 episode 记录驱动搜索，后继即下一个改进者；（2）在两模型设置 × 三基准上证明总体均值成功率的稳定提升，附带执行成本缩减与跨模型族 harness 迁移；（3）通过消融与轨迹分析解释改进来源——记录通道与演化改进者均必要，工具在谱系间与"自改进→下游"两个方向上复用。

工程层面的启示： 搜索与评估解耦后，$4.03 的搜索成本即可产出与公开评测头部 harness 打平的产物，说明 harness/scaffold 层是极高性能价格比的优化面，且该层改进具有跨模型的稳健性； 搜索期零基准接触，天然规避了开发集过拟合与任务分布绑定——代价是没有过程内质量闸门，候选方差只能靠事后评估消化； 论文自己指出的组合方向很有价值：在评估引导搜索的框架内，用 SelfSearch 把单次修改步骤扩展为若干个由 episode 记录指导的修订世代，再对外评估决定去留——生成与选择互补。

局限：总体均值提升但个体谱系表现不稳定（GPT Ba 在 Verified 上与 B₀ 持平、在对比实验中混合）；消融与主实验均为单次搜索，无跨独立搜索的方差报告；两谱系、十世代的搜索规模较小，方向提示词经过试点打磨（提示工程对结果的影响未量化）。

**与音视频技术的关联（引擎定位说明，非论文内容）**：本文无任何音视频直接实验。其可迁移性在于工程范式层面：其一，SWE-bench Multilingual 覆盖的 C/C++/Rust/Go 正是编解码器、流媒体服务端与媒体基础库的主流实现语言，SelfSearch 这类"智能体改写自身 harness 并沉淀可复用工具"的机制可平移到媒体软件栈的自动化维护与缺陷修复场景；其二，音视频下游评估（主观质量评测、线上 A/B、编解码回归测试）恰恰是典型的高成本评估，"reward-free 搜索 + 事后一次性评估"的成本结构对该领域有直接吸引力。以上为引擎基于论文范式的推断，论文未做相关验证。

## 7. 与其他论文的联系

- **paper:arxiv:2611.10787（TRUST）**：SelfSearch 搜索期不接触下游评估、也不做世代间候选选择，改进质量缺乏过程内保证，Discussion 自承增益一致性需跨独立搜索检验；TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证，恰好补上 SelfSearch 这类免奖励搜索最缺的质量闸门。两者是"低成本生成"与"可信筛选"的天然互补组合。
- **paper:arxiv:2611.14326（FGSE）**：同属"把改进过程经验固化为可复用资产"的路线。SelfSearch 的 episode 记录无条件只读挂载给后继；FGSE 则将经验教训视为可证伪假设、经三类探针验证后才写入记忆。SelfSearch 消融显示记录通道价值 2–3 pp，但其记录未做任何有效性过滤——FGSE 的证伪门控是对这一经验通道的直接增强方向。
- **paper:arxiv:2611.10463（LongCapHarness）**：两者都在 harness 层做免后训练搜索并强调低成本（LongCapHarness 成本低于基线 50% 且超越基线；SelfSearch 以 $4.03 搜索成本在 Terminal-Bench 2.1 九方对比中与最优 harness Codex 打平 82.0%）。差异在搜索信号源：前者以能力引导挂接长上下文底层能力，后者用自我改进经验替代评估信号；共同结论是 harness 层是高性价比优化面。
- **paper:arxiv:2611.12109（SkillDuet）**：递归自改进坐标系上的对偶路线。SkillDuet 以响应反馈同时更新 LLM 参数与外部技能库（动权重、任务级反馈）；SelfSearch 固定权重、只改 scaffold 仓库，反馈源是自改写 episode 而非任务响应。可组合点明确：SelfSearch 演化出的工具（文本搜索、行区间查看、精确替换）正是可沉淀进技能库的技能粒度资产。
- **paper:arxiv:2611.07319（WeightLoop）**：权重空间与代码空间的自我改写对照。WeightLoop 让 LLM 生成有界参数编辑程序持续改写已部署模型权重、免重训练；SelfSearch 同样免重训练，但编辑对象是仓库实现，且编辑者自身随世代演化（改进者也被改进）。两者共享"部署后持续自改进、不进入训练循环"的工程约束。
- **paper:arxiv:2611.14949（RSI-PDEbench）与 paper:arxiv:2611.11558（InfraRSI）**：领域特化 RSI 的两个实例（PDE 求解、训练基础设施），其共同痛点是下游评估昂贵（PDE 数值验证、分布式训练实测），正是 SelfSearch 免奖励设定针对的成本结构；将 SelfSearch 作为其智能体框架内的候选生成器，是可直接检验的组合方式。
- **paper:arxiv:2610.33845（AutoTavern）**：同为自我改进循环，但 AutoTavern 是 20 天量级的开放自主演化（含模拟器构建），SelfSearch 是十世代、四小时/回合上限、边界受控的短程搜索——代表自改进谱系中"开放演化"与"受控搜索"两端的工程取舍。
