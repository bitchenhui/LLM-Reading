## 1. 背景与动机

本文属于 LLM 数学推理 / 测试时自改进方向，核心问题是：现有 self-correction 方法把“纠错”当作生成后的独立精修步骤，依赖额外 prompt 与系统层编排来触发和终止纠错，而不是在单次推理过程中实时、自发地完成自我纠错。作者将现有范式归纳为两类“闭环”形态： 其一为纯纠错式闭环——Solution→Revise request→Solution 循环，每轮都需要外部注入 revise 指令；其二为验证+纠错混合闭环——需要外部注入 reflection request 才触发验证，验证后再由外部决定是否发起重写。两类范式的问题在于：触发与终止逻辑外置于模型，部署时需要额外系统设计（在推理管线中插入 prompt、判断循环退出条件），且测试时算力扩展不灵活。

作者进一步指出该方向的既有困境：纯 prompting 式自纠错（Huang et al., 2023; Qu et al., 2024）在没有外部反馈时改进甚微甚至退化；依赖 oracle 标签的方法（Shinn et al., 2023）在真实场景不可用；微调式方法（Saunders et al., 2022; Kumar et al., 2024; Qu et al., 2024）虽从人类标注、强教师或模型自身收集精修数据，但仍需在每条模型回复后接一个特定触发 prompt。多智能体框架（AutoGen、debate 类）虽然引入多角色，但缺少针对各角色的后训练，推理时存在分布漂移风险；训练独立纠错器的工作（RL4F、MALT 等）同样无法在解生成过程中自发纠错。

由此提出 SPOC（SPontaneOus self-Correction）：让模型在单次推理内交替生成“解”与“验证”，验证判定错误则自发重写，验证通过则自发终止——即“开环”范式，触发与终止完全由模型内禀能力决定，无需任何外部干预，从而把测试时算力扩展变成模型自身可学习的行为。对音视频领域的读者而言，这类“把外置控制循环内化为模型行为”的思路，与流式场景下希望模型边生成边自检（而非生成完再交给外部裁判重跑）的诉求同构，具有一定的上下游借鉴意义（详见第 6 节）。

## 2. 方法总览

SPOC 是“合成数据 SFT 引导 + 在线 RL 强化”的两阶段流水线，训练目标是让单一模型 πθ 在共享参数下扮演两个角色：解提议者与验证者。

**形式化**：给定数学问题集 D = {(xᵢ, yᵢ*)}，模型生成轨迹 τ = (y₁, v₁, …, y_L, v_L)，其中 y_l 是第 l 次完整解题尝试（到达最终答案），v_l 是对 y_l 的自验证（输出 Yes/No 二元结论外加简短错误说明）。作者将此建为扩展式博弈：n=2 个玩家（proposer/verifier），动作空间为 LLM token 空间，状态为上下文中的问题与已生成的解/验序列；由于数学推理的动态确定性与完美信息性质，不区分 history 与 state。关键设计是**参数共享的自博弈**：π^sl 与 π^vf 共享同一套 θ，模型依据上下文（当前该出解还是该验证）切换角色。作者特别注明这不同于 AlphaZero 式零和对称自博弈——两个角色的策略以上下文为条件是非对称的。

**优化目标**：KL 正则化目标 J(θ) = E[Q^π(s,a)] − η·E[KL(πθ‖πθ0)]，其闭式最优解 π*(a|s) ∝ πθ0(a|s)·exp(Q(s,a)/η)。由于参数共享，proposer 与 verifier 的两个个体目标用同一批生成轨迹经验联合优化。

**奖励设置（Corr）**：假设可访问基于规则的答案检查器，解消息奖励 r^sl(y, y*) ∈ {0,1}（答案匹配即 1）；验证消息奖励 r^vf(v, v*) ∈ {0,1}，其中 ground-truth 验证 v* = r^sl(y, y*)。联合奖励下，博弈存在唯一 Nash 均衡，对应共享策略同时产生正确解与正确验证。

**两阶段流程**： 阶段一 PairSFT：用初始模型自采样构造合成多轮纠错数据做 SFT，使模型习得多轮交替回复格式并初具验证能力； 阶段二 message 级在线 RL（默认 RAFT，可选 RLOO 变体）：以解正确性与验证正确性为奖励继续优化。

推理时（评估）不注入任何“请再试一次”式指令，模型在一条响应内自发输出：解①→reflection（验证）→若 No 则解②→reflection→……→验证通过后以终止 token 结束。

## 3. 关键设计

**（a）PairSFT 数据构造（Algorithm 2 的机理要点）**

对每个问题从基础模型 πθ0 采样 K 条单轮解 {yᵢ^k}，用规则检查器标注二元正确性。核心技巧在于**验证消息的构造方式**：要生成某条解（无论对错）的验证，把该解与一条采样到的正确解配对，prompt 同一个基础模型“识别潜在错误、两句话内简述、输出 Yes/No 结论”——即 D_pair = {(x, y⁻, v⁻, y*)} ∪ {(x, y⁺, v⁺)}。这与 generative critic（Zhang et al., 2024; Zheng et al., 2024）的“先理由后判分”思想一致，但刻意做了简化：只简述错误而非完整 COT 分析，作者明言强 COT 验证器需专门训练、超出本文范围。SFT 时对不正确消息的 token 做 mask。采样层面有两个约束：若某题全对或全错（best/worst-of-N 同为对或同为错）则跳过该题；每题的正/负样本各凑齐至少一条即停。

工程上最值得注意的一条经验：**把 {(x, y⁻, v⁻, y*)} 与 {(x, y⁺, v⁺)} 两个子集重加权到近似同等规模**，得到的 πθsft 验证精度更高、后续 RL 训练更稳定。不依赖任何强教师蒸馏，全部数据来自初始模型自身。

**（b）Message 级在线 RL 与两种优化器**

训练循环（Algorithm 1）：采样 batch 问题→每题 rollout K 条完整多轮轨迹→对轨迹中每个消息打二元奖励（验证的真值由对应解的规则检查结果给出）→任意策略优化算法更新。默认 RAFT（Dong et al., 2023）：按最后一条解消息选 best-of-N 轨迹，并过滤掉所有采样解全错或全无正确验证的问题（在 CGPO 约束框架下实现），再做一步 SFT 式梯度更新。RLOO 变体（Algorithm 4）：把 leave-one-out 换成消息级 reward 的 z-score 标准化——对每个 (问题， 轮次， 角色类型) 组合，在 K 条 rollout 上计算均值 μ 与标准差 σ，advantage = (r−μ)/σ，全部 K 条样本都参与更新，样本效率优于 BoN 选择。RLOO 变体在每个解/验证步骤上施加过程奖励，实验中在强底座上带来更大幅度提升（见第 4 节）。

**（c）消息级终止 token 协议**

为支持单次响应内的多消息结构，每个 assistant 消息以 assistant header tokens 开头、以 `<|eom_id|>` 结束，仅最后一条消息以 `<|eot_id|>` 结束整条响应。这是“开环自发终止”得以实现的关键工程基础——模型自己学会在验证为 Yes 时输出 eot 终止、为 No 时输出 eom 继续新一轮解题。评估模板中也只描述一次该协议（每次解题尝试后于 `<reflection>...</reflection>` 标签内自省并以 “Verification: ... (Yes/No)” 收尾，若 No 则换方法或纠错重写），不额外干预。

**（d）奖励配置的博弈论设计**

三种配置对比（Figure 3 语义）：**Corr**（默认）——解与验证各自按其正确性独立计分（双 1/1 均衡唯一）；**Last**——仅当最后一条解正确时给分，且验证不单独计分，实质是“只看最终结果”；**All**——仅当最后解正确时，之前所有正确解与正确验证统一计分。Last/All 不再有唯一 Nash 均衡，只鼓励“无论如何产出正确解”。消融显示 Corr 在三项任务中的两项占优（见第 5 节），印证联合优化解正确性与验证正确性的必要性。

**（e）迭代训练**：PairSFT→RL 可叠代执行，第二轮仍有整体一致的小幅提升，且在难题基准上增益更大。

## 4. 实验结果

**设置口径**：基座为 Llama-3.1-8B/70B-Instruct、Llama-3.3-70B-Instruct、DeepSeek-R1-Distill-Llama-8B/70B；训练数据 NuminaMath（剔除未人工校验的 Orca-Math 与合成子集）；基准 MATH500（500 题）、AMC23（40 题）、AIME24（30 题）；指标为 pass@1 最终答案精度，greedy 解码 + zero-shot COT；Llama 系最大生成长度 6144 token，R1-Distill 系 32768 token。训练用 32×H100，AdamW（β₁=0.9, β₂=0.95, weight decay 0.1），常数学习率 1.0×10⁻⁶，全局 batch 2048，训练 256 步。

要点解读： SPOC 在全部基座、全部基准上一致超过基座；Llama-3.1 8B/70B 上 MATH500 分别 +8.8/+11.6，AMC23 +10.0/+20.0，AIME24 +3.3/+6.7。 基座越强，SPOC 边际收益越小的趋势被 RLOO 打破：R1-Distill-70B + SPOC-RLOO 达到 94.6/92.5/76.7，文中说明与 R1 系原始评测的差距源于 tokenizer 与 chat 配置不同（R1tok-avg@4 口径下 R1-Distill-8B 为 88.9/92.5/48.3、70B 为 94.3/94.4/65.9，SPOC-RLOO 与之同量级或更高）。 对比 S²R 系列方法（GRPO 为 RL 算法），SPOC 用更简单的 RAFT 在 Llama-3.1-8B 同设定下即超过 S²R-ORL（MATH500 61.0 vs 55.0）。 Self-Refine 无 oracle 时显著退化（8B 上 MATH500 39.4，低于基座 52.2），印证纯 prompting 自纠错的脆弱性；带 oracle 的 Self-Refine 在 8B 上 MATH500 57.0，仍低于 SPOC 的 61.0。

**轮次动态（MATH500）**：8B 上 turn1→turn2 精度 59.0→61.0（+2.0），错误→正确翻转 18/79，正确→错误 8/29；70B 模型 turn1 已接近终值（77.0→77.4）；3.3-70B turn1/turn2 均为 77.8。8B 最多跑到 6 轮，70B 系最多 3 轮；需要追加解的题量随轮次递减，符合“循环至验证通过”的收敛行为。验证器可靠性诊断显示：任务越容易、提议者精度越高，验证器 TP/FP 越高、TN/FN 越低；8B 的高验证精度主要来自高 TN。

**迭代训练**：第二轮 PairSFT→RL 在 Llama-3.1-70B 上 AMC23/AIME24 分别 +10.0/+6.7（52.5→62.5 / 23.3→30.0），Llama-3.3-70B 上 MATH500 77.8→79.8、AIME24 23.3→30.0。

## 5. 消融要点

奖励配置消融（Llama-3.1-8B-Instruct，pass@1）：

| 配置 | MATH500 | AMC23 | AIME24 |
|---|---|---|---|
| SPOC-Corr（默认） | **61.0** | 32.5 | 6.7 |
| SPOC-Last | 59.8 | 27.5 | **10.0** |
| SPOC-All | 58.4 | **35.0** | 6.7 |

Last 与 All 两种退化奖励（不构成唯一 Nash 均衡、只鼓励产出正确解而不约束验证正确性）虽仍优于基座，但在三项任务中的两项劣于 Corr；Last 在 AIME24、All 在 AMC23 上仅比 Corr 多对一题，而 MATH500 上的差距（61.0 vs 59.8/58.4）主导了总体差异。结论：**解与验证的联合正确性优化是必要的**，单纯“以结果论英雄”的奖励会把验证器学歪。

此外虽未列为正式消融表，但正文中两条准消融结论同样关键： PairSFT 阶段的正负样本子集重加权（数据平衡）直接决定验证精度与 RL 阶段稳定性——作者将其列为三点主要贡献之首； RAFT 与 RLOO 的对比（R1-Distill 底座上 RLOO 全面大幅领先，如 8B MATH500 87.2 vs 77.6）表明消息级过程奖励 + 全样本利用优于 BoN 式选择，尽管 RAFT 在弱底座上已够用且实现更简单。

## 6. 贡献与启示

**学术贡献**： 把自纠错从“外置闭环编排”推进到“内生开环行为”，形式化为共享参数的非对称自博弈 EFG，并证明 Corr 奖励下存在唯一 Nash 均衡，为“同时学好解与验证”提供了博弈论依据； 端到端无需强教师蒸馏：初始模型自采样的 Pair-SFT 变体即可引导出交替多轮行为，其中“正确解与错误解配对生成验证 + 正负子集重加权”是可复用的数据配方； message 级 RAFT/RLOO（尤其带过程奖励的 RLOO 变体）在强推理底座上释放出大幅增益（R1-Distill-70B 上 MATH500 82.8→94.6），说明自验证/自纠错维度仍有可观的可优化空间。

**对音视频技术上下游的启示**（跨领域视角）：SPOC 的本质贡献之一是把“多轮外部编排（生成→裁判→重试）”压进单次模型前向，这在流式/实时音视频管线中有直接类比——例如流式 ASR/翻译/字幕生成中，外挂验证器-重写循环会引入不可接受的延迟与系统复杂度，而“模型自发在消息内验证并决定是否重写”的协议（eom/eot 终止 token + 标签化自省输出）提供了一种低编排成本的测试时算力扩展模板；其“规则可验证奖励 + 自采样数据平衡 + 消息级 RL”的训练配方，也适用于任何存在可程序化校验信号的模态（如结构化媒体描述生成、代码化视频处理脚本），前提是该域能构造等价于数学答案检查器的 verifier。局限方面：本文仅在数学域验证，验证器是简版（非 COT）判别，作者自己指出长 COT 链上的部分解纠错与步级过程奖励是未来方向；对音视频类长输出，单消息粒度可能过粗，需向步级/片段级验证演化。
