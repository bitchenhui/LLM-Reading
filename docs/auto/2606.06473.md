## 1. 背景与动机

论文处于 LLM agent 长程自治任务（AI for Science、自动化实验、端到端算法设计）这一快速演化的大类，核心命题是：在开放搜索空间和有限时间预算下，让 agent 具备"持续自进化"能力——不断生成方案、执行代码、依据反馈调整策略、并跨时间积累经验。Machine Learning Engineering（MLE）被选作代表性场景：任务形式化为在结构化解空间 S 中找 s* = argmax_{s∈S} h(T,s)，其中每个节点是一份覆盖预处理、特征工程、模型训练与预测的完整候选方案，h(T,s) 为任务相关指标（accuracy/AUC/loss 等）。

作者对现有 MLE agent 的批评收敛为三条，并逐一对应本文三大组件：

1. **孤立探索 + 非自适应探索策略**。贪心/演化搜索（AIDE、FM-Agent）易陷局部最优；树搜索类方法（ML-Master、AIRA-Dojo 用 MCTS，MARS 用预算感知 MCTS）把信息锁死在单个分支内，且全程固定探索常数，在有限预算下后期仍把资源浪费在低价值分支上。→ 对应 Progressive MCGS。
2. **低效经验复用**。多数框架只向后代传播标量奖励；带记忆的方法（AutoMind、Leeroo 的知识库是静态的；ROME 存"reasoning gradients"动量记忆；MARS 靠对比反思；ML-Master 2.0 用层级认知缓存）普遍需要额外 LLM 调用做反思/总结，缺乏搜索过程中的自动经验累积。→ 对应 Retrospective Memory。
3. **规划与代码一次性耦合**。每次迭代整份重写方案（如 AutoMLGen 等被点名的做法），不区分"改什么"与"怎么实现"，迭代效率低且修改不可控。→ 对应 Planner-Coder 解耦 + 自适应编码模式。

两点定位澄清值得注意：其一，与经典 Monte Carlo Graph Search（AlphaZero 系的状态合并式 MCGS）不同，本文的图结构**不用于压缩状态空间**——开放式的 LLM 代码生成中几乎不存在可合并的相同状态——而是通过动态引用边实现跨分支信息流、轨迹复用与方案组合；LocAgent/CodexGraph 一类图方法则把图当作静态依赖表示供检索，图本身不随搜索演化。其二，评测覆盖面与音视频技术直接相关：主基准 MLE-Bench 的 75 个 Kaggle 任务横跨 NLP、计算机视觉、信号处理（含音频）与表格分析，框架在多个音频多标签分类与图像任务上有实跑案例（见第 4 节），因此该工作可视为"音视频模型管线自动化设计"的一次系统化尝试。

## 2. 方法总览

MLEvolve 是一个 LLM 多 agent 框架，运行在 Plan → Generate → Execute → Evolve 的闭环上，输出 solution.py、submission.csv 及 top-k 候选，最终取图级 top 节点做集成提交。三组件构成：

- **Progressive MCGS（§3.2）**：把树搜索扩展为有向图，通过引用边打通跨分支信息流；引入熵启发的渐进式调度，随时间从广探索软切换到精英导向的集中开发。
- **Retrospective Memory（§3.3）**：静态领域知识库负责冷启动先验，动态全局记忆在搜索中自动累积结构化记录（plan、代码、指标、分析），供规划与调试阶段按需检索复用——全程不需要额外 LLM 做显式反思。
- **Hierarchical Planning + Adaptive Code Generation（§3.4）**：Planner 在模块级决定"改什么、为什么改"，Coder 在代码级决定"怎么改"，并按搜索状态在全量重写、逐模块生成、diff 补丁三种粒度间自适应选择。

框架由 9 个专门 agent 落地：Draft（根节点初始方案，可查知识库）、Improve（迭代精化，通常走 Diff 模式）、Debug（仅执行失败时触发，按错误迹做最小修复）、Evolution（分支内演化，聚合同分支最近节点提取经验）、Fusion（跨分支引用，停滞时引入他分支强解）、Aggregation（全局停滞时聚合多分支 top 轨迹开新分支）、Code Review（执行前查命名/导入错误、可疑模式与指标一致性）、Data Leakage（检查训练/评测切分泄漏，防止虚高分数）、Result Parse（解析执行日志回传结构化信息）。

工程资源口径：所有 agent 共用一个主干 LLM（主实验 Gemini-3.1-Pro-preview，温度 1.0），每任务上限 500 个扩展步、12 小时墙钟，运行于 21 vCPU + 234 GB RAM + 单张 NVIDIA H200。

## 3. 关键设计

### 3.1 图结构搜索空间：双边缘类型与统一扩展算子

搜索空间组织为有向图 G=(V,E)，E = E_T ∪ E_ref：

- **主边 E_T**：(u,v)∈E_T 表示 v 由父节点 u 经算子 o 生成，即 v = g_o(u,R)。主边保留父子生成序，是选择与回传的唯一通道，构成图的"树骨架"。
- **引用边 E_ref**：(r,v)∈E_ref 表示 v 在父节点之外额外吸收了节点 r 的信息。引用边连接跨分支或非相邻层的节点，承载知识流动与组合迁移，**不参与回传**。当 E_ref=∅ 时整个搜索退化为标准 MCTS。

所有扩展统一为 v_new = g_o(v_t, R)，其中 R 为引用集，按四种算子实例化（附录 B 给出精确定义）：

1. **Primary expansion（R=∅）**：仅由父节点生成，对应 Draft/Improve/Debug 等基线算子。
2. **Intra-branch evolution（R = R_hist(v_t,k)）**：取同分支最近 k 个祖先构成局部轨迹作为参考。设计动机是"复盘而非盲试"——agent 审视哪些改动有效、哪些失败，强化有效模式、避免重复犯错。
3. **Cross-branch reference（R = R_cross(N)）**：当前分支停滞时，取全部已评估分支中按表现排序的 top-N 节点作参考，类比竞赛选手在卡分时借鉴社区方案。
4. **Multi-branch aggregation（R = R_agg）**：全局停滞触发，R_agg = ⊕_{b∈B} T_b^top（各分支最优轨迹的拼接），在根 v_0 下新建一个分支起点。这不是单分支上的增量精化，而是多分支信息池化后开辟独立探索轨迹。

图算子的触发由两级停滞检测控制：分支级停滞（连续 τ_branch=3 次扩展未刷新分支最优）先走分支内演化，搜索后期其他分支已有强解时再叠加跨分支引用；全局级停滞（全局最优连续 τ_global=6 步无改进）触发多分支聚合。默认并行分支数为 3，主扩展产生的最大分支数 5（max_drafts），聚合最多额外增加 2 个分支（max_fusion_drafts）。

### 3.2 渐进式探索调度：从 UCT 到精英导向的软切换

选择阶段有一条明确的架构性约束：**UCT 只在主边构成的树骨架上自顶向下遍历**，图结构不进入选择。UCT(i) = Q_i + c(t)·sqrt(ln(N_v+1)/(N_i+ε))，其中探索常数 c(t) 按分段调度从 c_0=√2 衰减至 c_min=0.5（衰减相位比例 0.3、0.7）。

在此之上是论文的核心调度机制——熵启发的软切换。设局部时间窗内分支选择频率构成经验分布 π_t，其香农熵 H(π_t) 度量搜索努力的分散度；每步以时间相关权重选择策略：

- P(S_t = UCT) = w(t)，P(S_t = Elite) = 1 − w(t)

w(t) 从 1.0 单调衰减到 w_min=0.2，切换发生在搜索进度比例 [0.5, 0.7] 区间。调度目标即让 H(π_t) 随时间下降、把算力逐步集中到有希望的分支。Elite 模式绕过局部树遍历，直接从全局 top-K（K=elite_topk=3）按**逆排名加权**采样：

P(v_i | elite) = (1/rank(v_i)) / Σ_{j=1..K} (1/rank(v_j))

其中 rank 按任务指标对所有有效节点排序。这使后期能无视节点在图中的位置直接开发高价值解，同时保留概率性的探索余量。

附录 C 给出两条理论性质支撑：(i) **覆盖紧致性**——若某扩展上下文含 s≥2 个分支，这些分支在 branch-exposure 图中形成团 K_s；一次包含全部 q 个目标分支的聚合即实现 K_q（C(q,2) 条边），而每次上下文至多含 r 个分支（2≤r<q）时至少需要 ⌈C(q,2)/C(r,2)⌉ 次扩展才能覆盖同样的边集，论证了多分支聚合在上下文覆盖上的紧致性；(ii) **复用集中性**——逆排名采样下 p_i = (1/i)/H_K，命中 top-m 的概率 H_m/H_K 严格大于均匀采样的 m/K，期望排名 K/H_K < (K+1)/2，且以概率 ≥1−δ 命中 top-m 所需独立样本数少于均匀采样。

### 3.3 奖励设计与回传：三档奖励 + 主边专属回传

模拟阶段在解释器中执行候选代码，解析任务指标与日志，即时奖励为三档：

- R(v) = −1：执行失败或未取得有效指标；
- R(v) = +1：执行成功但未刷新分支最优；
- R(v) = +2：执行成功且刷新分支最优。

该结构显式区分失败运行、可行但不改进、真实改进三种情形，为 MCGS 提供稳定的信用分配。回传只在主边路径上进行：对每个祖先 u 更新 N_u ← N_u+1、W_u ← W_u+R(v)，Q_u = W_u/(N_u+ε)。引用边被排除在回传之外，理由是引用只表示辅助性信息复用而非父子生成，不应参与信用分配——这是"信息流"与"信用流"在图上的解耦，是该框架区别于朴素图搜索的关键工程决策。

### 3.4 Retrospective Memory：冷启动先验 + 运行时经验

**静态知识库**：按任务类型（图像分类、NLP、表格回归等）组织的候选模型与简明使用指南，综合自开源仓库与竞赛平台；给定任务 T，以任务描述与领域关键词匹配检索 R_KB(T)，作为初始方案生成 s_init = Init(T, R_KB(T)) 的可选信号，压低冷启动错误率。

**动态全局记忆**：每次有效节点执行后累积结构化记录（plan、outcome、analysis、feedback）。检索为词法（BM25）与语义（FAISS，向量模型 BGE-base-en-v1.5）双通道，经 Reciprocal Rank Fusion 融合：score(d) = α·1/(k+r_lex(d)) + (1−α)·1/(k+r_vec(d))，相似度阈值 0.7。检索是**阶段感知**的：规划阶段以自由文本初稿计划为查询，取回相关成功/失败经验以精化为模块级结构化规范；调试阶段以错误信息为查询，取回相似已解决错误及其修复策略。相对 ROME/MARS/ML-Master 2.0，该设计不引入额外 LLM 做反思总结，记忆的写入是执行过程的自然副产物。

### 3.5 Planner-Coder 解耦与三档编码粒度

Planner 在模块级工作，输入执行反馈、分支轨迹与检索到的记忆，输出结构化的"改什么/为什么"规范；Coder 在代码级实现，关注"怎么改"并保持既有代码结构与可用函数。编码模式三档自适应：**Base**（从零全量生成，用于无可靠方案的初始起草）、**Stepwise**（按 Planner 规范逐模块生成，用于需多阶段管线的复杂任务，降低单次生成难度）、**Diff**（对已有可用方案做定向补丁编辑，修改更稳定可控）。每次生成后由 Code Review agent 静态检查、Data Leakage agent 做泄漏防护，再进入执行。

两条结构性结论：(1) Progressive MCGS 内部，**分支内演化是最关键因子**（奖牌率 66.67→33.33，近乎腰斩），说明复盘同分支近期历史、避免跨迭代重复同类错误是收益主体；跨分支引用与精英开发降幅较温和但作用面不同——前者帮助逃逸停滞的局部轨迹，后者主要把已具竞争力的解进一步推向榜单高位（移除后 beat ratio 最低，71.39）。(2) 记忆系统中两个来源奖牌率降幅相同（均至 44.44%），但移除全局记忆的 beat ratio（73.58）低于移除知识库（76.07），表明动态累积的经验对长程解质量的贡献大于静态冷启动先验。

## 6. 贡献与启示

**贡献**：(1) Progressive MCGS——首个面向开放式 LLM 代码生成、以跨分支信息流（而非状态合并）为目的的图搜索扩展，配套熵驱动软切换调度与两级停滞触发的四个图算子；(2) Retrospective Memory——无需额外反思 LLM 的自动经验累积/检索机制，冷启动先验与运行时经验双源互补；(3) 12 小时（标准一半预算）下 MLE-Bench 65.3% 平均奖牌率的 SOTA，以及在 AlphaEvolve 数学任务上 11/15 最优的跨域泛化证据。

**方法学启示**：信息流与信用流的图上解耦（引用边不回传）是可迁移的设计——任何在 DAG 上做搜索的系统都可借此避免信息复用污染价值估计；三档奖励（−1/+1/+2）把"执行有效性"与"改进贡献"拆开，比连续标量奖励在含大量失败运行的 MLE 环境中信用分配更稳；自适应编码粒度（Base/Stepwise/Diff）本质是把代码修改的"最小作用面"原则工程化，diff 模式在有可用解时应成为默认而非例外。

**对音视频技术的上下游意义**：上游看，该框架是音视频模型管线的自动设计器——音频多标签分类、医学图像、图像分割类 Kaggle 任务是其主战场之一，损失函数选择（AsymmetricLoss）、时频前端参数（带通范围、n_mels、hop_length）、池化方式（GeM vs GAP）、骨干融合等音视频工程师的手工决策维度都被纳入了统一搜索空间；其知识库按任务类型组织先验的思路可直接移植为音视频领域知识库（例如按音频事件检测/声源分离/视频理解分类的模型卡）。下游看，它与 AlphaEvolve 一类算法发现工作同处"AI 优化 AI 技术栈"的链条：MLEvolve 负责应用层管线，若与训练基础设施层（如分布式训练优化）的自动化打通，可覆盖更完整的音视频系统开发闭环。

**局限与保留**：结果依赖强主干（主实验用 Gemini-3.1-Pro-preview，AIDE 换 o1-preview 时差距被主干能力放大，基线主干不齐是横向比较的固有噪声源）；基线数字取自排行榜/原论文而非同环境复现；每任务 12 小时 + 单 H200 的算力口径意味着"低成本自动化"仍不成立；Data Leakage agent 的存在暗示评测作弊防护是该范式的必要组件而非可选项。

## 7. 与其他论文的联系

- **paper:arxiv:2509.07367（SATLUTION）**：同属 AlphaEvolve 谱系的 LLM 代码进化搜索，且都把"超越已发表/人类设计结果"作为口径（SATLUTION 演化 SAT 求解器超越竞赛冠军，MLEvolve 在 AlphaEvolve 15 题上 11/15 最优）。关联依据是方法同源性与直接可比的评测目标；差异在于 SATLUTION 走进化路线并扩展到仓库级，MLEvolve 用图搜索 + 渐进调度，后者可视为对该谱系探索机制的一种替换方案。
- **paper:arxiv:2611.14844（AutoAssumption）**：同以"自动发现 ML 系统算法"为目标，但路线正交——AutoAssumption 把算法写成 Lean 证明图、通过 LLM 搜索放宽假设再重推导（在 KV 缓存驱逐与剪枝上超越已发表方法），MLEvolve 则在评测指标驱动的开放代码空间做图搜索。二者共同点是"引用/依赖结构上的显式搜索"，可互补：AutoAssumption 的假设显式化有望为 MCGS 的扩展算子提供可验证的改进方向。
- **paper:arxiv:2611.14326（FGSE）**：直接对照经验记忆机制。FGSE 要求经验教训作为可证伪假设经探针验证后才写入记忆；MLEvolve 的全局记忆将 plan/outcome/analysis 直接入库、无显式验证。这暴露了 MLEvolve 的一个改进面——被检索复用的"经验"可能本身是噪声或过拟合结论，FGSE 式写入门控是直接可嫁接的方案。
- **paper:arxiv:2611.12109（SkillDuet）**：同为"外部记忆与搜索协同"的设计，但 SkillDuet 演化的是可复用技能库并让 LLM 参数与技能协同更新（响应反馈闭环），MLEvolve 的记忆是记录级、主干冻结。粒度差异（技能 vs 记录）决定了经验跨任务迁移能力的强弱，ML-Master 2.0 的跨任务认知缓存是两者的中间形态。
- **paper:arxiv:2611.14949（RSI-PDEbench）**：共享"提案—评测—精化"的评测驱动自改进闭环结构，只是领域为 PDE 求解。MLEvolve 在 AlphaEvolve 数学任务上的结果（如 Sums and differences problems 1 从 1.1480 提至 1.1902）说明其搜索骨架对数值优化类任务可迁移，与该基准覆盖的问题形态部分重叠。
- **paper:arxiv:2611.10787（TRUST）**：为递归自改进提供错误率控制的在线多重假设检验框架。对 MLEvolve 的适用点在第 5 节所述的机制级风险上：分支内演化与记忆复用若持续采纳伪改进，会以停滞检测误触发和记忆污染两种形式劣化搜索；TRUST 的统计保证可作为其经验写入与精英集更新的置信层。
