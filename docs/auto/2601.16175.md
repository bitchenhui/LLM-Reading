## 1. 背景与动机

论文针对的核心问题是：如何用 LLM 在一个具体科学/工程问题上做出超越已知最优（state-of-the-art）的"发现"。此前的测试时扩展范式（以 AlphaEvolve 为代表）本质是**冻结模型 + 搜索**：把历史尝试存入缓冲区，用手工设计、领域定制的进化启发式（变异、交叉、适应度/多样性度量）把它们拼进新 prompt。其结构性缺陷在于：prompt 可以变好，模型本身不会——类比一个永远无法内化新知识的学生。作者的立场承接 Sutton 的"苦涩教训"式判断：在围棋、蛋白质折叠等难题上，学习最终取代了搜索，因此测试时也应该继续训练模型权重。关键洞察是：发现问题之所以难，是因为它超出训练分布；而模型在该问题上反复尝试产生的经验，恰好构成一个**该问题专属的数据分布**——测试时训练的天然训练集。

形式化上有两个与标准 RL 截然不同的目标设定，全文的方法设计均由此推导：(1) 策略只需解决这**一个**测试问题，无需泛化到其他问题；(2) 只需要产出**一个**最优解，策略只是手段而非目的——成功由 max 而非期望奖励定义，一个期望奖励极低的策略只要碰出一次新 SOTA 即为成功。

范围限定：只处理**连续可验证奖励**问题，覆盖数学、GPU 内核工程、算法设计、单细胞生物学四类，全部用开源模型 gpt-oss-120b（在 Tinker API 上训练），每题成本约几百美元。论文明确承诺报告所有尝试过的问题（包括未获胜的），并附领域专家或赛事组织者的逐字评审。

音视频视角：本文虽属 ML/系统方向，但其 GPU 内核工程一支直接处于音视频技术上游——Triton 内核优化、LayerNorm/门控/矩阵乘的算子融合模式正是视频生成模型（DiT 类架构）与多模态 LLM 推理栈的负载特征；MLA-Decode 一题即 DeepSeek 推理栈中的 KV 缓存注意力组件。此外"对单一难例做测试时强化学习"的范式与流媒体中的 per-title/per-scene 编码参数优化同构（详见第 6 节）。

## 2. 方法总览

**环境形式化（沿用 AlphaEvolve 框架）**：问题以文本描述 d 给出并恒为上下文；状态 s 为一个候选解（如一段 kernel/算法代码，或数学中的阶梯函数构造）；d 诱导连续奖励 R(s)（如内核运行时间的倒数）与转移函数。定义 s_sota/r_sota 为已知最优解及其奖励，"发现"即找到 R(s) > r_sota 的事件。动作 a ~ π_θ(·|d,s) 包含思考 token 与代码；转移为 s' = Parse(a)（编码类）或 s' = Python(Parse(a))（数学类，需执行代码）。考虑单时间步 MDP——因为状态复用实质上等价于给轨迹加时间步。

**搜索方法谱系**：Best-of-N 从固定初始状态（通常取 \<empty\> 而非 s_sota，避免过强先验扼杀探索）独立采样 N 次；状态复用维护缓冲区 H_i，用偏置高奖励但保留低奖励似然的 reuse 启发式采初始状态；状态-动作复用（即"进化搜索"）再把历史动作中的思考 token/中间结果转成自然语言上下文 c_i 一并喂入。

**主循环（Algorithm 1）**：每轮 (s_i, c_i) ~ reuse(H_i)；a_i ~ π_{θ_i}(·|d, s_i, c_i)；求值入缓冲区；θ_{i+1} = train(θ_i, ·)；最终返回历史最高奖励状态。

**朴素测试时 RL 的三个缺陷**（把 train 设为 PPO/GRPO 期望奖励目标、reuse 设为 δ_empty）： 目标函数对 SOTA 无感——内核从 2000µs 优化到 1900µs 可能需要突破，但奖励几乎不变； 有效视界短——每次从零开始限制了单次尝试能达到的复杂度，复用旧解相当于延长视界； 双层探索坍缩——策略层会收缩到安全高奖励动作，复用层会过度开发少数状态牺牲多样性。

**TTT-Discover = 两个组件替换**：train 用带自适应 β(s) 的熵目标 J_β；reuse 用 PUCT 规则在档案上选初始状态。与三篇并行工作（EvoTune、MiGrATe、ThetaEvolve）相比，其差异化主张是：学习目标与复用规则都为"发现"目标定制，而非套用标准 RL 或复杂脆弱的进化启发式。

## 3. 关键设计

### 3.1 熵目标：把期望目标改造成偏向 max 的目标

定义 J_β(θ) = E_{s~reuse(H)}[ log E_{a~π_θ(·|s)}[ e^{β(s)·R(s,a)} ] ]，梯度为 E[w_β(s)(a)·∇_θ log π_θ(a|s)]，其中 w_β = e^{βR}/E_π[e^{βR}]，并以 −1 为基线（因 E[w_β]=1），再叠加 KL 惩罚整形优势 A(a;s) = w_β(a) − 1 − λ·log(π_θ(a|s)/π_{θ0}(a|s))。β→∞ 时目标趋近 max，直觉上正是"发现"所需。并行工作（Jiang et al., [29]）在训练时 RL 中用常数 β=2 优化 pass@k；本文发现常数 β 跨任务难以设置：训练早期大 β 不稳定，后期小 β 使优势消失（改进越来越难时 e^{β·Δr} 趋于 1）。

**自适应 β(s)**：定义倾斜分布 q_β(τ|s) = π_θ·exp(βr)/E[exp(βr)]，w_β 恰是出现在策略梯度中的密度比，β 实际控制重加权诱导的有效步长。作者用 KL 预算约束选 β：KL(q_β(·|s) ‖ π_θ(·|s)) = γ，全实验取 γ = ln 2（类比 Relative Entropy Policy Search）。批实现上对 N 个同状态 rollout 的奖励做 softmax 重加权，二分求解 KL(q_β ‖ uniform) = γ；优势用留一法（LOO）估计，减去 r_max 保数值稳定。两条性质值得注意：(i) 接近目标的状态（改进一致地小）在给定 β 下权重分布不那么尖，同一 KL 预算允许更大 β；偶发大改进的状态则 q_β 迅速集中，预算强制更小 β，防止更新被个别离群轨迹主导——即自动实现"早期保守、后期锐化"的温度调度；(ii) 该估计对奖励的仿射变换（r → w·r + b, w>0）不变，免 reward shaping。

### 3.2 PUCT 复用：树搜索式的缓冲区调度

档案中每个状态评分 score(s) = Q(s) + c·scale·P(s)·√((1+T)/(1+n(s)))，scale 为档案奖励极差，c=1.0。关键偏离 AlphaZero 的四点： Q(s) 取该状态被用作初始状态时**子代最大奖励**（未扩展则取 R(s)），而非均值——关心从该状态出发的最好结果； 先验 P(s) 是按奖励降序排名的线性秩分布——"快内核更可能孵出快内核"，无需学习； 访问计数回传到所有祖先，扩展任一后代会衰减整个谱系的探索加成； 当前批次**屏蔽整个谱系**（祖先+后代）以保多样性，替代 virtual loss。档案维护：每个被扩展父节点保留 top-2 子代插入，全局截断为按 R 的 top-1000，初始种子永久保留。相比进化搜索的手工变异/交叉算子，这套规则无领域定制。

### 3.3 工程实现

gpt-oss-120b 在 Tinker 上以 LoRA（rank 32）训练 50 步，每步 512 条 rollout，分 8 组×64 条，同组共享同一初始状态与上下文（与熵目标的组内对比估计配套）。温度 1.0；上下文窗口 32,768；prompt+thinking 限制 26,000 token，超限则用 token 强制（"...okay, I am out of thinking tokens..."）逼出最终回答。不做离策略步——整批只走 1 个梯度步，但因采样器/学习器基础设施错配需做重要性采样比校正。Adam lr 4e-5；KL 系数 λ=0.1（算法工程任务用 0.01）。按平均 prompt 3000 + 采样 16000 token 估算，一次 50×512 的运行约 $500/题。

音视频关联：TriMul 的算子序列（LayerNorm→线性投影+门控→批量 GEMM→LayerNorm→门控→投影）与门控注意力/DiT 块高度同构，融合+FP16+委托 cuBLAS 的配方可直接迁移到视频生成模型服务；"单硬件训练奖励、跨 GPU 泛化"的实证对异构端侧/云端舰队（含 AMD MI300X）的内核自动调优有直接参考价值；MLA 解码内核正是多模态自回归生成（含视频/音频 token 流）服务路径上的 KV 缓存注意力算子。

## 6. 贡献与启示

**概念贡献**：把测试时扩展从"改 prompt"重构为"改权重"的单实例在线 RL，并系统论证了发现问题的两个特殊性（单问题、max 目标）如何映射为两个具体组件——熵目标（可视为 pass@k 风格的风险敏感 RL，配 KL 预算自适应温度）与 PUCT 档案调度（无手工进化算子的复用机制）。相比并行工作 ThetaEvolve，同模型同预算下仍显著更优（数学两题），作者归因于目标与复用的定制而非更复杂的启发式。

**实证贡献**：单一开源模型 + ~$500/题，在几乎全部尝试问题上刷新 SOTA（Erdős、AC1、TriMul 四型 GPU、AHC 两赛、去噪），A100/H100 提交官方 leaderboard 验证，B200/MI300X 用组织者确认的等价环境，并附专家逐字评审；同时诚实报告三处未胜（AC2、MLA-Decode 无显著优势、圆装箱仅持平），这种"报告全部尝试"的纪律在发现类论文中少见。

**工程启示**：LoRA rank 32 + 50 步即可承载测试时训练；单 H100 奖励训练出的内核跨 A100/B200/MI300X 泛化（对异构机队的内核自动化意义重大）；32k 窗口下的 token 强制收尾是实用的 rollout 管理 trick；OpenEvolve 基线因 prompt 膨胀被截断的现象提示：与冻结模型进化方法对比时必须对齐上下文预算。

**局限**（论文自述+笔者的评测性判断）：只适用连续可验证奖励，稀疏/二值奖励与非可验证领域明确列为未来工作；奖励即基准指标时存在明确的指标过拟合空间（去噪一节的免责声明、FP16 数值隐患）；32k 上下文限制了可承载的初始程序规模（AHC039 被迫压到 22k prompt+thinking）；MLA 案例暴露硬件代理训练（H200 代 MI300X）+ 实例方差下的选型风险。

**音视频上下游落点**： 上游（直接）：推理栈内核（MLA/KV 缓存注意力、融合 LayerNorm/门控/GEMM）是音视频多模态模型服务的吞吐瓶颈，本文提供了"以 1/运行时为奖励、按竞赛级验证器训练"的可复制流水线； 中游（范式）："单实例 + 连续验证奖励 + 测试时权重更新"恰好匹配 per-title/per-scene 编码优化的结构——奖励取该视频的 RD 分数（连续、可验证、单实例），ε-MemEvo 式跨任务经验则对应历史片库参数先验； 下游（模式）：主指标奖励+次指标硬约束的地板式安全设计（Poisson ∈ [0.97,1]）可平移到"优化感知分数、约束合规/漂移"的转码场景。成本上 ~$500/题目前只适合高价值资产（旗舰编码器配置、关键算子），尚不满足逐 chunk 实时预算。

## 7. 与其他论文的联系

- **paper:arxiv:2609.25510（Hill Sampling for Test-Time Scaling）**：同属"用冻结 LLM 反复采样、以当前最优程序为条件"的测试时扩展路线，且其主张（超越进化搜索与测试时训练）与本文核心命题正面相抵。关联依据：TTT-Discover 的消融行"No TTT / PUCT-only（2060.70µs）vs 完整方法（1203.10µs）"恰好量化了冻结模型条件采样类方法相对权重更新的差距，是两文论点交锋的实证界面。
- **paper:arxiv:2608.12522（ε-MemEvo）**：两者都在工程化"搜索过程的记忆"——ε-MemEvo 把跨任务成功策略外置为任务无关记忆并门控注入 LLM 程序进化；TTT-Discover 则把任务内记忆内化到 LoRA 权重（熵目标 RL）+ PUCT 档案。互补轴：跨任务迁移 vs 单任务策略改进，二者结合（档案跨任务初始化）是显然的后续方向。
- **paper:arxiv:2606.06473（MLEvolve）**：同以"自动发现 ML 算法"为目标类；本文单细胞去噪 SOTA 即一例 ML 算法发现，但用单问题测试时 RL 而非自进化多智能体框架实现，构成同一目标下的机制对照。
- **paper:arxiv:2611.14844（AutoAssumption）**：两者都自动发现推理栈/系统层算法；AutoAssumption 以 Lean 证明图上的假设搜索发现了 KV 缓存驱逐与剪枝算法——与本文 MLA-Decode（KV 缓存注意力内核）指向同一基础设施层。关联依据与互补性：形式化假设放宽+可证 vs 经验奖励+测试时 RL；对音视频推理栈的 KV 缓存优化，前者给保证、后者给实测 SOTA，可组合。
- **paper:arxiv:2611.08483（SwarmEvolve）**：AlphaEvolve 谱系的冻结模型进化搜索另一强基线（速度与得分超 AlphaEvolve），是本文"学习取代搜索"论点所针对范式的最新代表；其以 KV 缓存共享支撑蜂群 rollout 的做法与本文"8 组×64 同上下文 rollout"的分组采样在基础设施层面同构。
- **paper:arxiv:2610.03675（FrugalEvo）**：共享成本敏感性论点（单位成本收益最大化）；TTT-Discover 以单开源模型+RL 达到 ~$500/题，FrugalEvo 以强/弱模型分工降本，是预算受限工业部署（如编码器调参流水线）的两条并行降本路线。
- **paper:arxiv:2610.35077（Improving VLMs on Scientific Chart Analysis via Autonomous Evolution）**：同为冻结模型+AlphaEvolve 式程序进化，且落在图表理解这一多模态（音视频相邻）任务上；与本文对比恰好圈出边界——其精确匹配奖励偏二值/稀疏，正是 TTT-Discover 自述不适用的区域，说明进化式搜索在离散奖励多模态任务上仍是当前可用范式。
- **paper:arxiv:2610.35595（Agentic Algorithm Design）**：同以 LLM 自动产出优化算法替代人类设计者，但验证机制对立（Lean 机器检验期望运行时间界、零经验比较 vs 可验证连续奖励的实证发现）；与本文共同勾勒"算法发现"的实证/形式化两极，关联依据为互补的验证哲学。
