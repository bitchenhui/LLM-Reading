> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

本文属于计算机操作智能体（CUA）方向，处理的是“结构化工具调用 + 像素级 GUI 操作”的混合控制问题（与引擎核心的音视频技术为非同域，按 GUI 智能体领域标准评估，音视频关联见第 6 节）。LLM 驱动的 CUA 通过三种模态操作软件：GUI 视觉感知、经 Model Context Protocol（MCP）的结构化 API 调用、键鼠动作。MCP 的普及使混合交互成为桌面/网页自动化的常态，但两个先行基准刻画的现象尚未被方法层面解决：MCPWorld 证明 MCP+GUI 混合智能体优于纯 GUI 与纯 MCP 任一单模态；OSWorld-MCP 进一步显示 MCP 工具能显著提升准确率，但即便 SOTA 模型的工具调用率仍然偏低。二者回答了“混合更好”，没有回答“智能体如何学会何时用哪种模态”。

作者对现有训练范式的批评集中在三点（针对一次性 SFT 与在线 RL 的共性缺陷）：(1) 对所有训练样本或奖励一视同仁，不针对最需修正的弱点；(2) 不做系统性失败模式诊断，因而无法生成定向训练数据；(3) 不揭示进化机制与应用特定的 MCP–GUI 任务组成之间的交互作用——第三点是本文实验部分最有信息量的发现来源。

由此提出核心问题：智能体如何学习平衡 MCP 工具调用与 GUI 动作，何种机制支撑跨应用的迭代自改进。论文的中心主张：**蒸馏与经验增强面向根本不同的失败模式，二者互补而不可互换**——蒸馏教会“如何调用工具”（格式与语法），经验库教会“何时用哪种模态”（策略层），最优机制取决于目标应用的 MCP–GUI 任务组成，需做应用感知的机制选择。

## 2. 方法总览

**形式化：统一混合策略学习。** 计算机使用被建模为 MDP。状态 s = ⟨s_visual ∈ R^{H×W×3}, s_mcp, s_history⟩，即当前截图、可用 MCP 工具描述与动作历史。动作空间按模态二分：MCP 动作 a_mcp = ⟨tool_name, arguments⟩（协议化结构调用），GUI 动作 a_gui = ⟨action_type, coordinates, parameters⟩（点击/键入/滚动/快捷键）。任务为五元组 τ = ⟨g, s0, d, c, φ_judge⟩：自然语言目标、初始状态、难度 d ∈ {easy, medium, hard}、所需技能类别 c ⊆ C、LLM-judge 评估函数 φ_judge: ξ→[0,1]。C 为六个应用无关技能类别（数据检索、数据操纵、搜索查询、执行自动化、导航浏览、配置设置），既是画像维度也是经验库的组织索引，跨应用复用。

**两阶段策略迭代框架。** 学习过程被组织为迭代而非一次性模仿：第 k 轮包含评估与改进两阶段。Stage 1（策略评估）：当前策略 π_{k−1} 在任务集上经 LLM judge 评估，产出多维性能画像 P_k，充当标准 RL 中值函数的角色——定位策略弱在哪；Stage 2（策略改进）：基于 P_k 做差距分析生成新任务 G_k，经轨迹蒸馏与经验累积更新策略。训练目标为 π_{k+1} = argmax_π E_{ξ∼D_k}[log π(a*|s, g)]，其中 a* 在蒸馏时来自专家、在自提升时来自学生自身成功轨迹；数据分布跨迭代累积 D_{k+1} = D_k ∪ D_new(G_k, P_k)。整个框架镜像 policy iteration，但完全离线、依赖专家示范而非在线探索。

**全自动闭环管线（Algorithm 1）。** Phase 1：以 Claude Sonnet 4 为专家策略在种子任务 G0 上采轨迹，轨迹 ξ = {(s_t, r_t, a_t, o_t)} 完整记录截图、推理、动作（MCP 或 GUI）与观测；每任务多次尝试保留最高分轨迹；全部标准化为模型原生 `<tool_call>` 格式（这一步是后续蒸馏在 Qwen3-VL 上可行的前提）。随后可选初始 SFT 并构建初始经验库 E0。循环 K 轮：评估（带经验库增强的提示）→ 差距驱动生成新任务 → 专家采新轨迹 → 数据累积 → 从基模型重训 SFT → 重建经验库。最终输出双产物：微调智能体 π_K（利于 MCP 主导任务）与经验库 E_K（利于 GUI 密集任务的推理时增强），全程无人工介入。

## 3. 关键设计

### 3.1 多维性能画像 P_k

P_k = ⟨ρ, σ_d, σ_c, φ, η⟩ 覆盖五维：模态平衡（ρ_mcp / ρ_gui / ρ_hybrid）、难度级成功率（easy/medium/hard）、六技能类成功率、格式质量（φ_format / φ_parse / φ_args）、效率（平均步数、完成率、超时率）。这是“差距分析 → 任务生成”的输入，也是本文区别于常规 SFT 数据管线的关键：画像让每轮迭代的训练数据生成有明确的弱点靶点，而非均匀扩量。配套的演化记忆模块（附录 B.2）维护 TaskMemory（跨迭代任务成败）、IterationMemory（轮内统计）与 EvolutionMemory（全局模式），支撑画像的纵向对比。

### 3.2 差距驱动的任务与环境生成

差距按可配置阈值计算：Δ_mcp = ρ_target − ρ_mcp（模态差距）、Δ_d = γ_d − σ_d（难度差距）、Δ_c = γ_c − σ_c（技能差距），任务合成按差距加权。论文给出的实例：Chrome 第 2 轮画像识别出智能体 GUI-heavy、bookmark_page / delete_browsing_data 等工具使用不足，随即定向生成对应任务并采专家示范。

**自动环境生成是“全自动”的关键使能，也是本文工程上最值得复用的组件。** 每个生成任务都需要有效的应用初始状态（特定浏览器标签页、表格数据、打开的文件），这在现有基准中是人工编写的扩展瓶颈。管线用 LLM 从任务描述生成环境 setup 脚本，通过“目标应用是否达到预期初始状态”做校验，失败则携带错误反馈重试。基础设施层面包含健康校验、自动失败恢复、并行 GPU 执行的动态端口分配、Docker 容器内 MCP server 生命周期管理与应用级工作区重置。效果是差距分析产出的每个新任务立即可执行、无需人工配置。

### 3.3 离线策略改进（SFT）的两个防退化配置

损失为 L_SFT(θ) = −Σ_ξ Σ_t log p_θ(r_t, a_t | s_≤t, g)，同时拟合推理链与动作。两个细节值得注意：数据跨迭代全量累积 D_k = D0 ∪ D_new 以防灾难遗忘；且**每轮从基模型 θ0 重训而非接续 π_{k−1}**，防止误差在迭代链上累积，另以记忆回放混入历史成功轨迹。这是离线迭代范式中简单但必要的稳定性设计。

### 3.4 拒绝采样自提升

动机是专家–学生能力鸿沟：Claude 能可靠执行的动作，8B 学生未必能复现，硬模仿引入分布偏移、诱使学生尝试超出能力边界的动作。解法是 rejection sampling：每轮让学生模型对每任务至多 N = 3 次尝试，保留超过成功阈值 τ_success = 0.5 的轨迹，每任务按 LLM-judge 分数选最优，仅在这些自生成成功轨迹上微调。配合差距生成，Chrome 训练池从 44 条专家示范自主增长到第 3 轮的 79 样本。

### 3.5 经验库：免微调的推理时改进

与简单轨迹回放不同，经验库的知识单元是**规则而非轨迹**：用 LLM 对比同任务/同技能类别下的成功轨迹 ξ+ 与失败轨迹 ξ−，抽取差异化因素 (s, e, t) = LLM_extract(ξ+, ξ−, c)。按六技能类别组织，每类维护四型知识：任务特定策略（如“先截图确认当前视图”）、环境知识（UI 布局与应用行为）、工具使用模式（常见操作的有效 MCP 工具序列）、错误恢复策略。每类设有容量上限，超限时经 LLM 摘要合并 E_c^new = LLM_merge(E_c^old, E_c^fresh)；入库前按应用类型过滤防跨应用污染（论文早期实验中 VS Code 的 Ctrl+Shift+E 出现在 Chrome 经验库并被执行，加过滤后消除）。推理时按当前任务技能类别拼接：prompt_k = prompt_base ⊕ Experience(E_{k−1}, c_task)。

评估两种进化模式：Distillation + Experience（SFT 加经验增强提示）与 Experience-Only（纯推理时增强、零微调，适合算力受限场景）。全部规则由 LLM 轨迹对比自动发现、零人工编写。典型样例：Chrome 打印对话框任务，基线智能体调用错误语法工具（google_chrome.print 点号语法）后 17 步随机点击失败；进化一轮后经经验库习得“用 Ctrl+P 打开打印对话框”，单步解决——快捷键由轨迹对比自动发现并存入 Navigation 类别。

### 3.6 经验库设计原则（附录 G）

面向 7–8B 小模型总结五条：简洁性优于覆盖（不封顶的库因挤占注意力窗口反而降效，合并摘要只保留最具迁移性的模式）；可执行的具体性（“用 Ctrl+P 打开打印对话框”有直接收益，“高效使用工具”类抽象建议无可测效果——LLM 轨迹对比因精确定位成败轨迹的动作差异而天然产出具体规则）；域隔离；两机制互补；自动发现优于人工工程（人工规则无法跨应用扩展，也写不出“调用 open_privacy_settings 后接 GUI 步骤”这类交互细节）。

## 4. 实验结果

**设置。** 三桌面应用共 120 任务、36 个 MCP 工具：VS Code（30 任务 / 9 工具）、LibreOffice Calc（45 / 16）、Chrome（45 / 11），工具复杂度与应用域各异。学生模型 Qwen3-VL-8B，LoRA rank 8、LR 2e-5、每图 50,176 像素、单训练样本最多 30 图、截断长度 32,768；K ∈ {1, 3} 轮。Claude 任 LLM judge（评任务完成度/动作正确性/工具使用/效率，输出含 score、success、mcp_actions、gui_actions 的 JSON）。指标：Pass Rate（judge 独立于连续分给出的二元成败）、LLM Score（[0,1] 轨迹质量）、MCP Ratio（MCP 动作占比）。

**Chrome 单轮结果（45 任务）：**

| 策略 | Pass | Score | Eff. | MCP% |
|---|---|---|---|---|
| Baseline | 60.0% | 0.654 | 0.662 | 43.7% |
| + Exp. Bank（仅推理时） | 62.2% | 0.640 | 0.646 | 45.0% |
| + Distill. + Exp. | 77.8% | 0.770 | 0.724 | 36.3% |

蒸馏 +17.8pp，且难度分层明确：easy 100%（基线 80%）、hard 53.3%（基线 26.7%，12→8/15 翻倍）；经验库免训练 +2.2pp。值得注意蒸馏轮 MCP% 反降至 36.3%——论文解释为模型先学会工具语法、再优化工具选择，属暂时性下探（第 3 轮回升至 55.8%）。

**Chrome 三轮自进化：** Experience-Only 从 60.0% 稳步升至 64.4%（第 2 轮，Score 0.674）；Distill + Exp 单轮即达峰值 77.8%（第 1 轮，Score 0.770）。第 3 轮效率收益：MCP 采用率 43.7%→55.8%（+12.1pp），总动作数 243→163（−33%），训练池 44→79 样本。

**跨应用对比（pass rate %）——全文核心结论：**

| | Chrome (45) | VS Code (30) | Calc (45) |
|---|---|---|---|
| Baseline | 60.0 | 53.3 | 44.4 |
| + Exp. Bank | 62.2 | **63.3 (+10.0)** | 46.7 (+2.3) |
| + Distill. + Exp. | **77.8 (+17.8)** | 43.3 (−10.0) | 42.2 |

最优机制由应用的 MCP–GUI 组成决定。Chrome 大量任务可映射为直接工具调用（bookmark_page、navigate_to 类），蒸馏有效传授调用模式；VS Code 是 GUI 密集环境，经验库的键盘捷径规则绕开不可靠的视觉定位（+10.0pp），而蒸馏反伤 −10.0pp；Calc 基线 MCP 使用率已达 61.5%（三应用最高），SFT 后反降至 47.8%——作者将此作为分布错配的直接证据：专家轨迹把学生推向更少 MCP 的策略，且其多步 API 链（读单元格区→算公式→写结果）难以从有限示范中学到，hard 任务 0/15 在所有策略下未解。作者由此给出原则性判断：**当专家与学生行为分布分化时，推理时增强可能优于模仿**；经验库编码抽象策略（如“用 Ctrl+Shift+P”）对模型既有策略是增强而非覆盖。

**跨模型前提检验（Chrome 45 任务）：**

| 策略 | Qwen3-VL-8B | Qwen2.5-VL-7B |
|---|---|---|
| Baseline | 60.0% | 48.9% |
| + Exp. Bank | 62.2% | 40.0% (−8.9pp) |
| + Distill. + Exp. | 77.8% | 不适用 |

Qwen2.5-VL-7B 缺原生 `<tool_call>` 支持（MCP 比率 6.6% vs Qwen3 的 43.7%），把结构化工具语法与经验文本当噪声，经验增强反而 −8.9pp，蒸馏因格式前提缺失无法进行。结论：自进化只能放大既有双模态基础能力，不能无中生有；原生工具调用支持是最低门槛。

## 5. 消融要点

- **机制–失败模式正交性（第 7.1 节与附录 L）：** 蒸馏主要拉动 hard 任务 +26.6pp（学会新工具调用模式），经验库主要拉动 medium 任务 +13.4pp（策略性指导），easy 任务两策略下均自基线 ≥80% 快速饱和。这从难度维度独立验证了“蒸馏管语法、经验库管策略”的分工。
- **经验库容量消融（附录 G）：** 不封顶的经验库降效——冗长经验文本与任务相关信息争夺小模型注意力窗口；按类别封顶 + LLM 合并摘要是必要配置。
- **规则具体性消融：** 抽象策略无可测收益，只有规定具体动作的规则有效；LLM 轨迹对比因直接定位成败轨迹的动作差异而天然满足此性质。
- **域过滤消融：** 去掉应用类型过滤出现跨应用快捷键污染（VS Code 快捷键进入 Chrome 经验库并被执行），证实域隔离必要性。
- **机制失配的量化证据：** VS Code 蒸馏 −10.0pp、Calc 蒸馏后 MCP 使用率 61.5%→47.8%，二者共同指向专家–学生分布错配下模仿学习的风险；Calc 的多步 API 链揭示了蒸馏可受益性的边界——单步直调可蒸馏、组合式工具链需要更强训练信号（论文建议引入在线探索）。

## 6. 贡献与启示

**贡献（按论文自述四点）：** (1) MCP–GUI 交互的统一混合策略学习形式化，并实证蒸馏与经验增强互补而非可互换；(2) 全自动自进化管线（专家轨迹、环境生成与校验、经验库构建、LLM-judge 评估、多维差距分析、自适应任务生成，零人工介入）；(3) 经验库机制——按技能类别组织、容量受限、应用过滤，实现免微调的推理时改进；(4) Chrome / VS Code / LibreOffice Calc 三应用系统性分析，给出按 MCP–GUI 组成选择机制的实用准则。

**工程启示。** 第一，机制选择规则可直接落地：任务多映射为直接工具调用 → 蒸馏；视觉定位不可靠 / GUI 密集 → 推理时经验增强；组合式 API 链 → 两者皆弱，需在线探索或更强训练信号。第二，数据效率：44 条专家示范自举至 79 样本即获 Chrome +17.8pp，论文称环境交互量远低于在线 RL（对比 DigiRL）。第三，自动环境生成 + 校验回路消除了混合智能体数据扩展的人工瓶颈，是独立于主结论的最可复用组件。第四，每轮从 θ0 重训 + 记忆回放是离线迭代防误差累积/遗忘的廉价有效配置。

**局限（论文自述）：** 依赖专家模型做轨迹播种；假设 LLM-judge 可靠；经验库效果依赖模型指令跟随能力（Qwen2.5 反例）；Calc 揭示组合复杂度边界，hard 任务全策略未破。

**与音视频技术的上下游关联（范式级迁移推断，论文本身实验不含音视频应用）：** 下游——非线编、DAW、调色、字幕等桌面媒体生产软件与本文环境同构：脚本/快捷键密集的结构化操作面与像素级 GUI 并存，且恰恰是“GUI 密集 + 快捷键有效”的组成，对应本文经验库收益最大的场景（VS Code +10.0pp、Ctrl+P 单步替代 17 步探索的案例）；Chrome 上的导航/表单/配置类结论可直接外推到浏览器端音视频平台的发布、上传、字幕与隐私设置自动化。上游——状态空间以截图为视觉输入（每图 50,176 像素、单样本 ≤30 图），完全依赖 VLM 屏幕理解；迁移到含时间轴、波形、动态预览的媒体工具时，低频截图对时序状态的观测充分性是新问题，论文未覆盖。LLM-judge 产物校验范式可平移到音视频生产任务的成品验收。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326（FGSE, When Should Agents Remember?）**：同属“把经验写入智能体记忆以支撑自进化”的路线。EE-MCP 经验库入库仅做应用类型过滤与容量合并，无规则正确性验证；FGSE 则将经验教训作为可证伪假设、经三类探针验证后再写入记忆。EE-MCP 自身的证据（Qwen2.5 将经验文本当噪声致 −8.9pp、跨应用快捷键污染案例）正说明无验证写入的风险面，FGSE 的证伪门控是对该缺口的直接补法。
- **paper:arxiv:2611.12109（SkillDuet）**：同为“参数更新 + 外部技能/经验库”双轨自改进。EE-MCP 的增量在于实证两轨面向正交失败模式（工具语法 vs 模态策略），且需按应用的任务组成决定启用哪一轨；SkillDuet 以响应反馈让模型参数与技能库双向协同演化，暗示 EE-MCP 的“轨迹 → 经验库”单向流可闭环为双向反馈。
- **paper:arxiv:2611.10787（TRUST）**：EE-MCP 在局限中自述依赖 LLM-judge 可靠性做质量过滤，错误轨迹或错误规则可能在迭代中累积放大；TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证，可直接叠加到 EE-MCP 的拒绝采样阈值（τ_success = 0.5）与经验库入库环节，补齐其质量控制的统计缺失。
