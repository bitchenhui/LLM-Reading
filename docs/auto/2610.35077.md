# Improving VLMs on Scientific Chart Analysis via Autonomous Evolution

> Abhinav Sudhakar Dubey, Vidushi Goel, Kiran Rana, Shikhar Mathur, Vaggos Chatziafratis. *arXiv:2610.35077v1 (2026-10-26)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

论文出发点是开放权重 VLM 在科学图表问答（Chart QA）上系统性低于人类的问题，且作者通过失败模式分析提出了一个关键归因：相当一部分“错误”并非模型感知能力不足，而是推理管线造成的**不可评分答案**。在 CharXiv/ChartQA/PlotQA/EvoChartQA 这类以精确匹配（exact match, EM）为描述性问题评分协议的基准上，格式与语义同等重要——正确数值若被包裹在长句、单位符号或中间算术中即判错。文中给出的实例：Qwen3-VL-2B 被问“y 轴最高刻度”时回答"58"（真值 60）；被问百分比时回答"28%"（真值 38）；在朴素 prompt + 充足 token 预算下，Qwen3-VL-2B 在 ChartQA 描述性问题上仅 0.5%、PlotQA 上 0.0%。这些失败同时包含感知错误与呈现错误，但后者是纯管线层面的可修复损耗。

由此提出核心问题：**在不改动模型任何权重的前提下，能恢复多少精度？** 作者将介于“基准问题”与“被评分字符串”之间的全部代码定义为**推理程序**：系统提示、按问题类型（qid）的格式提示、解码 token 预算、把原始生成归一化为答案的后处理。实践中这套代码靠人工逐模型逐基准调优且难以迁移。

定位上，论文与三条既有路线划清边界：(1) prompt 优化器（OPRO/APE/EvoPrompt）只搜字符串空间，无法收缩冗长答案、剥离尾部百分号、调整 token 预算，对感知类失败帮助有限；(2) 图表专训/改权重路线（MatCha、UniChart）或中间表示（DePlot）成本高，且对闭源权重根本不可行；(3) 服务系统层优化与本文互补，本文产物可直接部署在 vLLM 等系统之上。

## 2. 方法总览

形式化：设冻结 VLM 为 f，基准为三元组 (x, q, a)（图表图像、问题、金标答案），每个问题携带类型标识 qid（如"highest y-tick"、"number of series"）。推理程序 p(x, q, qid)→str 是一个可零次或多次调用 f 的短 Python 模块，在集合 S 上的描述性 EM 为归一化后的逐题匹配率。给定训练窗口 T 与不相交的留出窗口 H，目标是最大化未见问题上的 EM。

进化循环每代五步，共 25 代、候选池至多 10 个程序、每 5 代一次交叉：

1. **种子**：第 0 代是刻意朴素的基线——朴素 prompt、充裕 token 预算、无后处理，模拟普通从业者的起点；
2. **候选生成**：Gemini 2.5 Flash 作为变异算子，基于父代做单点定向编辑（收紧 prompt、改 per-qid 提示、调 token 预算、重写后处理）；交叉则取两个强父本按问题类型保留各自更优规则合成子代；
3. **验证器**：五项静态不变量在任何 GPU 计算前拒绝坏候选；
4. **评估器**：报告四个量——描述性 EM（唯一选择信号）、推理 EM（仅作代理指标，因官方推理指标是开放式评分，EM 不适用）、延迟/吞吐、异常——后三者只记录不驱动搜索；
5. **种群管理**：池按训练精度排序、每代剪除最弱者；父本选择用三人锦标赛（80% 概率）加弱半区随机抽取（20%）平衡利用与探索；**落盘的却是留出精度最高的候选**，两个角色解耦以防过拟合。

候选契约：只允许编辑 `# EVOLVE-BLOCK-START/END` 标记之间的代码，全部落在单函数 `vlm_inference(image_path, question, qid) → str` 内；模型 id 与贪心解码（do_sample=False）全程由验证器锁定。这一固定解码保证了可复现性——任意两代间的精度差只能来自代码编辑而非 VLM 采样噪声，这是全文归因论证的方法学支点。产物包括每个（模型， 基准）的胜出程序、三个部署变体、逐代 JSON 历史（事件类型：seed/improvement/no_improvement/crossover/mutation_failed）及可复现脚本。

## 3. 关键设计

**失败感知变异与多样性控制。** 变异 prompt 中注入父代的 6 个具体失败三元组（问题、模型答案、金标），使编辑朝向实际断点而非随机重写。关键设计细节：6 个样本从**不同问题类型**中抽取而非取最差的 6 个——作者观察到若集中于单一失败类型，变异器会偏向只救该类型的窄修复并损害其他类型。这是一个针对 LLM 变异算子偏差的工程性纠偏。

**验证器作为计算防火墙。** LLM 生成的 Python 常在运行期因 chat 格式、错误导入、签名破坏而崩溃，而加载 VLM 跑评估是昂贵步骤。五项不变量：EVOLVE-BLOCK 标记存在；禁 do_sample=True；骨干模型 id 不变；`vlm_inference(...)` 签名完整；`ast.parse()` 通过。前四项是廉价字符串检查，先于语法与导入阶段，整组关卡先于任何 GPU 工作。不变量 2、3 同时兼任实验控制变量，双重角色设计得很经济。

**选择解耦。** 父本按训练精度选，但每代写入持久化的候选按留出精度选。日志摘录直接展示了该解耦的必要性：第 10 代交叉后子代 train=57.0%/holdout=61.5%，出现"best-by-train != best-by-holdout"。留出窗口从未参与适应度优化，是搜索的防过拟合锚点。

**部署变体与聚合分。** 从最终池中抽取 best_accuracy / best_speed / best_overall 三个变体。聚合分 `OVERALL = harmonic_mean(desc_acc, min(QPS/10, 1))`，描述性精度低于 30% 时置零：调和平均惩罚单维强势（快而多错、准而太慢均不加分），30% 下限反映“精度过低的图表阅读器无部署价值”。该分仅用于报告排序，进化搜索本身只优化描述性 EM——目标与报告指标的分离值得注意：吞吐提升是 EM 压力的**副产品**，不是被优化的量。

**搜索空间表达力。** 相比 prompt-only 优化（字符串子集）与 DSPy/TextGrad（声明式模块与文本参数），本文直接搜可执行程序，单次编辑可同时改变 token 预算、后处理与提示结构——作者称这类修复是“任何改写措辞都做不到的”。这一点是方法区别于既有工作的实质主张。

## 4. 实验结果

设置：三个开放 VLM——Qwen3-VL-2B-Instruct（图表任务三者中最强）、InternVL3（文档/图表强）、SmolVLM2（小而高效型），均 float16 经 HuggingFace Transformers 单查询模式贪心解码；四个基准 CharXiv/ChartQA/EvoChartQA/PlotQA 的描述性问题切分为训练/留出窗口（Qwen3-VL-2B/ChartQA 为 102 描述 + 51 推理训练、26 描述 + 13 推理留出）；25 代、池 10、每 5 代交叉、每次变异至多 6 个失败例；变异器全程 Gemini 2.5 Flash；Colab A100，单次运行量级为单卡数小时。**表 1 的最终精度在各基准完整描述性子集上计算**，而非仅留出窗口。

12 个（模型， 基准）对的描述性 EM（%）：

| 模型 | CharXiv 种子→进化 | ChartQA 种子→进化 | EvoChartQA 种子→进化 | PlotQA 种子→进化 |
|---|---|---|---|---|
| Qwen3-VL-2B | 38.3 → 66.4 (+28.1) | 0.5 → 55.7 (+55.2) | 1.0 → 47.4 (+46.4) | 0.0 → 33.3 (+33.3) |
| InternVL3 | 23.4 → 52.3 (+28.9) | 49.5 → 62.0 (+12.5) | 6.8 → 36.5 (+29.7) | 10.9 → 13.5 (+2.6) |
| SmolVLM2 | 35.2 → 37.5 (+2.3) | 11.5 → 41.1 (+29.6) | 9.9 → 28.6 (+18.7) | 12.5 → 21.4 (+8.9) |

均值 16.6% → 41.3%（平均 +24.7 点），12 组全部提升。增益强烈依赖种子失败类型：当种子能找对答案但以不可评分形式输出时（Qwen3-VL-2B 系），增益巨大（ChartQA +55.2、EvoChartQA +46.4、PlotQA 从 0.0 起步 +33.3）；当种子输出已干净、失败以感知错误为主时，头部空间小（SmolVLM2/CharXiv +2.3、InternVL3/PlotQA +2.6）。按增益排序的 12 组分布清晰呈现“格式可恢复 / 感知受限”两簇。

Qwen3-VL-2B/ChartQA 深挖（窗口：128 描述 + 64 推理样本）：

| 程序 | 描述 EM | 推理 EM | QPS | Overall |
|---|---|---|---|---|
| seed（起点） | 38.3% | 4.7% | 0.33 | 0.061 |
| hand-tuned（人工） | 56.3% | 17.2% | 1.20 | 0.198 |
| evolved | 58.6% | 9.4% | 0.78 | 0.138 |
| best_accuracy | 58.6% | 10.9% | 0.85 | 0.148 |
| best_speed | 58.6% | 14.1% | 1.24 | 0.205 |
| best_overall | 57.0% | 9.4% | 1.22 | 0.201 |

best_speed 相对种子约 +20 点精度、3.8× 吞吐（0.33→1.24 QPS），并在聚合分上压过人工调优基线（0.205 vs 0.198），描述 EM 也高 2.3 点。一个反直觉但机理清晰的结论：EM 增益不但不付出延迟代价反而提速——编辑产生短而可评分的答案、删掉不必要生成，生成长度缩短直接降低解码耗时。另一处值得注意的细节：推理 EM 上人工基线（17.2%）仍高于全部进化变体（9.4–14.1%），与“搜索从不优化推理指标”的设计一致，但也提示若目标含推理，需把相应指标纳入适应度。

## 5. 消融要点

论文无独立消融节，消融性证据散布如下，且存在若干审稿人会追问的空缺：

- **受控对照**：12 组种子 vs 进化对比本身是严格受控实验——模型 id、贪心解码、数据切分全程冻结，精度差可归因于代码编辑。这是论文最干净的方法学资产。
- **失败条件化设计**：跨问题类型抽 6 例 vs 取最差 6 例的选择基于作者对变异器窄修复偏差的定性观察（会偏袒单一题型、损害其他题型），未给出定量消融。
- **选择解耦证据**：日志中 best-by-train ≠ best-by-holdout 的实例（Gen 10 交叉子代）是解耦必要性的直接展示，但未量化若无解耦会过拟合多少。
- **明显缺口**：未实测 OPRO/EvoPrompt 等 prompt-only 基线，理由是“其搜索空间是我们空间的严格子集”加表 3 的定性分析（增益主要来自 prompt 之外的编辑）。该论证逻辑上成立，但缺少数字支撑，是全文最薄弱的对比环节。
- **人工基线覆盖面**：hand-tuned 仅在 Qwen3-VL-2B/ChartQA 一组上比较，其余 11 组无人工强基线。
- **部署变体**可视为对最终池的精度-速度权衡探测，显示三个变体描述 EM 几乎持平（57.0–58.6%）而 QPS 差 1.6 倍。
- **附录 D 工程摩擦**（对复现者重要）：Qwen3-VL-2B 的请求批处理因 Qwen2VLProcessor 右填充问题使精度被压到 29.7%；INT4 量化在 T4 上仅 0.04 QPS（约比 float16 慢 75 倍）而被放弃；若干候选模型因门控审批或统一推理模板不兼容被排除——说明批处理与量化这两个常规加速手段当前在该管线下是有损/不可用的，本文的提速走的是“缩短生成长度”这条正交路径。
- 作者自认的边界：对纯感知失败与空响应场景效果有限。

## 6. 贡献与启示

**核心经验结论**：图表问答基准上被记为“错误”的输出中，相当大比例是推理管线伪影而非模型能力缺陷；冻结模型 + 进化管线可达到并超过人工调优（在 Qwen3/ChartQA 上），且同时更快。按作者表述，这是首个将 LLM 驱动的代码进化应用于 VLM 推理管线的工作。

**工程含义**：(1) 方法适用于任何能塞进“单函数接口”的检查点，包括闭源权重模型——这是改权重路线（MatCha/UniChart/DePlot）做不到的；(2) 与服务系统层正交可叠加，进化产物可直接跑在 vLLM/Orca 之上；(3) 成本画像友好：单卡 A100 数小时、约百级训练样本窗口（102 描述题）即可完成一次针对特定（模型， 基准）的适配，适合按部署目标做轻量定制进化；(4) 归因方法学——锁定贪心解码使代际差异只可能来自代码——值得所有做推理时优化的工作借鉴。

**指标反思**：EM 协议使格式与语义同等重要，进化压力塑造了“短答案”这一产物形态并顺带带来 3.8× 吞吐；若部署侧评分换成宽松数值容差，进化出的程序形态会不同。这提示基准协议本身在主动塑造被优化的工件。

**与音视频技术链条的上下游关联**：本文虽属 VLM/图表理解方向，但其技术位置在多模态推理服务栈的**推理编排层**——上游是 VLM/LLM 推理服务（批处理、调度、KV 管理），本文明确不改服务基础设施、只优化“模型被要求做什么、允许生成多少、输出如何解析”，因此与 vLLM/SGLang 类系统是即插即用的叠加关系；附录 D 报告的批处理右填充精度坍缩（29.7% 上限）对使用 Qwen2VLProcessor 做批量视频帧/图像推理的工程团队是具体可用的警示。下游面向音视频内容理解中日益常见的结构化抽取任务——演示/授课视频中的幻灯图表解析、财经与监控大屏视频流里的图表/仪表盘读数、体育遥测叠加层、传感器时序图问答——这类任务的评分天然接近精确匹配或结构化抽取，正是本文“冻结权重、进化外围代码”配方的直接可迁移场景；且“短答案契约”缩短生成长度，直接减少解码时延与 KV 占用，对交互式视频问答与近实时视频摘要管线的吞吐收益是实质性的。对只能调用闭源多模态 API 的音视频产品团队，本文是少数完全可用的精度恢复路径。
