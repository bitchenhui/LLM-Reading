# Towards Real-Time Neural Video Codec for Cross-Platform Application Using Calibration Information

## 1. 背景与动机

神经视频编码（NVC）的 RD 性能已在部分场景超越 H.266/VTM，但距实际落地有两大障碍，本文同时正面处理这两点。

**跨平台非确定性**（Ballé et al., ICLR'19 首次定义）：NVC 普遍依赖算术编码，而算术解码对熵参数的数值差异极度敏感。浮点舍入是平台相关的（不同 CPU/GPU、不同算子实现对同一浮点表达式给出末位不同的结果），且 NVC 中熵模型与解码器在编码端与解码端都要执行（analysis-by-synthesis 结构），于是编码端得到 (μe, σe)、解码端得到 (μd, σd)。二者的微小差异在 σ 的**离散化**环节被放大为完全不同的量化索引与 θ，算术解码随之失步，重建彻底失败。本文实测（UVG ReadySteadyGo 96 帧、两 CPU 平台 × 两 GPU 平台的组合矩阵）：无对策时跨平台解码失败率达 94.8%–100%，同平台为 0%。既有解法——integer-only 网络、熵网络量化（Koyuncu et al., PCS'22）、PTQ（He et al., 2022）——本质上与通用 QAT/PTQ 同构，都需要在校准数据上做额外训练或对齐，工程代价高。

**实时性**：SOTA NVC 模型计算量巨大（本文未压缩的 P 帧模型约 1100G MACs），消费级 GPU 上解码速度仅约 2 FPS。

目标：**免训练**地解决跨平台一致性，同时把模型轻量化到消费级 GPU 实时——云端 A100 编码、RTX 2080 上以约 25 FPS 解码 720P 码流，RD 仍优于 H.265 (medium)。参照系方面，MobileCodec 是此前唯一的帧间 NVC 实时解码工作（手机端），但明确不处理跨平台问题。

## 2. 方法总览

底座沿用 Li et al. (ACM MM'22) 的上下文条件熵模型框架：编码器产出图像/上下文/运动三类 latents（ŷt），hyperprior 分支产出 ẑt；熵模型 Etp(ẑt, c) 预测 (μ, σ)，c 为帧间条件；算术编码按离散化后的 (μ, θ) 对 ŷt 编码。

核心洞察：浮点非确定性本身无害，**唯一的灾难放大点是 σ 的离散化**——连续小扰动经量化变为离散大跳变。因此无需对齐全部浮点计算，只需保证两端量化结果一致。据此设计四件套：

1. **CIT（校准信息传输）**：编码端用 ±ϵ 探针识别可能发生越界量化的坐标集合 Cb，把坐标经辅助码流传给解码端；两端对 Cb 内元素统一改用四舍五入量化 QD，其余仍用截断量化 Q。**零训练**、即插即用，论文声明理论上适用于一切“熵模型 + 算术编码”的编解码方案。
2. **PGC（分段高斯约束）**：微调期把中间变量 I 从整数边界拉向量化区间中心，从源头减少 Cb 规模，压低辅助码流。
3. **RPC（相对位置编码）**：Cb 展平后的坐标索引单调递增，改传差分，每坐标比特数由 log2(C×H×W)=20 降至 log2(max(Vrel))。
4. **实时化栈**：模型剪枝（P 帧 1100G→162G MACs、I 帧 950G→252.6G MACs）、运动估计输入降采样 ×2（计算量降为 1/4）、算术编码跳过（θ 极小的元素跳过编码、直接取 μ，省 60–70% 熵编码计算量）。组合后解码速度从 2 FPS 提至 25 FPS。

## 3. 关键设计

### 3.1 熵参数离散化管线

训练期率估计采用加均匀噪声的高斯：q(yt|ẑt,c)=∏i (N(μi,σi²)*U(−1/2,1/2))(yi)。实际编解码用非线性离散化 σ：I = r(σ) = clamp[(log σ − log σmin)/σstep; 0, L−1]，σstep=(log σmax − log σmin)/(L−1)；索引 Ĩ = Q(I) = ⌊I⌋（截断量化）；θ = LUT(Ĩ) = exp(log σmin + σstep·Ĩ)。实验配置 L=32、σmin=0.01、σmax=64。

### 3.2 CIT：探针式越界坐标标记 + 量化函数切换

失效机理示例：同一元素，编码端算得 Ie=1.9998、解码端算得 Id=2.0001（差异来自浮点误差），截断量化分别得 1 与 2，θ 完全不同，算术解码失败。

CIT 判据：**Cb = {(x,y,z) | |Q(Ie+ϵ) − Q(Ie−ϵ)| > 0}**，即对 ±ϵ 扰动会发生量化跳变的坐标。组合量化规则：Ĩ′ = Q(I)（坐标 ∉ Cb）或 QD(I)=⌊I⌉ 四舍五入（坐标 ∈ Cb）。两端从码流解出 Cb 后按同一规则执行，得到完全一致的 (μ′, θ′)。机理上这是一个漂亮的互补设计：**被标记元素位于整数邻域（离半整数舍入边界远），round-to-nearest 在此对浮点扰动最稳健；未标记元素距整数边界超过 ϵ，floor 本身稳定**——两类元素各处在自己量化函数的稳定区，全程不需要改动模型权重。

校准开销与平台间数值偏差强相关。论文给出关键实测：FP32 下 A100 与 2080 计算同一 I 的最大误差为 5e-5，故取 ϵ=1e-4 即可覆盖，辅助码流很小；ϵ 逐档放大到 1e-3、1e-2 时坐标数近似按 ×10 增长（见消融）。

### 3.3 PGC：把 I 推离整数边界

记 d(I)=|I−(⌈I⌉−0.5)|∈[0,0.5]，即 I 到最近半整数（量化区间中心）的距离，G(I,δ)=1/(δ√2π)·exp(−½((d(I)−0.5)/δ)²) 是以整数为峰、区间中心为谷的周期高斯。损失 Lcal=Σi M(Ii)·(G(0.5,δ)−G(Ii,δ))²，其中 G(0.5,δ) 恰为区间中心处的函数值：对危险带内的值（G(Ii)>G(0.5,δ)），二次差驱动 G(Ii) 向中心取值靠拢，几何上即**把 I 从整数边界拉向量化区间中心**（对应摘要所述"minimizes the number of output values ... near the integer boundaries"；正文"push to the integer centers"按式(13)(14)的几何应理解为整数区间的中心）。掩码 M 对两类值免约束：I<η（因式(3)的 clamp 下界，0 附近不可能向下越界）与 d(I)<η（已处于区间中心安全带，floor 无越界风险）。配置 δ=1.0、η=0.3、β=1.0，总损失 L = Lgen + β·Lcal。

训练流程两阶段：先用 Lgen 分别预训 I/P 帧模型再联合训练（Vimeo-90k 每段 7 帧，GOP=7）；再以 L 微调，因校准约束仅轻微修正熵模型输出，微调时冻结除熵模型相关模块外的全部参数。注意 CIT 本身可直接部署在仅用 Lgen 训练的模型上，PGC 微调是可选项，用于压低 Cb。

### 3.4 RPC：坐标差分编码

Cb 展平为一维索引 Vb（单调递增），传输相对索引 Vrel(i)=Vb(i)−Vb(i−1)，每坐标比特由 log2(C×H×W)=20（此处 C×H×W=737280）降为 log2(max(Vrel))。坐标越密，差分值越小、比特越省；论文按“校准位置在 latents 内均匀随机分布”的假设估计平均比特数。

### 3.5 实时化设计

- **剪枝 + I/P 非对称容量分配**：论文未展开剪枝算法本身（仅引用通用通道剪枝/蒸馏文献），给出结果口径：I 帧模型 950G→252.6G MACs、P 帧 1100G→161.7G MACs。设计上刻意让架构更简单的 I 帧模型承载更多参数与 MACs（23.71M/252.6G vs P 帧 10.17M/161.7G），实测 I 帧编码反而更快（26.0ms vs 36.5ms @A100）——**MACs 不等于墙钟时间**，架构的并行友好性主导实际耗时。
- **运动估计降采样**：运动估计网络输入降采样 ×2，计算量降为 1/4，主要节省编码端开销；因模型尺度不变，只需在最终优化阶段微调，无需重训运动模型。
- **算术编码跳过**（承 AlphaVC 的 skipping 策略）：当 θi 极小（模型对该元素高度确定）时跳过其算术编码，编解码两端直接采用估计值 μi。针对的是算术编码串行化这一最大时间瓶颈；论文指出分块并行化 AC 亦可行但本文未采用。

## 4. 实验结果

**设置**：训练 Vimeo-90k（89800 段 448×256，随机裁 256×256）；评测 UVG，每序列 96 帧、GOP=12，中心裁剪至 1920×1024（可整除 64），速度测试再裁至 1280×768（720P）。λ 取 (85,170,380,840)（PSNR）与 (10,20,40,100)（SSIM）。跨平台配置：A100（AMD EPYC 7K62）编码 / RTX 2080（Intel Xeon W-2133）解码，PyTorch 2.0、FP32 推理。锚点为 FFmpeg H.265 medium。

**RD 性能**（UVG，BD-rate，负值表示相对锚点省码率）：

| 方法 | PSNR-BPP | SSIM-BPP |
|---|---|---|
| H.264 | +45.8% | +32.6% |
| Ours 同平台（无 CIT） | −25.6% | −34.1% |
| Ours 跨平台（w CIT） | −24.2% | −33.7% |

跨平台加 CIT 后 PSNR 口径仅损失 1.4 个百分点、SSIM 口径 0.4 个百分点；无 CIT 时跨平台全部帧解码失败，根本无法产出 RD 曲线。与 MobileCodec 的 UVG 对比中，后者是唯一可参照的实时帧间神经解码器，但不处理跨平台一致性。头条配置（ϵ=1e-4 + PGC）下最大 PSNR BD-rate 收益即摘要的 24.2%。

**效率与复杂度**（GOP=1 I + 11 P，720P，FP32）：

| 模块 | Params | MACs | 时间 |
|---|---|---|---|
| I model（编码，A100） | 23.71M | 252.633G | 26.0 ms |
| P model（编码，A100） | 10.17M | 161.686G | 36.5 ms |
| I decoder（解码，2080） | 20.95M | 160.683G | 37.1 ms |
| P decoder（解码，2080） | 8.75M | 76.311G | 39.9 ms |

GOP 平均编码 35.6 ms/帧（A100，28.1 FPS）、平均解码 39.7 ms/帧（2080，25.2 FPS）。论文强调测试全部跑在无并行加速的 PyTorch 2.0 上，工程优化空间还很大，1080P 实时解码被认为高度可行（展望而非实测）。

## 5. 消融要点

**CIT 有效性**（UVG ReadySteadyGo，96 帧 1920×1024；CPU1=EPYC 7K62、CPU2=Xeon W-2133、GPU1=A100、GPU2=RTX 2080）：无 CIT 时同平台失败率 0%，跨平台组合 94.8%（CPU1→CPU2）、99.0%（CPU1→GPU1）、96.9%（CPU1→GPU2 / GPU1→CPU1 / GPU1→CPU2）、100%（GPU1→GPU2）；ϵ∈{1e-4, 1e-3, 1e-2} 的 CIT 下 8 种组合全部 0% 失败。

**PGC**（RD 与坐标数双口径）：

| 0（不校准） | −25.6% / – | – |

跳过不超过 70% 时 BD-rate 仅退化 1.1 个百分点，63.4% 处完全无损——印证高置信元素本可不参与串行熵编码，是极具性价比的加速旋钮。

## 6. 贡献与启示

**方法论贡献**：把跨平台确定性问题从“改造网络数值精度”（integer-only / QAT / PTQ 路线，均需再训练）重构为“**对齐熵参数离散化结果 + 少量显式边信息**”。识别出 σ 离散化是不一致的唯一放大点后，探针式越界检测（±ϵ 扰动探针）加“按坐标切换量化函数”即可零训练达成一致，且与模型架构解耦，对任何使用熵模型与算术编码的方案具备普适性——这是本文最有迁移价值的思路。

**工程启示**：(1) 该方案的隐含前提是 FP32 级别的平台间偏差（实测 5e-5）；若以 FP16/混合精度部署，偏差上升会迫使 ϵ 增大，校准坐标数按数量级膨胀（ϵ=1e-2 时即使带 PGC，BD-rate 已劣化到 +36.7%，差于锚点；论文自述误差达 1e-1 时辅助码流过大、方案失效）。(2) I/P 帧非对称容量分配（简单架构多给算力）与“运动估计降采样 + 尺度不变架构免重训”是可直接复用的轻量化手段。(3) 熵编码串行化是实时 NVC 的核心瓶颈，70% 跳过仅损 1.1pp 说明其计算冗余度；分块并行 AC 被点名可行但未做。(4) 测试基于无并行加速的 PyTorch 2.0，35.6/39.7 ms 的单帧耗时应视为工程化前的保守值。

**局限**：RD 锚点是 H.265 (medium) 而非 x265 slower 或 VTM，与 SOTA NVC 的离线 RD（超 VTM 一档）不在同一目标带，是明确的实时性取舍；失败率实验只用单序列（ReadySteadyGo）；评测仅 UVG；1080P 实时是展望。校准开销与跨平台误差强耦合这一根本限制由论文自身坦承。
