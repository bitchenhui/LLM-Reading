# UVG-VPC: Voxelized Point Cloud Dataset for Visual Volumetric Video-based Coding

> Guillaume Gautier, Alexandre Mercat, Louis Fréneau, Mikko Pitkänen, Jarno Vanne. *arXiv:2504.05888v1 (2025-04-08)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

体积媒体（点云、网格）配合 6DoF 是 XR 视觉形态的核心，其存储与传输压力倒逼压缩标准化。MPEG 的 V3C（ISO/IEC 23090-5:2021）统一压缩点云、带深度沉浸视频与网格等体积帧表示，当前含两个标准：V-PCC 与 MIV，本文聚焦 V-PCC。技术路线上，V-PCC 属"video-based"范式：将 3D 点云组织为 2D patch 序列后复用成熟视频编码器压缩几何与属性（论文引 [2] 综述口径）。因此 V-PCC 的研发评估天然横跨两端——上游是体积采集与 3D 内容特性（运动、纹理、遮挡），下游是 2D 视频编码工具链；合格的测试集必须同时覆盖两端变量。

评估侧的刚性约束是：RD 评估要求测试集覆盖广谱内容，且 V-PCC 主要面向电信与 XR 应用，CTC（ISO/IEC JTC1/SC29/WG11 N19518，2020）明确测试内容为体素化全身人形点云。作者的缺口分析（Table I 口径）：
- CWIPC-SXR（21 序列、30 fps、596–2768 帧、7 相机）与 Volograms & V-SENSE（3 序列、149–1830 帧、12/60 相机）**未体素化**，格式上无法直接进入 CTC 流程；
- 体素化数据集各锁单一精度：8iVFB v2（4 序列、300 帧、42 相机、10 bit）与 Owlii（4 序列、600 帧、11 bit）仅**部分进入 CTC**，8iVSLF（7 序列、1300 帧、39 相机、12 bit）精度档单一；
- 规模与内容维度覆盖均有限，结论是"没有一个对 V-PCC 工具开发是最优的"。

作者的贡献声明（原话口径）：UVG-VPC 是"第一个且唯一完全为 V-PCC 编码技术的开发、评估与验证而设计"的数据集。本笔记按数据集类论文的自身评价维度——格式合规性、内容覆盖与受控性、管线可复现性、开放深度——来评估其价值，并将其在音视频技术链条（多相机采集 → 3D 表示 → 2D 视频编码 → XR 流媒体）中的位置写明。

## 2. 方法总览

**采集端：Mantis Vision 体积采集棚。**
- 32 个相机单元（19 长 + 13 短），每单元 = 2×RGB + 1×IR 投射器 + 1×IR 相机 + 1×Intel NUC（i7-8665U @1.90 GHz、32 GB RAM、1 TB Samsung 970 EVO Plus SSD），即"有源 IR 立体深度 + RGB 外观"的混合采集；Table I 的 96 相机口径 = 64 RGB + 32 IR（32 台 IR 投射器不计入）。
- RGB 为 UI-328xCP-C（长）/ UI-308xCP-C（短），分辨率均为 2456×2054；立体基线长单元约 30 cm、短单元约 10 cm（长短混配以覆盖不同深度尺度，笔记推断）；IR 相机 UI-314xCP-M，640×512。
- 互连：10 Gbps 交换机树型拓扑，每台交换机接 4 个相机单元、两台交换机上联渲染主机（论文原文口径）。曝光调度：各相机在彼此微错开的时刻曝光以规避 IR 互扰，相对布置的相机同时曝光。光照：40 根 50 W LED 灯管，Sync LED 按录制帧率闪烁触发同步。
- 空间与帧率：棚体高 2.5 m、直径 3 m；可扫描体积高 2.2 m、直径 1.6 m；多数相机布置于上半部以提升面部采集质量；采集帧率上限 25 fps——这直接决定数据集为 25 fps（legacy CTC 内容均为 30 fps，Table I 口径），混用评估时需注意。

**生成管线（5 步；前 2 步为采集棚现货流程，后 3 步为本文设计，目标是使产物匹配 CTC 格式）：**
1. **点云采集**：NUC 将本单元 RGB+IR 融合为点云，连同相机数据经网络送渲染主机合并为 Raw Merged Point Cloud（.ply）。
2. **网格生成**：现货 Poisson 表面重建，得到 Mesh（.obj / .mtl / .jpg）。
3. **网格采样**：trimesh 库的 triangle point picking，从网格固定采样 10,000,000 点得 Sampled Mesh Point Cloud（.ply）；采样数是"足以支撑后续体素化 vs 可接受内存占用"的折中（论文明述口径）。
4. **体素化**：点云落入规则 3D 栅格，体素记录占用与否；体素内多点颜色取平均；体素边长 = 采集系统包围盒在所有维度上最大尺寸 / 2^N，N ∈ {9, 10, 11, 12}，几何精度 9–12 bit，RGB 属性 8 bit，输出 4 档 Voxelized Point Cloud（.ply）。
5. **法线生成**：Open3D 的 Knn 法线估计（12 邻居），为每个体素化点云输出 Normals（.ply）；依据是 CTC 用法线计算 D2 质量指标，随集发布可保证方案间公平比较。

值得注意的路径选择：管线并非对 Raw Merged PC 直接体素化，而是先 Poisson 网格化再均匀重采样。论文未解释该选择，工程上可解读为（笔记推断）：网格化隐式去除多视图融合噪声与悬浮点，采样点数成为可控的表面密度参数，使不同序列、不同精度下的体素化输入一致化；代价是属性经"网格化-重采样-体素平均"三次重采样。该推断可利用其开放的中间产物自行验证。

**开放策略**：除最终序列外，Raw Merged PC、Mesh、Sampled Mesh PC 中间产物全部开放，用途有二：自选几何精度重做体素化；服务网格生成与动态网格压缩等外溢方向（论文引 MPEG DMC 正式评估 [17]）。数据集与许可证见 ultravideo.fi/UVG-VPC/，为自有非商业许可。

## 3. 关键设计

**(a) 多精度体素化（9–12 bit）**。同一内容提供 4 档几何精度，覆盖全部 legacy 档位（10/11/12 bit）并向下增补 9 bit。评估意义：可做"精度-码率-质量"跨档扫描而非单点结论；在 V-PCC 中几何精度直接决定 occupancy/geometry patch 分辨率与属性映射粒度。体素边长锚定在采集系统包围盒的最大维度上，同一采集系统内物理体素间距跨序列一致、可比；若包围盒非立方，各轴有效采样密度不均（笔记推断，属 CTC 类惯例做法）。

**(b) 体素内颜色平均（明述规则）**。等价于对属性做体素尺度盒式滤波：粗精度档（9/10 bit）下纹理保真被体素化本身截断。对纹理 Complex 的序列（FlowerDance / FlowerWave），低精度档的属性编码增益评估需把该上限计入（推论）。

**(c) 10^7 采样点**。论文给出的口径仅为"体素化充分性 vs 内存"折中。可复核性来自中间产物开放：社区可改动该参数重跑第 4–5 步。

**(d) 法线随集发布（K=12 固定）**。D2 指标计算不再依赖各实验室自行估法线，消除跨实验室比较中的一个噪声源——这是数据集论文中少见的"评估协议完整性"设计。

**(e) 对比式内容设计（方法论核心）**。五维刻画：speed（动点速度）、motion field（动点数量）、RGB texture、3D geometry、surface occlusion（出现/消失点数量），各维分档。论文明述 12 条序列特征组合两两不同；更实质的是成对受控设计（依 Table III/IV 归纳）：
- BlueSpin vs CasualSpin、BlueSquat vs CasualSquat：同动作（匀速定轴旋转 / 深蹲），纯色 vs 条纹上衣+牛仔裤，主变量为纹理——属性编码归因实验的现成素材；
- ElegantDance vs FlowerDance、ElegantWave vs FlowerWave：同动作（舞裙旋转起舞 / 挥手），纯色长裙 vs 花裙，构成"复杂几何+简单纹理 vs 复杂几何+复杂纹理"对照；
- Dance vs Wave 同服装对照"Fast+Dense vs Slow+Sparse"运动场；
- BlueBackpack（从背包取外套穿上）、ReadyForWinter（戴帽子围巾）：配件交互制造复杂表面与 Plenty of 遮挡；
- HelloGoodbye：入出场设计，序列首尾捕获空间为空；
- Gymnast：单腿支撑的腿部遮挡。

这一控制变量式设计使数据集天然支持归因分析（如"纹理复杂度对属性编码增益的贡献"），而非仅端到端 RD 排序。

## 5. 消融要点

论文无传统消融实验；以下区分论文明述的权衡与笔记推断：
1. **采样点数 10M（明述）**：体素化充分性 vs 内存占用；中间产物开放使该参数可复核、可改动。
2. **体素边长 = 包围盒最大维度 / 2^N（明述）**：物理体素间距跨序列一致；包围盒非立方时各轴有效分辨率不均（推断）。
3. **体素内颜色取平均（明述）**：低精度档纹理保真受体素化本身限制，跨精度比较属性编码时应计入（推论）。
4. **25 fps（明述为采集系统上限）**：与 legacy CTC 的 30 fps 内容混用时时间采样间隔不同，时间预测与码率分配行为可能不同，需实测验证（推断）。
5. **法线 K=12 固定并随集发布（明述）**：保证 D2 可复现、跨方案公平。
6. **经网格再采样而非直接体素化 Raw PC（设计选择，论文未解释动机）**：降噪与采样密度可控的收益 vs 属性多次重采样的损失（推断，可由开放中间产物验证）。
7. **非商业许可证（明述）**：限制工业基准与商业用途。
8. **单人内容（依 Table III 描述归纳）**：12 条均为单人场景，多人交互与接触遮挡缺位；且论文未附基线 V-PCC 编码结果与主观质量实验，RD 锚点需使用者自建。

## 6. 贡献与启示

按数据集论文自身标准衡量：
- **格式合规**：直接命中 V-PCC CTC 输入格式（体素化几何 + 8-bit RGB + 法线），且一次覆盖 9–12 bit 四档，超越所有 legacy 单精度数据集；
- **覆盖与受控性**：五维特征刻画、12 组合互不重复、成对受控设计，支持归因式评估——这是本数据集区别于"素材堆"类数据集的方法论价值；
- **可复现与开放深度**：管线第 3–5 步全用开放库（trimesh、Open3D），中间产物开放使体素化可再生成、网格资产可外溢至 DMC 研究；
- **规模**：12 序列 × 250 帧 × 4 精度 + 法线，96 相机稠密有源立体的采集规格在同类开放数据集中最高（Table I 口径）。

对音视频上下游的启示：
- V-PCC 的"video-based"本质使 3D 内容最终落到 2D 视频编码器上，UVG-VPC 因此是视频编码工具（时间预测、环路/后置滤波等）进入体积视频工作负载的现成评估载体，也是 UVG 组从视频编码标准评估（同组的 UVG 数据集脉络）向体积媒体的自然延伸；
- 上游启示：96 相机 RGB+IR 有源立体稠密棚是 CTC 类内容的现行产线，其 25 fps 上限、单棚单主体构成本类基准的内容供给约束（产线由 Nokia 主导的 XR-SPACE 项目等资助，CIVIT/CSC 提供设施）；
- 方法论可迁移：对比式内容设计 + 中间产物开放，值得点云、网格、高斯等各类体积媒体基准借鉴；
- 使用注意：25 fps、单人、无主观/基线锚点、非商业许可四点约束决定了其在工业级评测与多人场景评测中的边界。

## 7. 与其他论文的联系

- **paper:arxiv:2610.04281（OctMesh，无损三角网格压缩）**：UVG-VPC 明确开放 Mesh 中间产物（.obj/.mtl/.jpg）并点名动态网格压缩为潜在用途（论文第 III 节末段引 MPEG DMC 评估）；无损网格编码器可直接将该网格资产用作测试内容。依据：论文开放中间产物的声明与格式清单。
- **paper:arxiv:2609.23606（TexF 表面对齐纹理场网格纹理压缩）**：同上，网格资产自带 .mtl/.jpg 纹理，表面对齐纹理场类方法可在同一内容上做网格纹理压缩评估，与本文网格外溢用途直接对接。依据：中间产物格式清单。
- **paper:arxiv:2609.37328（CASR，VVC 后置神经超分滤波）**：V-PCC 将几何/属性投影为 2D patch 后由视频编码器压缩（论文 [1][2] 的 video-based 定位），视频侧后处理改进可直接传导为 V-PCC 链路 RD 变化；UVG-VPC 正是评估"VVC 滤波 × 体积内容"组合的内容源。依据：V-PCC 对 2D 视频编码器的依赖关系。
- **paper:arxiv:2609.29041（双阶段 Morton 排序的 3DGS 编码）**：与 V-PCC 同属"3D 数据 2D 化 + 复用视频编码器"范式族；UVG-VPC 面向该范式的标准化分支（V-PCC），两类方法的对比评估可共享内容基础。依据：编码范式同源。
- **paper:arxiv:2609.33969（SAGA）/ paper:arxiv:2610.21121（ResStreamGS）**：3DGS 路线的动态体积视频压缩与移动端流式传输，与 V3C/V-PCC 面向同一 XR 流媒体应用与同类全身动态人体内容，属竞争表征路线；用 UVG-VPC 做跨表征对比时需先做表征转换适配（体素点云 vs 高斯资产）。依据：应用与内容类型重合、表征不同。
- **paper:arxiv:2610.25887 / paper:arxiv:2610.04606（稀疏视角 3DGS/4DGS 重建）**：采集端替代路线——少相机 + 监督增强/生成先验 vs 本文 96 相机稠密有源立体棚；两者产出同类全身动态人体体积内容，直接关系此类基准数据集的产线成本与可扩展性。依据：采集范式的对照关系。
