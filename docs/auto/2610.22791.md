## 1. 背景与动机

LLM 编码智能体的性能由两个组件共同决定：**policy model**（决定能力边界的模型本身）与 **harness**（决定能力如何被激发的外部脚手架——控制模型观测到什么、动作如何执行、收到什么反馈、episode 何时终止）。同一个模型配不同 harness，在同一问题上的成败可能完全不同。这是本文的问题出发点。

现有改进路线各自存在结构性缺陷：

- **Harness-only 优化**（固定 policy，搜索 prompt/workflow/agent 代码）：无法提升底层模型能力；
- **Policy-only 优化**（固定 harness，从成功轨迹或可验证奖励更新权重）：只能学到固定 harness 所能引导出的轨迹分布内的行为——harness 成为策略学习的采样上界；
- **近期联合优化工作**（WHALE、Evo2、HASE、MetaRSI 等）依赖**外部 harness proposer** 或为 frozen solver 训练独立 proposer，且都面临一个共同挑战：随着 policy 及其失败模式演化，优化目标是移动的（moving optimization target），而它们的 harness 搜索大多在固定任务集上进行，无法跟上失败模式的漂移。

核心动机由此形成：**harness 与 policy 互为强化**——为一个 checkpoint 调好的 harness 未必命中更新后 policy 的失败模式；policy 学习又被固定 harness 的轨迹引导范围所限。单独演化任何一方都是次优的。本文要回答的问题是：能否让编码智能体用**自己的 evolving policy 作为 harness proposer**，实现自驱动的递归自我改进（self-driven recursive self-improvement），同时让 harness 搜索目标跟随 policy 的失败模式演化。

工程视角下这个问题很实际：SWE agent 的部署形态就是“模型 + scaffold”，工业界普遍只优化其中一端（要么调 prompt/框架，要么 RL 训模型），本文给出了两端交替联合优化的可行配方。

## 2. 方法总览

**Self-HPO（Self Harness-Policy Optimization）** 是一个递归自我改进框架，交替执行两类更新：

- **H-step（harness 优化）**：冻结当前 policy $P_t$，令其兼任 task solver 与 harness proposer。当前 $(H_t, P_t)$ 对在搜索集 $S_t$ 上生成轨迹，proposer 检查失败证据并提出针对自身失败模式的 harness 修订（prompt 或可执行 runtime 逻辑）。K 次搜索迭代从 $H_t$ 出发逐步修订当前最优 harness（利用已评估 harness 及其轨迹的累积经验），所有候选在同一 $S_t$ 上评估，保留得分最高者作为 $H_{t+1}$。
- **P-step（policy 优化）**：冻结 $H_{t+1}$，在其上通过 RL 更新 $P_t \to P_{t+1}$。更新后的 policy 成为下一轮 harness proposer；训练中从未被解决的 hard task 构成下一轮搜索集 $S_{t+1}$。

形式化：给定任务 $x$，轨迹 $\tau \sim \pi_{H,P}(\cdot|x)$ 由可执行 verifier 打分 $y(x,\tau) \in \{0,1\}$，优化目标为 harness–policy 对的期望 resolve rate $J(H,P) = \mathbb{E}_{x\sim D}\mathbb{E}_{\tau\sim\pi_{H,P}}[y(x,\tau)]$。

算法循环（Algorithm 1）：从基座 $P_0$、种子 harness $H_0$、随机初始化 $S_0 \subset D$ 出发，每轮先 H-step 后 P-step，**停止条件为 hard-task 集在轮间稳定**。实验中实际执行了两轮交替（Base→H1→P1→H2→P2）。

两种实例化：

1. **Self-HPO（自改进设定）**：evolving policy 自己提 harness 候选，无需独立 proposer 模型；
2. **HPO（外部模型设定）**：同一交替循环，但用 Opus 4.8 作固定外部 proposer。

这一对照设计使得“自提议 vs 外部提议”可以干净解耦——消融中把 HPO 的外部 proposer 换成当前 policy 即得 Self-HPO。

## 3. 关键设计

### 3.1 失败条件化的 harness 搜索

H-step 的 proposer 本身以编码智能体形态运行（带 shell 访问），可读取：父 harness、其在搜索集上的轨迹、搜索集任务的参考修复、此前候选的输出、以及各轮追加的 notes。提案受严格约束：**父 harness 的所有方法逐字保留，每次只新增恰好一个机制**；policy、采样配置（temperature 0.95 / top-p 0.95）、step limit、最大 token、verifier 全部冻结；禁止注入参考 patch 或任务特定事实——机制必须在运行时自行计算信号（这一约束直接决定了 harness 改动能泛化到 OOD 而非记住训练任务）。

诊断信息按四个维度结构化：**coverage gap**（参考修复所需源文件 vs agent 实际触碰的文件）、**precision gap**（改对了文件但修复错误）、**submission loss**（轨迹中有真实源码编辑但最终提交 patch 为空/畸形）、**reference-fix archetypes**（多文件、签名变更、新 import、guard、错误处理等模式 vs agent 实际产出）。proposer 自行判断哪个失败最主导、最可被 harness 触达。搜索空间上，候选是子类化种子 agent 的 Python 类加 prompt 模板，可 override `step()` 以检查状态、在接受提交前返回反馈、替换提交 patch、或在任意步骤干预。

这套设计的工程含义：harness 搜索不是模糊的 prompt 进化，而是**基于可执行证据的因果性修补**——每个机制要求有 agent 自身状态中可检测的触发器 和具体动作。

### 3.2 演化搜索集：hard task 驱动目标对齐

搜索集在 H-step 内固定、跨轮演化。$S_0$ 从 $D$ 均匀采样 300 任务；之后每轮 $S_{t+1}$ 由前一个 P-step 训练轨迹中**从未被任何 rollout 解决**的任务构成（任务 ID 复用，下一 H-step 用更新后的 harness–policy 对重新生成新鲜失败证据）。这与 prior work 在固定任务集上搜索形成本质区别：harness 优化始终瞄准**当前** policy 的失败模式，而非反复优化对初始任务的拟合。消融显示固定搜索集会损失 1.5 点。

### 3.3 P-step 的 RL 配方

默认优化器为 GRPO + Orchard 的 Balanced Adaptive Rollout（BAR）。BAR 自适应追加轨迹构造奖励均衡组：每任务生成 8 条 rollout，选出 4 条构成成功分数在 0.25–0.75 之间的均衡组，采样持续到 32 组通过过滤（每 batch 128 条训练轨迹），缓解二元 outcome 奖励下零方差组无梯度的问题。损失为 assistant token 上的 clip 目标，$\varepsilon_{low}=0.2$、$\varepsilon_{high}=0.28$；Adam，学习率 $10^{-6}$，weight decay 0.01，entropy 系数 $10^{-4}$，无 KL 惩罚；rollout 温度 0.95/top-p 0.95。每个 P-step 50 次更新，从上一轮 policy 检查点续训。基础设施：SGLang 服务 Qwen3.5-35B-A3B，slime 框架，单节点 8×B200。

### 3.4 演化出的 harness 长什么样（case 层面的机理）

第二次 H-step 选出的 harness 完整继承种子 agent 循环，仅 override `step()` 增加四道检查，各自对应一类“有效仓库编辑未能变成有效提交”的失败模式：

1. **Budget valve**：接近 step/时间上限且未提交时注入一次性消息，强制停止探索、做最小改动并立即提交（对抗空结果终止）；
2. **Empty-patch guard**：一次性拦截空提交，提示 `git add -N` 暂存新建文件（对抗 untracked 新文件导致 `git diff` 为空）；
3. **Contract grounding**：拦截通过空检查的首次提交，要求对照仓库既有测试核对 API 名称/签名/错误形状（对抗“patch 能 apply 但实现了猜出来的错误契约”）；
4. **Patch fallback**：最终提交无法 clean apply 时，改用沙箱自身 `git diff` 作为提交。

值得注意的机理细节：这些改动是**运行时检查 + 行为引导的混合**，每条消息至多触发一次并附带一轮额外 policy 回合——即 harness 学会了“何时该给模型第二次机会”而非改写模型行为。附录 E 的对照案例（sphinx-doc__sphinx-9658）显示：同一 policy $P_2$ 在种子 harness 下以 prose summary 结束导致零分，在 $H_2$ 下被拦截首提交后写出有效 diff 并解决任务——直接展示了 harness 干预对固定 policy 的翻转能力。

## 4. 实验结果

**设置**：Qwen3.5-35B-A3B（35B 总参/3B 激活）为 base policy，mini-SWE-agent 为种子 harness；训练集 2,484 任务（SWE-rebench、SWE-rebench V2、Scale-SWE），两轮 H/P 交替，K=6 候选/H-step，50 RL 更新/P-step。评测：SWE-Bench Verified（500 任务，主基准）、SWE-Multi（300 任务、9 种非 Python 语言）、SWE-Pro 公开 V2 集（642 任务）；resolve rate，三次评测均值±标准差（avg@3）。基线：自改进设定下 RLVR（种子 harness 下 RL 训 policy）与 Self-Harness（用 base policy 提案优化 harness、不更新权重）；外部模型设定下 SFT（蒸馏 Opus 4.8 已解决轨迹）与 Meta-Harness（Opus 4.8 优化 harness、policy 冻结）。

**主结果（Table 1，resolve rate %）**：

|---|---|---|---|---|---|---|
| Base | ✘ | ✘ | 61.0±0.2 | 54.2±0.3 | 58.3±1.2 | 57.8±0.4 |
| SFT (Opus 4.8) | ✘ | ✓ | 65.0±1.1 | 49.6±0.8 | 49.1±0.6 | 54.6±0.5 |
| Meta-Harness | ✓ | ✘ | 69.1±1.9 | 56.5±0.9 | 64.8±1.4 | 63.5±0.8 |

| RLVR | ✘ | ✓ | 67.5±0.8 | 56.3±1.0 | 61.8±1.3 | 61.9±0.6 |

关键读数：

- **自改进设定**：Self-HPO 在 SWE-Verified 达 69.5%，超 RLVR 2.0 点、超 Self-Harness 4.3 点；平均分从 Base 的 57.8% 升至 64.8%（超最强单组件基线 RLVR 2.9 点）。
- **外部模型设定**：HPO 在 SWE-Verified 达 71.6%，超 Meta-Harness 2.5 点，平均高 2.8 点。
- **OOD 泛化**：训练只用 Python 任务，但增益迁移到 SWE-Multi（+5.5 vs Base）与 SWE-Pro（+6.9 vs Base），两处均超 RLVR 3.4 点。尤其 SWE-Multi 上 Self-Harness 仅比 Base 高 0.1 点，而 Self-HPO 高 5.5 点——说明纯 harness 改动难以跨语言迁移，而 harness 内化进权重后可以。
- **蒸馏对照**：Meta-Harness 比 SFT 在 SWE-Verified 高 4.1 点、平均高 8.9 点；SFT 在两个 OOD 基准上甚至低于 Base，Meta-Harness 两处均提升——从强模型迁移知识时，优化 harness 比蒸馏轨迹到权重更有效且不损伤 OOD。
- **交替轨迹**：共享首个 H-step 后，Self-Harness 在 SWE-Multi 从 55.0% 降到 54.3%（继续 harness-only 更新不稳定），而 Self-HPO 的第二个 H-step 与随后的 P-step 均持续提升，最终在所有基准超过两个单组件基线。
- **前沿对照（附录 Table 4，SWE-Verified 排行榜口径，mini-SWE-agent harness）**：Self-HPO 的 69.5% 已超 Gemini 3 Pro（69.6% 之下，即 69.5% 略低于其 0.1 点——准确说接近持平）、DeepSeek-V3.2（70.0%）以下、Kimi K2.5（70.8%）以下，但显著高于 GPT-5 mini（56.2%）、Qwen3-Coder-480B-A35B（55.4%）、GLM-4.6（55.4%）等；即一个 35B/3B 激活模型经联合优化可逼近或超越多数更大前沿模型。注意表中 Self-HPO 与 Gemini 3 Pro 的差距仅 0.1 点。

**分析性结果**：

- **pass@k（8 attempts，SWE-Verified）**：Self-HPO 对所有 $k\in[1,8]$ 高于 Base，pass@8 从 80.0% 升至 84.8%（+4.8）。按 Base 成功率分层（$p=0$ 为 Hard、$0<p\le 0.5$ 为 Medium、$0.5<p<1$ 为 Easy、$p=1$ 为 Resolved）：pass@1 增益 Medium +17.2、Easy +12.9、Hard +6.1，但 Resolved 组 **−2.2**——改进不均匀，存在少量原本稳定解决任务的回退。
- **训练信号质量**：最终 P-step 的零成功组比例在最后 10 次更新降至 6.5%，而 RLVR 最后 50 次更新维持在 11%–17%——优化后的 harness 确实在结构上缓解了二元奖励稀疏问题，这是 H→P 协同的一个直接机理证据。

## 5. 消融要点

在 SWE-Verified 上以 HPO（71.6%）为参照消融共享的 H-step–P-step 框架：

| 配置 | Resolve rate (%) |
|---|---|
| HPO | 71.6 |
| w/ SFT in P-step | 67.2 (−4.4) |
| w/ RFT in P-step | 70.5 (−1.1) |
| w/ Fixed search set in H-step | 70.1 (−1.5) |
| w/ Self-proposer in H-step | 69.5 (−2.1) |

三点结论：

1. **RL 优于 SFT/RFT 作为 P-step**：即使用 policy 自身成功轨迹做拒绝采样微调（RFT）仍比 RL 低 1.1 点，SFT（Opus 4.8 蒸馏轨迹）低 4.4 点——RL 应为默认。
2. **演化搜索集有效**：复用初始搜索集降 1.5 点；用前一 P-step 的 hard task 刷新搜索目标，使 harness 优化跟上 policy 进化。
3. **自提议保留大部分性能**：外部 Opus 4.8 proposer 换成当前 policy 仅降 2.1 点（71.6→69.5），且仍高于自改进设定两个单组件基线——外部模型有用但非必需，闭环自我改进成立。

**交叉评估（Table 3，SWE-Verified，行=harness、列=policy）**：$H_0/P_0$=61.0；$H_2$ 配 base policy 达 64.5（+3.5）；$P_2$ 配种子 harness 达 64.4（+3.4）；$H_2+P_2$=69.5（+8.5），**超两个组件单独增益之和（6.9）1.6 点**——超加性互补，是本文“联合优化优于边际优化”论断的最硬证据。另从矩阵可见对角线（$H_1/P_1$=67.8、$H_2/P_2$=69.5）高于错配组合（$H_2/P_0$=64.5、$H_0/P_2$=64.4），说明 harness 与 policy 存在协同适配。

**搜索过程（附录）**：首个 H-step 达 64.3% 后，继续 harness-only 搜索 12 候选最高到 65.2%；Self-HPO 分支先 P-step 到 67.8%，再 H-step 到 68.6%、P-step 到 69.5%——policy 更新“抬高了”后续 harness 搜索的起点。

## 6. 贡献与启示

**主要贡献**：（1）首个针对编码智能体、以 evolving policy 自身作 harness proposer 的递归自改进框架，且 harness 搜索集由 RL 训练中暴露的 hard task 驱动（论文Related Work 表格确认：同时具备“RL policy 更新 + evolving self-proposer + evolving 搜索集”三要素的仅此一家）；（2）三基准上系统证明联合优化优于单组件优化（57.8→64.8 平均分），增益 OOD 可迁移；（3）交叉评估揭示 harness/policy 增益的超加性互补；（4）pass@1 与 pass@k 同时改善——可靠性与能力前沿双提升，这对工业部署的抽样预算决策有直接意义。

**方法学启示**：

- **Harness 优化是比 SFT 更安全的知识迁移通道**：SFT 在 OOD 上低于 Base（能力收缩），而 harness 注入的机制（如 contract grounding）不改变权重、天然保留基座泛化性，再经 P-step 选择性内化——这是“先外挂、后内化”的两段式迁移范式。
- **失败诊断的结构化 taxonomy（coverage/precision/submission loss/archetypes）是可复用的工程资产**，可直接移植到任何 SWE agent 的 scaffold 迭代流程中。
- **Harness 优化的产出是“提交完整性保障机制”**：四道检查全部瞄准“编辑有效但提交无效”的失败类，提示这类损失在 SWE agent 总失败中占比可观，值得在自研 harness 中预先内置。

**局限与保留**：训练/搜索仅基于 Python 任务，OOD 结论限于三个 SWE-Bench 变体；仅两轮交替即触发停止条件（hard-task 集稳定），更长程递归的行为未验证；Resolved 组 −2.2 点的回退未深入分析；35B-A3B 单一基座，对更强/更弱模型的可复现性未报告；自提议与外部提议仍有 2.1 点差距，说明“自我诊断”能力受 proposer 水平约束。

## 7. 与其他论文的联系

以下条目与本文同属 **LLM 智能体递归自我改进** 这一快速成形的研究谱系，但关联性质各异：

- **paper:arxiv:2611.12109（SkillDuet）**：与 Self-HPO 同属“内外双组件协同演化”框架——Self-HPO 交替优化 harness 与 policy 权重，SkillDuet 以响应反馈协同 LLM 参数更新与外部技能库演化，实现技能级递归自我改进。两者共享的核心命题是：外部可演化组件与模型权重应联合更新而非单独优化，Self-HPO 的交叉评估结论（联合增益超加性）为这一命题提供了编码域证据，SkillDuet 可视为该命题在技能库粒度上的对应工作。
- **paper:arxiv:2611.14326（FGSE）**：处理同一“自我改进回路中何者应被写入”的安全面问题。Self-HPO 的 H-step 在提案约束中禁止注入任务特定事实、每轮只加一个可运行时验证的机制，可视为对 harness 进化污染的隐式防护；FGSE 则将经验教训作为可证伪假设经探针验证后写入记忆，把这种防护显式化、系统化为 falsification gate。两者互补地回答“自进化系统的更新安全”问题。
- **paper:arxiv:2611.10787（TRUST）**：直击 Self-HPO 未处理的统计风险面。Self-HPO 依赖经验性停止条件（hard-task 集稳定）与搜索集性能选择 harness，递归轮数加深时的错误累积无理论保证；TRUST 用在线多重假设检验控制错误进化率并提供统计保证，可作为 Self-HPO 这类 RSI 框架在选择/停止环节的理论加固层。
- **paper:arxiv:2611.14949（RSI-PDEbench）、paper:arxiv:2611.11558（InfraRSI）、paper:arxiv:2610.33845（AutoTavern）**：三者与 Self-HPO 构成递归自我改进在**不同任务域**的平行实例——PDE 求解、LLM 训练基础设施优化、游戏 AI 构建——均在无人工干预下迭代提升智能体能力。共性结构（失败驱动的迭代、验证器闭环）与 Self-HPO 的 H/P 交替一致；差异在于 Self-HPO 明确分解出 harness 与 policy 两条可分别演化的轴并证明其互补性，这一分解对这些域内的 scaffold 迭代同样适用。
