# OPT-BENCH: Evaluating the Iterative Self-Optimization of LLM Agents in Large-Scale Search Spaces

> Xiaozhe Li, Jixuan Chen, Xinyu Fang, Shengyuan Ding, Haodong Duan, Qingwen Liu, Kai Chen. *arXiv:2605.08904v1 (2026-05-09)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

论文的核心问题是：LLM 智能体是否具备**迭代自我优化**（iterative self-optimization）能力——即在缺乏外部求解器和重提示工程的前提下，仅凭环境反馈在大型搜索空间中持续精炼解。作者将其定位为区分“背记工具用法”与“内在认知适应”的关键判据：感知、推理、记忆是智能的稳定内核，工具接口快速演化，而当前评测大多停留在单轮开环范式（MMLU、BIG-bench、MATH/GSM8K、HumanEval/MBPP，乃至 NPHardEval 也是单次可解性测试），即便引入 CoT，测的也是“瞬时演绎”而非“随反馈的适应学习”。

已有的迭代类基准各有盲区：SWE-Bench/AlgoTune 关注缺陷修复与代码效率，反馈信号是单元测试通过与否；MLE-Bench 端到端跑 ML 工程流程，强调代码执行成功而非调参认知轨迹；AgentBench/WebShop/WebArena 评测“能否完成任务”，而非“能否随时间优化一个指标”。作者因此提出 OPT-BENCH，其差异化设计是**并置两类反馈地形**：

- **连续参数优化（ML，20 个 Kaggle 任务）**：反馈是带噪但有方向的标量信号（验证精度、RMSE 等），考验归纳式增量调参；
- **离散组合推理（NP，10 个经典 NP-hard 问题）**：反馈是脆性约束（valid/invalid + 错误消息），考验演绎式结构构造与局部修复。

这种“同一智能体框架、两种反馈形态”的对照设计，使论文能够剥离出**信号语义结构对自改进有效性的调制作用**这一变量——这是单域基准无法观测的。从音视频工程视角类比，这相当于同时考察“连续质量控制环路”（如编码器 RD 参数迭代调优，指标单调可导近似）与“离散结构决策环路”（如转码流水线的方案选型/配置组合，约束为硬性布尔），二者的反馈可利用性差异在工程上直接影响 LLM 智能体适合挂在哪一层。

## 2. 方法总览

整体框架分三层：数据集（OPT-BENCH）、评测智能体（OPT-Agent）、度量体系。

**数据构造**（每样本六要素）：
1. 任务描述：Kaggle 原始描述经 GPT-4o 精炼 + 人工核验消歧；NP 任务给出目标定义与示例 I/O（JSON 实例，拓扑复杂度不一）。
2. 数据规格：ML 提供 CSV 与特征描述；NP 提供 JSON 图/集合实例。
3. 提交格式：强制统一输出结构，保证自动解析。
4. 初始解（冷启动）：ML 侧用 AIDE 智能体生成初版脚本再经 4 位博士级专家精修，保证“可运行但次优”，留出改进空间；NP 侧提供一条合法但次优的解结构（如一条有效路径）。
5. 环境反馈机制：ML 在 hold-out 测试集上执行返回标量指标；NP 由规则脚本 validation.py 校验约束并给出二元判定 + 具体错误信息（如 "Node visited twice"）。这个脚本即“环境”。
6. 专家基线：ML 用 Kaggle 金牌方案作为人类专家上界；NP 用人类专家启发式（模拟退火、贪心等）作为“推理天花板”，刻意区别于工业求解器的理论最优——保证比较锚定在专家推理模式而非暴力计算。

**OPT-Agent 工作流**：设计灵感来自 AlphaEvolve 与认知 CoT 理论，刻意避免复杂提示工程与外部求解器，实现感知—记忆—推理循环，三个动作：
- **Drafting**：ML 合成 Python 训练脚本；NP 要求模型**直接构造解结构**（如路径序列），不借助代码解释器——这一约束迫使模型依赖内部规划而非把逻辑外包给执行器，是评测“内在推理”的关键设计。
- **Improving**：在拿到合法解后触发。模型作为优化器，检索历史上下文（过去的代码/路径、性能指标、反馈趋势），ML 侧做归纳推理调整架构或超参，NP 侧在保持约束合法的前提下精炼离散结构（如缩短 TSP 路径）。
- **Debugging**：环境返回失败信号（运行时错误或约束违反）时触发，模型分析错误日志诊断故障，评测自纠错与从非法状态恢复的能力。

**评测口径**：ML 环境 4 核 CPU / 32GB RAM，NP 仅需 2 核 / 16GB RAM——工程上 NP 侧的评测成本极低，可大规模复现。闭源模型走 API，开源（3B–72B）经 LMDeploy 部署。步数设置为 5/10/20 步三档，考察优化视界。

## 3. 关键设计

**度量体系**是本文方法论上最扎实的部分，四个指标构成闭环：

- **Win Count（反馈效用）**：OPT-Agent 战胜 Random Rollout（无历史上下文的无记忆生成，即下界）的任务数。高分说明性能增益来自有目的、历史驱动的精炼（基于累积信号剪枝搜索空间），而非随机波动。
- **Improvement Rate（IR）**：IR(α,β) = (1/n)Σαᵢ/βᵢ，其中 αᵢ 为优化后指标，βᵢ 为基线（初始解或无记忆生成）。IR > 1.0 表示有效利用环境反馈。注意这是逐任务比值再平均，对量纲异质的任务稳健。
- **Expert Gap（EG）**：Score_norm = (M_current − M_initial)/(M_expert − M_initial)，将 30 个异质量纲任务（MSE vs Accuracy vs 路径长度）归一到“从草稿到专家”的封闭区间，是解质量的**权威度量**。这一归一化设计与 MLE-Bench 的 leaderboard 百分位思路不同，直接以专家为锚，跨域可比。
- **Buggy Rate**：非法尝试（语法错误、约束违反）占比。论文特别指出其**随迭代下降**才有意义——表示智能体不仅在优化指标，也在逐步学会满足环境的结构约束（NP 域尤其关键）。

上下界协议：下界 Random Rollout（盲试），上界人类专家（ML 金牌 / NP 启发式）。所有"自优化能力"的判定都被夹在这两个锚点之间，避免了绝对分数的误导。

**NP 侧的硬约束环境**值得注意：validation.py 同时承担合法性裁判与错误消息生成器（"Not a cycle" / "Node visited twice" / "No edges between…"），错误信息是有语义的，但不含方向梯度。这构成与 ML 侧标量反馈的本质对照——论文后文的“反馈效率悖论”正源于此。工程上这等价于一个“编译器型”反馈源：信息有但稀疏、离散、不可微。

**NP 任务的直接构造约束**（不允许写程序求解）是一个有争议但自洽的设计：它牺牲了“程序化搜索”这条显然更强的路径（写个模拟退火脚本），换取对模型内部规划能力的纯净测量。这也解释了为何 NP 侧的人类基线刻意选启发式而非精确求解器——两边都被限制在“直接推理”的赛道上。

**Draft vs Refine 双设定**：主实验用 Refine（给初始解做精炼），附录 A.3 补充 Draft（从零生成）设定，用以分离“改进能力”与“从零构造能力”。

## 4. 实验结果

19 个模型、7 个家族（3B–235B，含通用、推理、开源三类）。核心结论分两个域。

**ML 域（Table 1，20 任务）**：强模型确实表现为归纳优化器。gpt-4o 在 20 步取得 18/2 Win Count、IR 1.89、EG 0.61 的支配性结果；gpt-4.1 在 20 步 IR 达 2.15（全场最高）。关键行摘录：

|---|---|---|---|
| gpt-4o-2024-08-06 | 18/2 | 1.89 | 0.61 |
| gpt-4.1-2025-04-14 | 14/6 | 2.15 | 0.58 |
| gpt-o3-mini | 13/7 | 1.35 | 0.65 |
| gemini-2.0-flash | 14/6 | 1.95 | 0.53 |
| Deepseek-V3.1-Thinking | 11/9 | 1.03 | 0.60 |
| Qwen3-235B-Thinking | 14/6 | 1.13 | 0.62 |

三个结构性发现：
- **模型规模的 Scaling Law**：Qwen2.5-72B EG 0.45 vs 7B 的 0.20。作者解释为认知阈值——小模型把复杂错误轨迹当噪声（语义工作记忆不足），大模型涌现多步归纳推理能力。
- **推理模型 vs 通用模型**：gpt-o3-mini 拿到最高 EG（0.65），CoT 范式使模型能推演失败因果机制而非随机猜参数。
- **优化视界**：20 步对专有模型增益显著（gpt-4.1 IR 2.15），弱模型早期即平台化——长视界自优化依赖强上下文保持，否则退化为近随机探索。值得注意的反例：Deepseek-V3.1-Thinking 从 10 步 12/8 掉到 20 步 11/9（IR 从 1.18 降到 1.03），说明推理模型在 ML 域长视界也可能回退。

**NP 域（Table 2，10 任务，注意论文 Table 2 标题误写为 OPT-BENCH-ML，实为 NP 结果）**：反馈收益锐减，与 ML 域形成鲜明反差：

- **反馈效率悖论**：gpt-4o 在 NP 侧 Win Count 仅 4/6，且**带历史（w）的 EG 0.47 反而低于无历史（w.o）的 0.54**——离散错误信号（"Invalid Cycle"）缺乏方向梯度，标准模型难以翻译为结构修复，自优化退化为“带记忆的随机搜索”。
- **推理模型守住有效性**：Deepseek-V3.1-Thinking buggy rate 0.00、最高 EG ≈0.79；gpt-o3-mini 与 Qwen3-235B-Thinking 同为 0.00 buggy rate。CoT 对维持全局拓扑一致性至关重要。但推理模型在 NP 侧同样“起步强、后劲弱”——作者推测 RL 对齐约束抑制了长视界探索。
- **有效性瓶颈**：小开源模型 buggy rate 约 0.80（起步阶段），NP 的硬 valid/invalid 约束意味着跨不过可行性阈值则历史反馈完全失效——从未建立合法基线，无优化可言。
- 例外信号：Qwen2.5-3B 在 NP 侧 Win Count 8/2 且带历史 buggy rate 低于无历史（0.38 vs 0.58），说明极小模型在离散域的历史信息对**降低非法率**仍有用，但对提升解质量（EG 0.21）几乎无效。

## 5. 消融要点

**温度消融**（Tables 3/4，gpt-4o / grok-3 / Qwen2.5-72B 三模型）揭示两域的最优探索—利用平衡点相反：

- **ML 域**：gpt-4o 在 T=0 达峰值（13/7 Win Count、IR 1.58、EG 0.58），T=0.8 显著退化（10/10、1.10、0.40）。机理：连续空间中环境反馈是有方向的梯度（“降低学习率”这类具体指令），T=0 保证严格遵循信号、最大化利用；高温引入“对抗噪声”，破坏数值精调所需的收敛，稀释历史上下文价值。grok-3 则在 T=0.2 略优（11/9），说明峰值温度点随模型而异，但高 T 一致有害。
- **NP 域**：T=0.2 的适度随机性反而降低 buggy rate——gpt-4o 在 T=0.2 时 buggy rate 0.18 vs T=0 的 0.28。机理：NP 地形“崎岖”，确定性解码会让模型固着于某个特定非法结构模式；轻微随机性提供逃离局部陷阱的必要探索。但 T=0.8 过量随机破坏约束保持所需的逻辑一致性，Win Count 掉到 4/6。grok-3 在 NP 侧 T=0.8 的 EG 反而最高（0.60），呈现非单调性——该消融样本量小（10 任务），个别翻转需谨慎解读。

工程含义：为 LLM 智能体设定自改进环路时，**解码温度应按反馈信号形态分域配置**——连续指标反馈域用低温（甚至 0），离散约束反馈域用轻度随机（~0.2）。这是一个可直接落地的调参结论。

**Draft 设定消融**（Table 5，附录）：三个强模型从零生成时，除 grok-3 在 5 步外，IR(d,r) 均 > 1——即 Draft 优化在能产出合法解时反而优于 Refine 精炼（gpt-4o 20 步 IR(d,r) 1.41；Qwen2.5-72B 10 步达 1.94），且所有步数下带历史的 Win Count 均为正收益。但 Qwen2.5-72B 的 buggy rate 持续高于专有模型（5 步时 0.40 vs gpt-4o 的 0.20），开源模型在 Draft 设定下的合法性生产是短板。结论指向：降低 buggy rate 是两类模型在 Draft 设定下共同的关键路径。

## 6. 贡献与启示

**贡献**：(1) 首个将连续（ML）与离散（NP）优化并置、严格评测“内在自优化”的基准，评测焦点从“能否跑通代码”转向“能否演化解”；(2) OPT-Agent 提供了去工程化的感知—记忆—推理循环评测框架；(3) 19 模型 × 7 家族 × 3 步数的系统分析，得出“强模型在连续域是有效归纳优化器、在离散域遭遇结构性推理屏障”的核心分歧。

**方法学启示（对自改进智能体设计者）**：
- 反馈信号的语义结构决定自改进上限。标量单调反馈（ML）天然可被模型当作“梯度”消费；离散错误反馈需要模型自带“错误→结构修复”的映射算子，当前模型普遍缺失——表现为丢弃整个解历史重新生成，而非局部修复（Hamiltonian cycle 中人类会补一条断边，模型倾向于整条路径推翻重来）。
- 可行性阈值是先决条件：跨不过合法线，一切历史反馈无效。这提示自改进系统应优先保障约束满足（如外挂验证器前置、结构化输出），再谈质量优化。
- 温度应按域分治（见消融节）。

**局限（论文自述）**：资源所限未纳入 Gemini 3 系列、GPT-5.2、Claude 4.5；基准仅 30 个环境，规模化留待未来。

**与音视频技术的上下游关联**：本文虽属 LLM 评测大类，但其“连续/离散双域反馈”框架可直接映射到音视频工程中的两类 LLM 智能体任务——(a) 连续域类似编码参数迭代调优（QP/码率/拉格朗日乘子随 VMAF/PSNR 反馈搜索，指标有方向性），论文结果表明强模型在这类环路上是可靠的，ML 域 18/2 的 Win Count 支持把 LLM 挂在率失真参数搜索外环；(b) 离散域类似转码流水线方案选型、GOP 结构/参考帧配置等组合决策，论文结果警示：当前 LLM 在硬约束离散域的“丢弃式重生成”倾向意味着直接挂载会退化为带记忆的随机搜索，需要显式的结构修复算子（如局部编辑 API）辅助。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326｜When Should Agents Remember? Falsification-Gated Self-Evolution**：本文 Discussion 指出 LLM 在 NP 域常把无效反馈直接写入历史并触发整体重生成，历史记忆反而降低 EG（gpt-4o 0.47 vs 无历史 0.54）；FGSE 的“经验教训作为可证伪假设、经探针验证后再写入记忆”恰好针对这一问题提供机制化解法——哪些反馈值得沉淀应由验证门控决定，而非全量入栈。二者构成“问题诊断—机制修复”的直接呼应。
- **paper:arxiv:2611.10787｜Trustworthy Recursive Self-Improvement with Statistical Guarantees**：本文发现弱模型把错误轨迹当噪声、强模型才可有效利用（72B EG 0.45 vs 7B 0.20），且随机波动与真实改进难以区分（故需 Random Rollout 下界）；TRUST 用在线多重假设检验区分真改进与噪声、控制错误进化率，为 OPT-BENCH 依赖的 Win Count/IR 判别提供了统计显著性层面的保障方法。
- **paper:arxiv:2611.12109｜SkillDuet**：OPT-BENCH 的 Improving 动作依赖模型在上下文中维护调参/修复经验且上限受基座能力约束（“上界适应性受基础能力根本限制”）；SkillDuet 将此类经验外化为可演化的技能库并与参数更新协同，恰是对“上下文内记忆天花板”的外部化突破路径。
- **paper:arxiv:2611.20430｜TrainExplorer**：OPT-BENCH 的 ML 子集（Kaggle 连续优化）与 TrainExplorer 的自主后训练同属“以标量指标为反馈的持续优化”形态；OPT-BENCH 证明强模型在此类反馈下可靠（18/2 Win Count），为 TrainExplorer 类长视界自主训练智能体的可行性提供了反馈可利用性侧的实证支撑。
