## 1. 背景与动机

LLM agent 的长期记忆已经从单一检索库演化为多模块子系统：编码什么（tip/insight/轨迹/工作流/技能宏）、以何种载体存储（向量/键值/图/混合）、推理时如何取回（语义/混合/对比/图遍历）、以及全生命周期如何维护（遗忘/去重/冲突消解/固化）。现有系统（Mem0、MemoryBank、A-MEM、Zep、Voyager、AWM、Agent-KB 等）基本是人工设计、部署后固定的。论文的核心动机是一个耦合性论断：**记忆失效有四个异质来源（漏编码、表示不可检索、检索选错、池内陈旧/冗余/冲突），单点优化任一模块（尤其是被过度关注的检索器）无法覆盖全部失效面**；因此记忆设计应被形式化为对完整架构的搜索问题，而非对单一组件的调参。

作者将记忆因式分解为 Encode / Store / Retrieve / Manage 四模块，依据既往系统构造离散菜单：5 种编码器、5 种存储、6 种检索器、4 种管理者，并剔除不兼容组合（如图检索必须配图族存储），得到合法空间 A = {(e,s,r,m) | Valid(e,s,r,m)=1}，所有候选合法解构造（valid-by-construction）。

预实验（随机均匀采样合法架构、骨干 Qwen3.5-122B-A10B）给出三条关键发现：

1. **强架构存在但任务特异**：GAIA 上最佳采样架构达 69.7%，超过同骨干最强固定基线 MemoryBank 的 67.8%；xBench-DeepSearch 上最佳采样 46.0% 超过已公布 SOTA 参考 45.0%。但三个基准上的最优配置在全部四个模块上都不同，且在某一基准上表现强的系统可能在另一基准上低于无记忆基线（GAIA No-Memory 为 65.0）。
2. **模块效应耦合而非可加**：强检索器救不了低质量编码；图存储没有配套检索策略则失效；池稀疏时激进管理会删掉有用信息。架构质量由跨模块兼容性决定，不能按单模块质量独立评估。
3. **随机搜索浪费评估预算**：每个候选需要完整 agent rollout，而盲采样不把失败转化为可复用信号；强架构呈孤立峰分布，加大预算只提高“撞中”概率，不使搜索更聪明。

由此给出任务定义：在评估预算 T（评测候选数 N_eval ≤ T）内求 a* = argmax E[Acc(A_a; B)]，同时要求记忆诱导增益 Δ(a;B) = Acc(A_a;B) − Acc(A_0;B) 为正且稳定，准确率相当时偏好更低 rollout 成本。

## 2. 方法总览

AutoMem 面对的本质困难是：A 离散、模块耦合、只能通过完整 agent rollout 观测，不存在解析梯度。其解法是**把失败轨迹编译为模块级文本梯度，驱动递归自改进搜索**。整体循环（Algorithm 1）：

1. 初始化：评估无记忆基线 A_0 于 Bs∪Bv；初始化经验账本 L、观测图 G、Pareto 前沿 P0=∅、文本反馈 δ1=∅。
2. 每轮 t：EGAS 以 (δt, L, G, Pt−1) 为条件提议 K=3 个合法架构；各候选并行在搜索批 Bs 上 rollout，记录准确率、记忆增益、成本与轨迹；按（准确率，增益，成本）三目标更新 Pareto 前沿；每 τ 轮在验证批 Bv 上复评前沿领导者；FGMD 分析本轮失败轨迹合成 δt+1；用本轮结果与模块级证据更新 L 与 G。
3. 终止后取经 Bv 验证的前沿领导者，在 held-out 测试批 Bt 上报告。

两个关键的实验设计约束值得强调：**三批数据（Bs/Bv/Bt）严格互斥**——预实验已证明在小搜索批上选出的“冠军”会过拟合（随机搜索的批内冠军在全量 GAIA 上跌至 63.0%，低于 No-Memory 65.0%），因此前沿领导者必须经 Bv 确认增益后才被接受，且只有验证过的改进才升格为 L/G 中的可靠经验；**搜索边界明确**——不更新骨干参数、不合成任意记忆实现代码，只在结构化合法空间内做坐标级编辑，这使每个候选可直接执行、可做受控单坐标消融。与最接近的两条自进化路线相比：MemEvolve 对单体记忆实现做元进化，难以做模块级信用分配与受控编辑；Evolvemem 的诊断-回退回路主要适配对话 QA 的检索配置。AutoMem 的差异点正在于对全部四模块做结构化、逐模块可归因的搜索。

## 3. 关键设计

### 3.1 合法性约束的因式空间

组件菜单（附录 Table 5，含血统）：Encode ∈ {tip, insight, trajectory, workflow, shortcut}；Store ∈ {json 键值， vector(FAISS), hybrid(json+vector), graph(NetworkX 实体关系)， llm_graph(LLM 时序 KG)}；Retrieve ∈ {hybrid 词法+语义， contrastive 成败队列对比， cbr_rerank 案例库+重排， graph 多跳遍历， hyde 假设文档嵌入， mmr 多样性重排}；Manage ∈ {lightweight 遗忘， json_full 合并+更新， tool_manager 验证， graph_consolidate 合并+演化}。跨模块约束由确定性 Valid() 检查器执行，非法提案直接拒绝重采样。存储是按单元类型路由的（附录运行时工件中可见 storage_routing 将 tip/trajectory/insight 分别指派到具体 store）。提案是四元组坐标而非重新生成实现——一轮内可执行“单坐标受控编辑”：附录 round-3 实例中两个候选仅在 Retrieve 坐标上分别改为 contrastive 与 cbr_rerank，其余坐标全部继承冠军，从而形成干净的同轮配对比较。

### 3.2 EGAS：经验引导的架构搜索

Propose_θ(δt, Lt, Gt, Pt−1) → K 个合法架构。为避免提议器只看最新反馈而反复探索已失败方向或过拟合近期轨迹，EGAS 条件于三类结构化搜索状态：

- **经验账本 L**：条目 ℓ = (c, u, q, z)——适用条件 c、推荐/劝阻的编辑 u、支撑证据 q、生命周期状态 z（active / pending / refuted）。active 条目正向偏置提议，refuted 与 dead-end 条目阻断对已证伪方向的重复探索。
- **观测图 G**：节点为任务模式、模块选择与观测结果，边记录经验关联，维护运行统计 μ(c,u)（条件 c 下含选择 u 的已评架构的平均记忆增益），作为软先验注入提议器。这对 Encode 尤其重要——漏编码（记忆缺失）比错检索更难从轨迹归因，属于“欠观测”失效，需要统计先验补偿。
- **Pareto 接受**：支配定义为 Acc_i ≥ Acc_j 且 Δ_i ≥ Δ_j 且 Cost_i ≤ Cost_j（至少一严格），前沿由非支配候选构成；前沿领导者周期性在 Bv 复评以防搜索批过拟合。

### 3.3 FGMD：失败引导的模块诊断

FGMD 回答三个问题：失败是否记忆可归因、哪个模块负责、下一步改什么。流水线四段：

1. **Scope gate（规则式）**：剔除工具错误、超时、网页不可用、评测歧义、与记忆无关的推理错误。只有轨迹中存在“记忆本可改变结局”的证据（缺失可复用信息、检索到无关记忆、陈旧记忆、冲突条目）才判入 scope。这一步是硬性降噪门：附录 dead-end 案例中一个高 hit-rate（0.929）架构 91% 的失败是 reasoning_error，scope gate 防止搜索在纯噪声上继续改检索。
2. **规则归因**：分类器从记忆轨迹信号（池中是否存在相关单元、是否被检索、一致性 judge 保留与否、保留单元是否陈旧）输出失败模式 f ∈ F = {extraction_gap, extraction_low_quality, retrieval_miss_topk, judge_rejected_all, retrieval_noise, memory_stale, domain_knowledge_gap}，固定表映射到 E/S/R/M：漏抽取/压成不可用形式→Encode；已编码但表示阻碍索引与跨记忆关联→Store；相关记忆存在却未被取出或排序靠后→Retrieve；池内陈旧/重复/矛盾干扰决策→Manage。规则无法归因的（检索与 judge 均通过但仍答错）交给诊断 LLM 抽查（超出固定条数则采样），把数值/格式/时间窗错误重标为 out-of-scope，锐化直方图。
3. **聚合与裁决**：单轨迹诊断噪声大，先聚合为模块失败直方图 H_t(q)；LLM 诊断器结合代表性失败轨迹裁决主瓶颈 q*_t，与直方图分歧时采纳诊断器结论并记录分歧。
4. **文本梯度合成**：δt+1 = (q*_t, E_t, ρ_t, R_t)——主瓶颈模块、接地证据（代表性失败任务 id）、三档置信度、受限编辑建议（如 Retrieve 瓶颈→从纯语义切 hybrid 或加多样性重排；Manage 瓶颈→去重/冲突消解/更保守遗忘）。合成对象携带 out-of-scope 标志与“规则-LLM 一致性”字段。

### 3.4 差分验证与原则生命周期

为避免持续跟随无效诊断方向，FGMD 逐轮对比：若上轮针对模块 q 的编辑未提升准确率/增益/验证表现，账本中降级该建议；若推进了前沿或验证领导者，则升格为 active 原则。附录给出完整生命周期实例：原则 P004（confidence 0.86，跨多轮累积约 20 条证据）编码了一条测量学洞见——**检索 hit-rate 高不等于准确率高**（某对比中 hit-rate 高 0.149 但准确率 −0.04）；原则 P010 在 round 6 的配对实验中获支持（+0.08），round 7 同一配对比较被反证（−0.10）后整体降级为 refuted（confidence 0.25），提议器随即停止跟随该编辑。这本质上给搜索启发式装上了证伪机制。

### 3.5 运行时闭环样例（xBench-DS，round 2→3，小批中间统计）

Round 2：30 任务 13 成功 17 失败；失败分解 retrieval_noise 9、budget_capped 6（被 scope gate 剔除、不驱动编辑）、extraction_gap 2；梯度判定主瓶颈 Retrieve（批准确率 0.40→0.433），建议 hybrid→contrastive。Round 3：候选 1 执行建议编辑（0.433→0.467），候选 2 同坐标探另一选项 cbr_rerank（0.433→0.500）成为新前沿领导者；账本沉淀原则 P003（confidence 0.4）与待验问题 Q006（在固定其余坐标下做 cbr_rerank vs hybrid 的受控比较）。这条链路完整展示了“归因→单坐标受控编辑→配对评估→差分验证→经验沉淀”的闭环机理。

### 3.6 记忆单元形态

五类编码单元中 tip/insight 为声明式（insight 从失败任务提取根因与纠正策略），trajectory/workflow/shortcut 为抽象度递增的过程式：接地动作-观测轨迹、带 ⟨PLACEHOLDER⟩ 的泛化模板、带 input_schema 的可执行宏；所有单元携带 use_when/avoid_when 注入守卫，在注入时检查。这一设计使 Encode 候选可自由组合且行为可控。

两组件呈现清晰的互补失效模式：**去掉 FGMD**（保留经验提议器，但反馈退化为“有些任务失败了”）后搜索失去方向，漂向昂贵但无效的架构——token 从 128.4k 翻到 226.7k，增益转负（64.2 低于 No-Memory）。**去掉 EGAS**（提议器只能看到当前架构与最新诊断，无账本/观测图/历史）破坏更严重：批内最优分从 0.70 逐轮衰减至 0.68/0.66/0.66，后期反复重提近似配置，有害设计被反复探索；round-1 冠军过拟合 50 任务搜索批、全量上低于 No-Memory；成本 297.3k 为全变体最高。论文的表述很准确：FGMD 提供梯度信号，EGAS 提供更新所需的记忆状态——缺前者无方向，缺后者无积累与信任。两者皆去即退化为随机搜索（63.0 / −2.0）。

另一个值得单列的测量学结论是 **hit-rate 与准确率的解耦**：w/o EGAS 的 hit-rate 81.7 与全量 81.2 几乎持平，准确率却差 13.6 点；与账本 P004（hit 高 0.149 而 acc −0.04）和 dead-end 条目（hit 0.929 / acc 0.36 / 91% 失败为 reasoning_error）互相印证——检索命中率不是可靠的代理指标，必须靠 scope gate 拦截非记忆失败、靠差分验证判定编辑是否真实有效。

## 6. 贡献与启示

**贡献**：（1）把异构记忆体系统一到 E/S/R/M 共享架构空间的坐标上（论文 Table 1 将 13 个代表性系统分解到四个模块列），并揭示既往系统各自专精一两个模块、其余落在通用默认值——这是“任务敏感性”的结构性根源：失败一旦发生在非专精模块即无解。（2）AutoMem 框架本身：诊断不止于定位（区别于既有多智能体失败归因工作），而是闭环到受约束架构编辑与差分验证；valid-by-construction 的结构化搜索相对 MemEvolve 的单体实现元进化，解决了候选可执行性、模块信用分配与受控消融三个工程难题。（3）经验账本+观测图构成“搜索过程的元记忆”：原则的 active/refuted 生命周期是对搜索启发式的选择性保留与证伪，附录中 P010 的支持-反证-降级轨迹是这一机制最透明的展示。

**工程启示**：一半的搜索 token 预算找到更强架构（0.47–0.55×），且推理期在部分基准上同时降低 token/延迟/步数——记忆增强不必以推理成本为代价，前提是架构与任务分布匹配。局限（论文自述）：搜索在任务/benchmark 级，单样本仍可能需要不同粒度/深度的记忆路由；空间限于已知组件的重组，不发明全新模块、接口或跨模块交互模式。

**与音视频技术的上下游关联（方法层迁移推断；论文实验全部为文本 web 任务，未涉及音视频模态）**：长视频理解、流式多模态 agent 与自动剪辑管线面临的正是同构的四模块耦合问题——Encode 对应“从已看片段沉淀什么”（片段轨迹、事件工作流、可执行 shortcut 宏，后者天然对应参数化滤镜链/剪辑配方模板）；Store 对应 clip 向量索引 vs 人物-事件关系图 vs 时间戳键值的选择；Retrieve 对应文本-视觉混合检索、hyde 式假设片段嵌入、mmr 多样性重排、已解场景的案例重排（xBench 上收敛出的 Tip+Insight+Trajectory/JSON/cbr_rerank/Lightweight 路由对“复用已解剪辑案例”类任务是直接可借鉴的选型）；Manage 对应重复镜头去重、陈旧帧遗忘、跨镜头冲突消解。AutoMem 的三目标 Pareto（准确率/增益/成本）与交互式音视频的延迟预算对齐——WebWalkerQA 上 182s/6.4 步表明记忆子系统可以不破坏交互延迟。文本梯度模块诊断范式也可平移到多模态检索管线的失效定位：ASR/OCR 抽取错误→Encode、索引形态不适配→Store、跨模态排序失准→Retrieve、时序整合与去重失当→Manage。对下游音视频生产 agent（自动剪辑、导览生成、直播摘要），AutoMem 提供了把“工具调用轨迹 + 可复用工作流”沉淀为记忆、并按任务分布自动选型整套 E/S/R/M 路由的完整参考实现与预算控制方法。

## 7. 与其他论文的联系

- **TGR-EvoDAG（arxiv:2610.32326）**：同属 text-gradient 递归/演化式自动设计家族。TGR-EvoDAG 以 DAG 多智能体代码演化生成式推荐完整管线（腾讯在线 CTR 相对 +0.40%），AutoMem 以同类“提议-评估-文本反馈”循环在四模块记忆空间做坐标级搜索；二者一个演化代码实现、一个演化结构化架构元组，AutoMem 的 valid-by-construction 约束正是对代码级演化信用分配难题的回应。另外 AutoMem 运行时本身构建在 DAG 并行 web-agent 框架之上，与 DAG 执行层形成互补层位。
- **TRUST（arxiv:2611.10787）**：对 AutoMem 元经验层最直接的补强方向。AutoMem 账本的原则升降级靠启发式差分验证、无错误率控制——附录 P010 展示同一配对比较一轮支持、一轮反证后被迫整体证伪，暴露噪声驱动翻转风险；TRUST 的在线多重假设检验可为这类原则库的错误进化率提供统计保证。
- **SkillDuet（arxiv:2611.12109）**：技能库内容演化 vs 记忆架构搜索，二者正交可组合。AutoMem 的 Encode 菜单本身就包含 Voyager/SkillWeaver 血统的 workflow/shortcut 单元，SkillDuet 式响应反馈驱动的内容演化可以嵌在被搜出的架构内部运行（架构层选型 + 内容层演化两层叠加）。
- **LongCapHarness（arxiv:2611.10463）**：同为免数据合成、免后训练、在冻结骨干之上优化单一子系统（长上下文推理能力 vs 记忆架构）的自改进路线，且同样以成本受限评估为核心卖点（LongCapHarness 成本低于基线 50%；AutoMem 搜索预算为随机搜索的 0.47–0.55×），共同构成“不动权重、动外围子系统”的自改进谱系。
- **RSI-PDEbench（arxiv:2611.14949）与 InfraRSI（arxiv:2611.11558）**：递归自改进范式在不同领域的实例化（PDE 求解、分布式训练基础设施）。AutoMem 相对这族的增量在于把 RSI 的作用对象限定为离散、逐模块可归因的记忆架构，并配三段式数据隔离与周期性验证门——与 InfraRSI 的五阶段验证工作流在“改前先验”的结构上同构。
- **WeightLoop（arxiv:2611.07319）**：反馈驱动的有界编辑作用于权重空间，AutoMem 则明确排除权重更新、只动架构坐标——同一“实验反馈编译为编辑信号”优化栈上的不同杠杆，逻辑上可串联（先搜记忆架构，再在选定架构上做权重微调）。
