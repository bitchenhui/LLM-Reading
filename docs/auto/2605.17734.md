## 1. 背景与动机

论文要解决的核心问题：LLM 智能体在多步任务中的失败呈可复现的模式（提前终止、中间结论脆弱、重复无效动作），学界通行做法是把历史经验抽象为“技能”复用，但这些技能几乎都以**自然语言文本**形式存在——注入 prompt、作为建议检索、或间接塑造成 RL 奖励。文本技能的根本缺陷是“劝告性”：它无法精确指定**何时**在策略循环内触发、**如何**修改下一个决策，且实际运行中常被模型忽略。论文将其概括为“语言化经验”与“可可靠控制智能体行为的经验”之间的鸿沟。

动机的技术内核是把技能从数据对象升级为**控制流对象**：技能应当是带显式激活谓词与干预算子的可执行函数，能在失败易发的运行时状态上确定性地触发，直接改写动作或注入修正上下文。这一设计同时打通三条使用路径：推理时直接干预智能体循环（免训练）、后训练时提供结构化中间步监督（而非仅有最终答案反馈）、以及自我改进式的技能库演化。作者明确将 HASP 定位为包裹基础策略的“外部 harness（控制层）”，而非替代策略本身——这与该领域“免训练记忆/技能演化”和“RL 策略优化”两条路线的张力直接相关：HASP 想证明的是，可执行技能 + 结构化监督可以在不做全量 RL 的情况下逼近甚至超过 RL 基线。

工程语境上，该工作面向的是可审计、可干预的智能体运行时：每次 PF 触发都留下 原动作→修复动作→执行效果 的记录，天然形成中间决策级监督信号与审计轨迹。这是对“只用最终答案 EM 做奖励”的训练范式的针对性反动。

## 2. 方法总览

HASP 的形式化设定：智能体策略 π_θ 在输入 x 上产生轨迹 τ = (s₀, a₀, o₁, …, s_T, a_T)，配备外部工具集 K。HASP 在每个决策点 t 插入一个控制层：

1. 基础策略提议动作 a_t^orig ~ π_θ(·|s_t)；
2. harness 从技能库 M 检索候选 PF 子集 R(s_t)；
3. 评估各 PF 的 `should_activate` 谓词；
4. 对激活的 PF 执行干预算子 Intervene，产出三元组 (ã_t, c_t, κ_t)：修订后动作、可选注入上下文、触发记录。无 PF 激活则 ã_t = a_t^orig。

**PF 接口**：每个 PF 是带类型的 Python 对象，暴露两个方法——`should_activate(step_context, action_type, arg) → bool` 与 `intervene(step_context, action_type, arg, teacher=None) → Intervention`。Intervention 的类型字段为 MODIFY_ACTION（改写动作类型/参数）、INJECT_CONTEXT（向下一观测追加文本）或 NOOP（弃权但仍发审计记录）。关键设计约束：`should_activate` 内**禁止 LLM 调用**（确定性谓词），保证 mock 执行验证可行；声明 `needs_teacher=True` 的 PF 在 intervene 中可获得教师模型句柄，但必须在 teacher=None 时优雅降级到确定性路径。

**初始化与三模式**：技能库从训练池中的可恢复失败案例归纳初始化，候选 PF 需通过语法、接口、mock 执行验证才入库。同一接口支撑三种范式： 推理时干预（PF-only 或加辅助教师选择 PF）； 后训练内化（SFT / 拒绝采样 RS / 在策略蒸馏 OPD，均以 PF 校正轨迹为监督源）； 自我改进演化（周期性重访当前 checkpoint 下的残余失败，经双层过滤后更新外部技能库 M_r → M_{r+1}，同时 π_θ → π'_θ）。

技能选择本身也是多层过滤系统：总开关（含按 1–5 难度分动态旁路的 difficulty gate）→ 四级选择器（SkillSelector 按 mode_match·0.5 + trigger_keyword_match·0.5 排序；PFSelector 每题一次，委托教师做 top-K 或用启发式分支规则）→ 运行时触发控制（谓词 + JSON 条件评估 + 每 PF 速率限制 + 投票聚合器，FINAL 被改写回 SEARCH 需超过 handler_vote_threshold，web 为 4、math 为 3）→ 三级预算（episode 级 max_steps/search/read、prompt 级技能数上限、执行级 pf_top_k 与每 PF 限次）。运行时还强制每 PF 速率上限（如 MODIFY_ACTION 类 _MAX_MODIFY_FIRES = 2，RetrievalFailurePF 每回合最多 3 次）以防止振荡。

## 3. 关键设计

**（a）干预模式与监督语义的解耦。** MODIFY_ACTION 直接产出可执行的修复动作（如改写过约束的搜索查询、把 FINAL 改回 READ），INJECT_CONTEXT 只向后续推理注入警示文本。设计上把“选择下一个动作”与“校正它”分离：(a_t^orig, ã_t) 对同时记录策略本来会做什么与 harness 如何修复，使技能使用成为**中间决策级监督**而非仅最终答案反馈。机制分析显示（web-search 全部触发事件统计）65.1% 为动作级干预、34.9% 为上下文级，说明 HASP 频繁直接改写可执行决策本身。

**（b）四信号干预质量打分（核心创新之一）。** 每次 PF 激活产生事件 e_t = (s_t, a_t^orig, ã_t, c_t, κ_t, Δt)，被分解为四个信号 z_t = (timing, mode, correctness, outcome)，粗粒度权重 (0.15, 0.10, 0.25, 0.50)，聚合为每步符号分 A_t，轨迹级分数 A(τ) = T⁻¹ΣA_t。关键性质是**带符号**：对安全步触发、对危险步漏触发、改写后仍失败等 undesirable 行为取负权——A_t 度量干预质量而非“干预本身”。细粒度分解（Appendix D）中，outcome 家族权重最重，因为它锚定到 ground-truth EM（s4.downstream +0.40、s4.local 按转移打分 0.8/0.7/0.5/0.3、s4.cost −0.10、s4.side_effect −0.10）；timing 家族中 s1.fp 与 s1.fn 均为 −0.10，显式惩罚误触发与漏触发。episode 级奖励是逐步均分与终端 EM 的 50/50 混合，避免“EM 完美但 PF 行为差”拿到满分。

**（c）三种内化配方。** RS（主配方）：Score(τ) = β₁·TaskSuccess + β₂·A(τ)，只保留 top 轨迹训练——相比仅按最终正确性过滤的标准 RS，额外偏好中间决策与 PF 校正对齐的轨迹。SFT 变体：L = −Σ w_t·log π_θ(ã_t|s_t)，w_t = A_t，阈值 τ=0.3 截断——因 A_t 带符号，阈值化直接剔除在安全态触发或修复失败的干预而非用小正权训练它们。OPD 变体：在学生自身状态上滚动，PF 保持激活，权重 ŵ_t 不依赖四信号而强调与参考轨迹发散的状态；论文明确指出 OPD 与技能库同时演化时不够稳定。

**（d）双层准入过滤的技能库演化。** 候选 PF 须过两道门：第一道是可执行二值门（ast.parse 语法 → 接口签名 → 3 个 mock 上下文 × {SEARCH, READ, FINAL} 共 9 次调用 mock 执行 → 返回类型构造 Intervention）；第二道是教师五维评审（concept/trigger/intervention/executability/validation，权重 0.25/0.20/0.20/0.20/0.15），多档阈值：Q_exec < 0.30 无条件硬拒（不可运行的技能无法靠更好触发器补救）、新类别门槛 η=0.75、同族精化门槛 0.60、[0.42, 0.60) 返回修改而非丢弃。库增长受速率限制（每 epoch 至多 5 个候选）、版本化（__v{N} 后缀，运行时只加载每个 base id 的最新版）且硬上限 50 个活跃技能。失败检测端采用 12 条手工启发式规则 + LLM 抽象双通道，token-Jaccard ≥ 0.5 去重、簇大小 <3 丢弃、novelty ≥ 0.3 标记新类别优先提案。

**（e）闭环的两种演化模式。** Full 模式跑完整 Phase A–H（一个演化周期约 1 小时，仅 E4 使用）；Lite 模式采样 20 条失败轨迹、由当前学生 vLLM checkpoint 提至多 3 个技能提案、只做 ast.parse 与去重，无教师 API 调用——约 5% 的 wall-clock 成本拿到大部分库增长收益，E5/E6 采用。

**领域适配的诚实呈现**：三域共享同一 loader/registry/dispatcher，仅 markdown 内容与谓词不同。但 coding 域动作空间坍缩为单次 FINAL，PF 只能做正则静态分析返回 INJECT_CONTEXT 或审计 NOOP（自动补丁学生代码被判定过于危险）——作者承认该域“PF 代码本身是审计而非改写”，行为引导主要靠 system prompt 注入。这个降级设定是评估其跨域泛化结论时必须记住的口径。

## 4. 实验结果

## 5. 消融要点

消融均在 web-search（HotpotQA/2Wiki/MuSiQue 平均）上进行，分三块（表 3）：

**推理时组件**：Full 56.2；PF-only 51.0（教师依赖的 PF 回退到确定性代码路径，如正则截短查询）；Teacher-only 50.7（无任何状态到干预对象拦截决策点，只剩外层格式后处理与多轮重试）。PF 基底单独已超过教师单独，二者叠加有 +5.2/+5.5 的互补。

**信号消融（在 E5 闭环 RS 上）**：全信号 60.3；去 Timing −7.8、去 Mode −15.5、去 Correctness −12.1、去 Outcome −12.8。Mode 掉得最狠，作者解读为“怎么干预与何时干预同等重要”——改写 SEARCH 查询与注入阅读提醒不可互换，缺模态信用的模型会混同二者。四个信号各自贡献 7–15 点，支持“PF 派生监督不可约化为单一标量”的核心主张。

**过滤消融（在 E5 上）**：全过滤 60.3 > 无演化 59.3 > exec-only 48.8 > teacher-only 47.2 > 无过滤 36.3。无过滤演化（−24.0）是全文最重的一个消融数字，且是唯一低于 multi-loop 基线区域的设置（36.3 vs 31.2 仅高 5.1，但仍属“主动有害而非仅无用”级别）——未过滤候选包括无法 import、触发过激、与现有 PF 冲突的技能，检索池噪声拖垮下游决策。这组数据是“记忆/技能库污染”假设的直接证据，也是论文把自演化定位为“经验证且限速的过程”而非无约束生成的依据。另一个值得注意的结论：闭环演化的净贡献其实温和（59.3→60.3，+1.0），强固定库才是地基。

**训练配方 × 回路拓扑（表 4，2×3 网格）**：web-search 上固定库 SFT/RS/OPD = 56.8/59.3/62.5（OPD 在固定库下最强，MuSiQue 单项冲到 54.0）；闭环后 SFT/RS/OPD = 58.5/60.3/56.7——Evolve+OPD 反而比固定库 OPD 掉 5.8 点，验证了“模型与技能库同时更新不稳定”的论断；RS 在两种拓扑下都是最稳的选择。训练动力学（Appendix G）与此一致：固定库曲线平滑，闭环在迭代边界处出现明显断点（V2 SFT 在刷新点后斜率变缓，因 post-evolve 目标池更难），梯度范数带（~10⁰–10¹）无迭代边界尖峰，排除了数值不稳定假象。

**技能内化模式**：行为纠正类 PF（读得不够、查询过长）训练后常“沉默”——multi_hop_reasoning_failure 与 retrieval_failure 在原触发案例上 100% 不再触发；而问题依赖类（decompose_complex_question）很少被内化。但只有 8–38% 的准确率增益可直接归因于“那些 PF 不再需要触发”，更大效应来自更广的行为改变（更多 SEARCH/READ 动作）。

**prompt 等价性检验（A.5）**：定义 A+B 判据（仅 INJECT_CONTEXT 且注入文本为无运行时替换的固定字面量）识别“与 prompt 提醒等价”的 PF：web 26 技能中 10 个、code 12 技能中 2 个满足，math 为 0。把这类技能叠加到 PF 库上的边际效应小且符号混杂（六数据集 ΔMBE：+3.5/−3.5/−1.0/0.0/+2.5/0.0），支撑“增益来自非 A+B 的 PF”的归因。

## 6. 贡献与启示

**方法学贡献**： 把技能形式化为带显式激活谓词与干预算子的可执行状态-动作干预函数，接口极简（两个方法、三种干预类型）但表达能力上严格区分了“何时”与“如何”——这是对 Reflexion/ExpeL 一系“言语化经验”路线的结构性升级。 单一干预记录接口同时服务推理、训练监督与库演化三条路径，且干预记录天然是审计轨迹（可检查的触发器、显式的 before/after 动作对、日志化理由）。 四信号符号化打分把“干预质量”从二值成功/失败细化为可负反馈的多维信用分配，其中 side_effect（改写后回合仍失败记负）与 timing 的 fp/fn 双向惩罚是工程上最值得借鉴的设计。

**对该领域的启示**： 自我改进的瓶颈不在生成而在**准入控制**——无过滤演化 −24 点的消融比任何正向增益都更有信息量，说明技能/记忆库的检索精度是比库规模更脆弱的资源。 库演化贡献温和（+1.0）且与 OPD 不兼容，提示“策略内化 + 外部技能库”存在联合优化的稳定性问题，RS 的鲁棒性来自其对噪声轨迹的过滤能力。 内化是选择性的：行为类技能被吸收进策略、输入条件类技能留在外库，这为“内外分工”（policy 管风格、harness 管内容依赖的检查）提供了实证刻画。 局限同样清晰（作者自陈）：强变体依赖外部教师（引入成本与偏差）；PF 只能吸收既有策略而非发现新策略（AIME24 上被 RL 系方法反超即为证据）；评估限于验证信号清晰的任务，向开放式、弱可验证环境迁移未解决；干预形式仅限动作改写与上下文注入两种。

**对音视频技术上下游的工程含义**（按其自身领域标准评估后的关联视角）：HASP 的 PF 范式本质上是一个**带审计轨迹的运行时策略护栏框架**，其“状态谓词 + 确定性触发 + 限速干预”的机制与音视频系统中流媒体 QoE 管控、编码参数在线决策、多步内容生成管线（如视频智能体的分段-检索-合成循环）中的“在失败易发状态上短路重试/注入校正上下文”需求同构。特别是其多层预算与每 PF 速率限制设计，直接对应实时系统里防止干预振荡（如反复切换码率档位）的工程约束；其“干预记录 → 结构化监督 → 内化”的闭环，则为多步生成任务中把人工运维规则逐步蒸馏进模型提供了可复用的数据构造协议。凡是有可枚举失败模式（丢帧、花屏、实体混淆、引用错位）且存在中间决策点的管线，均可低成本移植该 harness 结构。

## 7. 与其他论文的联系

基于相关论文清单，以下条目与本文存在真实的技术关联：

- **paper:arxiv:2605.17734 ↔ paper:arxiv:2610.24453（Hippo: Training-Free Agent Self-Evolution via Hippocampal Replay）**：同属“免训练/经验复用”路线。HASP 的推理时 PF-only 模式（51.0% vs ReAct 31.2%）与 Hippo 的外部记忆回放都试图不改参数地改进智能体，但机制分野明确——Hippo 选择性编码并回放经验内容，HASP 把经验编译为可执行干预函数。HASP 的无过滤演化消融（60.3→36.3）对 Hippo 类记忆框架同样构成警示：经验写入缺乏准入控制时的库污染问题具有跨框架的一般性。
- **paper:arxiv:2605.17734 ↔ paper:arxiv:2506.06698（Contextual Experience Replay for Self-Improvement）**：CER 将历史经验合成动态记忆缓冲区做推理期自改进，与 HASP 的固定库推理干预直接可比；而 HASP 进一步给出 CER 类工作未覆盖的两个维度——经验的结构化训练信号化（四信号打分供后训练）与库演化的准入门控。二者共同确认“经验复用 > 单次推理”但 HASP 把复用从 prompt 层提到了控制流层。
- **paper:arxiv:2605.17734 ↔ paper:arxiv:2610.07335（Selective Critique for Cost-Aware LLM Agents）**：SAG 的免训练门控按需调用批评，与 HASP 的 should_activate 谓词 + 速率限制在“选择性触发外部分析以控成本”上直接对应。HASP 的效率数据（教师调用 1.1 次/查询 vs Teacher-only 3.2 次，成本 $0.0495→$0.0418）与 SAG 的 token 效率目标同源；差异在 SAG 的门控作用于“是否请批评”，HASP 的谓词作用于“是否改写动作”。
- **paper:arxiv:2605.17734 ↔ paper:arxiv:2611.14326（Falsification-Gated Self-Evolution）**：关联最紧密的一篇。FGSE 将经验教训作为**可证伪假设**经探针验证后写入记忆，与 HASP 的双层准入门（可执行二值验证 + 教师评审多档阈值）解决的是同一个问题——自演化系统的更新安全性。HASP 的 exec-gate（Q_exec < 0.30 硬拒）与 FGSE 的探针验证在功能上等价：先保证“能运行/能成立”，再谈质量。HASP 的 exec-only 过滤消融（48.8%）恰好量化了“仅形式验证不够、还需语义审查”的边界，与 FGSE 强调证伪的思想互补。二者的差异在于 HASP 的验证是接口与执行层面的，FGSE 是假设内容层面的证伪。
- **paper:arxiv:2605.17734 ↔ paper:arxiv:2604.02268 / SkillRL / MemSkill / SAGE 系（论文表 6 中对比的 SKILL0）**：正文表 6 的定性对比显示 HASP 是唯一同时勾选“可执行技能形式 + 运行时控制 + 学习信号 + 策略训练 + 技能演化”五项的方法，SKILL0/SkillRL/SAGE 等至多覆盖四项且技能形式多为部分间接支持——这构成本文在技能演化谱系中的定位坐标。

清单中的 TrainExplorer、CompoundingKernel、RSI-PDEbench、零样本 NER 自改进等条目与本文无直接技术关联（分别属后训练探索、内核搜索、PDE 求解基准、NER 标注），不纳入对比。
