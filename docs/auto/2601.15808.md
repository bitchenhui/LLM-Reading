# Inference-Time Scaling of Verification: Self-Evolving Deep Research Agents via Test-Time Rubric-Guided Verification

## 1. 背景与动机

Deep Research Agent（DRA）指 LLM/VLM 驱动、面向多步信息获取与复杂问题求解的自主系统，任务横跨代码执行、网页导航、文件处理与长程推理。其核心痛点是长视野任务中的静默失败：错误动作、API 失败、幻觉、证据链断裂（论文例子：查找某研究者最早发表时依赖不全的二手来源给出错误结果）。当任务涉及数十页面、上百动作时，在线人工监督不可行，系统可靠性问题成为部署瓶颈。

已有推理时改进工作存在两条清晰缺口：

（1）**生成侧扩展的盲区**。主流 test-time scaling 是并行采样与选择（Best-of-N、多数投票）或跨迭代叙事聚合。论文点出其结构性缺陷：同一组错误在不同 rollout 中高度复现，采样量的增加无法消除系统性错误——错误是策略级的，不是随机级的。

（2）**反馈生成本身是难任务**。Reflexion 类方法用文本反馈自举 agent 响应，但产出高质量反馈需要复杂推理能力；弱反馈非但不能纠错，反而会把重试引向错误方向。

作者据此提出替代范式：不动策略模型权重，而是**自演化验证能力**——在测试时对策略输出做 rubric 引导的迭代验证，产出定向反馈驱动重试。两个理论支柱：一是验证不对称性（引 Wei 2025 "Asymmetry of Verification and Verifier's Law"）：检验正确性通常比生成容易，故复杂验证可分解为简单子任务实现降误差；二是 rubric 化奖励（引 Rubrics as Rewards、RL with Rubric Anchors 两线）：对无 ground-truth 对照的开放域提供结构化、可判别的信号。

相对已有 judge 类工作（Agent-as-a-Judge、AgentRewardBench 等）的差异化定位：此前工作集中于网页导航、通用推理与软件开发任务，无一针对 DRA 响应，更未研究验证自身的 scaling 效应；Zhang et al. (2025a) 系统分析了 DRA 失败模式但未提供自动检测与改进框架。本文的三段式贡献闭环为：自动构建的失败分类学 → 基于验证不对称的自动失败检测框架（DeepVerifier）→ 自演化验证（test-time scaling 闭环 + SFT 数据开源化）。

对音视频方向读者的定位说明：DRA 是典型的多模态长视野系统（GAIA 考多模态输入、网页浏览与工具使用；其验证 agent 具备截图能力），“验证不对称 + rubric 反馈”的推理时自纠错机制与音视频内容生成/理解中“评估比生成便宜”的经验同构，方法论可迁移性较强（第 6 节展开）。

## 2. 方法总览

整个框架分四层：

**第一层：DRA Failure Taxonomy（先验知识）。** 在 WebAggregatorQA 上收集失败轨迹，人工标注出 5 大类、13 子类失败分类学。选 WebAggregatorQA 构建分类学、选 GAIA/BrowseComp/XBench-DeepSearch 做评测，是为了规避数据泄漏并证明泛化。轨迹由 CK-Pro（Cognitive Kernel-Pro，完全开源的多模块 DRA 框架）+ Claude-3.7-Sonnet 生成，语料规模：2,997 个动作步、90 个独立任务、平均 33.3 步（跨度 2–156 步）、平均 8.2M token（GPT-4o 分词器口径，总计 738M），正确/错误比 0.96（近平衡）。两名标注者以人工参考解为 grounding 信号独立标注错误点，一方错误点平均 63.0% 与另一方重合（相对高一致性），合并后得 555 个错误点；以 50 个错误点的子集聚类产生初始标签，再经多轮“合并相似标签—删除不当类别—精化定义”的迭代得到最终分类学。

**第二层：DeepVerifier 三模块验证流水线。** Decomposition agent（轨迹摘要 → 错误定位 → 追问生成）+ Verification agent（CK-Pro 执行外部检索）+ Judge agent（1–4 分 rubric 裁决）。

**第三层：测试时扩展回路。** Judge 改造为纠错反馈生成器，产出不超过 3 条可执行指令回灌 DRA 重试，循环至 verifier 判对或达轮数上限。

**第四层：能力蒸馏。** 验证轨迹过滤平衡后转为 4,646 条 prompt-response 对（DeepVerifier-4K），微调 Qwen3-8B 得 DeepVerifier-8B，把反思能力注入开源基座。

核心设计哲学一句话：**验证不对称性的工程化**——放弃“整体重解式”判定（让 judge 重新解一遍任务，错误率与原 agent 相当），把“这个答案对吗”分解为“来源 X 是否陈述了断言 Y”“最新报告 X 中 Y 的确切数字是多少”这类可独立检索裁决的子问题，且只核验被分类学标记为脆弱的断言。论文明确指出该分解原则可自然延伸到报告生成类任务（引 Fan et al. 2025）。

## 3. 关键设计

### 3.1 失败分类学与 rubric 体系

五大类按频率递减：**Finding Sources**（主导类——咨询错误证据、依赖泛搜索，说明上游信息获取是最大塌陷点）、**Reasoning**（过早结论、误读指令、幻觉/过度自信断言——信息在位但推理跳跃）、**Problem Understanding**、**Action Errors**、**Max Step Reached**（后三者常为早期错误级联成长而无效的轨迹）。附录 C 给出 rubric 化版本，五维命名为 Finding Sources / Reasoning / Problem Understanding and Decomposition / Action Execution / Trajectory Efficiency，每维四档（Excellent / Good / Needs Improvement / Poor），每档有可操作的判据（如 Finding Sources 的 Poor 档定义为“频繁使用模糊、未验证或不当来源；关键证据缺失或无支撑”）。该分类学以提示词形式注入 decomposition agent 系统提示，实现 taxonomy-guided 的脆弱点定位——这是“从自由judge到结构化验证”的关键跃迁。

### 3.2 Decomposition Agent 三步工作流

- **Trajectory Summarization**：轨迹平均 8.2M token，远超任何 LLM 上下文窗口。生成按步索引的紧凑梗概：每步记录访问的来源与具体获取的信息（事实、数字、引文）。摘要被明确约束为**描述性而非解释性**，使下游核验无需回放全轨迹；论文同时引用先例说明简洁的步骤描述本身可改善 test-time scaling。
- **Potential Error Identification**：对照摘要与系统提示中的分类学扫描可疑行为，输出 ⟨可疑行为⟩⇒⟨潜在错误 + 分类标签⟩ 配对并附简短理由，把“哪里可能错、属于哪类错”结构化定位；无异常时返回固定字符串"No potential errors found"。
- **Follow-Up Question Formulation**：针对标记脆弱点起草“高杠杆”追问，提示词要求提出**最少**的 source-question 对、上限 3 对，且问题设计为基于特定来源的是非题——每题须能被外部证据一锤定音地确认或反驳某个风险断言。这是验证不对称性的落点：已充分落地的结论直接复用，只查可疑或无支撑断言。

### 3.3 Verification Agent 与 Judge

Verification agent 直接复用 CK-Pro（模块化多 agent，具备 web 搜索、截图、代码执行能力），顺序回答追问。Judge agent 综合任务描述、未验证答案、轨迹摘要、潜在错误列表、追问及答案，先给简短解释再打 1–4 分（1=全错，2=大部分错，3=大部分对，4=全对）；输出格式被硬约束为"Explanation + Score"。实验口径：≤2 判错、≥3 判对；**一旦判对立即终止反馈回路**。

### 3.4 纠错反馈回路（Corrective Feedback Prompt）

测试时扩展对 judge 提示词做了三点改造： 给出可执行的重试指令以避免重蹈覆辙； 若已有信息（历史轨迹或追问答案）足以确定正确答案，可直接在指令中给出； 先简短反思再给**不超过 3 条**指令。提示词中还内置隐式自我惩罚约定：“agent 将严格遵循你的指令，若仍不能得到正确答案，说明你的指令无用，你将被惩罚”，并偏好简洁准确的指令（长而复杂的指令会困惑 agent）。这套约束把 verifier 从“打分器”升级为“受控重试控制器”，是 Reflection 范式与工程可执行性之间的折中设计。

### 3.5 DeepVerifier-4K 数据构建

从 WebAggregatorQA 采样 400 个需大量在线探索与信息聚合的任务（覆盖 10+ 领域），用 CK-Pro + Claude-3.7-Sonnet 记录答案与轨迹；再用 DeepVerifier（Claude-3.7-Sonnet 骨干）验证并保存验证轨迹；**只保留 TP（正确拒绝错误答案）与 TN（正确接受正确答案）两类**，平衡后转为 prompt-response 对，共 4,646 条，强调反思与自我批评。DeepVerifier-8B = Qwen3-8B 在 DeepVerifier-4K 与 CK-Pro-8B 训练集（Fang et al. 2025b）混合数据上微调——混入 CK-Pro 数据是为了在注入反思能力的同时保持基础任务能力。

### 3.6 成本结构

论文明确给出三条成本控制：分解模块将验证收窄为 ≤3 个定向追问而非重解全任务；增益在第 3–4 轮见顶，支持实际早停；verifier 接受即停。相对 Best-of-N（完整重执行 N 次）给出有利的精度-成本折中，且全程零额外训练。Limitations 同时承认：迭代验证仍引入额外推理步与工具调用，增加运行时延与 token 开销。

## 4. 实验结果

设置：主骨干 Claude-3.7-Sonnet，泛化测试 GPT-4.1 与 Qwen3-8B（DV-8B）；主评 GAIA-Web（按 He et al. 2024 过滤的需网页浏览子集），扩展到 GAIA 全集（开发集 n=165）、XBench-DeepSearch（中文搜索/工具基准）、BrowseComp（极难纠缠信息检索）。验证指标为“拒绝”的 precision/recall/accuracy/F1，**TP 定义为 verifier 对错误答案给出 reject**。基线：LLM judge（Lù et al. 2025）、CK-Pro agent-as-judge。

**RQ3：反思能力 SFT**。DV-8B 经 10 轮反思后 GAIA 全集 32.2%，较非反思版 +5.5pp；仅用 CK-Pro 训练集的 CK-Pro-8B 增益只有 2.6pp；两者皆无的 Qwen3-8B 几乎无提升。结论：反思/验证能力可经 SFT 注入开源模型，且是该模型上 scaling 增益的必要条件。

## 5. 消融要点

- **去 Verification（分解-only 的 LLM judge）**：精度 100 但召回仅 14.29——只能抓执行失败等显性错误，漏掉二手来源依赖、过度自信断言、支撑错误答案的幻觉事实等隐性错误，大量错误答案被误接受。说明无外部证据核验的纯推理判定召回天花板极低。
- **去 Decomposition（vanilla agent-as-judge，保留外部访问）**：召回 47.62 仍不足。论文的归因值得注意：无定向分解时 judge 倾向于逐步重解整个任务，从而**继承与原 agent 相同的推理错误**——这是验证不对称性的反面教材，证明增益来自“分解为定向子问题”这一结构，而非“多了工具访问”。
- **跨模型消融视角**：GPT-4.1 增益（全集 +2.41~+3.01）远小于 Claude-3.7（+6.71~+12.22），与 Limitations 中“反馈质量依赖基座模型的 rubric 遵循、交叉核验与结构化反馈能力”自洽；而 DV-8B（8B 规模）经 SFT 后增益 +5.48 反超 GPT-4.1，说明 SFT 可部分弥补基座能力差距，验证了 DeepVerifier-4K 的实用价值。
- **训练数据消融（RQ3 三模型对照）**：DeepVerifier-4K 反思数据在 CK-Pro 训练集之上额外贡献约 +2.9pp（5.5−2.6），隔离了反思数据本身的边际贡献。
- **轮数消融**：所有设定峰值均在第 3–4 轮，其后平台或震荡，早停（结合“判对即停”机制）是必要的工程策略而非可选项。

## 6. 贡献与启示

**贡献**：(1) 形式化 DRA 反思管线，并以验证不对称性取得元评估优势（GAIA-Web 上 F1 较 agent-as-judge/LLM judge 高 12–48 个百分点口径）；(2) 首个自动构建的 DRA 失败分类学（5 大类 13 子类，555 错误点、63.0% 标注重合率）及派生 rubric，并将验证从整体重解改造为定向证据核验；(3) 证明“验证的推理时扩展”对闭源 API 与 SFT 开源模型均成立（GAIA/BrowseComp/XBench 三基准一致增益），并开源 DeepVerifier-4K 与代码（DeepVerifier、CognitiveKernel-Pro 两仓库）。

**对智能体方向的方法论启示**：
- 验证 scaling 与采样 scaling 是正交的两条轴：并行采样对付随机错误，验证-反馈对付策略级系统性错误；但 verifier 精度不足时回路自身引入对→错回归（第 1 轮即 12.79%），需要写入侧门控或统计控制（见第 7 节）。
- 反馈生成应被视为**受约束的控制问题**（≤3 条指令、可含直接答案、失败视为指令无效、偏好简洁指令），而非自由文本评价——这是 Reflexion 范式工程化的重要细节。
- 部署次序上应先做元评估（拒绝 P/R/F1）再接入反馈回路，否则闭环是噪声放大器。
- 论文自身展望：分类学与数据集可作为 reflection-enhanced RL 的自验证与奖励信号基础。

**与音视频技术的上下游关联（分析者视角，非论文原文主张）**：
- 上游（基础设施共性）：DRA 是多模态系统——GAIA 含多模态输入，CK-Pro 验证 agent 具截图与代码执行能力；其失败分类学（证据源选择错误 vs 推理错误 vs 动作执行错误 vs 效率类失败）可直接迁移为多模态视频问答/视频检索 agent 的错误分析框架。8.2M token 长轨迹压缩为“按步描述性摘要”的机制，与视频长时序理解中的镜头/关键帧摘要在结构上同构：都是把超长上下文转为可独立核验的稀疏锚点。
- 下游（范式迁移）：rubric 化结果奖励对音视频生成这类不可验证域（文本到视频/音频生成无客观 ground-truth 对照）提供了奖励设计范式——把“整体好不好”分解为可独立核验的是非断言（如“第 t 秒画面是否包含实体 X”），本质是多模态版的追问分解；论文引用的 rubric-reward 两线（Rubrics as Rewards、RL with Rubric Anchors）正是该方向的 RL 化延伸，本文的分类学-追问-裁决三段结构可作为其奖励生成器的蓝图。
- 验证不对称性在 A/V 中的成本同构：感知质量评估/事实一致性校验的计算代价远低于生成，因此“生成-校验-重试 + 早停”闭环在视频生成、自动剪辑、字幕/配音校对等流水线中具有与本文相同的成本结构（校验便宜、生成昂贵、峰值后早停），第 4 轮峰值的过渡率分析方法可直接复用于此类流水线的重试预算设计。

**局限（原文明示）**：依赖基座模型的 rubric 遵循与工具使用能力，弱模型下反馈退化为噪声；迭代验证增加运行时延与 token 开销。

## 7. 与其他论文的联系

- **FGSE（arxiv:2611.14326，When Should Agents Remember? Falsification-Gated Self-Evolution）**：同为自演化安全机制，且关联最为直接。本文 Table 5 直接暴露了对→错回归问题（第 1 轮 12.79%），根源是 verifier 不完美精度下的错误反馈；FGSE 的证伪门控（经验教训先作为可证伪假设经三类探针验证再写入记忆）正是针对此类污染的**写入侧防线**。两者互补：DeepVerifier 提供任务内瞬态反馈回路，FGSE 管跨任务持久记忆；且 DeepVerifier 的 ≤3 个定向追问本身就是“探针”，可为 FGSE 的探针生成提供模板。
- **TRUST（arxiv:2611.10787，Trustworthy Recursive Self-Improvement with Statistical Guarantees）**：本文只对错误率做了经验观察（过渡率表）并依赖早停止损，无任何统计控制；TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证，恰好补上本文“第 4 轮后增益衰减、回归持续存在”问题的理论化控制层。
- **SkillDuet（arxiv:2611.12109，Co-Evolving Models and Skills through Response Feedback）**：都采用“外部反馈 + 参数更新”双通道。DeepVerifier 将两通道解耦——推理时用闭源 API 反馈、离线蒸馏 DeepVerifier-4K 训 8B；SkillDuet 让响应反馈同时驱动权重更新与外部技能库协同演化。DV-8B 的 +5.5pp 增益证明 SFT 注入反思能力有效，间接支持 SkillDuet 类协同演化路线在验证能力上的可行性。
- **InfraRSI（arxiv:2611.11558）**：同属“验证工作流门控自改进产物”模式——InfraRSI 经五阶段验证后才落地基础设施改动，DeepVerifier 验证后才触发重试或接受；差异在域（分布式 LLM 训练优化 vs 开放研究问答）与被门控对象（工程产物 vs 答案文本）。
- **LongCapHarness（arxiv:2611.10463）**：同为免后训练、免数据合成的测试时能力挂接路线（其口径为成本低于基线 50%）。两者对超长输入的处理策略异曲同工：LongCapHarness 以能力引导挂接底层长上下文推理，DeepVerifier 用按步描述性摘要把 8.2M token 轨迹压至可核验梗概，都规避了长上下文硬扛。
- **AutoTavern（Build, Don't Play）**：自主构建外部制品（模拟器 + 游戏 AI）的自我改进研究 agent 系统；DeepVerifier 恰好可充当其缺失的外置验证/奖励模块——论文自身也定位为 reflection-enhanced RL 的奖励基础设施，可为这类构建型 agent 的“构建-评估”闭环提供 rubric 化信号。
- **WeightLoop（arxiv:2610.33845）**：光谱两端的对照——WeightLoop 用实验反馈持续改写已部署权重（持久、参数级自改进），DeepVerifier 完全不动权重（瞬态、推理级）；自然结合路径是 WeightLoop 的有界参数编辑程序经 DeepVerifier 式验证器门控后再应用。

（RSI-PDEbench 与本文仅共享“递归自我改进”大类标签，其 PDE 数值求解域存在客观可验证奖励，与本文针对的不可验证开放域验证问题机理不同，不构成实质技术关联，故不展开。）
