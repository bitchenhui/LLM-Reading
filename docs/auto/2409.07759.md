# SwinGS: Sliding Window Gaussian Splatting for Volumetric Video Streaming with Arbitrary Length

> Bangya Liu, Suman Banerjee. *arXiv:2409.07759v3 (2024-09-12)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

体积视频（自由视点视频，FVV）的表示基元经历了点云、mesh 到神经渲染的迁移。论文在动机部分给出的基元对比判断是：NeRF 质量高但采样式渲染拖慢帧率（<10 FPS），StreamRF、NeRFPlayer 提速的代价是模型尺寸暴涨（StreamRF 每帧 17.7MB）；mesh 紧凑且渲染友好但依赖大量人工；点云帧率好、易从稠密重建获取，但质量与点数强耦合、有补洞问题。3DGS 以“可微的体积点云”定位在质量/速度/存储上取得平衡（>100 FPS 光栅化渲染），且已有工业侧落地信号（Varjo Teleport、Pico 4 Ultra、Vision Pro 的 MetalSplatter）。

动态 3DGS 研究虽有两条成熟路线——deformation field 类（Deformable 3DGS 的 MLP 形变场、Hexplane 前置增强、SC-GS/HiFi4G/Superpoint Gaussian 的层级骨架绑定、SpacetimeGS 的多项式形变+MLP 外观）与 4D primitive 类（4DGS、4D-Rotor GS，将时间维作为第四维、渲染前投影/切片回 3D 再走 alpha blending）——但论文指出它们与“可流式传输的 3DGS 体积视频”之间有三个结构性缺口：

1. **模型过大**：逐帧独立静态 3DGS 的朴素做法流量不可接受；3DGStream 用逐帧 Neural Transformation Cache（NTC）做形变，仍约 7.8MB/帧，30fps 视频最低需 200MB/s 带宽；形变网络类方法整个模型数百 MB 且必须一次性传输，任何丢包都会阻塞整条渲染管线——这与流式系统的基本要求（分段、增量、可丢包恢复）直接冲突。
2. **时长受限**：形变类方法用随机采样 dataloader 预载全部训练视角，GPU 显存随帧数线性增长；更根本的是单一形变网络容量有限——论文引用 SpacetimeGS 的结果：Flame Salmon 场景片段从 50 帧加长到 300 帧，PSNR 从 29.48 降到 29.17。运动更剧烈、时长更长的场景退化会更严重。
3. **长期内容漂移**：多数方法没有物体进出场景时对应高斯的引入/退役机制。碎片化多个动态高斯模型虽可绕开，但带来片段间视觉不连续、模型传输的突发性，以及多个形变网络的额外存储。

另一个容易被重建侧论文忽略、但系统侧必须正视的约束是**码率整形**：流式内容要求数据量在时间轴上均匀。帧间高斯数量剧烈波动会直接摧毁客户端 QoS，尤其在带宽受限的高移动性场景。这一约束成为本文方法选型的核心驱动力。

从音视频系统视角看，这篇论文实质是把动态 3DGS 的表示问题重写为一个“传输友好”的编码问题：分段、恒定节奏更新、解码与 IO 解耦、支持自适应码率——即把传统视频流媒体工程的整套范式移植到 3DGS 载体上。

## 2. 方法总览

SwinGS 的核心范式转移是：**放弃 canonical 空间固定高斯集合 + 形变网络的紧耦合范式，改为逐帧更新的高斯集合，每个高斯携带显式生命期（lifespan，由 start/expire 两个整数定义），仅在其生命期覆盖的帧内参与渲染**。模型维护一个固定规模（num_gs）的活动高斯池，每帧退役一个子集、引入一个子集，优化焦点永远落在局部短片段而非全视频。

方法由三个协同组件构成：

- **滑窗连续训练**：外层循环将窗口从 [0, swin_size) 滑到序列末端，内层在窗口内随机采样帧训练。GPU 内同时持有两个集合：`gs`（当前可优化高斯）与 `matured`（已快照冻结高斯）。渲染与损失计算由两者共同参与，但只有 `gs` 接收梯度——这是“旧帧质量不被后续优化破坏”的结构性保证，把传统方法里困难的防退化约束问题转化为调度问题。
- **基于 3DGS-MCMC 的恒定数量密度控制**：训练采用 SGLD（对可优化活动高斯注入 scaled noise）与 Gaussian relocation（把低不透明度的“死”高斯重定位到高不透明度的“活”高斯处，再调整双方参数使分布近似不变），而非原生 3DGS 的 split/clone。高斯总数全程恒定，既实现精确数量控制（码率整形的前提），又天然支持退出物体的死高斯被回收复用为新出现物体（内容漂移的处理机制）。
- **slice 错相位成熟**：整个高斯池均分为 swin_size 个 slice，同一 slice 内高斯共享生命期、不同 slice 生命期错开，保证**每帧恰好一个 slice 到期**。于是流式传输被分解为恒定大小的逐帧切片更新，传输量解析地等于 FPS_video × (num_gs/swin_size) × 每高斯字节数——一条恒定码率公式。

客户端则极简：初始拉取前 swin_size 个 slice（共 num_gs 个高斯）填充 GPU 环形缓冲，之后每帧用收到的 slice 替换一个到期槽位；渲染就是按生命期过滤活动高斯后的标准 3DGS 光栅化，**没有任何神经网络推理**（对比 3DGStream 每帧对全体高斯做 NTC 推理刷新）。传输侧再叠加高斯属性量化（means/scale/opacity 不敏感，SH 系数敏感、只保留 DC 全精度）进一步压码率。

整体效果：训练与传输从“一个庞大模型的整体训练/整体传输”被解体为“封装逐帧更新的连续数据段的增量训练/增量传输”，任意时长在原理上可行，且 GPU 资源不随视频长度增长。

## 3. 关键设计

### 3.1 生命期显式化与成熟机制

每个高斯用整数三元组 birth/start/expire 标注生命期，仅当 start ≤ frame < expire 时参与该帧渲染。训练主体（论文 Algorithm 1）要点：

- `train_swin(st, ed)` 每次迭代从窗口内随机采样一帧，active 集合 = `gs` 中生命期覆盖该帧者 + `matured` 中覆盖者；渲染 → 光度损失 + 正则（opacity/scale，沿 3DGS-MCMC 实践）→ 反传（`matured` 无梯度）→ no_grad 下对活动 `gs` 注入 SGLD 噪声 → 每 relocate_period 次迭代执行一次 relocation。
- 窗口滑动一步后执行 `mature(st)`：`gs` 中 start < 新窗口起点的高斯视为到期，参数 detach 快照写入流，并入 `matured`（`matured` 只保留最近 num_gs 个，防止无界增长）；随后这些高斯“重生”：start 置为旧 expire，expire = start + swin_size，进入下一轮可优化周期。
- 主流程在首窗训练后调用 `schedule_expire` 为各 slice 分配错开的到期时刻；序列尾部做一次全量 mature 收尾。

值得注意的机理：`matured` 冻结快照在后续窗口中继续参与渲染，为新可优化高斯提供已定格的上下文，新高斯只需拟合残差——这等价于把时间维因果性编码进训练调度，而非靠损失项硬约束。论文在限制讨论中也指出，relocation 与 birth 字段允许一定程度的 slice 间高斯迁移。

### 3.2 密度控制即码率整形：3DGS-MCMC 选型逻辑

这是全文最具方法论启示的设计决策。原生 3DGS 的 split/clone 致密化使高斯数量随场景复杂度波动，直接后果是逐帧增量不均匀、带宽抖动。3DGS-MCMC 的 relocation 机制把“死”高斯（低 opacity）搬到“活”高斯位置并调参保持分布近似一致，使总数在致密化后恒定，从而： 数量可精确控制，恒定 slice 尺寸的流成为可能； relocation 本身促成相邻帧间高斯分布的平滑过渡——表示退出物体的 Gaussian 被逐步优化为 opacity/scale 递减的死高斯，随后被复用去表达新出现物体。重建算法的选择在这里被赋予了传输语义，即“以密度控制策略换取码流恒定性”。

### 3.3 slice 错相位：恒定增量流

以 swin_size=5 为例（论文正文以文字描述了该示例）：各 slice 的生命期棒在帧轴上首尾相接错开排布；训练帧 #N+1 时，slice #0/#1/#4 中的已成熟部分与 slice #2/#3 中的可优化部分共同参与渲染；窗口 [N, N+5) 训练结束后 slice #2 的到期段成熟——因为此后不再有机会在帧 #N 上继续优化。由此每帧恰好成熟一个 slice，逐帧传输量恒等于 slice_size 个高斯，形成 CBR 式均匀码流。带宽公式为：

BW = FPS_video × (num_gs / swin_size) × N_bytes/GS

即给定视频帧率与单高斯存储，流量正比于 slice_size。swin_size 越大，帧间共享高斯越多、流量越省；num_gs 越大，细节越好、流量越大——两个旋钮构成质量-码率平面。

### 3.4 面向跨帧高斯的训练改造

把为静态重建设计的 3DGS-MCMC 迁移到跨帧高斯上，论文解决了两个工程问题：

- **自适应梯度缩放替代 lr decay**：vanilla 3DGS 对高斯均值的学习率随迭代衰减以实现 coarse-to-fine；但 SwinGS 中不同“训练年龄”的高斯混在同一参数张量里由同一优化器管理，无法各自衰减。替代方案是按每个高斯已被训练的滑窗数量缩放其均值梯度——对 SGD 数学等价，对 Adam 是廉价近似。消融证实有效（见第 5 节）。
- **动态 dataloader**：原生 3DGS 代码库在训练启动时把全部训练图像载入 GPU，对多相机、数百上千帧的体积视频不可行。改造包括 LazyCamera 懒加载图像，以及 GPU 内常驻帧数上限 + 按需动态换入换出。这与高斯生命期局部性（某时刻只有子集视角与子集高斯需要参与反传）共同构成显存常数化的基础。

### 3.5 客户端双线程与槽位寻址

客户端（论文 Algorithm 2）将 GPU 缓冲划为 swin_size 个槽位，每个槽位容纳 slice_size 个高斯。收到的 slice 先进 CPU 侧 events 队列；update_thread 按 FPS 节拍睡眠唤醒，当某 slice 的 target_frame 与当前帧一致时执行 CPU→GPU 搬迁，槽位索引由 target_frame % swin_size 直接确定——错相位设计使槽位寻址无需任何查找或元数据协商。render_thread 持续以 vanilla 3DGS 速度渲染当前活动高斯，与 IO 密集的接收路径完全解耦。这一“解码/更新线程与渲染线程分离 + 抖动缓冲”的结构与成熟视频播放器的管线设计同构。相比 3DGStream 每帧重算并刷新全体高斯，SwinGS 每帧只有一次 GPU 内存写（一个 slice），这解释了其渲染 FPS 的优势。

### 3.6 WebGL 播放器与管线瓶颈

演示播放器基于开源项目 antimatter15/splat 扩展，模型托管于 HuggingFace（即静态文件 + 标准 Web 分发即可服务）。受 Web 应用无法直接操作 GPU 显存的限制，slice 更新发生在 rendering worker 内的高斯 buffer 上。渲染管线三段：原始字节解析（笔记本上一般 <1ms）、深度排序、纹理生成（WebGL 无法直接绘制 3D 高斯，必须先转为纹理数据再送 shader），后两段耗时与高斯数线性相关。这一瓶颈分析对后续移动端 3DGS 播放方案选型（WebGL vs 原生 vs 视频码流化）有直接参考价值。

### 3.7 ABR 雏形

num_gs 与 swin_size 是同时影响带宽与质量的可控参数，天然支持自适应码率。论文实现了朴素版本：带宽受限时对每 slice 更新的高斯做尾部丢弃（tail-drop 最低 opacity 者），或从每个 slice 中子采样一部分传输、其余以空填充占位——保持时间轴与槽位结构不变、只削减信息量，从而与经典 ABR 逻辑兼容。

## 4. 实验结果

设置：DyNeRF 数据集，每场景 300 帧；swin_size=5、num_gs=200K，即每帧更新 40K 高斯；首窗 30K 迭代，后续每窗 2K 迭代；COLMAP SfM 点初始化（随机初始化在其实验设置下易过拟合）；SH degree 取 1 以降存储。

| 方法 | Avg PSNR (dB) | 渲染 FPS | 每帧存储 | 任意长度 |
|---|---|---|---|---|
| 4DGaussians | 31.15 | 30 | 0.3MB | ✗ |

结论口径：SwinGS 超过 NeRF 类方法，与 3DGStream 质量相当；PSNR 略低于 SpacetimeGS，但 SpacetimeGS 不支持长序列且需整模传输。摘要声称相对先前工作传输成本降低 83.6%，与表中量化版 1.2MB/帧 对 3DGStream 7.8MB/帧的量级一致（7.8×(1−0.836)≈1.28MB）。FPS 优势的归因是明确的：基线需要为大量高斯做网络推理，SwinGS 开销主要来自 GPU 内存操作。

## 5. 消融要点

**自适应梯度缩放（Table 5，PSNR dB）：**

| 配置 | Cook Spinach | Cut Beef | Sear Steak |
|---|---|---|---|
| w/o 梯度缩放 | 33.35 | 33.44 | 33.62 |
| w/ 梯度缩放 | 33.81 | 33.71 | 33.62 |

Cook Spinach +0.46、Cut Beef +0.27、Sear Steak 持平——用梯度缩放近似 lr decay 对 Adam 有效，且几乎零成本。

**属性量化（Table 6，单场景口径，PSNR dB，none 基线 33.81）：**

| 量化项 | means fp16 | rotation uint8 | scale fp16 | SH feat fp16 | opacity uint8 |
|---|---|---|---|---|---|
| PSNR | 33.74 | 33.51 | 33.81 | **31.21** | 33.63 |

结论清晰：几何与不透明度属性对低精度鲁棒，球谐系数高度敏感（fp16 即掉 ~2.6dB）；工程取法是只保留 SH 的 DC 项且全精度。这与其他 3DGS 压缩工作中“SH 系数是压缩难点”的经验一致。

**配置敏感性（补充材料）**：scale_reg=1e-2、opacity_reg=2e-2、noise_lr=5e4、SH degree=1；DyNeRF 上 200K 总数与窗口 5 是时间一致性与计算/存储的折中；随机初始化易过拟合，COLMAP SfM 初始化对收敛速度与最终质量均重要。swin_size/num_gs 的结构性权衡（流量 ∝ slice_size）见第 3.3 节公式。

**自述局限——固定成熟调度**：当前每帧到期的是一个预先分配的固定子集（为了 GPU 内存批量操作效率），尚未做到“替换最无信息量的高斯、优先更新最有信息量的内容”。理想情形是 40K/帧的更新预算内向人体运动等动态内容倾斜、对静态背景低频更新——这实际上把“按显著性分配码率”的经典视频编码命题留给了后续工作。

## 6. 贡献与启示

按其所属的系统/流媒体领域标准评价（率-失真-延迟-资源四维而非单纯重建指标），本文贡献有三层：

1. **问题定义**：首个明确把 3DGS 从十几秒短片段推向任意长体积视频流式传输的工作（论文自述 first effort），并系统识别了模型尺寸、时长、内容漂移三个流式化缺口——这一框架本身成为后续 3DGS 流媒体工作的常用出发点。
2. **表示范式**：显式 lifespan + slice 错相位成熟，把 3DGS 流“视频化”了——每帧等量切片更新对应 CBR 恒定码流，slice 槽位对应固定时隙的环形缓冲，客户端“更新线程/渲染线程 + events 抖动缓冲”对应播放器的解码/渲染解耦，ABR 用子采样+空填充实现而不破坏时隙结构。这套设计证明传统视频流媒体的工程范式可以近乎无损地移植到 3DGS 载体，对做音视频系统的研究者是最大启示。
3. **训练范式**：滑窗连续训练 + matured 冻结参与渲染，把“防旧帧退化”从损失设计问题变成调度问题；配合动态 dataloader 实现训练显存对视频长度不变（~2.6GB 常数级），对云端长体积内容的生产/批处理有直接工程意义。

方法选型上的可迁移经验：**密度控制策略具有码率语义**——relocation 恒定总数换来恒定逐帧增量，这种“以重建算法性质换传输友好性”的思路对动态 3DGS 压缩与流媒体具有普适参考价值。

对音视频技术上下游的连接：上游依赖多相机采集与 COLMAP 标定（DyNeRF 式阵列），SfM 初始化质量直接影响收敛与防过拟合；下游方面，WebGL 播放器证明静态文件托管 + 浏览器即可分发，但 texture generation 是 Web 路径的硬瓶颈（M3 Pro 上 18.46ms/帧），原生/WebGPU/硬件编解码复用是明确的替代路线；论文自己的讨论还指出点云生态技术（GROOT 式八叉树→Octree-GS、ViVo 式视口感知→RTGS、MPEG PCC/算术熵编码、点云超分）可继续叠加降码率，代价是客户端解码时延。

需要保持的批判视角：PSNR 并未超越 SpacetimeGS（均值低约 0.4dB），其价值主张在流式属性（300 FPS、量化后 1.2MB/帧、显存常数、任意长度）；ABR 仅为 opacity 尾部丢弃的朴素版；成熟调度固定，尚未做信息量优先的更新分配；300 帧的评测长度虽是 DyNeRF 惯例，但“任意长度”主张的最强证据目前主要是显存常数化，而非数千帧级实测。

## 7. 与其他论文的联系

- **paper:arxiv:2412.04469（QUEEN）**：同属流式自由视点视频的逐帧更新 3DGS 编码。QUEEN 逐帧学习高斯属性残差并结合量化-稀疏化实现在线编码；SwinGS 则以生命期切片 + relocation 实现恒定增量。两者在量化依赖上可互证：QUEEN 重度依赖量化压残差，SwinGS 消融同样发现 SH 系数敏感、几何/不透明度鲁棒，说明“逐帧增量 + 属性量化”是该方向收敛的组合拳，分歧在增量语义（属性残差 vs 高斯切片替换）。
- **paper:arxiv:2409.13648（V^3）**：把动态 3DGS 当作 2D 动态视频以复用硬件视频编解码器，实现移动端体积视频流式播放。与 SwinGS 构成“原生高斯切片流 vs 高斯码流视频化”两条路线的分岔：SwinGS 的 WebGL 播放器自曝了 CPU 侧纹理搬运瓶颈（M3 Pro 上 18.46ms、占总延迟约 2/3），而 V^3 路线借硬件解码天然规避该类开销——两文对移动端播放管线的瓶颈分析互为补充。
- **paper:arxiv:2507.14432（Adaptive 3D Gaussian Splatting Video Streaming）**：同样面向 3DGS 体视频的带宽自适应流式传输，采用高斯形变场构建 + 混合显著性分块。与 SwinGS 的 opacity 尾部丢弃式 ABR 相比，其显著性分块正是对 SwinGS 自述局限（固定成熟调度、未按信息量分配更新预算）的问题空间的一种系统化解答，可视为该方向的直接延伸。
- **paper:arxiv:2610.21121（ResStreamGS）**：按高斯时间特性分流编码传输服务移动端体积视频流媒体。其“动静双流”与 SwinGS 自述的理想成熟调度（优先更新动态内容、低频更新静态背景）同向，同样可定位为对 SwinGS 固定 slice 调度缺陷的针对性改进路线。
- **paper:arxiv:2609.33969（SAGA）**：以 4D 稀疏锚点 + INR 解码与记忆模块压缩动态 3DGS 体积视频，BD-rate 大幅优于现有方案。与 SwinGS 的关联在编码层：SwinGS 每帧传输量化后的原始高斯切片，SAGA 代表“结构化锚点 + 隐式解码”的另一端压缩范式，可作为 SwinGS 切片流之上的编码层替代或叠加方案——关联强度弱于前四条，但同属动态 3DGS 体积视频压缩传输这一问题域。
