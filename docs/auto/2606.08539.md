# AgentTrust: A Self-Improving Trust Layer for AI-Agent Actions

> Chenglin Yang. *arXiv:2606.08539v1 (2026-06-07)*

## 1. 背景与动机

LLM 智能体已从“产出文本”进入“执行动作”：shell、HTTP、数据库查询、云控制面、依赖安装均以 tool-call 形式改变世界状态，单次调用即可删除文件系统、外泄凭据、签发持久 IAM 凭证或引入后门依赖。本文的核心立场是：被信任的基本单元必须从“智能体”下沉到“单个动作”，在 agent 效应器路径上插入 per-action 信任层，执行前给出 allow / warn / block / review 四值裁决。

现有主流是确定性策略（OPA/Rego、Nemo Guardrails、Rebuff/Vigil 类签名扫描，以及前作 v1 的规则拦截器）：快、便宜、可审计。作者指出的不是投入不足，而是一个结构性限制，且把论证轴从“按领域”换成“按威胁类型”：

- **lexical（固定签名）威胁**：危险内嵌于稳定 token——`rm -rf /`、反弹 shell 一行命令、硬编码私钥、`--acl public-read`、cloud metadata IP。正则/AST 即可高精度判定。
- **semantic（意图依赖）威胁**：恶意与良性动作共享同一表面，裁决取决于目的地/内容/范围——遥测 curl vs 外泄 curl（甚至滥用白名单端点）、调试 vs 窃取的 `kubectl get secret`（可逐字节相同）、`SELECT` vs `COPY ... TO` 外带、正常依赖 vs postinstall 执行代码的 typosquat。任何能命中攻击的正则必然命中其良性孪生——规则在构造上不可分离。

该断言被做成可证伪实验：在已有 170 条生产规则的底盘上，于开发集手工增补云/K8s/CI 规则包（steelman），held-out 总体准确率仅 48→56%，纯语义类目 0pp（data_db 29→29、observability 59→59、supply_chain 50→50）；直接对数据极限调参的 cheat 规则集也仅 47.6%——分布内调参不迁移。

第二个动机来自 v1 的失败遗产：v1 的 judge 是 opt-in，其朴素混合（对每个非 block 动作都问 judge、取更严裁决）把总体准确率拉低到 88.0%、FPR 从 2.3% 抬到 9.0%（“judge 有害”结果），且 v1 已预告非对称修正为 future work。v2 的任务是交付该修正、跨分布跨供应商地表征它，并进一步把静态层变为自进化系统。威胁模型上，对手控制动作内容（越狱或经间接提示注入驱动的 agent），可自由选择动作表面而独立于意图；信任层自身未被攻陷，沙箱逃逸与侧信道不在范围。

## 2. 方法总览

动作形式化为 a=(type, tool, description, content, params, session, timestamp)，裁决核心是 (type, tool, content, params)，session 支撑多步 RiskChain 视图与会话记忆。裁决形成严重度序 allow < warn < review < block；全系统受一条硬不变量约束：**良性动作永不被 hard-block**，最坏退化为 soft warn / review。

处理管线分层：

1. **ShellNormalizer**：9 种纯文本去混淆（变量展开、hex/octal 转义、alias 解析、命令替换、相邻引号拼接等），v1 消融中单组件价值最高（单独将混淆攻击漏检率减半），保证混淆后的 lexical 威胁仍落在规则可判定域；
2. **确定性规则地板（lexical 存储）**：42-pattern ActionAnalyzer + 170 规则 PolicyEngine（覆盖 AWS/GCP/Azure IAM、K8s、容器、DB 特权、凭据文件、反取证），零模型调用、每个 block 可溯源到命名规则；
3. **置信度门控语义判官**：地板未决动作交给强 LLM 读上下文，输出裁决+理由+置信度；只有置信度过阈值 τ 的“升级”（allow→warn/block/review）被采纳，否则保持地板裁决。τ 按供应商手工设定，是 load-bearing 参数；
4. **守护式 RAG 记忆（semantic 存储）**：语义先例经检索作为判官的附加证据而非替代裁决；
5. **分布感知融合**：分布内地板+escalate-only；分布外 judge 主导，因为地板 OOD 的 FPR 高达 22.4%，作为地基反而拖垮混合。

自改进回路把判官变成两个**不对称学生**的教师：lexical→规则蒸馏——判官对地板未覆盖的固定签名给出确信裁决后蒸馏为新规则，后续同签名动作由地板零成本解决（judge 调用率随流量下降，更便宜）；semantic→守护记忆——经佐证门的语义裁决进入 RAG，判官域准确率随记忆预热上升（更聪明）。语义类按构造不可规则化，永久留在判官域。端到端在线回放（30 条流 × 1500 动作 = 45,000）：judge 调用率 50%→44%，判官域准确率 71%→80%，总体 84%→85%（可规则化样本主导混合故平坦），全程 0 次良性 hard-block。

## 3. 关键设计

### 3.1 威胁二分与表面孪生（概念支柱）

可判定性论证的极形式是孪生对：“当良性动作与恶意动作是同一字符串时，该字符串的任何函数都无法分离它们”——`kubectl get secret` 行是最纯粹表述。三行孪生对专门用来击碎显然的规则式防御：(i) **白名单端点滥用**——egress allow-list 不仅不够，反而“许可”了攻击，通道被批准而路径/载荷归攻击者，只有对“发什么、为什么发”的推理能分离；(ii) **SELECT vs COPY-exfil**——危险行为是“查询变成带外传输”这一语义，表面形态众多（COPY、`\copy`、服务端函数、应用层分页循环），禁一个短语既抓不全也误伤；(iii) 逐字节相同的 secret 读取。该二分直接规定架构，并预言“以动作为键的裁决缓存必然失败”（孪生塌缩到同键），后文实验直接验证。

### 3.2 置信度门控判官

原始判官裁决从不直接生效，只允许升级方向且需过 τ 门。这把高召回但精度不完美的判官转成净增益组件：保住语义类捕获、压制对良性流量的低置信过度升级。τ 供应商相关：Claude 系校准良好可用宽松门，GPT 系在模糊流量上 trigger-happy 需紧门，但两种情形下置信度都能干净区分真捕获与误报。τ 手工设定，自动校准列为 future work。

### 3.3 分布感知融合

分布内 escalate-only 混合在 630 集上把 95.4/2.1/6.1 提到 98.3/2.1/0.9（FNR 降 6 倍以上、FPR 持平）；分布外地板是负资产，escalate-only 混合（≈78%）反而低于 judge 单用（≈85%），正确策略是 judge-leads（gated-replace）。同一对组件按分布重组合。

### 3.4 守护式 RAG 记忆（为何必须是 RAG 不是缓存）

负结果：以动作表面为键的 verdict-cache，raw-text 检索准确率 ≈58%（约等于多数类/随机水平），MiniLM 神经检索不救，且**任意覆盖率下都不存在 ≥95% 高精度区间**——良性/恶意实例互为最近邻，缓存在最要紧的样本上取回错误先例。TF-IDF 变体作为保守下界结论相同。这与规则失败同根：都以表面为键。因此先例只作判官推理的增强证据（CBR/RAG 血统），判官仍重读新动作的具体意图，孪生不塌缩到单一答案。

记忆投毒是自填充记忆的默认风险：把判官自身裁决无门禁写入，检索增益仅 +2pp 且实际毒化一个类目（observability 81→78，检索到的正是判官过去的错误）。修复是**佐证门**：仅当两个独立判官一致（实现为 no-RAG Sonnet-4.6 裁决与 Opus-4.8 一致）才准入；佐证率 62%（38% 候选被弃），记忆自身正确率 70%→97%，语义切片 70→84（+13pp）、零危险泄漏。代价是准入时的第二次判官调用，且这是唯一评估过的门变体。

### 3.5 安全不变量

任何融合路径不得把真良性动作变成 block；hard-block 仅保留给可正向论证为危险的动作。模糊孪生上的过度谨慎退化为摩擦，不破坏良性工作流。经验上在全部判官×数据集×45,000 在线动作上 0 违例——这是激进升级策略得以安全部署的前提。

## 5. 消融要点

- **规则 steelman（正反两面）**：+cloud 包总体 48→56.1，增益全部落在有稳定签名的类目，语义三类 0pp；cheat 规则集 47.6%——分布内 token 调参不迁移。这组实验是"rebuttal-proof"论证的核心：反驳者能主张的“再写规则”已被作者替他写完。
- **verdict-cache vs RAG**：≈58%（raw 与 MiniLM 均然）、任意覆盖率无 ≥95% 高精度区间、TF-IDF 保守下界同结论。负结果直接决定语义存储必须是检索增强而非答案缓存。
- **无门 vs 佐证门记忆**：+2pp vs +13pp，记忆正确率 70% vs 97%，且无门版本实际毒化一个类目——自填充记忆的默认形态是负资产而非弱正资产。
- **v1 朴素混合作为“门是 load-bearing”的反事实**：无门 always-on judge 使 FPR 2.3→9.0%、acc 降至 88.0%；同一判官加 escalate-only 置信门后在 630 集上全面净增益。
- **协议消融**：对 v1 地板做逐场景会话重置并剔除 4 条 benchmark_compat 合成域规则后重跑得 94.7/95.4，与 v1 发表的 95.0/96.7（兼容开 97.0）可对账——说明 v1 头部数字含少量基准兼容成分，本文口径更保守。
- **作者自陈的限制**：策展语料非生产流量（绝对数不声称迁移，只声称排序迁移）；回放非在线系统；摊销幅度保守（语料 52% 语义攻击密集，良性为主的真实流量下 judge 调用率降幅会更大，但作者拒绝外推具体金额）；佐证门是唯一门变体且需第二次判官调用；external 189/语义切片 98 的 N 偏小，分类别点估计勿过度解读；τ 手工设定且换供应商需重调。

## 6. 贡献与启示

**方法论贡献**：把“规则不行”从断言升级为可证伪实验——自己替反驳者写规则，在其最有利条件下展示语义类 0pp。这一论证模板适用于任何 detector-vs-rules 之争。**表征贡献**：给出此前文献缺失的判官-as-系统组件刻画—— 分布内判官单用不胜规则（差距在主观 warn 类），净增益必须靠门控混合； 判官优势是 OOD 现象； 召回在最小模型档饱和、能力买精度——这直接决定部署选型是“强判官+门控”而非弱判官。**系统贡献**：按可蒸馏性给学生定型的非对称双存储——lexical 蒸馏进确定性规则（省钱）、semantic 永久留在判官+守护记忆（变聪明），并以 never-hard-block 不变量把自改进的失败模式约束为摩擦而非破坏。

工程落地要点：per-provider τ 校准是真实部署成本；需要分布检测来切换 escalate-only 与 judge-leads 两种融合；蒸馏只施加于 lexical-novel 案例，避免语义类被错误规则化；佐证门每条准入多一次判官调用并弃 38% 候选。

**与音视频技术的上下游关联（笔记者延伸，非原文主张）**： 本文属智能体安全/系统方向，但其动作空间与媒体基础设施高度重叠，三个接口值得注意。 其一，内容识别/审核同构：版权指纹、感知哈希、黑名单匹配属 lexical 通道（快、确定、可审计）；“同一字节/同一指纹但授权语境不同”（授权分发 vs 盗版再分发、合理使用、区域授权差异）正是表面孪生——裁决取决于语境而非载体。verdict-cache 负结果对审核系统直接适用：以内容哈希为键缓存裁决会在孪生内容上取回错误先例，先例只能作为重判的增强证据；佐证门则对应双审/抽检人审机制，防止审核侧错误被固化为先例。 其二，媒体管线 agent 化的信任需求：渲染农场、转码集群、MAM、云存储/CDN 运维正被 agent 接管，动作通道（shell、db_query、cloud_api、http_request、package_install）与本文威胁模型完全同构；ffmpeg/转码作业输出指向远端 URL 即天然外泄通道，“白名单 CDN 端点滥用”孪生对在媒体资产分发场景逐字成立。 其三，成本结构借鉴：判官调用率随规则蒸馏单调下降的摊销模型，对大规模审核/策略执行管线的 LLM 成本控制有直接参考；“召回饱和、能力买精度”提示审核场景可用小模型保召回、以置信门换精度。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326，When Should Agents Remember? Falsification-Gated Self-Evolution）**：最直接的同类工作。两者都发现“无门禁地把系统自身产出写入记忆是净负资产”（本文：+2pp 且毒化类目；FGSE 的动机同为更新安全），并各设一道准入门：FGSE 把经验教训作为可证伪假设经三类探针验证后写入；AgentTrust 用双判官一致性（62% 佐证率）过滤先例并使记忆正确率 70%→97%。差异：FGSE 是面向 agent 行为经验的假设检验框架，AgentTrust 面向安全裁决先例，且额外证明了该存储必须是 RAG 而非答案缓存——其表面孪生论证对任何“以输入相似度复用输出”的设计（含内容审核缓存）都构成警示。
- **TRUST（arXiv:2611.10787，Trustworthy Recursive Self-Improvement with Statistical Guarantees）**：同属“可信自改进”问题轴。TRUST 用在线多重假设检验为递归自改进控制错误进化率并提供统计保证；AgentTrust 明确自陈其在线贡献是“经验与系统层面的，而非新的 regret 界”。二者互补：AgentTrust 的佐证门+never-hard-block 不变量是工程化护栏，TRUST 的检验框架恰好可替换/加固目前那道唯一的、手工的准入门。
- **SkillDuet（arXiv:2611.12109，Co-Evolving Models and Skills through Response Feedback）**：结构同型——都从系统自身的决策/响应流同时更新两个不对称学习基底。SkillDuet 是模型参数+外部技能库的协同演化（技能级递归自改进）；AgentTrust 是确定性规则地板+检索记忆的双存储，学生的“型”由威胁可判定性规定并受硬安全不变量约束。对照价值在于：SkillDuet 触及权重层，AgentTrust 完全停留在策略/记忆层，代表自改进栈的两个不同高度。
