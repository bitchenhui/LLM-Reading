## 1. 背景与动机

核心问题：LLM agent 在序列化任务中把每次交互当作孤立 episode，存在"操作性失忆"（operational amnesia）——不从成功中归纳策略、不从失败中规避错误。RAG 类框架只补外部知识缺口，不解决"从自身交互后果中系统性学习"这一更根本的缺口。

论文把既有 agent 学习范式归纳为三种并逐一指出缺陷（动机论证的骨架）：(1) Stateless Execution，标准 agent 用后即弃；(2) Learning by Raw Trajectories，检索完整历史轨迹直接指导决策，只模仿不复用，无法抽象出可迁移的战略原则（Reflexion、Generative Agents 一类把原始轨迹当记忆）；(3) Learning via External Scribing，外挂强 LLM 教师做反思总结存入外部记忆（ExpeL、Memento 一类），省资源但反思只是瞬时提示，agent 内在策略不变。另一条相关线是 RL 训练搜索型 agent（Search-R1、O2-Searcher、AutoRefine），它们优化了 LLM 与外部事实知识的交互，但不处理"利用自身内部经验的自改进"。值得注意的是 O2-Searcher 与本文作者团队高度重合，本文可视为该团队从"搜索工具 RL"向"经验生命周期"的推进。

EvolveR 的主张：把在线交互、离线自蒸馏、策略演化闭合成完整经验生命周期；agent 不只模仿过去交互，而是"基于所学到的内容演化"。工程定位上，这是一篇 NLP/agent 论文（非本库核心大类），但其"经验库检索 + GRPO 工具使用 RL"的配方对多模态/音视频 agent 训练有直接可迁移性，见第 6 节。

## 2. 方法总览

框架由三个交替衔接的组件构成。

**动作空间**：面向知识密集任务，agent 的动作集为三类——`<search experience>`（查内部经验库 E，返回 top-3 条蒸馏原则）、`<search knowledge>`（查外部知识库/搜索引擎，返回 top-3 文档）、`<answer>`（终止作答）；外层是 Think-Act-Observe 多轮循环。

**离线自蒸馏（参数冻结）**：用 agent 自身策略模型 πθ 以"专家"人设回看每条轨迹，按结局蒸馏出一句话自然语言原则 + 结构化 (subject, predicate, object) 三元组（表示法受 Mem0、G-Memory 启发）；成功轨迹产"指导原则"，失败轨迹产"警示原则"。

**经验库维护**：两级去重 + 动态评分。候选原则先在批内（同题、GRPO 采样冗余）做语义等价去重；再经嵌入余弦相似度预过滤（阈值 θ_sim=0.85，BGE-M3 嵌入）+ LLM 二元等价判别，novel 则入库，否则把源轨迹挂到最相似既有原则下（证据累积而非冗余扩库，式 1）。每条原则按 s(p)=(c_succ+1)/(c_use+2)（拉普拉斯平滑成功率）持续计分，周期性清除低于 θ_prune=0.3 的条目。

**在线交互**：检索到的原则不是事实信息而是启发式引导，可直接改写 `<think>` 内部独白并导向后续 `<search knowledge>`；由此产出的轨迹是"经验引导的结构化解题记录"，作为下一轮离线蒸馏的输入。经验库由域内数据（NQ、HotpotQA 训练划分）构建。

**策略演化（闭环）**：GRPO 更新 πθ。关键在于轨迹本身以检索到的原则为条件，因此优化显式学的是"如何利用自己蒸馏出的智慧拿到高回报"，而非通用推理策略。检索返回的 `<experience>`/`<information>` 段在损失中被 mask，作为上下文处理。

**训练流程**：冷启动 SFT 仅教交互格式——用 GPT-4o 以"已知答案逆向复原解题路径"的提示词，从 NQ/HotpotQA 训练集约 700 样本合成格式规范轨迹，LoRA 微调（LLaMA-Factory，3 epoch，lr 1e-4，batch 16）；随后进入在线/离线交替 + GRPO 演化。

## 3. 关键设计

**（1）原则的双模态表示**。自然语言描述（供人与检索）+ SPO 三元组（供结构化匹配），把语义检索与结构化判别解耦。示例：成功原则"对比较类问题，先分别收集两侧数据再下结论"配 (Comparison, needs, data on both sides)。

**（2）写时去重 vs 用时过滤的双层质控**。这是全文最重要的工程设计。写时：嵌入预过滤 + LLM 等价判别的两级匹配；用时：平滑成功率评分 + 周期剪枝。分工明确——去重控冗余、评分控质量，且评分天然以"被检索后的实际效用"为信号，比纯语义判断更贴近最终目标。

**（3）复合奖励的工程细节**。R = w_o·R_outcome + w_f·R_format，w_o=1.0、w_f=0.1，结果奖励（标准化后精确匹配 EM、稀疏二值）主导，格式奖励作过程塑形：R_format = I(τ_complete)·(R_think+R_search)/2。结构完整性指示器 I 要求轨迹至少各含一次 `<think>`、任一 search 与 `<answer>`，否则格式分为 0。R_think 分段映射：1 次思考 0.2，升至 6 次 1.0，超过 8 次封顶 0.5（抑制过度思考）；R_search = 多样性分（经验+知识两类检索都用 0.5、仅一类 0.2、都不用 0）+ 数量奖励（首检之外每次 +0.1、上限 0.5，合计 6 次封顶）。设计意图明确：强制两类检索行为在 rollout 中持续出现，保证经验库不断获得使用统计——否则动态评分机制会饿死。

**（4）GRPO 的接入方式**。每步采 128 个 prompt、每 prompt G=8 条轨迹，组内平均回报做基线，免价值网络；lr 1e-6、warmup 20 步、clip ε=0.2、KL 系数 β=0.001；rollout 用 vLLM（温度 1.0、top-p 0.95），最大输入 8192 / 最大回复 1024 token。经验条件化训练是闭环关键：RL 信号强化"检索高质量原则 → 产出高回报轨迹"的关联。

**（5）成本画像**。Qwen2.5-3B 全生命周期（冷启动 SFT + GRPO）在 8×A100(80GB) 上约 39.4 小时；经验库用 Milvus 向量检索，约 1.4 万条原则时 top-3 检索延迟约 0.06s，相对 LLM 生成耗时可忽略。

## 5. 消融要点

**自蒸馏 vs 教师蒸馏的规模交叉**（教师 = GPT-4o-mini）：0.5B 上教师版全面占优（平均 0.220 vs 0.150）；1.5B 教师仍略优（0.290 vs 0.270）；3B 反转，自蒸馏 0.382 > 教师蒸馏 0.370。作者解释为"认知对齐"：自身策略蒸馏出的原则与其自身失败模式和推理习惯兼容，外部通用建议可执行性差。这是全文信息量最大的结论之一——自蒸馏是随规模增长的相对优势，小模型需要教师引导。

**推理期经验检索依赖性**：两变体经历完全相同的经验驱动 RL 训练，唯一差别是评测时是否允许访问经验库。3B 从 0.382 降至 0.340；1.5B 从 0.270 腰斩至 0.123；0.5B 从 0.150 降至 0.078。掉幅随规模增大而收窄，说明大模型已把部分经验内化进策略参数，但最优性能仍依赖检索。

**组件归因**（3B）：Direct 0.134；仅 RL（无经验）0.325；蒸馏+检索、无 RL 0.357；蒸馏+RL、无检索 0.340；完整 0.382。三点结论：仅 RL 不足；无 RL 的结构化检索（0.357）已超过仅 RL（0.325），检索引导是主增益源；RL 再抬 0.025，二者互补——检索给引导、RL 学会利用。

**同一批轨迹 SFT vs GRPO**：复用在线阶段完全相同的成功轨迹做 SFT 仅 0.357，GRPO 0.382（论文口径约 7% 相对提升）。归因：SFT 只复现表层动作序列，不理解 `<search experience>` 这类动作的效用期望；GRPO 同时利用成功与失败 rollout。

**原则质量人工标注**（抽 100 条按分数分层）：低分层（0.30–0.44）Ideal/Vague/Incorrect = 26%/50%/24%；高分层（0.44–0.75）= 82%/10%/8%。评分-剪枝把误导性原则从 24% 压到 8%、可执行原则从 26% 提到 82%；低分层残余主失败模式是"模糊但正确"（50%）。定性对照：0.25 分的淘汰原则是"避免原则冗余"类元空话，0.80 分的保留原则给出具体场景的具体纠错动作。

**经验库长期扩展性**（3B，论文口径为跨六个基准随机抽 10% 验证子集）：规模 4,213→13,435→23,448→32,805→45,083→49,934，top-3 检索延迟 0.04→0.20s，EM 0.301→0.372→0.382→0.396→0.410→0.387。近 5 万条时延迟可忽略、性能不崩溃、45k 处达峰后 50k 轻微回落——去重+评分+RL 条件化对噪声累积相当鲁棒，但非单调，提示持续增长需更主动的库容量控制。

**超参与动力学**：θ_prune ∈ {0.1, 0.3, 0.7, 0.9} 在 1.5B 上平均 0.269/0.270/0.265/0.276，基本不敏感。RL 过程中动作频次先升后收敛至约 2 次经验检索、4 次知识检索、6 次思考/轨迹；按蒸馏时段分组的存量原则平均分从 Interval 1 的 0.462 升至 Interval 4 的 0.500（各组平均使用次数 8.22/24.10/17.82/12.36），说明模型蒸馏高质量原则的内在能力随训练提升，而非仅靠过滤。

**经验吸收的负结果**：把检索到的 `<experience>` token 从 loss mask 改为放开（exp-absorb），3B 平均 0.382 → 0.371。归因：top-k 检索的原则并非全部与当前上下文相关，无差别内化引入噪声；作者认为需要相关性加权的辅助机制才能让内化生效。该负结果与"认知对齐"正结果合起来给出清晰边界：经验先以外部上下文形式被策略利用，直接写入参数目前是净负收益。

## 6. 贡献与启示

按 agent 领域自身标准评估三点贡献：(1) 把"在线交互—离线自蒸馏—策略演化"闭成完整生命周期，相对三种既有范式给出清晰定位；(2) 一套完整经验库 curation 管线（批内去重、嵌入+LLM 两级匹配、平滑成功率评分、周期剪枝），且有质量分层标注与规模扩展性数据背书；(3) 自蒸馏/教师蒸馏的规模交叉规律（3B 处反转）。

工程启示（论文口径内可直接引用）：结构化原则检索是无 RL 时也成立的强基线（0.357 > 0.325），RL 的边际价值在于学"如何用经验"；过程塑形奖励需显式保护低频关键动作（此处是 `<search experience>`），否则经验评分机制无数据可用；外挂检索内容 loss-mask 是默认安全选择。局限（论文自述）：自蒸馏上限受基座能力约束；任务面仅限 QA，具身交互/创作生成未验证；真终身学习的算力效率开放；自演化原则若奖励未价值对齐可能产生不良策略。

**与音视频技术上下游的关联（引擎补充视角，非论文内容）**：
- 上游：整条流水线落在 Qwen2.5 + verl + vLLM + BGE-M3 + Milvus 的通用训练栈上，无文本专属耦合；"交错 think/tool token 的结构化格式奖励 + GRPO"配方原则上只需把 `<search knowledge>` 换成视频段落检索/ASR/镜头切分/时序定位等工具调用，即可迁移到长视频多跳问答与视频 agent 训练——这是本文对音视频 agent 训练最直接的借出点。
- 下游：经验库"自然语言原则 + 三元组"的表示与 0.06–0.20s 的检索延迟（1.4万–5万条规模）满足交互式音视频应用的实时预算；显式可读的原则库比参数内隐知识更可审计、可干预，利于媒体管线调试。
- 迁移风险提示：本文全部结论的口径是文本 QA 的 EM；开放性音视频任务无精确匹配奖励，R_outcome 需重设计（判别器或偏好信号），且 0.5B 级模型自蒸馏失效意味着端侧小模型同款方案需云端蒸馏服务引导——这两点是照搬配方前必须先解决的。

## 7. 与其他论文的联系

- **FGSE（arXiv:2611.14326）**：同属"经验教训记忆 + 自演化"谱系，质控位置互补——EvolveR 是用时过滤（经验分 + 周期剪枝，事后淘汰），FGSE 是写时验证（教训作为可证伪假设经探针验证后才入库）。EvolveR 低分层仍有 24% 误导性原则混入，正是 FGSE 写前门控可针对性补的口子。
- **SkillDuet（arXiv:2611.12109）**：结构同型——都是"策略参数 + 外部可演化库"双轨（EvolveR：GRPO 参数 + 原则库；SkillDuet：参数更新与外部技能库经响应反馈协同演化）。二者位于设计轴两端：EvolveR 证明库内容直接进参数（exp-absorb）当前是负收益（0.382→0.371），SkillDuet 显式追求库与参数的反馈耦合，可互为对照实验。
- **TRUST（arXiv:2611.10787）**：针对本文 curation 层的统计缺口。s(p) 是无置信区间、无多重检验修正的点估计；在近 5 万条原则上反复"检索-选择-评分"，误导性策略的假阳性累积风险随规模上升（本文 45k 峰值后 50k 回落 0.410→0.387 是否与此有关，论文未做归因）。TRUST 的在线多重假设检验恰好为该层提供错误进化率控制与统计保证。
- **WeightLoop（arXiv:2611.07319）**：替代"策略演化"半环的路线——以有界权重编辑程序 + 实验反馈免重训地自改进已部署模型。对 rollout RL 成本敏感的已部署音视频基座模型，这是比 GRPO 更轻的闭环选项。
- **LongCapHarness（arXiv:2611.10463）**：推理期 RSI 挂接 vs 参数更新的对照。EvolveR 的无 RL 变体（0.357）已超过仅 RL（0.325），与 LongCapHarness"免后训练即超基线"的结论互为佐证：结构化检索/挂接本身即是强增益源，参数更新是叠加项而非前提。
