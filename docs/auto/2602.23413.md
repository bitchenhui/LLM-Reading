## 1. 背景与动机

LLM 驱动的进化搜索（AlphaEvolve 一脉）已成为跨领域程序/算法自动改进的主流范式：维护候选解种群数据库，每步由**搜索策略**从历史解中选出父代、指定变异方式并构造灵感集，拼装成 prompt 交给生成器 LLM 产出新候选，评估后回填种群。论文的核心论点是：该范式的效能瓶颈不在生成器，而在搜索策略本身——即“选什么历史解、怎么变”。现有系统的搜索策略均为固定拓扑加手调旋钮：AlphaEvolve 采用 MAP-Elites 与预定义种群结构、选择比例；OpenEvolve 依赖静态精英与多样性启发式；ShinkaEvolve 前进一步，用 bandit 选择 LLM 生成器，但 exploitation 比例等关键参数仍手动固定；GEPA 沿 Pareto 前沿做选择，骨架同样静态。

论文指出两类典型失效。其一是**跨任务不通用**：装箱类问题对近可行解做小规模局部调整即可持续增益，而 GPU-model 放置问题上精修 least-loaded 启发式很快平台化，继续推进需要把问题重构为 bin-packing 式指派——不同任务需要质不同的搜索行为。其二是**任务内非平稳**：同一个优化运行中，搜索空间随种群演化而漂移；论文以多目标信号处理任务为例，MAP-Elites 式固定 explore-exploit 比例的策略早期进展快、后期停滞，切换为按目标维度分层的采样策略后才能继续提升。由此动机落点：把搜索策略本身当作可进化对象，构建解进化与策略进化的双层过程。

## 2. 方法总览

**形式化**（第 3 节）：评估器 E(x)→(s(x), a(x)) 返回标量分与辅助工件（日志/trace）；数据库 Dt 累积全部已评估候选；搜索策略 S 定义上下文构造 C_S(Dt)→(x_par, π, I)，即父代候选、变异算子 π 与可选灵感集 I ⊆ Dt；生成器 x′ ~ G_sol(·|x_par, π, I)。变异算子三类：local refinement（局部精修，exploit）、structural variation（结构变异，explore）、free-form variation（默认，不限编辑范围）；算子的任务特定语义在任务开始时由轻量模型从问题描述实例化为一组算子专用 prompt。目标为固定评估预算 T 下最大化终态最优分 max s。

**双层循环**（Algorithm 1）分三个阶段循环：

- **Phase I 解进化**：以当前策略 St 运行一个窗口 W 次迭代，St 决定每步的父代选择、算子与灵感集；
- **Phase II 进度监测**：计算窗口增益 Δ = s_end − s_start（窗口首尾种群最优分之差），并把策略得分 J(St|Dt) = Δ·log(1+s_start)/√W 记入策略数据库 H = {(Sj, ϕj, Jj)}；
- **Phase III 策略进化**：若 Δ 低于停滞阈值 τ，由策略生成器 G_str（论文用 GPT-5）以历史策略库 H 和当前种群描述子 ϕ(Dt) 为条件采样新策略 S′，通过 VALID 有效性校验后即时切换；重试至固定预算、全败则回退旧策略。

关键部署细节：窗口 W 取总迭代预算的 10%；切换**不重置**解种群 D，元层搜索不破坏内层进度；策略切换由停滞触发（demand-driven）而非固定周期，避免策略有效时的无谓更新。所有 EvoX 运行从最朴素的均匀随机采样策略起步。

## 3. 关键设计

**策略信用分配。** 策略塑造的是候选序列而非单次结果，故以窗口级而非样本级评估。J 的 log(1+s_start) 项对同等增量、更高起点的窗口加权——前沿处的增益通常更难获得；√W 归一化窗口长度。Δ<τ 的停滞判据使策略切换只在需要时发生。这个 J 是纯启发式设计，论文未给出理论论证，但消融中不同策略窗口的 J 排序与实际增益一致（如信号处理任务分层多目标窗口 +0.12/19 次迭代为最大）。

**状态条件化的元进化。** 策略有效性依赖种群状态（本质是非平稳优化：随数据库增长，候选质量/多样性/变异结果的分布漂移）。EvoX 的处理是双条件化：ϕ(Dt) 包含 分数统计（最优值、分位数、离散度）、前沿结构（top-k 分数）、进度指标（距上次显著改进的步数）、近期窗口统计（父代被选频率），使系统能把“停滞”解释为具体结构问题（多样性丧失、父代重复选择、变异无效）；策略库 H 则提供“哪类策略在哪类状态下曾诱导进展”的实证证据。元层操作与内层同构：对 H 做 score-biased 选择挑父策略，灵感集优先取历史强进展策略与描述子 ϕj 相似的策略，G_str 据此变异出 S′——变异对象是策略组件（父代选择规则、灵感集构造、对算子 π 的偏好）。

**策略即代码的工程接口。** 策略被实现为 `EvolvedProgramDatabase` 类，接口仅 `add`（如何入库）与 `sample`（选父代+算子标签+灵感集）两个方法；父代标签协议为 ""（free-form，默认）/ REFINE / DIVERGE，每步恰用一个算子。策略进化 prompt（附录 C）注入五块上下文：下游问题模板、搜索窗口上下文、种群状态摘要（含停滞信号、复用模式、执行 trace）、当前策略程序全文、相关历史策略变体；硬约束包括评估指标只读、类型校验（对 metrics 做 isinstance 数值检查）、变量必须安全默认值初始化。VALID 校验保证候选策略可执行，失败回退旧策略。这套“受限 DSL + 运行时校验 + 回退”的设计是元层不致挂死的关键，也是可直接移植到其他 LLM-as-optimizer 管线的工程模板。

**生成器分工。** 解生成用任务骨干模型（GPT-5 或 Gemini-3.0-Pro），策略生成固定用 GPT-5；两个回路解耦，元层成本与内层同骨干无关。

## 5. 消融要点

**初始策略鲁棒性**（Heilbronn triangle）：比较 Beam Search / Best-of-N / Top-K / MAP-Elites 四种固定初始化。Beam 与 Best-of-N 因集中算力反复精修头部候选而初始化最强；Top-K 保留多候选、分散优化压力而收敛慢；MAP-Elites 维护多样性网格、最落后。所有固定策略均早饱和；从任一初始化出发、允许策略进化的 EvoX 持续超越其固定版本——元层收益不依赖“好起点”，这回应了“是否只是初始化好”的质疑。

**信号处理案例（第 5 节）**：同 100 迭代预算下 EvoX 终分比静态基线高 34.1%（基线 0.499→0.530 后停滞，只能产出 NumPy 级 MA/EMA 简单滤波器）。策略轨迹完整展示了状态条件化切换：随机采样 → 迭代 20 换 greedy（因当前最优仍是简单 MA/EMA 结构，纯精修无突破）→ 迭代 40 分层+多目标采样（按目标维度选互补灵感，如高平滑父代配低滞后灵感，发现 SSA+Whittaker 混合设计，+0.119 为最大跳变）→ 迭代 60 UCB 选择 + 结构变异（描述子显示新候选分数趋同，遂加大结构变异压力、用 UCB 惩罚父代过用，引入 SciPy 高阶滤波、平滑核与 filtfilt 前后向滤波管线，+0.056）→ 迭代 90 UCB + 局部精修收尾（+0.022）。附录 A7 的逐窗口 Δ/W 与此一致：stratified+multi-objective 窗口 +0.12/19 为最大。

**圆装箱案例（附录 D.1/A8，Gemini）**：0.364→1.0004。随机采样窗口 +0.59/21 后饱和；随后 usage-penalized、tiered 采样窗口增益很小（+0.04、+0.004），但作用是**保种群多样性**；在 stagnation-aware 采样下，结构变异触发范式级跃迁——从手工位移启发式（逐圆独立调整、约束靠惩罚外生执行、易振荡）转为 SLSQP 约束优化（圆位置为联合优化变量、约束内生于更新规则、梯度协同消除振荡）；此后 elite refinement 窗口 0 增益、quantile-biased 精修 ~2e-5，进入收敛稳定期。论文据此提出核心主张：策略进化实现的是“优化**机制**发现”而非仅采样效率提升——静态策略中变异算子本身几乎不会触发范式转移。

**边界与失效面**：强生成器可部分替代策略自适应——Gemini 下 Cloudcast 纯随机采样即获大幅改进（附录 A6），说明收益集中在生成器较弱或任务较难的组合；Heilbronn triangle 与 MinMaxMinDist(d=3) 上 mean 落后 best（论文归因：早期随机初始化偶尔收敛进强局部最优，100 迭代预算内难逃逸）；ALE 的 AHC025 因强初始解偏置局部最优、增益小。

## 6. 贡献与启示

**方法学贡献**： 首次把 LLM 进化优化形式化为解进化与搜索策略进化的双层过程，把“选择规则 + 变异算子偏好 + 灵感集构造”整体作为可进化代码对象； 区别于 SOAR/ThetaEvolve/TTT-Discover/FLEX 调整生成器模型本身、也区别于 ShinkaEvolve 仅 bandit 化个别旋钮——EvoX 自适应的是完整的搜索策略，且带状态条件化的信用分配（J 公式 + ϕ(Dt) 条件化 + 策略库 H 检索）。 **实证贡献**：~196 任务上对开放框架多数任务占优（论文口径：数学+系统基准的 96% 任务），对闭源 AlphaEvolve 5/7 追平或超越，成本上 <$1 达到 0.031+ 分（对手 $7.6–$15.4）。

**工程启示**：对任何“LLM 提案 + 评估器打分”的迭代管线（含音视频工程中的编码参数搜索、ABR/调度启发式自动搜索、编解码器内工具选择），“把手调的 explore-exploit 旋钮交给元进化”是可复用的架构模式；J 的对数加权、10% 预算窗口、停滞触发、VALID+回退这组设计构成了低成本可移植的最小实现。系统组结果直接指向推理服务层：PRISM 的 KV-cache 压力感知放置与 EPLB 的 MoE 专家放置（best 0.1453 vs human 0.1265）是多模态大模型 serving 的调度算法；Telemetry Repair 与信号处理滤波合成则示范了该范式在 DSP/信号重建侧（丢包隐藏、错误掩盖、滤波器链设计同构问题）的可用性。

**局限**：三次运行的统计口径较薄；mean-best 差揭示对初始随机性仍敏感；AlphaEvolve 预算不可知使跨系统公平性存疑；策略生成（GPT-5）与算子实例化（轻量模型）的元层开销未单独列账；整个框架以可获得可靠标量评估器为前提，对评估昂贵或含噪的任务（不少音视频主观质量任务）需先解决评估瓶颈。

## 7. 与其他论文的联系

- **SwarmEvolve（arxiv:2611.08483）**：同为后-AlphaEvolve 程序进化框架、同以 AlphaEvolve/OpenEvolve 类系统为基线族；互补的自适应轴——SwarmEvolve 改造智能体种群架构与潜在空间协作（含推理侧 KV-cache 共享），EvoX 完全不动生成器、只元进化选择/变异策略，两者可叠加。
- **AutoAssumption（arxiv:2611.14844）**：目标域重叠——其自动发现 KV 缓存驱逐与剪枝算法，与 EvoX 系统基准中 PRISM 的 KV-cache 压力、EPLB 的专家放置同属 ML-serving 算法发现；机理相反：前者在 Lean 证明图中放宽假设重推导、产物带形式保证，EvoX 的 VALID 仅做运行时有效性检查、策略选择纯靠经验信用 J，两者分别覆盖“可证明”与“经验更强”的光谱两端。
- **FrugalEvo（arxiv:2610.03675）**：同关注 LLM 进化的成本轴。FrugalEvo 用强/廉价模型分工（策略 vs 写码）压单位成本，EvoX 的成本优势来自策略自适应减少无效迭代（<$1 vs $15.4）；正交可组合——EvoX 元层可引入 FrugalEvo 式模型分工进一步降本。
- **Hill Sampling（arxiv:2609.25510）**：直接对照证据。其主张冻结 LLM 以当前最优程序为条件的重复采样即可胜过进化搜索与测试时训练；而 EvoX 的信号处理案例显示固定策略（含朴素采样）停滞、策略切换才突破——说明“进化 vs 采样”之争的关键变量是搜索策略是否自适应，两者结论互为边界条件。
- **ε-MemEvo（arxiv:2608.12522）**：EvoX 的策略库 H 与描述子匹配是任务内元记忆，每任务从随机策略冷启动；ε-MemEvo 恰解决跨任务策略迁移（8 基准平均 +8.7%），把 EvoX 进化出的搜索策略以任务无关形式存取，是弥补该冷启动开销的直接延伸方向。
- **MLEvolve（arxiv:2606.06473）**：同为 LLM 自进化发现 ML 算法的框架（渐进 MCGS + 回顾记忆），差异在于 MLEvolve 固化搜索骨架、EvoX 把骨架本身（选择/变异策略）作为进化对象；EvoX 消融中“任意初始化均超越固定版”预示其元层可外套在 MLEvolve 类固定骨架系统之外。
- **Agentic Algorithm Design（arxiv:2610.35595）**：在 Lean 中机器检验所提出进化算法的期望运行时间界、无需经验比较；其对象（进化算法组件）与 EvoX 进化出的“选择规则+变异算子”呼应——前者提供形式化保证、后者提供经验适配，组合方向是用形式界约束 EvoX 的策略变异空间。
- **VLM 图表分析自主进化（arxiv:2610.35077）**：用 AlphaEvolve 式自主进化搜索冻结 VLM 的图表问答推理程序（精确匹配率 16.6%→41.3%、快 3.8×），是 EvoX 所改进的搜索层在多模态感知下游的直接应用面；以 EvoX 的自适应策略替换其固定搜索策略，是该范式向音视频理解负载迁移的自然实验。
