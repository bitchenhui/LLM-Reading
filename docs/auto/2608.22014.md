# DynaContext: Self-Improving Dynamic Contextualization of Optimized Prompts for Heterogeneous Parameter Extraction

> Joe Yu, Shibin Thomas Stanley Paul, Sven Mayer. *arXiv:2608.22014v1 (2026-08-22)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

自动提示/技能优化这条线——GEPA 的反思式 prompt 演化、DSPy 及程序级优化（Opsahl-Ong et al.）对指令与示例的联合调参、SkillOpt 从带分执行轨迹学习可复用过程技能——已经显著提升了 LLM 流水线可靠性，但它们共享一个隐含假设：**优化产物是静态文本，对所有输入原样复用，直到下一轮优化周期**。当输入共享同一输出结构时这成立；在 schema 异构的结构化预测上失效：目标 schema、单位约束、相关示例、可用证据都逐实例变化。

论文选的任务载体是电子元器件非结构化参数抽取（UPE）。供应商/报价数据以紧凑自由文本行到达（如 `RES-SM,1.00K,1/10W,0.5%,0402`），参数字段隐式；目标 schema 类别条件化（电容 schema 优先电容/耐压/介质/容差/封装，MOSFET schema 优先 Vds/导通电阻/电流/热限）；值必须数值-单位分离、每个非空字段带溯源、无支持字段强制弃权——输出直接喂下游成本模型与工程决策。且每个输入处于不同证据状态：有的行解析到内部精确记录，有的到外部已验证规格或官方数据手册，有的只能从描述推断。

相对属性-值抽取既有线（OpenTag、MAVE、Extract-GPT/WDC-PAVE 的 few-shot 基线），UPE 有三个驱动设计的差异：schema 类别条件而非扁平属性集；值-单位分离加单位类归一化；逐字段溯源加弃权（目录是受治理的，这正是弃权可检验的前提）。相对工业零件规格的多 LLM 检索增强集成与 EDA 数据手册流水线，DynaContext 以“单一优化核心逐实例条件化”替代模型共识，以验证过的溯源作为持久化门槛。

动机内核是两个解耦：把“离线优化什么”（可复用抽取核心、judge prompt）与“推理时组装什么”（schema、证据、未解析字段、示例）解耦；把“自我改进”与“改进的持久化”用验证门控解耦——只有人工核实的纠错才能进入记忆，防止 judge 或模型自评污染持久状态。

定位说明：本文属 LLM 结构化抽取/提示优化方向（非音视频核心类），但其处理对象是被动元器件参数——音视频硬件 BOM 的物理底座，其“schema 异构 + 单位归一 + 溯源 + 弃权”契约与音视频设备规格/媒体元数据抽取高度同构，迁移分析见第 6 节。

## 2. 方法总览

**形式化**：输入 xi = (di, mi, ui, ci, Ei)（描述、可选 MPN、可选厂商、可选类别提示、当前项已有证据）；输出闭世界结构化记录 yi = {解析类别 ĉi、所选 schema S、归一化 MPN、字段值对象集 {zif}、未解析字段集 Mi、校验/复核状态 qi、路由与来源元数据 Σi}。非空参数对象 zif = {value, unit, source}：量化字段分离数值与单位，类别字段用规范文本，所有发出值带溯源；schema 外字段即使出现在示例或邻类中也拒绝，schema 内无充分当前项支持的字段保持 null。

**证据模型**：证据限于当前组件的信息，四源——可信内部精确 MPN 记录、外部 API 结构化规格、PDF Web Agent 获取的官方数据手册证据、原始描述；按路由条件启用，而非穷举网页搜索。关键规则：从验证记忆检索到的示例**不属于 Ei**——只提供类别化解读、值-单位格式、空值行为的提示上下文，不能为当前组件的非空参数值提供正当性。源融合因此是当前项证据上的字段级归因问题，人工纠正是唯一能覆盖更高优先级来源的机制。

**框架三件套**： 确定性图控制器 + 局部 ReAct 式工具子流做证据获取与回退推理，路由策略确定、每条路由固定其示例预算与回退动作——逐实例适配被限制在显式安全约束内； 分支感知的推理时提示组装：Pt(xi) = A*(ĉi,t) ⊕ S ⊕ Mi ⊕ φ(Ei) ⊕ di ⊕ Rk(xi, Mt)，核心稳定、上下文逐项变化（部署配置中的核心为 SkillOpt，GEPA 为替代离线后端）； 三层输出门控（确定性校验 → GEPA 优化 judge → 人工复核）加验证门控自改进：记忆只收人工确认项，judge prompt 的 GEPA 再优化离线进行。输出以 Pydantic schema 约束字段/类型/单位类/空值行为，确定性后处理做单位标准化与 JSON 序列化。

## 3. 关键设计

### 3.1 MPN 锚定的确定性路由

预处理归一化描述并抽取规范 MPN m̂i，随后顺序判定三路由：

- **internal**（存在可信精确 MPN 记录）：可信记录整条复用，Mi = ∅，抽取 LLM 根本不被调用；
- **external**（外部 API 或官方数据手册验证 m̂i）：已验证类别选定规格模板，已取值不可再生或覆盖；Mi 为外部证据缺失字段，k = 0，LLM 只能从当前描述补缺；
- **fallback**（两者皆无）：类别抽取代理在组件库检索相似项并用 Jaro–Winkler 对 taxonomy 匹配出三级类别路径，据此选模板；Mi = S（全 schema 抽取），k > 0 检索类别匹配示例。

两条 MPN 锚定路由不做相似组件检索、taxonomy 匹配与示例检索——路由隔离是设计要点：证据可信度决定上下文组装复杂度。相似项只支持类别判定与上下文选择，其参数值不构成当前组件证据，是非证据性规则在类别层面的落实。

### 3.2 路由特定的源融合

internal：可信记录原样保留。external：外部 API 值 > 官方数据手册值 > LLM 对仍缺字段的补全。fallback：schema 约束下的描述抽取。逐字段保留最高优先级可用候选；候选必须 schema 合法、单位兼容、可归因当前项；低优先级候选只填 null 字段；不相容的非空值记为冲突送审。

### 3.3 分支感知提示组装与示例检索

组装公式见上节，三路由通过 (Mi, k) 差异化参数化 LLM 的自由度：internal 不实例化任何抽取 prompt，external 零示例只补缺，fallback 全 schema 加类别匹配示例。示例检索仅 fallback 路由查询 Mt，用 embedding 相似、BM25 重叠或去重 hybrid 排序取 top-k。示例来自运营中累积的人工核实纠错构成的验证记忆，由与评测不相交的记录集构建——评测记录不可能检索到自身作示例（防泄漏口径）。

### 3.4 三层验证与自改进门控

**确定性 guardrails** 在预处理、规格模板选择、最终后处理三处执行，拒绝：schema 外字段、畸形值-单位对、不兼容单位、非法 MPN 归一化、类别-schema 失配、无支持的非空值、缺溯源；组装后对生成候选再查一遍。

**GEPA 优化 judge**：输入 final JSON、所选 schema、路由、来源摘要、校验报告、未解析字段列表；检查类别-MPN 一致性、参数合理性、关键字段缺失、弱/冲突支持。判定只能是 approve / reject / request review，**不能增改参数值**——judge 是分诊门而非真值源。人工复核触发条件：校验失败、judge 标记、重要字段未解析、来源冲突、结果仅依赖弱 fallback 证据。

**Trace 驱动的自改进**：每项产生含路由、schema、证据、所用示例、输出、冲突、judge 判定、人工决策的 trace。仅 accepted 的人工决策更新记忆：Mt+1 = Mt ∪ {(xi, yhuman_i, tracei) : qi = accepted}；被拒案例与 judge-only 批准不晋升。已接受/纠正案例还可更新 MPN-类别库。GEPA 用接受/纠正 trace、judge 错误与人工决策在评测轮之间修订 judge prompt（离线步，非逐项判分）；工件更新晋升条件是：held-out judge 精度提升或减少触发复核的失败，**且不增加对无支持输出的误批准**。与 schema-grounded 记忆系统（Petrov et al.）在写路径上验证记录的做法不同，DynaContext 逐项验证输出并把记忆严格定位为非证据性示例；与从纠错信号做 RL 的线不同，改进落在工件与记忆而非模型权重。工程上这是把自我改进限制在“可审计 trace + 人审锚点”上，而非模型自评循环。

### 3.5 基准与评测口径

异构基准：133 条生产级报价记录、13 个 level-3 类别、131 条有 schema 支持字段、共 850 条非空 gold 字段-值事实，由电子成本工程师（即下游消费者）标注。单类基准：142 条陶瓷电容记录、固定 7 参数 schema，隔离“类别已知后局部上下文还能提多少”。两基准数据子集与聚合层级不同，数值不可直接互比：单类报 accuracy（固定 schema 使记录级/字段级可比），异构报字段级 F1（对匹配的预测字段-值事实算 P/R，兼顾漏检与幻觉字段）。重要口径：两项研究均固定 gold 类别与 schema，只有抽取核心与检索配置变化——**报告数字度量抽取段质量，不含路由/类别解析误差**；测量运行无人工介入，人工努力只通过既有记忆进入。

## 4. 实验结果

模型口径：同一组八个部署（GPT-3.5 Turbo、GPT-4o、GPT-4o mini、GPT-4.1 mini、GPT-5.4、GPT-5.4 mini、GPT-5.5、DeepSeek-V4-Pro）跑全部条件，配对设计；模型是 sweep 因素而非比较方法。区间为八个 per-model 分数上的 95% t-区间，记录级区间用 2000 次抽样的 cluster bootstrap；成本与时长由 logged token 数与记录的单价估算。

**单类（陶瓷电容，accuracy%，八部署均值）**。三核心 × {None, Vector, BM25, Hybrid} 全交叉：

| 核心, 检索 | 均值 [95% CI] | 最佳单次 |
|---|---|---|
| Base Prompt, none | 86.64 [82.6, 90.7] | 90.14 |
| Base Prompt, best | 94.83 [92.5, 97.1] | 98.79 |
| GEPA, none | 95.56 [95.0, 96.1] | 96.68 |
| GEPA, best | 98.49 [98.0, 99.0] | 99.50 |
| SkillOpt, none | 96.93 [96.4, 97.4] | 97.89 |
| SkillOpt, best | 98.59 [98.3, 98.9] | 99.20 |

"best" 为该核心最强检索策略（Hybrid；GEPA 例外为 Vector）。全 sweep 上，检索上下文把无检索条件均值从 93.05% 提至 97.09%；最强单点 99.50%（DeepSeek-V4-Pro + GEPA + Vector）；GPT-5.4 mini 用 GEPA+BM25 达 99.30%、SkillOpt+Hybrid 达 99.20%——类别固定时，优化核心加局部示例可替代大模型容量。

**异构（850 gold 事实，字段级 F1%，k = 5）**。GEPA 仅进单类研究；此处为核心 × 示例开关的两因子设计：

| 条件 | 均值 [95% CI] | 最佳单次 |
|---|---|---|
| Base prompt, none | 51.76 [48.9, 54.7] | 55.81 |
| Base prompt, k5 | 59.22 [57.1, 61.4] | 63.33 |
| SkillOpt, none | 66.89 [61.7, 72.1] | 73.86 |
| SkillOpt, k5 | 70.98 [65.9, 76.1] | 77.71 |
| Static-10（参考） | 53.96 [49.9, 58.0] | 61.66 |

Static-10 为本研究前的生产管线：无优化核心、无检索，对每条记录前置同样 10 条手挑示例；与四个交叉条件 prompt 不同，仅作参考不入消融。摘要口径的阶梯：无优化无示例对照 51.8 → 动态示例单独 59.2 → 优化核心单独 66.9 → 联合 71.0。固定模型下，全配置相对部署静态管线平均 +17.32 F1，代价是成本 1.05–1.93 倍（均值 1.48 倍）——多花的 token 买的是精度不是省钱。（细读注：表内 SkillOpt k5 与 Static-10 均值差为 17.02，正文 17.32 为逐部署配对平均口径，论文未展开其构成。）

**k 扫描**（Hybrid，k ∈ {1,3,5,10}）：k3 或 k5 对八个模型中六个最优；最强单点为 DeepSeek-V4-Pro + SkillOpt 核心 + 三条 Hybrid 示例，77.93 F1。

**成本-质量**（模型随配置变化，比较的是部署而非方法）：

| 配置 | F1 | 成本($) | 时间 |
|---|---|---|---|
| GPT-5.5, k5 | 75.71 | 2.955 | 768.9 |
| DeepSeek-V4-Pro, k3 | 77.93 | 0.498 | 422.3 |
| GPT-5.4 mini, k5 | 77.42 | 0.203 | 174.5 |

把预算花在更大模型上是最差替代：GPT-5.5 单次成本约为 GPT-5.4 mini 的 15 倍仍低 1.72 F1；全局最优 77.93 为 GPT-5.4 mini 的 2.45 倍成本只换 0.51 F1。同样的钱买 schema 与示例，优于让大模型隐式恢复这些上下文。

## 5. 消融要点

- **两因子分解（异构，配对口径）**：相对无示例 base（51.76），动态示例单独 +7.47 [6.42, 8.51]，优化核心单独 +15.14 [10.66, 19.61]，联合 +19.22 [14.18, 24.27]；每个效应在全部八个部署上为正（Wilcoxon signed-rank, p = 0.0039）。贡献比约 1:2。
- **次可加性**：示例在 base 上值 7.47，叠加在优化核心上只值 4.09 [2.18, 5.99]——两机制供应的是关于 schema、格式、空值行为的部分重叠信息，而非独立增益。论文强调配对区间才是有效检验：部署间差异大于部署内条件间差异，边际区间重叠而每个配对效应显著。
- **动态 vs 静态示例同条件对照**：Static-10（十条固定示例）53.96，低于 base + k5 的 59.22——动态检索的增益不能由“多几条示例”解释。
- **检索策略**：单类 sweep 中各核心 best 基本为 Hybrid（GEPA 例外，Vector 最佳）；异构实验不单比 Vector/BM25，理由是两信号各自不完整——词面重叠管 MPN 片段/封装/单位，语义相似管等价表述——转而扫 k 量级（过多示例引入邻族干扰字段，过少盖不住活动 schema）。
- **两 setting 差距的机理归因**：固定 schema 下示例只提供局部格式引导且同族示例强化目标 schema；异构下示例还须帮助解析活动族属，邻族相似示例会提示错误字段或单位约定——这解释了动态上下文提升异构 F1 但到不了固定 schema 天花板（论文明确两 setting 数值不可直接比，此处为量级性归因）。
- **失败标签体系**（字段级、指向应改进的部件）：类别/schema/示例失配错误 → 抽取器与检索策略；MPN/值/单位/数据手册/外部 API 错误 → 证据获取与归一化；judge 误批/误拒 → GEPA judge 调优；复核纠正标签 → 应晋升入验证记忆的人工反馈。

## 6. 贡献与启示

论文自述三点贡献：UPE 形式化为 schema 锚定、溯源保持、强制弃权的结构化预测，并给出两个成本工程师标注基准；DynaContext 框架（离线优化核心 + 推理时上下文化 + 验证门控自改进）；八模型两因子消融把异构增益归因到动态示例与优化核心（约 1:2、次可加），全配置相对生产管线 +17.32 F1，且小模型以零头成本追平最强单点。

对提示优化社区的启示：静态优化产物的收益在 schema 异构场景被系统性低估；“核心稳定 + 上下文逐实例组装”是与“提高优化频率”正交的另一维度；自我改进必须与持久化解耦——judge 只做分诊、人审做锚点、晋升有 held-out 门槛且不许增加误批准，这套 gating 对任何要在生产里跑的记忆型 agent 都可迁移。

局限（论文自陈，需认真对待）：基准小且来自单一工业语料；异构集不均衡——陶瓷电容与片式电阻占 gold 事实 74%，13 类中 5 类各不足 10 条，稀有类估计噪声大、聚合被两族主导；未在 WDC-PAVE 等公开基准评测；Jaro–Winkler 阈值与 hybrid 检索的静态 interleave 等启发式固定，未做敏感性分析；依赖专有外部 API 与数据手册检索（实验用带查询日期的缓存响应），多近邻变体的族表是数据手册抽取最不可靠处；judge 校准随输入分布漂移，稀有类别需保守送审；记忆跨复核轮次的改进未评测；底层数据保密不公开。

**音视频上下游关联**（笔记作者视角的迁移分析，非论文结论）：

- 上游：被动元件（MLCC、片阻、MOSFET、连接器）参数是音视频硬件——相机、编解码/流媒体设备、显示与音频功放——BOM 成本核算的直接输入。带溯源与弃权的字段级抽取直接服务 AV 硬件成本工程与选型：一条无支持的幻觉参数进入成本模型或工程决策的代价，正是本文 mandatory abstention + provenance 契约要消除的。
- 方法迁移：AV 领域存在同构任务——设备规格书/媒体资产元数据抽取同样面对类别条件 schema（相机参数表 vs 编码器参数表 vs 音频接口参数表）与单位类归一（Hz/kHz、Mb/s 与 Mbps、dB 容差、位深/采样位宽）。“内部库精确型号命中 → 外部 API → 官方 datasheet → 描述回退”的路由化证据栈可直接套用于设备规格聚合与器件替代选型；验证门控记忆对生产级媒体元数据管线同样关键（错误字段会污染下游推荐、合规与质检）。
- 成本结论的意义：小模型加正确 schema/示例优于大模型隐式恢复上下文，对大规模 AV 元数据/遥测批量结构化（如历史素材入库）是直接的架构与采购依据——上下文工程比模型容量更稀缺、更便宜。

## 7. 与其他论文的联系

- **paper:arxiv:2611.14326（FGSE，证伪门控自演化）**：机制上最接近。两者都在回答“经验何时才允许写入 agent 持久记忆”：FGSE 将教训作为可证伪假设经三类探针验证后写入；DynaContext 用确定性校验 + GEPA judge + 人工复核三重门，并显式规定 judge-only 批准不晋升。可视为同一安全目标下“探针/统计验证”与“人审锚点”两条实现路径的对照；DynaContext 更保守，但人力上限更低。
- **paper:arxiv:2611.10787（TRUST，带统计保证的可信递归自改进）**：TRUST 用在线多重假设检验控制递归自改进的错误演进率；DynaContext 对 judge prompt 更新的晋升条件（held-out 精度提升或减少触发复核的失败，且不增加误批准）是同一“防劣化更新”目标的非形式化实现。给 DynaContext 的晋升门槛配上 TRUST 式检验是自然的组合方向。
- **paper:arxiv:2611.12109（SkillDuet，模型与技能共演化）**：SkillDuet 以响应反馈让 LLM 参数更新与外部技能库协同演化；DynaContext 明确冻结模型权重，改进只落在离线工件（抽取核心、judge prompt）与示例记忆上。两者构成“自改进落在权重还是上下文/记忆”的设计对照，分别适配不同的更新成本与审计约束。
