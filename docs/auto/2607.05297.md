# MetaSkill-Evolve: Recursive Self-Improvement of LLM Agents via Two-Timescale Meta-Skill Evolution

## 1. 背景与动机

LLM agent 处理长程开放任务时开箱成功率低，主流补救手段是为其挂载 skill——可编辑的 Markdown 过程性知识规范，在主流 agent 框架中已是可移植的文件系统工件（Voyager、SkillWeaver 一脉）。手工固定的 skill 很少最优，也无法预适配任务分布的多样性；EvoSkill、GEPA、SkillWeaver 等自改进系统以 analyze→propose→evolve 流水线在失败轨迹后改写 skill 文件，逐步提升能力。

论文指出的核心缺口是：这类系统只演化“agent 做什么”（任务技能 s），不演化“agent 如何改进”（改进算子）。以 Good(1965) 超智能机与 Schmidhuber(2006) Gödel 机的递归自改进（RSI）术语来说，它们是 self-improving 但未达 recursively self-improving：失败如何诊断、提案如何生成、搜索力度如何分配、跨分支经验是否复用、已批准编辑如何落盘，全部一次性硬编码并在整个运行期对所有分支共享。失效模式很具体：分支无法改进自己的诊断方式——误读表格与算术错误被同一套流程处理；当该流程给出错误修复时，环内没有任何机制能修正它。

动机的形式化：演化式技能搜索由两个量支配。其一是当前技能效用 U(s)，即当前 skill 在验证批上的得分；其二是元生产率 P(m|s)，即分支在当前改进策略 m 下产出更强后代的速率。二者不等价——高分 skill 可能处在元策略疲弱的分支，中分 skill 可能处在产出持续上升的分支，后者才是更值得延展的谱系。只优化 U(s) 完全忽略第二个量；作者假设，这正是固定元层演化在“重复失败共享同一元流程无法修正的诊断风格”时停滞的主因。

由此提出的研究问题：改进流程本身能否作为一等公民对象、与其产出的任务技能一起、用同一套 agentic 流水线被演化？相对 LLM 时代的 RSI 实例——STOP（递归改写代码改进脚手架）、Promptbreeder（prompt 与 mutation-prompt 共演化）、Darwin Gödel Machine（改写自身设计）——这些在单一全局策略下对代码或 prompt 递归；本文的递归对象是技能文件，改进策略是分支局部而非全局的，递归深度有界（一层），且不引入额外模型或目标函数。

## 2. 方法总览

MetaSkill-Evolve 是双时间尺度演化框架。每个分支携带状态 b=(s, m, h)：任务技能 s、分支局部元技能 m=(ψ, σ, α, π, ε)、迭代历史 h。五个元技能分量分别参数化改进流水线的五个专家 agent：ψ→Analyzer（诊断）、σ→Retriever（跨分支共享）、α→Allocator（每步子代预算）、π→Proposer（编辑提案）、ε→Evolver（编辑落盘与校验）。快环每次迭代更新任务技能；慢环每 H 次迭代（默认 H=2）更新元技能，驱动信号是最近 H 个后代的改进幅度，即“当前改进策略是否仍多产”的运行时度量。

递归闭合的关键在于不新增任何架构组件：m 的每个分量本身是与任务技能同格式的 SKILL.md 文件，因此改写 s 的同一套五 agent 流水线可递归作用于 m 自身——自改进环在执行它的算子上闭合，形成有界的一层递归，无需新模型、无需新目标函数。

全部搜索历史持久化为 SQLite 中的 DAG G=(V,E)：节点 v 存储 (s_v, m_v, U_v, ΔU_v, ϕ_v) 外加分支路径与选择计数；边分两类——谱系边（父→子）与灵感边（σ 检索到的跨分支节点），均由旧指向新，构造上无环。持久化 DAG（而非定长 beam）允许 revisit 被降权的谱系、支持跨分支检索、并为任意最终节点保留完整溯源。子代仅在严格改进父代（ΔU>0）时进入档案库（可部署状态池，兼未来父代候选集）；中性/回退子代仍持久化供 σ 检索为灵感。每次迭代从档案库刷新前沿（top-K_F 节点，K_F=3），按 v* = argmax(η1·U_v + η2·P̂_v + η3·N_v) 选下一父代，N_v = 1/(1+times_selected)。

状态权威设计：运行时在展开任何分支前，先将其任务/元技能快照恢复到磁盘——分支状态由 SQLite 记录定义而非工作区残留文件，各分支从记录快照出发、隔离评估，杜绝谱系间泄漏。

论文自述四点贡献：双时间尺度框架（P(m|s) 作为慢目标与 U(s) 并列）；五 agent 流水线（在 analyze→propose→evolve 之上补两个带类型阶段：跨分支 Retriever 与自适应预算 Allocator）；类型化元技能 m=(ψ,σ,α,π,ε) 由同一流水线演化（有界一层递归，无新模型无新目标）；元感知前沿选择（效用/元生产率/新颖度三分量）。

## 3. 关键设计

### 3.1 递归的使能器：工件表示统一

m 的五分量各被恰好一个专家 agent 消费：ψ 将失败映射为标签 ϕ 与自由形式分析 a；σ 选取匹配 ϕ 的同分支+跨分支灵感；α 设定子代预算 K∈[1, K_max]；π 以最差样例、分析、灵感 (f, a, I) 为条件发出编辑 δ；ε 将 δ 写入磁盘并校验。由于每个元技能文件与任务技能同表示（如 skills/meta-analyzer/SKILL.md 与任务技能的 SKILL.md 同构），流水线无需任何修改即可细化 m。每次节点创建时五个文件快照入图，分支被选中展开时先恢复其元快照，保证每条谱系应用自己的局部改进策略；论文给出的分化示例是：一条谱系学到针对表格抽取失败的激进编辑策略，另一条发展出针对算术推理失败的保守增量编辑。谱系间传播的唯一通道是元层检索（σ 按元失败标签 ϕ_m 匹配跨分支谱系），不存在共享全局状态——“逃生策略”由此在谱系间传播而不污染各自策略。

### 3.2 前沿打分：每个贪心失效模式配一个矫正项

U_v（利用项）防止在弱父代上追逐易变的增益估计；P̂_v（轨迹质量项，= 子代 ΔU 均值，无子节点取 0）将搜索努力从已平台化的高分节点重定向到仍在产出有效后代的节点，同时充当保持“改进策略多样性”的质量-多样性描述子；N_v（访问冷却项）意味着被选 k 次的节点必须比未选兄弟高出 η3·k/(k+1) 才会被再次选中，防止预算垄断。置零任一 η_i 暴露对应失效模式：η2=0 时前沿锁死在停滞的高效用节点，η3=0 时搜索塌缩到单一谱系，η1=0 时把噪声性的单子代增益当作父代质量。重要的是不做谱系结构过滤——多样性是打分函数的性质而非结构约束。默认 η=(1.0, 0.5, 0.25)。

### 3.3 归档准入与失败信息复用

ΔU>0 的严格准入把部署资格与父代资格绑定在被验证的改进上；被拒编辑不丢弃——中性/失败子代仍在图中、进入 σ 的灵感池。失败信息被复用于后续提案但不获得繁殖权，是“利用负样本信号”与“避免坏基因扩散”之间的折中。

### 3.4 快环机理

选中前沿父代后：恢复快照→在训练批评估收集失败→取最差样例为诊断目标——刻意的高信号选择，又以“编辑按验证集增益 ΔU 而非该单例表现来评判”对冲离群风险。五 agent 依次为：Analyzer 产出结构化根因、≤15 词失败标签 ϕ 与目标技能文件，采用三层恢复链（final_answer 主解析→逐步输出扫描→受限 response_format 修复调用），target_skill 未显式给出时从 relevant_sections 自动推导（提升小模型鲁棒性）；标签词汇表本身由 ψ 维护、由慢环修订。Retriever 按标签相似度过采 3 倍（3L_same/3L_cross，默认 L_same=3、L_cross=2）再 LLM 重排收窄——广度/深度平衡本身是被学对象。Allocator 依据分支近期 ΔU 与分析选 K∈[1, K_max=3]：停滞（P̂≈0）后加宽、多产编辑后收缩。Proposer 对 K 个子代各发一编辑，K>1 时多样性提示引导第 k 个提案采取不同干预角度以减少近重复子代。Evolver 经 skill_tools 将 δ 翻译为文件写入，以改写前后哈希校验标记未实际改动目标文件的编辑，每次 apply 后刷新技能注册表。每个子代在验证批上评估得 ΔU_k；每 H 次迭代触发一次慢环，K 个子代携带刷新后的元技能提交入图并重同步前沿。

### 3.5 慢环机理

若每次迭代都更新 m，元技能会暴露在驱动任务技能演化的同一种单例噪声下；慢环每 H 次快迭代触发一次并在窗口上聚合，以反应性换稳定性。驱动信号是经验元生产率 P̂ = 最近 H 个后代 ΔU 的均值。作者将 P̂ 连同窗口内的标签、诊断、结果折叠成合成元失败轨迹 f_m——把改进历史重塑成一个“看起来像失败训练样例”的对象，使同一份 Analyzer 提示词可服务两个时间尺度（设计经济性）。随后同一五 agent 流水线重跑，仅把目标对象从任务技能文件切换为元技能文件；Analyzer 点名 {ψ,σ,α,π,ε} 中被牵连最深的单个分量——该诊断固定引导检索的失败标签 ϕ_m，但不收窄编辑范围。慢环与普通快环的三点区别：(i) 受限 Analyzer——空诊断或指向任务技能的诊断触发对五个分量名的轮转回退，既不因不可用目标中止，也不静默退化为冗余快环；(ii) 整体 m 重写——每轮 Proposer 顺序对五个文件提案、Evolver 并行执行（每文件一 worker），保持跨分量一致性（如假设更细标签词汇表的 π 编辑与配套 ψ 编辑共同落地）；(iii) 累积子代——第 k+1 个子代读取第 k 个子代写完的文件而非父代文件，移动目标驱动增量精修，而非 K_m 个相互独立、效果平均回退到父代的覆盖。

### 3.6 工程实现要点

技能目录渐进披露：agent 先收紧凑目录（技能名+单行摘要），仅对判定相关者载入完整 SKILL.md，资源文件再按需载入——在保满表达力下控制上下文长度。默认超参：η=(1.0, 0.5, 0.25)、H=2、迭代预算 5 次快迭代（H=2 下两次元更新）、K 初始 2 / K_max=3、前沿 K_F=3、前沿连续 5 次无改进早停；类别感知轮转训练每批 6 类×每类 3 样本；跨分支检索概率 p_cross=0.2；评估并发默认 16、QA 基准在 vLLM 后端升至 128（仅影响吞吐不影响精度）。

## 4. 实验结果

口径：三个互补基准——OfficeQA（企业级端到端接地文档推理）、SealQA（搜索增强推理）、ALFWorld（文本-具身交互任务，报聚合任务成功率）。各基准按类别列分层抽样切三个不相交分区：train（失败挖掘）、val（子代打分与前沿选择）、test（演化全程不可见），最终以独立 benchmark-mode 通道报告 test 准确率。全部五个流水线 agent 共享同一冻结 Gemma-4 31B 骨干、无任何微调——所有增益只能归因于演化出的技能与元技能。四配置同骨干：No-Skill（裸骨干、关闭反思）、Static（手工初始技能全程固定）、Single-Level（快环+冻结慢环：K_max=1、无跨分支共享、无元技能更新）、MetaSkill-Evolve（完整双时间尺度）。

主结果（held-out test 准确率 %）：

| 方法 | OfficeQA | SealQA | ALFWorld |
|---|---|---|---|
| No-Skill | 31.78 | 29.17 | 92.31 |
| Static skill | 36.09 | 29.41 | 90.38 |
| Single-Level | 48.94 | 37.21 | 92.31 |
| MetaSkill-Evolve | 55.32 | 45.26 | 94.23 |
| Δ vs. No-Skill | +23.54 | +16.09 | +1.92 |

按层分解：OfficeQA 上静态技能 +4.31、单层演化再 +12.85、慢环再 +6.38；SealQA 上静态技能近中性（+0.24）、单层 +7.80、慢环 +8.05（慢环贡献超过端到端总增益的一半）。两个 QA 基准上 No-Skill→Static→Single-Level→Ours 单调递增，说明“加技能、演化技能、再演化演化它的流程”三层设计各自独立兑现收益。ALFWorld 是相反体制：骨干已解 92.31%、近天花板，静态技能 −1.93，单层演化仅回到 No-Skill 水平（92.31%），端到端 +1.92 全部由慢环单独供给（至 94.23%）——任务技能演化饱和后，元技能自适应仍是起作用的成分。

数据划分敏感性（附录 G：各运行 test 集取种子化分层切分的交集后统一重评、不重跑，子集更小故绝对值与主表略异）：训练占比扫描（val=0.10，dual-evolve，5 外层迭代）中 ALFWorld 单调上升 87.74/88.68/90.57（tr=0.05/0.10/0.15），SealQA（45.98/43.68/48.28）与 OfficeQA（44.86/42.99/48.25）在噪声内持平（n≈87~107 上 ±1~4 题）——更多训练数据仅带来边际收益。ALFWorld 验证占比 0.10→0.25 在三个训练比下分别 +2.0/+4.3/+2.5 分：机制是高基线基准上小验证集含失败太少，Analyzer 几乎看不到失败轨迹，诊断→提案→选择环无信号可作用、慢环退化为 no-op。工程含义明确：饱和任务上，验证切分的失败密度（而非数据总量）决定演化环是否启动。另据附录 D 的定性扫描，中等强度跨分支检索在两个 QA 基准上一致有益，过度激进则因引入结构不相似分支的无关灵感而产生噪声。

## 6. 贡献与启示

方法学层面，本文的可复用要点有三。其一，递归的使能器不是新架构而是表示统一：让算子的参数与操作数同为 SKILL.md 工件，改进环即可零成本反身作用于自身——这是 Gödel 机式完全 RSI（需改进性证明）与固定元层演化之间的可落地折中。其二，P(m|s) 把“我改进得好不好”从“我表现好不好”中显式分离，并以前沿打分项（而非结构约束）实现轻量质量-多样性搜索。其三，SQLite DAG 作为状态权威 + 快照恢复的分支隔离 + 失败子代保留为灵感（不获繁殖权），构成可复现的工程模式。

论文自列局限：仅三个精选基准，未测开放式、反馈更噪的真实长程任务；五 agent 流水线自身的角色与接线固定——递归发生在工件层而非架构层；元更新以固定视界 H 触发。从消融还可推断部署敏感性：H 需匹配任务技能漂移速度（OfficeQA 案例即证）；验证集失败密度不足会使系统静默 no-op——这是实际部署中最隐蔽的失效模式，因为流程照常运转而毫无学习信号。

与音视频技术的上下游关联（论文本身无音视频内容，以下为方法学迁移视角，非其实验结论）：上游，该框架消费任意冻结 LLM 的工具编排场景；音视频工程中大量过程性知识天然是 Markdown 工艺/运维工件——转码配方选择、直播事故处置 runbook、画质抽检清单、编码器与 ABR 调参手册——皆可作为任务技能文件被该流水线演化。双时间尺度分离对应“单流/单内容快适配 vs 控制面慢策略演化”的常见架构分层；带谱系边/灵感边的持久 DAG 对应媒体处理多级管线中的溯源与回归定位需求；“验证集必须暴露足够失败”的结论直接警示：在骨干 agent 对常规 case 已近饱和的成熟音视频管线上，小验证预算会饿死演化环，需以故障注入或难例挖掘扩充验证集（类比 ALFWorld 扩 val 的 +2.0~+4.3 分效应）。下游，演化产物是可移植技能文件，可跨部署点共享，跨分支检索机制对应跨团队 playbook 复用。

## 7. 与其他论文的联系

- **SkillDuet（arXiv:2611.12109）**：同以技能库为演化对象、由执行/响应反馈驱动。SkillDuet 让反馈同时更新 LLM 参数与外部技能库；本文则以全五 agent 共享单一冻结骨干（Gemma-4 31B、无微调）作为对照设计，把增益严格归因到文件层演化——两文分别占据技能级递归自改进的“权重轴”与“文件轴”，互为消融对照。
- **RSI-Opt（arXiv:2610.32026）**：同样把“改进策略本身”提升为被演化对象。RSI-Opt 的元智能体跨训练运行演化优化器策略与代码库；本文在 agent 技能迭代层演化类型化的 m=(ψ,σ,α,π,ε)，并以显式元生产率 P(m|s) 进入前沿选择——同一“改进改进者”原理在训练环侧与 agent 技能环侧的两个实例化。
- **TGR-EvoDAG（arXiv:2610.32326）**：结构同源。两者都以持久 DAG 承载演化史、支持跨分支复用与被降权谱系的 revisit（TGR-EvoDAG 演化腾讯生成式推荐完整管线并取得在线 CTR 相对 +0.40%；本文演化技能文件并以 SQLite 持久化）——共同佐证 DAG 持久化优于定长 beam 的 agent 工件搜索。
- **TRUST（arXiv:2611.10787）**：安全性互补。本文的回退防护仅有严格归档准入（ΔU>0）与 Evolver 哈希校验；TRUST 用在线多重假设检验为 RSI 智能体控制错误进化率并提供统计保证——是元技能演化部署到高代价场景时的自然组合点。
- **WeightLoop（arXiv:2611.07319）**：目标相同（免重训练的反复自改进）、编辑位置不同——WeightLoop 在权重空间写有界参数编辑程序，本文在支架的文件空间重写 Markdown 技能；二者划出冻结模型下权重空间与上下文/工件空间自改进的两条路线。
- **RSI-PDEbench（arXiv:2611.14949）、InfraRSI（arXiv:2611.11558）、LongCapHarness（arXiv:2611.10463）**：递归自改进范式在 PDE 求解、训练基础设施、长上下文推理等垂直域的平行实例；其共性（改进脚手架全局固定）正是本文针对性改进的对象——本文将改进策略做成分支局部、类型化、且在更慢时间尺度上共演化的对象。
