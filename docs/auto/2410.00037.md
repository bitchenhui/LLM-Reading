# Moshi: a speech-text foundation model for real-time dialogue

> Alexandre Défossez, Laurent Mazaré, Manu Orsini, Amélie Royer, Patrick Pérez, Hervé Jégou, Edouard Grave, Neil Zeghidour. *arXiv:2410.00037v2 (2024-09-17)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

主流语音对话系统是 VAD→ASR→文本 LLM→TTS 的级联管线，论文指出其三个结构性缺陷：其一，延迟沿组件累积至秒级，而自然对话应答时延约 230ms（Stivers 等，10 种语言平均）；其二，文本作为中间模态丢弃副语言信息（情绪、口音）与非语音声学事件；其三，轮次切分假设无法建模重叠语音（占口语时间 10–20%，Çetin & Shriberg 2006）、打断与 backchanneling（“嗯”“OK”类非打断插话）。同期方案各有残缺：Spectron/SpeechGPT 的 Chain-of-Modality 需先生成整段文本再合成语音，与实时不兼容；PSLM 并行生成文语 token 但文本不构成音频的条件前缀，且仍依赖 ASR；dGSLM 是全双工概念验证，但非在线、无文本 LLM 知识、只建模语义 token。

Moshi 的核心命题：把口语对话整体建模为 speech-to-speech 的多流音频 token 自回归生成，彻底去掉“说话人轮次”这一离散状态；同时用文本 LLM 骨干弥补纯音频语言模型事实知识与推理能力的缺失。最终系统是首个（论文口径）实时全双工口语大模型：理论延迟 160ms、实际 200ms，可维持 5 分钟上下文。

## 2. 方法总览

系统四个组件：**Helium**（7B 参数文本 LLM，2.1T 公开英文 token 预训练）；**Mimi**（12.5Hz、1.1kbps、语义-声学一体化、全因果神经编解码器）；**RQ-Transformer** 双层自回归结构（Temporal Transformer 即 Helium 架构，32 层/4096 维；Depth Transformer 6 层/1024 维/16 头）；**Inner Monologue**（时间对齐文本 token 作为音频 token 的逐帧前缀）。

联合建模的子序列共 K = 2Q+1 = 17 条（Q=8 码本）：Moshi 的文本流、Moshi 的语义 token + 7 条延迟声学 token、用户的语义 token + 7 条延迟声学 token。声学延迟 τ 预训练取 2（延迟模式 [0,2,2,…]）、微调取 1，配合 80ms 帧长，最终理论延迟 160ms。推理时用户流的模型预测被真实音频编码替换（teacher forcing），但训练仍建模用户流，使模型可离线自我推演完整对话用于评测。Moshi 静音不是固定 token 而是解码为近静默波形的“自然静音”，文本流同时填充 PAD，文本流因此成为控制接口（如强制采样 EPAD 可令模型立即开口）。

训练四阶段（超参见论文表 1）：单流音频预训练（700 万小时 Whisper large-v3 转写音频，1M 步、batch 16h、5 分钟序列；文本 token 30% 概率 mask，文本-音频延迟在 ±0.6s 随机；一半 batch 保持纯文本并使用独立优化器状态以防灾难遗忘，音频 batch 上文本 embedding/输出层学习率 ×0.75）；PyAnnote 说话人日志驱动的模拟双流后训练（100k 步，二值掩码拆分说话人/残差两路流）；Fisher 双通道电话对话真双流微调（2000 小时，8kHz 经 AudioSR 升采到 24kHz，10k 步，文本流只含主说话人转写）；指令微调（>2 万小时合成数据，30k 步）。损失函数上文本 token 与音频 token 整体等权，音频内部语义 token 权重 100、声学 1，PAD 在音频 batch 交叉熵中权重减半。

Helium 文本数据管线：12.5% 精选源（5 个年份的 Wikipedia dump、StackExchange、peS2o 等）+ 87.5% 过滤 CommonCrawl（10 个 crawl）；行级 FNV-1a 哈希 + bloom filter 精确去重、fastText 分类器对 ≥3 连续行的模糊去重、文档级语言 ID（阈值 0.85）、9 类 fastText 质量分类器按行打分并长度加权聚合过滤。

## 3. 关键设计

### 3.1 Mimi：低帧率、语义内化、全因果

结构上以 SoundStream/EnCodec 的 SeaNet 因果卷积自编码器为基线：4 个下采样块 stride (4,5,6,8) 加末层 stride-2 卷积，24kHz 波形 → 12.5Hz、512 维潜表示；量化瓶颈前后各插入一个 8 层因果 Transformer（250 帧=20s 感受野、RoPE、LayerScale 初始 0.01）。帧长与总步长均为 80ms，实现流式编解码。潜维 512 在 RVQ 前投影到 256、量化后投影回 512。训练用 AdamW（weight decay 5e-2 仅作用于 Transformer 参数）、lr 8e-4、EMA 0.99、batch 128×12s 窗口、4M 步。

**Split RVQ 语义蒸馏**是 Mimi 的核心创新。参照 SpeechTokenizer 将 WavLM（16kHz/50Hz/1024 维）经平均池化（stride 4、kernel 8，且作者强调必须**非因果**池化——仅用于构造训练目标，不破坏流式推理）降到 12.5Hz，经线性投影后与第一个量化层输出做余弦距离蒸馏。关键改动是不再把语义蒸进单一 RVQ 的首层（那会迫使首层在语音可懂度与重建质量间权衡：ABX 6.5% 但 MUSHRA 跌至 57.8），而是蒸进一个独立 plain VQ，与 7 层 RVQ 并联求和——两者共同服务重建但解除了“声学信息必须保留在语义量化器残差中”的约束，MUSHRA 回升至 64.0（ABX 8.1%）。

两个反直觉训练技巧：其一，50% 量化率——按序列以 50% 概率将**未量化**嵌入直接送入解码器（区别于 Kumar 等以全数量化嵌入替换的做法），客观指标显著改善且码率越低增益越大，主观评价不显著；其二，纯对抗训练——去掉多尺度 mel 重建损失只留特征匹配 + 多尺度 STFT 判别器损失，VisQOL 崩塌至 1.84，但 MUSHRA 从 58.8 升至 81.0，主观质量大幅提升。

### 3.2 RQ-Transformer 与声学延迟

8 码本 × 12.5Hz 意味着每秒 100 个 token、5 分钟音频为 30000 个时间步（若展平建模），而文本仅 3–4 token/s——帧率是自回归语音生成的延迟与算力第一约束。RQ-Transformer 将建模分解：Temporal Transformer（继承 Helium）对每个时间步输出上下文向量 z_s（步数恒为 S=12.5/秒）；首条子序列由专属线性层从 z_s 出 logits，其余 K−1 条由 Depth Transformer 以 (z_s, V_{s,1..k−1}) 为输入逐条预测。**Depthwise parametrization**：Depth 内每条子序列的线性层/投影/全连接独立参数（不同码本需要不同变换），参数开销可忽略但有效。

**声学延迟** τ：语义层不延迟，声学层延迟 τ 步。其机理是降低同一时间步各子序列间的条件互信息，使小容量 Depth Transformer 得以近似联合分布；延迟由 τ=2（240ms）降到 τ=1（160ms）时质量损失可控（见消融）。相比 MusicGen 的 [0,1,2,…,7]（640ms 延迟），这是把延迟压进实时区间的前提。

### 3.3 Inner Monologue

构造：Whisper 词级时间戳把转写文本对齐到 12.5Hz 帧率——词首帧放置该词的文本 token，随后 PAD 填充至下一词，词前插入 EPAD 标记词尾，把“结束当前词”与“选择下一词”拆为两步决策；英语会话中 padding 约占 65%。该设计将 AudioLM 的 semantic→acoustic 层级扩展为 text→semantic→acoustic：文本逐帧前缀为无条件音频生成提供语言学脚手架，且每步只增加 1 个 token（17 vs 16）的推理开销。

延迟符号可翻转任务语义：文本超前音频 2s 并 teacher-forcing 文本 → 流式 TTS（附 80ms 精度词对齐）；音频超前文本 2s 并 teacher-forcing 音频 → 流式 ASR。零样本 TTS 时允许模型自由采样 PAD/EPAD，一旦试图输出实词即强制注入下一词，并通过在线 padding 占比对 PAD logit 加偏置来控制语速。注意用户侧不做文本建模——实时转写用户流需外挂 ASR，违背端到端原则。

### 3.4 指令数据与用户流增强

指令数据由微调后的 Helium（Open Hermes + 真实对话转写）生成脚本：Wikipedia/StackExchange 上下文驱动的知识对话、语音风格指令（70 余种说话风格标签）、错词澄清、纠错（对错误前提说“不”）、安全拒答等，再用多流流式 TTS（单一演员音色）合成 >2 万小时；用户侧音色随机以增强鲁棒性。用户流增强模拟真实拾音条件：随机增益 −24~+15dB（50%）、DNS 噪声（30%，相对音量 −30~+6dB，交替插入至多 30s 静音段）、Moshi 流回声注入（缩放 [0, 0.2]、延迟 100–500ms）、混响类增强，回声+混响联合施加 30%。仅指令微调阶段使用一致音色即足以让推理时声纹稳定（见实验）。

### 3.5 压缩与安全（工程侧）

PTQ 设置：激活 BF16、线性层输入动态对称 8bit（AbsMax）；权重非对称（MinMax）分块量化；embedding、RMSNorm 与 Mimi 不量化；Depth Transformer 对量化鲁棒，单独保精度收益不显著。安全面：再生（regurgitation）分析显示未去重预训练模型在 3s 提示、temp 0 时 100% 复现训练集中最高频片段（temp 0.8 时 98.4%），训练集频次去重后降为 0，对话微调模型 1000 次生成 0 次；水印实验中 Audioseal 经 Mimi 编解码往返后检测分 0.0805，与无标记（0.0855）不可区分，而生成式水印受 token 非幂等性阻碍（语义层无攻击重建一致率约 0.80，40ms 时移后降至约 0.48–0.50，深层码本更不稳定）。

## 4. 实验结果

**Helium 文本基线**（2.1T token，对比训练量 <2.5T 的开源 7B）：MMLU 54.3、ARCe 79.6、NQ 23.3、TQA 59.9/72.6，持平或超过 MPT/Falcon/Llama 2/OLMo；对比训练算力约 3 倍的 Mistral（MMLU 62.5）与 Gemma（64.3）在 ARC、OBQA、NQ 上仍具竞争力，验证数据管线质量。

**编解码器对比**（MUSHRA：20 听众 × 30 样本 × 10s；ABX：LibriSpeech dev-clean、Libri-light 默认参数、within-speaker）：

| 模型 | 帧率 | 码率 | 因果 | ABX↓ | MUSHRA↑ |
|---|---|---|---|---|---|
| RVQGAN | 75Hz | 1.5kbps | 否 | – | 31.3 |
| SemantiCodec | 50Hz | 1.3kbps | 否 | 42.2% | 64.8 |
| SpeechTokenizer | 50Hz | 1.5/4.0kbps | – | 3.3% | 45.1 / 74.3 |
| Mimi（Encodec 式混合损失） | 12.5Hz | 1.1kbps | 是 | 8.1% | 58.8 |
| Mimi（纯对抗损失） | 12.5Hz | 1.1kbps | 是 | 8.7% | 81.0 |
| 参考信号 | – | – | – | – | 90.6 |

Mimi 以 4 倍低于 SemantiCodec 的帧率取得更高重建质量，且是表中唯一全因果方案。

**口语问答**（0-shot，TTS 合成题面，Moshi 用户流注入题面音频 + EPAD 触发即时应答）：

| 模型 | Web Q. | LlaMA Q. | Audio TriviaQA |
|---|---|---|---|
| SpeechGPT (7B) | 6.5 | 21.6 | 14.8 |
| Spectron (1B) | 6.1 | 22.9 | – |
| Moshi（无 Inner Monologue） | 9.2 | 21.0 | 7.3 |
| Moshi | 26.6 | 62.3 | 22.8 |
| Helium（纯文本上限） | 32.3 | 75.0 | 56.4 |

Inner Monologue 使三项准确率接近翻三倍。与 Helium 的差距（尤其 TriviaQA 22.8 vs 56.4）主要来自多句/特殊句式问题与口语化微调数据的句法覆盖不足。

**音频语言建模**（sWUGGY/sBLIMP/sTopic-StoryCloze/sStoryCloze）：Helium 热启动 + 纯音频训练的 Moshi 为 74.3/58.9/81.8/58.7，多数指标超过 TWIST-13B 与 Spirit-LM 的纯音频版本；多模态 Moshi 的 MMLU 为 49.8，比 Spirit-LM（36.9）高 12 分。指令微调后 sWUGGY 降至 63.0，作者归因于用户流噪声/混响增强使细粒度词汇判断变难，并指出 textless NLP 指标与对话模型开发目标相关性不稳定。

**对话生成**（Fisher 1000 个 10s 提示）：temp 1.0 时 IPU/Pause/Gap/Overlap 为 50.8s/7.0s/4.5s/4.1s，与真实数据（51.1/6.4/4.2/3.3）接近；条件 PPL 79.3（GT 59.6、级联系统 45.9、dGSLM 非级联 195.9）。temp 0.8 时 PPL 最低（41.9）但轮转统计偏离 GT——温度是质量与对话动态的真实权衡。

**流式 ASR/TTS**（LibriSpeech test-clean，训练未见该数据；TTS 用 HuBERT-Large 转写、取 4–10s 片段、temp 0.6）：TTS WER 4.7%，优于 Vall-E（5.9%）、不及 NaturalSpeech 3（1.81%），但后两者需全序列而 Moshi 仅 2s lookahead；ASR WER 5.7%（相近 lookahead 的流式 FastConformer 为 3.6%），附带 80ms 精度词级对齐。作者明示此项意在演示延迟机制的任务通用性而非刷 SOTA。

**量化**：Helium W4A8（block 32）MMLU 52.97 vs BF16 54.3，模型 4.37GB（3.43× 压缩）；Moshi 指令版 BF16 49.7 → W8A8 47.6 → W4A8（block 32）42.2，在线 demo 采用 8bit。音频侧以 token 熵谱伪影分析（64 token 窗口）测得：4bit 无伪影占比 95.7%（未量化 95.8%），2bit block 256 时 gibberish 占 83.1%。结论：语言能力对量化更敏感（6bit 以下显著退化），音频质量可撑到 4bit。

**安全**：ALERT 总体安全分 83.05（居中；Llama 2 为 99.98、GPT-4 为 99.18）；声纹一致性 98.7%（10249 次主说话人段更接近参考），且随对话时长无漂移（20–45s 段 98.4–99.3%）。

## 5. 消融要点

- **RQ-Transformer 的必要性由延迟约束决定**：延迟模式 [0,1,2,…,7]（640ms）下引入 RQ-Transformer 仅带来边缘改善（ppl 42.2→40.3）；收紧到 [0,2,2,…]（240ms）后独立分类头 ppl 135.4 vs RQ-Transformer 36.8——低延迟下它从可选变必需。
- **延迟-质量曲线**：[0,0,…]（80ms）→ [0,1,…]（160ms）使转录 NLL 4.36→4.12、长度 486→529；240ms 再小幅改善（4.09/519）。
- **逐项叠加**（转录以 Whisper 转写后由 LiteLlama-460M 打分，长度是强质量代理——弱模型塌缩为静音）：语义 token 损失权重 100 → NLL 3.75/538；加 depthwise parametrization → 3.65/602；再加 Inner Monologue → **2.77/1920**，长度近 4 倍增长，是全部设计中对生成语音质量与长度影响最大的单项。
- **文本 batch 必须保留**：去掉预训练中 50% 纯文本 batch，口语 QA 从 26.6/62.3/22.8 降至 23.2/61.3/18.3——Helium 热启动不足以在音频训练全程维持文本知识。
- **Mimi 消融**：无蒸馏 ABX 23.3%（语义 token 不可用）；加编码器 Transformer 的蒸馏 6.5%；split RVQ 把 MUSHRA 从 57.8 拉回 64.0（ABX 8.1%）；解码器 Transformer 显著提升 MUSHRA；50% 量化率显著提升 VisQOL 但主观不显著。
- **指标失相关的方法论警示**：VisQOL 对“改结构”是可靠代理，但对“改训练目标”（去重建损失）完全失去预测力；MOSNet 无法区分噪声伪影与语音模式伪影（如重复性塌缩）。作者改用 token 熵谱定义伪影分类器（重复文本：文本熵平坦非零、斜率阈值 1e-3；静音/背景噪声：音频码本熵中位数阈值 2；gibberish：文本熵 >3.5；噪声：跨码本熵标准差 >0.6）。

## 6. 贡献与启示

系统层面：给出首个实时全双工口语 LLM 的完整可复现配方（160ms 理论/200ms 实际延迟，5 分钟上下文），多流联合建模从机制上消灭了 VAD/轮次切分/端点检测级联。方法层面三项可迁移贡献：split RVQ 语义蒸馏（单 tokenizer 同时满足语义可懂度、高保真、全因果、12.5Hz 低帧率）；RQ-Transformer + 声学延迟的低延迟 RVQ 建模配方（含 depthwise parametrization 与语义权重 100）；Inner Monologue（逐帧文本前缀，且同一模型仅靠延迟符号翻转即派生流式 ASR/TTS）。

对音视频技术上下游的含义：(1) **编解码器-生成模型接口的重定义**——面向传输的 codec（Opus 类）优化通信效率，而 Mimi 类“面向生成的 codec”以帧率决定自回归步数与延迟下限（12.5Hz→80ms/步）、以码本结构决定 Depth 建模负担，成为实时语音生成的关键前端；(2) **评测链路警示**——神经 codec 的感知质量客观指标在训练目标变化时失效，主观协议（MUSHRA）不可省；(3) **端侧部署**——4bit 权重下音频近无损但语言能力 6bit 以下崩塌的量化谱系，为显存受限部署给出直接边界；(4) **内容安全**——神经 codec 往返即抹除信号水印、token 非幂等阻断生成式水印，说明媒体取证与溯源管线不能假设 codec 是保真或“保伪证”的中立环节；(5) 全双工多流建模范式对实时交互类系统（替代显式端点检测/半双工逻辑）具有架构参考价值。

## 7. 与其他论文的联系

- **LFSC（arxiv:2409.12117）**：同期独立工作，同样以帧率为语音 LLM 延迟/算力瓶颈的论断出发——LFSC 以 21.5fps/1.89kbps 换取约 3 倍推理提速；Mimi 更进一步到 12.5fps/1.1kbps 并叠加语义蒸馏与全因果。两文共同确立“低帧率”为实时语音 LLM 编解码器的设计主轴，且 Moshi 的延迟核算（每时间步一次 Temporal 前向，帧长即延迟下限）为该论断提供了机理依据。
- **HALL-E（arxiv:2410.04380）**：用后训练重量化框架 MReQ 把 codec 帧率降至 8Hz，实现分钟级 TTS 单次推理。与 Mimi 的“训练期架构降帧率”路线互补，应用面向长篇 TTS 而非全双工对话，但共享同一量化关系：帧率↓ ⇒ 自回归步数↓。
- **X-Codec（arxiv:2408.17175）**：与 Mimi 的 split RVQ 蒸馏同属“语义注入声学 codec”问题空间，但手段不同——X-Codec 在 RVQ 前注入预训练语义特征、RVQ 后加语义重建损失；Mimi 的消融则实证了“蒸进单一 RVQ 首层会造成可懂度-保真权衡”这一失效模式并给出 split 结构解。两者可视为同一矛盾（语义判别性 vs 重建保真）的两种解法对照。
- **Single-Codec（arxiv:2406.07422）**：以 304bps 单码本单序列从另一端消除“每时间步多 token”问题——单码本则无需 RQ-Transformer/Depth 建模。与 Moshi 的多码本 + RQ-Transformer + 声学延迟构成“码本容量 vs 建模复杂度”的权衡谱系两端。
- **Streaming Endpointer（arxiv:2506.07081）**：用流式低码率 codec 特征 + 标签延迟训练做显式对话端点检测。与 Moshi 的多流隐式轮转处理构成“显式端点检测 vs 端到端全双工”的架构对照；其标签延迟训练与 Moshi 的文本/音频延迟机制在“用延迟控制信息流向”这一思想上有直接亲缘。
- **CodecAttack（arxiv:2605.20519）**：Moshi 第 6.4 节实证 codec 编解码往返即可将 Audioseal 检测分打回无水印水平（0.0805 vs 0.9999），CodecAttack 则证明潜空间对抗扰动可穿透 Opus/MP3/AAC 压缩。两者互补地表明：神经/有损 codec 潜空间既非可靠水印载体、也非可靠防御屏障，对音视频内容安全与溯源管线是双重警示。
- **CodecMOS-Accent（arxiv:2603.14328）**：跨口音的 codec 重合成/TTS MOS 基准，可为 Mimi 类 codec 补上更细粒度的感知评价维度——与 Moshi 关于客观指标失相关的发现正交互补。
- **FoundationTTS（arxiv:2303.02939）**：分层 VQ-GAN 离散 token + LLM 自回归合成的早期代表，是 Moshi 所属“codec token + LLM”谱系（AudioLM→VALL-E 一脉）的上游节点；Moshi 将该范式从单句 TTS 推广到多流全双工对话。
