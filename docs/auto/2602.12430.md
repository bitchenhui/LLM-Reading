## 1. 背景与动机

论文要解决的核心张力是：通用大模型具备广谱知识，但缺乏真实任务所需的**专用程序性知识**（procedural expertise）。作者逐一否定了两条既有路线：微调成本高且组合性差；RAG 检索到的语料是**被动的**——不能规定多步工作流、不能捆绑可执行代码、不能在运行时调整智能体的工具权限。Agent Skills 给出的答案是文件系统级的模块化抽象：一个技能不是模型也不是提示模板，而是自包含的目录包——结构化指令文件（SKILL.md）+ 可选脚本 + 参考文档 + 资产，由智能体在相关任务出现时发现、加载、遵循。

论文给出的关键概念区分贯穿全文：**工具“执行并返回结果”，技能“改造智能体解决问题的准备状态”**——注入程序性知识、修改执行上下文、启用信息的渐进式披露。这是技能与 function calling 在架构层面的本质差异，也直接决定了后文安全分析中技能独特的攻击面语义。

产业时间线支撑了综述的时效性主张：Anthropic 于 2025 年 10 月产品化 Agent Skills，12 月发布开放标准；四个月内 anthropics/skills 仓库积累超过 62,000 GitHub stars，Atlassian、Figma、Canva、Stripe、Notion 的合作技能进入策展目录，其他前沿模型厂商独立采纳了结构同构的架构。与之互补的 MCP 于 2024 年 11 月发布、2025 年 12 月捐赠给 Linux 基金会旗下 Agentic AI Foundation。作者由此提出“agentic stack”分层论断：**技能供给"what to do"，MCP 供给"how to connect"**。

能力扩展范式被组织为三段演进：prompt engineering（2022–2023，短暂、非模块化、难版本化）→ 工具调用（2023–2024，原子化单函数）→ skill engineering（2025 至今，指令/工作流/脚本/文档/元数据的捆绑包）。学脉上，Voyager（Minecraft 技能库）、CREATOR、Large Language Models as Tool Makers、Toolformer 属于“受限环境中模型自生成技能”；Agent Skills 范式的差异化在于**人写的、可移植的、可治理的生产级技能包**。综述方法论上，作者检索 arXiv、ACL Anthology、NeurIPS/ICML/ICLR 及官方技术出版物，显式排除泛 LLM agent 与泛工具使用综述的覆盖范围；部署一节以 CUA（computer-use agent）为扩展对象，但作者自认这是“代表性压力用例而非范式边界”——因为技能打包率先在软件侧环境成熟。

## 2. 方法总览

综述沿四轴组织，其结构本身就是对领域的一阶建模：

**轴一：架构基础**。SKILL.md 规范、渐进式上下文加载（三级披露）、技能与 MCP 的正交互补（六维对照：主角色/单元/加载方/修改对象/持久性/规范状态——技能是“目录+SKILL.md、触发时由 agent 加载、修改上下文与权限、文件系统级持久”，MCP 是“server+endpoint、配置时由 client 加载、修改可用工具与数据、会话级持久”）。另覆盖 Anthropic 2025 年 11 月 Advanced Tool Use 三机制对技能-工具集成瓶颈的作用。

**轴二：技能获取分类学**，六条路线：人类撰写（Anthropic 框架 + skill-creator 元技能脚手架 + 合作伙伴策展管道）、RL 与技能库（SAGE）、自主探索发现（SEAgent）、结构化技能基（CUA-Skill 的参数化执行图）、组合式合成（Agentic Proposing）、技能编译（Li 2026 的多智能体→单智能体压缩）。

**轴三：部署与基准**，以 CUA 栈为主轴（GUI 智能体架构、grounding 进展、基准版图），旁置 SWE-bench、BFCL、具身智能体等场景。

**轴四：安全**，首次整合三份并行实证研究（Schmotz 提示注入、Liu 大规模漏洞普查、恶意技能确认研究），并据此提出原创的 **Skill Trust and Lifecycle Governance Framework**：获取途径 × 验证门（G1–G4）× 信任层（T1–T4）× 生命周期信任演化。作者明确自我定位：这是治理提案而非实证验证系统，其价值在于“把信任假设显式化、可测试”。

## 3. 关键设计

### 3.1 SKILL.md 与三级渐进式披露

技能核心是一个含 YAML frontmatter（name、description）的 SKILL.md。智能体启动时**仅预载元数据**——正文口径为"typically a few dozen tokens"——进入 system prompt，由此支持大型技能库而无上下文惩罚；指令正文仅在任务语义匹配触发时注入；脚本、参考文档、资产存放于子目录、按需加载。作者引用的工程隐喻准确概括了三级语义：L1 是目录（table of contents），L2 是章节正文，L3 是技术附录。技能发现依赖意图与 description 的语义匹配路由。**工程含义：上下文窗口消耗成为一等设计变量**，技能库规模与路由精度从此构成一对核心权衡（后文 Li 的相变结论直接命中此处）。

### 3.2 技能执行生命周期

触发后执行两阶段操作：其一，指令与所需资源以**隐藏元消息**注入对话上下文（模型可见、UI 不渲染）；其二，修改执行上下文——激活预批准工具（如特定 bash 命令、文件读写权限）。关键机理再强调：技能修改的是智能体**生成响应之前**的知识与能力状态，而非直接产出结果。这一“准备态改造”语义是第 6 节安全分析的根源：一旦加载，技能指令被视为权威上下文，这就是提示注入的立足点。

### 3.3 Agentic Stack：技能与 MCP 的正交分层

MCP 以 JSON-RPC 2.0 标准化 agent 与外部数据/工具的连接，三原语为 tools（模型调用的函数）、resources（应用控制的数据）、prompts（用户调用模板）。二者非竞争关系：一个技能可以指示 agent 使用特定 MCP server、规定如何解读其输出、并定义连接失败的回退策略——**技能提供程序性智能，MCP 提供连接性**。Advanced Tool Use（2025-11）深化了该集成：Tool Search Tool 支持从大型注册表程序化发现工具，所引技术报告称相对预载全部工具定义 token 开销最高降低 85%；Programmatic Tool Calling 允许以代码而非结构化 JSON 执行工具，所报基准上 Opus 4.5 准确率从 79.5% 提升至 88.1%；Tool Learning 让模型研读工具文档以提升调用质量。这三个机制回应的正是技能库增长后“技能工作流内正确发现并调用工具”的瓶颈。

### 3.4 Skill Trust and Lifecycle Governance Framework（本文原创核心）

四道串行验证门构成纵深防御：**G1** 静态分析（模式匹配 + 依赖扫描，标记已知漏洞签名）；**G2** LLM 语义分类（检测技能声明用途与实际指令之间的**意图错配**，针对 Schmotz 等识别的间接提示注入向量）；**G3** 行为沙箱执行（捕获静态分析不可见的副作用，其设计依据是确认恶意技能平均含 4.03 个漏洞、横跨 3 个 kill-chain 阶段的实证）；**G4** 权限清单校验（将技能对所需能力——工具、文件路径、网络访问——的形式化声明与 G3 观测行为比对）。

信任层的关键设计洞察是**映射非二元而是分级、遵循最小权限**：未审查社区技能（T1，仅需 G1 自动分诊）仅获指令层访问与完全工具隔离；T2 及以上才开放指令层内容；可执行脚本要求 T3/T4 信任——即 **T1/T2 永不被授予脚本执行**，直接对应“捆绑脚本的技能漏洞概率 2.12 倍于纯指令技能”的实证；T4 厂商认证技能获得全部能力。框架刻意做到**架构感知**：治理分级与三级披露逐层对齐（L1 元数据在 T1 即暴露、L2 指令需 T2+、L3 脚本需 T3+），使权限决策落在真实攻击面上而非均匀施加。生命周期维度上，部署后技能受运行时监控：异常行为（意外工具调用、权限边界探测）触发降级或吊销，清白运行史可晋升——构成类似包管理生态声誉机制的激励结构。企业落地路径也已给出：入库时注册服务记录溯源并跑 G1–G2 方可被 agent 检索；请求脚本/文件系统/网络/外部 MCP 的技能进入沙箱暂存环境跑 G3 并在 G4 比对清单；运行时按所属层强制限制该技能激活期间可用的文件、工具、网络目的与审批范围。

**安全实证（三份并行研究）：** Schmotz 等证明技能可实现"trivially simple"的提示注入——在冗长 SKILL.md 及引用脚本中嵌入恶意指令即可外传内部文件或口令；且某流行编码智能体的系统级护栏可被绕过：一次良性的任务级审批（勾选"Don't ask again"）会**携带到相近但有害的动作上**。Liu 等从两大市场采集 42,447 个技能、以 SkillScan（静态分析 + LLM 语义分类的多级检测框架）分析 31,132 个：**26.1% 至少含一个漏洞**，覆盖 4 大类 14 种模式（数据外传 13.3%、提权 11.8%、提示注入、供应链）；捆绑可执行脚本的技能漏洞概率为纯指令技能的 2.12 倍（OR=2.12, p<0.001）；5.2% 呈高危模式、强烈提示恶意意图。后续研究对两个社区注册表的 98,380 个技能做行为验证，确认 **157 个恶意技能、共 632 个漏洞**，归纳出两类攻击原型：经供应链技术外传凭证的 Data Thieves 与经指令操纵劫持 agent 决策的 Agent Hijackers；**单一工业化行为者以模板化品牌冒名贡献了 54.1% 的确认案例**。

## 5. 消融要点

综述不运行消融，但其汇集的若干受控对比构成该范式的“消融级证据”，值得单独抽取：

- **技能库有无**（SAGE vs 基线 GRPO，AppWorld）：SGC 绝对 +8.9pp 的同时交互步数 −26%、token −59%——能力增益与推理成本下降**同源**，机理是技能把任务链上的搜索过程外化为可复用产物，Sequential Rollout 让早期任务生成的技能在后续任务中直接复用。
- **执行层风险隔离**（Liu）：捆绑脚本 vs 纯指令的 OR=2.12 把风险定位在可执行层，这是 G 门/T 层按披露级别设权的实证依据；元数据层暴露面最小（名称冒名）、指令层是提示注入主战场、脚本层是代码执行风险源。
- **预载 vs 按需加载**（渐进式披露本身即上下文消融）：常驻开销仅“几十 token/技能”；Tool Search 相对预载全部工具定义最高省 85% token 开销。
- **调用范式消融**（Advanced Tool Use）：代码式 vs 结构化 JSON 调用，79.5%→88.1%（Opus 4.5，所报基准）。
- **多智能体→技能编译**（Li）：编译后精度保持且 token/延迟大降，但库规模越过临界值后技能选择精度**相变式崩塌**——单智能体可有效管理的技能数存在硬上限，直接约束企业级技能库（数百到数千技能）的路由设计。
- **规模 vs 自进化消融**（Yuan）：7B + 3,000 样本 RL 自进化在 ScreenSpot-Pro 超 72B 模型 24.2pp，说明 grounding 能力可被自进化训练以小博大；Jedi 的 4M 数据将 OSWorld 从 5% 拉到 27%，则给出数据规模路线的对照。
- **治理框架零消融**：G1–G4/T1–T4 无任何误报/漏报率或攻击拦截率数据，作者自陈为提案——这是全文证据链最大留白，G2 的 LLM 语义分类器本身也可被对抗性技能针对。

## 6. 贡献与启示

**学术贡献**：首个聚焦技能抽象层的系统综述（相对既有泛 agent/工具/GUI agent 综述的差异化成立）；三份安全实证的首次整合；G1–G4/T1–T4 生命周期治理框架；七大开放挑战——跨平台可移植性（Claude 技能隐式依赖其代码执行环境、工具签名与模型行为，需通用技能运行时或面向目标平台的技能编译）、规模化技能选择、多技能编排（冲突消解/资源共享/失败恢复）、基于能力的权限模型、技能验证与测试（应含幻觉过程、级联失败、技能间死锁、静默提权、对抗性技能链的**负向测试**）、无灾难性遗忘的持续技能学习（引 Shenfeld 等自蒸馏路线）、技能级评估方法学（可复用性/可组合性/可维护性指标，而非仅任务完成率）。

**概念贡献**：技能=改造生成前准备态而非产出；skills/MCP 正交分层；渐进式披露=上下文经济学；信任从二元 accept/reject 解耦为与溯源和验证深度对齐的分级。最有张力的洞察在 Discussion：**学得技能（SAGE/SEAgent）是模型内部的——不可检视、不可分享、不可治理；人写技能可审计但静止**。弥合二者（让 agent 把学到的技能外化为可移植、可审计的产物）被指为统一获取与部署范式的关键方向。

**工程启示**：token 即部署成本（−59% 直接换算为推理费用）；技能库有容量相变，路由是组合难题；审批携带（"Don't ask again"）是一种可武器化的权限原语；良性技能的负向失效（幻觉过时指令、级联工具失败、组合死锁、审批过泛化）与恶意技能同属治理对象。

**对音视频领域的映射（笔记延伸，非论文主张——原文未涉及 AV 场景）**：上游侧，媒体处理程序性知识（转码链路、封装/切片、字幕流水线、响度规整、QC 校验）天然是“多步决策+脚本+边界情形”的捆绑体，与论文反复使用的 pdf-processing 技能示例同构，SKILL.md+scripts+assets 的打包形态可直接平移为媒体容器处理技能。中游侧，专业媒体软件（NLE/调色/DAW）GUI 重、API 覆盖弱，CUA 路线 + 技能库是自动化的一条现实路径，而 UGround/Jedi/GUI-Actor 的 grounding 进展与 OSWorld 类基准是前置能力；多模态输入（截图/帧）token 开销远高于文本，渐进式披露与 Tool Search 的 85% 开销削减对长时程媒体 GUI 任务价值更高。下游侧，安全结论对媒体技能生态同样成立：转码/MAM/CDN 凭证正是 Data Thieves 的外传目标，LUT/插件/脚本捆绑即“脚本 2.12 倍风险”的对应物，54.1% 单一行为者的模板化品牌冒名提示媒体供应链需在入库期即跑 G1–G2；MCP 则可作为连接媒体资产管理、转码农场与流分析后端的连接层。

**局限**：治理框架未验证；部署叙述偏 CUA（作者自认压力用例）；全文为快速演进领域的快照（数字截至 2026-02）；OSWorld-V 人类持平的窄切片解读、以及技能质量指标缺位（挑战 7）均由作者自陈。
