# KD-NVC: A Search-and-Distill Framework to Accelerate Neural Video Coding

## 1. 背景与动机

NVC 的率失真性能已系统性超越 VVC 系（如 DCVC-FM 在 YUV420、以 VTM-LDB-23.11 为锚的平均 BD-rate 为 IP32 −26.0% / IP-1 −24.6%），但部署瓶颈集中在解码端：VAE 结构导致编解码复杂度天然对称（DCVC-RT 解码 166.8 kMACs/pixel @1080p），扩散类编解码器更重。这与视频分发“一对多”范式根本错配——编码一次性摊销在高性能服务器，解码在大量资源受限端侧重复执行。解码侧模型加速因此成为 NVC 落地的核心短板。

知识蒸馏是模型加速的标准手段，但作者指出其移植到 NVC 面临三个结构性障碍，且各配实证观察：

**观察一（模块异质性）**：视频编码器单帧内推理链远长于图像编码（帧间预测→上下文编码→熵编码→上下文解码→重建→参考适配），叠加跨帧参考链。各模块功能分化导致对模型压缩的敏感度不同——有的模块可大幅简化而 RD 代价轻微，有的高度敏感。手工统一层/通道裁剪会把加速预算浪费在敏感模块上，需要 per-module 设计，即引入 NAS。

**观察二（NAS 成本不可负担）**：SOTA NVC 训练动辄百万迭代、数十 GPU 天（本文教师 DCVC-RT 复现即耗 8×V100 两周）。串行渐进式 NAS 需一个月以上；穷举并行式在 100 个候选规模下就需超过 10,000 V100 GPU 天。两条既有范式对 NVC 均不可行，必须设计“免训练架构级候选”的决策机制。

**观察三（率约束诱导的通道能量稀疏）**：这是本文最具辨识度的实证发现。作者定义通道能量 $e_c$ 为该通道响应幅值的空间均值（$e_c=\frac{1}{HW}\sum_{h,w}|F_{c,h,w}|$），用 top-10% 通道能量占比 T10 与归一化基尼系数 G 刻画稀疏度。实测：DCVC-RT 由浅到深三层中间特征的 T10/G 分别为 90%/0.87、25%/0.25、28%/0.29；把损失中的率项去掉后变为 28%/0.41、19%/0.21、17%/0.19。DVC 呈同样规律（深层 L3 有率约束时 T10=76%、G=0.83，无率约束时仅 11%/0.03）。对照的 ResNet/MobileNet/VAE 骨干分布均衡得多（T10 约 16%~36%）。结论：能量稀疏性是率约束诱导的、率友好的结构——少数通道承载大幅值、其余近零，有利于降熵与提高压缩比。而常规 KD 损失（逐点 MSE、频域距离、KL 散度）对各位置/通道/分量均匀加权，与该结构性先验脱节。

由此引出需求：（i）模块异质的加速预算分配 + 低成本架构搜索；（ii）感知率诱导稀疏结构的蒸馏损失。

## 2. 方法总览

KD-NVC 是两阶段"NAS-then-KD"框架，教师为作者复现的 DCVC-RT（原训练脚本未开源，复现融合了近期 NVC 训练技巧，IP32/IP-1 平均 BD-rate −15.3%/−19.0%，与原文报告的 −15.2%/−20.6% 基本一致），保证“教师—搜索—蒸馏”闭环自洽。

**阶段一（AE-NAS，确定学生架构）**：把轻量化形式化为约束优化 $M_S=\arg\max_{M\in\Omega}\eta(M)$ s.t. $S(M)\ge S_{target}$，其中加速效率 $\eta$ 定义为单位 BD-rate 退化换取的解码加速。为避免穷举，分两步：先经模块级候选短训获得各模块 Pareto 前沿，再把架构级搜索限定在前沿候选的笛卡尔积上，用估计的 $\hat\eta$ 排序选出最终架构——**架构级候选完全不训练**。

**阶段二（EFD + 一步蒸馏）**：选定学生以 $L_{total}=L_{RD}(M_S)+\beta\sum_i L_{EFD}(F_T^{m_i},F_S^{\bar m_i})$ 训练。EFD 对齐教师/学生各模块中间特征的空间聚合通道能量签名，显式迁移率诱导稀疏模式。所有模块同时优化，无 adapter、无分阶段冻结。

## 3. 关键设计

### 3.1 AE-NAS：模块级 Pareto 前沿 + 架构级免训练排序

**模块级搜索（Step 1）**。编码器分解为 M 个模块，第 i 个模块配 $N_i$ 个轻量变体（改变层数 L / 通道数 C / FFN 扩展率 F 及其组合，如 $\frac12 L$、$\frac12 C\,\frac14 F$）。关键效率设计：每个模块级候选只把 $m_i$ 替换为变体 $m_i^j$，**其余模块直接继承教师权重**，仅从头训练一个轻量模块，且训练量减至教师策略的 1/3（epoch 层面）。全部 $\sum N_i = 34$ 个候选相互独立、可完全并行。每候选测两个标量：BD-rate 退化 $\Delta$（六数据集口径，锚 VTM-LDB-23.11）与实测加速 $S$（单卡 Tesla V100、标准 PyTorch 算子、1080p）。由此确定每模块的 Pareto 前沿集合 $P_i$。

**架构级选择（Step 2）**。最终搜索空间 $\Omega = P_1\times\cdots\times P_M$。对每个组合：全局加速 $S$ 直接实测；全局 RD 退化按**可加性假设**估计 $\hat\Delta(M_{arch})\approx\sum_i\Delta(\bar m_i)$；$\hat\eta = S/\hat\Delta$。在满足 $S\ge S_{target}$ 的组合中取 $\hat\eta$ 最大者为 $M_S$。

两个重要工程约束值得注意：
- **搜索空间为蒸馏服务**：通道裁剪只作用于堆叠卷积的中间通道，输入/输出通道保持不变，教师与学生特征维度处处匹配，蒸馏因此无需任何 adapter——NAS 与 KD 在此是协同设计而非独立环节。
- **熵模型整体排除出架构级组合空间**：模块级评估显示其对简化高度敏感。最终 $\Omega$ 含 80 个候选（全组合空间为 704），按 ≈60% 与 ≈100% 两档加速目标选出两个学生：
  - **KD-NVC-S**：帧间预测 $\frac12 L$ + 解码器 $\frac13 L$ + 重建 $\frac12 C$；
  - **KD-NVC-T**：帧间预测 $\frac12 L\frac12 F$ + 解码器 $\frac13 L\frac12 F$ + 重建 $\frac12 L\frac12 C$。

成本核算：整个 NAS 仅需 34 个 1/3 训练量的模块级短训，零架构级训练，相对穷举（100 候选即 >10,000 V100 GPU 天）与串行渐进（>1 个月）在成本上可行。

### 3.2 EFD：空间聚合能量签名对齐

**机理**。NVC 特征的能量稀疏意味着“哪些通道该大、哪些该近零”本身就是率友好的结构信息。逐点 MSE/MAE 在稀疏背景下被海量近零通道主导且强制精确空间对应；频域对齐均匀对待所有频带；KL 假设特定分布形式。EFD 放弃逐点对应，仅对齐“通道 × 空间块”级能量分配：对中间特征施加 $k\times k$（$k=8$）自适应平均池化，得能量签名 $E\in\mathbb{R}^{C\times k\times k}$，损失为签名逐元素 L2：

$$L_{EFD}=\frac{1}{Ck^2}\sum_{c=1}^{C}\sum_{j=1}^{k^2}\left(E_T^{c,j}-E_S^{c,j}\right)^2.$$

这同时松弛了空间严格对齐（块内聚合）又保留通道间能量梯度（教师大能量通道学生亦须大）。

**一步蒸馏管线**。所有模块同时以 $L_{RD}+\beta L_{EFD}$ 优化；作者明确拒绝 learnable adapter（实验发现拖慢 NVC 收敛）与渐进/并行蒸馏范式。β 调度值得注意：β=1.0 仅用于第一阶段（约 1M 迭代），之后置 0 转纯 RD 训练——EFD 本质上是早期收敛加速器/正则项，最终 RD 由纯率失真优化主导，这与消融中“EFD 全程显著加速收敛”一致。

### 3.3 教师复现训练配方（复现贡献本身有参考价值）

5 阶段渐进 GOP 训练（global batch 8）：Stage1 1.0M iters（GOP 2→4，逐 P 帧梯度）；Stage2 200k（GOP 7）；Stage3 230k（GOP 15→32）；Stage4 60k（GOP 64，lr 1e-5→5e-7，patch 256×256）；Stage5 30k（GOP 128，lr 5e-7）。前两阶段用 Vimeo-90k（64k 序列），后三阶段用 8k raw Vimeo 裁剪长 GOP。配合层级失真权重 (0.9, 1.2, 0.9, 0.5)、首 P 帧随机重复、周期性学习率（降—升—降）与 partial cascaded fine-tuning（压缩长序列训练显存）。λ∈[1,768]。总计 8×V100 两周。

## 4. 实验结果

**设置**：YUV420 BD-rate，锚 VTM-LDB-23.11；测试集 HEVC-B/C/D/E、UVG、MCL-JCV；加速百分比在 1080p、单卡 Tesla V100-SXM2-32GB、标准 PyTorch 算子下测得；部署 FPS 在 5060/V100 上用 CUDA 定制算子替换标准算子、在 Apple M3 上走 MPS。三个蒸馏基线（Fu2024：对齐熵模型分布参数+重建；PRIM：一步对齐隐表示+重建；SMoDi：去特征损失、并行后合并）均使用 AE-NAS 选出的同一学生架构与同一训练策略，以纯隔离蒸馏范式变量。

## 5. 消融要点

**（1）AE-NAS vs 均匀裁剪**：在帧间预测/解码器/重建三模块上分别施加统一层裁剪与统一通道裁剪作对照，per-module 设计在“加速%–RD 退化%”平面上全程占优。结论明确：加速预算必须按模块敏感度异质分配。

**（2）supernet vs per-variant 训练**：图像压缩 NAS 中常用的权重共享超网在 NVC 上失效——超网训练难度大、帧间预测模块收敛差，导致错误判定该模块“加速潜力差”，而 per-variant 短训揭示其潜力良好。这是 LIC 超网方法在视频域不可移植的直接证据，也是本文放弃超网、采用 34 个独立短训的依据。

**（3）EFD vs 其他蒸馏损失**（同 KD-NVC-S 架构、同策略，第一阶段约 1M 迭代，锚点为全训 DCVC-RT）：
- KL 散度与 learnable adapter 甚至**劣于 direct training**（伤害收敛），归因于二者完全忽略通道间能量差异；
- MSE、MAE、频域对齐相对 direct training **无收敛收益**——逐点/逐频的均匀匹配不构成有效知识迁移；
- 4×4 / 8×8 / 16×16 三种池化尺度的能量损失全程显著优于全部基线且收敛更快，正文取 k=8。
- 开销对比（单 384×256 P 帧 patch）：

| 蒸馏损失 | 迭代时间 | 显存 |
|---|---|---|
| Direct | 69.3 ms | 1721 MiB |
| MSE / MAE / KL | 86.7 / 87.2 / 86.4 ms | 1816 / 1969 / 1822 MiB |
| Learnable adapter | 88.9 ms | 1839 MiB |
| 频域 | 482.1 ms | 22093 MiB |
| EFD | 85.4 ms | 1816 MiB |

EFD 与 MSE 同级、几乎零额外成本；频域损失时间贵约 5.6×、显存约 12×，实际不可用。

**（4）一步蒸馏 vs 其他范式**（同架构，以一步范式为锚）：

| 范式 | BD-rate 变化 | 训练成本 |
|---|---|---|
| Direct（无蒸馏） | +4.5% | ≈0.8× |
| 渐进 head-to-tail | +0.4% | ≈3× |
| 渐进 tail-to-head | +0.3% | ≈3× |
| 并行蒸馏 | +1.9% | ≈1.6× |
| 一步蒸馏 | 0.0% | 1× |

一步范式同时拿到最优码率与接近最低训练成本；渐进式花约 3× 成本仍劣于一步。“分阶段蒸馏更精细更好”的直觉在 NVC 上不成立，对后续 NVC 蒸馏流程设计有直接指导意义。

## 6. 贡献与启示

**贡献**：（1）面向 NVC 解码加速的系统化"NAS+KD"框架，明确并逐一解决模块异质、NAS 成本、率诱导能量稀疏三个问题；（2）AE-NAS：模块级 Pareto 前沿 + 可加性 RD 退化估计 + 加速效率指标，使架构级候选零训练即可排序；（3）EFD：以空间聚合通道能量签名为蒸馏目标，迁移率友好稀疏结构，并配一步蒸馏管线。

**工程启示**：
- “教师权重继承 + 单模块 1/3 训练量短训 + 完全并行”是 NVC 上做模块压缩敏感度分析的低成本范式；
- 搜索空间设计要为下游蒸馏预留接口（中间通道裁剪保持 IO 维度），NAS 与 KD 应联合设计；
- 压缩任务的“知识”定义不同于分类任务：蒸馏目标应匹配率约束塑造的特征统计（能量稀疏），而非 logits 或逐点特征；
- 蒸馏损失可以只在训练前段起作用（β 先 1 后 0），后期纯 RD 优化更优——蒸馏定位为收敛加速器；
- 局限与遗留：熵模型被证明不可简化，成为解码加速的硬约束（其占解码延迟的份额未单独拆分）；两档学生需各自完整训练，无复杂度可扩展码流；可加性 Δ̂ 估计在模块交互强时可能失准（论文未系统报告估计误差）；FPS 数据依赖 CUDA 定制算子，距离通用部署仍有距离。作者展望整数推理、量化感知训练、流水线并行与“一快多编”非对称设计。

## 7. 与其他论文的联系

- **NVRC++（arXiv:2606.28163）**：同属“把解码复杂度当作一等设计变量”的神经视频编码工作，但技术路线对偶。NVRC++ 走 INR 路线，以轻量 HiNeRV++ 骨干加多个高分辨率 feature grid 将复杂度与质量解耦，单模型四档（7k–360k MACs/pixel）覆盖全码率区间，S3 档质量与 NVRC 相当且解码快 7.6 倍；KD-NVC 则在 VAE-NVC（DCVC-RT 教师）上以架构搜索+蒸馏压低固定档位复杂度（解码 −44%/−57% kMACs，仅两档）。关联依据：两者针对同一“解码复杂度—质量”权衡问题；NVRC++ 的多档复杂度设计恰可作为 KD-NVC“每档重训一个学生”模式的替代方案参照。

- **S-NVRC（arXiv:2609.04273）**：提出单一嵌入码流同时支持码率与解码复杂度细粒度可扩展的 INR 视频编解码器，直接对应 KD-NVC 的主要局限——KD-NVC-S/T 是两个独立训练的固定架构，复杂度不可扩展、教师亦仅一档。关联依据：复杂度可扩展码流正是 KD-NVC 结论中非对称“一快多编”设计所指向的问题域，S-NVRC 的嵌入可扩展机制为 VAE-NVC 侧实现类似能力提供了参照。
