## 1. 背景与动机

NVC 的 RD 性能已非瓶颈：DCVC 系列等 SOTA 已超过 HM/VTM 乃至下一代原型 ECM。论文将问题重新定位为“最后一公里”——实用性：编码速度、跨设备一致性、码率控制。作者逐一指出现有实用性路线的硬伤：MobileNVC 在消费级硬件上实现实时解码吞吐，但压缩率甚至低于 x264；C3 解码高效但编码依赖耗时的逐实例优化；DHVC-2.0 需约 4 卡 GPU 流水线才达到实时解码吞吐，单卡环境下效率骤降且不满足实时延迟；Tian et al. 用辅助校准码流修正跨设备不一致但未达 1080p 实时；ELF-VC 等降算力方案同样未达实时。此外，现有可变码率方法均无法同时具备跨设备一致性与码控能力。

本文最核心的洞察是对复杂度的重新定义：决定编码速度的不仅是 MACs 口径的计算复杂度 Pcomp，还包括“操作复杂度”——由隐变量张量尺寸决定的内存 I/O 开销 Psize、由模块数量决定的调用次数/函数调用开销 Pnum。证据有两层：其一，把通道 C 减半，Pcomp 按 O(C²) 平方下降，推理时间却近似线性改善（因为 Psize 只随 C 线性缩小）；其二，通过平衡模块数 N、通道 C、隐变量分辨率 H×W 独立控制三个因子的实验表明，高算力基线下 Psize 是主导瓶颈，低算力基线下 Pnum 是主导瓶颈。这一结论直接导出设计哲学：算力不是主瓶颈，因此可以把省下的算力重新分配——删除非关键模块（显式运动编解码）以压 Pnum，改用单尺度低分辨率 latent 以压 Psize，同时把算力集中到帧编码关键模块以保容量。

目标主张：首个在消费级硬件（RTX 2080Ti，1080p 约 40/34 fps）上实现实时编码+实时解码、且压缩率超过 VTM（YUV420 下 -21.0%）的 NVC；A100 上达 125.2/112.8 fps。

## 2. 方法总览

DCVC-RT 仍属条件编码（conditional coding）范式，但结构上做了两处范式级修改：

- **单尺度 1/8 latent**：当前帧经 patch embedding 一步降到 1/8 分辨率，encoder/decoder/feature extractor/重建生成全部工作在该单一尺度，取代传统的逐层渐进下采样。
- **隐式时间建模**：彻底删除显式运动估计/运动补偿。时间上下文由一个简单 feature extractor 作用于已解码 latent f_{t-1} 得到，与当前 latent 沿通道维拼接后由 encoder-decoder 联合处理去冗余；编码侧另有独立的 feature extractor 产生上下文 F^e_{t-1} 供熵模型使用。

其余模块：two-step 熵估计（沿用 [26] 的两步分布估计，牺牲少量 RD 换速度）、hyper encoder/decoder 编码 z、Recon Generation 模块（仅解码侧执行；编码时参考特征在其之前缓存，故编码通常快于解码）。基本积木是 DC Block（depthwise conv + 1×1 conv + WSiLU(x)=x·Sigmoid(α·x)，α=4，含通道 chunk 拆分）。

系统层面有两项实用技术：**module-bank 码率控制**（超先验模块库 + 各模块向量库，单模型 64 个码率点，可插值扩展）与 **训练无关的 int16 整数化**（跨设备确定性）。

复杂度画像（1080p、A100）：单帧网络推理约 7.8 ms，熵编码至多约 2.6 ms——熵编码占比可观，因此引入**并行编码流水线**：与熵编码无依赖的网络模块并行执行（可 CPU 熵编码 + GPU 推理，硬件资源竞争不严重），编码提速 12%、解码提速 9%。解码侧利用 two-step 特性：z 的熵解码与 feature extractor 前半段并行，y_q1 的解码时间覆盖 feature extractor 推理，剩余部分与 y_q2 解码并行。

训练配置：Vimeo-90k 七帧序列训练，按 DCVC-FM 方式构造长序列微调；每次迭代 qp 在 [0,63] 随机采样实现单模型可变码率，λ 在 1–768 间插值（同 FM）；8 帧一组 qp offset [0,8,0,4,0,4,0,4] 实现层级质量，失真项按 DCVC-DC 的层级权重设置；YUV+RGB 联合失真支撑双色彩空间单模型。

## 3. 关键设计

### 3.1 复杂度解耦：为什么“少模块、小张量”优先于“少 MACs”

渐进下采样范式每层空间减半、通道加倍，各层 Pcomp 维持在 O(C²HW) 量级而 Psize 逐层减半——意味着大量计算发生在较大的 latent 上，内存 I/O 成本高。作者用“平衡 N、C、H×W”的方式独立控制三因子（例如 C 减半同时 H·W 加倍可保持 Psize 不变而降 Pcomp），得到两条结论：只降 Pcomp 对提速收效甚微；高算力时 Psize 主导、低算力时 Pnum 主导。这解释了自回归熵模型（低 MACs 但串行调用）与多层运动分支（低 MACs 但层数多）为何“算力便宜却很慢”，也说明不同模块需要不同优化策略——运动类“低算力多层”模块正是 Pnum 的典型受害者，应当整支删除而非瘦身。

### 3.2 单尺度 1/8 latent

在等 MACs 的公平对比下：学习 1/8 单尺度 latent 比渐进下采样编码提速约 3.6×，同等模型容量下 BD-Rate 仅 +0.3%。机理上，单尺度下多次堆叠同尺度卷积使深层感受野显著扩大，1/8 尺度下感受野甚至超过渐进下采样，有利于时间冗余去除。尺度选择有明确边界：1/2 尺度感受野受限，RD 明显退化；1/16 尺度（C=512）latent 尺寸仅 512·H/16·W/16=2·H·W，小于原帧的 3·H·W，表示容量不足导致压缩率下降；1/8 配 C=256 给出 4·H·W 的充分容量，是速度-容量的平衡点。

### 3.3 隐式时间建模

关键量化依据：DCVC-FM 的运动分支算力仅为条件编码分支的 1/13（74 vs 932 kMACs/pixel），层数却接近一半（123 vs 225 层）——低算力、高模块数，恰是 Pnum 瓶颈的极端形态。DCVC-RT 用单个简单 feature extractor 提取时间上下文并与当前 latent 通道拼接，由编解码器联合建模，模块数（即调用频率）直接下降，省出的算力重分配给帧编码模块。消融（MCL-JCV，运动幅度用预训练 SEA-RAFT 度量划分）：隐式建模平均 BD-Rate +2.1%，其中大运动 +3.2%、小运动 -0.4%、场景切换 -4.7%（场景切换本质无法被运动建模，隐式建模反而占优）；编码时间 8.0 ms vs 显式 27.2 ms（3.4×）。RD 小损失换 3.4× 速度，是典型的操作性价交换。

### 3.4 Module-bank 码率控制

关键观察：删除运动码流后，z 的比特量平均超过 y 的 10%（而常规 NVC 中 z 通常不足总比特 1%），z 承担了时空建模信息，其分布估计失准会被显著放大。因此对 z 不再使用单一 factorized prior，而是按 qp 学习一组超先验模块（module bank），使估计分布贴合真实分布，UVG 上节省约 3% 比特（图注口径 3.4%）。进一步为 encoder/decoder/feature extractor/reconstruction 分别设向量库（qe/qd/qf/qr），学习一组向量对 latent 做自适应缩放，实现细粒度幅度调整。实用性上：64 个码率点可通过向量线性插值 + factorized 取最近邻扩展到 128 个（实验显示质量过渡平滑）；层级质量仅需帧间 qp offset，相比 DCVC-FM 的独立 feature adaptor 与码率调整一致性更好、更灵活。

### 3.5 训练无关的 int16 整数化

映射规则：特征 v_i = round(512·v_f)（K1=512，浮点值 1.0 映射到 512，int16 有效域 [-32768, 32767] 对应浮点 [-64.0, 63.998]，足够覆盖推理取值）；权重/偏置以 K2=8192 量化。卷积推导为 y_i = clip((conv(x_i, w_i) + b_i·K1)/K2, -32768, 32767)，累加器用 int32，未观察到溢出；非线性 Sigmoid 用预计算查找表（任意 int16 输入映射到输出）。整个过程训练后直接整数化，无需重训。跨设备实验（A100 编码、RTX 2080Ti 解码）：浮点非确定性误差逐帧累积，约 30 帧后出现可见伪影并最终导致熵解码崩溃；int16 完全消除漂移。RD 代价约 3%（YUV420 平均 BD-Rate 从 -21.0% 到 -18.3%）。

## 4. 实验结果

测试口径：HEVC B–E、UVG、MCL-JCV；全帧低延迟、仅首帧 intra（intra-period=-1）；与传统编码器（HM/VTM/ECM 官方 low-delay 配置）对比时，所有 NVC 一律用**真实二进制码流（含头信息）**重新测试而非估计熵——因此 DCVC-FM/DC 数值与其原文略有差异。速度为 A100（AMD EPYC 7V13）上 1920×1080、跨 qp 平均延迟。

## 5. 消融要点

- **通道缩减实验**：C 缩减使 Pcomp 二次下降，推理时间近似线性下降——直接证据表明计算复杂度不是主瓶颈（linear 加速来自 Psize 随 C 线性缩小）。
- **独立因子控制**：高算力基线降 Psize 收益最大，低算力基线降 Pnum 收益最大——不同模块应采用不同加速策略。
- **latent 尺度（等 MACs 对比）**：1/8 单尺度提速 3.6×、BD-Rate +0.3%；1/2 因感受野受限性能退化；1/16 因 latent 容量（2·H·W < 3·H·W）性能退化。
- **隐式 vs 显式运动建模**（MCL-JCV，按 SEA-RAFT 运动幅度分组）：平均 +2.1%（大运动 +3.2% / 小运动 -0.4% / 场景切换 -4.7%），编码时间 8.0 ms vs 27.2 ms（3.4×）。
- **超先验模块库**：替代单一 factorized 模块后 UVG 节省约 3.4% 比特。
- **整数化**：fp16→int16 约 3% BD-Rate 代价（-21.0%→-18.3%），跨设备（A100 编 / 2080Ti 解）漂移完全消除。
- **并行编码**：编码 +12%、解码 +9%。
- **逐模块复杂度**（1080p 单帧、A100）：Feature Extractor 2.4 ms / 53.0 kMACs/px，Entropy Model 2.4 ms / 31.5，Recon Generation 2.2 ms / 56.4，Encoder 1.4 ms / 30.1，Decoder 1.4 ms / 34.0（流水线跳过部分模块，故延迟之和大于整体延迟）。

## 6. 贡献与启示

- **概念贡献**：首次在 NVC 中系统提出并实证“操作复杂度（Psize/Pnum）优先于计算复杂度”的加速视角，为“低 MACs 却慢”的自回归熵模型、多层运动分支等反例给出统一解释。这为后续高效 NVC 设计提供了明确的优先级：先减模块数与张量尺寸，再谈 MACs。
- **方法论**：算力再分配——删除运动支路（Pnum）+ 单尺度 1/8 latent（Psize），把算力集中给帧编码模块，形成“少而厚”的结构；1/8 尺度下感受野反超渐进下采样，说明单尺度并非单纯牺牲，时空建模反而受益。
- **工程价值**：单模型同时具备跨设备一致性 + 连续码控 + 层级质量 + YUV/RGB 双色彩空间，四项实用性能力此前从未同时实现；int16 整数化训练无关、K1=512/K2=8192 的定点方案和 LUT-Sigmoid 可直接迁移；熵编码 CPU/GPU 并行、编码侧跳过重建模块等流水线技巧有普适参考价值。
- **性能标杆**：消费级 2080Ti 上 1080p 30fps 编解码且 -21% vs VTM，是 NVC 走向实际部署的标志性结果；Large 版本（812G MACs、89.3/73.4 fps）证明该设计在同算力预算下 RD 上限更高（-30.8% vs FM 的 -21.3%）。
- **局限**（论文自述）：int16 在当代 GPU 上因缺乏专用支持反而慢于 fp16，跨设备一致性与速度暂时不可兼得；小模型高码率段（约 40 dB 以上）容量受限需 Large 版本补足；操作复杂度目前靠控制变量实验定性刻画，尚无解析度量模型，跨硬件的定量预测仍是开放问题。

## 7. 与其他论文的联系

- **MLVC（arXiv:2606.28027）**：DCVC-RT 的直接后继性工作。其出发点正是本文实用化路线在 NPU 生态的延伸：发现 DCVC-RT 这类以 scale/qp 条件化参数（module bank 向量）做码控的方案，在 NPU 跨平台熵解码时会崩溃，改为经 hyperprior 显式传输 scale 参数，并用 Gated Memory/ReGLU/LTR 恢复码率损失，首次在 Apple/Intel/Qualcomm NPU 上以 100 FPS 跑通 NVC 且 MOS 超 HEVC-QSV 70%+。可视为本文“实用性四件套”在非 GPU 硬件上的修正与验证。
- **NVRC（arXiv:2409.07414）/ NVRC++（arXiv:2608.28163）**：INR 路线与本文构成对照。本文 Related Work 明确把 INR 类方法归为“解码高效但编码需逐实例优化”的路线，DCVC-RT 则以非 overfitting 的前馈模型同时做到编解码实时。NVRC++ 用多个高分辨率 feature grid 把复杂度与质量解耦、四档单模型覆盖全码率区间，与 DCVC-RT 小/大模型分级（385G/812G MACs）及 64→128 码率点插值在“单模型全码率覆盖”目标上呼应，但路线（INR 表示 vs 条件编码）相反。
- **Efficient Contextformer（arXiv:2306.14287）**：问题同源的图像侧平行工作。本文第 1、3 节点名自回归熵模型“低算力但频繁函数调用”是操作开销的典型来源；eContextformer 恰是在图像压缩中用空-通道窗口注意力替代串行自回归上下文（解码提速约 210×、复杂度降约 145×），同样是“以并行结构换操作复杂度”，佐证了本文操作复杂度视角在神经压缩领域的普适性。
