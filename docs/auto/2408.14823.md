# LapisGS: Layered Progressive 3D Gaussian Splatting for Adaptive Streaming

> Yuang Shi, Géraldine Morin, Simone Gasparini, Wei Tsang Ooi. *arXiv:2408.14823v2 (2024-08-27)*

## 1. 背景与动机

3D Gaussian Splatting（3DGS）以显式高斯基元 + tile 光栅化 α-blending 实现了照片级实时新视角合成，成为 XR / 云游戏等 3D 在线世界的主流表达。但其模型体量（原始 3DGS 常达数百 MB）与异构终端算力、动态网络带宽之间存在根本矛盾。已有压缩路线（LightGaussian 剪枝、Compact3D 向量量化、HAC 上下文熵编码、自组织高斯网格等）面向"单点码率-质量"优化，产出的是**单一尺度**的静态模型，无法响应流式场景中带宽与设备能力的连续变化。

流媒体领域的经典答案是**分层可扩展编码**（H.264/AVC SVC 一脉）：base layer 保证基本质量，enhancement layer 逐步精化，客户端按可用带宽截断接收。将这一范式迁移到 3DGS，自然导向 Level-of-Detail（LOD）分层表示。但现有 3DGS 层级化工作（Octree-GS 的八叉树锚点、Kerbl et al. 的 splat 合并树、CityGaussian 的分块 + LightGaussian 逐级剪枝、Multi-scale GS 的反走样多尺度层）本质上是**基于空间剖分的层级**，论文指出其在流式场景下有三个结构性缺陷：

1. **层级不显式定义质量等级**：树遍历选择 splat 才能构成一个 LOD，计算开销大、对快速变化的网络条件适应性差；
2. **层级间无共享内容**：每个 LOD 由独立的锚点 splat 集合表示，层间无相关性，阻碍渐进传输，也无法做逐区域（而非逐 chunk）的灵活细节调节——后者正是 foveated / distance-aware 渲染所需；
3. **冗余编码导致体积膨胀**：各层独立重复编码相似视觉信息，全局与中间模型尺寸都显著增大（论文图 1 给出动机性数据：单尺度 103.8 MB；multiscale 四模型累计 103.8 MB；分层渐进模型四层累计 59.9 MB）。

因此论文提出 LapisGS：一个**以质量等级（而非空间块）为轴的累积式分层 3DGS**，自底向上逐级训练，层间显式共享视觉信息，天然对齐自适应流式的"base + enhancement"语义。从音视频系统的视角看，这是把 SVC 的码率可扩展性概念在 3DGS 显式表示上重新落地，面向的是 volumetric/3D 内容分发链路，而非传统的图像/视频编码。

## 2. 方法总览

LapisGS 的核心是把 3DGS 的训练重组织为**按分辨率递增的渐进式多阶段训练**，产出 $\{G_0, \{\Delta G_i\}_{i=1}^N\}$ 的分层模型：

- **图像金字塔驱动**：对全分辨率多视角图像集 $D_N$ 逐级 2× 降采样构造 $\{D_i\}_{i=0}^N$（每级分辨率减半），共 N+1 个质量等级 $L_0 \ldots L_N$（实验中 N=3，对应 8×/4×/2×/1×）。
- **基底 + 增量层**：先在最低分辨率 $D_0$ 上训练 base layer $G_0$（粗场景布局、低频特征）；随后每级在 $D_i$ 上训练 enhancement layer $\Delta G_i$，第 i 级的完整表示为 $G_i = G_0 + \sum_{k=1}^i \Delta G_k$。逐级渲染显示 $\Delta G$ 集中捕获高频细节，且因低频已被前级覆盖，收敛更快、跨级冗余更小。
- **动态不透明度优化**：训练 $\Delta G_i$ 时，冻结前级所有参数（位置、协方差、SH 颜色），**仅保留不透明度可训练**。由于 α-blending 中 splat 贡献是加性且由 opacity 加权，调 opacity 可重分配层间贡献而不改变任何空间结构——这是层间相干性与免重编码的关键。
- **占用图（occupancy map）**：每级维护一张 $O_i$ 追踪各 splat 的 opacity，低于阈值 0.005（沿用原 3DGS 剪枝默认值）的 splat 在流送与渲染时剔除；且阈值本身可作为码率旋钮实现自适应比特率选择。
- **连续层级过渡**：目标分辨率 $r_t$ 落在相邻层 $L_i, L_{i+1}$ 之间时，按连续插值因子 $t(r_t) = (r_t - r_i)/(r_{i+1} - r_i)$ 对 splat opacity 线性插值，实现无 popping 的平滑质量过渡，并支撑 splat 粒度的 foveated / distance-aware 视图自适应渲染。

## 3. 关键设计

**（1）累积式分层 vs 空间离散分层——架构层面**
树/八叉树层级中，LOD 是"从层级中选出的 splat 子集"，质量维度隐式、离散；LapisGS 中 LOD 就是"前 i+1 层之和"，质量维度显式、累积。这一差异直接决定流式语义：前者需要流决策器在树中检索构造 LOD（额外时延与决策复杂度），后者 base/enhancement 与 SVC 完全同构——先发 $G_0$，带宽富余再追加 $\Delta G_i$，接收即可增量渲染，且任意中间态都是合法模型。同时 splat 级 opacity 调节天然支持空间上非均匀的质量分配（注视区高层、外围低层），而 chunk 式结构只能以块为单位切换，且块边界与墙体、立柱等任意朝向的场景元素难以对齐，切换时产生 popping。

**（2）为何只优化前级 opacity——机理层面**
这是全文最核心的设计判断。三点依据：（a）α-blending 的贡献可分解性：每个 splat 对像素的贡献是加性的、被 $\sigma \cdot G'(x')$ 加权，因此调 opacity 等价于在不动几何的前提下重标定各层贡献；（b）空间不变性：与位置/尺度等属性不同，opacity 变化不改变场景空间信息，保证分层结构在训练中稳定、前级学习到的特征不被破坏；（c）免重编码：低层不需要随高层训练回传重写，流送中已发送的 base layer 永久有效。代价是低层中无法表达高频的 splat 若继续以高 opacity 参与渲染会污染高层结果——动态 opacity 优化恰好让这些"低层"splat 的 opacity 在高层训练中被压低，其重要性下降由 occupancy map 捕捉并在流送/渲染中剔除，形成"贡献衰减 → 标记 → 剔除"的紧凑化闭环。

**（3）损失函数的针对性设置**
每级损失为 L1 + D-SSIM 组合，但 λ 取 0.2，即 **80% 权重给 D-SSIM**（式 3）。原因：L1 对不改变结构的模糊与低分辨率伪影不敏感，在渐进管线中会导致过早收敛、低层 splat 得不到更新与致密化。论文明确说明这是相对 FreGS 式频率正则化的一种简单替代，频率正则化与本文方法正交、可叠加，此处不做展开。这一"用 SSIM 主导保结构性"的选择也是后文放弃 PSNR 评测（理由同为对模糊不敏感）的一致性延伸。

**（4）连续插值与视图自适应渲染**
层级过渡利用了 opacity 的可加性与人眼对渐变强度变化低敏感的特性：对介于两级分辨率间的目标，按式 (4) 逐 splat 插值 opacity，即可在渲染管线零改动的情况下产生连续的质量渐变（相对而言，树结构要么做图像域线性插值——Octree-GS 路线，要么做 splat 插值但仅限树内父子之间）。更进一步，opacity 本身可按视角距离/注视位置连续调制，实现 splat-wise 的质量场，这是离散 LOD 无法提供的操作原语。

**工程含义**：整个方案基于官方 3DGS 代码修改，训练超参数跨阶段一致，单卡 A100 完成训练；对现有光栅化渲染器无需任何修改（层级过渡只是改 opacity 输入），部署摩擦低。剥离（剔除透明 splat）在流送与渲染两侧同时省算力与存储——因为渲染成本近似正比于参与排序/混合的 splat 数。

## 4. 实验结果

**设置**：19 个物体/真实场景，覆盖 Synthetic Blender、Mip-NeRF360、Tanks&Temples、Deep Blending；每套数据按 2×/4×/8× 降采样构成多尺度。指标为 SSIM、LPIPS 与**归一化模型尺寸**（各场景内除以最大模型尺寸，落在 (0,1]）；明确排除 PSNR（像素级误差对模糊与低分辨率伪影不敏感）。三个对比方法：**Single**（全分辨率单模型多尺度渲染）、**Multiscale**（每尺度独立训练四个模型，质量上界，对应树式离散层级）、**Downsample**（Fan et al. 的 opacity×scale 显著性打分对全分辨率模型降采样，下界，对应传统点云采样式 LOD）。

| 数据集 | 方法 | L1 SSIM / Size | L3 SSIM / LPIPS / Size |

| Blender | Multiscale | 0.980 / 0.272 | 0.969 / 0.027 / 1.000 |
| Blender | LapisGS | 0.981 / 0.141 | 0.970 / 0.044 / 0.430 |
| Mip-NeRF360 | Multiscale | 0.947 / 0.531 | 0.918 / 0.124 / 1.000 |
| Mip-NeRF360 | LapisGS | 0.936 / 0.413 | 0.925 / 0.161 / 0.568 |

| Tanks&Temples | LapisGS | 0.942 / 0.241 | 0.916 / 0.163 / 0.608 |
| Deep Blending | Multiscale | 0.967 / 0.611 | 0.959 / 0.171 / 1.000 |
| Deep Blending | LapisGS | 0.961 / 0.431 | 0.951 / 0.219 / 0.544 |

相对 Multiscale 的尺寸差（论文以相对新模型尺寸的负百分比表达，越负减得越多）：Blender L1/L2/L3 为 −92.91%/−114.29%/−132.56%；Mip-NeRF360 为 −28.57%/−50.58%/−76.06%；T&T 为 −12.86%/−24.53%/−64.47%；DB 为 −41.76%/−68.71%/−83.82%。即**在 L3 端 LapisGS 以不到 Multiscale 一半的尺寸达到 SSIM 持平甚至略优（360、DB 的 SSIM 反超）**，LPIPS 略差（Blender L3 0.044 vs 0.027）——感知质量在最高层存在小幅让渡，换取最高 2.33× 的全局尺寸缩减。

四个关键结论（均带论文口径）：
1. **Downsample 全面崩坏**：直接减 splat 不重训，无法保持高斯各向异性分布下的保真度，质量随尺寸下降显著劣化（如 360 数据集 L0 仅 SSIM 0.548），证明传统点云采样式 LOD 不适用于 3DGS。
2. **对 Single 的优势**：低分辨率端最高 SSIM 提升 50.71%、LPIPS 改善 286.53%，同时模型仅为原尺寸的 23%——单尺度模型在不针对各尺度优化时无法兼顾两端。
3. **LapisGS 在全部数据集、全部尺度上尺寸最小**，且该缩减同时对应渲染时间下降（splat 数减少）。
4. 定性对比（Garden 等场景）显示 LapisGS 消除了 Downsample/Single 的常见伪影，视觉上与 Multiscale 相当（如 Garden L0–L3 SSIM 依次 0.95/0.94/0.96/0.96，对应尺寸差 −25.76%/−55.27%/−75.15%）。

## 5. 消融要点

唯一消融为 **Freeze 变体**：训练增强层时冻结前级全部参数（含 opacity），以隔离动态不透明度优化的贡献。四个数据集上 LapisGS 相对 Freeze 的平均差（表 5）：

| 数据集 | ΔSSIM ↑ | ΔLPIPS ↓ | ΔSize ↓ |
|---|---|---|---|
| Synthetic Blender | 0.82% | −26.74% | −118.90% |
| Mip-NeRF360 | 4.61% | −22.34% | −142.19% |
| Tanks&Temples | 5.01% | −32.31% | −123.10% |
| Deep Blending | 1.71% | −12.28% | −201.46% |

结论：无 opacity 优化时，低层中无法表达高频特征的 splat 持续以高贡献干扰高层表示，模型被迫追加 splat 补偿，导致体积大幅膨胀与质量下降；动态 opacity 优化通过压低这些 splat 的贡献并经 occupancy map 剔除，同时收紧了尺寸与保真度。逐场景数据（补充材料表 6–9）显示增益随层级升高而放大，极端案例如 Bonsai L3 尺寸差 −400.09%、Flowers L3 SSIM 差 +26.00%，但 Blender 多个场景在 L3 出现 LPIPS 反向（Lego +43.6%、Ficus +108.65%）——说明 opacity 优化在高层的感知收益并非一致为正，存在场景依赖的权衡。

## 6. 贡献与启示

**贡献**：
1. 首个明确以自适应流式为目标、把多 LOD 编码进**单一分层模型**的渐进式 3DGS 表示：层级即质量等级，base/enhancement 语义与 SVC 同构，接收端渐进渲染、层间共享内容消除冗余编码；
2. 动态不透明度优化 + 占用图管理：在不破坏分层结构与空间信息的前提下完成层间贡献重分配与 splat 级剪枝，是尺寸收益的主要来源（消融证实）；
3. 免额外模型的平滑层级过渡与 splat 粒度视图自适应渲染能力；
4. 跨四数据集验证：质量逼近"每尺度独立训练"上界的同时最高 2.33× 尺寸缩减，对 Single 低分辨率端 SSIM +50.71% / LPIPS +286.53% 而尺寸仅 23%。

**启示与局限**：
- 对 3D 流媒体工程而言，"以质量为轴的累积分层"给出了一条区别于树式空间层级的替代路线：LOD 选择退化为简单的层累加与 opacity 阈值/插值，流决策复杂度极低，天然适配 DASH 类分段传输。作者团队确已在此之上构建首个 DASH 式动态 3DGS 流系统（MMSys'25 的 LTS），并指出带宽波动下的实测评估超出本文范围。
- opacity 阈值是现成的连续码率旋钮，但目前未给出 RD 曲线式系统刻画；L3 端 LPIPS 相对 Multiscale 有小幅让渡、消融中高层 LPIPS 增益场景不一致，提示感知质量维度仍有优化空间。
- 方法限于静态场景；动态元素与实时更新是明确的未竟方向。渐进训练虽加速收敛，但整体训练仍需逐级进行（A100 上多阶段），离线成本与在线收益的权衡值得注意。
- 与音视频链路的接口意义：LapisGS 处于 volumetric 内容分发的"表示层"，其分层位流可直接对接自适应比特率控制逻辑（类比 SVC/H.265 分层码流的带宽自适应），下游可与终端渲染能力分级、QoE 驱动的码率分配（作者前作 QV4、V-PCC 流式系列）串联成完整 3D 流媒体管线。

## 7. 与其他论文的联系

- **paper:arxiv:2611.04498｜3DGS-VBench+ 与 3DGSV-Assessor**：LapisGS 在评估上采用 SSIM/LPIPS 并明确弃用 PSNR（对模糊不敏感），其分层/渐进压缩类 3DGS 输出恰是该工作所基准化的对象类型——3DGS 视频质量的多维主客观评估（3036 个 3DGS 视频、9108 个 MOS）可作为 LapisGS 这类质量-尺寸权衡表示更系统的感知评测手段，尤其在 L3 端 LPIPS 出现让渡的场景下。
- **paper:arxiv:2511.06953｜GFix**：LapisGS 的 enhancement layer 承担高频细节恢复，而 GFix 证明感知增强（单步扩散模型增强 3DGS 视频压缩，较 GSVC 最多省 72.1% LPIPS BD-rate）可在压缩表示之上后置进行；两者在"低码率下保感知质量"的目标上互补——LapisGS 管层间结构冗余，GFix 管残差感知修复，存在叠加于分层 3DGS 流式输出的组合空间。
- **paper:arxiv:2609.31509｜ClearGS**：同为从多视角视频出发的 3DGS 重建工作；ClearGS 关注输入侧画质混杂的鲁棒重建（可靠性感知视图分配），LapisGS 则假设输入多视角集干净、关注输出侧的分层与流式紧凑性。上游输入质量退化的场景中，ClearGS 式的预处理可作为 LapisGS 渐进训练金字塔（各级降采样同样会继承输入退化）的前置保障。
