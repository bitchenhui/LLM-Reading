# TGR-EvoDAG: A DAG-based Multi-Agent Code Evolution Framework for Generative Recommendation on Tencent

## 1. 背景与动机

本文处理的问题是：LLM 智能体驱动的递归自我改进（RSI）/代码演化，如何作用于生成式推荐（Generative Recommendation, GR）的级联训练管线。

论文先指出现有两条路线的结构性矛盾。通用代码演化框架（AlphaEvolve、DeepEvolve、CORAL、Arbor 等）具备成熟的搜索机制——种群式多分支探索与跨分支合并、树/图结构——但缺乏领域反馈信号；推荐专用演化框架则重反馈（模拟用户、诊断探针）而搜索原始：SERS（已部署于 YouTube 生产系统）只是固定基线上的 fan-out/fan-in，EvoRec 逐轮贪心线性推进只留单最优，Self-EvolveRec 仅从精英档案采样单亲本，均不维护、不合并并行分支。

传统序列推荐是端到端模型：改动触发均匀代价的全量重训、指标即时反馈，简单搜索尚可容忍。GR 则是三级联管线：Stage I 语义 ID 词元化（RQ-VAE/RQ-K-means 类）→ Stage II 生成式预训练（seq2seq Transformer + 层级交叉熵）→ Stage III 对齐后训练（偏好优化/RL）。论文给出的重训成本画像高度不对称：以 Stage I 为 1.00× GPU-hour 基准，Stage II 约 0.42×、Stage III 仅 0.11×——改词元器强迫全管线重训，改对齐只需重跑末端。

在此基础上，论文形式化了“朴素整合必然失败”的两个根因：(1) 成本盲：通用搜索对所有候选等权评估，不区分改动触达的阶段，会在昂贵的上游探索上系统性耗尽预算；(2) 短视评估：GR 各阶段紧耦合，上游创新几乎必然与未适配的下游不兼容而暂时掉点，按即时分数剪枝会系统性丢弃具备“延迟收益”的上游创新。并行工作 Auto-RecSys 聚焦长时实验的工程编排（持久状态、失败恢复、人审检查点），搜索仍线性推进、无 GPU-hour 预算与跨分支合并，论文将其定位为互补而非竞争。

工程背景：本文属腾讯 TGR 生成式推荐系列，TGR-EvoDAG 已作为内部 Uppimo 平台的演化引擎内核产品化。从音视频上下游看（本笔记定位）：GR 的语义 ID 词元化直接依赖多模态内容理解——种子代码用 LLaMA-3.1-8B 抽取物品文本表示，工业部署中物品文本还拼接多模态 LLM 生成的物品图像 caption；落地平台为日活超千万的商业媒体内容分发场景，是典型的多媒体内容推荐链路。

## 2. 方法总览

TGR-EvoDAG 将演化历史显式组织为 Code DAG。全局搜索状态 S(t)=(G(t), b(t))，其中 G(t)=(V,E) 为当前 DAG，b(t) 为剩余 GPU-hour 预算。每个节点 v_i 是自包含实验记录，含三类结构化属性：Provenance（父本集 P_i、算子 o_i∈{EXPLORE, MUTATE, MERGE}、假设 H_i、分支状态 Q_i）；Artifacts（增量改动 Δ_i、可执行代码快照 B_i、词表/checkpoint 等 A_i）；Empirical Execution（验证反馈 F_i、蒸馏教训 D_i、实测成本 C_i）。边由派生依赖自然诱导；新节点只从已评估节点派生且不改写祖先，DAG 性质有结构性保证。

单轮扩展流程：三个搜索算子之一生成子节点——EXPLORE 从单亲本开出根本性新方向，MUTATE 保持亲本核心假设做局部精调（损失权重、超参、采样策略），MERGE 以多亲本（r≥2）合成互补改进——随后经五阶段/七智能体流水线执行：① 阶段感知的算子与亲本选择；② Architect–Critic 假设开发（结构化蓝图 + 一致性/可测性校验循环）；③ Coder–Reviewer 实现与审查（隔离工作区、静态分析、防数据泄漏、跨阶段兼容性、MERGE 节点需校验各分支机制集成后仍功能有效）；④ 标准化环境评估与 Distiller 教训蒸馏；⑤ Pruner 拓扑控制与主动适配。智能体间只通过结构化 JSON 记录通信，单次调用约束为一条可解析记录，解析失败即丢弃重发而非修复，保证节点属性全部机器可校验。

种子代码库基于 APAO 官方实现构建，含四个解耦模块（物品词元化、backbone、预训练目标、可插拔后训练目标），共享同一 data loader 与 beam-search 评估器；数据层以上（含词元化模块）全部作为可变异代码暴露，候选可重拟合量化器、改层数/码本/量化算法，代价是下游重训。后训练变体覆盖主流对齐设计空间：SDPO（序列级 softmax 加权多负例 DPO）、SPRec（自博弈，用自身历史输出作负例去过滤气泡偏置）、ReReGRPO（受限束搜索采样候选 + 规则/排序混合奖励的 GRPO）、APAO（前缀级监督，前缀权重经指数梯度更新实现自适应最差前缀优化），构成演化可重组的算法先验。

## 3. 关键设计

**阶段感知成本规划。** 每个已评估节点按 Stage I/II/III 记录实测耗时，形成真实的不对称成本画像；Operator Selector 以结构化 JSON 声明 target_stage 与 training_scope，据此在执行前估算预期 GPU-hour 成本 C_c，与预期收益权衡后做预算决策——典型策略是将强迫全管线重训的上游改动推迟到较廉价的下游架构充分成熟之后。预算记账的严谨性值得注意：轮次实际扣减的是环境按阶段实测回收的 C_c，估计值仅用于决策；评审失败或中断的轮次计 τ_fail（失败前实测 GPU-hour），使“反复提出不可执行候选”无法零成本试错；LLM token 消耗单独记账、不占 b(t)。

**主动下游协同适配。** Pruner 是搜索路由器而非简单过滤器，输出两种改变搜索的标签态：[Pruned]（不可执行/违反协议的代码、item↔code 映射破坏、无可诊断路径的指标崩塌）永久掩蔽子树，对 Operator Selector 不可见；[Needs-Downstream-Adaptation]（由词元化或预训练等上游改动导致的指标回退）——后续 Selector 提示被严格条件化于该标签：冻结上游参数、强制子节点变异下游结构以恢复跨阶段兼容。关键语义在于：通过评审并产出有效 checkpoint 的节点即使相对父本回退也保持默认可选状态，因为“上游改动的即时回退”正是需要下游适配的信号而非弃用信号。

**MERGE 的上下文工程。** 多亲本聚合各分支假设、代码库与验证反馈，但不注入完整代码快照：每个亲本被序列化为相对 DAG 最低公共祖先的 unified diff，并配对结构化假设 H 与教训 D，在上下文窗口内保留化解跨分支语义冲突与接口依赖所需的信息；智能体任务为识别互补机制、解决冲突、在协同化假设下集成为统一功能代码库。

**三通道诊断反馈。** 通道一为离线验证指标（Hit@K/NDCG@K，束搜索 beam=20），对所有框架开放，且反馈包同时携带最终模型值与分阶段值支持阶段级归因。通道二为确定性数学探针，四族：sid_generation（逐层熵/置信度、top-5 质量、前缀多样性、逐层分支因子、束前缀崩塌率——诊断粗层崩塌与束塌缩）；sid_generation_raw（解除 trie 约束的原始解码行为、GT token 是否被干扰项掩埋）；output_behavior（重复率、跨类泛化、流行度偏置、品牌集中度）；representation_health（嵌入塌陷得分）。探针集可被候选扩展：以 agent.* 命名空间合并、只增不改，官方诊断面对各框架保持一致。通道三为定性用户诊断：模拟用户带三特质 persona（activity/conformity/diversity 各 LOW–HIGH），两步协议（item 级 align/misalign 二值判定 + 因果理由 → 列表级反馈捕捉误泛化与遗漏意图），Lead Analyst 聚合为单一宏观批评。两通道汇聚到统一 StandardDiagnosis schema（status/alignment/misalignment/overused_signals/missing_signals/primary_failure_mode/system_interpretation/diagnostic_signals_to_track/headline_metrics）；数学探针原始数值不直接喂给编码智能体，而由 Diagnosis Analyst 转译，且每条结论必须锚定具名指标数值（headline_metrics 带 3–6 个支撑值，可审计）。反馈包按阶段分字段（sft_*/post_*），仅当候选实际改动后训练才产出 post_* 字段。

**防泄漏评估设计。** 演化期用户诊断采样 50 个模拟用户，事后 Agent4Rec 评估用另外 100 个完全不重叠用户；评估指标只对预算内最终保留的单一 checkpoint 计算一次、绝不暴露给任何演化框架、绝不参与模型选择；评估模拟器的智能体种群、随机种子与交互模板固定且各框架共享，保证配对确定性比较。

**校验经济学。** Critic 只在四种硬条件下拒绝蓝图：违反硬不变量、无法产出可执行前向、no-op、未消化已记录教训而重提已证伪方向——拒绝一个蓝图耗一整轮智能体调用，接受一个平庸蓝图只耗一次评估，不对称代价设计刻意偏向放行。Distiller 拿到 Coder 工作区并先检查 Δ_c 再写教训，强制将结果归因到具体机制（某层/目标/初始化）而非复述假设。

## 4. 实验结果

**平台与协议。** 统一预算 B=24 GPU-hour；Claude CLI 外壳、推理全部路由 GLM-5.2；所有框架从同一 TIGER 种子（含四种后训练变体）出发，在 Amazon Office Products（|U|=4,905、|I|=2,420、|D|=53,258、平均序列长 10.86、密度 0.45%；five-core 过滤 + leave-one-out，历史截断 20 项）上演化——刻意选紧凑数据集使单次训练/验证循环低于 1 GPU-hour，从而 24 小时预算可容纳有意义的轮数。反馈分配：通用演化基线只得通道一；EvoRec/Self-EvolveRec/TGR-EvoDAG 及两个朴素整合基线（CORAL+Diag.、Arbor+Diag.）得全部三通道，以此解耦“反馈丰富度”与“搜索拓扑”两因素。模型选择仅用离线验证指标；用户诊断与 Agent4Rec 由 DeepSeek-v4-flash（temperature=0）驱动以保证确定性。测试集 leave-one-out 下每用户单 ground-truth，beam=20 时 top-20 恰为束输出、top-10 为其截断。

**工业迁移（RQ4）。** 冠军架构经 Uppimo 部署于日活超 1000 万的腾讯商业媒体平台（生产系统为检索–粗排–精排级联，演化模型作为新增检索通道）。离线：以 10 天连续工业日志（>1000 万交互、>30 万物品；正例为点击；物品文本 = 元数据 + 多模态 LLM 图像 caption；历史截断 500）从头训练，对 APAO 全指标提升：Hit@1 +12.16%、Hit@5 +4.83%、Hit@10 +1.52%、Hit@20 +0.57%、Hit@50 +0.25%。在线：14 天 A/B、5% 真实流量（服务 >100 万用户），采用 CUPED 方差缩减与分层 Benjamini–Hochberg FDR 控制（q≤0.05），系统整体 CTR +0.40%（p=0.019）显著；新通道贡献超过 10% 的独有曝光（既有通道完全未触达的相关物品），通道自身 CTR 约高于系统平均 13%。

## 5. 消融要点

**搜索机制消融（RQ2/RQ3）。** 受限变体：A（贪心：无多分支、任何回退即剪）、B（多精英采样、无跨分支合并）、C（完整搜索但无成本规划、各阶段预算均摊）。测试集与 Agent4Rec 指标均从 A→完整版单调上升：A 停在局部最优，短视贪心剪枝活不过下游协同适配所需的暂时回退；B 容忍延迟收益但看不见独立分支合并的复合增益；C 具备合并能力但成本盲——均摊预算耗尽后负担不起上游词元器重训，无法登顶；完整版靠阶段感知预算分诊攻克上游阶段解锁终端峰值。

**诊断信号因果性验证（RQ5，三个离线指标无行动方向的转折点）。** 其一，用户诊断：平台期模拟用户明确反馈推荐“过时”，驱动注入指数 recency bias；γ=0.9 弱先验无离线改进，诊断确认其被可学习权重吸收，改用 γ=0.5 强信号后突破平台期。其二，数学探针：定位出"smae coarse, wrong fine"（粗层命中、细层选错）的具体错误模式，直接催生粗层内硬负例对比损失——论文强调这是随机变异难以发现的设计。其三，分布探针：PSRQ 词元器灾难性掉点、纯离线搜索会将其丢弃时，探针精确定位 k-means 尺度失衡导致的语义 ID 碰撞率飙升至 65.7%，RMS 归一化修复后碰撞率回落至 1.0%，解锁词元器潜力。论文的总结论：离线指标只标记失败，诊断通道提供智能体执行定向修复所需的因果机制。

## 6. 贡献与启示

**核心贡献。** 其一，首次指出并形式化代码演化框架与级联 GR 管线的结构性失配（成本盲、短视评估），并给出对应机制——这不是又一篇 agentic ML 应用文，而是把“搜索机制必须适配训练管线的成本结构与耦合结构”作为一等研究对象。其二，在统一平台、统一种子、统一 24 GPU-hour 预算下首次完成完整 GR 管线（词元器→预训练→后训练）的全自主演化，并打通公开数据集到工业部署的迁移链路：公开数据上对最强非演化基线最高 +37.4%（NDCG@10），工业离线 Hit@1 +12.16%，在线 CTR +0.40% 统计显著。

**工程启示。** GPU-hour 作为一等预算资源的记账规范（实测扣减而非估计扣减、τ_fail 失败惩罚、token 分离记账）可直接移植到任何实验预算受限的自主优化系统；“回退即保留待适配”的分支状态语义与 LCA-diff 序列化的多亲本合并是领域无关设计；具名指标锚定的统一诊断 schema、探针只增不改的扩展策略、演化/评估用户群体隔离，为自主实验平台提供了可参考的防泄漏规范。论文明确展望 LLM 训练本身即级联多阶段，框架可自然扩展到多阶段 LLM 管线优化。

**批判性评估（本笔记观点）。** 演化在约 5k 用户的极小公开数据集上进行再迁移工业验证，所发现机制在更大规模公开基准上的直接演化未验证；在线增益 +0.40% CTR 在大流量场景属典型量级但幅度有限；LLM token 成本只记账不约束，token-GPU 联合预算优化未讨论；诊断探针体系是 GR/SID 专用设计，跨领域复用需重建探针族。

**与音视频技术的上下游关联（本笔记视角）。** 上游：GR 的语义 ID 质量直接受制于多模态内容表征——工业侧物品表示由文本元数据与多模态 LLM 图像 caption 拼接而成，音视频内容理解（封面/关键帧/标签抽取）是 SID 词元化的直接输入端；下游：落地即大规模商业媒体平台的内容分发，GR 作为新增检索通道改变曝光结构。方法论层面，音视频工程中大量同为级联、成本不对称、上下游紧耦合的管线——编码参数→转码→分发策略、ABR/QoE 调优、多阶段语音级联——正是“阶段感知成本分诊 + 延迟收益协同适配”机制的直接适用对象：上游编码改动同样需要下游码率/策略重调才能兑现收益，贪心逐轮搜索同样会短视丢弃此类改动。

## 7. 与其他论文的联系

- **paper:arxiv:2610.32026｜RSI-Opt**：同为“跨训练运行演化训练代码”的 RSI 范式，均以实验反馈为演化证据在多次训练运行间递归自我改进。差异在对象与结构：RSI-Opt 的元智能体演化优化器策略与代码库，TGR-EvoDAG 演化完整 GR 级联管线；且本文显式建模阶段不对称成本与跨阶段延迟收益，这是级联管线相对单段训练特有、RSI-Opt 未涉及的结构维度。
- **paper:arxiv:2611.11558｜InfraRSI**：同属 RSI 作用于训练基础设施/管线路线——InfraRSI 经五阶段验证工作流把开放式指令转化为分布式 LLM 训练优化（最高 2.75× 加速），TGR-EvoDAG 则把该思想从训练加速迁移到推荐算法架构发现。两者在长周期、高成本训练实验的验证工作流设计上互为参照，本文的阶段感知预算机制对 InfraRSI 场景同样必要。
- **paper:arxiv:2610.28201｜MaD-RSI**：MaD-RSI 提出“模型即数据”，把多模型失败轨迹作为训练证据直接优化跨异构 LLM 共享的智能体外壳。TGR-EvoDAG 的 DAG 节点同样把失败反馈（F_i）与证伪分支教训（D_i）沉淀为一等结构化数据并条件化后续搜索（Critic 拒绝“未消化教训重提已证伪方向”、Pruner 永久掩蔽证伪子树），两者在“以失败轨迹驱动外壳/框架演化”上同构，差别在本文证据粒度是阶段级训练实验而非多模型轨迹。
- **paper:arxiv:2611.10787｜TRUST**：互补关系。TRUST 用在线多重假设检验为 RSI 控制错误进化率并提供统计保证；TGR-EvoDAG 的搜索控制完全依赖 LLM 判断与结构化校验，演化过程本身无错误率统计控制——其统计严谨性仅体现在在线 A/B 环节（CUPED + 分层 BH，q≤0.05）。若将 TRUST 式检验嵌入节点评估环节，可为“保留待适配分支 vs 剪枝”这类关键路由决策提供置信度依据。
