## 1. 背景与动机

传统视频编码（H.264/H.265/VP8/VP9）依赖消除空间与时间冗余实现压缩，但视频中的冗余总量有限，压缩比存在由 Shannon 极限约束的上界；继续压码率只能丢弃非冗余内容，产生模糊与块效应。深度学习编解码器用神经网络替换手工模块，能建模更复杂的非线性运动与帧内相关性，但仍然运行在“去冗余”框架内，增益有限。另一条路线是神经增强流媒体（NAS/Nemo 系）：主动丢弃大部分信息（含非冗余信息），发送低码率视频并在接收端用超分网络恢复。其瓶颈在后处理网络的域差距——真实视频与训练集分布差异导致未见场景性能退化；对每段视频微调并传输网络虽然可缓解，但对短视频（如 TikTok 场景）网络传输开销不可接受。第三条路线是生成式流媒体（Face-vid2vid、Gemino、Reparo），发送侧提取 keypoints/运动场/离散 token，接收侧生成视频，码率极低但均为视频会议等人脸专用任务设计，缺乏通用性。

论文的核心动机来自 Stable Diffusion 的四个特性：(1) 互联网规模预训练（LAION-5B，58.5 亿图文对），学到几乎全部人眼视觉域的先验，天然规避域差距；(2) 生成能力极强——寥寥数词的 prompt 即可生成高分辨率复杂纹理图像，码率可从“图像尺度”降到“prompt 尺度”；(3) 关键洞察：**prompt 尺寸与生成分辨率解耦**——去噪过程不改变分辨率，生成图像分辨率只取决于输入噪声图的分辨率，而噪声图可任意采样；相比之下 VAE/H.265 等编码器式压缩必然随分辨率上升增加数据量，这是 prompt 表示与编码器表示的根本差异；(4) StreamDiffusion 等变体可达 100 FPS 实时生成，满足接收端实时播放。

但 SD 只定义了 prompt→图像的正向过程，没有图像→prompt 的逆过程。Captioning 或人工文本描述只能语义对齐、像素级差异巨大（即使人类描述也无法像素对齐）；ControlNet 只能对齐轮廓等结构，颜色纹理无法对齐；Textual Inversion 类工作从多图学习语义级 embedding，同样不保证像素对齐（Textual Inversion 用于图像压缩时像素对齐实际依赖低分辨率图作条件）。因此核心问题变成：**如何把真实视频帧反演为像素对齐的 prompt，并在此基础上构建可控码率、支持帧间压缩的流媒体系统**。

## 2. 方法总览

Promptus 是一个语义通信系统：发送端把帧反演为 prompt（替代视频编码），接收端用 Stable Diffusion 从 prompt 生成帧（替代解码）。系统由三个环环相扣的模块构成，分别对应三个技术挑战：

1. **像素对齐的 prompt 反演（梯度下降拟合框架）**：prompt 随机初始化，SD 据此生成一帧，计算与目标帧的像素级损失，反向传播求损失对 prompt 的梯度并迭代更新，直至损失充分小。SD 全程冻结，其先验知识通过梯度下降被“蒸馏”进 prompt。为使该框架可行，配套四个关键设计：单步去噪（SD 2.1 Turbo）避免展开长梯度链、以 text embedding 而非自然语言作 prompt 避开 CLIP 的不可微查表、以噪声化前一帧替代随机噪声作为去噪输入以缩短潜在空间距离、联合重建损失（MSE）与感知损失（LPIPS）兼顾对齐与锐度，外加 prompt 正则化约束 embedding 分布。

2. **码率控制（低秩分解 + 拟合感知量化）**：embedding prompt 是固定尺寸的浮点矩阵（如 1024×77、32-bit float），码率固定且高。Promptus 把 CANDECOMP/PARAFAC 分解的逆过程（c = u·v/√r，u 为 m×r、v 为 r×n）嵌入梯度下降，直接拟合低秩因子 u、v 而非先拟合再降维；秩 r 权衡表征能力与码率（参数量 ×r vs m×n）。再以可微伪量化把每个参数从 32 bit 压到 8 bit 且无质量损失。发送端预拟合多档秩的 prompt，按估计带宽选择最接近的档位传输。

3. **帧间压缩（插值感知拟合）**：prompt 逐帧独立拟合会使码率随帧率线性增长，且 prompt 矩阵形似随机噪声、无法用视频编码器压缩。利用“prompt 是高层语义、连续帧的 prompt 连续变化”这一性质，只稀疏传输关键帧 prompt，中间帧 prompt 由相邻关键帧 prompt 线性插值逼近；拟合时中间帧 prompt 作为中间变量，梯度经插值路径直接反传优化关键帧 prompt。

端到端数据形态为：发送端对关键帧拟合出低秩因子（u, v），8-bit 量化后稀疏发送；接收端反量化、重组为完整 embedding，对相邻关键帧 prompt 插值得到中间帧 prompt，配合自回归的噪声化前一帧，经 SD Turbo 单步去噪生成 latent，由轻量 TAESD 解码为像素帧。系统层面还有首帧 VAE 初始化、场景突变检测重置、低秩 ABR 等机制（§3.4）。

## 3. 关键设计

### 3.1 梯度下降式 prompt 拟合的四个组件与正则化

**单步去噪**。传统 SD 用 T 次迭代去噪（如 50 步），prompt 递归地影响生成结果，损失对 prompt 的梯度需展开全部去噪迭代，计算与显存开销不可行。Promptus 改用 SD 2.1 Turbo 的单步去噪，一次前向-反向即可完成梯度计算。代价是单步生成质量弱于完整 SD，但论文指出该质量损失可在端到端拟合中被补偿。

**embedding 作 prompt**。CLIP 文本编码涉及索引查表，不可微，梯度无法传回自然语言。Promptus 丢弃 CLIP，直接以连续 text embedding（1024×77 矩阵）作为条件，使前向全程可微。论文明确：prompt 本质是“引导生成的条件”，可以是文本、图像、音频、embedding 乃至 fMRI 信号，embedding 并不损失其作为 prompt 的资格；且生成分辨率只取决于噪声图尺寸、与 prompt 尺寸无关，分辨率解耦优势保留。

**噪声化前一帧**。将去噪过程理解为在 prompt 控制下于潜在空间中移动输入噪声点到目标图像点。单步去噪只能在潜在空间内移动有限距离，随机噪声离目标帧太远、一步无法到位，拟合收敛后生成帧仍有明显模糊、噪声伪影与细节错位。而视频中相邻帧在潜在空间中相近，故按 Nt = (1−γ)·Z_{t−1} + γ·N0 构造输入：Z_{t−1} 为前一帧 latent，N0 为固定噪声，γ=0.95（噪声占 95%、前一帧占 5%）。这一设计同时支撑了接收端自回归生成的误差分析——由于前帧信息只占 5%，单帧生成误差对后续帧几乎无传播放大。

**联合损失**。纯 MSE 倾向放弃误差较大的边缘与高频细节以压低整体像素误差，导致过度平滑；纯 LPIPS 追求主观质量但不保证逐像素一致。拟合损失取 D = α·D_rec + (1−α)·D_per，D_rec 为 MSE、D_per 为 LPIPS、α=0.8，兼顾像素对齐与锐度（论文可视化显示联合优化后生成帧与 GT 几乎一致，纯随机噪声或纯 MSE 的设置则分别残留噪声伪影与模糊）。

**Prompt 正则化**。即使有真实视频监督，拟合仍会偶发失败：随梯度下降推进，prompt 分布逐渐漂离 CLIP embedding 的分布，导致 SD 无法生成有意义的图像。为此加入 λ = ‖c − µ‖²，µ 为对大量文本统计得到的 CLIP embedding 均值（µ = −0.168），总损失 L = β·D + (1−β)·λ，β=0.9。其实质是把 prompt 拉住在其仍能驱动 SD 生成的嵌入流形附近。

### 3.2 低秩分解码率控制与拟合感知量化

码率控制沿“降维减参数量、量化减每参数比特”两轴展开。降维的关键选择是**端到端拟合低维 prompt，而非对拟合完成的完整 prompt 做事后 SVD/PCA**：后者只依据 prompt 自身数据分布降维，完全无视降维对生成结果的影响，必然损失质量。Promptus 把 c = u·v/√r 的组装过程作为可微中间层插入拟合图，c 不再被存储或直接优化，随机初始化并迭代更新的是 u、v——降维带来的表征损失在梯度下降中被端到端补偿。量化同理：采用可微伪量化（Q8BERT 式）嵌入拟合过程，自动补偿量化误差，实测 32 bit→8 bit 无质量损失。秩 r 是质量-码率的一阶控制量：r 越大表征能力越强、可拟合越多高频细节，但数据量 ×r 线性增长。

### 3.3 插值感知拟合的帧间压缩

直接把逐帧 prompt 重塑为矩阵用视频编码器压缩是无效的——prompt 形似随机噪声，无模式、无结构、无平滑区域，编码器无从下手。Promptus 的替代思路是利用 prompt 空间的连续性：只传关键帧（间隔 K，每 K 帧一个），中间帧 prompt 由相邻关键帧 prompt 线性插值。为保证插值出的 prompt 仍能生成有意义的帧，插值被纳入拟合过程：关键帧 prompt 随机初始化，中间帧 prompt 由插值计算得到、作为中间变量不直接优化，损失梯度经插值路径反传，直接优化关键帧 prompt。这等价于以“插值-生成”端到端质量为目标，主动把 prompt 空间中的帧轨迹线性化。论文展示插值结果既能保留细节也能逼近运动。场景突变时插值失效：Promptus 计算当前帧与前一帧的 latent 距离，超过阈值即判定突变，将后续内容按新视频处理（重新执行首帧初始化，突变前最后一帧补为关键帧并重新计数）。

### 3.4 流媒体系统两侧

**发送端**：(1) 首帧初始化——没有 Z₀ 时，用 VAE Encoder 把首帧自身映射到 latent 得 Z₀，按式加噪得 N₁；该带噪 Z₀ 随首帧 prompt 一并发送。(2) 场景突变重初始化如上。(3) 稀疏 prompt 流：仅关键帧 prompt 上行。(4) 低秩 ABR：预拟合多档秩的 prompt，按可用带宽选码率最接近的档位。重要工程特性：**prompt 不做熵编码**，码率可被精确设定（对比熵编码后只能估计码率的传统方案），从而能精确贴合带宽。

**接收端**：(1) 收到关键帧 i 的 prompt 后，先对关键帧 i−k 与 i 的 prompt 线性插值出中间 K−1 帧 prompt，再逐帧生成；每帧生成的 Z 加噪后作为下一帧输入噪声，形成自回归链。(2) 实时生成：生成流程五步（反量化、prompt 组装、prompt 插值、前帧加噪、SD 生成）中前四步均为线性计算、耗时可忽略，瓶颈在 SD；按 StreamDiffusion 的做法用 TAESD 替换 VAE Decoder、用 TensorRT 构建推理引擎，单帧总耗时 6.226 ms（4090D，512×512，秩 8），满足实时。

## 4. 实验结果

**设置**：四个域差异极大的数据集——QST（自然风景/人类活动）、UVG（长距户外+室内近景）、GTA-IM（3D 游戏）、Animerun（2D 动画），统一裁剪缩放至 512×512、30 FPS。基线四条：H.265；VAE（latent 变量用 H.265 编码做帧间压缩）；NAS（per-video 过拟合超分 DNN + 低分辨率视频，调两者控制总码率）；VQGAN（patch→VAE latent→按多域码本量化为 10-bit token 索引，调 patch 数控码率）。主指标 LPIPS（论文自定位为语义通信而非压缩任务，LPIPS 更贴近主观感知）。网络轨迹为真实采集的地铁/驾车/步行 2G/3G/4G trace，平均带宽 50–4000 kbps，单向时延 30–100 ms，Mahimahi 回放（队列 60，drop-tail）。

**码率-质量权衡（§5.2）**：秩从 4 提到 16（关键帧间隔=1），LPIPS 由 0.265 降至 0.221；秩=16 时间隔从 10 降到 1，LPIPS 由 0.274 降至 0.221。秩 4–32、间隔 2–8 的组合使码率覆盖 113–4284 kbps，实现可伸缩码率。同码率下配置不唯一：550 kbps 时“秩 8 + 间隔 4”（LPIPS 0.255）优于“秩 16 + 间隔 8”（LPIPS 0.264），故同码率下应优先缩小关键帧间隔。

**传输效率（§5.3）**：140/280/360/540 kbps 四档下 Promptus 的帧质量 CDF 全面左移。140 kbps 的 Promptus 平均 LPIPS 已优于 540 kbps 的 H.265，即对 H.265 有超过 4 倍带宽缩减。优势随码率下降扩大：

| 目标码率 | LPIPS 相对 VAE | 相对 H.265 | 相对 VQGAN |
|---|---|---|---|
| 540 kbps | −0.018 | −0.085 | −0.037 |
| 140 kbps | −0.139 | −0.118 | −0.046 |

机理解释：低码率下传统编码器用粗量化丢高频造成模糊/块效应；VAE 靠低维 latent 省码率、多数码率下优于 H.265，但极低码率下 latent 编码失真叠加 VAE Decoder 重建误差导致质量骤降；VQGAN 减少 token 同样是降表征容量，但没有梯度下降做质量补偿。Promptus 降码率时损失的是 prompt 表征能力（生成帧轻微错位），而 SD 生成先验仍保证锐度与细节，失真模式根本不同。

**跨域通用性（§5.4）**：四数据集平均 LPIPS 均低于多数基线；细节越丰富优势越大——细节稀少的 Animerun 上仅比 H.265 低 0.015（大面积纯色恰是 H.265 帧内预测/块划分/运动补偿的舒适区），细节丰富的 UVG 上差距扩大到 0.121。Animerun 上 Promptus 甚至不如 NAS（2D 动画是超分的强势域）。对手指、文字等 SD 本身难以生成的元素，端到端梯度拟合也能补偿生成器的固有缺陷。时域一致性（225 kbps，X-t 切片）显示生成运动与 GT 时域对齐、几乎无闪烁（另用盲视频 deflickering 后处理辅助），且没有 H.265 的 zig-zag 块效应。

**分辨率（§5.6）**：同一 prompt 配不同分辨率噪声图即可生成对应分辨率的近对齐图像；但低分辨率表现差（256×256 的 PSNR 最低），因为 SD 无法生成低分辨率图像——这是继承自生成器的反向限制。

**真实 trace（§5.7）**：平均 LPIPS 比 VAE/H.265/VQGAN/NAS 分别低 0.111/0.092/0.047/0.063；LPIPS>0.32 的严重失真帧比例仅 5.2%，而四个基线为 94.5%/96.9%/53.2%/98.2%。摘要在极低码率口径下报告：严重失真帧比例相对 VAE、H.265 分别下降 89.3% 与 91.7%。

**客观指标（§6，UVG 225 kbps）**：

| | H.265 | VAE | NAS | VQGAN | Promptus |
|---|---|---|---|---|---|
| PSNR ↑ | 32.685 | 28.008 | 33.466 | 25.740 | 30.378 |
| SSIM ↑ | 0.892 | 0.646 | 0.780 | 0.648 | 0.702 |
| LPIPS ↓ | 0.386 | 0.382 | 0.357 | 0.335 | **0.244** |

PSNR/SSIM 全面劣于 H.265 与 NAS，LPIPS 大幅领先——AIGC 模型对锐利纹理敏感而 PSNR/SSIM 偏向大面积平滑纹理，越锐利 PSNR 越低、越模糊 PSNR 越高的现象在此明确显形。

**开销（§5.9，Nvidia 4090D，512×512，秩 8，SD 867M 参数）**：接收端生成单帧分解如下（单位 ms）：反量化 0.016、prompt 组装 0.025、prompt 插值 0.013、前帧加噪 0.012、SD 生成 6.160、合计 6.226；生成显存 7846 MB。发送端反演每次迭代 150 ms，实践设定首帧（及新场景首帧）10000 次迭代、后续帧 500 次（按此推算约 1500 s/首帧、75 s/帧，离线量级）；反演显存 10 GB。选 SD 2.1 Turbo 而非 SDXL Turbo 是权衡：后者生成能力更强、拟合更易、可支持更高压缩比，但显存与时间开销更大。

## 5. 消融要点

**插值域消融（§5.8，以第 0、10 帧插值 1–9 帧）**：三种方案对比—— 端到端 latent 插值：去掉 U-Net、只留 VAE Decoder，在 latent 空间梯度拟合关键帧再线性插值——无法保持运动，出现空间重叠与鬼影，原因是相邻帧在 latent 空间**非线性连续**，线性插值无意义；这同时证明仅用 VAE 作反演生成器不可行——帧间压缩失效、逐帧传输带宽浪费。 端到端像素插值：对关键帧 GT 用 RIFE 估计中间帧——能保持运动，但遮挡、边缘、新出现物体处因错误匹配产生明显伪影。 prompt 插值：既保持运动又避免伪影、边缘锐利。结论：U-Net（扩散去噪）的作用是把帧从非线性连续的 latent 空间映射到线性连续的 prompt 空间，这是帧间压缩可行的前提，也是必须用完整 SD 而非仅 VAE Decoder 的根本原因。

**组件级定性消融（§3.1）**：随机噪声输入下即使损失收敛，生成帧仍有模糊、噪声伪影与细节不一致；噪声化前一帧解决距离问题；纯 MSE 损失导致过度平滑；两者与 LPIPS 感知项联合后生成帧接近 GT。prompt 正则化解决拟合偶发的分布漂移失败。

**收敛行为（§5.9 / 图 18 口径）**：新视频/新场景首帧从零拟合需数千次迭代收敛（示例中第二帧仅需 120 次迭代即达到首帧 2000 次迭代的视觉质量）——连续 prompt 空间为后续帧提供了充分场景先验，这是插值感知拟合带来的编码端加速副产品。

**参数敏感度（§5.2）**：质量随秩单调升、随关键帧间隔单调降；同码率下小间隔配置优于大间隔配置（550 kbps 例），系统决策应优先压间隔再提秩。

## 6. 贡献与启示

**贡献**：(1) 第一个以 prompt 反演替代视频编码、以 prompt 流替代视频流的系统尝试；(2) 梯度下降式 prompt 拟合框架，实现像素对齐反演（单步去噪 + embedding prompt + 噪声化前帧 + 联合损失 + 分布正则五个部件缺一不可）；(3) 完整流媒体系统（低秩 ABR、稀疏关键帧流、接收端实时生成），在四域数据集与真实弱网 trace 上验证。

**失真模式的范式转变**：传统/学习式编码器降码率的失真路径是“量化变粗→高频丢失→模糊/块效应”，感知质量断崖式劣化；Promptus 降码率（降秩）的失真路径是“表征容量不足→生成帧轻微错位但保持锐度”。这解释了码率越低优势越大（140 kbps 档 LPIPS 领先扩大到 0.118 vs H.265）以及严重失真帧比例的悬殊（5.2% vs 96.9%）。对工程而言，这意味着极低码率区间存在一条与编码器完全不同的 RD 曲线。

**码率可控性**：prompt 不熵编码、码率由（秩 r、间隔 K、量化位宽）解析决定，ABR 可精确打满带宽而非像熵编码方案只能逼近估计值——这是系统层被低估的实用优点。

**复杂度的非对称结构**：接收端 6.226 ms/帧实时、7.8 GB 显存；发送端反演 150 ms/迭代 × 500–10000 迭代，完全非实时。这决定了当前形态只能服务 VoD（DASH 大缓冲还能吸收插值等待后续关键帧的时延），直播/WebRTC/云游戏均不可用。论文自列的四条局限（发送端拟合非实时、插值引入额外时延、均匀关键帧在快变段近似差/平滑段浪费带宽、PSNR/SSIM 劣势）均源于此范式而非实现细节。

**指标口径的立场**：论文明确将自身定位为“高保真语义通信”而非视频压缩，以 LPIPS 为主指标；在 PSNR/SSIM 上劣于 H.265/NAS 是生成式方法的固有张力（锐利纹理 vs 平滑偏好），评估此类系统必须用感知指标族，否则结论会系统性反转。

## 7. 与其他论文的联系

- **paper:arxiv:2402.08934（Extreme Video Compression with Pre-trained Diffusion Models）**：同为“预训练扩散先验 + 解码端生成”的极低码率路线（该文低至 0.02 bpp、感知质量超 H.264/H.265）。关键差异在信息形态：该文解码端以已解码帧为条件自回归预测后续帧（帧预测式生成），Promptus 则把信息显式化为可梯度优化的连续 prompt 并以拟合保证像素对齐（prompt 容量式生成）。两者共同验证扩散先验在极低码率下维持感知质量的可行性，失真机制对照（预测漂移 vs 容量受限错位）有参考价值。

- **paper:arxiv:2604.08329（DiV-INR）**：同属“为预训练生成器寻找紧凑条件表示”的问题设定——DiV-INR 用 INR 参数化视频扩散模型的条件在 <0.05 bpp 下工作，Promptus 用低秩因子化 embedding 作条件并以端到端拟合控制容量。两者的码率控制本质都是“条件表示的容量→感知质量”通路，可与本文低秩秩 r 的权衡曲线互相印证。

- **paper:arxiv:2505.00335（NVTM）**：方法论同构——均为 per-content 梯度下降拟合紧凑表示的编码范式，均承受编码端迭代优化开销大、只适合离线/VoD 的结构性约束（Promptus 为 150 ms/迭代 × 数百至上万次迭代）。NVTM 以带运动信息的 2D 网格分解将 INR 编码提速 3 倍以上的思路，对降低 Promptus 发送端反演开销（论文自述的首要局限）有直接借鉴意义。

- **paper:arxiv:2607.23366（Codebook Capacity Governs Perceptual Quality）**：结论层面呼应。该文发现分层离散压缩中码本容量 K 而非空间分辨率主导 LPIPS；Promptus 的实验同样表明连续表示下秩 r（表征容量）是感知质量的一阶控制量、且降容量先表现为高频细节丢失而非画质崩坏。两者共同指向：生成式/学习式压缩中，表示容量参数是比分辨率更根本的感知质量控制轴，这可简化多分辨率/多档位部署。

- **paper:arxiv:2404.06620（Encoder-Quantization-Motion-based Video Quality Metrics）**：评估口径层面的关联。Promptus 依赖 LPIPS、在 PSNR/SSIM 上系统性劣势，生成式编解码的在线质量监控成为落地问题；而该类基于编码器/量化/运动码流特征的轻量实时指标依赖传统码流结构，对 prompt 流这种无码流语义的系统如何构造可实时计算的质量信号，是 Promptus 范式走向实用需补齐的一环。
