# Think, Prune, Train, Improve: Scaling Reasoning without Scaling Models

## 1. 背景与动机

本文属于 LLM 后训练/自训练方法类工作（非音视频核心类，按 LLM 训练领域标准评估，文末给出与音视频上下游的迁移关联）。出发点是推理型任务（数学、代码）的高质量训练数据瓶颈：公网数据边际收益递减，小模型（Gemma 2B/9B、LLaMA 1B 级）的主流后训练范式是“大模型蒸馏 + 推理链 SFT”，但蒸馏依赖教师模型存在，推理训练依赖外部数据集。作者提出的核心科学问题是：**小模型能否仅凭自生成数据学会推理**。

递归自训练的已知风险是 model collapse（Shumailov et al., Nature 2024：未过滤递归训练导致知识遗忘与幻觉）与 mode collapse（输出分布收窄、多样性下降）。作者的关键观察是：前述崩溃结论来自**无 ground truth 的开放文本生成**；而在终答可精确校验（数学 exact match）或可执行校验（代码测试）的任务上，“正确性剪枝”可以作为分布约束把递归 SFT 稳定下来。这一“域内存在廉价校验器”的前提，也是该方法向其他可验证指标领域（含音视频客观指标任务）迁移的门槛条件。

## 2. 方法总览

TPT（Think, Prune, Train）是一个三步闭环：

1. **Think**：以 CoT 提示（专家角色 + 分步推理要求 + 强制 `#### [Answer]` 终答格式）在温度 0.8 下对训练集每题生成 10 个解；
2. **Prune**：用 ground-truth 正确性过滤（GSM8K 为含格式的终答 exact match；CodeContests 为标准输入输出匹配）；
3. **Train**：从剪枝后样本池中随机采样固定规模子集（GSM8K 每轮 2000 条、CodeContests 每轮 1000 条，后者因数据集更小且模型准确率更低），对**当前模型**做单 epoch SFT，最多迭代 N=4 轮。

算法流程（Algorithm 1）：第 i 轮先以 f_{i-1} 微调 M_{i-1} 得 M_i；再用 M_i 对全部训练题各生成 10 解构成解集 S；施加剪枝策略 P；随机采样 f_i ⊂ S 进入下一轮。

两个方法论上最重要的设计约束：

- **数据规模跨轮恒定**：每轮每题只保留一个唯一样本，且每轮数据集**整体替换**而非累积。作者明确指出这是为了把“真正的迭代精化”与“数据集扩张带来的伪增益”解耦（针对 Gerstgrasser et al. 2024b 的批评——累积式递归训练的收益可能纯来自数据量）。结论是在严格恒定数据预算下迭代收益依然存在。
- **唯一选择机制是正确性剪枝**：不用 RL、不用学习型奖励模型、不用 DPO、不用外部纠正（对比 ReST 用学习奖励函数、LLaMA 3.1 用 DPO + 奖励模型 + ground truth、STaR 用反向 rationalization）。

实验对象：gemma2-2b-it、gemma2-9b-it、Llama-3.2-1B-Instruct、Llama-3.3-70B-Instruct（正文不同位置混用 LLaMA-3.1-70B/LLaMA-70B 指称 70B 模型，实验设置节明确为 3.3-70B-Instruct，数值以结果表口径为准）。SFT 配置：学习率 1e-6（Gemma）/ 1e-5（Llama），AdamW 默认权重衰减，单 epoch，10% 步数 warmup。评测：温度 0.7；GSM8K 取测试集 500 题子集，终答含格式的 exact match；CodeContests 取去除 image tag 的 140 题，标准输入输出判定。

## 3. 关键设计

**（a）SFT-on-pruned-data 是策略梯度的特例——本文的理论支点。** 在策略梯度框架 ∇J(πθ) = E_τ∼πθ[Σ_t ∇θ log πθ(a_t|s_t)·R(τ)] 中，状态为 token 前缀、动作为下一 token、奖励为二值稀疏（正例 +1 / 负例 −1）。作者利用**数学错误局部化**假设：正负解共享前缀、仅在少数分歧步上不同，则负例梯度与正例在这些步上等幅反号，于是

∇θ log π(x^w_{t+1}|x_{0:t}) − ∇θ log π(x^l_{t+1}|x_{0:t}) = 2∇θ log π(x^w_{t+1}|x_{0:t})

即“对正负例同时做策略梯度”退化为“仅对正例做 2 倍梯度的交叉熵 SFT”。工程含义：**正确性过滤 + SFT 本身就是隐式 RL，正确性即奖励信号**——在没有成熟 RL 基础设施（PPO 训练栈、奖励建模、KL 约束）的团队里，可以用“生成-校验-过滤-SFT”闭环近似可验证奖励 RL。该等价性的适用前提（错误局部化、奖励二值稀疏）在数学推理上成立，在长程开放任务上未验证。

**（b）与相关方法的机制差异。** 按“是否用 CoT / 是否仅依赖 ground-truth 剪枝 / 是否从已微调模型出发 / 是否多轮迭代”四维对比：TPT 四项全满足。LLaMA 3.1 的后训练在未剪枝自数据上训练曾导致性能退化，因而引入 SFT→DPO→再生成→剪枝的复杂管线；DeepSeek R1 依赖 RL 拒绝采样；ReST/ReST-EM 依赖学习型奖励或置信度加权；STaR 从 base 模型出发做拒绝采样 + 反向合理化，但不在改进后的模型上继续迭代。TPT 的贡献是把这个空间压缩到最简：**纯 SFT + 二值校验**，从而干净地隔离“结构化数据选择”这一单变量。

**（c）CoT 提示与校验器的格式耦合。** 附录 B.4 的提示模板强制“markdown 代码块内完整分步解 + 新行 `#### [Answer]`”，使终答抽取与 exact-match 校验零歧义。这是一个常被忽视的工程细节：**校验器的可靠性取决于提示端的格式约束**，二者需联合设计。

**（d）mode collapse 的正面处理。** 作者区分 model collapse（能力退化）与 mode collapse（分布收窄）：观察到 Pass@1 显著上升而 Pass@20/50 基本持平，说明模型在收敛到高置信正确解的同时未丧失采样多样性；并论证在正确性优先的域（数学/代码）中，这种“精确度换多样性”的偏置是可接受的。若多样性是目标，论文提供了 soft-positive 采样（保留通过部分测试的解）与数据累积两个备选旋钮（见消融）。

## 4. 实验结果

**4.1 合成数据规模（单轮 SFT，GSM8K，Gemma-2-2B）**：规模无单调增益，剪枝后 2B 自生成数据与 9B 蒸馏数据基本可比；人类原始解反而最差且随规模增大而下滑。

| 数据来源（剪枝） | 规模 | Pass@1(%) | Pass@20(%) |
|---|---|---|---|
| 基线 | — | 41.9 | 76.0 |
| 2B 自生成 | 4k | 54.8 | 82.6 |
| 2B 自生成 | 6k | 51.6 | 81.0 |
| 9B 蒸馏 | 2k | 54.0 | 83.8 |
| 9B 蒸馏 | 6k | 51.2 | 82.6 |
| 人类原始解 | 2k | 45.5 | 83.0 |
| 人类原始解 | 6k | 44.0 | 85.6 |

Gemma-2-9B 上自生成 1k/2k 分别为 80.5/81.1（基线 66.4）。CodeContests 上趋势更尖锐：2B 自数据从 1k 的 0.84% Pass@1 单调恶化到 4k 的 0.56%；人类数据从 1k 的 0.60% 跌至 6k 的 0.29%（基线 0.90%），作者归因于分布外效应。LeetCode 上 1k 规模 2B 自数据 14.65% Pass@1 反超 9B 数据的 12.82%（基线 13.66%）。

**4.2 递归自改进（TPT 主结果）**：GSM8K 上 Pass@1 持续上升、Pass@20 首轮后进入平台期；Correct@20（500 题中至少一解正确的题数）从 380 升至 416。

| 模型/阶段 | 数据源 | Pass@1(%) | Pass@20(%) |
|---|---|---|---|
| Gemma-2B 基线 | — | 41.9 | 76.0 |
| Init (M1) | 2B, 2k | 52.5 | 83.0 |
| Rec 2 (M3) | M2, 2k | 56.9 | 83.2 |
| Rec 3 (M4) | M3, 2k | 57.6 | 83.2 |
| Gemma-9B 基线 | — | 66.4 | 88.4 |
| Init (M1) | 9B, 2k | 81.1 | 90.0 |
| Rec 2 (M3) | M2, 2k | 82.4 | 90.2 |

Gemma-9B 的 82.4% 超过 LLaMA3.1-70B-Instruct 的 78%（论文口径）。CodeContests 上增益较弱：2B 四轮 Pass@1 从 0.90% 至 1.14%，Pass@50 在 7.14–9.20% 区间波动后回落至 7.85%（Correct@50 从 8 题至峰值 13 题再回 11 题）；9B 三轮 5.10%→7.90%，Pass@50 稳定在 17.8–18.5%。作者推测代码生成对分步推理的依赖弱于数学，是增益边际的原因。

**4.3 LLaMA 迁移与规模效应**：单轮 TPT 即可显著提升——Llama-1B 从 18.2%→20.8%（2k 数据）；LLaMA-70B 从 78.6%→91.5%（**单轮、6k 数据**，注意此处数据预算大于 2k 默认值），Pass@20 从 92.2%→95.8%，论文结论处称 91% 超过 GPT-4o（2024-08-06）的 82%。跨规模规律：**2B 需 4 轮、9B 需 3 轮、70B 单轮达峰**——模型越大，从自数据中单轮提取增益的效率越高。

## 5. 消融要点

**剪枝是自训练可行性的分水岭**（Gemma-2B，GSM8K）：2k 剪枝 52.5%/83.0%（Pass@1/Pass@20）对比 2k 不剪枝 45.13%/71.6%、6k 不剪枝 44.57%/71.0%——不剪枝时 Pass@20 甚至低于基线 76.0%，即未过滤自数据同时损害精度与多样性。这与 Setlur et al. (2024)“错误数据在规避关键错误时有价值”的结论相反。剪枝还**抹平了数据生成端的模型规模差**：不剪枝时 9B 数据优于 2B 数据，剪枝后两者可比。

| 策略（CodeContests, Gemma-2B） | Pass@1(%) | Pass@50(%) |
|---|---|---|
| 1k 不剪枝（2B 数据） | 0.85 | 5.70 |
| 1k 不剪枝（9B 数据） | 0.94 | 6.40 |
| 5k 不剪枝（9B 数据） | 0.67 | 9.29 |
| 1k soft-pos（保留通过 ≥1 测试的解） | 0.70 | 8.57 |

soft-positive 剪枝是明确的**多样性-精度旋钮**：Pass@50 升至 8.57%（高于全部不剪枝配置）但 Pass@1 跌至 0.70%。

**混合真实+合成数据在递归细化中一致失败**：单轮小规模混合可行（1k 各 500 时 Pass@1 达 1.0%），但递归混合微调降至 0.87%。作者假设真实数据破坏了递归自改进所依赖的自分布一致性——这对“迭代自训练管线中能否混入人工标注”给出了否定证据（单轮口径下）。

**迭代轮次的作用集中在单次尝试精度**：Pass@1 逐轮上升，Pass@20/50 首轮后平台，说明递归训练提升的是“首采即对”的可靠性而非解空间覆盖。与 s1（Muennighoff et al. 2025）的对照：s1 从显式推理训练过的模型出发用 budget forcing 拉长推理，TPT 则从普通 instruct 模型出发靠提示诱导推理行为。

## 6. 贡献与启示

按原文归纳的三点贡献：(1) 正确性剪枝使递归自训练稳定，规避 model collapse；(2) 系统刻画数据量、生成模型规模、剪枝策略、迭代轮次四个变量对自改进的影响；(3) 验证最简框架（结构化提示 + ground-truth 剪枝 + 验证解 SFT）即可在无外部监督下自提升。核心结论是**结构化数据选择比数据规模更关键**。

局限（依原文可查）：任务限于 GSM8K/CodeContests/LeetCode，GPQA 被有意排除（附录 A 论证其难度在冷门知识回忆而非推理结构）；评测集偏小（GSM8K 500 题子集、CodeContests 140 题）；递归最多 4 轮，长程稳定性未验证；代码域增益边际且 Pass@50 有回落；未与 RL 基线做受控对比（只论证了 SFT 路线的充分性）。

**音视频上下游迁移视角（笔记者观点，非论文主张）**：

- **可验证奖励域的映射**：TPT 的成立前提是“域内有廉价、无噪的 ground-truth 校验器”。AV 下游存在大量满足该前提的子任务——编码决策序列的 BD-rate/PSNR 判定、ASR/字幕的 WER/CER、时序定位的 tIoU 阈值、音画同步偏移检测。结合第 3 节的策略梯度等价性，缺乏 RL 训练栈的团队可以用 TPT 式“自采样→指标校验→过滤→SFT”闭环近似 RLVR，绕开 PPO 的稳定性与基础设施成本。
- **端侧小模型数据自给**：剪枝后 2B 自数据 ≈ 9B 蒸馏数据（GSM8K 2k：52.5 vs 54.0；LeetCode 1k 反超 14.65 vs 12.82），意味着 2B 级端侧 AV 模型（视频-语言理解、端侧码控/增强小模型）可不依赖大教师模型自举后训练。
- **数据策展的非单调性警示**：合成数据 4k→6k 回落、人类原始解随规模增大而劣化（CodeContests 0.60→0.29），与 AV 合成数据引擎（合成字幕/描述/TTS）中“量增质降”的经验同构，支持“校验优先于扩量”的策展策略。
- **多样性-精度权衡**：Pass@1 型收窄对判别/求解型 AV 任务是净收益，但对生成式任务（视频/音乐生成，多样性本身是产品指标）需警惕；soft-positive 剪枝给出了可量化的折中手段。
- **上游关联**：代码推理自提升（CodeContests 0.90→1.14/5.10→7.90，增益虽小）与 GPU kernel/编解码工具链的代码生成上游相通，为算子级优化提供模型侧基础。

## 7. 与其他论文的联系

- **SkillDuet (paper:arxiv:2611.12109)**：同为无外部教师的递归自改进闭环。关联依据：TPT 把闭环限制在“参数更新 + ground-truth 过滤自数据”这一最简形态，SkillDuet 则引入外部技能库与参数更新协同演化、以响应反馈实现技能级递归改进——TPT 可视为其“无外显知识载体”的退化特例；两者互补地证明迭代增益可分别落在参数与外存两个载体上。
- **TRUST (paper:arxiv:2611.10787)**：都处理递归自改进的稳定性问题。关联依据：TPT 用二值 ground-truth 硬过滤防退化，隐含“校验器无噪”假设；TRUST 用在线多重假设检验控制错误进化率并提供统计保证。在校验器含噪或无绝对真值的场景（如以主观质量代理指标作奖励的 AV 任务），TRUST 式软门控是对 TPT 硬剪枝的必要升级。
- **FGSE (paper:arxiv:2611.14326)**：“先验证再写入”原则的同构实现。关联依据：FGSE 将经验教训作为可证伪假设、经探针验证后才写入智能体记忆；TPT 将自生成解经 ground-truth 验证后才写入训练集——同一门控思想作用于记忆与训练数据两个载体，二者可组合成“数据层 + 记忆层”双门控的自进化系统。
- **CompoundingKernel (paper:arxiv:2611.19230) 与 RSI-PDEbench (paper:arxiv:14949 系)**：TPT 前提（可验证 ground truth）的应用侧对应物。关联依据：二者分别在 GPU kernel 优化（SOL-ExecBench/B200 榜单）与 PDE 求解（可判定通过率）上以程序化校验驱动递归自改进，与 TPT 的“正确性即奖励”前提同源；其中 GPU kernel 域与音视频编解码/处理算子生成直接相邻，是 TPT 式训练配方在 AV 算子优化上的天然靶点。
- **TrainExplorer (paper:arxiv:2611.20430)**：自主后训练编排框架。关联依据：TPT 是一个具体、可复用的后训练原语（递归剪枝 SFT），而 TPT 的因子分析——数据量、模型规模、剪枝策略、迭代轮次——恰好构成 TrainExplorer 类规划智能体的决策变量空间，二者是原语与编排的关系。
- **LongCapHarness (paper:arxiv:2611.11558)**：互补维度的同路线工作。关联依据：TPT 在**训练侧**以自数据 SFT 扩推理、LongCapHarness 在**推理侧**以能力制导免后训练提升长上下文（HELMET/RULER），两者同属“不扩参数规模而扩推理能力”路线；对 AV 而言分别对应离线模型自提升与部署期长视频上下文推理两条可叠加的路径。
