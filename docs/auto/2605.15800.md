## 1. 背景与动机

AV2 由 AOMedia 开发以接替 AV1，目标是在同等视觉质量下大幅降低码率，直接对应存储与分发成本削减、带宽受限环境下的质量提升，以及 UHD-2（8K）流媒体、VR/AR 等高码率需求场景。值得注意的是，工程约束在标准立项时即被前置量化：相对 AV1，编码器复杂度增幅不超过 5×、解码器不超过 2×，且要求存在可产品化的实现。这一红线决定了评测体系必须同时度量压缩增益与计算复杂度，防止标准在工具竞赛中滑向不可实现的高复杂度。

标准开发流程本身构成了第二个动机：AV2 的工具提案来自多家成员公司，需要严格、透明、可复现的框架对提案与基线做公平比较。AOM Testing Sub-Group 为此建立了 AV2 CTC（Common Test Conditions，文中引用版本 v8.0，CWG/F384o），统一数据集、编码配置与指标口径，强制所有贡献者在相同条件下测试，使结果直接可比，进而对工具采纳做出数据驱动决策。

与 MPEG/VCEG/JVET 传统 CTC 的差异化是本文的方法论出发点。传统 CTC（JCT-VC L1100、JVET-T2010/T2011）主要面向广播与存储应用，而 AOMedia 的业务重心是开放 web 与流媒体，由此派生四项具体差异：

1. **6 个 QP 点而非 4 个**：降低 RD 曲线构造中的插值误差，并支持基于分段三次 Hermite 插值的低/中/高码率段细粒度分析；
2. **首次纳入 UGC**：内容自带不同质量等级与预存压缩损伤，承认社交平台（YouTube、Facebook、TikTok）内容的主导地位；
3. **引入 AS（adaptive streaming）配置**：跨多分辨率编码并构造凸包，模拟真实 VoD/ABR 管线；
4. **引入序列内动态分辨率切换（resize mode）评测**：允许编解码器在帧边界无 IDR 切换分辨率，这是带宽自适应的关键能力。

指标体系上，PSNR（Y/U/V）仍是标准项，但 CTC 强制上报感知指标：PSNR-HVS、加权 PSNR(YUV)（按色度格式对平面施加不同权重：4:2:0 为 7/8、1/16、1/16；4:2:2 为 4/5、1/10、1/10；4:4:4 为 2/3、1/6、1/6，三组权重均归一）、SSIM、MS-SSIM、CIEDE2000、VMAF，以及针对平坦梯度 banding 的 CAMBI。全部指标统一在 libvmaf（v3.1.0）内实现，从工具链层面保证可复现。

## 2. 方法总览

CTC 由四个要素构成：测试序列集、编码/解码配置、质量与复杂度指标、增益评估流程。其设计立场值得强调：**CTC 评估的是规范性编码工具**，因此 two-pass、look-ahead、内容自适应 QP 调制、预滤波等编码器侧算法均属非规范性，在 CTC 中不启用。这意味着 CTC 数字代表“标准工具的潜力”，而非“最优产品编码器”的最终性能。

四种编码配置与用例的映射关系：

- **All Intra（AI）**：评估帧内编码方法；
- **Random Access（RA）**：面向 VoD、一对多直播与存储，允许帧重排序；
- **Low Delay（LD）**：面向实时通信与视频会议，无帧重排序；
- **Adaptive Streaming（AS）**：面向 ABR，跨分辨率构造 RD 凸包。

开发流程采用双轨制以保证并行度与权威性：开发周期内按类规定 tile 划分与线程模型（如 4K RA 规定 4 tiles）以支撑高并行仿真；每个 AVM 发布之后，Testing Sub-Group 以单 tile 模式对全部类做完整验证测试，作为编码增益的官方报告；日常开发则使用强制测试子集。

端到端评估流水线为：按规定配置编码并输出 .obu 裸流 → 依据文件大小精确换算码率（保留 6 位小数）→ libvmaf 计算全指标 → PCHIP 单调拟合 RD 曲线 → 分指标/加权 BD-rate（分质量区间）→ 与锚点 research-alt-v1-anchor r4.0 对比。

## 3. 关键设计

### 3.1 测试序列分类

开发周期之初选定的源序列覆盖 270p 至 4K/UHD 分辨率、自然视频/合成内容/UGC 三类内容、SDR（BT.709-BT.1886）与 HDR（BT.2100 PQ）及扩展色度格式；同类内统一色度采样（ECF 除外）与编码帧数，全部序列公开以支持复现。共六类：

- **Class A**：自然内容，270p–2160p，8/10 bit，4:2:0；
- **Class B**：合成内容（游戏、动画、屏幕共享），1080p，8/10 bit，4:2:0；结果表中进一步区分 B1（合成）与 B2（屏幕内容）；
- **Class E**：UGC，最高 4K，8 bit，4:2:0；
- **Class F**：静止图像，最高 8K，8 bit，4:2:0；
- **Class G**：HDR，BT.2100 色域 + PQ 传递函数，2160p，10 bit，4:2:0；
- **Class ECF**：扩展色度格式，最高 4K，8/10 bit，共六个子类——4:2:2 与 4:4:4（各自含 SDR 与 HDR-BT.2100-PQ），外加独立的 RGB 与 YCoCg-RE 子类。

### 3.2 编码配置

- **AI**：取序列前 15 帧（Class ECF 取前 5 帧；Class F 为静止图像）；
- **RA**：130 帧，即两个闭合 GOP（ECF 为 66 帧）；
- **LD**：仅帧 0 为关键帧，无帧重排序，130 帧（ECF 为 33 帧）；
- **AS**：对每条序列生成多分辨率编码集以构造凸包。以 Class A1（3840×2160）为例，另用 5 个下采样分辨率：2560×1440、1920×1080、1280×720、960×540、640×360；每档分辨率均以 RA 配置编码，解码后的低分辨率序列经上采样回源分辨率后对原始源计算质量指标。

AS 的口径设计有两点工程含义：其一，所有质量分数统一在源分辨率上对同一原始源计算，剥离了“客户端接收低分辨率但显示端放大”路径中的口径歧义；其二，该评估本质上度量编码器在 ABR 全分辨率阶梯上的 Pareto 上界，而非单一分辨率工作点。

### 3.3 AS 凸包构造

凸包评估要求精确分辨率转换，否则重采样误差会直接污染对源计算的 BD-rate。具体规范：

- **重采样核**：Lanczos 滤波（α=5），14-bit 整数精度，居中相位对齐，边界以样本复制填充，实现于 HDRTools；
- **色度样点定位随内容而变**：BT.709/非 HDR 用 Type 0（垂直），HDR 用 Type 2（与亮度 (0,0) 同位），静止图像用 center-siting（"JPEG"）；
- **数据密度**：每分辨率 6 个实测 QP 点之间在 log-bitrate 域均匀生成 7 个插值中间点（文中称 bilinear interpolation），最终凸包由所有分辨率上实测点与插值点的并集构造。log 域均匀布点与 RD 曲线跨数量级的码率范围相匹配，避免高码率段点密度不足导致凸包前沿估计偏差。

### 3.4 增益计算

- **BD-rate 拟合**：RD 点用 PCHIP（单调约束的分段三次 Hermite 插值多项式）拟合。单调约束避免了普通三次样条在 BD 积分区间内的过冲，是 6-QP 密集采样之外另一项稳健性设计。
- **加权 BD-rate**：BD-rate_weighted = A × BD-rate_Y + B × BD-rate_Cb + B × BD-rate_Cr，其中 A = 0.92（23/25）、B = 0.04（1/25），且该权重依据 luma/chroma RD 代价平衡在 CTC 评估中**周期性更新**——加权口径不是固定感知常数，而是随标准演化校准的工程参数，这在各标准 CTC 中较为少见。
- **质量区间**：利用 6-QP 设计，分别在低（QP1–QP4）、中（QP2–QP5）、高（QP3–QP6）三个窗口报告 BD-rate。
- **饱和区处理**：VMAF 等指标在 RD 曲线平坦饱和区出现非单调的点，此类点被剔除。
- **锚点**：research-alt-v1-anchor r4.0，基于 libaom AV1 参考编码器的代码分支，附加 scaler 量化设计修改，使锚点编码码率能达到低得多的范围——目的是保证锚点 RD 曲线与 AV2 在低码率段有足够重叠区间可供 BD-rate 积分。
- **QP 施加方式**：QP 显式映射到 AV1/AV2 的 qindex 语法元素，逐帧类型统一施加，不考虑输入内容特性。
- **码率计算**：输出 .obu（Open Bitstream Unit，类比 HEVC/VVC 的 NAL unit）裸流；Bitrate_kbps = FileSize × 8 × (fps_num/fps_denom) / (FrameNum × 1000)，帧率以有理数表示（如 59.94 fps 用 60000/1001），码率保留 6 位小数以匹配质量指标精度——码率噪声直接传导进 BD-rate，此处精度对齐是必要的。
- **QP 集合**：静止图像 60/85/110/135/160/185；AI 85/110/135/160/185/210；RA、LD、AS 均为 110/135/160/185/210/235（步长 25）。AI 与静止图像使用更低 QP 集合，对应生产场景中静止图像与序列内帧内帧需要更高编码质量的需求。

评测对象为 AV2 v13.0（AVM code base 的发布版），除 Class ECF 使用 CTC 并行 tile 配置外，其余全部类采用单 tile 配置以最大化编码增益；锚点为 research-alt-v1-anchor r4.0。下表汇总 BD-rate 节省（负向增益，数值越大越好）的关键行：

要点解读：

- **配置维度**：RA 是效率增益最高的规范性配置（4:2:0 总体 PSNR-YUV 29.81%、VMAF 33.79%）；AI 为 22.32%/23.58%；LD 为 26.05%/27.28%；AS 凸包口径下达到 31.34%/35.77%，为所有配置最高。LD 汇总行中论文未报告 Class G/E 的分类结果。
- **屏幕内容是最大受益者**：AI 下 Class B2 达 42.62%（PSNR-YUV）、RA 约 40%、LD 超过 44%（VMAF 44.97%），CIEDE2000 口径下 AI 达 50.89%。ECF 的 SCC 子类同样维持在 37–38% 量级（AI 38.39%、RA 37.77%、LD 37.09%，PSNR-YUV）。论文据此判断 AV2 新工具对计算机生成图形与锐利边缘保持尤为有效。
- **HDR 与 UGC**：RA 下 Class G 为 31.99%（PSNR-YUV）/37.08%（VMAF）；Class E（UGC）为 25.63%/29.30%——自然/UGC 类增益系统性低于合成类但依然可观。
- **扩展色度格式**：4:2:2 与 4:4:4 一致获益，ECF 总体 PSNR-YUV 在 AI/RA/LD 下分别为 25.40%、32.08%、28.75%；YCoCg(-RE) 子类 RA 下 PSNR-YUV 32.18%、CIEDE2000 达 40.18%。
- **静止图像增益最低**：Class F 仅 VMAF 15.12%（PSNR-YUV 13.81%），论文原文将其归因于 AV2 的编码改进（原文写作 inter-coding improvements，就帧内静止图像语境而言疑为笔误）。
- **色度增益 > 亮度增益**：跨所有配置的一致规律是色度分量增益普遍超过亮度平面，故 PSNR-YUV 得分相对 PSNR-Y 系统性偏高（如 RA 总体 29.81% 对 28.13%，AI 的 HDR 类 24.14% 对 20.17%）。
- **开发进展（2021–2025，v2→v13）**：每个 AVM 发布后做周期性测试，RA 与 AS 配置累计降幅最大；2160p HDR 的 VMAF 增益超过 40%，UGC 约 30%；2025 年之后改进速度进入平台期，反映标准成熟后边际增益难度上升。
- **复杂度现状**：AV2-CTC 平均编码时间 33×、解码时间 3.86× 于 AV1 锚点（随分辨率变化）；更快的预设已实现 10× 编码提速、编码损失 ≤2%；解码复杂度目前处于 2.5–4× 区间，优化仍在进行（VideoLAN 的 dav2d 解码器项目）。

## 5. 消融要点

本文不做工具级消融——那是各编码工具提案在 CTC 框架下的核心实验，本文提供的是该框架本身及其上的整体结果。其分析维度是配置 × 内容 × 指标 × 版本的四维交叉，承担了类似的诊断职能：

- **配置维度排序**：AS（31.34%）> RA（29.81%）> LD（26.05%）> AI（22.32%）（PSNR-YUV 总体）。AS 相对单分辨率 RA 再多约 1.5 个百分点（VMAF 口径 35.77% 对 33.79%），说明 AV2 的优势在跨分辨率 ABR 打包场景被进一步放大；一个合理推断是凸包在低码率段（低分辨率档）纳入更多工作点、而 AV2 在低码率段相对优势更大——论文未对此展开解释，此为笔记推断。
- **时域/空域分解（观察性）**：RA 与 AI 的总体差距（29.81% 对 22.32%）可粗略读作 AV2 帧间工具链相对 AV1 帧间基线的额外增益口径，但因锚点同为 AV1 全配置，这并非严格因果消融。
- **内容维度**：合成/屏幕内容（B2、ECF-SCC）在所有配置下均为最大受益者，UGC 与自然内容最低但仍约 25%（RA）。指向 AV2 工具对无传感器噪声、锐利边缘、重复图形结构内容的压缩潜力最大。
- **指标维度**：CIEDE2000 在全部配置的总体行中均为最大值（28.50%/34.38%/31.03%/34.74%/16.84%），MS-SSIM 常为最小（RA 总体 27.32%）；结合“色度增益普遍大于亮度”的现象，可推断 AV2 增益中色度/颜色保真成分可观（论文仅陈述现象，未指认具体工具归属）。
- **版本维度**：v2→v13 的累计增益曲线持续爬升至 2025 年后平台化，是标准成熟度的直接量化证据。

## 6. 贡献与启示

**方法论贡献**：

1. 将流媒体业务特征第一次系统性纳入标准 CTC：UGC、AS 凸包、resize 模式、扩展色度格式（4:2:2/4:4:4/RGB/YCoCg-RE）与 HDR 均为一等公民，而传统 JVET CTC 以广播/存储 SDR 内容为中心。
2. 6-QP + 三质量窗口 + PCHIP 单调拟合 + VMAF 饱和点剔除，构成比传统 4-QP CTC 更稳健的 BD-rate 口径；加权 BD-rate 的权重（A=0.92/B=0.04）随 luma/chroma RD 代价平衡周期性更新，是评测口径本身作为工程参数演化的少见实践。
3. 以 Testing Sub-Group 官方周期性测试给出权威数字：AV2 v13.0 对 AV1 锚点 RA 下 VMAF 节省 33.79%、AS 下 35.77%、屏幕内容约 40%。
4. 全链路开源可复现：测试序列（xiph 公开）、凸包框架（AVM tools）、HDRTools、libvmaf。

**工程与引用启示**：

- **复杂度鸿沟是核心工程问题**：CTC 参考实现编码 33×、解码 3.86×（区间 2.5–4×），与立项目标（编码 ≤5×、解码 ≤2×）尚有数量级或成倍差距；快速预设（10× 提速、≤2% 损失）与 dav2d 是收敛路径，但“参考实现增益”到“产品实现增益”的折损需要在部署评估中单独量化。
- **引用口径警示**：全部数字是“AV2 v13.0，单 tile（ECF 除外），对 research-alt-v1-anchor r4.0（经量化 scaler 修改的 libaom 分支）”的 CTC 口径，不等价于对生产级 AV1 编码器（SVT-AV1 等）的增益；跨论文、跨报告引用时必须注明锚点与配置。
- **可迁移的评测设计**：AS 凸包的"log 域加密采样 + 多分辨率点并集 + 上采样回源域统一计算”流程，以及色度 siting 按内容类型分类处理的做法，可直接迁移到神经编码器与 ABR 系统的评测；UGC 类的引入则承认“预存压缩损伤内容”才是现代编码器的真实输入分布，这一维度对 learned codec 评测同样关键。

## 7. 与其他论文的联系

- **Transform and Entropy Coding in AV2（arXiv:2601.02712）**：同属 AV2 标准文献。该文描述 AV2 规范性的变换、量化与熵编码工具（IST、TCQ、ATC、FSC）及其各自压缩增益，本文则给出这些工具在统一 CTC 条件下逐版本集成后的系统级总量（RA VMAF 33.79%）。两者构成工具级证据与端到端度量的互补视角；本文锚点对量化 scaler 的修改也正落在量化设计的衔接问题上。
- **FaSST: Fast Sparsifying Secondary Transform（arXiv:2605.15086）**：面向 AV2 帧内编码、基于 Givens 旋转分解的快速二次变换，以远低于 LFNST 的复杂度实现持平或更优性能。这与本文报告的 33× 编码复杂度形成直接呼应——CTC 的 AI 配置结果（总体 PSNR-YUV 22.32%）正是此类帧内工具贡献的度量场景，复杂度-增益权衡是两文共同的轴线。
- **DQ-Ladder（arXiv:2603.13597）**：以深度强化学习构建时间与质量感知的码率阶梯，与本文 AS 配置的穷举式凸包构造针对同一 ABR 问题。CTC 凸包（每分辨率 6 QP、log 域插值加密、上采样回源域评估）正是学习式阶梯预测方法所要对标的高成本全搜索基线，两文构成“全搜索基准 vs 学习近似”的方法论对照。
- **A Camera-Native Talking-Head Video Dataset（arXiv:2603.26763）**：以相机原生 FFV1 无损谈话头内容做多编码器 VMAF BD-rate 评测（H.266 较 H.264 最高节省 71.3%），其动机与 CTC 引入 UGC 类同源——用更贴近真实分发的内容提升评测代表性；可视为 VMAF BD-rate 评测范式在另一内容域与编码器代际上的平行应用。
