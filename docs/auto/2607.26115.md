## 1. 背景与动机

前沿 LLM 在智能体化部署中的核心安全瓶颈是对抗鲁棒性：模型须在恶意输入下保持既定行为。主流改进路径是 RL 对抗训练——用人类红队、提示式 LLM 或真实生产攻击构造恶意样本并奖励模型抵抗。论文指出的结构性缺陷：此类数据集规模有限，模型会迅速过拟合到样本中已出现的攻击模式，对自适应对手依旧脆弱（作者引 Nasr et al., 2025「attacker moves second」的结论），且模型能力与用例扩张使攻击面持续放大，静态数据集注定追不上。

论文的立论：应训练红队智能体本身——能从与目标的反复交互中学习、能适应具体目标模型的行为特征、能跨对抗目标/环境/攻击面切换策略，从而以鲁棒性训练所需的规模、多样性与质量产生对抗数据。攻击对象锁定两类：提示注入（直接/chat 型即指令层级 IH 冲突，间接/agentic 型即工具输出、检索文档、网页等不可信第三方内容劫持行为；IH 指 system/developer/user/tool 的特权分级与冲突时服从高特权指令，Wallace et al., 2024）与内容政策越狱（自伤、违法建议、生物/化学/网络风险等）。

对攻击者智能体提出三性要求，构成全文设计主线：

- 泛化：可作为任意目标模型、任意红队 harness、任意场景的 drop-in 红队（攻击未见过的新模型、新工作流如 Slack 消息、新生产环境）；
- 多样性：同一目标/环境也能产出多种攻击风格，避免策略塌缩，使大量对抗训练算力可集中于单一攻击者而无须维护多个专用攻击模型；
- 有效性：严格遵守现实威胁模型约束（攻击者不能随意操控防守方 rollout 的任意部分），防止智能体以「作弊/reward hack」方式拿分。

相关工作定位：离散优化对抗后缀一系（GCG、GPTFUZZER、AutoDAN、TAP 等）常需白盒访问或海量防守方查询且跨模型迁移差，作者视之为互补的另一族方法；早期 LLM 红队（Perez et al., 2022；MART 等）或用 prompted 攻击者或仅在窄目标/少环境上训练；另一支只做测试时算力扩展而不训模型（RedAgent、AgentXploit、MUZZLE）。方法论上最接近的是 Ma et al., 2023 与 Liu et al., 2025 的自博弈红队，本文在环境广度与对抗目标规模上大幅扩展；Deng et al., 2025（DuoGuard）只针对防守分类器而非通用 LLM。

## 2. 方法总览

总体配方是沿三个轴同时扩展的自博弈 RL：

（1）推理时算力——agentic 红队 harness。给攻击者一个有状态的 defender_model 工具，使其能像人类红队一样迭代试错（详见 §3.2）。

（2）环境多样性——把现有能力型任务转成对抗训练环境。核心操作：在防守方 rollout 中打断一次工具调用，允许攻击者编辑指定区域（某条工具响应、某个本地文件区域）。这样可直接继承生产模型后训练任务的广度（含 GPT-5.6 的常规后训练数据分布），使防守方在其训练分布内获得鲁棒性。

（3）训练算力——规模等同 OpenAI 最大的若干 RL 后训练 run。在此规模上，基本的双玩家博弈被扩展为「攻击者 vs 多样防守方群体」：避免攻击者过拟合单一防守方的怪癖，学会探测各模型独特弱点。

自博弈主循环（每次迭代）：

1. 采样 RL 环境：一段对话、初始文件系统状态、指定的防守方模型；
2. 选择上下文恰当的注入点（通常是某次工具调用）及攻击目标（如诱发从根目录 rm -rf、把 API key POST 到某 HTTP 端点），并向攻击者提供任务所需对抗知识（如最后一条用户消息）；
3. 攻击者 rollout 并与防守方交互，满意后提交最终攻击；所有中间 defender_model 调用被丢弃，不进训练数据；
4. 校验攻击与环境的合法性，非法攻击奖励为 0；
5. 将攻击消息插入预定位点，从注入点恢复防守方 rollout；
6. 计算环境特定奖励——通常非对称：同时检查攻击者是否达成目标、防守方是否完成原任务；
7. 用 RL 在 (rollout, reward) 对上同时更新攻防双方。

GPT-Red 训练配置：权重初始化自 GPT-5.5（当时最强前沿模型）；在 §6 列出的全部环境类型上训练；防守方套件包括既往最强模型（至 GPT-5.5）；为保持指令遵循、codex 场景交互性与诚实性等能力，混入标准 RL 后训练环境；总计算量与近期生产 GPT-5 系列模型的 RL 后训练大致相当——论文称这是有公开记载以来最大的单次 LLM 安全训练 run。

下游闭环：GPT-Red 及其前身（最早自 GPT-5.2 起融入生产训练）一方面在 RL 训练中生成对抗训练 prompt，另一方面作为评测器度量 in-/out-of-distribution 鲁棒性进展；GPT-5.6 由此获得对提示注入的高鲁棒性。

## 3. 关键设计

### 3.1 威胁模型与有效性校验（防作弊的地基）

- 攻击面：恒定假设攻击者只能修改防守方轨迹中的单条工具响应或一组非特权文件（如网页搜索任务替换一条搜索结果、幻灯片任务改若干非关键下载文件）；特权内容（用户 AGENTS.md 等）不可触碰。
- 知识与访问：攻击者可查看最近用户消息与将被放置攻击的原始工具响应/文件；对防守方为黑盒、限量查询；查询后有时可观察注入后的完整防守方轨迹，且常附带 token 对数似然。
- 注入执行：攻击提出后被放入 rollout 中预先指定的位置；可附加 schema 匹配、长度等约束。
- 校验：程序化 + LLM 混合检查自动拒绝非法攻击（非法即 0 分），在奖励层面惩罚作弊；作者对校验有效性做了定性评估（称 highly effective）。

工程含义：「单点编辑 + 黑盒限量查询」是数据现实性的锚；log-likelihood 回传是超出纯黑盒的让步，训练时可用，评测与迁移时未必成立。

### 3.2 defender_model 工具与终端（推理时扩展的载体）

攻击者仅两个工具：通用终端 + defender_model。流程：终端在虚拟文件系统中写攻击文件（可写代码程序化生成攻击——模板填充、字符串重复、多策略组合），再以 defender_model 提交文件路径；后端将攻击嵌入预定位点、采样防守方轨迹，返回轨迹、token log-likelihood 与 judge LLM 反馈。该设计使攻击者能在单次 rollout 内做结构化搜索（对消息变体分支）、以 token 高效方式直接编辑文件迭代攻击，并能用代码批量生成与测试攻击变体而不过度消耗自身上下文。部分场景下工具支持有状态多轮攻击（与防守方逐轮构建对话）。时间耗尽或自认满意时提交最终攻击路径。

### 3.3 多防守方群体（多样性的来源）

仅用单一防守方的预实验常导致攻击者塌缩到窄类策略。引入多个防守方、尤其是对不同攻击各自高鲁棒的防守方，激励攻击者「先探测该防守方的独特弱点再定制攻击」而非寻找单一通用强攻击。论文在九个（冻结）防守方上训练并做迁移评测，确认攻击明显专用于目标模型（见 §5）。

### 3.4 环境族

- 直接提示注入/IH：扩展 Guo et al., 2026 的 IH-Challenge。防守方收到高特权 developer/system 指令，攻击者编辑单条低特权 user/developer 消息；奖励可编程验证（永不泄露 PIN、执行正则替换、解析为结构化 schema 等）；相比既有直接注入数据集覆盖更广的指令类型、目标行为与语言。
- 间接提示注入：复用能力型 agentic RL 环境，攻击者只可改单条工具响应或非特权文件，覆盖四类场景：浏览（浅层即时搜索与 deep research，改单个网站文本）；连接器（Gmail/Google Calendar 等第三方服务文本输出，改邮件正文/日历描述）；通用函数调用（模拟 OpenAI FC API，防守方读取潜在不可信内容时覆盖单条工具输出）；agentic coding（本地文件系统、远程仓库等 Codex 式复杂交互，改部分本地文件或工具调用）。
- 多模态注入：同一受限插入威胁模型下，攻击者持有 OpenAI Images 2.0 的 API，最终攻击必须仅是一张渲染图像，可迭代调整布局、纳入相关源内容、修改图内指令。两类环境：CUA 视觉截图（防守方依截图导航操作，攻击者只改网页预定义区域如横幅广告/评论区）；浏览与文档检索（替换或向结果追加图像；替换必须保持任务可解性——保留回答用户问题所需事实、标签、数值与来源线索）。多模态攻击要求把指令字符串自然、可信地渲染进任意图像以躲过防守方检测（示例：把财务文档替换为保留关键数值但夹带对抗注释的扫描页；给咖啡店场景生成一张无缝嵌入伪造外传 URL 的小票）。
- 内容政策越狱：围绕用户对话构造任务（如良性软件调试对话被引向恶意软件协助），单轮 + 多轮（多轮允许攻击者先引导数轮再发出最终有害请求）。奖励用评分表度量防守方输出与「最大危害答案」的接近程度（攻击者最大化、防守方以安全完成或拒绝最小化）。两个防 hacking 过滤器：拒绝已含违禁内容、仅要求表面变换（如翻译）的攻击（对用户无实质新信息）；拒绝不像真实用户对话的攻击。

### 3.5 奖励结构

注入类环境中理想防守行为 = 忽略恶意指令 + 完成原任务；攻击者得分当且仅当最终攻击同时满足威胁模型约束与对抗目标达成。攻防奖励非对称，二者在同一批 (rollout, reward) 上分别更新。

## 4. 实验结果

### 4.1 红队能力

- IPI 2025 Q4 间接注入挑战场景（Dziemian et al., 2026；按原挑战以 GPT-5.1 为防守方；移除原人类攻击、由各攻击者重新生成；ASR 口径为「至少一个攻击成功的评测实例比例」）：单次生成攻击的 GPT-5.5 与人类红队平均 ASR 大致相当；给 GPT-5.5 配上 defender_model 工具后推理时扩展显著增强；GPT-Red 平均 ASR 全场最高、大幅超过人类红队，且随测试时算力（1x→100x）持续上升。附录同设置补充：相同 defender_model 调用次数下 GPT-Red 优于 GPT-5.5，且更倾向主动使用该工具。作者脚注声明这不代表 GPT-Red 全面优于人类（人类可能发现全新场景/攻击类别）。
- 泛化到留出模型：把训练 run 中收集的攻击重放到留出 GPT 版本（含更早的直至 GPT-5.2），在早期 GPT-5 模型上的成功率最高接近翻倍。
- 真实系统攻击（Vendy 售货机，Andon Labs 产、部署于 OpenAI 办公室的 Slack 对话+库存+定价+下单 agent）：给定系统描述与可迭代仿真环境，三个目标全部达成——把高价在售商品改为最低允许价 $0.50、订购 $100+ 新品并以 $0.50 出售、取消其他顾客订单；对生产系统的有效攻击依赖伪造「可信管理员」元数据。
- 内部红队（Codex CLI agent，基于 GPT-5.4 mini；10 个留出数据外传场景；换用一个允许攻击者跨任务顺序作业、携带经验并自选下一个攻击任务的异构 harness；各攻击者自独立初始状态跑 3 次）：简单任务上 GPT-Red 与 GPT-5.5 进度相当；更难任务上 GPT-5.5 停滞而 GPT-Red 随累计攻击 token 持续推进（均值曲线，区间为三次运行的 min–max）。
- 定性：训练早期攻击是「IGNORE PREVIOUS INSTRUCTIONS…」式的简单提示，后期涌现复杂策略。标志性攻击为 fake chain-of-thought：攻击文本伪装成防守方自己的 CoT（含虚构政策引用与推理过程），防守方将其当作自身先前推理并直接执行其中的外传命令；该攻击发现时独立新颖（与 Ye et al., 2026 并行工作撞车），对广泛模型可靠生效。同环境内多次尝试的攻击多样性高，给 few-shot 或高层策略指引时行为高度可控。

### 4.2 GPT-5.6 鲁棒性

留出评测协议（三重）：强 IID 攻击按多次试验平均成功率分半，弱半（后 50%）用于训练、强半（前 50%）留作评测；每个高层域（web search、FC 等）各留出一个数据集，且 agentic coding 整域留出；另做留出红队演练（IPI 同款场景内部镜像，GPT-Red 带全套工具逐个攻击自 GPT-5.3 起的各模型，报每次尝试平均 ASR）与 IPI 2025 挑战数据集（基于函数调用的人类注入攻击）评测。

三类留出上 GPT-5.6 的防守成功率：

| 留出方式 | 防守成功率 |
|---|---|
| 留出数据集（各域各留一个） | 56.1% |
| 留出域（含整个 agentic coding 域） | 89.1% |
| 留出强攻击（强半 IID） | 72.0% |

留出红队演练中 ASR 随模型代际单调下降（GPT-5.3，2 月 5 日 → GPT-5.4，3 月 5 日 → GPT-5.5，4 月 23 日 → GPT-5.6，6 月 25 日），GPT-5.6 间接注入 ASR 低于 4%；最严直接注入环境上 ASR 处于 0.00%–0.40% 量级（按论文坐标轴范围）。注意该演练不含系统级缓解，ASR 相对真实攻击者偏高；且早期 GPT 模型也已含 GPT-Red 前身的攻击，单调增益部分反映飞轮累积。人类攻击上，GPT-5.6 对 IPI 2025 挑战数据集取得 100% 鲁棒（其中一处误判成功经人工核验排除）。所有评测含标签噪声/固有歧义/奖励噪声，任何模型都难达 100%；模型在约等于 high reasoning 档位评测。

直接注入（IH）鲁棒性（生产 harness、高推理档；GPT-5.1 为有大量鲁棒性训练但不含强自动红队攻击的对照；六项基准中五项为 GPT-Red 生成攻击的新类别，一项为外部 TensorTrust——密码保护指令置于 Developer 消息、攻击置于 User 消息、以是否输出「Access Granted」作可验证奖励）：

| 基准 | GPT-5.1 | GPT-5.6（含自博弈） |
|---|---|---|
| Fake CoT 攻击 | 5.2% | 95.9% |
| System Override 攻击 | 66.0% | 99.5% |
| Multi-Defender 攻击（对十个强防守方训练所得） | 0.4% | 94.3% |
| Edge Case 提示（异常格式/多语/特殊字符） | 77.5% | 81.0% |
| Assorted（历次 run 攻击合集） | 29.7% | 76.5% |

结论：GPT-5.6 在全部评测上显著提升，fake CoT 一类最难评测上呈阶跃式改善（5.2%→95.9%）。

## 5. 消融要点

- harness vs best-of-N（IH-Challenge 环境，冻结 prompted 内部 helpful-only 攻击者对 GPT-5 系防守方，defender 查询数 1/5/10/25/50）：两条 ASR 曲线都随查询预算上升，但同预算下顺序 agentic 查询稳定优于独立 best-of-N 采样，且预算越大差距越大——恰是高算力对抗训练所在区间。机理：顺序查询允许在上下文内迭代精炼攻击。
- 攻击者类型 → 防守方鲁棒性（IH 留出平均直接注入鲁棒性，坐标范围 60–100%；受训防守方为较小的 GPT-5 系模型，论文标注 GPT-5 Mini）：冻结 prompted LLM < 冻结 LLM + agent scaffold < 自博弈训练攻击者；自博弈曲线近乎单调爬升且终值最高。结论：要吃到大算力对抗训练的红利，攻击者本身必须被训练。
- 检查点交叉评测（对某防守方大规模自博弈 run 的 5×5 攻/防检查点矩阵，IH 任务，行=防守方检查点、列=攻击者检查点）：同一防守方上后期攻击者普遍更强（如最新防守方上 12→29），防守方逐代变硬（最早检查点被 67–82% 攻破，最新仅 12–29%）；训练中攻击者 ASR 因防守方修补而周期性回落再爬升，构成双向课程。定性上，简单攻击（system override 类）先出现，更强更复杂的攻击（fake CoT 类）只在训练后期涌现。
- 攻击者单边训练（防守方冻结）：对所针对的防守方窄强、对留出目标更差，且更易策略模式塌缩——支撑共训必要性。
- 单 vs 多防守方（9 个冻结防守方上训练，结束后把对每个模型找到的攻击重放到其余 8 个，构成 9×9 迁移矩阵）：对角线（专攻目标）79–98%；跨模型迁移两极分化——对早期弱模型近乎全迁（强攻击者对早期模型 83–99%），对强模型显著衰减（如专攻 A 所得攻击打到 F–I 仅 25–36%；F–I 彼此间 57–79%）。证明攻击者学会先查验对手行为再定制攻击，群体训练是多样性来源。
- 训练/评测切分方法学：对一批攻击先测多次试验平均成功率再按强弱分半（弱半训练、强半评测），保证评测分布严格强于训练分布，是防「IID 虚高」的简单有效协议。
- 越狱奖励防 hacking：双重过滤器（拒「已含违禁内容 + 表面变换」、拒「非真实用户对话」）。

## 6. 贡献与启示

主要贡献：

1. 把 LLM 自动红队推到生产级规模：环境、防守方群体与训练算力三轴齐扩，算力与生产 GPT-5 系列 RL 后训练相当，号称有记载以来最大单次安全 RL run；
2. 迄今最强自动红队智能体：在留出场景/模型/harness 上超过人类红队与最强冻结基线，并对真实部署系统完成全部给定目标；
3. 用 GPT-Red 造出对提示注入阶跃式更鲁棒的 GPT-5.6；
4. 「安全飞轮」范式：今天的红队让明天的模型更鲁棒，更强的模型又给下一代红队更好的学习信号。

方法学启示（可迁移）：

- 「能力任务→对抗环境」的转换公式（打断一次工具调用 + 开放一个编辑位）可随生产任务分布自动扩展红队环境，无需手工造场景，这是规模化的真正杠杆；
- 有效性校验（程序化 + LLM、非法 0 分）+ 非对称奖励是防 reward hack 的最小完备配置；
- 多样性靠生态而非单一对手：防守方群体（而非单一最强对手）驱动攻击者探测个体弱点；
- 测试时扩展能力本身需要训练：给冻结模型配工具远不如训练它用工具（GPT-5.5 w/ 工具 < GPT-Red）。

攻击分类学（对防御工程的直接输入）：fake CoT/角色混淆（防守方把不可信文本当自身推理）、system override（伪造 SYSTEM 续写）、edge case 提示（多语言、特殊字符、Unicode 圆圈数字利用奖励函数歧义）、格式混淆（字符码构造禁词绕过字面检测）、LLM 固有弱点（50 层嵌套 JSON 的括号计数失败）、交互式 n 元搜索窃密（借 defender_model 对守密 PIN 做分段计数二分定位，论文附录示例逐步逼出 PIN 3207）、代码驱动并行变体测试（异步 API 批量采样攻击变体，绕开上下文窗口限制）。对应防御须覆盖 IH 冲突推理、CoT 来源完整性、Unicode 归一化、结构化输出校验等。

局限（作者自陈）：多模态、多轮攻击与越狱场景训练量仍少；评测含标签/奖励噪声；留出演练不含系统级缓解；GPT-Red 胜过人类是平均 ASR 口径，不排除人类发现全新攻击类别。

对音视频/多模态技术侧的外溢：本文的图像通道注入（对截图消费型 CUA agent、对搜索/文档检索结果的图像替换与追加）直接界定了视觉内容管线的注入风险面——任何摄取不可信图像/视频帧/扫描件的多模态系统（GUI 自动化、视频理解、扫描文档 RAG）都面临图内指令注入；「替换图像必须保留事实/标签/数值/来源线索以维持任务可解」的约束，实质是内容保持型对抗性媒体编辑，与媒体取证/篡改检测、内容溯源构成攻防对偶；攻击者用 Images 2.0 生成带无缝嵌入外传 URL 的仿真小票，说明 AIGC 图像的真实感显著抬高了视觉通道检测门槛。多模态恰是作者承认训练不足、后续版本明确要扩的轴。

## 7. 与其他论文的联系

说明：以下关联为方法学范式层面（共同演化/递归自改进回路）的对应，原文并未引用这些论文。

- paper:arxiv:2611.12109｜SkillDuet：以响应反馈协同演化「模型参数 ↔ 外部技能库」；GPT-Red 以对抗 rollout 反馈协同演化「攻击者 ↔ 防守方群体」。两者同构于「两个耦合学习体、一方产出即另一方训练信号」的共同演化训练结构；差异在于 GPT-Red 的奖励非对称且对抗，SkillDuet 为协作式技能积累。GPT-Red 的检查点交叉评测与 9×9 迁移矩阵正是这种耦合的经验证据。
- paper:arxiv:2611.10787｜Trustworthy Recursive Self-Improvement with Statistical Guarantees（TRUST）：用在线多重假设检验控制递归自改进的错误进化率并提供统计保证。GPT-Red 飞轮同样面对「自生成训练数据质量控制」问题，其手段是合法性校验、强弱攻击分半与 judge 过滤，但缺少错误率的统计保证——TRUST 的在线检验框架是给该飞轮中无效攻击/judge 误判累积提供形式化保证的自然候选方案。
- paper:arxiv:2611.14326｜When Should Agents Remember?（FGSE）：将经验教训作为可证伪假设、经探针验证后才写入智能体记忆；GPT-Red 中「攻击须通过威胁模型校验、并按实测成功率分流后才进入训练/评测回路」是同构的验证门槛式接纳机制，区别是 GPT-Red 作用于瞬时训练数据而非持久记忆。
