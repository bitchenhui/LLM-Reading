# Cross-Platform Neural Video Coding: A Case Study

## 1. 背景与动机

学习型视频编解码自 DVC 之后沿几条主线演进：SSF（Scale-Space Flow）在光流基础上引入尺度参数，使网络能按空间位置建模运动不确定性，从而改善运动估计与补偿，并沿用神经残差编码传输预测残差；DCVC 系列以条件编码取代残差编码，后续工作不断深挖时域上下文挖掘与时空混合熵建模；MaskCRT 进一步采用条件残差编码的 Transformer 框架。这些方案拓扑差异显著，但共享同一骨架：VAE 式压缩主干 + 超先验模型——后者为主潜变量的熵编码提供概率分布。CompressAI 实现的 SSF 提供九个质量档，各档对应一套独立预训练权重。

该骨架对数值一致性有刚性约束：编码端与解码端必须对主潜变量的先验分布参数（均值 μ 与尺度 σ）给出完全相同的结果，算术编解码才能保持符号级同步（该要求由 Ballé 等在图像压缩整数网络工作中明确指出）。而学习型编解码普遍依赖浮点运算，浮点舍入行为强依赖平台——不同 CPU 微架构、操作系统与运行库下的归约顺序、向量指令选择差异都会引入 ULP 级偏差。论文用对照实验坐实问题严重性：编码在 Intel Core i9-7920X @2.90GHz（Linux）、解码在 Intel Core i5 @1.80GHz（macOS），对 UVG 前 10 帧、SSF 九个质量档的非量化模型全部评估，所有序列、所有质量档均出现浮点误差。误差出现时机不定（YachtRide 质量档 1 的首帧无误差），但一经触发即经帧间预测逐帧放大；Beauty 第 5 帧的误差区域因运动补偿而显得更平滑，到第 5 帧时两个序列画面均已几乎不可辨识，且质量档 9（高码率端）劣化比质量档 1 更严重。论文的直接结论是：当前学习型视频编解码（以 SSF 为代表）尚不具备跨平台真实部署能力——这与高计算量、高访存量并列，构成产业落地的又一障碍，而本文聚焦后者。

既有补救手段集中在学习型图像编码，分两条路线，且各有代价：

| 方案 | 载体 | 需量化感知训练（重训） | 需额外码流信令 |
|---|---|---|---|
| Ballé 整数网络（ICLR'19） | 图像 | 是（全部网络层整数算术/查找表） | 否 |
| Sun 定点权重+激活（多码本） | 图像 | 是 | 否 |
| Q-LIC 通道切分 | 图像 | 是 | 否 |
| Safeguarding bitstream（风险标志位） | 图像 | 否 | 是 |
| 校准信息传输（Tian et al., ACM MM'23） | 视频 | 否 | 是（传易错熵参数坐标） |

本文的方法学占位由此清晰：针对学习型视频编解码（SSF 案例），提出免重训、免额外码流开销、仅需一次轻量校准的后训练静态量化方案，同时把跨平台浮点失配作为一级研究对象完成机理定位与实证。作者自称这是端到端学习型视频编码上最早期的此类尝试之一。

## 2. 方法总览

方案沿“定位—治理—选型—验证”四步推进。其本质是用“确定性整数域上的同一套计算”取代“指望两端浮点结果碰巧一致”，但只把这一约束施加在决定熵同步的狭窄通路上：

1. **失配源定位**：在解码端逐信号追踪 SSF 框图中的全部中间量（ẑ、μ/σ、各主潜变量与重建信号），对比同机与跨平台解码 Beauty 前 5 帧的结果，锁定错误源。
2. **治理**：仅对超先验解码路径施加 8-bit 整数静态量化（权重与激活同时量化），把 μ/σ 的计算约束到平台无关的整数算术；VAE 主路径保持浮点。
3. **选型**：PyTorch 量化框架下 observer × 量化方案组合空间庞大且存在兼容性硬约束，作者对超先验解码路径做 400 种组合的穷举搜索，在 Vimeo90k 上校准与测试，逐质量档重复九次，以 BD-rate 择优。
4. **验证**：在 UVG 与 HEVC-B（每序列 32 帧、1920×1080、九个质量档）上做同机/跨机 × 量化/非量化的对照评估。

部署假设符合真实场景的非对称性：编码端（常见于服务器级硬件）与解码端（消费级异构设备）无需浮点环境对齐，只要双方都运行量化后的超先验路径即可。

## 3. 关键设计

### 3.1 失配源定位与机理

SSF 含三条子编码路径：关键帧（帧内）路径、运动路径（运动编码器 + 运动超先验 + 光流解码 + 前向预测 warp）、残差路径，各自带有独立的超先验编码器-解码器对。信号追踪结果：三条路径上算术解码器输出的 ẑ（超先验潜变量重建值）跨平台完全一致——算术解码本身不是失配源；而三条路径的 μ、σ 均出现偏差，并沿后续模块传播。错误源由此锁定为超先验解码器的浮点前向计算。

机理上这是熵模型的结构性脆弱点：主潜变量以 (μ, σ) 参数化的分布做算术编解码；在典型的均值-尺度高斯实现中，解码端还需用 μ 将算术解码出的量化索引还原为 ŷ 的数值。因此 μ/σ 的平台间偏差会双重破坏一致性——概率模型失配可造成算术解码符号错位，μ 偏差直接令重建潜变量数值漂移——两者都从熵解码环节引入不可恢复的分叉，再经合成变换与帧间预测（运动补偿以重建参考帧为输入）沿时间轴放大。相对地，ẑ 的解码仅依赖固定的分解熵模型，不经过平台敏感的浮点网络前向，故天然确定。这一定位把治理范围从“整个网络”收缩到“三条超先验解码路径”，是方案得以轻量化、免重训的前提。

### 3.2 量化范围与部署方式

量化对象为三条子路径的超先验解码器，权重与激活一并做 int8 静态量化，推理时施加固定量化参数。部署关键细节（论文原句：量化的编解码器同时用于生成与解析码流）：编码端在熵编码主潜变量时同样经由量化后的超先验解码器计算 μ/σ，从而两端熵模型逐位一致。

VAE 主路径（分析/合成变换、运动补偿与 warp 等）不量化，其浮点差异只影响最终像素合成，不触碰熵解码同步。需明确的技术边界：该方案保证的是熵模型/解码潜变量层面的一致性，而非解码像素逐位一致——后者仍受未量化 VAE 路径制约，只是其量级与时间累积效应在 SSF 上实测可忽略（见第 4、5 节）。对一致性测试与合规场景，这一区分必须界定清楚。

### 3.3 PyTorch 静态量化机制与配置空间

静态量化在部署前预先固化权重与激活的量化参数，流程为：定义浮点↔int8 转换插入点 → 插入 observer → 用代表性数据校准收集分布统计 → 依 observer 参数量化模型。配置空间由两个维度张成：

- **Observer**（决定浮点→整数的 scale 与 zero-point）：MinMax 取校准期极值，对离群点敏感；MovingAverageMinMax 对多 batch 极值做滑动平均，统计更平稳；Histogram 用直方图跟踪分布，聚焦高频值、抑制离群点，映射控制粒度最细。
- **量化方案 QS**（决定整数映射规则）：对称（整数区间以零为中心）vs 仿射（零点可偏移的非对称映射）；逐张量 vs 逐通道（每个输出通道独立 scale/zero-point）。

### 3.4 穷举搜索协议

对“激活 observer×QS × 权重 observer×QS”共枚举 400 种组合。校准与测试数据互不重叠：从 Vimeo90k 随机抽取 78 段序列用于校准（裁剪为 256×256，随机裁剪），另抽 78 段随机子集用于测试（同尺寸，固定中心裁剪）。因九个质量档各用独立权重，每种组合须重复九轮校准/测试以产出九点 RD 曲线——搜索本身的工程成本可观。400 种组合中大量不可评估：部分 observer 与 QS 无法配对，部分 observer 与超先验解码器中的转置卷积模块不兼容，最终仅 36 种产出结果。这一兼容性实测（400→36 的可用率）对后续在 PyTorch 栈上做同类量化的团队有直接参考价值。

### 3.5 配置规律

搜索集（Vimeo90k、256×256、78 测试序列）上相对未量化 SSF 的 BD-rate：最优 +14.32%，最差 +2076.38%，离散度极大，说明超先验解码路径对量化配置高度敏感。头部/尾部配置呈清晰规律：

- **激活必须用逐张量对称（PTS）**：四个最优配置的激活 QS 全为 PTS，四个最差配置的激活全为 PTA（仿射）。该路径的激活分布应以零为中心对称映射，仿射零点偏移会严重劣化量化精度。
- **权重宜配 Histogram observer**：两个最优配置对激活与权重均用 Histogram；四个最差配置的权重无一使用 Histogram。

最优配置 QC#1：激活 Histogram+PTS、权重 Histogram+PTA，搜索集 BD-rate +14.3%。

## 4. 实验结果

主实验设置：UVG 与 HEVC-B，每序列 32 帧、1920×1080，SSF 九个质量档；量化模型同时用于编码与解码。逐帧 PSNR 实验用质量档 5，覆盖 2 数据集 × 同机/跨机 × 量化/非量化共八种组合。

穷举搜索关键行（Vimeo90k 256×256，相对未量化 SSF 的 BD-rate）：

| 配置 | 激活 Observer/QS | 权重 Observer/QS | BD-rate |
|---|---|---|---|
| QC#1 | Histogram / PTS | Histogram / PTA | +14.3% |
| QC#0 | Histogram / PTS | Histogram / PTS | +16.6% |
| QC#161 | MA MinMax / PTS | Histogram / PTA | +21.6% |
| QC#81 | MinMax / PTS | Histogram / PTA | +22.3% |
| QC#189 | MA MinMax / PTA | MA MinMax / PTA | +2021% |
| QC#105 | MinMax / PTA | MinMax / PTA | +2076% |

1080p 主实验（同机编码解码，量化 vs 未量化 SSF，九个质量档，平均 BD 口径）：

| 数据集 | BD-rate | BD-PSNR |
|---|---|---|
| UVG | +9.93% | −0.2913 dB |
| HEVC-B | +9.02% | −0.2776 dB |

逐帧与跨机结论（质量档 5，UVG 与 HEVC-B）：

- 非量化 SSF 跨机解码时 PSNR 显著崩塌、画面严重劣化，BD-rate/BD-PSNR 均无法计算；量化版跨机相对非量化版重建质量提升约 27 dB——这是方案的核心收益口径。
- 量化自身的逐帧 PSNR 损失 ≤0.04 dB，且主要显现在首帧（帧内编码帧），后续帧几乎不受影响。
- 量化模型在同机与跨机解码下的重建差异 <0.001 dB，来源于未量化的 VAE 路径；论文指出虽有理由预期该差异经帧间预测沿时间漂移累积，但在 SSF 上该效应远不及超先验路径失配，实测可忽略。

两点口径说明：其一，主实验 BD-rate（+9.93%/+9.02%）与搜索集 +14.32% 不可直接比较——前者为 1080p、UVG/HEVC-B、32 帧，后者为 256×256、Vimeo90k 短序列，论文对此有明确交代。其二，同机场景下的 BD 损失是“为跨平台可用性付出的代价”；在真实跨平台场景下非量化编解码根本不可用，因此方案实际带来的是压缩效率的正向改善。

## 5. 消融要点

- **量化配置消融（即穷举搜索本体）**：36 个可运行组合的 BD-rate 跨越 +14.32% ~ +2076.38%，证明超先验解码路径对量化方式极度敏感；最优解收敛于“激活 PTS + 权重 Histogram”，激活仿射量化是全部最差配置的共同特征。搜索同时暴露 PyTorch 量化栈的兼容边界（observer×QS 配对约束、与转置卷积不兼容）。
- **分辨率/数据集口径迁移**：同一量化体系在 256×256 短序列搜索集与 1080p/32 帧主实验间 BD-rate 相差约 5 个百分点（14.32% vs 9.93%/9.02%），提示小分辨率上的绝对损失乃至配置排序未必迁移到大分辨率。论文未显式重申主实验沿用的配置编号，行文衔接上应即搜索所得最优配置，严格来说是留白。
- **量化位置消融（隐含）**：仅量化超先验路径、VAE 保持浮点时，同机 vs 跨机解码差异 <0.001 dB，说明在 SSF 拓扑下 VAE 浮点差异既不破坏熵同步、也不构成可观的时间漂移；而量化损失集中在帧内首帧，与“超先验精度只影响熵参数估计”的机理自洽——首帧熵参数误差直接进入帧内重建，帧间路径则被运动补偿的预测冗余部分吸收。

## 6. 贡献与启示

贡献可归为三点： 在学习型视频编码上系统实证了浮点舍入导致的跨平台灾难性失配（全序列、全质量档复现），并给出可复用的信号级定位方法——追踪 ẑ→μ/σ 的分歧点，把问题收敛到超先验解码路径； 提出免 QAT、免额外码流信令的后训练 int8 静态量化方案，一次 78 序列级校准即可部署，直接兼容 CompressAI 现成九档 SSF 预训练权重，相对图像侧的 QAT 系方案与 Tian 等的额外信令方案形成清晰占位； 给出超先验解码路径量化的可操作配置规律（激活对称 PTS、权重 Histogram observer）与 PyTorch 量化栈兼容性实测。

工程启示： 学习型编解码互操作的前提是熵模型端到端一致，量化超先验路径是当前改造成本最低的达标手段，且 int8 化附带未来硬件实现降低功耗的红利（论文未报告耗时/吞吐变化，仅提功耗预期）； 同机约 10% 的 BD-rate 代价相对学习型编解码通常个位数的代际增益并不小，算子级部分量化（只量化对失配真正敏感的层）或轻量 QAT 是明确的改进方向； 方案保证的是解码潜变量/熵模型一致性，像素级逐位一致仍未达成，一致性测试规范需据此界定边界； 局限同样清晰：案例仅覆盖 SSF 这类“显式运动估计 + 残差编码”拓扑，其三条超先验路径相互独立、失配入口单一；DCVC 系条件编码与 MaskCRT 类 Transformer 编解码中，熵参数还依赖已解码上下文，失配敏感面更大——作者已将扩展至 context- 与 transformer-based 编解码列为后续工作，这也是判断该思路普适性的关键实验。
