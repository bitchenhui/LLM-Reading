## 1. 背景与动机

启发式是复杂搜索与优化的主力手段（模拟退火、禁忌搜索、迭代局部搜索等），但人工设计强依赖专家经验且不可迁移：不同应用需要不同算法/配置，逐一定制构成工程瓶颈。自动启发式设计（AHD，即 hyper-heuristics 谱系）的两条既有路线各有硬伤：遗传编程（GP）可解释但必须人工定义原语集与变异算子，实践中合适的原语库极难构造；机器学习辅助路线多需训练领域模型。

LLM 提供了第三条路：直接生成启发式代码。但论文明确援引 Mahowald et al. (2023) 的判断——纯 prompt 工程的独立 LLM 不足以产生超出既有知识的新颖且有用的想法；而 LLM-as-optimizer（用 in-context 学习直接生成试验解）在大搜索空间问题上失效。因此现实落点是 LLM+EC 的程序进化。代表作 FunSearch（Romera-Paredes et al., Nature 2024）将 AHD 建模为函数空间搜索，用 LLM 在进化框架中迭代改进函数，在 bin packing 等问题上超越人工基线，但机制低效：需约百万量级的程序生成（LLM 查询）才能得到高质量启发式，对多数用户不实用。

EoH 的动机来自对人类专家设计流程的模拟：专家在“想法”与“实现”两层交替迭代——先形成高层思路，落地为代码，再依据代码行为修正思路。FunSearch 只进化代码且不显式使用 prompt 策略；EoH 的核心假设是：以自然语言与代码双重表征启发式，并以精心设计的 prompt 策略驱动 LLM 在两层上推理，可用少二至三个数量级的查询预算取得相当或更优的结果，且分布外泛化更好。作者脚注声明其初步版本（arXiv:2311.15249）与 FunSearch 相互独立完成。

对本领域（音视频）读者的定位：编码器中的大量决策逻辑（QP 选择、模式判决、码率分配）本质是“状态特征→打分→离散选择”的启发式，长期靠人工查表与经验公式维护；EoH 范式正是这类逻辑的自动进化工具，关联细节见第 6 节。

## 2. 方法总览

EoH 维持 N 个启发式种群，每个个体是三元组：(1) 思路——LLM 生成的自然语言高层描述；(2) 代码块——遵循预定义接口的 Python 函数（显式约束函数名、输入变量、输出变量三要素）；(3) 适应度——在一组问题实例上运行对应算法取平均指标。这与经典 EA 的单实例目标评估不同，与 irace/SMAC 类 AHD 的实例集评估一致，实例集评估也因此成为主要算力成本。

每代循环：五个 prompt 策略（E1、E2、M1、M2、M3）各调用 N 次，每次执行：按适应度排名做 rank-based 父本抽样（个体 i 被选概率 p_i ∝ 1/(r_i+N)，r_i 为排名，N 为种群规模）→ 组装 prompt → LLM 先输出新启发式的一句话描述、再输出符合接口的代码 → 实例集评估适应度 → 可行个体并入种群；每代最多注入 5N 个新个体，随后截断保留 N 个最优进入下一代。

三个基准问题上的任务接口（启发式被约束为“单函数”）：

- **在线 bin packing**：设计打分函数，输入 item 尺寸与各可行箱剩余容量（NumPy 数组），输出各箱得分，item 放入最大分箱。进化评估集为 5 个 Weibull 分布实例（规模 5k、容量 100，沿用 FunSearch 设定），适应度 = lb/n 的平均值（lb 为 Martello–Toth 下界，n 为实际用箱数，越接近 1 越好）。
- **TSP**：在固定 GLS 框架（relocate+2-opt 两算子；局部搜索上限 1000 次迭代、每实例 60s）内设计“景观更新”策略：输入距离矩阵、当前局部最优路径、边使用计数矩阵，输出更新后的距离矩阵。评估集为 64 个 TSP100 实例（位置采样自 [0,1]²），适应度 = 相对 Concorde 最优解的平均 gap。
- **FSSP（置换流水车间）**：同样 GLS 框架（relocate+swap），设计时间矩阵更新 + 扰动作业选择函数：输入当前调度、时间矩阵、机器数/作业数，输出新时间矩阵与待扰动作业集。评估集为 64 个随机实例（50 作业、机器数 2–20、加工时间 U(0,1)），适应度 = 平均 makespan。

预算与算力口径：所有问题 20 代；种群 bin packing 为 20、TSP/FSSP 为 10；E1/E2 父本数 p=5；默认 GPT-3.5-turbo。bin packing 全程 LLM 查询 = 20 代 × 20 个体 × 5 策略 = 2000 次；整套框架为 Python 实现，单颗 i7-9700 CPU 跑通。

## 3. 关键设计

**双重表征。** thought 承载高层逻辑（抽象、可组合、可被 LLM 推理复用），code 承载实现细节与参数设置（可执行、可评估）。作者将二者定位为启发式的多视图表征，prompt 同时注入两视图，本质是细粒度的 in-context learning。

**五种进化 prompt 策略**（分探索 E 与修改 M 两组）：

- **E1（差异化探索）**：给 p=5 个父本，要求新启发式“与父本尽可能不同”——显式多样性压力，相当于语义空间上的交叉/变异算子。
- **E2（共性提取重组）**：给 p=5 个父本，先让 LLM 归纳共性思想，再基于该骨干思想引入新部件。这是“抽象-再组合”算子，消融显示其为跨容量/规模泛化的主引擎（第 5 节）。
- **M1**：单父本修改提性能；**M2**：仅调参数不换结构；**M3**：分析主成分、删除冗余部件——显式简化算子，抑制 LLM 代码进化中的表达式膨胀（GP 的老问题在此同样存在）。

这组策略模仿人类“查不同思路/归纳共性/调参/重构删冗余”的开发行为，问题无关，可直接移植到其他 LLM 辅助搜索框架。

**Prompt 模板五段式**：任务描述 / 策略指令 / 期望输出 / 注意事项 / 父本启发式（初始化 prompt 无父本段）。关键约束写在 Note 段：bin packing prompt 明确"Avoid utilizing the random component... maintain self-consistency"，即禁随机、保证确定性与自洽（工程上确保评估可复现），并压制多余解释 token。期望输出段强制“先一句话描述、后接口化代码”的生成顺序——先思后码；消融证明输出侧同时产出 thought+code 优于只输出 thought。

**搜索产物的实际形态**（附录给出的最终启发式）：bin packing 产物是多代累加成分的混合打分函数——剩余容量 diff 的指数项 exp(diff)、平方根项 sqrt(diff)、利用率项 1−diff/bins、以 diff > 3·item 为阈值的分段调整（+0.8/+0.3）、混合项 bins/((exp(diff)+0.7)·exp(diff))；对比 Best Fit 的一行式 item−bins，复杂度明显超出人工可维护范围。TSP 产物是类信息素的边距阵更新：对局部最优路径上的边计数，噪声因子 = U(0.7,1.3)/边计数 + d/平均边距 − (0.3/max 使用计数)×使用计数，更新式叠加 0.1 衰减；注意该问题允许随机成分，与 bin packing 的禁随机约束形成对照（约束按问题特性手工设定）。FSSP 产物为：随机选 30% 机器子集、随机权重加权平均加工时间、选 top 30% 作业扰动、对矩阵相应元素乘 U(0.8,1.2) 因子。三者共性：产物是表达式级启发式而非算法级重构，搜索空间被接口严格约束。

## 4. 实验结果

### 4.1 在线 bin packing（Weibull 实例，相对下界的平均超箱率，越低越好；训练分布仅 5k/C100）

|---|---|---|---|---|---|---|
| First Fit | 5.32% | 4.40% | 4.44% | 4.97% | 4.27% | 4.28% |
| Best Fit | 4.87% | 4.08% | 4.09% | 4.50% | 3.91% | 3.95% |
| FunSearch | 3.78% | 0.80% | **0.33%** | 6.75% | 1.47% | 0.74% |
| EoH | **2.24%** | **0.80%** | 0.61% | **2.13%** | **0.78%** | **0.61%** |

- EoH 在 6 个测试集中 5 个最优，在训练分布 5k/C100 与 FunSearch 打平（0.80%），唯一失利为 10k/C100（0.61% vs 0.33%）。

**组件消融**（六个 Weibull 测试集，相对下界 gap）：

| EoC（仅代码，仅 E1） | 148.63% | 3.23% | 24.55% | 150.89% | 12.53% | 32.02% |
| EoH-e1（仅 E1） | 4.13% | 0.99% | 0.60% | 58.17% | 55.48% | 54.79% |

- EoC 仅在训练分布（5k/C100）可用（3.23%），其余全面崩溃（1k 上 148–151%）——仅代码表征 + 纯差异化压力严重过拟合评估分布，thought 表征是泛化的必要条件。
- EoH-e1 在全部 C500 集上崩溃（约 55–58%）：“尽量不同”的多样性压力单独使用会失稳；E2 的共性提取是恢复泛化的主力（EoH-e2 降至 0.73–5.86%），M 系列修改策略提供最后一段精修增益（完整 EoH）。

**表征消融**（5k Weibull，3 次运行平均 gap）：仅代码输入 C2C 2.57%、仅思路输入 T2T2C 2.13%、双视图输入但仅输出思路 T&C2T2C 0.85%、完整 EoH 0.66%——输入侧双视图与输出侧双产物均有正贡献，输出侧同时产 thought+code 另贡献约 0.19 个百分点。

**LLM 底座消融**（2000 查询，3 次平均）：CodeLlama 1.07%、Deepseek 1.41%、Gemini Pro 0.71%、GPT-3.5 0.66%，全部优于对 GPT-3.5 随机采样 10000 次的 2.44%——进化框架的贡献大于底座档位；更强模型（GPT-3.5/Gemini Pro）仍占优。

**专家种子消融**：将 FunSearch 产出的启发式注入初始种群（其余随机初始化）后，平均 gap 从 0.66% 升至 0.55%（FunSearch 复跑为 0.97%）——专家知识可被继承并在进化中继续改进，无局部锁定。

## 6. 贡献与启示

**贡献**：(1) thought+code 协同进化范式，无需手工算法组件、无领域模型训练；(2) 五个问题无关、可移植的 prompt 策略；(3) 三个组合优化基准上超越人工与神经基线，bin packing 上以约 1/500 的查询预算（2k vs ~1M）打平或超越 FunSearch，且 OOD 泛化显著更优（1k/C500：2.13% vs 6.75%）。

**方法学启示**：启发式搜索空间没有 R^n 式良定义度量，多样性与距离实际隐式落在“自然语言思路空间”上；E2 的思路层抽象-重组是泛化主引擎，EoC 的崩溃则说明代码文本层的多样性度量不可靠——这为后续用求解轨迹行为相似性替代代码相似性的方向埋下伏笔。“先描述后编码”的输出顺序约束是一种零成本的推理增强。局限：实例集评估需完整跑算法，评估开销大；prompt 策略本身仍是手工设计（论文未来工作列出领域预训练 LLM、启发式搜索空间理论、人机交互三个方向）；单任务只产出一个启发式，未处理实例异质性下的覆盖问题。

**对音视频工程的映射**（本笔记侧重点）：

- **接口同构**：EoH 的任务模板“特征→打分→离散选择”与编码器决策完全同构——帧级/CTU 级 QP 选择、模式判决打分、参考帧选择、码控 λ 分配都是这个形状；bin packing 打分函数就是一个 RDO 式打分器。产物是 NumPy 表达式级启发式，可直接嵌入编码器决策路径，不引入神经网络训练/推理负担。
- **预算可行性**：数千次 LLM 查询（GPT-3.5 档、2000 次）使“按平台/内容类型定制编码启发式”在经济上成立；FunSearch 的百万级查询在编码器调优场景不可行。
- **下游实证**：清单中 VVenC 帧级 QP 自适应工作（arXiv:2606.20847）即以 EoH 式闭环 LLM 进化 Python 启发式为 VVenC 逐帧选 QP（DeepSeek 底座），自动发现“熵约束 RDO”，相对固定 QP 平均省约 1.26% 码率——证明该范式可迁移到 VVC 编码器这一典型音视频工程场景。
- **迁移警示**：EoC 消融表明适应度实例集覆盖不足会导致灾难性过拟合（训练分布 3.23% vs 其他容量 148%+）——映射到编码场景，进化评估集必须覆盖多样内容/分辨率/码点，否则打分函数在未见内容上崩溃；bin packing prompt 的禁随机约束对应编码器确定性与可复现要求（认证/回归测试需要 deterministic 行为时，应在 prompt Note 段显式禁随机，如同原文做法）。
