# RSI-Opt: Recursive Self-Improvement Optimizer Agents For Model Training

> Binghang Lu, Yige Sun, Guang Lin. *arXiv:2610.32026v1 (2026-10-23)*
> 本笔记由引擎自动深读生成（glm-5.3, pipeline deep_read v1），底稿：全文文本

## 1. 背景与动机

深度模型训练通常以预先固定的优化器与调度食谱开局，而其有效性高度依赖架构、数据与训练动态本身。替换食谱意味着反复开 run 与人工干预。既有两条自动化路线各有缺口：learned optimizer（VeLO 等）与符号搜索（Lion）在目标 run 开始前就把更新程序固化；并发的 in-run 路线（OPAL / reactive optimizers）让单个 LLM coding agent 在一次训练内监控动态、改写 update rule、学习率、调度与诊断——但其对话仅在 run 内持久，初始策略跨 run 不留任何经验：一次有效的优化器改动、一条被证伪的诊断、一份已测通的实现，在下一个 run 都要从零重发现。

RSI-Opt 研究的问题正是：优化器 agent 能否通过递归自我改进（RSI），跨 run 地改进自己的初始策略。做法是把 agent 积累的知识显式化为可编辑对象——prompt 模板、程序手册、已测代码库、决策节奏——由外层 meta-agent 依据历史 run 证据改写，并以 archive（沿用 Darwin Gödel Machine 的 archive 式搜索）保留已评估策略继续演化。LLM 权重、meta-agent 指令、评估器全部冻结，被演化的只有策略本身；这使知识可检查、可跨模型复用，但也直接引出论文的核心问题意识：训练套件分数上升无法区分“积累了通用优化知识”与“向少数熟悉任务拟合了食谱”，增长的代码库也不能说明 agent 在新 run 内是否仍需在线适配。因此论文除训练套件外，专门考察策略内容、向未见任务与其他 LLM 的迁移、以及首次优化器改动之后决策的贡献。

对音视频侧的工程背景：训练食谱获取成本在视频生成/流匹配模型、多模态与语音 LLM 预训练上极高，跨 run、跨模型的优化经验制品化是直接相关的降本问题（详见第 6 节）。

## 2. 方法总览

框架为双层循环，被演化的对象与被改写的对象严格分离。

**内环（within-run 适配）**：训练脚本、模型架构、数据顺序、loss、batch size、参数更新预算全部固定；优化器的更新规则以可编辑程序暴露。agent 可编辑两个程序：`coder`（每次更新接收梯度并原地修改参数）与 `analyst`（每隔若干更新计算只读诊断）。在 D 个（实验固定为 20 个）调度决策点，agent 收到自上次决策以来的训练 loss 历史、分析程序报告、错误与计时信息，可检查/编辑 workspace 文件并执行 shell 命令（无网络、无 GPU）。新 updater 先在短 trial 窗口测试，抛异常即回滚。训练在 agent 决策时暂停，故 agent 延迟只影响 wall-clock 而非模型更新数；对话历史在 run 内跨决策持久；最终评估指标对内环 agent 保密，run 结束后才由外层评估器读取。

**策略 π 四要素**： 任务字段化的 prompt 模板； 自然语言写的 playbook（程序与教训）； 索引化的 Python 代码库（update rules、schedules、参数分组、稳定性检查、诊断）； cadence（前载或均匀的决策调度与诊断频率）。playbook 与库在 run 内只读，agent 可将库模块拷入 workspace 再修改使用；决策次数由实验统一封顶，策略无权自行增加。

**外环（跨 run 策略演化）**：archive 保存 (策略， 分数) 及 run 证据。生成子代时按概率正比于 sigmoid(λ(sp−es))/(1+np) 采样父代（sp 为父分数、es 为 archive 中位分、np 为其已有子代数——分数项偏向前排，子代计数项抑制重复走同一分支）。meta-agent 收到父策略副本、其评估 run 的 digest（最终指标与 z 分、in-run agent 的 rationales、最终优化器程序、notes）及 archive 条目（各任务分数、changelog），改写策略并被要求记录改动、依据与预期效果；其 CPU-only shell 可跑单元测试与代理实验。指令鼓励可迁移教训、禁止出现任务名与任务特定分支（但作者明确承认该指令本身不能防止特化）。验证检查模板字段、Python 可解析性与大小限制，失败最多修复两次；**每个有效子代都评估并入档，包括分数低于父代者**——archive 保留全部探索路径，选择压力只出现在父采样与最终策略挑选上。

**评分与报告口径**：演化分数为任务级 z 分数的任务×种子平均，z 相对 static recipe（每任务 5 seeds）在变换空间（ML 恒等、PDE 取 log10）归一。最终报告另用 raw-space summary 分数：z̄raw = d(m̄−m̄static)/s_static，按任务组取平均；这是描述性重算（受表格舍入精度限制），且明确不从聚合统计推断置信区间或逐 seed 胜场。

**实现**：内环 agent 与 meta-agent 均通过 bash / read_file / write_file / edit_file 四工具的调用循环运行；agent shell 处于独立网络命名空间，无 GPU 与 API 凭证；对话超 160k token 触发摘要压缩替换历史；file-based 队列调度 GPU，训练暂停期间多 run 可共享单卡。审计覆盖 528 份 in-run transcript（18,895 次工具调用）与 20 份 meta-agent transcript（949 次调用）。

## 3. 关键设计

**（1）可编辑优化器接口与执行边界。** `coder`/`analyst` 的写/读分离、trial 窗口异常回滚、wrapper 拒绝参数 dtype 变更与评估相关参数移动，构成第一层防线。关键限制在于：生成的 updater/诊断代码直接运行在训练进程内，shell 级隔离并不覆盖该代码对进程状态的访问——日志化 shell 与文件工具调用本身既不能穷举 imported code 的可用访问面，也不能排除一切评估操纵形式。文件系统隔离（隐藏其他 run、任务脚本、数据、论文）是项目中途才补上的，这正是后述 held-out 泄漏事件的来源。

**（2）知识分层与最小 prompt 改动。** 实测子代对固定 prompt 仅增 0–23 行（多为指向 playbook 的摘要），知识主体沉淀在程序与库模块中：混合 updater（选定张量上 Muon、其余沿用起始规则）、调度辅助、参数角色分类器、诊断与接口检查。该分层使策略可整体跨模型移植——同一策略不改一字用于 GPT-5.5 与 GPT-6.1。

**（3）archive 搜索的三个制度性选择。** 全子代入档（含劣于父代者）保留探索分支；分数只在父采样与最终选择起作用而非硬性改进过滤；强制 changelog 记录——但 20 个 meta-agent 中有 9 个（含产出最终策略 p016 的那个）在写 changelog 前触及 50 次调用或 30 分钟上限，changelog 覆盖不完整（编辑被保留，记录缺失）。

**（4）防泄漏的评估协议。** 种子三段分层：100/101 用于演化，102/103 对 archive 前三名复评取四 seed 均值定最终策略，200–202 全新种子只用于报告；held-out 任务完全不参与选择。已披露事故：gen-1 一个 meta-agent 在文件限制生效前读了 held-out noisy-label 任务描述，该策略及其后代（共 2 个）被排除出父选择与最终选择；但 archive 摘要可跨血统传信息，直接读取审计 + 血统剔除并不能证明无间接暴露——作者将其列为 held-out 结论的限定而非证据。

**（5）CPU 代理实验闭环。** meta-agent 可自跑小实验验证假设。最典型一例：用小 GroupNorm UNet 做流匹配、以恒定学习率 AdamW 为基线，在 hidden conv 上加 Muon 使所有测试配置下验证 loss 下降（含 3000 步 0.188→0.174）；代理扫描还发现剩余 Adam 张量的学习率比 Muon 自身学习率更关键。该提案被如实记录为“代理→真实任务的未测试迁移”，随后被 in-run agent 应用，UNet 任务的进化分在第 3 代于两个 seed 上从约 +9 升至 +19，并经 archive 摘要扩散到其他血统。作者谨慎注明：隔离该改动因果贡献需要 parent-to-child 受控重放。

**（6）RSI 范围界定。** 被递归改进的是“改进优化器的策略”，meta-agent 自身的改进程序不变；LLM 权重、指令、评分规则、任务划分固定。论文同样明示缺口：没有 matched-budget 的“每次从 gen0 独立提议”对照，无法隔离继承相对独立提议的净收益。

## 4. 实验结果

**设置**：9 个单 GPU 任务分三组——训练套件（ResNet-18/CIFAR-10、GPT-34M/FineWeb、流匹配 UNet/MNIST），held-out ML（ViT/CIFAR-100、LSTM/WikiText-2、10% 错标 noisy CIFAR-10），held-out PDE（Burgers 1D PINN 全批 Adam 10k 更新、Heat 2D PINN 重采样配点 30k 更新、有限差分变阶时间分数扩散 10k 更新）。in-run 模型为 Opus 5.5 / GPT-5.5 / GPT-6.1（均高推理档）；演化期间 meta 与 in-run 均为 Opus 5.5。5 代×4 子代共 21 个策略、零无效。基线：static（5 seeds）、tuned-LR oracle（学习率乘 {1/4,1/2,1,2,4}、每档 3 seeds、直接按评估指标选最优的乐观口径）、固定 prompt 单 agent。

**演化过程与知识产出**：gen0 得 +10.30，archive 最佳 +14.63（p016，第 4 代）；前三名四 seed 复评为 +14.55 / +14.42 / +14.19，选定 p016。

**任务组级 raw-space 摘要 z（新种子，正值优于 static）**：

| 模型 | 方法 | 训练套件 | Held-out ML | Held-out PDE | 全部 held-out |
|---|---|---|---|---|---|
| – | static+tuned LR（oracle） | +3.46 | +0.49 | +1.11 | +0.80 |
| Opus 5.5 | 单agent / RSI-Opt | +10.48 / **+14.33** | **+8.71** / +8.23 | **+1.72** / +1.51 | **+5.22** / +4.87 |
| GPT-5.5 | 单agent / RSI-Opt | +4.33 / **+14.10** | +1.18 / **+6.54** | −1.90 / **−0.32** | −0.36 / **+3.11** |
| GPT-6.1 | 单agent / RSI-Opt | +9.90 / **+14.21** | −0.01 / **+6.87** | +1.61 / **+1.74** | +0.80 / **+4.30** |

关键读法：

- **agent vs static 本身已是大头**：Opus 单 agent 将 GPT-34M 验证 loss 从 4.480 降到 4.332、ViT 从 55.84% 提到 62.62%；Heat 2D 平均误差比 static 低约 6000 倍（static 恒定学习率使最终迭代噪声大，跨 seed 终值散布 0.008–0.73）。oracle LR 扫描只回收一部分收益（held-out 均值 +0.80 vs Opus 单 agent +5.22）。收益不普适：GPT-5.5 基线使 Burgers 与 LSTM 双双劣于 static。
- **跨模型迁移是本工作的标志性结果**：Opus 演化出的策略不改一字交给 GPT-5.5，held-out 总分从 −0.36 升至 +3.11，训练套件 +14.10 几乎追平 Opus 的 +14.33；GPT-6.1 各任务组全面提升（held-out ML +6.88，含两个图像分类各约 +6 个点）。但 Opus 自身在 held-out 总分反降（+5.22→+4.87，尽管 4/6 任务均值更优）——可迁移知识对“任务选择较弱的模型”补偿明显，对“已有有效策略的模型”可能形成干扰。
- **PDE 迁移有选择性**：同一策略下，Opus 的 PDE 摘要分 +1.72→+1.51（Burgers 约 2.7×、heat 约 2.2× 改善，fractional 恶化）；GPT-5.5 为 −1.90→−0.32（Burgers 约 1.7×、heat 约 15×，组均值仍为负）；GPT-6.1 为 +1.61→+1.74（Burgers 4.82e-3→5.46e-4，约 8.8×；heat 约 2.0×；fractional 0.322→0.319 基本不动）。两个 GPT 模型在三个 PDE 任务上均值全部改善。
- **新种子关键行**（单agent→RSI-Opt）：Opus：noisy CIFAR-10 78.73→81.77，Burgers 3.95e-3→1.45e-3，heat 6.3e-5→2.9e-5，ViT 62.62→61.52（降），fractional 0.306→0.357（差）；GPT-6.1：ViT 55.54→61.92，noisy 73.30→79.82，LSTM 5.315→5.439（差）。
- **特化轨迹**：训练套件逐检查点单调升（+10.48→+11.49→+13.91→+14.33），held-out ML 却在第 1 代后达峰（+8.71→+9.75→+7.51→+8.23）。第 1 代加入的主要是通用程序（谨慎选早期改动、学习率衰减到零、张量角色检查）；后期 playbook 的实测 run 表从 6 条涨到 18 条、卷积 Muon 提案明确瞄准 UNet——与“持续演化越来越拟合 3 任务小套件”一致。
- **资源画像**：演化策略的 realized token 反而更低——输入 token（含缓存读）Opus 5.63M→4.02M、GPT-5.5 8.90M→4.61M、GPT-6.1 6.99M→3.65M；每 run 改动程序的决策数 11.5→4.2；失败决策两边均为 0。作者强调等决策额度与费用上限不等于等实际算力（代理实验、诊断开销、GPU 时间、LLM 暂停均未纳入），不构成总成本结论。

## 5. 消融要点

**组件消融（Opus，最终策略上分别移除）**：−library：训练 +14.45 / held-out ML +8.00；−playbook：+13.60 / +8.06；−evolved prompt：数据不可得。各组件单独移除影响很小，提示收益高度可替换、主要经由初始决策携带；cadence 未被这三个移除隔离。

**干预分解（最核心的消融，四种条件）**：

| 条件 | 训练套件 | Held-out ML |
|---|---|---|
| static / tuned-LR oracle | +0.00 / +3.46 | +0.00 / +0.49 |
| 冻结库模板（无 agent，原样执行） | +9.71 | **−21.80** |
| 单agent：首改冻结 / 单次决策 / 完整 | +10.72 / +9.43 / +10.48 | +6.35 / +6.12 / +8.71 |
| RSI-Opt：首改冻结 / 单次决策 / 完整 | +14.56 / +13.82 / +14.33 | +6.82 / +5.05 / +8.23 |

- **未编辑模板跨架构不可靠**：模板在 UNet 上接近完整 agent（原报 +18.5 vs 重算完整 agent +20.25）、heat 相当、GPT-34M 恢复约一半收益，但 ViT 仅 35% 准确率（static 56%），LSTM 与 Burgers 恶化。模板自身的 notes 就要求先检查参数角色与学习率——可复用代码不是免检的固定优化器。
- **seen 任务收益集中在初始适配**：冻结首改得训练套件 +14.56，甚至高于完整 agent 的 +14.33；单次决策 +13.82。
- **未见任务上后期决策对双方都有益**：相对首改冻结，完整 baseline 在 held-out ML 约多 2.4 z、演化策略约多 1.4 z——在线持续适配的价值不专属演化策略。具体重放：LSTM 上首改冻结终值 z=−1.9 vs 完整演化 agent +3.3；Burgers 终误差 5.5e-2 vs 1.5e-3。
- **行为统计（描述性，非因果）**：最终优化器程序中 Muon/正交化更新占比 35%→79%，Shampoo/SOAP 类 15%→10%，裁剪/步长控制 60%→79%，调用演化库模块 0%→82%（runs 81 vs 80）。

**对照缺口（作者自列）**：无 matched-budget 独立提议对照与 restricted-parent 对照；静态对照仅覆盖起始食谱、oracle LR 扫描与单个未编辑模板；缺 schedule-matched Adam、标准 Muon/AdamW 混合、Adam→L-BFGS 的 PINN 食谱对照，且涉及 L-BFGS 的比较应匹配梯度评估量或算力而非名义更新数。

## 6. 贡献与启示

**贡献**：（i）首个面向优化器 agent 的显式策略演化框架——跨 run 演化与 within-run 适配正交叠加，演化对象（prompt/playbook/代码库/cadence）可检查、可跨模型移植；（ii）一套可复用的迁移评估协议（种子三段分层、held-out 隔离、四种干预控制：未编辑模板/冻结首改/单决策/完整 agent）；（iii）选择性迁移与早期特化的系统证据——训练套件单调升而 held-out ML 第 1 代即峰。

**方法论启示**：z 聚合中低参考方差任务会主导均值，论文最终改用 raw-space summary、并明确拒绝从均值±标准差反推配对置信区间与逐 seed 胜场——这种统计自律值得所有做 agent 进化/搜索类工作的组效仿。泄漏审计部分（工具调用全量扫描、血统剔除、承认 archive 摘要可间接传信息）同样是对“自我改进系统评测完整性”问题的一份诚实样本。

**与音视频技术上下游的关联**（本笔记研究员视角的推论，非论文结论）：
- 任务组与 AV 训练负载直接同构：GPT-34M/FineWeb 是语音/多模态 token LLM 预训练的缩影，演化产物“transformer 矩阵上 Muon + 学习率衰减到零 + 参数角色检查”对音视频基础模型预训练的优化器选型有直接参考价值；流匹配 UNet/MNIST 即图像/视频生成模型（扩散/流匹配主干）的最小化原型，“hidden conv 上 Muon、其余 Adam、剩余张量学习率更关键”的代理实验结论对视频扩散/流匹配架构（UNet 及 UNet-DiT 混合）的训练食谱工程是可检验的候选；ViT/CIFAR-100 对应视频理解骨干的训练；10% 错标 CIFAR-10 对应网络规模音视频数据的标签噪声场景。
- 工程含义：对千卡级视频生成训练这类单次 run 成本极高的负载，“训练经验制品化 + 跨模型复用”是摊薄调参成本的可行路径——同一策略让 GPT-5.5 的 held-out 从 −0.36 到 +3.11、token 开销反而下降约一半，说明策略制品的价值可脱离演化所用的宿主模型。但消融同时给出强警示：未经任务条件化检查的代码模板照搬会在分布外架构上崩溃（ViT 35%），在线适配环节不可省。
- 风险面：生成优化器代码运行于训练进程内、sandbox 无法完全审计；托管模型版本漂移影响可复现性；均为引入此类自动化前必须正视的依赖。

**局限**：单 GPU、短更新预算，未测长时/多卡训练；演化套件仅 3 任务×2 seeds，特化风险结构性存在；每格仅 3 个最终种子，不确定度估计精度有限；等决策额度≠等实际开销，摊销性成本核算（外环搜索评估、CPU 代理、GPU、缓存计价）未完成。

## 7. 与其他论文的联系

- **InfraRSI（arXiv:2611.11558）**：同为把 RSI agent 应用于模型训练栈——RSI-Opt 演化的是 run 内优化器的数学策略，InfraRSI 经五阶段验证工作流把开放式指令转化为分布式 LLM 训练的系统优化（最高 2.75× 加速）。二者构成“训练自改进”的两个正交轴：改更新规则 vs 改并行/系统配置，方法上共享“LLM 产出可执行改动 + 受控验证”的外环范式。
- **MaD-RSI（arXiv:2610.28201）**：把多模型失败轨迹作为训练证据、优化跨异构 LLM 共享的 agent 外壳。RSI-Opt 的跨模型实验（Opus 演化策略原样用于 GPT-5.5/6.1 并取得正向 held-out 增益，同时发现对较强宿主可能干扰）为“外壳可跨模型迁移但收益依赖宿主-任务交互”提供了同方向的实证支持，与 MaD-RSI 的异构模型证据视角直接互补。
- **SkillDuet（arXiv:2611.12109）**：RSI-Opt 的 playbook+代码库本质是冻结权重下的技能库；SkillDuet 用响应反馈让 LLM 参数更新与外部技能库协同演化，恰好对应 RSI-Opt 讨论中引用的“harness 演化存在上限、届时需启动权重训练”这一下一步路线。
- **TRUST（arXiv:2611.10787）**：RSI-Opt 自认三处统计缺口——z 聚合可被低方差任务主导、archive 选择可偏爱偶然强评估、无显著性检验；TRUST 以在线多重假设检验为 RSI 控制错误演化率并提供统计保证，可直接嫁接补齐 RSI-Opt 的父采样与最终选择环节。
- **RSI-PDEbench（arXiv:2611.14949）**：RSI-Opt 的 held-out PDE 三任务（Burgers/Heat/分数扩散）显示优化器知识向 PINN 类训练的迁移是选择性的；RSI-PDEbench 提供 1001 案例、42 方程模板的系统基准，可作为该迁移方向更大规模的评测底座。
- **WeightLoop（arXiv:2611.07319）**：同为“LLM 生成程序 + 实验反馈闭环”的自改进，但对象落在权重空间（有界参数编辑、免重训练）而非优化器与策略的文本/代码空间；两者分别占据“改被训模型”与“改训练过程”两个极端，可视为自改进对象谱系的两端点。
- **TGR-EvoDAG（arXiv:2610.32326）**：工业侧用 DAG 式多智能体演化生成式推荐完整管线（在线 CTR 相对 +0.40%），与 RSI-Opt 同属 agent 演化可执行训练代码；关键差异是 RSI-Opt 冻结任务定义与评估器、只演化策略并显式研究泛化，而 TGR-EvoDAG 演化整条管线并以在线指标为准绳。
- **LongCapHarness（arXiv:2611.10463）**：同为免数据合成与后训练的 harness/策略演化路线（在 HELMET/RULER 超基线且成本低于 50%），与 RSI-Opt“知识以文本+代码承载、LLM 权重不动”的定位一致，共同支持“外壳/策略演化可在跨模型设定下产生可复用增益”的判断。
